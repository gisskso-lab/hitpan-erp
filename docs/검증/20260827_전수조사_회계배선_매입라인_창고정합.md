
> *⚠️ 이 시험이 못 하는 것 — 화면에 「반품」 글자가 뜨는지는 못 잰다. 서비스가 내려보내는 행 수까지가 범위다.*

⇒ 게이트는 **서비스 반환값**까지만 본다. 사장님은 **게시된 화면**을 보셨다. 그 사이는 게이트가 **설계상 못 본다.**
= "고쳤다 ≠ 갔다" **5차**. 다만 이번엔 게이트가 자기 한계를 **명시**해 둔 게 다르다.

## 5. 착수 순서 (PM 판단 · 전결)

```
1차  회계 계정과목 확장 (8 → 20여개) + DB-32 시드 동기화
       ↑ 3·4차의 물리적 전제. 계정이 없으면 FK 1452 로 죽는다
2차  수금·지급 기표 배선      (계정 준비 후)
3차  경비·급여 기표 배선      (승인 시점 훅 = FinanceService.cs:308)
4차  안내문 메서드 삭제       (AppendUnpostedNoticeAsync — 예고된 폐기)
─────────────────────────────
5차  매입라인 상태값 정합    (canceled/cancelled · PO enum 불일치)
6차  창고 스위치 배선        (use_multi_warehouse 연결 + 원장 UNIQUE 키)
```

**회계를 먼저 두는 이유**: 오더 1번이 먼저 오셨고, 계정과목 확장이 다른 모든 회계 작업의 전제다.
**창고를 뒤에 두는 이유**: `stock_ledger` UNIQUE 키 변경은 **DDL 변경 + 기존 데이터 영향**이라 단독 작지서가 필요하다.
