## 판단 1줄
**조건부 가** — 제어 코드 32개 대응 삭제는 이미 수정본인 같은 파일에 「구성 요소 삭제」 하나를 더한 것이라 앞서 정한 수정본 조건(㉠~㉤ · 11/20 꼬리표 원문 인용 글자) 안에 그대로 든다 · 새 라이선스 의무 0 · 꼬리표 글자(D14-6) 무변. **더 지킬 조건 2**: ⓐ 손질 = 유니코드 하위표에서 U+0000~U+001F 대응을 빼는 것만 — 글리프 · 윤곽 · 너비 · 이름 기록 무변(꼬리표 「글리프 = 나눔고딕」 이 사실로 남는 조건 · 확인 = [3-V] · [4] 가 바뀐 줄이 cmap 삭제뿐인지 대조 · 새 코드 요구 0) ⓑ 자체시험 가짜 글꼴 = 원본 글꼴 바이트 0 으로 프로세스 안에서 만들고 저장소 · 산출물 반입 0(지시서 §2 합격 시험 글자 그대로).

## 근거
1. **수정본 분류 무변**: 정의 "'Modified Version' refers to any derivative made by adding to, deleting, or substituting – in part or in whole – any of the components of the Original Version…" → 대응 삭제 = 「deleting … components」 = 수정본. 이 파일은 이름 고침으로 이미 수정본(11/19 근거 표 2) → 새 분류가 생기지 않음 · OFL 은 수정 정도에 따라 의무를 나누지 않음.
2. **조건별 대조**: ㉠ 수정 파일 · PDF 러너 밖 0 = 무변(재확인 3줄 · 질문 전제) → 조항 2 고지 의무가 생긴 일 0 / ㉡ 조항 3 예약 이름 제한 = "the primary font name as presented to the users" 에만 · cmap 은 이름 기록 아님 → 무변 / ㉢ 손질 자리 = 이름 고친 뒤 · 저장 앞(지시서 §2) → 저장본을 다시 읽어 세는 `preserveSame`(ID 0 · 7 · 13 · 14 등 보존 기록 바이트 같음)이 손질까지 덮음 / ㉣ · ㉤ = 결과표 글자 — 글리프 무변이므로 「글리프 = 나눔고딕(SIL OFL 1.1)」 · 원문 인용 그대로 정확.
3. **바꾼 곳 표시 의무 없음**: OFL 1.1 조항 1~5 에 「바꾼 곳을 표시하라」 는 조항 없음(단독 판매 금지 · 고지와 라이선스 동봉 · 예약 이름 · 권리자 이름 홍보 금지 · 같은 라이선스로 배포뿐) → 꼬리표에 손질 사실을 덧붙일 필요 0. 사실 파일 `cmapDropped`(하위표별 지운 수) = 내부 변경 기록으로 충분(권고 · 이미 지시서 §2 에 있음).
4. **표시 정확성은 오히려 나아짐**: ㉣ · ㉤ 의 목적 = 공개 결과표가 사실과 같을 것. 띄어쓰기가 U+0001 로 거꾸로 읽히는 것을 판정기 덧칠 없이 글꼴 표에서 막으면 결과표 글자가 실제 렌더와 더 맞음 → 법무상 걸림 0.

## 범위 경계(다시 묻는 경우)
- 같은 꼴(cmap 대응 빼기만)이면 U+00AD 를 결재 ② (가)로 바꿔 함께 빼도 이 판단 안 — 따로 묻지 않는다.
- 다시 묻는다: 글리프 · 윤곽 · 너비를 바꾸거나 대응 빼기 말고 다른 손질을 더함(꼬리표 「글리프 = 나눔고딕」 이 흔들림) · 이름 기록 손질 범위를 넓힘 · 수정 파일이나 고친 글꼴로 그린 PDF 를 러너 밖으로 냄.
