## 0. 한 줄

**DB 가 바뀌면 자동 업데이트가 막히던 것을 풀었다.
이제 컬럼을 추가하는 주체가 ERP 안에 있고, 실제로 도는 것을 눈으로 확인했다.**

---

## 1. 무엇이 문제였나

업데이트는 **프로그램 파일 교체**만 한다. DB 컬럼을 추가하는 주체가 **없었다.**

```
새 프로그램: "local_company 에서 seal_url 읽어와"
고객 PC DB : 그런 칸 없는데요
          → 500. 회사정보 화면이 안 열린다
```

워치독은 이걸 알고 **새 마이그가 있는 릴리스를 스스로 차단**해 왔다:

> *"워치독은 DB 마이그를 적용하지 않으므로(고리5 미구현) … 통과시키면 적용 주체가 없어 500 P0."*
> — `UpdateOrchestrator.cs:512`

**차단은 결함이 아니라 정직한 안전장치였다.** 다만 그 결과 —
**DB 가 바뀔 때마다 자동 업데이트가 막히고 재설치로만 갈 수 있었다.**

---

## 2. 무엇을 했나

### 2-1. 적용 주체를 세웠다 (고리5)

`MigrationRunner` 는 **이미 완성돼 있었다.** 부르는 자리만 0건이었다.
설계 주석이 그렇게 적고 있다 — *"① 단계는 클래스 존재 + 호출하면 동작까지만.
앱 시작 자동 실행 배선 0건 — ②단계 범위."*

⇒ `Program.cs` 의 `var app = builder.Build()` **직후**에 배선했다.

**왜 그 자리인가** — 스왑 순서가 `api 교체 → 기동` 이므로,
**새 코드가 첫 쿼리를 던지기 전에** 컬럼이 생긴다.

### 2-2. 안전 조건 3가지 (사장님 승인 조건)

| 조건 | 구현 | 실측 |
|---|---|---|
| ① 이미 된 건 건너뛴다 | `MigrationRunner:104` | 🟢 §3-3 |
| ② 실패하면 멈추고 알린다 | `MigrationRunner:143-162` | 🟢 §3-1 |
| ③ 업데이트 전 자동 백업 | 워치독 기존 흐름 | (기결재) |

### 2-3. 🔴 내가 빠뜨렸던 것 — 실측이 잡았다

**clean DDL 의 `schema_migrations` 시드에 DB-85 를 안 넣었다.**

이건 이미 설계돼 있던 장치다. 주석에 **DB-85 를 예시로 명시**까지 하고 있었다:

> *"다음 릴리스에 DB-85 추가 시 여기 INSERT 도 갱신해야 하며,
> `scripts/ddl-smoke-test.sh` 가 자동 대조해 한쪽만 갱신하면 CI 빨간불이 된다."*

⇒ 시드에 `('DB-85','clean-ddl',1)` 추가. **소스 56개 == 시드 56개 일치 확인.**

> 안 넣었으면 **신규 고객의 첫 자동업데이트가 전량 차단**됐다.
> 2026-07-22 에 실제로 났던 사고와 같은 자리다.

⇒ `ddl-smoke-test.sh` 핵심 컬럼 스모크에도 DB-85 컬럼 3종 추가.
신규설치 DDL 에서 빠지면 CI 가 잡는다.

### 2-4. 워치독 게이트 — 차단 → 경고 후 통과

적용 주체가 섰으므로 전제가 바뀌었다.

**단, 그냥 풀지 않았다.** 적용 주체가 **있다**는 것과 그 적용이 **성공한다**는 것은 다르다.
⇒ 무엇이 실려 왔는지 로그에 남기고 통과시킨다. 사고 시 "무엇이 적용되려 했나"를 즉시 안다.

**`applied is null`(DB 를 읽지도 못함) 분기는 그대로 차단으로 뒀다.**
고리5 가 있어도 판정 자체가 불가능한 상태이며, 이건 DB 연결 문제라 자동 교체로 풀 일이 아니다.

## 3. 실측 — 눈으로 확인한 것

### 3-1. 실패 시 정말 멈추는가 (1회차 · 의도치 않은 실측)

첫 기동에서 **진짜 실패가 났고, 그게 안전 설계를 증명했다.**

```
[MigrationRunner] 마이그 실패 — 중단. 실패 마이그: DB-02. 다음 마이그 진행 안 함.
[Startup/Migration] 🛑 DB 스키마 갱신 실패 — 실패 마이그: DB-02.
                    사유: Duplicate column name 'platform_id'.
                    이 지점에서 중단했고 다음 마이그는 진행하지 않았습니다.
```

DB 확인 결과 **`schema_migrations` 에 `DB-02 / success=0` 한 줄만** 남았다.
DB-03~85 는 **건드리지 않았다.** DB 손상 0.

> 원인은 이 개발 PC DB 가 **clean DDL 시드 이전에 만들어진 옛 DB** 라
> 이력이 비어 러너가 처음부터 재시도한 것이다. **신규 고객은 시드가 이 일을 대신한다.**
> ⇒ 실제 적용 상태(DB-02~79·81)를 `success=1` 로 백필해 실측을 이어갔다.

### 3-2. 실제로 적용되는가 (2회차)

```
[MigrationRunner] 적용 완료: DB-80 (DB-80_reseller_applications.sql)
[MigrationRunner] 적용 완료: DB-82 (DB-82_watchdog_update_consents.sql)
[MigrationRunner] 적용 완료: DB-83 (DB-83_local_update_status.sql)
[MigrationRunner] 적용 완료: DB-84 (DB-84_schema_migrations.sql)
[MigrationRunner] 적용 완료: DB-85 (DB-85_local_company_address_detail_and_images.sql)
[MigrationRunner] 완료 — 신규 적용 5건, 멱등 skip 51건.
[Startup/Migration] ✅ DB 스키마 갱신 완료 — 신규 적용 5건, 건너뜀 51건.
```

**컬럼이 진짜 생겼는지 확인:**

```
Field           Type          Null
address_detail  varchar(200)  YES
seal_url        varchar(200)  YES
header_url      varchar(200)  YES
```

### 3-3. 몇 번을 켜도 안전한가 (3회차 · 멱등)

```
[MigrationRunner] 완료 — 신규 적용 0건, 멱등 skip 56건.
[Startup/Migration] DB 스키마 최신 — 적용할 것 없음(건너뜀 56건).
Now listening on: http://127.0.0.1:5257
Application started.
```

🟢 **신규 0건.** 재기동해도 아무것도 다시 하지 않는다.

### 3-4. 사장님이 지적하신 것이 실제로 고쳐졌나

**저장 → 조회 왕복을 실제 SQL 로 실행:**

| 필드 | 저장한 값 | 조회된 값 |
|---|---|---|
| `address` | `서울시 강남구 테헤란로 123` | 🟢 그대로 (합쳐지지 않음) |
| `address_detail` | `5층 501호` | 🟢 **따로 살아있음** |
| `seal_url` | `seal/demo.png` | 🟢 저장됨 |

**중복 누적 재현 시험 — 같은 값으로 4번 저장:**

```
addr_len  address                      address_detail
16        서울시 강남구 테헤란로 123      5층 501호
```

🟢 **4번 저장해도 16자 그대로.** 종전이라면 저장할 때마다 길어져
`"…테헤란로 123 5층 501호 5층 501호 5층 501호"` 가 됐을 자리다.

> ⚠️ **실측 후 demo 데이터는 원상복구했다**(전부 NULL). 헌법 #39.
> 실측 전 **DB 전체 백업 455MB** 확보 후 진행했다.

## 6. 판단 근거를 남긴다 — 실패해도 앱을 죽이지 않은 이유

`Environment.Exit` 을 하면 ERP 가 아예 안 뜬다. 고객은 화면조차 못 보고,
본사 원격 진단도 불가능하다(고객 PC 로컬 구조, 헌법 #30 본사 의존 0).

⇒ 기동은 시키되 **무엇이 실패했는지 명확히 남긴다.**
새 컬럼을 쓰는 화면만 오류가 나고 **나머지 업무는 계속 돌아간다** — 전면 중단보다 피해가 작다.

⚠️ **이 판단은 '부분 실패' 전제다.** 마이그가 **데이터를 변형하는 종류**로 넓어지면
그때는 기동 차단이 맞을 수 있다. **그 시점에 재결재를 받는다.**
