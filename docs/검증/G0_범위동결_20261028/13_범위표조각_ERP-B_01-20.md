## §0 분류 읽는 법 (이 조각이 쓴 해석 — 합본 때 갈래 간 통일 필요 · 질의 Q-1)

| 분류 | 이 조각에서의 뜻 |
|---|---|
| **베타 필수** | 베타 사용 경로에 판정식 ⓐ(업무 중단 · 원장/재고·데이터 불일치 · 손실 · 권한 침범 · 법적 오인) 또는 ⓑ(대표 실측 입증)가 **정상 사용만으로 닿는** 결함이 있다 ⇒ 베타 전 봉합 대상 |
| **서버 비활성 후 정식 이후** | 베타에 쓸 이유가 없거나 고칠 값이 결재에 달려 있다 ⇒ 서버 입구(404)·권한·상태표시(메뉴·모바일 입구 포함)까지 닫고 정식 이후. 행마다 확인 항목을 적는다 |
| **제안 보류** | 동결 예외 근거가 없다(결함 없음 · 미실측 가설 · 특수 실패·경합에서만 닿음) ⇒ **현 상태 그대로 베타에 남기고** 조사서 🔵 개선 제안은 동결. 재현 필요 항목은 G2·G3 실측에서 재판정 |

- 「코드 확인 필요」 = 분류가 서버 실행 경로에 달렸는데 이 갈래가 코드로 닫지 못한 칸.
- §11-2 에 따라 코드를 다시 연 행 = 06·09·10·11(서버 입구가 분류를 가른다) — grep 만 · 결과는 각 행에 「이 갈래 재확인」으로 표시.

## §3 질의 (PM · 합본 전)

- **Q-1** 3분류를 「행(기능)의 베타 전 **작업**」으로 읽었다(결함 없는 행 = 제안 보류 = 현 상태로 베타 노출). 갈래마다 다르게 읽으면 합본 집계가 섞인다 — 합본 전 통일 필요.
- **Q-2** K10 은 매입현황의 「작성중 포함」만 묻는다. 판매현황·순위·통계(01b-04·05·07)도 같은 질문이 걸린다 — K10 을 넓힐지, 새 K 로 둘지.
- **Q-3** 01b-11 은 서버 입구를 정상 장부(01b-17)와 함께 쓰므로 화면·메뉴만 닫는 비노출을 제안했다. 판정식 「비노출 = 서버까지」의 예외로 볼지 판정 필요.
