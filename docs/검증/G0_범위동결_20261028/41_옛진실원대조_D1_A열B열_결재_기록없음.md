## §0 읽는 법

- 🔴 **분류 해석 (한 줄)** — 이 갈래의 「귀속」 = **그 항목이 게이트 표의 *종료 조건·진입 조건·증거* 칸 안에서 처음 「증거로 닫히는」 단계**다. 작업을 *시작*하는 단계가 아니다(준비 병행 = Q6 는 별도). 「정식 이후」 = 베타 범위 밖 제안(원칙 2 동결 · 서버 비활성 여부는 ① 범위표 소관). 「폐기」 = 다른 결재로 대체돼 더 지킬 대상이 없는 것(사유 필수).
- 한 행에 두 단계가 갈리는 항목(예: 봉합 G1 · 측정 G3)은 **둘 다 적고 앞의 것을 「처음 닫히는 자리」**로 본다.
- 근거 칸의 「게이트 G1⑤」 = 부록 게이트 표 G1 종료 조건 ⑤ · 「결재문 §2 K4」 = 사장님 결재문 §2 K4 행.
- 상태 칸은 **진실원 원문 기준**이다(10/15~10/26 정정 누적 포함). 10/27 이후 재측정 0 ⇒ 「상태 미재측정」은 표시만 한다.
- 🔴 공개 레포 — 보안 결함은 P0 번호·조사서 행ID 로만 가리킨다. 경로·줄 번호 새로 적지 않음.

## §6 진실원 항목 수 = 대조 행 수 (명령 두 개)

**명령 1 — 진실원(origin/main) 항목 수**

```bash
J="git show origin/main:docs/베타배포_진실원.md"

$J | sed -n '/^# 🔴 §6/,/^# 🔴 §7/p' | grep -cE '^\| [0-9]+ \|'                        # §6 = 10
```
