## §0 읽는 법

- **3분류 해석(이 조각)** — 「베타 필수」 = 그 행이 베타 사용 경로에 있고 베타 전에 결함을 닫아야 하거나(수선) 결함 없이 그대로 쓴다(「현행 그대로 · 신규 작업 0」 — 11 ERP-A 조각과 같은 읽기 · 13 ERP-B 의 「결함 없음 = 제안 보류」 읽기와 **다르다** ⇒ §4 합본 쟁점) / 「서버 비활성 후 정식 이후」 = 베타에서 안 쓰는 기능 — 서버 입구·권한·상태표시까지 닫고 구현·재판정은 정식 이후 / 「제안 보류」 = 분류가 미결 결재(K)·운영 확인에 달려 이 조각이 고르지 않는 행.
- **7영역 방향**(원문 줄) = 「결제·설치 안내·진행 상태의 불일치 제거」 — 칸에는 그 행이 닿는 축(결제 / 설치 안내 / 진행 상태 / 방향 밖=가입 접수·본사 승인 바탕)만 적는다.
- **판정식**(§1) — ⓐ 베타 사용·외부 노출 경로의 출하 차단 결함 5종(업무 중단 · 원장/재고·데이터 불일치 · 손실 · 권한 침범 · 법적 오인) · ⓑ 대표·승인된 실측으로 업무 불능이 입증된 누락. 이 영역은 **ⓑ 근거 0**(조사서 §0 ⓐ 사장 확인 0/24 · §A ① 칸 근거 — 사장님 10/20 원문은 「진행 중」이라 판정 아님) ⇒ 아래 「베타 필수」 수선 행은 모두 ⓐ 근거다. 「법적 오인」은 16 랜딩 조각과 같은 폭(외부 노출 문구가 사실·결재와 다르면 해당)으로 읽었다.
- **재현** — 05·보충3 조사서는 새 실측 0. 모든 행의 증거 = 조사서 파일:줄(정적 코드). 이 조각이 다시 연 행은 「재열람」으로 표시.
- **코드 재열람**(§11-2) — 분류가 「서버에서 실행 가능한 경로인가」에 달린 행(A-9 · A-22)과 결함 실재가 비어 있던 행(A-14 · A-20)만 다시 열었다. 🔴 공개 레포 — 보안 결함은 새 경로·줄 번호 없이 조사서 행ID·S번호·P0 번호로만 가리킨다.
- **G0-S 소관** = 작G0S (A) 익명 결제확인 입구(P0-2) · (B) 가입이 일으키는 DNS 삭제(P0-3) — 분류하지 않는다.
