## §0 읽는 법

- **3분류 해석(이 조각)** — **베타 필수** = 베타에 남기는 행(그 행에 판정식 ⓐ 결함이 있으면 그 결함 수선만 동결 예외 · 새 기능 0) / **서버 비활성 후 정식 이후** = 베타 동안 화면·서버 입구·상태표시까지 닫는 행 / **제안 보류** = 분류가 미결 K 하나에 달려 갈래가 정할 수 없는 행.
- **7영역 방향**(모바일 줄 원문) = 「조회·기존 구현 기능의 안정화 중심, 범위 확대 보류」(`docs/운영기록/20261027_오더접수_베타로드맵G0G5_GPT하브루타_출시일재정의.md:61`) — 칸에는 그 행이 닿는 축(조회 / 안정화 / 범위 확대=보류 대상 / 방향 밖=폐기 경로)만 적는다.
- **판정식**(§1) — ⓐ 베타 사용·외부 노출 경로의 출하 차단 결함 5종(업무 중단 · 원장/재고·데이터 불일치 · 손실 · 권한 침범 · 법적 오인) · ⓑ 대표·승인된 실측으로 업무 불능이 입증된 누락. 모바일 11행은 **ⓑ 근거 0**(07 §0 ⓐ 사장 확인 0/11 · §E) ⇒ 아래 「베타 필수」의 결함 근거는 모두 ⓐ 이다.
- **K6 이 11행 전부를 쥔다** — 종합 §5 K6 「모바일 11화면 — 베타에 넣는다 / 숨긴다」 미결. 이 조각은 오더 방향 원문(조회·안정화 · 확대 보류)에 맞춰 **2~11행 = 넣는다(조회·PDF 그대로) · 1행 = 닫는다** 쪽으로 제안하고, 「숨긴다」가 골라질 때의 갈림을 결재 칸에 적었다.
- 🔴 **2~11행은 서버를 닫을 수 없다** — 보충7 은 10행 모두 「데스크톱과 **같은 메서드·같은 API**」로 읽었다(행마다 보충7 §A ② 칸). ⇒ 모바일을 숨겨도 서버 입구는 데스크톱 몫으로 열려 있고, 폰 접속 자체도 막히지 않는다(반응형 레이아웃 · 07 §A 끝 줄). 판정식 「비노출 = 서버까지」를 2~11행에는 채울 수 없다 → 「숨긴다」 = 화면만 닫는 예외(사장님 판정 칸 · 13 ERP-B 01b-11 과 같은 쟁점).
- **재현** — 07·보충7 모두 새 실측 0. 모든 행의 증거 = 조사서 파일:줄(정적 코드). 사장님 실측 원문 0/11(07 §E — 5/26 모바일 PDF P0 의 닫힌 원문도 못 찾음).
- **코드 재열람**(§11-2) — 분류가 「서버에서 실행 가능한 경로인가」에 달린 행 = **1행**(모바일 전용 서버 입구). 기준판 확인: `git diff --stat b9f34ccd HEAD -- src` = 0줄(HEAD `9c3af4c9`) ⇒ 조사서 판과 지금 판의 `src` 가 같다. 1행은 HEAD 에서 `git grep` 으로 화면 쪽 호출을 다시 셌다(아래 1행). 2~11행은 「데스크톱 공용 API」 가 분류 근거라 보충7 행 열람으로 인정.
- **행ID** = `07-{조사서 §A 행 번호}`.
