## §0 읽는 법

- **7영역 방향**(랜딩 줄 원문) = 「가입·결제·계정 생성의 정확성과 보안 확보」 — 칸에는 그 행이 방향의 어느 축에 닿는지(가입 / 결제 / 계정 생성 / 보안 / 방향 밖=문구·안내)만 적는다.
- **판정식**(§1) — ⓐ 베타 사용·외부 노출 경로의 출하 차단 결함 5종(업무 중단 · 원장/재고·데이터 불일치 · 손실 · 권한 침범 · 법적 오인) · ⓑ 대표·승인된 실측으로 업무 불능이 입증된 누락. 랜딩 18행은 **ⓑ 근거 0**(조사서 §0 ⓐ 사장 확인 0/18 · §E-2) ⇒ 아래 「베타 필수」는 모두 ⓐ 근거다.
- **재현** — 03 조사서는 새 실측 0(§E-1)이다. 모든 행의 증거 = 조사서 파일:줄(정적 코드). 임원이 다시 열어 본 행만 「임원 정적 재확인」으로 표시.
- **코드 재열람**(§11-2) — 분류가 「서버에서 실행 가능한 경로인가」에 달린 행(P4 · L5 · D1)만 다시 열었다. 나머지는 조사서 행 열람으로 근거를 인정.
- 「베타 필수」의 대상은 **기능을 새로 짓는 것이 아니라 그 행의 결함을 닫는 것**이다(대부분 문구·기록). 판정식상 동결 예외는 결함 수선뿐이다.

## §4 한계 · 반증 여지

1. **ⓑ 근거 0** — 랜딩은 사장님 원문 판정이 한 줄도 없다(조사서 §E-2 검색식 기준). 검색식 밖에 원문이 있으면 「베타 필수」 근거가 ⓐ 에서 ⓑ 로 바뀔 수 있다.
2. **베타 필수 12 중 문구·약관 정정이 다수** — 판정식 ⓐ 「법적 오인」을 넓게 읽은 결과다. 사장님이 ⓐ 를 「업무 중단·데이터 불일치」 쪽으로 좁게 읽으시면 P1 · P2 · P6 · L1 · L2 가 「제안 보류」로 갈 수 있다 — 단 이 행들은 익명 외부 노출 첫 화면·가입 필수 동의라 **베타 첫 등장 게이트**(91 #15 등급 메모)와 직결된다.
3. **P2 · L4 의 대안 분류** — 페이지·선택 칸 비노출을 고르면 「서버 비활성 후 정식 이후」로 옮겨진다(요금 공개 API 처리 포함). 조각은 둘 중 하나를 고르지 않고 사장님 칸에 남긴다.
4. **보안 결함 세부는 새로 적지 않았다** — P4 · D1 재열람 결과는 「익명 입구 실재 · 호출 화면 0」까지만 적었다. 결제 확인 입구(P5)는 G0-S 소관으로 한 줄만 두었고, GPT B1(Toss 익명 확인)은 G0-S [1-V] 가 범위 밖 등재로 둔 백오피스 쪽 입구라 랜딩 18행에 넣지 않았다.
5. 조사서 §E-3 이 안 연 파일(css · 옛 레이아웃 · 검증 컨트롤러 본문 · 메일 본문)은 이 조각도 열지 않았다.
