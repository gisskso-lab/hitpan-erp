## 1. v1 반려 — "봉합한 척"이었다

[3-V] 실시간검증이 v1(`59f29a2`)을 **P0 5건으로 반려**했다. 핵심 2건:

### P0-1 — 가드가 절대 발동하지 않았다

작성된 코드:
```pascal
if ScStopCode = 1060 then  // taskkill 건너뜀
```

실측 반증:
```
$ cmd /C "sc stop NoSuchSvcXyz > f 2>&1"
EXITCODE = 36              ← 1060 이 아니다
파일 본문: "[SC] OpenService 실패 1060: ..."
```

**1060은 종료코드가 아니라 출력 본문의 메시지 텍스트다.**
`= 1060` 은 참이 될 수 없으므로 taskkill 은 봉합 전과 **100% 동일하게 실행**됐다.

⚠️ 작성자가 자기 설계서 §2 에 *"IsPreviouslyInstalled 가드를 쓰면 봉합한 척만 하는 셈"* 이라고
써놓고, **다른 방식으로 똑같은 실수를 저질렀다.** 이 사실 자체를 기록에 남긴다.

### P0-4 — 인과 근거가 무효였다

주장: "7/30 로그가 침묵했으니 hang 이다."

반증:
```
$ git show e55a1e9:installer/HitPan-Universal.iss | grep -c "ExecLogged"
0
```

**그 버전엔 로깅 코드 자체가 없었다.** 침묵은 hang 의 증거가 아니라 기록 코드 부재의 결과다.
⇒ 침묵을 근거로 삼은 추론 전체를 파기.

## 2. v2 봉합 — 실측 종료코드 기반 재작성

측정 사실:

| 명령 | 서비스 없음 | 서비스 있음 |
|---|---|---|
| `sc query cloudflared` | **36** | **0** |
| `sc stop cloudflared` | 36 | 0 (권한부족 5) |
| `taskkill /F /IM ...` | 128(대상없음) | 0 |

봉합 코드(`5a12cad`):
```pascal
ScStopCode := ExecLogged('6-1-svcprobe', 'sc query cloudflared');
...
if ScStopCode <> 0 then      // ← '= 36' 이 아니라 '<> 0'
  Log('...건너뜀 — 서비스 미등록/조회불가라 잔존 프로세스 없음')
else
begin
  Log('...실행 — 서비스 존재 → 잔존 프로세스 정리 필요');
  ExecLogged('6-1-taskkill', 'taskkill /F /IM cloudflared.exe');
end;
```

**`<> 0` 판정 채택 근거**: `= 36` 으로 하면 미지의 실패코드(권한·정책·SCM 이상)에서
가드를 빠져나가 taskkill 이 다시 실행된다. 0 이 아닌 모든 값은 "서비스 존재를 확인하지 못함"
이며, 그때 죽일 프로세스가 있다고 볼 근거가 없다.
⇒ **코드값을 추측하지 않는다**는 원칙. v1 실패의 직접 교정.

적용 지점 2곳: 설치 6-1(`~:1910`) · 제거 경로(`~:2327`).

## 4. 🔴 유보 — 정직하게 남긴다

### 4-1. 진범 확정이 안 됐다

**Windows Sandbox 에서 `taskkill /F /IM` 이 실제로 hang 하는지 재현하지 못했다.**

- 이 PC(일반 Win11)에선 128 로 즉시 반환
- 7/21 작1 원문도 *"실 PC 에도 나는지 불확실"* 이라 유보 상태였다
- 7/30 당시 setup 로그는 Sandbox 휘발성으로 **소실**

⇒ 이 봉합의 성격은 **"taskkill 이 진범이면 막는다"는 조건부 안전장치**다.
   진범이 아니어도 해는 없다(백지 환경엔 죽일 프로세스가 애초에 없다).
   **진범 확정은 오늘 실측 로그가 한다.**

### 4-2. 이 판정은 "안 터진다"는 보증이 아니다

3관문 중 **독립 반증이 미완**이므로, 통과가 아니라 **조건부 통과**로 판정한다.
백지 실측 로그가 들어오기 전까지 이 봉합은 검증 완료가 아니다.

### 4-3. 별건으로 남은 것 (이번 범위 밖 — 실측 결과에 영향 가능)
