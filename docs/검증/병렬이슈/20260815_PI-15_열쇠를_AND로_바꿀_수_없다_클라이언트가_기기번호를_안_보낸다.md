# 병렬이슈 PI-15 — 열쇠를 AND 로 바꿀 수 없다. 클라이언트가 기기번호를 아예 안 보낸다

| 항목 | 내용 |
|---|---|
| 적발 | [3-V] 동시 병렬검증 **2회차** · 보안상무 안철수 · 2026-08-15 |
| 대상 | 명세서 **§17-1** ("PI-08 을 닫았다" 는 주장) |
| 등급 | 🔴 **P0** — 1회차 P0(PI-08) 이 **닫히지 않았다.** 설계는 실행 불가능한 지시를 남겼다 |
| 상태 | ⬜ 미봉합 |

---

## 1. 무엇이 문제인가

§17-1 은 PI-08 을 닫았다고 선언하며 이렇게 적었다.

> ```sql
> WHERE tenant_id = (JWT 클레임)
>   AND device_id = @Id
>   AND auth_key_hash = @Hash
>   AND status = 'approved'
> ```
> ⇒ `VerifyAuthKeyAsync:479` · `DeviceAuthMiddleware:107` 도 같이 고친다

🔴 **그 둘은 `@Id` 를 만들 수 없다.** 두 자리 모두 **기기번호를 전달받는 통로 자체가 없다.**
설계는 "AND 로 고쳐라" 라고만 쓰고, **AND 의 오른쪽 항을 어디서 가져올지를 정하지 않았다.**

이것은 PI-08 이 지적한 것과 **정확히 같은 종류의 결함**이다.
PI-08 은 *"AND 인지 OR 인지 안 정했다"* 였고, §17-1 은 *"AND 라고는 정했는데 값을 어디서 받을지 안 정했다"* 이다.
**한 칸 앞으로 갔을 뿐 여전히 구현자가 임의로 고르게 된다.**

---

## 2. 근거 (실측)

### (1) 미들웨어는 헤더를 **하나만** 받는다

`src/HitPan.API/Middleware/DeviceAuthMiddleware.cs:30`
```csharp
private const string DeviceKeyHeader = "X-HitPan-Device-Key";
```
**이 헤더 하나뿐이다.** `:98` 에서 이 값만 읽는다.
```csharp
var authKey = context.Request.Headers[DeviceKeyHeader].ToString();
```

### (2) 보내는 쪽도 **키 하나만** 싣는다

`src/HitPan.Web/Services/HitPanApiAuthHandler.cs:130-138`
```csharp
private async Task AttachDeviceKeyAsync(HttpRequestMessage request)
{
    var key = await js.InvokeAsync<string?>("hitpanDevice.getAuthKey", ...);
    if (!string.IsNullOrWhiteSpace(key))
        request.Headers.TryAddWithoutValidation(DeviceKeyHeader, key);
}
```
🔴 **기기번호를 싣는 줄이 없다.** 이 메서드가 전부다.

### (3) 기기번호는 브라우저에 **있는데도** 안 보낸다

`src/HitPan.Web/wwwroot/js/device-fingerprint.js:239-241`
```javascript
getDeviceId: function () {
    try { return localStorage.getItem('hitpan_device_id'); }
```
값은 브라우저에 보관돼 있다. **읽어서 실어 보내는 쪽만 없다.**

### (4) `VerifyAuthKeyAsync` 는 시그니처에 기기번호가 없다

`src/HitPan.Infrastructure/Services/TenantDeviceService.cs:478`
```csharp
public async Task<string?> VerifyAuthKeyAsync(string authKey, string tenantId, CancellationToken ct = default)
```
🔴 매개변수가 **키와 테넌트 둘뿐**이다. 게다가 이 메서드의 **존재 이유가 "키로 기기번호를 찾아내는 것"** 이다
(`:485` — `SELECT device_id ...`). 기기번호를 입력으로 받으면 **메서드가 할 일이 없어진다.**
⇒ §17-1 의 지시는 이 메서드에 대해서는 **의미가 성립하지 않는다.** 설계가 이 자리를 안 보고 썼다.

## 3. 터지면 무슨 일이 나나

구현자가 이 지시를 받으면 셋 중 하나를 **임의로** 고른다.

| 구현자의 선택 | 결과 |
|---|---|
| ① 헤더를 추가하지 않고 **SQL 만** AND 로 바꾼다 | `@Id` 가 null ⇒ **조건이 항상 거짓** ⇒ 🔴 **모든 승인 기기가 403. 전 고객 업무 중단** |
| ② 그냥 못 고치고 **키만 보는 현행 유지** | PI-08 이 **그대로 살아 있다.** 요금 누수 미봉합인데 "닫혔다" 고 기록된다 |
| ③ 헤더를 추가하되 **기존 기기 호환을 안 본다** | 아래 (4) 참조 — 이미 쓰고 있는 기기가 막힌다 |

### 🔴 (4) 그리고 ③ 을 제대로 해도 **기존 승인 기기가 막힌다**

지시 프롬프트가 물은 것 — *"인증키만 갖고 device_id 를 아직 못 받은 기기가 있는가"* — 의 답은 **있다.**

`hitpan_device_id` 는 `setDeviceId` 로 저장되는데, 이 값은 **로그인 응답의 `DeviceId` 를 받아야 채워진다.**
그런데 `AuthController.cs:101-105` 는 `allowed=false` 면 **`Unauthorized` 를 반환하고 `response.DeviceId` 를 채우지 않는다.**

```csharp
if (!allowed)
{
    return Unauthorized(new { message = reason });   // ← DeviceId 를 못 받는다
}
response.DeviceId = deviceId;                        // ← 여기까지 와야 채워진다
```

⇒ **한도초과·폐기 상태를 한 번이라도 겪은 기기**, 그리고 **사생활 보호 모드·localStorage 초기화를 겪은 기기**는
**인증키는 있는데 기기번호가 없다.** AND 로 바꾸면 이들이 **전부 403** 이 된다.

⚠️ 더 나쁜 것: 1차 작지서(작3)는 §14 의 401 제거를 **2차로 미뤘다.**
즉 **401 이 살아 있는 채로** 열쇠만 AND 가 되면 빠져나올 길이 좁아진다.

## 4. 어떻게 고치나

**설계에 다음 3가지를 명시한 뒤에** 구현에 넘긴다.

1. **기기번호를 실어 보내는 통로를 먼저 만든다** — 헤더 이름을 설계가 확정한다
   (예: `X-HitPan-Device-Id`). `HitPanApiAuthHandler.AttachDeviceKeyAsync` 에 **함께** 싣는다.
   🔴 **헤더 추가가 SQL 변경보다 반드시 먼저 배포돼야 한다.** 순서가 뒤집히면 전 고객이 막힌다.
2. **기기번호가 없는 요청의 처리를 정한다.**
   - 권고: **키만 맞으면 통과시키되, 그 요청에 대해 기기번호를 응답으로 내려 보관시킨다**(자가 치유).
   - AND 강제는 **기기번호 보유율이 실측으로 확인된 뒤**에 켠다.
3. **`VerifyAuthKeyAsync` 는 AND 대상이 아니다.** 이 메서드는 "키로 기기를 찾는" 자리라 구조가 다르다.
   PI-08 이 지적한 요금 누수는 **미들웨어(문 열기)가 아니라 이 조회(줄 붙이기)** 에서 난다 —
   여기는 **AND 가 아니라 "키가 여러 줄에 걸리면 거부"** 로 막아야 한다(`LIMIT 1` 제거 + 2줄 이상이면 null).

⚠️ **이 건은 2차(작4) 것이라 1차에서는 손대지 않는다** — 그것이 옳다.
다만 **명세서가 "P0 반영 완료" 라고 기록한 것은 사실이 아니다.** 그 표시를 정정해야 한다.
"닫혔다" 고 적힌 채로 넘어가면 **2차에서 아무도 이 자리를 다시 안 본다.**

---

## 5. 판정

🔴 **PI-08 은 닫히지 않았다. "AND 로 한다" 는 방향만 정해졌고, 실행 가능한 설계가 되지 않았다.**
§17-1 을 **미결(⚠️)** 로 되돌리고, 위 3가지를 채운 뒤 2차 작지서에 넣는다.
