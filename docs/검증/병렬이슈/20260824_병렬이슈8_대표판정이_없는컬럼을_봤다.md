| 항목 | 값 |
|---|---|
| 적발 | **[3-V] 동시검증** · 2026-08-24 |

| 등급 | 🔴 **P0** — 잡히지 않았으면 **런타임 500** |
| 상태 | ✅ **봉합 완료** (같은 세션 내) |

---

## 무엇이 잘못됐나

`ApprovalService.IsOwnerEmployeeAsync` — 「모든 결재」에서 **대표인지 가리는 쿼리**가
`employees` 표의 PK 를 **`e.emp_id`** 로 적었다. 실제 컬럼명은 **`employee_id`** 다.

```sql
-- 🔴 짤 때
WHERE e.tenant_id = @TenantId AND e.emp_id = @EmployeeId

-- ✅ 봉합
WHERE e.tenant_id = @TenantId AND e.employee_id = @EmployeeId
```

---

## 🔴 왜 빌드가 못 잡았나

**SQL 은 문자열이다.** C# 컴파일러는 그 안을 보지 않는다.
빌드 **errors 0 + warnings 0** 이 그대로 나왔다 —
헌법 #19 를 통과했는데도 **실행하면 죽는 코드**였다.

> 🔴 **빌드 0/0 은 검증이 아니다.** 이 건이 그 산 증거다.

## 어떻게 잡혔나

[3-V] 가 **쿼리를 실제 DB 에 돌려봤다**(헌법 #13 — 새 SQL 작성 전 DESCRIBE 의무).

```
DESCRIBE employees;
  → employee_id  varchar(36)  PRI     ← emp_id 가 아니다
```

⚠️ 코드리뷰로는 못 잡는다. `emp_id` 는 **그럴듯한 이름**이라 읽어서는 안 틀려 보인다.
**표에 물어봐야** 갈린다.

---

## 터졌으면 무슨 일이 났나

「모든 결재」를 고르는 **순간** 500 이 난다.
그런데 필터1 의 나머지 4개(대기·완료·반려·내가보낸)는 이 함수를 **안 부른다**(`scope == "all"` 일 때만 탄다).

⇒ **다섯 중 하나만 죽는다.** 대충 눌러보면 멀쩡해 보이고,
「모든 결재」를 누른 사람에게만 터진다. 가장 늦게 발견되는 형태다.

## 교훈

| | |
|---|---|
| 🔴 | **빌드 0/0 이 SQL 을 보증하지 않는다** — 문자열은 컴파일 대상이 아니다 |
| 🔴 | **새 SQL 은 DB 에 돌려본다**(#13) — DESCRIBE 로 컬럼을 확인한다 |
| 🔴 | **기존 코드가 쓰는 이름을 grep 한다** — `EmployeeService` 는 5곳 전부 `employee_id` 였다 |
| ⚠️ | **갈래가 나뉘는 코드는 갈래마다 재라** — 5개 중 1개만 죽는 결함은 눈으로 안 보인다 |
