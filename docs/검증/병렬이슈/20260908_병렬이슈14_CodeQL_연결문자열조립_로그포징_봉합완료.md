## 1. critical — `MdbReconciliationService.OpenMdb` 연결문자열 (`:894`)

```csharp
// 🔴 짤 때 — 경로·비번을 string.Format 으로 이었다
"Provider=…;Data Source={0};Jet OLEDB:Database Password={1};Mode=Read;"
// ✅ 봉합 — OleDbConnectionStringBuilder 가 값을 따옴표로 감싼다
var b = new OleDbConnectionStringBuilder { Provider = provider, DataSource = mdbPath };
b["Mode"] = "Read"; if (!string.IsNullOrEmpty(password)) b["Jet OLEDB:Database Password"] = password;
```

**왜 위험한가**: `folderPath`·`mdbPassword` 는 요청 파라미터다. 비번 칸에 `x;Mode=ReadWrite` 를 넣으면 포맷 조립은 그대로 키가 되어 **읽기 전용 약속이 깨진다**. 경로 쪽은 `ResolveMdbPaths` 가 절대경로·`..` 차단·존재 확인·고정 파일명으로 이미 좁혀 뒀지만, 문자열에 `;` 가 들어가면 같은 문제다.
**같은 모양이 5월 코드에도 있다** — `MdbMigrationService.OpenOleDb`(`:55` 템플릿). CodeQL 은 "이번 PR 에서 바뀐 코드" 만 새 경고로 세기 때문에 옛것은 안 잡혔다 ⇒ **작22 항목**(같은 빌더로 통일).

## 2. medium ×8 — `MigrationController.ReconcileLegacyMdb` 로그 (`:150~189`)

`_logger.LogWarning(ex, "[Reconcile] … folder={Folder}", folderPath)` — 사용자가 친 경로에 개행을 섞으면 로그에 가짜 줄이 생긴다.
봉합: `ForLog()`(줄바꿈·탭 제거 + Trim) 로 감싸서 8곳. Preview(5월)의 같은 로그 8곳은 옛 코드라 이번 경고 밖 — 작22.

## 3. 왜 [3-V]·[4] 가 못 잡았나

- [3-V] 는 **#2 tenant·#5 PII·#15 빈 catch·금지어** 를 grep 했고, **연결문자열 조립 방식**은 보지 않았다. 5월 코드와 같은 모양이라 "기존 패턴 준수" 로 읽혔다.
- [4] 도 (g) 에서 같은 세 조항만 봤다.
- ⇒ **보안 체크리스트에 두 줄 추가**: ①사용자 입력이 들어가는 연결문자열·경로·명령은 **빌더/화이트리스트**로 ②사용자 입력을 로그에 넣을 땐 개행 제거.
