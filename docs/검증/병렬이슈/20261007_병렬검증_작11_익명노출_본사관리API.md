### 이슈 3 · 🟡P2 — 게이트 `G_W11_5` 는 `[Authorize]` **단독**을 합격으로 센다 ⇒ 2026-08-02 사고 모양을 게이트가 못 잡는다 · 미봉합

- 근거: `BackofficeAnonymousAdminApiGateTests.cs:150-153`
  `var classAuth = t.GetCustomAttributes().Any(a => a is IAuthorizeData);` — **정책·권한키를 따지지 않는다.**
  `[Authorize]` 만 있으면 적발 목록에 오르지 않는다.
- 대리점 JWT 가 본사 관리 API 를 통과하는지는 **봉합한 4라우트에 대해서만**(`G_W11_2`) 검사한다.
  따라서 새 관리 컨트롤러가 `[Authorize]` 만 달고 등장하면 **게이트는 초록인 채 대리점에 열린다.**
- 이게 「게이트가 통과하면서도 봉합이 뚫리는 조합」이다: ①새 `api/admin/...` 컨트롤러 ②`[Authorize]` 단독
  ③`[BoPermission]` 없음 ⇒ `G_W11_1`(토큰없음 401) 통과 · `G_W11_5` 통과 · 대리점 토큰 200.
- 보강 처방(최소): `G_W11_5` 가 `[Authorize(Policy=...)]`·`[BoPermission]`·`[Authorize(Roles=...)]` 중 하나를
  요구하도록 올리고, 「`[Authorize]` 단독인 관리 컨트롤러」는 **사유표 등재 필수**로 한다.

### 이슈 4 · 🟡P2 — 게이트가 실제 호스트를 띄우면서 `WebhookDispatcher` 가 **즉시 1회 틱** · 로컬 실DB·외부 웹훅을 건드릴 수 있다 · 머지 전 교정 권고

- 근거: `src/HitPan.Backoffice.API/Services/WebhookDispatcher.cs:45-58`
  `ExecuteAsync` 가 루프 **첫 바퀴에서 지연 없이** `TickAsync` 를 부른다(`await Task.Delay(1분)` 은 틱 **뒤**에 있다).
  `TickAsync` 는 `status='pending'` 행을 읽어 **실제 HTTP POST** 를 보내고 `webhook_outbox` 를 갱신한다.

  스키마 적용은 껐지만 **연결문자열을 덮지 않았다.** 따라서 `appsettings.json:12-14` 의

  ⇒ 그 DB 가 있는 PC(개발PC·사장님 PC)에서 시험을 돌리면 **시험이 실제 웹훅을 외부로 발송하고 DB 행을 바꾼다.**

  시험 순서에 따라 결과가 달라지는 길을 열어 둔 것이다.
- 처방: Factory 의 `ConfigureWebHost` 에서
  `builder.UseSetting("ConnectionStrings:BackofficeDb", "...존재하지 않는 DB...")` 를 추가한다.
  (내 프로브가 정확히 그렇게 했고 17건과 같은 판정이 나온다 — 401·403 은 컨트롤러 앞에서 갈리므로 판정에 영향 0.)

  DB 접속·조회 자체를 하지 않는 것이 #39 에 더 안전하다고 판단했다. 코드 경로는 사실, 발동 여부는 미확인.
