## §2 V-1 — 게이트가 파일을 만든다 🟡

**측정**
- 만드는 자리 = `MigrationGateDb.RunnerSqlDir()` = `AppContext.BaseDirectory/Migrations/SQL` (= `src/HitPan.Tests/bin/.../Migrations/SQL`). **레포 밖**이다.
- 레포 자리 `RepoSqlDir()` 는 **읽기만** 한다(`File.Copy` 의 원본).
- `finally` 에서 `CleanRunnerSqlDir()` 가 폴더째 지운다.
- 🔴 실측: 음성 대조군 전건 뒤 `git status --short src/HitPan.API/Migrations/SQL/` = **0줄**.

**🟡 남은 위험**: 시험이 **프로세스째 죽으면** `finally` 가 안 돈다 ⇒ `bin` 에 깨진 파일이 남고, 그 뒤 `Db3960` 이 `MaterializeRepoSql()` 로 폴더를 **지우고 다시 만들어** 자동 복구된다(그래서 치명적이지 않다). 🔴 **`bin` 은 게시물 경로가 아니다** — 출하물은 `HitPan.API.csproj:62` 가 레포 폴더에서 복사한다. ⇒ 고객 도달 **0**.

## §3 V-2 — DB 를 DROP 한다 🔴 → 🟢

`MigrationGateDb.ReadyAsync` 가 `DROP DATABASE IF EXISTS` 를 돈다. **#39(운영은 읽기만)의 정면**이다.

**봉합 — `ErpCsGateDb` 와 같은 모양**
- 환경변수로 받은 이름에 `test` 또는 `gate` 가 **없으면 거부**하고 무작위 이름으로 돈다.
- 🔴 실측으로 뒷받침: 이 PC 의 `hitpan` 계정은 `hitpan_*` 이름을 **1044 로 거부**당한다 ⇒ 실수로 실물 이름을 줘도 **서버가 막는다**.
- 🔴 실물 ERP 스키마(`hitpan_erp*`)는 이 PC 에 **0건**(`SHOW DATABASES` 실측).

🔴 **그래도 이 가드는 「사람이 환경변수를 틀리게 주는 것」만 막는다.** CI 는 root 로 돌고 격리 DB 를 만들었다 지운다 — 거기서 운영 이름을 주면 지워진다. 그 위험은 이 차수가 **새로 만든 것이 아니다**(선례 전건 동일). 올려 둔다.

## §4 V-3 — `schema_migrations` 를 지우고 쓴다 🔴 → 🟢

G-W13-1·2·3·4·5 가 `DELETE FROM schema_migrations` 와 `INSERT … ON DUPLICATE KEY UPDATE success = 1` 을 돈다. 적용 이력을 조작하는 일이라 실물 DB 에서 돌면 **고객 스키마가 낡는다**.

**봉합**: 전부 §3 의 격리 DB 안에서만 돈다. 실물 연결 문자열을 쓰는 길이 **없다**(`DbConnString()` 이 `_dbName` 을 붙인다 · `_dbName` 은 §3 가드를 지난 값).

🔴 **그리고 `ShapeAsync` 가 `schema_migrations` 를 모양 비교에서 제외한다** — 이 게이트가 그 표의 **행을 직접 지우며** 재므로, 자기 손길을 모양 차이로 되읽으면 거짓 빨강이 된다. 칸 정의는 안 건드린다.
