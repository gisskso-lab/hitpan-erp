> **담당**: 보안상무 안철수 (사장님 지정 2026-07-28)  ([폴더담당 표](../../POLICY_폴더담당.md))

## 이 폴더가 따로 있는 이유 (사장님 지시)

병렬검증에서 나온 지적을 **최종 작업리뷰서에만 적으면 묻힌다.**
그래서 **별도로 관리**한다 — 언제 무엇이 적발됐고 봉합됐는지 추적 가능하게.

```
[3] 개발팀 작업(PM 지휘)  ⟷  [3-V] 안철수 상무 병렬검증
     📄 개발/개발명세서            📄 여기 (이슈 1건 = 파일 1개)
                                        ↓
[4] 검증팀이 §6에서 "봉합됐나" 확인 → 미봉합 있으면 반려
```

## 파일명

```
{YYYYMMDD}_병렬이슈_{순번}_{한줄주제}_{상태}.md
예: 20260728_병렬이슈_01_시크릿게이트_appsettings유출_봉합완료.md
```

## 상태 표기

| 상태 | 뜻 |
|---|---|
| 🔴미봉합 | 적발됐고 아직 안 고쳐짐 → **[4] 검증에서 반려 사유** |
| 🟡봉합중 | 개발팀이 작업 중 |
| ✅봉합완료 | 고쳐졌고 재확인됨 |
| ⬛보류 | 사장님 결재로 이번 범위 밖 처리 |

## 이슈 문서에 남길 것

| 항목 | 내용 |
|---|---|
| 적발 시점 | 작업 어느 단계에서 나왔나 |
| 무엇이 | 코드·설정·문서 어디의 무슨 문제 |
| 왜 위험한가 | 등급(P0/P1/P2)과 근거 |
| 재현 방법 | 실제 명령·조건 |
| 봉합 | 무엇을 어떻게 고쳤나 + 커밋 해시 |
| 재확인 | 봉합 후 증상이 실제로 사라졌나 (실측) |

> **참조식**: 개발명세서·작업지시서 내용을 옮기지 않는다. 주소만.

## 이 폴더의 문서는 지우지 않는다

봉합이 끝나도 **삭제하지 않는다.** 상태만 ✅봉합완료로 바꾼다.
같은 사고가 반복되는지 추적하는 게 이 기록의 값어치다. (헌법 #42 · 문서 보관·관리 원칙)
