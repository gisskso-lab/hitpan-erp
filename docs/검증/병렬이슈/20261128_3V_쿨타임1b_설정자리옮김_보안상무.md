## 참고 (등급 없음 · 이번 고침이 만든 것 아님)

1. 화면 `[Authorize(Roles=…)]` 은 `employees.role` 에서 온 `role` 클레임(`AuthService.cs:1362-1377`)이라 「부모계정 = account_type」 과 같은 축이 아님 — 지시서의 「세 겹」 중 진짜 부모 거름은 서버 정책 + Sidebar 둘. 막는 본체는 서버라 지금 구멍은 아님.
2. 자식이 직접 주소 → `/login` 으로 튐(설명 없음) — 기존 설정관리 화면 전부 같은 꼴 · 쉬움(#25) 별건.
3. `ResolveCooltimeAsync` 의 지금 값 읽기는 트랜잭션 밖(잠금 없음) — 동시 저장 2건이면 마지막이 이김(잃는 갱신). 세 칸을 늘 함께 쓰므로 「켬인데 시각 빔」 불변은 깨지지 않음. 기존 루트 길과 같음.
4. 행 없는 회사에 첫 저장 2건이 동시면 `SELECT … FOR UPDATE`(없는 키 = 틈 잠금) 두 개 + INSERT 로 교착 → 한쪽 500 · 값은 한쪽 것으로 일관. 대표 한 사람이 쓰는 화면이라 확률 낮음 · 기존 루트 길과 같음.
5. 설계 §6 리스크 「CT 가 새 주소 404」 — API 호스트는 모르는 GET 에 화면 첫 장 200 HTML(M-5a)을 주므로 라우트 오타는 404 가 아니라 JSON 해석 실패로 드러남. G-P1 이 같은 글자를 단언하므로 실해 없음.
