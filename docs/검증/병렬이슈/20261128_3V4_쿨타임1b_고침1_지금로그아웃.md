## [3-V] 보안상무 안철수 — 반증

### 확인 1. 손 로그아웃 길이 서버 접속을 실제로 끝내나 (PI-4) — 새 구멍 없음
- 길: `CooltimePrompt.razor:272` `UseManualLogout` → `:369 ManualLogoutAsync` → `:379 AuthService.LogoutAsync()` → `Services/AuthService.cs` `POST api/auth/logout`(본문 `new { }`) → API `AuthController.cs:353` `[Authorize] Logout`.
- API 처리기: JWT `sid` 기준으로 `refresh_tokens` 폐기(`user_id` 동반) + `user_sessions` 1행 삭제. 실패 = 500(200 금지) → 화면은 `LogoutGate.IsServerLogoutDone` 로 미완료 판정 → 로그인 화면에 「로그아웃 미완료」 표. `TermsConsentMiddleware` 우회 목록에 `/api/auth/logout` 있음.
- ended:false 가 나오는 서버 자리(`CooltimeController.cs:60~` · `CooltimeEngine` API 끝내기 조건 `asked_at > 지금-65초 AND user_id = JWT`): ⓐ 물음 없음(끔 · 다른 탭 계속) ⓑ 물음 65초 만료 ⓒ 행이 이미 지워짐 ⓓ `sid` 빈 옛 토큰. ⓐⓓ = 세션 살아 있음 → auth/logout 정상 통과. ⓑ = 살아 있음(서버 작업 ① 이 아직 안 돎) → 통과. ⓒ = 세션 확인 미들웨어 401(→ 완료로 봄) 또는 캐시 창 안이면 통과 후 0행 삭제 200. **409 · 401 로 거절돼 세션이 남는 새 길 없음.** 409 를 내는 미들웨어는 `IdempotencyMiddleware`(키 머리글 있을 때만) 뿐 — 로그아웃 요청엔 해당 없음.
- 결론: 남은 세션으로 다른 PC 8시간 막힘(PI-4)은 **5xx 실패 때만**이고, 그 경우도 머리글 [로그아웃] 과 같은 「미완료」 안내 길. 쿨타임이 꺼진 상태라 서버 작업 ① 이 대신 끝내 주지 않는 점만 옛 흐름(팝업 닫고 계속 로그인)과 다르다 → **P3-4** 로 기록.

### 확인 2. 퇴근 기록 — 이중 기록 없음 · 뜻이 바뀌는 좁은 창 1
- 손 로그아웃 퇴근 = `HrService.CheckOutAsync` : `work_date = 오늘 AND check_out IS NULL` 1행만, UPDATE 에도 `AND check_out IS NULL`(§271 F6). 쿨타임 「끝냄」 이 먼저 정시 퇴근을 썼으면 0행 → 예외 → `AuthController` 가 경고 로그만(로그아웃은 진행). **이중 기록 불가.**
- 다른 탭 [계속] 직후 버튼: 서버는 [계속] 으로 물음 칸을 비움 → 버튼의 쿨타임 logout = ended:false → 손 로그아웃 → 퇴근 = 지금(사람이 고른 로그아웃). 마지막 행동(로그아웃)이 이김 — §285 결정 뜻과 맞음. 다른 탭도 같은 `sid` 라 함께 끊긴다(확인 4).
- 카운트다운 0초와 버튼이 겹친 경우: 0초 루프는 `_busy` 를 보지 않아(옛 그대로) 쿨타임 logout 이 두 번 갈 수 있다. 한쪽이 Ended → `EndLocallyAsync` 가 `_ending=true` 를 먼저 세우면 `ManualLogoutAsync:371` 이 바로 빠짐. 버튼 응답(ended:false)이 먼저 처리되면 손 로그아웃의 `CheckOutAsync` 가 이미 쓰인 정시 퇴근을 못 덮음(0행). 이중 기록 없음.
- **P3-1** 좁은 창: ⓑ 물음 65초 만료 ~ 서버 작업 ①(15초 주기) 사이에 버튼이 닿으면, 옛 흐름은 다시 확인 → 「물음 만료 = 끝남」 → 저장소만 비움 → 서버 작업 ① 이 **정시 퇴근 · `check_out_source='cooltime'`** 을 썼다. 새 흐름은 손 로그아웃이 먼저 세션을 지우고 **퇴근 = 누른 시각 · 출처 NULL(손)** 로 남고, 서버 작업 ① 은 지울 행이 없어 아무것도 안 함. 화면 마감 = 받은 순간 + 서버가 준 남은 초라 푸시 지연이 5초를 넘을 때만 열리는 창(빈도 낮음). 판정 함수가 `Recheck` 전부(ⓐ~ⓓ)를 손 로그아웃으로 보내는데 근거 문구는 ⓐ(끔 · 다른 탭 계속)만 말함 → 의도된 범위인지 PM 기록 한 줄 필요.
- **P3-2** 자정 넘김: 손 로그아웃 퇴근은 `work_date = 오늘` 만 찾는다(쿨타임 퇴근은 출근일 행 24시간 이내를 찾음). 자정 넘어 쿨타임이 꺼진 채 버튼을 누르면 퇴근이 안 남는다. 머리글 [로그아웃] 과 같은 옛 한계 — 이번 고침이 새로 만든 것은 아님. 기록만.

## [4] 검증팀장 데이비드 박 — 리뷰

### 회귀(다른 계기) — 바뀌지 않음
- 판정 `UseManualLogout(trigger, outcome) = outcome == Recheck && trigger == "button"(Ordinal)` (`CooltimeScreenRules.cs:178`). 0초(`countdown`) + Recheck → 옛 `RecheckAsync` 그대로. 401 · 2xx+ended:true → `EndLocallyAsync` 그대로. 5xx · 연결 실패(null) → Failed → `EndLocallyAsync` 그대로. 503 → 1초 뒤 한 번 더(옛 그대로).
- 서버로 가는 `trigger` 문자열: 상수 값이 옛 리터럴과 같음(`"button"` · `"countdown"`) → 서버 `CooltimeEndCause` 판정 변화 없음.
- 쿨타임 [계속] 길(`ContinueAsync`) 무변경.

### P2-1 머리 주석의 🔴 규칙 줄이 새 동작과 정면 반대(#1 ⬛ 관례 누락)
- 파일:줄 `src/HitPan.Web/Components/Common/CooltimePrompt.razor:10~11`
  > 🔴 끝낼 때 손 로그아웃(`AuthService.LogoutAsync` → api/auth/logout)을 부르지 않는다 — 그 길은 「그 순간 = 퇴근」 을 적는다 …
- 새 코드는 바로 그 `AuthService.LogoutAsync` 를 부른다(`:379`). 위 7~9 줄은 11/27 고침 때 🆕 덧줄로 바꿨는데 이번엔 덧줄이 없다. 다음 사람이 이 🔴 줄을 규칙으로 읽고 고침 1을 「되돌리는」 길이 열린다(같은 파일 안에서 규칙 ↔ 코드 모순).

### P3-5 배선 시험이 「계기 자리」 를 바꿔 끼워도 통과
- `src/HitPan.Tests/Integrity/CooltimeRuleGateTests.cs` `고침1_배선` : `Contains("FinishWithLogoutAsync(CooltimeScreenRules.TriggerButton)")` · `Contains("…TriggerCountdown)")` 를 **파일 전체**에서만 찾는다. 0초 루프(`:184`)와 `LogoutNowAsync`(`:256`)의 상수를 서로 바꿔 끼우면(= 0초가 손 로그아웃, 버튼이 다시 확인 — 고침 뜻의 정반대 + §273 V1 탭 2개 보호 깨짐) 순수 함수 시험 · 배선 시험 모두 통과(정적 추론 · 변이 실행은 안 함).
- 또 `await AuthService.LogoutAsync();` 가 파일 어디든 있으면 통과 — `UseManualLogout` 분기 안에서 `ManualLogoutAsync()` 를 부르고 `return` 하는지는 안 잰다(분기 몸을 `RecheckAsync()` 로 바꿔도 통과).
- 고칠 방향: `LogoutNowAsync` 메서드 몸 · `_secondsLeft <= 0` 블록 몸을 잘라 각각 맞는 상수를 단언 / `UseManualLogout(trigger, outcome))` 다음 `{ … }` 안에 `await ManualLogoutAsync();` 와 `return;` 단언. 변이 2건(상수 맞바꿈 · 분기 몸 교체) FAIL 확인.
- `Live()`(주석 `//` 줄 빼기) 자체는 이 파일에선 맞게 동작: 낡은 줄이 모두 `//` 로 시작해 `DoesNotContain("FinishWithLogoutAsync(\"button\")")` 가 살아 있는 줄만 본다. 다만 Razor `@* … *@` 블록 주석은 못 뺀다 — 지금 머리 주석엔 단언 문자열이 없어 무해(기록만).

### P3-6 계기 상수 ↔ 서버 비교 문자열을 잇는 시험 없음
- 화면 `TriggerCountdown = "countdown"`(`CooltimeScreenRules.cs:166`) 과 서버 `CooltimeController` 의 `string.Equals(request?.Trigger, "countdown", OrdinalIgnoreCase)` 가 따로 적혀 있다. 상수를 바꾸면 서버는 0초를 「사람이 고름(UserChoice)」 으로 조용히 분류한다. 이번 고침으로 상수가 판정의 열쇠가 됐으니 짝 시험(상수 == 서버 문자열 리터럴 · 또는 서버 계약 파일의 상수 공유) 권장.

### P3-4 손 로그아웃 요청이 오래 걸리면 팝업이 멈춘 채 남음
- `ManualLogoutAsync` 는 `StopCountdown()`(`:372`) 뒤에 `AuthService.LogoutAsync()` 를 기다린다. 요청이 늘어지면(HttpClient 기본 100초) 팝업은 카운트다운도 꺼진 채 「누른 상태」 로 남고 0초 안전판도 없다. 옛 흐름(`EndLocallyAsync`)은 서버를 기다리지 않고 바로 로그인 화면이었다. 머리글 [로그아웃] 과 같은 성질이지만, 쿨타임 꺼짐 상태에선 서버 작업 ① 이 대신 끝내 주지도 않는다(확인 1).
- 고칠 방향(선택): 손 로그아웃 요청에 짧은 시간 제한(예: `CancellationTokenSource` 10~15초) → 넘으면 미완료 표 남기고 `/login`. 이번 차수 필수 아님.
