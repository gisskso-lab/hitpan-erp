- **사실 3 (선례)**: 같은 나무 `src/HitPan.Application/Services/BackupService.cs:815-870` `EnsureRestrictedSystemFolder` 가 바로 이 꼴(C-12 ⓐ 소유자 · ⓑ 그룹 권한 줄 거부 · ⓒ 재분석 지점 거부 · 보호 ACL 로 만들기)을 이미 막아 두었고 `public static` 으로 열려 있다. 새 기록기는 이것을 쓰지 않는다.
- **재현 꼴** (일반 Windows 계정 · 관리자 아님):
  1. 첫 복원 · 첫 비번 되찾기 전에 `mkdir C:\ProgramData\HitPan\audit` → 그 사용자가 소유자.
  2. (가) 그대로 두면 → 언제든 `restore-audit.log` 지우기 · 통째 바꿔치기(사슬 다시 만들기) · 미리 꾸민 파일 심기(`OpenOrCreate` 가 남의 파일을 그대로 열어 이어 씀).
     (나) `audit` 를 비우고 교차점(junction)으로 바꿔 `\RPC Control` 에 걸고 객체 관리자 심볼릭 링크 `restore-audit.log → C:\임의\경로` → **SYSTEM 프로세스가 임의 경로에 파일을 만들거나 기존 파일 끝에 줄을 덧붙임**(일반 사용자 권한 상승 원재료 · 시스템 파일 끝 오염).

- **고칠 방향(적발만 · 결정은 [3]/[2])**: `audit` 폴더를 `BackupService.EnsureRestrictedSystemFolder` 와 같은 판정으로 만들기(보호 ACL SYSTEM · Administrators · 소유자 검사 · 재분석 지점 거부 · 만든 뒤 다시 검사) + 파일 열기 직전 파일 자신의 재분석 지점 · 소유자 검사. 시험 = 「남이 먼저 만든 폴더 → 거부」 「교차점 폴더 → 거부」 변이 대조.
- **판정**: 🔴 (갈래 0 안에서 닫을 것 · A · C 착수 조건).

### F2 🟡 P2 — 한 PC 5 슬롯이 파일 하나를 같이 씀 + `ReadUnfinishedSwapsAsync(tenantId = null)` 기본값 「모든 회사」 → 다른 회사의 미완 교체를 「정리됨」 으로 닫을 수 있음 (R17 회복 건너뜀)

- **사실**: 설치기는 한 PC 에 사업자 슬롯 1 ~ 5(포트 · DB · 계정 · 폴더 분리)를 둔다(`installer/HitPan-Universal.iss:236` · :1985 「슬롯별 DB·계정·포트·폴더 분리」 · :2990 슬롯마다 API 프로세스). 감사 파일만 슬롯을 가르지 않는다(명세서 §3 「한 PC 한 파일」).
- **재현 꼴**: 슬롯 1(회사 X) 교체 중 끊김 → `SwapStarted(X, op1)` 만 남음 → PC 다시 켬 → 슬롯 2(회사 Y) API 가 먼저 떠 기동 복구에서 `ReadUnfinishedSwapsAsync()`(인자 없음) → op1 을 받음 → 자기 DB(Y) `restore_history` 에 op1 없음 → `RecoveryResolved(op1, rolledback)` 를 씀 → 슬롯 1 이 떠도 op1 은 이미 닫힘 → **회사 X 의 「기록 채움 + 모두 끊기 + 캐시 비움」(설계 §7 R17) 이 안 돈다**. 기동 때는 JWT 가 없어 A 가 넘길 「서버 확정 회사 값」 이 무엇인지 계약이 정하지 않았다.
- **고칠 방향**: `tenantId` 를 필수로(기본값 null 지움 · 「모든 회사」 는 별 이름의 진단용 메서드로) 또는 슬롯별 파일. 작업지시서 §7-3 #13 ④ 「여러 회사 폴더(PM)」 확인 칸과 묶어 판정.
- **판정**: 🟡 (A 착수 전 계약 고정 조건 — §7-3 #5).

### F3 🟡 P2 — `ReadUnfinishedSwapsAsync` 가 지문 틀린 줄 · 사슬 끊긴 줄도 믿는다 → 지문 계산 없이 꾸민 줄 한 줄로 회복을 켜거나 끔

- **자리**: `W:334-336` 은 `Bad(...)` 만 적고 `W:352` 에서 **무조건** `Entries.Add(entry)` · `W:98-106` 은 `FirstBadLine` · `selfHashOk` 를 안 본다.
- **재현 꼴**: 파일 끝에 `v1⇥N⇥시각⇥X⇥u⇥SwapCompleted⇥Succeeded⇥op1⇥⇥(아무 16진 64)⇥(아무 16진 64)` 한 줄을 붙임(SHA 계산 불필요) → `VerifyChainAsync` 는 빨강이지만 `ReadUnfinishedSwapsAsync` 는 op1 을 「끝남」 으로 보고 회복 생략. 반대로 가짜 `SwapStarted` 를 붙이면 다음 기동이 없는 복원을 「정리」 하며 모두 끊기 + `restore_history` 에 가짜 기록 채움.
- **고칠 방향**: 미완 목록은 「처음 틀린 줄 앞까지」 만 쓰거나 사슬 결과를 함께 돌려주고, 사슬 빨강이면 회복 쪽이 닫힘(fail-closed) 판단을 하도록 계약에 적기. (F1 이 닫히면 쓰기 주체가 SYSTEM · 관리자로 줄어 위험이 낮아짐.)

## 3. 조건 (🟡 → 🟢)

1. **F1** — 갈래 0 안에서 보호 폴더 만들기 · 재분석 지점 · 소유자 검사 + 변이 대조 시험(남이 먼저 만든 폴더 · 교차점) → A · C 가 부르기 전.
2. **F2** — `tenantId` 필수화 또는 슬롯별 파일 — 계약 고정(§7-3 #5) 전 결정.
3. **F3 · F4** — A 설계에 「사슬 빨강이면 회복 닫힘」 · 「DB 와 seq · 지문 맞대기」 를 넣거나, 설계 §6 문구를 좁혀 한계를 결재로 올림. `VerifyChainAsync` 「파일 없음」 별도 표시.
4. **F5** — fail-open/closed 를 A · C 설계에 한 줄로(추천 = 둘 다 닫힘).
5. P3(F6 ~ F10) — A · C [3-V] 때 다시 봄 · 막는 조건 아님.

ACL 판정 근거는 **이 PC 상속 ACL 읽기**(개발 PC · `icacls` 읽기만)다 — 고객 PC 실측은 [4](시험 환경 · 이 PC 아님). 기본 `%ProgramData%` ACL 은 Windows 기본값이라 고객 PC 도 같을 공산이 크나 ⚠️ 미실측.
