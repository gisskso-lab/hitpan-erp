## 무엇이 문제인가
- 봉합2 전 S0 는 **보기만** 했다(`Test-UpdateBusy`). 봉합2 후 S0 는 `.rbk` 를 열어 보고(`Test-DirFree :788-794`)·싣고·지운다(`Clear-Leftover :809-834`) — 서비스는 안 멈춘 상태.
- ⓐ **예외 경로** — 스크립트는 `$ErrorActionPreference='Stop'`(`:40`). `Test-DirFree` 의 `Get-ChildItem -Recurse`(`:789`)·문지기 안 `Test-HasCarryData`/`Get-CarryApiDirs`(`:327-349`) 는 try 밖이다(`Clear-Leftover` 의 try 는 finally 뿐 · catch 없음). 하위 폴더 접근 거부·경로 길이·정션 고리(병렬이슈 12) 한 번이면 던진다 ⇒ 바깥 catch(`:1088-1092`)가 `Complete-Swap 'broken' 'revert_failed' 'S0'`.
- ⓑ **끊김 경로** — S0 정리 도중 전원·재부팅·작업 강제 종료 ⇒ 요청서는 `running`/`S0` 로 남고, 30분 뒤 `ClearStale`(`LocalSwapLauncher.cs:183-188`)이 `broken`/`worker_interrupted` 로 적는다(`parts_after` 없음).
- 런처 M4(`JudgeLeftoverRbk`): `.rbk`(반쯤 치운 잔재)가 남아 있고 `last.State == Broken` 이면 — ⓐ는 `parts_after` = 지금 판 그대로, ⓑ는 대체 규칙 `From == api || To == api` 가 **S0 끊김이면 항상 참**(살아 있는 판 = `from`) ⇒ `swap_interrupted`.
- M4 는 `last.Step` 을 보지 않는다. 설계 §15-0 M4 의 뜻은 「S7R — 세 폴더 전부 `to`, `.rbk` = 검증된 옛 판의 유일한 사본」인데, **정지 전 단계(S0~S2)에서 끝난 broken** 도 같은 표로 잡힌다.
- 결과: 아무것도 멈추거나 바꾸지 않았는데 끝 상태는 `broken`(이벤트 로그 Error · 화면 「끝까지 되지 않았다」), 그 뒤 되돌리기·수동 업데이트가 다음 게시판이 올 때까지 `swap_interrupted` 로 막힌다. 봉합2 가 풀려던 「잔재 하나로 두 기능 잠김」(N-1)이 다른 입구로 돌아온다.

## 발생 시나리오
1. 지난 되돌리기가 `success`+`cleanup_pending` 으로 끝남(`web.rbk` 잔재).
2. 다음 날 수동 업데이트 [예] → 일꾼 S0 가 `web.rbk` 를 지우는 몇 초 사이 PC 재부팅(Windows Update 예약 등).
3. 30분 뒤 화면을 열면 `ClearStale` 가 `broken`/`worker_interrupted` 로 적고, M4 대체 규칙이 참 ⇒ 「끝까지 되지 않았습니다」 + 두 기능 잠김. 실제로 바뀐 것은 없다.

## 막는 방향 (한 줄)
S0 정리를 자기 try/catch 로 감싸 실패는 `refused`+`cleanup_pending` 으로 적고, 런처 M4 는 `last.Step` 이 정지 전(S0~S2)이면 적용하지 않는다(대체 규칙 포함).
