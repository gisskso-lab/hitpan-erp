## 2. 확인한 것 (반증 시도 → 못 깸)

1. **#2 테넌트** — 새 API 0(컨트롤러 무변 · `CreateYTemplateAsync` 는 아직 어떤 컨트롤러도 안 부름). 저장 문은 종전대로 `HttpContext.Items["TenantId"]`. 옮기기는 DB 행의 `tenant_id` 로 (회사 · 종)을 순회하고, 그 아래 조회 · 잠금 · UPDATE · INSERT…SELECT · 재사용 후보 조회 **모두** `tenant_id = @TenantId` 조건. 남의 회사 id 로 Y 단추를 불러도 첫 조회에서 `NotFound`. 준비 확인 ①(대상 수)② 키 ③ 적용 결과 표는 회사 조건이 없는데, 셋 다 시스템 판정(요청 값 아님 · 워치독이 `tenant_id` 를 NULL 로 씀)이라 위반 아님.
2. **한 회사 실패가 남을 건드리나** — (회사 · 종)마다 트랜잭션 하나 · 실패 시 그 트랜잭션만 되돌리고 다음으로. EF 트랜잭션 Dispose = 되돌림(UnitOfWork 확인). 취소만 위로 다시 던짐. 다른 회사 행 · 파일 쓰기 0.
3. **그림 경로** — 저장 경로를 `GetFullPath` 뒤 **그 회사 폴더 + 구분자** 접두로 대조(`..` · 다른 회사 폴더 · `abc` vs `abcd` 접두 혼동 · UNC · `\\?\` 모두 「밖」). 회사 값에 파일 이름 금지 글자 · `..` 있으면 「밖」. 파일 · 위 폴더 · 그림 뿌리의 링크(심볼릭 · 정션)면 「밖」. 사본 이름은 서버가 만든 시각 + GUID · 확장자 허용 목록 · `overwrite: false` → 원본 덮어쓰기 0. 대체 데이터 흐름 꼴(`a.png:x`)은 확장자 판정에서 걸러짐. 해시는 SHA-256 · 고정 시간 비교.
4. **SQL** — C# 쪽 전부 매개변수 · 이어 붙이기 0. DB-150 의 `PREPARE` 문자열은 고정 글자 2개뿐(사용자 값 0). DB-150 이 `form_templates` 행을 쓰는 줄 0(감사 기록만). 옛 키는 「새 키 있음 **그리고** 옛 키 있음」 일 때만 지움 · 새 설치 DB 위 재실행에서 없는 키 지우기 0 · 감사 줄은 `NOT EXISTS` 로 회사당 1줄(멱등). 새 표 0 → #17 해당 없음. 출하 DDL 의 계산 칸 정의 · 주석 · 키 이름 · 칸은 마이그와 같다(순서만 P3-2). `schema_migrations` 시드에 DB-150 더함.
5. **1062 사람 말** — 화면 문구는 고정 두 문장(키 이름은 **분기 판단에만** 쓰고 밖으로 안 나감 · SQL · 원문 0 · #23 개발 용어 0). 원문 예외는 서버 로그에만. 만들기 · 고치기 본문이 한 트랜잭션 → 「옛 기본 내림」 만 남고 저장이 실패하는 반쪽 상태 0. 고치기 뒤 다시 읽기(`template_id` 만 조건 · 종전 줄)도 같은 트랜잭션 · 바로 위 UPDATE 가 회사 조건으로 성공한 id 라 남의 행 읽기 0.
