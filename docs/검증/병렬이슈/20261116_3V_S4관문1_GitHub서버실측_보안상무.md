## 지적

### 🟡 Y1. 자격증명 꼴이 JSON 키-값을 못 잡는다 — 자체시험 대조군도 `=` 꼴 하나뿐
- 근거: leak-scan.js:152 `(?:password|pwd|secret|token|api[_-]?key)\s*[=:]` — 키 뒤에 `"` 가 오면 `:` 에 못 닿는다. selftest-leak.js:42 의 사례는 `password=...` 꼴만.
- 재현(합성 값 · 로컬 node): `kindsInText(JSON.stringify({password:"<12자 임의>"}))` → 걸림 0 · `{accessToken:"<12자>"}` → 0 · `{client_secret:"<18자>"}` → 0. 22자 미만이라 긴 토큰 꼴도 안 걸린다.
- 원자료는 거의 전부 JSON/JSONL 이라 이 꼴이 실제로 쓰일 자리를 비워 둔 셈. 지금 생산자(시험 앱 · 콘솔 160자)는 자격증명을 다루지 않아 실해는 낮다. 그러나 게이트가 「잡는다」고 주장하는 꼴을 대조군 없이 둔 것(게이트는 글자가 아니라 동작).
- 권고: 키 뒤 `["']?` 허용 + 자체시험에 JSON 키-값 사례 · 대조군 추가.

### 🟡 Y2. 긴 토큰 꼴이 `+` `/` `=` 에서 끊긴다 — 표준 base64 비밀값이 가림 · 누출 둘 다 통과
- 근거: mask.js:13 `TOKEN_RE = [A-Za-z0-9_-]{22,}` (leak-scan 도 같은 꼴을 가져다 씀 · leak-scan.js:135,178)
- 재현: `Qx7pLm2z9aBcDeF/gHiJkLmNoPqRsT+u=` 꼴(32자 · 중간에 `/` `+`) → 조각 15·15자 → 가림 0 · 누출 0.
- 권고: 문자 집합에 `+/=` 를 넣은 base64 꼴을 별도로 두거나, `[A-Za-z0-9+/_-]{22,}={0,2}` 로 넓히고 경로 오탐은 러너 경로 가림이 먼저 지우는 순서를 단언.

### 🟡 Y3. 40 · 64자 16진은 무조건 허용 — 64자 16진 비밀 키가 통과
- 근거: mask.js:14,47 · leak-scan 도 같은 판정(isLongToken 공유).
- 재현: `k=` + 64자 16진 → 걸림 0 (32자 16진은 걸림 = 길이로만 가름).
- 원자료에 정당한 64자 16진은 릴리스 해시 · SHA256SUMS 값 · 커밋 SHA 뿐이다. 허용 범위가 「16진이면 다」 라서 너무 넓다.
- 권고: 허용을 「장치가 아는 값」(expected-sums.txt 4개 · 장치 커밋 · 나무 · 원자료 SHA256SUMS 값)으로 좁히거나, 16진 허용을 해시 목록 파일 · `sha256` 칸에만 둔다.
