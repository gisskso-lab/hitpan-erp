## 3. 확인한 것

- 쉬운 알림 글은 상수 하나이고 `ex` 는 거름 판정(`ShouldNotify`)에만 쓰인다. 화면 글로는 안 나간다.
- `ShouldNotify` 는 취소(시간 초과 아님) · 401 · 403 을 거르고, 시간 초과(`TimeoutException` 안쪽)는 알린다. 401 · 403 은 공통 처리기가 알리는 것을 `HitPanApiAuthHandler.cs:114` 에서 확인했다.
- 백업 막힘: 예외 · 503 · 403 · 401 · JSON 깨짐 · 취소 · 시간 초과에서 모두 `_settingsLoadFailed = true` 가 되고 단추와 저장 함수 머리 두 겹으로 막힌다. 다음 조회가 성공하면 풀린다. 「지금 백업」은 서버 쪽 설정으로 돌므로 막지 않은 것이 맞다.
- 결제 · 인증서 · 결재선 · 메일 화면: 실패한 칸은 「없습니다」 대신 「—」를 보여 거짓 안내가 없다. 메일 설정은 필수 칸 검사(호스트 · 발신 주소 · 비번)가 빈 저장을 막는다.
- 네 조회를 동시에 띄우는 결제 화면의 `loadFailed ??=` 닫힘은 WASM 단일 스레드라 경합이 없다. MySqlConnection 이 아니라 HttpClient 라 #16 과 무관하다.
- 파일별 catch 수: `EmployeeService` +1(기록 있음) 말고는 증감 0 · `throw` 증감 0.
- #43: 업데이트 경로 파일 diff 0 · Sidebar 의 #43 3줄은 그대로 · 시험 장치는 `api/auth/update-status` 를 가로채지 않는다.
- #18 · #22: 새 외부 주소 0 · 사용자 지정 기록 제공자 0 · 콘솔을 가로채는 JS 0.
- 시험 장치: 자체시험 13/13 PASS(직접 돌림) · `judgeScene` 반례 3개(가로챔 0 → 거짓 · 띠 null → 거짓 · 정상 → 참) · CI 단계는 `rc` 를 모아 `exit $rc` 로 끝나므로 숨는 실패가 없다(`continue-on-error` 없음).

## 4. 못 본 것

- CI 런 로그와 결과표(`console-error-band-result.json`) 원본은 직접 열지 않았다. 「44f909a6 전 잡 초록 · 13/13」은 카드에 적힌 사실을 그대로 받았다.
- 실제 브라우저에서 콘솔에 찍히는 꼴(Release WASM 의 `ex.ToString()` 길이 · 호출 줄 표시 여부)은 실측하지 않았다. 코드와 .NET 기본 동작으로 판단했다.
- 서버 쪽 오류 본문(`{Body}` 3자리)에 무엇이 담기는지는 API 를 전수로 보지 않았다(옛 줄과 같은 양이라 이번 PR 의 변화는 아님).
- 개발명세서 5개 본문과 화면 57곳 하나하나의 알림 붙임은 표본(백업 · 결제 · 인증서 · 결재선 · 메일 · 매입 통계 · CS 상세 · 어음 · 카드 · 통장)만 봤다.
- `dotnet build` · `dotnet test` 는 돌리지 않았다(CI 초록을 받음 · DB 접속 금지 규칙).
