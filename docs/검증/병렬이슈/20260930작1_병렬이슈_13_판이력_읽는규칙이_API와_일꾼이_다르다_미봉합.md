## 무엇이 문제인가
1. **규칙 불일치** — API 는 `|` 로 나눠 **정확히 두 칸**인 줄만 읽는다(`RollbackMaterialFinder.cs TryReadPreviousVersion` · 기록기 `LastVersion` 도 같음). 일꾼은 `$line.Split('|')[0]` — 칸 수를 안 본다(`local-swap.ps1:629`). 찢긴 줄 `1.3.4`(원래 `1.3.45|…`) 은 API 에선 무시, 일꾼에선 판 `1.3.4` 로 읽힌다 ⇒ API 가 재료 ② 를 보여 주고 확인 번호를 준 뒤, 일꾼 S1 이 「직전 판 아님」으로 `material_invalid`. 반대 방향(일꾼만 허락)도 같은 뿌리.
2. **과도기** — 이력 줄이 2개 미만이면 두 쪽 모두 「모름 → prev 묵음 규칙만」(`TryReadPreviousVersion` `seen.Count < 2` · 일꾼 `:636`). 기록기가 처음 들어간 판 L 에서: 옛 판들을 **설치 EXE** 로 올린 PC(prev 없음)는 staging 에 남은 옛 zip 이 「가장 큰 아래 판」 이면 두 판 뒤로 간다(병렬이슈 05 모양 1회 잔존).
3. 기록은 **API 가 떠야** 남는다 — 판 N 이 설치됐으나 API 가 한 번도 못 뜬 채 다음 판으로 넘어가면 N 이 이력에서 빠진다(→ 「직전 판」 이 한 칸 앞 판으로 판정). ⚠️가설: 워치독 S6 실패 후 되돌림이면 영향 없음.

## 막는 방향 (한 줄)
줄 규칙을 한 벌로(일꾼도 `칸 수 == 2` + 시각 칸 파싱) · 과도기 1회는 「이력 1줄 + prev 없음」 이면 재료 ② 를 쓰지 않는 쪽으로(안전 방향).
