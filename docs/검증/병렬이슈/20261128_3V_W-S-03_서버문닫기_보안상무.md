- 시나리오: 뒤의 누군가가 다른 컨트롤러(예: `AuthController` · `AccessStatusController` — 둘 다 이미 `ITenantDeviceService` 주입)에 새 주소로 `RegisterMobileByTokenAsync` 를 부르는 액션을 더하면 옛 QR 등록이 새 주소로 살아난다. G-S3-1(`BetaClosedServerGateTests.cs` :122 ~ :125 · :157)은 **경로 문자열**만 보므로 새 주소는 못 잡는다. 게다가 `mobile-register` 는 원래 `[AllowAnonymous]` 설계(:335)였으니 새 길에 `TenantMiddleware` 면제를 같이 달면 익명 등록이 된다.
- 권고: 소스 grep 게이트 한 개 — 「`src/HitPan.API` 안에서 두 메서드 호출 = `DeviceController` 의 `[NonAction]` 두 자리뿐」. 시험 추가 범위는 PM 판단.

## 3. ⑤ 사본 정책 — 왜 거짓 초록이 아닌가
- 닫힘 변이(`[NonAction]` 뗌)일 때 빨강이 나는 조건 = 처리기 도달 → Strict 가짜(:139 ~ :145)가 값을 줘 200. 사본 정책이 `tenant_admin` · `tenant_user` 를 통과시키는 한 변이는 빨강.
- 실물 정책이 **좁아지면**(예: `tenant_user` 막음): 사본이 더 넓어 시험은 여전히 처리기까지 닿을 수 있음 → 닫힘 판정은 오히려 엄격. 실물이 **넓어지면**: 시험은 두 계정 종류만 보내므로 영향 0.
- 거짓 초록이 되는 유일한 꼴 = 사본을 고쳐 두 계정 종류를 막는 것(시험 자체 훼손). G-S3-2-2(로그인 없음 401)는 실물 `TenantMiddleware`(:107)에 달렸고 사본과 무관 · 시험 스스로 「닫힘 증거 아님」 명시(:172).
