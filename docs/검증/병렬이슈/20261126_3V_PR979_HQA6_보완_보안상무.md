## §4 고칠 제안 (코드는 손대지 않음)

1. **P1** — 별 작업 대장 줄 W-G1-51-후1(지시서 §9)에 「판매 반품 화면 읽기(`SalesService.cs` L2241) items 조인 회사 조건」 을 **명시 추가**. 저장 4길 검사와 같은 작업지시서에서 함께 고쳐야 §3 P1 근거의 「고쳐 저장 거절」 혼란 문구를 같이 설계할 수 있다. 기한 = 고객 첫 설치 전(같은 줄).
2. HQA 재의뢰서에는 「반품 줄을 읽는 곳 = 인쇄 로더 2(이번에 닫음) · 매입 반품 화면(조건 있음) · 판매 반품 화면(별 작업 대장)」 세 줄을 밝혀 두면, 화면 쪽을 되묻는 회송을 줄인다.
3. DoD ③ 변이 런 표에 **G-1 · G-0 이 변이에도 초록**이었음을 같이 적을 것(변이가 조건 하나만 잰다는 증거 · 지시서 §4-2).

## §5 틀릴 수 있는 자리

- **NULL 품명 렌더**: 조건이 붙으면 다른 회사 품목 줄의 `ItemName` 은 DB 에서 NULL 이다. 매핑 라이브러리가 NULL 칸을 건너뛰어 기본값 빈 글자가 남는다고 보지만 **로컬 실측은 안 했다**. 틀리면 G-2 가 예외로 빨강이 되므로 CI 가 잡는다(명세서 Q1 과 같은 판단).
- **콜레이션**: `utf8mb4_unicode_ci` 에서 회사 id 비교는 대소문자를 가리지 않는다. 대소문자만 다른 회사 id 가 한 DB 에 있으면 조건이 둘을 같게 본다. 이는 기존 `WHERE … tenant_id = @TenantId` 와 같은 성질이고 회사 id 를 시스템이 만드는 한 실해 없음으로 봄.
- **CI 실측 미확인**: 3-2 · 3-5 · 3-6 은 코드를 따라간 판단이다. DB 게이트 6 사실의 실제 초록 · 변이 빨강은 CI 런 결과로만 확정된다.
- **양식 지정 렌더**: 시험은 양식이 빈 값인 기본 렌더만 탄다. 사용자 양식 렌더는 같은 스냅샷 글자를 쓰므로 데이터 축은 같다고 봤으나 그 경로로 그린 PDF 는 재지 않았다.
