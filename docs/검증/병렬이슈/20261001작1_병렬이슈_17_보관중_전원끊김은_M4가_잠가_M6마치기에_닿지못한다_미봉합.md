## 무엇이 문제인가
- 설계 §16-0 판정 근거: 「표식은 `.rbk` 를 옮기기 **전**에 쓰고 … **도중에 던지든 전원이 나가든 표식이 남는다**」 → M6 는 「일꾼(성공 정리 재시도 · S0)」이 마친다.
- 그런데 **전원이 나간 경우** 다음 교체는 일꾼 S0 까지 가지 못한다:
  1. 성공 정리(`Invoke-SuccessCleanup` → `Clear-AfterSuccess` → `Save-PrevGeneration`)는 `Complete-Swap 'success' … 'S6'`(`local-swap.ps1:1172-1173`) **앞**에서 돈다 ⇒ 끊기면 요청서는 `running`, step 은 S3 이후 값(정지는 S3 `:1144-1146`).
  2. 런처 `ClearStale`(`LocalSwapLauncher.cs:199`)이 `broken/worker_interrupted` 로 적는다 — step 은 그대로.
  3. `JudgeLeftoverRbk`(`:144-151`): `broken` 이고 `IsBeforeStop` 아님 → `PartsAfter` 없음(요청서 `parts_after` 는 `Complete-Swap` 에서만 씀 `:886`) → `From==api || To==api` → 살아 있는 판 = `to` 이므로 참 ⇒ **M4 `swap_interrupted`**.
  4. 런처가 새 요청을 안 만든다 ⇒ `last` 가 영영 그 `broken` ⇒ 잠김은 **워치독 업데이트로 판이 바뀔 때까지** 계속. 판이 바뀌면 표식 `to ≠ live` → 낡은 표식 → `.rbk` 는 M5 로 치워진다(그땐 두 판 뒤라 옳다).
- 즉 봉합3 이 「전원 끊김」을 위해 만든 M6 마치기 경로는 **던짐 경우에만 닿는다.** 전원 끊김은 종전과 같이 M4 잠김으로 끝난다(지우지 않는 건 맞음).
- 같은 뿌리의 틈 하나 더: `Save-PrevGeneration` 은 **옛 `prev` 치우기(`Remove-AppDirSafe $prev` · `:899`) 뒤에** 표식을 쓴다(설계 16-1ⓐ 순서 그대로). 옛 `prev` 치우기는 고객 자료 싣기 + 세 프로그램 폴더 삭제라 수 초 걸린다. 이 사이 끊기면 표식 없이 `.rbk` 만 남는다 — 지금은 위 M4 가 막아 주지만, M4 가 풀리는 순간(판 변경 · 또는 훗날 M4 완화) **M5 로 지워지는 쪽**이다. 설계 문장 「전원이 나가든 표식이 남는다」는 표식을 쓴 **뒤**에만 참이다.

## 안 되는 경우 (재현 절차 · 실측 0)
1. `-TestRoot` rig 업데이트 모드 · `PVHH` 로 `web.rbk` 를 쥔 채 성공 정리 재시도 중 일꾼 프로세스를 강제 종료(`Stop-Process`).
2. 요청서 `state=running` · `step` 확인 → `ClearStale` 시한 경과 가짜 시계 → `JudgeLeftoverRbk`.
3. 기대(설계 16-0): 다음 교체 S0 가 M6 마침. 코드 추적상 실제: `swap_interrupted` · 일꾼 미기동.
