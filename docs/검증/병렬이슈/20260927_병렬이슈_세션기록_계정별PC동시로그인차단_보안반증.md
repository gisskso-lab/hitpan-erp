## 0. 한 줄 요약

**차단의 열쇠를 공격자에게 쥐여 줬다.**
축 B(계정별 PC 동시로그인 차단)의 발동 여부 전체가 클라이언트가 JSON 으로 **자기 신고**하는
`deviceType` 한 칸에 달려 있다. `"mobile"` 한 단어면 차단은 영원히 안 걸린다.
설계는 이것을 "받아들인 구멍"이라 적었으나, 그 판단 근거(*"과금 축이 계정으로 바뀌어 매출로
이어지지 않는다"*)는 **순환논증**이다 — 「계정 1개 = PC 1대」를 강제하는 장치가 바로 이 차단이다.

## 1. 🔴 P0-1 — `deviceType: "mobile"` 한 줄로 차단이 영구 우회된다

### 근거 (🟢 코드 확인)

| 위치 | 내용 |
|---|---|
| `src/HitPan.Application/DTOs/Auth/LoginRequest.cs:22` | `public string? DeviceType { get; set; }` — **요청 본문에서 그대로 받는다** |
| `src/HitPan.Application/Services/AuthService.cs:196-198` | `NormalizeDeviceKind` — `"pc"` 와 같지 않으면 전부 `"mobile"` |
| `src/HitPan.Application/Services/AuthService.cs:214` | `if (!string.Equals(deviceKind, "pc", ...)) return;` — **판정 첫 줄에서 그냥 나간다** |
| `src/HitPan.Application/Services/AuthService.cs:226-228` | 기존 세션 조회도 `device_kind = 'pc'` 한정 ⇒ mobile 행은 **세지도, 막지도, 밀어내지도 않는다** |
| `src/HitPan.API/Controllers/AuthController.cs:110-113` | **같은 값**이 기기슬롯 등록(`RegisterDeviceRequest.DeviceType`)으로도 흘러간다 |
| `src/HitPan.API/Migrations/SQL/DB-127...sql:55-60` | 설계가 이 구멍을 **스스로 적어 두고 수용**했다 |

### 왜 수용 판단이 틀렸나 — 설계 논거 3개를 하나씩 반증

**① "이미 그렇게 판정된 원칙(모르는 것은 싼 칸)이다"**
그 원칙은 **과금 칸을 고르는** 규칙이다(고객이 안 쓴 비싼 자리에 돈을 물리지 않는다).
여기서는 **보안 통제의 적용 여부**를 고르는 데 쓰였다. 축이 다르다.
과금에서 "모르면 싼 쪽"은 고객 보호지만, 차단에서 "모르면 안 막음"은 **통제 해제**다.
같은 문장이라고 같은 규칙이 아니다.

**② "ERP 웹은 항상 보낸다(`Web/Services/AuthService.cs`)"**
🟢 `/api/auth/login` 은 `[AllowAnonymous]` 다. 우리 화면이 무엇을 보내든,
공격자는 우리 화면을 쓰지 않는다. `curl` 한 줄이면 된다.
**"우리 클라이언트가 착하게 보낸다"는 보안 논거가 될 수 없다.**

**③ "과금 축이 계정으로 바뀌어 이 구멍이 매출로 이어지지 않는다"**
🔴 **순환논증이다.** 9/25 결재의 「베이직 5계정 = PC 5대」가 성립하는 **유일한 이유**가
「계정 1개로는 PC 1대만 쓸 수 있다」는 이번 차단이다. 그 차단이 클라이언트 한 칸으로
꺼지면 고객은 **계정 1개를 사서 PC 5대에서 동시에 쓴다.**
차단 누락이 곧 매출 누수다. 둘은 분리되지 않는다.

### 자기모순 — DDL 자신이 이 판단을 부정한다

`DB-127...sql:23-35` 는 `user_agent` 를 쓰지 않는 이유를 이렇게 적었다.

> ① UA 는 **사용자가 바꿀 수 있다.** 모바일이 FREE 이므로 UA 만 모바일로 바꾸면
> **PC 에서 무제한 접속이 된다.** 과금이 그대로 뚫린다.
> ③ **브라우저가 말해주는 것 위에 정책을 세우면 안 된다.**

`deviceType` 은 UA 보다 **더 바꾸기 쉽다.** UA 는 브라우저 설정·확장이 필요하지만
`deviceType` 은 JSON 필드 하나다. 즉 이 파일은 **자기가 거부한 바로 그 이유가
더 강하게 적용되는 대안**을 채택했다. 서버는 여전히 아무것도 판정하지 않는다 —
"서버가 판정해 적는 칸"이라고 주석에 썼지만, 실제로 적는 값은 **클라이언트가 준 값의 정규화**다.

### 게이트가 이 구멍을 「정상」으로 굳혔다

| 위치 | 내용 |
|---|---|
| `src/HitPan.Tests/Integrity/SessionRecordConcurrentPcGateTests.cs:294-295` | mobile 세션 2개 공존을 **기대값으로** 검사 |
| 같은 파일 `:316-323` | `""`·`null`·`"무엇인가"` → `mobile` 을 **기대값으로** 검사 |

⇒ 게이트 G-3 은 이 결함을 잡는 장치가 아니라 **결함을 고정하는 장치**다.
"그 값은 게이트 G-3 가 지킨다"(DDL:60)는 서술은 **지킨다는 뜻이 아니다** — 바뀌지 않게 막을 뿐이다.

### 악용 시나리오 (⚠️ 런타임 미실측 — 코드상 성립)

```
1. 사무실 PC 5대. 계정은 1개만 구매.
2. 각 PC 에서 브라우저 개발자도구 또는 프록시로 로그인 요청 본문의
   deviceType 을 "mobile" 로 바꾼다 (또는 필드를 지운다).
3. 5대 전부 로그인 성공. 409 없음. 밀어내기 없음.
4. user_sessions 에 mobile 행 5개. device_kind='pc' 조회에 안 잡히므로
   이후 누가 정상 PC 로그인을 해도 서로를 밀어내지 않는다.
5. 기기슬롯도 mobile 로 등록되어 PC 슬롯을 먹지 않는다 (AuthController.cs:110-113).
```

두 과금 축(기기슬롯 · 계정)이 **같은 자기신고 값 하나**에 달려 있다.

### 보안상무 의견

이 한 건 때문에 이번 트랙은 **"동시접속 제한이 한 번도 안 걸렸다"는 문제를
"동시접속 제한이 원할 때만 걸린다"로 바꾼 것**에 그친다.
서버가 스스로 판정할 축(예: `mainpc-proof` 왕복 · 화면 크기·입력수단이 아닌 서버측 신호)을
쓰지 않는 한, 이 통제는 **정직한 사용자에게만 적용된다.**
⚠️ 대안 설계는 이 문서 범위 밖 — 사장님 결재 사안(과금 정책과 직결).

### 악용 시나리오 (⚠️ 런타임 미실측 — 코드상 성립)

```
1. 밀려날 것 같은 PC 에서 정상 상태일 때 문서 다운로드 토큰을 1개 받아 둔다(2시간).
2. 다른 PC 에서 [그 컴퓨터 접속을 끊고 여기서 사용하기] 로 밀려난다.
```

⚠️ 그 범위가 정확히 몇 개인지는 세지 않았다(미실측).

**이 경로 자체는 이번 작업이 만든 것이 아니다**(선존재). 그러나 이번 작업이
**"sid 없으면 통과"라는 영구 규칙**을 세우면서 **보안 통제를 우회하는 값**으로 승격시켰다.
앞으로 누가 토큰 발급 경로를 하나 더 만들면서 `sid` 를 잊으면, **조용히** 세션 통제 밖으로 나간다.
경고도 로그도 없다.

### 기록만 (고치지 않음)

통과 규칙에 만료 근거(발급 시각 기준 7일 = refresh 수명) 또는 `token_type` 화이트리스트가
없다는 사실. 봉합안은 설계 몫.

이 `DELETE` 는 **전부터 있었다.** 그러나 넣는 코드가 0건이라 **한 번도 효과가 없었다.**

작업지시서는 "지우는 코드는 이미 있다"를 **자산**으로 적었으나, 그것이 `user_id` 전체
삭제라는 점은 검토되지 않았다.

### 9/25 결재와 정면 충돌

> "모바일 FREE (PC 와 동시 가능)"

🟢 코드상: 모바일에서 로그아웃 버튼을 누르면 → `user_id` 의 **모든** 세션 행 삭제 →
같은 계정으로 전표를 입력 중이던 **PC 가 10초 안에 끊긴다.**
"동시 가능"이 아니라 "모바일이 PC 를 끊을 수 있다"가 된다. 헌법 #20(흐름 안 끊김) 저촉.

### 악용 시나리오 (⚠️ 런타임 미실측)

```

PC 쪽 작업자의 입력 중이던 화면이 예고 없이 끊긴다. 권한 상승은 아니나
「저장 안 한 내용이 날아간다」는 사용자 피해를 비밀번호 없이(이미 로그인된

```

## 5. 🟡 P2-1 — 조회 3곳이 `tenant_id` 없이 돈다 (#2 방어깊이)

### 🟢 먼저 — **헌법 #2 위반은 없다**

`tenant_id` 를 **요청 파라미터에서 받는 곳은 0건**이다.
`INSERT` 의 `tenant_id` 는 DB 의 `user` 행에서 온다(`AuthService.cs:262-270`),
킬스위치 조회는 `user.TenantId`(DB) 와 `context.Items["TenantId"]`(TenantMiddleware 가
JWT 에서 채운 값)를 쓴다. **JWT·DB 출처만 쓴다 — #2 준수.**

### 다만 좁히는 조건이 빠져 있다

| 위치 | 조회 조건 | 빠진 것 |
|---|---|---|
| `SessionValidityMiddleware.cs:87` | `WHERE session_id = @Sid AND expires_at > ...` | `user_id`·`tenant_id` 둘 다 |
| `AuthService.cs:226-228` | `WHERE user_id = @UserId AND device_kind='pc' ...` | `tenant_id` |
| `AuthService.cs:241` (DELETE) | `WHERE user_id = @UserId AND device_kind='pc'` | `tenant_id` |
| `AuthService.cs:484-487` (UPDATE) | `WHERE session_id = @SessionId` | `user_id`·`tenant_id` |

### 현재 실효 위험 — 낮다 (🟢 근거 제시)

- `session_id` 는 PK 다 (`installer/hitpan_db_clean.sql:4253`) ⇒ 한 행만 맞는다.
- `session_id`·`user_id` 모두 GUID ⇒ 현재 채번으로는 테넌트 간 충돌이 사실상 없다.

### 그래도 기록하는 이유

세션 생존 판정이 **"이 토큰의 주인이 이 세션의 주인인가"를 한 번도 확인하지 않는다.**
`sid` 존재 여부만 본다. 한 PC 에 여러 사업장을 두는 구성(`multi_business_per_pc` 결재)에서
같은 표를 공유하므로, 앞으로 `user_id` 채번 방식이 바뀌거나 세션 복제 기능이 생기는 순간
이 빠진 조건이 바로 교차 테넌트 판정이 된다. **지금 한 줄이 없다**는 사실만 남긴다.

## 7. 🟢 P2-3 — 409 정보 노출: **없다.** 단 값이 부정확하다

### 노출 판정 — 🟢 문제 없음

호출 순서를 코드로 확인했다.

```
AuthService.LoginAsync
  :40  사용자 조회 → 없으면 UnauthorizedAccessException (같은 문구)
  :47  계정 잠금 확인
  :53  BCrypt.Verify — 비밀번호 검증
  :68  IsActive 확인
  :115 EnforceSinglePcLoginAsync  ← 409 는 여기서만 나온다
```

⇒ **비밀번호가 맞아야만 409 가 나온다.** 계정 존재 여부·사용 패턴을 캐는 데 쓸 수 없다.
로그인 실패는 전부 401 이고 문구도 통일돼 있다(`InvalidCredentialMessage`).

### 다만 — `otherPcLastActiveAt` 값이 최대 8시간 낡았다

`last_active_at` 을 갱신하는 곳은 **로그인(`:262`)과 토큰 갱신(`:484`) 둘뿐**이다.
`SessionValidityMiddleware` 는 `SELECT` 만 하고 `last_active_at` 을 건드리지 않는다(`:86-88`).
access 토큰 수명이 8시간이므로 갱신은 8시간에 한 번이다.

⇒ 화면은 "마지막 사용: 9월 27일 09:00" 이라 보여주지만 **지금 이 순간에도 쓰고 있을 수 있다.**
사용자는 이 값 하나를 보고 "끊어도 되나"를 판단한다(`ConcurrentPcLoginException` 주석이
그렇게 적고 있다). **판단 근거로 쓰라고 만든 값이 판단을 틀리게 한다.**
전표 입력 중인 동료를 "8시간 전이네" 하고 끊는다. P2 — 데이터 손실로 이어질 수 있다.

## 9. 🟢 `sid` 유출 — 단독으로 할 수 있는 일: **없다**
