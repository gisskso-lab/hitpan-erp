## 원인 (코드 읽음 · ⚠️미실측)
- `SalesService.cs:1306-1313` `UPDATE collections SET is_active=0 ... ref_doc_type='sales_delivery' AND ref_doc_id=@Did` — 연결 수금 전부 비활성.
- 뒤이은 역분개는 `RecordSalesDeliveryCancelAsync`(매출·부가세 ↔ 외상매출금)뿐. 꺼진 수금 각각의 원 분개(`source_type='collection'` · 차 현금 / 대 외상매출금)는 그대로 남는다. `RecordCollectionCancelAsync` 호출처는 `CollectionService.cs:236` 하나(grep).
- 우회 판정: 이관 명세서는 `MigratedDocumentLock.EnsureDeliveryEditableAsync` 로 취소 자체가 막혀 이관 수금은 이 경로로 안 꺼진다(✅). `legacy_balance` 수금도 ref 유형이 달라 안 꺼진다 — 단 병렬이슈42 표기 변형은 예외.
- ⚠️ 같은 블록 재집계(`:1331-1335`) `total_receipt` = `ref_doc_type='sales_delivery'` 수금 합만 → 그 거래처의 **이월잔액 매칭 수금·ref 없는 수금이 total_receipt 에서 사라진다**. R-A5③(R2) 이 이 두 종류를 넣는지 R2 개발명세서에서 확인 필요.

## 요구
- 확정취소가 끈 수금 id 마다 `RecordCollectionCancelAsync`(원 수금일) 호출 — 매입 쪽 대응 경로도 grep.
- G8 또는 G9 에 「수금 붙은 명세서 확정취소 → collection_cancel 건수 = 꺼진 수금 건수 · total_receipt 에 legacy_balance 수금 유지」.
