## 🔴 I-0 — 루틴 정직 신고: 이번에도 [3-V] 가 [3] 과 **동시에 안 돌았다**

규모 M 이고 PM 이 순차로 구현했다 ⇒ 이 문서는 **[3] 뒤에** 썼다. 동시였다고 적지 않는다. [4] 는 **독립 문맥**에서 돌려 작성자 ≠ 결재자를 지켰다.

---

## I-1 🟢 새 질의칸이 **주입 경로를 열지 않았다**

`?purpose=` 는 사람이 보내는 값이다. 그 값이 SQL 로 가는 길을 전수로 봤다:

| 경로 | 결과 |
|---|---|
| `etc` | `" AND (r.purpose = 'etc' OR r.purpose IS NULL)"` — **상수 문자열** 하나. 값이 SQL 에 안 섞인다 |
| 허용 4종(`update`·`notice`·`promo`·`etc`) | `" AND r.purpose = @Purpose"` — **매개변수** |
| 그 밖 전부 | `""` — **조건을 아예 안 단다** |

⇒ 🔴 **사람이 보낸 글자가 SQL 문자열에 이어붙는 길이 0건**이다. 허용목록(`PurposeFilterable`)을 **먼저** 통과해야 매개변수 경로로도 들어간다 — 통과해도 매개변수라 이중 방어다.

🔴 `origin` 도 같은 모양이다(상수 분기만). 작1 이 세운 그 모양을 그대로 따랐다 — 질의칸이 둘이 됐는데 **모양은 하나**다.

## I-2 🟢 테넌트 격리(#2)가 한 칸도 느슨해지지 않았다

- `WHERE r.tenant_id = @TenantId` 가 **그대로** 맨 앞이고, 새 조건은 **그 뒤에 더해질 뿐**이다.
- `tenant_id` 는 여전히 `HttpContext.Items["TenantId"]`(토큰 클레임 유래)에서만 온다 — 매개변수로 안 받는다.
- 새 인덱스도 `tenant_id` 를 **선행 칸**으로 둔다 ⇒ 남의 테넌트 행을 스캔할 길이 없다.

## I-3 🟢 #18·#22 — 본사로 가는 칸이 늘지 않았다

용도는 **받는 쪽에서만** 쓴다. 본사로 올라가는 것은 도착확인 봉투의 `outboundIds` 하나뿐이고 이 차수가 그 모양을 **한 글자도 안 바꿨다**. 고객 업무 데이터가 새 나가는 칸 **0건**.

## I-4 🟡 마이그 안전 — 재실행은 안전하고, **잠금 시간은 못 쟀다**

| 축 | 결과 |
|---|---|
| 재실행 | 🟢 `ADD COLUMN IF NOT EXISTS`·`ADD KEY IF NOT EXISTS` — 두 번 돌아도 같다 |
| 부분 적용 | 🟢 칸만 들어가고 KEY 가 안 들어간 상태에서도 **읽기·쓰기 전부 돈다**(KEY 는 속도 축이다) |
| 데이터 변경 | 🟢 `UPDATE`·`DELETE` **0건** |
| 🟡 **잠금 시간** | 🔴 **못 쟀다.** 운영 규모(행이 많은) `cs_requests` 가 이 PC 에 없다. MariaDB 11.4 의 `ADD COLUMN` 은 대개 즉시지만 **그건 측정이 아니라 통설**이다 ⇒ [5] 의 못 쟀는 것으로 올린다 |
| 신규 설치 | 🟢 출하 DDL 의 **표 정의 + 시드** 둘 다 들어갔다(#36). 🔴 시드를 처음에 빠뜨렸고 **전체 회귀가 잡았다**(개발명세서 §2-④) |

## I-5 🟢 흐름 안 끊김 (#20) — 칸 없는 상태를 세 자리에서 봤다

용도 칸은 **업데이트 직후 마이그 전 1회** 없는 상태로 돈다. 그때 1054 가 나면 **목록이 통째로 죽고 같은 응답에 실린 본사 답변까지 못 보인다**(10/12 사고 모양).

| 자리 | 가드 |
|---|---|
| 수신기 INSERT | 🟢 칸 이름을 **아예 넣지 않는다**(주기마다 묻는다 · 캐시 없음) |
| 목록 SELECT | 🟢 `NULL AS purpose` 로 대체 |
| 목록 WHERE | 🟢 **조건을 안 단다**(칸 없는 DB 에서는 필터가 전체로 떨어진다) |

🔴 `G-W11-2` 가 **칸을 실제로 떼고** 이 셋을 한 번에 돈다 — 글자로 흉내내지 않았다.

## I-6 🟡 관찰 — 낱말이 **응답마다 다시 계산**된다

행마다 `PurposeLabel` 을 부른다(200행이면 200번). `switch` 식 한 번이라 비용은 사실상 0 이고, **캐시를 두면 낱말을 고친 차수 뒤에 옛 글자가 남는 위험**이 생긴다(작2 가 낱말을 고쳤다) ⇒ **계산하는 쪽이 맞다.** 기록만 남긴다.
