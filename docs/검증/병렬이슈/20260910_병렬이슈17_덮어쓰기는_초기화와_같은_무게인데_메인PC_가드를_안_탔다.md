# 병렬이슈 17 — 덮어쓰기는 초기화와 같은 무게인데 **「자료보관 컴퓨터에서만」 가드를 안 타고 있었다**

| 항목 | 내용 |
|---|---|
| 발견 | 2026-09-10 · 작업 루틴 [3-V] (A1 구현 도중 자기 반증) |
| 대상 | `MigrationController.PrepareOverwriteAsync` (20260910작1 A1 신설분) |
| 심각도 | **P1 — 게시 전 필수** (봉합 완료) |
| 상태 | ✅ 봉합 + 게이트 2개(G-OW8·G-OW9) · 무력화 시험 확인 |

## 1. 무엇이 잘못됐나

「모든데이터 초기화」는 컨트롤러 전체가 `[MainPcOnly]` 다 — **자료가 들어 있는 그 컴퓨터에서만** 부를 수 있다.
2026-08-11 사장님 지시: *"자료관리는 **부모계정 + 메인PC 환경에서만** 돌도록"*.

그런데 A1 이 새로 만든 「모두 지우고 새로 가져오기」는 `POST legacy-mdb/start` **안의 분기**다.
`MigrationController` 에는 클래스 수준 `[MainPcOnly]` 가 없다(「없는 것만 보태기」는 어디서든 되어야 하므로 없는 게 맞다).

⇒ **덮어쓰기가 초기화를 호출하는데, 초기화의 가드는 안 탔다.**
바깥(터널)에서 주소만 알면 대표 비번과 확인 문구만으로 **회사 장부를 통째로 지울 수 있는 문**이 열려 있었다.

> 🔴 이것이 이 프로젝트가 반복해 온 모양이다 — **같은 무게의 일이 두 문으로 들어오는데 한쪽 문에만 자물쇠가 있었다.**
> 화면(`MdbMigration.razor`)에는 애초에 `MainPcOnly` 래퍼가 없어서, 화면 감춤조차 없었다.

## 2. 어떻게 찾았나

A1 을 짜고 나서 *"초기화 화면이 지키는 규칙 중 덮어쓰기가 안 지키는 게 있나"* 를 항목별로 대조했다.
`DataResetController` 는 ① `TenantAdminOnly` ② `MainPcOnly` ③ 비번 재검증 ④ 확인문구 ⑤ 강제백업 — 다섯이다.
덮어쓰기는 ①③④⑤ 를 탔고 **②만 빠져 있었다.**

## 3. 봉합

- `MainPcOnlyAttribute` 에 판정을 `public static bool IsMainPc(HttpContext)` 로 **뽑았다**(본문 무변경 · 헌법 #1).
  어트리뷰트와 덮어쓰기 분기가 **같은 규칙 한 곳**을 본다 — 복붙하면 한쪽만 고쳐지는 날이 온다.
- `PrepareOverwriteAsync` 맨 앞에서 물어 아니면 **403** + 화면 문구
  「기존 자료를 모두 지우고 새로 가져오기는 회사 자료가 들어 있는 컴퓨터에서만 할 수 있습니다.」
- 화면: 자료보관 컴퓨터가 아니면 **그 선택지를 고를 수 없게** 하고 이유를 적는다
  (`api/devices/is-main-pc` — 초기화·백업 화면이 쓰는 **같은 주소**). 못 물어보면 **잠근 채로 둔다.**

> 🔴 **화면만으로 막지 않는다.** 화면을 잠그는 것은 차단이 아니다 — 서버가 같은 규칙으로 다시 판정한다.

## 4. 게이트 (무력화 시험 실측 2026-09-10)

| ID | 무엇 | 봉합을 빼면 |
