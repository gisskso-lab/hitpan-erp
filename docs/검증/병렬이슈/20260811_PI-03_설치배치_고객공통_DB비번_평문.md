## 무엇인가

MariaDB 비번이 **평문 상수**로 저장소에 흩어져 있다.

**🔴 실측 (git 추적분, HEAD 기준) — `installer/install.bat` 한 파일이 아니다:**

```
git grep -l "<비번>" HEAD | wc -l   →  60 개 파일
```

| 구역 | 대표 파일 | 건수 |
|---|---|---|
| **설치·배포** | `installer-build/scripts/install-setup-v107.ps1` | 7 |
| | `installer/install.bat` | 4 |
| | `installer/HitPan.iss` | 3 |
| **🔴 운영 코드·설정** | `src/HitPan.Backoffice.API/appsettings.json` | 2 |
| | `src/HitPan.Application/Services/BackupService.cs` | 1 |
| | `src/HitPan.IntegrationTests/Infrastructure/DbFixture.cs` | 2 |
| **문서** | `docs/PRD_설치파일.md` · `docs/개발/erp/13_소스코드_가이드.md` 등 | 다수 |

> ⚠️ **값은 이 문서에 적지 않는다.** 확인은 `git grep -l "<비번>" HEAD`.

⚠️ **처음 이 이슈를 열 때 PM 은 "install.bat 5줄" 로 적었다.** 워크플로 주석에 적힌 그 한 파일만 보고
**세지 않고 옮겨 적은 것**이다. 실제로 세어보니 **60개 파일**이었고, **운영 코드에도 있다**.
⇒ 봉합 범위가 "설치 배치 한 곳" 이 아니라 **전수**다.

## 왜 P0 인가 — 이건 고객 **공통** 비번이다

설치 배치가 모든 고객사 PC 에 **같은 비번**을 심는다.

- 고객 한 곳의 PC 에서 값이 새면 → **다른 모든 고객사 DB 가 같은 열쇠로 열린다**
- 배치 파일은 설치 폴더에 그대로 남는다. 고객 PC 를 만질 수 있는 사람이면 누구나 읽는다
- 헌법 #30 대로 DB 는 고객 PC 로컬에 있다 — **본사가 안 가져서 안 털리는 구조**인데,
  그 구조의 이점을 **공통 비번 하나가 상쇄한다**

## 왜 여태 안 잡혔나 — 잡혀 있었다. 아무도 안 봤을 뿐이다

`.github/workflows/trufflehog.yml:68` 에 보안팀이 적어 뒀다:

> *"⚠️ 진탐(installer/install.bat 의 고객 공통 DB 비번)은 **제외하지 않았다.**
>  그래서 이 스캔은 계속 실패로 뜬다. **덮지 않는 것이 의도다.**"*

**빨간 X 는 고장이 아니라 표식이었다.** 7/31 봉합 때 일부러 남겼다.

🔴 **그런데 그 표식이 상시 빨강이라 "늘 실패하는 체크" 가 됐다.**
오늘 PM 이 정확히 그 함정에 빠져 *"무관한 소음, 별건 정리"* 로 마감문서에 적었다.
같은 파일 44~49행이 경고하는 구조가 **그대로 재현됐다** —
*"결과는 빨간 X 라 '늘 실패하는 체크' 가 되어 아무도 안 보게 됐다 — 진짜 유출이 나도 못 알아본다."*

## 🔴 PM 이 이 건을 기록하다가 유출을 한 부 더 만들었다

문서화하면서 **비번 값을 그대로 3개 문서에 옮겨 적었다.**
저장소에 한 곳이던 값이 **네 곳**이 됐다. PR 시크릿 스캔이 잡았다
(오늘 다른 PR 은 전부 통과했는데 이 PR 만 `pull_request` 스캔까지 실패 — 그게 신호였다).

**⇒ 사고 기록에는 '어디가 새는지' 를 적고 '새는 값' 은 적지 않는다.**

값을 빼내고 재푸시하니 두 스캔 모두 즉시 통과. **스캔이 옳았고 PM 이 틀렸다.**

## 봉합 방향 (제안 — 결재 필요)

| 안 | 내용 | 평가 |
|---|---|---|
| **(가)** | **고객사별 무작위 비번 생성** — 설치 시 난수 발급 → `db.conf` 에 저장 | 🟢 권장. 공통 열쇠가 사라진다 |
| (나) | 배치에서 비번을 지우고 설치 중 입력받기 | 🔴 헌법 #25 "쉽게" 위반 — 고객이 입력할 게 늘어난다 |
| (다) | 스캔 제외 목록에 추가 | 🔴 **절대 금지** — 문제를 덮는 것. '죽은 장치' 하나 추가 |

**(가) 검토 시 확인할 것**
- 업데이트 시 `db.conf` **보존**되나 (기존 고객 접속 끊기면 P0)
- 🔴 **60개 파일 전수** — 설치 배치만 고치면 운영 코드(`BackupService.cs`·`appsettings.json`·`DbFixture.cs`)가 남는다 (헌법 #12 grep 의무)
- 이미 설치된 고객사 **소급 처리** 방안 — 안 하면 기존 고객은 계속 공통 비번
- ⚠️ **비번을 바꾸면 백업·복구·마이그레이션·통합테스트가 동시에 깨진다.** 어느 것 하나 놓치면 고객 PC 에서 터진다 ⇒ **작업지시서 + 전수 실측 필수**

## 왜 오늘 당장 손대지 않았나

이건 **한 줄 봉합이 아니다.** 60개 파일 · 운영 코드 포함 · 기존 고객 소급까지 걸린다.
헌법 #29·#33·#42 — **작업지시서 없이 손대지 않는다.** 사장님 결재 후 정식 SOP 로 착수한다.

⚠️ **다만 지금 이 순간에도 노출 상태다.** 결재를 미루면 그만큼 노출이 이어진다.

## 재발 방지

- **상시 빨강인 체크는 표식일 수 있다.** 끄기 전에 **왜 빨간지 워크플로 주석부터 읽는다**
- 유출 기록 시 **값 복사 금지** — 위치만 적는다
