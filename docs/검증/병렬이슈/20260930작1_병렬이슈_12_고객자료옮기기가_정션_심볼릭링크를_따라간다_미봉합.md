## 무엇이 문제인가
- API 쪽 폴더 문지기는 경로의 재분석 지점을 거부한다(`BackupService.ThrowIfReparsePointOnPathWindows`). 일꾼 쪽 새 함수들은 **한 번도 안 본다**: `Get-ChildItem -LiteralPath $src -Recurse -File -Force`(`local-swap.ps1:291`) → 파일마다 `Move-Item`(`:303`) → 빈 폴더 `Remove-Item`(`:306-309`). `Test-HasCarryData`(`:324`)도 같은 열거.
- 대상 폴더가 이미 있을 때만 파일 단위로 가므로(`:284-288` 폴더 통째 이름 바꾸기가 먼저), 발동 조건 = 옮길 곳에 같은 이름 폴더가 이미 있을 때(prev·stage 에 잔재 · S7 되돌리기 `api → api.rbk`).

## 시나리오
- **악의(관리자)**: `{app}\api\chat-files\x` 를 `C:\Users\<다른사람>\Documents` 로 정션 → 되돌리기 → SYSTEM 이 그 문서들을 `api.rbk\chat-files\x\` 로 **옮겨** 원래 자리에서 없앤다(권한 경계 넘김은 없음 — 관리자 = SYSTEM 이 이미 가능 · 다만 감사 기록 상 「히트판이 했다」가 된다).
- **정상 사용**: `chat-files` 가 D: 로 정션인 PC → 파일 단위 경로에서 볼륨을 넘는 `Move-Item`(복사+삭제) → 전원 끊김 시 대상에 반쪽 파일 · 원본 잔존 → 다음 회차 `.dup-{ticket}` 로 반쪽 파일이 「고객 자료」로 보존된다.
- `.dup-{ticket}` 이름 조립 자체는 안전(티켓 `^[0-9a-f]{32}$` 검증 `:48`).

## 막는 방향 (한 줄)
옮기기 전 원본·대상의 재분석 지점(`Attributes -band ReparsePoint`)을 재고 있으면 **따라가지 않고** 그 항목은 이름만 옮기거나 그대로 두고 로그 — API 문지기와 같은 규칙.

## 게이트 제안 (대조군)
- 시험 루트 밖 폴더를 가리키는 정션을 `chat-files` 아래 심고 S7 되돌리기 → 바깥 폴더의 파일 수가 줄면 FAIL. 대조군: 정션 없음 → 옮김 정상.
