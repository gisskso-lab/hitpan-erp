## 2. 이슈

### P1-별건 — `[MainPcOnly]` 가 사무실 LAN 에서 5234 프록시를 지나면 「로컬 콘솔」 로 통과한다 (기존 결함 · 갈래 C 가 기대는 겹 하나가 없음)

- 파일:줄
  - `installer/web-server.ps1:54` — `$listener.Prefixes.Add("http://+:$port/")` = 모든 네트워크 카드에서 받음
  - `installer/web-server.ps1:97-102` — 프록시가 들어온 헤더를 그대로 복사, **X-Forwarded-For 를 붙이지 않음**, 대상 = `localhost:{API_PORT}`
  - `installer/scripts/FirewallRules.ps1:40` — `HitPan Web (TCP 5234)` 인바운드 Private 열림
  - `installer/HitPan-Universal.iss:3031-3034` — web-server.ps1 = ONSTART SYSTEM 예약 작업(+ 접두가 실제로 열림)
  - `src/HitPan.API/Security/MainPcOnlyAttribute.cs:53 · :57` — 판정 = 「CF/XFF 헤더 없음 + 원격 주소 루프백」
- 공격 꼴: 같은 사무실의 다른 PC 에서 `http://메인PC주소:5234/api/parent-reset` 로 보내면 → API 가 보는 원격 주소 = 127.0.0.1(프록시) · CF/XFF 헤더 0 → `IsLocalConsole` = 참 → `[MainPcOnly]` 통과.
- 갈래 C 에 미치는 것: 본인 확인의 몸은 256비트 1회용 표라 **이 구멍만으로 비번이 바뀌지는 않는다**. 그러나 컨트롤러 · TenantMiddleware 주석의 「`[MainPcOnly]` 가 먼저 자른다」 는 LAN 에서 거짓 — 익명 끝점이 LAN 전체에 열려 있다(P3-3 감사 줄 채우기의 입구).
- 별건 까닭: 같은 판정을 쓰는 **기존** 메인PC 전용 기능(자료관리 · 백업 · 초기화 등)이 모두 같은 구멍을 가진다 — 갈래 C 가 만든 것이 아니므로 갈래 C 머지 조건으로 걸지 않는다. 별 병렬이슈 · 별 작업으로 올릴 것.
- 고침 추천(별 작업): ① web-server.ps1 프록시가 `X-Forwarded-For`(원 접속 주소)를 **덮어써서** 붙임 — 루프백 접속이면 안 붙임 ② 또는 MainPcOnly 가 「원격 주소 루프백」 대신 프록시가 넘긴 원 접속 주소까지 루프백인지 봄 ③ 동작 게이트: LAN 주소에서 5234 를 지난 요청이 403 인지 잼(글자 게이트 금지).
