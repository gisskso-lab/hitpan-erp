## 무엇이 문제인가
- 되돌리기 성공 정리 `Clear-AfterSuccess` 는 `{api,web,watchdog}.rbk` 를 문지기 `Remove-AppDirSafe` 로 지운다(`local-swap.ps1:783`). 문지기는 ① 고객 자료를 살아 있는 `api` 로 못 옮기면 **일부러 남기고**(`:356-358`) ② `Remove-DirSafe` 가 실패해도(파일 잠금 — 백신 검사·색인기) 로그만 남기고 폴더가 남는다(`:260-264, :361-362`). 반환값은 `[void]` 로 버려진다.
- 업데이트 모드도 같다: `Save-PrevGeneration` 문지기 실패 분기 `:752` · `Move-Part` 도중 예외(`:756` → catch `:768` 「best effort」) ⇒ `.rbk` 잔존.
- 그 뒤 상태는 `success` 로 적힌다(`:878`). API `CheckBusy` 는 `.rbk` 가 있으면 **마지막 상태가 broken 일 때만** `swap_interrupted`, 아니면 `update_in_progress`(`LocalSwapLauncher.cs:106-108`) ⇒ 「자동 업데이트 진행 중」이 **영원히**. 일꾼 S0 `Test-UpdateBusy` 도 `.rbk` 면 무조건 거부(`local-swap.ps1:724`).
- `.rbk` 를 치우는 기동 복구는 API·워치독·일꾼 어디에도 없다(06 ③ 그대로 — 워치독 `UpdateFolderRecovery` 는 `.old` 만). `ClearStale` 은 요청서·작업만 다룬다(`LocalSwapLauncher.cs:122-157`).
- 06ⓑ 의 `swap_interrupted` 도 문구만 바뀌었을 뿐 **잠김은 그대로**다(`:108` 이 여전히 null 이 아닌 거부 사유를 돌려준다).

## 발생 시나리오 (악의 불필요)
1. 되돌리기 성공 → S6 통과 → `Clear-AfterSuccess` 에서 `api.rbk` 지우는 중 Defender 가 그 안 DLL 하나를 검사 중이라 `Remove-Item -Recurse` 실패 → `api.rbk` 반쯤 남음. 상태 `success`.
2. 이후 「업데이트」·「되돌리기」 화면은 항상 「자동 업데이트가 진행 중입니다」. 30분·하루·재부팅 뒤에도 같다.
3. 워치독 자동 업데이트는 `.rbk` 를 모르므로 계속 돈다 — 수동 두 기능만 조용히 죽는다(자동 경로 결함 시 마지막 수단이 사라짐).

## 막는 방향 (한 줄)
「마지막 요청이 끝 상태(success/reverted)인데 `.rbk` 가 남았다」를 바쁨이 아니라 **잔재**로 판정해 다음 교체의 S0 가 문지기 경유로 먼저 치우고 진행(또는 API 기동 시 1회 정리) — 치우기 실패가 두 기능 영구 거부로 번지지 않게.

## 게이트 제안 (대조군)
- 성공 정리 중 `api.rbk` 삭제 실패 주입 → 다음 `CheckBusy` 가 `update_in_progress` 를 돌려주면 FAIL(현 코드 = FAIL 기대). 대조군: `.rbk` 없음 → null.
