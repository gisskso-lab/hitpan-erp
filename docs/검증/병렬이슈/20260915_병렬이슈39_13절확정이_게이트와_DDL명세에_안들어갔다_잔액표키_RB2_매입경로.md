## 근거
1. **G7** 은 두 보관 표만 본다(작지 §11-3). `partner_legacy_balances` 표 · `item_stock.avg_cost decimal(19,6)` ALTER 가 출하 DDL = 마이그인지 단언 없음(#36). 설계 §15 에 `partner_legacy_balances` 칼럼·**UNIQUE 키 명세 없음** → 재이관 멱등(G4 「재실행 0」)의 근거 키 미정.
2. **재이관 이중 잔액 (④)**: DataReset(`DataResetService.cs:111-148`)은 tenant_id 칼럼 있는 표만 지운다. 새 표에 tenant_id 가 빠지거나 PreservedTables(`:47-70`)에 들어가면 덮어쓰기 뒤 잔액이 남아 2배. 병합 모드는 DataReset 을 안 거침 → UNIQUE 키 없으면 병합 재이관마다 누적. ⚠️ F 코드 미도착 — 미확인.
3. **R-B2**: G5 는 계산서 발행·취소만. 확정된 잠금 대상 `SalesService.UpdateDeliveryAsync`(:913 · draft 만 허용이라 이관 명세서 status 확인 필요) · `CancelConfirmedDeliveryAsync`(:1144 · 이관분 확정취소 시 sales_cancel 입고 원장이 레거시 원장과 이중) · `DeleteDeliveryAsync`(:1094 → confirmed 면 :1116 확정취소 위임) 게이트 없음.
4. **「매입 쪽 대응 경로」**(§13 R-B2): PurchaseService 에 매입명세서 확정취소 메서드 없음(grep `CancelConfirmed*`·`Cancel*Receipt*` 0 · 삭제 `DeletePurchaseReceiptAsync`:1930 만) → 잠글 대상이 삭제인지 결정 기록 필요.
5. **정당한 후속 흐름(③)**: 반품 생성(`CreateSalesReturnAsync`:2179 · delivery_id 잔량 검사) · 마이너스 계산서(`IssueCreditNoteAsync`:285 · 반품 기준) · 수금은 잠금 대상 아님 — 잠금을 공용 가드로 넣으면 이 셋이 끊긴다(#20). G5 대조군에 셋 포함 요구.

## 요구
- §11-3 G4·G5·G7 에 위 단언 추가 · §15 에 `partner_legacy_balances` DDL(tenant_id NOT NULL · UNIQUE(tenant_id, legacy_buy_code 또는 partner_id, 기준일)) 명세.
