### 2-1. V-1 ① — 등급 유지, 그러나 **언제 터지는지가 틀렸다**

측정: `scripts/deploy-ncp-secrets.sh:48` 이 `echo "[Service]" > "$OVERRIDE_FILE"` 로 **검사 전에 기존 override 를 먼저 비운다.** 적재 중 모양 안 맞는 줄이 하나라도 있으면 `:87` 에서 `exit 1` ⇒ `:92-98` 의 `chmod 600`·`chown`·`daemon-reload`·`restart` 에 **못 간다.**

🔴 **정정할 것** — 「돌던 자격증명 파손」이라 읽으면 그 자리에서 장애가 보일 것처럼 들린다. 내 재현 결과는 반대다:
- `restart` 를 안 돌았으므로 **돌던 프로세스는 멀쩡하다.** 그 순간 화면·API 전부 정상이다.
- 그런데 디스크의 override 는 이미 **부분본**(내 재현: `[Service]` + 2줄)으로 바뀌었다.
- ⇒ **다음 재기동**(재부팅 · OS 업데이트 · 워치독 · 무심한 `systemctl restart`)에서 `HITPAN_BO_JWT_SECRET` 이 없으면 `Program.cs:76` 이 **기동을 중단**한다 ⇒ **백오피스 전면 다운.**

**시간차 신관이다. 아무도 그 순간을 못 본다.** 등급 P0 유지, 성격은 「즉시 장애」가 아니라 **「장전된 장애」**. #43·#28 축(재부팅 후 자가회복)과 직접 부딪힌다.

### 2-2. V-1 ② — **P2 로 강등** (디렉터리가 덮어 준다)

측정으로 ②의 전제는 **맞았다**: `umask 0022` 에서 override 파일은 **`-rw-r--r--` (0644)** 로 만들어지고, `chmod 600` 은 `:92` — 중단 시 거기 못 간다. 파일은 0644 로 남는다.

그런데 **상위 디렉터리가 막는다**: `:38-39` 가 `mkdir -p` + **`chmod 700`**, 소유자 root. Linux 에서 `drwx------ root root` 면 비root 사용자는 **진입 자체가 안 된다** ⇒ 안쪽 파일이 0644 라도 **읽을 수 없다.** 기밀성은 유지된다.

남는 위험은 심층방어 결함뿐이다:
- ㉠ 실패한 실행 뒤 0644 파일이 **무기한** 남는다(다음 성공 실행까지 아무도 안 고친다).
- ㉡ **root 로 도는 백업·로그 수집기·이미지 스냅숏**에는 그대로 보인다(디렉터리 700 이 root 는 안 막는다).
- ㉢ 나중에 다른 배포 도구가 그 `.d` 디렉터리를 755 로 다시 만들면 **그 순간 전부 노출**된다.

⇒ **P2.** 고치는 값은 싸다(`chmod 600` 을 생성 직후로 올리거나 `umask 077` 한 줄). 다음 차수.

🔴 **V-2 가 안 본 칸이 더 위험하다 — pepper 2개(별도 P1).** V-2 는 서명키 2개만 봤다. 11칸 전수로 재니 이게 나왔다:

| 칸 | 공백이면 소비자가 | 보안 결과 |
|---|---|---|
| `Jwt:Secret` (BO JWT) | 기동 가드 **통과** → HMAC 키 1바이트 | 로그인 전면 불가. 위조 아님. **미측정**: 라이브러리 최소 키길이 거동 |
| `Bootstrap:TokenKey` | 백오피스는 서명, ERP 는 거절 | 설치·웹훅 401 (위 본문) |
| **`License:Pepper`** | 🔴 `?? throw` 를 **통과** → `HMACSHA256(1바이트)` | **예외 0건 · 해시가 계산되고 저장된다** |

| `Toss:*` 2칸 | 결제 호출 실패 | 기능 저하 |

🔴 **pepper 가 치명인 이유 — `HMACSHA256` 은 1바이트 키를 거부하지 않는다.** 서명키는 어디선가 터지지만 pepper 는 **조용히 끝까지 간다**:

1. **#22 무력화** — `license_key_hash` · `fingerprint_hash` 의 존재 이유가 「본사가 평문을 안 가진다」다. pepper 가 추측 가능하면 그 해시는 **역산 가능**해지고, 본사 DB 가 평문을 가진 것과 같아진다. 그리고 그 pepper 를 소비하는 엔드포인트 중 **8개가 `[AllowAnonymous]`** 다(실측: `InstallerBootstrap` · `LandingPublic` · `LandingSignup` · `SerialVerify` · `DeviceRegistration` · `Telemetry` · `CsInbound` · `BackofficeAuth`) ⇒ 인증 없는 외부 트래픽이 그 해시 경로를 민다.
2. **조용한 데이터 손상** — 공백으로 한동안 돌다가 뒤늦게 진짜 pepper 를 넣으면 **그 전에 저장된 해시 전건이 안 맞는다.** 시리얼 조회·기기 등록·텔레메트리 대조가 전부 어긋나고, 오류 메시지는 「없는 시리얼」이라 원인을 못 찾는다.
3. 화면은 이때 **빨강**이다(`Probe` 가 `IsNullOrWhiteSpace`). 사장님이 보시는 화면과 실제 상태가 또 갈린다 — 이번엔 **빨강인데 돌고 있다.**

⇒ **pepper 2칸 = P1**, 그리고 세 차수가 **손대지 않은 자리**다.

### 2-4. V-3 — **P1 유지, 근거 교체**

재현으로 확정했다. `:84` 의 `echo "    - ${s%%=*}"` 는 `=` 가 **없는** 줄에서 아무것도 깎지 못해 **줄 전체를 그대로 찍는다.** 내 scratch 실행 출력이 그 줄을 통째로 보여줬다. ⇒ `:83` 주석 *「값은 찍지 않는다」* 는 **거짓이다.**

**① 출력이 어디로 가나** — `sudo bash` 의 stdout = 사장님 SSH 터미널과 그 스크롤백(§3 에 그렇게 돌리라고 적혀 있다). CI 로도 간다 — `:80-88` 이 `P0GATE` 구간 **안**이라 게이트가 실제로 돌린다. 다만 **CI 유출은 0건**이다: 게이트 고정값이 전부 자리표시자(`aaa`·`bbb`·`ccc`·`망가진줄`)임을 직접 확인했다.

**② 여러 줄 값 비밀이 실제로 있나** — 레포 안에는 **0건**이다(`secrets/` 는 `.gitignore:77` 에 있고 worktree 에 **부재**, 추적 파일 0건 확인). 🔴 **그런데 하나 있다**: `Program.cs:63` 주석이 `HITPAN_SERIAL_SIGN_PRIVATE_KEY` 를 **ECDSA 개인키 PEM** 이라고 적어 뒀다. ### 2-5. V-11 — **익명 노출 0건(실측) · P2**

**① 인증·권한을 직접 읽었다.** `CredentialsStatusController.cs:19-21` 클래스에 `[ApiController]` + `[Authorize]`, 그리고 **세 액션 전부**(`Status`:38 · `Healthz`:105 · `TestMail`:321) 첫 줄이 `if (!IsOwner()) return StatusCode(403, …)`. `[AllowAnonymous]` **0건**. `OwnerClaims.IsOwner` 는 `user?.Identity?.IsAuthenticated != true` 를 먼저 막고, `role ∈ {owner, super_admin}` 또는 `account_type = platform_owner` 만 통과시킨다. 정책 이름이 아니라 코드 판정 한 자리다.

### 🔴 S-2 (P1) systemd `Environment=` 값 미이스케이프 — 들어간 키 ≠ 만든 키

`deploy-ncp-secrets.sh:58` 이 `echo "Environment=\"${key}=${val}\"" >> …` 로 값을 **검사·이스케이프 없이** 그대로 넣는다. systemd 의 `Environment=` 파싱에서 값 안의 `"`·`\` 는 토큰을 끊고, **`%` 는 systemd 지정자**로 해석된다.
