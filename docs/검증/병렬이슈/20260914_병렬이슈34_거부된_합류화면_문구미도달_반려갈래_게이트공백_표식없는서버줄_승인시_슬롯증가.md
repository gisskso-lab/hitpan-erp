## ② 거부 문구가 화면에 닿지 않고, 대표에게 가짜 요청 알림이 매번 간다

- 가드는 `(false, "이 화면이 쓰던 기기 정보가 더는 쓰이지 않습니다. [회사서버 컴퓨터]를 다시 눌러 연결해 주세요.", id, false)` 를 돌려준다.
- `AuthController.cs:162-` 승인대기 갈래 → `response.DeviceNotice = reason` · **`device_pending` 알림 「○○ 님이 새 기기에서 접속했습니다. 확인 후 승인해 주세요.」** 을 대표에게 보낸다(로그인마다).
- `Login.razor:316` 은 `DeviceNewlyRegistered == true` 일 때만 `DeviceNotice` 를 띄운다 — 여기선 false ⇒ **문구 미표시.**
- 관문(`DeviceAuthGate.razor:24-`)은 「기기 등록을 요청했습니다 · 대표님 컴퓨터에서 등록을 허락하면 바로 시작됩니다」.
  - 대표 계정: [회사서버 컴퓨터] 버튼 → `JoinServerRowAsync` 가 `IsMainPc ∧ approved` 줄로 옮김 → 빠져나온다 ✅ (문구 안내는 없음)
  - 대표 아닌 계정: 버튼 없음 → 대표가 [등록 기기 관리]에서 승인 → `ApproveAsync` 「폐기된 기기는 승인할 수 없습니다. 그 기기에서 다시 접속해 주세요」 → 다시 접속하면 또 거부 ⇒ **순환**
- 게이트 G-M8b 는 `reason == GuardMessage` 를 단언하지만 그 문구는 사용자에게 가지 않는다 (「막는 것 ≠ 알려주는 것」 · 병렬 반복사고 계통).
- 미실측: 브라우저 화면 실측 · `gate-status` 의 `Reapplied` 값.

## ③ 표식 없는 서버줄이 대기·반려 상태면 대표 승인으로 PC 슬롯을 먹는다

- 가드 ① 은 `revoked`·`rejected` 로그인만 막는다. `ApproveAsync` 는 **`revoked` 만** 막는다.
- 검증자 실측(격리 33307 · 실제 서비스): 표식 없는 **대기** 서버줄 + 사장님 줄 → 합류 localhost 로그인 = 대기(표 무변화 · 알림 발송 갈래) → `ApproveAsync("서버줄")` 성공 → `approved ∧ is_main_pc=0` · **승인 PC 1 → 2** · 이후 로그인 허용.
- 반려 서버줄: `ApproveAsync` 코드상 같은 길(미실측). ②의 알림이 대표를 그 승인 버튼으로 이끈다. 관문 자기승인 버튼(`_selfApproving`)이 같은 장비넘버로 승인하는지 미실측.
- 도달 가능성: 8/18작4 가 서버줄을 `revoked ∧ 표식0` 으로 내린 뒤 1.3.40 이전 원격 합류 로그인이 `:366` 으로 `pending` 전환했을 수 있다 — 실물 건수 미확인(#39 운영 읽기만).
- §9-4 결재 가드 밖이므로 이번 반려 사유는 아니다. 작지 불변 「요금 계수 무이동」·원칙 「서버가 만든 줄은 브라우저 로그인으로 상태가 안 바뀐다」와 맞닿아 **범위 판단을 PM 결재로 올린다.**
