## 무엇이 문제인가
- PM 결재 X-2 조건 「기동을 막지 않음 · 재시도 0」. 설계 19-1 도 「기동 비차단」이라 적었다. 그러나 **게이트 G-NK5 의 통과 조건은 「요청 1 · 실패여도 `StartAsync` 던지지 않음」뿐** — `StartAsync` 가 `await CheckAsync(...)` 로 끝까지 기다려도 초록이다.
- `UpdateClient.GetLatestManifestAsync` 는 `http.Timeout = 30초`. DNS 는 되는데 443 이 응답 없이 버려지는 망(회사 방화벽·프록시 필수 환경)이면 30초를 다 쓴다.
- 기존 `InstalledVersionLedger`(같은 호스트 · `Program.cs:437`)는 동기 파일 쓰기라 짧다. 새 확인은 **네트워크**라 성격이 다르다. 등록 순서상 뒤에 붙으면 그 뒤 호스트 서비스와 Kestrel 듣기가 모두 밀린다(⚠️가설).
- 이 PC 이력: 웹 자동복구 3연발로 한도 3/3 소진(M-24 · 메모리 9/24). 기동이 30초 밀리면 같은 한도를 기동 지연만으로 소진할 수 있다(⚠️가설).

## 요청 모양(#18/#22 · 필수 #5) — 판정: 깨끗
- 피드 요청 = `GET {feed}/manifest.json`(`UpdateClient.cs:72-73`) · 쿼리 0 · 헤더 추가 0 · 기본 `HttpClient`(`Program.cs:231` `AddHttpClient()` · 전역 기본값·처리기 덧붙임 0 grep 확인) ⇒ User-Agent 도 안 보낸다. 받기 요청도 같은 클라이언트(`:211-214`).
- 다만 **G-NP6 는 받기 요청만** 잰다. 기동 확인 요청의 모양은 G-NK5 가 「요청 1」로 세기만 한다 ⇒ 나중에 누가 기동 확인에 고객 식별을 붙여도 초록. PM X-2 조건 「요청 모양 = 기존 피드 호출과 동일」의 게이트가 없다.

## 막는 방향 (적발만 · 결정은 설계)
- `StartAsync` 는 일을 **띄우고 바로 돌아온다**(`Task.Run`/`BackgroundService` · 앱 종료 토큰 연결 · 예외는 `LogWarning` 한 줄).
- G-NK5 에 두 줄 추가: (a) 응답을 **영원히 안 주는** 가짜 처리기 → `StartAsync` 가 짧은 상한(예: 1초) 안에 끝나야 통과 · 대조군 = `await` 로 기다리는 사본 → 상한 초과 FAIL (b) 기동 확인 요청에도 G-NP6 와 같은 모양 단언(쿼리 0 · 기본 밖 헤더 0 · tenant·사용자 글자 0).
