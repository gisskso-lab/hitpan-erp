## 1. 적발

### S-1 🟠 중 — my-level 이 대표 판정 예외에 묶여 다른 화면 동작이 바뀜
- 근거: `src/HitPan.API/Controllers/UserController.cs:373-378`(작업 사본) — 관리자면 `await dataReset.GetResetGateAsync(...)` 를 try 없이 부름. 이 질의가 예외(연결 끊김 · 잠금 대기 시간 초과 등)면 my-level 전체가 500.
- my-level 을 관리자로 읽는 곳은 사이드바만이 아님: `src/HitPan.Web/Pages/Users.razor:693` · `src/HitPan.Web/Pages/Settings/EmployeePage.AccountLink.cs:47` 가 `isAdmin` 을 읽어 버튼을 가름. 500 → 모델 null → `isAdmin=false` → **대표 · 관리자에게 계정 연결 버튼이 사라짐.** 종전에는 단계 질의 하나만 성공하면 됐다.
- 덧: 위 두 화면이 뜰 때마다 users 집계 질의 1번이 더 돈다(관리자 한정 · 가벼움).
- 권고: 컨트롤러에서 판정만 감싸 `catch (Exception ex) { _logger.LogWarning(ex, ...); dataResetGate = not_parent; }` (#15 · 못 읽으면 안 보임 원칙) — `level` · `isAdmin` 은 판정 실패와 무관하게 그대로 돌려줌. 시험: 판정이 던지는 가짜 서비스로 my-level 200 + `isAdmin` 유지 + `dataResetGate=not_parent` 대조.

### S-2 🟡 하 — 시험 이름이 CI 에 먼저 들어가 「0건 초록」 자리가 생김 (진행 중 확인 거리)

### S-3 🟡 하 — 판정 순서상 대표 아닌 관리자도 「대표 없음」 상태를 앎 (V3)

- 노출 정도: 코드 글자 4종뿐 · 대표 이름 · 아이디 · 수 0. `multiple_parents` 는 본인이 대표일 때만 닿음(:250 이 먼저 거름). **받아들일 수준.**
- 덧(하): 종전 단일 문구(「비밀번호가 일치하지 않거나 부모계정이 아닙니다」)가 코드별로 갈려, 비번 없이 「내가 대표인가」 를 알 수 있게 됨 — 이미 관리자 문 안이라 받아들임.
