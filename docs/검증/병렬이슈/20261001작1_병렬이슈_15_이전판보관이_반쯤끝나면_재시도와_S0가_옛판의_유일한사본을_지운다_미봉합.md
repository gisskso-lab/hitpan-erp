## 무엇이 문제인가
- 업데이트 모드 성공 정리 `Clear-AfterSuccess`(`local-swap.ps1:894-896`) → `Save-PrevGeneration`(`:864-892`):
  ① 옛 `rollback\prev` 를 먼저 지운다(`:869`) ② `foreach` 로 `{p}.rbk → prev\{p}` 를 `Move-Part` 로 옮긴다(`:875`) ③ 그 뒤에야 `version.txt`·`sha256.txt`(`:876-886`).
  ②가 한 부분에서 던지면(`Move-Item` 폴더 이름바꾸기 실패 — 안쪽 파일을 백신이 쥐고 있는 순간 등 ⚠️) catch 가 로그 한 줄만 남기고 끝난다(`:888-891` 「best effort」). ⇒ `prev` 는 **일부만** 있고 `version.txt`·`sha256.txt` 없음, 나머지 `{p}.rbk` 는 앱 루트에 남는다 = **이 시점 옛 판의 유일한 사본**.
- 봉합2 전: 남은 `.rbk` 는 그대로 있었다(병렬이슈 09 의 영구 잠김 — 그러나 옛 판은 손으로라도 되살릴 수 있었다).
- 봉합2 후:
  - 같은 실행 안 재시도 `Get-SuccessLeftover`(`:936-946`)는 **보관을 다시 시도하지 않고** `Remove-AppDirSafe({p}.rbk)` 로 **지운다**(`:943`). 10초 간격 3회 — 백신 잠금이 풀리는 바로 그 시간을 지우기에 쓴다.
  - 다 지워지면 `Get-RbkLeftReason` = null ⇒ 끝 상태는 **사유 없는 `success`**(`:1058-1059`). 화면·사용 기록 어디에도 「이전 판 보관 실패」가 없다.
  - 재시도도 못 지우고 남으면, 런처는 M5(세 폴더 있음 · 판 맞음 · broken 아님)로 통과시키고(`LocalSwapLauncher.cs` `JudgeLeftoverRbk`) 다음 교체의 일꾼 S0 `Clear-Leftover`(`:809-834`)가 같은 `.rbk` 를 지운다.
- `RollbackMaterialFinder.cs:124-125` 는 `sha256.txt`·`version.txt` 없는 `prev` 를 재료로 안 본다 ⇒ 바로 앞 판 재료 = 없음 → 다른 재료(워치독 zip)로 넘어가면 병렬이슈 05 경로.
- 설계 §15-0 판정표의 근거 「S0 에서 보이는 `.rbk` 는 끝났거나 끊긴 지난 교체의 것」은 맞지만, **업데이트 모드에서 끝난 교체의 `.rbk` 는 「치울 잔재」가 아니라 「아직 `prev` 로 못 간 보관 대상」**일 수 있다 — 표에 이 모양이 없다.

## 발생 시나리오
1. 1.3.50 → 1.3.51 수동 업데이트. S4 교체·S5 기동·S6 검증 통과.
2. 성공 정리: 옛 `prev`(1.3.49) 지움 → `api.rbk → prev\api` 이름바꾸기 중 백신이 `api.rbk` 안 dll 하나를 검사 중 ⇒ 던짐 ⇒ 「previous generation save failed」.
3. 재시도 3회: 10초 뒤 잠금은 풀렸지만 코드는 `api.rbk`·`web.rbk`·`watchdog.rbk` 를 **지운다**(첨부는 문지기가 먼저 실어 무손실).
4. 끝 = `success`, 사유 없음. 사장님이 「이전 버전으로 되돌리기」를 누르면 되돌릴 판(1.3.50)이 없다 — 1.3.49·1.3.50 모두 이 PC 에서 사라졌다.

## 막는 방향 (한 줄)
업데이트 모드에서 `prev` 가 완성되지 않았으면(`version.txt`·`sha256.txt` 없음) 재시도·S0 는 `.rbk` 를 **지우지 말고 `prev` 로 옮기기를 다시 시도**하고, 끝내 못 하면 정직한 사유(예: 보관 실패)를 `success` 옆에 적는다 — 판정표에 「업데이트 성공 뒤 보관 미완」 모양 추가.

## 게이트 제안 (대조군)
- rig 업데이트 모드: `Save-PrevGeneration` 두 번째 `Move-Part` 에서 던지게 주입(`web.rbk` 한 파일 `FileShare.None` 으로 쥐었다가 재시도 전 놓음) → 기대: `prev` 세 폴더 + `version.txt`·`sha256.txt` 완성 또는 사유 있는 `success`. 현 코드 = `.rbk` 소실 + `prev` 반쪽 + 사유 null ⇒ FAIL.
- 대조군: 주입 없음 → `prev` 완성 · 사유 null(통과해야).
