### P3-1 잠금 대기 = 스레드 풀 스레드를 붙잡음 · 취소 토큰 미전달 · 타임아웃 없음 (서비스 거부 꼴 · 미측정)
- `lock`(Monitor) 대기는 비동기 대기가 아니라 요청 스레드를 막는다. 세금계산서는 한 장에 재기 생성이 이진 탐색으로 여러 번(`ResolveVisibleLineCount` :1621 · `ResolveCopyPageChunks` :1657) 잠금을 잡았다 놓는다. 품목이 아주 많은 전표 · 급여 일괄 메일(`PayslipMailService:98` 순차) 중에 다른 직원 인쇄 · 미리보기는 줄 선다. 동시 요청이 코어 수를 넘으면 대기 스레드가 쌓여 로그인 등 다른 API 까지 늦어질 수 있다(1V 처리량 2.5배 저하 실측과 같은 방향).
- `RenderDocumentAsync(..., ct)` 의 `ct` 는 통로까지 안 온다 → 접속이 끊긴 요청도 줄을 끝까지 서서 생성한다(연타 · 새로고침이 줄을 늘림).
- 「한 회사의 큰 PDF 가 다른 회사를 막는」 꼴: 고객 PC 로컬 ERP 는 프로세스 = 한 회사라 회사 사이 영향은 다중 테넌트로 도는 시험 · 시연 환경에서만이다. 회사 안 직원 사이 대기는 실재.
- 타임아웃 없음은 지시서 §11 결재 6 · §13 ⑥ 채택 사항이라 반려 사유 아님. **「동시 N 명 인쇄 시 다른 API 응답 시간」 측정이 0 이다** — 지시서 :170 「생성 하나가 멈추면 전 인쇄가 멈춤 · 미측정」 그대로. 베타 전 측정 한 번 권고.
