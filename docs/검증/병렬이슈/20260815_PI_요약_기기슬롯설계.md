## 게이트 신설 권고 (총 7개)

현행 G-1~G-10 은 **전부 "합쳐지면 정답" 방향**이라 **과소 계수를 구조적으로 못 잡는다.**

| 게이트 | 검사 | 출처 |
|---|---|---|
| **G-11** | 기기 A 의 인증키를 B 에 넣음 → **2줄이어야 통과** | PI-08 |
| **G-12** | 장비넘버 없이 인증키만 → ①에 **안 걸려야** 통과 | PI-08 |
| **G-13** | 같은 기기 **동시 로그인 2건** → 1줄 | PI-13 |
| **G-14** | 남의 장비넘버 심기 → **2줄이어야 통과** | PI-13 |
| **G-15** | 다른 회사 장비넘버 → 남의 줄에 **안 붙는다** (#2 회귀) | PI-13 |
| **G-16** | `enterprise` 가 **자기 한도**를 받는가 | PI-14 |
| **G-17** | 모르는 티어 → **경고 로그**가 남는가 | PI-14 |

🔴 **G-8 은 다시 써야 한다** — *"코드 리터럴에 없는지"* 는 상수를 옮기면 통과한다.
⇒ **"DB 값을 바꾸면 재빌드 없이 한도가 바뀌는가"** 로 교체.
작지서가 인용한 **8/15 메신저 교훈(`ChatWindowGuardTests` 가 글자만 검사)** 이
**G-8 에 그대로 재현돼 있다.** 교훈을 적어놓고 같은 형태를 다시 만들었다.
