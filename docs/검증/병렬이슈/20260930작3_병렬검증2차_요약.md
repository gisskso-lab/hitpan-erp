### 2-2. 대조 실험 — 명령줄 이스케이프가 따옴표 밖으로 새나

`EscapeSqlLiteral` 과 `sql.Replace("\"","\\\"")` 을 그대로 흉내 내 `ProcessStartInfo.Arguments` 로 C 런타임 프로그램(py)에 넘겨 `-e` 값을 되읽었다(스크래치 · DB 무접촉).

| 넣은 detail | `-e` 로 도착한 SQL 안 리터럴 | 판정 |
|---|---|---|
| `'; DROP TABLE t; --` | `'\'; DROP TABLE t; --'` | 리터럴 안 ✅ |
| `q\"'; SELECT 1; -- ` | `'q\"\'; SELECT 1; -- '` | 리터럴 안 ✅ |
| `end\` | `'end\\'` | ✅ |
| `x\"` · `a\\"b` | `'x\"'` · `'a\\"b'` | 리터럴 안 ✅ — 단 `"` 바로 앞 역슬래시가 **반으로 준다**(표시 손실뿐 · 탈출 아님) |

⇒ 명령줄 단계에서 `"` 앞 역슬래시는 늘 홀수가 되어 `"` 는 글자로만 도착하고, SQL 구분자 `'` 앞 역슬래시 수는 바뀌지 않는다. **탈출 경로 없음.** 지금 detail 은 전부 고정 문구라 손실도 실제로는 0.

## 4. 조건 (조건부의 이유 — 코드 결함 아님)

1. **병렬이슈 01·02·04 문서 상태가 아직 「🔴미봉합」**(카드 머리 · `INDEX.md:60-63` · `INDEX_ALL.md:7-10`). 코드는 §1 대로 봉합돼 있다. 문서는 지우지 않고 상태만 바꾼다 — PM 이 봉합 커밋·게이트 이름을 붙여 「✅봉합」으로 바꿔야 [4] §6 이 「봉합됐나」를 문서로 가를 수 있다. 02 는 DB 게이트라 **CI `db-gate` 초록 + `[SKIP]` 0** 을 확인한 뒤에 바꾼다.
2. **병렬이슈 03 의 N-UPD7 필수조건이 인계 문서에 안 옮겨졌다.** 작업지시서 `docs/운영기록/20260929작3_업데이트미완료안내_동의막다른길_작업지시서.md:57` · 설계 `docs/설계/erp/20260929_설계_업데이트미완료안내_N-UPD2-4.md:132` 는 여전히 「N-UPD7 은 **규칙 C 를 따라** 고친다」고만 적는다 — 03 이 경고한 **바로 그 함정**(익명 새 approve 반복 → 업무 중 ERP 반복 정지)이다. 작업리뷰서 ⑥(「로그인 사용자 기준」 범위 표기)도 미결로 남아 있다. N-UPD7 착수 전 (a) 로그인 전 승인은 메인PC 에서만 (b) 최신이 [나중에]면 익명 approve 거부 (c) 이미 쓴 approve 뒤 익명 새 approve 금지 · 게이트 「익명 N회 → 동의 행 ≤ 1」 이 작업지시서에 들어가야 한다.

## 5. 참고 (P3 · 적발 아님)

- **R4 뒤 남는 표식.** 검증 중 전원 종료(R4)면 표식이 영구히 남는다(`RecoverAtStartup` 은 R4 를 손대지 않고 표식도 안 지운다). 그 뒤 다음 교체의 `ClearStaleOldDirsForSwap` 이 `web.old` 는 잠겨 못 지우고 `api.old` 만 지운 **바로 그 순간** 전원이 꺼지면 R3 모양 + 옛 표식 ⇒ 기동 복원이 R4 시절 옛 web 을 되돌린다(새 api·옛 web). 창이 밀리초 단위라 실사용 빈도는 무시할 만하나, `ClearStaleOldDirsForSwap` 앞에서 옛 표식을 지우면 창이 닫힌다 — 설계팀 판단 몫.
