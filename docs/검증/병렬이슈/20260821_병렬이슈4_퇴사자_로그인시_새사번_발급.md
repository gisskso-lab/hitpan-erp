## 0. 🔴 PM 정정 — 1차 작성분이 틀렸다

**1차에 *"퇴사자가 로그인된다"* 라고 적었다. 틀렸다.**

`AuthService` 에서 `is_active`(스네이크)만 grep 해서 **`user.IsActive`(프로퍼티)를 놓쳤다.**
시험을 돌렸을 때 `로그인이_퇴사자를_차단한다` 가 **예상과 달리 통과**했고,
그 초록불을 그냥 넘기지 않고 파고들어 잡았다.

> ⚠️ **교훈**: 예상과 다른 초록불은 **시험이 틀렸거나 내가 틀렸다는 신호**다.
> 넘겼으면 **이미 있는 방어를 또 만드는** 헛작업을 했다.

### 실측 — 로그인은 이미 막힌다 ✅

```
ResignAsync   UPDATE employees SET is_active = 0
              UPDATE users     SET is_active = 0     ← 🔴 계정도 끈다
                   ↓
LoginAsync    if (!user.IsActive) throw "비활성화된 계정입니다"
```

⇒ **사장님 지시 ②("모든 기능 비활성")는 로그인 축에서 이미 지켜지고 있다.**

## 1. 진짜 결함 — 백필의 퇴사자 미구분

`BackfillParentEmployeeAsync` 는 **고아 계정 자가치유**용이다(2026-06-22·08-14 봉합).
그런데 판정이 `IsActive` 하나뿐이다:

```csharp
var already = existing.FirstOrDefault(e => e.UserId == user.Id && e.IsActive);
if (already is not null) return already;
   ↓ 퇴사자는 is_active=0 이라 already = null
★ 새 employees 행 INSERT + 새 사번 채번 ★
```

🔴 **퇴사자와 고아 계정을 구분하지 않는다.**
- 고아 계정 = employees 행이 **없다** → 만들어 주는 게 맞다 ✅
- 퇴사자 = employees 행이 **있는데 꺼져 있다** → 만들면 **중복 행** 🔴

## 2. 지금은 왜 안 터지나 · 🔴 언제 터지나

| 시점 | 도달 |
|---|---|
| **지금** | ⚠️ 어렵다 — `ResignAsync` 가 계정을 꺼서 로그인 자체가 막힌다 |
| 🔴 **재입사 기능 후** | **열린다** — 부모계정이 계정을 되살리는 순간 |

### 재입사에서 벌어지는 일 (설계 주의)

```
부모계정이 재입사 처리  →  users.is_active = 1 로 되살림
                        ↓
        (employees.is_active 를 아직 안 켰다면)
본인이 로그인            →  백필이 먼저 돈다 → ★새 사번 발급★
                        ↓
        퇴사 기록 1행 + 새 재직 1행  = 같은 사람이 둘
```

⇒ 사장님 지시 ③ *"재입사도 상태변경으로"* 가 **깨진다.** 상태변경이 아니라 **새 사람이 생긴다.**

🔴 **그래서 순서가 정해진다: 백필 차단 → 그다음 재입사 기능.**
