## 1. 🔴 P0-1 — `await` 가 ERP 정지 구간을 늘린다

### 1-1. 무엇이 문제였나

초안은 보고를 `await` 했다. **예외는 잘 막았는데 지연을 못 막았다.**

```csharp
await ReportUpdateHistoryToHqAsync(manifest, result, detail, ct);   // ← 초안
```

호출 위치가 급소였다:
```
_lock.Acquire()                          ← ERP 정지 시작
  ...
  RecordApplyStatusAsync("success")      ← :235  여기서 본사 응답을 기다림
  CleanupAfterSuccess()
finally { RestoreKeepalive() }           ← :248  ERP 복귀
```

⇒ **본사가 죽지 않고 '느리기만' 하면**(TCP 는 붙는데 응답 없음 — nginx 과부하·DB 락·패킷 유실)
   타임아웃을 꽉 채운다. 그동안 **고객 ERP 는 내려가 있다.**

> 완전히 죽으면 즉시 RST 라 오히려 빠르다. **어중간하게 느린 게 최악**이다 —
> 초안 검증(V-7)은 '죽은 본사'만 시험해서 이걸 못 봤다.

### 1-2. 실측 (봉합 전/후 대조)

블랙홀 주소(`10.255.255.1`, SYN 무응답)로 '느린 본사'를 재현:

| 방식 | 호출부 대기 |
|---|---|
| **봉합 전 (await)** | **5.3초** ← 그만큼 ERP 가 더 내려가 있다 |
| **봉합 후 (fire-and-forget)** | **0.00초** |

봉합 후에도 **보고 자체는 백그라운드에서 계속 진행**돼 정상 종료됨(타임아웃 로그로 확인).

### 1-3. 봉합

```csharp
// ⚠️ ct 를 넘기지 않는다 — 넘기면 업데이트 종료와 함께 보고가 취소된다.
_ = ReportUpdateHistoryToHqAsync(manifest, result, detail, CancellationToken.None);
```
- 흐름에서 완전히 분리(`await` 제거)
- 타임아웃 **10초 → 5초** (오래 붙들어서 얻는 것이 없다)

> 놓친 보고는 다음 업데이트의 현황(`current_version`)이 따라잡는다. **정확성보다 고객 ERP 가 우선이다.**

## 2. 🔴 P0-2 — 사장님 오더 3시점 중 ③ 이 통째로 빠졌다

### 2-1. 무엇이 문제였나

작4 §3-6 은 **성공·실패·거부 3시점** 보고를 명시했다. 그런데 거부는 구현되지 않았다.

`RecordApplyStatusAsync` 호출부 전수(실측): `blocked`·`rolled_back`·`success`·`rollback_failed` **4종뿐.**
**`"rejected"` 를 넘기는 호출부 0건** ⇒ 그 switch 분기는 **도달 불가 코드**였다.

실제 거부 경로(`Worker.cs:444`)는 로그만 찍고 펜딩을 해제한다 — 보고 경로를 지나지 않는다.

### 2-2. 왜 P0 인가 — 사장님이 이 기능을 요구한 이유가 정확히 이것이다

> **A 케이스**(사장님 2026-07-20): *귀찮아 업데이트 안 한 고객 → 이미 고친 문제 겪음 →
> CS 가 버전 보고 "업데이트하세요"로 간단 조치.*

거부가 안 잡히면 **"이 고객사가 왜 계속 구버전인가"를 CS 가 영영 모른다.**
현황 테이블의 `current_version` 도 안 올라가니 화면상 구버전으로만 보이고 **이유가 없다.**

### 2-3. 봉합

`UpdateOrchestrator.ReportConsentRejected(manifest)` 신설 → `Worker.cs:449` 거부 분기에서 호출.

실측 — 3시점 전부 배선 확인:
```
① 성공 : 1건    ② 실패 : 6건    ③ 거부 : 1건
```

> 🔴 **거부는 정상 동작이다**(고객 통제권 — 헌법 #24). 보고만 하고 아무것도 강제하지 않는다.

## 3. P1-1 / P2-1 — 함께 봉합

**P1-1 `unknown` 해시 충돌**: `GetTenantId()` 는 db.conf·env 를 못 읽으면 `"unknown"` 을 준다.
`sha256("unknown")` 은 **모든 PC 에서 같은 상수**라, 현황 테이블 PK 가 충돌해 여러 고객사가
**한 행을 서로 덮어쓴다.** 라이선스는 각자 유효해 401 로도 안 걸러진다.
⇒ 송신측에서 `unknown` 이면 보고를 생략하고, 서버도 거부한다(2중).

**P2-1 인스톨러 템플릿 누락**: `.iss` 가 `appsettings.json` 을 통째로 새로 쓰는데 새 키가 없었다.
`.Bind()` 라 C# 기본값이 살아 **동작에는 지장 없으나**, 현장에서 경로를 바꿀 자리가 없다.
⇒ 템플릿·appsettings 양쪽에 추가.
