| 작업 | [20260904작21](../../운영기록/20260904작21_MDB마이그v2_대사표_P0봉합_작업지시서.md) A5 지급 이관 (`MigratePaymentsAsync` 신설) |

## 무엇이 잘못됐나

작업지시서 A5 가 `payments.payment_type='payment'` 로 넣으라 했고 갈래 A 는 **지시대로** 짰다.
그런데 ERP 가 매입 지급을 읽는 자리는 **전부 `'purchase'`** 다.

| 읽는 자리 | 값 |
|---|---|
| `src/HitPan.Web/Pages/Finance/PaymentPage.razor:454,511` — 지급 입력 화면이 **저장하는** 값 | `"purchase"` |
| `CollectionService.cs:456` `GetPayablesAsync` — 지급 목록 | `payment_type = 'purchase'` |
| `FinanceService.cs:843` — 대시보드 미지급 KPI 차감 | `payment_type='purchase'` |

```csharp
// 🔴 짤 때 (작지서 A5 그대로)
.Append(",'payment',@A")
// ✅ 봉합
.Append(",'purchase',@A")
```

## 🔴 왜 작지서가 틀렸나 — **주석은 코드가 아니다**

PM 이 작지서를 쓸 때 `payments` DDL 의 COMMENT `receipt:… payment:…` 를 근거로 삼았다.
그 주석은 **설계 당시 어휘**이고, 실제 화면은 다른 값을 쓴 채 굳어 있었다.
**값을 넣을 때는 그 값을 읽는 화면·식을 grep 해야 한다.** 이 팀이 8/25 에 두 번 속은 자리와 같다.

## 🔴 왜 게이트가 못 잡았나 — **게이트가 작지서를 믿었다**

갈래 A 의 배선 게이트 W5 는 `Assert.Contains("'payment'", pay)` 로 **작지서의 오기를 그대로 기대값**으로 두었다.
게이트 64/64 초록불이었다. **기대값이 틀리면 게이트는 오류를 통과시키는 장치가 된다.**
⇒ 게이트 기대값도 **읽는 쪽 코드**에서 뽑아야 한다.

## 어떻게 잡혔나

갈래 B 가 대사표 ⑨ 미지급 식을 `FinanceService` 에서 **그대로 복사**하면서
"작지서 A5 와 어긋난다 — 그대로면 ⑨ 는 봉합 후에도 DIFF" 라고 보고에 적었다.
**같은 값을 쓰는 쪽과 읽는 쪽을 서로 다른 사람이 짰기 때문에** 어긋남이 드러났다(SoD 의 부수효과).

## 터졌으면 무슨 일이 났나

- 지급 2,228건(실측)이 DB 에는 있는데 **지급 목록에 0건**, 미지급 KPI 는 **매입 전액 그대로**(영구 과대 — 6/23 C2 P1 과 같은 모양, 헌법 #20)
- 대사표 ⑨ 미지급이 **봉합 후에도 DIFF** → 사장님이 *"안 맞는다"* 를 보시고서야 드러난다

## 봉합

| 자리 | 변경 |
|---|---|
| `MdbMigrationService.MigratePaymentsAsync` | `'payment'` → `'purchase'` (리터럴 1곳) + 요약주석에 근거 3곳 명기 |
| `MdbMigrationV2MappingGateTests.W5` | 기대값 `'payment'` → `'purchase'` |
| 무력화 | `'purchase'` 를 `'payment'` 로 되돌리면 **W5 FAIL** (실측 — 작업리뷰서 게이트 결과 참조) |

## 교훈

| | |
|---|---|
| 🔴 | **DDL COMMENT 도 주석이다** — 값 어휘는 그 값을 **저장하는 화면**과 **읽는 식**에서 grep 한다 |
| 🔴 | **게이트 기대값을 작지서에서 베끼지 마라** — 작지서가 틀리면 게이트가 그 오류를 지킨다 |
| 🟢 | 쓰는 쪽(A)과 읽는 쪽(B)을 **다른 사람**이 짜면 어휘 어긋남이 저절로 드러난다 — 대사표는 그 자체가 검증장치 |
