## 3. 진범

`MigrationRunner` 는 `_connFactory.CreateOpenAsync()` → **`MigrationDbConnectionFactory`** 의
연결을 쓰는데, 그 연결문자열에 **`AllowUserVariables=true` 가 없었다.**

멱등 마이그(DB-88·89·90)는 이 관용구를 쓴다:

```sql
SET @col_exists := (SELECT COUNT(*) FROM information_schema.columns WHERE ...);
SET @sql := IF(@col_exists = 0, 'ALTER TABLE ...', 'SELECT 1');
PREPARE stmt FROM @sql; EXECUTE stmt; DEALLOCATE PREPARE stmt;
```

옵션이 없으면 MySqlConnector 가 `@col_exists` 를 **파라미터로 착각**해 실행 자체를 거부한다.

⚠️ 같은 문법을 쓰는 마이그는 **DB-03 · DB-75 · DB-88 · DB-89 · DB-90** 5건이다.
(DB-03·DB-75 는 이미 적용된 기존 고객에겐 skip 되어 드러나지 않았다.)

## 4. 🔴 왜 못 봤나 — 개발PC 가 거짓 신호를 줬다

PM 은 마이그를 **`mysql.exe` 로 직접 넣어** 확인했다. 그 경로는 이 옵션과 무관해 **정상 통과**했다.
히트판이 실제로 쓰는 경로는 다르다.

> 사장님 원칙(`feedback_dev_pc_proves_nothing`): **"개발환경 PC 정상작동은 큰 의미 없다"**
> 오늘 그 원칙이 그대로 맞았다. 빌드 0/0 도, mysql.exe 통과도 검증이 아니었다.
> **검증은 히트판이 실제로 쓰는 경로로 해야 한다.**

## 5. 봉합
