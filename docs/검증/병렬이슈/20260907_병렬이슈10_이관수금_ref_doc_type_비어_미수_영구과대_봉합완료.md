# 병렬이슈 10 — 이관 수금의 **`ref_doc_type` 이 비어** ERP 미수 식이 한 푼도 차감하지 않았다

| 항목 | 값 |
|---|---|
| 적발 | **[3-V] 동시검증** · 2026-09-07 · 갈래 B 가 ERP 미수 식을 복사하다 발견 |
| 작업 | [20260904작21](../../운영기록/20260904작21_MDB마이그v2_대사표_P0봉합_작업지시서.md) A5 수금 이관 (`MigrateCollectionsAsync`) — **5월 이관 코드부터 있던 결함**, 작지서에도 없었다 |
| 등급 | 🔴 **P0** — 이관 고객의 **미수금이 매출 총액 그대로** 뜬다(수금 121억이 있어도 0원 차감) |

## 무엇이 잘못됐나

ERP 의 미수 식은 **`ref_doc_type='sales_delivery'` 인 수금만** 뺀다 — 세 곳이 같다.

| 자리 | 식 |
|---|---|
| `FinanceService.cs:834` 대시보드 미수 | `− SUM(amount) FROM collections WHERE … AND ref_doc_type = 'sales_delivery'` |
| `CollectionService.cs:396` 미수 집계 | 같은 조건 |
| `SalesService.cs:1291` 명세서별 수금 | 같은 조건 |

이 조건은 6/23 6차 전수조사 C2 봉합이 **일부러 좁힌 것**이다(`IN('sales_delivery','sales_order')` 가 다른 집계와 불일치라서).
수금 입력 화면(`CollectionPage.razor:495,552`)은 **항상** `RefDocType = "sales_delivery"` 로 저장하므로 화면 경로는 문제가 없다.
**이관 경로만** `ref_doc_type` 을 안 채웠다 — 5월부터. 선행검증서 P0-E 는 계열(수금/지급) 분리만 봤고 이 컬럼은 못 봤다.

```sql
-- 🔴 이관 INSERT (5월~) — ref_doc_type 없음 ⇒ NULL
INSERT IGNORE INTO collections (collection_id, …, collection_method, memo, …)
-- ✅ 봉합 — 화면과 같은 값. ref_doc_id 는 특정 명세서에 안 묶이니 NULL 그대로
INSERT IGNORE INTO collections (collection_id, …, collection_method, ref_doc_type, memo, …) VALUES (…, 'sales_delivery', …)
```

봉합 자리 4곳(모두 `MdbMigrationService.cs`): legacy fallback INSERT · BulkCopy 컬럼 매핑 · stage→본표 `INSERT IGNORE … SELECT` · `BuildCollectionsDataTable` 컬럼+값.

## 🔴 왜 아무도 못 잡았나 — **"넣었나" 만 재고 "읽히나" 를 안 쟀다**

5월 30차 *"99.7% 정합"* 은 `collections` 행수·합계를 **표에서 직접** 세었다. 표에는 잘 들어가 있었다.
그 표를 **미수 식이 어떻게 읽는지**는 아무도 안 봤다. *"고쳤다 ≠ 갔다"* 의 데이터 판이다.

## 어떻게 잡혔나

갈래 B 가 대사표 ⑧ 미수 식을 ERP 식 **그대로** 복사한 뒤 *"이관 collections 는 ref_doc_type 을 안 채우므로 ⑧ 은 봉합 후에도 안 맞는다"* 고 보고했다.
**대사표를 ERP 화면 식과 똑같이 만들었기 때문에** 드러났다 — 대사표가 ERP 식과 다르게 "표 합계" 로 만들어졌다면 초록불이 났을 자리다.

## 터졌으면 무슨 일이 났나

이관 고객 대시보드 미수 = **매출 총액**(공영정보 기준 121억). 수금 111,819건이 DB 에 있는데 **한 푼도 안 빠진다.**
업체별원장도 같은 식이라 거래처마다 미수가 매출 전액으로 뜬다 — *"레거시와 같은 값"*(오더 1) 정면 위반.
