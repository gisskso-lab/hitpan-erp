## 2. 뜻

| # | 무엇이 되나 | 근거 |
|---|---|---|
| B1 | **로컬 Windows 사용자 누구나 덤프 파일을 읽는다** — `Users (OI)(CI)(RX)` 가 파일까지 내려간다. 덤프에는 평문 업무 컬럼 전부·비번 해시·암호문 컬럼이 들어 있다 | A1·A3 |
| B2 | 같은 계정은 `C:\Program Files\HitPan\db.conf` 를 **읽지 못한다**(접근 거부) → **자료 전체(덤프)가 자격증명 파일보다 약하게 보호된다** | 원인분석 C §3 E11 |
| B3 | **폴더 선점** — `Users (CI)(WD,AD)` 로 일반 사용자가 API 보다 먼저 `Backup` 을 만들 수 있다. 만든 사람이 `CREATOR OWNER` 로 소유·완전 제어 → 이후 API 가 거기 쓰는 덤프를 읽고, 권한을 바꾸고, 폴더를 다른 곳을 가리키는 연결점으로 바꿀 여지 | A1 · 🟡 공격 경로(재현 안 함) |
| B4 | 대조 ① 지금 실제로 떨어지는 `C:\Windows\System32\HitpanBackup` — System32 도 Users 읽기 상속이라 **읽기(B1)는 같다**. 그러나 일반 사용자는 System32 에 하위 폴더를 못 만든다 → **선점(B3)은 K2 에서 새로 생긴다** | 🟡 System32 표준 ACL(이 PC 미조회) |
| B5 | 대조 ② 원래 의도한 기본값(API 실행 계정의 문서 폴더)은 그 계정 전용이다 → K2 는 **의도 대비 기밀성 후퇴** | `BackupService.cs:51-53` |
| B6 | 대안 `C:\HitpanBackup`(K2 대안) 은 `C:\` 루트 하위라 인증된 사용자 수정 권한이 상속될 수 있어 **더 나쁠 수 있다** | 🟡 미조회 |

⬜ 전제: API 실행 계정(원인분석 C §3 E10 — 조회 거부). SYSTEM 이면 B3 의 영향이 커진다.
