## 무엇이
- `TenantAdminOnly` = `account_type == tenant_admin`(`Program.cs:394-396`). 자식 계정도 role=TenantAdmin 이면 `tenant_admin`(`UserService.cs:249` · `:123`). 「대표」를 가르는 클레임 없음(`is_parent` 클레임 grep 0).
- `UserService.UpdateAsync`(:243-306) 의 대표 가드는 `is_active=false` 만 거절(:263-264). **`role`·`account_type` 은 대표에게도 그대로 쓴다**(:279-280) ⇒ 직원 관리자가 `PUT /api/users/{대표id}` `role=User` → 대표가 `tenant_user` → 대표가 TenantAdminOnly 화면·API 전부 403, 스스로 못 되돌림.
- `ResetPasswordAsync`(:345-361) `WHERE user_id AND tenant_id AND is_deleted=0` — **`is_parent` 조건 없음** · 응답에 임시 비번 원문(`UserController.cs:206`) ⇒ 직원 관리자가 `POST /api/users/{대표id}/reset-password` 로 **대표로 로그인**.

## 재현(시험 환경)
1. 대표가 직원 X 를 role=TenantAdmin 으로 만든다. X 로 로그인.
2. `POST /api/users/{대표id}/reset-password` → 200 + `tempPassword` → 대표 아이디로 로그인 성공.
3. 또는 `PUT /api/users/{대표id}` `{role:"User", isActive:true, ...}` → 200 → 대표 재로그인 후 `POST /api/users/{id}/suspend` 403.
- 대조군: 같은 X 로 `POST /api/users/{대표id}/suspend` → 400(「부모 계정은…」) — Suspend·Retire 는 막는데 PUT·reset 은 안 막는 비대칭.

## 봉합(권고 · 결재 대상)
