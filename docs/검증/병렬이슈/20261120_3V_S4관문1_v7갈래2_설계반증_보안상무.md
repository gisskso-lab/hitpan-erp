## ② t0(가림 전) 해시 — 남기지 않음

- **바깥 사람은 다시 셀 수 없다**: t0 원바이트는 공개되지 않으므로 누구도 sha256(t0) 를 독립으로 다시 셀 수 없다 → HQA 가 말한 「입력 동일성」 셈에 못 쓴다. HQA 가 요구한 것은 **M7 이 실제 읽은 시점**(회신 L16) = t1 이지 t0 가 아니다.
- **짐작 대조 도구가 된다**: t1(가린 뒤)은 공개되고, 가림 기록(자리 · 꼴 · `tokens_replaced` · `distinct_tokens`)도 공개된다 → t0 와 t1 의 차이는 **가려진 덩어리뿐**. 가림 꼴(`mask.js` L26 `TOKEN_RE` = 22자 이상 영숫자 · `_` · `-`)은 CSS 클래스 이름 · 파일 이름 · 공개 커밋 SHA 같은 **뻔한 값**도 가린다 → 뻔한 덩어리를 다 맞혀 넣으면 남은 한 덩어리(낮은 엔트로피 비밀이면)를 sha256(t0) 로 대조해 맞힐 수 있다.
- **소금(salt)으로 고쳐지나**: 소금을 공개하면 같은 문제, 소금을 숨기면 아무도 대조 못 함(값 0). 소금을 따로 보관해 나중에 열 계획도 없다(보류 원본은 ⓓ 로 지움) → 소금을 쳐도 쓸모가 없다.
- **판정**: 지시서 §9 거리 2 설계팀장 안의 둘째 길 — **t0 → t1 사슬은 「가림 단계 기록」(자리 · 꼴 · 개수 · 값 0)으로만**. §4 표 t0 줄 「해시만」 → 「기록 0 · 가림 기록만」 으로.

## ③ 보류 원문 해시 — 남기지 않음 · §6 칸 표 해시 칸 줄임

- 같은 이유: 보류 원문은 공개 0 이라 바깥 사람이 다시 셀 수 없음 = 검증 값 0. 보류 파일은 이름 · 꼴 종류만 남기는 지금 방식(`leak-scan.js` L124~ entries · 값 0)을 이어가면 HQA 「최종 publish 보류 목록」(회신 L16) 은 채워진다.
- **더 큰 구멍 — 지시서 §6 L137 「`run.json` 원값 = 칸 단위 표 · 값의 정규 JSON sha256」**: 칸 하나씩 해시하면 칸 하나씩 사전 대입이 된다. 예: 경로 칸(`/home/runner/...`) = 즉시 맞힘 → 실행기 경로 확인 · 자격증명 꼴로 보류된 칸(`leak-scan.js` L22~ 끝 줄 = 값 6자 이상)은 6자 영숫자면 약 5.7×10¹⁰ 경우 = GPU 수 초 안 대입.
- **요구**: 칸 표의 자유 글자 칸 = **키 경로 · JSON 타입 · 바이트 길이 · 걸린 꼴 종류**만(해시 0). 정수 · 참거짓 · 고정 열거 글자 = 값 그대로(지시서 안 유지). 16진 칸은 **그 값이 다른 공개 파일에도 있는 경우에만** 값 그대로(=해시 아님 · 공개값의 반복). 공개 어디에도 없는 값의 해시 = 남기지 않음.
- HQA 정적 4칸 중 「입력 동일성 · 저장 출력 해시 일치」 는 **공개 바이트(t1 · t2 · verdict · 판독 4파일)의 해시**로 센다 → ②③ 을 빼도 지시서 §6 시험 마지막 칸 질문은 닫힐 수 있다(시험 자료로 [3] 실측 · 지금은 미측정).
