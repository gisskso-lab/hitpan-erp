## 무엇이 문제인가
- 코드 자신의 불변식(`local-swap.ps1:912-913` 주석): 「`PrevSaveUnmarked` 가 `$true` 인 동안 `.rbk` 는 표식 없는 옛 판 — **재시도가 지우면 안 된다**」.
- 그런데 막는 조건은 `:1106` `if ($null -eq $pm -and $script:PrevSaveUnmarked)` — **표식 파일이 아예 없을 때만** 선다.
- 표식 파일이 **있지만 이번 실행 것이 아닌** 경우 `$pm` 은 `stale=$true` 로 돌아온다 → `:1106` 건너뜀 → `:1116`(낡지 않을 때만) 건너뜀 → `:1118` `Remove-AppDirSafe {p}.rbk` 세 번.
- 설계 17-1 P2-2 ⓒ 도 「`$pm`=null **그리고** `PrevSaveUnmarked`」로 적혀 있어 코드는 설계와 일치한다 — **설계의 틈**이다.

## 어떻게 그 상태가 되나 (두 갈래)
1. **낡은 표식이 살아남은 경우** — S0 `Clear-Leftover` 가 낡은 표식을 지우다 실패하면 로그만 남기고 계속 간다(`:845` 「judged stale again next time」 · 거부 아님). 같은 파일을 누가 **읽기 공유(`FileShare.Read`)로 쥐고 있으면**(읽는 도구의 흔한 기본값): 지우기 실패 → `Save-PrevGeneration` 이 옛 `prev` 를 지운 뒤(`:919`) `WriteAllText`(`:952`)도 실패 → `PrevSaveUnmarked=$true` → 재시도의 `ReadAllText` 는 **성공**(읽기끼리는 공유) → `to`=옛 판 ≠ 지금 판 ⇒ `stale` ⇒ `.rbk` 삭제. `FileShare.None` 으로 쥐면 18 봉합으로 `unread` 가 되어 안전하다 — **쥐는 방식에 따라 결과가 갈린다.**
2. **이번 실행이 표식을 반쯤 쓴 경우** — `WriteAllText` 는 파일을 먼저 만들고(자르고) 쓴다. 만든 뒤 쓰기가 던지면 0바이트·부분 파일이 남고 `Write-PrevSavingMark` 는 `$false`. 재시도에서 `:974` 칸 모자람 ⇒ `from`/`to` null ⇒ `stale` ⇒ `.rbk` 삭제. 설계 17-5 P3-2(「쓰기 중 끊김 → 빈 표식 = 낡음」)는 **전원 끊김 → 다음 S0** 만 다뤘고, **같은 실행 재시도**에서 P2-2 막음을 무력화하는 이 길은 목록에 없다. ⚠️가설: 설치 폴더 NTFS 에서 30바이트 쓰기는 MFT 상주라 디스크 부족만으로는 잘 안 날 수 있다(실측 0).

## 게이트 관점
- G-PV7 주입 `PVMW`·`PVMW1`(`Write-PrevSavingMark` try **첫 줄** throw)은 파일을 만들기 **전에** 던진다 ⇒ 「표식 없음」만 재고, 「다른 표식이 있는데 못 씀」·「만들고 못 씀」은 대조군 0. 지금 코드는 두 경우 `.rbk` 를 지우고도 `success`·사유 null 로 초록이 된다.

## 막는 방향 (적발만 · 결정은 설계)
- `PrevSaveUnmarked` 가 `$true` 면 `$pm` 의 모양(null·stale)과 무관하게 `.rbk` **삭제 금지**. 다시 쓰기 시도 조건은 「`prev` 없거나 빔」 그대로 두되, 남아 있는 표식이 이번 실행의 `ticket` 이 아니면 덮지 말고 `.rbk` 무접촉 `continue`(끝 사유 `Get-RbkLeftReason`).
- 게이트: (a) 시드로 낡은 표식을 깔고 `FileShare.Read` 로 쥔 채 업데이트 모드 실행 → `.rbk` 해시 = 시드 (b) `Write-PrevSavingMark` 가 파일을 만든 **뒤** 던지는 주입 → `.rbk` 해시 = 시드. 대조군 = 현 `:1106` 조건.
