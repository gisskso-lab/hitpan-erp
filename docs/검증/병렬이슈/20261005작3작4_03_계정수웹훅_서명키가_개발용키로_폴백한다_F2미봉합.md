## 무엇이
- `WebhookInboundController.cs:227-232` 키 = db.conf → `Bootstrap:TokenKey` → **`"DEV-bootstrap-token-key-change-in-production-32+chars"`**(레포에 적힌 값). 같은 상황에서 `SerialProofVerifier.cs:133-143` 은 Production 이면 거부한다 — 비대칭.
- 경로 `/api/internal/webhook/*` 는 `[AllowAnonymous]`(:28) + `TenantMiddleware.cs:71` 통과 + 터널로 인터넷 노출.
- 키 없는 옛 설치 = 누구나 서명 가능. 키는 전 고객사 공통(설계반증 F2).
- subscription 길(새 판 `extra_accounts` 대입 · 같은 파일 HandleAsync)은 본문 TenantId 를 이 PC 회사와 대조하지 않는다(account-count 만 `local_company` 대조).
- 덤: `AccountSeatGuard.cs:109-110` `baseLimit + extra` 가 `int` 그대로 — `extra_accounts=2147483647` 이면 넘쳐 **음수 한도** ⇒ 그 회사 계정 추가·되살리기 전부 409(서비스 거부).

## 재현(시험 환경)
1. db.conf 에 `HITPAN_BOOTSTRAP_TOKEN_KEY` 없는 API 기동.
2. 본문 `{tenantId:<그 회사>, iat:<지금>, nonce:"x", extraAccounts:500, ...}` 를 개발용 키로 HMAC → `POST /api/internal/webhook/subscription` → 200 · `GET /api/users/seats` limit 505.
- 대조군: 같은 본문을 `SerialProofVerifier` 경로로 보내면 Production 거부.

## 봉합(권고 · 결재 대상)
- 키 없음 = 401(폴백 금지 · SerialProofVerifier 선례) · `extra_accounts` 상한/checked 합 · 고객사별 키는 백오피스 트랙 입력서.
