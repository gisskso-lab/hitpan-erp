## 무엇이 문제인가
1. **작업이 남는다** — 일꾼은 `try/finally` 로 끝에서 `HitPan-LocalSwap` 을 지운다(`local-swap.ps1:664-674`). 그런데 그 앞의 조기 종료 `exit 3~8`(`local-swap.ps1:582-587`)은 `try` **밖**이라 finally 를 안 탄다. 스크립트가 아예 못 뜨는 경우(그룹 정책 ExecutionPolicy · AppLocker · EDR 가 `SYSTEM 예약작업 → powershell -ExecutionPolicy Bypass -File` 을 막음 — ⚠️ 실측 0 · #31)도 작업이 남는다.
2. **남은 작업에 유효기간이 없다** — `CheckBusy` 는 `swap.lock`·`request.json` 에는 30분 묵음 판정을 두면서 작업 존재는 **무조건** 바쁨이다(`LocalSwapLauncher.cs:90-91`). API 안에 그 작업을 지우는 곳은 `/Run` 실패 직후 한 곳뿐(`LocalSwapLauncher.cs:189`). ⇒ 영구 `swap_in_progress`.
3. **`.rbk` 가 남는다** — S4~성공 정리 사이 중단(전원·재부팅·작업 강제 종료) · `Save-PrevGeneration` 부분 실패(`local-swap.ps1:534-556` best effort) · S7 `broken` 이면 `{app}\{api,web,watchdog}.rbk` 가 남고, `CheckBusy` 는 `.rbk` 가 있으면 무조건 `update_in_progress`(`LocalSwapLauncher.cs:96-97`). `.rbk` 를 되돌리거나 치우는 기동 복구 코드는 API·워치독 어디에도 없다(워치독 `UpdateFolderRecovery` 는 `.old` 만 본다).
4. **S4 한가운데 중단** — `Move-Part` 는 `api → api.rbk` 다음 `stage\api → api`(`local-swap.ps1:365-377`). 사이에서 끊기면 `{app}\api` 가 없다. 부팅 안전망은 keepalive 만 다시 켤 뿐 폴더는 안 돌린다 ⇒ ERP API 가 안 뜬다(창은 이름 바꾸기라 짧다).
5. ⚠️가설 — `schtasks /Create` 기본 설정은 「AC 전원일 때만 시작 · 배터리로 바뀌면 중지」다(`/XML` 없이 만든다 `LocalSwapLauncher.cs:177-178`). 노트북 메인PC 에서 교체 중 전원선이 빠지면 4 가 된다. 실측 필요(시험 환경에서 `schtasks /Query /XML`).

## 발생 시나리오
- 회사 PC 에 PowerShell 실행 정책 GPO 가 걸려 있다 → [예] → 작업 등록·`/Run` 은 성공(202) → 스크립트 안 뜸 → 화면은 「진행 중」에서 영원히 멈춤 · 업데이트도 되돌리기도 다시 못 누름.
- 교체 중 정전 → 재부팅 뒤 ERP 는 떴지만(또는 안 떴고) `.rbk` 가 남아 두 메뉴가 영구 잠김.

## 막는 방향 (한 줄)
`HitPan-LocalSwap` 존재·`.rbk` 에도 유효기간(요청서 시각 + 한도) 판정을 두고, 넘으면 API 가 스스로 작업을 지우고 `.rbk` 를 「S4 중단 모양」 이면 제자리로 돌리는 기동 복구 한 벌(조기 exit 도 finally 안으로) · 작업은 `/XML` 로 배터리 조건을 끈다.
