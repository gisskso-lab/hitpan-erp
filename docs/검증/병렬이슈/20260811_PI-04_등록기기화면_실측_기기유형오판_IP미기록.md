## P0-1 🔴 아이폰이 `Mac · Safari` 로 잡혔다 — 슬롯 과금 오판

사장님이 **아이폰**으로 QR 등록했는데 기기명이 `Mac · Safari`.

**원인**: 아이패드·아이폰 사파리는 데스크톱 사이트 요청 시 **자신을 Mac 으로 신고**한다.
UA 문자열만 보면 구분이 안 된다(애플이 의도적으로 그렇게 만들었다).

**왜 P0 인가**
히트판은 **기기 수로 과금**한다. 유형 판정이 틀리면 PC 슬롯과 모바일 슬롯이
**서로 잘못된 칸에서 차감**된다. 개발명세서 §1 에 적어둔 그 문장이 그대로 걸린다 —
*"기기 수로 과금하므로, 실제보다 많이 세면 고객이 돈을 더 낸다."*

⚠️ **이번엔 우연히 모바일 칸에 들어갔다**(1/3 로 집계됨). 그러나 **이름이 틀렸다 = 판정 근거가 약하다**.
아이패드는 PC 로 샐 가능성이 높다.

**봉합 방향(제안)**
- UA 단독 판정 금지. **터치 지원 + 화면 크기 + `navigator.maxTouchPoints`** 병행
  (iPadOS 는 `maxTouchPoints > 1` 인 "Mac" 이라는 점이 유일한 실마리)
- 🔴 **QR 등록 경로는 애초에 모바일이 확실하다** — 등록 출처를 신뢰하는 쪽이 UA 추측보다 정확하다.
  `device_register_tokens` 로 들어온 등록은 **무조건 모바일**로 확정하는 게 맞다

## P1-3 🟡 IP 가 전부 `127.0.0.1` — 보안 추적 무의미

`test1.hitpan.kr` 로 **cloudflared 터널을 타고** 들어왔는데 전부 로컬로 기록됐다.
터널 뒤라 원본 IP 는 `X-Forwarded-For` 에 있는데 그걸 읽지 않는다.

**왜 문제인가**
- 어느 기기가 **어디서** 접속했는지 알 수 없다 — 나중에 사고가 나면 이 기록으로 아무것도 못 밝힌다
- 등록기기 화면에 IP 칸을 둔 이유 자체가 무의미해진다

**봉합 방향**: `ForwardedHeaders` 미들웨어 + **신뢰 프록시 지정**
⚠️ 무조건 신뢰하면 **헤더 위조로 IP 를 속일 수 있다**. cloudflared 대역만 신뢰해야 한다.
