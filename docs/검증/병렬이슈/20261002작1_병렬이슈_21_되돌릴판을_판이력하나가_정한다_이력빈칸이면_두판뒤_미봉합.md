## 반증 질문별 판정 (작업지시서 18-1 필수 #1 · #3)
- **#1 저장본 바꿔치기** — 막힌다. 저장본만 바꾸면 T5 「안의 판 == P」에서 걸린다(P 는 이력이 정한다). 서명이 맞는 다른 판 manifest 를 넣어도 **0 판**. 폴더(`{app}\rollback\…` · `{autopf}\HitPan`)는 문지기(`BackupService.EnsureRestrictedSystemFolder` — 상속 끊음 · SYSTEM·Administrators·실행 계정·개별 사용자 줄만)라 일반 사용자는 못 쓴다.
- **#3 판 이력 조작** — 같은 폴더라 일반 사용자는 못 쓴다. 관리자는 위협 모델 밖. **그러나 조작이 없어도 이력은 빈칸이 생긴다** — 아래.

## 무엇이 문제인가
1. **서명은 판의 순서를 증명하지 않는다.** 서명 본문(`UpdateManifestSigning.cs:53-64`)은 version·channel·url·sha256·size·migration 뿐 — 날짜·일련번호·「이 판의 직전 판」 칸 0. 워치독이 옛 판 재생을 막는 수단은 `IsNewerVersion`(어댑터 머리말 `:11` 「다운그레이드·재생 공격의 마지막 방어선」)인데, 조각 B 는 **이 선을 일부러 넘는다**(옛 판 manifest 를 `Verify` 만으로 재사용 · 19-0 사실 4). ⇒ 「어느 옛 판까지 받아도 되나」의 근거가 서명에서 **ACL 걸린 평문 파일 하나**(판 이력)로 옮겨 간다. 설계는 이 이동을 적지 않았다.
2. **판 이력은 빈칸이 생기게 만들어져 있다.** `InstalledVersionLedger.cs:13` 「기동을 막지 않는다」 — 문지기 실패(`:74-75`) · 읽기·쓰기 실패(`:92-95`) · 판 형식 불량이면 **로그 한 줄 남기고 그 판을 안 적는다.** 예: 1.3.50(적힘) → 1.3.51(쓰기 실패 · 안 적힘) → 1.3.52.
   - 이력 = `50, 52` ⇒ T3 `TryReadPreviousVersion` = **1.3.50**(실제 직전 설치 판은 1.3.51).
   - 조각 A 보관 규칙 「지금 판 아래는 이력에 있는 판 중 가장 높은 것 하나」 ⇒ 1.3.51 때도 1.3.52 때도 `manifests\1.3.50.json` 을 남긴다 ⇒ **T5 성립**.
   - 일꾼 `Get-StagingZipRefusal`(`local-swap.ps1:628-656`)도 같은 이력을 읽어 1.3.50 을 「직전 판」으로 인정 ⇒ 통과.
   - NCP 에 `hitpan-1.3.50.zip` 이 남아 있으면(보관 3이면 남는다) **1.3.52 → 1.3.50**. 지금 막는 것은 서버 보관 수 2(⚠️가설 · 레포 밖 회전)뿐 — 범위 밖(19-5)에서 바뀌면 코드 변경 없이 구멍이 열린다.
3. **일꾼의 재확인이 API 보다 약하다.** API T3 은 「이력이 P 를 모르면 안 받는다」. 일꾼은 이력이 **없거나 못 읽거나 마지막 줄 ≠ 지금 판이면 `$null`(허용)**(`:641` · `:648-651` · `:652`). p1(설계 19-1)은 경로·이름·sha 모양만 본다. ⇒ 요청서를 쓰는 API 쪽 판정이 틀리면(버그·경주) 일꾼은 NCP 에서 받은 zip 을 이력 확인 없이 깐다. 「API 검증 뒤 쓰기 직전 한 번 더」(p2 취지)가 **판 선택**에는 서지 않는다.
4. **보관 규칙과 T3 규칙이 다르다**(가용성 · fail-closed). 보관 = 이력 중 지금 판 아래 **가장 높은** 판 · T3 = 이력 **시간순 바로 위** 다른 판. 설치 EXE 로 낮은 판을 깐 PC(예: 이력 `50, 48, 51`)는 T3=48 · 보관=50 ⇒ T5 불성립 ⇒ `no_previous_version`. 새지는 않지만 두 규칙이 같은 것을 가리킨다는 전제가 틀렸다.

## 게이트 관점
- G-NP2 「T3 이력 모름」은 **이력이 없을 때**만 잰다. 「이력은 있는데 한 판이 빠졌을 때」(위 2) 대조 0 · G-NW1 은 일꾼이 이력 없이도 `manual_zip` 을 받아들이는지 안 잰다.

## 막는 방향 (적발만 · 결정은 설계)
- 판 선택 근거를 이력 한 줄에만 두지 않는다 — 예: 저장본을 **그 판이 「지금 판」일 때 남긴 것**만 T5 재료로 인정(남길 때 「지금 판 == manifest 판」 표시를 함께 · 서명 재생성 0) · 그리고 P == 그 표시가 붙은 가장 최근 판일 때만.
- 일꾼 p1 에 「rollback + `manual_zip` 은 이력이 지금 판으로 끝나고 직전 판 == to 일 때만」(이력 모름 = 거부)을 더해 API T3 과 같은 강도로 맞춘다(기존 줄 수정 0 · 덧붙임으로 가능).
- 보관 규칙을 T3 과 같은 함수(`TryReadPreviousVersion`)로 고른다.
- 게이트: (a) 이력 `50, 52` + `manifests\1.3.50.json` + 가짜 서버에 1.3.50 zip → 열리면 FAIL (b) rig 에서 이력 파일 없이 rollback + `manual_zip` → `request_invalid` 여야 함. 대조군 = 현 설계.
