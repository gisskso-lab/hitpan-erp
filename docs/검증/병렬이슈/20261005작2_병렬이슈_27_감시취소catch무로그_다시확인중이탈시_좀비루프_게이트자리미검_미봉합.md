## 무엇이
- **(a) #15 · 설계 §5** — `RollbackProgressOverlay.razor:95` `catch (OperationCanceledException) { /* 주석만 */ }` — `when` 도 `LogWarning` 도 없다. 설계 §5 「catch 는 전부 `when(...)` + `LogWarning` · 오버레이 빈 catch 베끼지 않는다」와 다르다. (지금은 화면 이탈 때만 오지만, 이 catch 가 다른 원인의 취소까지 소리 없이 삼켜 덮개를 「되돌리는 중」에 멈춰 두는 자리다.)
- **(b) 좀비 루프** — `RetryAsync` 가 `CheckOnceAsync(..., CancellationToken.None)`(`:146`) 를 부른다. 그 사이(최대 4초 + 상태 25초) 화면을 떠나 `Dispose` 가 돌면, 돌아온 뒤 `Waiting` 이면 `Watch()` 가 **새 CTS 로 10분 루프**를 다시 건다 — 아무도 취소하지 않는다(5초마다 `api/app-version`·상태 API 헛 호출 · 10분).
- **(c) 게이트 빈칸** — G-W10(`RollbackWatchGateTests.cs:201-213`)은 `"<RollbackProgressOverlay"` 글자만 찾는다 ⇒ 덮개를 `<MainPcOnly>` **안으로** 옮겨도 PASS(코드 판독). 설계 §5 가 「MainPcOnly 밖」을 핵심으로 적었는데 그 자리를 잰 것이 없다.
- 참고(적발 아님): 덮개는 브라우저 뒤로가기를 막지 않는다 — 꺼진 동안 뒤로 가면 다른 화면이 오류를 그린다. 설계 범위 밖이면 [5] 실물 항목으로만.
