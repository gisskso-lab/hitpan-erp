## P0-1. 설계 §5 의 기본 경로(숨은 iframe)가 **우리 API 가 스스로 세운 헤더에 막힌다**

**근거**

| 자리 | 글자 |
|---|---|
| `src/HitPan.API/Program.cs:599` | `h["X-Content-Type-Options"] = "nosniff";` |
| 🔴 `src/HitPan.API/Program.cs:600` | `h["X-Frame-Options"] = "DENY";` |
| `src/HitPan.API/Program.cs:665` | `"frame-ancestors 'none'"` (CSP 끝줄) |

🔴 **`X-Frame-Options: DENY` 는 `if (!isDevelopment)` 블록 _밖_ 에 있다**(그 블록은 `:602` 에서 시작한다). ⇒ **개발 PC·터널·운영 가리지 않고 API 의 모든 응답**에 붙는다. 운영에서는 `frame-ancestors 'none'` 이 한 겹 더 선다.

**설계가 적은 것**

> §5 「같은 출처인가 — 🟢 운영(터널)은 `ApiBaseUrl` 이 현재 페이지 출처로 폴백 ⇒ 같은 출처 ⇒ `contentWindow.print()` 가 선다」
> §5 클라이언트 「숨은 `<iframe>` 에 inline URL → `onload` → `contentWindow.print()`」

**반증** — 같은 출처는 **필요조건일 뿐**이다. `X-Frame-Options: DENY` 가 붙은 응답은 **출처가 같아도 액자에 들어가지 못한다.** `onload` 가 아예 안 오거나 오류 문서로 온다. ⇒ §5-1 의 되돌아갈 길 ①은 **코드를 한 줄 쓰기 전에 실패가 확정**이고, G-C2 는 항상 ②(새 창)나 ③(내려받기)으로만 통과한다.

🔴 **이게 왜 사고가 되나** — 「인쇄 대화상자가 안 뜬다」를 만난 개발자가 **가장 먼저 손대는 곳이 바로 이 전역 한 줄**이다. 그 줄을 지우거나 느슨하게 하는 순간, `[AllowAnonymous]` + 쿼리스트링 토큰으로 열려 있는 `/api/documents/{type}/{id}/pdf`(`DocumentController.cs:134-136`)가 **아무 사이트의 액자 안에 들어간다** — 클릭재킹과 토큰 URL 재사용이 한꺼번에 열린다. 인쇄 단추 하나 때문에 API 전역 액자 방어가 내려가는 교환이다.

🔴 **선결 요구(코드 착수 전)**
1. §5-1 ①(iframe)을 **버리고 ②(새 창 inline)를 기본으로** 바꾸거나,
2. 꼭 ①로 가야 하면 **그 한 엔드포인트의 응답에만** `X-Frame-Options`/`frame-ancestors` 를 `SAMEORIGIN`/`'self'` 로 좁혀 여는 안을 **보안상무 결재**로 올린다. 🔴 **전역 완화는 반려다.**
3. 어느 쪽이든 **G-C2 가 「3단 중 어느 길로 떴는지 기록」하는 것만으로는 부족**하다 — ①이 구조적으로 못 선다는 사실을 작지에 먼저 적어야 개발이 그 한 줄을 안 건드린다.

⚠️ 브라우저 실거동은 **실물 재현 0회**(빌드·기동 금지). 헤더가 실재한다는 것은 **사실**이고, 그 결과는 **강한 추정**이다(§5-1).

## P2-2. 「인쇄」는 **여러 건 선택**이 되는데 설계가 1건만 본다

## P2-4. 호출자 전수를 **작지에 사실로 적어라** (「이메일이 안 끊긴다」의 진짜 근거)
