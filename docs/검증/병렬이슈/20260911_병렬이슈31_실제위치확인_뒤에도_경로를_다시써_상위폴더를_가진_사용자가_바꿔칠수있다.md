## 1. 사실

| # | 사실 | 근거 |
|---|---|---|
| F1 | C-12 ② 는 새로 연 핸들의 실제 위치를 **한 번** 확인하고, 덤프 바이트는 그 핸들로 쓴다 → 쓰는 동안 바꿔치기는 막힌다 | 🟢 `:469-475` · G-BK4 ② PASS |
| F2 | 그 뒤 단계는 전부 **경로를 다시 푼다**: 크기 확인 `new FileInfo(primaryFile)` · 보관 정리 `Directory.GetFiles(settings.PrimaryPath)` → `Delete` · 실패 정리 `File.Delete(outFile)` · 이력 `primary_file` 에 경로 문자열 저장 | 🟡 코드 |
| F3 | 폴더 판정은 `Backup` 의 소유자·권한 줄·재분석 지점과 **상위 경로의 재분석 지점**만 본다. 상위 `%ProgramData%\HitPan` 의 **소유자**는 보지 않는다 | 🟡 `:821-866` |
| F4 | `HitPan` 을 가진 일반 사용자는 소유자 권한(권한 변경)으로 자기에게 하위 삭제 권한을 주고 → 보호된 `Backup` 을 다른 이름으로 옮긴 뒤 → 같은 이름의 교차점을 둘 수 있다 (옮긴 폴더의 보호 권한은 그대로라 **안의 백업은 못 읽는다**) | 🟡 Windows 동작 · 실측 ⬜ (실물 `ProgramData` 변경 금지) |
| F5 | 설치기가 설치 때 `{commonappdata}\HitPan` 을 만든다(`installer/HitPan-Universal.iss:2471` registry.json) → 설치 뒤에는 일반 사용자가 `HitPan` 을 가질 수 없다. **설치 전에 먼저 만든 경우만** 성립 (이미 있으면 설치기는 그대로 쓴다) | 🟢 grep · 🟡 이미 있을 때 동작 |

## 2. 뜻 — ② 확인 뒤 · 보관 정리 전 수 초 창에 바꿔치면

| 결과 | 영향 |
|---|---|
| 크기 확인이 교차점 너머 같은 이름 파일을 읽음 | 실제 백업은 이미 진짜 폴더에 있음 · 성공/실패 판정만 흔들림 |
| 보관 정리가 교차점 대상 폴더의 `hitpan_backup_*.sql` 을 API 계정 권한으로 삭제 | 이름 틀이 고정이라 범위 좁음 |
| 이력 `primary_file` 경로가 교차점 경유 위치를 가리킴 | 🔴 **복원이 이력 경로로 파일을 읽으면 공격자가 둔 SQL 을 DB 계정 권한으로 복원** — 지금은 C-11 로 복원이 맨 앞에서 막혀 도달 불가 |

공격 조건: 설치 **전** `%ProgramData%\HitPan` 선점 + 같은 PC 에 로그인하는 두 번째 Windows 계정 + 백업 1회가 도는 사이의 짧은 창. 병렬이슈29(교차점 사전 우회)보다 조건이 훨씬 좁고, 덤프 내용은 노출되지 않는다.
