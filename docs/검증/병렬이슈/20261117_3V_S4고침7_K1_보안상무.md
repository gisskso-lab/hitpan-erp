### P1-1 두 식 판별 열쇠(`item`) ≠ 셈 열쇠(`cell`) — 장치 식 하나만으로 「성립」 이 새는 길

- 결과(V3 실행): `cell` 은 I-4 키보드 칸 · `item` 만 다른 옛 꼴 표본은 `xCls` 에 없어 `xExcl` 거짓 → 재현 셈 · 같은 줄 셈에 장치 식으로 들어감 → 키보드 대조 「성립」 · 표지 · 빨강 0 · 분류 총수에서도 사라져 T19 등식이 그대로 맞음.
- 자체시험이 못 잡는 까닭: 자체시험의 짝 구현(`k1Problems` 의 T19 · `k1Touchable`)도 같은 `s.item === 'I-4'` 열쇠라 판독기와 같이 눈을 감는다. 대조군이 판독기와 같은 전제를 공유한다.
- 근거: CTO §3-1 반려 근거 ②(「칸을 안 쓴 기록기(옛 측정 코드 · 회귀)는 못 잡는다」)와 같은 계열 — 실측 기록기가 지금 `item` · `cell` 을 맞게 쓴다는 것은 막는 장치가 아니다.
- 고칠 문안(새 빨강 0 유지): 판독기에서 「I-4 표본」 을 **계획 칸 기준**으로 고른다 — `const i4Keys = new Set(plan.cells.filter((c) => c.item === 'I-4').map((c) => c.key));` → L506 · L918 의 조건을 `s && (s.item === 'I-4' || i4Keys.has(s.cell))` 로. 자체시험 `k1Touchable` · T19 짝 구현도 같은 기준. 새 시험 1쌍: check = `item` 만 바꾼 옛 꼴 2건 → 여전히 비교 불가 2 · T7 기대 그대로 / 심은 위반 = 판독기 조건을 옛 `s.item === 'I-4'` 로 되돌린 사본 → 빨강.
