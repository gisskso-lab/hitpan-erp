### 발견 1 상세 — 왜 500 인가 (드라이버 2.6.2 · Dapper 2.1.72 원본 판독)

| 갈래 | 경로 | 결과 |
|---|---|---|
| 정상 시간 초과 | 5초 타이머 → 별도 연결로 `KILL QUERY` → 1317 → `CreateForTimeout` (`ResultSet.cs:259`) · 세션 정상 복귀 | 🟢 결제 조회 진행 · 상세 200 + 「확인 불가」 |
| 취소 실패 또는 소켓 단절 | `KILL` 연결 실패 · 2초 내 무응답(`ICancellableCommand.cs:80-82`) · 서버 재시작 · TCP 끊김 → 읽기 실패 → `SetFailed` (`ServerSession.cs:1180`) → 연결 상태 **`Broken`** (`:2148`) | 🔴 아래 |

- Dapper 자동 재연결은 `State == Closed` 일 때만이다(`SqlMapper.Async.cs:427`). `Broken` 은 해당 없다.
- 다음 명령은 `MySqlCommand.IsValid` 에서 `InvalidOperationException` 「Connection must be Open; current state is Broken」 (`MySqlCommand.cs:451-452`).
- 이 예외는 `FillAsync` 밖이므로 `Get` 바깥 catch 로 가서 500.
- `List` 는 뒤 문장이 없어 안전하다. 🟢
- 드라이버 문구는 설치된 2.6.2 DLL 에서도 확인했다. `Broken` 전이는 태그 원본 판독이고, 실행 재현은 ⬜.

**영향**: 표시가 거짓이 되지는 않는다. 데이터 영향 0 · 새로고침으로 회복. 그러나 이 갈래는 DB 가 힘든 순간에 열리고, 상세 화면 전체가 막힌다. 그래서 P0 이 아니라 P1 이다.

**최소 고침 근거**: 호출을 뒤로 옮기면 깨진 연결을 이어받을 문장이 없어진다. 새 로직 · 새 연결 0 · 파일 추가 0. 🔴 설계 §4 「결제 조회 앞」 을 바꾸므로 **PM 결재 뒤** 고친다.

### 발견 2 상세 — 거짓 「완료」 두 갈래
