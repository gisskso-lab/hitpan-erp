## 판정: 🟡 조건부

코드 자체(판정 한 자리 · 문 한 곳 · 안내 글자)는 깨끗하다. 법정 3종 누수 0 · 메일 · 팩스 무변 · 테넌트 경계 · #14 · #15 · #18 · #43 위반 0.
**조건 1건(P1)**: 이미 들어간 「F-1 옮기기」(양식지 → Y 사본 자동 복제)와 맞물리면, 고객이 아무것도 안 해도 업데이트 뒤 기본 양식이 K3 가 되어 **전표 [인쇄]에서 데이터가 사라지는 길**이 있다. 대표 §59 질문은 「고객이 빈 A4 에 그림만 올리고 칸을 안 맞춘」 경우였고, 옮기기로 **시스템이 만든** K3 는 질문에 없었다. PM 판단(→ 필요 시 대표) 전에는 머지 보류를 권한다.

## 발견

### P1-1 F-1 옮기기 사본이 K3 가 되어 업데이트만으로 인쇄 데이터가 사라진다 (가설 · 코드 읽기 근거 강함)
- 옮기기 대상 = `paper_mode='preprint' AND print_background=1 AND is_active=1` — **칸 개수 조건이 없다** (`src/HitPan.Application/Services/FormTemplateService.cs:704` · `:713~716`).
- 사본은 원본의 `field_coords_json` 을 그대로 옮기고(빈 칸이면 빈 칸), 원본이 실효 기본이면 **사본이 기본이 되고 원본은 기본에서 내려간다** (`FormTemplateService.cs:861` · `:958` · `:997`).
- 그 사본 = plain + 저장된 그림 찍기 켬 + 그림 경로 + 칸 0 → §59 판정(`src/HitPan.Application/Services/PdfRenderService.cs:2980~2986`)에서 참 → 전표 [인쇄] = 그림만.
- 업데이트 전(main) 이 고객의 종이: 양식지 + 칸 0 + 찍기 켬 = 그림 + 데이터(기본 본문). 업데이트 후: 그림만 · 데이터 0. 고객 손 0번. 안내는 미리보기 창에 뜨지만 「칸을 맞춰라」 는 지금 거래명세서를 내야 하는 직원에게 해결이 아니다(#20 흐름 끊김 · #25 쉽게).
- 작업지시서 · 개발명세서 어디에도 이 맞물림이 없다(「옮기기」 언급은 편집창 겹침뿐).
- 확인 방법(제안 · 테스트 환경에서): 양식지 + 찍기 켬 + 그림 + 칸 0 행 하나로 옮기기 1회 → 전표 [인쇄]. 실측 전까지 가설.
- 고칠 쪽 결정은 PM: (가) 옮기기에서 칸 0 행 제외 (나) §59 판정에서 옮기기 사본 제외 (다) 대표가 받아들임. 이 검증은 고치지 않는다.

### P3-1 안내와 종이가 어긋나는 길 — 직접 호출에서만 (실측 0)
- 안내 문은 저장된 양식만 보고, 인쇄 문은 요청의 `Options.PrintBackground` 를 받는다(`PdfRenderService.cs:101` → `:142`). 요청으로 그림을 끄면 종이 = 기본 양식(데이터 있음)인데 안내 = 「그림만 나옵니다」.
- 화면(미리보기 창)은 이 옵션을 보내지 않는다(`src/HitPan.Web/Components/Common/DocumentPrintPreviewDialog.razor:152~158`) → 고객 경로에서는 안 일어난다. 기록만.

### P3-2 창을 열 때마다 그림을 두 번 읽고 디코드한다 (가설)
- 안내 문(`PdfRenderService.cs:3929~3950`)이 렌더와 별도로 양식 읽기 + 그림 읽기 · 디코드를 한 번 더 한다. 그림 파일이 없거나 못 읽는 양식이면 같은 경고 로그가 창 한 번에 두 줄. 상한(`MaxBackgroundBytes`) 안이라 위험은 낮다. 기록만.

### P3-3 다음 갈래 주의 — 「4화면 PDF 단추 → 양식 렌더」(결재 기록 §77 줄)
- 그 단추를 양식 렌더로 옮길 때 인쇄 문(`DocumentController.cs:841` 의 `NoCoordsImageOnly = true`)을 타면 PDF 저장도 그림만이 되고, 다른 문을 타면 인쇄 = 그림만 · PDF = 데이터로 갈린다. 그 갈래 작업지시서에 한 줄 필요. 이번 범위 밖.

### 참고(이번 변경이 만든 것 아님) — 그림 읽기 폴더가 회사별이 아니다
- 렌더 쪽 그림 읽기는 단일 허용 폴더만 본다(`PdfRenderService.cs` `TryLoadFormBackground`). 한 설치에 회사가 둘 이상이면 다른 회사 그림 경로를 가리키는 길이 이론상 남는다(저장 문의 경로 검사 여부 미확인 · 가설). 안내 문은 참/거짓만 돌려주므로 **새로 넓힌 길은 없다**. 별 건으로 넘긴다.
