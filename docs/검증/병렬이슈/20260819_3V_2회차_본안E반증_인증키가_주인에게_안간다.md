> ⇒ 정확히 *"고쳤다 ≠ 갔다"* 계통이다. **관문만 풀고 일은 못 하게 된다.**

## 🔴 치명 3 — **`_gateActive` 는 `_awaitingApproval` 의 파생값**이라 G-C 가 성립 못 한다

| 근거 | 무엇 |
|---|---|
| `DeviceAuthGate.razor:21` | 관문 UI 는 `@if (_awaitingApproval)` **블록 안에만** 존재 |
| `DeviceAuthGate.razor:76` | 두 번째 블록 `else if (_blocked)` |
| `DeviceAuthGate.razor:147-153` | `_gateActive = _awaitingApproval \|\| _blocked` — **파생값** |

«PM 확인» ✅ 블록은 `:21`·`:76` **둘뿐**임을 확인.

**무엇이 깨지나**: 승인 성공 → `MarkAllowed()`(`:278`) → `_awaitingApproval=false`
⇒ 🔴 **승인 구역을 담은 블록 자체가 사라진다** — 인증키를 보여줄 화면이 **그 순간 소멸**(치명2 와 한 몸).
반대로 상태를 유지하면 **관문이 안 풀린다.**

> 🔴 **본안 E 의 핵심 주장 *"`_gateActive` 를 안 건드린다"* 가 성립하지 않는다.**
> `_gateActive` 를 안 건드리려면 `_awaitingApproval` 을 안 건드려야 하는데,
> 그것을 안 건드리면 **관문이 안 풀린다.**
> ⇒ **G-C(관문 유지)** 와 **실2(관문이 스스로 사라짐)** 는 **동시에 만족 불가능.**
