## §2 관찰 1건 — 본 커밋 무변경 · 범위 밖 (고치라는 말이 아니다)

### O-1 `unread-count` 의 JOIN 에 테넌트 짝 조건이 없다 (종전 코드 · X-9 로 손대지 못하는 자리)

`CsRequestController.UnreadCount` 의 본사 쪽 집계가 이렇게 붙는다.

```sql
SELECT COUNT(*) FROM cs_replies p
  JOIN cs_requests r ON r.cs_request_id = p.cs_request_id
 WHERE p.tenant_id = @TenantId AND p.read_at IS NULL AND r.origin = 'hq'
```

- 같은 질의의 **다른 자리**(`List` 안의 답 개수 서브쿼리)는 `p.tenant_id = r.tenant_id AND p.cs_request_id = r.cs_request_id` 로 **짝을 맞춘다** — 두 자리의 모양이 다르다.
- 노출이 아니다: 바깥 `WHERE` 가 `p.tenant_id` 로 이미 걸러 **남의 쪽지 자체가 세어지지 않는다**. 어긋날 수 있는 것은 `cs_request_id` 가 테넌트를 넘어 겹칠 때의 **hq / reply 분류**이고, 결과는 숫자 2개의 치우침이다.
- 🔴 **못 쟀다.** `cs_request_id` 가 테넌트 간 겹칠 수 있는 열쇠인지 실측하지 않았고, 이 자리는 작지서 **X-9(「`unread-count` 서버 응답 손대기」 금지)** 에 걸려 이 차수가 건드릴 수 없다.
- **본 커밋은 이 줄을 한 글자도 안 바꿨다**(diff 0줄). ⇒ 작1 의 반려 사유가 아니다. **별건 트랙으로 적어 두는 것**까지가 이 문서의 몫이다.
