## 1. P0-1 — 보고 근거는 틀렸고, 진짜 위험은 따로 있었다

### 1-1. 검증팀 주장
> "이미 Running 인 서비스에 `Start-Service -ErrorAction Stop` 은 예외를 던진다(실측)."
> ⇒ Guardian 이 교체 창에 신버전을 먼저 띄우면, 교체 스크립트의 `Start-Service` 가 예외 →
>   catch 진입 → **성공했는데 롤백**된다.

### 1-2. PM 실측 — 그 전제는 틀렸다

```
Winmgmt (Running) 에 Start-Service -ErrorAction Stop
  → ServiceCommandException
  → 메시지: "Cannot open Winmgmt service on computer '.'"   ← 권한 부족 사유
```

권한 있는 서비스로 다시 시험:
```
ALYac_RTSrv   (Running) → 예외 없음 (통과)
ALYac_UpdSrv  (Running) → 예외 없음 (통과)
Appinfo       (Running) → 예외 없음 (통과)
ALUpdateService        → 예외 (Cannot open = 권한)
AppHostSvc             → 예외 (Cannot open = 권한)
```

⇒ **예외 사유는 "이미 Running" 이 아니라 "권한 부족"이었다.**
   검증팀은 관리자 권한 없이 시험해 놓고 그 예외를 "Running 이라서"로 오독했다.
   실제 교체 스크립트는 `/RU SYSTEM` 으로 도니 권한 문제가 없다 ⇒ **제시된 시나리오는 성립하지 않는다.**

### 1-3. 그런데 진짜 위험이 있었다 (다른 메커니즘)

Guardian 실물(`installer/scripts/InstallWatchdog.ps1:118`)은 무조건 `Start-Service` 하지 않는다:
```powershell
if ($null -eq $svc -or $svc.Status -ne 'Running') { ... }
```
즉 **Stopped 인 창에서만 발화**한다. 교체 창이 정확히 그 창이다(5분 주기).

발화하면 **구버전 EXE 가 실행 중**이 된다. 그 상태의 폴더는:
```
Move-Item   : 성공 (실행 중이어도 폴더 이동은 된다)
Remove-Item : 실패 → UnauthorizedAccessException (실행 중 EXE 는 삭제 불가)
```
`SwapDir` 은 목적지를 먼저 지운다(A-1 봉합). 그 `Remove-Item` 이 실패하고
`$ErrorActionPreference='Stop'` 이라 **교체가 중단**된다.

⇒ 영구 고립은 아니지만 **자기교체가 매 사이클 실패 = 기능 목적 자체가 무효화**된다.
   워치독 버그를 자동으로 못 고치는 원래 문제로 되돌아간다.

### 1-4. 봉합 — 레포에 이미 있던 검증된 관용구를 따랐다

`UpdateProcessGate.cs:15` 가 **똑같은 종류의 문제**(keepalive 가 교체 중 프로세스를 되살림)를
이미 해결해 두었다. 새 기법을 만들지 않고 그 선례를 따른다(작10 교훈: *선례 없는 기법을
검증된 패턴이라 부르지 않는다*).

```powershell
$guardian = 'HitPanWatchdogGuardian'
function GuardianOn { schtasks.exe /Change /TN $guardian /ENABLE ... }
schtasks.exe /Change /TN $guardian /DISABLE ...   # /End 가 아니라 /DISABLE — /End 는 트리거를 살려둔다
```

**3층 복원 보장** (하나만 살아도 Guardian 은 돌아온다):
1. 교체 스크립트의 **모든 종료 경로**에 `GuardianOn` — 실측으로 4개 exit 전부 확인
2. **부팅 복구 스크립트 맨 앞**에서 조건 없이 ENABLE — 교체 직후 정전 대비
3. **워치독 기동 시 자가 점검**(`CleanupStaleSelfReplaceArtifacts`) — 재시작 경로

> ⚠️ Guardian 이 꺼진 채 남는 것은 **업데이트가 안전망을 없애는 꼴**이라 P0 급이다.
> 그래서 복원을 한 곳이 아니라 세 곳에 둔다.

## 2. P1-1 — `/` 는 리터럴이 아니라 문화권 날짜 구분자다

`{runAt:yyyy/MM/dd}` 의 `/` 는 **자리표시자**다. 로케일별 렌더:
```
ko-KR → 2026-08-06     (고객 PC 대다수)
de-DE → 2026.08.06
hu-HU → 2026. 08. 06   ← 공백 포함 = 인자 쪼개짐 위험
en-US → 2026/08/06
```
현재 ko-KR 에서 schtasks 가 `-` 형식도 받아 **우연히** 동작한다. 우연에 기대지 않는다.

**봉합**: `CultureInfo.InvariantCulture` 고정.

## 3. P1-2 — 부팅 복구 작업이 영구 잔존

`Recover` 작업(ONSTART)은 **교체 스크립트가 성공했을 때만** 스스로 지워진다.
예약 후 2분 사이에 서비스 재시작·정전이 나면 교체는 안 돌고 복구 작업만 매 부팅 남는다.
(무해하지만 무기한 누적 = 바닥을 안 치우는 것)

**봉합**: 워치독 기동 시 자가 점검 `CleanupStaleSelfReplaceArtifacts()` 신설.
- `watchdog.new` 가 **없으면** = 교체가 끝났거나 할 게 없다 ⇒ 안전망을 걷는다
- `watchdog.new` 가 **있으면** = 아직 교체 예정 ⇒ 건드리지 않는다
- 호출부: `Worker.cs:104` (기존 `SelfHealKeepaliveIfAbandoned` 바로 옆 — 같은 성격)

> ⚠️ **호출부 없는 메서드를 만들지 않았다.** 이 프로젝트가 반복해 온 '죽은 장치' 구조
> (7/24~7/31 main Ruleset 이 꺼진 채 방치된 것과 같은 실패)를 피한다.

## 4. P1-3 — 고아 프로세스 + 버려지는 실패 사유

```csharp
if (!p.WaitForExit(30_000)) return -1;   // Dispose() 는 자식을 죽이지 않는다
```
① 타임아웃 시 `schtasks.exe` 가 고아로 남는다(매 업데이트마다 누적).
② 출력을 리다이렉트해놓고 **한 번도 읽지 않아** 실패 사유가 버려진다 — 로그에 종료코드만 남는다
   (헌법 #15 침묵 금지의 취지 미달).

**봉합**: `Kill(entireProcessTree: true)` + 비동기로 stdout/stderr 를 읽어 실패 시 사유 기록.

## 5. 봉합 후 재검증 (실측)

**교체 스크립트** — 실제 생성물의 로직 그대로, 환경 의존 호출만 무해화:

| 경우 | exit | watchdog | 중첩 | Guardian 복원 |
|---|---|---|---|---|
| 정상 교체 | 0 | **NEW** | 없음 | ✅ |
| 시작 실패 주입 | 1 | **OLD** (구버전 복귀) | 없음 | ✅ |
| 중지 실패 주입 | 1 | **OLD** (교체 미시작) | 없음 | ✅ |

※ A-1 재현 조건(`watchdog.old` 기존재)에서 시험 — **중첩 0건 유지**.

**부팅 복구 스크립트** — 전원 차단 시점별 전수:

| 경우 | exit | 결과 |
|---|---|---|
| S2 교체중 정전 (watchdog 없음) | 0 | `.new` 로 복구 |
| EXE만 없음 (폴더는 있음) | 0 | `.old` 로 복구 |
| 정상 | 0 | 복구 불필요 |
| 전부 없음 | 1 | 기록만 (상태 악화 없음) |

**공통**: 4경우 모두 맨 앞에서 Guardian ENABLE 실행 확인.

**기타**: 빌드 경고 0 / 오류 0 · 생성 스크립트 비ASCII **0자** · 파싱오류 0건.

## 6. 남은 한계 (정직한 기재)

**샌드박스 종단 실측은 아직 안 했다.** 위 검증은 개발 PC 격리 실측이다.
`feedback_dev_pc_proves_nothing` 기준으로 **최종 통과가 아니다.**

미수행:
- 실제 Windows 서비스 기동을 동반한 교체 (`/RU SYSTEM` 권한 필요)
- 폴더 없는 창에서 **강제 재부팅** → 부팅 복구 실동작 (작3 §5 V-4)
- Guardian 이 실제로 5분 주기로 끼어드는 상황의 종단 재현

⇒ [4] 검증팀 단계에서 샌드박스 실측 필요. **이 문서는 그 전제로 작성됐다.**
