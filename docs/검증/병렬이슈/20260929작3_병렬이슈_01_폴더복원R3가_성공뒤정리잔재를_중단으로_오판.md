## 무엇이 문제인가

설계 §6 은 **폴더 모양만 보고** 판정한다. R3 = 「`web.old` 있음 · `api.old` 없음 · `web`·`api` 있음」 ⇒ 「web 만 새 버전(섞임)」으로 보고 `web`→`web.failed`, `web.old`→`web` 으로 되돌린다.

그런데 **성공한 업데이트의 정리 단계**가 바로 이 모양을 남긴다.

- `src/HitPan.Watchdog/AutoUpdate/UpdateOrchestrator.cs:1000-1001` `CleanupAfterSuccess` — **`api.old` 를 먼저, `web.old` 를 나중에** 지운다.
- `UpdateOrchestrator.cs:637-647` `TryDeleteDir` — 실패해도 경고만 남기고 넘어간다. `Directory.Delete(recursive)` 는 중간에 실패하면 **일부 파일만 지워진 채** 폴더가 남는다.

아래 경우 모두 결과는 「web·api 새 버전 + api.old 없음 + web.old 남음」 = **R3 모양**이다.

| 경우 | 흔한가 |
|---|---|
| `web.old` 안의 파일 하나가 잠겨 있다(Defender 검사 중 · 탐색기 창 · 백신) → 지우기 실패 | 흔하다 (#31 백신·EDR 과 같이 사는 환경) |
| `web.old` 를 지우는 **도중에** 전원이 꺼졌다 | 오더 ②가 바로 이 「전원 종료」 |
| `api.old` 를 지운 뒤, `web.old` 를 지우기 전에 전원이 꺼졌다 | 가능 |

다음 워치독 기동(재부팅 · 워치독 자기교체 뒤 재기동)에서 R3 가 걸리면:
1. **정상인 새 버전 `web` 을 `web.failed` 로 치우고**
2. **옛 버전(또는 파일 일부가 지워진) `web.old` 를 `web` 자리에 넣는다**
3. ⇒ api 는 새 버전, web 은 옛 버전(섞임) — 또는 web 파일이 빠져 **ERP 화면이 아예 안 뜬다**

이 복원은 「이 버전이 성공했다」는 DB 기록과 무관하게 돈다(설계 §6 「DB 무관」). 그리고 다음 성공 업데이트의 `CleanupAfterSuccess:1004` 가 `web.failed` 를 지우므로 **되돌릴 근거 폴더까지 사라질 수 있다.**

⚠️ 실제로 이동이 일어나는지는 서비스 기동 순서에 달렸다: 웹 서비스가 먼저 떠서 `web` 폴더를 쓰고 있으면 `Directory.Move(web, web.failed)` 가 실패해 아무 일도 없다. 워치독이 먼저 돌면 이동된다 ⇒ **간헐적**으로 나타난다(재현이 잘 안 되는 종류).

## 교체 중 중단과 정리 중 중단을 모양으로는 못 가른다

교체 순서(`UpdateOrchestrator.cs:360` web 먼저 → `:366` api)가 남기는 중단 모양:

| 시점 | 모양 | 설계 판정 |
|---|---|---|
| web 밀어냄 직후 | web 없음 · web.old | R1 ✅ |
| 새 web 넣음 · api 아직 | web · web.old · api | **R3** |
| **성공 뒤 정리 중(api.old 먼저 지움)** | web · web.old · api | **R3 ← 똑같다** |

⇒ 폴더 모양 넷만으로는 R3 의 두 뜻이 원리적으로 안 갈린다.

## 권고 (고르는 것은 설계팀장 · PM)

1. **표식 파일(권장)** — `TrySwapFilesAsync` 가 첫 `Directory.Move` **전에** `{app}\update.swapping`(대상 버전 기록)을 쓰고, `CleanupAfterSuccess` **맨 앞**(`.old` 지우기 전)에 지운다. 기동 복원은 **표식이 있을 때만** R1~R3 를 돈다. 표식이 없으면 `.old` 잔재는 「정리 못 한 찌꺼기」로 보고 **건드리지 않는다**(로그만).
2. 또는 최소한 **정리 순서를 뒤집는다** — `web.old` 먼저, `api.old` 나중. 그러면 정리 잔재는 「api.old 만」 또는 「둘 다(R4)」가 되어 R1~R3 에 안 걸린다. 단, #1 원칙상 기존 순서 변경은 설계 결재가 필요하고, 1 보다 약하다(앞으로 다른 정리 경로가 생기면 다시 깨진다).
3. 게이트 G-W6 에 **음성 대조군** 추가: 「성공 뒤 정리 잔재(web·api·web.old, api.old 없음, 표식 없음) → 복원 0 · `web` 무변경」. 지금 G-W6 는 R1·R2·R3 를 「복원해야 하는 경우」로만 잰다 — 복원하면 **안 되는** 경우를 안 잰다.
4. R3 에서 `web.failed` 가 이미 있으면(앞선 롤백 잔재) `Directory.Move` 가 실패한다 — 지우지 말고 이름을 바꿔 비키는지(예: 시각 꼬리표) 구현 확인.
