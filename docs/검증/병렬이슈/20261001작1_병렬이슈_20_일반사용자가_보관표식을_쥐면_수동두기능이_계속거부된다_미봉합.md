## 누가 · 어떻게
- 설치 폴더 `DefaultDirName={autopf}\HitPan`(`installer/HitPan-Universal.iss:83`) · `[Dirs] Permissions:` 0건 · `icacls` 는 `db.conf` 등 개별 파일만 ⇒ `{app}\rollback\prev-saving.txt` 는 Program Files 기본 상속(⚠️가설: `Users` 읽기·실행).
- 읽기 권한만 있으면 `File.Open(path, Open, Read, None)` 으로 쥘 수 있다 ⇒ **일반 사용자 프로세스**가 `ReadAllText` 를 공유 위반으로 실패시킨다 ⇒ `Get-PrevSavingMark` 안쪽 catch ⇒ `unread`.
- 일반 사용자는 표식을 **만들 수는 없다**(쓰기 권한 없음) ⇒ 표식이 있을 때만 가능: (a) 보관이 끊겨 표식이 남은 PC (b) 정상 실행 중 표식을 쓰고 지우는 몇 초 사이를 폴더 감시로 낚아채기 — 낚이면 `Complete-PrevGeneration` 끝의 표식 지우기가 던져 표식이 남는다(⚠️가설).
- 쥔 프로세스가 사는 동안 매 S0 `refused`(`cleanup_pending`) · 표식 파일은 재부팅에도 남으므로 **사용자 로그온 예약 작업**으로 다시 쥐면 사실상 영구(⚠️가설). 풀림 = 쥔 프로세스 종료 → 다음 S0 가 읽음(대개 `sha256.txt` 있음 ⇒ 낡음 ⇒ 정상 길).

## 곁 관찰 (⚠️가설 · 관리자 전제라 위협 모델 밖)
- 표식에 읽기 **거부 ACL** 을 걸면 PS5.1 `Test-Path` 가 예외 대신 `$false` 를 돌려줄 수 있다 ⇒ `unread` 가 아니라 **`$null`(없음)** ⇒ S0 가 `.rbk` 를 M5 로 지운다(「못 읽음」이 「없음」으로 새는 길). ACL 변경은 관리자 권한이라 P3 곁가지로만 둔다.

## 막는 방향 (적발만 · 결정은 설계)
- `{app}\rollback` 에 `Users` 읽기 제거(SYSTEM·Administrators 만) — `db.conf` 와 같은 `icacls` 한 줄. 또는 받아들이고 고객센터 절차 문서(C~E 표)에 「표식을 쥔 프로세스 확인(`handle`·리소스 모니터)」 한 줄.
- `cleanup_pending` 문구(「다음 업데이트·되돌리기 때 먼저 치웁니다」)는 이 경우 **거짓 약속**이 반복된다(설계 17-3 🟡 와 같은 결).
