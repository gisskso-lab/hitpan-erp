## 무엇이 다른가

PM 판정 ②(작지 §15)는 G-RC6 이 **제품 private 문장을 복제**한 것을 「같은 모양이면 된다」로 받았다.
실제로는 **매입 축에서 문장 하나가 빠져 있다.**

제품 `CollectionService.EnsurePaymentTargetAllowedAsync` (S1b ㉲ 로 나눈 뒤) — 사용액은 **두 문장의 합**이다.

```
paid     = SELECT SUM(amount) FROM payments … {LockTailFor(mode)}
returned = SELECT SUM(rti.supply_amount + rti.vat_amount)
             FROM purchase_returns rt JOIN purchase_return_items rti … {LockTailFor(mode)}
used     = paid + returned
```

게이트 `RcSafePathGateTests.TryDocMatchAsync` (매입 축) — `payments` **한 문장뿐**이다.

```
used = await c.ExecuteScalarAsync<decimal>(
    $"SELECT COALESCE(SUM(amount), 0) FROM payments WHERE tenant_id=@T AND is_active=1 AND payment_type='purchase' AND ref_order_id=@D{tail}", …);
```

→ 나눈 두 문장 중 **반품 쪽**은 G-RC6 이 한 번도 안 돌린다.
CI 주석이 적은 무력화 시험 「`LockTailFor` 를 항상 빈 문자열로 1건 → G-RC6」 은 **양쪽을 동시에** 빼는 변이라 잡힌 것이고,
**반품 문장의 꼬리절만** 지우는 변이는 게이트 11사례 어디에도 안 걸린다(G-RC10 은 RR 재계산 상수 5개를 재지, D1 전표 합은 안 잰다).

즉 **S1b ㉲ · PM 결재 B-3 로 새로 만든 문장이 감시 밖**이다.

## 부차 — 게이트가 제품 문자열을 안 쓴다

`Assert.Contains("40,000원입니다", e2!.Message)` 는 게이트가 **자기 손으로 만든** 문구를 자기가 확인한다.
제품 상수 `MsgReceiptOver` / `MsgDeliveryOver` 를 안 본다 → 제품 문구가 바뀌어도 초록이다(고객 문구 회귀 미감시).
전표 조회 조건도 제품과 다르다 — 제품은 `sd.is_deleted=0 AND sd.status IN ('confirmed','invoiced')` · `pr.status='confirmed'` · `MigratedUnderLegacy` 까지 보지만 게이트 복제문은 안 본다.

## 요구 (코드는 안 고쳤다)

1. G-RC6 매입 축을 **`paid + returned` 두 문장**으로 맞추고, 확정 반품이 있는 전표로 사례를 하나 더 만든다.
2. 「반품 문장의 꼬리절만 제거」 변이를 실제로 넣어 G-RC6 이 빨간불이 되는지 확인한 뒤 CI 주석의 무력화 목록에 추가한다 — 지금 목록은 이 변이를 안 담고 있다.
3. 가능하면 복제 대신 제품 경로(`CreatePaymentAsync` 진입점)로 재고, 비교 문구는 제품 상수를 쓴다.

## 확인한 것

- ✅ 제품 두 문장 · 게이트 한 문장은 소스 대조로 확정했다(`CollectionService.cs` 846~866줄대 ↔ `RcSafePathGateTests.cs` 520~556줄대).
- ⚠️ 미실측 — 변이를 실제로 넣어 초록임을 보이지는 않았다(코드 수정 금지 범위).
