## 지적
- **P2 실패 착지** — 위조방지 실패 시 `/backoffice/login?error=…` 로 보냄. 로그인 화면은 인증 사용자를 돌려보내지 않음(grep 0) · 그 화면엔 로그아웃 단추 없음. 안내 「새로 고친 뒤 다시 눌러」 를 그 화면에서 따를 방법이 없다 → 쿠키(IsPersistent) 산 채로 자리 떠남 = 고친 위험이 실패 경로에 남음. 재현 꼴: 탭A 열어 둠 → 탭B 에서 다른 계정 재로그인 → 탭A 로그아웃 = 토큰 사용자 불일치 실패 · 계정B 쿠키 남음. 고침 후보(설계 몫): 착지를 `/backoffice`(본사)/대리점 첫 화면 + 안내, 또는 로그인 화면이 인증 상태면 「로그아웃」 단추 노출.
- **P3 거짓 실패 안내** — 쿠키 8h 만료(회로 활동은 슬라이딩 갱신 안 함) 또는 SessionGuard 가 그 요청에서 쿠키를 버린 뒤 → 익명 ≠ 토큰 사용자 → 「로그아웃이 끝나지 않았습니다」 인데 실제론 이미 나가 있음(Guard 의 삭제 Set-Cookie 는 Redirect 에 실림). 안전엔 문제 없음 · 문구 정확성.
- **P3 기존 칸** — `?error=` 아무 글자나 로그인 화면에 찍힘(인코딩돼 XSS 아님 · 피싱 문구 주입 가능) · 이번 변경이 만든 것 아님.
- 별건 확인만: 다른 탭 회로·뒤로가기 bfcache 화면은 옛 인증으로 남음 = D2·D3 별건(대표 결재대로).
