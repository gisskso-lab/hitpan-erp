# 병렬이슈 18 — 지우는 동안 화면이 안 잠겨, **두 번 누르면 첫 이관을 도중에 지운다**

## 1. 무엇이 잘못됐나

「없는 것만 보태기」는 `/start` 가 **1초 안에** 잡 번호를 돌려준다. 그래서 화면은 그 응답을 받고 나서야 잠근다.

그런데 **「모두 지우고 새로 가져오기」는 그 한 번의 호출 안에서** 전체 백업(`mysqldump`) + 전 자료 삭제 + 회사 기본자료 다시 깔기를 **다 끝내고서야** 돌아온다. 고객 규모 DB 라면 수십 초에서 수 분이다.

그 사이 화면에는 **스피너도, 안내도, 버튼 잠금도 없었다.**

- `StartMigrationAsync` 안에 `_loading = true` 가 **0건**(`_loading` 은 응답을 받은 뒤 `RunJobFlowAsync` 에서야 선다)
- 「이관 시작」 버튼의 `Disabled` 조건은 `_loading || _reconLoading || _previewResult == null` — 셋 다 안 걸려 **계속 눌린다**

⇒ 아무 일도 안 일어난 줄 아신 사장님이 한 번 더 누르면, **첫 이관이 자료를 넣고 있는 중에 두 번째 지우기가 전 표를 비운다.** 잡도 둘이 같은 표를 동시에 돈다.

곁가지: 브라우저 HTTP 타임아웃이 10분(`HitPan.Web/Program.cs`)이라, 그보다 오래 걸리면 `PostAsJsonAsync` 가 **try/catch 없이 던져** 화면만 죽고 **서버는 계속 지우고 가져온다.**

> 🔴 코드 바로 위에 `// 1) Start — 즉시 JobId 반환 (1초 내)` 라는 주석이 그대로 남아 있었다.
> **덮어쓰기를 붙이는 순간 그 주석은 거짓이 됐는데, 아무도 그 전제를 다시 안 봤다.**

## 2. 어떻게 찾았나

만든 사람이 아닌 검증자가 *"이 호출이 정말 1초에 돌아오나"* 를 호출 사슬로 따라갔다 —
`/start` → `PrepareOverwriteAsync` → `ResetAllAsync` → `BackupService` → `mysqldump.exe` **동기 실행**.

## 3. 봉합

- **POST 를 보내기 전에** `_loading = true` 를 세우고 화면을 다시 그린다 ⇒ 버튼이 그 즉시 잠긴다.
- 지우는 방식이면 안내 문구를 다르게 준다:
  「기존 자료를 백업하고 정리하는 중입니다. 시간이 걸릴 수 있으니 이 화면을 닫지 마세요...」
- 호출을 `try/catch` 로 감쌌다. 응답을 못 받아도 **"다시 누르세요" 라고 하지 않는다** — 서버는 계속 돌고 있을 수 있다.
  「응답을 받지 못했습니다. 작업은 계속 진행 중일 수 있으니, 이 화면을 다시 열어 진행 상태를 확인해 주세요. **다시 누르지 마세요.**」
  (화면을 다시 열면 `legacy-mdb/current` 가 진행 중인 잡에 다시 붙는다 — 작22 A3 에서 이미 만든 길이다.)

## 4. 왜 게이트로 못 잡았나 — 정직하게

이 결함은 **화면의 시간 축**에 있다. 지금 게이트는 서버 분기와 DB 결과만 잰다.
Blazor 컴포넌트의 "응답 오기 전 상태" 를 재려면 bUnit 같은 도구가 필요한데 이 저장소에 없다.
⇒ **⚠️ 게이트 미보유**로 남긴다. *"게이트가 없다"* 를 *"문제가 없다"* 로 적지 않는다.
사장님 화면 실측 항목에 **「지우고 가져오기를 누른 직후 버튼이 잠기고 안내가 뜨는가」** 를 넣었다.

## 5. 회귀인가

**아니다 — 오늘 만든 코드의 결함이다.** 1.3.38 에는 덮어쓰기가 없어 `/start` 가 실제로 1초에 돌아왔다.
