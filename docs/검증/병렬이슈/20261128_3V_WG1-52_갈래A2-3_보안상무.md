### P3 (11)
1. **`RunAsync` 에 뒷정리 그물 없음** — `VerifyAsync` · `OverlayAsync` 는 `DbException` 만 잡는다. `FingerprintFromAsync` 의 `InvalidOperationException`(판 대조 표 이름 꼴 밖) · 요청 끊김 `OperationCanceledException` 은 그대로 새어 → `StopAsync` 안 불림 → `restore_history` = `running` 그대로 · `rs_new__*`(백업 업무 자료 전부) · 사본 임시 표가 다음 붓기 · 기동까지 남음. 합류 지휘가 감싸지 않으면 남는다.
2. **⑤ 도중 프로세스가 죽으면 `running` 이 영원** — 서버가 거래를 되돌려 라이브는 안전(G6b). 그러나 기동 청소(`Program.cs:665-680`)는 임시 표만 지우고 `restore_history` `running` 줄을 닫지 않는다 · 로컬 감사도 「교체 시작」 뒤 끝 줄 0. 정본 기록에 「무슨 일이 있었나」 가 빈다. 워치독 자동 업데이트 · 정전이 실제 길.
3. **⑤ 에 요청 취소 토큰** — `SwapAsync` 의 문장 · `tx.CommitAsync(ct)` 가 부르는 쪽 `ct` 를 씀. 합류에서 HTTP 끊김 토큰을 넘기면 브라우저를 닫는 순간 교체가 되돌려지고, 커밋 중 취소면 「결과 모름(check_needed)」 이 괜히 난다. ⑤ 시작 뒤는 `CancellationToken.None` 이 맞는지 [4] · 합류 판단.
4. **기록 쓰기가 세션 autocommit 에 기댐** — `BeginHistoryAsync` · `FailHistoryAsync` · `RecordPreBackupAsync` 는 거래 밖 단문. `ResetSessionAsync` 가 `autocommit = @@GLOBAL.autocommit` 로 되돌리므로 전역 0 인 PC(D15 전제)에서는 뒤따르는 `SET autocommit = 1` 이나 영구 표 `DROP TABLE`(암묵 커밋)이 **우연히** 커밋해 줄 때만 남는다. 지울 임시 표가 0 이면 `failed` 줄이 연결 닫힘과 함께 사라진다. D15 ③ 시험은 붓기만 잰다.
5. **활성 계정 조각 복사 1** — `CountBackupOnlyLinkMismatch` 가 `u.is_deleted = 0 AND u.is_active = 1 AND … 'resigned+%' … 'retired+%'` 를 글로 따로 적음(덧2-4 ③ 독립 셈 의도 · 어긋나면 멈춤 쪽 = 안전 방향). 다만 둘을 묶는 게이트가 없어 표식이 늘면 복원이 늘 멈춘다. 빈칸 정규화 뒤 `ActiveAccount("u")` 와 같은 뜻인지 보는 게이트 1 또는 「허용 복사 1」 로 명세서에 적기.
6. **R′ 의 「계정 없음」 = `u.is_deleted = 0` 만**(`ResignTargets`) — 셋째 정의 · 상수 밖. `resigned+` · `retired+` 계정(지우지 않음)의 백업에만 있는 결재자는 ② 에서 연결 NULL 인데 R′ 에 안 들어 결재 줄이 켜진 채 남을 수 있다. 설계 글(보1)과 대조는 [4] 몫.
7. **「`@t` 하나」 글자** — `ResignLinesOff` · `ResignDocsRecall` 은 `@TenantId`(옛 퇴사 뒤처리 글 그대로). 값은 같아 길은 0. C6 게이트는 글자 회사 값만 막고 「회사 칸 있는 표 문장마다 `@t` 묶음」 은 안 잰다.
8. **라이브 표 엔진을 ④ 가 안 봄** — 변환기는 임시 표에 `ENGINE=InnoDB` 를 요구하나, 라이브 「백업 값」 표는 옛 마이그(`DB-02_3tier_schema.sql` 등 `ENGINE` 없는 `CREATE TABLE`)라 서버 기본값에 기댐. 비거래 엔진 표가 하나라도 있으면 ⑤ 되돌림 뒤 그 표만 반쯤 바뀐 채 남는다. ④ 에 `information_schema.TABLES.ENGINE = 'InnoDB'` 1 질의.
9. **P3-9 게이트가 글자 검사** — `P3_9_오류글_옮기기0` 은 `Message = …ex.Message|LogDetail` 정규식. `var m = ex.Message; … Message = m` 꼴은 못 잡음. 합류 때 동작 시험(걸이로 표식 글 든 예외 → 응답 `Message` ∈ 고정 표 · 틀)으로.
10. **D1 이름이 응답에 실림** — `users.user_name`(평문 varchar 50 · 로컬) 최대 5명. 본사 전송 0 · 대표에게만이라 #18 영향 0. 합류 조건: 화면 B 는 글로만 그림(MarkupString 0) · `AccountNames` 를 로그 · 감사 · 본사 길에 싣지 않음.
11. **바쁨 확인이 ④ 앞 한 번** — D4 · D13 은 ④ 앞에서만 읽음 · ④ ~ ⑤ 사이에 자료이관 · 워치독 업데이트가 시작되면 다시 안 봄. 합류의 점검 상태가 새 요청은 막지만 워치독(다른 프로세스)은 못 막음 → ⑤ 직전 한 번 더 읽기(값싼 1줄) 판단.
