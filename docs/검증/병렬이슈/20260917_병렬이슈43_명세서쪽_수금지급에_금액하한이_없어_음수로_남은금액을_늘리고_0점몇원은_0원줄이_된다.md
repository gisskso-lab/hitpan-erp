## 원인 (파일:줄)
- `CollectionService.cs` `EnsureCollectionTargetAllowedAsync` 명세서 쪽: `if (request.Amount > remaining)` 상한만. 지급 `EnsurePaymentTargetAllowedAsync` 도 같다. 이월잔액 쪽만 `amount <= 0` 거절(`LegacyBalanceMatching.cs:210`).
- ref 없는 수금·지급은 금액 검사 자체가 없다(종전부터).
- `amount > 0m` 은 0.004 도 통과 — 칼럼 `decimal(15,2)`.

## 재현·실측
- 코드 읽음: 거래명세서 합계 110,000 에 −50,000 수금 → collected −50,000 → remaining 160,000 → 이어서 160,000 수금 통과(P2 「남은 금액 초과 거절」 우회). ⚠️미실측(서버 기동 안 함).
- 격리 33306(`sql_mode=STRICT_TRANS_TABLES`): amount 0.004 INSERT → `Note 1265 Data truncated` · 저장값 **0.00** (오류 아님). 이월잔액 매칭 0원 줄·0원 분개가 생긴다.

## 요구
- 수금·지급 등록 공통 입구에서 `Amount > 0` 이고 소수 둘째 자리까지(`decimal.Round(a,2)==a`) 아니면 400.
