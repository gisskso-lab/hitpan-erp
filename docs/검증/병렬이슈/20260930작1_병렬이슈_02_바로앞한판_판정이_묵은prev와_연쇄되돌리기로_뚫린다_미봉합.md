## 경우 ① — 묵은 `prev` (W 제외의 부작용)
설계 §3-3 ①: 「`prev\version.txt` 가 곧 바로 앞 판(**보존은 직전 교체에서만 생긴다**)」. 이 문장은 **워치독도 교체 때마다 `prev` 를 새로 채운다(갈래 W)** 는 전제 위에 있다. 개정 결재가 W 를 뺐다(워치독 무변경) ⇒ `prev` 를 만드는 것은 **수동 업데이트뿐**이고, 워치독 자동 업데이트는 `prev` 를 건드리지 않는다.

| 순서 | 일 | 현재 판 | `prev\version.txt` |
|---|---|---|---|
| 1 | 수동 업데이트 N → N+1 | N+1 | N |
| 2 | 자동(팝업) 업데이트 N+1 → N+2 — 워치독은 `prev` 무접촉 | N+2 | **N (묵음)** |
| 3 | 「이전 버전으로 되돌리기」 — 재료 ① 이 1순위 | → **N** | — |

⇒ **N+2 에서 N 으로 두 판** 되돌아간다. N+1·N+2 의 마이그가 모두 남은 DB 위에서 N 이 돈다. G-M1 `rollback-floor.txt` 도 「현재 패키지(N+2)」 한 판 기준이라 N+1 의 파괴형 마이그를 모른다.

## 경우 ② — 연쇄 되돌리기 (한 번에 한 판 × 여러 번)
「한 판」은 **호출마다** 판정되고 누적되지 않는다. 되돌리기는 DB 를 안 쓴다(§5) ⇒ DB 는 계속 가장 높은 판의 모양이다.
- N+2 → N+1 (재료 ①) 뒤, N+1 에도 메뉴가 있다(§13-2 효력 시점 N+1 부터).
- N+1 에서 재료 ① 은 소진 → 재료 ② 워치독 staging zip(삭제 코드 0 · [1-V] P3) 에서 「현재보다 낮은 최고 판」 = N · 이력 `local_update_apply_status` 에 「N 성공 → N+1 성공」이 **이어서** 있다 ⇒ 통과.
- ⇒ N 으로 또 간다. 코드 N · DB N+2. 설계 §6 「1.3.48 ↔ N+1 사이 마이그 = DB-135 하나」 식의 **한 판 호환 검토**는 이 경우를 덮지 못한다.

## 권고 (봉합 조건)
1. **재료 ①**: `prev` 에 `version.txt` 만이 아니라 **「어느 판으로 바꾸면서 남겼나」(`replaced_by`)** 를 함께 적고, `replaced_by = 현재 판` 일 때만 쓴다. 아니면 재료 ① 없음 처리(묵은 `prev` 는 되돌림 재료가 아니다).
2. **연쇄 차단(①②공통)**: 이 PC 가 이미 되돌린 상태면 다시 되돌리지 않는다. 판정은 읽기만으로 가능 — 예) `schema_migrations` 에 **현재 코드가 모르는 마이그 id** 가 있으면(= DB 가 코드보다 앞서 있다) 거부 · 또는 일꾼 결과 기록(`%ProgramData%\HitPan\rollback\` 의 마지막 `success` 가 rollback 이고 그 뒤 업데이트가 없으면) 거부. DB 쓰기 0 원칙과 부딪히지 않는다.
3. 설계 §3-3 ① 문장(「보존은 직전 교체에서만」)은 W 제외 뒤 **거짓** ⇒ ⬛ 표시하고 위 1 로 대체.
