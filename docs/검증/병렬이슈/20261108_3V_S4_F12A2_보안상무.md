## ① `_open` 은 9.3 의 열림과 언제 어긋나나 (볼 것 ①)

### 1-1 맞물림 근거 — `_open` = `_openState.Value` 의 동기 거울
- 9.3 의 열림 값은 `_openState` 하나(L22). 바뀌는 곳은 **L525 `SetValueAsync(false)` · L586 `SetValueAsync(true)` 두 곳뿐**(`grep _openState` — 나머지 L501 · L513 · L607 · L653 · L715 · L1016 · L1133 은 읽기만).
- `SetValueAsync`(Param L128~150)는 `_value` 를 먼저 바꾸고 **값이 달라졌을 때만** 콜백을 부른다. 콜백 = `new(null, 대리자)` → 받는 쪽 null 이라 대리자를 바로 부름 → `OnMenuOpenChangedAsync` 첫 줄 `_open = open;`(:172)이 **첫 await 전에** 끝난다. 사이에 다른 사건이 끼어들 틈 0.
- 부모가 다시 그려도 조용히 안 바뀐다: `OnParametersSet`(Param L161~171)은 `_lastValue` ↔ 매개변수 `Open` 이 다를 때만 `_value` 를 덮는다. 이 칸은 `Open` 을 안 넘김(:43~50) → 둘 다 늘 false → 덮어쓰기 0 · 콜백 없는 전이 0. `WithChangeHandler(OnOpenChanged)`(L56 · L482)도 같은 이유로 안 불림.
- 초기값: `_open` 기본 false · `_openState` 초기 = `Open`(false · Param L153~159). 같다.
- 결론: **값 기준으로는 어긋남 0.** 어긋날 수 있는 것은 「값」 과 「화면(팝오버 DOM)」 사이 — 값이 바뀐 뒤 L526 · L587 `StateHasChanged` 렌더가 브라우저에 닿기까지 1 왕복 이내.

## ② 마우스로 연 목록 Esc(E1-a 본래 목적) (볼 것 ②)
- 길: 9.3 내장 단추(`MudMenu.razor` L47~65 · `OnClick=ToggleMenuAsync` L16 상대줄) → L653 닫힌 값 → `OpenMenuAsync` → **L586 `SetValueAsync(true)` → 콜백 → `_open = true`**. 마우스든 키보드든 같은 L586 하나뿐 → 마우스로 연 목록도 `_open` 참.
- 그 뒤 초점이 칸 안 단추에 남아 Esc keydown 이 칸 div `@onkeydown`(:21)에 오면 `!_open` 거짓 → 고침 A 줄(:156) 그대로 → 닫힘 + 단추 초점. **E1-a 목적 유지(원문상).**
- 단서 ⓐ: 열린 동안 렌더마다 L1016~1020 이 래퍼에 초점을 보내므로, 실물에서 Esc 가 칸 div 로 오는지 9.3 목록 쪽(L1001~1003)으로 가는지는 측정 몫 — 어느 쪽이든 닫힘. [4] §5 에서 **M12′ 미측정** → A2 머리에서 반드시.
- 단서 ⓑ: 칸 div 는 단추에 초점이 있을 때만 키를 받는다(:163). 클릭으로 단추에 초점을 안 주는 브라우저(맥 사파리 등)는 E1-a 부터의 기존 한계 · A2 무관 — 기록만.
