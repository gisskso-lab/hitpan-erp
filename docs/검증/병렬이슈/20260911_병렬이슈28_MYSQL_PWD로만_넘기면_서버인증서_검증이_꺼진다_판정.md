## 1. 사실

| # | 사실 | 근거 |
|---|---|---|
| F1 | `MYSQL_PWD` 만 준 `mariadb-dump`(11.4): exit 0 · 정상 덤프 · stderr 경고 `option --ssl-verify-server-cert is disabled, because of an insecure passwordless login.` | 🟢 선행검증서 §5 K1-1 |
| F2 | `-p{비번}` 대조군은 이 경고가 없었다 | 🟢 선행검증서 §5 판정 재료 3 |
| F3 | 클라이언트는 **명령줄 옵션으로 받은 비번**만 보고 "비번 없음"으로 판단한다. `MYSQL_PWD` 는 접속 라이브러리가 접속 순간에 읽으므로 옵션 검사 단계에서는 안 보인다 → 실제로는 비번으로 인증하면서도 검증을 끈다 | 🟡 F1 경고 문구 + 인증 성공(K1-1) 로 정합 |
| F4 | MariaDB 11.4 는 자체서명 인증서도 **비번에서 나온 값으로 서버를 확인**할 수 있다 → 비번을 옵션으로 받으면 검증이 켜지고, 못 받으면 끈다 | 🟡 11.4 기본 TLS 동작 |
| F5 | 연결 대상은 설정 `DB_HOST` — 설치 기본은 이 PC 루프백 | 🟢 `InfrastructureExtensions.cs:20` (`?? "localhost"`) |
| F6 | **API 본 연결은 같은 호스트·포트에 인증서 검증 없이 상시 접속한다** — 연결 문자열에 `SslMode` 없음 → MySqlConnector 기본값(`Preferred` = 되면 암호화, 인증서는 안 봄) | 🟢 `InfrastructureExtensions.cs:55` · `src` 전체 grep `SslMode` 0건 · 🟡 기본값 `Preferred`(공식 문서 · 로컬 XML 에 기본값 표기 없음, `MySqlConnector.xml:1470·5943`) |
| F7 | 경고는 stderr 로만 나오고 exit 0 이면 현행 코드는 예외를 던지지 않는다 | 🟢 `BackupService.cs:369` |

## 2. 루프백에서 인증서 검증이 막는 것

| 위협 | 검증이 막나 | `MYSQL_PWD` 로 새로 열리나 |
|---|---|---|
| T1 루프백 도청(수동) | 검증과 무관 — **암호화는 그대로 켜져 있다**(검증만 꺼짐). 루프백 캡처는 관리자 권한 필요 → 그 권한이면 DB·`db.conf` 를 직접 읽는다 | 아니오 |
| T2 **가짜 서버**: MariaDB 서비스가 내려간 사이 일반 사용자 프로세스가 같은 포트를 먼저 잡고 접속을 받는다 | **예** — 검증이 막는 유일한 실질 위협 | **아니오** — API 본 연결(F6)이 이미 같은 포트로 **검증 없이** 인증을 보낸다. 백업 자식이 한 번 더 보내는 것은 새 노출이 아니다 🟢 코드 비교 |
| T3 원격 호스트 연결(`DB_HOST` 가 다른 PC) | 예 | 조건부 — 그러나 이 경우도 F6 로 API 본 연결이 먼저 무검증. 이 판정은 루프백 전제, 원격이면 별도 판정(C28-3) |

**교환 비교**: `-p` 는 비번 값을 명령줄로 내보낸다 → 프로세스 생성 감사·EDR 원격 수집·다른 계정 프로세스의 명령줄 조회(작업지시서 §6). `MYSQL_PWD` 는 T2 방어 한 겹을 잃지만 그 한 겹은 **API 본 연결에 애초에 없다**. ⇒ 순이득 🟢.

## 3. 막을 인자가 있나 (평가 · 코드 0)

| 인자 | 효과 | 판정 |
|---|---|---|
| `--ssl-verify-server-cert` 명시 | 경고 문구가 "disabled" 라 명시해도 꺼질 것으로 보임 | ⬜ 격리 실측 1회로 확정 (§4 C28-2) |
| `--ssl-ca` / 지문 고정 | 11.4 자동 생성 인증서는 파일 CA 가 없고 재시작마다 바뀔 수 있음 → 고객 PC 에 배포 불가 | ❌ 비현실 |
| `--skip-ssl` | 경고는 사라지나 **암호화 자체를 끈다** — T1 방어 후퇴 · 이득 없음 | ❌ 금지 권고 |
| `--defaults-extra-file`(비번 파일) | 옵션으로 비번을 받아 검증이 켜짐 · 그러나 비번이 디스크에 남음(작업지시서 §6 ❌) | ❌ |
| `-p` 복귀 | 명령줄 노출 복귀 | ❌ |

⇒ **이득 있는 인자 없음.** 경고는 받아들이고 흐름·기록에서 오판만 막는다.

## 4. 조건 ([4] 확인)

- **C28-1** 경고가 섞인 stderr 를 **실패로 판정하지 않는다**(exit 코드로만) · 성공 시 stderr 를 `error_message`·`last_error` 에 쓰지 않는다 · 실패 시 저장되는 stderr 에 이 경고 줄이 섞여도 사용자 화면 문구가 이것을 원인처럼 보이게 하지 않는다 (게이트 G-BK1 이 성공 판정을 exit 코드로 하는지 코드로 확인).
- **C28-2** 격리 인스턴스에서 `MYSQL_PWD` + `--ssl-verify-server-cert` 명시 1회 — 경고·exit·접속 결과 기록(선행검증서 절차 재사용 C-7). 결과가 "명시하면 검증 켜지고 성공"이면 그 인자를 넣는 것이 낫다 → [3] 에 전달.
- **C28-3** 이 판정은 **`DB_HOST` 루프백 전제**. 개발명세서 「안 한 것」에 한 줄 기록 · 원격 호스트 설치 형태가 생기면 API 본 연결 `SslMode` 와 함께 별건 판정.
- 곁 기록(별건 · 이번 범위 밖): API 본 연결 무검증(F6)은 T2 에 대해 백업보다 넓은 노출이다 — 루프백 전용 설치라 실해 낮음 🟡 · 워치독 `WatchdogBackupRunner.cs:59` 의 `-p` 는 #43 무접촉.
