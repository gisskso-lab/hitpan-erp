## 무엇이 문제인가
- 수동 업데이트 순서: 확인 → 받기 → 해시 → **백업**(`ManualUpdateService.cs:339-343`) → 넘기기(`:388-396`).
- 런처는 넘기기에서 처음으로 `Slot`·설치 루트·일꾼 원본·작업 폴더 안전을 본다(`LocalSwapLauncher.cs:116-119, 124-135`). `Slot` 은 db.conf `SLOT_INDEX` 가 없으면 null(`LocalSwapLauncher.cs:324`) ⇒ `request_invalid` 거부. 이 거부는 요청서를 안 쓰므로 **쿨다운도 안 걸린다**(`:87-88` 은 요청서 상태로만 판정).
- 앞단 판정 `Start` 는 `CheckBusy` 만 본다(`ManualUpdateService.cs:205`) · 확인 화면 `CheckAsync` 도 같다 ⇒ 화면은 「업데이트 가능」을 보여 준다. 되돌리기도 `GetStatus` 가 슬롯을 안 보고 확인 번호를 준다(`LocalRollbackService.cs:34-47`) → [예] 에서야 거부.
- 백업 보관은 파일 개수 기준 30개(`BackupService.cs:69` · `ApplyRetention :592-603` — 종류 구분 없음).

## 발생 시나리오
- SLOT_INDEX 가 없는 옛 db.conf(워치독 주석 `DbConfReader.cs:69` 「구버전 db.conf·LOCAL」 — 실재 여부 ⚠️미확인) PC 에서 관리자가 「업데이트」 → 몇 분 받고 백업하고 「요청이 올바르지 않습니다」 → 다시 누름 × 30 ⇒ 매일 백업 30개가 전부 **같은 날 같은 모양**으로 바뀐다. 그 전 상태로 돌아갈 복원 지점이 없어진다.
- 폴더 안전 판정 실패(`folder_unsafe`)·일꾼 원본 없음(`script_missing`)도 같은 경로.

## 막는 방향 (한 줄)
런처의 정적 판정(슬롯·루트·원본·폴더 안전)을 `CheckBusy` 와 같은 「사전 판정」 으로 빼서 확인 화면·`Start`·`GetStatus` 가 받기·백업 **전에** 부르게 하고, 넘기기 거부도 쿨다운에 넣는다.
