## 무엇이 문제인가
- 예약은 `TryReserve` 때 한 번 시각을 찍고(`LocalSwapLauncher.cs:~200-209`), 30분(`OpenRequestStale`) 넘게 **갱신이 없으면 없는 것으로 본다**(`ExpireReservation :230-236`).
- 수동 업데이트는 `Start` 에서 한 번 예약하고(`ManualUpdateService.cs:~230`) 받기(`:331`)·백업(`:366`) 동안 **다시 예약하지 않는다**(호출처 grep: `TryReserve` = `Start` 1곳·되돌리기 1곳뿐). 해제는 넘기기 뒤(`:407`).
- 되돌리기 쪽은 `ManualUpdateService` 의 작업 여부(`_job.IsRunning`)를 보지 않고 예약만 본다(`LocalRollbackService.cs:69-70`).
- ⇒ 받기+백업이 30분을 넘으면 예약이 풀린 것으로 판정되고, 그 사이 누른 되돌리기가 통과한다. 일꾼 S3 가 API 를 멈추면 **같은 프로세스 안에서 돌던 수동 업데이트 백업이 한가운데서 끊긴다**.

## 발생 시나리오
1. DB 수 GB · 느린 HDD PC 에서 관리자 A 가 「업데이트」 — 받기 10분 + 백업 25분.
2. 35분째(백업 중) 관리자 B 가 「이전 버전으로 되돌리기」 [예] → `TryReserve` 성공(만료) → `Launch` → `CheckBusy`: 수동 업데이트는 아직 요청서·`swap.lock` 을 안 썼으므로 통과.
3. 일꾼 S3 → API 정지 → 백업 파일 반쪽이 `HitpanBackup`/백업 폴더에 남음(보관 30개 중 1개 차지 · 복원 지점처럼 보이는 불량 파일). A 의 화면은 끊기고 결과·사용 기록 없음.

## 막는 방향 (한 줄)
예약 만료를 「시각」이 아니라 「주인의 생존」에 묶는다 — 수동 업데이트가 단계마다 예약을 갱신(`TryReserve(owner)` 재호출)하거나, 되돌리기 판정에 `ManualUpdateService` 작업 진행 여부를 한 줄 더 본다.
