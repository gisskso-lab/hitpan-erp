### ② `_busy` 가 실패 갈래에서 내려가나 (내려감 · 영구 잠김 0)

`_busy = true`(:1473) ~ `try`(:1479) 사이는 속성 읽기 하나뿐(던질 것 없음). 실패 응답(else · 본문 읽기 예외 포함) · 요청 예외 · 지우기 루프(항목마다 자체 catch) · `Close` 예외 전부 `finally`(:1512~:1515)를 지난다. 검증 실패(:1461~:1465)는 `_busy` 를 켜기 전에 돌아간다. **고객이 영영 못 닫는 창은 없다.** 다만 시간 상한은 아래 P3-1.

### ③ `SameBackgroundPath` 의 null · 빈 값 · 공백뿐 (유해 길 0)

- 어느 한쪽이 비면 「같지 않다」(:1063~:1064). 보낸 값이 null · 빈 값 · 공백뿐 → 목록 전부 지움 = 양식 행이 아무 파일도 가리키지 않으니 맞다. 목록에는 빈 값이 들어갈 수 없다(:1194 검사).
- 잘못 「같다」 → 건너뜀 = 파일 남음(무해) 쪽뿐. 잘못 「다르다」 → 지움(유해) 쪽은 서버가 같은 파일로 푸는데 화면이 다르게 읽는 모양에서만 생긴다 → P3-2.

### ④ `BgUnsavedNow` 가 실제로 바뀐 양식을 저장 안 하고 닫게 하나 (P1 0)

- `BgRemoveUndone`(:1075~:1077)이 참이려면 화면 그림 경로 = 불러온 양식 그림(공백 · 대소문자만 다름)이어야 한다 → 그림은 저장된 그대로 = 그림 쪽에서 잃는 것 없음.
- 다른 칸(이름 · 좌표 등)만 바뀐 경우: 종전(`!_bgUnsaved` → 바로 닫음)도 되묻지 않았다 — 되묻기는 처음부터 그림 전용. 좁은 한 길(뺌 → 도로 적음 → 이름 고침 → [취소])에서 종전엔 **엉뚱한 그림 문구로 우연히** 되물었고 이제는 안 묻는데, 이는 고객이 [취소] 를 직접 누른 것이라 저장된 데이터 손실이 아니다. 회귀 아님 · 기록.
- 반대 방향(사실과 다른 되묻기)은 남음 → P3-3.
