# PI-07 — char(36) 이 Guid 로 와서 양식템플릿 화면 500

| 항목 | 내용 |
|---|---|
| 적발일 | 2026-08-12 |
| 적발자 | **사장님 실측** (샌드박스 · 삼화페인트백화점(테스트) · 1.2.69) |
| 등급 | **P0** — 화면이 아예 안 열림. char(36) 쓰는 표 전체에 잠복 |
| 상태 | 🟢 봉합 완료 (연결문자열 9곳 + 재발방지 시험) |

---

## 1. 무엇이 났나

설정관리 → 양식템플릿 진입 시:

```
양식 목록 조회 실패: net_http_message_not_success_statuscode_reason, 500, Internal Server Error
```

고객 PC 로그에 남은 진짜 원인:

```
System.Data.DataException: Error parsing column 0 (TemplateId=0a4cbd4b-... - Guid)
  RequestPath: /api/settings/form-templates
  RequestPath: /api/settings/form-templates/seed-defaults   ← 시드도 같이 죽었다
```

## 2. 원인

**MySqlConnector 는 기본으로 `CHAR(36)` 컬럼을 `Guid` 로 돌려준다.**
우리 DTO 는 이런 ID 를 전부 `string` 으로 받으므로 Dapper 가 값을 못 넣고 터진다.

**⚠️ 왜 여태 안 터졌나 — 대부분의 표가 `varchar(36)` 이라서다.**

| 표 | 컬럼형 | 드라이버 반환 | 결과 |
|---|---|---|---|
| `partners.partner_id` | **varchar(36)** | String | 멀쩡 |
| `form_templates.template_id` | **char(36)** | **Guid** | **500** |

같은 폭탄이 `common_codes` · `item_specs` · `migration_jobs` · `sync_tokens` ·
`etax_send_history` · `device_register_tokens` · `reseller_applications` 등
**char(36) 을 쓰는 표 전체**에 잠복해 있었다. **화면을 안 열어봤을 뿐이다.**

## 3. 실측 — 개발 PC 에서도 그대로 재현됐다

사장님 오류와 **글자 하나까지 같은 메시지**가 나왔다.

```
① 지금 운영 설정 (GuidFormat 없음)   FAIL  Error parsing column 0 (... - Guid)  ← 사장님 오류와 동일
② GuidFormat=None  ← 봉합안          OK    반환형=String, 3행 정상
③ GuidFormat=Char36 (대조군)         FAIL  Error parsing column 0 (... - Guid)
```

⇒ **환경 차이가 아니었다.** 개발 PC 에서도 똑같이 터지는데 그 화면을 안 열어봤을 뿐이다.
   (사장님 원칙 — *"개발환경 PC 정상작동은 큰 의미 없다"*. 이번엔 개발 PC 조차 정상이 아니었다.)

## 4. 봉합

연결문자열에 **`GuidFormat=None`** 추가 — *"Guid 로 바꾸지 말고 있는 그대로(String) 달라"*.

**⚠️ 연결문자열을 만드는 곳이 9곳이다** (각자 복사본). 하나만 고치면 그 경로만 낫는다.
전부 적용했다:

| # | 파일 |
|---|---|
| 1 | `InfrastructureExtensions.cs` (런타임 주 경로) |
| 2 | `MigrationDbConnectionFactory.cs` |
| 3 | `AppDbContextFactory.cs` |
| 4 | `CompanyBootstrapProvisioner.cs` |
| 5 | `MainPcRegistrationService.cs` |
| 6 | `IntegrityCheckService.cs` |
| 7 | `IdempotencyCleanupService.cs` |
| 8 | `AuditLogMiddleware.cs` |
| 9 | `WebhookInboundController.cs` |

## 5. 재발방지 — 소스 스캔 시험

새 연결문자열을 만들면서 이 옵션을 빠뜨리면 **그 경로만 조용히 터진다.**
빌드도 통과하고 다른 화면도 멀쩡해서 **그 화면을 열기 전까지 아무도 모른다.**
⇒ `ConnectionStringGuidGuardTests` 로 CI 가 잡는다.

### 🔴 그 시험이 처음엔 "막는 척만" 했다

처음 판은 **주석에 든 `GuidFormat=None` 을 보고 통과**시켰다.
일부러 옵션을 빼고 돌렸는데 **통과했다** — 게이트가 아무것도 안 막고 있었다.

⇒ 주석을 걷어낸 뒤 코드만 보도록 고쳤고, **양방향으로 증명**했다:

| 상태 | 결과 |
|---|---|
| 일부러 옵션 제거 | **실패** ✅ (잡는다) |
| 원복 | **통과** ✅ |

> **교훈**(PI-06 과 같다): 게이트를 넣으면 **일부러 깨뜨려 보고** 실제로 잡는지 확인한다.
> 통과만 확인하면 "막는 척만 하는 게이트" 를 진짜로 착각한다. 오늘 하루에 두 번 겪었다.

## 6. 곁가지 확인 — 샌드박스는 옛 비번 설치본이었다

```
user=hitpan_t003  db=hitpan_erp_t003  pwlen=32
```

**32자 = 옛 무작위 비번.** 비번 통일(PR#112) 이전 설치본이고 자동 업데이트로 1.2.69 만 받았다.
`HitPan-Universal.iss` 주석에 적어둔 한계가 실측으로 확인됐다 —
**자동 업데이트는 설치 EXE 를 실행하지 않으므로 옛 설치본은 재설치 전까지 옛 비번을 유지한다.**
CS 응대 시 이 PC 들은 `db.conf` 에서 비번을 읽어야 한다.

## 7. 곁가지 확인 — PI-05 봉합은 정상 작동했다

같은 로그에서 확인:

```
[MigrationRunner] 적용 완료: DB-90 (DB-90_form_templates_print_options.sql)
[MigrationRunner] 완료 — 신규 적용 1건, 멱등 skip 60건
```

**DB-88·89·90 전부 적용됨.** PI-05(`AllowUserVariables`) 봉합이 고객 PC 에서 실제로 돌았다.
⇒ 처음 의심했던 "마이그 실패" 는 **아니었다.** 그건 잘 갔다.
