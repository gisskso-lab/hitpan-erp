## 1. 봉합한 결함 8건

### 1-1. 🔴 P0 — 기능이 아예 안 되던 것 3건

| # | 자리 | 증상 | 실측 |
|---|---|---|---|
| **C-1** | `AbsenceService` INSERT | **휴직 저장 100% 실패** | `ERROR 1364: absence_type doesn't have a default value` |
| **C-2** | `ChatService` 경비 갈래 | 경비 첨부 **500** | `ERROR 1054: Unknown column 'status'` |
| **C-3** | `ChatService` 보고서 갈래 | 보고서 첨부 **500** | `ERROR 1054: Unknown column 'report_date'` |

**대조 실험 — 봉합의 증명**

```
[봉합 전] SELECT status FROM expenses         → ERROR 1054
[봉합 전] SELECT report_date FROM hr_reports  → ERROR 1054
[봉합 전] INSERT INTO employee_leave_of_absence (...) → ERROR 1364

[봉합 후] 경비·보고서 쿼리 → 정상 실행(0행)
[봉합 후] 휴직 INSERT      → INSERT OK
```

🔴 **원인은 하나다 — 헌법 #13(새 SQL 작성 전 DESCRIBE 의무)을 안 지켰다.**
컬럼 이름을 확인하지 않고 **추측해서** 썼다.

**봉합**
- C-1 → `DB-102` 로 `absence_type` 기본값 `'other'` + INSERT 에 명시
  (컬럼은 지우지 않는다 — 헌법 #1·#37 *"안 읽힌다 ≠ 잔재"*)
- C-2 → `status` → **`approval_status`**
- C-3 → `report_date` → **`submitted_at` · `period_start`**

### 1-2. 🔴 보안 3건

| # | 자리 | 위험 |
|---|---|---|
| **S-1** | 경비 갈래에 `employee_id` 필터 누락 | 직원이 **회사 전체 경비** 열람 → 남의 경비를 대화방에 붙일 수 있었다 |

목록에 뜨면 붙일 수 있고, 받은 사람은 그 문서로 가는 링크를 얻는다.

### 1-3. 조용히 틀리던 것 2건

| # | 자리 | 증상 |
|---|---|---|
| **Q-1** | `AnnualLeaveService` 근속 계산 | `Math.Round(days/365.25, 2)` → **364일이 1.00 년**으로 판정 |
| **Q-2** | `GetSettingsAsync` | `INSERT IGNORE` 후 **코드 상수**를 돌려줌 → 고객사가 정한 한도 무시 |

**Q-1 실측**

| 입사일 | 근속 | 봉합 전 | 봉합 후 |
|---|---|---|---|
| 2026-01-01 | **364일** | 1년 이상 갈래 | **1년 미만 갈래** |
| 2024-01-01 | 3년 | 16일 | **15일**(설정 그대로) |
| 2022-01-01 | 5년 | 17일 | **16일** |

⇒ 반올림을 걷어내고 **실제로 지난 햇수**(`CompletedYears`)로 판정한다. 가산 주기의 `+1` 도 제거.

🔴 **숫자가 커지는 것이 문제가 아니다.** 잘못된 `grant_type` 으로 저장되면
`uk_grant_emp_year_type`(UNIQUE) 때문에 **담당자가 나중에 고치지도 못한다** —
수동으로 정할 자유를 코드가 뺏는다(반자동 원칙 위반).

**Q-2** 는 사장님 기조 그대로 봉합했다 — *"고객사가 입력한 값만 우리는 처리해 주면 되는걸로"*.
코드 값은 **첫 줄을 만들 때만** 쓰고, 그 뒤로는 설정표를 다시 읽는다.

## 2. 🔴 사장님 기조 반영 — 법을 코드에 넣지 않는다

> *"우리가 고객사 근로기준법 까지 생각할 필요는 없어. 국세청, 고용노동부 법령은 수시로 바껴.
> 이걸 우리가 자동화 시키며 일일히 할 필요까진 없다."*
> *"업종, 사업장 노동자수, 면세사업자, 일반사업자, 사회적기업, 법인사업자 상장기업 등등
> 기준도 너무 달라서 표준을 잡기 어려워."*
> *"고객사가 입력한 값만 우리는 처리해 주면 되는걸로"*

⇒ 봉합 중 **법 조항을 근거로 적은 주석을 전부 걷어냈다.**
법을 근거로 남기면 다음 사람이 *"법이 바뀌었으니 코드를 고쳐야 한다"* 고 오해한다.

**남긴 것**: 설정표에서 읽는 제안값 하나. 그것도 담당자가 덮어쓴다.
**고친 이유**: 법정 정확성이 아니라 **설정을 잘못 읽던 계산식**이다.
