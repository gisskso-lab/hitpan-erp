### 4-2. 🔴 G-RC16 보고표가 **재현되지 않는다** — PM §10-2 와 다른 값

### 4-3. 🔴 G-RC17 **0% 칸은 측정 실패(-1)를 그대로 통과시킨다** — 거짓 초록 구멍

V-2 에서 PM 이 한 주장(*「끝내 못 잡으면 `-1` 을 그대로 둔다 — 거짓 초록을 안 만든다」*)의 **반쪽만 맞다.**
`-1` 은 확실히 **반환**된다. 🔴 **그런데 `G_RC17_PairInequality` 의 0% 칸은 그 `-1` 을 잡지 못한다.**

코드(`RcSafePathGateTests.cs` `G_RC17_PairInequality`):

```csharp
if (s.Sum != 0 && s.Locked <= 0)     // ← A-1′ 가드
    failures.Add("A-1′ 위반 …");
```

* 0% 칸은 **정의상 `s.Sum == 0`** 이다 (PM 자신이 「0% 칸은 맞은 전표가 하나도 없다가 정의라서 구조적으로 0」이라고 적었다).
* ⇒ **가드의 첫 조건이 거짓** ⇒ A-1′ 를 **건너뛴다.**
* 이어서 `ratio = (double)s.Locked / b.Locked = -1 / 110661 = -0.000009`
* 판정식은 `if (ratio > 0.80)` 뿐이다 ⇒ **음수는 언제나 통과.**

🔴 **결론: 0% 칸에서 `innodb_trx` 재조회가 12회 모두 실패하면, G-RC17 쌍 부등식은 「비 -0.0000 · 통과」로 초록을 낸다.**
이것은 가설이 아니다 — **PM 의 `run1` 로그(§9-1)가 정확히 그 모양이다**:
`채움 0% … 봉합후 -1 · 비 -0.0000 · 판정`. 그때 빨간불을 낸 것은 **별개 시험인 A-3** 이었지 이 게이트가 아니었다.
⇒ **A-3 시험이 없었거나 그 회차에 A-3 이 우연히 잡혔다면, 0% 칸의 측정 실패는 아무도 못 봤다.**

⚠️ **덧붙임**: `fill > 0` 칸은 `s.Sum != 0` 이라 가드가 산다. **구멍은 0% 한 칸이다.**
🔴 **그리고 0% 는 작2 가 「이관 직후」로 가장 중요하게 본 칸이다.**

### 4-4. ⚠️ 살아있음 단언이 **다른 실패에 가려진다**

`G_RC16_NeighborProbes_W3` 의 살아있음 검사:

```csharp
if (failures.Count == 0 && baselineBlockedTotal == 0)
    failures.Add("🔴 살아있음 위반 …");
```

🔴 **다른 실패가 하나라도 있으면 살아있음 검사를 아예 안 한다.**
「W-3 위반 1건 + 살아있음 0건」인 회차에서 보고에는 **W-3 만** 뜬다 — *게이트가 아무것도 안 재고 있다* 는 더 중요한 사실이 가려진다.
⚠️ 초록 회차에는 영향이 없다(그때 `failures.Count == 0`). **우선순위 낮음 · 별건 권고.**
