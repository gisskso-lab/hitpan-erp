## 1. ④ 직원계정 등록했는데 사원이 없다 — 🔴 P0 진범 확정

### 증상
직원계정관리에서 등록 → **자식계정은 생성됨** → 그런데 사원관리·HR직원현황·
메신저 어디에도 **그 사람이 없음.**

### 진범 — 채번 충돌 + 트랜잭션 없음, 두 개가 겹쳤다

`UserService.CreateAsync` 는 `users` 와 `employees` **둘 다** 넣는다. 그런데:

```sql
-- UserService.cs:156  사번 채번
SELECT COALESCE(MAX(CAST(SUBSTRING(emp_no, 5) AS UNSIGNED)), 0) + 1
FROM employees WHERE tenant_id = @TenantId AND emp_no LIKE 'EMP-%'
```

🔴 **`EMP-%` 만 센다.** 그런데 실측한 이 DB 의 사번은:

```
0001            ← 부모계정 (AuthService 백필이 만든 형식, 접두 없음)
LEGACY_FALLBACK
MIG-0001 ~ MIG-0010   ← 마이그레이션분
```

**`EMP-` 형식이 0건이다.** ⇒ 채번이 **항상 `1`** 을 돌려준다 ⇒ 언제나 `EMP-001`.

`employees` 에는 **`uq_tenant_empno (tenant_id, emp_no)` UNIQUE** 가 있다(실측).
⇒ 두 번째 자식계정부터 **INSERT 실패.**

그리고 `CreateAsync` 에 **트랜잭션이 없다**(실측 — `BeginTransaction` 0건).
⇒ `users` INSERT 는 **이미 커밋됐다.**

```
users      INSERT ✅ 커밋됨      ← 계정은 생겼다
employees  INSERT ❌ 사번 충돌   ← 사원은 안 생겼다
           (되돌릴 트랜잭션이 없다)
```

**이것이 사장님이 보신 그대로다.**

### 왜 되돌릴 수도 없나 (더 나쁜 부분)

한 번 이렇게 되면 **스스로 못 고친다**:

| 시도 | 결과 |
|---|---|
| 같은 이메일로 재등록 | "이미 사용 중인 이메일입니다" 로 막힘 |
| 사원관리에서 그 사람 추가 | **user_id = NULL 인 별개 행**이 하나 더 생긴다(연결 안 됨) |
| 로그인하면 자동 복구되나 | ❌ 백필은 **`tenant_admin` 에만** 돈다. 자식은 제외 |

🔴 **기존 계정을 사원에 잇는 화면·API 가 아예 없다.** DB 직접 수술 외엔 길이 없다.

### 곁가지 결함 2개
- **`dept_id` 를 안 넣는다** — 등록창에서 부서를 받는데 `employees.dept_id` 는 NULL.
  ⇒ 만들어져도 **부서가 빈칸**. 메신저 목록은 `ORDER BY d.sort_order` 라 **맨 뒤로 밀린다.**
- `POST /api/users/children` 는 **아무것도 안 쓰는 빈 껍데기**인데 `202` 를 돌려준다.
  지금 화면은 안 쓰지만, 쓰는 순간 "성공했다는데 아무것도 없음" 이 된다.

## 2. ⑤ 권한 다 풀었는데 자식계정이 막힘 — 🔴 P0 구조적

### 증상
메인PC 부모계정으로 자식계정 권한을 **전부 켰는데**, 클라이언트PC 첫 접속에서
**아무것도 못 함.**

### 진범 — 저장하는 표와 막는 곳이 다르다

```
권한설정 [저장]  →  user_permissions 표에 기록 ✅
                          ↕  서로 안 본다
화면 진입 차단   →  [Authorize(Policy="TenantAdminOnly")]
                     = JWT 의 account_type 만 본다 ❌
```

자식계정은 `account_type = "tenant_user"` ⇒ 상품마스터를 누르면
**컨트롤러 코드가 돌기도 전에 403.** `user_permissions` 는 **읽지도 않는다.**

⇒ **권한을 20개 다 켜도 소용이 없다.** 컨트롤러 **15개**가 통째로 이 상태다
(사원·부서·직급·창고·마감·인증서·연차·결재라인·과금…).

### 더 나쁜 것 — 체크박스 절반이 아무 데도 안 붙어 있다

권한설정에서 켤 수 있는 **20개 중 11개**는 서버에 강제 장치(`[RequirePermission]`)가
**아예 없다**: 상품·업체·거래명세·견적·재고·원장·BOM·수주·발주·매입·대시보드.
⇒ 켜도 꺼도 **서버 동작이 같다.**

### 왜 여태 안 잡혔나
`PermissionService:231` — **`tenant_admin` 은 권한검사를 통째로 건너뛴다.**
부모계정은 모든 정책을 통과하고 권한검사도 우회한다.
⇒ **이 기능은 자식계정만 밟는 길이고, 우리는 그 길을 한 번도 안 밟았다.**

### 첫 접속에서 즉시 막힌 것은 별개 원인일 수 있다
| 후보 | 실측 |
|---|---|
| 기기승인 미들웨어 | ❌ 아님 — `DeviceApproval:Enabled = false` 확인 |
| **약관동의 미들웨어** | 🔴 **유력** — 자식계정도 **면제 없음**. 동의 기록 없으면 **모든 API 403** |

⇒ 자식계정 첫 로그인 시 약관 4건 동의 화면이 제대로 뜨는지 확인 필요.

## 3. ① 화면 아래 흰 띠 — 🔴 **진범 확정** (사장님 Network 탭이 잡았다)

### 사장님 화면이 보여준 것
```
departments        403   ← 자식계정이 TenantAdminOnly 에 막힘 (§2 와 같은 건)
messages?limit=50  403
messages?limit=50  400   ← 🔴 이게 흰 띠다
messages?limit=50  400   (반복)
```

### 진범 — `Forbid(문자열)` 오용

`ChatController.cs:107` 등 **4곳**:
```csharp
catch (UnauthorizedAccessException ex)
{
    return Forbid(ex.Message);        // 🔴
}
```

**ASP.NET Core 의 `Forbid(string)` 은 그 문자열을 에러 메시지가 아니라
`인증 스킴 이름`으로 받는다.** `ChatService` 가 던지는 값은:
```
"이 대화를 볼 수 있는 권한이 없습니다."   (ChatService.cs:297)
```
그런 이름의 인증 스킴은 없다 ⇒ **서버가 예외를 던진다** ⇒ 403 이 아니라
**400/500 이 나가고**, 클라이언트는 그 응답을 해석하지 못해 **흰 띠**를 띄운다.

### 왜 전 화면·모바일에서 뜨나
`ChatButton`·`ChatPopup` 이 `TopHeader` 에 있어(`TopHeader.razor:23,29`)
**어느 화면을 열든 메신저가 같이 뜬다.** 대화 권한이 없는 방을 한 번 건드리면
그 뒤로 **모든 화면에서** 흰 띠가 따라다닌다.

### 해당 4곳
`ChatController.cs` **107 · 125 · 206 · 232** — 전부 `Forbid(ex.Message)`.

⇒ `StatusCode(403, new { message = ex.Message })` 로 바꾼다.
**메시지를 사람에게 보여주면서 403 도 정확히 나간다.**

⇒ **한 줄 보여주려고 매번 전부 다시 읽는다.** 카카오톡처럼 "새 줄만 붙이는" 구조가 아니다.

## 6. ⑥ 계층분리 점검

②⑤ 결론과 한 몸이다. 지금은 계층이 분리된 게 아니라:

```
부모(tenant_admin) = 모든 정책 통과 + 권한검사 우회  → 전부 됨
자식(tenant_user)  = 정책에서 차단                  → 사실상 아무것도 안 됨
```

**중간이 없다.** 사장님이 말씀하신 *"고객이 설정한대로 계층분리"* 가
구조적으로 성립하지 않는 상태다. ⑤ 봉합과 함께 전수로 봐야 한다.
