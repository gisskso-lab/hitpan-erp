# §5 PM 가설이 깨진 자리 — 한 줄씩

| | 깨진 자리 |
|---|---|
| 1 | 🔴 **「결재 6·7 이면 O1-5·K1-4 가 열린다」** — 두 칸의 담당에 **법무**가 들어 있고, **약관 v2.0.0 §6** 이 이미 다른 일정을 고객에게 약속했다. **결재 6·7 은 내부 정책이고, 고객 제재의 근거는 약관이다** |
| 2 | 🔴 **「결재 7 = 사장님 결재」가 아니다** — **10/19 PM 전결**이다(결재3 `:56`). 고객에게 *"끝까지 열어 둡니다"* 를 약속하는 문장을 **PM 전결 + 코드 0건 + 약관 언급 0건** 위에 세우고 있다 |
| 3 | 🔴 **「3·7·14 = 4단계」가 아니다** — 결재는 **숫자 3개**, 단계는 **4개**. 14일에 쓰기제한과 잠금을 겹친 것은 **🟡 PM 해석**(결재2 `:114`)이다. 합격선은 *"4단계를 고객 말로"* ⇒ **PM 해석을 고객 글에 사실로 적는 자리** |
| 4 | 🔴 **「K1-6 은 열렸다」** — 합격선은 **「미확정 0」**이고 결재 6·7 이 **완전히 푸는 미확정은 0건**(§3-①) |
| 5 | 🔴 **「조임 낱말 0건」의 범위가 좁았다** — 출하 DDL 과 코드 기본값에 **「유예일 7」이 이미 산다**(§3-②). 정책 숫자는 셋, 칸은 하나 |
| 6 | 🔴 **사실 5·6 은 사실이 아니라 요구다** — 결제 이력 화면은 **영구 빈 목록**(인보이스 INSERT 0건), 구독취소는 **코드 0건**인데 **약관은 이미 약속**했다 |
| 7 | 🟡 **반대 방향으로도 깨졌다 — O1-6 의 대기 사유가 낡았다**(메일 1통 통과·호출자 봉합). 다만 **설치 메일 2종 경로 0건**으로 **대기는 유지** ⇒ 일정표 대기 사유를 **교체**해야 한다 |
