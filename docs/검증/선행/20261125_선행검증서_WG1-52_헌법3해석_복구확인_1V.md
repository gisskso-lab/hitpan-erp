## 1. ⚠️미확인 10건 — 닫음 / 실측 불가

### 1-1. [닫음] 백업 덤프 꼴 = **DROP TABLE → CREATE TABLE → INSERT** (표 단위 · DB 문 없음)

- 덤프 인자: `BackupService.cs:414` `-h … -P … -u … --single-transaction --routines --triggers --default-character-set=utf8mb4 {db}`
- 덤프 도구 = `mariadb-dump` 우선(`:672-692`). mariadb-dump/mysqldump 는 `--opt` 가 **기본 켜짐**이고 `--opt` 는 `--add-drop-table` 을 포함한다. `:414` 에 `--skip-opt` · `--skip-add-drop-table` · `--no-create-info` 가 **없다** ⇒ 각 표마다 `DROP TABLE IF EXISTS` → `CREATE TABLE` → `INSERT`.
- `--databases` 가 없다 ⇒ `CREATE DATABASE`·`USE` 문 없음 ⇒ 가져넣기 명령의 `{db}`(`:422`)에 그대로 붓는다.
- 워치독 업데이트 전 백업도 같은 꼴(`src/HitPan.Watchdog/AutoUpdate/WatchdogBackupRunner.cs:59` 같은 인자). 즉 복원 원본이 어느 쪽 파일이든 같다.
- `git grep -n "single-transaction\|--no-create\|--skip-add-drop\|--add-drop\|--databases" origin/main -- 'src/**/*.cs'` → 위 두 줄뿐.
- 🔴 초안에 없는 함의 2개:
  - ⓐ **덤프에 없는 표는 안 지워진다** — 백업 **뒤**에 마이그로 생긴 표는 그대로 남고, 마이그 이력 표는 백업 시점으로 돌아간다 ⇒ 「반쪽 스키마」 가능(설계 몫 · 실행 0).
  - ⓑ DROP/CREATE 는 DDL 이라 MariaDB 에서 **트랜잭션으로 묶을 수 없다** ⇒ C-11 「트랜잭션 없음」은 고칠 수 있는 결함이 아니라 이 방식의 성질이다 ⇒ 10/27 CTO 결재문 :27 「임시 DB 복원 → 대조 → 교체」가 **필수**인 까닭(초안 §2-1 조건 3 근거 보강).
- 한계: 실물 덤프 파일은 안 열었다(지시대로). 판단 근거 = 인자 + 도구 기본값.

## 5. 상신서에 고칠 것 (PM 몫 · 검증팀은 고치지 않음)

1. **§1-2 「복원이 하는 일」 보강** — 장부 2표뿐 아니라 감사 기록 · 복원 기록 · 계정/비번/권한 · 기기·구독 캐시까지 백업 시점으로 돌아간다(1-2). 덤프 꼴 = 표마다 DROP → CREATE → INSERT · 백업 뒤 생긴 표는 남음(1-1).
2. **§3 ② ⚠️ 닫기** — 「덤프 꼴 미확인」 → 확정(근거 `:414` + 도구 기본값 `--opt`). 「트랜잭션 없음」은 이 방식의 성질(DDL)이라 고칠 수 없음 → 조건 3(임시 복원→대조→교체)이 필수라고 적기.
3. **§3 ③ 보강** — 01a 보충2 행 = `:418-423` 전체. `:422` `-p` 에 더해 **`:420` 옛 해석기 때문에 깃발만 걷으면 복원이 안 돈다**.
4. **§3 ④ 고침** — 「⚠️미확인」 → **확정: TenantAdminOnly 는 자식 관리자도 통과**(Program.cs:407-409 · UserService:143 · AccessStatusController:66). 문은 `:16` + **`:23` MainPcOnly**. 「부모계정 전용」 = is_parent 판정 추가가 설계 입력.
5. **§3 ⑤ · §2-1 조건 5 고침** — 「추론」 → **코드로 확정**: 복원 기록이 성공 응답과 함께 사라지고, 초기화 감사 기록도 지워질 수 있다(1-2). 조건 5 는 PM 안이 아니라 이미 결재된 「감사 기록」(CTO :27 · 00 :116)을 지키기 위한 최소선이라고 적기.
6. **9/11 대표 결정 (가) 걷기를 명시** — 01a §B :45 「(가)를 걷는 결재가 먼저」. 「10/27 ② 결재가 (가) 걷기를 포함한다」고 PM 이 해석할 거면 해석이라고 표시하고 대표 확인을 받든지, 결재 칸에 한 줄 더한다.
7. **§1-3 · §4 K25 표기** — 「결재 여부 ⚠️미확인」 → **「결재 기록 없음 · 미결」**(1-5). 초기화가 지금 열려 있고(그리고 자식 관리자에게도 · P4) 복원이 닫혀 되살릴 길이 없다는 사실을 쟁점 ② 옆에 적기.
8. **§5 쟁점 ③ 좁히기** — 「복구 확인」 실물 1건은 판 1.1(60_WBS:464 · 11/7 대표 Q5)에 이미 있음. (B)는 결재된 WBS 변경, (C)는 G3 이중이라고 밝히고 질문을 「실물 1건 = (A) 내용이 맞나」로. 인용 「60_2 :89」는 맞음(WBS :204 의 「:81」은 오기 — 상신서에 옮기지 말 것).
9. 경미: 6/23 인계서 인용 `:28-29` → `:29`. §9 ⚠️ 목록 1·2·3·4·5·7 을 「닫힘(선행검증서 §1-x)」로 상태만 바꿈(지우지 않음).
