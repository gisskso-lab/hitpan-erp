## 판정
**전제 맞음 (조건부 확장)** — 원인은 Blazor 8 의 「미리 그린 화면 → 회로 연결 뒤 통째 교체」가 맞다(원문 코드 근거 + 실측). 그런데 등재문보다 **범위가 넓다**: 초점만 떨어지는 게 아니라 **교체 전에 한 입력 전부(클릭 · Enter · 글자)가 소리 없이 사라진다.** 상태 칸만이 아니라 일반 단추 · 입력란 · MudButton 모두 같다. 그리고 **h1 이 있는 화면(로그인 포함 5곳)은 `FocusOnNavigate` 가 첫 렌더 직후 초점을 h1 으로 옮기는 2차 원인**이 따로 있다.
추천 = **안 ② 미리 그리기 끄기** (App.razor 1파일 2줄 · `Routes` 와 `HeadOutlet` 둘 다). 레포 수정 0 · git 쓰기 0 · 운영 접촉 0 · DB 0.

## 장치 (레포 밖)
- 앱: 레포 밖 임시 앱 (net8.0 · MudBlazor 9.3.0 · `Routes` InteractiveServer · `FocusOnNavigate Selector="h1"` · 쿠키 인증 · 폼 POST 로그인 + `AntiforgeryToken` — 백오피스 App.razor · Routes.razor · Program.cs 와 같은 꼴). repro_s4 원본은 건드리지 않음.
- 갈래(경로로 선택): `pre`(현행 = 미리 그리기 켬) · `restore`(안 ① 초점 · 값 되돌리기 JS) · `block`(안 ③ 연결 전 `inert` + 「불러오는 중」) · `nopre`(안 ② `new InteractiveServerRenderMode(prerender: false)`) · `preh`/`nopreh`(HeadOutlet 정적 = 백오피스 현행 꼴).
- 지연: 프록시 `proxy.js` 0(직결 5899) / 150ms(5901) / 300ms(5902) — 덩어리마다 양방향 지연이라 실제 왕복시간보다 창을 **부풀린다**(최악 쪽 장치).
- 측정 `m.js`: 화면에 `#in1` 이 보인 시각(첫 화면) 뒤 d = 0/200/400/700/1000/1500ms 에 실제 마우스 · 키 입력 → 회로 붙은 뒤 0.9초 기다려 서버 상태로 판정. 시험 5종 click(일반 단추) · mclick(MudButton) · type(입력란에 abc) · tab(in0 클릭 → Tab → x 가 in1 에) · enter(입력란 Enter). 교체 시각 = 미리 그린 `#app` 제거(MutationObserver), 회로 = 첫 WebSocket 프레임.
- 원파일: `res/main_{5899,5901,5902}.jsonl`(360행) · `r2_*.jsonl`(안 ① 2판 + h1) · `late_5901.jsonl` · `login.log` · 요약 `sum.js`.
