## 1. 대상·판·그려질 조건
- 판 9.3.0(F1) · 제공자·회로 정상(F2) → 「메뉴가 그려질 조건이 없다」 꼴 아님. 원인은 **열기 연결 부재**(F3·F6·F7).
- 등재 §2 「언제부터 안 열렸나」 — 미측정(판 올림 이력 대조 안 함). 10/13 작2 때 판이 9 미만이었다면 그때는 감싼 칸이 열었을 가능성 — 가설.

## 2. 바깥 전파 막음과 열기 연결의 맞물림
- Blazor 는 이벤트를 안쪽부터 처리하고 `stopPropagation` 은 그 요소 **위로** 가는 것만 막는다 → `span` 의 열기가 먼저 돌고 바깥 `div` 에서 멈춘다. 행 클릭(F5) 새지 않음 약속 ③ 유지.
- 🔴 **이중 토글 위험(안 되는 경우)**: #691 고침은 `MudIconButton`(기본 `ClickPropagation=false` — 단추가 스스로 전파를 막음). `span` 은 스스로 막지 않는다 → 만약 9.3 감싼 칸에 손잡이가 있다면(F7 을 본 [1-V] 이 dll 로 재확인 못 함) 열림→닫힘이 한 번에 일어난다. ⇒ **span 에도 `@onclick:stopPropagation="true"`** 를 다는 꼴이면 감싼 칸 손잡이 유무와 무관하게 한 번만 토글(F9 컴파일 확인).
- 메뉴 항목은 팝오버 제공자 쪽(행 밖)에 그려지므로 항목 클릭이 행으로 새는 길 없음 — 코드 읽기 · 동작 미측정.

## 3. span 에 다는 꼴 · 키보드 · 약속 ②
- 인자 꼴: `ToggleAsync(EventArgs)` 메서드 그룹 → `@onclick`(MouseEventArgs) 로 바뀜 — 컴파일 0/0(F9). `PositionAtCursor` 미사용이라 좌표 영향 0.
- 키보드: `span` 은 탭 포커스 0 · Enter 0. **지금도 0** 이라 고침이 나빠지게 하지는 않음. 단추(`MudButton`/`button`)로 바꾸면 접근은 생기나 꼬리표 모양이 바뀜 → 대표 질문 Q1.
- 약속 ②(옛 값 = 고르지 못함)는 `ChildContent` 의 `Disabled` 항목(`CsStatusCell.razor:23~33`)이 지킴 — 열기 연결과 무관. 약속 ①(건마다 목록 다름)도 같은 자리 — 무관.
- `ActivationEvent="@MouseEvent.LeftClick"`(`:15`)는 남겨 둬도 무해(#1 추가만).
