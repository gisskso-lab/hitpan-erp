## 설계에 넘길 조건

- **C1(N1)** 실행 목록과 계수 목록을 한 규칙으로: ⓐ S8 이 실제로 실행한 파일 이름을 목록 파일로 남기고 판정기가 그 목록과 자기 폴더 셈을 대조(불일치 = 빨강) 또는 ⓑ 두 쪽이 같은 함수 하나를 쓰게. 목록 파일을 업로드 폴더에 두면 S10 누출 검사·S11 업로드 대상이 된다(표준출력 tee 금지 규칙과는 별개). 경계 꼴은 「가운데 빈 이름」 외에 「줄바꿈 든 이름」도 있다(리눅스에서만 가능 · 코드 읽기 근거 · 미재현).
- **C2(L14 H 키)** H 기대 키를 고정 목록으로 만들지 말 것. 참고 런에서 첫 브라우저는 약관 관찰 갈래(관찰 줄 + 동의 줄), 둘째 브라우저는 일반 갈래(자리 줄)로 갈렸고, 시험 2개는 첫 브라우저에만 있다. 키 틀 = 「브라우저별 필수 키 + 갈래별 둘 중 하나」 꼴이어야 약관 결함이 고쳐진 뒤에도 거짓 빨강/거짓 초록이 없다. 심은 빨강 줄 · 흐름 끊김 줄은 정상 런에 없는 키 → 기대 키 틀이 「모르는 키」를 어떻게 다룰지 명시. 중복 키 = 실패.
- **C3(N2)** 고침 꼴은 「던지기」 쪽이 콘솔·판정이 엇갈리지 않는다. 「형 보존」 만 하면 기록 함수 콘솔 표시는 글자 「false」 를 여전히 PASS 로 찍고 판정기만 빨강이 된다(표시 엇갈림). 실런에서 현 호출 37곳 중 걸린 줄 0 을 확인 항목으로.
- **C4(N3)** 위 경로 1·2·3 은 필수 · 5·6 은 범위 판단 후 기록. 소독 함수 재사용 시 기본 300자 자르기가 이름표에도 걸린다 — 상한 값을 정할 것. 판정기는 별도 단계라 그 프로세스 안에서만 알던 값은 모른다(런 환경 등록분만 안다) — 대조 시험은 등록값 기준으로.
- **C5(L16)** 자체시험을 UI 잡 안에 넣으면 H 접두사 가지에서만 돈다(장치 파일만 고치는 다른 가지에선 안 돎). 조건 없는 별도 잡으로 두면 모든 PR 에 한 칸 늘어난다(약 5초 + 체크아웃) — 어느 쪽인지 설계에서 정하고 문서화. **자체시험의 한 칸이 레포 workflow 폴더의 대상 파일 수·이름을 세므로**, workflow 를 고친 뒤 그 칸 PASS 를 다시 확인할 것. 자체시험은 레포 밖 사본에서 돌리면 그 칸이 실패한다(이번 실측에서 사본 63/64 · 레포 64/64) — CI 에서는 레포 위치 그대로 실행.
