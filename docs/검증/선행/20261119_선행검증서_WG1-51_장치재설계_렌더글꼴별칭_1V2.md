### 2×2 거짓 초록 · 거짓 빨강
- **G0 거짓 초록 확정**: `fc-match` 는 fontconfig 별칭을 따르므로 D1 설정만 맞으면 초록. 그러나 렌더(QuestPDF)는 fontconfig 를 보지 않음 → G0 초록이 「렌더 글꼴 준비됨」 을 뜻하지 않는다.
- **T8 = 빨강 예정**: 견본이 같은 QuestPDF(E15) → 글꼴 칸 = Lato(부분집합 접두 붙은 이름) → ⑴ 분류. ⑴ 은 원인 이름은 맞게 붙지만, **쏘기 전에 결과가 정해진 판정 0 런**이 되고 R 자리 1 을 쓴다(§3-3 3 · 대표 §51).
- **⑵(하네스 결함)와 ⑴ 구분**: T8 빨강의 원인이 별칭인지 하네스인지 런 결과만으로는 가를 근거가 G0 뿐인데, G0 가 거짓 초록이므로 ⑴/⑵ 가 섞일 수 있다(분류 오판 위험).
- 별칭 없이 나눔 글리프가 찍혀 「글꼴 칸 ≠ Lato」 로 거짓 초록이 날 길: 환경 글꼴 쪽은 E10 으로 막혀 **없음**. 앱 폴더 쪽은 미확인(위 표).

## §3 재설계에 줄 조건

1. **M6 성립** — 지금의 D1(fontconfig 별칭)로는 비교 런을 쏘지 않는다. 설계 고침 → 대표.
2. G0 를 남긴다면 `fc-match` 가 아니라 **렌더 라이브러리가 실제로 보는 것**을 재야 한다: `/usr/share/fonts/` 아래 파일의 **파일 안 family 이름**이 정확히 「Malgun Gothic」 인지(fontconfig 결과 아님). 판독 도구는 측정 전 대표 결재.
3. 어떤 길이든 **같은 QuestPDF 판(2026.2.4)** 으로 잰다. 공개 문서 최신판은 설정 이름이 다르다(`UseSystemFonts` 기본 false · `FontDiscoveryPath` 단수 · `ThrowOnMissingTextGlyphs` 기본 켜짐) — 판을 올리면 위 결론 전부 다시 잰다.
4. 남는 길(사실만 · 고르지 않음):
   - ① 파일 안 family 이름 = 「Malgun Gothic」 인 OFL 파생 글꼴을 `/usr/share/fonts/` 아래(또는 앱 출력 폴더)에 둠 → E10 정확 일치로 잡힘. **이름 바꾼 글꼴 파일 = 대표 몫**(작업지시서 범위 밖) · OFL 예약 이름·상표 검토는 법무.
   - ② 제품에서 `FontManager.RegisterFontWithCustomName("Malgun Gothic", …)` 또는 `FontFamily` 대체 목록 — **제품 0줄 규칙 밖**.
   - ③ 윈도 러너(DirectWrite · 맑은 고딕 기본 탑재) — 작업지시서 줄 66 `runs-on` 변경 금지에 걸림.
   - ④ CI 에서 앱 출력 폴더(`FontDiscoveryPaths` 기본)에 한글 글꼴 복사 — 이름 일치는 여전히 실패. 글자 단위 대체가 되는지 미확인 · 되더라도 글꼴 이름·글자 폭이 맑은 고딕과 달라 좌표 판정(R3) 기준이 바뀜.
5. Z5 「Lato · 빈 글리프」 는 장치 결함이 아니라 **설계 전제(fontconfig 경유) 결함**으로 분류한다.
