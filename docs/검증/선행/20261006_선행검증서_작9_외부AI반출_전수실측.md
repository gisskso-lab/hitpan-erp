## 2. 노출 상태 (1.3.53) — 판정: **조건부 켜짐** (기본은 안 나감, 그러나 차단 장치 0)

- 챗봇 입구는 **전 직원 상시 노출**: TopHeader.razor:9 `<ChatbotBar />` — 끄는 설정 스위치가 **존재하지 않는다**. API 는 `TenantOnly`(ChatbotController.cs:15) = 로그인한 전 직원.
- 외부 반출 발화 조건: `local_subscription` 의 BYOK 키 존재 + status='valid' (②는 ChatbotService.cs:412-426, ①은 630-636). **출하 기본 = 키 NULL**(DB-27) ⇒ 키 안 넣은 고객은 외부 호출 0 (KB-only 폴백).
- 키 입력 입구: 메뉴 Sidebar.razor:67 「AI 도우미 연동」(/settings/ai-assistant) — 화면 `tenant_admin` 전용(AiAssistantPage.razor:5), API `TenantAdminOnly`(AiSettingsController.cs:15).
- 🔴 **SaveApiKeyAsync 는 저장 즉시 status='valid'**(ChatbotService.cs:1283) — 연결 확인 없이 붙여넣는 순간 ①② 전부 산다. 이후 **전 직원**이 ChatbotBar 로 반출 경로를 쓴다. 고지·동의·계약 게이트 0.
- ⇒ Q-7 방침("봉합 전 노출 금지") 기준으로는 **노출 중**이다: Tool·메뉴·키 입력구가 1.3.53 에 전부 실려 있고, 막는 것은 "고객이 아직 키를 안 넣었다"는 우연뿐.

## 3. 키 출처 — `ai_mode` · `hitpan_pool`

- `ai_mode` 컬럼: DB-27 신설, 기본값 'hitpan_pool' (comment: hitpan_pool/byok/hybrid). **코드 어디에서도 분기 조건으로 읽지 않는다** — 읽는 곳 전부 표시용 DTO(ChatbotService.cs:744·787·887·945)와 백오피스 전시·프로비저닝 payload 뿐.
- **pool(본사) 키는 코드·설정 어디에도 없다**: appsettings 2종에 AI 키 0건, Program.cs 가 읽는 건 모델명·max_tokens 뿐(Chatbot:Model 등, Program.cs:246-279). 실제 호출 키는 전부 `local_subscription.{anthropic|openai|google}_api_key_encrypted` — **고객이 /settings/ai-assistant 에서 직접 넣은 테넌트 소유 BYOK**(AES 암호화 저장, 키 값은 본 문서에 기재하지 않음).
- ⇒ 작지서 §0 ⚠️미확인("hitpan_pool 이면 본사 계정 키로 나간다") → **현 코드에서는 사실 아님** — pool 키 경로 미구현. 키 없으면 외부로 아예 안 나간다.
- 🔴 다만 **장부가 거짓말을 한다**: ai_usage_logs.charge_mode 가 실제 키 출처와 무관하게 'hitpan_pool' **하드코딩**(ChatbotService.cs:236·484·566). 고객 자기 키로 나간 호출이 "본사 pool 과금"으로 적힌다 — 향후 pool 구현·정산 때 이 로그는 증거로 못 쓴다.

## 4. 법인/개인사업자 구분 로직 — **없음**

- partners 테이블에 법인/개인 구분 컬럼 자체가 없다(출하 DDL 실독 — `partner_type` 은 매출/매입처 구분, `biz_type` 은 업태).
- SearchPartnersAsync(PartnerService.cs:195-209)에 구분 필터 0 — **1인(개인)사업자 거래처의 사업자번호·전화도 법인과 동일하게 반출**된다. 개인사업자 bizNo+성명성 상호+전화 조합 = 개인정보로 볼 여지(법무 판단 재료).
