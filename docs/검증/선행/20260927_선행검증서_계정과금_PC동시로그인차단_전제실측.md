## 2. 판정 재료가 영원히 0 이다 — 미들웨어는 결백하다

`SessionLimitMiddleware` 는 등록돼 있고([`Program.cs:640`](../../../src/HitPan.API/Program.cs#L640)), 세는 코드도 정상이다.

| 역할 | 자리 | 상태 |
|---|---|---|
| **세는 곳** | [`SessionLimitMiddleware.cs:113-115`](../../../src/HitPan.API/Middleware/SessionLimitMiddleware.cs#L113-L115) | 🟢 정상 |
| **지우는 곳** | [`AuthController.cs:336`](../../../src/HitPan.API/Controllers/AuthController.cs#L336) — 로그아웃 시 `DELETE` | 🟢 있다 |
| **넣는 곳** | — | 🔴 **레포 전체에 0건** |

**0건 확인 — 서로 다른 도구 2개로 교차 확인**(한 도구의 패턴 실수로 0 이 나오는 것을 막기 위해):

| 도구 | 질의 | 결과 |
|---|---|---|
| ripgrep | `(?i)insert\s+into\s+\`?user_sessions` (`src/`) | **0건** |
| grep -rniE | 같은 패턴 (`src/`) | **0건** |
| ripgrep | `class UserSession` · `DbSet<UserSession` · `UserSession\b` | **0건** (ORM 경유 쓰기도 없다) |

`user_sessions` 를 언급하는 **`src/` 파일은 단 3개**다 — 위 세는 곳·지우는 곳, 그리고 초기화 목록([`DataResetService.cs:50`](../../../src/HitPan.Application/Services/DataResetService.cs#L50)).

⇒ 테이블은 **항상 비어 있다.** 판정식 `activeCount > limit` 의 왼쪽이 **영원히 0** 이므로,
한도가 8이든 180이든 **참이 될 수 없다.** 제한은 **한 번도 걸린 적이 없다.**

> 🔴 **「고장」이 아니라 「미완성」이다.** 고칠 곳은 미들웨어가 아니라 **로그인 경로**다.
> P-2 를 그대로 두고 미들웨어를 팠다면, 멀쩡한 코드를 들여다보며 시간을 버렸을 것이다.

### 2-1. 실패해도 조용하다 — 그래서 아무도 몰랐다

[`SessionLimitMiddleware.cs:143-149`](../../../src/HitPan.API/Middleware/SessionLimitMiddleware.cs#L143-L149) 의 `catch` 는 예외를 삼키고 **요청을 통과시킨다**(가용성 우선). 로그는 남기지만(#15 준수), 화면에는 아무 일도 안 일어난다.
⇒ 테이블이 없거나 컬럼이 틀려도 **증상이 안 보인다.** 「안 걸린다」가 눈에 띌 방법이 없었다.

### 2-2. 지난 사람도 돈다고 믿었다

[`DB-28`](../../../src/HitPan.API/Migrations/SQL/DB-28_tenant_settings_missing_columns.sql#L25-L30) 이 `user_sessions.expires_at` 컬럼을 추가하며 주석에 **"SessionLimitMiddleware 참조"** 라고 적었고, 기존 행에 `UPDATE ... SET expires_at = login_at + 24h` 까지 돌렸다.
⇒ **행이 있다고 전제하고 스키마를 확장**한 것이다. 로그아웃의 `DELETE` 도 같은 전제다.
**넣는 곳만 없다.** 이 비대칭이 최소 2명을 속였다.

## 3. 대조군이 깨졌다 — 그래서 DB 0건은 증거가 아니다

접근 가능한 DB 에서 행 수를 쟀다.

| DB | `user_sessions` | 비고 |
|---|---|---|
| `hitpan_e2e` | **0** | ⬇ 아래 |
| `hitpan_trgtest` | 테이블 없음 | — |
| `hitpan_backoffice` | 테이블 없음 | — |

🔴 **`hitpan_e2e` 의 0 은 증거로 쓸 수 없다.** 같은 DB 에서 대조군을 재니:

```
user_sessions    0
refresh_tokens   0     ← 로그인이 한 번도 없었다는 뜻
users            1
```

`refresh_tokens` 까지 0 이므로 **이 DB 에는 로그인 이력 자체가 없다.**
로그인이 없으면 세션 행이 없는 게 당연하다 — **"넣는 코드가 없어서 0"** 과 **"로그인이 없어서 0"** 을 가르지 못한다.

> 🔴 **0 은 양성 대조 없이는 아무것도 증명하지 않는다.** 여기서 "실물 DB 도 0이니 확정"이라고 적었으면,
> 근거 없는 확정을 다음 사람에게 사실로 물려줄 뻔했다.

⇒ **§2 의 코드 증거만으로 판정한다.** 코드에 넣는 곳이 0건이면 DB 를 안 봐도 결론은 같다. DB 측정은 **보강**이지 필수가 아니다.

## 4. 🔴 축이 다르다 — 기존 미들웨어로는 새 정책을 영원히 못 만든다

판정식을 글자 그대로 읽는다:

```sql
SELECT COUNT(DISTINCT user_id) FROM user_sessions
 WHERE tenant_id = @TenantId AND expires_at > NOW()
```

| 항목 | 기존 미들웨어 | 9/25 확정 정책 |
|---|---|---|
| 세는 단위 | **테넌트 안의 서로 다른 사용자 수** | **한 계정이 동시에 붙은 PC 수** |
| 막는 것 | 회사 전체 동시 사용자 총량 | **같은 계정으로 2대 동시 로그인** |
| 한도 출처 | `SlotPolicyDefaults` (기기 한도 × 1.5) | 계정 수 (베이직 5 / 프로 8) |

🔴 **`DISTINCT user_id` 이므로, 한 계정이 5대에서 붙어도 `1` 로 센다.**
9/25 정책이 막으려는 바로 그 행위가 **이 식에서는 수치상 보이지도 않는다.**

⇒ **기존 미들웨어를 고쳐 쓰는 길은 없다.** 둘은 다른 축의 다른 기능이다.
⇒ 9/25 인계2 의 「미들웨어 무접촉」은 **맞는 결론**이지만, 근거를 이걸로 바꿔 적어야 한다.

> ⚠️ **설계([2])에 넘기는 질문**: 기존 미들웨어(테넌트 총량 제한)를 **살릴 것인가 버릴 것인가.**
> 살린다면 넣는 코드를 만들어야 하고, 버린다면 미들웨어·컬럼·`DELETE` 를 어떻게 할지 결재가 필요하다.
> **PM 이 정하지 않는다** — 모듈 경계 판단이다.

## 6. ⚠️ PM 이 못 잰 것 — V-1 (실물 DB 행 수)

`hitpan` 계정으로 보이는 DB 는 **4개뿐**이다:

```
hitpan_backoffice · hitpan_e2e · hitpan_trgtest · test  (+ information_schema)
```

🔴 **`hitpan_erp` 도 `hitpan_erp_t004` 도 목록에 없다.** GRANT 가 위 이름들에만 걸려 있다.
⇒ 실제 로그인 이력이 있는 DB 에 PM 권한으로 닿지 못한다. root 비번은 사장님만 갖고 계신다.

**사장님이 해주시면 30초로 끝난다** (읽기만 · #39 준수):

```sql
SELECT 'user_sessions' t, COUNT(*) c FROM user_sessions
UNION ALL SELECT 'refresh_tokens', COUNT(*) FROM refresh_tokens;
```

- `user_sessions = 0` **이고** `refresh_tokens > 0` 이면 → §2 확정 (로그인은 있었는데 세션이 안 쌓였다)
- 둘 다 0 이면 → §3 과 같은 상황이라 **아무것도 못 가른다** (그 DB 도 로그인 이력이 없다)

> 🔴 **`refresh_tokens` 를 같이 안 세면 이 측정은 의미가 없다.** §3 에서 실제로 그 함정을 밟았다.

## 7. 이번에 PM 이 틀렸던 것

1. **「실물 DB 0 이면 확정」이라고 9/25 인계2 에 적어뒀다** — 대조군 없는 0 은 증거가 아니다(§3). 인계2 §U-1 의 그 줄은 **이 문서가 바로잡는다.**
2. **「미들웨어 무접촉」의 근거를 편의로 적었다** — 실제로는 축이 달라서 **손댈 수가 없는** 것이다(§4). 결론은 같지만 근거가 틀리면 다음 사람이 뒤집는다.
