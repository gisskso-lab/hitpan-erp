## §2 전제 밖 적발 — 설계가 반드시 받아야 할 2건

### A-1 🔴 「종류 칩」과 「제목 속 낱말」이 서로 다른 말을 하게 된다

작1 의 공지 화면은 종류 칩을 **`KindLabel() => "본사 안내"` 로 못 박아** 세운다(`CsNoticePage.razor:111`). 작2 가 제목 쪽 낱말을 6종으로 늘리면 **한 줄 안에서**

> `[업데이트공지사항] 1.3.58 안내`  ← 제목
> `본사 안내` ← 칩

이 **동시에** 보인다. 거짓말은 아니지만 **같은 축을 두 번 말하고 값이 다르다.**

🔴 **칩을 고치는 것은 작3 의 일이다**(용도 칸이 생기면 칩이 그 값으로 선다 — 일정표 §3). 작2 가 칩을 건드리면 **칸 없이 본문 글자를 되쪼개는** 임시 코드가 생기고, 그건 결-D 에서 사장님이 **ⓐ(본문 글자 읽기)를 안 고르고 ⓑ(칸 신설)를 고른** 결정을 뒤집는 것이다.

⇒ **설계 판단**: 작2 는 칩을 **안 건드린다.** 대신 이 사실을 **작3 설계 입력**으로 넘기고, 사장님 실측표에 **「칩과 제목이 다른 말을 한다 — 작3 에서 합친다」**를 미리 적어 둔다(사장님이 보시고 놀라지 않게).

### A-2 🔴 「본사안내」 fallback 을 지워서는 안 된다

6종을 다 적고 나면 `_ => "본사안내"` 가 **안 쓰이는 줄처럼** 보인다. 지우면:

- 백오피스가 **나중에 7번째 값**을 더하는 순간 ERP 가 `switch` 에서 **아무 것도 못 돌려주고** — C# 은 `switch` 식이 다 안 맞으면 **런타임 예외**다 ⇒ 수신 사이클 전체가 죽고 **답까지 못 내려온다**(10/12 사고와 **같은 모양**: 담은 응답이 죽으면 같이 실려야 할 것도 못 간다).

⇒ **설계 판단**: fallback 은 **반드시 남긴다.** 그리고 **「모르는 값이 와도 안 죽는다」를 도는 게이트**를 넣는다(#37 의 정신 — 안 읽힌다 ≠ 잔재).
