## 0. 왜 이 문서가 있나

사장님이 3·4번을 *"실측으로 확인해 봐야 하는 항목"* 으로 물으셨고, 제가 4개를 한 덩어리로 올렸던 것을 갈랐다.

## 1. 3번 전제 — *"게이트가 CI 목록에 없다. 이제 전부 초록이라 등록 가능"*

### 🔴 반증됨 — 깜빡 빠진 게 아니라 **의도적으로 막아둔 것**이었다

`.github/workflows/build-and-test.yml` 에 주석으로 이유가 남아 있었다:

```
# 🔴 20260903작19 WarehousePickingGate 는 아직 안 문다.
#    G-P1 이 **의도적으로 빨간불**이다(배분 로직 W4 미착수 — 사장님 배분규칙 결재 대기).
#    지금 넣으면 CI 가 상시 빨간불이 되어 "빨간불에 익숙해지는" 더 나쁜 상태가 된다.
#    ⇒ W4 완료 시 이 줄의 주석을 풀어 등록한다. 등록이 곧 완료 판정이다.
# GATES="$GATES|WarehousePickingGate"
```

제가 인계6 에 *"잔업: 작19 게이트 CI 등록 (이제 전부 초록이라 가능)"* 이라고 적은 것은 **이 주석을 안 읽고 쓴 것**이다.

### 그러나 등록 조건은 실제로 충족돼 있었다 — **다른 방식으로**

주석이 기다린 것은 "배분 로직 W4 완료" 였는데, **배분(C안)은 만들어진 게 아니라 폐기됐다.**
사장님 지시 2번 — *"분산은 재고이송으로 수동변경"*. 자동배분은 만들지 않는다.

⇒ G-P1 이 재는 대상이 **"배분" 에서 "창고결정" 으로 바뀌었고**, 작19 로 봉합됐다.
조건이 사라진 게 아니라 **조건의 대상이 바뀐 것**이다.

### 🔴 등록 근거는 "초록불이라서" 가 아니다 — 무력화 시험

초록불만 보고 등록하면 9/3 에 저지른 실수(초록불의 출처를 안 본 것)를 반복한다.

| 시험 | 결과 |
|---|---|
| `WarehouseResolver` 의 ②단(상품마스터 기본창고)을 죽임 | **G-P1 FAIL** — `WH-MAIN` 을 뱉음 |
| 그 상태의 나머지 9건 | 통과 (대조군 정상) |
| 봉합 복구 후 | 10건 전부 통과, SKIP 0 |

FAIL 메시지가 **테스트1창고 −15 를 만든 그 경로**와 같은 모양이었다. 게이트가 진짜다.

## 2. 4번 전제 — *"BOM 실제 생산은 안 잰 것"*

### 🔴 반증됨 — 안 잰 게 아니라 **실제로 깨져 있었다**

#### 2-1. 정적 판정 (코드 읽기)

`BomService.AssembleAsync` 의 창고 결정은 이것 하나뿐이었다 (BomService.cs:528-536):

```sql
SELECT warehouse_id FROM warehouses
 WHERE tenant_id=@TenantId AND is_active=1
 ORDER BY (CASE WHEN wh_code IN ('MAIN','WH-MAIN') THEN 0 ELSE 1 END), wh_code
 LIMIT 1
```

`items` 표를 쳐다보지도 않는다. `default_warehouse_id` 낱말 등장 횟수:

| 서비스 | 횟수 |
|---|---|
| 매입 `PurchaseService` | 5 |
| 매출 `SalesService` | 4 |
| **BOM `BomService`** | **0** |

⚠️ **낱말 개수만 세는 것은 8/28 에 내가 틀렸던 방식(#32)** 이라 여기서 멈추지 않고 실측했다.

#### 2-2. 실측 (진짜 `AssembleAsync` 를 DB 에 물려 실행)

게이트 `BomWarehouseResolutionGateTests` 4건을 새로 짜서 돌렸다.

| 게이트 | 봉합 전 | 실측값 |
|---|---|---|
| G-B1 자재가 마스터 기본창고에 있으면 생산된다 | ❌ FAIL | A창고에 **100개 있는데** "자재 재고 부족"으로 차단 |
| G-B2 자재는 마스터 기본창고에서 빠진다 | ❌ FAIL | A창고 100 **그대로**, MAIN 100 → **80** |
| **G-B4 창고가 늘어도 자재가 더 빠지지 않는다** | ❌ FAIL | 10개 생산에 자재 **20개** 차감 |
| G-B3 대조군 — 기본창고 없어도 안 끊긴다 | ✅ PASS | 정상 |

🟢 **대조군이 통과한 것이 중요하다.** 게이트가 무조건 빨간불인 게 아니라 **정확히 그 조건에서만** 걸린다.

#### 2-3. 🔴 G-B4 는 G-B2 를 짜다 발견한 **별개 결함**이고 더 무겁다

`GetAsync` 의 자재 조회가 창고를 안 본다 (BomService.cs:222):

```sql
LEFT JOIN item_stock s ON s.tenant_id = bi.tenant_id AND s.item_id = bi.material_item_id
```

`item_stock` 은 (item_id, warehouse_id) 단위라 **자재가 2창고면 BOM 자재 1건이 2행**이 된다.
`AssembleAsync` 가 그 목록을 그대로 돌며 차감하므로 **같은 자재를 두 번 뺀다.**

SQL 로 직접 확증했다 — BOM 자재 1건 + 창고 2개 → **조인행수 2**.

⇒ **창고가 3개면 30개가 빠진다.** 원장·원가·분개도 같은 목록을 쓰므로 **회계까지 부푼다.**

🔴 같은 파일의 `GetListAsync`(:73-76)·`GetAssembleAutoOrderCandidatesAsync` 는 **이미 창고합산 서브쿼리를 쓰고 있었고, 주석까지 이 사고를 정확히 설명하고 있었다.** `GetAsync` 만 안 고쳐져 있었다.

## 4. 도구가 나를 세 번 방해했다 (누적 교훈 갱신)

| # | 증상 | 원인 |
|---|---|---|
| 1 | `perl -0pi` 치환 **0건인데 성공**으로 끝남 | 파일이 **CRLF** 라 `$` 앵커가 안 맞음. **눈으로 diff 를 봐서 잡음** |
| 2 | CI 주석에 `작19` → **`쟅19`**, `곧` → **`곳`** 으로 깨짐 | 내가 쓴 유니코드 이스케이프가 틀린 글자. **UTF-8 파일로 써서 끼워넣는 방식**으로 해결 |
| 3 | 게이트가 빨간불인데 **이유가 딴 것** (`Unknown column 'bh.bom_name'` → `i.spec`) | fixture 스키마를 손으로 베껴 부실. **`SHOW CREATE TABLE` 로 실제 정의를 읽어오게** 바꿈 |

🔴 **3번이 특히 위험했다.** 빨간불을 보고 "재현됐다" 고 보고할 뻔했다 — 8/25 에 FK 1452 를 붙들고 오진했던 것과 같은 모양이다.
**증상 모양(오류 메시지)이 안 맞으면 재현이 아니다.**

⚠️ `CREATE TEMPORARY TABLE x LIKE x` 는 MariaDB 가 거부한다(`Not unique table/alias`) — 같은 이름이라 LIKE 원본을 임시표 자신으로 해석한다.
