## 1. 사실 (실측)
1. **batch4 다시 셈(기존 원자료 · 새 측정 아님)**: `grep -c 'Unhandled exception in circuit'` 은 줄 수다. 회로 ID 로 묶으면 F-H 구간 죽은 회로 = **base 29 · fixA 31 · head 32**. head 의 `ArgumentException` 17줄은 **전부 이미 `JSException` 으로 죽은 회로 안 두 번째 줄**(첫 줄이 `ArgumentException` 인 회로 0). 브라우저 쪽 「There was an unhandled exception」 본 표본도 fixA 16+15 · head 16+16 — 같음.
2. **component ID 109 = 1번 줄 상태 칸 9.3 내장 단추(MudButton)**. 진단 사본에서 반영(reflection)으로 번호를 적음: 1번 줄 `cell=82 menu=97 button=109`(29개 화면 모두 같음). 2번 줄 이하 button 112 · 115 …. 오류 30줄(15건) 모두 ID 109.
3. 그 단추의 클릭 손잡이 = 9.3 `MudButton.razor` L10 `this.AsNonRenderingEventHandler(OnClickHandler)` → 손잡이 안 예외는 `EventUtil.cs` L79~87 에서 `RenderHandle.DispatchExceptionAsync` 로 단추 컴포넌트에 넘김 → 컴포넌트가 이미 치워졌으면 `GetRequiredComponentState` 가 `ArgumentException`.
4. **넘겨진 원래 예외(진단 d0)**: 되돌림 길 `CloseAllMenusAsync` 를 감싼 기록에서 `TaskCanceledException` 26 · `JSDisconnectedException` 15. `TaskCanceledException` 은 되돌림 시작 **정확히 60.0초 뒤**(예: 11:28:04.312 → 11:29:04.319) = 서버 JS 호출 기본 시한(1분). 회로가 죽은 뒤 브라우저가 JS 호출에 답하지 않아 단추 초점(`L553 FocusActivatorAsync` → `_buttonActivator.FocusAsync()`)이 시한까지 걸려 있다가 깨진다. 같은 시각에 멈춰 있던 다른 클릭 사슬이 풀리며 되돌림 길을 한 번 더 타고 곧바로 `JSDisconnectedException`.
5. 9.3 `MudMenu.razor.cs` L1088~1114 `FocusActivatorAsync` 는 `catch (JSException)`(L1111) 만 — `JSDisconnectedException` · `TaskCanceledException` 은 통과. 반면 9.3 키 가로채기 구독·해지는 `InvokeVoidAsyncIgnoreErrors`(두 예외 모두 삼킴) → **고침 A · base 의 같은 자리 멈춤 사슬은 조용히 끝나 두 번째 줄 0**.
6. 사건 순서(d0 한 표본 · 방향당 지연 · 11:28:47): 1번 줄 단추 Enter 반복 keydown(`rep=True`) 마다 9.3 단추 클릭 → 열림 → 목록 쪽 Enter 로 닫힘 이 30~50ms 간격으로 엇갈림. 단추 다시 누름으로 닫힌 한 번만 `restore=True`(47.050) → 되돌림 사슬이 Task.Yield · JS 초점 왕복 동안 열림/닫힘 7번이 끼어든 뒤 47.363 끝. 47.44 9.3 `MudMenu.OnAfterRenderAsync` 초점 `JSException` 으로 회로 죽음(9.3 원래 결함 · F14). 그 직후 막 시작한 되돌림 사슬은 답 없는 JS 호출에 걸림 → 회로 정리 뒤 위 4번 경로로 `ArgumentException`.
7. 덧붙여 본 것(범위 밖 · 기록): 길게 누름 중 목록 항목 고름(`OnPick`)이 살아남은 표본에서 16~18회 — 모든 판 같음(9.3 목록 Enter = 고르기). 행 클릭 0.
