## 1. 사실 (실측 · 원문)
1. 9.3 `MudMenuItem.razor.cs` L171~174: 항목은 **`OnInitialized` 에서만** `ParentMenu.RegisterItem(this)`. 등록을 푸는 코드는 없다(버려져도 목록에 남음).
2. 9.3 `MudMenu.razor.cs` L508~527 `CloseMenuAsync`: `_menuItems.Clear()`(L510) **뒤에** `await Task.Yield()`(L511) · 키 가로채기 해제 JS 왕복(L517) · `SetValueAsync(false)`(L525). 이 틈에 그려진 항목은 Clear 뒤에 등록돼 **닫힌 뒤에도 목록에 남는다**.
3. 9.3 목록 내용(래퍼 div · 항목)은 MudMenu 가 아니라 `MudPopoverProvider.razor` L7~16 의 `MudRender` 가 `handler.ShowContent` 일 때만 그린다. `PopoverService.UpdatePopoverAsync`(L131~170) 알림으로 **MudMenu 보다 뒤 묶음**에서 그려질 수 있다 → 그 사이 MudMenu 의 `_menuWrapperRef` 는 **지난 열림의 래퍼**(이미 지워짐)를 가리킨다.
4. L1012~1029 `OnAfterRenderAsync`: 그릴 때마다 상태를 **그 순간 값으로** 읽는다(`_openState` 참 · `_focusedIndex == -1` → L1020 래퍼 초점, 키보드면 L1026 첫 항목 초점). 서버 렌더 확인이 왕복만큼 늦으므로 그 사이 상태가 바뀌어도 그대로 보낸다.
5. 화면 틀 `blazor.web.js` `domWrapper.focus` 는 찾은 요소가 `HTMLElement` 가 아니면(지워져 null) `Unable to focus an invalid element` 를 던진다 → .NET 8 `Renderer.GetErrorHandledTask` → 경계가 없으면 **회로 종료**.
6. 호출 줄 가르기: 스택에 `MudMenu.FocusItemAsync` 가 있으면 L1026, 없으면 L1020(`FocusAsync` 는 async 가 아니라 프레임이 안 남는다). g0 진단(반영으로 상태 기록)이 같은 답을 준다(`fiNow=0` = L1020 통과 뒤 L1026 실패).
