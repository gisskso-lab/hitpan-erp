## §0. 사장님 오더 원문

> "너희가 전수조사 하고 분석해서 원인을 찾아봐."

- 앞선 실측(병렬이슈24 §1·§3-2): 「모두 지우고 새로 가져오기」·「모든데이터 초기화」 둘 다 502 `API proxy error … GetResponse … 작업 시간이 초과되었습니다`

### 결론 한 줄

**백업은 느린 게 아니라 시작하자마자 멈췄다.** `BackupService` 는 DB 연결을 **연 뒤에** 연결 문자열에서 비밀번호를 꺼낸다. 그런데 MySqlConnector 는 연결이 한 번 열리면 연결 문자열에서 비밀번호를 지워서 돌려준다. 그래서 mysqldump 가 `-p`(값 없음)로 실행되고, 아무도 볼 수 없는 숨은 콘솔 창에서 비밀번호 입력을 영원히 기다린다. 100초 프록시 제한은 원인이 아니라 **이 멈춤을 드러낸 것**이다. 제한을 늘려도 끝나지 않는다.

## §7. 사장님 관리자 PowerShell 보충 조회 제안 (**실행하지 않음** · SELECT/SHOW·읽기만)

> 비밀번호는 명령줄에 쓰지 않는다: `& "C:\Program Files\MariaDB 11.4\bin\mysql.exe" -u hitpan -p -D hitpan_erp_t004` 로 들어가면 **사장님 화면에서** 비밀번호를 묻는다. DB 이름은 메모 기준이며 ⬜ — 틀리면 Q0 로 먼저 찾는다.

| # | 목적 | 조회 |
|---|---|---|
| Q0 | 백업 표가 있는 DB 찾기 | `SELECT table_schema FROM information_schema.TABLES WHERE table_name='backup_history';` |
| Q1 | 고아 덤프가 DB 에 붙어 있지 않음 확인 (기대: mysqldump 흔적 0 · 긴 트랜잭션 0) | `SELECT ID,USER,HOST,DB,COMMAND,TIME,STATE FROM information_schema.PROCESSLIST WHERE COMMAND<>'Sleep' OR TIME>600;` · `SELECT COUNT(*) FROM information_schema.INNODB_TRX;` |
| Q2 | 오늘 두 시도의 이력 상태 (D3: `running` 인가 `failed` 인가) + 과거 성공 사례 유무 | `SELECT started_at,finished_at,status,triggered_by,file_size_bytes,LEFT(error_message,120) FROM backup_history ORDER BY started_at DESC LIMIT 15;` |
| Q3 | 실제 백업 경로 설정 (D1) | `SELECT primary_path,mirror_path,schedule_mode,last_run_at,last_status FROM backup_settings;` |
| Q4 | DB 크기 — (가) 수치 보강 | `SELECT table_schema, ROUND(SUM(data_length+index_length)/1048576,1) AS mb, SUM(table_rows) AS rows_est FROM information_schema.TABLES WHERE table_schema LIKE 'hitpan%' GROUP BY table_schema;` |
| Q5 | 시각 +9h 여부와 18:43 이후 감시 줄 (R3·R4) | `SELECT action_type, created_at, NOW() FROM audit_trail WHERE action_type IN ('integrity_alert','data_reset','data_reset_failed','data_reset_aborted','data_reset_denied') ORDER BY created_at DESC LIMIT 12;` — 기대: `created_at` 이 18:4x~19:0x 대 → 화면 03:4x 는 표시 문제. 18:53·19:03 감시 줄이 같은 두 경고면 자료 잔존 확정 |
| W1 | 덤프 실행 계정·실행파일 (D2) — **CommandLine 은 뽑지 않는다** | `Get-Process -Id 21540,36284,3848 -IncludeUserName \| Select-Object Id,ProcessName,UserName,Path` |
| W2 | API 실행 계정의 PATH 판정 (D2) | W1 의 `UserName` 이 `SYSTEM` 이면 머신 PATH 만 → MariaDB 11.4 덤프 · 사장님 계정이면 MySQL 8.4 덤프 |
| W3 | 워치독 백업(대조군)이 실제 파일을 만들었나 | `Get-ChildItem "C:\Windows\System32\config\systemprofile\AppData\Local\HitPan\Updates\pre-update-backup" \| Select-Object Name,Length,LastWriteTime` |
