## §3 잠금 범위 · 시간 (질문 3)

- 앞 탐침 원문(`05ba242d…\scratchpad\Probe59ConcurrencyTests.cs.txt`) P6: `await Gate.WaitAsync(); try { b = await GenK4(); } finally { Gate.Release(); }` · `GenK4()` = `Svc(K4()).RenderDocumentAsync(...)` 통째. 판독(`Read`)만 잠금 밖. ⇒ **「생성만 잠금 0」 은 렌더 통째 잠금의 결과**다.
- 이번 A2: 문서 구성(`Document.Create`)은 잠금 밖 · **`doc.GeneratePdf()` 한 줄만** `lock` → 순수 QuestPDF 60장 ×3 = **0 · 0 · 0**(D1 · D2 · D3 모두). 대조: 같은 문서 무잠금 병렬 = 15 · 24 · 27 · 26 · 23(×5).
- 주의: QuestPDF 는 `Document.Create` 람다를 **`GeneratePdf` 안에서** 실행한다 → 「호출만 잠금」 이어도 구성 람다는 잠금 안이다. 잠금 밖으로 뺄 수 있는 것은 그 전 단계(DB 조회 · 그림 미리 열기 · 측정 전 준비)뿐.
- 시간(A3 · 8코어 · Debug · 데우기 5회 뒤):

| 대상 | 1장 중앙 | 1장 p90 | 60장 순차 | 60장 병렬 무잠금 | 60장 병렬 잠금 | 잠금 60장 동시 요청 완료 p50 / 최대 |
|---|---|---|---|---|---|---|
| 순수 QuestPDF | 21.4ms | 132.1ms | 1117ms | 390ms | 1788ms | 1083 / 1743ms |
| 제품 K4 | 30.6ms | 35.9ms | 2013ms | 527ms | 1292ms | 587 / 1120ms |

  - A3 의 「잠금」 은 렌더 통째(SemaphoreSlim) 꼴. 잠금 처리량 ≈ 순차와 같은 자리(K4 는 판독 · 준비가 겹쳐 순차보다 빠름). 무잠금 대비 약 2.5배 느림.
  - 운영 뜻: 동시 인쇄가 몰려도 장당 30ms 줄서기 — 60장 동시가 최악 1.1초. 사람 체감 문제 없음(추정 · 실운영 부하 미측정).
- 미측정: 제품 코드에서 「`GeneratePdf` 호출만」 잠근 꼴의 0 · 시간 — 제품 고침이 있어야 잴 수 있음 → 조건 카드 C3 의 게이트로 잰다.
