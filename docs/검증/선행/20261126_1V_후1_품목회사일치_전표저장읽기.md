## 7. 위험 등급 · 범위 제안 · 대표 질문 (항목 7)

### 7-1 위험 등급 — P1(고객 첫 설치 전 · P0 아님) 유지

- 성립 조건: 같은 설치(한 DB) 안에 회사가 둘 이상 + A 직원이 B 품목 id(36자 UUID 꼴)를 알아야 함. 화면으로 B 품목 id 를 얻는 길은 이번에 찾지 않음.
- 성립하면: ① A 종이 · 메일 · 팩스에 B 품목 이름 · 규격(정보 노출 · #2 정신) ② A 원장 · 재고에 숨은 행(정합) ③ B 재고 수 영향 없음(§5).
- 등급을 올릴 수 있는 것: MDB 이관이 품목 id 를 추측 가능한 꼴(옛 코드 · 순번 기반)로 만들면 「36자 추측 불가」 전제가 깨짐 — **확인 필요**(`MdbMigrationService.cs:1536 · 2261 · 2313` 품목 INSERT 의 id 출처 미확인).

### 7-2 범위 제안 (검증팀장 의견 · 결재 아님)

| 안 | 내용 | 장점 | 약점 |
|---|---|---|---|
| (가) 결재 글자 그대로 | 로더 6 + 반품 저장 4길 + 판매 반품 화면 1 | 결재 범위 안 · 바로 착수 | W3 · W4 상속이 원본 무검사라 반품 저장 검사만으로 「품목 회사 일치」 를 말할 수 없음 · HQA 「같은 지적 다시」 위험(전표 5종 저장) |
| **(나) 추천** | (가) + 전표 저장 5종(견적 · 수주 · 거래명세(일괄 포함) · 발주 · 매입명세서) 신규 · 수정에 같은 검사 하나(공용 함수 1개 · `SELECT item_id FROM items WHERE tenant_id=@Tid AND item_id IN @Ids` 수 대조) | 모든 상세행 입구가 한 규칙 · 상속 길이 저절로 닫힘 · 시험 꼴 하나로 7길 | 범위 확장 = 대표 결재 필요 · 시험 · CI 런 늘어남 |
| (다) 가장 넓음 | (나) + 창고 · 거래처 id 소유 검사 | 본문 id 소유 문을 한 번에 닫음 | 메뉴 영역 넓어짐 · 기한(고객 첫 설치 전) 압박 |

- 출력 쪽 고침 꼴: 수주 · 거래명세 · 세금계산서 · 발주 · 매입 = `AND i.tenant_id = <상세>.tenant_id` / **견적 = `AND i.tenant_id = @TenantId`**(F-1).
- 시험: 반품 시험 꼴(TEMPORARY 표 · 대조군 G-0)을 로더 6 으로 늘림 · 저장 거절 시험 · 판매 반품 화면 읽기 시험 · **새 시험 이름을 GATES 목록에 넣어야 CI 가 문다**(작업지시서 §2-4 사실).
- 이미 들어간 자료: 고침은 앞으로 들어오는 것만 막음 · 이미 섞인 상세행 · 원장 행 찾기(점검 SQL)는 별도 — 정상 자료에서 0 일 것으로 보나 실 DB 는 #39 로 안 봄.

### 7-3 대표께 여쭐 질문 (쉬운 말)

- **Q-A** 「다른 회사 물건이 전표에 섞이지 않게 막는 검사를, 결재하신 반품 4곳에만 넣을까요, 아니면 견적 · 수주 · 거래명세서 · 발주 · 매입명세서 저장에도 똑같이 넣을까요? 확인해 보니 반품만이 아니라 전표 저장 전부가 지금 검사가 없습니다. 반품만 막으면 매입명세서에서 반품으로 바꾸는 길로 같은 문제가 그대로 넘어옵니다.」 — ① 반품 4곳만(결재 그대로) ② **전표 저장 전부(추천)** ③ 따로 나중
- **Q-B** 「같은 검사를 물건(품목)만 할까요, 창고 · 거래처까지 할까요?」 — ① **품목만(추천 · 이번 결재 뜻과 같음 · 창고 · 거래처는 별 대장 줄)** ② 셋 다

### 7-4 이 판정이 틀릴 수 있는 자리

1. 발주 · 매입명세서 **수정** 길을 못 찾음 — EF 로 상세를 고치는 길이 있으면 §2 표에 한 줄 더(설계 [2] 첫 거리).
2. 컨트롤러 · DTO 검증(`[Remote]` 같은 꼴)은 이번에 전표 5종 모두를 열어 보지 않음 — 서비스 · 전역 필터 · EF 훅까지만 봄. 컨트롤러 안에 품목 소유 조회가 있으면 §2 판정이 바뀜.
3. §5 재고 · 원장 읽기 전수는 grep 묶음 기준(§5 한계) — 회사 조건 없는 읽기가 하나라도 있으면 「B 재고 흔들림 0」 이 바뀜.
4. 한 설치에 회사가 여럿인 경우가 실제 몇인지(CTO (c)) 모름 — 0 이면 등급은 더 낮아지지만 범위 판단은 그대로.
5. MDB 이관 품목 id 꼴(§7-1) 미확인.
6. 화면에서 다른 회사 품목 id 를 얻는 길(목록 · 자동완성 API)이 있으면 등급이 오름 — 이번에 안 찾음.
