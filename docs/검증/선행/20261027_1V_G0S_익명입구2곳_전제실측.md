## §3 전달 경로

- 두 경로 모두 **백오피스 API(NCP, `back.hitpan.kr`)** 코드다. 랜딩(`landing.hitpan.kr`)은 /payment 화면만 관련. **ERP 자동업데이트·설치파일 재게시는 안 낀다**(설치기·ERP 프로젝트가 이 파일을 참조 0 — `installer/` grep 0건). 단 (A) 사슬 끝의 `InstallerBootstrapController` 도 같은 백오피스 API 안이다.
- `.github/workflows/deploy-ncp.yml` — 트리거 `push: [main, develop]` + 경로 필터 `src/HitPan.Backoffice.API/**`·`src/HitPan.Backoffice/**`·`src/HitPan.Landing/**` + `workflow_dispatch` · build(0/0 게이트) → deploy 잡 `environment: production`(승인 대상). ⇒ **main 머지 = NCP 배포 런 기동**(메모리: can_admins_bypass · 묵은 승인대기 런 = 되돌림 폭탄).
- `gh run list` 읽기(10/27): 최근 NCP 배포 런 8건 전부 `completed success` · 마지막 10/18 `d905bd04` · **waiting/queued/pending/action_required 0건**. `d905bd04` 는 `8582e291` 의 조상이고 그 사이 위 세 경로 diff **0** ⇒ 운영 NCP 에는 main 과 같은 판이 돌고 있을 것(배포 성공 ≠ 반영 — §5-1 로 확인).
- 봉합 PR 이 위 경로를 건드리면 머지 즉시 배포 런이 생긴다. 「승인」 전에 **같은 워크플로의 다른 대기 런이 없는지** 다시 볼 것.
