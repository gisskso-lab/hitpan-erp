## 5. 다른 회사 · 없는 id 를 넣으면 (코드 흐름 · 실측 아님)

1. 컨트롤러가 JWT 회사 값(내 회사 A)을 넘김 → 서비스가 `tenant_id = A` 로 **A 의 원장에** `item_id` · `warehouse_id` = 요청 값 그대로 INSERT.
2. **피해 회사 B 의 자료는 안 바뀐다** — 모든 읽기 · 쓰기에 `tenant_id` 조건이 있고, 원장 유일 키도 `tenant_id` 를 포함(`installer/hitpan_db_clean.sql` `uq_stock_ledger_source` · 앞 문서 §2-4). 이름 조회(`StockService.cs:270-279`)도 A 로 걸러 빈 이름을 돌려줌 → B 의 품목명 · 창고명 누출 0.
3. 그러나 A 쪽은 **되돌릴 수 없게 오염**: 유령 창고 재고 · 회사 합산 재고 부풀림(→ 판매 회사 합산 음수 검사 통과 · `SalesService.cs` SALES-04 계열) · 접속기록(`StockService.cs:281` · `:438`)에 남의 id. 원장 INSERT ONLY(#3) · 외래키 0 → 지울 길 없음.
4. 따라서 성격 = **기밀 누출이 아니라 원장 무결성(#3 · #20)**. 남의 id 를 알아야 하는 것도 아님 — **아무 문자열**이면 같은 결과. 「다른 회사 id」 보다 「없는 id」 가 더 쉬운 길이다.
