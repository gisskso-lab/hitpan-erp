### 🔴 설계가 반드시 알 것 (실측에서 새로 나온 것)
1. **NCP 「이전 판 보관」은 「PC 의 이전 판」이 아니라 「최신 게시의 직전 판」이다.** 1.3.51 이 게시되면 `packages/` = 1.3.51·1.3.50 ⇒ 아직 1.3.50 인 PC(Major 동의 미루기 가능)는 1.3.49 를 못 받는다(1.3.47 zip HEAD **404** 실측 — 회전이 실제로 돈다).
2. 레포 `publish-update.sh:340` `PKG_KEEP` 기본값 = **3**(현행 제외 3개) ↔ 서버 실측 = 직전 1개. 레포 밖 회전(서버 cron ⚠️)이 보관 수를 정한다 ⇒ 「직전 판이 남아 있다」는 **레포로 보장되지 않는다** ⚠️.
3. 1.3.50 첫 기동 때 versions-seen = `[1.3.50]` 한 줄 ⇒ 직전 판을 **모른다**(`TryReadPreviousVersion` `seen.Count < 2 → false`). 직전 판 후보 = `local_update_apply_status.applied_version`(워치독 보호 표 · 자동업데이트 판만) · staging zip 이름 — EXE 설치 PC 는 둘 다 비어 있다.
4. 「피드 서명 manifest 저장」 안(정방향)은 **그 판이 피드 최신인 동안 API 가 한 번이라도 피드를 봐야** 성립. 지금 API 는 업데이트 페이지를 열 때만 본다(`ManualUpdateService.cs:191`) ⚠️ — 기동 때 보게 하려면 새 바깥 요청(모양은 워치독 1분 주기와 같음).
