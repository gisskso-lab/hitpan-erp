## §2 읽는 법 — 흰 띠 부품 파일:줄은 어느 줄에서 나오나

1. 로그 S8 단계에서 `K 닫힌문 dxsnap S3HOME 착지+3초` · `+10초` → `흰 띠 보임` 인지 먼저(띠가 늦게 뜨는지도 여기서).
2. 같은 창 `first-home` 구간의 **`dxcon`** 줄 중 `crit:` · `Unhandled exception rendering component` · `WebAssemblyRenderer` 가 든 줄 = Blazor 가 흰 띠를 띄우게 한 처리 안 된 예외. 그 글 안 `at HitPan.Web.<네임스페이스>.<부품>.<메서드>` 가 부품 · 메서드다. 판 빌드에 줄 정보가 실리면 `in …/<파일>.razor:line <n>` 이 파일:줄 — 없으면 부품 · 메서드까지가 산출이고 줄은 [2] 가 코드에서 짚는다(확인 필요 표시).
3. `dxperr` 줄 = JS 쪽 예외(차트 · 저장소 연동 · 설계 §7 ㉡ 후보) — stack 의 `파일.js?(쿼리 뗌):줄:칸`.
4. 예외 줄의 `+ms` 를 `dx4xx` 줄의 `+ms` 와 나란히 놓아 **어느 부름 바로 뒤 예외인지** 잇는다(선행 §2-1 의 4번째 403 주소가 이번엔 잘리지 않고 한 줄씩 나온다).
5. 비교: `S3O1`(대표 · 권한 있음)에 같은 예외 · 띠가 없고 `S3HOME` 에만 있으면 권한 0 길 · `S3HOME` 의 `/welcome` 구간(`끝` 구간)에 띠가 없으면 「로그인 직후 첫 그림」 길(선행 §2-3 후보 1).
6. T1 · D1 이동 목록 = `K 닫힌문 관찰 T1|D1 착지 … · 이동 …` + 그 구간 `dxdoc`(시작/끝 · `실패 net::ERR_ABORTED` 꼴). T1 가설 확정 꼴 = `/terms=실패 → /=200`(설계 §5).
