## 1. 계측 규칙 (이 트랙에서 비싸게 배운 것)

1. **빈 표의 EXPLAIN 은 근거가 못 된다** — 측정용 DB 는 전 표 행수를 먼저 찍고 시작한다.
2. **잠금은 격리해서 하나씩 잡고 잰다** — 동시에 잡으면 한 원인이 다른 원인을 가린다.
3. **대조군이 가르는 변수가 실제로 관측된 잠금이 있는 인덱스 안에 있는지** 확인한다.
4. **잰 것과 추론한 것을 섞지 않는다** — 명령과 출력이 있는 것만 「실측」.
5. MariaDB 11.4 에 `performance_schema.data_locks` 없음 · 1205 는 대기 중에만 보임 → 다른 연결에서 `SHOW ENGINE INNODB STATUS`.

## 3. T1-5 — 마이그가 요청 처리 전에 끝나는가 (최우선)

✅ **실측 완료 — 답: 예(끝난다). 단, 「끝난다」이지 「성공한다」가 아니다.**

### 3-1. 코드 근거 (파일:줄)

| 순서 | 위치 | 문장 |
|---|---|---|
| ① | `src/HitPan.API/Program.cs:415` | `var app = builder.Build();` — 호스트 생성. **아직 리스닝 안 함** |
| ② | `src/HitPan.API/Program.cs:445` | `using var migScope = app.Services.CreateScope();` — 마이그 블록 시작 |
| ③ | `src/HitPan.API/Program.cs:455` | `var result = await runner.ApplyPendingAsync(appVersion).ConfigureAwait(false);` — **await 로 기다린다** |
| ④ | `src/HitPan.API/Program.cs:494` | 마이그 블록 `}` 닫힘 |
| ⑤ | `src/HitPan.API/Program.cs:660` | `app.Run();` — **여기서 비로소 Kestrel 이 포트를 열고 요청을 받는다** |

- 최상위문(top-level statements) 안의 `await` 이므로 컴파일러가 `async Main` 으로 만든다 → ③이 완료되기 전에는 ⑤에 도달하지 않는다. **순서가 언어 차원에서 보장된다.**
- ①~⑤ 사이에 포트를 여는 다른 문장 없음 (`app.Start`/`StartAsync`/`RunAsync` 검색 0건 · `Program.cs:640~660` 의 `WatchdogHandoffBootstrap.ScheduleIfPending` 은 백그라운드로 던지고 즉시 반환 · 리스닝과 무관).
- `Program.cs:54` 의 `SeedParentCommand.RunAsync` 는 `args[0] == "seed-parent"` 서브커맨드 경로로 **웹 호스트를 띄우지 않고 종료**한다 — 웹 경로에 영향 없음.

### 3-3. 🔴 그러나 — 조건 P-1ⓐ 가 이것으로 전부 닫히지는 않는다

P-1ⓐ 의 걱정은 「힌트가 없는 인덱스를 가리키면 1176 으로 등록이 통째로 죽는다」였다. 위 실측은 **순서**만 보장한다.

- `Program.cs:476~494` — 마이그가 **실패해도 앱은 뜬다**. 실패 시 `LogError` 만 남기고 기동을 계속한다(주석 "🔴 실패해도 앱을 죽이지 않는 이유" · 헌법 #30 본사 의존 0).
- `MigrationRunner.cs:143~162` — 실패한 마이그는 `success=0` 으로 기록하고 **즉시 중단**, 다음 마이그를 건드리지 않는다.
- 따라서 **DB-125 가 실패한 상태로 서비스가 뜨는 경로가 존재한다.** 그 상태에서 제품 SQL 이 `USE INDEX(ix_purchase_receipts_tenant_partner)` 를 들고 있으면 1176 이 난다.

**정리 — 두 줄로 구분한다.**

| 물음 | 답 | 근거 |
|---|---|---|
| 마이그가 요청 처리 **전에** 끝나는가 | **예** | Program.cs:455 `await` → :660 `app.Run()` · 로그 0.821초 |
| 마이그가 요청 처리 전에 **성공하는가** | **아니오(보장 없음)** | Program.cs:476~494 실패해도 기동 계속 |

→ T1-5 자체는 **「예」** 이므로 **M-2(멈추고 PM 보고) 발동 아님 · T3 착수 금지 아님.**
→ 다만 **T3 에 조건을 하나 더 달아야 한다**(§X 에 올림): 힌트가 붙은 경로는 **인덱스 부재 시 1176 로 죽지 않는 방식**이 필요하다. 이것은 「마이그 순서」가 아니라 「마이그 실패 허용 정책」에서 나오는 별개의 구멍이며, **설계에 되물을 사안**이다(PM 판정 대상).
