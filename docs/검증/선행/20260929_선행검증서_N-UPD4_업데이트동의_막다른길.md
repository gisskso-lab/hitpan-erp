### 3-2 P2 「영원히」 반증 (🧪 + 🟢)

🧪 `test` DB 세션 임시표(DB-82 동일 DDL) — ReadLatest·멱등 SQL 을 **글자 그대로** 실행:

🟢 팝업이 다시 뜨는 조건: `UpdateAvailable`(설치 < 적재) **그리고** 이 탭 sessionStorage 값 ≠ 그 버전. DB 동의는 조건이 아니다.
🔴 **같은 탭에서는 다시 안 뜬다** — 키가 `storage.js:33-34` `AUTH_ALL_KEYS` 에 없어 로그아웃(`:98·:102`)이 안 지운다 ⇒ 같은 탭 로그아웃·재로그인은 재안내 0. 새 탭·브라우저 재시작·재부팅이면 뜬다.
⇒ 탈출구는 있으나 **사용자가 「새 창으로 다시 로그인」을 알아야** 열린다. 화면이 그걸 가르치지 않는다(#24).

### 3-3 P3 Reject 뒤 펜딩 (🟢 순서 추적)

```
루프 n   Consume → ReadLatest=reject → ReportConsentRejected(본사) → 펜딩 null → 게이트 null
루프 n+1 펜딩 없음 · 게이트 null → manifest 재조회 → RequireConsent → 펜딩=m · Upsert
루프 n+2 = 루프 n  (주기 2루프 = 120초, 끝없음)
```

- 새 approve 가 들어오면 n+2 에서 잡힌다 ⇒ 재생성 경로는 **살아 있다**. 막는 것은 ReadLatest 값뿐.
- 🔴 **신규 적발 R-1**: reject 가 최신인 한 **2분마다 본사 `rejected` 보고 + manifest GET + `local_update_status` UPSERT** — 하루 720회. 9/29 N-UPD3(UpdateHistory 500)과 겹치면 본사 로그를 덮는다. N-UPD2 상태(멱등집합 보유)도 같은 2분 주기로 manifest 를 두드린다(결1 109 「1분마다 발견→적재→해소」와 일치 — 실제는 격루프). ⚠️ 본사 수신측 부하 미실측.

## §4 P4·P5 — N-UPD2 겹침 · 거짓 문구 조건

### 4-1 P4 (🟢)

- `_consentAppliedVersions`(`Worker.cs:102`, 인메모리)는 Approve 분기에서 **적용 전에** Add(`:637`) ⇒ blocked·rolled_back 여도 그 버전은 워치독 재기동까지 무시.
- 이 상태에선 DB 가 무엇이든(approve 가 최신이어도) `:602` 에서 먼저 끝난다 ⇒ **N-UPD4 를 고쳐도 N-UPD2 가 그대로 막는다.**
- 반대로 N-UPD2 만 고쳐도 approve→reject 는 남는다.
- 9/29 시간표 대입: 19:23~20:17 = **N-UPD2**(approve 최신인데 무시) · 20:32 이후 = **N-UPD4**(집합 비었는데 reject 최신). 한 사건에서 둘이 **이어 달렸다.**
- 🔴 반대 방향 사실: 워치독 재기동은 옛 approve 로 **묻지 않고 재시도**한다(20:19). 실패 버전이 부팅마다 재시도될 수 있다 ⇒ 되물을 것 1.

| N-UPD1 | 차단 안내 0 | 원인은 알지만 풀 수단이 여전히 막힘 |

⇒ 🔴 **N-UPD7 → N-UPD4 순서는 뒤집으면 안 된다**(7 만 먼저 나가면 거짓 문구가 고객 화면에 새로 생긴다). 묶음 범위·순서는 PM·설계 판단 — 이 문서는 재료만 준다.
⇒ 설계가 답해야 할 칸: ①로그인창 멱등이 「approve 존재」가 아니라 무엇을 봐야 하나 ②화면 문구가 서버 메시지·실제 워치독 상태 중 무엇을 따르나(`Login.razor:307` 은 서버 메시지를 버린다) ③R-1 본사 보고 폭주를 이 묶음에 넣나.

## §7 P7 — 헌법 #43 과의 접점 (제약만 · 설계 아님)

원문(`헌법원문_1-43.md:422-439`): `[예] → 즉시 적용 (백업 → 교체 → 재기동 → 검증 → 실패 시 롤백)` · `[나중에] → 적용 안 함. 다음 로그인에 다시 물어본다` · 「이 흐름 하나뿐」 · 금지 3 「동의 팝업 컴포넌트·동의 소비 로직을 실측 편의로 우회」.

| # | 제약 | 봉합 방향이 부딪칠 여지 |
|---|---|---|
| C-1 | [나중에] = 적용 안 함 | 「최신 1건」을 버리고 「approve 가 하나라도 있으면」으로 바꾸면 **사용자의 나중 [나중에] 를 무시** ⇒ #43 위반. 막다른 길을 풀되 reject 의 효력은 살려야 한다 |
| C-2 | 다음 로그인에 **다시 물어본다** | 🔴 지금 코드가 이미 어긋남 — 같은 탭 재로그인은 안 묻는다(§3-2). 봉합이 이 가드를 건드리면 #43 쪽으로 가는 것이고, 그대로 두면 막다른 길 탈출구가 좁다 |
| C-3 | 흐름은 팝업 Y/N 하나 | 로그인창 버튼(작12 · 사장님 결재 탈출구)은 **로그인 전** 경로다. 이 버튼이 reject 를 뒤집는 권한을 갖는지 = 흐름에 두 번째 입구를 여는 것인지 ⇒ **사장님 결재 사안** |
| C-4 | 실패 시 롤백 — 그 뒤는 원문에 없음 | 워치독 재기동 시 옛 approve 로 자동 재시도(§4-1)가 「[예] = 즉시 적용」의 연장인지, 다시 물어야 하는지 원문이 말하지 않는다 ⇒ 되물을 것 1 |
| C-5 | 금지 3 우회 금지 | `force-update.ps1` 식 수동 INSERT 로 막다른 길을 푸는 **운영 처방**은 #43 금지 3·#39 양쪽에 걸린다 ⇒ 봉합은 코드여야 한다 |
| C-6 | ESC = [나중에]? | 원문은 버튼 둘만 말한다. ESC 를 reject 로 적는 현재 동작의 유지 여부 = 되물을 것 3 |
