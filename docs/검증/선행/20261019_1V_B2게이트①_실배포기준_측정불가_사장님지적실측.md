## §2 🔴 왜 이렇게 만들어졌나 — 전제가 이미 사라졌다

스크립트 주석이 그대로 말한다.

- `:50` — *"fail-closed 로 전환: test 환경임이 명시 증명될 때만 실행. **demo 엔 마커가 절대 없으므로** 100% 차단."*
- `:58` — *"**demo 서비스**(cloudflared, 접미사없음) Running 인데 test 마커도 존재 = 위험상태"*
- `:148` — *"**demo API 와 test API 둘 다 `HitPan.API.exe`** 라 ProcessPath 가 `$ApiSlotPath` 하위일 때만 kill"*

⇒ 🔴 **이 가드들은 「같은 PC 에 demo 운영과 시험이 함께 있던 시절」의 안전장치다.** 그때는 이름·경로가 둘을 가르는 **유일한** 수단이었다.

🔴 **그런데 demo 는 삭제됐다.** 이 PC 는 이제 **정식설치 실물** 한 벌이고, 시험은 **별 PC** 에서 한다.
⇒ **전제가 사라졌는데 가드는 남아 있다.** 남은 가드가 지금은 **고객 환경을 재는 것을 막는 쪽으로** 작동한다.

## §3 🔴 그러면 어떻게 고치나 — 판정축을 바꾼다

안전장치의 **목적**은 *"운영 PC 에서 못 돌게"* 다. 지금 구현은 그 목적을 **서비스 이름**으로 판정한다. 목적은 유지하고 판정축만 바꾼다.

| 가드 | 지금 | 🔴 제안 |
|---|---|---|
| 마커 파일 `ENV=TEST` (`:42-53`) | 있음 | 🟢 **유지** — 별 PC 임을 증명하는 핵심 |
| `db.conf` 의 `PRIMARY_DOMAIN` 이 `demo` 인가 (`:70-78`) | 있음 | 🟢 **유지 + 강화** — 실고객 도메인까지 거절 |
| 운영 `cloudflared` Running 동시 검사 (`:57-64`) | 있음 | 🟢 **유지** — 운영이 도는 PC 면 거부 |
| 🔴 **서비스 이름 `-test` 강제** (`:78-79`) | 있음 | 🔴 **뗀다** — 실배포 이름 그대로 시험 |
| 🔴 **경로 `C:\HitPanTest` 강제** (`:21`·`:153`) | 있음 | 🔴 **실배포 경로를 허용**(마커가 있는 PC 에서만) |

🟢 **이렇게 하면**: 별 PC 에 **고객과 똑같이 설치**하고 **실배포 이름·경로 그대로** 죽여 볼 수 있다. 안전은 **「그 PC 가 운영이 아님」** 으로 지킨다 — 이름이 아니라 **환경**으로.

🔴 **이것은 안전장치 완화이고 코드 변경이다** ⇒ **#29·#39 에 닿는다** ⇒ 작업지시서 + 사장님 결재 없이는 손대지 않는다.

## §4 사장님 두 번째 문장의 처분 — **둘 다 돌린다 = 대조실험**

> *"다른 pc에서 별도의 테스트 공간도 돌리기는 해"*

⇒ 🟢 **별 PC 는 쓴다. 거기서 테스트 공간도 돌린다.** 다만 **본안은 실배포본**이다.

| 구분 | 무엇 | 숫자의 뜻 |
|---|---|---|
| **본안** | 별 PC + **고객 실배포본 그대로** | 🟢 **이것이 고객 환경 숫자다. 성적서에 올라간다** |
| **대조군** | 같은 PC + 테스트 공간(`-test`) | 🟡 비교용. **둘이 다르면 그 차이가 곧 발견이다** |

🔴 **대조실험이 되므로 오히려 더 강한 측정이다** — *"고쳤다 ≠ 갔다"* 를 가르는 방식과 같다.
