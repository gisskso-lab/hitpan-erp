## §0 카드 — 설계가 받아야 할 것

1. 🟢 **본보기가 있다** — `DB-144`(origin 칸 신설)가 같은 모양이다. 추가형 `IF NOT EXISTS` + 조건부 읽기 가드 + 캐시 리셋까지 한 벌로 서 있다(P-3·P-4).
2. 🔴 **필터는 서버로 간다.** 쪽별 `LIMIT 200` 이 이미 있어 화면에서 거르면 **200 밖 행이 사라진다** — 작1 A-1 과 같은 모양이다(P-5).
3. 🔴 **낱말은 서버가 내려보낸다.** ERP Web 은 서버 코드를 참조하지 않으므로(P-7) 화면에 표를 두면 **사본이 둘**이 된다 — 작2 가 그 자리에서 이미 한 번 어긋났다(C-2).
4. 🔴 **값과 낱말을 둘 다 내려보낸다.** 필터는 **값**으로 걸고 표시는 **낱말**로 한다 — 그게 결-D ⓑ 를 고른 이유(「낱말을 바꿔도 필터가 안 깨진다」)를 지키는 유일한 모양이다.
5. 🔴 **기본값은 `NULL` 이다.** `'etc'` 로 채우면 **옛 행이 「기타였다」고 거짓 주장**을 하고, 칸을 안 적는 기존 INSERT 가 깨진다(P-11).
6. 🟢 **게시 때 마이그 켜는 것을 잊을 수 없다** — 워크플로에 **fail-closed 교차검증**이 있다(P-9).

## §2 전제 밖 적발 2건

### A-1 🔴 「기타 공지사항」이 **두 가지 뜻**을 갖는다

- 명시 `etc` = 본사가 **「기타 공지사항」으로 골라** 보낸 것
- `NULL` = **작3 이전에 내려온 옛 쪽지** — 종류를 **모른다**

화면에는 **같은 말**로 보여야 한다(결-D: 「옛 쪽지는 기타로 보인다」). 그런데 **데이터는 구분해야 한다**(P-11 — 모르는 것을 안다고 적으면 거짓이다).

⇒ **설계 판단**: 저장은 `NULL` 그대로, 표시는 「기타 공지사항」, **필터는 `purpose = 'etc' OR purpose IS NULL`**. 🔴 이걸 안 적으면 「기타 공지사항」을 골랐을 때 **옛 쪽지가 사라져** 사장님이 「쪽지가 없어졌다」로 보신다.

### A-2 🔴 C-5(칩과 제목이 다른 말) 봉합이 이 차수에 묶여 있다

작2 [4] 조건 C-5 를 **작3 으로 유예**했다. 지금 한 줄 안에서 제목은 「[히트판 공지사항]」, 칩은 「본사 안내」로 **두 번 말하고 값이 다르다.** 게다가 코드에 **표기가 두 가지**다 — 칩 쪽 「본사 안내」(띈다) / 낱말 표 fallback 「본사안내」(안 띈다).

⇒ **설계 판단**: 칩을 **용도 칸 값의 낱말**로 세우면 제목과 칩이 **같은 출처**가 된다(두 번 말하는 문제 자체가 사라진다). 🔴 표기는 **한 가지로** 합친다 — 어느 쪽으로 합칠지는 설계 §에서 한 줄로 정하고 게이트로 묶는다.
