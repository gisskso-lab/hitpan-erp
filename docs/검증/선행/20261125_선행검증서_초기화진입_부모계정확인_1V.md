## §5 전제 5 — 끊길 수 있는 흐름 · 3시스템 경계 · 기존 시험

**흐름(#20)**
- F1 덮어쓰기 자료이관: 서비스를 고치면 자식 관리자의 덮어쓰기도 막힌다. 8/11 대표 지시(코드 주석 `DataResetController.cs:17-18` · `Sidebar.razor:330-332` 「자료관리는 부모계정 + 메인PC」)와는 맞으나 **동작 변화**이므로 작업지시서에 적을 것.
- F2 부모 행 없는 설치본: is_parent=1 행이 없으면 초기화 · 덮어쓰기가 **누구도 못 하게 닫힌다**(닫힌 쪽). 이미 뼈대 재시드도 같은 경우 대표 사원을 못 만든다(`CompanyBootstrapProvisioner.cs:622` `if (parent is not null)`). ⚠️미확인 — **테스트 환경에서 잴 것**: 출하 DDL 신규 설치 · 6/4 이전 설치본 · demo 각각에 `is_parent=1 AND is_deleted=0` 행 수(0 / 1 / 2+).
- F3 부모 2명 이상: 1명 보장 제약이 없다(§2). `TenantDeviceService.cs:1353` 「대표가 여럿일 수 있고, 그중 원본은 부모다」. is_parent 로 가르면 2명 모두 통과 — 설계가 「본인이 is_parent=1」인지 「회사 부모 1명」인지 정할 것.
- F4 화면: WASM 은 is_parent 를 클레임으로 모른다(§2). 서버만 고치면 자식 관리자가 메뉴를 보고 들어가 비번까지 친 뒤 거절된다(「처음 보는 사람이 혼자 쓸 수 있냐」 기준 미달). 메뉴를 감추려면 API 한 번(`UserModels.IsParent` 등) 또는 토큰 변경이 필요 — 토큰 변경은 계정 인증 전체에 번진다.
- F5 #3 예외: 초기화는 원장 DELETE 를 쓰는 #3 예외 경로(`DataResetService.cs:18-19`). 들어갈 사람을 좁히는 것은 예외의 전제(「사장님이 명시 결재한 전체 초기화」)를 강화하는 쪽 — #3 과 충돌 없음.

**3시스템 경계(#35 · #18 · #22)**
- 초기화 · 판정 재료(`users.is_parent`)는 전부 고객 PC 로컬 DB. 고침에 본사 호출이 필요할 이유 0 · 지금 초기화 길에 본사로 가는 호출 0(`DataResetService.cs:20` · 서비스 의존성 = DB · 백업 · 감사 `:30-34`). 설계가 백오피스에 「부모 확인」을 묻는 쪽으로 가면 #30 · #40(:280 「백오피스에서 호출해 온다」 즉시 반려) 위반.
