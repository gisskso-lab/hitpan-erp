## 2. 증상 ③ — 같은 함수를 타는데 **입력이 두 갈래**다

두 미리보기는 같은 `RenderDocumentAsync` 를 탄다. 갈리는 것은 `PdfPreviewOverrides` 두 칸이다.

| 경로 | 세우는 칸 | 양식지 그림 |

```

```

`print_background` 기본값은 **0**(DB-148 ①·출하 DDL `hitpan_db_clean.sql:1436` — 둘 다 `NOT NULL DEFAULT 0`, [실측]).

## 3. 증상 ② — ③ 과 한 뿌리 · 그리고 H3

②(*"새 견적서 양식에 데이터 바인딩 실패"*)는 ③ 의 둘째 자리와 **같은 줄**(`:97`)이다.
`plain` + 양식지 그림에서는 값이 **그림의 칸이 아니라 히트판 자기 표**로 들어간다. 그림만 바뀌고 글자는 제자리 ⇒ 고객 눈에는 「내 양식에 데이터가 안 붙었다」다. 10/25 *「두 겹 겹침」* 과 같은 모양이다.

### 🔴 [가설] H1·H2·H3 — 내 측정이 지지하는 쪽은 H3

| | 내용 | 내 판정 |
|---|---|---|
| H1 | 새 양식을 「기본 양식」 체크 없이 저장 → 시드 기본 행이 이긴다 (`FormTemplateService.cs:117` `FirstOrDefault(t=>t.IsDefault) ?? FirstOrDefault()`) | **가능 · ⚠️미측정.** 성립엔 `estimate` 행이 2개 이상이어야 한다 |
| H2 | `plain` 은 좌표를 영영 안 탄다 (`:97`) | **구조적으로 참.** `plain` 이면 ② 의 모양은 **반드시** 난다 |
| **H3** | **업로드는 파일만 만들고 양식 행에 안 적는다** — `FormTemplateController.cs:176~200` 주석이 *"저장하지 않는다 — 양식 행에 적는 것은 고객이 저장 단추를 누를 때다"* 로 **명시**. 창을 닫으면 **파일만 남고 `background_image_url` 은 빈다** | **[실측]이 가장 강하게 지지** |

**H3 를 지지하는 [실측]**: `form-backgrounds/<tenant>/` 에 **같은 크기(129,147 bytes) 그림이 네 번** 올라가 있다(10-25 22:31·22:32·22:38 · 10-26 16:51). 같은 그림을 네 번 올리는 것은 **「올렸는데 안 먹는다」를 네 번 겪은 흔적**이다.
H1 이라면 그림을 다시 올릴 이유가 없다(체크 한 번 + 저장이면 된다). H3 는 **올릴 때마다 미리보기에 보이고, 저장을 안 하면 전표에 안 나오는** 되풀이를 정확히 만든다.

**그리고 화면이 그 되풀이를 거든다** (`FormTemplateEditorDialog.razor:1000~1014`):
업로드 성공 시 *"양식용지 그림을 올렸습니다. 아래 미리보기로 확인하십시오."* + **즉시 미리보기**(그림이 보인다 — `IsFormDesignPreview=true` 라 무조건 깔리므로).
🔴 **「저장을 눌러야 전표에 반영됩니다」를 말하는 글자가 0건이다.** 고객은 보이는 그림을 근거로 끝났다고 읽는다.

🔴 세 가설 중 어느 것도 **행 한 줄을 보면 끝난다.** 코디가 준 SELECT 한 줄이 가른다 — **나는 못 돌렸다**(⚠️미측정 1).
🔴 **네 번째 뿌리 가능성을 닫지 않는다.** 위 셋 중 아무것도 안 맞으면 억지로 끼우지 말 것.
