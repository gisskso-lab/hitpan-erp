## §2-3 보강 — 🔴 **확정됐다 (2026-10-12 사장님 실측)**

§2-3 은 「운영 45번 미적용」을 **가설**로 남겼다. 그 값이 사장님 손으로 측정됐다.

작4 봉합이 운영에 선 뒤 백오피스 CS창구 → 쪽지보내기를 누르자:

> 이 서버에는 쪽지 보관기한·선발신 기능의 자료방이 아직 준비되지 않았습니다.
> 본사 담당자에게 알려 주세요(백오피스 스키마 45번 적용 필요).

이 문장은 작4 A-1 가드(`SchemaPendingResult`)가 **표 2개가 없을 때만** 내는 답이다
(`information_schema.tables` 로 `bo_cs_outbound`·`bo_cs_retention_policy` 를 직접 센다).

⇒ **운영 백오피스에 45번이 적용되지 않았다 — 가설이 아니라 사실이다.**
⇒ 증상 ①②③ 의 뿌리 판정(§2-1)이 맞았다. 500 3건은 전부 같은 한 자리였다.
⇒ 가드는 의도대로 동작했다: 종전 **500 + 빈 body**(화면이 JSON 파싱 예외를 뱉던 모양) 대신
   **사람이 읽을 문장**이 나왔고, 되던 화면은 죽지 않았다.

### 🔴 그래서 아직 **동작하지 않는다** — 가드와 기능은 다른 사실이다
§2-3 에 적어 둔 경고가 그대로 실현됐다. 가드는 「안 터지게」 까지다.
**보관기한·선발신은 45번이 적용돼야 돈다.** 남은 일은 봉합이 아니라 **적용**이다.

### 남은 한 칸 — #29 사전 승인 사안
`SchemaMigrator` 는 `HITPAN_BO_AUTO_MIGRATE=1` **일 때만** 돈다(기본 off · 통제권 사장님 · #29).
deploy 워크플로에 그 설정은 **0건**이고, 그게 설계 의도다 — 코드가 DB 를 임의로 바꾸지 않는다.
10/11 작1 §F 가 쓴 것과 **같은 절차**(「스위치 1회용 재기동 1회」)가 필요하다.

적용 범위(45번 실독 — 기존 자료에 미치는 영향):
- `CREATE TABLE IF NOT EXISTS` ×2 (`bo_cs_outbound` · `bo_cs_retention_policy`)
- `INSERT IGNORE` 1행 — 보관기한 **무기한**(기본값) · 사람이 설정한 값은 덮지 않는다
- `ALTER TABLE bo_cs_tickets ADD COLUMN IF NOT EXISTS` ×3 (`purged_at`·`purged_by`·`purge_reason`) — 한 문장에 한 절
- **기존 자료를 바꾸는 DML 0건**

`_schema_migrations` 는 (파일명 + 내용해시)로 멱등이라 10/11 에 들어간 `00`~`44` 는 다시 안 돈다 ⇒
이번 재기동에서 **실제로 적용되는 것은 45번 하나**다.
