## 설계에 넘길 사실

- **F-1 (출시 꼴 = 시험 꼴 아님)**: 출시 길은 `PublishSingleFile=true`, CI `publish-migsmoke` 는 아님. 실림 게이트를 migsmoke 에 붙이면 꼴이 다르다. 출시 꼴 publish 를 따로 한 번 더 하든지(시간 · 빌드 잡 30분 한도 확인), 꼴 차이를 받아들이는 근거를 적어야 한다(이 PC 실측: 단일 파일 꼴에서도 None · 네이티브 dll 은 낱개로 남음).
- **F-2 (글꼴은 낱개 파일이 아님)**: 글꼴 바이트는 `HitPan.Application.dll` 안 → 단일 파일 출력에선 다시 exe 안. 「게시 폴더 글꼴 실림」 은 파일 존재 검사로는 못 잰다. 지금 시험 ②(빌드 산출 dll 의 내장 리소스 = 고정 해시)가 잡는 범위가 곧 상한. 게시 exe 안 바이트까지 원하면 번들 해석이 필요(과함 · PM 판단).
- **F-3 (고지 바이트는 줄바꿈 따라 바뀜)** 🔴: `.gitattributes` 에 `*.txt` 규칙 0 · 이 PC `core.autocrlf=true` → 블롭 LF 5,682 B(SHA `20c156a2…`) ↔ 체크아웃 · 출력 CRLF 5,803 B(SHA `3c1ba247…`). 「고지 전문 바이트 대조」 를 고정 해시로 하면 체크아웃 설정마다 빨강/초록이 갈린다. 선택지: ⓐ `.gitattributes` 에 그 파일 `-text` 또는 `eol=lf` 한 줄(저장소 설정 변경 · PM) ⓑ 줄바꿈 정규화 뒤 해시 ⓒ 출력 파일 = 저장소 체크아웃 파일 바이트 같음(자기 대조). CI windows 러너의 autocrlf 값은 **미측정**.
- **F-4 (qpdf 쪽 고정 재료)**: 네이티브 6개 해시(출력 = 캐시 일치 · `f2_publish_listing.txt`) · 꾸러미 contentHash · 잠금 파일 없음. CTO §3 ⓑ 「잠금 파일의 꾸러미 해시」 는 잠금 파일을 켜야 함 = 빌드 설정 변경(CTO 판정 :94 「범위 PM」).
- **F-5 (qpdf 고지)**: 꾸러미 안 `ExternalDependencyLicenses/qpdf.txt` 등 13개는 publish 출력에 **안 실림**(LatoFont 폴더만 실림 · 이 PC 실측). C4 qpdf 고지(법무 1줄)를 같은 `licenses\` 자리에 둘 때 같은 Link 방식 선례 = `HitPan.API.csproj:128`.
- **F-6 (시험 프로젝트 경로)**: `HitPan.Tests` 가 `HitPan.API` 를 ProjectReference(:32) → `licenses\…` 가 시험 출력에도 복사될 수 있음(미측정). 이것을 쓰면 publish 없는 시험이 되나 「게시 폴더」 실림은 아님.
- **F-7 (범위 밖 관찰 · F-2 와 무관 · 기록만)**: 출시 꼴 publish 출력에 `artifacts/ui03-api-build/`(저장소에 추적된 옛 빌드 산출 121개 · 2026-04-10 추가 · `appsettings.json` 사본 포함)와 `AI/` 폴더(.md 3개)가 함께 실림. 각각 #41 · #23 관점 확인 거리 — 별건으로 PM 에게.
