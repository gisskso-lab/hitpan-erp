## §2. 실측 사실 3건

### F-1 🔴 `Build & Test` 는 이 브랜치에서 **한 번도 돈 적이 없다**

트리거 실측 — `.github/workflows/build-and-test.yml` L8~L12:

```
on:
  push:
    branches: [develop, main]
  pull_request:
    branches: [develop, main]
```

`feat/20260920-rc-safe-path` 는 **push 대상도 PR 대상도 아니다.**

CI 이력 실측 (`gh run list --branch feat/20260920-rc-safe-path --limit 10`) — **10건 전부 `TruffleHog Secret Scan`**.
`Build & Test` **0건**. TruffleHog 만 도는 이유는 그쪽 트리거가 `push:`(브랜치 무제한)이기 때문이다.

⇒ 🔴 **봉합 커밋 `5aa6196e` 를 아무리 밀어도 CI 는 안 깨어난다.**
⇒ **§4-2 는 「기다리면 닫히는」 항목이 아니다.** 깨울 방법을 만들어야 닫힌다.

> 이것이 **별건 C(CI 트리거)** 가 가리키던 자리다. 인계서는 「CI 에서 돈 흔적을 봐라」고만 적었고,
> **볼 수 있는 상태인지는 아무도 안 쟀다.** 이번에 쟀다.

### F-2 🟢 CI 로그는 **시험 이름을 한 줄씩 찍는다** — 원하는 증거의 모양이 존재한다

과거 실제 CI 로그 실측 (`gh run view 35241263441 --log` · main · 9/17 · 4,131줄):

```
DB 게이트 (Integrity — 실제 DB 실행) … Passed HitPan.Tests.Integrity.SalesChainLinkGateTests.G3_… [n ms]
```

**「DB 게이트」 스텝 안에서만 `Passed …` 291줄.** ⇒ `--verbosity normal` 이 개별 시험 이름을 찍는다.
⇒ 🟢 **`RcLockRatioGateTests.G-RC16…` 이 CI 로그에 뜨는 것은 원리상 가능하다.** (CTO 가 요구한 증거 형태가 실재한다)

### F-3 🔴 증거를 **어느 스텝에서 긁느냐가 판정을 가른다** — `build` 잡은 증거가 못 된다

같은 로그에서 `Passed HitPan.Tests.Integrity.…` 줄이 **`Build (errors 0 + warnings 0)` 잡에도** 있다(L547~).
그 잡의 `dotnet test src/HitPan.sln` 은 **필터 없이 전부** 돌린다 ⇒ **DB 없는 곳에서 DB 게이트는 `[SKIP]` 로 초록**.

⇒ 🔴 **`build` 잡 로그에 `RcLockRatioGate` 가 떠도 그것은 「돌았다」가 아니다.**
   그대로 세면 이번에 봉합한 사고(**안 돈 게이트를 통과로 셈**)를 **판정 쪽에서 똑같이 반복**한다.
⇒ 증거는 **`DB 게이트 (Integrity — 실제 DB 실행)` 스텝 안 + `Passed`** 두 조건을 동시에 만족해야 한다.

## §3. PR 이 유일한 경로인가 — 대안 3개를 재고 고른다

| 안 | 내용 | 판정 |
|---|---|---|
| **(가)** | **PR 을 연다** (base `main`) — `pull_request` 트리거 발화 | 🟢 **채택.** 워크플로 **무수정** · 어차피 이 브랜치의 종착지가 main PR 이다 |
| (나) | `workflow_dispatch` 추가 | 🔴 CI 파일을 **또** 고친다. 봉합 확인하러 봉합 대상을 건드리는 꼴 |
| (다) | push 트리거에 feature 브랜치 추가 | 🔴 확인 끝나면 되돌려야 하는 **임시 배선**. 되돌림을 잊으면 잔재 |

🔴 **PR ≠ 머지.** 머지 차단(⛔)은 그대로다. PR 은 **CI 를 깨우는 계측 장치**로만 쓴다.
안전을 위해 **draft** 로 연다 — 초록이 떠도 실수로 못 누른다.

## §4. PR 을 열면 **같이 깨어나는 워크플로** 전수 (배포 오발 방지)

| `trufflehog` | 🟢 예 | 이미 push 마다 돌고 있음 |

| `deploy-ncp` | 🔴 **아니오** | `push: [main, develop]` 전용 — **PR 로 안 깨어남** |
| `deploy-update` | 🔴 **아니오** | `workflow_dispatch` 전용 (#43 Major 팝업 규율) |
| `zap-baseline` | 🔴 **아니오** | `push: [main]` 전용 |

⇒ 🟢 **배포 계열 4개 중 어느 것도 PR 로 발화하지 않는다.** PR 을 여는 것은 게시와 무관하다.
