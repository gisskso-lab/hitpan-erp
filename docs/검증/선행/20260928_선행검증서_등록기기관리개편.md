## §2 전제 2 — 승인 걷기가 무엇을 깨나 · 무엇이 지키나 · 슬롯 잔재

### 2-1 인증 통로 (`DeviceAuthMiddleware.cs` 285줄)

- 🟢 스위치 `DeviceApproval:Enabled` 가 꺼지면 **통째로 건너뛴다**(`:77` · `:83-87`). 같은 스위치를 `TenantDeviceService.cs:92` 가 보고 새 기기를 `pending` 으로 만든다(`:759`).
- 🔴 그 스위치가 **출하본에 켜져 있다**(`appsettings.json:15-21` `"Enabled": true` · 8/16 전결 주석). #21 로 이 파일은 수정 금지 ⇒ **「꺼서 걷기」는 불가.** 선택지는 (가) 코드에서 승인 판정을 걷는다 (나) 스위치를 회사별 DB 설정으로 옮기고 끈다 — 축 B 킬스위치가 이미 이 방식이다(`AuthService.cs:240` *"#21 로 appsettings 불가"*).
- 🟢 통과 조건 3갈래: ① 기계비밀(`:144` `VerifyDeviceSecretAsync`) ② **메인PC 기기번호 + `approved` + `is_main_pc=1`**(`:186-194`) ③ 대표계정 탈출 경로 `/api/devices`·`/api/auth` 만(`:233-239` · `:268-272`). 셋 다 아니면 403 `forbidden_device_auth`(`:241-249`).
- 🔴 **판정식만 고치고 새 기기 `pending` 생성을 그대로 두면** 기존 대기 직원·새 직원 모두 ②③ 어디에도 안 걸려 403 이다. 반대로 **대기 생성만 끊고 판정식을 두면** 기계비밀이 없는 새 기기는 여전히 403 이다 ⇒ **생성(`TenantDeviceService.cs:759`) · 판정(`DeviceAuthMiddleware`) · 직원 관문(`DeviceAuthGate`) · 대표 화면 넷이 한 묶음.** 9/25 「① 화면 → ② 판정식」 2단계 분리는 이 묶음을 쪼개므로 🔴 **그대로 따르면 안 된다**(R-1).
- 🟢 로그인 시 기기 등록(`AuthController.cs:161` → `RegisterOrRefreshAsync`)은 승인 대기를 **401 로 바꾸지 않는다**(`:163-175` 8/16 P0 봉합) — 로그인은 되고 ERP 앞 관문에서 멈추는 구조. 걷은 뒤에도 이 호출 자체를 지울지는 설계 몫(메인PC 표식 갱신이 이 경로를 탄다 — `TenantDeviceService.cs:760` 주변 주석 「표식은 다음 접속에 제자리」 ⚠️ 호출 제거 시 메인PC 표식 갱신 경로 확인 필요).

### 2-2 메인PC (살아 있어야 함)

- 🟢 `MainPcRegistrationService` 는 **같은 표 `tenant_devices`** 에 쓴다(`:150` · `:191-204` UPDATE `d.status='approved'` · `:250` 1대 검사). 서버 기동 시 스스로 `approved` 로 등록.
- 🟢 메인PC 통행은 미들웨어 갈래 ②(`status='approved' AND is_main_pc=1`)와 **왕복 증명**(`MainPcGate`·`mainpc-*` API · `DeviceController.cs:513-607`)이 따로 지킨다.
- ⇒ **걷어도 되는 것**: `pending`·`rejected` 를 만드는 코드, 인증키·재발급·QR. **남겨야 하는 것**: `tenant_devices` 표·`status` 열·`is_main_pc`·`mainpc_*` 열 · 메인PC 줄의 `approved`. 열 제거 금지(#1 · #37 취지 — 「안 읽힌다 ≠ 잔재」).
- ⚠️ 기존 고객 DB 에 남은 `pending`·`revoked` 일반 기기 줄의 처리(무시/정리)는 결재 D-1.

> **PM 메모 (9/28)** — 이미 사장님 답이 있는 것은 다시 묻지 않는다:
> - **D-2** ⇒ **이 화면의 일이 아니다.** 사장님 원문 *"퇴사자는 계정관리에서 막는다 = 이건 사용자가 퇴사자 처리시 할 일."* — 고객사 담당자가 퇴사 처리 때 계정관리에서 막는다. 이 화면에 [접속 끝내기] 같은 기능을 만들지 않는다.
> - **D-4** ⇒ **모바일 설계 트랙의 일.** 사장님 원문 *"모바일은 조회만 된다 = 이건 모바일 설계시 할 것임."* — 동시로그인 차단·이 화면 개편 범위 밖.
> - **순서** ⇒ 사장님 원문 *"동시로그인이 지금 된다는게 문제인거지"* — **PC 동시로그인 차단 켜기가 먼저**, 이 화면 개편은 그 다음. 나머지 D-1·3·5·6·7·8 은 화면 개편 [2] 착수 때 여쭌다.
