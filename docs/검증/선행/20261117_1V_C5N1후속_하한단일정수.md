## 4. M4 — 변이 2건 (정적)

- **방식**: 개발명세서 §5 꼴 그대로 가능 — 버림 가지 · 변이마다 커밋 1 · push 1 · 자체시험 단계 빨강 + 해당 `miss` 1줄(숫자만) · 다른 시험 동반 빨강은 기록 · 원인 대조.

- **변이 ②(닫힌 꼴 → 옛 꼴 「비교 실패 = 거짓」)** 🆕: 확인 줄이 남아 있으면 확인을 통과한 값은 전부 정상 정수(1~9자리 숫자)라 비교 실패가 **일어날 수 없다** → 어떤 입력으로도 ② 단독은 빨강이 될 수 없다(정의상 미측정). 잴 수 있는 것 = 「① + ② 동시 되돌림 = main `d93d525f` 원래 꼴」 → 빨강(S10a 「지금 코드라면 깨끗 0 — 대조군」 과 같은 꼴). → 결-3.

## 5. M5 — K5 판정 재료 (실측 · 파일)

- 공개 잡 로그에 찍히는 것 = 판정 줄 `:177` 「판정: 깨끗 — 결과 0건 · 훑은 양: chunks:N bytes:N commits=N」. `scanned` 는 **첫 기록 줄**에서 정규식에 맞은 `chunks`·`bytes` 를 전부 이어 쓰므로, 한 줄에 조각 꼴이 둘이면 판정 줄에 `chunks:` 가 두 번 보인다 → 「첫 기록 줄의 값 개수」 는 판정 가능.
- 안 보이는 것: ① **기록 줄 개수**(`-m1`) ② 정규식에 안 맞는 새 꼴(그 경우 빈 값 → 커밋 > 0 이면 검사 오류로 드러남) ③ 「찾음」 길(종료 183)에서는 하한을 안 보므로 값 검사도 안 섬.
- 엔진 기록 원문 공개 0: `engine.log` 는 임시 폴더(`scan.sh:67` `mktemp -d` · `:68` 끝날 때 지움)에만 있고, 오류 길도 줄 **수**만 찍는다(`:191~192`). 워크플로 `trufflehog.yml` 에 업로드 단계 0(`upload` · `artifact` 검색 0). → HQA 가 말한 「원본 로그」 = Scan 단계 잡 로그이고, K5 는 거기서 **반쪽**만 잰다.
- 고친 뒤에는 「여러 값 = 검사 오류」 라서 새 판 실제 Scan 이 초록이면 첫 기록 줄 값이 하나라는 것은 런 자체가 증명한다. 기록 줄 개수까지 공개 판정하려면 판정 줄에 숫자 칸 하나가 더 필요하다 → 결-6.
