## 0. 카드 — 설계 전 해소 vs 설계 반영 조건

**설계 전 해소 (대표 확인)**
- Q1. 「그 고객사를 보는 화면」 목록 확정 — §1 표의 확인 필요 3묶음을 넣을지 뺄지.
- Q2. 표시줄을 눌러 들어간 **고객사로 걸러진 고객A/S창구 목록**에서도 표시줄이 그 고객사 숫자를 유지하나. 추천 = 유지. 안 그러면 목록은 그 고객사, 아래 숫자는 전체가 되어 오더의 「숫자와 목록이 같아야」 가 깨진다.

**설계 반영 조건 (등급)**
- C1 (P1) 사이드바 빨간 숫자 = 언제나 전체. 지금은 표시줄·사이드바·고객A/S창구가 **같은 숫자 한 벌**(`CsCountsService`)을 나눠 쓴다. 고객사 숫자를 같은 칸에 쓰면 사이드바가 고객사 숫자로 바뀐다 ⇒ 전체 한 벌과 고객사 한 벌을 **따로** 둔다(§3).
- C2 (P1) 사이드바는 자기 시계가 없다(처음 한 번만 셈 · `BackofficeSidebar.razor:149-154`). 60초 다시 세기는 표시줄 시계가 한다(`CsStatusBar.razor:51-52`). 고객사 화면에서 표시줄이 고객사 숫자만 세면 **사이드바 전체 숫자가 멈춘다** ⇒ 고객사 화면에서도 전체 숫자 다시 세기는 계속 돈다.
- C3 (P1) 주소 꼴 `/admin/tenants/{TenantId}` 와 같은 높이에 글자 주소 `/admin/tenants/issue`(고객 발급 화면 · `AdminTenantIssuePage.razor:11`)가 있다. 「`/admin/tenants/` 다음 한 칸 = 고객사」 로 읽으면 발급 화면을 고객사 화면으로 잘못 안다 ⇒ 글자 주소는 빼고 읽는다.
- C4 (P1) 고객A/S창구 목록의 고객사 거름은 **고객사 고유값 일치**로 받는다. 지금 있는 검색 `q`(회사명·테넌트넘버 부분 일치 · `CsAdminController.cs:192`)로 대신하면 이름이 비슷한 다른 고객사가 섞여 숫자 ≠ 목록.
- C5 (P2) 목록은 최근 300줄에서 끊긴다(`CsAdminController.cs:194` · 화면은 「최근」 표기 `AdminCsListPage.razor:201-203`). 숫자는 끊지 않는다. 한 고객사 한 단계가 300건을 넘으면 숫자 ≠ 줄 수 — 지금 전체 화면에도 있는 꼴이고 화면 글자는 이미 정직하다.
- C6 (P2 · 기존 꼴 기록) 숫자는 `bo_cs_tickets` 만 세고(`:133-144`) 목록은 `tenants` 와 안쪽 결합(`:187`). 고객사 완전 삭제가 CS 쪽지를 지우지 않는다(`TenantsAdminController.cs:245-272` 에 `bo_cs_` 0건 · 외래키 0) ⇒ 지운 고객사 쪽지는 **전체 숫자에는 있고 목록에는 없다**. 고객사 화면 숫자에는 영향 없음.
- C7 (P2) 조회 실패 때 「0으로 지우지 않기」(`CsCountsService.cs:44-50`)를 고객사 숫자에도 지킨다. 단 **다른 고객사로 옮겼는데 조회가 실패하면 앞 고객사 숫자에 새 회사명이 붙는 꼴**이 생긴다 ⇒ 고객사가 바뀌면 그 숫자는 비우고 「불러오는 중」, 같은 고객사 다시 세기 실패만 직전 값 유지.

## 3. 세는 서버 길 — 고객사 거름 가능

- 길: `GET api/admin/cs/counts` (`src/HitPan.Backoffice.API/Controllers/CsAdminController.cs:402-416`) · 식 `StageCountSql`(`:133-144`) · 단계 뜻은 목록 거름과 같다(`:183-187`).
- 거름 추가: 하위 질의 안쪽에 고객사 고유값 일치 조건 하나 + 선택 인자 하나. 색인 `idx_bo_cs_tenant (tenant_id)` 있음(`installer/backoffice/40_backoffice_cs.sql:41`). 칸을 형변환으로 감싸지 말 것(색인 무력화 · 같은 컨트롤러 `:792-797` 에 형변환 맞춤 주석).
- 권한: 컨트롤러 전체 `[Authorize(Policy = "PlatformAdmin")]`(`:21`) — 정책은 `platform_admin`·`platform_owner` 만(`src/HitPan.Backoffice.API/Program.cs:101`). 대리점(`reseller_admin`)은 숫자 길 자체가 막힘 · 대리점 화면엔 표시줄 없음 · 사이드바도 본사일 때만 셈(`BackofficeSidebar.razor:149`) ⇒ **대리점이 남의 고객사 숫자를 볼 길 0**. 새 인자가 같은 정책을 물려받으면 유지. 고객사 값은 주소에서 오지만 보는 사람은 본사뿐 — #2(ERP 의 JWT 테넌트 원칙)가 아니라 본사 관리 화면의 조회 거름.
- 분리: 사이드바·표시줄·고객A/S창구 3곳이 `CsCountsService` 한 벌을 씀(`BackofficeSidebar.razor:4·159` · `AdminCsListPage.razor:28·299·351·416·472`). C1·C2 대로 **전체 한 벌(사이드바·평소 표시줄) + 고객사 한 벌(고객사 화면 표시줄)** 로 나누면 분리 가능. 고객A/S창구의 다시 세기 4곳은 전체 + (걸러진 상태면) 고객사 둘 다 움직여야 한다.
- 인자 없으면 지금과 같은 응답 ⇒ 사이드바 무영향(시험으로 문다 · §7).

## 4. 고객A/S창구 목록 — 고객사 + 단계 함께 받기

- 지금 주소 칸은 `stage` 하나(`AdminCsListPage.razor:220-221`). 서버 목록 길은 `status·q·mine·stage`(`CsAdminController.cs:157-159`)이고 고객사 일치 인자 없음 ⇒ **화면 주소 칸 + 서버 인자 둘 다 신설**.
- 단계 거름은 세는 식과 같은 뜻 — 같은 기준. 고객사 거름도 같은 고유값 일치로 두면 같은 기준(C4).
- (P1) 주소 칸 반영 식(`OnParametersSetAsync` `:234-245`)은 「들어온 단계 = 지금 단계면 조회 안 함」. 고객사 칸을 더하면 **고객사만 바뀌고 단계가 같은 이동**에서 조회 0회 ⇒ 견주는 기준에 고객사도 넣는다.
- 걸러졌다는 표시 + 「전체 보기」 로 풀 길 필요(풀면 표시줄도 전체 — Q2 와 함께 확정).

## 5. 회사명 출처 · 실패 꼴

- 고객 상세는 회사명을 이미 불러온다(`AdminTenantDetailV2.razor:190`). 다만 표시줄(바탕틀)은 그 값에 닿지 못한다(방법 B 일 때만 재사용).
- 추천: 숫자 길이 고객사 인자를 받으면 **회사명도 같이 돌려준다**(목록 질의가 이미 같은 결합 `CsAdminController.cs:168·187`) — 조회 한 번 · 숫자와 회사명이 어긋날 길 0. 회사명은 본사 고유 데이터(고객사 메타) — #5·#18·#22 저촉 없음(새 데이터 수집 0).
- 실패 꼴: C7. 고객사 값에 맞는 고객사가 없으면(지워짐·잘못된 주소) 숫자 0 + 빈 회사명이 아니라 「고객사를 찾지 못함」 · 전체 숫자에 회사명을 붙이지 않는다(거짓 표시).
