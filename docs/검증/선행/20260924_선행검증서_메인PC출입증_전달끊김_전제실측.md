## §1 — 화면 문구의 출처가 403 이 아니다 (P-1 보정)

사장님이 보신 **"자료보관 컴퓨터에서만 사용할 수 있습니다"** 는 백업 API 403 의 메시지가 아니다.
403 본문 문구는 `MainPcOnlyAttribute.cs:102` 의 *"이 기능은 회사 자료가 들어 있는 컴퓨터에서만 사용할 수 있습니다"* 이고,
화면 문구는 `MainPcOnly.razor:33` 이 자기 판단으로 그린다. 그 판단의 입력은 **별도 호출** `GET api/devices/is-main-pc` 하나뿐이다
(`MainPcOnly.razor:51-52` → `DeviceController.cs:113-125`).

⇒ 콘솔의 403 세 줄과 화면 문구는 **원인은 같지만 경로가 다르다.** 봉합 대상이 둘이라는 뜻이다.
403 만 없애도 화면은 그대로 닫혀 있고, `is-main-pc` 만 고쳐도 API 는 막힌다.
(설계 주석 `DeviceController.cs:117-120` 이 이미 "한쪽만 고치면" 을 경고하고 있다 — 지금이 그 자리다.)

## §2 — 🔴 R-1 봉인과 해제가 서로 다른 금고를 연다

`SealKey` 는 TPM 공급자를 **명시**한다.

- `TpmKeyService.cs:78` `Provider = CngProvider.MicrosoftPlatformCryptoProvider`
- `:83` `CngKey.Create(CngAlgorithm.Rsa, KEY_NAME, keyParams)` → 그 공급자 안에 키를 만든다
- `:85` RSA-OAEP-SHA256 로 암호화한 **RSA 암호문**을 돌려준다

`UnsealKey` 는 공급자를 **안 준다**.

- `TpmKeyService.cs:111` `CngKey.Exists(KEY_NAME)`
- `:113` `CngKey.Open(KEY_NAME)`

.NET 의 1인자 오버로드는 기본 공급자가 **`MicrosoftSoftwareKeyStorageProvider`** 다 —
TPM(`MicrosoftPlatformCryptoProvider`)에 만든 키는 **거기에 없다.**

⇒ `Exists` 가 false → `:118` `ProtectedData.Unprotect(RSA 암호문, LocalMachine)` → `CryptographicException`
→ `:120-123` catch → `Unprotect(..., CurrentUser)` → **또 예외, 이번엔 밖으로 나간다.**

그 예외를 받는 자리가 `MainPcProofService.cs:137-146` 이고, 거기 주석은
*"이것이 「컴퓨터가 바뀌었다」 신호다 — 오류가 아니라 **정상 경로**다"* 라고 적혀 있다.
⇒ **모든 해제 실패가 「컴퓨터가 바뀌었다」로 흡수된다.** 진짜 고장이 정상 경로로 위장된다.

결과는 `DifferentPc` → `Consume` 이 출입증을 **안 준다**(`:171-174`) → 도메인 접속은 영원히 403.

### 현장 증거와의 대조 (⚠️가설이 아니라 예측의 적중)

9/24 팝업 버튼이 **[이 컴퓨터로 바꾸기]** 였다. 그 글자는 `MainPcGate.razor:92` 에서
`_prompt == Prompt.Change` 일 때만 나오고, `Change` 는 `:131` 에서 **`DifferentPc`** 에만 붙는다.
`DifferentPc` 는 `MainPcProofService.cs:122-123` 에 따라 **봉인키가 이미 DB 에 있을 때만** 나온다.

⇒ 9/23 등록이 봉인키를 **심었고**, 그 키가 **같은 PC 에서 안 풀렸다.**
이것이 R-1 이 예측하는 바로 그 모양이다. PM 이 세운 "전달 경로가 끊겼다" 로는 이 팝업 글자를 설명할 수 없다 —
전달만 끊겼다면 DB 에는 멀쩡한 키가 있으니 판정은 `MainPcConfirmed` 여야 하고, 팝업은 **안 떠야** 한다.

## §3 — 경주는 사실이나 2차 원인이다 (P-5)

`BackupPage.razor:158-167` `OnInitializedAsync → LoadAsync` 가 설정·이력·복원이력 3개를 곧바로 부른다.
`<MainPcOnly>` 는 `:17` 에서 **마크업만** 감싼다 — 페이지의 `@code` 는 그 밖이다.
⇒ 메인PC 든 아니든, 출입증이 있든 없든 **이 3콜은 언제나 나간다.** 클라이언트 PC 직원 화면에도 콘솔 403 이 상시로 찍힌다.
(사장님 지시 *"고객은 인증키가 도는지 모르게"* 와 정면으로 어긋난다.)

순서도 확인했다. `MainPcGate` 는 `OnAfterRenderAsync(firstRender)` 에서 시작한다(`:111`) — **첫 렌더 이후**다.
`BackupPage.OnInitializedAsync` 는 **첫 렌더 이전**에 돈다. ⇒ 출입증이 있을 수 없는 시점에 3콜이 나간다.
F12 순서 `mainpc-proof 200 → restore-history 403 → mainpc-verify 200` 가 정확히 이 모양이다.

단 이것만으로는 사장님 증상이 안 난다. 출입증이 한 번이라도 발급됐다면 sessionStorage 에 남아
(`hitpan-mainpc-proof.js:69-80`) 다음 로드부터 `HitPanApiAuthHandler.cs:173-177` 이 **모든 요청에** 싣는다.
⇒ 새로고침 한 번이면 열렸어야 한다. **안 열린다 = 출입증이 아예 없다** = §2.

## §PM. PM 실측 추가 — **R-1 핵심 명제를 동작으로 증명했다** (2026-09-24 · 브라운킴)

### 실험 (🚨 TPM 무접촉 · `KEY_NAME` 무접촉)

임시 키를 **Software KSP 에만** 만들고, 세 가지로 찾아봤다.
키 이름은 `HitPanTest.ProviderMismatch.<랜덤8>` — `HitPan.TaxInvoice.MasterKey` 와 **글자가 겹치지 않는다.**
`SealKey` 는 부르지 않았다.

```
키를 Software KSP 에만 만들었다: HitPanTest.ProviderMismatch.9bb97a26
① Exists(name)            = True     <- UnsealKey:111 이 쓰는 1인자 오버로드
② Exists(name, Software)  = True
③ Exists(name, Platform)  = False    <- SealKey:78 이 쓰는 공급자
임시 키 삭제 완료 · 잔재 Exists(name) = False
```

### 판정

🟢 **①=② ⇒ 1인자 `CngKey.Exists(name)` 는 Software KSP 를 본다** (기본 공급자).
🟢 **③=False ⇒ 공급자별로 키 공간이 완전히 분리된다.** 이름이 같아도 건너편은 못 본다.

⇒ **R-1 확정.** `SealKey`(TpmKeyService.cs:78 `MicrosoftPlatformCryptoProvider`)가 TPM 에 만든 키를
`UnsealKey`(:111 `CngKey.Exists(KEY_NAME)` · :113 `CngKey.Open(KEY_NAME)`)는 **구조적으로 못 찾는다.**
⇒ `Exists` false ⇒ `ProtectedData.Unprotect(LocalMachine)` 로 흘러 **TPM RSA 암호문을 DPAPI 로 풀려다 실패**
⇒ `MainPcProofService` 가 `DifferentPc` 로 흡수 ⇒ **출입증이 애초에 발급되지 않는다.**

⚠️ **방향은 대칭이라 이 실험으로 충분하다** — 분리 자체를 증명했기 때문이다.
⚠️ **여전히 미확인 1건(U-2)**: *이 PC 에서 실제로 그 경로를 탔다*는 실행 로그는 못 봤다.
  API 로그는 이벤트로그에 **안 들어온다**(2일치 전수: `HitPanWatchdog` 31,389건뿐 · `HitPan.API` 0건) ·
  `C:\Program Files\HitPan\api` 는 접근 거부(M-23). ⇒ **PM 권한으로는 못 잰다.**
  🟢 다만 **정황이 적중한다** — 9/24 팝업이 `[이 컴퓨터로 바꾸기]`(=`DifferentPc`)였다.
  봉인키가 DB 에 있는데 같은 PC 에서 안 풀렸다는 뜻이고, "전달만 끊겼다"로는 이 팝업이 설명되지 않는다.
