| Persist Security Info | 시점 | 키 목록(값 출력 안 함) | 비번 포함 | `ResolveDbCredentials` (실제 코드) |
|---|---|---|---|---|
| 없음 (**현행**) | 열기 전 | Server, Port, Database, **User**, Password, … | 🟢 있음 | user **빈 값** · pass 있음(일치) |

| true (대조) | 열기 전 | … + Persist Security Info | 있음 | user 빈 값 · pass 있음 |
| true (대조) | 열기 후 | Server, Port, User ID, **Password**, Database, … | 있음 | user 있음 · pass 있음(일치) |

## §5. 추가 대조 (PM 요청 · 작업지시서 20260911작5 §6 K1) — `-p` 제거 · 비번은 자식 환경변수 `MYSQL_PWD` 로만

인자 = `:335` 에서 `"-p{pass}"` **만** 뺌 · PSI 동일 · 자식 환경에서 `MYSQL_PWD` 를 먼저 지운 뒤 경우별로 넣음 · 대기 한도 15초 · 격리 인스턴스 동일.

| # | 실행파일 | 비번 전달 | 결과 |
|---|---|---|---|
| K1-1 | 설치된 MariaDB 11.4 **`mariadb-dump.exe`** | `MYSQL_PWD` | 🟢 **5.3초 exit 0 · 267,037B** · stderr 경고 1줄 `option --ssl-verify-server-cert is disabled, because of an insecure passwordless login.` |
| K1-2 | PATH 에 먼저 잡히는 `mysqldump.exe` (실제 `ResolveMariadbBinary`, 이 PC 사용자 PATH) = **MySQL 8.4** | `MYSQL_PWD` | 🔴 2.2초 **exit 2** · 1,561B · COLUMN_STATISTICS 실패 — **인증은 통과**(1045 아님) |
| K1-2b | 같음 + `--column-statistics=0` | `MYSQL_PWD` | 🟢 5.3초 exit 0 · 272,801B (인증 통과 분리 확인용) |
| K1-3 | MariaDB 11.4 `mariadb-dump.exe` | **없음** (`-p`·`MYSQL_PWD` 둘 다 없음) | 🟢 **2.2초 exit 2 · 0B · `1045 Access denied`** — **대기 없음** |
| K1-4 | MySQL 8.4 `mysqldump.exe` | **없음** | 🟢 **2.1초 exit 2 · 0B · `1045 Access denied … (using password: NO)`** — **대기 없음** |

판정 재료 (봉합안은 [2] 몫):

- `MYSQL_PWD` 는 **두 클라이언트 모두 인증에 쓰인다**. 비번이 없으면 **멈추지 않고 2초 안에 실패**한다 → 「영원히 멈춤」이 「실패 기록」으로 바뀐다.
- 🔴 단 `MYSQL_PWD` 로 바꾸는 것만으로는 **비번이 빠지는 원인(§2)이 안 고쳐진다**. 빈 비번을 넘기면 K1-3 처럼 1045 로 실패할 뿐 백업은 안 된다. 자격증명을 어디서 읽느냐는 따로 풀어야 한다.
- 🟡 MariaDB 11.4 클라이언트는 명령줄 비번이 없으면 「passwordless」로 보고 **서버 인증서 검증(`ssl-verify-server-cert`)을 끈다**(K1-1 경고). `-p{비번}` 경로(§3 대조군)는 이 경고가 없었다. localhost 한정이라 실해는 낮다고 보이나 **보안상무 판단 사항**. 또 경고가 stderr 로 나오지만 exit 0 이면 코드가 예외를 안 던지므로(`:369`) 흐름에는 영향 없음.
- 🔴 MySQL 8.4 는 비번 전달 방식과 **무관하게** COLUMN_STATISTICS 로 실패 → D2 는 K1 과 **별개 결함**. K1 만 고치면 PATH 에 MySQL 8.4 가 먼저 있는 PC 에서 다음 벽.
- (참고) MySQL 8.4 는 명령줄 비번에 `Using a password on the command line interface can be insecure` 경고를 내고, 실패 시 코드가 stderr 전체를 `error_message` 로 저장한다(§4 대조군 B 이력). 비번 값 자체는 안 들어간다. `MYSQL_PWD` 의 MySQL 쪽 지원 중단 예고 여부는 이번에 문서 확인 안 함(⬜).
