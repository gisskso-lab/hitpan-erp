## §1 P1 — 지금 롤백은 DB 를 되돌리나

**결론 🟢: 안 되돌린다. 사장님 원칙 위반은 지금 코드에 없다.**

| 경로 | 무엇을 되돌리나 | 근거 |
|---|---|---|
| 교체 실패(`TrySwapFilesAsync` false) | 폴더 역복원(web·api) | `UpdateOrchestrator.cs:230-245` · `:448-476` |
| 재시작·검증 실패 → `FinishWithRollbackAsync` | `api.old→api` · `web.old→web` · keepalive 복원 · 재기동 | `:877-928` |

| 워치독 자기교체 실패 | `watchdog.old → watchdog` | `:1292-1311`(PS 스크립트) |

- 🟢 주석 원문 `:873-874` *"DB 자동복원은 하지 않는다(사장님 결재 #3) … DB 를 되돌리면 업데이트 중 들어온 정상 거래가 삭제된다. 백업은 보험으로 존재만 한다."*
- 🟢 `WatchdogBackupRunner.RunPreUpdateBackupAsync` 결과 `backupFile` 의 사용처는 **null 검사(`:177`)와 로그(`:186`) 둘뿐**. 복원 호출 0. 워치독 안에 `mysql.exe` 로 덤프를 흘려 넣는 코드 0(워치독의 `mariadb.exe` 호출은 상태·동의 표 읽기/쓰기뿐 — `WatchdogStatusWriter.cs`·`WatchdogConsentReader.cs`).
- ⬛ `WatchdogBackupRunner.cs:20` 주석 「산출 .sql 파일 경로를 반환해 **롤백(고리4)이 쓴다**」 는 **낡은 주석**이다(실제로 안 쓴다). 설계가 이 주석을 근거로 삼으면 틀린다.
- 🟢 DB 복원 경로는 제품에 **하나뿐** = 사용자가 누르는 백업 복구(`BackupController.cs:69` → `BackupService.RestoreAsync:300`). 사장님 말씀 「백업데이터복구」 그것이다.

🔴 **설계가 반드시 알 것 — 「옛 프로그램 + 새 DB」는 이미 일어나는 일이다**
- 새 API 는 기동하면서 `app.Run()`(`Program.cs:700`) **앞에서** 마이그를 적용한다(`Program.cs:460-469`). 워치독 검증(`/health`+FileVersion)은 그 **뒤**다.
- ⇒ 검증 실패로 `rolled_back` 되면 **새 스키마·새 마이그의 데이터 변경은 남은 채** 옛 프로그램이 돈다. PC 안 롤백도 같은 모양이다 — 새 위험이 아니라 **기존 위험의 반복**이다. 그래서 P2 호환성이 곧 롤백의 성립 조건이다.

⚠️ **곁 발견(이 트랙 밖 · 기록만)**: `pre-update-backup\*.sql` 과 `staging\hitpan-{V}.zip` 은 **지우는 코드가 없다**(워치독 `AutoUpdate` 안 삭제 호출 6곳 전수 — 어느 것도 이 둘이 아님). 업데이트마다 덤프 1개 + zip 1개가 SYSTEM 프로필 아래 쌓인다. 9/29 C: 디스크 부족 사건과 같은 축 ⚠️(원인이었다고 단정 안 함).

## §4 P4 — 누가 롤백을 시작하나 · 후보별 제약

공통 전제(🟢 코드): 프로그램 교체는 「keepalive DISABLE → 프로세스 종료 → 폴더 이동 → keepalive ENABLE → 재기동」이다(`UpdateProcessGate` · `:894-918`). API·Web·keepalive 는 **SYSTEM · HIGHEST 예약작업**(`HitPan-Universal.iss:2888·:2915-2917·:2930-2932`). 즉 **워치독 밖 주체도 결국 이 다섯 동작을 해야 한다.**

🔴 **공통 함정 — 워치독을 같이 안 되돌리면 막다른 길**
- 워치독의 「설치 버전」 = **워치독 자기 어셈블리 버전**(`Worker.cs:979` `VersionInfo.Current` · `:153-158`).
- api·web 만 1.3.48 로 되돌리면: 옛 ERP 는 「새 버전 있음」 팝업을 띄운다 → [예] → 워치독은 `IsAboveInstalled`(`Worker.cs:165-178·:767`) 에서 「설치본보다 높지 않음」으로 **무시**. 사이드바 안내가 영영 안 풀린다.
- ⇒ 되돌릴 단위 = **api·web·watchdog 셋**. 워치독 교체 = 서비스 정지·시작 = #29 목록의 「Windows 서비스」.

## §6 P6 — 헌법 #43 원문과 부딪히나

원문(`docs/헌법/헌법원문_1-43.md:422-430·:449-452`):
```
Major 발견 → local_update_status 적재 → ERP 로그인 시 Y/N 팝업
  [예]     → 즉시 적용 (백업 → 교체 → 재기동 → 검증 → 실패 시 롤백)
  [나중에] → 적용 안 함. 다음 로그인에 다시 물어본다
이 흐름 하나뿐이다.
예외가 필요하면 — 사장님 결재 후 워크플로 파일 자체를 고친다.
```

- 🔴 **롤백은 원문에 「[예] 안의 자동 단계」로만 있다.** 사람이 따로 시작하는 롤백은 원문에 없다 ⇒ 어떤 모양이든 「이 흐름 하나뿐」에 **흐름을 하나 더한다** = 사장님 결재 사항(PM·설계 권한 밖).
- 금지 표 #1~#4 는 「팝업을 건너뛰는 **배포**」·「동의 소비 로직 우회」다. PC 안 롤백은 새 판 배포가 아니므로 #1 글자에는 안 걸린다 ⚠️해석. 그러나 **동의 소비가 고장 난 상황에서 그것을 비켜 가는 길**이라 #3 「동의 소비 로직을 우회」의 취지와 겹친다 ⚠️해석.
- 🔴 **되돌린 뒤의 흐름**: 원문대로면 옛 판에서도 N+1 은 「다음 로그인에 다시 물어본다」. 고장 난 워치독을 같이 되돌리면(§4 공통 함정) 옛 워치독이 N+1 을 다시 받아 **같은 고장 판을 다시 깔 수 있다.** 되돌린 판을 다시 묻지 않게 하려면 흐름을 바꿔야 한다 = #43 저촉. ⇒ 실무상 **되돌림 판 R(더 높은 번호) 게시와 짝**이어야 원문 흐름 안에 머문다(오더 기록 §3).
- 결론: 「롤백도 Y/N 을 거쳐야 하나」는 **원문이 답하지 않는다** → 사장님 유권해석(§8 K-1).
