## §2 내려오는 쪽 — 답장은 🟢 / **선발신은 🔴 길이 없다**

| 축 | 실측 |
|---|---|
| 답장 Pull | `CsOutboxSenderWorker.cs:292` `POST /api/backoffice/cs/replies/pull` · 주기 **5분**(`:36`) · 백오피스 `CsInboundController.cs:146` 이 받는다 🟢 |
| 답장 저장 | 워커 `:316~322` `INSERT IGNORE INTO cs_replies … SELECT … FROM cs_requests r WHERE r.cs_request_id = @CsRequestId` 🟢 |
| 🔴 **원본 없는 건** | **같은 줄.** `cs_requests` 에 그 `cs_request_id` 가 없으면 `SELECT` 가 **0행** ⇒ `INSERT` **0줄**. 예외도 경고도 없다 — **조용히 사라진다** |
| 🔴 **선발신이 내려오나** | **안 내려온다.** Pull 응답 계약은 `{"replies":[…]}` 하나뿐(워커 `:386` `PullResponse`). 백오피스 Pull 은 `bo_cs_replies` 만 읽는다(`CsInboundController.cs:161`) — `bo_cs_outbound` 를 **안 본다** |
| 🔴 **전달 표식** | `bo_cs_outbound.delivered_at` 을 채우는 코드가 **레포 전체에 0곳**(작2 가 칸만 만들었다) |

⇒ **작2 가 쌓는 선발신 쪽지는 지금 「전달 대기」에 영원히 머문다.** 화면이 그렇게 정직하게 말하도록 만들어 둔 상태다.

## §3 ERP 쪽 「본사 선발신이 앉을 자리」 — 🔴 **없다** (실측)

| 확인 | 실측 |
|---|---|
| `cs_requests` 에 **방향·출처 칸** | **없다** — `DB-139_cs_requests.sql:23~38` 전수. 칸은 `cs_request_id`·`tenant_id`·`created_by`·`category`·`sub_tag`·`body`·`screen_code`·`erp_version`·`status`·`created_at` 뿐 |
| `cs_replies` 가 홀로 설 수 있나 | **못 선다** — 워커 저장문이 `FROM cs_requests r` 로 **원본을 요구**한다(§2) |
| 쪽지함 화면이 무엇을 읽나 | `CsInboxPage.razor:133` `GET api/cs/requests/{RequestId}/replies` ⇒ **원본 쪽지 1건에 매달린 화면**이다. 원본이 없으면 **열 길이 없다** |
| 목록 화면 | `CsRequestController.cs:178` 이 `cs_requests LEFT JOIN cs_outbox` 로 그린다 ⇒ 목록도 **`cs_requests` 기준** |

⇒ 🔴 **본사 선발신을 보여주려면 `cs_requests` 에 「본사발신」 행이 서야 한다.** 그래야 기존 목록·쪽지함이 **화면 변경 없이** 그대로 보여준다(#20 흐름 불단절).
⇒ 🔴 그리고 **고객이 「내가 쓰지 않은 쪽지」를 보게 된다** ⇒ 구분 표식이 없으면 혼란이다(「처음 보는 사람이 혼자 쓸 수 있냐」 기준).

### §3-1 에코(되돌아감) 위험 — 실측으로 **없다**
`cs_outbox` 에 넣는 코드는 `CsRequestController.cs:141` **한 곳뿐**이다(전수 grep).
워커가 `cs_requests` 에 직접 넣으면 **큐에 들어가지 않는다** ⇒ 본사 선발신이 본사로 되돌아가는 고리는 **안 생긴다.**

## §7 [2] 설계가 답해야 할 것 (이 문서는 답하지 않는다)

1. 본사 선발신을 ERP 의 **어느 표에** 앉히나 — `cs_requests` 에 「본사발신」 행이냐, 새 표냐
2. 「내가 쓰지 않은 쪽지」를 화면이 **어떻게 구분해 보여주나** (출처 칸이 필요한가 · 추가형 마이그 DB-NN)
3. Pull 응답 계약을 **어떻게 넓히나** — 기존 `replies` 를 깨지 않고 `outbound` 를 더하는 모양
4. `delivered_at` 을 **누가 언제** 채우나 — Pull 이 내려준 순간이냐, ERP 가 저장 후 **ack** 를 보내는 순간이냐
   🔴 앞쪽이면 「보냈다」의 축소판이다(ERP 가 저장했는지 모른다)
5. **실패·재시도** — 못 나간 선발신이 조용히 사라지지 않는 구조(#20)
6. 멱등 — `bo_cs_outbound.outbound_id`(varchar 36) 를 ERP 가 **열쇠로 그대로 쓸 수 있나**(양쪽 칸 폭 동일 · 실측)
7. 오더 1·2 의 **「최종」 판정 기준** — 무엇을 재면 닫힌 것으로 보나
