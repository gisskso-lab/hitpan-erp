## §3 재설계에 줄 조건

1. **`saveDoc` 성공 확인 필수**: 저장 뒤 성공 알림 「저장 완료: {전표번호}」(또는 응답 전표 번호)를 읽어 번호를 남긴다. 오류 알림 0 ≠ 성공. 견적 양성 대조 칸에도 같은 판정을 걸어 다시 증명.
2. **저장 길의 확인 창 처리**: 거래명세서 새 전표 = 「수주서 자동 생성」 창의 「저장」(창 안 `.mud-dialog` 범위)을 눌러야 한다. 창 문구 · 단추 글자는 `DeliveryPage.razor:624~628` 원문 대조를 자체시험에 넣는다(글자 아닌 동작 확인).
3. **판매 반품 차림 = 확정까지**: [반품하기]는 `confirmed` 일 때만 켜진다(`DeliveryPage.razor:109`). 장치에는 거래명세서 확정(전송) 단계가 없다(grep 0) → 저장만 고쳐도 판매 반품 26칸은 「[반품하기] 꺼짐」 으로 다시 실패한다. 확정 단계 + 확인 창 처리를 넣는다.
4. **확정 = 재고 필요**: 확정은 재고 부족이면 막히고 자동발주 안내로 간다(`:736~754`). 장치 종류 순서는 거래명세서(2번째)가 매입처리(5번째)보다 먼저 → 표지 품목 재고 0 일 가능성. 차림에서 재고를 먼저 넣거나 순서를 바꾸고, 재고 확보를 값으로 확인한다.
5. **수주 자동 생성 부작용**: 거래명세서 저장은 표지 거래처 수주서를 하나 더 만든다(`:650~653`). 수주서 입구 고르개가 `rows => rows` 첫 줄이므로(`capture.js:119`) 자동 생성 수주를 집을 수 있다 → 수주서 입구는 장치가 만든 전표 번호로 고른다.
6. 날짜 고르개(F9-1)는 실물 화면 조각으로 시험(CTO §4 ⑵ 유지).
