## §4 🔴 ③ 고객사 쪽지 보내기 — 백오피스만 고치면 **조용히 사라진다**

### §4-1 ERP 가 받는 유일한 길

`POST api/backoffice/cs/replies/pull` 이 돌려주는 것(`CsInboundController.cs:154`):
`reply_id` · **`client_ticket_uid AS csRequestId`** · `body` · `replied_by_kind` · `approved_at`

### §4-2 🔴 ERP 수신부가 **원본 티켓이 없으면 버린다**

`CsOutboxSenderWorker.cs:316`:
```
INSERT IGNORE INTO cs_replies (reply_id, tenant_id, cs_request_id, …)
  SELECT @ReplyId, r.tenant_id, r.cs_request_id, …
    FROM cs_requests r WHERE r.cs_request_id = @CsRequestId;
UPDATE cs_requests SET status='답변도착' WHERE cs_request_id = @CsRequestId AND status <> '종결';
```

ERP 에 그 `cs_request` 행이 **없으면** `SELECT` 가 0행 ⇒ **INSERT 0건 · UPDATE 0건.**
본사가 **먼저** 보내는 쪽지는 ERP 가 만든 원본이 없으므로 **받을 자리가 없다.**
🔴 그런데 로그는 `[CS수신] 답 N건 수신` 만 찍는다 — **버려진 건수를 세지 않는다.** 화면에도 흔적이 없다.
⇒ 이 축을 모르고 보내기를 붙이면 **「보냈습니다」라고 말하는데 고객사는 못 받는다**(「고쳤다 ≠ 갔다」 8차 재발이 된다).

### §4-3 🟢 사장님 결재 (2026-10-11) — **전달 대기 큐 + 상태 표시**

ERP 수신 자리는 **다음 작업(ERP CS 파이프라인)** 이다. 그 사이:
- 쪽지는 **백오피스에 저장되고 「전달 대기 — ERP 수신 준비 중」으로 보인다**
- ERP 통로가 열리는 순간 쌓인 것이 **자동으로 나간다**(흐름을 끊지 않는다 · #20)
- 🔴 **화면이 「보냄」이라고 거짓말하지 않는다**

## §7 🔴 오더 추가 (사장님 2026-10-11 · 선행검증 보고 직후)

### §7-1 ① 요금제 — **등록 + 「요금제 제외」 버튼**
> *"그럼 요금제 넣고, 요금제 제외 버튼을 추가로 넣을것. 이유 = 베타버젼 테스트시 필요, 그리고 대리점은 히트판 구독요금 면제정책을 쓸 예정."*

**실측 — 「제외」의 재료가 이미 반쯤 있다**

| # | 사실 | 자리 |
|---|---|---|
| 1 | `POST plans/{planId}/toggle-active` 가 **API 에는 있다** | `PricingAdminController.cs:179` |
| 2 | `pricing_plans` 에 `is_visible` 칸이 있고 `PUT` 이 그 칸을 쓴다 | `:124` |
| 3 | 그런데 **화면에는 그 버튼이 없다** — 사람이 쓸 길이 0 | `AdminPricing.razor` 전수 |

⇒ 「제외」는 **행을 지우는 것이 아니라 과금·노출에서 빼는 것**으로 설계한다(이력·감사 보존).
🔴 **대리점 구독요금 면제정책은 다른 축이다** — 그건 요금제(상품)가 아니라 **고객사·대리점 속성**이다.
요금제 제외만으로는 면제가 안 된다. **별건 트랙으로 분리**하고 이 작업에 섞지 않는다(범위 확장 금지).

### §7-2 ③ 쪽지 — **관리대상 데이터 · 폐기기한 · 임의삭제 · 본사 선발신 필수**
> *"고객사에게 주고받은 쪽지는 관리대상임. 받고 저장해야 할 데이터 필수. 그리고 관리후 폐기기한설정 혹은 임의 삭제도 되야 함. 또한 프로모션, 이벤트, 혹은 구독요금 미결재 이슈로 인해 고객사에게 백오피스가 먼저 쪽지를 보낼 기능도 필수."*

**실측 — 보관은 이미 되고 있다. 없는 것은 「보낼 길」과 「지울 길」이다.**

| 축 | 지금 | 판정 |
|---|---|---|
| 받고 저장 | `bo_cs_tickets`(쪽지) · `bo_cs_replies`(답) · `bo_cs_ticket_logs`(전이 이력) | 🟢 **이미 보관된다** |
| 본사 선발신 | 🔴 **없다** — `reply` 는 기존 티켓에 매달린다 · ERP 수신부는 원본 없는 답을 버린다(§4) | 🔴 신설 |
| 폐기기한 설정 | 🔴 **레포 전체에 보관기한·retention 코드 0건** | 🔴 신설 |
| 임의 삭제 | 🔴 CS 쪽지 삭제 엔드포인트 **0개** | 🔴 신설 |

🔴 **설계가 조심할 것**
1. **삭제는 흔적을 남긴다** — 무엇을 언제 누가 지웠는지(건수·사유)는 `bo_audit_log` 에 남긴다. 몸통은 지워도 **지웠다는 사실은 안 지운다.**
2. **자동 폐기는 기본 꺼짐** — 기한이 지난 것을 **「폐기 후보」로 보여주고 사람이 확정**한다(히트판 반자동 원칙 · 100% 자동화 없음). 기한이 지나자마자 말없이 지우면 **고객 분쟁의 증거가 사라진다.**
3. **폐기기한 기본값은 사장님 결재 사항**(법무 축 — 개인정보 보관기간). 제안: **기본 무기한 + 설정값 입력** · 자동삭제 0.
4. 선발신 쪽지도 **같은 표에 쌓인다** — 보관·삭제·기한 축이 쪽지 1벌로 끝나야 관리가 갈라지지 않는다.
