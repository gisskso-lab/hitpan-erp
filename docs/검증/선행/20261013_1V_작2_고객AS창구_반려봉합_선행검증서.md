## 0. 사장님 반려 사유 (원문 그대로 보존)

> 2번 반려사유.
> 1) 고객사 쪽지발송으로 들어온 인바운드 cs는 자동등록, 상태표시 또한 처리상태에 따라 변경되야 함. 그리고 해당쪽지로 어떤 대화를 했고, CS건을 처리 했는지 과정또한 쉽게 볼 수 있어야 함.
> 2) 쪽지로 받은 CS인데 처리상태, 분류, 응대유형?? 상태, 분류, 고객평가. 세가지 볼 수 있게 하고. 응대유형은 "히트판a/s센터"로 고정
> 3) 수기로 작성한 +as접수 처리기록만 응대유형을 받을수 있도록 함. 수기기록은 또한 상태기록만 하고, 처리상태를 고객사에게 보여주지 않음으로, 접수와 완료만 기록한다!!
> 4) 무엇보다 중요한 AS목록칸에 상태변경이 잘 안됨. 이건 점검요망.

## 2. 🔴 가장 중요한 발견 — 반려 4건이 **2개 뿌리**로 모인다

```
 뿌리 ①  완료 전이가 응대유형에 묶여 있다
          └ 4) 상태변경이 안 된다          ← 증상
          └ 1) 상태표시가 안 바뀐다        ← 같은 증상의 다른 얼굴
          └ 2) 응대유형을 「고정」하라      ← 사장님이 내신 해법

 뿌리 ②  쌓아만 두고 안 보여준 것이 둘
          └ 1) 처리 과정 (bo_cs_ticket_logs — 쓰기 5곳 · 읽기 0곳)
          └ 2) 고객평가 (rating — 상세 SELECT 가 안 읽는다)
```

사장님 2)의 「응대유형 고정」은 **디자인 주문이 아니라 뿌리 ①의 해법**이다. 고정하면 4)가 같이 풀린다.

## 3. V-1 🔴 4) 「상태변경이 잘 안 됨」 — 범인 2개

### 범인 ① 서버가 완료를 거부한다 🟢 파일확인

`src/HitPan.Backoffice.API/Controllers/CsAdminController.cs:264-271`

```
if (to == "완료")
{
    var via = SELECT handled_via FROM bo_cs_tickets WHERE id = @Id;
    if (string.IsNullOrEmpty(via))
        return BadRequest("어떻게 응대했는지(쪽지·전화·원격지원) 먼저 골라 주세요");
}
```

그리고 **쪽지로 들어온 건은 `handled_via` 가 처음부터 NULL** 이다 — 🟢 `CsInboundController.cs:112-125` 의 INSERT 칸 목록에 `handled_via` 가 **없다**:

```
INSERT INTO bo_cs_tickets
    (tenant_id, reseller_id, client_ticket_uid, received_channel,
     category, sub_tag, shape_tag, body, status, screen_code, erp_version, auto_class, received_at)
```

⇒ **쪽지 CS 는 응대유형을 먼저 따로 저장하지 않으면 「완료」로 못 간다.** 화면에는 노란 글귀가 뜬다.

🔴 이 거부는 **의도된 것**이었다(실적 소급 불가 방지). 그러나 **쪽지 건에까지 사람 손을 요구한 것**이 틀렸다 — 쪽지 건의 응대 창구는 처음부터 정해져 있다. 사장님 2)가 그 지점을 짚었다.

### 범인 ② 상태 바꾸는 손이 접힌 칸 안에 있다 🟢 파일확인

`Components/CsTicketDetailPanel.razor:92` — 상태 콤보(`:95-102`)와 「상태 변경」 단추(`:103-104`)가
**`<MudExpansionPanel Text="처리 (상태·분류·담당·약속·응대·등재·폐기)">` 안**에 있고 **기본 접힘**이다.

목록의 상태 칸(`AdminCsListPage.razor:110-123`)은 **읽기 전용 `<span>`** 이다 — 누를 것이 없다.

🔴 **재구성 전 판과 대조했다** — `git show 642e3f4c~1` 의 같은 파일 `:312-320` 에 상태 콤보+단추가 있고
**접힘 패널이 아니었다.** ⇒ **접어서 숨긴 것은 작1(내 작업)이다.** 기능을 버린 건 아니지만 손이 멀어졌다.
작1 설계 §3 의 「10번 중 9번은 읽고 답한다」는 전제가 **상태 변경에는 맞지 않았다.**

## 5. V-3 2) 쪽지 CS 에 상태·분류·고객평가

| 칸 | 목록 | 상세 |
|---|---|---|
| 상태 | 🟢 있다 (`:112`) | 🟢 있다 |
| 분류 | 🟢 있다 (`:97-102` · 8종 + 7모양 보조) | 🟢 있다 |
| **고객평가** | 🟢 값 있을 때만 ★ (`:119-122`) | 🔴 **영영 안 보인다** |

클라이언트 모델 `CsTicketDetail : CsTicketRow` 에는 `Rating`·`RatedAt`·`ReadAt` 칸이 **있지만**
(`AdminCsListPage.razor:521-523`) 서버가 안 보내므로 **늘 null** 이다.

귀결 두 개:
1. 상세에서 **고객평가 ★ 가 영영 안 뜬다**
2. 상세의 「안 읽음」 판정도 null 이라 **늘 안 읽음으로 보인다**

🔴 이 칸은 **작1 [4] 작업리뷰서에 내가 「미봉합」으로 적어 두고 손대지 않은 그 칸**이다
([작업리뷰서](../백오피스/20261013_작업리뷰서_작1_고객지원센터_프론트재구성.md)). 사장님이 바로 그 자리를 짚었다.

🟢 **칸은 전부 이미 있다** — `42_backoffice_cs_stages.sql:22-32` 이 `read_at`·`read_by`·`handled_via`·`rating`·`rated_at`·`rating_comment` 를 다 더해 놓았다. ⇒ **DDL 0건.**
