| 칸 | 표 | 읽는 곳 | **쓰는 곳** | 판정 |

🔴 **그래서 화면이 거짓을 말한다.** `src/HitPan.Backoffice/Components/Pages/Platform/AdminTenantsV2.razor:79-93` 의 「설치」 칸은 **`IsLocked == 1` 하나로** 체크/대기를 가른다. 그 칸을 1 로 만드는 코드가 백오피스에 없으므로 **설치가 100% 성공해도 전 고객이 영구 「ERP 설치 미완료」** 로 보인다. 상세 화면(`AdminTenantDetailV2.razor:86`)도 같은 모양.

🔴 **왜 그런가 — 판이 둘이기 때문이다.** 같은 이름의 두 칸이 **다른 엔진의 다른 표**에 있다: ERP 는 자기 로컬 `local_company`(MariaDB)에 `is_locked_from_landing=1` + `bootstrap_at` 을 적는다(`src/HitPan.API/Services/CompanyBootstrapProvisioner.cs:84`·`:101-102`). 🔴 **그 값을 백오피스 `tenants` 로 옮기는 경로는 0건**이다. 이름이 같아서 「이미 올라온다」고 읽히는 자리다.

### 3-3. ERP 5분 메타(직원·기기·버전·헬스) vs 설치 실적 — **다른 표다**

| 축 | 어디로 | 받는 자리 | 표기 |
|---|---|---|---|
| CS 쪽지 | ERP → `api/backoffice/cs/*` | 🟢 있다 | `bo_cs_*` |
| 업데이트 이력 | 워치독 → `api/telemetry/update-history` | 🟢 있다(`TelemetryController.cs:65`) | `tenant_update_*` |
| 대표 아이디(S-2) | ERP → `api/telemetry/owner-report` | 🟢 있다(`:209`) | `tenants.owner_account_id` |
| 🔴 **메타 ping(직원 수·기기 수·헬스)** | 워치독 → **`https://back.hitpan.kr/watchdog/ping`** · `/watchdog/emergency` (`src/HitPan.Watchdog/WatchdogOptions.cs:12-13`) | 🔴 **받는 라우트 0건** — 백오피스에 그 경로 **선언이 없다**(grep: `TelemetryController.cs:20` 주석이 *"→ 400"* 이라고 자기 입으로 적어 뒀다) | 🔴 **설치 실적도 생존 신호도 이 길로는 안 온다** |

⇒ **설치 실적 ≠ 5분 메타.** 5분 메타는 **도착하지도 않는다**(400). 집계를 「메타에서 센다」로 설계하면 전제가 틀린다.

### 3-4. #18·#22 선 — 집계에 섞일 수 있는 칸

🟢 **지금 집계 재료에 업무 데이터는 없다** — 후보 칸 전부 설치·시리얼·시각·상태값이고, 거래처·금액·재고 칸은 0개(§3-2 표 전수). 🟢 수신부에 금지필드 게이트가 2중으로 선다(`CsInboundController.cs:27` 주석 · `TelemetryController.cs:93`·`:200 ContainsForbiddenContent`).
🔴 **단 선에 닿는 칸 2개를 표시해 둔다**: `serial_verify_attempts.client_ip` · `serial_verified_fingerprint`(기기 지문). 「설치 실적」 집계 화면에 이 둘을 올리면 **본사가 고객 PC 식별자를 상시 보유**하게 된다 ⇒ #22(*"본사가 안 가지면 털릴 일 없다"*) 유권해석 거리. **집계는 건수·시각까지**로 묶는 것을 권고하고, 판단은 사장님 몫이다(결-8 「생존 칸 3개」와 같은 축).

### 3-5. 🔴 판정 — 조회냐 신설이냐

**신설이다.** 근거 셋: ⓐ 집계(COUNT) API 가 `tenants`/설치 축에 **0건**(BO 컨트롤러 전수 grep — 나오는 COUNT 는 `status`·기기·가입 중복 검사뿐) ⓑ 화면 판정축 `is_locked_from_landing` 에 **쓰는 코드 0곳** ⓒ 유일하게 쌓이는 `serial_verify_attempts` 는 **시도 로그**라 「설치 몇 대 성공」으로 바로 못 읽는다.
⇒ **B2⑤ 의 작업량 성격이 바뀐다**: 「PM 이 DB 를 한 번 조회한다」(§6-10) 가 아니라 **①설치 성공을 적는 자리 확정 + ②쓰는 코드 1곳 + ③집계 조회 1개 + ④화면 축 교정**. ⬜ **그리고 운영에 지금 몇 건 있는지는 못 쟀다**(#39 · 조회는 PM·사장님 승인 축).
