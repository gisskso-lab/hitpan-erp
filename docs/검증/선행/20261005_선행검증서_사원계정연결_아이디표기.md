**[2] 가 먼저 정할 것 (C-1~C-6)**
- C-1 **퇴사 판별식** — `is_active=0 OR is_resigned=1` 로 볼지. MDB 이관 퇴사자(is_active=1·is_resigned=1)를 B 가 막아야 하고, 목록 「재직」 표시도 같이 어긋나 있다(P6 · 목록 필터 변경은 범위 판단 필요).
- C-2 **상태 판정 SQL 의 집** — 목록 `HasUserAccount` 를 바꿀지 새 칸을 더할지. 지금 0 = 「없음+사용중지+지운 계정」 섞임. 바꾸면 이 칸을 읽는 다른 화면(⚪전수 안 함)이 영향.
- C-3 **연결 경로의 잠금** — 「기존 사원 고르기」 시 그 사원 행을 `FOR UPDATE` 로 잡고 `user_id IS NULL` 재확인(두 창 동시 연결 경쟁). `user_id` UNIQUE 를 걸면 출하 DDL·마이그(추가형) 둘 다 + 중복 선검사.
- C-4 **user_id 가 남은 채 지워진 계정**(옛 Deactivate · 옛 퇴사) 을 미등록으로 볼지 — 「만들기」 때 user_id 를 덮어쓸지, 먼저 끊을지.
- C-5 **버튼 노출 기준** — 사원관리 [계정 만들기]·[직원계정으로] 를 `account_type=tenant_admin` 에게만(P8·P10).
- C-6 **대표 사원 이메일 칸 오염** — 부트스트랩의 `Email = loginId` 를 이번 판에서 끊을지(앞으로) · 기존 행은 건드리지 않음(#1) 이 기본. 그리고 [2] 의 「아이디」 전환 대상 목록에 §3 을 그대로 쓸 것.

**사장님께 되물을 것 (전제가 깨진 것만)**
- Q-1 (P10) 사원관리(그룹웨어)와 직원 계정 관리(설정관리)는 **다른 대메뉴**입니다. C 「직원계정 화면으로 보내는 버튼」은 대표에게만 보이게 해도 되나요? (인사 담당 직원은 설정관리 메뉴가 안 보여 그 화면으로 못 갑니다.)
- Q-2 (P12) 「사원 이메일로 메일이 간다」는 **급여명세서 메일은 이미 그렇게 돕니다**. 그런데 대표님 사원 행의 이메일 칸에는 설치 때 **로그인 아이디가 들어가 있습니다**. 이번 판에서 앞으로 새로 설치하는 회사는 비워 두게 할까요? (기존 회사는 사원관리에서 직접 고치시면 됩니다.)
