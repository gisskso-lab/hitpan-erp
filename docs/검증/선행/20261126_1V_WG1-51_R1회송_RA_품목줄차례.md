## 5. 옛 전표 차례 되살림

- **새 ERP 에서 넣은 전표: 되살릴 정보 없음** — 시각 열 0 · 자동 증가 0 · 주키 GUID v4(시간 정보 없음) · 고쳐 저장은 지우고 새 GUID 로 다시 넣음. 줄 차례는 어디에도 남지 않음.
- 부분 예외(⚠️ 실측 전 가설): ① 이관 줄 — 거래명세서 · 매입처리 줄 `source_id` = `{원본키}-{순번:D3}`(MdbMigrationService :5375 · :5436) → 옛 레거시 줄 순번이 글자에 남아 있어 이관분은 되살릴 수 있을 수 있음(어느 표에 붙는지 다음 [1-V] 에서 확인) ② 견적에서 변환한 수주 — 견적 `sort_order` 를 item_id 로 맞대면 일부 추정 가능(같은 품목 두 줄이면 못 가름).
- 결론: 옛 전표는 `line_no` 0 으로 두고 「0 이면 주키 순(지금과 같음)」 이 현실적. 되살림은 이관분만 따로 판단.
