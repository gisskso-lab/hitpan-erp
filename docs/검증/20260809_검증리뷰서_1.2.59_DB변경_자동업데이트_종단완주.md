### 원인 — 닭과 달걀 (PM 오판)

오늘 이 게이트를 *"차단 → 경고 후 통과"* 로 고쳤는데,
그 코드는 **1.2.59 안**에 있고 고객 PC 에서 도는 건 **1.2.57** 이었다.

> **새 규칙을 받으려면 옛 규칙을 통과해야 하는데,
> 옛 규칙이 막는 이유가 바로 그 새 규칙이 풀려던 것이다.**

⇒ 상세: [병렬이슈 09](20260809_병렬이슈09_고리5_자기부트스트랩_불가_P0.md)

### 🟢 다만 안전장치는 설계대로 작동했다

| 단계 | 동작 |
|---|---|
| 백업 | ✅ 교체 전 705KB 확보 |
| 차단 | ✅ 위험 감지 → **교체하지 않음** |
| 복원 | ✅ **39초** 만에 ERP 복귀 |
| 기록 | ✅ `blocked` |
| 데이터 | ✅ **손상 0** |

**차단이 없었다면** DB-85 컬럼 없이 새 코드가 깔려 회사정보 화면이 500 이었다.
502 로 보였던 39초는 **정상적인 교체 구간**이었다.

### 응급 조치 — 게이트를 한 번만 열었다

게이트는 `schema_migrations` 에 해당 마이그가 **있으면 통과**시킨다.
⇒ DB-85 를 먼저 적용해 옛 워치독이 "신규 없음" 으로 보게 했다.

```sql
ALTER TABLE local_company
  ADD COLUMN IF NOT EXISTS address_detail VARCHAR(200) NULL DEFAULT NULL,
  ADD COLUMN IF NOT EXISTS seal_url VARCHAR(200) NULL DEFAULT NULL,
  ADD COLUMN IF NOT EXISTS header_url VARCHAR(200) NULL DEFAULT NULL;
INSERT IGNORE INTO schema_migrations (migration_id, app_version, success)
VALUES ('DB-85','manual-gate-open',1);
```

새 코드의 고리5 는 **이미 적용된 것을 건너뛰므로**(멱등) 충돌하지 않았다.
실제로 최종 이력은 **56건 — 중복 0**.
