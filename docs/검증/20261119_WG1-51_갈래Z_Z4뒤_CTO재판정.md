## 3. 근본 진단 — 왜 세 번 연속 장치에서 멈췄나
1. **CI 런이 유일한 통합 시험이다.** 이 PC 는 실물 정식설치 PC 라 화면 차림 · 판독 입구를 로컬에서 돌릴 수 없다(명세서 §4 ⑶). 그래서 상한이 걸린 측정 런이 매번 「처음 지나는 길」의 통합 시험 노릇을 했다. 런마다 한 겹씩 더 들어갔지만(403 → 500 → 판독기) 남은 겹이 몇 개인지는 아무도 모른다.
2. **자체시험이 실제 길을 안 지났다.** 함수를 직접 불러 통과했고, 워크플로가 실제로 부르는 입구(`read` 명령 → 파일 쓰기)는 안 지났다. 게이트가 글자만 보고 동작은 안 본 것이다.
3. **런 전체를 0으로 만드는 길은 하나뿐이다.** 양성 대조(견적 기본 폼 「품명」 · 「공급가액」 · K2 양식지 그림 해시 + 칸 5)가 실패하면 「그 런 전체 미측정」이다. R-3(13칸) · R-4(39칸)는 그 칸만 차림 불가로 남고 런은 산다.
4. **양성 대조 길에는 아직 한 번도 안 지난 겹이 넷 남아 있다.** ⓐ 사실 JSON 직렬화(R-1) ⓑ 제품 PDF 글꼴에서 한글 낱말 뽑기 ⓒ 양식지 그림 해시 · 칸 뽑기 ⓓ 판정기가 실물 사실 JSON 을 처음 읽는 일. R-1 만 고치고 쏘면 ⓑⓒⓓ 중 하나에서 **또 0칸**이 날 수 있다. 이것이 다음 런의 진짜 위험이다.
