## ① P1-1 — 막을 자리

### 사실(입력 문서 기준)
- 사슬([4] ① 코드 확인 · 실행 0): 옮기기 대상에 칸 조건 없음(`FormTemplateService.cs:704` · `:725`) → 사본 = plain + 찍기 1 + 칸을 그대로 옮김(`:970~990`) → 원본이 실효 기본이면 사본이 명시 기본이 됨(`:957~964` · `:996` · 재사용 `:1003~1010`) → 렌더가 기본을 고름(`PdfRenderService.cs:3986`) → K3 참(`:2980~2986`) → 빈 본문 · 머리글 0 · 쪽번호 0. 고객 손 0(기동 뒤 배경 단계).
- 데이터를 지우는 마지막 고리 = §59. F-1 만 있으면 사본 = 그림 + 데이터([4] ①).
- §10 #1: Y 는 「칸 맞춘 뒤」 Y/N → 순백 목록에 1개 추가(흰 종이에 양식 + 데이터). §10 #2: 「함께 인쇄」 없앰 · 「Y 템플릿으로 대신」 · 양식지 = 늘 데이터만 · 기존 값 옮기기 = 설계 확인 필요.
- §56: F-1 CTO 판정 (나) — 「옮기기가 (원본 찍기 값을) 내림」.
- §59: 빈 A4 + 그림 + 칸 0 = 그림만 + 안내. 질문은 「고객이 그림을 올리고 칸을 안 맞춘」 경우였고, 옮기기가 만든 경우는 질문에 없었음([3-V]).

### 핵심 해석
「함께 인쇄 켬 + 칸 0 양식지」 고객 무리에서 대표 답 둘(§10 「Y 로 대신」 · §59 「칸 0 Y = 그림만」)이 부딪힌다. Y 로 옮기면 §59 가 데이터를 지우고, 안 옮기면 그림이 빠진다. 서열은 #20(흐름은 절대 안 끊김 · 끊기면 P0)이 위다. 그래서 데이터를 지키고 그림을 잃는 쪽이 헌법이 내는 답이다. 이 무리가 업데이트 전에 받던 종이는 R6 의 「기본 양식 위에 그림이 겹쳐 찍힘」 이고, 대표가 §59 에서 버린 모양이다. 그 모양을 지킬 의무도 없다.

### (가) 채택 조건 — 불변식 3(시험으로 확인)
- **I1** 옮기기가 만들거나 다시 쓴 사본은, 기본이 되는 순간에 K3 참이 될 수 없다.
- **I2** 칸 0 양식지가 실효 기본인 회사는 옮기기 뒤에도 **실효 기본(`GetDefaultAsync` 가 돌려주는 행) = 원본**이다. `is_default` 칸만 보지 않고, 이름순 실효 기본까지 본다(사본 이름이 앞에 정렬되는 경우 포함).
- **I3** 기동을 2회 이상 해도, 재사용 길(`:893~894` · `:1003~1010`)을 타도 기본이 안 움직인다. 3자리(`:957` · `:996` · `:1003~1010`) 중 하나라도 빠지면 2번째 기동에서 재사용 길이 사본을 기본으로 올린다. 그래서 시험은 반드시 기동 2회.

## ② P2-1 — 「칸 0」 기준
- **채택**: K3 의 「칸 0」 = 저장된 칸이 비었음(NULL · 빈 글자 · 공백만 · 빈 목록. 정확한 집합은 설계팀장이 표로 정함). 읽어 낸 칸 수가 아님.
- 근거
  - (a) §59 질문 글자 「칸을 하나도 안 맞춘 채」 = 저장된 칸 0. 기준을 좁히는 쪽이 원문 그대로다.
  - (b) 칸을 저장했는데 모두 무효(종이 밖 · key 없음 · 깨진 JSON)인 고객에게 「아직 칸을 안 맞췄습니다」 는 거짓 안내다 → #25 위반이고 「처음 보는 사람이 혼자」 기준도 실패.
  - (c) 그 경우 종전 동작 = 기본 배치 + 데이터 + 경고 → 데이터를 지킴(#20).
  - (d) P1-1: 옮기기 쪽 칸 0 판정과 렌더 쪽 칸 0 판정이 같은 함수 하나여야 어긋남이 없다. 읽어 낸 칸 수는 종이 크기에 따라 달라서 옮기기 쪽이 쓸 수 없다. 저장 기준이면 C# 함수 1개를 둘이 함께 부른다(SQL 로 따로 적지 않음).
- 대가(받아들임): 모두 무효 칸인 양식은 R6 겹침 모양이 그대로 남는다. 더 나은 안내(예: 「맞춘 칸이 종이 밖에 있습니다」)는 별건 후보로 두고 이번 범위에 넣지 않음.
- 대표 질문 거리가 아님 — 원문 글자대로 좁히고 종전 동작을 유지한다. 합류본 보고 1줄에 합침.

## Q. 조건부 대표 질문 — 발동 조건: 사실 F3 에서 F-1 옮기기가 이미 고객 설치에서 돌아 칸 0 기본 사본이 생긴 곳이 있을 때만

> ① 다음 업데이트 때 원래 양식을 자동으로 다시 기본으로 돌림(그림 양식은 목록에 남김 · 고객 손 0) (Recommended)

## 반증 — 이 판정이 틀릴 수 있는 곳
1. (가)의 3자리 중 하나가 빠지면 2번째 기동에서 재사용 길이 사본을 기본으로 올린다 → 기동 2회 시험(M2 i · ii)으로만 잡힘.
2. 실효 기본이 이름순이고 새 사본 이름이 앞에 정렬되면, 명시 0 이어도 사본이 실효 기본이 된다 → I2 는 `GetDefaultAsync` 결과로 시험.
3. §56 「내림」 이 칸 0 행에 안 걸리면 (가)에도 (나)와 같은 지연 발동이 생긴다 → 확인 필요 F1.
