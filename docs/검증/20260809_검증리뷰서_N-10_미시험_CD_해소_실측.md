## 3. 🔴 실측 결과 — 통과가 허수가 아님을 반증으로 증명

**"통과했다"만으로는 부족하다.** 테스트가 실제로 무언가를 잡는지 확인해야 한다.
그래서 **코드를 일부러 망가뜨려(mutation) 테스트가 적발하는지** 봤다.

### 반증 1 — 미래 시각 방어를 무력화

```csharp
if (utc > DateTime.UtcNow)                    // 원본
if (utc > DateTime.UtcNow.AddYears(100))      // 무력화 주입
```

```
[FAIL] C_미래_시각이_적혀있으면_확인한적_없음이다
실패: 1, 통과: 13
```

⇒ 🟢 **정확히 그 테스트 하나만 실패했다.** 다른 것을 건드리지 않고 그 방어만 지킨다.

### 반증 2 — 영속화를 무력화 (종전 인메모리 결함 재현)

```csharp
File.WriteAllText(...)                        // 원본
if (utcNow.Year > 3000) File.WriteAllText(...) // 사실상 쓰지 않음
```

```
[FAIL] D_기록한_시각을_다시_읽을수_있다
[FAIL] D_새_인스턴스가_같은_기록을_읽는다_재시작_모사
[FAIL] D_연속_재기동_5회에도_기록이_유지된다
[FAIL] 과거_시각은_그대로_읽힌다
실패: 4, 통과: 10
```

⇒ 🟢 **D 3건이 전부 잡았다.** 이것이 바로 **종전 `_lastUpdateCheckDate` 인메모리 결함**이며,
그 결함을 재현하면 테스트가 즉시 적발한다는 뜻이다.

### 원상복구 확인

```
git diff --stat src/HitPan.Watchdog/AutoUpdate/UpdateCheckStampFile.cs   →  변경 0
```

**운영 코드는 한 글자도 바뀌지 않았다.** 반증은 임시 주입 후 즉시 되돌렸다.

## 6. 🔴 남은 것 — A·B 는 이 문서가 대신하지 않는다

| # | 항목 | 왜 여기서 못 하나 |
|---|---|---|
| **A** | 재시작 없이 새 버전 발견 | **실제 게시본 + 60분 경과**가 필요하다 |
| **B** | N시간 경과 후 재확인 | A 와 동시 관측 |

### ⚠️ A·B 실측의 전제 — 게시를 두 번 해야 한다 (오늘 실측으로 확인)

```
updates.hitpan.kr/manifest.json  →  1.2.55 (2026-08-06 게시)
N-10 봉합                        →  2026-08-07 (e3342b9)
```

🔴 **현재 게시본에는 N-10 코드가 없다.** 발견할 워치독 자체가 N-10 을 가져야 하므로:

```
[1] 1.2.56 게시 (N-10 포함)  → 사장님 승인 (environment: production)
[2] 백지환경에 설치           → 사장님 (Windows Sandbox)
[3] 1.2.57 게시 (미끼)        → 사장님 승인
[4] 재시작 없이 60분 대기     → 로그에서 발견 확인
```

**게시 2회 × 25분 + 설치 + 60분 ≈ 2시간 반.** 사장님 손이 3회 필요하다.

> ⚠️ **개발 PC 에서는 A 를 시험할 수 없다**(사장님 2026-07-06). 백지환경 실측만 인정된다.
