## §1 C (로고 있음 × 워터마크)
### 1-1 사실
- R6 WM-가-on 13칸 빨강 사유 = ⓑ 종횡비 하나(밝기 순서 일치 · 이웃 차 충족). ⓒ 실효 불투명도 = 그 앞에서 끊겨 미측정 · 사실 파일에 불투명도 칸 자체가 없음 · 로컬 사본에 원 PDF 없음.
- 정적: `TryBuildWatermarkSvg` = 캔버스 1000×1000 · `<image width=1000 height=1000 preserveAspectRatio='xMidYMid meet'>` · 주석 「로고가 찌그러지면 안 된다」 → 비율 지킴은 의도 · 정사각은 캔버스 모양. 그림 1716 px = 151.34mm 를 288dpi 로 구운 크기와 맞음(셈) → `<g opacity filter>` 묶음을 캔버스 통째 래스터로 구운 꼴(추정).
- 설계 :71 이 이 구조(「SVG 안 `<g opacity>` 속 래스터」)를 근거로 적고도 종횡비를 캔버스가 아닌 로고에 걸었음 = **설계 · 장치 판정 기준 결함**(제품 몫 아님).

### 1-2 판정
- 종횡비 = 장치 기준 문제. 제품 결함 최종 확인 = 같은 그림의 **알파(불투명) 영역 상자** 종횡비 1.333 ±2% · 위아래 여백 알파 0. 맞으면 「찌그러짐 0 · 여백 투명」 확정 / 안 맞으면 찌그러짐 결함이나 대표 ① 「반영 0」 과 다른 결함 → 따로 등재 · C 고칠 자리 근거로 안 씀.
- 결과: main ① (가) = ⓐ 있음 · ⓑ 밝기 있음 · ⓒ 미측정 → 「main 빨강」 무효 · 판정기를 고치면 main 이 초록으로 바뀔 공산 큼 → 설계 :86 대로 「차림이 대표 조건을 못 만듦 → 멈춤 · 측정 재설계」.
- **거짓 초록 길 둘 다 반려**: ① 제품 캔버스를 로고 비율로 바꿔 판정기에 맞추는 고침(받아쓰기 · 대표 실패와 무관한 초록 · 8/27 작7 꼴) ② 판정기만 고친 뒤 고친 판 WM-가-on 초록을 ① 고침 근거로 세는 것(main 도 초록이면 짝 없는 초록).

## §4 E-6 고지 자리 (기술 쪽만)

- 법무 ③ (가) 글자 「설치 폴더(API 실행 파일 옆)」 → API 실행 파일 자리 = api 폴더 → 기술상 해석 거리 없음. PM 이 따로 물은 답이 「설치 루트」 면 `.iss` + 업데이트 판 구조 변경 = 멈춤 · 대표 결재 거리.
- 조건: 고지 · 라이선스 전문 파일은 **API 프로젝트**에 출력 복사(선례 `HitPan.API.csproj:119` 꼴) — Application 프로젝트 출력 복사의 publish 전파는 미실측이라 쓰지 않음(쓰려면 §3 publish 로 실측). 글꼴 = Application 내장 리소스(P-5) · 저장소 파일 ↔ 빌드 산출 내장 리소스 바이트 해시 대조 시험(법무 ⑥) · 저장소 안 글꼴 옆 라이선스 · 저작권 원문(법무 ③ (다)).
- 실림 실측 = §3 과 같은 이 PC publish 1번에 함께(출력 폴더 고지 파일 · 글꼴 리소스 해시) → [4] 몫.
