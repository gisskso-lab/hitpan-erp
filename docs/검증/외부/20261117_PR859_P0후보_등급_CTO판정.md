## §1 Q1-1 — P1 근거

1. **경로는 참이다.** 엔진 결과의 탐지기 이름이 걸러지지 않고 `::error` 주석 · 잡 로그 · 잡 요약에 나간다(M1). HQA 지적 위치와 일치.
2. **그 칸은 값을 싣는 칸이 아니다.** #859 뒤 「찾음」 을 낸 유일한 런의 실제 값 = 엔진 유형 이름 2종뿐(M2). 비밀 값(Raw) 은 이 경로에 없다.
3. **주입 폭이 좁다.** 공백 앞 한 토큰 · 줄바꿈 없는 한 줄(M3) ⇒ 새 워크플로 명령을 시작할 수 없고 주석 본문 안에만 머문다.
4. **더 주는 권한이 0 이다.** `pull_request` 는 PR 쪽 스크립트를 그대로 돌리므로 PR 작성자는 이미 `scan.sh` 를 직접 바꿀 수 있다 · 권한 `contents: read`(M4).
5. ⇒ 피해가 나려면 「엔진이 이 칸에 민감 문자열을 넣는다」 가 먼저 성립해야 하고, 성립해도 공격 면은 늘지 않는다 = **심층 방어 결함(P1)**. 고치기는 한다(ㄱ′-1).

**조건(P1 유지의 전제 — 하나라도 깨지면 P0 로 되돌린다)**
- **C1** ㄱ′-1(탐지기 이름 정리)은 HQA 고침 확인 요청 **전에** 머지한다.
- **C2** 정리는 `::error` 주석과 **잡 요약(`write_summary` · 마크다운으로 그려짐)** 둘 다에 건다. 잡 요약은 마크다운 링크 · 그림 문법이 한 토큰 안에서도 성립한다. ㄱ′-2 자체시험도 두 출력을 모두 단언한다.
- **C3** 엔진 판을 올리는 변경은 **M2 재측정(실제 탐지기 이름 값)** 을 관문으로 한다 — 작업지시서에 적는다.
- **C4** 엔진 이미지가 **다이제스트로** 고정돼 있는지 확인(아래 확인 필요 1). 태그만 고정이면 「판 고정이 막는다」(1-V §2) 는 반쯤만 참이다.
- 설계 의견([2] 몫): 정리 규칙은 「문자 종류 + 길이 상한」 이 필요조건이다. 고정 이름 목록은 선택 — 목록은 엔진 판과 함께 낡지만, 낡으면 「기타」 로 떨어져 **새는 쪽이 아니라 정보가 줄어드는 쪽**으로 실패하므로 둘 다 안전하다.

## §2 적발 A — P0 근거

1. **가설이 아니라 관측이다.** #859 머지 뒤에도 push 12런이 옛 단계로 돌았고, 빨강 3런은 공개 주석에 후보의 파일 경로 · 시작 줄을 남겼다(M5 · M6). 설계서 §3-3 「값 · 위치 · 줄은 찍지 않는다」 정면 위반.
2. **우리 다음 단계가 밟는다.** S4 장치 가지 · 공개 검토 가지 · 시험 앱 가지 모두 #859 앞 바닥 — 인계19 의 「장치 가지 push → 리허설 6」 을 그대로 하면 같은 주석이 다시 생긴다(1-V §3-5).
3. **판 고정 없는 외부 코드(`@main`)가 push 마다 돈다.** #859 가 닫으려던 공급망 위험이 옛 바닥 349 가지에 그대로 남아 있다.
4. 값 자체는 이미 공개 파일 안에 있으므로 주석이 더하는 것은 「색인」 이다. 그러나 그 색인이 가리키는 후보 중 진탐 수가 **미측정**(1-V §6)이라 등급을 낮출 근거가 없다.
5. ⇒ **P0.** 여기서 P0 의 뜻 = 「ⓐ 없이 옛 바닥 가지에 push 금지(지금부터)」 + 「A 는 ⓑ 와 동작 대조 시험까지 끝나야 닫힌다」.

## §4 반증 — [1-V] 가 놓친 것

- **R1 탐지기 이름 값 범위 단정의 한계.** 관측은 1런 · 값 2종 · 고정 판 한정이다. 그런데 M6 에서 판 고정 없는 옛 래퍼(최신 엔진)는 **사용자 규칙 이름을 찍었다** — 엔진 판이 바뀌면 출력 내용이 바뀐다는 실물 방증이 [1-V] 자기 측정 안에 있다. 「유형 이름뿐」 은 엔진 성질이 아니라 **이 판의 사실**이다. Q1-1 등급은 바뀌지 않는다(규칙 이름은 우리가 쓰고 이미 공개) — C3 · C4 로 묶는다.
- **R2 옛 래퍼 잡의 토큰 권한 미측정.** 판 고정 없는 외부 코드가 옛 바닥 가지 push 마다 우리 저장소 토큰을 쥐고 돈다. 옛 워크플로 파일의 권한 칸 · 저장소 기본 토큰 권한(읽기/쓰기)을 재지 않았다. **「쓰기」 면 A 는 「색인 공개」 가 아니라 공급망 쓰기 권한 문제**다 ⇒ 리허설 6 과 무관하게 ⓑ 재확인을 최우선으로 올린다.
- **R3 「다시 실행」 경로.** 옛 런을 다시 돌리면 옛 SHA · 옛 래퍼로 돌아 새 위치 주석이 생긴다. ⓐ 로는 못 막고 ⓑ 만 막는다. [1-V] §3 에 없다.
- **R4 ⓐ 는 사람 절차다.** 다른 창 · 다른 사람 · 자동화가 옛 바닥 가지에 push 하면 못 막는다(두 창 동시 작업 전례 있음). 그래서 A 닫힘에 ⓑ 가 필요하다 — 검증팀장 ⓒ 권고를 지지한다.
- **R5 ⓑ 의 「main 검사 1회 초록」 은 배포 계열을 재지 않는다.** 배포 · 설치 워크플로는 수동 실행 · 태그로만 돌고 무접촉 원칙상 시험 실행을 못 한다 ⇒ 첫 실제 검증 = 다음 ERP 게시. 요구: (가) 배포 계열 워크플로의 외부 액션 사용 전수 대조표를 작업지시서에 첨부 (나) 다음 게시 직전 PM 이 설정 값 확인 (다) 허용 거부가 **잡 단위**로 일어나면 다중 잡 워크플로가 앞 잡을 마친 뒤 멈춰 「반쯤 게시」 가 될 수 있는지 확인 필요 (라) 조직 수준 정책이 저장소 설정을 덮거나 잠그는지 확인 필요. 이름 허용을 `@*` 로 두면 배포 쪽 공급망은 여전히 판 고정 없음 — 이번 범위 밖, 기록만.
- **R6 ⓑ 효과는 설정 값 다시 읽기가 아니라 동작 대조로 잰다.** 옛 바닥 커밋에서 push 해 「시작 단계 실패 · 위치 주석 0」 을 봐야 한다(게이트는 글자가 아니라 동작). 단 ⓑ 가 안 먹었을 때도 주석이 안 생기도록 **후보 0 이 확인된 범위**로 시험을 설계해야 한다 — 옛 래퍼의 push 범위 계산 방식이 먼저 확인돼야 한다([2] 몫 · 확인 필요 3).
- 범위 밖 기록: 옛 바닥 가지 push 는 비밀 검사 말고 다른 옛 워크플로도 그 가지 판으로 돌린다. 이번 판정 대상 아님.
