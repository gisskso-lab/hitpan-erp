# HQA 화이트해커 가동 판단 — 보안상무 1단계 (2026-11-08)

> 판단 순서: **보안상무(이 문서) → 3인(PM · 검증팀장 · 보안상무) → CTO → 대표**
> 진실원: 인계15 (PR #853) · 근거 루틴: [`WORKFLOW.md`](../../WORKFLOW.md) §8-1
> 🔴 이 문서는 **원리 수준만** 적는다. 공격 절차 · 값 · 사슬 원문 0건. 공개 레포다.
> 상태: 🟡 보안상무 의견 · 결재 아님

## §0 한 줄 판정

**조건부 가동 — 필요하다, 그러나 지금은 아니다.** 세션 경계 묶음 고침 [3] 결과가 시험 앱 가지에 오른 뒤, [4] 와 **동시에**, **운영 배포 전**에 1회. 조건 G1~G4 가 모두 닫혀야 출발한다.

| 조건 | 내용 | 닫는 사람 |
|---|---|---|
| G1 | 로그아웃 3회차 · F6 머지 · 세션 경계 별건 [1-V] · [2] 끝 | PM · 검증팀장 |
| G2 | 결과 원문을 공개 PR 댓글과 분리하는 **비공개 회신 경로** | 대표 결정 |
| G3 | 시험 묶음 위생 — 합성 데이터만 · 시험 전용 비밀값 · 값은 우리도 안 본다 | 검증팀장 |
| G4 | 범위 확정 — 3인 → CTO → 대표 | 대표 |

## §1 필요성 — 지금 관문으로 못 잡는 것

내부 [3-V] 는 **코드·문서를 읽고** 반증한다. HQA 관문은 **화면을 정상 사용자처럼** 실측한다. [4-X] 는 **읽기 전용 · 의심 제기권만**이다(§8-1). 셋 다 「일부러 규칙을 어기는 사용자」 역할은 하지 않는다. 그 빈칸에 남는 항목(이름만):

1. 세션 수명 경계 — 로그아웃·만료 뒤의 재사용
2. 쿠키와 그 안의 인증값이 서로 다른 상태 (10/15 사고 계열)
3. 다중 탭·다중 기기 경합
4. 테넌트·권한 경계의 옆걸음 (#2 · #7)
5. 오류 응답의 정보 노출 · 외부 노출 금지어 (#23)
6. 반복 시도 내성 (속도 제한 · 잠금)
7. 공용 PC 브라우저 잔류

→ 4개 이상이 **세션 경계**와 한 뿌리다. 지금 고치는 묶음이 바로 이 자리다.

## §2 시점 — 왜 지금이 아닌가

- 세션 경계 고침이 아직 [1-V] · [2] 단계다. 지금 두드리면 **이미 아는 결함을 다시 찾는다** — 비용만 들고 새 정보 0.
- 고침 뒤에 두드리면 「고쳤다 ≠ 갔다」(반복 사고)를 **악의 축**에서 반증한다. EVF 6대 영역 중 「악의」 실측이 베타 게이트에 들어간다.
- 운영 배포 **뒤**로 미루면 운영에서 찾게 된다 — #39 위반 위험이 생긴다.

| 순서 | 단계 |
|---|---|
| ① | G1 — 세션 경계 [1-V] · [2] → [3] |
| ② | [3] 결과가 시험 앱 가지에 오름 |
| ③ | **[4] 와 화이트해커 동시 착수** (G2 · G3 · G4 닫힌 뒤) |
| ④ | 결과 대응표 → CTO 대조 → 대표 → 운영 배포 |

## §3 교전 규칙 — 하나라도 어기면 즉시 중지

| # | 규칙 | 근거 |
|---|---|---|
| R1 | **시험 앱만** 대상. 운영(백오피스 운영 · 고객 ERP · 대표 PC)은 공격 0 · 접속 0 | #39 |
| R2 | **공개 터널 0** — 시험 앱을 외부로 여는 터널·DNS·방화벽 조작을 화이트해커 때문에 새로 만들지 않는다 | #29 |
| R3 | **실제 계정 0** — 실제 고객·대표·직원 계정 · 실 비밀번호 사용 금지. 시험 전용 계정만 | #40 · G3 |
| R4 | **본사 업무 데이터 0** — 시험 데이터도 합성만. 고객 업무 자료 복사본 금지 | #18 · #22 |
| R5 | 공개 레포에 **운영을 겨눌 수 있는 절차 0** — 재현 순서·요청 모양은 비공개 경로(G2)에만 | 공개 레포 |
| R6 | **값 0** — 토큰·쿠키·비밀값·키를 문서·댓글·커밋·화면 캡처 어디에도 남기지 않는다(모양도 금지) | 반복 사고 「자격증명 모양」 |
| R7 | 시험 앱이 운영 DB · 운영 비밀값을 가리키지 않는지 **착수 전 확인**(이 PC 3306 사고 계열) | 반복 사고 |
| R8 | 결함을 찾아도 **고치지 않는다** — 적발만. 봉합 즉석 금지 | #29 · #33 |

**산출 형태** (두 겹)
- **공개 쪽**: 항목 이름 · 등급(P0~P2) · 영향 범위 한 줄 · 「재현 원문은 비공개 경로」 표시. 이것만 PR 댓글·이 폴더에.
- **비공개 쪽**: 재현 원문 · 사슬 · 증거. G2 로 정한 경로에만. 공개 문서는 그 위치의 **이름도** 적지 않는다.
- 등급과 처리는 기존 [4-X] 와 같다 — 원문 보존 → PM 대응표 → CTO 대조. 판정은 화이트해커가 아니라 우리 임원이 한다.

## §4 범위 안 — 3개 중 하나

| 안 | 범위 | 장점 | 약점 |
|---|---|---|---|
| **A (추천)** | **세션 경계 묶음만** — 로그인 · 로그아웃 · 재발급 · 만료 · 다중 탭 (백오피스 시험 앱) | 고침과 1:1 대조 · 짧다 · 산출 작다 | 테넌트 옆걸음 · 입력 경계는 남는다 |
| B | A + 백오피스 인증·권한 전반 (역할별 메뉴 · 대리점 경계) | §1 항목 4 까지 덮는다 | 기간 두 배 · 범위 다툼 생김 |
| C | B + ERP 로그인 경로 | 3시스템 인증을 한 번에 | ERP 는 고객 PC 로컬 + 터널 — R1 · R2 를 지키는 시험 환경이 아직 없다 → 지금 불가 |

- 추천 이유: §2 의 「고침 뒤 반증」 목적에 정확히 맞는 최소 범위다. 최소주의 = 「필요한 만큼」 — 세션 경계가 지금 필요한 만큼이다.
- **상단 검색**은 A 에서 **뺀다**(세션 경계와 뿌리가 다르다) — 단, 쟁점 ③ 으로 올린다.

## §5 안 할 때 위험

- 세션 경계 고침이 「정상 사용자 경로」로만 확인된다 → 악의 경로의 재발은 **운영에서 고객이** 찾는다(EVF 「악의」 축 미측정 = 베타 게이트 빈칸).
- 백오피스는 NCP 공개 서비스다 — 외부 공격자는 우리 일정을 기다리지 않는다. 내부가 먼저 두드리지 않으면 첫 두드림은 남이 한다.
- 「대조군 없는 게이트 = 미측정」(반복 사고 31번+) — 고침의 반대 경우를 누구도 시도하지 않은 채 「고쳤다」가 진실원에 들어간다.
- 반대로, **조건 없이 지금** 하면: 재현 원문이 공개 PR 에 남아 운영을 겨누는 지도가 된다 · 이미 아는 결함만 다시 나온다 · 루틴 근거 없는 작업이 된다(#42). → 「안 함」도 「지금 함」도 위험하다. 조건부가 답이다.

## §6 쟁점표 — 3인 · CTO 에게

| # | 쟁점 | 보안상무 의견 | 결정 |
|---|---|---|---|
| ① | **공개 PR 댓글 vs 결과 원문 분리** — 지금 [4-X] 회신은 공개 PR 댓글이다 | 원문은 비공개 경로 필수(G2). 공개 쪽엔 §3 「공개 쪽」 형태만. 경로가 없으면 출발하지 않는다 | 대표 |
| ② | **능동 시험이 §8-1 [4-X](읽기 전용 · 의심 제기권만) 밖이다** | 근거 없는 작업 금지(#42). ㉠ WORKFLOW 개정으로 새 단계 신설 또는 ㉡ HQA 관문 확장(화면 실측 관문에 「악의 사용자」 역할 추가). 보안상무는 **㉡ 쪽** — 이미 시험 앱에서 도는 관문이라 R1 · R2 를 새로 만들 게 적다. 어느 쪽이든 **문서 개정이 착수보다 먼저** | 3인 → CTO → 대표 |
| ③ | **상단 검색을 범위에 넣나** | 이번엔 뺀다(뿌리 다름 · 범위 다툼). 별건으로 등재해 다음 차수 후보 | 3인 |
| ④ | **공개 가지에 이미 있는 쿠키 관련 사슬**을 어디까지 적나 | 공개 문서는 **원리 수준이 상한** — 「어떤 종류의 경계가 약했다」까지. 순서 · 조건 · 요청 모양 0. 이미 공개된 글도 더 키우지 않는다 | CTO |
| ⑤ | **베타 전 게이트로 삼나** | 삼는다 — EVF 「악의」 축. 단 「범위 A 1회 통과」를 하한으로 두고, B · C 는 베타 뒤 후보로 미룬다(일정 부풀리기 방지) | 대표 |
| ⑥ | **결과 등급 · 공개 시점** | P0 는 고침 · 배포 끝난 뒤에만 공개 쪽 요약을 올린다. P1 이하는 대응표와 함께 | CTO |
