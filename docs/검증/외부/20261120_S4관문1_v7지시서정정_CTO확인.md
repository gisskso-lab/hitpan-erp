## 2. C1′ 이 「항목 🔴 · 대조 무효인데 머리 초록」 길을 닫는가 — 닫는다 (조건 셋)

- **닫히는 까닭(실물 대조)**: 지금 머리 초록 = 목록 4개 빔(L1206). 대조 무효는 어느 목록에도 안 들어 초록이 났다(§99 P1). ⑤′ 가 「대조 성립 안 함」 목록을 더하고 초록을 그 목록까지 빈 때로 묶으면 대조 무효 · 대조 기준 미정이 머리 초록과 함께 나올 길 0. `red` 뜻 무변(대조 무효 = 장치 빨강도 제품 빨강도 아님) 도 맞다.
- **새로 생기는 길 셋 — 조건으로 막음**:
  - **C-1 (N-2 · 머리 초록이 영영 안 나옴)**: N-2 는 계획 칸 8 중 `/after` 4칸이 판정 칸(L1173 식 · 대조 화면 표에 N-2 없음 → `before`)인데 `contrastState` 가 **없다**(`fourCells` 는 I-1~I-7 · N-1 · I-8 만 · L1021 · L1025). ⑤′ 글자 그대로(「성립」 아님)면 N-2 `/after` 가 늘 「대조 성립 안 함」 → v7 머리 초록 0. → ⑤′ 적용 = **`contrastState` 가 있는 항목의 판정 칸만** · N-2 = 정본 글자 「기록 · 판정 HQA」(L807 · L809)대로 **기록만 칸**(① · ⑤′ 밖 · S2 · S3 · S4 상태는 그대로)으로 적음. 새 기준 0.
  - **C-2 (양성 대조 시험)**: 정정 1 이 더한 시험은 모두 음성(ⓐ~ⓓ). 「전 계획(I-1 ~ I-8 · N-1 · N-2) S1 · 꼴 미재현 · 대조 모두 성립 → 머리 초록 · 종료 0」 시험 1 을 반드시 더함. 이것이 없으면 C-1 같은 「늘 초록 아님」 이 숨어 장치 결함과 제품 결함을 가를 수 없다.
  - **C-3 (초록 = 목록 기준 유지)**: 초록 = **목록 다섯이 모두 빔**(지금 코드 방식 유지) **그리고** 여섯 셈의 초록 아닌 칸 0 — 둘 다. 불변식 시험: `red === true` 이면 `green === false`.
- C-4 (K-7): I-2 꼴 = `typeof R.openCountAfter === 'number' && R.openCountAfter === 0` · 숫자 아님 → S4 를 `v7Classify` 에서 S1 앞에 판정. 자체시험: 대조 칸 · 판정 칸에 `openCountAfter: null` → 둘 다 S4(대조 성립 0 · 빨강 0).
- C-5 (K-8 · K-9): I-5 = `typeof R.focusAfterKey?.inOpenList !== 'boolean'` → 통과로 안 셈(S4 또는 `i4FocusNotBool` 선례대로 장치 실패 — 설계팀장이 하나 고름). 자체시험 1.

## 3. K-6 — 🟡 은 기록만 (이대로)

- 정본 N-1 글자가 「🟡 = 기록 · K2 입력」. 🟡 를 「초록 아님」 에 넣으면 정본에 없는 우리 기준(새 기준 외관)이고, 머리 초록이 안 나오는 길도 하나 더 생긴다.
- 덧 1줄: 사전 공개 글자에 「머리 초록이어도 🟡(기록)은 항목 글자(`items.*.labels[]`)에 남음」 을 적어, 초록 머리가 「깨끗함」 으로 읽히지 않게 한다(셈 · 종료 코드 무관).

## 4. I-2 · I-5 실패 꼴 인용 — 받음 (조건)

- **I-2 받음**: 정본 A §3 2 항목(Enter/Space 로 열림)의 부정 + 11/7 §7-2 M7 대조군 칸. I-1(M6 대조군) · I-4(「의 부정(추론)」) 와 같은 꼴로 이미 받은 선례가 있다. rules `source` 에 「부정 · 기대 채택 아님」 표지.
- **I-5 받음(🟡)**: 「초점 끌어감」 은 정본 A §2 검증팀장 줄에 글자가 있고, 원리(§12-3 ⑤)만 「추론」. rules `source` 에 「추론」 표지를 그대로 두고, 사전 공개 사실 행 + HQA 재대조 회신 없이 런 = 반려(CTO 몫 판정 R1 다시 확인).
- 안 받는 경우의 길: 지시서 §17-2 둘째 점 「defined=false → ⑤′ 대조 기준 미정 = 초록 아님」 이 있고, 실물 `stateOf` L952 와 맞음 → **있음**.
- 남는 점(기록): 실패 꼴만 보므로 I-5 에서 「초점이 body 로 빠짐」 은 꼴 밖 = 초록. 기대 동작을 확인한 게 아니라 「인용된 실패 꼴 미재현」 일 뿐 — 이 뜻을 사전 공개 글자에 한 줄로.

## 5. Q-1 — CTO 추천: (가) + 같은 HQA 재대조 편에 「대조 화면을 따로 정할지」 질문 함께

대표께 올릴 글(쉬운 말):
> 1. 고치기 전 화면(/before)은 원래 결함(I-1: 키보드로 단추에 못 감) 때문에 키보드로 시험하는 세 항목(I-2 · I-5 · I-6)을 아예 시험할 수 없습니다. 지금 비교 화면을 우리가 새로 고르면 리허설 결과를 보고 기준을 바꾼 꼴이 되고, 새 화면이 결함을 재현하는지도 시험을 돌리기 전엔 모릅니다.
> 2. 그래서 「세 항목은 판정 못 함 → 이번 판 머리는 초록 아님」 을 미리 공개에 적고 v7 을 돌리길 권합니다. 거짓 합격은 없고, 나머지 일곱 항목의 장치 확인을 처음 실물로 얻습니다.
> 3. 비교 화면을 새로 정할지는 외부검증팀(HQA) 글자로 정해야 하니, 런 전에 어차피 하는 HQA 재대조 때 같이 물어 한 번에 끝냅니다(HQA 가 「따로 정하라」 하면 그때 (나) 로 갑니다).

- 덧(대표 글 밖): 이미 다른 대조 화면 선례가 있다(I-4 키보드 = `e1t3` · N-1 = `a2` · I-8 = `v2` · `rules.json` `contrastScreen`). 다만 그 화면이 I-2 · I-5 · I-6 실패를 재현하는지는 측정이 없다 → 우리 손으로 고르면 추측. 150 · 300 단은 미측정이나 I-1 결함은 시간 차가 아니라 구조라 같은 결과일 가능성이 높다(추론).
- 일정 영향: v7 로는 관문 ① 합격이 안 나옴이 거의 정해짐 → 대조 화면 확정 판(v8)이 한 바퀴 더 필요할 수 있음. 주간 보고에 ±n 으로 적을 거리.
