## 무엇을 하는 장치인가 (3줄)
1. PR 마다 GitHub 시험 서버에서 빈 DB 컨테이너 + 출하 DDL 로 히트판을 띄우고, 브라우저(Chromium · WebKit)로 화면을 눌러 결과표를 만든다.
2. 런 안에서만 쓰는 비밀값(DB·서명·로그인)을 런마다 새로 만들고 가린 뒤, **로그·스크린샷·결과표를 공개 업로드하기 전에** 누출 검사(원문·base64·URL 인코딩 3꼴)를 통과해야만 올린다.
3. 판정은 결과 줄의 종류(TEST · DEVICE · 허용된 OBS 1개)로 빨강/초록을 낸다.

## 질문 (세 가지)
- **ⓐ 새는 길**: 런 안 비밀값(DB 비밀번호 · 서명 키 · 로그인 비밀번호 · 런 중 받은 접속·갱신 토큰)이 공개 로그나 업로드물로 나가는 길 가운데, 누출 검사가 보지 않는 경로나 3꼴(원문·base64·URL 인코딩) 밖의 꼴(JSON `\u` 이스케이프 · 줄 나뉨 · 두 번 URL 인코딩 · 16진 · 이미지 메타데이터)로 빠지는 길이 있는가? 런 중 토큰을 못 가로채 검색 대상이 비었는데도 통과되는 경우를 포함한다.
- **ⓑ 초록이 거짓인 길**: 업로드 단계가 누출 검사 성공이 아닐 때도 도는 길(`always()` · `continue-on-error` · outcome 과 conclusion 차이)이 있는가? 판정이 누출 검사를 안 돌았거나, 결과 줄이 빠지거나, 단계가 일찍 끝났을 때도 초록을 낼 수 있는가? 잡 `if`(head_ref 접두어) · 포크 PR · 수동 실행으로 권한이 올라가는 길이 있는가?
- **ⓒ 가로채기 밖의 길**: `page.route`·응답 가로채기 밖의 길(WebSocket · 서비스워커 · 워커 · 리다이렉트 · API 프로세스의 직접 송신)로 런 중 값이 밖으로 나가거나, 가려지기 전에 찍히는 길이 있는가?
