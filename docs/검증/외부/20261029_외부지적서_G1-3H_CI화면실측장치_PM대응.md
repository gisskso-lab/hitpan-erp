### X702-H1 상세 — 어디가 막혀 있고 어디가 뚫렸나
1. **사후 검출은 있다(예방은 아니다).** 예외 메시지가 실리는 줄(`describeError()`)은 모두 `rec()` 를 거친다 — 장치 스크립트가 직접 찍는 `console.log` 는 예외 **이름**만 찍는다. `rec()` 는 같은 `got` 을 **결과표 파일에 먼저 쓰고** 콘솔에 찍는다(`lib.js` 5차 ①). 결과표는 S10 이 URL 인코딩 꼴까지 찾으므로, 인코딩 꼴이 콘솔에 나가면 **같은 런의 S10 이 빨강 · 업로드 0** 이 된다 — 🆕 CTO 정정: **값이 온전한 꼴일 때만.** `describeError()` 200자 · `rec()` 300자 상한에 잘린 반쪽 값은 S10 도 GitHub 가림도 못 잡는다. 그 줄은 S10 보다 **먼저** 공개 잡 로그에 나간다 — 회신 지적 그대로다. 🆕 CTO 정정: 실제로 로그에 **보이게 남는지는 미측정**(GitHub 가림이 인코딩 꼴까지 가리는지 아무도 안 쟀다).
2. **뚫린 자리 = 두 곳.** ⓐ `rec()` 를 거치지 않는 출력 — Node·Playwright 가 처리기 밖에서 직접 찍는 것(측정 0). ⓑ S10 3꼴 밖의 꼴(JSON `\u` 꼴 · HTML 엔티티 등) — 파일·로그 둘 다 못 잡는다(측정 0).
3. **실제로 걸리는 값.** S0 일곱 값 중 hex 넷(`openssl rand -hex`)은 URL 인코딩해도 글자가 같아 지금도 지워진다. **비밀번호 셋(`Ui#…`)은 `#` 이 `%23` 으로 바뀌어 인코딩 꼴이 원문과 달라진다** — 이 셋이 회신의 경로에 실제로 걸리는 값이다. 런 중 등록값(`UI_SECRET_*`)은 꼴에 따라 다르다(측정 0).
4. **영향.** 값은 모두 **런마다 새로 만든 일회용**(저장소 Secrets 0) · 컨테이너는 런 끝에 사라진다 · 고객·운영 접촉 0. 그래도 장치의 약속(「공개 출력에 값 0」 · `lib.js` 규칙 ②)이 깨지는 길이고, K(#691)가 붙으면 등록값이 늘어난다. **PM 의견 = P2(일회용 값) · 등급 확정은 CTO.**
