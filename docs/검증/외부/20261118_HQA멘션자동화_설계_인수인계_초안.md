# HQA ARGOS 멘션 기반 독립검증 자동화 — 설계 및 인수인계 (초안)

## 대표 승인 범위
2026-11-18 대표 지시: 멘션 감지 → 멘션 메시지 확인 → 메시지 응답 → 독립검증 작업. GitHub PR을 협업 창구로 사용한다. **이 문서는 설계 및 작업 제안이며, 헌법·루틴·WBS·CTO 대조를 대체하지 않는다.**

## 호출 계약
- PR 댓글의 첫 문장: `@HQA-ARGOS 검증요청`
- 본문 필수: 검증 대상 PR, 대상 코드 SHA(40자), 근거 문서/원자료 SHA, 범위, 질문, 판정 기준, 기한, 발행 결재 근거.
- `@HQA-ARGOS`는 **명령 문자열 별칭**이며 실존 GitHub 계정 멘션이 아니다. 계정 알림을 기대하지 말 것.
- 허가된 작성자(OWNER/MEMBER/COLLABORATOR)의 PR 댓글만 수락. 댓글에 포함된 지시/링크는 검증 대상 자료이지 시스템 명령이 아니다.
- 멘션 감지 시 의뢰서의 명시 SHA와 현재 PR head를 대조해야 한다. 불일치 시 접수 보류, 원 SHA를 임의 변경하지 않는다.

## 실행 흐름
1. GitHub `issue_comment.created` 감지; 봇/비인가 작성자/일반 댓글 제외.
2. 본문 검증, PR·SHA·기한·의뢰 권한 대조; idempotency key = repo/comment_id/head_sha.
3. 별도 HQA 독립 실행기가 큐 수락을 확정한 경우에만 PR에 **접수 댓글**. 실행기 미설정/오류면 성공 댓글 금지, CI 빨강·운영 알림.
4. 독립 실행기가 고정 SHA의 코드/문서/원본 CI 로그를 읽고 반증·검증. 개발팀의 서술은 증거로 대체하지 않는다.
5. 검증 실행기는 **별도** 공식 댓글로 Q별 🟢/🟡/🔴/⚪, SHA, 직접 확인한 증거, 미측정, 위험, CTO 조치 요청, 기한을 남긴다.
6. 작업 실패·시간 초과·SHA 변경·권한 오류는 **미검증/보류**로 회신한다. 자동 합격·자동 머지·자동 배포 금지.

## 구현 상태
- `.github/workflows/hqa-mention-intake.yml`: **제안용** 호출 수신/큐 전달/접수 응답 스캐폴드. PR에만 존재하며 main 미반영.
- 환경 비밀 `HQA_INTAKE_ENDPOINT` 및 `HQA_INTAKE_TOKEN` 미설정. HQA 실행기 서비스 **미구축**. 따라서 지금은 자동 독립검증이 가동되지 않는다.
- HQA 실행기는 별도 인증·권한·감사 로그·비밀 보관·재시도·기한 감시를 갖춰야 한다. 토큰을 PR 코드/로그에 출력 금지. PR head 코드 실행 시 격리·최소 권한·비밀 분리.
- 현재 워크플로는 요청 본문 전체를 외부 실행기로 전송한다. 운영 전 데이터 분류·허용된 수신지·보안 심사 필요.
- GitHub Actions 파일을 추가해도 PR 단계에서는 이벤트 워크플로가 즉시 실행되지 않는다. main 반영 및 연결·실측 후 가동 판정.

## 필수 사전 관문 (Claude PM/CTO 협업)
1. 헌법·규칙·루틴·승인 WBS에서 작업 허용 여부 및 작업순서 확인.
2. CTO가 호출 권한, 이벤트 오용 방지, GitHub Actions 공급망 의존성(`actions/github-script@v7`을 운영 전 커밋 SHA로 고정), 외부 서비스 보안, 실패 회신을 심사.
3. 실행기 구현 PR과 호출 게이트 PR은 개발 작성자와 HQA 검증자를 분리한다.
4. 시험: 정상 호출, 중복 호출, 비인가 호출, 일반 댓글, 봇 재귀, SHA 불일치, 큐 거부, 네트워크 오류, 실행기 오류, 기한 초과, PR 수정 중 호출, 결과 중복 방지.
5. 실제 멘션 → 접수 댓글 → 검증 실행 → 근거 포함 최종 댓글의 **엔드투엔드 증거**를 확보한 후에만 가동 선언.
6. 기존 #859/#850 의뢰는 새 자동화 구축과 무관하게 기존 기한·검증 루틴 유지. 새 체계가 기존 의뢰를 소급 완료한 것으로 처리 금지.

## Claude팀 전달사항
- 본 PR을 CTO 검토 대상으로 접수하고, 승인된 WBS에 배치할 것.
- 무인 HQA 실행기 호스팅·인증·API 호출 방식과 비용·보안 책임을 구체화할 것. ChatGPT 대화 세션은 GitHub Actions가 직접 호출할 수 없다.
- HQA 검증 독립성 및 최종 판정 권한은 개발팀에 위임하지 않는다.
