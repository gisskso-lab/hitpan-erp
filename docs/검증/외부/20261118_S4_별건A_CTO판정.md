### 근거 (위치)
**결-A10**
1. **판독 쪽 오염은 이미 드러난다.** 근거는 §1-2 「셈」 칸이다. HQA 재판독만 센다 · 다르면 그 회차 판독 = 합격 근거 0. M7 · `pin` 에 들어간 `BASH_ENV` · `NODE_OPTIONS` 는 verdict 불일치로 드러난다. 독립성이 못 덮는 곳은 §1-2 「못 닫는 범위」 인 표본 수집(항목 단계 · 재실행 불가)이다. (B) 는 바로 그 단계를 빼고 덮는다. 비용을 엉뚱한 층에 쓰는 셈이다.
2. **남은 길은 전부 악의 꼴이다.** 스스로 지우는 `BASH_ENV`, 경로를 보고 거짓말하는 해시 도구는 우발로 생기지 않는다([4] F1 · F2 측정 꼴). 같은 실행기의 악의는 `env` · `bash` · 해시 도구 · node 실행 파일 자체를 바꿀 수 있다. 그래서 (B) · (C) 로도 「막는다」 는 주장이 서지 않는다(§11-2 추천 이유 ①). 우발 경로는 세 겹으로 닫는다. K2″ 절대 경로(PATH · 셸 함수 꼴), G1(숨지 않는 꼴), A10-2 정적 셈이다.
3. **(B) 의 거짓 빨강 위험은 실재한다.** 셋 다 미측정이다(§11-5 Q11).
   - `env -i` 는 잡 · 단계 변수를 전부 지운다. M7 이 쓰는 변수를 하나라도 다시 정하지 않으면 판독이 0 이 된다.
   - node 절대 경로는 이미지 갱신 때 바뀐다.
   - 셸 옵션 · 지역 설정이 v4 M7 과 다르면 verdict 바이트가 v4 와 달라질 수 있다.
   - 런 여유는 상한 9 − 계획 7 = 2 뿐이다(§6-3).
4. **(C) 는 F1 을 못 막는다.** 재확인 단계의 셸이 먼저 실행해 지우기 때문이다(§11-2 표). 게다가 둘째 허용 목록이 생겨 거짓 빨강 위험이 가장 크다.
5. **HQA 오독 위험은 실재하지만, 읽히는 내용이 사실이다.** HQA 기준(6970680614)은 추적성 + 독립성이다. HQA 스스로 「해시 식별은 추적성의 근거」 라고 적었다. 런 안 확인을 「보장」 으로 약속한 적은 없다.
   - 더 큰 위험은 반대쪽이다. V4 「`BASH_ENV` 심으면 빨강」 을 그대로 두면 HQA 가 F1 을 스스로 찾을 때 그 문장이 거짓 주장이 된다.
   - 다만 §11-4 문안은 그대로는 모자란다. ① 표본 수집 몫이 빠졌다. §1-2 는 이 한계를 v5 공개에 적기로 했는데 이 단락은 판독기만 말한다. ② guard(M3 뒤)부터 `pin` 사이 단계가 G 항목 밖이라는 말이 없다. ③ 「기본 명령」 이라는 말로는 node · git 이 가리켜지지 않는다. ④ HQA 첫 우려(§16 #1 「앞 단계 설치가 뒤 측정에 영향」)에 v5 가 무엇을 고정했고 무엇이 남았는지 답하는 문장이 없다.

**결-A11**
6. 허용 장치 이름 3개는 점검 · 항목이 자동화 패키지와 브라우저를 고르는 실행 경로다([3-V] K3 · K2 #3). 값을 안 보면 상주 프로세스가 덧붙인 경로가 G1 을 지나간다. 기대값은 boot.sh 가 스스로 만든 값이라 새 허용 목록 · 새 개념이 0 이다.
7. (C) 는 node · git 만 앞당긴다. `bash` · 해시 도구 · `cmp` 는 여전히 G3 전에 돈다. 얻는 몫은 일부뿐인데 [4] V4 전 경우와 null 꼴을 다시 세야 한다(§11-3 이유 ② · ③). 남는 「확인 전 실행」 은 A10-1 (c) 로 공개한다.
8. (A) 반려 — 범위 안에서 고칠 수 있는 구멍을 한계로 두면 「알고도 둠」 이 된다.
9. **(B) 바이트 자체에 대한 반증 3건**

   - `pwd` 와 git 최상위 경로는 심볼릭 링크에서 다를 수 있다.
   - 공개 덧말 「값까지 확인」 은 경로 안 파일 내용까지 확인한 것으로 읽힐 수 있다.
   - → A11-1 ~ A11-3.

### 조건 (번호 · [3] 고침 · [4] 재셈 전 · 새 런 0)
- **A10-1 한계 단락 보강.** §11-4 문안에 다섯 가지를 더한다. 옛 글자 보존 · 설계팀장 글자 · PM 확인.
