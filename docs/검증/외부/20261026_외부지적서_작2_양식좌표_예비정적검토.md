## 1. 잠재 P0 — A-1 `plain` 좌표 모드와 머리글·바닥글의 공간 충돌 가능성

- **증거 상태:** 정적 검토상 위험. **내부 판정:** 미확정. 실제 발생 확인 전 자동 반려가 아님.
- **GPT 직접 확인:** `PdfRenderService.cs:97`에서 `useCoords`는 현재 `isPreprint`일 때만 참. 승인된 A-1은 이 제한을 푼다. `:181~195`에서 좌표 경로에 여백 0을 적용한다. 그런데 `:230~245`는 `!isPreprint`인 경우 머리글과 바닥글을 계속 만든다. `:2898~2932`의 `ComposeBodyCoords`는 높이 297mm의 좌표 레이어를 만든다. 따라서 `plain + FieldCoords` 활성화 시 A4 본문 297mm와 머리글·바닥글이 공존하는 구조가 된다.
- **잠재 고객 영향:** PDF 레이아웃 오류로 전표 인쇄 중단, 또는 고객 양식지 기준 좌표 오프셋. 어느 양상이 실제로 발생하는지는 실행 전까지 미확인.
- **내부 기존 근거와 중복 여부:** 작2 [1-V] §머리카드는 297mm 고정을 A4 용지 고정으로 **음성** 판정했으나, 이는 기존 preprint 좌표 경로에 대한 설명으로, **신설 plain 좌표 + header/footer** 결합은 별도 대조하지 않았다. 현재 검토한 [1-V]·설계·작업지시서에 이 조합에 대한 반증은 발견되지 않음. 전체 내부 기록 전수 대조 전이므로 '독립 고유 발견' 확정 아님.
- **PM 확인 요청:** A-1 구현에서 좌표 모드와 머리글·바닥글 분기 기준을 함께 검토할 것. `plain + FieldCoords>=1`에 대해 `ShowCompanyLogo=true/false` 각각 PDF 생성 성공과 실제 mm 좌표 위치를 [4] 검증에서 확인할 것. 별도 고객 환경 실측은 사장님 승인 절차를 따를 것.
