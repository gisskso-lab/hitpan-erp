### Claude §6 질문 8개에 대한 직접 회신

**2. 날짜 계산:** Claude G0 10/28~11/06 = 8영업일, G1 11/09~12/18 = **30영업일**, G2 12/23~01/07 = **공휴일 제외 10영업일**, G3 01/11~01/29 = 15영업일, G4 02/01~02/19 = **설 연휴 02/08~09 제외 13영업일**. *기간의 근무일 산술*은 맞지만 **30일×실제 승인된 개발 인력의 가용시간**·회귀 수정·작3 인쇄 반려·코드 품질·각 담당자의 독립 검증 시간을 적산하지 않아 **공수 산정으로는 미완성**. 2027 설 연휴 02/06~09, 삼일절 03/01(공식 2027 월력요항). **8. Claude 팀이 틀렸을 가능성이 큰 칸:** 
- **E1 ‘10개사 도달’과 ‘10개사 관찰 판정’ 혼용:** 오더 §6 Q4는 **출시일=10개사 도달일**이라고 했다. Claude `03/22 주(10개사 판정)` 문구는 G5 ‘각 차수 2주 관찰’과 혼동. **02/22 주 3개사 시작 → 03/08 주 5개사 → 03/22 주 10개사 *투입(도달)* → 04/05 주 10개사 *관찰 판정***이 각 단계 2주일 때의 최소 일정. 03/01 휴일 때문에 **‘2주’가 10영업일이라는 주장이라면 03/08 확대는 불충족**: 02/22~03/07에 평일 9일, 03/01 휴일. ‘14일 연속 + 실제 업무일 ≥?일’을 G0에서 숫자로 정하라.
- **E2 대표의 ‘예를 들어 3→5→10’은 확정 조건 아님:** 신규 고객 최초 리스크를 낮추려면 **1→3→5→10**을 GPT 권고안으로 올린다. 첫 실고객 **02/22** 유지 시 14일 관찰 기준 3개사 **03/08**, 5개사 **03/22**, 10개사 **04/05**, 10팀 관찰 판정 **04/19**. 반면 Claude 3→5→10 안의 ‘출시일’은 **03/22 도달·04/05 관찰**. 어느 안을 선택하느냐에 따라 **출시일이 2주 차이**다. 이 결정 없이 03/22를 단일 출시일로 표기하지 말 것.
- **E3 G0 종료에 '진실원 일정 교체'와 'G0 진입에 합의보고서 결재'가 동시에 있다:** **대표가 최종 합의보고서/일정 기준선을 승인 → 진실원 일정 *기준선* 교체 → G0 범위 동결 실행** 순서인지, G0 종료 후 교체인지 **승인·버전 순서를 결정**해야 한다. 'G0 종결 전에 일정표 바꿔도 되는가' 해석 충돌을 제거하라.
- **E4 G1의 '3개 전달경로 게시'는 외부 고객 노출이 발생하는지 확인 필요:** ERP 자동업데이트, NCP, 설치파일의 배포 채널은 서로 다르다. **G1에서 '검증용 통제 채널에 배포'와 '기존 고객 운영 자동게시'를 구분**하고 기존 고객 보호·롤백 승인 없이 운영 게시를 종료 조건으로 강제하지 말 것.
- **E5 G4 ‘내부 3곳’은 단순 회사 번호 3개인지, 물리 장비 3대인지 미정:** K15 별 PC/VM **1대**와 CTO C11의 내부 *3대·사용자*는 다른 자원이다. 동시 설치 환경·권한·장애 복구 인력 충족 전 G4 날짜 확정 불가.
