## 2. 경계 규칙 — 이 계열(작업 나무 쓰기만으로 G5 판정 · 저장소 판정을 비켜 감)

**코드로 닫는 조건은 ㉠ 하나와 ㉡ 전부다.** ㉠ (ⅰ) 실행기 기준으로 G5 거짓 초록이 나거나 측정 단언 값(run.json 2회차 원격 등)이 바뀐다. 측정이든 코드 읽기든 같다. 이것이 P1 이고 언제나 코드다. 또는 (ⅱ) 공개 문장이 사실보다 넓어 어차피 새 머리가 생기고, 그 자리를 「코드 읽기 · 미측정」 에서 개발 PC 로 잴 수 있는 직접 단언으로 바꿀 수 있다(이번 A1). ㉡ 승인 파일(boot.sh · MAPPING) 안이다. 워크플로 · 판독 4파일 · pin 바이트는 무변이다. 새 외부 명령 · 새 G 번호 · 새 원자료 칸은 0 이다. 몇 줄이고 실행기 거짓 빨강 거리가 정적으로 0 이다.

**한계 문장 또는 기록으로 간다.**
- (a) 방향이 빨강 쪽뿐이면(측정 멈춤 · 판독 0) 기록만 한다(A2).
- (b) 지워 숨기기 · 상주 프로세스 · 저장소 내부(개체 · 팩 · 뿌리 `.git` 바꿔치기)는 같은 실행기 악의다. 한계 단락 기존 범주에 들면 새 문장 0. 안 들면 문장을 쓴다.
- (c) 진단 · 글자 정밀도뿐이면 새 머리를 만들지 않고 다음 머리 때 같이 고친다.
- (d) 실행기에서만 잴 수 있으면 리허설 확인 목록에 넣는다.
- 단, 공개 문장이 사실보다 넓으면 공개 전에 언제나 고친다(F10 선례). 이것만으로 새 머리가 생기면 재셈은 글자 대조만 한다(바뀐 줄 ↔ 코드 사실 · 무변 셈). 같은 계열의 새 우회는 찾지 않는다.

**순환 끊기.** K2⁷ 재셈부터 새 머리 사유는 ㉠(ⅰ) 하나뿐이다. ㉠(ⅱ) 는 이번 한 번으로 닫는다. ㉠(ⅰ) 이 또 나오면 PM 은 고치기 전에 CTO 재판정에 올리고, 대표 주간 보고에 회차를 적는다.
