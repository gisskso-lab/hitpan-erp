## 3. 과장 (잰 범위보다 넓게 쓴 곳)

- **§2-5 「그 밖 시험 · 잡 — 그대로」** — 변이 런 build 잡은 시험 단계 172 · 3358 까지만 돌았다. 정상 런(시도 1 · 5 표본)에서 도는 뒤 시험 단계 399 · 3 은 앞 단계 실패로 **돌지 않았다**. 「빨강은 위 2건뿐」 은 「돈 시험 안에서」 로 좁혀야 맞다(F2).
- **§2-5 첫 줄 괄호 「1차 지적 『기존 변이 ≠ 최종 SHA』 에 대한 답」 · §8 #5** — 이번 변이는 자동발주 가드 하나만 잰다. 다른 15 가드의 1차 변이(#1004)는 최종 머리 재실행이 아니다(원고 §2-5 끝 줄이 스스로 밝힘). 괄호와 질문을 「자동발주 가드에 한한 답」 으로 좁힌다(F3).
- **§2-3 「발주 두 표가 임시 표로 가려졌는지 먼저 확인」** — 실제 단언은 두 표가 가림 루프와 같은 선택식(시험 DB 기본 표 · FULLTEXT 0)에 드는지일 뿐, 가린 임시 표 자체를 세지 않는다. 내부 고침 대조 P3-4 도 「간접 증명」 으로 적었다(F4).
- 그 밖 「0」 · 「없음」 은 잰 범위를 함께 적었음(§7 「0 은 검사한 패턴 한정」 · §2-6 build 잡 미측정 · §3 X3 · X4 미확인) — 🟢.

## 5. 빠진 것 (먼저 밝혀야 할 위험)

- **X1 ~ X5 의 이관처 · 기한 없음** — 원고는 「우리 쪽 대장 몫」 으로만 적었다. 결재 기록 §259 · §260 에 이미 대장 줄이 있다: X1 · X2(재고 조정 · 원장 INSERT ONLY 오염) = **W-G1-51-후7 · 고객 첫 설치 전(우리 쪽 대표 결재)** · X3 ~ X5 = **후8 · 베타 전**. 1차는 범위 밖마다 대장 번호 · 기한을 적었다. HQA 가 §8 「1-덧」 을 판정하려면 이 글자가 있어야 한다. 특히 X1 은 P1 과 같은 꼴(요청 품목 id → 지울 수 없는 원장)이라 기한을 숨긴 것으로 읽히면 두 번째 반려 사유가 된다(F5).
- **변이가 보여 준 「실제 길」** — 가드 없는 판에서 섞인 후보가 예외 없이 끝까지 갔다(고침 대조 §5 덤). HQA 1차 판정의 「타사 품목이 실제 저장된 사례는 측정하지 않음」 에 대한 우리 쪽 관찰이다. 인정(§2-1) · 실물 데이터 미측정(§9 ⑤)과 이어지므로 추정 꼬리표를 달아 밝힌다(F6).
- 덧(막지 않음): §9 ⑨ — 먼저 밝힌 것 맞음 · 안 고치는 판단 맞음(시험 코드 · 심각도 note 2 · warning 1 · 동작 영향 0 · 고치면 판정 대상 SHA 가 또 바뀜 · 새 코드의 같은 꼴 2건은 이미 고침). 줄 번호 하나와 번호 순서만 틀림(F1).
