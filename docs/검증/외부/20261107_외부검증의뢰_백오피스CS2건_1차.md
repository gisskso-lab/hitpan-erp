## 🔴 부탁
- 이 레포는 공개다. 검토 중 **이 범위 밖**의 결함을 보시면 공개 댓글에 파일 · 줄 · 재현을 적지 말고 「범위 밖 발견 N건 — 비공개 전달 요청」 한 줄만 남겨 주십시오.
- 권한은 **의심 제기**뿐입니다(판정 · 수정 · 게시 없음).
- 기준 SHA 에는 우리 쪽 판정 문서(검토서 · 이슈 기록 · 명세서 · 대상 확인 기록 등)가 함께 있습니다. **그 문서들은 읽지 말고 아래 코드 · 런 원본 · 참조 한 개로만 판단**해 주십시오.
- **회신 머리에 세 줄**(질문이 아니라 요청):
  1. 우리 판정 문서를 열었는가 — 열었다면 어느 것.
  2. 기준 SHA 밖(다른 커밋 · main)을 읽었는가 — 읽었다면 무엇.
  3. 범위 밖 발견 N건 — 비공개 전달 요청(없으면 0).
- 회신 자리 = 이 의뢰서를 올린 PR 의 댓글.
- 시간이 모자라면 ⓐ → ⓑ → ⓒ 순으로 봐 주십시오.

## 질문 (세 가지 · 하위 물음 각 4개 이내)
- **ⓐ 인가 · 노출**
  1. 새 입구 · 목록 인자가 본사 관리자 밖 주체에 열리는 길
  2. 응답 · 오류 응답 · 로그가 작업지시서 §5 보다 많이 내놓는 길
  3. 고객사 값이 SQL 글자로 들어가는 길
- **ⓑ 거름 정확성**
  1. 숫자와 목록이 같은 규칙인가
  2. 다른 고객사가 섞이는 길
  3. 인자 없음 · 없는 고객사일 때 응답이 §5 와 다른가
  4. 주소 해석기가 고객사 화면 아닌 주소를 고객사로 읽거나 그 반대
- **ⓒ 대조군 실효**
  1. 질의 시험이 거름을 빼거나 바꾼 구현에서도 통과하는 자리
  2. 해석기 시험이 새 글자 주소 화면을 놓치는 길
  3. 시드가 갈리는 값을 갖는지 시험이 먼저 단언하나
