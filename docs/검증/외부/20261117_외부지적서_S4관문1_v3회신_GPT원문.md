대상: 사전 공개 #6921734895(11/17 01:05 KST), 기능 `16e88c01092d33eb643c6cac454703f00efa02ac`, 시험 앱 `88085da1d797b915b8e8be314517af180d0b9939`, 공개 검토 장치 `ae0115c6577a95773267fcaf0a423c498080ec12`. HQA는 v3 공개 원문과 장치 `rules.json`·`judge.js`·`items/i-items.js`를 **읽기 전용**으로 대조했습니다. 장치의 Linux 실측·원자료 대조·장전 재현은 **수행하지 않았습니다.** 이 답변은 *사전 설계의 조건부 수용/보류 의견*이며 관문 합격·CTO 결재·머지 승인과 다릅니다.

### Q-H별 회신

- **Q-H1 — 예(조건부):** I-4는 `mouse-open=/before`와 `kbd-open=e1t3`를 분리해 읽고, **양쪽 모두 대조 성립**해야 항목 성립으로 판독하는 구조를 수용합니다. 어느 한쪽이라도 장치 실패/대조 무효라면 전체 I-4 성립으로 처리 금지. 사전 공개의 경우별 집계와 장치 `fourCells`·`stateOf` 경로를 확인했으나 실행 검증은 아님.
- **Q-H2 — 예(조건부):** 11/7 작업지시서 L306의 공백 상태 칸 회귀를 T3의 **정의**로 수용하고, I-8 대조 성립은 *공백 꼴(blank)만* 판정 입력으로 삼는 `item`을 허용합니다. 단 **빈 문자열·null의 After 기대(상태 칸 표시)는 삭제되지 않습니다**. 이 두 꼴은 명시적 미판정/관찰 항목으로 남기고 정상으로 간주하지 마십시오. 장치 규칙 `t3ReadUnit=item`과 `device.i8.itemKind=blank` 확인.
- **Q-H3 — E1T3 예(조건부), V2 예(조건부):** E1T3는 **I-4 키보드 경우에만**, V2는 **I-8 T3에만** 사용. A2는 기존 HQA 의견대로 **N-1에만** 허용. 화면 blob·동일 시험 앱·절차/브라우저 차이를 구분하고, 범위를 임의 확장하거나 다른 대조판으로 전환 금지. 비교판 수용 ≠ 해당 항목 대조 성립 또는 합격.
- **Q-H4 — 아니오(보완 필요):** e1t3 키보드 지연 0·150·300 세 칸은 과거 결과가 노출되었고, **'한 칸이라도 재현'** 규칙이라 이미 알려진 300ms만으로 대조 성립을 얻을 수 있습니다. 단순 `exposed` 표시와 신판 원자료 재측정만으로 독립성 제약을 해소했다고 판단하지 않습니다. **기존 3칸은 원자료 그대로 보존·공개하고 독립 판정에는 노출 제약을 명시**하십시오. 노출 칸만으로 I-4 전체 합격을 확정하지 말 것. 추가 미노출 재현 증거가 필요하면 자극/표본/조건의 *사전 고정 변경안*을 대표에게 별도 상신하십시오. 본 의견은 이미 결재된 첫 회차 자체의 삭제 명령이 아닙니다.
- **Q-H5 — 예(조건부):** `per-direction-ms`, 각 방향 0/150/300, N-1 500은 기존 HQA 측정의 방향당 단위와 부합합니다. `delay-proxy.js` 실제 적용 경로와 `run.json`의 양방향 실제 기록은 장전 원자료에서 검증. **N-1 500ms 원래 단위는 공개본도 미확정**이므로 '완전 동등'이라고 선언 금지.
- **Q-H6 — 예(조건부):** 열린 메뉴 관측→700ms 유지→Esc, 열림 미관측이면 Esc 입력 없이 장치 실패 처리를 허용. 실제 `items/i-items.js`에서 해당 순서를 정적으로 확인했습니다. 판정 전에 입력·관측 시각과 `actualWaitMs`를 대조합니다.
- **Q-H7 — 예(실행 선택값 한정):** 관측·polling 50ms를 **개발팀 사전 고정 실행 선택값**으로 수용합니다. 과거 HQA와 동일한 관측 해상도라는 증거는 아니므로 해상도 차이와 실제 간격은 남기십시오. 결과를 본 뒤 간격을 바꾸면 새 회차.
- **Q-H8 — 예(잔여 위험 명시):** 기다림 중 읽기 0, Esc 직전 1회 판독은 관찰자 간섭을 줄이는 설계로 조건부 수용합니다. **중간 순간 닫힘→재열림 및 직전 읽기와 실제 Esc 사이 경합은 감지하지 못합니다.** 장전에서 의심되는 표본은 자동 합격 금지, 관측 원자료로 HQA가 판정.
- **Q-H9 — 예(조건부):** Esc 후 메뉴 0 관측→최대 3초 초점 polling, 키보드 경우 메뉴 0 미관측을 장치 실패로 수용합니다. 마우스 경우는 Q-H12와 분리하여 읽습니다. '한 번이라도 복원'은 최종 초점 유지의 증거와 다르며, 최초 복원 시각 및 끝 상태를 보존하십시오.
- **Q-H10 — 아니오(정본 전범위 충족으로는 불수락):** Enter만 측정·Space 미측정 **사실 기록 자체는 허용**하지만, 11/7 정본의 Space/길게 누름 경로는 이 회차에서 확인되지 않습니다. 90분 한도를 이유로 생략했다고 **전 항목 합격**으로 간주하지 않습니다. 이번 회차를 증거 수집 회차로 진행하려면 Space 미측정의 영향과 별도 후속 회차 계획을 대표에게 보고하고, 최종 관문 미통과 제한을 유지하십시오. Space를 억지로 추가해 90분을 넘기는 것도 승인하지 않습니다.
- **Q-H11 — 아니오(판독 식 동등성 미확정):** 소스상 동등하다는 설명은 검토했지만 컴파일된 MudBlazor DOM과 실행에서 두 식이 **항상 같은 값을 낸다는 실측이 없습니다**. 한 polling에서 두 식 모두 기록하되, 두 식이 불일치하면 장치 식 하나만으로 통과 판독 금지(불일치 표본 식별·HQA 검토). 식 변경은 별도 결재.
- **Q-H12 — 예(조건부):** mouse-open에서 메뉴 0 미관측을 `/before`의 '열림 남음' 실패 재현값으로 보존하는 것은 대조 목적상 타당합니다. 다만 Before/After에 **동일한 관측 시간창**을 적용하고, 3초+2×지연 확장이 원래 HQA 절차와 *완전 동등*하다는 주장은 금지합니다. window 차이·관찰 시각은 공개하고, After 정상성을 판정할 때 긴 창이 실패를 가리는지 별도 점검.
- **Q-H13 — 아니오(동등 조건으로는 불수락):** 과거 headless-shell/Edge 1280×900과 현재 릴리스 Chrome 1280×720의 차이가 명시되어 있습니다. **이번 회차의 새로운 독립 증거로는 읽을 수 있으나 과거 실패/수정 결과와 동일 조건 재현으로 인정할 수 없습니다.** 1280×900 동등 조건 확인이 필요하면 별도 재상신·사전 고정하십시오. 현 1280×720 결과를 과거 측정의 그대로 재현한 것처럼 쓰지 말 것.
