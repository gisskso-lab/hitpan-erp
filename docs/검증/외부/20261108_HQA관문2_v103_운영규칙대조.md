## 3. 보완 요청 (HQA 판단 · 받아쓰기 아님)
- **G2-1 닫힌 뒤 초점 판독 방식** — 9.3 Esc 길(`CloseAllMenusAsync`)은 「목록 지우는 그리기」 를 먼저 보내고 「단추 초점」 을 뒤에 보낸다(9.3 원문 `MudMenu.razor.cs` `CloseMenuAsync` 끝 `StateHasChanged`(L550 호출 안) → L553 `FocusActivatorAsync` · [CTO 판정](../백오피스/20261108_S4_F12_CTO대조판정.md) §1-2). 고침 A 도 같다. 모듈은 목록 0 을 본 **바로 그 순간 1번** 읽으므로 두 사이에 읽으면 거짓 빨강이 난다. 관문 ① 은 3초 polling 이었고, CTO 조건 C2 로 이제 「단추로 온 뒤 3초 유지」 까지 본다 → 관문 ② 도 **3초 안 단추 도착 + 도착 뒤 3초 유지** 로 맞추기를 제안한다(Tab · 좌표 읽기 범위 안).
- **G2-2 「아래쪽 줄」** — 마지막 적격 줄이 화면 아래쪽이 아닐 수 있다(아래 줄들이 「안 읽음」 이면). 대표 반려 S4 는 **아래쪽 줄**이었다. 대상 줄의 `y / 창 높이` 와 전체 줄 중 몇 번째인지를 함께 찍어 「아래쪽 줄을 쟀는지」 가 출력에서 보이게 하기를 제안한다(좌표 읽기 범위 안 · 고객 정보 0).
- **G2-3 다시 누름 = F13 틈** — Enter 로 다시 연 뒤 목록이 보이자마자 꼬리표를 누른다. 이는 대표가 별건으로 고치라 한 F13(키보드로 연 직후 틈의 다시 누름 → 초점 `BODY`)과 같은 길이다. 지금 모듈은 닫힘만 보고 초점은 안 읽어 그 결함이 PASS 뒤에 숨는다. 데이터 영향은 0 이다. 다시 누름 뒤에도 G2-1 과 같은 초점 판독을 넣기를 제안한다(F13 고침판 기대 = 단추).
