1. **표본 단위 장치 실패로 생긴 빨강의 성격** — 표는 단계 실패와 verdict 빨강만 가른다. F5 · F15 사실만 적는다. 원인 **가설**: (가설 1) 시험 앱 after 화면에서 1행 상태 칩이 없거나 가려져 클릭할 수 없다 = 제품(시험 앱) 쪽 · (가설 2) 항목 스크립트의 클릭 대상이 after 화면 꼴과 맞지 않는다 = 장치 쪽. 어느 쪽인지 원자료만으로 가르지 않았다(그림 66 장 확인 · 시험 앱 after 꼴 대조 전).
2. **P-f 대조 기준값이 원자료에 없음** — P-f 는 「원자료 `run.json` `mask_verdict` 로 가름」 · 분기 1 기준 = 「`verdict_sha256`」(L55 · L56). 둘 다 `run.json` 안이라 빠졌다. 그래서 P-f 1 ~ 3 중 어느 분기인지 **표대로는 가를 수 없다**. 로그에 남은 값(측정 잡 L1334 M8′ 줄 · L1365 회차 줄 요약)과 `SHA256SUMS.raw` 의 `verdict-device.json` 줄은 사실로만 적고, 대신 쓸 기준으로 정하지 않는다 — 기준을 정하는 것은 HQA 몫.
3. **publish 기대 파일 검사가 꺼진 채 지나감** — `run.json` 이 빠지자 `selftest-judge.json` 상태가 `no-run`(F9 L609 · F10 L31)이 되어 장전 빨강 검사(L86)가 돌지 않았다. 이번에는 `selftest-judge.json` 이 원자료에 있어 잃은 것 0(F11). 장치 기록 사실로만 공개.
4. **빠진 `run.json` 은 측정 런 아티팩트에는 남아 있음** — 아티팩트는 publish 재검 **전** 묶음이다(F8 · F9). 회차 줄은 M9 뒤에 붙어 측정 단계 누출 검사를 거치지 않는다(F16) · 리허설 런은 판독 0 이라 회차 줄 판독 칸이 처음 채워졌다. long-token 의 정체 **가설**: 회차 줄에 처음 들어간 64자 해시 칸(`verdict_sha256` 등)이 허용 문맥 밖이라 걸림 = 비밀 아님. **값 확인 전에는 가설** → 확인 필요(§6).
