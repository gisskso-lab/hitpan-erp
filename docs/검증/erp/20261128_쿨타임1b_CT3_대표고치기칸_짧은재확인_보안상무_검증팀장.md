## 2. 꾸밈 · 옛 토큰 · 자식

- **자식이 account_type 을 꾸미는 경우**: 브라우저 토큰을 고치면 화면은 열리지만 서버는 서명을 다시 검증한다 → 401/403. 화면 값은 표시용(`HrAttendancePage.razor:322` 주석과 같음). 서버 권한이 넓어지지 않음. **문제 없음.**
- **자식 계정**: `IsTenantAdmin` = false(클레임이 없으면 `tenant_user`, `AccountTypeHelper.cs:12-13`) → 전과 같은 `HR_PROXY` 수정 판정. **변화 없음.**
- 🟡 **정보 ①: 옛 대문자 "TenantAdmin"이 화면과 서버에서 다르게 판정됨**: 화면 `AccountTypeHelper.IsTenantAdmin`(`src/HitPan.Web/Helpers/AccountTypeHelper.cs:31-35`)은 `"TenantAdmin"` 도 대표로 보지만, 서버 Layer 0(`PermissionService.cs:263`)은 소문자만 본다. 이론상 `users.account_type` 에 대문자 값이 있는 행이면 「화면만 열리고 서버 403」이 된다. 다만 발급 · 저장 코드는 소문자만 쓰고 출하 DDL 기본값도 `tenant_user` 다(`installer/hitpan_db_clean.sql:4394`). 대문자 `TenantAdmin` 은 `role` 컬럼 값이다(`DB-03_test_accounts.sql:19-20`). 그래서 실제로 생길 길은 찾지 못했다. 같은 도우미를 쓰는 다른 화면에도 원래 있던 꼴이라 이번 커밋 범위 밖이다. 등급 = 정보(대장 후보).

## 3. 같은 화면 판정 · 설계 · 헌법

- `CanEditTarget`(`HrAttendancePage.razor:336-337`) = `_canEditCheckOut && IsEditableSource` → 「자동」 출처만이라는 조건(C-5 앞 절)은 그대로다. 안내 분기(`:165-168`)도 그대로.
- 🟡 **정보 ②: `_canProxy` 와 판정이 어긋남**(`:268-270`): 대표 화면에서 대리 출근 카드(`:34`)는 계속 숨는다(HR_PROXY 만 봄). 서버는 대표를 허락하므로 「되는데 안 보이는」 쪽(안전 쪽)이다. 커밋 메시지도 범위 밖 · 대장 후보라고 밝혔다. 등급 = 정보. 한 화면에서 두 판정이 달라 처음 보는 사람이 헷갈릴 수 있으니 다음 차수에서 결재받기를 권한다.
- 설계 C-5(`docs/설계/erp/쿨타임_자동로그아웃_설계_20260928.md:189`)는 「권한 = HR_PROXY · 새 권한 없음」이다. 이번 고침은 새 권한을 만들지 않았고, 서버에 원래 있던 부모 전권(Layer 0)을 화면에 비춘 것뿐이다. **어긋남 없음.**
- 헌법 #7: `tenant_admin` 은 ERP 계정 계층(부모/자식 · #38)이지 SaaS 계층(본사 · 대리점)이 아니다 → 위반 아님. #11: 업종 · 규모 템플릿이 아니고 어드민 권한 설정도 우회하지 않는다(자식은 여전히 어드민 설정을 따름) → 위반 아님. #2: tenant · user 는 JWT 에서만 → 지켜짐. #1: 옛 줄을 ⬛ 주석으로 남김 → 지켜짐.
- 기존 게이트 `src/HitPan.Tests/Integrity/AttendanceProxyGuardTests.cs` 는 `_canEditCheckOut` 식을 고정하지 않는다 → 깨지는 게이트 없음(실행 확인은 CI 몫).
