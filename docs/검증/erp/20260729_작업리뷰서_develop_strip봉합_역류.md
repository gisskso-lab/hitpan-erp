## 4. 발견 — 병렬이슈 01 판정

**[3-V] 보안상무가 적발한 regex 비대칭을 검증팀이 독립 재현했다.**

`appsettings.Production.json.bak` → strip **미제거** / 게이트 **차단** → 배포 fail.

### 이게 작2 통과를 막는가 → **막지 않는다**

| 근거 | 내용 |
|---|---|
| ① | 작2 완료 판정 기준은 **"main 과 동형"**이다. 이 결함은 **main 에도 동일**하므로, 동형을 달성한 시점에 작2 목표는 충족됐다 |
| ② | 여기서 고치면 **동형이 깨져** 작2 판정 자체가 불가능해진다 |
| ③ | **안전측 실패** — 시크릿이 유출되는 게 아니라 배포가 멈춘다. P2 타당 |
| ④ | 발현 조건 실측 **0건** (`.bak`·`.old` 파일 없음) |

### 🔴 단, 이관은 필수 조건

**별도 작업지시서로 반드시 이관한다. main·develop 동시 적용이 전제다.**
develop 만 고치면 작2 가 없애려던 브랜치 갈림을 새로 만든다.

> **적발 자체를 높이 평가한다.** 작업이 끝난 뒤였다면 "동형 확인 ✅"로 통과됐을 건이다.
> [3-V] 가 **동시에** 돌았기 때문에 잡혔다 — 루틴 설계 의도대로 작동했다.
