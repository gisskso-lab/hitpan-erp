## 2. 🟢 작11 전제 — 실측으로 확증됨

### 2-1. 대표는 권한이 전부 `false` 인데 확정 API 를 통과한다

`GET /api/permissions` 실측 — 대표 계정의 `DELIVERY` 권한:

```
"menuCode":"DELIVERY" canView:false canCreate:false canUpdate:false canDelete:false canExport:false
```

그 상태로 확정 4곳 호출:

| 엔드포인트 | HTTP | 의미 |
|---|---|---|
| `sales/deliveries/{id}/confirm` | **400** | 인가 통과 → 업무로직 도달 |
| `purchase/receipts/{id}/confirm` | **400** | 인가 통과 |
| `purchase/returns/{id}/confirm` | **400** | 인가 통과 |
| `sales/returns/{id}/confirm` | **400** | 인가 통과 |

🔴 **403 이 하나도 없다.** 권한이 전부 꺼져 있는데 **아무것도 막지 않았다.**
(400 = 없는 문서ID 라서 업무로직이 거절한 것 = **인가는 이미 통과했다는 뜻**)

🟢 **설8 §2-2 Layer 0 주장이 살아 있는 시스템에서 확증됐다** —
JWT 실측 `"account_type":"tenant_admin"` ⇒ `PermissionService.cs:236-244` 무조건 통과.
⇒ **대표 락아웃 없음**(작11 G-3 선확인).

### 2-2. 🔴 메뉴코드 정정이 실물로 확인됐다

`GET /api/permissions` 가 돌려준 코드 **21개** 실측:

```
ACCOUNTING APPROVAL BOM CERTIFICATE COLLECTION DASHBOARD DELIVERY HR HR_PROXY
ITEM LEDGER MONTHLY_CLOSING PARTNER PAYMENT PURCHASE PURCHASE_ORDER QUOTATION
SALES_ORDER SETTINGS STOCK USERS
```

🔴 **`SALES` 없음** · 🟢 `DELIVERY` 있음 · 🟢 `PURCHASE` 있음
⇒ 설8 초안(`SALES`)이 틀렸고 작11 정정(`DELIVERY`·`PURCHASE`)이 **맞다**.
   소스가 아니라 **돌아가는 API 응답**으로 확인했다.

## 3. 🟢 작10 A (근태 대리입력) — 실측 통과

### 3-1. `HR_PROXY` 가 실물에 있다

권한 목록 응답에 **`HR_PROXY` 존재 확인**. 1.3.0 배포본에 실제로 실렸다.

### 3-2. 🚨 테넌트 격리 — [3-V]가 뚫었던 그 자리

인수인계서 §1-2 ②: *"`tenant_id` 를 빼 테넌트 격리를 뚫었는데 5/5 통과"* —
**문자열 시험이 못 본 자리**를 실물로 확인했다.

| 입력 | 응답 | HTTP |
|---|---|---|
| **남의 회사** `employee_id`(존재하지 않는 GUID) | *"대상 직원을 찾을 수 없습니다"* | 400 |
| **자기 회사** 유효 `employee_id` | *"오늘 이미 출근 처리되었습니다"* | 400 |

🔴🔴 **이 두 줄이 핵심이다.** 둘 다 400 이지만 **메시지가 다르다.**
- 남의 것 → **격리 가드에서 걸렸다**(대상 조회 실패)
- 자기 것 → **격리를 통과하고 업무규칙에서 걸렸다**(중복 출근)

⇒ 가드가 **아무거나 다 막는 게 아니라 소속을 실제로 본다**는 뜻이다.
   같은 400 만 봤으면 *"그냥 다 실패하는 것"* 과 구분 못 했다 — **대조가 판정했다.**

### 3-3. 🟢 자동 근퇴가 살아 있다 (회귀 없음)

자기 회사 사원 대리 출근이 *"오늘 이미 출근 처리되었습니다"* 로 거절됐다.
⇒ 오늘 이미 출근 기록이 있다 = **로그인 시 자동 출근(`AuthController.cs:236-258`)이 돌았다.**
⇒ 인수인계서 §5-3 *"자동 근퇴 여전히 정상 — 회귀 없음"* **확인**.

### 5-1. 🔴 미1 이 가장 중요한데 막혔다

작11 의 **진짜 근거**는 *"`sales_user` 가 확정할 수 있다"* 이다.
지금 실측한 것은 *"**대표**가 권한 없이 확정 API 를 통과한다"* 이고,
대표는 **원래 통과해야 맞다**(Layer 0 · 락아웃 방지).

⇒ 🔴 **대표 실측은 작11 을 증명하지 않는다.** 소스 근거(`Program.cs:335-343` 에
   `sales_user` 가 `SalesOnly` 에 포함)는 그대로 유효하나, **실물 확인은 아직이다.**
   ⚠️ 이것을 *"실측 완료"* 로 적으면 **거짓봉합**이다.

**막는 것**: 비대표 계정 생성 = 테넌트에 **쓰기**. 사장님 판단 필요.
