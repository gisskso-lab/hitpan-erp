### 10-3. PI-1 전제 오류가 게시 판단에 주는 영향

사실(코드 판독 · 두 판 대조): 1.3.46 `storage.js:4` `SESSION_KEYS = {'access_token','refresh_token'}` · C# 칸 이름은 `hitpan_*` ⇒ **1.3.46 도 토큰은 localStorage.** 따라서:

1. **§7 1~4번(R-1~R-4 로그인 유지)의 기대값 「유지」는 새 판에서 여전히 맞다.** 그러나 **1.3.46 대조군도 「유지」다** — 이 네 줄은 「PI-1 P0 봉합 증거」가 아니라 **회귀 확인**으로 읽어야 한다. 대조군 기대 칸이 따로 있다면 「1.3.46 = 유지(차이 없음)」로 고친다. 1~4번이 「로그인 화면」으로 나오면 원인은 저장소가 아니라 **갱신 경로(절P·I·S)** 쪽이다 — 되돌림 판단은 그대로.
2. **§7 0번 기대값이 틀렸다** — 「Local Storage 에 `access_token`」: 실제 칸은 `hitpan_access_token` 이고 **1.3.46 에도 있다** ⇒ 새 판 도착을 못 가른다. 정정: Sources `js/storage.js?v=20260928b` + 로그인 뒤 Local Storage 에 **`hitpan_token_store_v2` = 1**(새 판에서만 생긴다).
3. **§7 비상 줄 「1.3.46 재게시 … 사용자 1회 재로그인」은 틀렸을 공산이 크다** — 1.3.46 도 같은 칸(localStorage `hitpan_*`)을 읽으므로 되돌려도 로그인이 이어진다(⚠️ 판독 기반 · 실물 미측정). 「재로그인 1회 가능성」 정도로 낮춘다.
4. **[5] 에 올릴 사실** — K-6 (가) 「대가: 공용 PC 에서 로그아웃 없이 닫으면 다음 사람이 앞 계정으로 열린다(상한 7일)」는 **새 위험이 아니다. 4/24 `7f285b96` 부터 이미 그랬다.** 사장님은 새로 수용한 것으로 알고 계실 수 있다 — 결재 문구를 「기존 상태 확인」으로 고쳐 올린다. 절H 는 실제 칸에 대해 동작 변화가 없다; 이 PR 의 실질 변화는 절I(탭 간 잠금)·절P(401 만 지움)·절S(비교 후 지움)·서버 차단 켜기다.
