  - 화면은 `_coords.Any(c => !string.IsNullOrWhiteSpace(c.Key))` — **Key 만** 본다.
  - 서버는 `FieldCoords.Count > 0` 이고 그 목록은 `ParseFieldCoords`(`:2540`)가 만드는데 **세 겹으로 버린다**: `key` 가 비면 `continue` · `x`·`y` 가 없으면 `continue` · 종이 밖(>420·>594)이면 버린다.
  - ⇒ 🔴 **키는 있는데 x·y 가 빈 행만 있는 양식**: 화면은 「위치를 맞춰 두셨기 때문에 A4 세로로 인쇄됩니다」라고 **거짓 안내**하고, 서버는 `useCoords=false` 라 **A5 를 그대로 낸다**. 화면 말과 종이가 반대다.
  - 🟢 음성 대조군: 키·x·y 가 다 있으면 양쪽이 일치한다(화면 경고 + 서버 A4). 🟢 빈 Key 행만 있으면 **양쪽 다 「좌표 없음」** 으로 일치한다(내가 2차에 걱정한 방향은 **문제 없음**).
  - 고치는 방향: 화면 조건을 `Key` + `x`·`y` 셋으로 맞추거나, 판정을 서버 한 자리에서 받아 쓴다.

## 6. 🔴 통과로 적지 않는 것 (미측정)

1. **사람 눈으로 종이 본 적 0회** — 열한 차수 연속. 법정 가드·좌표 가드가 실제 종이로 확인된 적 없다.
2. **브라우저에서 그림을 올려 본 적 0회** · **화면에서 `PaperChoiceIgnored` 안내를 눈으로 본 적 0회** — razor 는 **글자 대조와 빌드**까지만 쟀다.
3. **실제 전표 PDF 의 MediaBox 0회** — 축⒣ 는 여전히 작성기를 안 탄다(한계 명시는 인정).
4. **축⒤ 가 CI 에서 도는지 0회** (T-2) · **뿌리 junction 을 실제 `%ProgramData%` 에서 만들어 본 적 0회**(운영 무접촉 · 합성 뿌리로 의미론만 쟀다 — T-1 재현 절차는 가설).
5. **걷어내기 누출이 축⒢ 를 실제로 거짓 초록으로 만드는지 0회** (T-3).
6. **`ParseFieldCoords` 가 빈 Key 를 거르는지 0회** (T-5) · **면세계산서·입금표 법정성 판정 0회**(법무 몫).
7. **DB 실측 0회** · **고객 루틴(설치파일→라이선스키→자동업데이트→터널 도메인) 0회** — 개발PC 정상은 검증이 아니다.
8. **기존 157 실패는 묵은 빨강**이고 내가 가리지 않았다 — 대조는 「실패 수가 안 늘었다」까지다.
