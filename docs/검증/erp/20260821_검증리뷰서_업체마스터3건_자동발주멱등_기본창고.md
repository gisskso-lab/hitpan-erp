## 1. 🔴 W4 대조실험 — 게이트가 진짜인지 (feedback_gate_must_test_behavior)

**글자검사 금지.** 필터를 **빼고** 같은 데이터로 실행해 결과가 달라지는지 확인했다.

| 시나리오 | 필터 없음 (대조군) | 필터 있음 (운영) |
|---|---|---|
| C1 미결 자동발주(`ordered`) | 나옴 | ❌ **사라짐** |
| C2 발주 없음 | 나옴 | ✅ 나옴 |
| C3 `cancelled` 만 | 나옴 | ✅ 나옴 (재발주 가능) |
| C4 `partial` | 나옴 | ❌ **사라짐** |
| C5 수동발주(`is_auto=0`) | 나옴 | ✅ 나옴 |
| C6 타테넌트 발주 | 나옴 | ✅ 나옴 (누수 없음) |
| **합계** | **6건** | **4건** |

**6 → 4.** 필터가 실제로 거른다. 가짜 봉합이 아니다.

### 🔴 음성 대조 — 테넌트 조건이 장식인지 확인
`poi.tenant_id = i.tenant_id` 를 **일부러 제거**한 쿼리를 돌렸다.
→ C6(타테넌트 발주)이 결과에서 **사라졌다** = 크로스테넌트 누수 실제 발생.
→ 운영 SQL 은 C6 을 정상 반환.

**tenant_id 조건이 실제로 일하고 있음을 반증으로 입증** (§#2).

### 왕복 검증
`CreateAutoOrdersAsync` 가 실제 쓰는 값(`status='draft', is_auto=1`)이 제외 집합에 들어간다.
그 INSERT 를 재현하니 해당 품목이 후보에서 **즉시 사라졌다.** 쓰기와 읽기가 맞물린다.

### 성능
`idx_poi_tenant_item (tenant_id, item_id)` 를 `ref` 로 탄다 (rows=1). 풀스캔 아님.

## 2. 🔴 W6 유령창고 회귀검사 (10차 P0-4 재발 여부)

이 프로젝트는 과거 실재하지 않는 `warehouse_id` 가 `item_stock`·`stock_ledger` 에 기록되어
재고 정합이 깨진 사고가 있었다. **이번 변경이 그것을 되살리는지**가 최대 위험이었다.

6개 품목 동시 투입 → 헬퍼 SQL 1회 실행 → **유효 1건만 반환**:

| 위험 케이스 | 결과 |
|---|---|
| 존재하지 않는 창고 ID | ✅ 걸러짐 (JOIN 미매치) |
| `is_active=0` 비활성 창고 | ✅ 걸러짐 |
| **다른 테넌트 창고** (§#2) | ✅ 걸러짐 |
| 빈 문자열 | ✅ 걸러짐 |

**인과 확인**: `is_active=1` 로 켜니 반환 → `0` 으로 끄니 사라짐.
조건이 우연이 아니라 **실제로 판정하고 있음**을 토글로 입증.

⇒ **10차 P0-4 유령창고 사고는 재발하지 않는다.**

### 대조실험
| 국면 | 반환 |
|---|---|
| 기본창고 설정 | 해당 창고 반환 |
| 같은 품목 `NULL` 로 변경 | **0행** → 테넌트 폴백으로 감 |
| 복원 | 재출현 |

**상태를 바꾸면 결과가 달라진다** — 헬퍼가 일을 한다.

### 부가 확인
- **빈 `IN ()` 가드 필요성 입증**: 가드 없으면 `ERROR 1064` 하드 실패.
  라인 전체에 창고가 지정된 **정상 매입에서 500** 이 난다. **가드 제거 금지.**
- 빈 문자열은 DB 가 그대로 받으므로 코드의 NULL 정규화 + SQL 의 `<> ''` **이중방어가 둘 다 필요**

## 4. 🔴 미검증 — 완료로 보고하지 않는 것

지오코딩 코드는 작성·빌드됐으나 **한 번도 실행되지 않았다.**
- 실제 좌표 반환 형식 미확인
- `x`=경도 / `y`=위도 매핑 **미검증** (뒤바뀌기 쉬운 자리다)
- 폴백 `kakaomap://search?q=` 는 **문서가 상충** (안드로이드=선택 / iOS=필수) — 실기 확인 필요

### 4-2. W2 이메일 실수신
버튼·다이얼로그 배선은 됐으나 **실제 메일 수신 미확인**. SMTP 설정된 환경 필요.

### 4-3. W3 팩스 실송출 — 검증 불가 (설계된 상태)
벤더 미결이므로 실송출 경로가 존재하지 않는다.
**Mock 이 `Success=false` 를 돌려주고 화면이 보내기 전에 경고**하는 것까지가 이번 범위.

> 이것은 **미완이 아니라 정직한 미완**이다. 성공을 위장했다면 그것이 결함이다.

### 4-4. 백지환경 종단
개발PC 빌드·DB 검증만 했다. **개발PC 정상은 검증이 아니다** (feedback_dev_pc_proves_nothing).

## 5. 🔴 사장님 판단 필요 — 수동발주 중복

멱등 필터는 `is_auto=1` 만 제외한다. **수동발주는 통과**한다.
⇒ 담당자가 수동 발주한 직후 자동발주가 **한 번 더** 나갈 수 있다.

사장님 오더는 *"자동발주 클릭한 항목"* 의 중복이었으므로 **오더 범위 밖**이라 손대지 않았다.
막을지 말지는 현장 판단이다 — 막으면 재고 부족 위험, 안 막으면 중복 위험.

**결재 전 확인 권고.**
