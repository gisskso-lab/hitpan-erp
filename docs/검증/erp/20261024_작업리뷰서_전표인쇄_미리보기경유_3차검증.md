## 3. 반려 항목 — 재현 조건 → 틀린 결과

### 3-1. (먼저) DDL 정합은 참이었다 — 출하 DDL 실측

`installer/hitpan_db_clean.sql` 에서 직접 뽑은 칸 목록. PM 이 쓴 칸이 **전부 있다.**

- `purchase_returns` : return_id tenant_id return_no receipt_id partner_id return_date return_type status **total_amount vat_amount memo** … ✅
- `purchase_return_items` : **return_item_id return_id tenant_id item_id qty unit_price supply_amount vat_amount** warehouse_id memo ✅
- `sales_returns` : return_id tenant_id return_no delivery_id partner_id return_date return_reason status **total_amount vat_amount memo** … ✅
- `sales_return_items` : **return_item_id return_id tenant_id** delivery_item_id **item_id qty unit_price** original_unit_price **supply_amount vat_amount** warehouse_id is_loss memo ✅
- `partners` : partner_name biz_no address manager_name ✅ / `items` : item_name spec ✅

두 로더는 **이미 돌고 있는 `LoadPurchaseReceiptAsync` 와 구조가 글자까지 같다**(같은
`LoadByQueriesAsync` 통로 · 같은 별칭 이름 · 같은 `items` JOIN). 그래서 **런타임 500 위험은 낮다**(가설 — 실행 0회).

`#2` 테넌트 격리: head·lines **모든 질의에 `tenant_id = @TenantId`** 가 있고 `partners` JOIN 도
`AND p.tenant_id = pr.tenant_id` 를 달았다. `items` JOIN 에 `tenant_id` 가 없는 것은
**기존 6종 로더와 동일한 기존 규약**이고 `item_id` 가 PK 라 교차테넌트로 끌 수 없다 — 등재만.

### 3-2. 🔴 R-11 (신규 반려) — 저장 안 한 전표에서 「인쇄」 = 백지

**재현 조건**

1. 매출반품(또는 매입반품·견적·수주 등) 화면을 **새로** 연다.
2. 아무것도 저장하지 않고 상단 **「인쇄」** 를 누른다.

**왜 통과하는가**

- `SalesReturnPage.razor.cs:500` → `PrintPreview.ShowAsync("sales-return", _draft?.Id, "반품명세서")`
- 새 전표의 `_draft.Id` 는 `Guid.NewGuid().ToString()`
  (`SalesReturnPage.razor.cs:67`·`193`·`414` · `ReturnPage.razor.cs:46`·`295`·`361`·`565`)
  — **DB 에 없는 클라이언트 GUID** 다.
- `DocumentPrintPreview.ShowAsync` 의 문은 `string.IsNullOrWhiteSpace(docId)` **하나뿐**이다.
  GUID 는 비어 있지 않으므로 **통과**한다.
- 단추에 `Disabled` 가 **없다**(`SalesReturnPage.razor:123` · `ReturnPage.razor:90`).

**틀린 결과**

`WHERE sr.tenant_id=… AND sr.return_id='<클라이언트 GUID>'` → 0행 →
`LoadByQueriesAsync` 가 빈 스냅샷 → **미리보기 창에 백지**. 「미리보기가 곧 인쇄물」이므로
**종이도 백지**. PM 이 로더로 막으려던 바로 그 사고가 **다른 문으로 그대로 들어온다.**

**범위 판정**: 6화면은 이 사고가 **이전부터** 있었다(등재). 그러나 **매출반품 단추는 이
커밋이 새로 달았고**, 이 커밋의 R-6 봉합(`_draft.Id` → `_draft?.Id`)이 손댄 자리가 정확히
그 문이다. **「널 안전」으로만 고치고 「저장됐나」는 안 봤다** ⇒ 이 차수 반려.
