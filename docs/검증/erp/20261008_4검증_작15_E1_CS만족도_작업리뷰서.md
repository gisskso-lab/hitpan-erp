## ③ 🔴 한글 문자열 단언 / 음성축-양성축 점검 (10/8 `\uXXXX` 사고 재발 여부)

**결론 — 그 사고 축은 닫혀 있다.** 단 글자 단언 1건은 남아 있다.

1. **음성 문자열 단언 0건.** 전수 그렙에서 `Assert.DoesNotContain` · `Assert.NotEqual` · 한글 음성 비교가 **한 건도 없다.** JSON 이스케이프로 늘 통과하는 음성 단언의 모양 자체가 없다.
2. **JSON 을 보는 모든 단언이 파싱 후 숫자·ASCII 키다** — `Body()`(`:259-260`)가 `SerializeToElement` 로 바꾼 뒤 `reason`·`alreadyRated`·`rating`·`csRequestId`·`duplicated` 만 읽는다. 한글 `message` 는 **아예 안 읽는다**.
3. **한글이 들어간 단언은 G-E1-9 축① 하나뿐**(`:533-536`). 이것은 JSON 이 아니라 **레포 UTF-8 원문**이고, `pairs.Count == 3` + `Single(p => p.Label == "...")` 3건이 **양성(미끼) 축**이다 — 못 찾으면 `Single` 이 던진다. ⇒ **「음성만 있고 양성 미끼가 없는 게이트」는 없다.**
4. 다만 축①은 **동작이 아니라 소스 글자**다(§②-G-E1-9). 정규식 `new\(\s*(\d)\s*,\s*"([^"]+)"\s*\)` 는 그 파일 어디에 있든(주석 안이라도) 맞는다. **반려 사유로는 올리지 않되(축②가 숫자 흐름을 실제로 잼), 조건 C-3 에 둔다.**
