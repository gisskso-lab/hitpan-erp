## 2. V-2 🔴 P1 — 지우기의 울타리가 영구히 안 도는 죽은 코드다

**증상.** `SettingsController.cs` 의 지우기는 칸을 비운 뒤 *"반환값을 **버리지 않는다** — 못 적었으면 화면에 참을 말해야 한다"* 고 적고 `if (!cleared)` 로 400 을 돌려준다. 그런데 그 반환값은 **항상 `true`** 다.

**재현 경로.** `src/HitPan.Application/Services/SettingsService.cs:573~596`

```csharp
await _db.ExecuteAsync(new CommandDefinition(sql, new { TenantId = tenantId, Path = ... }));
return true;
```

`ExecuteAsync` 의 **적용 행 수를 받지도 보지도 않는다.** `sql is null`(모르는 종류)일 때만 `false` 인데, 그 종류는 호출 **전에** `IsKnownKind` 로 이미 걸러진다(`SettingsController.cs:338`) ⇒ `if (!cleared)` 분기는 **도달 불가**다. 올리기 쪽의 `if (!written)`(`:249~255`)도 같은 까닭으로 도달 불가다 — `CompanyImageStore.cs:51` 이 모르는 종류를 먼저 거절한다.

**무엇이 틀어지나.** `UPDATE … WHERE tenant_id = @TenantId` 가 **0행**을 고쳐도 성공으로 보고된다 ⇒ 화면은 「등록되었습니다」·「지웠습니다」를 말하고 DB 는 안 바뀐다. 🔴 이것이 **§B-4 가 봉합 명분으로 적은 바로 그 10/25 사고**(*"화면은 「등록되었습니다」라 말하고 서버는 null 을 저장했다"*)와 같은 모양이다. 게다가 P2-5 로 **지우기가 DB 칸만 보게** 바뀌었으므로, 칸이 빈 채 파일이 남으면 지우기는 **204 「이미 비어 있다」** 를 돌려주고 그 파일은 **화면으로 영영 못 지운다.**

**⚠️ 미재현.** `local_company` 행은 `CompanyBootstrapProvisioner.cs:81` 이 설치 때 넣는다. 그래서 「행 없음」 상태를 **나는 만들어 보지 못했다** — 「실제로 터진다」고 쓰지 않는다. 🔴 그러나 **울타리가 글자뿐이라는 것은 조건 없이 확정**이다. 울타리는 「그럴 리 없다」로 세우지 않는다.

**봉합안.** `ExecuteAsync` 의 행 수를 받아 `rows > 0` 을 돌려주고, 0행이면 적어도 `LogWarning` 을 남긴다. 그리고 그 축(0행 → `false` → 400)을 게이트로 세운다.
