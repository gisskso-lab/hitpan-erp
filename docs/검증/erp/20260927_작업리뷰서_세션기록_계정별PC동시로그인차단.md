## 4. 발견

### 🚨 F-1 (P0) — 마이그 1건 실패가 **전면 잠금**이 된다. 그리고 끌 수 없다

**위치**: `src/HitPan.Application/Services/AuthService.cs:250-295`(INSERT 실패를 삼킨다) × `src/HitPan.API/Middleware/SessionValidityMiddleware.cs:86-113`(세션 없으면 401) × `src/HitPan.API/Program.cs:488-498`(마이그 실패해도 기동한다)

**연쇄** (🟢 세 파일 실측 · ⚠️ 실물 재현은 안 했다 — 운영 DB 접촉 금지 #39, 개발 PC 는 `CREATE DATABASE` 권한 없음):

1. `MigrationRunner` 는 **첫 실패에서 멈추고 그 뒤 마이그를 진행하지 않는다** — `Program.cs:492` 로그 원문 *"이 지점에서 중단했고 다음 마이그는 진행하지 않았습니다"*. 그리고 **기동은 시킨다**(사전 결재된 판단).
2. ⇒ DB-127 이 안 붙은 채 API 가 뜬다. `user_sessions.device_kind` 없음.
3. 로그인 → `InsertSessionAsync` 가 `Unknown column 'device_kind'` 로 실패 → **`catch` 가 삼키고 로그인은 200 으로 성공**(설계 G-6 "가용성 우선" 그대로).
4. 그 토큰에는 `sid` 가 **들어 있다**(`AuthService.cs:667`). 세션 행은 없다.
5. 다음 요청 → 미들웨어가 `SELECT 1 … WHERE session_id=@Sid` → 없음 → **401 + "다른 컴퓨터에서 이 계정으로 접속해 연결이 끊어졌습니다"**.
6. 화면이 자동 갱신을 돈다 → `RefreshAsync` 는 `sid` 가 **있으므로** `isNewSession=false` → `UPDATE … WHERE session_id=@sid` 가 **0행** → 세션은 여전히 없다 → 또 401.
7. 재로그인해도 3~6 이 그대로 반복된다. **로그인은 되는데 아무 화면도 안 열린다.**

🔴 **이게 P0 인 결정적 이유 — 이 차단에는 킬스위치가 없다.**
축 B 킬스위치 `enforce_single_pc_login` 은 **`EnforceSinglePcLoginAsync` 안에만** 있다(`AuthService.cs:218-222`). `SessionValidityMiddleware` 는 그 값을 **읽지 않는다**(읽는 건 축 A 값 `enforce_tenant_session_limit` 뿐 — `SessionValidityMiddleware.cs:138`).
⇒ 고객이 `enforce_single_pc_login=0` 으로 꺼도 **401 은 계속 난다.** 설계 §4-1 *"축 A·축 B 각각 설정 한 줄로 끌 수 있어야 한다"* 를 **축 B 는 절반만 만족**한다. 그런데 사고를 내는 쪽은 꺼지지 않는 그 절반이다.
⇒ 복구 경로 = **재배포**(372MB·수십 분) 또는 DB 직접 수술. 헌법 #30(고객 PC 자가 회복 · 본사 의존 0) 과 정면 충돌.

**더 넓다 — 마이그 실패만의 문제가 아니다.** 세션 INSERT 가 실패하는 모든 경우(연결 끊김 순간, 표 손상, `DataResetService.cs:50` 의 초기화가 `user_sessions` 를 비우는 순간)에 **같은 잠금**이 걸린다. 설계가 "가용성 우선"으로 로그인을 통과시킨 그 선택이, 절G 가 붙는 순간 **가용성을 0 으로 만드는 선택**으로 뒤집혔다. 두 안전장치를 따로 설계했고, 합친 모습을 아무도 안 봤다.

> 방향(코드는 안 고친다): ① 미들웨어가 **축 B 킬스위치를 같이 읽는다** ② `InsertSessionAsync` 가 실패했으면 그 토큰에 `sid` 를 **안 넣는다**(그러면 옛 토큰 경로로 통과한다) — 둘 중 최소 ①. 어느 쪽이든 설계 변경이라 [2] 로 돌려보낸다.

### 🚨 F-2 (P0) — 게이트가 봉합을 안 잰다. 이 트랙이 막으려던 재발을 **못 막는다**

**위치**: `src/HitPan.Tests/Integrity/SessionRecordConcurrentPcGateTests.cs:54-66`

시험 파일이 운영 SQL 을 **문자열 상수로 복사**해 두고 그것을 돌린다:

```csharp
private const string InsertSessionSql =
    @"INSERT INTO user_sessions (session_id, user_id, tenant_id, login_at, last_active_at, expires_at, device_kind)
      VALUES (@SessionId, @UserId, @TenantId, UTC_TIMESTAMP(6), UTC_TIMESTAMP(6), @ExpiresAt, @DeviceKind)";
```

🟢 **실측** — 이 파일 전체에서 운영 코드를 부르는 곳은 **단 한 줄**이다(`:323` `AuthService.NormalizeDeviceKindForTests`). `InsertSessionAsync`·`EnforceSinglePcLoginAsync`·`LoginAsync`·`SessionValidityMiddleware` 를 부르는 곳은 **0건**(grep 확인). G-1·G-1N·G-2·G-2c·G-3·G-8 여섯 건이 전부 제 손으로 쓴 SQL 을 제가 돌린다.

⇒ **`AuthService.cs:156` 의 `await InsertSessionAsync(...)` 한 줄을 지워도 게이트 8건이 전부 초록이다.** 컴파일도 된다.
⇒ 이 트랙은 *"세는 곳·지우는 곳은 있는데 **넣는 곳이 0건**이라 아무도 몰랐다"* 에서 시작했다. **그 사고가 재발해도 이 게이트는 초록을 유지한다.** 막으려던 것을 못 막는다.

같은 파일 `:25` 주석은 *"판정 규칙은 AuthService 의 **실제 메서드**를 부른다"* 라고 적혀 있다 — G-3b 한 건에만 해당하는 말이 파일 전체의 설명처럼 달려 있다. 다음 사람이 이걸 읽고 "동작을 잰다"고 믿는다.

🔴 G-1N 도 같다. 컬럼을 지우고 **시험 제 SQL** 이 실패하는 것을 본다. DDL 이 필요하다는 것은 증명하지만, **운영 경로가 그 INSERT 를 부른다는 것은 증명하지 않는다.** 음성 대조군이 가리키는 과녁이 틀렸다.

**작지 §4 의 "🔴 대조 두 쪽을 같은 파서로 읽지 마라"** 가 정확히 이 자리를 겨눈 문장인데, 같은 커밋에서 어겼다. 선례도 파일 안에 적혀 있다(`SessionLimitMiddleware.TierSessionLimitForTests` — 상수를 옮기면 통과하던 가짜 게이트). 규칙을 알고 G-3b 에는 적용했는데 SQL 여섯 건에는 안 했다.

**추가로 빠진 게이트**: 작지 §5 완료조건은 *"G-1~G-6 CI 에서 실제로 돌고 통과"* 인데 **G-4(로그아웃 → 행 삭제)·G-6(INSERT 실패해도 로그인 성공 + `security_alerts`)·G-2b(밀어내기 버튼)** 이 없다. G-7 의 음성 쪽(`sid` 있고 세션 죽음 → 차단, 미들웨어 401 분기 `SessionValidityMiddleware.cs:103-113`)도 **어느 시험도 태우지 않는다** — F-1 의 잠금이 나오는 바로 그 코드가 무시험이다.

### 🔴 F-3 (P1) — 작지 금지 #3 정면 위반. 결재 없이 뒤집었다

**위치**: `src/HitPan.API/Migrations/SQL/DB-127_user_sessions_device_kind.sql:92` · `src/HitPan.Application/Services/AuthService.cs:203-206`

작지 §3 금지 #3: **"`device_kind` 기본값을 `'mobile'` 로 두지 마라 — 모르면 과금되는 쪽(`'pc'`)으로"**. 표 머리에 *"어기면 즉시 반려"*.
설계 §3-1 도 같다: `DEFAULT 'pc'` · *"🔴 기본값이 `'pc'` 인 이유: 모르면 과금되는 쪽으로 떨어뜨린다."*
