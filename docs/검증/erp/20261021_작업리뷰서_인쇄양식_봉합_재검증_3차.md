## §2 반려·조건

### 🔴 C-1 (반려성 조건) — N-1 은 닫히지 않았다. 「주석은 코드가 아니다」가 그대로 재발

**주장**(`TaxInvoicePdfRenderGuardTests.cs` T-7 음성 대조군 주석):
> *"지원 범위(0~30mm)에서는 폴백으로 떨어지지 않는다 — `TaxInvoicePageSlackPt` 2pt 여유가 선 자리가 바로 이 판정이다([4] 2차 N-1: 그 상수를 재는 게이트가 0건이었다). 상수를 키우거나 재는 코드가 보수적으로 기울면 **이 단언이 빨개진다.**"*

**측정**(제품을 실제로 틀고 다시 빌드해서 가드 전건 실행):

| 슬랙 상수 | DLL 실제값(reflection) | 가드 결과 | `Assert.NotNull(CopyChunks)` 루프(0~30mm × 1·3·30·40·80·100 = 48칸) |
|---|---|---|---|
| **2f** (봉합값) | 2 | 94/94 초록 | NULL **0/48** |
| **50f** (25배) | **50** ✔확인 | **94/94 초록 — 안 잡힌다** | NULL **0/48** |
| **400f** (200배) | 400 | **빨강** (T-7 다수 실패) | — |

**왜 안 잡히나 — 코드로 확인했다.** `TaxInvoicePageSlackPt` 의 사용처는 **전체에서 1곳**이다:
```
PdfRenderService.cs:1157   return probe.Height <= probe.AvailableHeight - TaxInvoicePageSlackPt;   // MeasureBothCopiesFitOnePage 안
```
게이트가 지목한 `ResolveCopyPageChunks` 는 **`MeasureCopyPageFits`** 를 쓴다 — 슬랙이 **없는** 다른 함수다. 즉 그 `Assert.NotNull` 루프는 **원리적으로** 이 상수의 변화를 못 잰다. 400f 에서 빨개진 것은 그 단언이 아니라 **T-7 의 조각 판정**이고, 그건 「두 벌이 한 장에 들어가나」 판정이 극단적으로 뒤집힐 때만 나타난다.

**무엇이 반려 거리인가** — 다음 사람이 이 상수를 2 → 50 으로 (또는 재는 코드를 그만큼 보수적으로) 바꿔도 **가드 94/94 초록**으로 통과한다. 2차 N-1 의 지적(「그 상수를 재는 게이트가 0건」)은 **글자만 바뀌고 측정은 그대로 0건**이다.
🔴 **요구**: 상수를 **그 상수의 실제 사용처**(`MeasureBothCopiesFitOnePage` 의 판정 결과)에 걸어 재는 단언을 세울 것. 그리고 **그 단언이 2f→3f 수준의 작은 변화에서 빨개지는지**를 음성 대조군으로 적을 것. (🔴 코드는 내가 고치지 않았다 — 측정용 변경은 전부 되돌렸다.)

### 🔴 C-2 (조건) — 조이기의 **근거 숫자가 틀렸다.** 31~50mm 고객이 까닭 없이 종이가 바뀐다

제품 주석 · DTO 주석 · 작지서 §17 이 **세 곳 모두** 같은 숫자를 적고 있다:
> *"실측: 여백 **40mm 이상**에서 세금계산서 이어쓰기가 어제의 반려 모양(머리 없는 쪽 · 품목 0줄 쪽)을 다시 내고, 80mm 이상은 종이가 아예 안 나온다."*

**내가 조이기를 끄고 같은 342칸을 다시 재서 얻은 실제 경계**:

| 여백 | 조이기 **끈** 판(= 봉합 전 제품) | 판정 |
|---|---|---|
| 0 ~ **50mm** | 전건 정상 — 예외 0 · 머리 없는 쪽 0 · 품목 0줄 쪽 0 · 합계 일치 (31·35·40·50 포함) | 🔴 **「40mm 이상에서 깨진다」는 거짓** |
| **60mm** | 깨진다 — 예: `both·60mm·80줄` → 16쪽 `heads=[1,0,1,0,…]` **머리 없는 쪽 8개 · 품목 0줄 쪽 2개** | 여기가 실제 첫 고장 |
| **80·100·120mm** | `TargetInvocationException`(안쪽 `DocumentLayoutException`) — 종이 0장 | 작지서의 「80mm 이상」만 맞다 |

**고객에게 무엇이 바뀌나**(조이기 켠 판 vs 끈 판, 같은 전표):

| 고객 저장값 | 봉합 전 종이 | 봉합 후 종이 | 바뀌나 |
|---|---|---|---|
| 0 ~ 30mm | — | — | 🟢 **안 바뀐다** (지문 280/280 일치 · §3-C) |
| **31 ~ 50mm** | 정상 종이(고장 없음) | **30mm 로 그린 종이** | 🔴 **바뀐다 — 그런데 고칠 고장이 없던 구간이다.** 예: `both · 40mm · 100줄` → 봉합 전 **8쪽** `items=[33,33,33,1,33,33,33,1]` / 봉합 후 **6쪽** `[37,37,26,37,37,26]`. 여백도 40→30mm 로 10mm 줄어 **전체가 올라붙는다**(§0-2-b) |
| 60mm 이상 | 조각 종이 또는 종이 0장 | 30mm 정상 종이 | 🟢 바뀌는 게 맞다(고장 수리) |

🔴 **요구(택1, 고치지 말고 결재로)**: ⓐ 상한 근거를 **실측대로 고쳐 적고**(첫 고장 = 60mm) 30mm 라는 보수적 상한을 **그 보수성까지 글로** 남긴다 · ⓑ 또는 상한을 실측 경계에 맞춘다. 어느 쪽이든 **「지원 범위 안은 한 글자도 안 바뀐다」는 참이지만(§3-C), 「범위 밖은 전부 고장이었다」는 거짓**이므로 보고서가 그걸 숨기면 안 된다.
🔴 **이 조건은 안전 쪽으로 틀린 것**이다(30mm 는 60mm 보다 안전). 그래서 **반려가 아니라 조건**으로 둔다 — 다만 사장님 보고서에 **「31~50mm 고객 종이가 바뀐다」**가 들어가야 한다.
