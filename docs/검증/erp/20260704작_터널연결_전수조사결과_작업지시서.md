### 전수조사 3건 교차 결과
| 층 | 파일 | 핵심 결함 |
|---|---|---|
| 백오피스 발급 | `CloudflareDomainService.cs` | 터널명 `hitpan-{tenantCode}` **고정**(L182) → 재가입·재설치가 **같은 관리형 터널 UUID 공유**. ingress PUT은 **전체 덮어쓰기**(L252~) → 마지막 도메인만 남음. |

## 2. ⚠️ 교차검증에서 갈린 지점 (독립반증 — 결재 전 반드시 확인)
전수조사가 "여러 PC 토큰 충돌"을 위험으로 지목했으나, **우리 실제 상황은 "한 PC에 4번 재설치"**다. 둘은 다른 문제다:
- **우리 사고 = 단일 PC 재설치.** 여러 PC 동시 사용 아님. 그러니 이번 530의 직접 원인은 "PC 간 토큰 충돌"이 아니라 **service install 자체가 이 PC에서 실패했거나 토큰이 빈값이었던 것**일 가능성이 크다.
- **미확정 = 오늘 G_TunnelToken이 실제로 빈값이었나, 아니면 값은 있었는데 install이 실패했나.** 이건 테스트 PC의 `db.conf`(TUNNEL_TOKEN 줄)와 `Setup Log #004`의 6-2 흔적을 봐야 확정. **결재 전 이 한 가지 실측 필요** (아래 3-A).
- 결론: "터널 공유 구조"는 **미래(한 고객사 여러 PC) 결함**으로 실재하나, **오늘 사고의 직접 진범 확정**은 위 실측 후에 못박아야 한다. 지금 공유구조부터 뜯으면 오진 위에 설계하는 것.

## 3. 봉합 후보 (우선순위·난이도, 아직 미착수)

### 3-A. [P0·선행] 오늘 진범 확정 실측 (코드 0건)
테스트 PC에서 2개만 확인 → 진범이 "토큰빈값" vs "install실패"로 확정:
- `type "C:\Program Files\HitPan\db.conf"` → `TUNNEL_TOKEN=` 뒤에 값이 있나 빈값인가
- `type "...\Setup Log 2026-07-04 #004.txt" | findstr /i "service install cloudflared sc "` → 6-2가 실행됐는지
→ 이 결과로 3-B/3-C 중 무엇이 진짜 봉합인지 결정.

### 3-B. [P0] 설치 EXE — install 실패를 잡아라 (헌법 #15)
- `HitPan-Universal.iss` L1150 `service install` 후 ResultCode 검사 + 실패 시 재시도 + 사용자/로그 안내.
- L1156 `sc start` 도 동일. L1128 토큰 빈값이면 "터널 미설치" 명시 경고(조용히 완료 금지).
- 난이도 中. 이게 "설치 완료인데 터널 없음"의 직접 봉합.

### 3-C. [P1] 백오피스 — 토큰 빈값이 안 나가게 + 재사용 시 토큰 정합
- `IssueTunnelAsync` 재사용 경로에서 토큰이 확실히 응답에 실리는지. `InstallerBootstrapController` 응답 `tunnelToken` 빈값 방지.
- 난이도 中.

### 3-D. [P1·설계] 터널 격리 구조 (미래 여러 PC/재설치)
- 터널명을 tenantCode 고정이 아니라 **설치 인스턴스(도메인/기기)별**로? or 재설치 시 기존 터널 정리 후 재발급? 관리형 vs 자가관리 재검토.
- **설계 논점이라 별도 설계서 필요**(헌법 #28·#30·#31 정합). 급하게 손대지 말 것 — 사장님 "설계부터" 지시 정합.
- 난이도 高. 3-B/3-C로 오늘 종단부터 뚫고, 이건 설계 결재 후.

### 3-E. [P2] 워치독 사각지대
- 토큰 빈값 시 본사 비상통지 or db.conf 미발견 경고. 3-D 설계에 흡수 가능.

### 진범 = 인증 미들웨어 화이트리스트 누락 (커밋 `ed46b1f`, 2026-06-25)
- `TenantMiddleware.cs` L25~35 인증 면제 목록에 **`/api/setup` 이 없다.** 있는 것: /health·/swagger·/api/auth/login·/api/auth/refresh·/api/backoffice/auth·/api/landing·/api/install·/api/internal.
- 부모계정 정식 경로 = `CompanyBootstrapController` 라우트 **`/api/setup/bootstrap`**(회사정보 저장→is_locked_from_landing=1)·**`/api/setup/create-parent`**(부모계정 INSERT). 컨트롤러는 `[AllowAnonymous]`(L30)지만 **미들웨어가 먼저 돌아 L48 `IsAuthenticated!=true` → 401** → 컨트롤러 도달 못 함.
- 커밋 `ed46b1f`가 구 백도어 `/api/tenants/setup` 익명 제거하면서 **신 경로 `/api/setup` 화이트리스트 등재를 누락**(L27 주석이 그 흔적).
- **증상 체인**: bootstrap 401 → local_company 저장 안 됨 → create-parent 가 L229 "bootstrap 먼저" 가드에도 막히고 애초에 create-parent 자체도 401 → users 0 → 로그인 불가. **프론트(ERP Web)가 이 401 저장 실패를 사용자에게 안 막고 다음 단계로 진행**시켜 "정상처럼" 보임(2차 결함).

### 영향 범위 (P0인 이유)
- **재설치만이 아니라 모든 신규 고객 설치**가 부모계정을 못 만든다 = 설치해도 로그인 불가 = 헌법 #20(워크플로우 끊김)·#34(설치 정식완성도) 정면 위반.
- 화면이 성공처럼 보여 고객·본사 모두 사고를 늦게 안다(가장 위험).
