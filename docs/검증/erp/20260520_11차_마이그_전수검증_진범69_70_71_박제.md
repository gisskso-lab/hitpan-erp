
### 봉합 옵션

- **옵션 B**: UI 카드 "원본 116,420 / 적재 115,460 / 중복 차단 960" 3중 표시 (투명)

## 🚨 진범 #70 — journal_lines UNIQUE 키 사고 (회계 무결성 위험)

### 결정적 증거
```
journal 정공법 완료: 엔트리 23,170/23,170행 라인 23,406/27,661행
↓
라인 staging 27,661 → INSERT 23,406 / 손실 4,255건 (15.4%)
```

### 원인 — `uk_journal_line_dedup` UNIQUE 키 구조
```sql
UNIQUE KEY uk_journal_line_dedup (tenant_id, entry_id, account_code)
```

**한 분개(entry) 안에 같은 계정과목(account_code)은 1개만 허용**. 그러나 DOCF7 원본에서는 한 분개에 "현금"·"외상매출금" 등 같은 계정으로 **여러 라인 기록**된 경우가 흔함 (예: 보조부서/거래처별 세부분개).

### 회계 무결성 영향
- **차/대 균형 깨질 가능성**: 한 분개의 "현금" 라인 3개(각 100만/200만/300만) 중 1개만 살아남고 2개가 IGNORE → **불균형 entry 발생**
- 5/19 헌법 #20 워크플로우 끊김 위반 가능성
- 5/20 자문 #8 결재 (헌법 #20 vs 5/14 fallback 영역) — fallback item 봉합과는 별개 사고

### 봉합 옵션
- **옵션 A**: `uk_journal_line_dedup` 키에 `line_no` 추가 → `(tenant_id, entry_id, account_code, line_no)` — 같은 entry+account 여러 라인 허용
- **옵션 B**: 같은 분개의 같은 계정 라인을 마이그 단계에서 SUM 합산 → 1개로 만들기 (적재량 줄지만 균형 유지)
- **옵션 C**: 마이그용 source_id 패턴에 `account_code + sun(라인순번)` 포함 → UNIQUE 충돌 회피

ERP·DB 매니저 자문 후 사장님 결재 권장 (회계 헌장 정합 필수).

### 검증 SQL (4,255건 손실 사실 확인용)
```sql
-- 한 entry에 같은 account_code가 staging에 여러 번 있었는지 확인
SELECT entry_id, account_code, COUNT(*) AS cnt
FROM journal_lines
WHERE source_type = 'migration'
GROUP BY entry_id, account_code
HAVING cnt > 1
LIMIT 10;
-- (현재 INSERT IGNORE 후 결과는 cnt=1만 남았으므로 빈 결과 예상.
--  staging temp 테이블은 트랜잭션 종료로 사라져 직접 추적 불가.
--  다음 마이그 시 staging dump 로그 추가 필요.)
```

## 🚨 진범 #71 — tax_invoices 652건 손실 (DOCFE 그룹화 누락 추정)

### 결정적 증거
```
tax_invoices BulkCopy 적재: 66,631행, warnings=0
tax_invoices 정공법 완료: 헤더 후보 66,631 → INSERT 65,979 / 손실 652
품목 후보 69,583 → INSERT 68,696 / 손실 887
```

### 4개 UNIQUE 키 분포 (DB 실측)
```
distinct invoice_no           65,979
distinct source_id            65,979
distinct direction+tax_no     65,979
distinct migrated_source_hash 65,979
total inserted                65,979
```

**모두 동일 = staging 단계에서 같은 키 652쌍 생성**. INSERT 후 4개 키 모두 일치하는 것은 정상.

### 원인 추정
DOCFE 원본에서 **같은 tax_no가 여러 row로 분산 기록**된 경우 — 사장님 자문 #1 결재 결과 `KE_DT + KE_SEQ + KE_BUYC` 그룹화가 정답이었으나, 현재 코드가 이 그룹화를 적용 안 했을 가능성.

### 검증 필요
```bash
grep -n "DOCFE\|KE_DT\|KE_SEQ\|KE_BUYC\|tax_invoices.*그룹화" \
  src/HitPan.Application/Services/MdbMigrationService.cs
```

→ 적용되어 있으면 손실 652건은 정당한 중복 차단.
→ 미적용이면 진범 #23-Q 본구현 시 함께 봉합.
