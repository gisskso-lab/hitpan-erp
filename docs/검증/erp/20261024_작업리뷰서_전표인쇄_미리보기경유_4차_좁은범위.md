## §1 V-1 — R-11 봉합이 「DB 에 없다」를 실제로 막나

### 1-1 🟢 `?.` 와 「DB 에 없다」의 구분 — 코드에서 참이다

- 화면의 `IsNullOrWhiteSpace(docId)` / `_draft?.Id` 는 **값이 비었나**만 본다. 화면이 만든 GUID 는 비어 있지 않으므로 통과한다.
- 봉합은 **값**이 아니라 **조회 결과**를 본다: `DocumentSnapshot.Found`(`PdfRenderService.cs:740`, 기본값 `true`) → `ShouldRejectMissing`(`PdfRenderService.cs:336~342`) → `KeyNotFoundException`(`PdfRenderService.cs:68~72`).
- `Found=false` 를 올리는 자리는 **두 곳뿐**이고, 그 두 곳이 모든 경로를 덮는다:
  - `PdfRenderService.cs:677` — `LoadByQueriesAsync` 의 `h is null` 분기.
  - `PdfRenderService.cs:358` — `LoadDocumentAsync` 의 `_ =>` fallback(로더 없는 종).
- **전수 확인**: 8개 로더(`LoadQuotationAsync`·`LoadSalesOrderAsync`·`LoadDeliveryAsync`·`LoadTaxInvoiceAsync`·`LoadPurchaseOrderAsync`·`LoadPurchaseReceiptAsync`·`LoadPurchaseReturnAsync`·`LoadSalesReturnAsync`)가 **전부** `LoadByQueriesAsync` 한 자리로 들어간다(`PdfRenderService.cs:386·412·437·529·564·589·623·655` 의 return). 새 `DocumentSnapshot` 을 따로 만들어 돌려주는 로더는 **0건**이다.
- `tax_invoice` 는 `LoadByQueriesAsync` 결과를 받아 칸만 덧칠하고(`snap.DocNo`·`DocDate`·`AmendmentReason` 등) `Found` 를 **되돌리지 않는다**. 못 찾으면 `Found=false` 가 그대로 올라간다.

### 1-2 🟢 API 직타·로더 없는 종도 같이 막힌다

- `RequireExisting = true` 를 세우는 자리는 **전 레포에서 한 곳**: `DocumentController.cs:839`(`POST {type}/{id}/preview-pdf`). 화면 8곳이 아니라 **문 하나**이므로 창을 안 거친 직타도 같은 판정을 받는다.
- **로더 없는 종 실측**(내가 직접 반사로 지도표를 불렀다):
  `map[invoice-exempt] = invoice_exempt` · `map[payment-receipt] = payment_receipt` → 이름은 **매핑되지만**(400 이 아니다) `LoadDocumentAsync` 의 switch 에 분기가 없어 `_ =>` 로 떨어져 `Found=false` ⇒ **404 + 사람 말**. 백지 0건. 주장대로다.
- `map[return] = purchase_return` · `map[sales-return] = sales_return` — 화면이 쓰는 하이픈 이름 8개 전부 서버가 받는다.

### 1-3 🟢 「인쇄」·「이메일」·「팩스」가 한 글자도 안 바뀌었나 — 참 (#1 · #20)

- `RequireExisting` 을 세우는 호출부는 `DocumentController.cs:839` **하나뿐**이다(테스트 제외 전수 grep).

### 1-4 🔴 **반려하지 않되 등재** — 저장된 전표가 「저장 안 했다」로 막히는 통로가 남아 있다

| 재현 조건 | 틀린 결과 | 근거 |
