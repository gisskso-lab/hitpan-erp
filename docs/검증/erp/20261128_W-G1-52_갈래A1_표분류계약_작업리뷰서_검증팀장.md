## 3. 이슈

### P1-1 — G13 ⓕ(무른 참조) 조용히 빠짐 · 실제 걸리는 칸 2개
- 설계 §15-4 ⓕ(11/27 반증 반영 R8 ②): 「지금 값 표의 `_id` · `_code` 칸이 백업 값 표를 가리키는 것 0 · 전수 = [3] DESCRIBE #13」. 코드 · 시험 · 명세서 어디에도 ⓕ 가 없고 「A-2 로 미룸」 기록도 없다(ⓖ 는 S5 · D5 로 했음 → ⓕ 만 빠짐).
- 검증팀이 출하 DDL 로 지금 값 표 칸을 훑음(`_id` · `_code` · `_no` 끝 · JSON 칸은 못 봄):
  - `users.dept_id` (`installer/hitpan_db_clean.sql` :4391) → `departments`(백업 값). 복원 뒤 계정이 백업에 없는 부서를 가리킬 수 있음.
  - `tenant_etax_settings.notify_manager_id` (:4182 · COMMENT 「employees.employee_id」) → `employees`(백업 값). 복원 뒤 계산서 알림 담당이 없는 사원.
  - 설계 가설 「`tenant_settings` → 기본 창고」 = 그런 칸 없음(가설 깨짐) · `approval_settings` · `workflow_settings` 에 사원 칸 못 찾음(JSON 칸 안은 미확인).
- **조건**: (가) A-1 에 ⓕ 시험(칸 목록 대조 · 알려진 무른 참조 목록 상수 + 새 칸 생기면 빨강) 더함, 또는 (나) PM 이 「ⓕ = A-2 대조 ④ 로 미룸」 을 결재 기록에 적고 위 2칸을 A-2 작업지시서 대조 ④ 입력으로 넘김. 둘 중 하나 없이 [5] 금지.

### P2-1 — S7 트리거 읽기가 `CREATE TRIGGER IF NOT EXISTS` 를 못 봄
- `src/HitPan.Tests/Integrity/RestoreTableClassificationGateTests.cs` :62-64 정규식이 `TRIGGER` 바로 뒤 이름을 요구. MariaDB 는 `IF NOT EXISTS` 를 받음 · 마이그 쪽은 대부분 `IF NOT EXISTS` 꼴로 씀(표 쪽 관례). V3 실측 = 초록.
- D4 는 출하 DDL 신규설치본만 보므로 마이그로만 생긴 트리거는 DB 쪽도 못 봄 → 두 겹 다 빈다. 정규식에 `(?:IF\s+NOT\s+EXISTS\s+)?` + 시험 S10 같은 자체 시험 1줄 권고.

### P2-2 — S2 가 이름 바꾸기(`RENAME TABLE` · `ALTER TABLE … RENAME TO`)를 못 봄 · `tenants_old` 빠짐
- 같은 파일 :58-60 은 `CREATE TABLE` 만 셈. V4 실측 = 초록. 선례 있음: `DB-09_tenants_rebuild_utf8_comments.sql` :32 `RENAME TABLE tenants TO tenants_old, tenants_rebuilt TO tenants` · :34 `DROP TABLE tenants_old`.
- `tenants_rebuilt`(도중에 죽을 때만 남는 자리)는 지금 값에 넣었는데, 같은 창(:32 ~ :34 사이에 죽음)에 남는 `tenants_old` 는 없음 → 그 옛 PC 는 걸음 ① 이 늘 멈춤(멈춤 쪽이라 위험은 낮음 · 일관성 문제). RENAME 대상 이름도 셈에 넣고 `tenants_old` 를 지금 값에 더하는 것 권고.

### P2-3 — `SafeRestoreResponse.DataUnchanged` 기본값 `true` = 실패 쪽이 아님
- `src/HitPan.Application/DTOs/Backup/BackupDtos.cs` :199. A-2 에서 교체 커밋 뒤(감사 · 캐시 비움 · 표지 쓰기 등) 예외 길이 이 칸을 안 고치면 화면이 「자료는 바뀌지 않았습니다」 라고 거짓말을 한다(설계 §11 4장 문구). B 착수 조건 = 이 DTO 고정이므로 지금 정해야 함. 기본 `false`(또는 `bool?` · 서버가 증명했을 때만 true) 권고.

### P3-1 — DB 쪽 D1 ~ D5 는 「출하 DDL 신규설치본」 만
- `MigrationGateDb.ReadyAsync` = DDL 적재만 · 마이그 적용기 안 돎. 옛 고객 DB(= 옛 DDL + 마이그)와 마이그의 `ALTER … REFERENCES`(S6 도 출하 DDL 만 파싱 · :75-90)는 G13 밖. 지금 DB-02 외래키는 지금 값끼리(platforms · resellers · tenants)라 걸리는 것 0 — 앞으로의 구멍. 다른 게이트(G-W13 모양 대조)가 일부 메움 · 기록만.

### P3-2 — 명세서 변이표에 설계가 정한 외래키 변이 없음
- 설계 §15-9 G13 변이 = 「표 1개 뺌 · 지금 값 표에 백업 값 부모 외래키 더함」. 명세서 M1 ~ M3 엔 뒤엣것이 없음. 검증팀 V1 · V2 로 잡히는 것은 확인 → 명세서에 옮겨 적기만.

### P3-3 — 갈래 C 1회용 표와의 머지 순서
- 설계 §5 「새 표(이 일감) 1회용 표 = 지금 값」. 나중에 머지되는 쪽이 이 상수에 한 줄 더해야 G13 초록 — 게이트가 강제하니 사고는 아님 · PM 머지 순서 메모.

### (가설 · 미측정) 주석 걷기가 따옴표를 모름
- `StripComments` :52-56 의 `/\*(?!!).*?\*/` 는 문자열 속 `/*` 를 주석 시작으로 볼 수 있어, 뒤 `CREATE TABLE` 을 삼키면 S1 · S2 에서 빠짐(S1 은 `≥100` 만 지킴). DDL 은 D1 이 메우나 마이그는 못 메움. 실측 안 함 — 등급 없음.
