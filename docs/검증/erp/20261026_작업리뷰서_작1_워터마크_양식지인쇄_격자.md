## R-1 🔴 P1 — 가로 양식에서 크기 71% 이상이면 워터마크가 통째로 사라진다

**증상**
| 용지 | 60% | 80% | 100% |
|---|---|---|---|
| A4 세로 (210×297) | 🟢 73KB | 🟢 119KB | 🟢 132KB |
| A4 가로 (297×210) | 🟢 131KB | 🔴 **7.3KB** | 🔴 **7.3KB** |
| A5 가로 (210×148) | 🟢 73KB | 🔴 **7.3KB** | 🔴 **7.3KB** |

7.3KB = base64 로고가 **PDF 에 안 들어갔다**. 래스터해서 보면 60% 는 로고가 보이고 **80% 는 완전 백지**다(M-3).

**재현 경로**
- `src/HitPan.Application/Services/PdfRenderService.cs:238~245` — `var widthMm = pageWidthMm * watermark.ScalePct / 100f;` → `.Width(widthMm, Unit.Millimetre).Svg(...)`
- `src/HitPan.Application/Services/PdfRenderService.cs:2321~2330` — SVG 가 `width='1000' height='1000' viewBox='0 0 1000 1000'` 인 **정사각**이라 **높이 = 폭**이 된다.
- `src/HitPan.Contracts/Forms/WatermarkDefaults.cs:MaxScalePct = 100` — 상한이 **용지 폭**만 본다. 주석은 *"100% 🔴 넘으면 종이를 벗어난다"* 라고 적었는데, **가로 용지에서는 70.7% 에서 이미 벗어난다**(297×0.707 = 210 = 종이 높이).
- 화면도 100 까지 권한다 — `FormTemplateEditorDialog.razor` 「크기 (종이 너비의 %)」 `Max="100"` · `PrintSettingsPage.razor` 같은 칸.

**그대로 두면**
사장님 오더 ③ 은 *"위치 = 정중앙 **크게**"* 다. 고객이 크게 하려고 숫자를 올리는 **바로 그 동작**이 워터마크를 없앤다. 예외도 로그도 없어 고객은 *"켰는데 안 보인다"* 만 보고, 우리는 로그를 봐도 아무것도 없다. 가로 양식은 거래명세서·현황표에서 흔하다.

**봉합안**
① `ClampScalePct` 를 **용지 폭이 아니라 min(폭,높이) 기준**으로 조이거나, 그릴 때 `.MaxHeight(pageHeightMm, Millimetre)` 를 같이 건다(그러면 넘쳐도 **줄어들어 보인다**).
② 화면은 가로 양식일 때 상한을 낮추고 *"가로 용지라 70% 까지만 올라갑니다"* 를 **참으로** 적는다.
③ 게이트: **가로·세로 두 판** × 60/80/100 을 **픽셀로** 재고, 대조군은 60%(보임).

## R-2 🔴 P1 — 「모든 양식 공통」이 거짓이고, 양식을 한 번 저장하면 워터마크가 조용히 꺼진다

**증상 ⓐ — 공통 켜기가 양식 행이 있는 양식에 영영 안 닿는다**
`PdfRenderService.BuildWatermarkLayerAsync`:
```
var formSays = (bool?)template?.ShowWatermark;
if (formSays == false) return null;     // ← 행이 있으면 여기서 끝. 공통을 읽지도 않는다
var common = await LoadPrintCommonAsync(...);
if (formSays != true && !common.WatermarkEnabled) return null;
```
`template?.ShowWatermark` 는 **비널러블 bool** 이라 `null` 이 되는 경우는 **양식 행 자체가 없을 때뿐**이다.
`show_watermark tinyint(1) NOT NULL DEFAULT 0` 이므로 **「나는 정하지 않았다」를 표현할 칸이 없다.**
⇒ 공통 설정의 켬/끔은 **행이 없는 양식에만** 먹는다.

그런데 화면·DDL 은 이렇게 적었다 — **전부 거짓이다**:
- `PrintSettingsPage.razor` 제목 「로고 워터마크 (**모든 양식 공통**)」
- 같은 화면 주석·본문 「**여기 값이 모든 양식의 기본**이고, 양식마다 따로 끄거나 숫자를 바꿀 수 있습니다」
- `installer/hitpan_db_clean.sql:1456` `watermark_enabled` COMMENT 「1=**기본으로** 워터마크를 깐다. 양식마다 끌 수 있다」

**증상 ⓑ — 여백만 고쳐도 워터마크가 꺼진다 (더 위험한 쪽)**
공통을 켠 고객 → 견적서는 양식 행이 없어 워터마크가 나온다 → 고객이 양식정보설정에서 견적서 여백만 고쳐 저장 →
`FormTemplateEditorDialog` 의 체크박스는 **공통을 읽지 않으므로 꺼진 채**이고 `ApplyWatermarkToForm()` 이 `ShowWatermark=false` 로 저장 → **워터마크가 사라진다. 고객은 워터마크를 건드린 적이 없다.**
(편집창은 10/21 S-2 사고를 막으려고 *양식의* 값을 읽어 오지만, **공통에서 온 켬**은 읽을 자리가 없다.)

**증상 ⓒ — 「공통값 따름」으로 되돌리면 넣어 둔 수치가 말없이 지워진다**
`ApplyWatermarkToForm()` 의 `else` 가 수치 3개를 **null 로 덮는다**. 라디오를 「공통 설정값 그대로 쓰기」로 바꾸거나 워터마크 체크를 껐다 켜면 그 양식에 넣어 둔 진하기·색감·크기가 **아무 말 없이** 사라진다(#1 — 덮어쓰기). 화면에 경고 0줄.

**봉합안**
① 켬/끔도 3값(`공통 따름 / 켬 / 끔`)으로 간다 — 칸을 지우지 말고 `NULL` 허용으로 **넓히는** 쪽(#1·#37).
②(최소) 편집창이 공통값을 읽어 와 체크박스 초기값·「공통 설정에서 켜져 있습니다」를 보여 주고, 공통 화면의 글을 **참으로** 고친다.
③ ⓒ 는 「따로 정한 값이 지워집니다」를 묻고 지운다.
🔴 **글만 고치는 봉합은 받지 않는다** — ⓑ 는 글 문제가 아니라 동작 문제다. 봉합에는 **공통만 켠 고객의 종이를 그려서 재는 게이트**를 함께 낸다.
