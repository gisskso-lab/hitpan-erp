## 1. 물음 1 — C6 ③ 을 무엇으로 닫나

**추천 = (가)** · 단 「C6 ③ 닫힘」 이라고 한 줄로 쓰지 않는다. ③ 을 둘로 나눠 적는다.

| 쪼갠 칸 | 무엇을 재나 | 증거 | 상태 |
|---|---|---|---|
| ③-ㄱ 역할 거름 | 일반 계정(`tenant_user`)이 대표 화면 · 초기화에 못 들어감 | 화면 A1-4 · A2-3 · A2-4 → 이름을 「역할 거름 대조군」 으로 고침 | 화면 실측 |
| ③-ㄴ 대표 판정 줄 | 관리자 역할 자식(`tenant_admin` · `is_parent=0`) → `not_parent` · 백업 0 · 업무 줄 그대로 | CI db-gate `DataResetParentOnlyGateDbTests` P2(대표 1 + 관리자 자식) · P7(자료이관 덮어쓰기) · P9(대표 2 + 관리자 자식) · P8 `m1` | CI 증거 |
| ③-ㄷ 설치본 위 거절 경로 실물 실행 | test1234 설치본에서 대표 판정 거절이 실제 도는지 | 없음 | ⚠️ **미측정** — 「닫힘」 으로 쓰지 않음 |

CI 근거 확인(내가 직접 본 것):
- P2 = 대표 1 + `admin: true, parent: false` 자식 · 맞는 비번 → `DenyCode = not_parent` · 안내 문구 · 백업 0 · 업무 줄 그대로 (`src/HitPan.Tests/Integrity/DataResetParentOnlyGateDbTests.cs:215-228` · 단언 `:178-189`).
- 출하 DDL 로 새 스키마를 깔고 잼(`:105-140`) · CI 에서 SKIP = FAIL (`.github/workflows/build-and-test.yml:439` `HITPAN_REQUIRE_DB` · GATES 에 `DataResetParentOnlyGate` `:570-574`).
- 서비스를 바로 부름 → 컨트롤러 문(`TenantAdminOnly` + `MainPcOnly`)은 `DataResetParentOnlyGateTests.cs:124-130` N3 가 속성 존재로 따로 묶음.

**조건 (어기면 🔴)**
1. **「게이트가 있다」 ≠ 「그 커밋에서 돌았다」.** 증거 = 게시할 main 커밋의 build-and-test 런 ID + db-gate 잡 초록 + 그 잡 로그의 `DataResetParentOnlyGate` P2 · P7 · P9 통과 줄. G-3 와 같은 런으로 기록. → **확인 필요: 게시 커밋 런 ID · 통과 건수(P1 ~ P9).**
2. **③-ㄷ 은 ⚠️ UNKNOWN 으로 남긴다.** 설치본에서 같은 서비스 메서드가 도는 것은 C3-1(대표 성공 경로) + A2-0(판 번호)로 간접만 보인다.
3. **기대 글자 연쇄 고침** — 대조 계정이 매니저(`tenant_user`)면 지금 글자로는 3칸이 거짓 FAIL → 멈춤에 걸린다.
   - **A2-3**: 「자료관리 묶음은 보임」 → **자료관리 묶음 자체가 안 보임**. 묶음 전체가 `@if (_isTenantAdmin)` 안에 있음 (`src/HitPan.Web/Layout/Sidebar.razor:333` · 플래그 `:538` `AccountTypeHelper.IsTenantAdmin`). → 확인 필요: 이 helper 가 `account_type` 만 보는지(직무 role 도 보면 결과가 달라짐).
   - **A2-4**: 서버 대표 판정 문구는 **안 나온다.** 화면 문 `DataResetPage.razor:6` 은 `Roles`(= `ClaimTypes.Role` = 연결된 사원의 직무, `AuthService.cs:1362-1377`)를 보고, 서버 문 `TenantAdminOnly` 는 `account_type` 클레임을 본다 (`src/HitPan.API/Program.cs:407-409`). → 대조 계정이 **직무 「관리자」 사원에 연결되면 화면은 열리고 서버가 403**(화면 문구 미정 = 멈춤 거리), 연결 안 됐거나 일반 직무면 화면 문에서 막힌다. **연결 조건을 지시서에 못 박는다**(사원 연결 안 함 또는 일반 직무) · 기대 = 화면 문에서 막힘 · 백업 새 줄 0 · 데이터 그대로.
   - **C3-3**: 「A2-4 를 했으면 `data_reset_denied` 1행 not_parent」 → **0행**. 매니저는 서비스(`DataResetService.cs:85`)까지 못 감. 1행이 나오면 그게 이상한 것 = 멈춤.
   - A1-3 · A2-2 역할 「관리자」 → 「일반」(`Users.razor:192`) · §6 A1-4 · A2-3 칸 「관리자 역할 계정」 → 「매니저(일반 계정) 대조군」.
4. **덧(데이터 손 0 · 선택)**: A1-2 옆에 직원 계정 관리 역할 칸 「관리자」 개수를 같이 센다. 「관리자」 수 > 「대표」 수면 옛 판 · 이관에서 온 「대표 아닌 tenant_admin」 이 실물에 있다는 뜻 = I-5 현장 사례로 기록. 그 계정으로 로그인 시도는 하지 않음.

**(나) 반려** — 고객 첫 설치 전에 다시 재도 화면 길 0 이라 같은 벽이다(새 계정 창 · 수정 창 둘 다 「일반 사용자」 · 「매니저」 뿐 `Users.razor:379-380` · `:495-496` · 사원 연결 길은 Role 을 안 보냄 → `UserService.cs:760`). 남는 수단은 DB 직접(#39 · 지시서 금지)뿐 → 미측정이 영구화된다. 판정 줄 자체는 CI 가 출하 DDL 위에서 더 정확히 잰다.

**(다) API 직접 호출(계정 생성 `Role=TenantAdmin`, `UserService.cs:141` 이 받음) 반려** — 화면 밖 우회(§6 「우회 0」) · 그렇게 만든 `tenant_admin` 은 직원 계정 화면 조치가 막힌다(`UserService.cs:1058-1059` 「대표·관리자 계정은 대표님만 바꿀 수 있습니다」 — 대표가 비활성 처리할 수 있는지는 확인 필요) → 실물에 대표 아닌 관리자가 남아 I-5 대표 수 판정에 섞인다.

## 2. 물음 2 — §249 #4 다시 물어야 하나

- **별도 결재로 다시 묻지 않는다.** 대표가 고른 행동(매니저 계정 1개 만들고 대조 뒤 사용중지)은 그대로 한다.
- **그러나 PM 전결로 끝나는 일도 아니다 — 대표께 보고는 해야 한다.** §244 #4 원문은 「관리자 역할 직원 계정」 이었고, §249 #4 「매니저 (추천)」 은 PM 추천 위 결재다. 그 추천 전제(매니저 계정으로 ③ 을 잰다)가 틀렸다. 그래서 C6 ③ 의 증거가 화면에서 CI 로 바뀐다 = 대표가 승인한 「게시 전 화면 확인」(§244 #3)의 범위가 줄어든다.
- **방법**: G-0 게시 결재 글(지시서 §4 G-0)에 한 줄을 넣는다 — 「C6 ③ 중 대표 판정 줄은 화면으로 못 잽니다(대표 아닌 관리자 계정을 화면으로 만드는 길이 없음). CI 자동 시험(P2 · P7 · P9 · 런 ID)으로 닫고, 설치본 실물 거절은 미측정으로 남깁니다.」 G-0 은 어차피 대표 결재라 대표에게 짐이 늘지 않는다.
- 지시서 §6 멈춤 조건 「관리자 역할 계정을 화면으로 못 만듦(Q2)」 은 이미 걸렸다 → **측정 시작 전에 지시서를 고쳐서** 푼다(측정 중 즉석 고침 아님).
