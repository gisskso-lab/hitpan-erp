## 4. stock_ledger 특수 (헌법 #3 핵심)

```
PRIMARY: ledger_id (BTREE)
idx_tenant_date: (tenant_id, ledger_date) — 일별 조회
idx_tenant_item_date: (tenant_id, item_id, ledger_date) — 품목별 원장
uq_stock_ledger_source: (tenant_id, source_type, source_id, item_id, move_type) HASH — 멱등 키
```

**해석:** stock_ledger는 INSERT ONLY이므로 source_type+source_id+item_id+move_type 조합이 같으면 두 번 INSERT 불가 → 자동 멱등성. HASH 인덱스로 정확 매칭만.

## 5. journal_lines 멱등 (헌법 #3 + 멱등)

```
PRIMARY: line_id (bigint, BTREE)
idx_jl_entry / idx_jl_entry_tenant (entry_id)
idx_jl_tenant_account (tenant_id + account_code)
idx_jl_partner (tenant_id + partner_id)
uk_journal_line_dedup: (tenant_id, entry_id, account_code) — UNIQUE
```

**해석:** 한 entry 내에서 같은 계정 코드 두 번 INSERT 금지 → AutoJournalHelper의 멱등 보장.

## 6. tax_invoices 1:1 강제

```
PRIMARY: invoice_id
uk_tax_invoices_delivery: delivery_id UNIQUE — 거래명세서 1건당 계산서 1건만
uk_tax_invoices_invoice_no: (tenant_id + invoice_no) UNIQUE
idx_amendment (amendment_of) — 수정계산서 추적
idx_status_scheduled (status, etax_scheduled_at) — 전자발행 스케줄
idx_tax_invoices_etax_status (tenant_id, etax_status)
idx_tax_invoices_tenant_issued (tenant_id, issued_at)
```

**해석:** 거래명세서 ↔ 계산서 1:1 무결성 강제. 취소 시 NULL 환원 가능 (delivery.tax_invoice_id MUL 인덱스 존재).
