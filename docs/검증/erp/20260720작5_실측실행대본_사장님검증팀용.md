## 3. 실측 케이스 2 — 롤백 유도 (실패해도 구버전 살아있는지 — CTO B-3)

성공만 보면 롤백 미검증 = 거짓봉합. 아래 중 1건:

**방법 A — 다운로드 검증 실패 주입 (권장, 간단)**
- 1.2.34 zip 을 게시하되 **manifest 의 sha256 을 일부러 틀리게** 적어 게시
- 관측: watchdog 로그 "다운로드/검증 실패 — 적용 차단" + **ERP는 1.2.33 그대로 살아있음**(다운 안 됨)
- `local_update_apply_status` = blocked or 미기록(적용 진입 전 차단)

**방법 B — 백업 실패 강제**
- 백업 대상 경로를 쓰기 불가로 만들어 백업 실패 유도
- 관측: 로그 "🛑 적용 전 백업 실패 — 물리적 차단, status=blocked" + **ERP 1.2.33 무손상**

→ **핵심 = 실패했는데 ERP가 죽지 않고 구버전으로 살아있는가.** 이게 롤백/차단의 존재 이유.

## 6. PM 정지선 (스스로 못박음)

- **PM은 "실측 완료/성공"이라 말하지 않는다.** 관측은 사장님·검증팀 손. PM은 대본 제공 + 결과 받아 종합 보고([9])만.
- NCP·Sandbox·시간대 제약으로 PM이 여기서 완결 못 함 = 정직하게 명시. 이것도 "그냥 되면 되는 것"(사장님 정공법 정신).
