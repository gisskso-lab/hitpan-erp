## 3. 반증 ② — 표지 글자를 다른 장면 · 키가 써서 면제받는 길

`knownDefectFail` 을 직접 부름: 목록 밖 키(direct-welcome) + 표지 · webkit + 표지 · scope H + 표지 · 앞 공백 + 표지 · `pass="false"` 글자 · 결과 칸 객체 = **전부 거짓**. 키 무결성은 판정 시작 때(`knownDefectListProblems`) · 중복 키는 `bad` 로 먼저 빠짐. K 본문 `rec` 는 `res.known === true` 이고 키가 대장에 있을 때만 머리를 붙임 → 다른 장면(welcome · gate 등)은 붙일 수 없음. **길 없음.**

## 4. 반증 ③ — K 본문이 죽을 때 초록이 나오는 길

- 결과표 없음 → 판정기 `⚫ FAIL [장치] 결과표 없음`(손 0). 두 키 줄 없음 → 필수 키 누락 빨강(K-C27b 가 잼).
- 장면 예외 → `dev()` = DEVICE → `knownDefectFail` 거짓(TEST 만) → 면제 0(K-C27e · E3 직접 확인 끝 코드 1).
- 처리 안 된 예외 → 끝 코드 ≠ 0.
- `endCode([] , 0) = 0` · `endCode(null, 0) = 0` — 고침 2 의 `bad === 0` 과 같은 성질(새 구멍 아님). 본 흐름은 `fillDevice` 가 남은 키를 DEVICE 거짓으로 채우고 판정기가 누락을 따로 잡아 초록 길은 없음 → P3-3 기록만.

## 5. 보안 (4)

- 결과 칸 머리 = `KNOWN_WHY` + 대장 이름(상수) + 종전 결과 JSON. 저장은 `L.rec` → `sanitize(…, 300)`(비밀 값 전 꼴 `***`) 그대로 · 판정표 줄은 OBS 선례대로 `showCtl(L.sanitize(x.got, 1200))`.
- 결과 JSON 안 경로는 `pathOnly`(쿼리 뗌) · 문서 끝 사유 `sanitize(…, 40)` — 고침 2 그대로 · 이번 손 0.
- `::notice::` = 상수 + `m()` 소독 키 칸(id · g · path · browser) → 줄바꿈 · `::` 주입 자리 없음.
- 비밀 값이 표지 글자와 겹쳐 `***` 로 바뀌면 `startsWith` 거짓 → 빨강 쪽(닫힌 쪽) · 안전.
- 금지어(헌법 #23) · tenant · 암호화 컬럼 · 본사 전송 — 해당 없음(시험 장치만 · 새 바깥 통신 0).
