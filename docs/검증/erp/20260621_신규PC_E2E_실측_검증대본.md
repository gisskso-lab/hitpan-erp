# 신규PC 실설치 E2E 실측 검증 대본 (2026-06-21)

> 작성: PM 브라운킴 / 대상: 사장님(실행 주체) + 다음 세션 PM
> 목적: 7차 봉합(A-P0-1·B-1·D6-P0-01) + D6-P0-02 봉합이 **실제 신규 PC에서 작동**하는지 1회 실측.
> 사장님 격언: "테스트 100% = 실제 70~80%." 코드상 닫힘 ≠ 진짜 통과. 이 대본 PASS가 베타 GO의 마지막 관문.
>
> ⚠️ **실행 주체 = 사장님**. PM은 EXE 빌드(헌법: EXE 빌드 홀드)·터널 발급·실제 설치를 임의로 못 함(헌법 #29).
> PM 역할 = 이 대본 작성 + 결과 판독 보조. 빌드/설치 GO는 사장님 결재 후.

---

## 0. 사전 준비 (실행 전 체크)

| 항목 | 확인 |
|---|---|
| 깨끗한 신규 PC 또는 VM (Windows 10/11 64비트) | 히트판 한 번도 설치 안 된 환경 — 잔존 db.conf·서비스 0 |
| 최신 EXE 빌드 | 사장님 GO 결재 후 `build-installer.ps1` (현재 홀드 상태) |
| 백오피스 가입/시리얼 발급 동선 | 신규 고객사 시리얼 1개 준비(관리형 터널 발급되는 정식 경로) |
| 인터넷 연결 | 터널·백오피스 통신 필요 |

> VM 권장: 스냅샷 찍어두면 실측 반복·롤백 쉬움.

---

## 1. 설치 → 부모계정 로그인 (A-P0-1-REGRESSION 검증)

**무엇을 검증**: 7차 봉합이 부모계정(모든 고객사 첫 사용자)을 403으로 막던 회귀를 봉합했나.

1. EXE 실행 → 설치 완료까지 진행(목표 10분)
2. 설치 끝나면 브라우저 자동 오픈 → **부모계정 생성**(사업자 정보 입력)
3. **부모계정으로 로그인**

✅ **PASS 기준**: 로그인 성공 + 메인 화면 진입. "오류가 발생했습니다" / 로그인 500 없음.
❌ **FAIL 신호**: 로그인 직후 흰 화면·500·"권한이 없습니다".

---

## 2. 결재 흐름 끝까지 (A-P0-1 검증)

**무엇을 검증**: 결재 식별자(user_id ↔ employee_id) 봉합으로 결재가 실제로 도나.

1. 설정 → 사원관리 → 사원 1명 추가(자식계정)
2. 권한설정 → 결재선 설정
3. 자식계정으로 **연차/지출 결재 상신**
4. 부모계정(또는 결재자)으로 **결재 대기함 확인 → 승인**

✅ **PASS 기준**:
- 상신한 문서가 **결재 대기함에 보임**(빈 목록 아님)
- 승인 버튼 눌러 **상태가 "승인"으로 변경**
- "결재 권한이 없습니다" 차단 없음

❌ **FAIL 신호**: 대기함 항상 빈 목록 / 승인 시도 시 403.

---

## 3. 같은 품목 2라인 거래명세서 확정 (B-1 검증 ①)

**무엇을 검증**: stock_ledger UNIQUE 라인 합산 봉합으로 다라인 확정 시 롤백 안 나나.

1. 상품마스터에 품목 A 등록 + 재고 확보(매입 확정으로 입고)
2. 거래명세서 작성 시 **같은 품목 A를 2개 라인**으로 입력(예: 창고 다르게 or 단가 다르게)
3. **거래명세서 확정**

✅ **PASS 기준**:
- 확정 성공(500/롤백 없음)
- 재고가 **2라인 수량 합만큼 정확히 차감**("재고 안 빠짐" 없음 — 헌법 #20)

❌ **FAIL 신호**: 확정 시 500 / "이미 처리됨" / 재고 안 변함.

---

## 4. 같은 자재 조립품 2라인 판매 확정 (B-1 검증 ②)

**무엇을 검증**: BOM 자재 OUT의 공통자재 합산 봉합.

1. 공통 자재 M을 쓰는 조립품(BOM) 2종 등록 — 둘 다 자재 M 소비
2. 두 조립품을 **한 거래명세서 2라인**으로 판매 확정

✅ **PASS 기준**: 확정 성공 + 자재 M 재고가 2라인 소비량 합만큼 차감.
❌ **FAIL 신호**: 확정 시 UNIQUE 위반 500.

## 5. ⭐ 터널 강제 종료 → 5분 내 자가복구 (D6-P0-02 검증, 이번 봉합 핵심)

**무엇을 검증**: 관리형 터널이 죽었을 때 워치독이 토큰으로 자가복구하나(헌법 #27·#28).
이번 봉합의 P1(서비스 생존+secret 무효화 사각지대)이 실제로 닫혔나.

### 검증 파라미터 (코드 실측값)
- 워치독 정기 루프 = **60초** / 헬스 실패 임계 = **3회**(약 3분) / CoolDown = 시간당 5회
- 자가복구 로그 위치 = **이벤트 뷰어 → Windows 로그 → Application → 원본 "HitPanWatchdog"**

### 5-A. 서비스 강제 종료 시나리오 (가장 흔한 다운)
1. 관리자 PowerShell에서 cloudflared 서비스 **강제 중지**:
   ```
   Stop-Service cloudflared -Force
   ```
2. 외부 기기(폰 LTE 등)에서 `https://{고객사도메인}` 접속 → **다운 확인**(외부 헬스가 실제 실패해야 복구 트리거)
3. **최대 5분 대기**.
   - 복구 경로(코드 실측): 관리형 터널은 서비스가 *중지*돼도 등록은 남아 `!ServiceExists`=false라 정기 루프 D는 안 잡힘.
     대신 **외부 헬스 3회 연속 실패(약 3분) → FullRecovery 발동 → `IsManagedTunnel()`=true → D 강제(WS-28-E→D)** 경로로 복구.
   - 즉 1~2분이 아니라 **약 3~4분**에 복구 로그가 뜨는 게 정상(5분 헌법 게이트 내).
4. 이벤트 뷰어에서 **"WS-28-E: FullRecovery 발동"** → **"WS-28-E→D"** 또는 **"WS-28-D: cloudflared service reinstalled and started"** 로그 확인
5. 외부 기기에서 도메인 재접속 → **복구 확인**

✅ **PASS 기준**: 5분 이내 도메인 재접속 정상 + 이벤트 로그에 FullRecovery→WS-28-D 계열 복구 기록.
⚠️ **주의**: db.conf의 `PRIMARY_DOMAIN`이 비어있으면(LOCAL 모드) 외부 헬스가 항상 통과로 처리돼 FullRecovery가 안 뜸 — 이 시나리오는 외부 도메인 발급된 정식 설치에서만 유효.

### 5-B. 서비스 삭제 시나리오 (재설치 경로)
1. 관리자 PowerShell:
   ```
   Stop-Service cloudflared -Force; sc.exe delete cloudflared
   ```
2. **최대 5분 대기** → 워치독이 `!ServiceExists` 감지 → WS-28-D 재설치
3. `Get-Service cloudflared` → **서비스 재등록 + Running 확인**

✅ **PASS 기준**: 서비스 자동 재설치 + Running + 도메인 복구.

### 5-C. (선택) 재부팅 후 복구 (WS-28-B PostReboot 검증)
1. PC 강제 재부팅
2. 부팅 후 5분 내 이벤트 로그 "WS-28-B: post-reboot check active" + 복구 기록 확인
3. 도메인 정상 접속 확인

> ⚠️ **관리형 토큰 검증 포인트**: 5-A·5-B에서 복구가 되려면 db.conf에 `TUNNEL_TOKEN`이 저장돼 있어야 함.
> 설치 후 `C:\Program Files\HitPan\db.conf`를 관리자로 열어 **`TUNNEL_TOKEN=...` 줄이 있는지** 먼저 확인.
> (LOCAL 모드면 빈 값 — 그 경우 5-A·5-B는 자가관리 폴백 경로라 별도 판단)

## 7. FAIL 시 다음 PM 행동

- **5-A/5-B FAIL(복구 안 됨)**: db.conf TUNNEL_TOKEN 유무 먼저 확인 → 있으면 이벤트 로그에서 WS-28-D ExitCode 확인(cloudflared 인자 오류?) → 없으면 인스톨러 G_TunnelToken 추출 실패(백오피스 응답 tunnelToken 필드 점검).
- **2 FAIL(결재 차단)**: employees 행 생성 여부 DB 직접 확인(`SELECT * FROM employees WHERE user_id=...`).
- **3/4 FAIL(확정 롤백)**: API 로그에서 stock_ledger UNIQUE 위반 메시지 확인.

> 모든 FAIL은 실측 로그·스크린샷 첨부해 다음 세션 인수인계.
