| 구분선 | **1px** | `hp-toss.css:1009` |
| **행 1개 = 72.2px** | (뷰포트 높이 >820px 이면 **80.2px**) | |

🔴 **설계 §9-3 의 「여백을 `--hp-space-2` 로 줄인다」가 제 몫을 다 못 한다** — 줄인 8px 중 8px 이 `.mud-list-item-text` margin 으로 되돌아온다. F-7 을 넣으면 **64.2px**.

### §3-2 8행 예산 — 743px 필요

| 성분 | 값 | 출처 |
|---|---|---|
| 상단 헤더 + 테두리 | 48 + 1 = **49px** | `hitpan.css:60·64` |
| 본문 위 여백 (`mud-py-4`) | **16px** | `MainLayout.razor:81` |
| PageHeader | 제목 18×1.3=23.4 + 부제 2+18=20 + `padding-bottom` 8 + `margin-bottom` 16 = **67.4px** | `hitpan.css:1020~1041` |
| 카드 위 테두리 | **1px** | `hp-toss.css:995` |
| `MudList` 위 패딩 | **8px** (`Padding="false"` 안 걸었다) | MudBlazor 기본 |
| **첫 행 위 소계** | **141.4px** | |
| 8행 (마지막 구분선 없음) | 8×72.2 − 1 = **576.6px** | §3-1 |
| `MudList` 아래 8 + 카드 테두리 1 + 본문 아래 16 | **25px** | |
| **합계** | **743.0px** | |

### §3-3 판정 — 두 가지 답이 나온다

| 기준 | 여유 | 8행 서나 |
|---|---|---|
| **뷰포트** 768px (설계가 쓴 숫자) | 768 − 743 = **+25px** | ✅ 선다 (아주 빡빡) |
| **화면** 1024×768 에서 작업표시줄(40) + 브라우저 크롬(~105) 뺀 **뷰포트 ≈ 623px** 🔴 추정 | 623 − 743 = **−120px** | ❌ **6행** ((623−166.4)/72.2 = 6.3) |

- `@media (max-height: 820px)` 분기는 **켜진다**(623 < 820 · 768 < 820) — 하지만 이미 켜진 상태의 숫자가 위 743px 이다. **그 분기만으로는 못 맞춘다.**
- F-7 적용 시 행 64.2px → (623−166.4)/64.2 = **7.1행**. 여기에 메타를 `--hp-lh-snug`(1.4, 16.8px) + 메타 위 여백 0 으로 더 줄이면 57.8px → **7.9행**(겨우 8).
- **제안(결재 대상)** — `hp-toss.css:1051` 뒤에 한 단 추가:
```css
/* 🔴 설계 §9-3 8행 — 브라우저 크롬을 뺀 실제 뷰포트가 700px 아래로 내려갈 때 한 칸 더 줄인다. */
@media (max-height: 700px) {
    .hp-cs-board .hp-cs-row .mud-list-item-text { margin-top: 0; margin-bottom: 0; }
    .hp-cs-row-meta { margin-top: 0; line-height: var(--hp-lh-snug); }
}
```
- 🔴 **못 쟀다**: 623px 은 **추정**이다(브라우저·북마크바·배율 100%/125% 로 ±40px 흔들린다). **아무도 렌더하지 않았다.** 이 축은 §5 D-15 사장님 실측이 유일한 판정이다. 이 문서는 「8행이 안 선다」고 **단정하지 않는다** — 「768 뷰포트에서는 서고, 실제 창에서는 6~7행이 될 산술 근거가 있다」까지다.

### §3-4 ① 쪽 8행
① 은 행 높이가 **가변**이다(미리보기 줄바꿈 + 칩 `flex-wrap`). 1024 폭에서 칩 4개면 행이 2줄로 늘어 **행당 ~115px** ⇒ 같은 뷰포트에서 **4~5행**. ②와 「같은 화면 분량」이 안 된다.

## §4 D-4 좁은 폭 (1024) / D-5 색 대비

### §4-1 1024 폭 — 말줄임이 안 걸린다 (F-1)

- 1024px 에서 사이드바는 **안 접힌다**: `.hitpan-sidebar-aside{width:var(--hp-sidebar-w)}` = **260px** 고정이고, 숨김 분기는 `@media (max-width:767px)` 뿐이다(`hitpan.css:41·47·329`). `--hp-sidebar-w-narrow`(64px)는 **아무도 안 쓴다**.
- ⇒ 본문 폭 = 1024 − 260 − 32(`mud-px-4` 양쪽) = **732px**. `max-width:860px` 에 **안 닿는다** ⇒ 카드 732px · 행 안쪽 **700px**.
- 말줄임 3줄은 다 있다 — `white-space:nowrap`(`:1029`) + `overflow:hidden`(`:1027`) + `text-overflow:ellipsis`(`:1028`) ✅
- 🔴 **그런데 안 걸린다**: `.hp-cs-row-title` 은 `.hp-cs-row-head`(`display:flex`) 의 **직접 자식**이고, flex 자식 기본 `min-width:auto` = `min-content`. `nowrap` 글자의 min-content 는 **글자 전체 폭**이다 ⇒ 줄어들지 않는다. `.hp-cs-row-chips{flex-shrink:0}` 도 안 줄어든다 ⇒ **합이 700px 을 넘으면 그대로 넘친다.**
- 넘는 조건: `Title()` 이 **60자**까지 통과시킨다(`CsNoticePage.razor:98`). 한글 14px ≈ 14px/자 ⇒ 60자 = **~840px**. 칩 2개(「본사 안내」 ~84px + 「안읽음」 ~60px + 틈 16px) = ~160px. **840+160 = 1000px > 700px** ⇒ 🔴 **넘친다.**
- 한 단계 위(`.mud-list-item-text`)에는 MudBlazor 가 `min-width:0` 을 넣어 두었다 ✅ — **끊긴 자리는 우리가 만든 `.hp-cs-row-title` 한 곳**이다.
- F-1 적용 후: 제목 가용폭 = 700 − 160 − 8 = **532px ≈ 38자**에서 「…」 ⇒ 말줄임이 **실제로** 걸린다.
- 칩 줄바꿈: ②는 `.hp-cs-row-head` 에 `flex-wrap` 이 **없고** 칩 묶음이 `flex-shrink:0` ⇒ **안 넘긴다** ✅ (작지서 D-14 ② 통과). **①은 `flex-wrap` 이 있어 넘긴다** ❌.
- 🔴 **못 쟀다**: 「한글 14px ≈ 14px/자」는 Pretendard Variable 의 평균 전각폭 가정이다. 실제 글자폭은 렌더해야 안다.

🔴 **F-3 의 뿌리 — `design-tokens.css` 의 MudBlazor 다리(`:244~261`)가 죽어 있을 수 있다.**

- `MudThemeProvider` 는 `PaletteLight` 에 **안 적은 칸까지 기본값으로 전부 내보낸다**. `App.razor:46~53` 은 `Primary·Secondary·Appbar*·Error` **5칸만** 적었다 ⇒ `Info`·`Success`·`Warning`·`LinesDefault` 는 **MudBlazor 기본값**(`Info=#2196f3`, `LinesDefault=rgba(0,0,0,0.12)`)이 선다.
- 이것이 ①의 테두리가 `#D5DAE0` 이 아닌 이유(F-8)와 같은 뿌리다.
- 🔴 **단정하지 않는다.** `<style>` 주입 위치는 MudBlazor 버전 구현 사항이고 **렌더로 확인하지 않았다.** 그래서 F-3 의 제안은 **다리를 믿지 않는 쪽**(칩에 `--hp-status-info-fg` 를 직접 주기)으로 썼다 — 어느 쪽이 이겨도 6.62:1 이 선다.
- `App.razor` 의 `PaletteLight` 에 `Info = "#1C5BB0"` 를 더하는 **전역 수선은 이 차수에서 제안하지 않는다** — `Color.Info` 를 쓰는 **모든 화면**이 같이 바뀐다(범위 밖 · 설계 §10). 별건 트랙으로 올린다.
