### 2-2. `Sec-Fetch-Site` 헤더 생존 확인 (K1 ⑤ 조건 · 회의록 §6-1 F-3 · #31)

- 문제: K1 은 `Sec-Fetch-Site ∈ {same-origin, none}` 이 없으면 거부한다(§7-2 K1). **백신 웹실드·프록시가 이 헤더를 지우면** 정상 사용자가 전부 거부된다.
- 방법(🔴 실물 금지 → **백지 Sandbox** 에서):
  1. Sandbox 에 정식 설치 + 실제 터널 + **백신 1종 이상**(Windows Defender 기본 + 가능하면 1종 추가).
  2. **실제 엣지·크롬**으로 `http://127.0.0.1:5257` 창을 열어 로그인 → 개발 갈래가 넣은 진단 로그(요청 헤더 덤프) 또는 응답 코드로 `Sec-Fetch-Site` 값 확인.
  3. 헤더가 살아 있으면 K1 ⑤ 그대로. **지워지면** → 「⑤ 헤더 부재 시 통과 + 불변식 게이트(인증 쿠키 0 · 파괴급 POST 만)로 대체」로 전환하고 **근거를 이 문서에 기록**.
- 대조군: 백신 없는 Sandbox 와 값 비교(헤더 변형이 백신 탓인지 가른다).
- 참고 🟢: 지문(`HFPv2-`)은 origin 이 달라도 같은 브라우저·화면이면 같은 값임을 격리 테스트로 이미 확인(선행검증서 CTO-4). 즉 127 창은 지문으로 도메인 줄에 붙으므로 **J 는 지문 조회보다 먼저 판정해야** 한다(§6-1 F-1) — 이 순서를 db-gate 로 재확인.

### 2-3. 실물 무접촉·게시 순서 (작업지시서 §8 C-9·C-10 — 주소로)

- **C-9 실물 무접촉**: 이 PC 의 `127.0.0.1:5257` 과 3306 운영 DB(`hitpan_erp_t004`)는 **실물 설치본**이다. 개발·게이트·검증 어느 갈래도 요청·접속 0. 검증은 TestServer(메모리)·CI db-gate·격리 환경만. 🔴 **게시 전 필수 ①(조회)은 사장님이 직접** 돌리신다(검증팀 실행 금지 · 헌법 #39). 로컬 DB 게이트 실행도 PM 확인 전 금지(작지서 §8 C-9).

## 4. 사장님 화면 실측 대본 (게시 후 · 주소를 반드시 함께 안내)

4. **자료관리 → 찾아보기** → 폴더 선택(경로 직접 입력도 가능).

   - 🔴 **첫 세션부터** 403 없이 진행되나(AC-02·14).
   - 도메인 탭(`test1234.hitpan.kr`)을 따로 열어 업무 화면이 정상인가 — **안 갇히나**(AC-02).

   - 덮어쓰기 직후 버튼 잠금·「백업하고 정리하는 중」 안내(병렬이슈18 · 게이트로 못 재는 자리).
