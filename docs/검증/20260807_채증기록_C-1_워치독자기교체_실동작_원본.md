### 2-1. 이 로그가 왜 결정적인가

출발점이 **1.2.52** 다. 이 버전은 **자기교체 능력이 없는 구버전**이다.
스스로 못 바꾸는 워치독이 깔린 PC 를 **새 API 가 대신 교체**했다는 뜻이며,
이것이 W4-3-H 설계의 존재 이유이자 두 달 무한루프의 유일한 탈출구다.

관련 소스: `src/HitPan.API/Startup/WatchdogHandoffBootstrap.cs`
- `:62` `StageDirName = "watchdog.handoff"` — 구버전이 "잔재"로 오판해 지우지 못하도록 이름을 분리
- `:145` 현재 워치독이 스스로 교체 가능하면 핸드오프는 물러난다(이중 교체 방지)
- `:305` 교체 예약 완료 로그

### 2-2. ⚠️ 로그 한글 깨짐 (부수 발견)

콘솔 출력에서 한글이 `?좊쾭???뚯튂?낆쓣` 형태로 깨졌다.
**기능 결함은 아니나**, CS 상담원이 원격지원 중 이 로그를 읽어야 하는 상황에서
**판독 불가**가 된다. 별도 항목으로 이관한다(§6 이관사항 D).

## 5. 채증 중 새로 드러난 사실 3건

> 이 절이 이 문서의 실질 가치다. 통과를 확인한 것보다 **통과 과정에서 드러난 것**이 중요하다.

### 5-1. 🔴 워치독이 새 버전을 스스로 발견하지 못했다 (신규 · 미봉합)

**실측 경과**

| 시각 | 사건 | `latest_version` |
|---|---|---|
| 19:30:01 | 워치독 발견 기록 | 1.2.54 |
| — | 사장님이 **직접** `sc.exe stop` → `sc.exe start HitPanWatchdog` 실행 | — |
| 19:34:27 | 재시작 직후 발견 | **1.2.55** |

즉 **워치독을 사람이 재시작하기 전까지 1.2.55 를 발견하지 못했다.**

**왜 심각한가**

고객 PC 에서는 아무도 `sc start` 를 치지 않는다.
"고객 손 0번"(헌법 #30) 이 이 지점에서 성립하지 않는다.
사장님은 히트판을 만든 사람이라 재시작을 떠올렸지만, 고객은 떠올릴 수 없다.

**등급**: 🔴 **P0 후보** — 원인 규명 전이므로 확정하지 않는다.
**다음 조치**: 원인 규명 필요(발견 주기 · 캐시 · 매니페스트 조회 실패 재시도 등).
현재는 **현상만 기록**한다. 추측으로 원인을 적지 않는다.

### 5-2. 🟡 `Get-ScheduledTask` 접근 거부 — CIM 세션 실패

```
Get-ScheduledTask : Cannot connect to CIM server. 액세스가 거부되었습니다.
```

관리자 권한(`IsElevated: true`)인데도 실패했다.
**기지의 사고다** — `ae18dc0 fix(설치/P0·P1): 워치독 Guardian 등록순서 + CIM 회피 + 종료코드 규약 (#55)`
에서 이미 제품 코드는 회피 처리했으나, **CS 진단 절차에는 반영되지 않았다.**

**영향**: 원격지원 중 상담원이 예약작업 상태를 확인하려다 막힌다.
**회피**: `schtasks /query /TN "..."` 사용.
**이관**: CS 매뉴얼 (§6 이관사항 B)

### 5-3. 🔴 디스크 여유공간 — 측정값 0GB / 제품 검사 0건

채증 결과:
```
사용(GB)  여유(GB)
   0         0
```

샌드박스 가상디스크 특성으로 `Get-PSDrive` 가 0 을 반환했을 가능성이 있어
**이 수치 자체는 결함 증거로 채택하지 않는다.**

다만 **제품이 디스크를 한 번도 재지 않는다**는 사실은 별도로 확인되었다:

```
grep -rn "DriveInfo|AvailableFreeSpace|TotalFreeSpace" src/HitPan.Watchdog/  → 0건
```

설계팀 최종설계서 **P0-2** 와 동일 사안이다.
업데이트 1회가 수백 MB 를 요구하는데 사전 검사가 없고,
**롤백도 디스크를 쓰므로 부족한 순간 안전망까지 함께 무너진다.**
전례: `eaba641 fix(작9/P0): NCP 디스크 100% DB 사망 근본봉합`

## 7. C-3 미채증 사유 (기록)

C-3(교체 중 실패 주입 → `watchdog.bak` 복원 확인)는 **오늘 수행하지 않았다.**

**사유**: 현 샌드박스는 교체가 **이미 완료**되어 재료(`watchdog.new`/`.old`)가 정리된 상태다.
이 환경에서 실패를 주입하면 "교체 중 실패"가 아니라 "정상 워치독을 파손"한 것이 되어
**다른 시험을 하고 C-3 를 했다고 기록하는 거짓봉합**이 된다.

**다음 차수 조건**: 구버전(예: 1.2.52)을 설치한 새 백지환경에서,
교체가 시작되는 시점을 붙잡아 실패를 주입해야 한다.
