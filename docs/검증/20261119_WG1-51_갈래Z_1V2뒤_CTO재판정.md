### §0-1 대표 질문안
「고친 판 시험 1번(비교 런)에 쓸 **시험 컴퓨터 글꼴 길**을 골라 주십시오. 지난 길(글꼴 별명)은 인쇄 부품이 별명을 아예 보지 않는다는 것을 쏘기 전에 찾아 멈췄습니다 — 1번은 잃지 않았습니다.」
- **① 시험 컴퓨터 안에서만, 무료 한글 글꼴(나눔고딕)의 속 이름을 「Malgun Gothic」 으로 바꿔 둔다 (추천)** — 제품 · 설치본 · 저장소 0 · 시험이 끝나면 사라짐 · 법무팀장 확인 뒤 착수 · +1일 안팎.
- ② 글꼴 파일은 그대로 두고, 시험 때만 프로그램 시작 앞에 「이 글꼴을 Malgun Gothic 으로 불러라」 를 끼운다 — 법무 부담 가장 적음 · 먹는지 모르는 칸이 더 많음 · +1~2일.
- ③ 시험 컴퓨터를 윈도로 바꾼다 — 고객과 가장 같음(그 컴퓨터에 맑은 고딕이 있는지는 미확인) · DB 차림을 다시 짬 · 수일 · 실행 비용 늘어남.
- (공통) 어느 길이든 글꼴이 또 안 먹으면 §51 그대로 그 1번을 잃고 다시 여쭙니다.

## §2 판정 2 — R1 · 머지 · A~F

- **R1 = 같은 벽.** 근거: ① ui-print 잡 · `runs-on: ubuntu-24.04` 동일 ② 렌더 = 같은 QuestPDF 리눅스 네이티브 ③ T8 견본(PrintProbe)은 판과 무관하게 같은 QuestPDF 로 그림 → T8 빨강이 판 고침과 상관없이 정해짐 ④ 앞 재판정 §3 「R1 양성 대조 실패 → 같은 장치로 R2 안 쏨」 규칙.
- 고친 합류본에 E⑵(글꼴 내장 자리)가 렌더러에 한글 글꼴을 등록하더라도 T8 은 여전히 빨강이고, main 칸은 여전히 빈 한글이다 → 벽은 그대로 · 오히려 두 판이 다른 글꼴로 차려지는 비대칭 위험이 더해짐(**F6 확인 필요**, R1 전).
- **「머지 = R1 통과 뒤」 는 측정 환경 고침 없이는 영영 안 열린다 — 맞다.** 그러므로 이 줄을 풀지 않는다(검증 전 머지 = 8/27 작7 꼴). 대신 **글꼴 길 결재를 머지의 임계 경로로 올려** 대표 보고에 그렇게 적는다. 대표가 셋 다 고르지 않거나 법무가 ① · ⑤-가를 모두 막으면, 그때 머지 줄 자체를 다시 여쭌다(지금 여쭐 일 아님).
- **A~F 코딩 계속** — 앞 재판정 §3 의 갈래별 표 그대로. 반증: 손실 상한이 「재설계 + R1 한 바퀴 코딩분」 에서 「글꼴 길 결재 대기분」 만큼 더 늘어난다 → 결재된 갈래 밖 새 착수 0 · 겹치는 파일(`PdfRenderService.cs`)은 갈래 차례를 PM 이 정함.

## §4 판정 4 — 추천 ① 과 그 반증

- **① 을 ⑤-가 보다 앞에 두는 까닭**: ① 은 [1-V] 가 세운 바로 그 장치(폴더 훑기 · 이름 정확 일치)를 맞춘다 — [1-V] §3-4 ① 스스로 「E10 정확 일치로 잡힘」. ⑤-가 는 미확인 넷 위에 서고, T8 이 API 프로세스의 고리를 증명하려면 T8 도 같은 고리로 돌아야 한다. 먹을 확률 = ① > ⑤-가. 법무 부담 = ⑤-가 < ①. §51 이 「1번 잃음」 을 가장 무겁게 봤으므로 **먹을 확률을 앞에 둔다.**
