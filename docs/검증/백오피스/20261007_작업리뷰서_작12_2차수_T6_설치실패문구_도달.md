## §6 PM 변경 결재 반영 (2026-10-07 · ⓑ 삭제 + `G-T6-4` 음성 신설)

> 받은 변경: **설계 §2-1 의 `$human` 폴백 ⓑ(`ErrorDetails.Message` 원문) 삭제** · ⓐ 실패 시 **고정 한글 문장** · 원문은 `ErrorFile` 로만 · 신설 **`G-T6-4` 음성**(`message` 없는 본문의 글자가 한 조각도 안 섞인다 · ⓑ 되살리면 FAIL).

### §6-1 내 §2 V1 지적과의 관계 — 🟢 **닫힌다**

V1 이 수치로 잡은 두 갈래(400 ProblemDetails **212자** · 엣지 502 HTML **144자**)는 **전부 ⓑ 경유**다. ⓑ 가 없어지면 그 212/144 자가 **고객 대화상자에 올라올 길이 사라진다.**
⇒ 🟢 **V1 을 「ⓑ 삭제로 닫힘」으로 내린다.** 내 지적 등급은 유지하되 처방은 **PM 결재가 먼저 나왔다**(내가 「문구는 내가 정하지 않는다」로 남긴 자리를 PM 이 메웠다).
🔴 **단 게이트 조건이 하나 늘었다**: `G-T6-4` 음성은 **「섞이지 않음」**만으로는 모자라다. **고정 한글 문장이 실제로 그 자리에 떴는지**(길이 ≠ 0 · 「알 수 없는 오류」가 아님)를 **같이 단언**해야 한다. 안 그러면 `message` 가 빈 채로 `:604` 의 `'알 수 없는 오류'` 로 떨어져도 **음성 단언은 통과**한다.

### §6-2 🔴 PM 이 넘긴 질문 ① — 「423·401·500 은 전부 `message` 키를 가져 ⓐ 로 닿는다」가 사실인가 → 🟢 **사실이다 (내가 검산)**

**근거 1 — 코드 전수**(`git show origin/main:src/HitPan.Backoffice.API/Controllers/InstallerBootstrapController.cs`): 이 컨트롤러가 **스스로 내는 비-2xx 는 6개뿐**이고 **6개 전부 `message` 를 싣는다.**

| 줄 | 코드 | `message` |
|---|---|---|
| `:73` | `BadRequest(new { success=false, message="시리얼 키를 입력해주세요." })` | 🟢 |
| `:75` | `BadRequest(... "PC 정보가 누락되었습니다.")` | 🟢 |
| `:160`·`:164` | `StatusCode(423, … "시리얼 입력 5회 실패로 잠시 중지되었습니다. 1시간 뒤 다시 시도해주세요.")` | 🟢 |

| `:389` | `StatusCode(500, … "부트스트랩 처리 중 오류가 발생했습니다.")` | 🟢 |

**근거 2 — 동작 측정**(§2 V1 표 · 설계 §2-1 규약 이식): 세 본문을 ⓐ 에 먹여 **42 · 29 · 22 자**가 나왔다. `ConvertFrom-Json` 실패 0건 · `.message` 빈 값 0건.
⇒ 🟢 **「ⓑ 를 없애도 423·401·500 의 목적(1시간 뒤 다시 시도)은 안 깎인다」는 맞다.**

🔴 **그러나 조건 3개를 붙인다 (「안 되는 경우」)**:
1. **`message` 가 빈 문자열이면 ⓐ 가 조용히 실패한다.** 위 6개는 상수라 안 비지만, **`.message` 가 있는데 공백**인 경우의 분기가 설계·결재에 없다 ⇒ **ⓐ 성공 판정은 「키 존재」가 아니라 「다듬은 뒤 길이 > 0」**이어야 한다.
2. **이 컨트롤러 밖에서 오는 비-2xx 는 `message` 가 없다** — `[ApiController]`(`:26`) 자동 400 ProblemDetails · 미들웨어 · 엣지(NCP·CF) 오류 HTML. 즉 **「전부 `message` 를 가진다」는 컨트롤러에 닿은 경우에만 참**이다(그래서 ⓑ 삭제가 옳다).
3. **ⓒ(`$_.Exception.Message`) 의 처리가 변경 결재에 안 적혔다.** 🔴 **오늘 통신 사고에서는 고객이 쓸모 있는 한글 18자를 본다**(내 측정 V11: `원격 서버에 연결할 수 없습니다.` · `"`·`,`·`}`·개행 0건). ⓒ 까지 고정 문장으로 덮으면 **오늘보다 정보가 줄어든다.** ⇒ **ⓒ 유지/교체 여부 = 미결(결재 필요).** 내가 정하지 않는다.

### §6-3 🔴 PM 이 넘긴 질문 ② — 새 Pascal 함수가 `\uXXXX` 를 되돌리나 · 고객이 외계어를 보나

| 축 | 측정 | 판정 |
|---|---|---|
| **지금 한글이 `\uXXXX` 로 오나** | PS 5.1 `ConvertTo-Json` 직접 측정 → `{"n":"\u0026\u003c\u003e\u0027한"}` | 🟢 **한글은 생글자로 온다.** `가` 꼴 외계어는 **오늘 안 난다** |
| **그럼 무엇이 `\uXXXX` 로 오나** | 같은 측정 | 🔴 **`&` `<` `>` `'` 넷** → `\u0026` `\u003c` `\u003e` `\u0027` |
| **설계 §2-2 규약이 되돌리나** | 규약을 이식해 실측 → `A\u0026B상사 …`(38자) → **`A&B상사 …`(33자)** | 🟢 **규약대로면 되돌아온다** |
| **옛 함수는 되돌리나** | `ExtractJsonValue`(`:340-365`)에 `\u` 처리 0줄 | 🔴 **안 되돌린다** |

🔴 **그래서 남는 구멍 두 개**:
1. **비대칭이 남는다.** W-2 는 `message` **1곳**만 새 함수로 간다(W-3 · `:603`). 나머지 8개 이름은 옛 함수 ⇒ **`companyName` 에 `&` 가 있으면 오늘처럼 `\u0026` 가 그대로 들어간다**(§1-3 측정 · 8/9). **고객 상호에 `&` 는 흔하다.** 별건 과녁으로 접수해야 한다 — `ExtractJsonValue` 무수정 방침과 충돌하므로 **내가 정하지 않는다**.
2. **구현 축 3개가 미측정(⚠️가설)** — Pascal 쪽은 ISCC 가 없어 못 쟀다:
   - ① `\uXXXX` 의 **소문자 16진**(`\u0026` vs `\u002a` vs `\U0026`) 처리
   - ② **대리쌍**(이모지 `\uD83D\uDE00`) — Inno 문자열은 UTF-16 이라 코드유닛 2개를 이어 붙이면 되지만 **안 재 봤다**
   - ③ `\u` 뒤에 **16진이 4자 안 되는 깨진 입력**에서 `Copy`/`StrToInt` 가 어떻게 되나(예외·0·무한루프)
   ⇒ **게이트 케이스로 못 박아야 한다**(§5 C-11 에 `&`·`'`·소문자16진·깨진 `\u` 4종 추가).
