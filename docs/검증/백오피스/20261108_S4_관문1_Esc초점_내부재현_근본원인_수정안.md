## 0. 한 줄
**지연이 길면 「목록이 그려진 뒤 ~ 첫 항목에 초점이 가기 전」 사이에 틈(방향당 300ms 에서 약 0.6초)이 생긴다. 그 틈에 Esc 를 누르면 Esc 가 단추에 떨어져 우리 E1-a 손잡이가 닫는데, E1-a 는 닫기만 하고 초점을 단추로 돌려놓지 않는다. 이미 출발한 「첫 항목 초점」 이 뒤늦게 도착해 초점을 목록 안으로 옮기고, 곧 목록이 지워지며 초점이 BODY 로 떨어진다.** 내부 [4] 는 첫 항목 초점이 간 것을 확인한 뒤 Esc 를 눌러 이 틈을 한 번도 밟지 않았다.

## 3. 근본원인 — 🟢 실측 확정 (기록 원문 · 방향당 300 · Enter · Esc 기다림 900)
```
 8374  목록 DOM 추가(그려짐)                       ← HQA 「열림 관측」
 9018  focus() 목록 wrapper(초점 못 받는 div) → 초점 그대로 단추
 9311  Esc 누름 → keydown 대상 = 1번 줄 단추       ← 첫 항목 초점이 아직 안 옴
 9623  focusin 첫 항목 · focus() 첫 항목          ← 서버가 Esc 를 받기 전에 이미 보낸 「첫 항목 초점」 도착
10551  focus() wrapper ×2
10553  focusout 첫 항목 → null                    ← 닫기 렌더가 목록을 지움 → BODY
10554  focus() 첫 항목(이미 떨어져 나감) → BODY 그대로
10555  목록 DOM 제거
       (단추로 초점 돌려놓는 호출 0)
```
- 정정(CTO 대조 §1-3): `10554 focus() 첫 항목` 은 MudMenu 호출이 아니라 **Blazor 렌더러가 렌더 배치 적용 뒤 하는 초점 복원 시도로 보인다(추정 · 미확인)**. 「단추로 돌려놓는 호출 0」 결론은 그대로.
1. **틈이 생기는 까닭(9.3 원문)** — `MudMenu.OnAfterRenderAsync`(L1012~1029)는 열린 뒤 `await _menuWrapperRef.FocusAsync()`(L1020) 왕복을 **기다린 다음에** `FocusItemAsync`(L1026)로 첫 항목 초점을 보낸다. 그려짐 → 첫 항목 초점 = 약 2 왕복(실측 1.23~1.26초 @ 방향당 300).
2. **Esc 가 단추에 떨어지면 우리 손잡이가 받는다** — 그 틈에는 초점이 단추에 있다 → 9.3 의 Esc 길(목록 wrapper `@onkeydown` → `HandleDismissalKeyAsync` → `CloseAllMenusAsync`)에 안 닿고, E1-a `OnCellKeyDownAsync` 가 받는다.
3. **E1-a 는 닫기만 한다** — `_menu.CloseMenuAsync()`(9.3 L495~527)는 닫기만 하고 초점을 건드리지 않는다. 9.3 이 단추로 초점을 돌려놓는 것은 `CloseAllMenusAsync`(L535~554)의 `FocusActivatorAsync`(L553 → L1088~1115) 뿐이다.
4. **늦게 온 첫 항목 초점이 초점을 끌고 간다** — 9623 에 첫 항목 초점이 도착해 초점이 목록 안으로 간다 → 10553 닫기 렌더가 목록을 지우면서 초점이 BODY 로 떨어진다 → 단추로 돌려놓는 호출이 없어 BODY 로 남는다.
- 마우스로 연 경우(C 9/9 🟢)는 `_lastInteractionWasKeyboard` 가 거짓이라 첫 항목 초점을 보내지 않는다 → 초점이 단추에 그대로 남아 E1-a 가 닫아도 문제없다.
- 지연 0 · 방향당 150(A 24/24 🟢)은 700ms 안에 첫 항목 초점이 이미 와 있어 Esc 가 9.3 길로 간다.
- **인계15 의 가설(「Esc 뒤 다시 그리기와 초점 처리 시점 어긋남」)은 반만 맞았다** — 어긋나는 것은 Esc 뒤가 아니라 **Esc 앞(열기 쪽 첫 항목 초점이 늦게 옴)** 이고, 본질은 **E1-a 닫기 길에 초점 돌려놓기가 빠진 것**이다.

## 4. 실사용 영향 (등급은 CTO · 대표)
- 틈 너비 ≈ 1 왕복, 그려진 뒤 약 1~2 왕복 사이. 실사용 왕복(터널 · 백오피스 NCP)이 100ms 면 그려진 뒤 0.1~0.2초 사이 Esc — 잘못 연 목록을 바로 닫는 손이면 밟을 수 있다.
- 증상: 목록은 닫힌다 · 고름 0 · 행 상세 0 · 데이터 영향 0. **초점이 BODY 로 떨어져 다음 Tab 이 화면 맨 위부터 다시 시작**(키보드 · 화면읽기 사용자가 자리를 잃음). 작업지시서 M12-k 위반.
- PM 의견: **받아들임 비추천** — 원인이 우리 E1-a 한 줄이고 고침이 9.3 공개 메서드 한 단어라, 받아들일 까닭(고침 비용 · 위험)이 없다.
