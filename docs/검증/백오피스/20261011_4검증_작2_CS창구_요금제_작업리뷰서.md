### V-3 🔴 **P1** · 폐기가 `bo_cs_replies.body` 를 안 비운다

| 항목 | 내용 |
|---|---|
| 증상 | `PurgeTicket` 은 `bo_cs_tickets.body` 만 `NULL` 로 만든다. 같은 티켓의 `bo_cs_replies` 는 손대지 않고, `Detail` 이 그 `replies` 를 **본문 포함** 그대로 돌려준다. ⇒ 화면에 「폐기됨」 칩이 뜬 티켓을 열면 **본사 답장 전문이 그대로 보인다.** |

| 🔴 결재 필요 | 답장도 비울지(`body=NULL` 은 **NOT NULL 이라 불가** — 빈 문자열이냐 별도 표식이냐) 는 **PM·법무 결재 사항**이다. 내가 정할 수 없다 |

### §5-1 절B 가 올린 판정 요청 2건 — 검증팀 의견

**ⓐ 「제외」를 글자 교체로 좁힌 것이 오더를 만족하나**

🟢 **만족한다고 본다. 단 근거는 절B 가 적은 것과 다르다.**

오더는 「요금제 제외 버튼을 추가로 넣을것」이다. 사장님이 **「제외」라는 낱말로 가리킨 동작**(과금·노출에서 빼되 지우지 않기)이 화면에 **사람이 누를 수 있는 버튼**으로 서 있으면 오더는 충족된다 — 버튼을 **새로** 만들었는지는 사장님 관심사가 아니다. `AdminPricing.razor:185~199` 가 양방향 버튼 + 상태 칩 + 설명 한 줄을 갖췄고, 「활성/비활성화」(개발 용어) → 「제외/포함」·「판매중/제외됨」으로 바뀐 것은 **#23 고객 노출 용어 축에서도 개선**이다.

🔴 **다만 ⓐ 를 「만족」으로 닫기 전에 V-10 을 먼저 봐야 한다.** 버튼은 섰지만 **버튼이 하는 일을 화면이 사실과 다르게 설명한다.** 「신규 가입에서 빠집니다」는 코드가 보증하지 않는다. 문구를 사실에 맞추는 것이 **ⓐ 의 조건**이다.
🔴 **그리고 PM 전제가 틀렸다는 절B 의 보고는 사실이다** — 내가 `16669004` 트리에서 직접 확인했다. 토글 버튼과 상태 칩이 이미 있었다. 「버튼 0개」는 실측이 아니라 **낱말 대조**였다.

**ⓑ 제외 축이 `is_active` 단독인 것이 맞나**

🟡 **축 선택은 맞다. 그러나 「과금에서 뺀다」는 서술은 코드가 뒷받침하지 않는다 — 사장님 결재로 올려야 한다.**

- 🟢 **축을 하나로 둔 판단은 옳다.** `is_active` 를 쓰면 공개 요금표 2곳이 동시에 막힌다(`LandingPublicController.cs:66` · `PromotionsAdminController.cs:293` 둘 다 `is_active=1 AND is_visible=1`). `is_visible` 만 내리면 `LandingPublic` 은 막히지만 **축이 둘로 갈라진다** — 절B 의 우려가 정확하다.
- 🔴 **그런데 「제외 = 과금·노출에서 빼기」(작업지시서 §2 B-3)의 「과금」 쪽은 집행자가 0명이다.** `pricing_plans` 소비처 7곳을 전수로 봤다(실측): `is_active` 를 보는 곳은 **공개 요금표 2곳뿐**이다. 구독·청구 경로에서 `is_active` 를 읽는 코드 **0건**, 가입 입구 검증 **0건**(V-10), `DeviceRegistrationController.cs:69` 의 기기 상한 JOIN 은 `is_active` **무조건 무시**.
- ⇒ **지금 「제외」의 실효 범위 = 「새 고객에게 안 보인다」뿐이다.** 기존 가입자 과금과 기기 상한은 그대로 간다.
- 🔴 **사장님이 쓰신 이유가 「베타 테스트시 필요」다.** 그 뜻이 ㉮「새 고객에게 안 보이게」면 **지금 구현으로 충족**이다. ㉯「그 요금제 과금을 멈춰라」면 **별건 트랙이 필요하다**(구독 축 — §6-1 대리점 면제정책과 같은 자리). **둘 중 어느 것인지는 내가 정할 수 없다 — 사장님 결재.**

## §8 이 폴더의 다음 사람에게

- 🔴 **`installer/backoffice/*.sql` 의 `ADD COLUMN IF NOT EXISTS` 는 MariaDB 전용인데 「고치면 안 되는」 문법이다.** 적용기(`SchemaMigrator.StripAlterExistsTokens`)가 MySQL 경로에서 벗긴다. **SQL 파일만 보고 「MySQL 8 에서 1064」라고 판정하지 마라** — 적용기를 먼저 읽어라.
- 🔴 **표를 더하면 `BackofficeSchemaMysql8GateTests` 의 목록이 세 개다** — `RequiredTables` · `RequiredColumns` · `RequiredColumnTypes`. **표만 더하고 칸을 안 더하면 작1 사고가 그 자리에 다시 열린다**(이 트랙의 V-1 이 그 실례).
- 🔴 **백오피스는 시각 기준이 두 갈래다** — 코드는 `UTC_TIMESTAMP(6)` 로 통일됐는데 **DDL 의 `DEFAULT current_timestamp(6)` 는 세션 시간대(KST)** 다. 칸을 안 채우고 DEFAULT 에 맡기면 **그 줄만 +9h** 가 된다. 로컬 실측 **540분**.
- 🔴 **CS 대화는 표가 셋이다** — `bo_cs_tickets`(받은 것) · `bo_cs_replies`(답) · `bo_cs_outbound`(선발신). **「쪽지를 지운다」를 설계할 때 셋을 다 세라.** 지금 폐기는 첫 번째만 건드린다.
- 🔴 **백오피스 게이트는 컨트롤러 메서드를 직접 부른다** — `[Authorize]`·미들웨어를 **안 지나간다**. 권한을 새로 걸었으면 **그 게이트로는 확인이 안 된다.**
- 🟢 **요금제 상태 글자를 선택자로 쓰는 E2E 는 0건이다**(2026-10-11 전수 확인). 칩·버튼 글자는 자유롭게 바꿔도 E2E 가 안 깨진다.
