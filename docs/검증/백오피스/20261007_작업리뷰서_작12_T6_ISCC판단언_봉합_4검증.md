## §4 내가 찾은 "안 되는 경우"

### V-1 🚨 **P0 — 봉합이 빨강을 못 닫는다. 오히려 「영구 빨강」을 만들었다** (실측 M-12·M-13)

`ISCC.exe` 의 FileVersion·ProductVersion 이 둘 다 `0.0.0.0` 이므로:
- `IsSameInnoVersion("0.0.0.0", "6.7.1")` = **false** (내가 M-14 에서 직접 재었다 — 표 5행)
- 보조 OR 인 글자 대조도 false (배너에 숫자 없음 — 주장 3)
- ⇒ 세 OR 전부 false ⇒ **무조건 throw.** 러너 ISCC 가 진짜로 6.7.1 이어도(주장 4 로 사실 확인됨) **항상 FAIL** 한다.

이건 단순 미완이 아니라 **방향이 바뀐 사고**다. 이 레포는 "늘 실패하는 체크는 아무도 안 보게 된다"를 이미 겪었고 그 교훈이 `.github/workflows/trufflehog.yml` 주석에 그대로 적혀 있다 —
`"즉 시크릿이 발견된 게 아니라 **스캔이 시작조차 못 했다.** 그런데 결과는 빨간 X 라 '늘 실패하는 체크'가 되어 아무도 안 보게 됐다"`.
지금 T-6 게이트가 같은 모양이 됐다.

### V-2 🔴 **게이트는 "시험본 == 출하본" 을 재지 않는다 — 같은 파일 안의 리터럴과 자기를 재고 있다**

N4 의 약속은 "시험본 Inno 판 == 출하본 Inno 판" 이다. 그런데 실제 비교는
**러너 ISCC ↔ `build-and-test.yml:114` 에 손으로 적힌 `"6.7.1"`** 이다.
출하 쪽 핀(`build-installer.yml:179` · `deploy-update.yml:581`)과 **대조하는 장치는 레포에 0건**(M-11 · 전수 grep).

⇒ 누가 `build-installer.yml` 을 `6.8.0` 으로 올리고 `build-and-test.yml` 을 안 고치면,
시험본(6.7.1)과 출하본(6.8.0)이 **실제로 갈렸는데 게이트는 초록**이다. N4 가 막겠다던 바로 그 사고를 못 막는다.
세 리터럴을 서로 묶는 게이트(또는 단일 진실원 1곳) 가 없는 한 이 단언은 **자기참조**다.

### V-3 🔴 **기대값 절단 = 조용한 초록** (M-14 실측)

`IsSameInnoVersion` 은 `actual.StartsWith(expect + ".")` 이다. `expect` 의 **자릿수를 아무도 단언하지 않는다**.

| actual | expect | 결과 | 뜻 |
|---|---|---|---|
| `6.7.1` | `6.7.1` | **TRUE** | 기준 양성 |
| `6.7.1.0` | `6.7.1` | **TRUE** | 4자리 양성 (PM 의도) |
| `6.7.10` | `6.7.1` | false | PM 음성 대조군 — 잘 막는다 |
| `""` | `6.7.1` | false | 판 못 읽음 — 잘 막는다 |
| **`0.0.0.0`** | `6.7.1` | **false** | ★ **CI 실측값 — V-1** |
| **`6.9.9.9`** | **`6`** | **TRUE** | 🔴 기대값이 `6` 이면 **Inno 6.x 전부 통과** |
| **`6.7.9`** | **`6.7`** | **TRUE** | 🔴 기대값이 `6.7` 이면 패치 갈림을 **못 본다** |
| `6.7.1.0` | ` 6.7.1` | false | 앞공백 → 빨강(안전 방향) |
| `6.7.1.0` | `6.7.1 ` | false | 뒤공백 → 빨강(안전 방향 · `expect` 는 **trim 안 함** — `fileVer`/`prodVer` 만 trim) |

| `6.7.1-beta` | `6.7.1` | false | 프리릴리스 빨강(안전 방향) |
| `6.07.1.0` | `6.7.1` | false | 0 패딩 빨강(안전 방향) |

PM 의 `G_T6_5e` 는 **음성 3건이 전부 `expect="6.7.1"` 고정**이다. **기대값 쪽을 흔드는 축이 0건**이라 위 6·7행(조용한 초록)은 대조군이 못 잡는다.
⇒ 대조군이 재는 범위를 「판정식 전체」라고 쓴 것은 과하다. 재는 건 「expect 가 3자리일 때의 actual 축」이다.

### V-4 🔴 **`HITPAN_ISCC_EXPECT_VERSION` 이 비면 단언이 통째로 사라진다**

```
if (expectVer.Length > 0 && !IsSameInnoVersion(fileVer, expectVer) && …)
```
`expectVer == ""` 이면 **N4 단언이 아예 실행되지 않고** 게이트는 어떤 Inno 판으로도 초록이다.
워크플로가 env 이름을 바꾸거나 지워도 **아무 장치가 알려주지 않는다** — 전용 단계의 조용한초록 판별은 `N != 0` 과 `iscc-optout.log` 부재만 본다(M-8 로그의 단계 스크립트 전문 확인). `iscc-skips.log`/`optout` 과 달리 **「판을 안 쟀다」 표식이 없다.**
봉합 전부터 있던 구멍이지만, 봉합이 **이 자리를 건드리면서도 닫지 않았다.**

### V-5 ⚠️ **글자 대조 보조 OR 이 새 우회로다**

봉합은 글자 대조를 **세 번째 OR** 로 남겼다(`|| !vOut.Contains(expectVer, Ordinal)`). 전에는 **유일한 검사**였으니 우회로가 아니었지만, 지금은 **탈출구**다.
`vOut` 은 ISCC 의 stdout+stderr 전체이므로, 설치 경로나 오류 메시지에 `6.7.1` 이라는 글자가 **어떤 이유로든** 섞이면 판 자원이 달라도 통과한다(예: `C:\Tools\Inno 6.7.1\` 에 6.8.0 을 깐 경우).
현 러너에서는 배너에 숫자가 없어 실제 발화 확률은 낮다 — **구조상 열린 길**이라는 지적이고, 발화는 **미측정**.

### V-6 ⚠️ **전용 단계의 「건수」 의미가 조용히 바뀌었다**

전용 단계 필터는 `FullyQualifiedName~InstallerBootstrapMessageGateTests.G_T6_5` 로 **접두 부분일치**다.
신설 `G_T6_5e` 가 이 필터에 **같이 걸린다** — 실측으로 `Total tests: 4` → **`Total tests: 5`** 로 늘었다(M-8 vs M-12).
`G_T6_5e` 는 **ISCC 를 안 쓴다.** 즉 이 단계의 "N 건" 중 1건은 **실물 계측이 아닌 순수 단위시험**이다. `N -eq 0` 검사만 있어 지금 당장 깨지진 않지만, 「실물 Inno Pascal 전용 단계」의 건수에 실물과 무관한 건이 섞인 건 **다음 사람이 오해할 계측**이다.

**사유 (한 줄)**: 봉합이 닫겠다고 한 과녁(`main CI 빨강`)이 **PR #485 자기 CI 에서 같은 단계·같은 단언으로 아직 빨갛다**. 봉합의 전제 — "Inno 판은 바이너리 판 자원에서 잰다" — 가 실물에서 거짓이다(`FileVersion='0.0.0.0'` · `ProductVersion='0.0.0.0'`).

### 머지 전 닫아야 하는 조건

1. 🚨 **V-1 — `FileVersionInfo` 경로를 폐기하거나 보강한다.** `ISCC.exe` 는 판 자원이 `0.0.0.0` 이다. 이 코드로는 러너 ISCC 가 올바른 6.7.1 이어도 **영구 빨강**이다. 다음 봉합은 **추정 금지** — U-1′ 의 대안 경로(`Compil32.exe` 판 자원 · choco 가 보고하는 패키지 판 · `ISCC.exe /?`)를 **CI 에서 먼저 한 바퀴 찍어 실측값을 확보한 뒤** 식을 고른다. 세 번째로 추정해서 고치면 안 된다.
2. 🔴 **V-4 — `HITPAN_ISCC_EXPECT_VERSION` 이 비면 단언이 사라지는 길을 막는다.** 전용 단계(`HITPAN_REQUIRE_ISCC=1`)에서 기대값이 비었으면 **스킵이 아니라 FAIL**. 그리고 `iscc-skips.log` 처럼 **「판을 안 쟀다」 표식**을 남겨 단계 스크립트가 잡게 한다.
