## 2. 깨뜨리려 한 것 — 못 깨뜨린 축 (대조군 포함)

> 방법: 임시 xUnit 탐침을 `src/HitPan.Tests/Integrity/` 에 넣어 실물 `SplitStatements`·`StripAlterExistsTokens` 를
> 직접 호출하고 **끝난 뒤 지웠다**(커밋 0 · `git status` 깨끗함 확인 · 지운 뒤 재빌드 0/0 확인).

### 2-A. `StripAlterExistsTokens` — 적대 입력 18종, **전부 정확**

| 입력 | 결과 | 평가 |
|---|---|---|
| `… DEFAULT 'IF NOT EXISTS'` | 리터럴 **보존** | 🟢 지워선 안 될 것을 안 지운다 |
| `ALTER TABLE IF EXISTS t ADD COLUMN IF NOT EXISTS c` | 둘 다 벗김 | 🟢 (MySQL 8 은 `ALTER TABLE IF EXISTS` 도 모른다) |
| `ADD UNIQUE INDEX IF NOT EXISTS` / `ADD FULLTEXT KEY …` / `ADD SPATIAL KEY …` | 셋 다 벗김 | 🟢 |
| `ADD COLUMN IF\n  NOT\n  EXISTS c` (줄바꿈 끼움) | 벗김 | 🟢 |
| `DROP COLUMN IF EXISTS c` | 벗김 → 없으면 **1091**(관용 안) | 🟢 |
| `… COMMENT 'IF NOT EXISTS here'` | COMMENT **보존** | 🟢 |
| `ADD COLUMN IF NOT EXISTS g int AS (IF(x>0,1,0)) STORED` | 생성열 식의 `IF(` **보존** | 🟢 |
| `ADD COLUMN IFX int, ADD COLUMN IF NOT EXISTS y int` | `IFX` **안 건드림** | 🟢 단어경계 정확 |
| `` ADD COLUMN IF NOT EXISTS `if` int `` | 역따옴표 식별자 `if` **보존** | 🟢 |
| `/* note */ ALTER …` · 소문자 전체 · 끝에 `--` | 전부 정상 | 🟢 |
| `INSERT INTO t (c) VALUES ('IF NOT EXISTS')` · `-- ALTER TABLE x` 선행 | **비(非)ALTER 로 판정, 무변경** | 🟢 음성 대조 |

**잔존 구멍 1건(오늘은 비어 있다)**: `CREATE INDEX IF NOT EXISTS ix ON t (c)` 는 **안 벗긴다**(설계대로 ALTER 전용).
MySQL 8 은 `CREATE INDEX IF NOT EXISTS`·`CREATE TRIGGER/VIEW IF NOT EXISTS` 도 모르므로 1064 가 된다.
오늘 14파일에 그 모양 **0건**(grep 확인)이라 사고는 아니다. 그러나 **코드 주석은 「ALTER 에만 설 자리가 있다」고 적었는데
그건 MySQL 문법 사실이 아니라 「오늘 우리 파일 사정」이다.** 다음 사람이 `CREATE INDEX IF NOT EXISTS` 를 넣으면 다시 11번 사고다.
→ 조건 C-4.

### 2-B. `SplitStatements` — 실물 14파일 역산 + 적대 입력 10종

**역산(PM 이 안 한 것)**: 파일마다 `SplitStatements` 결과를 `;` 로 다시 이어 붙여 원문과 비교(공백·`;` 무시).

| 파일 | 문장수 | 역산 |
|---|---|---|
| `00` | 30 | **꼬리 주석만 탈락** (첫 차이 지점 = `SET FOREIGN_KEY_CHECKS=1` 뒤의 `-- ====` 배너) |
| `10` / `20` | 3 / 4 | 같음 (꼬리 주석만) |
| `11` `30` `31` `32` `40` `41` `42` `43` `44` `90` `91` | 3·1·6·1·4·4·2·2·3·2·1 | **완전 일치** |

꼬리 탈락분을 눈으로 확인했다 — **전부 주석 배너**다(`AddIfExecutable` 의 설계된 동작). **실행문 손실 0건 · 오분할 0건.**

적대 입력: `SELECT 1--x;`(공백 없는 `--` 는 주석 아님 → 정상 분할) · `DEFAULT -1` · `'it''s;ok'` ·
`` `t;x` `` 역따옴표 안 `;` · `'a#b'` · `'a-- b'` · CRLF 주석 — **7종 전부 정확**.
미닫힘 블록주석·미닫힘 인용은 **나머지 전체를 한 문장으로 삼킨다** — 그 입력은 MySQL 에서도 문법오류이고
관용 목록에 없는 1064 로 **크게 터진다**. 조용한 통과가 아니라서 받아들인다.

## 3. 깨뜨린 것 (심각도 순)

### 3-1. 🔴 V-1 (P1) — 여러절 ALTER + 1060 관용 = 「적용됨」으로 기록되고 칸이 안 생긴다

**사실(쟀다)**

- `32_backoffice_s2_owner.sql` = **문장 1개에 `ADD COLUMN` 4절**(`owner_account_id`·`owner_email`·`owner_collected_at`·`owner_collect_path`).
- `42_backoffice_cs_stages.sql` #1 = **문장 1개에 `ADD COLUMN` 6절**(`read_at`…`rating_comment`).
- (`44` 는 3문장으로 **쪼개져 있다** — 같은 일을 올바르게 한 대조군이 같은 PR 안에 있다.)

**실측 — 로컬 MariaDB 11.4.10 `test` DB, 임시표 1개 만들고 지웠다**(운영·`hitpan_backoffice`·`hitpan_erp` 무접촉 #39):

```
-- owner_account_id 만 미리 있는 표에, 벗긴 모양 그대로
ALTER TABLE … ADD COLUMN owner_account_id VARCHAR(100) NULL,
              ADD COLUMN owner_email VARCHAR(255) NULL,
              ADD COLUMN owner_collected_at DATETIME NULL,
              ADD COLUMN owner_collect_path VARCHAR(30) NULL;
→ ERROR 1060 Duplicate column name 'owner_account_id'
→ 직후 칸 목록: id, owner_account_id  ... **나머지 3칸 전부 안 생겼다**
```

중복절이 **가운데**에 있어도 같다(`zz1`·`zz2` 도 안 생겼다). 즉 **절 하나가 중복이면 문장 전체가 롤백**된다.

**적용기가 그 1060 을 관용한다** (`IsAlreadyThere`) → `tolerated++` → 로그 1줄 → **파일을 `_schema_migrations` 에 기록** →
해시 멱등이라 **다음 기동부터 영영 `skip (적용됨)`**. 운영에는 `owner_email`·`owner_collected_at`·`owner_collect_path`(또는 42번 5칸)가 없는데
적용기는 성공을 보고한다. **10/11 사고와 같은 500 이, 이번엔 조용히 돌아온다.**

**왜 가설이 아니고 live 위험인가**
- `00_backoffice_core.sql:101` 이 스스로 적는다 — `domain_alias: 원본 DDL이 어느 .sql에도 없음(**운영 수동 ALTER만**)`.
  즉 이 운영 DB 에는 **파일 밖에서 칸을 더한 전례가 문서로 남아 있다.**
- `44` 파일 자신도 적는다 — `운영에 세 칸이 이미 있으면(시드가 실행됐을 수도 있다 — **미확인**)`.
- 지금 운영은 11번에서 멈춰 있으니 **1차 적용은 빈 상태에서 전절 성공한다.** 위험은 **그 다음**이다 —
  부분 실패 후 재기동, 손으로 한 칸 더한 뒤 재기동, 복구본 위 재적용.

**게이트가 못 잡는다**: G-M8-2 는 **빈 DB** 에 적용하므로 관용 경로를 안 탄다. G-M8-3 은 관용을 타지만
**4칸이 전부 있는 상태**에서 재적용해 4칸을 세므로 통과한다. **「1칸만 있는 부분 상태」를 만드는 게이트가 없다.**

### 3-2. 🔴 V-2 (P2) — 1060 은 형을 안 본다. 게이트도 형을 안 본다

**실측**: `owner_account_id varchar(10)` 이 있는 표에 `VARCHAR(100)` 을 요청 → 1060 → 관용 →
`information_schema` 확인 결과 **그대로 `varchar(10)`**.

관용이 덮는 운영 증상(구체 경로):
- `44`: `price_display varchar(50) NOT NULL DEFAULT 'number'` 가 다른 형으로 이미 있으면 → 요금제 조회의 문자열 매핑에서 터진다 = **요금제 500 그대로**.
- `32`: `owner_account_id` 가 짧은 varchar 로 있으면 → S-2 대표 아이디 수집 INSERT 에서 **1406/잘림**.
- `11`: `approved_at_dt` 가 `datetime` 아닌 형으로 있으면 → 월 정산 날짜축이 깨진다.

**G-M8-2 가 잡나? 못 잡는다.** 쿼리가
`SELECT LOWER(CONCAT(table_name,'.',column_name)) FROM information_schema.columns` —
**`column_type`·`is_nullable` 을 안 읽는다.** 존재만 본다. 설계가 「형이 달라도 통과」를 명시적으로 허용한 셈인데
설계문서·명세서에 그 자백이 없다.

### 3-3. 🔴 V-3 (P2) — 「보정은 MariaDB 에서도 정답」은 측정으로 틀렸다

구현자 주장(개발명세서 §2 A-1)과 코드 주석(`SchemaMigrator.cs:59-60`):

> 판정 못 하면(빈 문자열) 보정 경로로 간다 — **보정 경로는 MariaDB 에서도 정답이기 때문이다**

**실측(MariaDB 11.4.10)** — 같은 이름 FK 를 두 번 더하면:

```
ALTER TABLE … ADD CONSTRAINT fk_dp_x FOREIGN KEY (pref) REFERENCES …;   -- 1회차 성공
ALTER TABLE … ADD CONSTRAINT fk_dp_x FOREIGN KEY (pref) REFERENCES …;   -- 2회차
→ ERROR 1005 (HY000) … (errno: 121 "Duplicate key on write or update")
```

**1826 이 아니다. 1005 다.** `IsAlreadyThere` = {1060,1061,1091,1826} 에 **없다.**

귀결: 판 판정이 MariaDB 를 못 알아보면(`SELECT VERSION()` 빈값 · 프록시가 자기 판 문자열을 돌려줌 ·
`mariadb` 글자 없는 표기), **이미 적용된 MariaDB 백오피스는 `31` 번의 `ADD CONSTRAINT fk_landing_signups_tenant` 에서
1005 로 멈춰 기동이 영구 거부된다.** 그 파일은 이력에 안 남으니 재기동마다 같은 자리에서 또 멈춘다 —
명세서 §2-1 ②가 「영영 안 열린다」고 적은 바로 그 덫이 **반대 판에 그대로 열려 있다.**

트리거 가능성은 낮다(`5.5.5-10.x-MariaDB` 옛 표기도 `mariadb` 글자를 담으므로 안전 — 확인했다).
심각도는 **「문서가 안전하다고 단언한 자리가 안전하지 않다」**는 데 있다. 1005 를 관용에 더하거나,
**판독 실패를 MariaDB(종전 경로)로 떨어뜨리는 것**이 맞다 — 종전 경로는 양쪽에서 오래 돌았고 MySQL 에서는 1064 로 **크게** 터진다.

### 3-4. 🟡 재실행 전수 — 파일별 짚기 (관용 4개로 **충분한가**)

| 파일 | 재실행 시 나는 오류 | 관용에 있나 | 판정 |
|---|---|---|---|
| `00` `10` `20` `40` `43` | 없음 (`CREATE TABLE IF NOT EXISTS` 전수 확인 — 미보호 `CREATE TABLE` **0건**) | — | 🟢 |
| `11` | 1060 · UPDATE 2건 멱등 | ✔ | 🟢 |
| `30` `41` `44`(3문장) | 1060 | ✔ | 🟢 |
| `31` | 1060 · 1061 · **1826(MySQL)/1005(MariaDB)** · UPDATE 멱등 · `bo_audit_log` INSERT 는 재실행마다 1행 증가 | 부분 (§3-3) | 🟡 |
| `32` `42` | 1060 — **단, 부분 상태면 §3-1** | ✔ 코드는, ✗ 의미는 | 🔴 |
| `90` `91` | `INSERT IGNORE` — 1062 불가 (확인) | — | 🟢 |

추가로 짚은 것:
- **1050(표 중복) 은 도달 불가** — 14파일의 모든 `CREATE TABLE` 에 `IF NOT EXISTS` 가 있다(grep 전수).
- **1062 도달 불가** — 시드 2개가 `INSERT IGNORE`.
- **1054 도달 불가** — `90` 의 `bo_permissions` 정의가 `00` 과 **칸 구성 동일**(직접 대조).
- **1091 은 오늘 죽은 관용** — 14파일에 `DROP`/`MODIFY`/`CHANGE` **0건**. 해롭지 않다.
- **`43` 의 `promotions_legacy`·`promotion_usages` 정의는 `00` 과 바이트 동일**(`diff` 로 확인) ⇒ 먼저 만든 쪽이 이기는 조용한 분기 **없다**. 🟢
- **`31` FK 형 일치**: `landing_signups.tenant_id varchar(36)` ↔ `tenants.tenant_id varchar(36)`, 표 콜레이션 둘 다 `utf8mb4_unicode_ci` ⇒ 3780 위험 낮다. **단 운영 실물 콜레이션은 못 쟀다**(#39).
- **`SET FOREIGN_KEY_CHECKS` 는 보정 경로에서도 산다** — 같은 `MySqlConnection` 에서 문장을 순차 실행하므로 세션 설정이 유지된다. 🟢

## 4. `bo-mysql8-gate` 잡 — 실제로 돌 수 있나 (YAML 눈 검산)

| 축 | 확인 | 판정 |
|---|---|---|
| 구조·들여쓰기 | `db-gate`(:228~) 와 **같은 모양**(`services:` → `<name>:` → `image/env/ports/options: >-`) | 🟢 |
| 액션 판 | `checkout@v7`(파일 내 6회) · `setup-dotnet@v6`(3회) — **기존과 일치** | 🟢 |
| `options: >-` 접힘 | 4줄이 공백으로 이어져 `--health-cmd="…" --health-interval=10s …` 1줄이 된다 | 🟢 |
| `--filter` 가 0건 고르나 | 로컬 `--list-tests` 로 **7건 선택 확인**(G-M8-1·2·3·4·5a·5b·5c) | 🟢 |
| 0건 가드 | `No test matches…` grep + `dotnet test` 비정상종료 둘 다 빨강. 기본 셸 `bash -e` + 스크립트가 직접 `set -o pipefail` | 🟢 |
| `HITPAN_REQUIRE_DB` 주입 | `'true'` → `DbGateEnvironment.IsCi=true` → **못 붙으면 `SkipOrFailStrict` 가 던진다**. 조용한 초록 경로 **없다**(코드로 추적 확인) | 🟢 |
| MariaDB 오배치 방어 | 판이 MariaDB 면 `IsCi` 라서 **「게이트 오배치」로 FAIL** | 🟢 |
| 접속 문자열 | `ServerConnString().Replace("User=", …)` — `AllowUserVariables=true` 에 `User=` 부분일치 **없음**(확인). 생성값 유효 | 🟢 (다만 취약한 기법) |
| `HITPAN_BO_SEED_ADMIN_HASH` 미주입 | 맞다 → `91` 건너뜀 → G-M8-1 의 `expected` 에서 제외돼 일치 | 🟢 |
| 기존 `db-gate` 오염 | `db-gate` 의 `GATES` 열거에 `Backoffice*` **0건** ⇒ 새 시험이 MariaDB 잡에 집히지 않는다. **기존 잡 빨강 유발 없다** | 🟢 |

**🟡 V-4 — 기동 대기가 TCP 를 안 잰다.**
`docker exec … mysql -uroot -p… -e "SELECT VERSION()"` 은 **컨테이너 안 소켓**으로 붙는다.
`--health-cmd="mysqladmin ping -h localhost"` 도 소켓이다(게다가 자격증명 없이 — `mysqladmin` 은 PING 단독일 때
접근거부에도 0 을 돌려주므로 **초기화 중인 임시 서버에도 초록**이 될 수 있다).
게이트는 **호스트 127.0.0.1:3306** 으로 붙는다. 두 축이 다르다 ⇒ 운이 나쁘면 아직 TCP 가 안 열린 때 붙어 실패.
**방향은 안전하다**(실패 시 `HITPAN_REQUIRE_DB` 때문에 **빨강**, 거짓 초록 아님). 그래도 **깜빡임은 다음 사람의 판단을 흐린다.**
고칠 자리 한 줄: 대기 단계를 러너에서 `mysqladmin --protocol=TCP -h127.0.0.1 -P3306 …` 로, health-cmd 도 `-h 127.0.0.1` 로.

**🟡 V-5 — `caching_sha2_password` 는 못 쟀다.** `mysql:8.0` 기본 인증은 `caching_sha2_password` 다.
접속 문자열에 `AllowPublicKeyRetrieval` 이 없다(MySqlConnector 기본 `false`). 기본 `SslMode=Preferred` +
mysql 이미지의 자동 생성 인증서로 **TLS 위에서 통과할 것으로 보이지만 — 이 PC 에 MySQL 8 이 없어 못 쟀다.**
틀리면 **첫 CI 실행이 빨강**으로 드러난다(조용한 초록 아님).
