## 2. Q2 — 재현 / 대조 무효 / 대조 기준 미정 / 미측정 / 장치 실패

- 🟢 네 칸 따로: `d1Reproduced` · `contrastState{state,reason,cells}` · `notMeasured{flag,reason}` · `deviceFailure{flag,reasons,cells}` (judge.js:579~608). 상태 글자 셋(성립 · 대조 무효 · 대조 기준 미정)과 「대조 불가(장치 실패)」 = state null + 사유는 서로 다른 칸 · 같은 필드 덮어쓰기 0. 옛 `contrast`(I-6 · I-7 문자열, judge.js:548)는 #1 대로 유지 · 새 칸 이름을 `contrastState` 로 갈라 충돌 피함.

- 🟡 **미측정 판정 근거가 「받은 표본 0」 하나뿐**(judge.js:606 `flag: got === 0`). 판독기는 시도 기록을 받지 않으므로 「시도했으나 원자료 0(장치 실패)」 과 「시도 0」 을 못 가른다. 자체시험(selftest-judge.js:975)은 이 경우를 「I-7 시도 · 원자료 0 → 미측정 표지 + 장치 실패」 로 **기대값으로 고정**했다 — 한 항목이 미측정과 장치 실패를 동시에 단다. HQA Q2 「미측정은 실제 시도·원자료 자체가 없는 경우에만」 과 정면 충돌인지는 「계획된 항목 = 시도됨」 을 장치가 보장하는지에 달렸다 → **확인 필요**(시도 증거 칸 · 예: run-items 항목 시작 기록을 판독기에 넘기거나, 계획 안 항목의 원자료 0 은 장치 실패로만 적기). 대조군 M3 이 초록인 것도 같은 구멍.
