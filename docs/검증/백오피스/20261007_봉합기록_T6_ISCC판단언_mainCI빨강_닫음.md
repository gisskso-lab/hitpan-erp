## §2 원인 — 실측 (가설 아님)

CI 로그 원문:

```
[G-T6-5] ISCC=C:\Program Files (x86)\Inno Setup 6\ISCC.exe · 판 배너='Inno Setup 6 Command-Line Compiler' (exit 1)
  ISCC 판이 기대(6.7.1)와 다르다 — 시험본·출하본 Inno 판 갈림(N4).
```

1. 앞선 단언식은 판을 **ISCC 가 뱉는 글자**에서 찾았다 — `vOut.Contains("6.7.1")`.
   그 `vOut` 은 배너 한 줄이 아니라 **stdout+stderr 합본 전체**다(`RunExe` 가 `so + se` 를 돌려준다).
   그게 FAIL 했다 ⇒ **ISCC 출력 어디에도 패치 판 번호가 없다.**
2. 🔴 **인계4 §0 의 가설 「판 번호는 보통 다음 줄에 있다」는 틀렸다.** 배너 둘째 줄을 읽게 고치는
   봉합은 **또 빨강**이다. 글자에는 애초에 그 숫자가 없다.
3. 🟢 **인계4 §0 의 미확인 항목 닫힘 — choco 단계는 돌았다.** 같은 run 로그:
   `InnoSetup v6.7.1 already installed.` ⇒ 러너 ISCC 는 **실제로 6.7.1 = 출하본과 같은 판**이다.
   즉 게이트가 지키려던 **N4 는 사실로는 이미 충족**이었고, 깨진 것은 **재는 방법**뿐이었다.
   (제품 결함 0건 — 설치 문구 도달 자체는 2차수 리뷰서 §1 에서 이미 통과했다.)
