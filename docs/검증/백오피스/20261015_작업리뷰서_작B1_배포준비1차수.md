### ④ `stub_mode` vs `not_implemented` (과녁4)

- 실물 분기(`EmailSenderService.cs:60-74`): ⓐ 열쇠 없음 → `not_configured` · ⓑ `provider=stub` + 열쇠 있음 → `stub_mode` · ⓒ `provider=ses|sendgrid` + 열쇠 있음 → **`stub_mode`**.
- **ⓒ 가 운영자에게 거짓 안내다.** 운영자는 SES 키를 넣었고 `stub_mode` 를 보면 **설정 스위치를 찾는다**. 실제 벽은 설정이 아니라 **벤더 SDK 0줄**(코드)이다. `not_implemented` 가 정직하다.
- **그러나 이 차수 판정은 `stub_mode` 유지가 맞다**: §5 G4 ⓒ 숫자식이 *「사유코드 2종」* 으로 고정돼 있고, 3종으로 늘리면 PM 결재된 합격선을 구현이 임의로 넓히는 것이다(갈래 조건을 뒤 문서에서 넓히지 않는다).
