### 1-2. 못 받는 것 — §0 「A′ 쪽 결과가 고객에게 나쁜 반복 확인 0」
- c1o 세 번 × 2브라우저 × 3 = 18표본: 목록 끝 **A′ 6 · 대조 0** · 입력칸(안 끌려간 좋은 끝) **A′ 1 · 대조 4**. 같은 쪽 세 번 반복이고 우연으로 보기 어렵다(참고 손셈: 정확검정 한쪽 p ≈ 0.01). 왜 A′ 에서만 나는지 **원인 미확인**.

## 4. 나중에 안 터지나

### 4-1. MudBlazor 판 올림
- 가장 위험한 길: `MudComponentBase` 가 장차 `IHandleEvent` 를 스스로 구현하면 A′ 재구현이 그것을 **조용히 건너뛴다**(빌드 통과 · 동작만 바뀜). 그 밖: ↑ · ↓ 길에 JS 호출이 늘면 그것도 받아 목록을 닫음 · 이벤트 묶기가 바뀌면 입구를 안 지나 회로 죽음 재발.
- 지금 막는 것 = 작업지시서 §9 종이 점검표뿐. 자동 경보 시험은 **미확인**(이 결재에서 시험 폴더 미열람). 보안 권고로 패키지 판이 갑자기 올라간 전례가 있다 → **별건 B-1**: 반사 검사 시험(`MudMenu` 의 `IHandleEvent` 구현이 `ComponentBase` 에서 온다 · MudBlazor 판 = 9.3.0 · 다르면 실패 + §9 안내). 판 올림 PR 은 이 경보 없이 머지 금지.

### 4-2. .NET 판 올림
- 옮겨 쓴 몸통이 .NET 8 에 고정된다. 8.0.x 패치도 §9 대조 대상(지시서에 있음). 백오피스를 WebAssembly 로 옮기면 재검 — .NET 원문은 AOT 사유로 예외 필터를 피했고 A′ 는 `when` 필터를 쓴다.

### 4-3. 느린 회선
- 자가 닫힘 ≈ 3 RTT(0.6초 회선 ≈ 1.9초). 그 창 안 Tab → 같은 줄 단추 되끌림(E3 · 80/80 같은 줄 · 다른 줄 0). Esc 뒤 ≈ 1.3초 안 다른 칸 누름 → 되끌림(두 판 공통).
