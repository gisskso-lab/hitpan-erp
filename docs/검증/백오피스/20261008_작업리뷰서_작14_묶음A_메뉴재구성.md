  `/admin/tenants` · `/admin/tenants/{임의id}` · `/admin/resellers` · `/admin/resellers/{임의id}` · `/admin/reseller-applications` · `/admin/reseller-serials` · `/admin/reseller-settlements` · `/admin/signups` · `/admin/pricing` · `/admin/cs` · `/admin/stats` · 🔴`/admin/promotions` · 🔴`/admin/bo-users` · 🔴`/admin/approvals` · 🔴`/admin/mfa-setup` · 🔴`/admin/tenant-domains`
- **동시에 기록할 것**: ① HTTP 상태 ② 화면에 **실제 렌더된 글자**(상태코드만 보면 Blazor 가 200 안에 화면을 그려도 통과로 읽힌다) ③ F12 Network 에서 백오피스 **API(5258) 응답 코드**(화면 잠금과 API 잠금을 분리 기록 — `BoAccessGuard` 403 이 화면 잠금처럼 보이면 안 된다)
- **판정**: A·B 양쪽 모두 거부 = PASS. **하나라도 렌더 = FAIL**.

### §5-2 G-1c (양성 대조군)

- `platform_admin` 과 `platform_owner` **두 계정 각각**으로 §5-1 의 같은 16개 주소를 같은 A·B 2단으로.
- 기대: **200 + 화면 실물 렌더**. 하나라도 거부면 「잠그다 본사까지 막은」 사고 → 즉시 반려.
- 🔴 `platform_admin`(Owner 아님)으로 `/admin/bo-users`·`/admin/approvals`·`/admin/mfa-setup`·`/admin/tenant-domains` 를 쳤을 때의 결과는 **G-1c 의 기대값이 아니라 V-7 의 측정값**이다. 섞어서 기록하지 마라 — 「본사면 200」으로 뭉치면 Owner 분리 구멍이 대조군에 삼켜진다.
- 🔴 대조군이 **진짜 음성인지** 먼저 확인: 잠금을 뺀 사본에서 G-1 이 **FAIL 을 내는지** 한 번 본다. FAIL 을 못 내는 게이트는 글자다(누적 26회).

### §5-3 G-3 (껍데기 메뉴 0건) — **동작 기준**

- 사이드바 **노출 15줄 전수**(`BackofficeSidebar.razor:30-33·39-40·46·52·60-65` 본사 13줄 + `:74·79` 대리점 2줄)를 `platform_owner` 로 **하나씩 클릭**.
- 줄마다 기록: ① HTTP 200 ② F12 Network 에서 **백오피스 API 호출이 실제로 일어났고 2xx** ③ 화면에 **「준비 중」·「차수 대기」·「신설 대기」·「자동 활성화」 문구가 0건** ④ 데이터 0건이면 **빈 DB 때문인지 API 부재 때문인지** 구분(`EmptyState` vs 안내 껍데기).
- 🔴 ③ 금지어 모양의 실례: `AdminDashboard.razor:17-19` · `ResellerRevenue.razor:15-19`. 이 문구가 사이드바 노출 줄에서 나오면 FAIL.
- 🔴 **대리점 2줄은 대리점 계정으로 따로** 잰다(본사 계정으로는 `else` 블록이 안 그려진다 — `BackofficeSidebar.razor:69`).
- 미노출이지만 shim 으로 닿는 `/platform/dashboard` → `/admin/dashboard` 는 **G-3 대상 밖**(메뉴가 아니다)이지만 V-9 로 따로 기록.
