## 1. 확인 1 — 집계 규칙: **경우 단위 · 칸 합산 · 「하나라도」**

- I-4 `kbd-open` 경우는 대조 화면 e1t3 의 지연 칸 셋(왕복 0 · 150 · 300)을 **하나로 모아** 판독한다. 세 칸 어디서든 유효 표본 1개만 실패 꼴을 내면 경우 「성립」 · 세 칸 모두 재현 0 이면 「대조 무효」. 칸별 상태는 없다(칸별 재현 수는 cells 줄에 기록만).
- 세 칸 중 한 칸이라도 장치 실패(유효 표본 < 계획 표본)면 경우 전체 state = null(대조 불가) — 다른 칸이 재현했어도 같다.
- 항목 I-4: 한 경우라도 null → null · 한 경우라도 「대조 기준 미정」 → 미정 · 두 경우 모두 성립 → 성립 · 그 밖 → 대조 무효. = 결-H4 「두 경우 모두 성립일 때만」.
- 근거(judge.js · `ab23f03a`): L679 `isCc`(대조 칸 = 그 경우 대조 화면의 칸 전부 · 지연 제한은 N-1 만) · L131~145 `delaysFor`(e1t3 = `iDelays` 전부) · L685~695 경우별 집계(L688 byCase · L691 null 우선 · L692 미정 · L693 every 성립 · 그 밖 무효) · L721~744 `stateOf`(L735 칸 하나라도 장치 실패 → null · L738 rep = 칸 합산 · L741 `rep > 0` → 성립) · L333 실패 꼴 `'I-4/kbd-open': !ku && R.focusOnSameRowBtn === false` · rules `contrastScreen` `"I-4/kbd-open": "e1t3"` · `"I-4/mouse-open": "before"` · `iDelays [0,150,300]` · `delayUnit = round-trip-ms` · `readingText.h4.contrastByCaseRule`.
- 자체시험: `selftest-judge.js` L1404~1408 — e1t3 표본 하나만 재현시킨 대조군 v4b 가 항목 「성립」. 「한 칸만 재현」 꼴의 칸별 심은 위반은 없음(P3 · 남는 위험).
- 작업지시서와 정면 어긋남 0. 다만 H4 §8 Q4ⓒ ③(L183) 「지연 0 · 150 칸 … 대조 무효가 날 수 있다」 는 칸 단위로 읽힘 — 코드엔 칸 단위 상태가 없다 + 왕복 0 · 300 은 11/8 「실패 없음」 측정 → 공개 묶음 v2 에서 고침 · H4 §15 정정 표시.

**공개 묶음에 넣는 한 줄(확정)**: 「I-4 의 키보드로 연 경우(kbd-open)는 비교 화면 e1t3 의 지연 세 칸(왕복 0 · 150 · 300)을 한데 모아 읽습니다. 세 칸 중 어디서든 유효 표본 하나라도 실패 꼴(Esc 뒤 초점이 같은 줄 단추로 돌아오지 않음)을 내면 그 경우는 '성립', 세 칸 모두 재현이 없으면 '대조 무효', 세 칸 중 한 칸이라도 장치 실패면 '대조 불가'입니다. I-4 항목은 마우스로 연 경우(/before)와 키보드로 연 경우가 모두 '성립'일 때만 '성립'입니다(장치 ab23f03a judge.js 의 fourCells 함수 안 stateOf 와 경우별 집계 · rules.json contrastScreen · readingText.h4.contrastByCaseRule).」
