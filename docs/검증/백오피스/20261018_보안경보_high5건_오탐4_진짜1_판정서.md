## 2. 오탐 4건 — 왜 오탐인가 (근거는 코드)

### #3926 — 「민감정보를 평문 저장」
그 줄은 **작B1 이 이미 고친 바로 그 줄**이다.
```
_logger.LogInformation("[LandingSignup] payment confirmed token={Token} …", MaskToken(req.SignupToken), affected);
```
`MaskToken`(`:530-535`)은 **SHA-256 해시의 앞 12자**만 돌려준다 — **되돌릴 수 없다**. CodeQL 이 「가입 토큰 → 로그」 흐름만 보고 **해시를 정화로 인정하지 않는다.**
🟢 사유: `False positive` — *토큰은 SHA-256 으로 단방향 마스킹 후 기록된다*

### #1426 — 「함수 수준 접근제어 누락」
`:280` 은 `PricingPublicController.GetPublicPlans` — 라우트 `api/landing/pricing/plans`, **랜딩페이지 요금표**다. **익명이 맞다**(고객이 가입 전에 가격을 본다). 읽는 것은 `pricing_plans` 뿐이고 고객 데이터 0건이다.
CodeQL 은 **같은 파일 위쪽의 `PromotionsAdminV2Controller`·`RewardsAdminController` 가 `[Authorize(Policy="PlatformAdmin")]` 를 달고 있는데 이 클래스만 없다**는 이유로 경보한다 — 한 파일에 공개·관리자 컨트롤러가 섞여 있어서 생긴 착시다.
🟢 사유: `False positive` — *공개 요금표 API. 설계상 익명이며 고객 데이터를 읽지 않는다*
⚠️ 다만 **파일을 나누면 이 경보가 영구히 사라진다** — 별건 개선 후보로만 적어 둔다(지금 손대지 않는다).

### #1140 · #1139 — 「XSS」 (같은 뿌리 2건)
둘 다 국세청 API 로 보낼 JSON 을 문자열로 조립하는 자리다.
```
new StringContent($"{{\"b_no\":[\"{bizNoNormalized}\"]}}", …)
```
그런데 그 값은 **숫자만 남긴 뒤** 쓴다:
- `LandingSignupController.cs:63` — `new string((req.BizNo ?? "").Where(char.IsDigit).ToArray())` + **길이 10 검사**(`:64`)
- `BizNoVerifyController.cs:44-45` — `Replace("-","")` 후 **`Length != 10 || !All(char.IsDigit)` 면 반려** + `:49` **체크섬 검증**

⇒ 따옴표·역슬래시·꺾쇠가 **원리적으로 통과할 수 없다.** CodeQL 이 `Where(char.IsDigit)`·`All(char.IsDigit)` 를 정화기로 인식하지 못한다.
🟢 사유: `False positive` — *숫자 10자리만 통과시킨 뒤 사용. 주입 문자는 도달 불가*

## 3. 🔴 #1999 — 진짜다. 그리고 CodeQL 이 가리킨 것보다 **더 크다**

CodeQL 은 `:72`(`req.TenantIdHash.StartsWith("sha256:")`)를 「사용자가 통제하는 값이 보안 판단에 쓰인다」고 짚었다. 코드를 끝까지 읽으니 **짚은 자리는 증상이고, 병은 그 아래 있다.**

| 줄 | 무엇 |
|---|---|
| `:107-116` | 🟢 **인증 자체는 제대로 한다** — `License:Pepper` 로 HMAC 해 `tenants.license_key_hash` 와 대조, 없으면 401 |
| 🔴 `:140-155` | `tenant_update_history` INSERT — `tenant_id` 는 인증으로 얻은 값이지만 `tenant_id_hash` 는 **요청이 준 값 그대로** |
| 🔴 `:162-180` | `tenant_update_state` **UPSERT 의 키가 `tenant_id_hash`**(요청값)이고, 충돌하면 `tenant_id = VALUES(tenant_id)` 로 **덮는다** |

⇒ 🔴 **`req.TenantIdHash` 가 인증된 테넌트의 것인지 **아무도 대조하지 않는다.** 정상 라이선스를 가진 고객 A 가 고객 B 의 해시를 실어 보내면 **B 의 업데이트 현황 행을 덮어쓰고 그 행의 주인까지 A 로 바꾼다.**

- 🔴 **헌법 #2 정면 위반** — *테넌트 식별자는 파라미터로 받지 않는다*
- 🔴 코드 주석 `:76-80` 이 *「모든 PC 가 공유하는 unknown 해시는 받지 않는다 — 받으면 현황 1행을 서로 덮어쓴다」* 고 **같은 사고를 이미 알고 있었다.** 특정 값 하나만 막고 **일반 경우를 안 막았다**
- 🟡 악용 난도: 남의 해시를 알아야 한다(즉시 터지는 구멍은 아니다). **그래서 P0 가 아니라 P1 로 본다**

### 처분안 (오늘 손대지 않는다 — #29 · 봉합 즉석 금지)
1. `:111` 에서 라이선스로 얻은 `tenantId` 에 대해 **`tenant_id_hash` 가 그 테넌트의 것인지 대조**하거나, 아예 **요청값을 버리고 서버가 가진 해시를 쓴다**
2. 게이트: 「A 의 라이선스 + B 의 해시」 요청이 **401/400 으로 막히는지** — 🔴 **글자가 아니라 동작으로**(음성 대조군 = 자기 해시는 통과)
3. 작업지시서 → PM 결재 → B2 이후 차수
