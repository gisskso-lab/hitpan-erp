## 2. 오탐 4건 — 왜 오탐인가 (근거는 코드)

### #3926 — 「민감정보를 평문 저장」
그 줄은 **작B1 이 이미 고친 바로 그 줄**이다.
```
_logger.LogInformation("[LandingSignup] payment confirmed token={Token} …", MaskToken(req.SignupToken), affected);
```
`MaskToken`(`:530-535`)은 **SHA-256 해시의 앞 12자**만 돌려준다 — **되돌릴 수 없다**. CodeQL 이 「가입 토큰 → 로그」 흐름만 보고 **해시를 정화로 인정하지 않는다.**
🟢 사유: `False positive` — *토큰은 SHA-256 으로 단방향 마스킹 후 기록된다*

### #1426 — 「함수 수준 접근제어 누락」
`:280` 은 `PricingPublicController.GetPublicPlans` — 라우트 `api/landing/pricing/plans`, **랜딩페이지 요금표**다. **익명이 맞다**(고객이 가입 전에 가격을 본다). 읽는 것은 `pricing_plans` 뿐이고 고객 데이터 0건이다.
CodeQL 은 **같은 파일 위쪽의 `PromotionsAdminV2Controller`·`RewardsAdminController` 가 `[Authorize(Policy="PlatformAdmin")]` 를 달고 있는데 이 클래스만 없다**는 이유로 경보한다 — 한 파일에 공개·관리자 컨트롤러가 섞여 있어서 생긴 착시다.
🟢 사유: `False positive` — *공개 요금표 API. 설계상 익명이며 고객 데이터를 읽지 않는다*
⚠️ 다만 **파일을 나누면 이 경보가 영구히 사라진다** — 별건 개선 후보로만 적어 둔다(지금 손대지 않는다).

### #1140 · #1139 — 「XSS」 (같은 뿌리 2건)
둘 다 국세청 API 로 보낼 JSON 을 문자열로 조립하는 자리다.
```
new StringContent($"{{\"b_no\":[\"{bizNoNormalized}\"]}}", …)
```
그런데 그 값은 **숫자만 남긴 뒤** 쓴다:
- `LandingSignupController.cs:63` — `new string((req.BizNo ?? "").Where(char.IsDigit).ToArray())` + **길이 10 검사**(`:64`)
- `BizNoVerifyController.cs:44-45` — `Replace("-","")` 후 **`Length != 10 || !All(char.IsDigit)` 면 반려** + `:49` **체크섬 검증**

⇒ 따옴표·역슬래시·꺾쇠가 **원리적으로 통과할 수 없다.** CodeQL 이 `Where(char.IsDigit)`·`All(char.IsDigit)` 를 정화기로 인식하지 못한다.
🟢 사유: `False positive` — *숫자 10자리만 통과시킨 뒤 사용. 주입 문자는 도달 불가*

## 3. 🔴 #1999 — 진짜다. 그리고 CodeQL 이 가리킨 것보다 **더 크다**

CodeQL 은 `:72`(`req.TenantIdHash.StartsWith("sha256:")`)를 「사용자가 통제하는 값이 보안 판단에 쓰인다」고 짚었다. 코드를 끝까지 읽으니 **짚은 자리는 증상이고, 병은 그 아래 있다.**

| 줄 | 무엇 |
|---|---|
| `:107-116` | 🟢 **인증 자체는 제대로 한다** — `License:Pepper` 로 HMAC 해 `tenants.license_key_hash` 와 대조, 없으면 401 |
| 🔴 `:140-155` | `tenant_update_history` INSERT — `tenant_id` 는 인증으로 얻은 값이지만 `tenant_id_hash` 는 **요청이 준 값 그대로** |

⇒ 🔴 **`req.TenantIdHash` 가 인증된 테넌트의 것인지 **아무도 대조하지 않는다.** 정상 라이선스를 가진 고객 A 가 고객 B 의 해시를 실어 보내면 **B 의 업데이트 현황 행을 덮어쓰고 그 행의 주인까지 A 로 바꾼다.**

## 6-1. 🟢 일치 — dismiss 번호는 바뀌지 않는다
`#3926` · `#1426` · `#1140` · `#1139` **4건 오탐** / `#1999` **진짜** — 복심도 같은 결론에 **독립으로** 도달했다.
🟢 **§5 에서 내가 자진신고한 한계 1개가 해소됐다**: 복심이 `bizNoNormalized`·`normalized` **대입 자리를 전수 추적**해 각각 **1곳뿐**(재대입 0건)임을 확인했다 ⇒ xss 2건 오탐 판정이 입력경로 전수로 뒷받침된다.
🟢 복심 보강: `#1139` 의 그 값은 **응답에 도달하지 않는다**(`:170` 은 국세청이 준 `bStt`·`taxType` 만), `#1140` 의 싱크는 브라우저가 아니라 **국세청 외부 요청 본문**이다.

## 6-2. 🔴 교정 — 「헌법 #2 **정면** 위반」은 내가 틀렸다
나는 §3 에서 `#1999` 를 **「#2 정면 위반」**이라 적었다. **그 표현을 철회한다.**

**실측 확인**: `TelemetryController.cs:37` = **`[AllowAnonymous]`** (클래스 전체). 이 경로는 **JWT 가 아예 없는 워치독 수신구**다.
⇒ #2 의 조문(*테넌트 식별자는 **JWT 클레임에서만***)을 글자대로 들이대면 **「JWT 를 붙여라」는 엉뚱한 봉합**을 부른다 — **워치독은 JWT 를 들 수 없다.**
⇒ 올바른 표기는 **「#2 취지 위반」** — *테넌트 식별자를 요청 파라미터로 받아 그대로 신뢰했다*.
🔴 **위 §3 의 「정면 위반」 글자는 지우지 않았다**(#1). 이 줄이 그 정정이다.

## 6-3. 🔴 교정 — 처분은 「2안 중 택1」이 아니라 **단일안**
§3 처분안 1 에서 나는 *「대조하거나, 아예 서버가 가진 해시를 쓴다」* 로 **두 길을 동급으로** 적었다. 복심이 근거를 댔다:
송신측 공식이 코드에 박혀 있다 — `UpdateHistoryClient.cs:98` · `MetaPingClient.cs:126-130` = **`"sha256:" + hex(SHA256(tenant_id))`**.
⇒ 서버는 `:111` 에서 얻은 **진짜 `tenantId` 로 해시를 재계산할 수 있다.** 「못 해서 요청값을 쓴 게」 아니라 **할 수 있는데 안 한 것**이다.
⇒ **처분 = 요청값 폐기 · 서버 재계산 단일안.** (「대조」는 요청값을 살려 두어 다음 사람이 또 쓴다.)

## 6-4. 🔴🔴 복심이 찾은 **진짜 2호** — CodeQL 경보 **밖**이다 (내가 못 봤다)

`LandingSignupController.ConfirmPayment` 가 **회사명을 테넌트 식별 키로 쓴다.** PM 이 직접 재측정했고 **전건 사실**이다:

| 측정 | 결과 |
|---|---|
| `:407-411` 결제확인 UPDATE | `WHERE company_name = @CompanyName AND status = 'pending'` — 🔴 **`LIMIT` 이 없다** |
| `:420` 웹훅용 재조회 | `WHERE company_name = … AND status='active' ORDER BY created_at DESC **LIMIT 1**` |
| `tenants` 유일성 | `00_backoffice_core.sql:135-138` — **`UNIQUE KEY uq_tenant_code` 하나뿐.** `company_name` 에 유일성 **0건** |
| 가입 시 동명 검사 | 🔴 **0건** — `:310` INSERT 앞뒤로 `company_name` 중복 확인 코드가 없다 |
| `landing_signups` 에 `tenant_id` 칸 | 🔴 **없다**(`:147-167`) — 🔴 **이게 뿌리다.** 가입서와 테넌트를 잇는 열쇠가 없어 **회사명이 사실상 조인 키**가 됐다 |

⇒ 🔴 **동명 회사 2곳이 `pending` 이면, 한 건의 결제확인이 두 행을 모두 `active` 로 만들고 두 테넌트에 같은 `license_key_hash` 를 박는다.** 그러면 `TelemetryController:111` 의 `WHERE license_key_hash = @Hash LIMIT 1` 이 **아무 쪽이나** 고른다.
🔴 **한국에서 동명 회사는 드문 일이 아니다.** 그리고 `landing_signups` 에는 `biz_no_hash` 와 그 인덱스가 **이미 있다**(`:147-167`) — **쓸 수 있는 신원이 있는데 회사명을 썼다.**
🟡 `affected`(`:414`) 는 **로그만 하고 판단에 쓰지 않는다** — 2행이 바뀌어도 아무도 모른다.

**처분**: 🔴 **진짜 2호로 등록. 오늘 손대지 않는다**(#29 · 봉합 즉석 금지). 작업지시서 → PM 결재 → B2 이후. 봉합 방향은 **`landing_signups.tenant_id` 신설**(뿌리) 이며, 게이트는 **「동명 pending 2행을 심고 결제확인 1회 → 1행만 active 가 되는가」**를 **동작으로** 재야 한다(음성 대조군 = 동명 아닐 때 정상 통과).

## 6-5. 🟢 복심 보강 — dismiss 는 **영구가 아니다**
