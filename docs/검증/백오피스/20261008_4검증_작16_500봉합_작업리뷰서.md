### N-2 🔴 **00 변경이 운영에서 00 전체 재실행을 부른다** — 아무 게이트도 안 문다
`SchemaMigrator` 의 멱등 키는 **(파일명 PK + 내용 SHA256)** 이고, 내용이 바뀌면 **다시 돌린다**
(`SchemaMigrator.cs:78-86`, `ON DUPLICATE KEY UPDATE content_hash`). 작16 이 `00_backoffice_core.sql` 을
고쳤으므로 운영 기동 시 **00 이 통째로 재실행**된다. 실패하면 `throw` → **백오피스 기동 거부**
(`SchemaMigrator.cs:120-124`) — 500 4건보다 큰 사고다.
- **내 실측 결론: 00 은 재실행 안전하다.** 00 전체에서 `CREATE|ALTER|INSERT|UPDATE|DELETE|DROP` 으로
  시작하는 줄 중 `IF NOT EXISTS` 가 없는 것은 `SET FOREIGN_KEY_CHECKS` **2줄뿐**이고(`:28`, `:694`),
  `CREATE TABLE IF NOT EXISTS` 28개 · `INSERT`/`ALTER` **0건**이다. ⇒ 전부 no-op.
- 🔴 **그러나 `G-MIG-1` 의 2회차 목록에 `00` 이 없다**(`G_DB:425-430` = 31·43·44 셋뿐).
  이번엔 안전하지만, **다음에 누가 00 에 `INSERT`/`ALTER` 를 한 줄 넣는 날 아무도 안 잡는다.**
  ⇒ 2차 과녁: G-MIG-1 의 2회차 목록에 `00` 추가.

### N-3 🟡 **운영 `pricing_plans` 에 세 칸이 「이미 있고 형이 다르면」 44 가 안 고친다**
`44` 는 전부 `ADD COLUMN IF NOT EXISTS` 다. 설계가 내건 조건은 「운영 표 모양을 몰라도 한 번에 맞는 봉합」인데
**섞인 모양**에 구멍이 있다:
- `max_pc_devices` 가 **`NOT NULL DEFAULT 0`** 으로 이미 있으면 → 500 은 안 나지만
  `DeviceRegistrationController.cs:65` 의 `COALESCE(p.max_pc_devices, 5)` 가 **0 을 돌려주고 기기 등록이 전부 막힌다**.
  `COALESCE` 는 NULL 만 막는다 — 설계 §4-2 가 스스로 적어 둔 그 함정이 **운영 쪽에서는 못 닫힌다**.
