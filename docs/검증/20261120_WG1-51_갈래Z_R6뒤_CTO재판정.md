- **push 때 고르기 예고**: §3-4 (가) 가 워크플로 줄 없이 안 되거나 일정상 main 확인을 먼저 해야 하면 「(가) R1 안 main 같이(추천) / (나) main 만 먼저 1번(6번째 · 고친 판 남은 자리 4 · 예비 0)」 을 그때 여쭘.

## §5 법무 1건 — 꼬리표 저작권 글자
- 사실: 꼬리표 「© NAVER Corp.」 ↔ 글꼴 파일 ID 0 원문 「Copyright © 2011 NHN Corporation」(회사 이름 다름).
- 판정: **M7′ 다시 열림 아님** — ㉣(꼬리표 있음) 은 지켜짐 · 문제는 글자 정확도. 옛 NHN 과 지금 NAVER 가 같은 권리자인지 = **확인 필요(법무)**.
- 길: 법무팀장 1줄(런 0) → 추천 글자 = **파일 원문 그대로 인용**(덧붙일 설명은 법무가 정함) → D14-6 으로 판정기 고정 글자 고침 → 이미 올라간 R6 결과표는 지우지 않음(지우기 금지) · 다음 결과표 머리에 정정 한 줄. 법무가 「판단을 뒤집음」 이라 하면 그때 M7′ → 법무 + 대표.

## §6 남은 위험 · 확인 필요
① F1 이 리눅스 경로에서만 나면 이 PC 에서 고침을 확정 못 함 → R1 의 띄어쓰기 견본이 첫 실측 · 못 읽으면 판정 0 = 1번 잃음(대표 보고 때 알림). ② 「없음」 검사 공허 여부(3-1 ②) 미확인. ③ K3 정답 미확정 — 고친 판 갈래 구현도 같은 답을 기다림. ④ 잡 시간 초과 때 `always()` 뒤 업로드 동작 = 여전히 미측정(R6 21분 · 상한 90분). ⑤ 굵게 미측정 그대로. ⑥ 같은 런 `ui-k35` 별건(재시도가 앞 설치 잠금을 안 기다림)이 R1 런 결론을 또 빨강으로 만들 수 있음 — 판정은 ui-print 잡 결론으로.
