## §2 (나) 조건 — 빠지면 재반려

1. **판정 = 서버 · DB 현재값** — 양식지 고치기 저장값 = (DB 현재 `paper_mode`='preprint' 그리고 `print_background`=1 그리고 `background_image_url` 무변) ? 1 : 0. 양식지에서는 요청의 `PrintBackground` 를 읽지 않는다(갈래 B 가 선택칸을 없애며 보내는 값이 바뀌어도 안 깨지게).
2. **그림을 바꾼 저장 = 0(ⓘ-11 그대로)** → 그 뒤는 갈래 B Y/N 몫. Y = `CreateYTemplateAsync` · N = 고객 명시 거절이라 Y 0 · 옮기기가 N 을 뒤집는 길 0. 「그림 바꿈」 은 B 확인창 띄움 조건과 같은 기준이어야 한다 — **확인 필요: 그림 올리기가 같은 경로로 덮어쓰는 길이 있는지**(있으면 경로 비교로 못 잡음 → B 가 「새로 올림」 을 요청에 실어 서버가 0).
3. **코드 자리** — `FormTemplateService.cs` `UpdateCoreAsync`(`:284~` · `:290` 앞)에서 같은 트랜잭션 안 `SELECT … FOR UPDATE` 로 현재 행을 읽고 C# 으로 정한다. `CreateCoreAsync`(`:157`) = 그대로 0. `ResolvePrintBackgroundToSave`(`:986`) 서명 그대로 — 인자를 더하지 말고 고치기 길에 새 함수 1개(반사로 부르는 시험 깨짐 막음).
4. **MariaDB 함정** — 한 UPDATE 문 SET 안 CASE 로 하지 말 것. 이 UPDATE 는 `paper_mode`(2번째) · `background_image_url`(10번째)을 `print_background`(17번째)보다 먼저 쓰고, MariaDB 기본 동작은 SET 을 왼쪽부터 적용해 뒤 칸이 **새 값**을 본다 → 「무변」 이 늘 참. 읽기 → 판정 → 쓰기를 나눈다.
5. **옮기기와 경쟁** — 옮기기는 종 행을 잠근 뒤 대상을 다시 뜬다(`RunYMigrationOnceAsync` `:594~` · `:609`). 저장이 먼저 잡으면 옮기기가 기다렸다 1 을 보고 Y 를 만들고, 옮기기가 먼저면 저장이 0 을 읽어 0 — 결과 같음. 잠금을 빠뜨려도 다음 기동 재사용(ⓘ-10)으로 Y 1개에 모이지만 잠금은 넣는다.
6. **DB-150 미적용 창** — 키 칸(`is_default` · `is_active`) 처리는 무변이라 옛 키 아래 새 1062 길 0. 행은 1 로 남아 DB-150 이 선 다음 기동에 옮겨진다. 1 로 남긴 저장 때 이름 붙은 정보 로그 1줄(「옮기기 대기 중 저장 — 다음 옮기기에서 Y 로 만듦」).
7. **출하 묶음** — F-1 단독 게시 금지 · 갈래 B(Y/N)와 같은 판으로만(조건 2 의 「그림 바꾼 저장」 Y 길이 B 확인창이다). [3-V] P2-1 · P2-2 고침(개발 2 진행 중)과 겹침 0 — (나)는 `CreateYTemplateCoreAsync` 를 안 건드린다. 창 안에서 고친 여백 · 매수는 옮기기가 편집 뒤 행을 복사하므로 Y 에 그대로 실린다(맞는 동작).
