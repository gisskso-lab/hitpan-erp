## 1. 🔴 P0-1 — 봉합 실효 범위가 PM 주장보다 좁다 (병렬검증 적발)

### 사실

`installer/HitPan-Universal.iss:1055-1061` (비-LOCAL = **정식 설치** 경로):

```pascal
TargetUrl := 'https://' + G_PrimaryDomain;
FixupOneAppSettings('{app}\web\wwwroot\appsettings.json', TargetUrl);
FixupOneAppSettings('{app}\web\wwwroot\appsettings.Local.json', TargetUrl);
FixupOneAppSettings('{app}\web\wwwroot\appsettings.Development.json', TargetUrl);
FixupOneAppSettings('{app}\api\wwwroot\appsettings.json', TargetUrl);
```

`FixupOneAppSettings`(`:1018-1030`)는 대상 파일을 **읽지 않고 고정 2키 JSON 으로 전면 덮어쓴다.**

### 결과 — 봉합 실효 범위

| 경로 | PM 봉합(빈 값) 실효 |
|---|---|
| 자동업데이트 | ✅ 있음 |
| LOCAL 모드(시리얼 없음) | ✅ 있음 — `:1046-1049` 가 빈 값으로 정정 |
| **정식 설치(시리얼 있음)** | ❌ **덮인다** |

⇒ 정식 설치에서 격리는 여전히 **`G_PrimaryDomain` 단일 실패점**에 걸려 있다.
  그 값이 오염되면(7/01·7/07 계통) 즉시 재붕괴하며 **이번 봉합은 못 막는다.**

### 부수 피해
PM 이 오늘 심은 `_comment_ApiBaseUrl` 재발방지 가드가 **설치 시점에 100% 소멸**한다.
다음 사고 조사자가 고객 PC 를 열면 경고문을 못 본다.
`appsettings.Local.json` 에는 원본에 없던 `BackofficeApiBaseUrl` 키가 주입된다(스키마 변형).

### 권고
`FixupOneAppSettings` 를 **전면 덮어쓰기 → ApiBaseUrl 값만 치환**으로 변경.
비-LOCAL 분기도 `""`(자기 출처 폴백) 통일 검토 — `web-server.ps1:89` 프록시가 같은 출처를
처리하므로 도메인을 써넣을 필요 자체가 없다.

## 2. 🔴 P1-1 — 스모크 테스트가 봉합을 되돌린다 (병렬검증 적발)

`scripts/smoke-test.ps1:57-68`:

```powershell
Check "appsettings.json ApiBaseUrl 정상" {
    $r.Content -match 'api-demo.hitpan.kr'          # api-demo 가 있어야 PASS
}
Check "appsettings.Development.json ApiBaseUrl 정상" {
    $r.Content -match 'api-demo.hitpan.kr'
}
```

**오늘 P0 의 원인 문자열을 '정상'으로 검사한다.**
봉합하면 이 스모크가 FAIL 로 뒤집힌다. 두 결말 모두 나쁘다:
- (a) 통과시키려 봉합을 되돌린다 → **P0 재발**
- (b) 상시 적색 → 무시 습관화

**오진 3회의 공통 패턴 — "검증기가 틀린 걸 정답으로 알고 있다" — 와 동일 계통.**

> ⚠️ **봉합보다 먼저 처리하지 않으면 게이트가 봉합을 되돌린다.**

## 4. ⚠️ PM 주석의 미검증 단정 2건 — 정정 필요

**오진 3회와 동일한 "실측 없이 확정" 패턴이 봉합 문서에까지 이어졌다.**

| PM 이 쓴 것 | 검증 결과 |
|---|---|
| "`Local.json` 이 `appsettings.json` 보다 우선 적용된다" | ❌ **로드 코드 0건.** `AddJsonFile` 등록 없음. Blazor WASM 은 `appsettings.json` + `appsettings.{Environment}.json` 만 읽고 `Local` 은 표준 환경명이 아니다. **파일이 서빙된 것과 로드된 것을 혼동했다** |
| "`Development.json` 은 출하 payload 에서 strip 이 제거" | ❌ **제거 코드 0건.** `build-installer-universal.ps1` 전체에 없다. `deploy-web.sh:54` 의 EXCLUDES 는 NCP 백오피스 전용이라 고객 EXE 와 무관. **고객 PC 로 출하된다** |

※ `Development.json` 의 실피해는 낮다 — Blazor WASM 은 `blazor-environment` 헤더가 없으면
  Production 이라 로드하지 않는다(헤더 설정 코드 없음 확인). 그러나 **주석의 단정은 거짓**이다.

**값을 비운 것 자체는 두 건 모두 타당**(로컬 빌드·수동 배포 시 실릴 수 있음). 주석만 정정한다.

## 5. ✅ 반증 실패 — 타당하다고 확인된 것 (억지 지적 아님)

### ⭐ 7/30 "비웠더니 405" 모순 — **규명 완료, 모순 아님**

가장 중요한 검증 지점이었다. 두 상황은 **물리적으로 다른 배치**다.

| | demo 개발환경 (7/30, 405) | 고객 설치본 (지금) |
|---|---|---|
| Web 출처 | `demo.hitpan.kr:5234` | `{고객사}.hitpan.kr` |
| API 출처 | `api-demo.hitpan.kr:5257` — **다른 도메인** | **같은 출처** |
| `/api/*` 프록시 | **없음** (NCP nginx 정적 서빙만) | **있음** — `web-server.ps1:89-137` |

7/30 의 405 는 프록시가 없는 demo 배치에서 자기 도메인을 부른 결과다.
고객 설치본에는 프록시가 실재하므로 같은 증상이 나지 않는다.
demo 는 `appsettings.Development.json` 이 `api-demo` 를 유지해 안 깨진다. **PM 판단이 옳다.**

### 그 외 반증 실패 항목
- **폴백 체인** — 환경변수 2단계는 Blazor WASM 브라우저 샌드박스라 항상 null. 위험 없음
- **모든 배포 형태 안전** — 터널·localhost·LOCAL·demo 4경로 실증
- **랜딩 HTML `back.hitpan.kr` 고정** — `/api/landing/beta-signup` 은 백오피스 API 에만 존재
  (`LandingPublicController.cs:91`). 빈 값이면 404. 본사 공용 창구라 고정이 정답(헌법 #35)
- **`db.conf` 부재/손상 시** — `DbConfReader.cs:29,41` → 빈 값 → `WS28E:29-31` 이 헬스체크 건너뜀.
  demo 로 새지 않는다. 설계가 옳다
- **업데이트 통교체 구조** — 손대지 말 것. 병합 로직은 상태를 만들고, 폴백은 이미 무상태 정답.
  통교체는 롤백 대칭성(헌법 #20)을 확보한 검증된 구조
