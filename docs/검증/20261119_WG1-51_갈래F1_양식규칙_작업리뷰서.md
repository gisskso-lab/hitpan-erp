## §4 PM 확인 요청 사실 재기

### Ⓐ 옮기기 전 창에 옛 켬 양식지를 저장하면

| 묻는 것 | 사실 (줄 근거) |
|---|---|
| 무엇이 되나 | 화면은 DB 에서 읽은 `PrintBackground`=true 를 그대로 보낸다 → 고치기 `UpdateCoreAsync`(:290)가 `ResolvePrintBackgroundToSave`(:986 · 양식지면 무조건 false)로 **0 저장** → 그 행은 옮기기 대상 조건(`paper_mode='preprint' AND print_background=1 AND is_active=1`)에서 빠진다 → 그 뒤 어느 기동에도 Y 0 · 고객에게 알림 0 |
| 결과가 Q14 와 어긋나나 | **실제로 어긋난다.** 옮기기 전에도 갈래 A 로 원래 양식지는 이미 「데이터만」 나간다(배경 단계 경고 문구 그대로). 저장 뒤에는 그 상태가 굳어 「그림까지 인쇄하던 모양」 으로 돌아갈 길이 고객이 그림을 다시 올려 Y/N 확인(Q17)을 밟는 것뿐이다 |
| 창이 얼마나 열려 있나 — 보통 | 새 판 API 기동 → 워치독 /health 확인 최대 60초(`UpdateOrchestrator` 검증 게이트) → `success` 기록(`:280`) → 배경이 30초 간격으로 봄(`Program.cs:621`) ⇒ **기동 뒤 대략 1분 반 안팎** |
| 창이 길어지는 길 | ① `KeysNotReady`(DB-150 실패 · 미적용) → 기동마다 즉시 끝(`Program.cs` 경고 줄 · `return`) ⇒ DB-150 이 설 때까지 **무기한** ② `NotConfirmed` 가 10분 넘음 → 그 기동은 쉼(`:620` 기한 줄) ⇒ 다음 기동 · 성공 기록이 끝내 안 생기면(쓰기 실패 · 판 글자 꼴 불일치 · 업데이트 아닌 길) **다음 업데이트 성공까지** ③ 행 단위 실패(폴더 밖 · 사본 실패 · 종 거래 되돌림) → 그 행만 **다음 기동까지** (기동당 1회 · 다시 열지 않음) |
| 판정 | P1-1 — 설계 결재 두 줄(ⓘ-11 · 대상 조건) 사이 빈칸. 코드 위반 아님 |

|---|---|
| 새 키 아래 | `UPDATE … SET is_active = 0, is_default = 0`(:391) → 계산 칸이 NULL → 유일 키는 NULL 을 겹침으로 보지 않음 ⇒ **1062 길 0** |
| 옛 키 아래 | 같은 종에 이미 끈 행이 있으면 `(회사, 종, 0, 0)` 겹침 ⇒ 1062 → 컨트롤러 `:90` 잡는 곳 0 · API 전역 예외 처리 줄 0 ⇒ 500 (main 과 같음) |
| 옛 키 DB 가 실제로 생기는 길 | ② 건너뜀은 「겹침 ≥ 1」 일 때만인데 옛 키가 서 있으면 겹침이 생길 수 없다(옛 키와 모순) → **② 건너뜀으로는 옛 키 DB 가 안 남는다.** 남는 길 = DB-150 파일 자체가 실패하거나 안 돈 DB(적용기가 실패를 남기고 기동은 계속하는 부분 실패 정책 · `Program.cs:499` 무렵 주석) 하나뿐. 새 판에서 옛 판으로 되돌아가도 새 키는 남고 옛 키는 다시 안 생김 |
| 판정 | P2-3 — 새로 생긴 위험 아님 · 범위 넓힐지는 PM |
