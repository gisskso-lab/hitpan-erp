## §4 발견

### P2-1 미리보기 다시 그림의 겹침 — 늦게 끝난 옛 그림이 덮음(가설 · 실행 0)
- `PreviewAsync`(`:1519~1574`)는 `_previewBusy` 를 **확인하지 않고** 켠다. 미리보기 단추(`:579`)만 `Disabled="_previewBusy"` 로 막히고, 그림 올리기(`:1294`) · 그림 지우기(`:1335`) 길은 `PreviewAsync` 를 그대로 부른다(올리기 칸 막힘 = `_bgBusy` 뿐 · 지우기 = `_bgBusy || _busy`).
- 시나리오: 「격식」 고름 → 고르기 고리의 그림이 도는 중 → 1초 안에 양식 그림 올림 → 그림 두 장이 동시에 돎. ① 고르기 쪽이 늦게 끝나면 **그림 없는 격식 판**이 미리보기에 남음(편집창 상태 = 그림 깐 양식 · 인쇄 모양 흐림) ② 먼저 끝난 쪽이 `finally` 에서 `_previewBusy=false` → 고리의 `while (_previewBusy)` 기다림이 다른 그림 도중에 풀림 ③ 둘 다 시작 때 `ClosePreviewAsync` 를 부르므로 먼저 만든 주소 1개는 거둬지지 않음(작은 메모리 남음).
- 지시서 §6 약속 「늦게 끝난 옛 그림이 새 고름을 덮는 일 0」 은 **고르기끼리는 지켜짐**(고리 1개 · 순서대로). 위 겹침은 다른 길과의 겹침이고, 같은 종류 겹침(올리기 vs 단추)은 E⑷ 전부터 있던 것 — E⑷ 가 새 출발점 하나를 더함.
- 명세 §8 은 「창 닫기 뒤 1번 더 그림」 만 기록 → 이 겹침 기록 0.
- 조치: 명세 §8 기록 + 갈래 D 측정 칸. 고침(그림 세대 번호로 늦은 응답 버림 등)은 PM 판단 · 즉석 봉합 금지.
