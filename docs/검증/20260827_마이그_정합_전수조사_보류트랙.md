## 5. 🟡 부수 발견 (금액 영향 없음)

### 5-1. 명세서↔계산서 링크가 **작성돼 있는데 안 돈다**
- `sql/migrations/20260518_WSF_DOCFB_TAXNO_LINK.sql` — `IJ_TAXNO ↔ TX_NO` 로 양방향 링크
- 🔴 **실행 배선 0건**: 러너가 `Migrations/SQL/DB-*.sql` 만 읽는다(`MigrationRunner.cs:39-40, 230-252`) — 경로·파일명 둘 다 불일치
- ⇒ `DB-NNN` 으로 옮기면 켜진다. **없는 데이터를 안 만들고 실제로 끊긴 사슬을 잇는다**
- ⚠️ 켜기 전 확인할 결함 2개:
  - `CAST(legacy_tax_no AS CHAR(8))` — 앞자리 0 소실 가능(`IJ_TAXNO` 는 char(8) 인데 int 로 저장)
  - 센티널 불일치: 코드는 `99999999` 를 NULL 처리(`:4298`), 문서는 **`"00000000"`** 이 "워크플로우 없음"(`MIGRATION_MAPPING_OFFICIAL.md:52`)

### 5-2. 마이그는 상위문서 링크를 **양쪽 다** 안 채운다
- `sales_deliveries.order_id` — `DeliveryHeaderRow`(`:4814`)에 필드 **없음**
- `purchase_receipts.po_id` — `ReceiptHeaderRow`(`:4849`)에 필드 **없음**
- ⇒ **매출만의 문제가 아니다.** 같은 DOCFB 분기 코드라 필연

### 5-3. 🔴 수주·발주 소급 생성은 **하지 마라**

| 레거시 원본 | 건수 |
|---|---:|
| DOCFB 거래명세서 | **236,139** |
| DOCFO 수주 | **180** |
| DOCFA 발주 | **682** |

- 레거시 사용자는 **수주·발주를 거의 안 썼다**(0.1% 미만). 명세서부터 쳤다
- DOCFB 에 **수주번호 필드가 없다** ⇒ 이을 열쇠도 없다
- 만들면: 수주현황 리포트에 `is_auto` 필터가 **없어**(`ReportService.cs:185,203,222,242,263`) 소급분 전량 합산 ⇒ **180건이 수만 건으로 왜곡**
- 반대로 수주 목록은 `is_auto=0` 하드코딩(`SalesService.cs:1279`) ⇒ **안 보임**
- ⇒ **"목록엔 없는데 리포트엔 있다"** 비대칭
- 🟢 **회계·재고에는 기여 0** (수주는 원장·분개 미접촉 — 실측 확인)

🔴 **사장님 기준(*"그 이후 잡히는 건부터 사슬이 이어져도 상관없다"*)에 따라 소급은 불필요 확정.**
