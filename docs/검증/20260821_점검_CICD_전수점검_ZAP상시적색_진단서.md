## 1. 🔴 A — ZAP: main 푸시마다 100% 실패

### 실측
```
main 최근 8회: failure ×8  (8/20 08:54 ~ 19:47)
```

### 진범은 스캔 결과가 아니다 — 3축 분해

**축① 스캔 자체는 통과했다**
```
FAIL-NEW: 0   FAIL-INPROG: 0   WARN-NEW: 5   PASS: 65
```
게다가 워크플로에 **`fail_action: false`** 가 박혀 있다(`zap-baseline.yml:35`).
⇒ **취약점 때문에 실패한 게 아니다.**

**축② 진짜 실패 지점 = 아티팩트 업로드**
```
##[error]Create Artifact Container failed:
        The artifact name zap_scan is not valid.  (HTTP 400)
```
`zaproxy/action-baseline@v0.12.0` 이 `actions/upload-artifact` **구버전 API(6.0-preview)** 를 쓴다.
GitHub 가 해당 API 를 폐기 → **우리가 커밋 한 줄 안 해도 남이 우리 CI 를 깬 구조.**
(#206 Inno 사건과 **같은 종류**: 외부 의존을 고정 안 하면 남이 우리를 깬다)

**축③ 스캔 대상이 죽어 있다 — 별건 문제**
```
https://api-demo.hitpan.kr/           → HTTP 530   ← 실측
https://api-demo.hitpan.kr/robots.txt → HTTP 200
Job spider error ... status code returned : 530 expected 200
```
530 = Cloudflare 터널 오리진 다운. **루트가 죽었는데 robots.txt 만 산다.**
⇒ ZAP 이 **실질적으로 아무것도 스캔하지 못하고 있다.** PASS 65 는 헤더 검사일 뿐이다.

> 🔴 **이게 더 위험하다.** 봉합해서 초록불이 떠도 **스캔 대상이 죽어 있으면 DAST 는 여전히 0건**이다.
> 헌법 #23 5중검증 ④ DAST 가 **서류상으로만 도는** 상태.


**`#206` 봉합이 진짜인지 대조실험**:
| 조회 | 결과 | 의미 |
|---|---|---|
| `api/v2/package/innosetup/6.7.1` (현재 핀) | **HTTP 302** | 존재 ✅ |
| `api/v2/package/innosetup/6.7.3` (죽인 핀) | **HTTP 404** | 없음 — 실패 원인 확정 |

## 3. 🟡 C — TruffleHog: 의도된 적색

`push` 이벤트(전체 히스토리)에서만 간헐 실패. **차등 스캔(PR)은 통과.**
인수인계서 §7 에 이미 정리된 **진탐 119건** 건이다.

> `.github/trufflehog-exclude-paths.txt` 팀 주석: *"제외하면 덮는 것이다. 스캔은 계속 빨간 X 로 남는다. **그것이 의도다.**"*

⚠️ **이건 "고쳐야 할 CI 고장"이 아니다.** 별건 작업지시서로 **비밀값 자체를 걷어내야** 닫힌다.
CI 를 초록으로 만드는 방향(제외 추가)은 **금지** — 덮는 것이다.
