## 5. 🟢 사장님 판정식이 그대로 게이트가 된다

사장님 결재 1(기본 로직)이 **글자로는 절대 못 만드는 게이트**를 준다.

`GetStockLedgerAsync` 는 view=item 과 view=partner 가
**같은 `stock_ledger` 를 읽고 GROUP BY 만 다르다**(`ReportService.cs:2532~2590`).

⇒ **같은 사실의 두 절단이니 총합이 반드시 같아야 한다.**

```
Σ(상품축 수량) == Σ(업체축 수량)
Σ(회계 매출)   == Σ(명세서 확정 − 반품 확정)
```

봉합이 깨지면 **재고는 2배 빠지는데 회계는 1배**라 **반드시 FAIL** 한다.
문자열 검사로는 흉내 낼 수 없다.

## 9. 검증팀 권고 — 착수 순서

| 순 | 내용 | 왜 이 자리인가 |
|---|---|---|
| **1** | 🔴 **CI 에 DB 잡 신설** | 없으면 **새 게이트도 전부 SKIP**. 안 고치면 오늘 일이 반복된다 |
| **2** | **탐지 먼저** — 정합성 검사 매출 대칭 + 오염 건수 확정 | 대조군 없이 고치면 봉합 후 *"0건"* 이 증거가 안 된다 |
| **3** | 🔴 **게이트를 봉합 전에 짜서 빨간불 확인** | 초록이면 가짜. **게이트는 봉합자가 짜지 않는다**(SoD) |
| **4** | 상태 한글 전환 + 봉합 | 상태가 먼저 서야 버튼·목록을 한 번에 맞춘다 |
| **5** | 교차검산 등식 + 무력화 시험 (**봉합자 아닌 사람이**) | 하나라도 초록이면 그 게이트는 가짜, 미완료 |

🔴 **봉합부터 하면 안 된다.** 3번을 4번 뒤로 미루는 순간 오늘과 같은 *"1100 통과"* 가 다시 나온다.
