## 0. 이 문서가 실측보다 먼저 있는 이유

> **실측하면서 기준을 만들면 결과에 기준을 맞추게 된다.**

작10 은 이미 한 번 그렇게 실패했다. 설계서를 코드 뒤에 썼더니 위험분석에서 cmd 파싱이 0건이 되었고,
P0 2건이 그대로 통과했다([검증리뷰서](20260730_작10_P0-5_설치6단계관측성_검증리뷰서.md) §11).

**같은 역전을 반복하지 않으려고 판정 기준을 먼저 확정한다.**
실측 중에 이 문서를 고치지 않는다. 기준이 틀렸다고 판단되면 **고치는 게 아니라 기록하고 사장님께 보고**한다.

## 1. 실측 환경 — 백지여야 한다

| 조건 | 요구 | 불가 시 |
|---|---|---|
| 환경 | **Windows Sandbox** 또는 포맷 직후 PC | 개발 PC 실측은 **인정 안 함** |
| 사전 상태 | `cloudflared` 서비스 **미등록** (`sc query cloudflared` = 1060) | 잔재 있으면 백지 아님 → 환경 재생성 |
| 설치 방식 | EXE 1회 실행. **수동 개입 0** | 수동 `sc start` 를 한 순간 그 회차는 **실패 처리** |
| 로그 위치 | `%temp%\Setup Log*.txt` | |

> 🚫 **개발 PC 정상 작동은 검증이 아니다** (사장님 못박음 2026-07-06).
> 오늘 봉합한 6단계는 **백지에서만 드러나는 경로**다.

## 2. 판정 기준 (통과/실패를 미리 못박는다)

### RV-3 — `6-1-scdelete` 에 실제 종료코드·출력이 남는가

**무엇을 보나** 설치 로그에서 `[작10 P0-5][6-1-scdelete]` 줄

| 판정 | 조건 |
|---|---|
| ✅ **통과** | 종료코드 줄이 있고, 그 값이 **`0` 이 아닌 실제 sc 코드**(백지면 `1060` 예상). 즉 `timeout` 의 0 이 아님 |
| ✅ 통과(대안) | 종료코드 0 이면서 **출력 본문에 sc 의 성공 메시지**가 함께 남음 |
| ❌ **실패** | 종료코드 0 인데 출력 본문이 없거나 `timeout` 카운트다운 문자열이 보임 |
| ❌ 실패 | `[6-1-scdelete]` 줄 자체가 없음 |

> **이것이 P0-2 의 직접 반증이다.** 봉합 전에는 `sc delete` 가 실패해도 `종료코드 0 (성공)` 이었다.
> 백지 신규설치는 지울 서비스가 없으므로 **1060 이 나와야 정상**이다.

---

### RV-4 — `6-1-2` 가 정상 분기를 찍는가

**무엇을 보나** `[6-1-2]` 로 시작하는 줄

| 판정 | 조건 |
|---|---|
| ✅ **통과** | **`[6-1-2] 좀비 서비스 없음(정상) — delete 건너뜀`** 이 정확히 출력 |
| ❌ **실패** | `(명령 자체가 실행되지 않았을 수 있다)` 가 보임 → **P0-3 미봉합** |
| ❌ 실패 | 백지인데 `좀비 서비스 잔존 확인` 이 찍힘 → 분기 판정 오류 |
| ⚠️ 조건부 | 환경에 실제 잔재가 있었다면 `잔존 확인` 이 정상 — 단 §1 백지 조건 위반이므로 회차 무효 |

---

### RV-5 — 토큰이 설치 로그에 0건인가

**무엇을 보나** 설치 로그 전문

**실행할 명령** (실측자가 그대로 친다)
```
findstr /C:"eyJhIjoi" "%temp%\Setup Log*.txt"
```
> `eyJhIjoi` = cloudflared 터널 토큰(base64 JSON)의 고정 접두. 토큰 전체를 문서에 적지 않는다.

| 판정 | 조건 |
|---|---|
| ✅ **통과** | **검색 결과 0건** |
| ✅ 통과 | `***TOKEN-MASKED***` 만 발견 (마스킹이 작동한 것 — 단 RV-6 은 ❌가 된다) |
| ❌ **실패** | 토큰 원문이 1건이라도 발견 → **즉시 P0. 배포 중단.** |

---

### RV-6 — `cloudflared service install` 이 토큰을 에코하는가 🔴 **필수**

**무엇을 보나** `[작10 P0-5][6-2-serviceinstall]` 의 출력 본문 줄

| 판정 | 조건 | 후속 |
|---|---|---|
| ✅ **에코 없음** | 출력에 토큰도 `***TOKEN-MASKED***` 도 없음 | 마스킹은 무해한 보험으로 유지 |
| ⚠️ **에코 있음(마스킹 작동)** | `***TOKEN-MASKED***` 가 보임 | 마스킹이 **실제로 유출을 막은 것**. 유지 필수. `db.conf`·워치독 등 **다른 토큰 경로 전수 점검** 착수 |
| ❌ **에코 있고 마스킹 실패** | 토큰 원문이 보임 | **별건 P0. 즉시 배포 중단·봉합** |

#### ⚠️ 코드 주석이 이 항목을 미리 단정하고 있다 (검증팀 주의)

`HitPan-Universal.iss:1933` 주석:

> *"출력 본문은 cloudflared 의 메시지일 뿐 **토큰을 되뱉지 않는다**"*

**이 단정은 실측 근거가 없다.** RV-6 이 검증하려는 바로 그 명제를 주석이 이미 참으로 적어놨다.
검증리뷰서는 이 위험을 **V-4 미확정**으로 남겼고, 그래서 봉합 코드에 마스킹을 넣었다.

⇒ **실측자는 이 주석을 근거로 삼지 말 것.** 실측 결과가 나오면 주석도 함께 정정한다.
⇒ 작10 의 P0 3건이 나온 원인이 *"검증된 패턴이라 불렀지만 선례 0건"* 이었다. 같은 종류다.

### RV-7 — 기존 성공 경로 무변경 (회귀 없음)

**무엇을 보나** 6-3 구간 + 종단 접속

| # | 확인 | ✅ 통과 조건 |
|---|---|---|
| 7-1 | `[6-3-scconfig]` | 종료코드 0 |
| 7-2 | `[6-3-scstart]` | 종료코드 0 |
| 7-3 | `[6-3-scquery]` | 종료코드 **0** (서비스 존재) |
| 7-4 | `[20260714작1 W1-3]` 재시도 로그 | **출력되지 않아야 정상** (1차 성공 시) |
| 7-5 | 서비스 상태 | `sc query cloudflared` → `RUNNING` |
| 7-6 | **수동 개입** | `sc start` 를 사람이 친 적 **0회** |
| 7-7 | **종단** | `{고객사ID}.hitpan.kr` 접속 → **로그인 성공** |

> 🔴 **7-6·7-7 이 작10 의 진짜 게이트다.**
> 로그가 아무리 예뻐도 **수동 `sc start` 없이 터널이 붙고 로그인까지 가야** 작10 이 끝난다.

## 3. 이번 실측의 본래 목적 — 잊지 말 것

작10 은 **원인을 찾는 코드**지 **원인을 고치는 코드가 아니다.**

7/30 샌드박스 실패의 회귀 원인은 아직 **모른다.** 전제 조건이 전부 정상인데 결과만 실패했고,
로그가 침묵해서 추적이 불가능했다([설계서](../설계/설치배포/20260730_설치6단계_관측성_설계서.md) §1-2).

⇒ **이번 실측에서 `[6-2-serviceinstall]` 줄이 회귀 원인을 말해줘야 한다.**

| 결과 | 의미 | 다음 |
|---|---|---|
| 설치가 **성공**해버림 | 회귀가 재현 안 됨 | 관측성은 검증되나 **원인은 미해결**. 재현 조건 탐색 필요 |
| 설치 **실패 + 원인 로그 확보** | **작10 목적 달성** | 로그가 지목한 원인으로 별건 작업지시서 |
| 설치 **실패 + 로그 여전히 침묵** | **작10 실패** | 관측 지점이 틀렸다 — 설계 재검토 |

> 3번 결과가 나오면 봉합이 헛일이었다는 뜻이다. 그것도 사실대로 기록한다.
