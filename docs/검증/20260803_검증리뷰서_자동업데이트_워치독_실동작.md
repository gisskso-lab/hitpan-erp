### 부수 확인 — 왜 처음엔 안 떴나 (결함 아님)

게시(20:57) **전에** 워치독을 재시작해 1.2.48 을 "최신"으로 판정했고, 그 날짜가 남아 재조회하지 않았다.

⚠️ 운영 시사점: 새 버전 게시 후 즉시 반영을 원하면 **게시 완료 후** 워치독 재시작이 필요하다.

| 채널 | 동작 |

## 3. 오늘 확정된 진범 (실측 채증)

```
> sc delete Cloudflared          → [SC] DeleteService SUCCESS
> cloudflared service install    → "already installed at Cloudflared"
> cloudflared service uninstall  → "marked for deletion"
> cloudflared service install    → ✅ 성공
   Cannot install event logger:
   SYSTEM\CurrentControlSet\Services\EventLog\Application\Cloudflared
```

**cloudflared 는 서비스 존재를 SCM 이 아닌 자체 레지스트리 키로 판정한다.**
`sc delete` 는 그 키를 지우지 않는다 → 잔재가 남으면 영구히 설치 거부 → 1033.

### ③ 이 빌드됐으면 8/02 무한정지가 재발했다

봉합안이 쓰려던 명령을 **빌드 전에 종료코드 실측**한 결과:

```
sc queryex type= service state= all | findstr /I "cloudflared"
  있는 서비스 → exit 0
  없는 서비스 → exit 0    ← 항상 0
```

파이프가 `sc`(exit 0)의 코드를 내고 `findstr`(exit 1)을 삼킨다.
괄호 묶기·`&` 체인·리다이렉트 위치 변경 **4형태 전부 동일**.

⇒ 6-1 taskkill 가드(`ScStopCode <> 0`)가 **항상 거짓 → taskkill 항상 실행 → Sandbox 무한 hang.**
   8/03 에 겨우 봉합한 것이 통째로 무력화될 뻔했다.

**교훈(재확인): 종료코드는 추측하지 않고 실측한다.** — 검증팀 P0-1 교훈과 동일.

### 부수 확인 — `sc query` 실패 코드는 환경 의존

⇒ `<> 0`(안전측) 판정이 옳았음이 재확인됐다. 특정 코드값 판정 금지.
