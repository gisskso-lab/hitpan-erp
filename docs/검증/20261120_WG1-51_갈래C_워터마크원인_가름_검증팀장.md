## 0. 한 줄 결론

**C 의 전제 「로고 있음」 이 기록에 없다.** CTO §1-3 은 「로고 있음 × 반영 0」 을 전제로 가설 셋을 세웠는데, 그 전제는 대표 11/18 Q1 답(「로고를 뺐으면 … 아무것도 안 보여주면 되지」 = **로고 없을 때 바라는 모양**)을 설계 :22 · :118 이 「그러니 ① 원인은 로고 있음 경우」 로 넓혀 읽은 것이다. 대표가 10/26 에 로고를 올렸다는 원문 · 실측은 0건이고, 같은 날 [1-V] 실측은 **로고 보관소 0건**이었다. ⇒ 가설 셋 앞에 **H-C0(그때 로고가 없었다)** 을 세워야 하고, 기록상 가장 강하다. 기록만으로는 못 닫는다 → **대표 1문항 필요**(§5).

## 4. ③ 증상 ③ 과 한 뿌리인가 — H-C4

**H-C4(새)**: 대표가 워터마크를 **양식정보설정의 한 양식(「새 견적서 양식」)에서만 켰고**, 전표 [인쇄] 는 그 양식을 안 탔다(증상 ③ 「새 견적서 폼 안 나오고 기본 폼」) ⇒ 쓰인 양식 = 없음 또는 다른 양식 → `formSays` = NULL → 공통 `watermark_enabled`(기본 0 · N2 · N2a) → 겹 null. 이러면 ① 과 ③ 은 **한 뿌리(양식 고르기)**.

- 맞물림: 대표 ③ 이 같은 때 [인쇄] 가 양식을 안 탔다고 적음 · [1-V] 작2 `:45` 가 「대표가 워터마크를 켠 화면이 `/print-settings` 인지 `/settings/form-templates` 인지」 를 **대표께 한 줄 확인 필요**로 남겼고 답 기록 0.
- 약점: 작2 [1-V] 는 ②③ 뿌리를 「순백(plain) 양식은 좌표를 못 탄다」(H3)로 지지 — 이 뿌리면 [인쇄] 는 양식 **행은 탔고** 좌표만 안 쓴 것이라 `show_watermark` 는 읽힘 → H-C4 약해짐. 「행을 안 탔다」(is_default 누락 · H1)면 H-C4 강해짐. 작2 는 H1 · H2 를 「DB 행 없이 못 가름(⚠️미측정)」 으로 남김.
- 1.3.67 양식 고르기 규칙(`TryLoadTemplateAsync`)과 [인쇄] 창이 보내는 `ShowWatermark` 첫 값(N2b) = **이번에 못 읽음 → 미측정**.
