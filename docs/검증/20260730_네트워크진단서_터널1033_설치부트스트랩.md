## 0. 결론 먼저

**터널 발급 코드는 정상이다. 백오피스 API 도 정상이다. 끊긴 곳은 "발급 조건"과 "실패 은폐" 두 곳이다.**

1. 터널은 **`tenants.status='active'` 일 때만** 발급된다 → 승인 안 된 계정은 **애초에 터널이 없다**
2. 터널·DNS·ingress 실패가 **전부 `catch` 로 삼켜지고 부트스트랩은 "성공"으로 응답**한다 → 설치는 완료되고 접속만 안 된다

> ⚠️ **PM 최초 진단은 오답이었다.** 아래 §5 에 정정 기록.

## 1. 증상 (실측)

| 대상 | 결과 | 시각 |
|---|---|---|
| `test1.hitpan.kr` (Sandbox) | **HTTP 530 / Error 1033** | 2026-07-30 06:00 UTC |
| `test2.hitpan.kr` (타 PC) | **HTTP 530 / Error 1033** | 동일 |
| `landing.hitpan.kr` | 200 ✅ | |
| `back.hitpan.kr` | 200 ✅ | |
| `updates.hitpan.kr` | 200 ✅ | |

**Error 1033 = Cloudflare 가 호스트를 터널로 인식하지만 연결(cloudflared)이 없음.**
즉 DNS(CNAME)는 있고 **터널 연결이 없거나 ingress 가 비어 있다.**

## 2. 회귀 아님 — 먼저 배제했다

사장님 의심(*"정상설치건 건든거 아니야?"*)에 따라 전수 확인:

- `649ed88..origin/main` 의 `installer/`·`Watchdog/` 변경 = `0cd19bf`(게시배선)·`c6c48fd`(문서경로) **2건**
- **터널·cloudflared·DNS 코드 변경 0건**
- 사장님 확정: *"다른버젼이지"* — 종전 성공본과 `1.2.43` 은 다른 빌드

⇒ **오늘 작업이 깨뜨린 것이 아니다.** 신규 경로를 처음 밟아 드러난 것.

## 3. 실측 채증

### 3-1. 백오피스 bootstrap API — **정상**

```
POST https://back.hitpan.kr/api/installer/bootstrap
{"licenseKey":"TEST-INVALID-0000","machineFingerprint":"diag-pm-20260730", ...}

→ HTTP 401
  {"success":false,"message":"올바르지 않은 시리얼이거나 승인되지 않은 계정입니다."}
```

**API 살아있고, 인증 거부도 정상, 한글 안내문까지 정상.** 서버는 무죄.

### 3-2. 설치 EXE 의 호출 경로 — **구현 완비**

게시 EXE 는 `HitPan-Universal.iss`(2,038줄)로 컴파일된다
(`deploy-update.yml:344-348` — ISCC 인자 실측).

| 요소 | 위치 | 상태 |
|---|---|---|
| 시리얼 입력 | 91건 참조 | ✅ 있음 |
| `CallBootstrapApi(Serial)` | 455행 | ✅ 있음 |
| `BackofficeApi = https://back.hitpan.kr` | 36행 | ✅ 있음 |
| TLS 1.2/1.3 명시 | PS 스크립트 | ✅ (PS 5.1 기본 TLS1.0 사고 방지) |
| `-UseBasicParsing` | 동일 | ✅ (IE 의존 0) |
| 실패 진단 로그 | `{tmp}\bootstrap-error.txt` | ✅ 있음 |

> **CORS 는 이 경로와 무관하다.** `Invoke-RestMethod`(PowerShell 서버사이드) 호출이므로
> 브라우저 동일출처 정책이 적용되지 않는다. `HitPan-Universal.iss:176` 의 CORS 기록은
> **웹 setup(브라우저) 경로**의 옛 사고이며 현재 EXE 경로에는 해당하지 않는다.

### 3-3. ⭐ 터널 발급 조건 — **여기가 1차 급소**

`InstallerBootstrapController.cs:65-78`

```sql
WHERE t.license_key_hash = @Hash AND t.status = 'active'
```

`tenants.status='active'` 가 되는 시점은 **백오피스 승인(approve)** 뿐이다
(`SignupsAdminController.cs:137-141` — `UPDATE tenants SET status='active'`).

| 계정 상태 | bootstrap 결과 | 터널 |
|---|---|---|
| `pending` (미승인/반려) | **401 거부** | ❌ 발급 안 됨 |
| `active` (승인 완료) | 200 + 토큰 | ✅ 발급 |

> 🔴 **`test1`·`test2` 가 `active` 인지 확인이 필요하다(§6-1).**
> `pending` 이면 1033 은 **정상 동작**이다 — 승인 안 된 계정에 터널을 주지 않는 것이 옳다.
> 그렇다면 문제는 터널이 아니라 **"승인 안 된 시리얼로 설치가 진행되고 완료된 것"** 이다.

### 3-4. ⭐⭐ 실패 은폐 — **2차 급소이자 진짜 결함**

`InstallerBootstrapController.cs:102-145` 3중 `try/catch` 구조:

| 단계 | 실패 시 | 결과 |
|---|---|---|
| `IssueTunnelAsync` (터널 발급) | `catch` → `LogWarning` | **부트스트랩 성공 응답** |
| `UpdateDnsTunnelTargetAsync` (DNS PATCH) | `catch` → `LogWarning` | 동일 |
| `UpdateTunnelIngressAsync` (ingress PUT) | `catch` → `LogWarning` | 동일 |

**코드 주석에 1033 재발 이력이 이미 3건 적혀 있다:**

- `:117` — *"봉합 2026-06-16 (사고: test000 1033 재발): 기존 DNS record 가 잘못된 터널 가리키는 사고"*
- `:130` — *"봉합 2026-06-17 (v1.2.12 P0-B): 본 PUT 이 없으면 cloudflared 가 트래픽 어디로 보낼지 모름 → **1033 100% 재발**"*
- `:126`·`:139` — 각 실패에 *"(1033 사고 가능성/재발 가능성)"* 명시

> 🔴 **세 곳 모두 실패해도 `tunnelTokenIssued=false` 로 200 을 반환한다.**
> 주석 *"실패해도 DNS만으로 동작 가능 — 부트스트랩은 성공으로 처리"*(:109) 가 그 근거인데,
> **DNS 만으로는 동작하지 않는다.** cloudflared 연결이 없으면 1033 이다.
> 이 낙관적 처리가 **"설치는 성공했는데 접속은 안 되는"** 상태를 만든다 — 헌법 #15 침묵 금지 위반.

### 3-5. Cloudflare 미구성 시 — 조용히 건너뜀

`:102` `if (_cfDomain.IsConfigured)` — 필요 환경변수(`CloudflareDomainService.cs:54-56`):

```
CLOUDFLARE_API_TOKEN · CLOUDFLARE_ZONE_ID · CLOUDFLARE_ACCOUNT_ID
```

**하나라도 없으면 `IsConfigured=false` → 블록 전체 건너뜀 → 터널·DNS 발급 0 → 그래도 200.**
로그조차 남지 않는다(else 절 없음).

> ⚠️ 메모리 기록: *"환경변수 판정은 NCP를 봐라 — 백오피스 실행/환경변수 전부 NCP"*.
> 이 PC 소스로는 판정 불가. **§6-1 에서 사장님 SSH 확인 필요.**

## 4. 진단 결론 — 원인 후보 3개 (실측으로 갈린다)

| # | 가설 | 확인 방법 | 해당 시 성격 |
|---|---|---|---|
| **A** | `test1`·`test2` 가 `pending`(미승인) | NCP DB `tenants.status` 조회 | **정상 동작** — 문제는 "미승인인데 설치가 완료된 것" |
| **B** | `IsConfigured=false` (환경변수 누락) | NCP 환경변수 조회 | **P0** — 터널 발급 자체가 안 돎 |
| **C** | 발급은 됐으나 ingress·DNS PATCH 실패 | NCP 백오피스 로그 `grep 1033` | **P0** — 6/16·6/17 봉합 재발 |

**A·B·C 모두 "설치 EXE 는 성공으로 끝난다"는 공통 결말**을 가진다. 그것이 이 사고의 본질이다.

## 7. 봉합 방향 (원인 확정 후 작지서화 — 지금은 착수 금지)

| # | 봉합 | 근거 |
|---|---|---|
| **N-1** | **터널 미발급 시 부트스트랩을 실패로 반환** — `tunnelTokenIssued=false` 면 설치 중단 | 헌법 #15·#20. 지금은 침묵 성공 |
| **N-2** | `IsConfigured=false` 를 **명시 로그 + 실패**로 | 조용한 건너뜀 차단 |
| **N-3** | 설치 EXE 가 `tunnelTokenIssued` 를 검사해 **안내 후 중단** | 헌법 #24 가르침 의무 |
| **N-4** | 설치 후 **자체 헬스체크**(`https://{도메인}` 200 확인)까지 마쳐야 "설치 완료" | 헌법 #27·#34 |

> **N-1~N-4 는 전부 "실패를 숨기지 말라"는 한 가지 원칙이다.**
> 오늘 랜딩 404 도 같은 계열이었다 — `success` 인데 파일이 없었다.

## 8. CS 이관 사항 (사장님 지시 — *"통신이슈는 CS영역에 넘긴다"*)

CS팀장 강지원에게 이관한다. **고객이 실제로 겪는 증상 기준**으로 작성할 것(개발용어 금지, 헌법 #23·#24).

| 고객이 보는 것 | CS 안내 방향 |
|---|---|
| 설치는 됐는데 주소 열면 "Error 1033" | "설치 마무리가 덜 됐습니다" — 개발용어(터널·토큰·DNS) 노출 금지 |
| 언제 발생 | 승인 전 시리얼로 설치 / 본사 설정 누락 시 |
| 고객 자력 조치 | **없음.** 본사 확인 필요 — 억지 안내로 고객 시간 낭비 금지 |
| 문의 시 받을 정보 | 시리얼 키, 회사명, 설치 시각. `{tmp}\bootstrap-error.txt` 존재 시 첨부 요청 |
| 절대 하지 말 것 | "재설치해보세요" 선반사 — **덮어 재설치는 존재하지 않는 경로**(사장님 못박음 2026-07-15) |

> CS 지식은 **히트판 만든 사람이 직접 정의**한다(외부 긁어오기 금지 — 사장님 헌법).
> 이 문서 §1·§4 를 근거로 CS팀장이 지식베이스 항목을 작성한다.
