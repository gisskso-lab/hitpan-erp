## 0. 이 검증이 존재하는 이유

PM 이 절차를 어겨 **설계문서 없이 먼저 코딩**하고 사후에 설계서를 썼다.
그 결과 아무도 반증하지 않은 코드가 배포 직전까지 갔다.

사장님 지시로 **독립 검증자**가 반증에 들어갔고, **P0 3건을 잡았다.**

> 검증 원칙: *"됐다"를 확인하는 게 아니라 **"안 되는 경우를 찾는다."***
> 검증 방법: **cmd 파싱을 추측하지 않고 실측했다.** 아래 P0 는 전부 실측 채증이 있다.

## 1. 🔴 P0-1 — 리다이렉트가 마지막 명령에만 붙는다 (G-2 미달성)

**위치** `HitPan-Universal.iss:1307` (`ExecLogged`) / 호출 `:1858`, `:1983`

`ExecLogged` 의 인자 조립:
```
'/C ' + CmdLine + ' > "' + OutFile + '" 2>&1'
```

`CmdLine` 에 `&` 체인이 들어가면 cmd 는 `A & B & C & (D > file 2>&1)` 로 파싱한다.
**리다이렉트는 마지막 명령 D 에만 적용된다.**

### 실측 채증 (검증팀 + PM 재현)

```
입력: sc delete NoSuchSvcXyz & timeout /t 1 /nobreak > "v1.txt" 2>&1
결과: EXITCODE = 0
파일: "1초 기다리는 중, 끝내려면 <CTRL+C>를 누르십시오 ...0"
```

**파일에 남은 것은 마지막 `timeout` 의 카운트다운뿐.** `sc delete` 의 `1060` 오류 메시지는 한 글자도 없다.

대조군(단독 실행)은 정상 캡처:
```
sc delete NoSuchSvcXyz    exit=1060   출력 2줄 ✅
sc query  NoSuchSvcXyz    exit=1060   출력 2줄 ✅
sc query  Winmgmt         exit=0      출력 8줄 ✅
```

### 실패 시나리오

좀비 서비스가 `sc delete` 로 안 지워지는 상황(STOP_PENDING·핸들 점유·`1072 MARKED_FOR_DELETE`)에서
**그 오류가 로그에 안 남는다.** 다음 `6-2 service install` 이 `1073`(이미 존재)으로 실패하는데
왜 좀비가 남았는지는 여전히 알 수 없다. **오늘과 똑같은 "로그가 침묵한다" 가 6-1 에서 재현된다.**

### 설계서 §6 은 허위 예시였다

설계서가 "원인을 찾아주는 방식"으로 제시한 유일한 증거:
```
[작10 P0-5][6-1-stopdel] > [SC] OpenService 실패 1060: ...
```
**이 줄은 절대 출력되지 않는다.**

## 2. 🔴 P0-2 — 종료코드가 `timeout` 의 것이라 항상 0 (G-1 미달성)

**위치** `:1307-1314` / 호출 `:1858`, `:1983`

`cmd /C "A & B & C & D"` 의 종료코드는 **마지막 명령 D 의 것**이다.

| 명령 | 실제 exit | 로그에 찍히는 문구 | 판정 |
|---|---|---|---|
| `sc query NoSuchSvcXyz` (단독) | 1060 | `❌ 종료코드 1060 (실패)` | ✅ 정확 |
| `sc delete X & timeout /t 1` | **0** | `종료코드 0 (성공)` | ❌ **거짓** |
| `sc stop X & timeout & sc delete X & timeout` | **0** | `종료코드 0 (성공)` | ❌ **거짓** |

### 이것이 P0 인 이유 — 침묵보다 나쁘다

`6-1-stopdel` 은 `sc stop`·`sc delete` 가 **전부 실패해도** `종료코드 0 (성공)` 을 찍는다.
`timeout` 은 항상 0 을 반환하기 때문이다.

> **침묵을 거짓 성공으로 바꿨다.**
> 다음 세션의 PM 이 이 줄을 보고 "6-1 은 성공했다"고 판단하면 **10번째 오답**이 된다.
> 설계서 §1-4 가 지적한 실패 패턴을 코드가 새로 만든 것이다.

## 3. 🔴 P0-3 — 백지 신규설치 전건에 거짓 진단이 찍힌다

**위치** `:1870` / 설계서 §4-6

### 실측 채증

```
sc query Winmgmt      && echo X > "c1.txt" 2>&1  → exit=0     파일: "X" (sc query 출력 없음)
sc query NoSuchSvcXyz && echo X > "c2.txt" 2>&1  → exit=1060  파일: (미생성)
```

세 가지가 겹친다:

| # | 사실 | 영향 |
|---|---|---|
| 1 | `&&` 게이팅은 안 깨졌다 | ✅ 헌법 #1 위반 아님 (A-2 우려 반증) |
| 2 | `sc query` 출력이 유실된다 | ❌ `>nul` 제거의 **유일한 목적이 실효 0** |
| 3 | 좀비 없음(정상)이면 출력 파일이 **아예 안 생긴다** | ❌ 거짓 진단 |

3번의 결과 — `ExecLogged:1333` 이 이렇게 찍는다:
```
[작10 P0-5][6-1-2-recheck] > (출력 파일 미생성 — 명령 자체가 실행되지 않았을 수 있다)
```

**이 메시지는 거짓이다.** 명령은 정상 실행됐고 좀비가 없다는 (좋은) 결과였을 뿐이다.
그리고 **백지 신규설치에서는 항상 이 줄이 찍힌다**(좀비가 없으니까).
다음 PM 이 이 줄을 보고 "cmd 가 실행 안 됐나?" 를 10번째 가설로 세운다.

## 6. 설계서의 허위·과장

| # | 설계서 주장 | 판정 |
|---|---|---|
| §4-2 | "이 파일의 **기존 검증된 패턴**(395·519행)" | ⚠️ **부정확.** 395·519 는 PowerShell 이 `WriteAllText` 로 쓴 파일을 읽는다. **cmd 셸 리다이렉트는 이 파일에 선례 0건인 신규 도입.** 이 오칭으로 C-2 위험을 낮게 잡은 것이 P0-1·P0-2 를 놓친 직접 원인 |
| §4-6 | "뒤쪽이 이기며 **cmd 파싱이 흔들린다**" | ❌ **틀린 진단.** 실측상 `>nul` 과 `>file` 은 다른 명령에 붙어 충돌 자체가 없었다. 근거 없는 추측을 근거로 코드를 바꿨다 |
| §6 | 예시 로그 | ❌ **허위.** 재현 불가 (P0-1) |
| §5 | 위험 R-1~R-7 | ❌ **cmd 파싱 위험이 한 줄도 없다.** 설계 핵심 기법이 cmd 리다이렉트인데 그 고유 위험 3건 누락 |
| §7 | 검증기준 V-1~V-6 | ⚠️ **G-1·G-2 를 검증하는 항목이 없다.** V-5 는 "줄 존재"만 봐서 **내용이 거짓인 경우(P0-2)를 통과시킨다** |

**필요했던 검증 기준**: *"`6-1-stopdel` 로그에 `sc delete` 의 출력·실제 종료코드가 남는가"*
— 이게 있었으면 **코드 작성 전에** P0-1·P0-2 가 걸렸다.

## 8. 1차 결론 — 반려

> 이 코드는 목적을 **절반만** 달성하고, 달성하지 못한 절반에서 **새로운 오답 유도 장치**를 만들었다.
