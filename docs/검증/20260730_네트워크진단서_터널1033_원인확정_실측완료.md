## 2. P0-1 — 서비스 등록만 하고 시작 안 함

### 2-1. 원인

`cloudflared service install <token>` 은 **Windows 서비스를 등록만** 한다.
**자동으로 시작하지 않는다.** 설치 스크립트에 `sc start` 또는 시작 호출이 없다.

`installer/HitPan.iss:273-277` 이 같은 패턴을 보인다(`service install` 만 실행).
게시본은 `HitPan-Universal.iss` 이므로 **[3] 이 그 파일의 해당 지점을 확인해 봉합**한다.

### 2-2. 함께 확인해야 할 것 — 시작 타입 (미확인)

```
sc qc cloudflared      ← START_TYPE 확인 필요
```

`AUTO_START` 가 아니면 **PC 를 껐다 켤 때마다 또 멈춘다.**
헌법 #28(Windows Update 후 터널 자동복구 · 고객 손 0번) 위반이 된다.
**[3] 착수 시 이 확인이 선행 조건이다.**

### 2-3. 왜 아무도 몰랐나

- 설치 프로그램이 **"설치 완료"로 정상 종료**한다 — 서비스 시작 여부를 검사하지 않는다
- 백오피스 부트스트랩도 **200 성공** — 토큰까지 다 줬으므로 서버 관점에선 성공
- ⇒ **모든 지표가 초록인데 고객만 접속 불가.** 오늘 랜딩 404(`success` 인데 파일 없음)와 **같은 계열**이다

## 3. P0-2 — API 주소 `api-demo` 하드코딩 🔴

### 3-1. 채증

```
src/HitPan.Web/wwwroot/appsettings.json:2
  "ApiBaseUrl": "https://api-demo.hitpan.kr"

src/HitPan.Web/wwwroot/appsettings.Local.json:2
  "ApiBaseUrl": "https://api-demo.hitpan.kr"

(추가) landing.html:476 · landing-web.html:833 · landing-sns.html:624
  const API_BASE = 'https://api-demo.hitpan.kr';
```

브라우저 콘솔 실측:

```
Access to fetch at 'https://api-demo.hitpan.kr/api/auth/login'
from origin 'https://test2.hitpan.kr'
blocked by CORS policy: No 'Access-Control-Allow-Origin' header
→ net::ERR_FAILED
→ 화면: "서버에 연결할 수 없습니다. API 서버를 확인해주세요."
```

### 3-2. 무엇이 문제인가

**모든 고객사가 `demo` 회사의 API 주소를 호출한다.**
`test2` 고객이 `api-demo` 를 부르니 CORS 차단으로 로그인 자체가 불가능하다.

각 고객은 자기 도메인(`api-test2.hitpan.kr` 또는 동일 출처 `/api`)을 불러야 한다.
`InstallerBootstrapController:96` 이 `apiDomain = $"api-{subdomain}.hitpan.kr"` 를 이미 계산해
**응답으로 주고 있다** — 받아서 쓰지 않는 것이 문제다.

> ⚠️ **격리 관점 검토 필요(보안 매니저 1)**: 현재는 CORS 가 막아 **차단**되고 있다.
> 그러나 만약 `api-demo` 가 CORS 를 열어주면 **다른 회사 API 로 요청이 가는 구조**가 된다.
> CORS 가 사고를 막아준 것이며, 설계상 안전한 것이 아니다. 헌법 #2·#18 관점 심사 대상.

### 3-3. 🚨 헌법 #21 충돌 — 반드시 결재 필요

> **헌법 #21**: `appsettings.json`·`appsettings.Development.json` **삭제·수정 금지** (WASM 부트 필수)

**이 파일은 함부로 못 고친다.** 메모리에도 같은 이유로 커밋 보류된 이력이 있다
(`project_appsettings_backoffice_url_pending`).

⇒ **P0-2 봉합은 사장님 결재 필수.** 후보 3안:

| 안 | 방법 | 헌법 #21 |
|---|---|---|
| **A** | 설치 시 `appsettings.json` 의 `ApiBaseUrl` 을 **자기 도메인으로 치환** | ⚠️ 파일 수정 — 결재 필요 |
| **B** | 런타임에 **현재 접속 도메인 기준**으로 API 주소 유도(`window.location`) | ✅ 파일 무수정. **설계팀 권고** |
| **C** | bootstrap 응답의 `apiDomain` 을 `db.conf` 에 저장 → Web 이 읽음 | ⚠️ 배선 추가 |

**설계팀 권고 = B.** 파일을 안 건드리고, 어느 고객이든 자기 도메인을 부르게 되어
같은 사고가 **구조적으로 재발 불가**하다. 단 API 가 동일 출처로 서빙되는지 확인 선행
(`api/wwwroot` 로 Blazor 를 서빙하는 구조가 이미 있음 — `deploy-update.yml:148` 참조).
