## 2. 🔴 검증이 실제로 잡아낸 것 2건

> "됐다"를 확인한 게 아니라 **"안 되는 경우"** 를 찾았다. 둘 다 게이트가 먼저 잡았다.

### 2-1. 빈 catch — 헌법 #15 감시기가 적발

```
warning HP0015: catch 블록이 비어 있습니다. 최소한 _logger.LogWarning(ex, ...) 한 줄을
추가하세요 (헌법 #15).  ChatService.cs(820,9)
```

실시간 알림 실패를 삼키는 자리에 **주석만 있고 로그가 없었다.**
→ `ILogger` 주입 후 `LogWarning` 추가. 빌드 0/0 복구.

**의미**: 알림이 조용히 죽으면 *"메시지를 보냈는데 상대가 못 받는"* 현상이 원인 없이 반복된다.

### 2-2. 🔴 마이그 시드 누락 — `MigrationLocationGuardTests` 가 적발

```
clean DDL 의 schema_migrations 시드에 빠진 마이그레이션이 있다 —
신규 설치 고객이 이미 반영된 마이그를 다시 돌리게 된다. 빠진 것: DB-101
```

clean DDL 에 **표는 넣었는데 시드에 DB-101 을 등록하지 않았다.**
→ 그대로 뒀으면 **신규 설치 고객이 이미 있는 표를 또 만들려다 실패**한다.

**이것이 [[project_migration_real_path]] 재발 방지 게이트가 일한 자리다.**
8/12 에 같은 계열 사고(마이그가 배포본에 안 실림)가 있었고, 그때 만든 게이트가 오늘 걸렀다.

## 4. 🔴 검증팀이 짚는 잔여 위험

> 합격이지만 **개발 PC 는 아무것도 증명하지 않는다**([[feedback_dev_pc_proves_nothing]]).

| # | 위험 | 지금 상태 | 언제 드러나나 |
|---|---|---|---|
| R1 | **파일 폴더가 백업에 안 들어감** | DDL·코드 주석에 명시했으나 **백업 스크립트 미수정** | 고객이 복구할 때 파일만 사라짐 |
| R2 | **실환경 종단 미실측** | 코드·시험만 통과. 두 계정으로 실제 주고받기 안 해봄 | 고객 PC 에서 |
| R3 | **SignalR 실시간 미실측** | 배관은 검증된 것을 재사용했으나 메신저 경로는 첫 사용 | 두 사람이 동시에 접속할 때 |
| R4 | **부서방 인원 실측 0건** | 부서가 0건이라 부서방을 실제로 못 만들어봄 | 고객이 부서를 만든 뒤 |

**R1 이 가장 급하다.** 나머지는 실측으로 풀리지만, R1 은 **고객이 백업을 믿고 있다가 잃는** 종류다.

⇒ 다음 작업에서 백업 범위에 `chat-files` 폴더를 넣어야 한다.
