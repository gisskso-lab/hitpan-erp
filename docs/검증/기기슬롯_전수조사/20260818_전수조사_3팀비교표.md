## §3. ⚠️ 세 팀이 **갈린** 것 — PM 실측 판정

### 쟁점 1. "관문이 화면을 덮는가?"

| 팀 | 판정 | 근거 |
|---|---|---|
| **개발팀** | 🔴 **안 덮는다** | `MainLayout.razor:52` 에서 `<main>` 과 **형제**. 컴포넌트 317줄에 `@Body`·`RenderFragment` **0회** |
| 검증팀 | (판정 안 함) | 게이트 부재만 지적 |
| 설계팀 | 🟡 우회 가능 | 콘솔 한 줄로 통과 가능 |

**🔴 PM 실측 판정 — 개발팀 표현을 정정한다**

```css
/* hitpan.css:1909 */
.hp-device-gate { position: fixed; inset: 0; z-index: 2000; background: rgba(255,255,255,0.82); }
```

- **형제 배치·`RenderFragment` 0회는 사실** (개발팀 관찰 정확)
- 그러나 CSS 가 **화면 전체를 덮는다** → 눈으로는 막힌다
- **다만 DOM 은 살아 있다** — 뒤에서 API 를 계속 부르고 자료도 그려진다

⇒ **판정: "시각적으로 막히나 구조적으로 안 막힌다."** 개발팀 **취지는 맞고 표현은 정정.**

---

### 쟁점 2. "증상② 의 정체가 무엇인가"

| 팀 | 판정 |
|---|---|
| **개발팀** | 사장님이 보신 "슬롯"은 **요금 슬롯이 아니라 기기 목록의 줄**이다. `pending` 은 계수에서 빠지므로 **요금은 당장 안 새고**, 대기 목록에 줄만 쌓인다 (P0-2) |
| **검증팀** | **QR 경로 미봉합**이 원인 — 장비넘버 조회가 로그인에만 있고 QR 엔 없다 |
| **설계팀** | **localStorage 를 장비넘버로 착각**한 것이 뿌리 — 7/2 에 무너진 그 저장소 |

**🔴 PM 판정: 셋이 모순이 아니라 층위가 다르다. 전부 사실이며 겹친다.**

```
[설계층] 장비넘버(hardware_id) 미구현 → localStorage 로 대체   ← 설계팀
    ↓
[코드층] localStorage 가 비면 지문에만 의존 → 새 행 발생        ← 개발팀
    ↓
[경로층] QR 은 아예 장비넘버를 안 봄                            ← 검증팀
    ↓
[게이트층] 이 전부를 보는 게이트가 0개 (G-1 부재)              ← 설계팀
```

⚠️ **단 개발팀의 "요금은 안 샌다"는 확정이 아니다** — 사장님이 보신 화면이 *기기 목록*인지 *슬롯 카운터*인지 실측이 필요하다(§6).

## §4. 🔵 **한 팀만** 본 것 — 사각지대 (다른 팀은 놓쳤다)

| 발견 | 본 팀 | 왜 다른 팀이 못 봤나 | 등급 |
|---|---|---|---|
| **배포 금지 조건 위반** — 설계 §5-A-2 *"G-1·G-4·G-9 통과 못 하면 배포 안 한다"* 인데 셋 다 부재 | **설계팀만** | 개발팀은 소스만, 검증팀은 **있는 게이트**만 봤다. **없는 게이트**는 문서를 봐야 안다 | 🔴 **최상** |
| **B-4 가 항진명제** — `ceil(devices×1.5) >= devices` 는 0~500 전수 대입 반례 0건 | **검증팀만** | 수식을 **실제로 계산**해야 보인다. 코드를 읽으면 정상으로 보인다 | 🔴 |
| **B-3 이 파일을 보는데 실제 한도는 DB 에 있다** — 그 파일은 미실행 | **검증팀만** | 코드·문서로는 알 수 없다. **배포 상태**를 알아야 한다 | 🔴 |
| **대표계정 전면 우회로 승인제 무력화** | **개발팀만** | 설계팀은 AND→OR 위반으로 봤고, **무력화 범위**는 코드를 따라가야 안다 | 🔴 |
| **기기 인증 실패 시 전면 통과**(`catch` 가 통과시킴) | **개발팀만** | 예외 경로라 문서·게이트에 안 나온다 | P1 |
| **거부되면 무한 폴링** — 사장님 *"거절하면 첫 화면 회귀"* 미구현 | **설계팀만** | 화면 흐름은 오더 문서를 알아야 결함으로 보인다 | P1 |
| **대표 알림 0곳**(§14-4) — 대표는 요청이 온 줄도 모른다 | **설계팀만** | 코드에 "없는 것"이라 grep 으로 안 잡힌다 | P1 |
| **PI 14건 전부 ⬜미봉합** — 닫힌 것조차 상태 미갱신 | **설계팀만** | 문서 상태 관리는 코드 조사 범위 밖 | P2 |

> 🔴 **교훈: 3팀 병렬이 아니었으면 최상급 발견 3건을 전부 놓쳤다.**
> 특히 **"없는 것"(부재)** 은 코드·게이트 조사로는 원리적으로 안 잡힌다 — 문서 대조만이 잡는다.

## §5. 팀별 강점·한계 (다음 조사 설계용)

| 팀 | 🟢 잘 잡는 것 | 🔴 원리적으로 못 잡는 것 |
|---|---|---|
| **개발팀** | 죽은 코드 · 끊긴 배선 · 조용한 예외 · DTO 불일치 | **없어야 할 것이 없는 것**(부재) · 배포 상태 · 문서 약속 |
| **검증팀** | 게이트 진위 · 항진명제 · 초록불 출처 | 게이트가 **아예 없는 자리** · 설계 의도 |
| **설계팀** | 약속 vs 실재 · 부재 · 오더 미반영 · 순환 인용 | 코드 세부 동작 · 런타임 경로 |

**⇒ 세 팀 중 하나라도 빠지면 사각지대가 생긴다. 이번이 그 증명이다.**

## §6. 🔴 세 팀이 **공통으로 확정 못 한 것** — 사장님 실측 필요

| # | 무엇 | 왜 못 정하나 | 필요한 실측 |
|---|---|---|---|
| **1** | **증상② 의 정확한 모습** | 사장님이 보신 "슬롯 추가"가 ①기기 목록 줄인지 ②슬롯 카운터 숫자인지에 따라 **원인이 갈린다** | 설정 → 기기 관리에서 **KPI 숫자**가 늘었는지, **목록 줄**만 늘었는지 |
| **2** | **지문이 두 번 달랐나** | 같은 엣지면 달라질 이유가 없는데 달라졌다면 `screen.availWidth` 등 | 두 창에서 F12 → `hitpanDevice.getFingerprint()` 대조 |
| **3** | **localStorage 가 살아있나** | 저장 실패가 조용히 삼켜진다 | 두 창에서 `localStorage.getItem('hitpan_device_id')` 대조 |

**⇒ 이 세 줄이면 증상② 가 즉시 갈린다. 추측으로 고치면 7번째 재발이다.**
