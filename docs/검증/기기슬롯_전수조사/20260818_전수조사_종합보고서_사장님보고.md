### P0-2. QR 경로에 2차 봉합이 적용되지 않았다 — 증상 ② 미봉합

제가 2차에서 *"증상 ②는 ①의 다른 얼굴이니 R-2a 가 둘 다 닫는다"* 고 보고했다. **틀렸다.**

**실측:**
- QR 중복 판정(`TenantDeviceService.cs:689-691`)은 **지문 하나로만** 한다
- `device_id = @DeviceId` 조회는 파일 전체에 **1곳뿐**(`:215` — 로그인 경로)

```sql
-- QR 경로: 지문으로만 찾는다
SELECT device_id FROM tenant_devices WHERE tenant_id = @TenantId AND fingerprint = @Fp
```

⇒ **폰이 브라우저를 바꿔 QR 을 다시 찍으면 여전히 새 슬롯을 먹는다.** 그리고 이것을 보는 게이트가 **0개**다.

---

### P0-3. 봉합이 "진실원"이라 선언한 자리가 구멍이다

8/18 봉합(미커밋)이 *"이 물음이 관문의 진실원"* 이라 적은 API —

`DeviceController.cs:109-110`
```csharp
if (string.IsNullOrWhiteSpace(deviceId))
    return Ok(new { approved = true, confirmCode = (string?)null });
```

**장비넘버를 안 보내면 무조건 통과**다. 브라우저 콘솔 한 줄로 관문을 열 수 있다.

---

### P0-4. 열쇠가 AND 여야 하는데 OR 다 — 그 세 번째 OR 를 오늘 내가 넣었다

설계 §17-1: **"열쇠는 AND"**

실제(`DeviceAuthMiddleware.cs:109-172`):
```
authKey 맞으면 통과  OR  deviceId 맞으면 통과  OR  대표계정이면 무검사 통과
```

세 번째는 **PR#169(대표 잠김 봉합)에서 내가 넣은 것**이다. 사장님이 자기 화면에서 막힌 것을 풀려고 넣었는데, **설계가 금지한 OR 를 하나 더 늘렸고 어느 문서에도 기록하지 않았다.**

---

### P0-5. `hardware_id` — 4차수째 빈 칸

DDL 에 칸을 만들고, **출하 DDL 주석에 이렇게 적어 고객 DB 에 심었다**:

> `fingerprint`: [옛 기기 호환 전용] … 새 기기는 **`hardware_id` 로 잡는다** (DB-103 격하)

**그런데 ERP 본체에서 읽고 쓰는 코드가 0곳이다.** 설계 §4-5(*"이 한 가지가 새는 슬롯을 막는다"*)도 한 줄도 없다.

⇒ 내가 2차에서 *"장비넘버를 1순위 열쇠로 썼다"* 고 보고했으나, 실제로 쓴 것은 **localStorage 의 `device_id`** 다. **7/2 실측대본이 "origin 격리로 무너진다"고 판정한 바로 그 저장소다.** 재발 뿌리가 그대로 살아 있다.

## §4. 세 팀이 갈린 자리 — PM 실측으로 판정

**쟁점: "관문이 화면을 덮는가?"**

개발팀은 *"`DeviceAuthGate` 가 `<main>` 과 형제이고 자식을 감싸지 않아 업무 화면이 함께 그려진다"* 고 판정했다.

**PM 실측 — 개발팀 판정을 일부 정정한다.**

`MainLayout.razor:52` 에서 형제인 것은 **사실**이고, `RenderFragment` 가 **0회**인 것도 사실이다.
그러나 CSS(`hitpan.css:1909`)가 실제로 덮는다:

```css
.hp-device-gate { position: fixed; inset: 0; z-index: 2000; background: rgba(255,255,255,0.82); }
```

⇒ **화면은 덮인다.** 다만 **DOM 은 살아 있다** — 뒤에서 API 를 계속 부르고, 자료도 그려진다. 눈에만 안 보인다.

> 🔴 **판정: 시각적으로는 막히나 구조적으로는 안 막힌다.** 개발팀 지적의 취지(진짜 차단이 아니다)는 맞고, 표현(안 덮인다)은 정정한다.

## §7. 왜 같은 실수가 6번 반복되나 — 구조적 원인

검증팀 결론(PM 동의):

> **게이트를 "만든 것을 확인하는 도구"로 쓰고 있다.**
> 봉합한 사람이 **같은 머릿속 모형으로** 게이트를 짜서 "고친 것"을 확인한다.
> 텍스트 검사는 싸고 동작 검사는 비싸서, 싼 쪽이 비싼 쪽을 밀어낸다.
> **"초록불이 어디서 오는가"를 묻는 단계가 공정에 없다.**
> ⇒ **사람을 바꿔도 재발한다.**

**증거**: 건강한 게이트(`DeviceSlotSeedGateTests` 6개 중 5개 진짜)는 **격리 DB + 출하 DDL + 실제 코드**를 태운다. 게이트당 **6~9초** 걸린다.
가짜 게이트는 전부 **밀리초** 안에 끝난다. **실행 시간이 곧 깊이였다.**
