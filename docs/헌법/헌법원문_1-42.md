26. **마이그·대량처리 목표-Timeout 분리 (사장님 v3 2026-05-18 재정의)** — 사장님 헌법 (2026-05-14 원안 → 2026-05-16 10분 러프 → **2026-05-18 v3 목표-Timeout 분리**): *"10분은 목표시간이고, 타임아웃이라는 물리적 시간으로 제동을 걸면 방대한 데이터 양을 가진 업체들은 마이그레이션이 아예 불가하다. 그럼 안 된다."* + *"2기가 짜리 데이터라고 치자. 그럼 타임아웃이 있다면 아예 마이그가 안 된다는 거잖아."*

    ### 핵심 분리 (목표 ≠ Timeout)
    - **목표 시간 = 10분 러프 (소형 표준 지향값)** — 정공법 5축+α로 달성, 헌법 #19 정합
    - **Timeout = 물리적 한계 위 (24시간 = 86400초)** — 마이그 가능성 보장 안전망, 차단 도구 아님
    - **Y/n 다이얼로그 = 10분 경과 시 고객 통제권** — *"데이터 양이 많아 작업이 지연되고 있습니다. 계속 진행하시겠습니까?"*

    ### 절대 원칙
    - Timeout을 목표 시간(10분)과 동일시 금지
    - Timeout으로 마이그 가능성을 막는 코드 금지 (2GB·30년 누적 대형 도소매 = 사업 성립 필수)
    - 대형 고객사 마이그 불가 = 사업 실패 = 본 헌법 위반

    ### 목표 시간 달성 5축+α (정공법)
    1. MySqlBulkCopy LOAD DATA LOCAL INFILE
    2. OLEDB 병렬 SELECT (3 MDB 동시)
    3. Stream 처리 (DataTable 폐기, OleDbDataReader → CSV stream)
    4. 인덱스 DISABLE→ENABLE KEYS
    5. 테이블별 병렬 마이그 (헌법 #16 준수)
    - +α 백신 5종 예외 자동 등록 (헌법 #31 정합)
    - +α 청크 단위 Commit (10만건씩)
    - +α 재개 가능 마이그 (실패 청크부터 source_id 멱등)

    ### 전임 PM 닥터스트레인지 오박제 회수 (v2 → v3)
    v2 *"데이터 양과 무관하게 최대 10분 이내"* (5/16 닥터스트레인지 박제) = 사장님 *"10분 러프"* 원안 왜곡. 2GB·30년 누적 고객사 마이그 불가 사고 유발. v3에서 목표-Timeout 분리로 정정.

    ### 적용 코드 영역
    - Command Timeout 1800 → 86400 (`MdbMigrationService.cs` 7곳 일괄)
    - BulkCopyTimeout 1800 → 86400 동일
    - row-by-row INSERT·청크 INSERT IGNORE 코드는 목표 시간 위반 (본 헌법 §"5축+α" 위반). Timeout 늘림이 row-by-row 정당화 아님.

    | **부모계정** | `tenant_admin` | 백오피스에서 등록(가입 시 발급) | **존재** (계정 ID = 라이선스) | ERP 최상위, 자식계정 생성·권한부여 |
    | **자식계정** | `tenant_user` | 부모가 ERP 안에서 직접 생성 | **안 남음** (ERP 로컬 DB에만) | 부모가 부여한 권한만 |

    **ERP가 발급하는 account_type 은 `tenant_admin`·`tenant_user` 둘뿐이다.** 다른 값은 ERP에 존재할 수 없다.

    ### 리셀러·어드민(본사·대리점) 계층은 ERP에 없다 — 왜
    - **`platform_admin`(본사 어드민)·`reseller_admin`(대리점) 은 백오피스에서 나눌 계층**이지 ERP 계층이 아니다. ERP에 들어간 건 **잘못 나눈 것**이다(헌법 #7 SaaS↔ERP 권한 혼용 금지·#35 3시스템 분리 위반).
    - 2026-06-18 보안 격벽 결재: ERP JWT 토큰에 `platform_id`·`reseller_id` **계정 식별자 클레임 미발급**, `account_type` 도 tenant_admin/tenant_user 만 발급. 이유 = *"고객사 PC가 뚫려도 본사·타 고객사 계층 식별자가 노출되지 않게"*(헌법 #22 데이터 최소주의).
    - 본사·대리점 인증·인가·화면·라우트는 **`HitPan.Backoffice` 전담**이며 ERP(`HitPan.API`·`HitPan.Web`)에서 물리 분리 완료.

    ### 잔재 처리 원칙 (계정 계층 잔재 ≠ 덩어리2)
    - ERP 코드에 남은 `platform_admin`/`reseller_admin` **계정 계층 잔재**(권한 정책 OR 절·죽은 분기·고아 DI 등)는 **청소 대상**이다. 격벽으로 토큰에 그 값이 안 실려 도달 불가능한 죽은 분기라, 제거해도 부모/자식 무손상 — 단 제거 시 부모/자식 인증·권한이 안 깨지는지 확인 후 진행.
    - **단, `reseller_id`/`reseller_tier` 수신 캐시 컬럼(덩어리2, 헌법 #37)과 절대 혼동 금지.** reseller_id 는 *계정 계층*이 아니라 *영업 출처 메타데이터*다. 계정 계층 잔재(platform_admin/reseller_admin 권한 분기)는 제거, 영업 메타 수신 캐시(reseller_id/tier 컬럼)는 보존 — **둘은 다른 것이다.**
    - 자식계정을 본사/백오피스로 전송하는 코드 = 헌법 #18·#22 위반 P0(자식계정은 ERP 로컬에만). 전수조사 시 본사 전송 경로 발견되면 즉시 P0.

    ### 전수조사(클로드·사람) 오판 방지
    - "ERP에 platform_admin 분기가 있네 = 본사 계층 살아있음" 오판 금지 → 격벽으로 무력화된 죽은 분기다(청소는 OK, 공포 금지).
    - "reseller_id 가 안 읽히네 = 잔재다 제거하자" 오판 금지 → 덩어리2(헌법 #37) 보존 대상이다.
    - 계정 계층(부모/자식) ↔ 영업 메타(reseller_id) ↔ 본사 계층 잔재(platform_admin 분기) **3개를 구분**해서 판정하라.

41. **문서 무지성 축적 금지 — 폴더 분류 + INDEX + 진실원 표시** — 사장님 헌법 (2026-07-28 신설, 문서 대정리 실행과 동시 제정):

    ### 왜 헌법인가
    정리 안 된 .md 가 한 폴더에 수백 개 쌓이면 클로드(AI)가 **오래된 오답 문서를 최신으로 오판**한다. 이게 두더지잡기(무한반복)의 문서 쪽 원인이다. 문서 정리는 파일 정리가 아니라 **AI 신호 대 잡음비(SNR)를 높이는 인프라**다 — SNR이 오르면 정확도↑·속도↑·토큰↓가 동시에 개선된다.

    ### 폴더 구조 (2026-07-28 확정, docs 하위)
    | 대분류 | 서브 | 용도 |
    |---|---|---|
    | `개발/` | erp·랜딩·백오피스·설치배포·업데이트배포 | 구현·작업지시서·봉합 기록 |
    | `검증/` | erp | 전수조사·검증팀 판정·감사 결과 |
    | `설계/` | erp·랜딩·백오피스·설치배포·업데이트배포 | 설계·PRD·ERD·아키텍처 |
    | `운영기록/` | — | 인수인계서·회의록·보고·결재 이력 (시간순) |
    | `헌법/` | — | 헌법·원칙·조직 정의 |
    | `CS/` | — | AI 챗봇·고객지원 |

    ### 절대 원칙 (위반 = 반려)
    1. **새 문서는 반드시 위 대분류 폴더 안에** 만든다. `docs/` 루트나 옛 `handoff/`에 새로 쌓지 않는다.
    2. **폴더에 문서를 추가·수정하면 그 폴더 `INDEX.md` 한 줄을 같이 갱신**한다. INDEX 없는 폴더 = 미완성.
    3. **계열의 최신 문서는 폴더 INDEX 상단에 🟢진실원으로 명시**하고, 그것이 대체한 옛 문서는 ⬛흡수/🔴폐기로 표시한다. 표시 없는 옛 문서를 최신으로 읽는 사고를 차단.
    4. **`docs/INDEX.md`(MASTER)가 전체 진입점**이다. 세션 시작·문서 탐색 시 여기부터 읽는다.
    5. **문서를 옮기면 참조 링크를 같은 커밋에서 함께 고친다** (링크깨짐 0 게이트). CLAUDE.md·메모리 참조 포함.

    ### 신규 문서 권장 형식 (점진 적용)
    - 파일명: `{YYYYMMDD}_{주제}_{종류}.md` — 파일명만으로 시기·주제 파악
    - 상호참조: `[[문서명]]` (MEMORY.md 와 동일 규약). 끊긴 링크도 허용 = "나중에 쓸 문서" 표시
    - 결정·주장에는 근거 각주(커밋해시·PR번호·검증팀 판정)를 단다 — 헌법 #32(받아쓰기 금지)·SOP(기록주의) 정합
    - 프론트매터(status·category·tags·related·updated)는 **신규 문서부터** 강제, 기존 문서는 핵심 계열부터 점진 적용

    ### 미완 영역 (다음 차수)
    2026-07-28 1차 정리는 handoff 371 + design·erp-handover 80 = **451건 이동 완료**. `work-orders`·`audit`·`migration`·`governance` 등 약 199건은 이미 주제별로 나뉘어 있어 다음 차수로 미룬다. `docs/INDEX.md` 하단 "미정리 폴더" 목록이 그 대상이다.

42. **모든 작업 루틴은 문서로 남기고, 그 문서를 근거로 작업한다 (문서 근거주의)** — 사장님 헌법 (2026-07-28 신설):

    > **"일단 모든 작업루틴은 문서로 남긴다. 그리고 그 문서를 근거로 작업을 한다. 이걸 원칙으로 하자."**

    ### 핵심 정의
    문서는 작업의 **부산물이 아니라 근거**다. **문서 없는 작업 = 근거 없는 작업 = 즉시 중단.**
    기억으로 일하지 않는다. **대화로만 합의한 것은 작업 근거가 되지 못한다** — 반드시 문서로 남긴 뒤 그 문서를 보고 일한다.

    ### 왜 이 헌법인가 (실측 근거 — 전부 문서 없이 일해서 난 사고)
    - **헌법 #37·#38**: AI가 `reseller_id` 를 "잔재"로 반복 오판 → 사장님이 헌법에 못박아야 했음
    - **헌법 #39**: demo 환경 즉석 수술 → "고치려다 더 망가지고 그걸 또 고치는" 두더지잡기
    - **헌법 #33**: 의중 확인 없이 코드 → PricingPage 누락·ResellerSidebar 작동불가
    - **2026-07-28**: PM이 조직 정의가 "없다"고 판단해 인물 이력을 **임의로 지어냄** (근거 문서 미확인)

    | [3] 개발 | **PM(개발팀장)** 지휘·역할분배·코딩 | **개발명세서** | 개발/{영역}/ |
    | [3-V] 병렬검증 | **보안상무 안철수** — [3]과 **동시** | **병렬이슈** (1건 1파일) | **검증/병렬이슈/** |

    ### [7] 일일작업보고서 ↔ [★] 인수인계서 — 언제 참조하느냐로 갈린다 (사장님 정의 2026-07-28)
    | 문서 | 언제 참조 | 내용 |
    |---|---|---|
    | **[★] 인수인계서** | **세션이 끝나 새 창을 열 때** (같은 날, 이어서) | 지금 상태·함정·다음 첫 행동 |
    | **[7] 일일작업보고서** | **다음날 컴퓨터 켜고 새 창 열 때** | 어제 이슈·작업·수정·결재 대기 |

    - 인수인계서 = **세션 단위** 이어받기 / 일일작업보고서 = **날짜 단위** 이어받기.

    - **일일작업보고서는 그날 인수인계서들을 참조(주소)로 묶는다.** 내용을 옮겨 적지 않는다(참조식).

    ### 🔴 [6] 결재+검증 완료 = 무조건 커밋 (사장님 확정 2026-07-28)
    > **"최종 내가 결재하고, 작업·검증 완료된 건에 대해선 무조건 커밋!!!!"**
    - **[5] 사장님 결재 ✅ + [4] 검증 통과 ✅ → 예외 없이 커밋.** 미커밋으로 남기지 않는다.
    - 검증 미통과·결재 전이면 커밋하지 않는다 → [3]·[4]로 되돌린다.
    - **왜**: 결재·검증까지 끝난 작업이 워킹트리에 남으면 다음 세션이 그 상태를 모른다.
      *"어제 됐는데?"* 사고의 원인이고, 세션이 겹치면 유실된다.
    - 커밋 메시지는 **참조식** — 작업지시서·개발명세서·작업리뷰서·병렬이슈 **주소와 결재 이력**만 적는다.
    - **세션 종료 시 `git status --porcelain --untracked-files=no` 는 0이어야 한다.**

    **해당 문서가 없으면 그 단계는 하지 않은 것이다.**
    - **작성자 ≠ 결재자**: 설계팀장이 쓰고 PM 이 결재한다(SoD).
    - **[2] PM 결재 없이 코딩 금지.**
    - **[3-V] 는 작업이 끝난 뒤가 아니라 도는 중에** 실시한다. 이슈는 최종 리뷰서에 묻히지 않게 별도 폴더로 관리.
    - **최종 결재는 임원(CTO→사장님)** 이 한다. 팀 내부에서 종결하지 않는다.

    ### 모든 문서는 보관·관리한다 (사장님 지시 2026-07-28)
    - **문서를 지우지 않는다.** 대체·폐기된 것도 상태만 바꿔 남긴다(🟢진실원 / 🟡진행중 / ⬛흡수됨 / 🔴폐기).
    - 지우면 "왜 그렇게 결정했나"를 추적할 수 없고, 같은 사고가 반복돼도 모른다.
    - 새 문서가 옛 문서를 대체하면 **같은 작업에서** 옛 문서에 ⬛흡수 표시 + 현재 진실원 주소 + "언제 이걸 열어야 하나" 안내를 단다.
    - **INDEX 에 없는 문서 = 관리되지 않는 문서.** 만들면 반드시 폴더 INDEX 에 등재한다.
    - **모든 문서는 참조식으로 쓴다** — 다른 문서 내용을 옮겨 적지 않고 주소만 가리킨다.
