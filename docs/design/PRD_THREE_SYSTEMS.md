# 히트판 PRD — 3개 시스템 제품 요구사항 정의서

> 작성일: 2026-05-06 | 상태: 확정

---

## 1. 제품 개요

히트판은 3개 시스템으로 구성된 SaaS ERP입니다.

| 시스템 | 대상 | 핵심 목적 |
|--------|------|----------|
| 랜딩페이지 | 잠재 고객 | 가입·결제·설치 |
| 백오피스 | 본사 운영팀·대리점 | 고객·대리점 관리 |
| 히트판 ERP | 고객사 직원 | 업무 처리 |

---

## 2. 랜딩페이지 PRD

### 2-1. 목적
- 잠재 고객이 히트판을 발견하고 가입·결제·설치까지 완료하는 단일 경로

### 2-2. 핵심 기능 요구사항

| 기능 | 설명 | 우선순위 |
|------|------|---------|
| 회원가입 | 이메일·회사명·대표자명 입력 → 테넌트 생성 | P0 |
| 구독결제 | 토스페이먼츠 연동, 3티어 (29k/59k/100k) | P0 |
| 다운로드 | 라이선스 키 + EXE 다운로드 링크 이메일 발송 | P0 |
| 약관 동의 | 이용약관·개인정보·위탁·마케팅 동의 | P0 |
| 요금제 안내 | 기능별 비교표 | P1 |
| 대리점 신청 | 대리점 가입 신청 폼 | P1 |

### 2-3. 가입 흐름

```
[1] 요금제 선택
[2] 회원정보 입력 (이메일·회사명·대표자명·연락처)
[3] 약관 동의 (필수 3개 + 선택 1개)
[4] 결제 (토스페이먼츠)
[5] "설치 준비 중" 화면 (백그라운드 프로비저닝)
[6] 이메일 수신: 라이선스 키 + 다운로드 링크
```

### 2-4. 프로비저닝 (가입 후 자동)

```
백오피스 서버가 자동 처리:
  ① hitpan-{계정명}.kr DNS 생성 (Cloudflare API)
  ② cloudflared 터널 생성 → credentials 발급
  ③ 라이선스 키 생성 (UUID 기반)
  ④ 이메일 발송
소요시간 목표: 2분 이내
```

### 2-5. 비기능 요구사항
- 가입 완료까지 5분 이내
- 모바일 반응형 필수
- 결제 실패 시 자동 재시도 안내

## 3. 백오피스 PRD

### 3-1. 목적
- 본사 운영팀이 고객·대리점을 통합 관리하는 내부 도구

### 3-2. 핵심 기능 요구사항

| 기능 | 데이터 원본 | CRUD |
|------|-----------|------|
| 고객(테넌트) 관리 | 랜딩페이지 Push | 조회·수정·정지 |
| 직원계정 조회 | ERP Pull (5분) | 조회만 |
| 등록기기 조회 | ERP Pull (5분) | 조회만 |
| 구독결제 관리 | 랜딩/ERP Push | 조회·환불·변경 |
| 대리점 영업실적 | 백오피스 직접 | 전체 CRUD |
| 대리점 프로모션 | 백오피스 직접 | 전체 CRUD |
| 대리점 영업이익 | 백오피스 직접 | 전체 CRUD |
| 프로비저닝 현황 | 백오피스 직접 | 조회·재시도 |

### 3-3. 데이터 수집 방식

```
즉시 Push (실시간):
  - 테넌트 가입 (랜딩 → 백오피스)
  - 구독결제 변경 (랜딩/ERP → 백오피스)

Pull (5분 주기, 백오피스 스케줄러):
  - 직원계정: GET {erp}/api/sync/employees
  - 등록기기: GET {erp}/api/sync/devices
  인증: Sync 전용 토큰 (읽기 전용)

백오피스 독자 관리:
  - 대리점 영업이익·실적·프로모션
```

### 3-4. Pull 장애 대응
- ERP 무응답 시: 15분 후 재시도
- 3회 연속 실패: 운영팀 알림
- 마지막 성공 Pull 시각 화면 표시

### 3-5. 계정 체계

| 계정 유형 | 접근 범위 |
|----------|----------|
| platform_admin | 전체 |
| reseller_admin | 담당 고객사만 |

### 3-6. 비기능 요구사항
- 내부 도구. 외부 공개 불필요
- 본사 IP 화이트리스트 접근 제한 권장
- 헌법 #18 준수: 고객사 업무 데이터 절대 수집 금지

## 4. 히트판 ERP PRD

### 4-1. 목적
- 고객사 직원이 매입·판매·재고·재무 업무를 처리하는 독립 운영 시스템

### 4-2. 설치 흐름 (원클릭)

```
[1] 이메일에서 EXE 다운로드
[2] 더블클릭 → 라이선스 키 입력 (유일한 입력)
[3] 인스톨러 자동 처리:
    - 환경 체크 (MariaDB·닷넷·포트 충돌 자동 해결)
    - 본사 API에서 credentials + 도메인 수신
    - MariaDB 설치 또는 재사용
    - 닷넷 런타임 설치
    - 히트판 API 배포
    - cloudflared Windows 서비스 등록
    - appsettings.json 자동 기입
    - 바탕화면 바로가기 생성
    - 엣지·크롬 즐겨찾기 자동 추가
[4] 완료 → https://hitpan-{계정명}.kr 자동 오픈
목표: 설치 완료까지 10분 이내
```

### 4-3. 첫 로그인 약관 동의

```
로그인 완료 → 미동의 확인 → 약관 동의 페이지 강제 이동

필수 동의 (미동의 시 진입 불가):
  ① 서비스 이용약관
  ② 개인정보 처리방침
  ③ 개인정보 처리 위탁
  ④ 만 14세 이상 확인

선택 동의:
  ⑤ 마케팅 정보 수신

저장: 동의 일시·IP·약관 버전 DB 기록
적용: 모든 사용자 (대표·직원 구분 없음)
```

### 4-4. 핵심 업무 기능

| 단계 | 기능 |
|------|------|
| 1. 설정 | 일반정보·직원관리·권한·기기관리 |
| 2. 마스터 | 거래처·상품·BOM·특별단가 |
| 3. 매입 | 발주·매입·반품·재고반영 |
| 4. 판매 | 견적·수주·거래명세서·세금계산서 |
| 5. 현황 | 재고·매입·판매·계산서 현황 |
| 6. 재무 | 회계·경비·경리 |

### 4-5. 백오피스 연동 (ERP 관점)

| 항목 | 방향 | 내용 |
|------|------|------|
| 직원계정 | ERP → 백오피스 Pull | 이름·이메일·직급·재직여부만 |
| 등록기기 | ERP → 백오피스 Pull | 기기ID·기기명·등록일만 |
| 구독결제 | ERP → 백오피스 Push | 결제 변경 시 즉시 |
| 업무 데이터 | 전송 없음 | 절대 본사로 안 나감 |

### 4-6. 독립 운영 원칙
- 인터넷 끊겨도 ERP 정상 운영
- 백오피스 서버 장애와 ERP 운영 완전 분리
- 라이선스 체크: 월 1회 본사 API 호출만

### 4-7. 비기능 요구사항
- 처음 쓰는 직원이 설명서 없이 3분 안에 사용 가능
- 스크롤 없이 한 화면에서 핵심 정보 표시
- 모바일 사파리·크롬 지원

## 5. 시스템 간 경계 원칙

```
✅ 허용:
  랜딩 → 백오피스: 테넌트·결제 정보
  백오피스 → ERP: Pull (직원·기기 복사본)
  ERP → 백오피스: 결제 변경 즉시 Push

❌ 절대 금지:
  ERP → 백오피스: 업무 데이터 (매출·매입·원장·재고 등)
  백오피스 → ERP: 업무 데이터 쓰기
  인스톨러 EXE 내부에 Cloudflare API 토큰 포함
```
