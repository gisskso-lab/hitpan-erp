# 출하 DDL ↔ 코드 스키마 동기화 검증 — 실측 import 스모크 CI 설계

> 작성: 2026-06-23 (6차 전수조사 후속, 사장님 결재 "실측 import 스모크 CI로")
> 관련 결함: AICHAT-P0-01(BYOK 컬럼 clean DDL 누락 → 신규설치 DOA)

## 1. 배경 — 5차 "마이그 파이프라인 P0" 오진 정정

5차 전수조사가 제기한 "build-installer 가 migrations 미번들 + install.bat 미적용 = P0 구조결함"은
**오진**이다. 설계팀장+DB매니저 6차 재진단 결과:

- **신규설치 진실원 = `installer/hitpan_db_clean.sql` 단일**(121 테이블, 빈 스키마 + 트리거 + common_codes 시드).
- `HitPan-Universal.iss` 가 이 단일 DDL 을 import 하고, **121 테이블 + users 실존 게이트**로 무결성을 강제한다.
- `src/HitPan.API/Migrations/SQL/DB-*.sql`(DB-02~DB-81)은 **기존 DB 진화 이력**일 뿐 신규설치 진실원이 아니다.
- `installer/migrations/` 폴더는 사실상 죽은 폴더(BYOK 1건만, 어디서도 미참조).
- **install.bat/.iss 에 migrations 적용 루프를 다는 것은 오히려 위험**(멱등성·순서·운영데이터 보호 게이트 충돌) → 채택 금지.

## 2. 진짜 결함 — clean DDL ↔ 코드 컬럼 동기화 보장 장치 부재

개발자가 새 테이블/컬럼을 코드에 쓰면서 `hitpan_db_clean.sql` 갱신을 잊으면, 신규설치 고객 PC 에서
런타임 500(기능 DOA). AICHAT-P0-01(BYOK 컬럼)이 정확히 이 사고였고, **사후 봉합으로 clean DDL 에
직접 편입 완료**.

### 정규식 정적분석 게이트 시도 → 실패(기록)
C# 코드의 SQL 문자열에서 테이블명을 정규식 추출해 clean DDL 과 대조하는 게이트를 시도했으나,
**오탐 과다**로 신뢰 불가:
- 컬럼명·별칭이 `FROM`/`UPDATE` 뒤 토큰으로 오인(`total_payment`, `current_qty`, `avg_cost` 등)
- MDB 레거시 테이블(`DOCCD`, `DOCF1` 등 — 마이그 소스, ERP 테이블 아님)
- 백오피스 클라우드 전용(`bo_users`, `resellers`, `promotions` 등 — ERP DDL 에 없는 게 정상, 헌법 #35)
- 뷰(`v_partner_balance` 등 — CREATE VIEW 라 CREATE TABLE 정규식에 안 잡힘)

→ allowMissing 에 90개를 박아야 통과 = 게이트 무력화(자기기만). **삭제함.**

## 3. 채택 방향 — 실측 import 스모크 CI (사장님 결재)

정적분석 대신 **실제 import + 기동 + 스모크**가 유일하게 신뢰 가능(AICHAT-P0-01 도 실측으로 잡힘).

### CI 파이프라인 단계
1. **빈 MariaDB 컨테이너 기동** (CI 러너, 신규 고객 PC 의 첫 설치 상태 모사)
2. **`hitpan_db_clean.sql` import** (`.iss` 와 동일하게 `mysql < hitpan_db_clean.sql`)
   - 게이트: 121 테이블 + 3 트리거 생성 성공, common_codes 외 데이터 0건 (SHIP-DDL-01 게이트 재사용)
3. **API 기동** (`ASPNETCORE_ENVIRONMENT=Production`, 그 DB 가리키게)
4. **핵심 경로 스모크 테스트** — 신규 고객이 설치 직후 반드시 쓰는 흐름:
   - 로그인 → 사원/권한 → 상품·거래처 마스터 CRUD
   - 매입 확정 → 재고 반영 / 판매 확정 → 재고 차감 → 세금계산서
   - AI 키 저장·설정조회(BYOK — AICHAT-P0-01 회귀 가드)
   - 연차 신청·승인(결재선 포함)
   - 손익·재고 리포트 조회
   - 각 경로에서 **HTTP 500(Unknown column 등) = 빌드 실패**
5. 실패 시: 어느 컬럼/테이블이 빠졌는지 stderr 로그 → clean DDL 편입 후 재실행

### 효과
- AICHAT-P0-01 류(코드 사용 ↔ DDL 누락) **100% 차단**.
- 정규식 오탐 0(실제 쿼리가 도는 것만 검사).

### 필요 인프라 (별도 구축 과제)
- CI 러너(GitHub Actions 등)에 MariaDB 서비스 컨테이너
- API 통합테스트 스모크 스위트(`HitPan.Tests` 확장)
- 빌드 파이프라인에 단계 추가

## 4. CI 구축 전 1차 방어선 — 개발 규약

CI 가 구축되기 전까지는 규약으로 막는다(헌법 #13 DESCRIBE 의무의 연장):

> **코드가 SELECT/INSERT/UPDATE 하는 새 테이블·컬럼은 반드시 `installer/hitpan_db_clean.sql` 에
> 먼저 편입한다(헌법 #13 DESCRIBE 후). 출하 DDL = 신규설치 단일 진실원. 마이그(DB-*.sql)에만
> 추가하고 clean DDL 갱신을 잊으면 신규설치 DOA(AICHAT-P0-01 사고).**

## 5. 기존 고객 업데이트(ALTER) 경로 — 별건 공백

`project_update_backup_workflow`(업데이트=DB ALTER 마이그레이션)는 **설계 의도이나 구현 미구축**.
기존 고객 PC 가 업데이트 받을 때 DB-*.sql ALTER 를 적용하는 러너(updates.hitpan.kr·워치독 기반)는
아직 없다. 신규설치(.iss)와 분리되는 것은 정상 방향이나, 업데이트 측 ALTER 러너는 향후 설계 필요.
