## 1. 검증 항목

### V1 — 도메인 일원화(canonical 리다이렉트) 실환경 검증
- 대상: `installer/web-server.ps1` canonical 301 로직(2차 봉합).
- 검증: 정식 도메인(PRIMARY_DOMAIN) 설정된 상태에서
  1. loopback(localhost/127.0.0.1) 접속 → **리다이렉트 안 됨**(메인PC 정상).
  2. 엉뚱한 host(IP 직접 등) 접속 → 정식 도메인으로 **1회 301**, 무한 루프 없음.
  3. 이미 정식 도메인 접속 → 리다이렉트 안 됨.
  4. LOCAL 모드(PRIMARY_DOMAIN 빈값/localhost) → canonical 비활성, 아무 것도 안 막음.
- ⚠️ 실환경(터널) 미준비 시: 최소한 web-server.ps1을 로컬에서 띄워 Host 헤더를 바꿔가며(curl -H "Host: ...") 각 분기 동작 확인. 터널 종단은 별도(사장님 "나중" 승인분).
- 완료 기준: 4개 분기 전부 의도대로. 특히 **접속 차단·무한 리다이렉트 0**(최악 사고).

### V2 — 메인PC loopback 면제 실동작 검증
- 대상: `AuthController.cs` isMainPcLoopback 분기(1차 봉합).
- 검증(ERP 전체 기동 필요):
  1. loopback으로 로그인 → tenant_devices에 기기 **등록 안 됨**(슬롯 미소모), 로그인 성공.
  2. 비-loopback(터널/도메인)으로 로그인 → 기기 등록·슬롯 소모 정상.
- 완료 기준: 메인PC는 슬롯 0 소모, 클라이언트만 소모.

### V5 — 전체 회귀 + 검증팀 독립 반증(SoD)
- 대상: 작1 봉합 전체(1·2차).
- 검증:
  1. **같은 기기 반복 로그인 N회 → tenant_devices 1건 유지**(증식 0). (지문 보강 실동작 — 정적 도구 아닌 실제 로그인 경로로)
  2. 슬롯 한도 초과 시 "등록된 기기가 아닙니다" 차단.
  3. 빈 지문 시 500(NOT NULL) 안 남 — 로그인 허용·등록 스킵.
  4. **거짓봉합 반증**: 봉합이 "됐다"는 주장을 검증팀이 코드·실동작으로 반박 시도. 특히 지문 보강이 실제 로그인 payload에 실려 서버 저장까지 가는지(정적 도구는 JS만 봤음 — 실제 API 경로 미확인).
  5. 3관문: 빌드 0/0 + ddl-smoke + 독립 반증.
- 완료 기준: 4개 실동작 PASS + 검증팀 반증에서 거짓봉합·회귀 0.
