## 0. 회의 전제 — 사장님 못박음 (재확인)

1. **챗봇 지식·정답은 히트판 만든 사람이 직접 정의.** 외부 긁기·추측·환각 금지. ([[project_chatbot_knowledge_source]])

3. **CS 자동화는 '기술 도입'이 아니라 '현장 정책 정의'** — 챗봇이 할 일 ↔ 사람이 할 일 경계를 먼저 긋는다.

## 2. CS 자동화 그림 — 사장님 흐름 설계 확정본

```
① 고객사 직원: 챗봇에 "0000가 안돼요" 입력
        ↓
② 챗봇 1차 자동진단 (FN-30) — 오류·작업 로그 + KB 매칭
   · "세금계산서 안 눌려요" → 3대 차단원인(미확정/사업자번호/세율) 자동 체크
   · "재고 안 늘어요"     → 매입 확정 여부 확인
   · "권한 없대요"        → 직무권한 매트릭스 제시
        ↓
③ 챗봇 등급 분기 (FN-31)
   · 사용법·단순오류  → 챗봇이 끝까지 (혼자 해결)
   · 돈·마감·로그인불가·500 → 즉시 본사 인계
        ↓ (인계 시에만)
④ 본사 인계 (FN-32) — 증상·오류유형·진단결과만 (본문·금액·거래처 제외, 헌법 #22)
        ↓
⑤ 본사 아웃바운드 (FN-33) — 백오피스 CS 큐 → 전화/SMS
        ↓
⑥ 원격지원 (FN-34) — 애니서포트, 동의 2분리(데이터전송/화면공유)
```

**핵심 원칙: 채널 병행(FN-35)** — 챗봇을 강제 관문화하지 않는다. 전화도 동시에 열어둔다. (현장 직원이 "챗봇 통과 안 하면 사람 못 만남"이면 헌법 정신 위반)

## 3. 할 일 ↔ 사람 일 경계 (현장 정책 = 이 표가 기획서의 핵심)

### 3.1 AI 챗봇이 혼자 끝내는 영역 (커버율 목표)
| 카테고리 | 예시 | 목표 |
|---|---|---|
| 메뉴 찾기 | "결제예정 어디서 봐요?" | 95%+ |
| 단계별 작성법 | "견적서 어떻게 써요?" | 90%+ |
| 기간 조회 안내 | "지난달 매출 보는 법" | 85%+ |
| 단순 트러블슈팅 | 세금계산서 3대 차단·재고 미증가·권한 | 70~90% |

### 3.2 반드시 사람(본사) — AI 답변 금지/신중
| 영역 | 이유 | 정책 |
|---|---|---|
| 회계·세무 해석 | 오답 = 세무조사 리스크 | KB priority=999 강제 매칭 or 본사 인계, LLM 자유생성 금지 |
| 환불·구독료·계약 | 법적 책임 | 무조건 본사 인계 |
| 법적 해석 | 책임 귀속 | 법무 경유 |
| 보안 이슈 | 공격벡터 노출 | 즉시 본사+보안팀 |
| 데이터 주권 문의 | 다테넌트 기술 판단 | 본사 인계 |

### 3.3 실행은 항상 사람 (헌법 #6)
AI는 초안·근거·"~합니다, 맞습니까?" 확인까지. **확정 버튼은 사람이.** 삭제 금지·역전표 복구(흔적 보존).

## 4. 지식 소스 정책 (환각 차단 = 신뢰의 뿌리)

- **만든 사람의 정답 7대** System Prompt 내장: 재고 3개의 문 / 원장 INSERT ONLY·역전표 / 6단계 워크플로우 / 세금계산서 3대 차단 / 상품등록≠재고 / 퇴사≠삭제.
- **KB 초기 30건** seed 준비됨(메뉴 12·시나리오 8·FAQ). 베타 시작 시 적재.
- **RAG 색인 = 자체 자산만** (컨트롤러/서비스/화면/매뉴얼/설계). 외부 인터넷·타 ERP 0건.
- **모르면 "준비 중" + 본사 인계.** 지어내기 금지(System Prompt 명시).
- 지식 수집 방식 = **하브루타**(개발팀·CS팀 토론으로 정답 확정). ([[project_cs_havruta_20260619]])
