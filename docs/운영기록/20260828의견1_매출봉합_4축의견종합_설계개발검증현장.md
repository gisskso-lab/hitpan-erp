## 0. 왜 4축으로 나눠 받았나

같은 조사 결과를 놓고 **네 자리가 서로 다른 것을 본다.**
한 축만 들으면 그 축이 안 보는 자리가 통째로 빠진다.

| 축 | 누가 | 무엇을 보나 |
|---|---|---|
| **설계** | 설계팀장 존 | 구조가 맞나 · 나중에 안 터지나 |
| **개발** | PM(개발팀장) 브라운킴 | 어디를 몇 줄 고치나 · 공수 |
| **검증** | 검증팀장 데이비드 박 | **안 되는 경우**를 찾는다 |
| **현장** | ERP 매니저 · 기술영업팀장 | 실제 경리가 이걸 쓰나 · **팔리나** |

🔴 **현장 논리가 개발팀 의견보다 우선한다** (CLAUDE.md 팀 정의).
실제로 이번에 **현장이 P0 2건을 새로 찾았고**, **부가세 등급을 뒤집었다.**

## 1. 설계 축 — 설계팀장 존

### 판정: **마이너스 전표가 옳다. 단 사슬이 없으면 안 하느니만 못하다**

| 항목 | 의견 |
|---|---|
| 마이너스 vs 반품메뉴 | **마이너스.** 국세청 이세로가 이미 이 방식이고, 원장 INSERT ONLY(#3)와 구조가 맞는다 |
| 사슬 필수성 | 🔴 **근거 없는 마이너스는 장부를 못 읽게 만든다.** 「왜 −100만원인가」에 답이 없으면 세무 대응이 불가 |
| 층 전파 | **수주까지 올려야 한다.** 명세서 층에서만 상계하면 수주 잔량이 안 돌아와 그 위에 또 만들 수 있다 |
| 화면 | **신설 반대.** 새 화면은 곧 새 진입점이고, 진입점이 늘면 가드가 또 한쪽에만 붙는다 (P0-1 이 정확히 그 사고) |

### 🔴 설계축이 짚은 위험 — 「과도기」

상태 한글 전환을 **판매만** 하면 매입·매출이 한동안 다른 어휘를 쓴다.

- 🟢 **감수 가능** — 사장님 지시(*"업무 다른 데로 새지 않게"*)가 동시착수를 금한다
- ⚠️ 단 **문서에 과도기임을 명시**해야 한다. 안 그러면 다음 세션이 *"매입이 안 바뀌었다"* 를 결함으로 잡는다

### 설계축 권고

> **잔량을 「가드」가 아니라 「화면이 채우는 값」으로 두라.**

가드는 넘으려는 시도를 막지만, 화면이 잔량만큼만 채우면 **넘을 경로 자체가 없다.**
막는 것보다 **없애는 것**이 구조적으로 강하다.

## 3. 검증 축 — 검증팀장 데이비드 박

### 판정: 🔴 **봉합보다 검증체계가 먼저다**

> **"오늘 P0 4건이 1100개 시험을 뚫고 나왔다.
> 봉합만 하고 끝내면 다음 P0 도 똑같이 뚫는다."**

### 3-1. 무엇이 무너져 있었나

```
build 잡      : dotnet test 1100개 전부      DB 없음
ddl-smoke 잡  : 스모크 1개                    DB 있음
```

**DB 를 띄우는 잡은 시험을 안 돌리고, 시험을 돌리는 잡은 DB 가 없다.**

DB 게이트 **101곳**이 서버 미가용 시 `return` 으로 빠져나온다 — **xUnit 에게 이건 PASS 다.**

⇒ **진짜 게이트 3종마저 한 번도 안 돌았다.**

### 3-2. 무력화 시험 — 진짜 3 / 가짜 8

| 죽인 것 | 1100개 |
|---|---|
| 계산서취소 가드 = P0 완전 복원 | 🔴 전부 통과 |
| 사슬 표기 NULL | 🔴 통과 |
| 국세청 이중전송 차단 제거 | 🔴 통과 |
| 분개 불균형 | 🔴 통과 |

가짜 8종은 전부 **파일을 읽어 문자열이 있는지만 본다.**

### 3-3. 검증축 요구 — SoD

> 🔴 **게이트는 봉합자가 짜지 않는다.**

봉합한 사람이 게이트를 짜면 **자기가 고친 자리만** 검사하게 된다.
P0-1 이 그 증거다 — 가드는 실재했는데 **화면이 지나가는 경로엔 없었다.**

### 3-4. 착수 순서 (이 순서가 검증축의 결론)

```
1. CI 에 DB          ← 이게 없으면 2~5 가 전부 무의미
2. 탐지 먼저          ← 대조군 없이 고치면 "0건" 이 증거가 안 된다
3. 게이트 → 빨간불 확인 ← 초록이면 가짜
4. 봉합
5. 무력화 시험 (봉합자 아닌 사람이)
```

🔴 **3번을 4번 뒤로 미루면 오늘이 반복된다.**

## 4. 현장 축 — ERP 매니저 · 기술영업팀장

### 판정: 🔴 **아무도 안 본 자리에서 P0 2건이 더 나왔다**

현장축은 코드를 *"구조상 맞나"* 로 안 보고 **"실제 경리가 이렇게 일하나"** 로 되물었다.
그 질문에서 **P0-3·P0-4** 가 나왔다.

### 4-1. P0-3 — 명세서 취소가 과거 반품을 증발시킨다

**경리의 질문**: *"4월에 반품 처리한 게 5월에 왜 되살아나요?"*

```
4월   반품 200만원 처리          → 미수 정상 차감
5월   전혀 다른 오타 명세서 1장 취소
        ↓
      🔴 4월 반품이 사라지고 미수가 1,000만원으로 부활
```

- 🔴 **조용하다.** 오류도 경고도 없다
- 🔴 **매입엔 이 코드가 없다** — 또 매출만
- ⚠️ 이건 **코드리뷰로는 안 잡힌다.** SQL 한 줄은 문법상 완벽하다

### 4-2. P0-4 — 업체별 원장이 「돈 원장」이 아니다

**영업의 질문**: *"거래처원장을 데모에서 열면 뭐가 보입니까?"*

| 더존·이카운트의 거래처원장 | 히트판 현재 |
|---|---|
| **미수금 대사 화면** | 🔴 **수량 수불부** |
| 전표별 줄 · 이월잔액 · 부가세 | 없음 |

> 🔴 **"데모에서 거래처원장에 수량이 나오면 제품 카테고리 자체를 의심받는다."**

기능 결함이 아니라 **영업 사고**다.

🟢 다만 **계산이 틀린 게 아니다** — `partner_balance.balance` 는 정확하다.
**화면이 어느 표를 보느냐**의 문제다.

### 4-3. 🔴 현장이 등급을 뒤집었다 — 부가세

PM 이 **P1** 로 분류한 것을 현장이 **P0 1순위**로 올렸다.

> **"급한 건 큰 사고가 아니라 안 들키는 사고다."**

- 부가세 신고서·매입매출장은 **세무사에게 나간다**
- 화면에서 안 보이니 **아무도 모른다**
- 마이너스 계산서를 완성해도 **신고서에 안 비치면 완성이 아니다**

### 4-4. 화면 신설 반대 — 히트판 정신

> *"레거시 히트판이 살아남은 이유는 딱 하나. **쓰기가 겁나 쉬웠기 때문이다.**"*

- 반품 전용 화면을 새로 만들면 **담당자가 배워야 할 화면이 하나 늘어난다**
- **[반품하기] → 이미 아는 거래명세서 화면에 (−)** 가 교육 0

🟢 **이 의견이 결재 5로 그대로 채택됐다.**

| 축 | 로직 | 무엇이 문제인가 |
