## §2 🔴 구조 방식 — **묵은 가지를 머지하지 않는다**

**왜 머지가 아닌가**
- 12건 중 다수가 **`CONFLICTING`·`DIRTY`** — 두 달 반 묵은 가지라 지금 `main` 과 충돌한다
- 다수가 **`Scan secrets`(TruffleHog) 실패** — 묵은 **커밋 이력**이 물릴 가능성
- 머지하면 그 가지의 **다른 변경까지 따라 들어온다**(일부 PR 은 코드 파일도 품었다)

**방식: 내용만 옮긴다**
```
1. 🔴 선행 — 22개 파일을 각 PR 가지에서 읽어 자격증명 모양 검사
          값은 출력하지 않고 건수만 센다. 🔴 걸린 파일은 그대로 못 건진다
2. 현재 main 위에 새 가지 1개 (docs/20261015-recover-branch-only-records)
3. 22개 파일을 그 가지에 둔다 — 파일 내용 그대로, 경로 그대로. 🔴 한 글자도 고치지 않는다
4. 각 파일이 속한 폴더 INDEX 에 한 줄씩 등재 (#41) — PM 이 쓴다
5. PR 1건 → 머지 확인
6. 🔴 그 확인 후에 묵은 PR 12건을 닫는다
```

🔴 **3번에서 내용을 고치면 안 된다.** 그 문서들은 그때의 기록이다. 틀린 줄이 있어도 **고치지 않고 상태만 바꾼다**(불변 규칙). 정정이 필요하면 **별도 줄로 병기**한다.

## §3 🔴 이 사고가 왜 생겼나 — 재발 방지

| 축 | 사실 |
|---|---|
| 모양 | 루틴 산출물을 **작업 가지에서 작성**하고, 그 PR 이 머지되지 않은 채 **열린 상태로 남았다** |
| 왜 안 보였나 | 문서가 **로컬 작업트리에도 없다** ⇒ `ls` 로도 `find` 로도 안 보인다. **PR 가지만 들여다봐야 보인다** |
| 누적 | 7/31 부터 10/11 까지 **12건** — 두 달 반 동안 아무도 몰랐다 |
| 🔴 되풀이 막는 법 | **세션 끝 5줄의 「미커밋 0」이 「미머지 0」을 뜻하지 않는다.** 커밋은 됐고 가지에 있었다. ⇒ 점검 항목에 **「내가 쓴 문서가 `origin/main` 에 있나」** 를 더해야 한다 |

⇒ 🔴 **진실원 §11 「세션 끝 5줄」 개정 제안**: ② *미커밋 0* → ② *미커밋 0 **+ 내가 쓴 문서가 `origin/main` 에 있나 확인***. **사장님 결재 사안**(진실원 개정).
