## §5. 함정 — 다음 세션이 밟을 지뢰
- 🔴 **계산서 봉합은 「빈 DB 에서만」 짝을 가른다**(병렬이슈 15). 이제 덮어쓰기가 생겨 근본은 해소됐지만, **「없는 것만 보태기」로 재이관하면 여전히 흡수된다.** 66,631 은 **지우고 새로 가져온 기준**이다.
- 🔴 **HTTP 로 경로 유무를 가르려 하지 마라** — 인증이 라우팅보다 먼저 서서 **없는 주소도 401** 이다.
- 🔴 **`sed -i` 가 이 저장소 파일의 CRLF 를 LF 로 바꾼다.** git 은 정규화해서 diff 는 멀쩡해 보이지만 작업본은 바뀐다 ⇒ 치환 뒤 `file` 로 줄끝을 보고, 필요하면 `sed -i 's/$/\r/'` 로 되돌려라. **오늘 두 번 겪었다.**
- 🔴 **`perl -0pi -e` 는 0건 치환도 성공으로 끝난다.** 오늘 두 번(백슬래시 경로·여러 줄 패턴) 조용히 아무것도 안 바꿨다 ⇒ **바뀐 자리를 눈으로 보고 다음으로 가라.**
- 🔴 **`iconv` 는 이 PC 에 없다.**
- ⚠️ **테스트 DB 는 부트스트랩을 안 태운다** — 그래서 대표 사원이 없었고, 대사표 ⑩ 이 고객 DB 에서만 +1 이 되는 것을 **여태 못 봤다**. *"테스트에서 안 보인다 ≠ 고객에게 안 보인다"*(DB-100 계통). 새 항목을 만들 때 **e2e 와 실제 설치의 차이**를 먼저 적어라.
- ⚠️ 측정 도구가 `HitPan.API` 를 참조하게 되면서 `Microsoft.Extensions.Logging.Console` 을 10.0.7 로 올렸다(도구 전용).
- 🔴 **CodeQL 초록불은 「다 고쳤다」가 아니다.** PR 검사는 **이번에 바뀐 줄**만 새 경고로 센다 — 같은 모양이 옆에 10곳 남아 있어도 초록이었다(병렬이슈 19). 로그·연결문자열 계통은 **전수 grep 으로 따로** 확인해라.
- 🔴 **무력화 시험이 빨간불이었다고 단언이 옳은 것은 아니다.** FAIL 의 이유가 내가 적은 이유와 다를 수 있다 — 오늘 두 건이 그랬다(G-OW6·G-OW9 는 언제나 참인 단언이었는데 무력화는 빨간불이었다). **왜 FAIL 인지까지** 확인해라.
- ⚠️ **덮어쓰기를 화면에서 눌러 본 적이 없다.** 게이트는 재시드를 단독으로 재고 e2e 는 도구로 잰다 — **사장님 실측이 첫 확인**이다(§4-1 7·8번).
