## §3 🔴 다음 사람이 먼저 알아야 할 것 7가지

1. 🔴 **두 판이다.** 백오피스 = **MySQL 8.0.45** / ERP = **MariaDB**. 운영 DB 종류를 모르고 DDL 을 쓰지 마라.
2. 🔴 **게이트가 한 판에서만 돌면 다른 판 사고는 영원히 안 잡힌다.** 게이트 **개수는 증거가 아니다.**
3. 🔴 **「파일이 서버에 갔다」 ≠ 「적용됐다」.** 적용기는 **스위치가 켜질 때만** 돈다 — 배포만으로는 스키마가 안 들어간다. 10/8 절차서가 이 축을 빠뜨렸고 사장님 손을 한 번 헛되게 썼다.
4. 🔴 **머지 직전 PR 머리 SHA 를 다시 확인하라.** GitHub API 가 **5분간 옛 SHA**(`mergeStateStatus=UNKNOWN`)를 보고했고, 그 상태로 #511 을 머지해 **봉합 한 커밋(`3e9efb74`)이 main 에서 빠졌다.** 10/8 인계서에 적어 둔 행동을 PM 이 안 했다. → #513 으로 복구.
5. 🔴 **여러 절 `ALTER` + 「이미 있다」 관용 = 조용한 누락.** `32`(4절)·`42`(6절)가 그 모양이다. **1060 을 로그에서 1건이라도 보면 칸 17개를 직접 세라.** `44`(3문장)가 올바른 모양이다.
6. 🔴 **전수조사는 「줄 머리」만 세면 틀린다.** `FOREIGN KEY IF NOT EXISTS` 가 이어진 줄에 있어 PM 의 1차 grep 이 놓쳤고, **게이트가 잡았다.**
7. 🔴 **여러 줄 붙여넣기는 서버 창에서 깨진다**(`^[[200~` → `rm: command not found`). 사장님께 드리는 명령은 **한 줄씩**.
