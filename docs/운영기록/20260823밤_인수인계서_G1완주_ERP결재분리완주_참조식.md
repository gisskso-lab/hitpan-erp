## 사장님이 PM 권고를 정정하신 자리 (이 작업의 핵심)

⇒ 반드시 넣어야 할 사람을 못 고르는 화면 — **G1 이 스스로와 충돌**할 뻔했다.

**사장님 확정 = 부모계정, 그리고 권한자만.**

## 🔴 실측이 잡은 버그 — 시험 636개가 다 통과했는데 뚫렸다

1.3.1 에서 **계정 없는 사원**을 결재선에 저장 → `HTTP 200 "저장되었습니다"`.

**원인 — SQL 3값 논리.** 계정이 없으면 `u.is_parent` 가 NULL 이라

```
NOT (NULL = 1 OR NULL IS NOT NULL) → NOT(NULL) → NULL
```

`WHERE` 는 NULL 을 TRUE 로 안 보므로 **그 사람이 결과에 안 담긴다.**
⇒ *"못 막는 사람"* 목록에조차 안 잡혀 저장이 통과했다.
⇒ **제일 확실히 막아야 할 사람(로그인 자체가 안 되는 사람)이 제일 잘 빠져나갔다.**

**봉합**: `COALESCE(u.is_parent, 0)` (#242) · 1.3.2 에서 **400 으로 막히는 것 실측 확인**.

⚠️ **왜 종전 시험이 못 잡았나** — `계정없는_사원은_후보가_아니다` 는 **조회**만 봤다.
**저장**을 안 봤다. 같은 사람인데 **경로가 둘**이었다.
