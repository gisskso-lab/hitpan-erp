## 0. 사장님 질문에 대한 답 — 선택적 교체가 맞다고 볼 근거가 없다

PM 은 앞서 "위험해서 미뤄뒀다"고 **이유만 설명하고 질문에 답하지 않았다.**
사장님 질문은 *"왜 선택적으로 하느냐"* 였고, **답은 "그럴 근거가 없다"** 이다.

### 0-1. 현재 상태 (실측)

업데이트 패키지에는 워치독이 **이미 들어 있다.**
```
hitpan-1.2.53.zip
  ├─ api        → Directory.Move 로 교체 ✅
  ├─ web        → Directory.Move 로 교체 ✅
  └─ watchdog   → watchdog.new 에 뒀다가 성공 시 삭제 ❌
```

| 지점 | 코드 |
|---|---|
| `UpdateOrchestrator.cs:342` | *"watchdog 은 스왑하지 않는다(W4-3 제외). 신버전 워치독을 곁에 두기만 한다."* |
| `:346-350` | `Directory.Move(extractWatchdog, appWatchdogNew)` — `watchdog.new` 로 배치 |
| `:881-882` | *"고리5 전까지는 쓰지 않으므로 성공 시 치운다"* → `TryDeleteDir(watchdog.new)` |

⇒ **다운로드는 다 해놓고, 안 쓰고, 지운다.** 트래픽만 쓰고 결과가 없다.

### 0-2. 이 선택이 만든 모순 (사장님 지적의 핵심)

```
사장님 확정 : 덮어 재설치는 존재하지 않는 경로 (2026-07-15)
코드 실측   : 자동업데이트는 워치독을 교체하지 않는다
─────────────────────────────────────────────────
결론        : 워치독 코드의 버그는 영원히 고쳐지지 않는다
```

**2026-08-06 실제 피해:**
- 오늘 봉합한 **영업시간 즉시적용**(20260806작1) — 워치독 코드 → 고객에게 도달 불가
- 오늘 봉합한 **Guardian 등록순서**(20260804작1) — 워치독 설치 스크립트 → 자동업데이트로 전달 불가
- 두 건 모두 "고쳤는데 갈 방법이 없는" 상태다.

### 0-3. 게다가 이 선택이 **릴리스 자체를 막기 시작했다**

`UpdateOrchestrator.cs:505-506` (마이그 교차검증 게이트)
> *"워치독은 DB 마이그를 적용하지 않습니다(**고리5 미구현**) — 통과 시 신 스키마 부재로 500.
>  이 릴리스는 **수동 경로(재설치)로 적용해야 합니다** — 자동교체를 중단합니다"*

⇒ 워치독 미교체가 **DB 마이그레이션이 포함된 모든 릴리스를 차단**한다.
그리고 그 대안으로 지목한 "재설치"는 **사장님이 폐기한 경로**다. **출구가 없다.**

### 0-4. 판정
선택적 교체는 **보수적 안전 선택이 아니라, 시간이 갈수록 커지는 부채**다.
- 워치독 버그 → 영구 고정
- 마이그 포함 릴리스 → 차단
- 유일한 탈출구(재설치) → 폐기됨

**⇒ 사장님 말씀대로 같이 교체하는 것이 맞다.**

## 1. 왜 여태 못 했나 — 진짜 기술적 난점 (핑계가 아니라 설계 조건)

`UpdateOrchestrator.cs:514`
> *"구버전 워치독(자기교체 W4-3 제외로 정상 상태)이 깨지면 그 PC 는 **영구 고립** = 재설치 외 복구 불가."*

**자기가 자기를 바꾸는 문제:**
```
워치독이 실행 중 → 자기 EXE 파일은 잠겨 있어 교체 불가
워치독이 자기를 멈춤 → 멈춘 뒤엔 교체를 실행할 주체가 없음
교체 중 실패 → 살려줄 사람이 없음 (api·web 은 워치독이 살리지만, 워치독은?)
```

이건 **실재하는 난점**이다. 그래서 미뤄둔 판단 자체는 이해되나, **미뤄둔 채 잊힌 것**이 잘못이다.

## 2. 봉합 설계 — 밖에서 바꾼다

**핵심: 워치독이 자기를 바꾸지 않는다. 밖에 있는 예약작업이 바꾼다.**

### 2-1. 이미 있는 재료
| 재료 | 현재 상태 | 근거 |
|---|---|---|
| 새 워치독 파일 | ✅ `watchdog.new` 로 이미 내려온다 | `:346-350` |
| Guardian (5분 주기 부활) | ⚠️ 코드 있음, **이 PC 미설치** | `InstallWatchdog.ps1`, 20260804작1 |
| 부팅 안전망 예약작업 | ✅ `UpdateProcessGate` 가 이미 쓰는 패턴 | `UpdateProcessGate.cs:75-80` |
| 서비스 자동 재시작 | ✅ `sc failure` 5초/5초/60초 | `InstallWatchdog.ps1` |

### 2-2. 교체 절차 (제안)
```
① 워치독: watchdog.new 검증 (버전·서명·EXE 존재)
② 워치독: 교체 예약작업 등록  ← 반드시 ③보다 먼저(바닥 없으면 안 뛴다)
③ 워치독: 자기 서비스 중지 요청
④ 예약작업: watchdog → watchdog.old, watchdog.new → watchdog
⑤ 예약작업: 서비스 시작 → 헬스 확인
⑥ 실패 시: watchdog.old 복구 → 서비스 시작 (Guardian 이 2층 백업)
```

### 2-3. 불변 규칙
| # | 규칙 | 근거 |
|---|---|---|
| 1 | **예약작업 등록 성공을 확인한 뒤에만** 자기 중지 | 바닥 없이 뛰지 않는다 (`UpdateProcessGate.cs:75-80` 동일 정신) |
| 2 | `watchdog.old` 를 **성공 확인 전까지 지우지 않는다** | 롤백 경로 보존 |
| 3 | **Guardian 이 살아 있어야 한다** — 없으면 자기교체를 시작하지 않는다 | 최후 안전망. 20260804작1 봉합 선행 필요 |
| 4 | api·web 교체와 **분리된 단계**로 수행 | 한쪽 실패가 다른 쪽을 오염시키지 않게 |
| 5 | 실패해도 **구버전 워치독이 살아 있어야** 한다 | 영구 고립 절대 금지(`:514`) |

### 2-4. Guardian 문제 — 사장님 지시로 해소된다

> **사장님 오더 (2026-08-06)**: *"히트판버젼 .54에 워치독 복구한거 같이 넣고,
> 워치독도 히트판 버젼업 할때 새로 설치되도록 해!!"* / *"그럼 되잖아"*

PM 은 "Guardian 이 먼저 실환경에 깔려야 자기교체를 켤 수 있다"며 **선행 조건으로 미루려 했다.**
그러나 사장님 지시대로 **1.2.54 에 둘을 같이 실으면 그 조건이 자연히 해소된다:**

```
1.2.54 패키지
  ├─ 워치독 자기교체 코드   ← 이걸로 워치독이 교체된다
  └─ Guardian 봉합 포함본   ← 교체되는 워치독에 이미 들어 있다
        ↓
  교체 완료 시점부터 Guardian·자기교체가 동시에 살아난다
```

**닭이 먼저냐 달걀이 먼저냐가 아니다** — 한 패키지에 같이 실으면 한 번에 해결된다.

⚠️ 단 **첫 교체(1.2.53 → 1.2.54)만은 구버전 워치독이 수행**한다. 그 시점엔 Guardian 이 아직
없을 수 있으므로, **그 한 번을 위해 롤백 경로(§2-3 규칙 2·5)가 반드시 동작해야 한다.**
첫 교체가 안전하면 이후로는 Guardian 이 항상 뒤를 받친다.

## 3. 검증 계획 (SoD)

| # | 시나리오 | 기대 |
|---|---|---|
| D1 | 정상 자기교체 | 워치독 버전이 새 버전으로 바뀌고 서비스 RUNNING |
| D2 | **교체 중 실패 주입** | `watchdog.old` 복구 + 서비스 RUNNING (**영구 고립 0**) |
| D3 | 예약작업 등록 실패 | **자기중지를 시작조차 안 함** |
| D4 | Guardian 미설치 상태 | 자기교체 **시작 거부** |
| D5 | 마이그 포함 릴리스 | `:505` 차단 게이트 해제 가능 여부 재평가 |

**D2 가 통과하지 못하면 이 작업은 실패다.** 영구 고립은 재설치 외 복구가 없다.
