## 2. 🔴 이번 반려가 말해주는 것 — 또 자리가 옮겨갔다

작7 에서 봉합한 것은 **불러오는 로직**(`FillFromDeliveryAsync`)이었고 **그건 정상 작동한다** — 4번이 통과한 게 증거다.

이번에 끊긴 자리는 **다이얼로그가 고른 행을 돌려주는 자리**다.
같은 기능의 **두 입구 중 한쪽만** 살아 있었다.

> **[[project_fixed_vs_delivered_gap]] 5차 재발.**
> 코드는 이번에도 정상이었다. 끊긴 건 **전달 경로**고, **끊기는 자리만 또 옮겨갔다.**
> 작7 게이트(`ReturnDeliveryLinkGateTests`)는 **채우는 함수**를 검사했다. 그래서 초록불이었다.
> 🔴 **입구가 둘이면 게이트도 둘이어야 한다.**

## 3. 원인 — 코드로 확인한 것

### [2번] 「판매불러오기」가 판매를 못 불러온다 🔴

- 자리: `src/HitPan.Web/Components/Sales/SalesListDialog.razor`
- 행을 고르는 수단이 **`@ondblclick` 하나뿐**이다.
- 체크박스를 켜도 그 선택을 **호출부로 돌려주는 버튼이 없다.**
  하단 버튼은 계산서발행·전자발행·반품·선택삭제·종료뿐.
- 「종료」는 `DialogResult.Cancel()` → 호출부 `if (result.Canceled) return;` → **아무 일도 안 일어난다.**

**4번이 통과한 이유** = 그 경로는 「반품」 버튼이 행을 명시적으로 넘긴다(`CreateReturnAsync`).
**즉 로직이 아니라 입구의 문제다.**

### [5번] 거래처를 한 번 더 골라야 한다 🔴

- 자리: `src/HitPan.Web/Pages/Sales/SalesReturnPage.razor:38`
- `FillFromDeliveryAsync` 는 `PartnerId`·`SalesCompany` 를 **정상적으로 채운다**(519~520줄).
- 그런데 거래처 칸이 `MudAutocomplete` + `Value="_draft.SalesCompany"` **단방향**이다.
- `_partnerCache` 적재와 `PartnerId` 확정이 `OnPartnerChangedAsync` **안에만** 있어,
  사람이 직접 고르기 전엔 화면이 그 상태를 확정하지 못한다.

### [7번] 반품확인현황·반품직원 그리드가 빈다 ⚠️→🟢

- 자리: `src/HitPan.Application/Services/ReportService.cs:1069` (SR_BY_* 4종)
- 현황 SQL 4종 전부 `sr.status = 'confirmed'` 로 거른다.
- 저장은 `SalesService.cs:1963` 에서 **`'draft'`** 로 들어간다.

⇒ **저장만 하고 「반품확정」을 안 누르면 현황에 안 뜨는 것이 설계대로다.**
재고·회계가 confirmed 에만 반응하므로 현황도 같은 잣대여야 한다(헌법 #6, 작3·작6 계승).

🔴 **그러므로 필터를 풀지 않는다.** 풀면 재고·회계와 숫자가 어긋난다.

**진짜 결함은 따로 있다** — 저장 후 *"확정해야 현황에 뜬다"* 는 **안내가 없다.**
사용자는 저장했으니 끝났다고 믿는다. 그게 이번 실측에서 벌어진 일이다.

> [[feedback_workflow_integrity_first]] — 정합성이 이긴다. 단 **흐름은 끊지 않는다**(#20).
> 필터는 그대로 두고, **다음 행동을 알려주는 것**으로 푼다.

## 4. 작업 범위

### W1 — 다이얼로그에 「선택」 경로 신설 (2번)
- `SalesListDialog.razor` 에 **「선택」 버튼** 추가. 체크 1건일 때만 활성.
- `MudDialog.Close(DialogResult.Ok(picked))` 로 호출부에 행을 돌려준다.
- 더블클릭 경로는 **그대로 둔다**(헌법 #1 — 추가만).
- 🔴 `ListType="sales"` 파라미터를 호출부에서 넘긴다 — 지금 `SalesReturnPage` 는 빈 `DialogParameters()` 를 넘겨 `DeliveryPage` 와 다르게 열고 있다.

### W2 — 거래처 자동 확정 (5번)
- `FillFromDeliveryAsync` 안에서 `_partnerCache` 를 **미리 적재**하고
  서버가 준 `detail.PartnerId`·`PartnerName` 으로 화면 상태를 **확정**한다.
- 사람이 한 번 더 고르지 않아도 되게 한다. **자동 선택이 아니라 이미 고른 값의 반영이다** — [[feedback_semi_auto_principle]] 위반 아님.

### W3 — 확정 안내 (7번)
- 저장 성공 직후, **확정 전 상태면** 다음 행동을 알린다:
  *"저장했습니다. 「반품확정」을 눌러야 반품확인현황에 반영됩니다."*
- 🔴 **SQL 필터는 건드리지 않는다.**
- 현황 화면이 0건일 때의 안내문도 확정 조건을 알려주도록 손본다.

### W4 — 게이트
- `SalesListDialog` 가 **행을 돌려주는 경로를 갖고 있는지** 검사.
- 현황 SQL 4종이 **여전히 confirmed 로 거르는지** 고정(회귀 방지 — 나중에 누가 "안 뜬다"고 풀어버릴 자리다).
- 🔴 게이트는 **봉합을 빼면 FAIL 하는지 먼저 확인**한다 — [[feedback_gate_must_test_behavior]] (가짜 누적 9번).
