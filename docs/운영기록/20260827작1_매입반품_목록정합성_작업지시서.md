## 1. 오더를 이렇게 이해했다 (명문화)

- **사장님 의중**: 같은 반품인데 화면마다 건수·금액이 다르게 보인다. 어느 화면을 믿어야 할지 모르는 상태다.
- **안 하면 무슨 일이 나는가**: 반품 건수·금액이 화면마다 달라 담당자가 어느 숫자로 거래처와 정산할지 판단 불가.
  취소한 반품이 살아있는 것처럼 보여 **이미 되돌린 건을 또 처리**할 수 있다.

### 🔴 실측 근거 (헌법 #32 — 추측 금지)

로컬 `hitpan_e2e` 에 4건을 넣고 **세 화면의 실제 SQL 을 그대로** 돌렸다.
(confirmed 2 · canceled 1 · draft 1, 전부 `is_deleted=0`, 동일 30일 창)

| 화면 | 필터 | 건수 | 금액 |
|---|---|---|---|
| 반품**현황**(집계) | `status = 'confirmed'` | **2** | 120,000 |
| 반품**목록** `GetReturnsAsync` | **없음** | **4** | 260,000 |
| 매입목록 「반품」표기 | `status <> 'canceled'` | **3** | 200,000 |

**같은 데이터·같은 기간에 2 / 4 / 3 건.** 이것이 사장님이 보신 불일치다.

### 원인은 2개 (증상은 여러 개로 보였다)

**원인 ①  세 화면의 반품 필터가 제각각**
- `ReportService` RT_BY_* 4종 = `status='confirmed'` ← **8/25 사장님 결재로 이미 바로잡힌 정본**
- `PurchaseService.cs:608` ReturnStatus = `status<>'canceled'` (draft 포함)
- `PurchaseService.GetReturnsAsync` = **필터 없음** (canceled·draft 전부 포함)

**원인 ②  두 목록이 서로 다른 날짜 컬럼으로 30일을 자른다**
- 매입목록 = `pr.receipt_date`(매입일) / 반품목록 = `r.return_date`(반품일)
- 둘 다 기본 `AddDays(-30)`
  (`PurchaseReceiptPage`, `ReturnStatusPage.razor:86`)
- ⇒ **7월 매입을 8월에 반품하면** 반품목록엔 뜨는데 매입 행 자체가 30일 창 밖이라
  「반품」 표기가 **나타날 자리가 없다.** 실측 대조군으로 확인: 창을 6월까지 넓히니
  `매입-003` 이 나타나며 `ReturnStatus=confirmed` 로 정상 표기됐다.
  ⇒ **표기 로직은 처음부터 정상이었다. 행이 화면에 없었을 뿐이다.**
