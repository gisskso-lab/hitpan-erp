## §3. 🔴 무엇이 잘못됐었나 — 다시 안 하려면 이걸 읽어라

### 3-1. 네 겹이 쌓인 경로

```
이관 매칭을 만들며 READ COMMITTED 를 골랐다
 → 그 방식이 일부 서버에서 거절(1665)      → RR 폴백을 만든다
 → RR 은 남은 금액을 잘못 센다              → 재계산 문장(L2·L4·L5)을 만든다
 → 재계산이 표 전체를 훑어 잠금이 넓다      → 인덱스 마이그(DB-124·125)를 만든다
 → 인덱스 마이그가 조용히 실패할라          → 워치독을 고친다   ← 여기서 모듈 경계를 넘었다
```

🔴 **맨 위 선택을 다시 보지 않고 아래로만 쌓았다.** 겹마다 [1-V]·CTO 조건·사장님 결재가 붙어서 **각 걸음은 근거가 있었고**, 그래서 아무도 *"맨 위가 틀린 것 아니냐"* 를 안 물었다.

### 3-2. PM 이 주제를 넘은 지점 4개 (사장님 지적)

| # | 무엇 |
|---|---|
| 1 | **게시를 PM 이 막았다** — 인계서에 「게시 전 필수」라고 써서 **8일을 묶었다.** 게시 여부·시점은 사장님 결정이다 |
| 2 | **선택지를 PM 이 좁혔다** — 세 안 **전부 워치독 전제**. 「워치독을 안 건드리는 길」이 없었다. 고르시게 한 게 아니라 **고르게 만들었다** |
| 3 | **모듈 경계를 PM 이 넘었다** — 배포 모듈 수정은 설계 경계 변경이다. 작업자가 정할 일이 아니다 |
| 4 | **심각도를 PM 이 매겼다** — 재기 전에 「필수·P0」를 붙였다. 오늘 재 보니 **잡아 놓은 값의 1/1000** |

### 3-3. 🔴 앞으로의 규칙 (사장님 앞에서 약속한 것)

- **「필수 · P0 · 게시 전 조건」 등급을 PM 이 붙이지 않는다.** 잰 값과 영향 범위만 올리고 **등급은 사장님이** 매긴다.
- **선택지에 「아무것도 안 하기」와 「원래대로 두기」를 항상 넣는다.** 빠지면 틀을 좁힌 것이다.
- **모듈 경계를 넘는 일은 코드 쓰기 전에 그 사실만 따로 여쭌다** — *"이 작업은 ○○ 모듈을 건드립니다"* 한 줄로.
- **다른 대메뉴·다른 모듈로 넘어갈 것 같으면 그 자리에서 멈추고 보고한다.**

## §5. 오늘 실측으로 확정된 것 (재설계 입력)

- **L5 실제 잠금 보유 창 = 6.7~27.3ms**(15회). 설계가 쓴 **인위 25초의 약 1/1,000**.
- **1205 문턱 = `innodb_lock_wait_timeout` 기본 50,000ms** ⇒ **실측 조건에서 1205 안 난다.** (양성 대조군 55s 로 1205 확인 · 음성 2/2)
- 🔴 **진짜 위험은 1213 교착 — 시간과 무관.** DB-124 없으면 **8회전 8회(100%)**, 있으면 **0/8**.
- 🔴 **DB-124 인덱스 하나가 L5 를 잡는다** ⇒ *"L5 는 처방 없이 닫음"* 이라는 설계 전제와 충돌. ⚠️ **가설**(PC 1대·데이터 1벌·시나리오 1개).
- **고객이 실제로 보는 것**은 재시도 포함해서 봐야 한다 — `MatchTxRetryableErrors={1213,1205,1665}` · **3회** · 백오프 50·150ms+지터.
- 🔴 **위험 서버는 「기존 MariaDB 재사용 설치」 한 경로뿐.** 신규 설치도 사장님 PC 도 안전(`log_bin 0 / MIXED` 실측).
