- 이해: ① 열린 목록을 꼬리표로 다시 누르면 닫혀야 한다 — 어느 줄에서 열든. ② 키보드로도 상태 칸이 열려야 한다(앞 오더 · 지금 판은 탭이 못 감 = D1). 오더에 없는 것 0: Esc · 열린 뒤 항목 고르기 키보드 동작 · ERP 알림 종 = 손대지 않음.
- 안 하면: 아래쪽 줄에서 연 목록을 닫으려 다시 누르면 **목록 항목이 눌린다** → 「(지금)」 이면 무반응(대표 증상) · **다른 항목이면 그 상태로 바뀐다**([1-V] §2 5행 「완료」가 골라짐) = 손이 의도하지 않은 상태 기록. 덮임은 불편이 아니라 잘못 기록 위험이다.

## §4 [ⓐ 덮임 막기 — 목록이 꼬리표를 덮지 않게]
### §4-1 지금 왜 덮이나 (9.3.0 원문)
- 지금 설정 `AnchorOrigin=BottomLeft`(`CsStatusCell.razor:15`) · `TransformOrigin` 기본 `TopLeft`([MudMenu.razor.cs L299-301](https://github.com/MudBlazor/MudBlazor/blob/v9.3.0/src/MudBlazor/Components/Menu/MudMenu.razor.cs#L299-L301)) → 목록 왼쪽 위 = 꼬리표 왼쪽 아래. 겹침 판정 기준 상자 = 메뉴 바깥 `div`(`popoverNode.parentNode.getBoundingClientRect()` · [mudPopover.js L268](https://github.com/MudBlazor/MudBlazor/blob/v9.3.0/src/MudBlazor/TScripts/mudPopover.js#L268)).
- 뒤집기 기본값 = `OverflowBehavior.FlipAlways`([PopoverOptions.cs L80](https://github.com/MudBlazor/MudBlazor/blob/v9.3.0/src/MudBlazor/Services/Popover/PopoverOptions.cs#L80)) · 백오피스는 `AddMudServices()` 만(`Program.cs:40`) → 기본값 그대로.
- 아래 공간이 모자라고 위가 더 넓으면 위로 뒤집는다(`shouldFlipVertical = popoverHeight > spaceBelow && spaceAbove > spaceBelow` · [L355-378](https://github.com/MudBlazor/MudBlazor/blob/v9.3.0/src/MudBlazor/TScripts/mudPopover.js#L355-L378)) → 목록 아래끝 = 꼬리표 위끝. 여기까지는 안 겹친다.
- 🔴 **위로 뒤집어도 위 공간이 목록 높이보다 작으면** 두 군데서 목록 위끝을 화면 위 24px 로 끌어내린다: 화면 밖 막기(`top = overflowPadding` · [L528-534](https://github.com/MudBlazor/MudBlazor/blob/v9.3.0/src/MudBlazor/TScripts/mudPopover.js#L528-L534)) · 목록 높이 자르기(`if (isFlippedUpward) { ... if (shouldClamp) { top = overflowPadding; offsetY = 0; } }` · [L571-577](https://github.com/MudBlazor/MudBlazor/blob/v9.3.0/src/MudBlazor/TScripts/mudPopover.js#L571-L577)). 목록은 꼬리표와 **같은 세로줄**에 있으므로 끌려 내려온 목록이 꼬리표를 덮는다 = [1-V] §2 5행 · 대표 「아래쪽 줄 · 덮었다」 와 같은 모양.
- 🟡 실제 백오피스 화면 높이 · 목록 높이에서 위 공간이 모자랐던 수치는 미측정(창 크기 · 줌 미확인). 이 설계는 수치와 무관하게 **세로 당김이 일어나도 겹치지 않는 자리**로 옮기는 것이라 그 미측정에 기대지 않는다.

### §12-1 왜 지금 Esc 가 안 먹나
- 9.3 은 Esc 를 **목록 쪽 키 가로채기**로만 받는다: 열 때 L592 → L1071~1082(`keyDown: HandleKeyDownAsync`) → L834~836 → `HandleDismissalKeyAsync` L990~997. 목록은 칸과 다른 DOM 자리에 그려져, 마우스로 열고 초점이 칸 안 단추에 남으면 Esc 가 닿지 않는다(1회차 M12 무반응 = 실측).
- 칸 쪽 9.3 키 손잡이는 맨 바깥 div `TrackKeyboardInteraction`(razor L13 · L1129~1146) 하나 — 키보드 표시 + 열린 때 ↑↓ 첫·끝 항목 초점만 · Esc 처리 0.

### §12-2 꼴 (E1 · `CsStatusCell.razor` 한 파일)
- 마크업 ① 바깥 칸 `<div @onclick:stopPropagation="true">` → 옛 줄은 ⬛ 주석으로 남기고(#1 · 이 파일 관례) 새 줄 `<div @onclick:stopPropagation="true" @onkeydown="OnCellKeyDownAsync">` ② `MudMenu` 여는 태그에 `@ref="_menu"` 속성 줄 **하나 끼움**(기존 속성 줄 글자 무변 · 태그 안 주석 금지 → 설명은 태그 위 새 주석 블록).
```csharp
    // @code 끝에 추가 — 기존 매개변수 · PickTitle 무변
    private MudMenu? _menu;   // E1 — 목록 닫기용 참조(20261107작 S4)

    private async Task OnCellKeyDownAsync(KeyboardEventArgs e)
    {
        if (e.Key != "Escape" || _menu is null) return;   // Esc 외 키 = 손대지 않음(엔터·스페이스·화살표·Tab 은 9.3 그대로)
        await _menu.CloseMenuAsync();                     // 닫힌 때 불러도 닫힌 직후 상태와 같다(§12-3 ①④)
    }
```

- 지킬 것: `ToggleMenuAsync` 안 부름 · 엔터·스페이스 분기 0 → F2 같은 두 길 토글 0 · `@onkeydown:preventDefault` · `:stopPropagation` 0(§12-3 ②) · JS · CSS · `ChildContent` · 페이지 · 서버 무변. 🔴 「열려 있을 때만」 거름은 넣지 않는다(§12-3 ④ · D9).

### §13-1 왜 (근본원인 · 분석 §3 실측 확정 · CTO §1 채택)
1. 9.3 은 키보드로 열면 래퍼 초점 왕복(L1020)을 **기다린 뒤** 첫 항목 초점(L1026)을 보낸다 → 「목록 그려짐 ~ 첫 항목 초점」 사이 약 1 왕복 **틈**(방향당 300 에서 그려진 뒤 약 0.5~1.25초). 틈 안 초점 = 아직 단추.
