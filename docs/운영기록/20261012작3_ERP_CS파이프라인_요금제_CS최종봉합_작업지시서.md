## §1 설계 결론 — 끊긴 한 자리만 잇는다

[1-V] 가 재서 확정한 것: **올라가는 쪽은 이미 다 서 있다.** 끊긴 것은 **본사 선발신이 내려오는 길** 하나다.

```
🟢 이미 섬 : 자식계정 → cs_requests+cs_outbox → 워커(30초) → 3중 봉투 → bo_cs_tickets → CS 창구
🟢 이미 섬 : bo_cs_replies → Pull(5분) → cs_replies → ERP 쪽지함
🔴 이을 것 : bo_cs_outbound → Pull 에 실어 내림 → ERP 착지 → 쪽지함에 보임 → ack → delivered_at
```

**그래서 이 작업은 「파이프라인을 새로 깔기」가 아니라 「한 자리를 잇고, 전체가 실제로 도는지 처음으로 재기」다.**

## §2 설계 판단 7건 — 왜 그렇게 하나

| # | 판단 | 왜 (대안을 버린 이유) |
|---|---|---|
| D-1 | 본사 선발신은 **`cs_requests` 에 「본사발신」 행 1줄 + `cs_replies` 1줄**로 앉는다 | ERP 목록(`CsRequestController.cs:178`)과 쪽지함(`CsInboxPage.razor:133`)이 **둘 다 `cs_requests` 기준**이다. 새 표를 만들면 **화면 두 개를 새로 짜야** 하고 흐름이 끊긴다(#20). 기존 자리에 앉히면 **화면 변경 0** 으로 보인다 |
| D-2 | **출처 칸 1개 추가** — `cs_requests.origin varchar(10) NOT NULL DEFAULT 'local'` (`'hq'` = 본사발신). 추가형 마이그 **DB-144** + 출하 DDL 추가 | 칸이 없으면 고객이 **「내가 쓰지 않은 쪽지」를 자기 쪽지와 구별 못 한다**(「처음 보는 사람이 혼자 쓸 수 있냐」 기준). `category='etc'` 같은 기존 값으로 흉내내면 **분류 통계가 오염**된다. `DEFAULT 'local'` 이라 **기존 행은 한 줄도 안 바뀐다**(#1) |
| D-3 | Pull 응답에 **`outbound` 배열을 더한다** — 기존 `{"replies":[…]}` 는 **한 글자도 안 바꾼다** | 계약을 바꾸면 **옛 판 ERP 가 깨진다**(고객 PC 판이 섞여 있다). 더하기만 하면 옛 판은 모르는 칸을 무시한다(`PullResponse` 는 `replies` 만 읽는다 — 실측) |
| D-4 | 🔴 `delivered_at` 은 **ERP 가 저장한 뒤 ack 를 보내는 순간**에 채운다. 입구 = `POST /api/backoffice/cs/outbound/ack` | Pull 이 내려준 순간에 채우면 **ERP 가 저장했는지 모르고** 화면이 「전달됨」이라 말한다 — 작2 가 거부한 **「보냈다」 거짓말의 축소판**이다. 내려보낸 것과 도착한 것은 다른 사실이다 |
| D-5 | 멱등 열쇠 = `bo_cs_outbound.outbound_id` 를 **`cs_requests.cs_request_id` 로 그대로** 쓴다 | 양쪽 다 `varchar(36)`(실측). 같은 쪽지가 두 번 내려와도 `INSERT IGNORE` 로 **1건**. 열쇠를 새로 만들면 양쪽 대조가 불가능해진다 |
| D-6 | 재시도 = **ack 가 안 오면 `delivered_at` 이 안 채워지고 다음 Pull 에 또 내려온다** | 유실 0(#20). D-5 멱등이 중복을 막으므로 **몇 번 내려와도 안전**하다. 별도 재시도 장치를 만들 필요가 없다 |
| D-7 | 에코 차단은 **구조로** — 워커가 `cs_requests` 에 **직접** 넣는다(`cs_outbox` 를 거치지 않는다) | `cs_outbox` INSERT 는 `CsRequestController.cs:141` **한 곳뿐**(실측) ⇒ 워커가 직접 넣으면 **큐에 안 들어가** 본사로 되돌아가는 고리가 **안 생긴다** |

## §3 구현 범위 — 절 A·B·C

### 절 A — 백오피스: 선발신을 Pull 에 실어 내리고 ack 를 받는다

| # | 무엇 | 어디 |
|---|---|---|
| A-1 | `replies/pull` 응답에 `outbound` 배열 추가 — `bo_cs_outbound` 에서 **`delivered_at IS NULL AND canceled_at IS NULL AND purged_at IS NULL`** 만 · `LIMIT 50` · 오래된 것 먼저 | `CsInboundController` |
| A-2 | 내려보내는 칸 = `outboundId`·`purpose`·`title`·`body`·`createdAt` **다섯뿐** (#18·#22 — 본사 내부 식별자·사람 id 는 안 싣는다) | 같음 |
| A-3 | `POST /api/backoffice/cs/outbound/ack` 신설 — 같은 **3중 일치** 문을 쓴다 · 몸통 = `{"outboundIds":[…]}` · 최대 50 | 같음 |
| A-4 | ack 는 `delivered_at` 을 **최초 1회만** 채운다(`WHERE delivered_at IS NULL`) · **자기 테넌트 것만** | 같음 |
| A-5 | 취소·폐기된 것은 **내려보내지 않는다**(A-1 조건) · 이미 내려간 뒤 취소되면 ack 는 받아도 **상태를 안 바꾼다** | 같음 |

### 절 B — ERP: 내려온 선발신을 앉히고 화면에 보인다

| # | 무엇 | 어디 |
|---|---|---|
| B-1 | 마이그 **DB-144** — `cs_requests.origin varchar(10) NOT NULL DEFAULT 'local'` + 출하 DDL(`installer/hitpan_db_clean.sql`) 같은 칸 추가 | 신규 SQL |
| B-2 | 워커 Pull 처리에 `outbound` 갈래 추가 — `cs_requests`(`origin='hq'` · `created_by='headquarters'` · `status='답변도착'`) + `cs_replies` 를 **한 거래로** `INSERT IGNORE` | `CsOutboxSenderWorker` |
| B-3 | 저장 성공분만 모아 **ack 전송**(A-3). 실패하면 보내지 않는다 ⇒ 다음 주기에 다시 내려온다(D-6) | 같음 |
| B-4 | 목록·상세가 `origin` 을 돌려준다 · 화면이 **「본사 안내」** 로 구분해 보인다 | `CsRequestController` · `CsRequestPage`/`CsInboxPage` |
| B-5 | 🔴 본사발신 쪽지는 **고객이 지울 수 없고**, 만족도 평가·재전송 대상도 아니다(질문이 아니다) | 같음 |

### 절 C — 「최종 도는지」 계측 (오더 3의 과녁)

| # | 무엇 |
|---|---|
| C-1 | 게이트 **G-W3-1** — 올라가는 왕복: 쪽지 작성 → 큐 → 워커 → 수신 → `bo_cs_tickets` 1건 (가짜 본사 아님 · **실물 두 컨트롤러를 한 시험에서 맞물린다**) |
| C-2 | 게이트 **G-W3-2** — 내려오는 선발신: 백오피스 선발신 1건 → Pull 에 실림 → ERP 착지(`origin='hq'`) → **쪽지함이 보여준다** → ack → `delivered_at` 채워짐 → 화면이 **「전달됨」** |

| C-5 | CI 등록 — `db-gate` GATES 에 `CsPipelineRoundTripGate` |
