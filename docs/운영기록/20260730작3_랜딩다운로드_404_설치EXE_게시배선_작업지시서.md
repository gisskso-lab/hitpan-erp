### 4-2. 🔴 핵심 제약 — 래퍼가 EXE 를 거부한다

[`installer/deploy/publish-run.sh:47-61`](../../installer/deploy/publish-run.sh#L47-L61) 실독:

```bash
while [[ $# -gt 0 ]]; do
  case "$1" in
    --zip)      ZIP="$2"; shift 2 ;;
    --manifest) MANIFEST="$2"; shift 2 ;;
    *) die "허용되지 않은 인자: $1 (이 래퍼는 --zip/--manifest 만 받습니다. 오버라이드 차단 B-2)." ;;
  esac
done
[[ "$ZIP" == "/tmp/hitpan-"* ]] || die "zip 경로가 허용 접두로 시작하지 않습니다"
```

**이 거부는 결함이 아니라 의도된 보안 장치다.** sudoers 가 이 래퍼 1개만 NOPASSWD 로 허용하고,
래퍼가 인자를 2개로 못박아 `publish-update.sh` 오버라이드(`--webroot` 등) 주입을 막는다.
게다가 sha 3중 대조 + B-4 GitHub 독립 재조회(`main` 조상 확인·run conclusion 확인)까지 한다.

> **⇒ 여기에 `--exe` 를 그냥 추가하면 신뢰경계가 넓어진다.** 사장님 결재 없이 손대지 않는다(헌법 #29).

### 4-3. 설계 선택지 (PM 권고 = 안 ①)

| 안 | 방법 | 장점 | 단점 |
|---|---|---|---|
| **① 권고** | **EXE 를 update zip 과 같은 게시 단위에 포함** — `build-manifest.ps1` 이 zip 을 만들 때 EXE 도 같은 경로에 배치하고, 래퍼가 zip 처리하며 **함께** 게시 | 래퍼 인자 **불변**(신뢰경계 무변경) · 자동업데이트와 **구조적으로 묶임**(사장님 오더 정합) · 버전 갈라짐 원천 차단 | zip 게시 시간 증가 · `publish-update.sh` 내부 수정 필요 |
| ② | 래퍼에 `--exe` 인자 추가 | 단순 | **신뢰경계 확장** — 사장님 결재 필수. B-2 차단 정신 훼손 |
| ③ | EXE 전용 래퍼 신설 | 경계 분리 | sudoers 항목 추가 = 인프라 조작(#29) · 관리 포인트 2배 |

> **PM 권고 이유**: 사장님 오더가 *"설치 EXE 빌드·게시 파이프라인을 **자동업데이트와 묶는다**"* 이다.
> 안 ①이 그 말 그대로다. **한 번 게시 = zip + EXE 동반**이라 다음 릴리스에서 또 빠질 수 없다.
> 안 ②·③은 "두 개를 각각 올린다"라서 **같은 사고(한쪽만 올림)가 재발할 구조**다.

**⛔ 안 선택은 사장님 결재 사항이다.** 결재 전 코드 착수 금지(헌법 #33·#42).
