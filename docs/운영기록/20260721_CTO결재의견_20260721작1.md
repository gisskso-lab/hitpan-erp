## 🔴 BLOCKING C-1 — 수신 경로가 이미 확정되어 있음 (지시서 누락)

### 지적

§6 W-3-1이 수신 엔드포인트를 "신설"로만 기술. 그러나 워치독은 **이미 특정 주소로 송신 중**이다.

```
src/HitPan.Watchdog/appsettings.json:20      https://back.hitpan.kr/watchdog/ping
src/HitPan.Watchdog/appsettings.json:21      https://back.hitpan.kr/watchdog/emergency
src/HitPan.Watchdog/WatchdogOptions.cs:12-13 (동일 기본값 하드코딩)
```

### 위험

1.2.34가 이미 고객 PC에 배포되어 있고, 그 EXE는 **이 주소로만** 보낸다.
백엔드가 다른 경로로 만들면 **전 고객 메타핑이 영구 단절**된다.

7/16 고리4 서명 사고(`openssl DER ≠ 검증기 P1363`)와 동일 유형 —
**송신·수신 계약 불일치**가 전 고객 기능을 조용히 죽인다. 헌법 #20 위반.

### 요구

- 메타핑 경로 **`/watchdog/ping`·`/watchdog/emergency` 고정**, 변경 금지 명시
- 설치 보고는 별도 경로 신설 허용
- 불가피한 변경 시 **구 경로 병행 유지** → 전 고객 버전 소진 후 제거

### 조치 결과
✅ **반영 완료** — 지시서 §6 W-3-1에 경로 고정 + 경고 명시

## 🔴 BLOCKING C-2 — "fail-open" 문구가 보안 완화로 오독 가능

### 지적

§6 W-4-4가 `RateLimitMiddleware`를 "fail-open 전환"으로만 기술. **문구가 위험하다.**

실제 코드 확인:
```csharp
RateLimitMiddleware.cs:33-41  로그인 1000회/5분 초과 → 429 반환 후 return
RateLimitMiddleware.cs:48-54  쓰기 600회/분 초과 → 429 반환 후 return
```

### 위험

**이 429 반환은 정상 동작이지 "실패"가 아니다.**
개발자가 지시서를 문자대로 읽고 "fail-open = 초과해도 통과"로 구현하면
**레이트리밋이 무력화되어 브루트포스가 열린다.**

### 요구

| 구분 | 처리 |
|---|---|
| 레이트리밋 **초과 판정**(429) | 그대로 유지 — 보안 기능 |
| 로직 **자체의 예외**(헤더 파싱 등) | catch 후 `_next()` 통과 |

`HealthIpWhitelistMiddleware`도 동일 — **차단 판정 유지**, 설정 파싱 예외만 격리.
보안 상무(안철수) 사전 검토 대상 지정 (헌법 #23 5중 검증 ②).

### 조치 결과
✅ **반영 완료** — 지시서 §6 W-4-4에 구분 표 + 금지 문구 명시
