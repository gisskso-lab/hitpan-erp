### 1-5. 시리얼 검증 + 5회 잠금

| 영역 | 동작 |
|---|---|
| `POST /api/landing/serial/verify` | 시리얼 + client_fingerprint 입력 → 검증 |
| 5회 실패 시 | 기기 지문별 잠금 (60분 윈도우) |
| 잠금 해제 | 본사 수동 (`POST /api/admin/serial-locks/{id}/unlock`) |
| 회사정보 응답 | 인증 성공 시 tenant 회사정보 + 구독 정보 |
| 이력 | `serial_verify_attempts` (INSERT ONLY, 헌법 #3) |
| 잠금 상태 | `serial_verify_locks` (fingerprint UNIQUE) |

### 1-6. 기기 등록 (네이버·넷플릭스 방식)

| 영역 | 동작 |
|---|---|
| `POST /api/landing/device/register` | "이 PC 등록?" Y → 시리얼 재검증 → device_token 발급 |
| `POST /api/landing/device/check` | 로그인 시 device_token + 지문 3중 검증 |
| device_token 형식 | `dvc_{base64url-256bit}` (예: `dvc_2KRe7rXbCrwbKTli...`) |
| 저장 위치 | 브라우저 localStorage (베타1) → DPAPI 전환 예정 (베타2) |
| DB 저장 | `tenant_devices.device_token_hash` (HMAC-SHA256) |
| PC/모바일 분리 카운트 | ✅ device_type별 한도 비교 |
| 한도 초과 시 | 차단 + 본사 한도 증가 요청 안내 |
| 본사 차단 | `POST /api/admin/devices/{id}/revoke` |

**시험 결과**:
- PC 5대 등록 OK / 6대째 "PC 기기 한도(5대)를 초과" 차단 ✅
- 다른 지문에서 잘못된 토큰 → "등록되지 않은 기기입니다" ✅
