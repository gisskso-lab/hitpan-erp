# 🔴 §7 ERP 매니저 의견 (더존 30년 SI)

## 7-1 판정 — **「세금계산서」로는 못 쓰고, 「거래명세서」로는 쓸 수 있다**

지금 나오는 종이는 **범용 거래문서**다. 그래서 **견적서·거래명세서·발주서로는 현장에서 통한다.**
🔴 **그런데 세금계산서는 다르다.** 세금계산서는 **법정 서식**이고, 모양이 다르면 **거래처 경리가 반송**한다. 세무 대리인도 안 받는다.
⇒ 🔴 **제목만 바꿔 쓰는 구조 자체가 문제다.** 세금계산서는 **범용 틀에서 분기할 수 없고 별도 레이아웃이 필요**하다.

## 7-2 🔴 현장이 실제로 요구하는 것 (우선순위대로)

| | 요구 | 왜 |
|---|---|---|
| **1** | 🔴 **양식용지(preprint) 좌표 정확도** | 중소 제조·유통은 **인쇄소에서 산 양식용지**에 찍는다. 0.5mm 밀리면 칸을 벗어나 **못 쓴다.** 🟢 `field_coords_json` 칸이 **이미 있다** — 그 경로를 살려야 한다 |
| **2** | 🔴 **공급자/공급받는자 2장 분리** | 한 장은 거래처, 한 장은 보관. **절취선이 없으면 두 번 뽑는다** |
| **3** | 🔴 **영수 / 청구** | 수금 담당이 이것으로 일한다. 없으면 전화가 온다 |
| **4** | **업태·종목** | 법정 기재사항. 없으면 반송 사유 |
| **5** | **합계금액 한글 표기**(일금 ○○○원정) | 아직 요구하는 거래처가 있다 |
| 6 | 디자인(색·글꼴) | 🔴 **마지막이다.** 현장은 예쁜 것보다 **칸이 맞는 것**을 본다 |

## 7-3 🔴 ERP 매니저 건의 — **순서를 바꾸자**

| | PM 이 §5 에 적은 건의 | 🔴 ERP 매니저 건의 |
|---|---|---|
| 범위 | 세금계산서 1종 먼저 | 🟢 **같다 — 세금계산서 1종 먼저** |
| 우선 | 「디자인을 QuestPDF 로 그린다」 | 🔴 **「법정 서식 요소를 채우는 것」이 먼저다.** 디자인은 그 다음 |
| 합격선 | 2장 나오나 | 🔴 **「거래처 경리가 받아 주나」** — 서식 7요소(§6-2) 전수 |
| 🔴 선행 | — | 🔴 **법무 대조가 실제로 선행이다.** 기재사항이 빠진 서식을 예쁘게 만들면 **두 번 만든다** |

🟢 **엔진 선택(ⓐ QuestPDF)에는 ERP 매니저도 동의한다** — 이유는 다르다: 🔴 **양식용지 좌표**는 브라우저 인쇄로 못 맞춘다(프린터마다 여백이 다르다). **좌표를 mm 로 직접 찍는 경로가 필요**하고, 그건 QuestPDF 쪽이다.

# 🟢 §9 사장님 질문 — **"이 HTML 디자인으로 PDF 편집해서 넣을 수 있어?"**

> 사장님 2026-10-20: *"**pdf로 그리는 엔진 좋아!!** 기존레거시 히트판하고도 관통해. 하지만 양식이 못쓸정도로 너무 허접해. 그렇다면, **지금 내가 준 html파일에 나온 그 디자인으로 pdf로 편집해서 넣을 수 있어?**"*

## 9-1 🟢 답 — **넣을 수 있습니다**

방식 = HTML 을 **디자인 정본(설계도)**으로 두고, **QuestPDF 로 같은 모양을 그린다.** 자동 변환이 아니라 **사람이 같은 칸을 짜는 것**이고, 주신 HTML 이 **치수까지 적어 둔 설계도**라 그대로 옮길 수 있다.

🟢 **엔진 확정 = QuestPDF**(사장님 결재) · 근거 보강: **레거시 히트판과 같은 방식**(종이 양식에 직접 찍는 축)

## 9-2 🟢 칸 대응표 — 전부 표현된다

| 주신 HTML | QuestPDF |
|---|---|
| `.copy` **136mm** × 2장 + 절취선 7mm | A4 297mm 안에 **136+7+136 = 279mm** ⇒ 여백 포함 **들어간다** |
| `.parties` 공급자/공급받는 자 **2단 격자** | `Row` + `RelativeItem` 2개 + `Border` |
| `.fields` **23mm / 1fr** 라벨-값 격자 | `Table.ColumnsDefinition(ConstantColumn(23mm), RelativeColumn())` |
| `.amounts` 공급가액/세액/수정사유 **3칸(1.4:1:1)** | `Table` 비율 그대로 |
| `.items` **7열**(8/29/12/9/14/14/14%) | `Table` RelativeColumn 비율 그대로 |
| `.summary` 합계 + **현금·수표·어음·외상미수금** | `Row` + 내부 `Table` |
| `.bottom` 비고 / **영수·청구** + 직인 | `Row` 2단 |
| 음영 `#f4f4f4` · 테두리 | `.Background()` · `.Border()` |
| 🟢 글꼴 `"Malgun Gothic"` | 🟢 **이미 같다** — 현 PDF 도 `FontFamily("Malgun Gothic")`(`PdfRenderService.cs:80·576`) ⇒ **글자 모양이 바뀌지 않는다** |

🟢 **QuestPDF 2026.2.4** 사용 중 — 위 요소 전부 지원 범위 안이다.

## 🔴 9-3 똑같이 안 되는 자리 — **미리 밝힌다**

| | 무엇 | 어떻게 되나 |
|---|---|---|
| 1 | **절취선 점선** | QuestPDF 는 CSS `dashed` 테두리를 **직접 지원하지 않는다** ⇒ 가는 실선 + `✂ 절취선` 글자, 또는 짧은 조각 반복으로 흉낸다. **미세하게 다르다** |
| 2 | 🔴 **품목 5줄 고정** | 주신 양식은 **5줄**이다. 실제 거래는 더 많다 ⇒ **5줄을 넘으면 136mm×2 구조가 깨진다.** **페이지 분할 규칙 결재가 필요**(사장님도 「페이지 분할 미연결」이라 하셨다) |
| 3 | 원형 직인(`border-radius:50%`) | 원은 그릴 수 있으나 **수단이 다르다**(글자 둘레 원) |
| 4 | `overflow-wrap:anywhere` 같은 **세밀한 줄바꿈** | QuestPDF 기본 줄바꿈 정책으로 대체 |
| 5 | 🔴 **양식용지(preprint) 모드** | **이 디자인은 「순백지(plain)」용**이다. 양식용지 모드는 **좌표만 찍는 별 경로**(`field_coords_json`)다 ⇒ **두 모드를 같은 디자인으로 덮지 않는다** |

## 🔴 9-4 그래서 결재가 필요한 것 **3건**

| | 무엇 | 선택 |
|---|---|---|
| **ⓐ** | **품목이 5줄을 넘으면** | ① **다음 장으로 이어 찍는다**(공급자용·공급받는자용 각각 여러 장 · 건의) ② 한 장에 줄을 **줄여 담는다**(글자 작아짐) ③ **줄 수 상한**을 두고 넘으면 별지 |
| **ⓑ** | **인쇄 글꼴** | 🟢 **맑은 고딕 유지**(건의 — 윈도우 기본이라 고객 PC 에 **반드시 있다** · 레포에 글꼴 파일 **0건**) · 🔴 자료 서체 정본(**Pretendard**)과 **다른 축**임을 확인해 주십시오 |
| **ⓒ** | **절취선 모양** | 🟢 실선 + `✂ 절취선` 글자로 간다(건의) / 점선을 꼭 원하시면 조각 반복으로 흉낸다(느려짐·미세 어긋남) |

# §10 레거시 양식(이미지) + **"이미지로 만들어 가져오면 간단하겠네"** 에 대한 답

> 사장님 2026-10-20: *"현 레거시히트판 양식을 보니, **이미지파일로 되있어.** 추후 레거시 히트판의 양식도 추가할거야. **이미지파일 pdf로 편집해서 가져오는거 가능하지??**"*
> *"그렇다면 **내가 준 파일을 가져오는 방식도 간단하겠네. 이미지 파일로 만들어서, pdf로 가져오면 되겠네**"*

## 10-1 🟢 레거시 양식(이미지) — **가능하고, 그 길이 정답이다**

| | 실측 |
|---|---|
| 칸 | 🟢 **`form_templates.background_image_url`** 이 **이미 있다** — 주석: *"미리보기용 (**HITWIN JPG 참조**)"* |
| 좌표 | 🟢 **`field_coords_json`** + **구현 실재** — `PdfRenderService.cs:738` `e.Layers()` · `:770` `PlaceText(...)` · 품목 줄은 `row_pitch` 로 **반복 인쇄**(`:749-758`) |
| 기준 층 | 🟢 `:741` `layers.PrimaryLayer().Height(297, Unit.Millimetre)` — **배경이 들어갈 자리가 비어 있다** |
| 🟢 결재 이력 | **「컬러 = 양식용지 · 흑백 = 순백지」** 가 이미 결재돼 있다(`paper_mode`) |

⇒ 🟢 **레거시 양식은 이미지로만 존재하므로 「배경 이미지 + 좌표」가 유일한 길이고, 뼈대가 이미 서 있다.**

## 🔴 10-2 그런데 — **「간단하다」에 반증 3건** (쉽다는 순간이 가장 위험하다)

| | 반증 | 실측 |
|---|---|---|
| 1 | 🔴 **이미지를 PDF 에 깔는 코드가 0건이다** | `.Image(` 호출 **전수 0건**(범위 `src/**/*.cs`, obj 제외) · `Background()` 는 **색만** 칠한다 ⇒ **배경 이미지 기능을 새로 만들어야 한다**(작지만 0 은 아니다) |
| 2 | 🔴 **좌표를 손으로 40~60개 맞춰야 한다** | 머리말 필드는 `field_coords_json` 에 **하나하나 x_mm·y_mm**. 품목 줄만 `row_pitch` 로 반복된다 ⇒ **양식 1종당 수작업** |
| 3 | 🔴🔴 **품목이 조용히 사라진다** | `:734` 주석이 스스로 적었다 — *"몇 줄까지 찍을 수 있나 — **넘치면 종이 밖으로 나가 조용히 사라진다**"* · 코드 `:753` `i < limit` ⇒ **경고 0건** 🔴 **세금계산서에서 품목이 사라지면 세금 사고다** |

## 🔴 10-3 신규 기본 양식(주신 HTML)을 **이미지로 가면 잃는 것**

| | 이미지 배경 방식 | QuestPDF 로 그리는 방식 |
|---|---|---|
| 글자 선명도 | 🔴 **칸 선·라벨("등록번호"·"공급자")이 이미지** ⇒ 확대하면 흐려진다 | 🟢 전부 **벡터 텍스트** |
| PDF 검색·복사 | 🔴 라벨은 **검색 안 된다** | 🟢 된다 |
| 용량 | 🔴 A4 300dpi 2장 = **수 MB** (메일 첨부 시 부담) | 🟢 수십 KB |
| 칸 하나 옮기기 | 🔴 **이미지 재제작 + 좌표 재조정** | 🟢 **숫자 하나** 수정 |
| 품목 줄 넘침 | 🔴 **조용히 사라진다**(§10-2) | 🟢 **다음 장으로 이어 찍기**를 코드로 처리 |
| 작업 속도 | 🟢 **빠르다**(디자인 재제작 0) | 🔴 레이아웃을 짜야 한다 |

🔴 **사장님 말씀이 맞는 자리와 아닌 자리가 갈린다** — 속도는 이미지가 빠르고, **세금계산서의 안전성은 그리는 쪽이 낫다.**

## 🟢 10-4 PM 건의 — **두 경로를 다 쓴다** (이미 그렇게 설계돼 있다)

`paper_mode` 분기가 이미 있으므로 **싸울 필요가 없다.**

| 경로 | 쓰는 곳 | 방식 |
|---|---|---|
| 🟢 **A. 그리는 경로** | **신규 기본 양식**(주신 HTML) · 세금계산서 | QuestPDF 로 그린다 · 줄 넘침은 **다음 장 이어 찍기** |
| 🟢 **B. 이미지+좌표 경로** | **레거시 HITWIN 양식** · 고객이 가진 **양식용지** | 배경 이미지(신설) + `field_coords_json` · 🔴 **줄 넘침 경고를 반드시 붙인다** |

🟢 **B 경로의 가치가 크다** — 레거시에서 넘어오는 고객이 **쓰던 양식 그대로** 쓸 수 있다(히트판이 살아남은 이유 = 쉬움).
🔴 **다만 B 를 신규 기본 양식에까지 쓰면, 가장 중요한 서식에서 가장 약한 방식을 쓰는 것**이 된다.
