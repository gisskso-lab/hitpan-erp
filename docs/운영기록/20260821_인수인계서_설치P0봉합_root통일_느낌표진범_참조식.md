## 2. 진범 — 두 겹이었다

### 2-1. 첫째 겹 — 난수 root (R-1)

`installer/HitPan-Universal.iss`

```
MariaRootPw := GenerateRandomKey(24);     ← 설치마다 난수
...
if NeedsMariaDB then begin                 ← MariaDB 가 이미 있으면 이 블록을 건너뛴다
    msiexec ... PASSWORD="{난수}"          ← 그래서 난수가 실제 DB 에 적용되지 않는다
end;
...
"-u root -p{난수}"  ×12개소                 ← 그런데 이후 전부 그 난수를 쓴다
```

⇒ **MariaDB 가 이미 깔린 PC 에서는 설치가 원천 불가.** `ERROR 1045` → `TBL_COUNT=0`.

🔴 **실물 확증**: 실패한 설치가 남긴 `hitpan-keys.conf` 의 `MARIADB_ROOT_PW` 로 root 접속을 시도 → **실패**. 난수를 **기록만 하고 DB 에는 적용하지 않았다**는 증거.

**이력**: 난수는 `9bc16a09`(2026-06-11) 도입 후 오늘까지 그대로. 8/11 통일은 `hitpan` 계정만이었고 **root 는 명시적으로 제외**돼 있었다(L1821 주석). 아무도 되돌린 게 아니라 **처음부터 반영이 안 됐다.**

### 2-2. 🔴 둘째 겹 — 느낌표 (R-3) · 이게 진짜 오래 걸린 자리

R-1 을 넣고 빌드한 1.2.94 로 설치했는데 **또 `ERROR 1045`**. 이 PC root 를 통일값으로 맞춰 뒀는데도 안 붙었다.

```
db-setup.bat 은 'setlocal enabledelayedexpansion' 을 켠다
그 안에서 평문 '!' 는 조용히 사라진다:
    -pHITPAN2026!   →  cmd 가 먹어  →  -pHITPAN2026
실제 root = HITPAN2026!  → 불일치 → ERROR 1045
```

🔴 **`BatEscape()` 함수(L1082)가 정확히 이 목적으로 정의돼 있었는데 호출부가 0건이었다.**
주석(L2008)에만 `BatEscape(G_DbPassword)` 라고 적혀 있어 **마치 쓰이는 것처럼 보였다.**

그리고 **그 주석 스스로가 답을 적어 두었다**:

> *"이스케이프 결과를 예측하려 들지 않는다 — 예측이 틀려서 난 사고다."*

같은 파일이 `hitpan` 계정에는 **이미 옳은 답**을 쓰고 있었다 — SQL 을 파일로 넘긴다. **root 만 명령줄에 남아 있었다.**

### 2-3. 🔴 진짜 파괴력 — 다중 사업자가 죽어 있었다

`DetermineMultiTenantSlot()` 은 **한 PC 최대 5 사업자**를 이미 구현해 두었다(슬롯별 DB·계정·포트·폴더 분리).

```
1번째 사업자 : MariaDB 없음 → msiexec 실행 → 난수가 실제 적용 → 성공
2번째 사업자 : MariaDB 있음 → msiexec 건너뜀 → 불일치 → 설치 실패
```

⇒ **설계된 다중 사업자 기능이 6월부터 한 번도 동작한 적이 없다.** 헌법 #20 P0.
사장님이 짚어주신 *"메인PC에 두 개 설치될 수도 있다"* 가 정확히 이 자리였다.

## 6. 🔴 PM 실패 — 같은 계통이 반복됐다

### 6-1. "고쳤다" ≠ "갔다" — 5차 재발

**1차 봉합(R-1)은 *"난수 대신 통일값"* 까지만 봤다. 그 값이 배치까지 온전히 가는지는 안 봤다.**
코드는 고쳤는데 값이 **도중에 변형**됐다(`!` 소실). 그래서 빌드·설치를 두 번 더 돌았다.

⇒ **다음부터: 값을 바꿨으면 *그 값이 최종 소비 지점에 그대로 도착하는지* 를 따로 확인한다.**

### 6-2. 확인 없이 쓴 함수

`InputQuery` 를 R-2 폴백에 썼다. **Delphi 함수이고 Inno Setup 에는 없다.** CI 컴파일이 잡았다.
⇒ 빌드 1회 낭비. 확인하고 쓸 것.

### 6-3. 🔴 포트 판정 오판 — 사장님이 잡아주심

*"5357 열렸으니 슬롯 2 가 돌았다"* 고 보고했다. **틀렸다.**
사장님 반문: *"디비가 없는데 어떻게 포트가 열려??? 디비가 없으면 물리적으로 부모계정 컬럼이 없어서 로그인 자체가 안될건데??"*

실측: **PID 4 = Windows `System` 커널.** 5234·5357 은 Windows 기본 서비스(WSDAPI)가 원래 쓰는 포트였다. 히트판과 무관.
⇒ **`netstat` 의 LISTENING 만 보고 소유 프로세스를 안 봤다.** 포트는 **누가 잡고 있는지**까지 봐야 한다.

### 6-4. 지시를 잘못 읽음

사장님 *"root 패스워드를 통일하자"* 를 PM 이 *"이 PC 의 root 를 바꾸자"* 로 읽었다.
실제 뜻은 **설치 프로그램이 난수 대신 고정값을 쓰게 하자**였다. 그 오독으로 root 재설정을 두 번 시키고 MariaDB 삭제까지 검토했다(불필요했다).

### 6-5. 기록에 있던 답을 늦게 찾음

⇒ **설치가 중간에 죽으면 파일만 남아 다음 실행을 막는다.** 별도로 볼 자리.

## 8. 범위에서 뺀 것

### root 입력 폴백

통일값과 root 가 다른 PC(통일 이전 설치본 등)는 여전히 설치가 막힌다. 화면에 원인·해결책을 띄우고 멈추게는 했으나, **비번을 입력받아 진행하는 길은 안 만들었다.**

이유: 이 지점은 `ssPostInstall` 이라 마법사 페이지를 띄울 수 없고, Inno Setup 에 `InputQuery`/`InputBox` 가 없다. 하려면 `CreateInputQueryPage` 로 **앞단에 페이지를 세워야** 한다. **별도 작업지시서 사안.**

영향 범위: 통일 이전에 깐 고객 + MariaDB 를 따로 쓰던 고객.

## 9. 🔴 헌법 #23 — 보안 사후 감수 대상

`HitPan-Universal.iss:1821` 에 **반대 취지의 2026-08-11 결재**가 있었다:

> *"🔴 root(MariaRootPw)는 통일하지 않는다 — 그 PC 의 DB 전부를 여는 열쇠라 한 곳에서 새면 다른 고객사까지 열린다."*

**본 작업은 사장님 지시로 이를 뒤집었다.** 근거(작업지시서 §4):

1. **한 PC = 한 고객사** — 슬롯은 *같은 회사의 여러 사업자*다. 남의 회사가 같은 PC 에 없다.
2. **실 격리는 계정 단위** — `hitpan_{tenantCode}` 가 `GRANT ALL ON {자기DB}.*` 로 묶인다.
3. 2026-08-11 `hitpan` 계정 통일과 **같은 논리**.
4. 통일 안 하면 **슬롯 2~5 가 영구 봉쇄** — 잃는 것이 지키는 것보다 크다.

주석은 지우지 않고 경위를 갱신했다(헌법 #1). **보안상무 사후 감수 요망.**
