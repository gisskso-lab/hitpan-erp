# 📋 2. WS-D-3 DOCFE IJA_AMT 의미 자문서 (사장님)

## 배경

PM 식별 결과 DOCFE = 거래명세서 결재 라인 (117,112행).
컬럼 의미 미확정 = 사장님 또는 ERP 매니저 자문 필요.

## DOCFE 컬럼 구조 (PM 실측)

```
IJA_DT      char(8)     — 결재일자 (예: 20000103)
IJA_IO      smallint    — 1=매출, 2=매입
IJA_SEQ     int         — 시퀀스
IJA_BUY     int         — 거래처 코드 (음수 = 주민번호 추정)
IJA_SAWON   string      — 담당사원 이름
IJA_AMT1    decimal     — 금액 1 (예: 320000)
IJA_AMT2    decimal     — 금액 2 (예: 32000)
IJA_AMT3    decimal     — 금액 3 (예: 352000)
IJA_AMT4    decimal     — 금액 4 (대부분 0)
IJA_AMT5    decimal     — 금액 5 (대부분 0)
IJA_AMT6    decimal     — 금액 6 (대부분 0)
IJA_REM     string      — 비고
IJA_LINE    int         — 라인 번호
IJA_SSUN    int         — 결재 순번 (1, 2, ...)
IJA_SSUNH   int         — 결재 단계 H
IJA_SSUNH1  int         — 결재 단계 H1
IJA_SSUNC   int         — 결재 단계 C
IJA_SSUNE   int         — 결재 단계 E
```

## PM 가설 (사장님 검증 필요)

### IJA_AMT1·2·3 패턴
실측 샘플 1: AMT1=320,000 / AMT2=32,000 / AMT3=352,000
→ **AMT3 = AMT1 + AMT2 (합계)** 100% 일치

**PM 가설:**
- **AMT1 = 공급가액**
- **AMT2 = 부가세** (10% 정확히 = 32,000 / 320,000)
- **AMT3 = 합계 (AMT1 + AMT2)**
- AMT4·5·6 = 미사용 (구버전 추가 항목 또는 할인·운반비·기타?)

### IJA_SSUN·SSUNH·SSUNH1·SSUNC·SSUNE 결재 단계

**PM 가설:**
- SSUN = 결재 진행 순번
- SSUNH = 결재 단계 H = **헤더(상신) 단계?**
- SSUNH1 = 결재 단계 H1 = **헤더 1차 결재?**
- SSUNC = 결재 단계 C = **현업(Current) 또는 결재 완료?**
- SSUNE = 결재 단계 E = **End(최종)?**
- = 4단계 결재 워크플로우 (상신 → 1차 → 검토 → 최종)

# 📋 3. ERP 매니저 매핑 의뢰서 (Q5 결재 반영)

## 배경

WS-D-2 (commit d670a41) DOCF7 → journal_entries·journal_lines 마이그 시 **SC_KCODE 4자리를 그대로 account_code(varchar 10)에 저장**.

사장님 결재 Q5: *"SC_KCODE 매핑은 ERP 매니저가 정의"*.

## ERP 매니저 작업 요청

### 작업 1: SC_KCODE → 한국 표준 5자리 계정코드 매핑표 작성

**파일 위치:** `sql/migrations/20260519_account_mapping_DOCF7.csv`

**컬럼:**
```csv
legacy_code,standard_code,account_name,account_type,notes
1001,?????,상품매출,revenue,예시 — ERP 매니저 정의
1002,?????,?,?,?
...
```

**SC_KCODE 누적 4자리 코드 (마이그 후 확인 가능):**
```sql
SELECT DISTINCT account_code, account_name
FROM accounts
WHERE tenant_id = '<TENANT_ID>'
  AND account_type = 'unmapped'
ORDER BY account_code;
```

### 작업 2: 매핑표 검토 기준
- 한국채택국제회계기준 (K-IFRS) 표준 계정과목
- AutoJournalHelper.cs 상수 5종 (40100·25500·10800·50100·17600·23200) 기준
- 기존 운영 자동 분개와 정합 검증

### 작업 3: 매핑 완료 후 UPDATE SQL
```sql
UPDATE accounts a
INNER JOIN tmp_account_mapping m ON a.account_code = m.legacy_code
SET a.account_code = m.standard_code,
    a.account_name = m.account_name,
    a.account_type = m.account_type
WHERE a.account_type = 'unmapped';

-- 동시에 journal_lines도 UPDATE
UPDATE journal_lines jl
INNER JOIN tmp_account_mapping m ON jl.account_code = m.legacy_code
SET jl.account_code = m.standard_code;
```
