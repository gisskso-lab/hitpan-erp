## §1. 무엇이 고장났나

메신저 팝업창(`/chat-window`)이 **빈 화면**이다. 창은 뜨는데 아무것도 안 그려진다.

**사장님 실측 증언**:
- *"채팅동작은 팝업으로 띄우기 전에는 잘 돌았어."*
- *"팝업으로 띄우고 창이 안뜨는거야."*

## §2. 진범 — namespace 가 갈렸다

| 파일 | namespace |
|---|---|
| `ChatWindowPage.razor` | `HitPan.Web.Pages.HrUi` (선언함) |
| **`ChatPage.razor`** | **선언 없음** → 폴더 기반 `HitPan.Web.Pages.HR` |

`ChatWindowPage` 는 `HrUi` 에 있으면서 `<ChatPage />` 를 부른다. 그런데 `ChatPage` 는
`HR` 에 있고, `_Imports.razor` 에 **둘 다 `@using` 이 없다.**

🔴 **Blazor 는 모르는 태그를 오류 없이 HTML 요소로 흘려보낸다.**
그래서 `<ChatPage RoomId="..." />` 가 의미 없는 태그로 렌더링되고 화면은 빈 채로 남는다.

## §3. 왜 조용했나 (이 절이 이 문서의 값어치다)

증상이 **전부 정상으로 보였다**:

| 확인한 것 | 결과 | 그래서 오판했다 |
|---|---|---|
| 빌드 | errors 0 / warnings 0 | 알 수 없는 태그는 HTML 로 취급되어 컴파일을 통과한다 |
| 브라우저 콘솔 | 오류 0건 (경고 5건은 폰트 CDN·PWA 배너로 무해) | 죽은 게 아니라 **안 그린 것**이라 오류가 없다 |
| 토큰 | 부모·팝업 **양쪽 localStorage 에 동일** | 인증은 처음부터 정상이었다 |
| `/chat` 직접 입력 | **정상 표시** | 라우트로 도니까 namespace 와 무관 |
| `ChatWindowGuardTests` | 통과 | `"<ChatPage"` 라는 **글자만** 검사한다 |

⇒ **게이트가 있었는데 못 잡았다.** §5-2("린트 통과 ≠ 컴파일 성공")와 같은 계열이다.

## §6. 별건 — 손대지 않는다 (기록만)

🔴 **`storage.js` 의 `SESSION_KEYS` 가 무효다.**

```js
const SESSION_KEYS = new Set(['access_token', 'refresh_token']);   // 접두어 없음
```

실제 저장 키는 `hitpan_access_token` · `hitpan_refresh_token` (`AuthStorageKeys`).
⇒ `SESSION_KEYS.has()` 가 **항상 거짓**이라 민감 토큰이 **localStorage 로 간다.**
주석은 *"민감 토큰은 sessionStorage — XSS 노출 창 짧음"* 이라는데 **실제로는 반대로 동작 중.**

실측 확인: 부모·팝업 양쪽 **Local storage** 에 토큰 존재(사장님 8/15 확인).

⚠️ **이번 봉합 대상이 아니다.** 보안 판단(XSS 노출 창)이 걸린 자리라 별도 결재가 필요하다.
어제 넣은 `inheritFromOpener` 도 이 때문에 **작동한 적이 없다**(찾는 키가 없어 조용히 `false`).
단 localStorage 는 같은 출처면 창끼리 공유되므로 **팝업 기능에는 지장 없다.**
