## 1. 오더를 이렇게 이해했다 (명문화)

### 사장님 의중

**흐름의 순서가 뒤집혀 있었다.** 슬롯이 늘어나야 "부족"에 도달하고, 부족해야 추가슬롯을 산다.
승인이 안 되면 슬롯이 안 늘고, 슬롯이 안 늘면 **아무도 추가슬롯 화면에 도달하지 않는다.**
⇒ 추가슬롯(의제3)을 먼저 만드는 것은 **아무도 안 가는 길을 포장하는 것**이다.

근거: [`docs/검증/기기슬롯_전수조사/20260818_하브루타_최종봉합안.md`](../검증/기기슬롯_전수조사/20260818_하브루타_최종봉합안.md) §6

### 안 하면 무슨 일이 나는가

| 방치 시 | 결과 |
|---|---|
| 인증키가 회사 공용 열쇠 | 아무 기기나 **남의 줄을 열어** 통과한다 — 요금·접근통제가 동시에 무너진다 |
| 대표 예외가 전 API | 대표 계정으로 로그인하면 **미승인 기기가 ERP 전체**를 쓴다 |
| `rejected` 없음 | 거절당한 직원이 **무한 폴링에 갇힌다** — 사장님 *"첫 화면 회귀"* 가 불가능 |
| 관문이 화면을 안 막음 | 화면만 덮이고 **뒤에서 API 가 계속 돈다** |
| 1회용화만 하고 재발급 없음 | **오타 낸 직원이 영구 차단** — 8/10 사고와 같은 모양 |

## 5. 검증 방법 (SoD — 만든 사람 ≠ 검증하는 사람)

**[3-V] 동시 병렬검증** — 보안상무 안철수, 작업 도는 **중에** 실시
- 적발 이슈 → `docs/검증/병렬이슈/` 에 **1건 1파일**

### 🔴 게이트 3원칙 (어겼다가 8/15~16 에 가짜 게이트가 **다섯 번** 나왔다)

**① 게이트는 "두 번째 접속"을 센다.**
한 번 등록해서 맞는지가 아니라 — **다시 왔을 때 같은 줄인가 / 종류가 승격되나 / 옛 값이 새 값을 덮나.**
개발팀 주장 3건이 전부 철회된 공통 원인이 *"등록/최초/동일 페이로드라는 좁은 창으로만 봤다"* 였다.

**② 🔴 초록불로 태어난 게이트를 믿지 않는다.**
G-31·G-32 는 **지금 당장 빨간불이어야 한다.** 그것이 게이트가 진짜라는 최선의 증거다.
⇒ **게이트를 짠 직후 봉합을 빼고 FAIL 을 확인하는 절차를 반드시 밟는다. FAIL 이 안 뜨면 그 게이트는 없는 것이다.**

**③ 🔴 "초록불이 어디서 오는가 — 내 코드인가, DB 제약조건인가?"**
8/16 에 G-21 이 `UNIQUE(tenant_id, policy_key)` 때문에 **코드 가드를 둘 다 빼도 초록불**이었다(1062 를 catch 가 삼킴).
**코드가 아니라 제약조건을 시험하고 있었다.** 글자검사(`Assert.Contains`) 금지 — **모양·값**을 본다.

### 신설 게이트 (봉합안 §3 근거)

| 게이트 | 무엇을 태우나 | 통과 판정 | 🔴 지금 예상 | 봉합 빼면 |
|---|---|---|---|---|
| **G-1a** | 격리DB + 실서비스 | device_id 고정 · **지문 매회 변경** ×100 → `COUNT(*) == 1` | 미구현 | FAIL 떠야 함 |
| **G-1b** | 〃 | device_id 없음 · 지문 고정 ×100 → `COUNT(*) == 1` | 미구현 | FAIL 떠야 함 |
| **G-4** | + `MainPcRegistrationService` | 메인PC + 브라우저 3종 → `COUNT(*) == 1` | 🔴 **FAIL 예상** | — |
| **G-31** | **실제 `verify-key`** | 기기 B 가 A 의 키 입력 → **A 의 device_id 가 반환되면 FAIL** | 🔴 **FAIL (확정)** | 1-1 되돌리면 FAIL |
| **G-32** | **실제 미들웨어** | `is_main_pc=0` 행의 device_id 를 헤더에 → **통과하면 FAIL** | 🔴 **FAIL (확정)** | 1-2 되돌리면 FAIL |

> 🔴 **진짜 게이트는 격리 DB + 출하 DDL + 실제 코드를 태워 6~9초 걸린다. 밀리초로 끝나면 가짜다.**

### ⚠️ 게이트로 만들 수 없는 것 — **약속하지 않는다**

**origin 격리 시험은 xUnit 으로 불가능하다.** `localStorage` 가 origin 별로 갈리는 것은 **브라우저 동작**이라
xUnit 에서 재현할 수단이 없다. ⇒ **Playwright 실측 시나리오로 분류한다. 게이트로 약속하면 못 지킨다.**

| Playwright 실측 항목 | 통과 기준 |
|---|---|
| origin 격리 (`localhost` ↔ 터널 도메인) | 주소가 달라져도 **행이 안 는다** |
| 증상③ 관문 노출 | 로그인 후 **"등록을 하시겠습니까"** 가 실제로 뜬다 |
| 관문 뒤 API 정지 | 관문 상태에서 **업무 API 호출 0건** (네트워크 탭) |
| 거절 → 첫 화면 회귀 | 대표가 N → 직원 화면이 **죽지 않고** 재신청 가능 |
