## §1 담당 절 — P0-1 `deploy-ncp-secrets.sh` 가 정본 이름을 못 보낸다

**지금**(`scripts/deploy-ncp-secrets.sh:42`)
```
if [[ "$line" =~ ^([A-Z_][A-Z0-9_]*)=(.+)$ ]]; then
```
🔴 **대문자만 받는다.** 코드가 읽는 정본 이름은 **섞인 대소문자**다 — `License__Pepper` · `Backoffice__BizNoPepper` · `Smtp__Host`.
🔴 **그리고 안 맞는 줄은 `if` 를 그냥 빠져나간다** — 에러도 경고도 없다. 「OK」만 몇 줄 찍히고 끝난다.
🔴 **이 스크립트를 무는 게이트는 레포 전체에 0건**이다(`grep -rln deploy-ncp-secrets` = 0).

**할 일**
1. 정규식을 `^([A-Za-z_][A-Za-z0-9_]*)=(.+)$` 로 넓힌다. 🟢 종전 줄은 **주석으로 남긴다**(#1)
2. 🔴 **건너뛴 줄을 모은다.** 빈 줄·`#` 주석은 정상 통과, **그 외에 안 맞는 줄이 1개라도 있으면 목록을 찍고 `exit 1`**(#15 — 조용히 넘기지 않는다)
3. 적재한 키 **개수를 찍는다**(「몇 개 넣었다」가 없으면 0개 넣고도 성공처럼 보인다)
4. 🔴 **값은 한 글자도 찍지 않는다** — 키 이름만

**덤으로 고칠 것** — 이 파일에 **금지어 3곳**이 있다(사장님 헌법: 「박제/박다/박았다/박힘」 일체 금지). 내가 이 파일을 여는 차수이므로 **이 파일 안에서만** 고친다. 🔴 **레포 전체 금지어 소거는 이 차수 밖**이다.

# §8 🔴 정정 차수 (작P0-2) — **§3 의 내 규칙이 틀렸다**

> 🔴 **사장님 실측이 내 봉합을 반증했다.** 배포 후 화면에서 **6칸이 빨개졌다**:
> JWT (ERP API) · JWT (백오피스) · 토스 Client Key · 토스 Secret Key · 국세청 API · 부트스트랩 토큰 키

## 8-1 내가 무엇을 틀렸나

§3 에서 나는 **「`Probe` 는 설정키만 본다」**로 통일했다. 근거는 *「정본 모양은 `ProbeSmtp` 다」* 였다.
🔴 **그게 틀렸다 — `ProbeSmtp` 가 설정키만 보는 건 「발송기가 설정키만 읽기 때문」이다.** 모양을 베낀 것이고, **소비자를 하나씩 확인하지 않았다.**

실측하니 소비자가 **한 모양이 아니다**:

| 칸 | 소비자가 보는 자리 | 내 §3 봉합 결과 |
|---|---|---|
| pepper 2칸 | `_config[...]` **설정키만**(`DeviceRegistrationController:56` 등) | 🟢 맞았다 |
| SMTP 4칸 | 발송기도 설정키만 | 🟢 맞았다 (`ProbeSmtp`) |
| 국세청 | **env `NTS_API_KEY` 먼저** → 설정 (`BizNoVerifyController:70`) | 🔴 **거짓 빨강** |
| 토스 2칸 | **env `HITPAN_TOSS_*` 먼저** → 설정 (`TossPaymentsController:47`) | 🔴 **거짓 빨강** |
| 부트스트랩 | **env `HITPAN_BOOTSTRAP_TOKEN_KEY` 먼저** → 설정 (`InstallerBootstrapController:275`) | 🔴 **거짓 빨강** |

⇒ 🔴 **나는 거짓 초록을 거짓 빨강으로 바꿨다.** 방향만 뒤집었고 규칙은 여전히 틀렸다.

## 8-2 🔴 올바른 규칙

> ## **칸은 소비자가 보는 자리를, 소비자와 같은 순서로 본다.**

종전 결함은 **env 를 본 것**이 아니라 **없는 이름을 본 것**이다 — 화면 `HITPAN_JWT_SECRET` ↔ 소비자 `HITPAN_BO_JWT_SECRET`. 이름이 어긋난 게 병이고, env 자체는 병이 아니었다.
⇒ `Probe(configKey, display, envName = null)` 로 되살렸다. `envName` 은 **소비자가 실제로 쓰는 이름만** 넘긴다(건별 실측).
