### 3-3. G-5 를 어떻게 잴 것인가 — 설계팀장 판정
🟢 **채택: (나) 리플렉션 + (나)의 구멍을 G-5b 로 메운다.** PM 기울기와 같으나 근거는 아래다.

- **(다) `TimeProvider` 주입 기각** — 작2(절A~절F)는 **커밋됐고 [4] 검증이 아직 안 됐다**(M-1). 시험을 붙이려고 생산코드 서명을 바꾸면 [4] 가 재야 할 대상이 바뀐다. 시험이 대상을 바꾸면 그건 시험이 아니다.
- **(가) 61초 대기 기각** — 정직하지만 `db-gate` 는 이미 `timeout-minutes: 30` 안에 게이트 40여 종을 돌린다. 만료 게이트가 늘 때마다 61초씩 선형 증가하고, 느린 게이트는 결국 꺼진다.
- **(나) 채택 · 구멍을 명시**: `_challenges` 의 `Entry.ExpiresAt` 를 과거로 돌려 **생산코드의 `IsExpired` 가 실제로 거부하는지** 잰다. **이 방식은 `IssueChallenge` 가 60초를 넣는지 못 잰다.** ⇒ **G-5b 를 별건으로 세워** `ChallengeLifetime`(static readonly)이 `TimeSpan.FromSeconds(60)` 임을 읽어 D-2 를 고정한다. **G-5a·G-5b 둘이 다 있어야 D-2 를 쟀다고 말한다. 하나만 붙이면 안 된다.**
- 🚨 **리플렉션은 조용히 통과한다** — `_challenges`·`Entry`·`ExpiresAt`·`ChallengeLifetime` 중 하나라도 이름이 바뀌면 리플렉션이 `null` 을 물고 시험이 *아무것도 안 재고* 초록이 된다. ⇒ **찾지 못하면 그 자리에서 `Assert.Fail`** 로 떨어뜨린다. 이름이 바뀌면 게이트가 빨간불이 되는 것이 맞다.

## 4. 어떻게 하는가 ([3] 개발팀용)

지휘: **PM(개발팀장)**. 대상 시험 프로젝트 `src/HitPan.Tests/HitPan.Tests.csproj` (xunit 2.9.3 · Moq 4.20.72 · **Sqlite 없음** ⇒ 가짜 DB 로 대체하지 말고 실제 MariaDB 격리 DB 를 쓴다).

### 4-1. 파일 2개 — 🔴 DB 쓰는 것과 안 쓰는 것을 섞지 않는다
섞으면 **DB 없는 로컬에서 SKIP 되는 범위가 순수 게이트까지 넓어진다.** 순수 게이트는 로컬·`build` 잡에서도 반드시 돌아야 한다.

| 파일 | DB | 담는 게이트 | 골격 |
|---|---|---|---|
| `src/HitPan.Tests/Integrity/MainPcProofRoundTripGateTests.cs` | **무접촉** | G-1a·G-2a·G-4·G-5a·G-5b·G-6·G-7a·G-7b·G-9·G-13a | `ServerAvailable()`·`SkipOrFail` **안 쓴다**(쓰면 DB 게이트로 오해된다). `DefaultHttpContext` + 가짜 `ITpmKeyService` |
| `src/HitPan.Tests/Integrity/MainPcSealRegistryGateTests.cs` | **필요** | G-11a·G-14·G-15·G-16·G-17·G-18·G-19a | 형제 `Integrity/MainPcLocalConsoleGateTests.cs`(533줄) 골격 |

**DB 파일 골격 — 형제에서 무엇을 베끼고 무엇을 베끼지 않는가**
- 베낀다: `[Collection("DeviceAndKeyGate")]` · `hitpan_mainpc_gate_<guid8>` 격리 DB → **출하 DDL `installer/hitpan_db_clean.sql` 한 방**(#36) → 실제 서비스 호출 → 표를 읽는다 → `IDisposable` 로 DB 삭제(#39)
- 🔴 **베끼지 않는다**: 형제는 `if (!ServerAvailable()) return;` 로 **조용히 SKIP** 한다(작14 W1 에서 봉합한 그 사고 모양이다). 이번 파일은 `MainPcRestartMarkGateTests.cs:403` 형태를 쓴다 — `if (!ServerAvailable()) { DbGateEnvironment.SkipOrFail(nameof(게이트)); return; }`. `HITPAN_REQUIRE_DB` 가 있으면 던진다.
- `tenant_devices` 시드: `device_id`·`tenant_id`·`device_type`·`fingerprint` NOT NULL · `uq_tenant_fp(tenant_id,fingerprint)` · `fk_device_user` 가 `users` 를 가리키므로 **`user_id` 는 NULL** 로 둔다.
- DB-126 컬럼은 출하 DDL 에 이미 있다: `mainpc_sealed_key varbinary(1024)` · `mainpc_key_issued_at` · `main_pc_key` = `GENERATED ALWAYS AS (if(is_main_pc=1, tenant_id, NULL)) VIRTUAL` + `uq_tenant_main_pc UNIQUE`.

### 4-2. 🚨 static 전역 상태 — 두 파일 모두의 함정
`MainPcProofService` 의 `_challenges`·`_passes` 는 **static ConcurrentDictionary(프로세스 전역)** 이다. xunit 은 서로 다른 collection 을 **병렬**로 돈다 ⇒ 두 시험이 같은 `tenantId`/`sessionKey` 를 쓰면 **한쪽의 표를 다른 쪽이 소비한다.** 붙는 즉시가 아니라 **CI 에서 깜빡임으로** 나타난다(별건 `G-RC12` 와 같은 모양).
대응 **둘 다** 한다: ① 시험마다 `Guid.NewGuid()` 로 고유 `tenantId`·`sessionKey` ② 두 파일을 같은 collection 으로 묶어 직렬화. `SweepThreshold = 256` 이므로 표를 쌓아 남의 표를 밀어내지 않도록 시험 수를 늘리지 않는다.

### 4-3. CI 등록 — 어느 잡이 `HITPAN_REQUIRE_DB` 를 주는가 (실측 · 파일·줄)
- `.github/workflows/build-and-test.yml`
  - **`db-gate` 잡** — 잡 `db-gate:` **91줄** · name **92줄** · 스텝 `Run Integrity gates (실제 DB)` **178줄** · `HITPAN_REQUIRE_DB: 'true'` **183줄**. **이 한 곳뿐이다.**
  - **`build` 잡**(**18줄**)은 안 준다 ⇒ 🔴 **`build` 초록은 DB 게이트가 돌았다는 증거가 아니다.**
  - `Gate — SKIP 이 한 건도 없어야 한다` **435줄** — 로그에 `[SKIP]` 이 있으면 실패시킨다.
- **지시 ①** `GATES="$GATES|RcSafePathGate|RcLockRatioGate"`(**421줄**) **다음 줄**에 추가:
  `GATES="$GATES|MainPcSealRegistryGate"` + 바로 위에 **무력화 시험 결과 주석**(§5 표에서 실제로 뺐다 되돌린 근거). 기존 등록 주석들과 같은 형식으로, *"초록불이라서"* 를 근거로 쓰지 않는다.

## 5. 🚨 G-3 대조군 — 어느 한 줄을 빼면 어느 게이트가 FAIL 해야 하는가

## 6. 🚨 이 시험이 못 하는 것 — 초록불을 실측으로 읽지 마라
`CspFrameSrcGateTests.cs:34` 의 *"이 시험이 못 하는 것"* 문단과 **같은 주석을 두 파일 머리에 넣는다.** 내용:

- **브라우저가 실제로 loopback 을 두드리는지 못 잰다.** 왕복의 첫 바퀴는 화면이 돌린다. 🔴 헤드리스로 대신 재면 **정반대 결과**가 나온다(인계3 §6-2).
- **자료관리 메뉴가 열리는지 못 잰다** — 재는 것은 `IsMainPc` 판정값까지다.
- **팝업이 뜨는 횟수를 못 잰다**(G-11b·G-12·G-20).
- **키가 물리적으로 그 PC 에 묶였는지 못 잰다**(G-13b) — 임의 바이트가 안 풀리는 것은 *다른 PC 의 봉인이 안 풀리는 것*과 같지 않다.
- **실제 백업/복원을 못 돌린다**(G-19b) — 재는 것은 복원이 만든 DB 상태의 전이다.
- **`TpmKeyService` 의 실제 봉인을 못 잰다** — §3-0 때문에 가짜를 쓴다. ⇒ 실물 TPM 경로는 **한 번도 안 돌았다.**
- **DB 없는 로컬에서 `MainPcSealRegistryGate` 의 PASS 는 SKIP 이다.** `db-gate` 잡의 `.trx` 로만 통과를 센다.

🔴 **이 시험 전부가 초록이어도 M-1(실물 실측)은 여전히 0회다.** 그것이 이 작지의 다음 단계다.
