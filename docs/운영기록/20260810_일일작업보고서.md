## 4. 🔴 오늘 가장 값진 것 — 같은 결함이 하루에 세 번, 얼굴만 바꿔서 나왔다

세 건 모두 **"만들었다"** 는 맞았다. 틀린 것은 **"그게 실행된다"** 였다.

| # | 무엇을 만들었나 | 왜 안 돌았나 | 누가 잡았나 |
|---|---|---|---|
| 1 | 마이그레이션 SQL | `installer/migrations/` 에 뒀는데 **그 폴더는 아무도 실행하지 않는다** | 🔴 **사장님 실측** (QR 500) |
| 2 | `requiresMigration` 입력 | 워크플로가 `build-manifest.ps1` 로 **넘겨주지 않았다** → 항상 false | 배선 점검 |
| 3 | clean DDL 테이블 | `schema_migrations` **시드에 DB-87 을 안 넣었다** (58 파일 vs 57 시드) | CI DDL Smoke |

**이건 8/10 아침 "4차 사고" 와 같은 계통이다.** 메모리에 적힌 그 문장 —
*"코드는 매번 정상, 끊긴 건 전달 경로이고 끊기는 자리만 옮겨간다."*
오늘의 변주는 **"파일을 썼다 ≠ 그 파일이 읽힌다."**

### 🔴 왜 CI 가 1번을 못 잡았나 — 다음 사람이 반드시 알아야 할 것

- 빌드 0/0 — SQL 파일 **위치**는 컴파일과 무관하다
- DDL Smoke 통과 — clean DDL 에는 제대로 넣었기 때문이다
- ⇒ **신규 설치는 정상이고 기존 고객만 깨진 상태**였다.
  **돌고 있는 DB 에 업데이트를 얹어야만** 드러난다. CI 에 그 환경이 없다.

### 재발 방지 — 새 테이블·컬럼은 **세 곳 모두**

1. `installer/hitpan_db_clean.sql` — 신규 설치 (헌법 #36)
2. `src/HitPan.API/Migrations/SQL/DB-NN_*.sql` — **기존 DB 업데이트**
3. 게시 시 `requiresMigration: true`

①만 하면 **신규 고객은 되고 기존 고객만 깨진다.**
