## 0. 가장 먼저 — 절대 잊지 말 것

### 사장님 운영 설계 (100번 박힌 영역)

```
hitpan.kr (가비아 등록, 사장님 보유)
  │
  ├── {고객사ID}.hitpan.kr  → 고객사 PC 로컬 + cloudflared 터널 → 히트판 ERP
  ├── landing.hitpan.kr     → NCP 클라우드 → 랜딩페이지
  └── back.hitpan.kr        → NCP 클라우드 → 백오피스
```

### PM 절대 금지 (반복 사고 차단)

❌ `www.hitpan.kr` 같은 일반 관례 갖다 붙이기
❌ ERP를 본사 클라우드로 옮기는 가정
❌ 사장님 박힌 결정을 PM이 다시 흔들기 (사양·디스크 5번 흔든 사고)
❌ 본사 데이터 산출 시 ERP 업무 데이터까지 포함 (원칙 #18·#22 위반)

## 3. 내일 (6/7 일) 작업 — 배포

### PM 환경 한계 (정직 박음)

PM 도구로 비밀번호 SSH 자동화 불가:
- Bash ssh = TTY 요구 (비대화형 환경 불가)
- echo password | ssh 안 됨
- sshpass 미설치 (Git Bash)
- Posh-SSH PowerShell 모듈 설치 차단 (NuGet 권한)

→ **인증키 SSH 활성화 후에만 PM 단독 작업 가능**.

### Phase A — 사장님 5분 동행 (인증키 SSH 활성화)

1. PowerShell 열기 (관리자 X)
2. SSH 접속:
   ```powershell
   ssh root@211.188.58.140
   ```
3. 비밀번호 입력 (사장님 별도 메모장 보관)
4. PM이 명령어 한 줄 알려드림 → 사장님 복붙:
   ```bash
   mkdir -p ~/.ssh && curl -s "<PM이 임시로 안내" >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys
   ```
   (정확한 명령은 6/7 일 PM이 다시 안내. PM 공개키 생성 후 그것을 등록하는 흐름)
5. exit
6. → PM이 인증키 단독 SSH 가능 확인

### Phase B — PM 단독 작업 (약 2시간, 사장님 부담 0)

7. Ubuntu 업데이트 + 보안 패치
8. .NET 8 SDK + 런타임 설치
9. Nginx 설치
10. MySQL 8.0 설치 + 백오피스 DB 생성
11. 백오피스 스키마 적용 (`db/migrations/*.sql` 중 백오피스 영역 선택)
12. 백오피스·랜딩 코드 빌드 (로컬 PC `dotnet publish`)
13. SCP로 서버 업로드
14. systemd 서비스 등록 (자동 재시작 — 원칙 #28·#30 정합)
15. Nginx 리버스 프록시 설정 (landing.hitpan.kr → 랜딩 포트, back.hitpan.kr → 백오피스 포트)
