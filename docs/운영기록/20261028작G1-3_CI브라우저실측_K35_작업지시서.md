## §2 [사실] (파일:줄 읽기 · 실행 0)
### §2-1 지금 CI
- `build-and-test.yml` 잡: `build`(windows) · `db-gate`(ubuntu · `mariadb:11.4` 서비스 · `:288~`) · `ddl-smoke` · `permission-menu-sync` · `migration-id-collision` · 백오피스(mysql 8). **브라우저 시험 0건.**
- `db-gate` 의 DB 올리는 법(재사용할 꼴): 서비스 컨테이너 + 헬스체크(`:292~302`) → apt `mariadb-client` 3회·4분 제한(`:315~325`) → 대기 루프(`:327~335`) → `max_connections` 올림(`:337~342`) → `CREATE DATABASE … utf8mb4_unicode_ci` + `installer/hitpan_db_clean.sql` 적재(`:344~358` · #36) → SKIP 0 검사(`:1354~1363`) → `upload-artifact@v5`(`:1365~1371`).
### §2-2 API·화면을 CI 에서 띄우는 데 필요한 것
- 설정은 `TenantConfigReader`(`src/HitPan.Application/Common/TenantConfigReader.cs:24·47~51·73`) — db.conf/hitpan-keys.conf 후보 경로가 비면 **환경변수 폴백** ⇒ `appsettings*.json` 무접촉(#21)으로 띄울 수 있다.
- 읽는 키: `DB_HOST·DB_PORT·DB_NAME·DB_USER·DB_PASSWORD` · `JWT_SECRET·JWT_ISSUER·JWT_AUDIENCE` · `ERP_ENCRYPTION_KEY` · `HITPAN_BOOTSTRAP_TOKEN_KEY` · `TENANT_CODE·LICENSE_KEY` · `HITPAN_HQ_API_URL` · `ASPNETCORE_ENVIRONMENT`.
- `JWT_SECRET`: Production 이면 32자 이상 + 약한 표지 낱말 포함 금지(`AuthExtensions.cs:17~41`) ⇒ **16진 난수 64자**로 만든다(16진 글자로는 표지 낱말이 안 생긴다).
- 화면: API 실행파일 옆 `wwwroot/index.html` 이 있으면 API 가 화면을 같이 싣는다(`Program.cs:58~65·698~761`) · 화면 `ApiBaseUrl` 빈 값 → 지금 열린 페이지 출처로 폴백(`HitPan.Web/Program.cs:14~35`) ⇒ **한 출처(127.0.0.1) 하나로 띄운다**(CORS 0).
- 🔴 화면 `wwwroot/appsettings.json` 의 `BackofficeApiBaseUrl` = 운영 백오피스 주소. 수정 금지(#21) ⇒ **브라우저 쪽에서 127.0.0.1 밖 요청을 전부 끊고 센다**(§3-4).
- 🔴 API `HITPAN_HQ_API_URL` 기본값 = 운영 백오피스(`HeadquartersClient.cs:20`) ⇒ 환경변수로 **닫힌 로컬 포트**를 준다(#18·#39 — 시험이 본사로 한 건도 안 간다).
- 부모계정 생성 길: `HitPan.API seed-parent <입력JSON>`(`Program.cs:49~55` · `SeedParentCommand.cs`) — 설치 마법사가 쓰는 실물 길. 입력에 **서명된 증표**가 필요하고 검증 공개키는 환경변수 덮어쓰기 `HITPAN_SERIAL_PUBLIC_KEY__<kid>` 를 받는다(`SerialProofVerifier.cs:24·55~66`).
- 자식계정 길: `POST api/users/children`(`UserController.cs:12·451` · 부모 권한).
- 대화: `POST api/chat/rooms` · `POST api/chat/rooms/{roomId}/messages`(`ChatController.cs:29·61·117`) · 알림은 SignalR(`NotificationClient.cs:35·78`) ⇒ **토스트 길은 실제 메시지로만 생긴다.**
- 로그인 뒤 막을 수 있는 문: 약관 4건(`TermsConsentMiddleware` `Program.cs:742`) · 기기(`DeviceAuthMiddleware` `:747`) · 세션(`SessionValidityMiddleware` `:729`) — CI 첫 로그인에서 어떻게 서는지 **미실측**(§8 ③).
### §2-3 게시 규율과의 관계
- `deploy-update.yml:45~52` — 「dispatch 전 그 커밋이 build-and-test 초록인지 확인」(사람 규율 · 자동 연결 0 · `workflow_run` 0건). ⇒ 화면 시험을 `build-and-test.yml` 안에 넣으면 **「초록」의 뜻이 바뀐다.** 그래서 **별도 파일**로 둔다(배포 무접촉).
### §2-4 CI 로 못 재는 것 (정직하게 남긴다)
- 터널 경로(G1-1 §5-3 「실사용 경로」) — CI 는 127.0.0.1. 팝업은 브라우저 쪽 동작이라 터널 영향은 작다고 **본다(가설 · 미실측)**.
- G1-1 §6 리스크 1 「`await` 뒤 `window.open` 을 브라우저가 사용자 동작으로 안 봄」 — Playwright 브라우저의 팝업 차단은 실제 사용자 브라우저 기본값과 다를 수 있다(⚠️미확인). ⇒ WebKit 1회로 일부를 보되 **「CI 초록 = 실제 크롬에서 안 막힘」으로 말하지 않는다.**
- 모바일 — 범위 밖(G1-1 §5-3 과 같다).

## §3 [설계] 새 워크플로 `ui-browser.yml`
### §3-1 트리거·자리
- `pull_request`(develop·main) + `workflow_dispatch`. **경로 거르기(paths)는 안 쓴다** — 필수 검사로 지정될 때 「대기 영원」이 되는 꼴을 피한다. 필수 검사 지정 여부는 대표 결재 칸(§8 ⑥).
- `permissions: contents: read` · `concurrency` 로 같은 PR 의 앞 런 취소(사람이 누르는 재실행이 아니라 새 커밋이므로 §5 위반 아님).
- 🆕(결재 조건 ④-4 · 보안상무) **포크 PR 런**(PR 머리 레포가 이 레포가 아닌 런)에서는 **trace 를 업로드하지 않는다**(S11). 그 밖의 업로드물은 S11 조건 그대로.
- 잡 1개 `ui-k35` · `ubuntu-latest` · `timeout-minutes: 30`.
