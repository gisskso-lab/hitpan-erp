## 2. 원인 — 화면 권한이 서버 정책과 어긋나 있었다

`SalesReturnPage.razor` 의 「반품확정」·「반품취소」 버튼:

```
<AuthorizeView Roles="tenant_admin,purchase_manager">   ← 매입 역할
```

서버 `POST api/sales/returns/{id}/confirm`:

```
[Authorize(Policy = "SalesManager")]
  = system_admin · sales_manager · TenantAdmin · tenant_admin
```

**어긋난 결과가 양방향이다:**

| 역할 | 서버 | 화면 | 결과 |
|---|---|---|---|
| `sales_manager` | ✅ 허용 | 🔴 **버튼 안 보임** | **이번 실측 증상** |
| `purchase_manager` | 🔴 403 | ✅ 버튼 보임 | 눌러도 거부 |

🔴 **이 화면은 작6 에서 매출반품 전용으로 갈라져 나왔는데, 버튼의 권한 목록만 매입 쪽에 남아 있었다.**
화면을 갈랐을 때 **권한도 같이 갈랐어야** 했다.

> [[project_fixed_vs_delivered_gap]] **6차 재발.**
> 코드는 이번에도 정상이었다(저장 통과가 증거). 서버도 정상이었다.
> **끊긴 건 화면과 서버 사이**고, **끊기는 자리가 또 옮겨갔다.**
> 작8 은 "고른 행이 안 돌아오는 자리", 작9 는 "권한이 안 맞는 자리".

**왜 작8 게이트가 못 잡았나** — 작8 게이트는 **안내·배선·필터**를 봤다.
**버튼이 보이는지**는 아무도 안 봤다. 안내를 아무리 잘 해도 **누를 버튼이 없으면 소용없다.**

## 3. 작업 범위

### W1 — 화면 권한을 서버 정책에 맞춘다
- 「반품확정」·「반품취소」 **두 자리 모두** `system_admin,tenant_admin,sales_manager`
- 🔴 확정만 고치고 취소를 두면 **확정한 사람이 되돌리지 못하는 반쪽**이 된다
  (작7 의 *"생성은 넣고 수정은 안 넣던 비대칭"* 과 같은 실수)

### W2 — 게이트
- 화면 권한 == 서버 정책 고정 (양쪽 함께)
- 🔴 봉합을 빼면 FAIL 하는지 **먼저 확인**

---

## 4. 범위 밖 — 손대지 않는다

- 🚫 **매입반품 화면**(`Pages/Purchase/ReturnPage.razor`) — `purchase_manager` 가 **거기서는 맞다**
- 🚫 서버 정책 변경 — 매출반품을 판매 담당자가 확정하는 게 옳다
- 🚫 매입 영역 전체 — 오더 없음
