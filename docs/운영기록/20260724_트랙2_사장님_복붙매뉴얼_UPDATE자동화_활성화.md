# 🟢 트랙2 사장님 복붙 매뉴얼 — UPDATE 자동배포 켜기

> **이 문서 사용법**: 위에서부터 순서대로. 각 칸의 **회색 명령을 그대로 복사 → 붙여넣기 → 엔터**.
> 각 단계 끝에 "**이 화면이 나오면 성공**"이 있습니다. 그 화면이 나오면 다음 칸으로.
> 안 나오면 **멈추고** 그 화면을 저(PM)에게 보여주세요. 절대 억지로 다음 안 넘어갑니다.
>
> 준비물: ① 사장님 PC의 터미널(PowerShell) ② 웹브라우저(GitHub 로그인 된 것) ③ 휴대폰
> 소요: 약 20~30분. 중간에 멈춰도 됩니다(다음에 그 칸부터).

---

## 🗺️ 전체 그림 (지금 어디쯤인지 파악용)

```
[디스크 정리] ✅ 이미 끝남 (90%→73%)
    ↓
[1단계] 래퍼 2개를 NCP에 올리기        ← 복붙 (PC 터미널)
    ↓
[2단계] 배포 전용계정 + 권한(sudoers)   ← 복붙 (NCP 안에서)
    ↓
[3단계] git 미러 + GitHub 토큰          ← 복붙 + 토큰발급(브라우저)
    ↓
[4단계] GitHub 승인게이트 + 브랜치보호   ← 클릭 (브라우저)
    ↓
[5단계] 비상경로(복구코드) 만들기        ← 복붙 (NCP 안에서)
    ↓
[6단계] 자동배포 켜기(.disabled 제거)    ← 복붙 (PC 터미널)
    ↓
[첫 실측] 딸깍 한 번 → UPDATE 뜨나 확인  ← 클릭 + 휴대폰 승인
```

> 각 단계는 아래에서 "복붙 명령 한 줄씩"으로 풀어드립니다. 준비되면 저에게 "1단계 줘" 하시면
> 그 단계 명령을 화면에 띄워드립니다. (이 문서는 지도, 실제 명령은 제가 한 단계씩 드림)

## 공통 약속 (매 단계 적용)

- **NCP 접속 명령**(사장님 PC 터미널에서):
  ```
  ssh -i "C:\Users\소순근\Downloads\hitpan-key.pem" root@211.188.58.140
  ```
  이걸 치면 NCP **안으로** 들어갑니다. 프롬프트가 `root@...:~#` 로 바뀌면 들어온 것.
  NCP에서 나올 때는 `exit` 엔터.

- **"복붙"이 안 되면**: 터미널에서 마우스 우클릭 = 붙여넣기(PowerShell 기본).

- **한글 깨져 보여도** 명령은 정상 작동합니다(영문·숫자만 실행에 쓰임).

## 1단계 — 래퍼 2개를 NCP에 올리기

**무엇**: 트랙1에서 만든 안전장치 스크립트 2개(`deploy-web.sh`·`publish-run.sh`)를 NCP에 배치.
**왜**: 이게 있어야 "광역 권한을 래퍼 하나에 가둔다"가 성립(보안 핵심).
**어디서**: 사장님 PC 터미널 (NCP 접속 전, 로컬에서 실행).

→ 준비되면 "1단계 줘" 하세요. `scp` 복붙 명령 + 권한설정을 드립니다.
**성공 화면**: NCP `/opt/hitpan/deploy/` 에 `deploy-web.sh`·`publish-run.sh` 2개가 `-rwxr-xr-x`(실행권한)로 보이면 성공.

---

## 2단계 — 배포 전용계정 + 권한(sudoers)

**무엇**: `hitpan-deployer` 계정을 만들고, 그 계정이 **딱 래퍼 2개만** root로 실행하게 허용.
**왜**: 계정이 뚫려도 래퍼 2개 외엔 아무것도 못 함(개인키 열람 불가 = 헌법 #22).
**어디서**: NCP 안에서.
**주의**: sudoers는 한 글자만 틀려도 서버 잠김 위험 → 제가 `visudo -c`(문법검사) 포함해 드립니다. 검사 통과 못 하면 **자동으로 안 저장**되게.

→ "2단계 줘" 하세요.
**성공 화면**: `sudo -l -U hitpan-deployer` 실행 시 래퍼 2개만 NOPASSWD로 뜨면 성공.

---

## 3단계 — git 미러 + GitHub 토큰 (B-4 보안 핵심)

**무엇**: (a) NCP에 레포 사본(git 미러) 두기 (b) GitHub 읽기전용 토큰 발급해 NCP에 저장.
**왜**: NCP가 "이 게시가 진짜 승인된 것인지" **스스로 GitHub에 직접 물어봐** 확인(침해된 자동화 방어).
**어디서**: 토큰 발급 = 브라우저 / 나머지 = NCP 안에서.
**토큰 발급 화면 경로**: GitHub → 우측상단 프로필 → Settings → Developer settings →
  Personal access tokens → Fine-grained tokens → Generate new token
  (권한: 이 레포 읽기 `Contents: Read` + `Actions: Read`만. 그 외 전부 No access)

→ "3단계 줘" 하세요. 화면 클릭 순서 + NCP 저장 명령을 드립니다.
**성공 화면**: NCP에서 테스트 조회 명령이 `200`(또는 레포 정보 JSON) 뜨면 성공.

---

## 4단계 — GitHub 승인게이트 + 브랜치 보호 (사장님 폰 1탭의 정체)

**무엇**: (a) `production` 환경에 **사장님을 필수 승인자**로 등록 (b) 브랜치 보호 켜기.
**왜**: 게시하려면 **사장님 휴대폰에 "승인?" 알림**이 뜨고, 탭해야만 진행. 이게 결재하신 "폰 1탭".
**어디서**: 전부 브라우저(GitHub) 클릭.
**화면 경로**:
  - 승인자: 레포 → Settings → Environments → `production` → Required reviewers 체크 → 본인 추가
  - 브랜치보호: 레포 → Settings → Branches → Add rule → `main`(또는 develop) → Require review 체크

→ "4단계 줘" 하세요. 클릭 위치를 그림 설명으로 하나하나 드립니다.
**성공 화면**: `production` 환경에 Required reviewers = 사장님 이름이 보이면 성공.

---

## 5단계 — 비상경로(복구코드) 만들기

**무엇**: 사장님 폰이 막혔을 때 쓸 **1회용 봉인 복구코드** 준비(결재 4번).
**왜**: 부승인자가 없어(1-of-1) 사장님 폰이 유일 게이트 → 그 폰 막히면 P0 핫픽스 영구차단 방지.
**어디서**: NCP 안에서 코드 생성 → 사장님이 안전한 곳(예: 폰 메모·금고)에 보관.
**성격**: 1회용 + 쓰면 로그 남고 + 사후 통지. 오용 차단.

→ "5단계 줘" 하세요.
**성공 화면**: 복구코드 1개가 화면에 뜨고, 사장님이 그걸 안전한 곳에 적으면 성공.

---

## 6단계 — 자동배포 켜기 (.disabled 제거)

**무엇**: 지금까지 오배포 막으려 잠가둔 워크플로(`deploy-update.yml.disabled`)의 `.disabled`를 뗌.
**왜**: 이걸 떼야 GitHub에서 "게시 버튼(dispatch)"이 생김.
**어디서**: 사장님 PC 터미널(git) — 제가 커밋·푸시까지 대행 가능(코드 조작이라 #29 무관).
**전제**: 1~5단계 전부 성공 확인 후에만. (안 그러면 첫 게시가 실패)

→ "6단계 줘" 하세요.
**성공 화면**: GitHub → Actions 탭에 "Deploy Auto-Update" 워크플로가 보이고 "Run workflow" 버튼이 생기면 성공.

## 🎯 첫 실측 — 딸깍 한 번

**무엇**: GitHub에서 버전(예: 1.2.40) 넣고 "Run workflow" → 사장님 폰 승인 → UPDATE 게시되나 확인.
**확인 지점**(오판 방지 — 이것만 봄):
  1. GitHub Actions 초록불(빌드·게시 성공)
  2. `updates.hitpan.kr/manifest.json` 이 새 버전 가리킴
  3. (있으면) 백지 Sandbox ERP에서 업데이트 팝업 뜸

→ 6단계까지 성공하면 "실측 가자" 하세요. 버전 정하고 같이 딸깍.

## ⚠️ 안전 규칙 (제가 지킴)

- 각 단계는 **읽기→보여드림→사장님 확인→실행** 순. 삭제·덮어쓰기는 dry-run 먼저.
- sudoers·토큰 같은 위험 작업은 **문법검사·되돌리기 명령**을 함께 드림.
- 하나라도 "성공 화면"이 안 나오면 **멈춤**. 두더지잡기(억지 진행) 금지.
- 운영본(backoffice·landing)·개인키는 **절대 안 건드림**.
