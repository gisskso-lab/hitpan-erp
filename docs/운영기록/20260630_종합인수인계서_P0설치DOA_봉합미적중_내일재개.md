## 2. 🔴🔴 내일 첫 작업 — P0 봉합 재규명 (최우선)

### 사고 상태
- **증상**: 샌드박스 신규설치(시리얼 없이)에서 `데이터베이스 초기화 실패(코드 1). 스키마 미설치.` → 설치 DOA.
- **1.2.11**: 에러 `55:11858`, 에러로그 `ERROR 1045 Access denied for user '-p106501cce...'@'localhost' (using password: NO)` = G_DbUser 빈값 → -p가 유저명으로 밀림.
- **1.2.16(봉합본)**: 에러 `57:12129` — 줄 이동(봉합 포함 확인: a252f19 21:01 < 빌드 21:12)인데 **여전히 DB초기화 실패.**

### ⚠️ 1차 봉합(작6)이 미적중인 이유 = 내일 규명 대상
- 작6 봉합 = DB셋업 직전(HitPan-Universal.iss L859-860) `if G_DbName='' then ...` / `if G_DbUser='' then ...` 빈값 가드.
- **그런데도 실패** → 가설들(내일 에러로그로 판정):
  1. **G_DbUser는 채워졌으나 다른 원인** — 예: 시리얼없이 설치는 hitpan 계정 비번이 **랜덤(G_DbPassword, L861)**인데 CREATE USER 또는 import 단계의 비번/권한 문제.
  2. **L864 `GRANT ALL ON %s.*`(회사DB만)** — hitpan 계정이 전역권한 없어 후속 작업 실패 가능.
  3. 봉합 위치가 실제 실행경로보다 늦거나, DB셋업 블록 자체 호출 조건 문제.
  4. 비번 SQL 특수문자/이스케이프.

### 🎯 내일 0초 첫 행동 (반드시 이것부터)
**샌드박스 띄워(.wsb로!) 1.2.16 시리얼없이 재설치 → 「확인」 후 에러로그 캡처:**
```
Get-Content $env:TEMP\hitpan_import_err.log -Tail 40
```
- 유저명이 **여전히 `-p...`로 깨졌으면** → 봉합 미실행/위치오류(L859 가드가 안 탄 것).
- **정상 유저명인데 다른 에러**(비번/권한/특수문자)면 → 새 원인. 그에 맞춰 재봉합.
- 추가: `Get-Content "$env:LOCALAPPDATA\HitPan\db.conf"` 로 실제 기록된 DB_USER/PASSWORD/NAME 확인.
- **에러로그가 진짜 원인의 단일 진실원. 추측 금지(샌드박스 실측이 오늘 P0 다 잡음).**
