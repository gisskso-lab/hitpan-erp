### Q-2 답 (사장님 10/5)
- 원문: *"1,2번 = 테스트중 문제 생길시 확실한 물리적 봉합을 하되, 일단은 놔두자. 3번 = 지켜보되, 문제생길시 물리적 봉합으로 재설계 해보는 쪽으로 하자. 일단은 놔둬. 판정 = 1,2,3번 모두 통과."*
- PM 이 올린 근거(코드 확인 · 실측 아님):
  - ① 이동 주소 `Nav.Uri`(`UpdateProgressOverlay.razor:156` `:248`) — 새 판에서 **그 화면을 지웠을 때만** NotFound. 올라가는 업데이트에선 드묾 · 메뉴로 빠져나옴(갇힘 아님).
  - ② 익명 401 — 출입 토큰 15분(`AuthExtensions.cs:10`) vs 업데이트 1분 안팎 · 401 이면 `HitPanApiAuthHandler` 가 refresh(토큰 줄은 DB · 재기동에 안 지워짐). 끊기는 길 = 업데이트 도중 다른 창 로그아웃 · 동시로그인 밀어내기 정도. 끊겨도 10분 상한 → [다시 확인] · F5.
  - ③ CF 4시간은 `blazor.webassembly.js`·`dotnet.runtime.js` 둘뿐(선행검증서 M-2) · 우리 화면(`.wasm`·`blazor.boot.json`)은 `no-cache` ⇒ forceLoad·F5 로 새 화면. 위험은 **.NET 런타임 패치가 판 사이에 바뀐 게시**에서만 · ⚠️미재현.
- 처리: 별건 트랙 **안 연다**. 시험·실물에서 문제가 생기면 그때 ①② = 물리적 봉합 · ③ = 물리적 봉합으로 재설계. 그때도 #43 원문 판단이 먼저.
- 지켜볼 것(③): 게시 전 직전 판과 .NET 런타임 패치가 같은지 본다(달라지면 이 항목을 다시 연다).

## §5. 함정 (오늘 새로)
- **되돌리기 화면 고침은 「누르는 쪽 판」에만 들어간다** — 되돌린 판에는 그 화면·팝업·주소가 없을 수 있다(1.3.49 에 `/data/rollback` 0건 → F5 = 「페이지를 찾을 수 없습니다」). 이동은 늘 `"/"`.
- **되돌리기 대상 = 그 PC 직전 설치 판**(「늘 ≥1.3.50」은 틀린 전제 — 건너뛴 PC 는 더 옛 판).
- **NCP 회전 KEEP=2** 가 게시 때 두 판 전 zip 을 지운다 → 확인표(`previous-manifest`)가 가리키는 zip 이 404 가 될 수 있다(1.3.50→1.3.49 첫 회 길은 1.3.51 게시로 닫힘).
- **「서버 키 불일치」는 틀린 진단이었다** — `ssh-keyscan` 지문 대조로 먼저 가른다. 하네스는 명령마다 따로 판정(읽기·쓰기·대기 루프·기록 커밋이 각각 거절될 수 있다 · 서버 파일 목록을 문서에 적으면 「Excess Sensitive Detail」).
- **`requiresMigration` 은 true 로** — false 면 워치독 B안이 `Migrations/SQL` 의 .sql 을 보고 강제 중단.
- 검증은 차수마다 더 좁은 가장자리를 찾았다(25→31) — 에이전트 상한(M=5)에서 멈추고 CTO 결재문에 「독립 재검증 없음」을 적었다.
- 시험 기대값을 제품 상수로 쓰면 대조군이 안 깨진다(C5 — 「10분」을 글자값으로 고침).
