## 2. 실측으로 확정된 사실 3개 (추측이 사실로 바뀐 자리)

### 2-1. 🔴 [1-V] 의 **ⓑ 경우가 참이었다** — 설치는 착수 즉시 500 이었다
교정 전 서버에는 **`BACKOFFICE_License__Pepper` 만** 있었고 코드가 읽는 **`License__Pepper` 는 0건**이었다.
⇒ 그 상태로 B2②(제3자 설치)를 열었으면 **1단계에서 500** 으로 끝났다. **[1-V] 가 막았다.**

### 2-2. 🟢 **SMTP 6칸은 이미 정본 이름으로 들어 있었다** (`override.conf`)
`Smtp__Host` · `Smtp__Port`(**587** 🟢) · `Smtp__User` · `Smtp__Password` · `Smtp__From` · `Smtp__FromName`
⇒ **B1①2단의 전제가 바뀐다** — 「값을 넣는 일」은 이미 끝나 있었고, **메일 0통의 원인은 값도 포트도 아니다.** 남은 것은 **실발송 1통으로 원인을 좁히는 것**뿐이다. 🔴 사장님 손 ①(SMTP 값 투입)은 **사실상 소멸**했다.

### 2-3. 🔴 **자격증명 건강화면 4칸이 거짓초록이라는 실물 증거**
| 화면이 읽는다는 이름 | 서버의 실제 이름 | |
|---|---|---|
| `HITPAN_JWT_SECRET` | `HITPAN_BO_JWT_SECRET` | 🔴 다름 |
| `HITPAN_NTS_API_KEY` | `NTS_API_KEY` | 🔴 다름 |
| `HITPAN_LICENSE_PEPPER` | (없음 · `License__Pepper` 로 존재) | 🔴 다름 |
| `HITPAN_BIZNO_PEPPER` | (없음 · `Backoffice__BizNoPepper` 로 존재) | 🔴 다름 |
⇒ **4칸 전부 이름이 다르다.** 별건 P0 의 「4칸 거짓초록」은 이제 **추측이 아니라 실측**이다.

## 3. 서버에 한 조치 (사장님 실행 · #29 본인 승인)

```
sudo sed 's/^Environment="BACKOFFICE_/Environment="/' secrets.conf | sudo tee 99-fix.conf > /dev/null
sudo chmod 600 99-fix.conf
sudo systemctl daemon-reload && sudo systemctl restart hitpan-backoffice-api
```
- 🟢 **`secrets.conf` 는 한 글자도 안 지웠다**(#1) — 접두사를 뗀 **사본 1장을 더 얹는** 방식
- 🟢 **되돌리기 1줄**: `sudo rm 99-fix.conf` + 재시작 → 즉시 원위치
- 🟢 값은 **사람도 PM 도 보지 않았다** — `sed` 가 파일 안에서 이름만 바꿔 복사했다
