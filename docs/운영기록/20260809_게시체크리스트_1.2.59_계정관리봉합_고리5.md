## 4. 🔴 적용 후 반드시 확인할 것

### 4-1. 고리5 가 실제로 돌았나 (이번 게시의 핵심)

Sandbox 에서 확인:

```powershell
Get-EventLog -LogName Application -Source HitPanWatchdog -Newest 30 |
  Where-Object { $_.Message -like "*Migration*" } | Format-List TimeGenerated, Message
```

기대 로그:
```
[Startup/Migration] ✅ DB 스키마 갱신 완료 — 신규 적용 1건(DB-85), 건너뜀 55건.
```

DB 직접 확인:
```sql
SHOW COLUMNS FROM local_company WHERE Field IN ('address_detail','seal_url','header_url');
```

### 4-2. 사장님이 지적하신 것이 화면에서 고쳐졌나

| # | 확인 방법 | 기대 |
|---|---|---|
| 1 | 회사 정보 → 우편번호 찾기 → 상세주소 입력 → 저장 → **새로고침** | 상세주소칸에 값이 **남아있다** (종전엔 사라지고 주소에 합쳐졌다) |
| 2 | 같은 화면에서 **여러 번 저장** | 주소가 **길어지지 않는다** (종전엔 중복 누적) |
| 3 | [로고 등록] 클릭 | **파일 선택창이 열린다** (종전엔 안 열렸다) |
| 4 | 계정관리 메뉴 | [결재라인 설정]이 **없다** (9→8개) |
| 5 | 회사 정보 화면 | [사용자추가·관리] 버튼이 **없다**, 시리얼 입력란이 **없다** |
| 6 | 구독정보 카드 | "Business / 7·10" 가짜값이 **아니다** |

### 4-3. 권한이 실제로 먹나 (가장 중요)

```
권한 설정 → 직원 하나 선택 → "상품마스터 조회" 체크 → 저장
→ 그 직원으로 로그인 → 상품마스터 들어가기
```

**기대: 들어가진다.** 종전에는 저장 성공 메시지가 떠도 계속 403 이었다.

⇒ 이게 되면 ①번 봉합이 **코드가 아니라 실제로** 확인된다.

## 5. 실패하면 어떻게 되나 (미리 적어둔다)

| 상황 | 일어나는 일 | 대응 |
|---|---|---|
| 마이그 실패 | 그 지점에서 중단 + success=0 기록. **ERP 는 기동한다.** 새 컬럼 쓰는 화면만 오류 | 이벤트 로그에서 사유 확인 |
| 교체 실패 | 워치독이 `.old` 로 롤백 | 구버전으로 복귀, 재시도 |
| 팝업 안 뜸 | 60초 주기 확인(1.2.58부터) | 로그인 다시 |

⚠️ **업데이트 전 워치독이 자동 백업**을 한다(사장님 결재 흐름). 백업 실패 시 업데이트는 물리적으로 차단된다.
