## §5 [적발 A ⓐ — 옛 바닥 가지 push 전 규칙]
**적용 대상**: `#859` 머지 앞 바닥에서 갈라진 가지를 **다시 push 할 때마다**(S4 장치 가지 · 공개 검토 가지 · 시험 앱 가지 · fixture 가지 포함). push 하지 않는 가지는 손대지 않는다.

1. **넣는 것** — push 시점 `origin/main` 의 비밀 검사 파일 4개를 그대로: `.github/workflows/trufflehog.yml` · `.github/scripts/trufflehog/{range,scan,self-test}.sh`. 규칙·제외 파일(`.github/trufflehog-config.yaml` · `.github/trufflehog-exclude-paths.txt`)은 `git diff --quiet origin/main <가지> -- <두 파일>` 로 재서 **차이가 있으면 main 것으로 맞춘다**(차이가 그 가지의 의도라면 §9 K5 — push 멈추고 PM 보고).
2. **S4 장치 가지** — 위 파일을 **「장치 값 커밋」 에 함께** 넣는다(별도 커밋 금지 · SHA 가 한 번만 바뀐다). 그 SHA 가 HQA SHA 대조의 대상에 들어간다는 것을 HQA 회신 문구에 적는다. 커밋에는 도구 이름·공동 작성자 줄 0.
3. **push 전 확인 3줄**(셋 다 통과해야 push):
   - ① `git diff --quiet origin/main <가지머리> -- .github/workflows/trufflehog.yml .github/scripts/trufflehog/` → 종료 0
   - ② `git grep -nE '^\s*-?\s*uses:\s*["'"'"']?trufflesecurity/' <가지머리> -- .github/workflows/` → **0줄**
   - ③ 규칙·제외 파일 `git diff --quiet` → 종료 0
   - ⚠️ 「`trufflesecurity` 문자열 0건」 으로 재면 **main 자체가 걸린다** — 새 워크플로도 엔진 이미지 주소(`ghcr.io/trufflesecurity/…@sha256`)와 이력 주석에 그 글자를 가진다. 재는 것은 **`uses:` 줄**이다.
4. **push 뒤 확인**: 그 push 런의 비밀 검사 잡 단계에 `TruffleHog OSS scan` **0** · `Self-test` 단계 **있음** · 검사 주석 중 `path`+`start_line` 을 가진 것 **0**.
5. ㄱ′ 머지 전에 push 하면 `be21d2e8` 판 4개를 넣는다(위치 주석 길은 이미 없음) · 머지 뒤 push 는 새 판. 어느 쪽이든 「push 시점 main」 이 기준.
