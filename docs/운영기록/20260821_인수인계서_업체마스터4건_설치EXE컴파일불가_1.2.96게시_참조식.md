## 1. 오늘 한 일 — 사장님 오더 5건

> *"업체주소 카카오맵 연동 / 업체팩스 실제 전송 / 담당자 이메일 자동 전송 /
>   자동발주 중복 방지 / 기본창고 코드리뷰"* + *"루틴대로 설계→코딩→검증 =동시검증"*

### W1 업체주소 좌표 — 🔴 **설계 전제가 틀린 걸 코드 쓰기 전에 잡았다**

초안은 *"우편번호 서비스가 좌표를 함께 준다"* 는 **키 0건** 안이었다.
공식 문서 확인 결과 **`oncomplete` data 에 좌표 필드가 아예 없다.**

> 그대로 짰으면 좌표는 늘 NULL, 지도는 여전히 안 찍히는데 **코드는 정상으로 보이는** 상태가 됐다.
> 전형적인 **가짜 봉합**이 될 뻔했다. 조사 한 번이 그걸 막았다.

**진범**: 카카오 스킴은 `lat,lng` 를 요구하는데 **주소 문자열**을 좌표 자리에 넣고 있었다.
사장님 결재로 **카카오 REST 지오코딩** 채택. 키는 `geocoding_settings` 에 테넌트별 암호화(#18·#21·#22).
키 없으면 주소검색 폴백 — 좌표 없어도 안 끊긴다(#20).

### W2 담당자 이메일 — `mailto:` → 실발송
기존 `IEmailService`·`EmailSendDialog` **재사용, 신규 서비스 0**. `mailto:` 는 보조로 존치(#1).

### W3 팩스 — 인프라 신설, 🔴 **Mock 이 성공을 위장하지 않는다**
`IFaxProvider` 로 벤더 교체점 분리. `MockFaxProvider` 는 **`Success=false`**, 이력 `status='mock'`,
다이얼로그가 **누르기 전에** 경고한다.

> 여기서 "성공"을 돌려주면 화면은 초록불인데 거래처는 못 받는다.
> **가장 위험한 거짓봉합**이라 원천 차단했다(#23).
> ⚠️ 후임자: Mock 을 `Success=true` 로 바꾸는 건 개선이 아니라 **안전장치 제거**다.

### W4 자동발주 중복 (P0)
판매 경로가 **실시간 재고만** 봤다. `is_auto=1` 을 **쓰기만 하고 읽지 않았다.**
(BOM 경로는 `stock_alerts.status` 로 이미 정상 — 두 경로를 일치시켰다)

🔴 **DESCRIBE 가 설계 초안을 교정했다**: enum 에 **`partial`(부분입고)** 이 있었다.
빠뜨렸으면 **부분입고에서 중복 발주가 그대로 재발**했다.

### W5·W6 기본창고 — 사장님 지적이 맞았다. 원인은 예상과 달랐다
`ItemDetail.razor:121` 에 그대로 적혀 있었다:
```csharp
private string? _selectedWarehouseId; // 참조용 — DB에 저장하지 않음
```
드롭다운이 **아무것도 저장하지 않았고**, `items` 40컬럼에 **창고 컬럼 자체가 없었다.**
저장 버그가 아니라 **저장할 자리가 없었다.** 화면이 사용자에게 거짓말을 하고 있었다.

결재 **A안**: 컬럼 신설 + 발주·매입 2곳 배선.
`라인지정 → items.default_warehouse_id → 테넌트 MAIN → 명확한 오류` (기존 폴백 위에 한 단계만 얹음, #1)

## 2. 🔴 오늘의 진짜 사건 — 설치 EXE 가 컴파일조차 안 되고 있었다

1.2.96 게시가 EXE 굽는 단계에서 죽었다:
```
Error on line 1876: Unknown identifier 'InputQuery'  → Compile aborted.
```

`InputQuery` 는 **델파이 VCL 함수**다. **Inno Setup 에는 없다.**

### 파괴력 — 1.2.96 만의 문제가 아니었다
- **어떤 버전도 게시 불가** (EXE 자체를 못 굽는다)
- **두 번째 사업자 설치**(어제 P0)도 이 EXE 가 나와야 시작한다

### 어디서 왔나
어제 `310f8d49`(PR #199) R-2 봉합. **설계는 옳았다** — `20260425작3:102` 에 처음부터 있던 흐름이다.
구현이 **없는 함수**를 썼다.

### 🔴 왜 어제 안 걸렸나 — 가장 중요한 교훈

| 검사 | 하는 일 | 잡나 |
|---|---|---|
| PR CI `Installer Inno Setup Lint` | **파싱만** | ❌ |
| 실제 게시 (ISCC) | `[Code]` **컴파일** | ✅ |

**PR 검사 9개가 전부 초록인데 게시에서 터졌다.**
⇒ *초록불이 어디서 오는지* 봐야 한다 (feedback_gate_must_test_behavior).

> 🔴 **어제 인수인계서 §6 에 "`InputQuery` 확인 없이 사용"이 이미 적혀 있었다.**
> **적어만 두고 고치지 않아서** 오늘 터졌다. **기록은 봉합이 아니다.**

### 봉합
`AskPassword()` 신설 — `CreateCustomForm` + `TPasswordEdit`.
마법사 페이지는 못 쓴다: 이 코드는 `CurStepChanged(ssInstall)`, **마법사가 끝난 뒤**에 돈다.
R-2 로직(3회 재시도·실패 시 `DB-ROOT-AUTH` 중단)은 **그대로 두고 부르는 함수만** 바꿨다(#1).

### 함께 막은 것 2건 (조사에서 새로 드러남)
1. **무인설치 무한대기** — 모달은 `/SILENT` 에서 답할 사람이 없는데 **영원히 기다린다.**
   실패가 아니라 **멈춤**이라 고객이 스스로 못 빠져나온다. `WizardSilent` 가드 + `SuppressibleMsgBox`.
   ※ 현재 무인설치 경로는 레포에 없다. 지금 나는 사고는 아니다.
2. **CI Inno 버전 미고정** — 6.6.0 에서 `CreateCustomForm` 시그니처가 바뀐 전례.
   **우리가 커밋 하나 안 해도 남이 우리 게시를 깰 수 있는 구조**였다.

### 검증 — 글자검사 아님, 실제로 컴파일
이 결함이 **글자검사를 통과해서** 터졌으므로 같은 방식으로 확인하지 않았다.

| 검사 | 결과 |
|---|---|
| 봉합 전 로컬 재현 | ✅ `line 1876` — **CI 와 동일** |
| 봉합 후 | ✅ `exit=0`, EXE 실제 산출 |
| 🔴 **대조실험** | ✅ 호출부만 되돌리니 **다시 Compile aborted**(line 1984) |

**대조실험이 핵심** — `AskPassword` 함수는 남긴 채 호출부만 되돌렸으므로, 통과 이유가 봉합임이 확정된다.

## 6. ⚠️ 미검증 — "됐다"고 말하면 안 되는 것

**컴파일되는 것 ≠ 설치가 완주하는 것.**
`AskPassword` 대화상자가 실제로 뜨고, 비번을 받아, 설치가 끝까지 가는지는 **확인하지 않았다.**
**백지 PC 종단 실측이 진짜 게이트다.** 개발PC 컴파일 성공은 검증이 아니다.

좌표·이메일·팩스 3건도 코드만 있고 **실측이 없다.**

## 7. 🔴 알고 있는 미봉합 — 시크릿 스캔 (진탐)

`Scan secrets` 가 전체 히스토리 스캔에서 **119건**을 잡는다. **오탐이 아니다.**

`.github/trufflehog-exclude-paths.txt` 에 우리 팀이 직접 적어놨다:
> *"이 둘은 오탐이 아니라 진짜 문제다. 제외하면 덮는 것이다.
>   ⇒ 스캔은 계속 빨간 X 로 남는다. **그것이 의도다.**"*

- 규칙: `hitpan-db-password` — 잡는 문자열은 `.github/trufflehog-config.yaml` 참조
  > ⚠️ **여기에 그 값을 그대로 적지 않는다.** 적는 순간 이 문서가 스캔에 걸린다.
  > (실제로 1차 작성분이 정확히 그렇게 걸렸다 — 제외 파일이 이미 같은 경고를 적어뒀는데
  >  그걸 읽고도 반복했다. `.github/trufflehog-exclude-paths.txt` 오탐1 주석 참조)
- 실측: **73개 파일** (실행코드 **29개** + 문서 44개)
- `installer/install.bat` — 모든 고객 PC 에 **동일 DB 비번**으로 계정 생성

**차등 스캔(변경분)에서는 통과**한다(`42ddd7e4` success 실측). 전체 히스토리 스캔에서만 뜬다.
**머지는 막지 않는다.** 오늘 P0 우선이라 손대지 않았고, **별건 작업지시서**로 봉합해야 한다.

> ⚠️ 이건 "빨간 X 니까 무시"가 아니다. **덮지 않기로 결정한 진짜 문제**다.
