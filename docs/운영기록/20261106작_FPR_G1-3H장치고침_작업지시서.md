## §4 [설계]
### C1 — 선택과 계수를 한 규칙으로 (A1)
- 판정기에 **공용 분류 함수**(이름 목록 → 「실행할 것」 · 「이상한 것」)와 폴더 감싸개를 둔다. 판정기의 K 본문 셈은 이 함수로.
- S8 의 셸 글롭 반복을 **새 실행기 파일 1개**로 바꾼다. 실행기는 같은 함수를 부르고, 이상한 이름이 하나라도 있으면 아무것도 돌리지 않고 실패 · 정상 이름은 하나씩 돌려 하나라도 실패면 실패. 표준출력은 그대로 흘린다(tee 0 · 업로드 폴더에 쓰기 0).
- 새 파일 이름은 K 본문 머리를 쓰지 않는다(C8). 기존 셸 줄은 YAML 주석 「⬛」 으로 남긴다.
- 대안 ⓐ(S8 이 실행 목록을 결과표에 남기고 판정기가 대조): 두 규칙이 그대로 남고 목록이 업로드 · 누출 검사 대상이 된다 → 차선. 대안 ⓒ(정규식만 맞춤): CTO 가 차선으로 적음 · 비추천.

### C2 — H 기대 키 틀 (A2)
- 키 = 범위 · 이름표 · G · 경로 · 브라우저 다섯 칸. 같은 키 두 줄 = 중복 = 빨강.
- 틀(판정기 안 상수 · 참고 런 24행 기준 · 키 이름은 로컬 세부): ① 브라우저 없음 필수 ② 두 브라우저 각각 필수 ③ 첫 브라우저만 필수 ④ 브라우저마다 「관찰 갈래 묶음」 · 「일반 갈래 묶음」 중 **정확히 하나**(둘 다 / 둘 다 없음 = 빨강) — 약관 결함이 고쳐져 두 브라우저가 다 일반 갈래가 돼도 초록(C21d).
- 브라우저 집합 = 장치가 도는 두 브라우저 고정. 결과표의 브라우저 칸이 그 밖이면 빨강.
- 모르는 H 키 = **빨강**(예외 목록 0). 끊김 줄 · 심은 빨강 줄은 정상 런에 없고 그 자체로 빨강인 줄이라 더 빨개질 뿐이다.
- **G 자리**: 틀에 G 칸을 빈 채로 둔다. K 본문이 있는데 G 칸이 비어 있으면 빨강 · H 아닌 범위 줄이 G 틀 밖이면 모르는 키. → K 연결 PR 은 G 키를 채우지 않으면 초록이 될 수 없다(D3 「G 키 = K PR 안」 을 장치가 강제).
- 판정 순서: [시험] 실패 → 줄 꼴 이상 → **키 틀(새)** → 돈 시험 0 → K·G 0 → [장치] 실패. 화면에는 누락 · 중복 · 모르는 · 갈래 수를 한 줄로(키 글자는 소독 뒤).
- 대안: 모르는 키 = 노랑 표시만 → 틀 밖 줄이 초록 사이로 새는 길 · 비추천.

### C3 — N2 던지기 (A3)
- 기록 함수는 결과 칸의 형이 참거짓이 아니면 **줄을 넣기 전에** 고정 이름의 예외를 던진다. 메시지 = 소독된 이름표 + 형 이름만(값 0).
- 흐름 안 = 기존 흐름 잡이가 끊김 줄(거짓 리터럴)을 남긴다 → 판정기 빨강. 흐름 밖 = 프로세스 처리기가 종료 코드 1 → S8 실패. 시드 2종 = 처리기 유무를 [3] 이 확인해 개발명세서에 적는다(종료 코드 ≠ 0 이 기대값).
- 콘솔은 PASS 를 찍기 전에 멈추므로 콘솔 · 판정이 엇갈리지 않는다(C3). 관찰 줄도 같은 계약.
- 대안 「형 보존」: 콘솔이 글자 거짓을 PASS 로 찍고 판정기만 빨강 = 표시 엇갈림 → 비추천.

### C4 — N3 소독 상한 (A4)
- 기록 함수: 이름표 · G · 경로 · 브라우저 · 범위 = 기존 소독 함수 · **상한 120자** · 설명 = **300자**(결과 칸과 같음 · 지금 가장 긴 설명 약 200자 실측). 콘솔 줄도 소독된 줄 값으로 찍는다.
- 판정기: 좋은 줄 다섯 칸 · 시드 두 칸 · 외부 호스트 목록 = 소독. 판정기는 런 환경에 등록된 값만 안다 → 대조 시험은 등록값 기준(C4).
- 키 칸이 가려지거나 잘리면 키가 바뀐다 → C2 틀에서 모르는 키 = 빨강(조용히 지나가지 않음).
- 대안: 경로 5·6 은 기록만 → 같은 파일 한 줄씩이라 넣는 쪽 추천.

### C5 — 자체시험 별도 잡 (A5 · PM 결정의 꼴)
- 기존 UI workflow 파일 **안** 새 잡 1개 · 잡 조건 0(대상 PR 전부 + 수동 실행) · 잡 권한 = 읽기만 명시 · 시간 상한 짧게(10분) · 비밀값 · 환경 등록 0.
- 단계 = 체크아웃(기존 잡과 같은 꼴) → 러너 임시 아래 빈 작업 폴더 → **레포 위치 그대로** 자체시험 실행(사본 실행 시 셈 칸 실패 · C5).
- workflow 셈 칸 재확인: 고친 뒤에도 대상 파일 1 · 잡힘 0 이어야 한다 — 새 줄에 셈 칸 낱말(비밀값 · 입력 칸 · 저장소 변수 · 토큰 · 위험 트리거 · 외부 주소) 0.
- 같은 workflow 의 concurrency 를 그대로 받는다. 필수 검사 지정 = 안 함(기존 결재 그대로).
