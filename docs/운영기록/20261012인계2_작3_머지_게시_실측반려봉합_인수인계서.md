## §2 사장님 실측 결과 (이 문서의 중심)

| | 결과 |
|---|---|
| **① ERP → 백오피스 CS 창구 쪽지 보내기** | 🟢 **통과** |
| **② 백오피스 → ERP 쪽지 보내기** | 🔴 **반려** — 「백오피스에서 보낸 메시지를 어디서 보는지, **메뉴가 없음**」 |

### 반려 ② 를 내가 가린 것

**메뉴는 있었다. 말을 안 했다.**
본사 안내는 실제로 `cs_requests`+`cs_replies` 로 착지해 **「CS 요청」 목록에 「본사에서 보냄」 칩(확성기)까지 달고 선다.**
목록 질의도 `tenant_id` 만 거르므로 빠지지 않는다(코드 직독 확인).
그런데 **받는 쪽을 말하는 글자가 한 자도 없었다**:

- 사이드바 메뉴 이름 = 「CS **요청**」 (보내는 쪽)
- 그 화면 부제 = 「…쪽지로 **보내면** 담당 상담원이 답을 보냅니다」 (보내는 쪽)

⇒ 「이 화면, 처음 보는 사람이 혼자 쓸 수 있냐」에 걸린다. **사장님이 못 찾으셨다 — 그게 증거다.**

### 🔴 그 과정에 더 나쁜 것을 찾았다 — 전역 배너가 거짓을 말하고 있었다

안읽음 숫자(`cs_replies.read_at`)와 엔드포인트(`replies/unread-count`)는 **종전부터 있었고**,
`MainLayout` 의 `CsReplyBadge` 가 **모든 화면**에 띄운다. 그런데 그 배너가 **무조건**
「**CS 답변** N건이 도착했습니다」 + 「**답** 보러 가기」라고 말했다.
**본사 안내는 답변이 아니다.** 고객은 「내가 뭘 물었지?」 하며 답을 찾다가 못 찾는다.
[4] V-4(「쪽지함이 본사 안내를 「답」이라고 말했다」)와 **같은 종류가 전역 배너에 남아 있었다.**

### 봉합 — 사장님 결정: 「이름·자리 그대로 + 안읽음 표시」

- 🔴 **메뉴 이름·자리 무접촉** (결-10 · 「자리 자체가 결재 사항 — 개발팀이 정하지 않았다」)
- 사이드바 「CS 요청」에 **안읽음 배지** · 🔴 **못 읽으면 0 = 안 보여 준다**(틀린 숫자는 안 보여주는 것보다 나쁘다)
- 배너가 **사실을 말한다** — 안내만 왔으면 「**본사 안내 N건**」, 섞이면 「본사 안내 N건 · CS 답변 M건」, 단추도 「안내 보러 가기」
- 안읽음을 **출처별로** 내려준다(`hqCount`·`replyCount` **추가**) · 🔴 합계 `count` 는 **그대로** 둬 옛 화면 무해(#1) · 옛 판 응답엔 새 칸이 없어 0 으로 떨어지고 문구가 종전과 같아진다
- `origin` 칸이 없는 DB 에서도 살게 **가드를 지난다**([4] V-2 교훈)
- 부제 = 「보낸 문의와 그 답, 그리고 **히트판 본사가 보낸 안내**를 여기서 함께 봅니다」

### 게이트 G-W3-8 신설 (전부 동작 단언)

① 본사 안내가 **안읽음에 잡히나**(안 잡히면 배지도 배너도 뜰 수 없다 = 사장님이 못 찾는다)
② **출처별로 갈라 내려주나**(안 갈라 주면 화면이 사실을 말할 방법이 없다)
③ 🔴 음성 대조 — **고객 자기 문의를 본사 것으로 안 세나** · 아무것도 안 왔으면 0
④ 🔴 항등식 `count == hqCount + replyCount` — 깨지면 한 숫자가 두 자리에서 다르게 읽힌다
🔴 `replyCount` 는 **0** 이어야 한다 — 1 이면 화면이 「CS 답변이 왔다」고 거짓을 말한다

| 볼 곳 | 「입구 문제」면 | 「아직 안 간 것」이면 |

🔴 ⓑ가 「전달 대기」면 봉합 ②와 무관하게 **하행이 아직 한 번도 안 돈 것**이다. 그때는 §6-1 로 간다.

## §5 `Build` 빨간불 봉합 — 10/8 부터 있던 것

사장님 지시 「빌드까지 모두 마무리 해」.

**판이 다른 게 아니었다 — 읽는 방법이 없었다.**

| 실측 | |
|---|---|
| choco | 「InnoSetup v**6.7.1** already installed」 → 러너 판 = **출하본과 같다** |
| `ISCC.exe` 파일판·제품판 | **`0.0.0.0`** — 판 정보를 아예 안 들고 있다 |
| `ISCC.exe` 배너 | `Inno Setup 6 Command-Line Compiler` — 판 번호 없음 |

종전 단언은 ISCC 표준출력에서 `6.7.1` 을 찾고 있었다 — **원리적으로 불가능**했다.
🔴 그래서 **G-T6-5 본체(실물 Inno Pascal 왕복)가 판 검사에서 멈춰 10/8 이후 한 번도 안 돌았다** — 빨간불 하나가 그 아래 계측까지 가리고 있었다.

**봉합**: 출하 `.iss` 가 쓰는 **그 ISPP 에게 묻는다**(`#if VER < EncodeVer(6,7,1)` / `>= EncodeVer(6,7,2)` / `#error HPVER_MATCH`).
범위가 `[6.7.1, 6.7.2)` ⇒ **N4 약속(판이 같아야 한다)은 그대로, 약화 0.**
🔴 표식이 하나도 없거나 프로브가 터지면 **통과가 아니라 실패**다. 실패 문구에 **ISPP 전문 + Inno 폴더 전 파일의 판**을 찍는다.

🟢 **`Build` 초록 확인됨**(`a960ad78`) — ISPP 가 통했고 **G-T6-5 본체도 처음 돌았다.**

**손대지 않은 것**: `installer/` 의 `.iss`·설치 스크립트·배포 워크플로·워치독·시리얼 **0줄** · **출하 Inno 판 핀(6.7.1) 그대로**(핀을 내려서 맞추지 않았다). 고친 파일은 **시험 파일 하나**.

## §8 다음 사람이 바로 알아야 할 것

1. 🔴 **머지 ≠ 게시 ≠ 적용.** main 머지는 백오피스만 자동으로 올린다. ERP 는 `Deploy Auto-Update` **수동 dispatch**, 그리고 고객 PC 에서 **팝업 [예]** 를 눌러야 적용된다. 세 단계가 전부 다르다.
2. 🔴 **`requiresMigration` 는 새 `DB-NN` 이 있으면 true.** 애매하면 true. `false` 인데 SQL 이 있으면 **워치독이 업데이트를 강제 중단**한다(1.2.63 전례).
3. 🔴 **상행 통과가 적용을 증명하지 않는다.** 상행은 옛 판에서도 돈다 — 새 기능을 잴 때 「한쪽이 되니 적용됐겠지」로 읽지 마라.
4. 🔴 **「도착을 알리는 숫자」가 있어도 그 숫자를 쓰는 화면이 거짓을 말하면 없는 것과 같다.** 전역 배너가 그랬다.
5. **G-W3-1~8 은 로컬에서 돈다** — `HITPAN_W3_ERP_DB=test_w3_erp HITPAN_W3_BO_DB=test_w3_bo … HITPAN_REQUIRE_DB=true`. 🔴 DB 를 DROP 하므로 이름에 `test`·`gate` 가 없으면 지정을 거부한다. 🔴 **클래스를 하나씩** 돌려라.
6. ⚠️ **`CsMessagePipelineGate` 는 로컬에서 못 돈다** — 그 게이트가 만드는 DB 이름이 `hitpan_gate_cs_*`(접두가 `test_` 가 아니다)라 개발 계정 권한에 걸린다. 내 게이트와 같은 방식으로 뚫을 수 있다(후속 후보).
7. ⚠️ **`Scan secrets`(push) 가 새 갈래 첫 푸시에서 빨갛게 뜬다** — `BASE=0000…000` 이 되어 **레포 전체 이력**을 훑기 때문이다. 같은 SHA 의 **pull_request 스캔**과 `main` 스캔이 초록이면 새 누출이 아니다.
8. **`DB-144` 자체를 도는 게이트는 0건**이다 — 게이트는 ERP DB 를 **출하 DDL import** 로 세우므로 「칸이 출하본에 있다」만 증명하고, **기존 고객이 지나가는 마이그 경로는 안 돈다**([4] V-8ⓐ).
