## §5. 🔴 함정 — 다음 세션이 밟을 지뢰 (이 문서의 핵심)

### ① 게이트를 넣었으면 **일부러 깨뜨려 봐라** — 오늘 하루에 두 번 당했다
- **PI-06**: 사이드카로 대조하는 게이트를 짰는데 그 파일이 **403**이었다. 안 읽히면 대조가 **조용히 건너뛰어져** 아무것도 안 막는다.
- **PI-07**: 소스스캔 시험이 **주석에 든 `GuidFormat=None` 을 보고 통과**시켰다. 일부러 옵션을 빼고 돌렸는데 **통과**했다.
- ⇒ **통과만 확인하면 "막는 척만 하는 게이트" 를 진짜로 착각한다.** 반드시 **깨뜨려 실패 확인 → 원복 통과** 양방향으로 증명하라.

### ② 🔴 EXE 검증은 **ASCII grep 으로 하면 안 된다**
`.NET 문자열 리터럴은 UTF-16LE` 다. `grep -a "GuidFormat=None"` → **0건**(있는데도).
게다가 우연히 잡히는 것은 **MySqlConnector 자체 클래스명**이라 "있다"고 오판한다.
- ⇒ **UTF-16 + UTF-8 둘 다** 세라. 검증 코드: `scratchpad/exescan/`(이번 세션 산출)
- ⚠️ **이전 게시 보고들의 "EXE 내 봉합분 N건 확인" 은 전부 이 오류였다.** 아무것도 증명 못 했다.

### ③ `requiresMigration` 을 **반드시 넘겨라** (게시 시)
`gh workflow run` 에서 이 입력을 빠뜨리면 기본값 `false` 가 들어간다.
새 마이그가 있는데 false 면 **워치독이 고객 PC 에서 업데이트를 강제 중단**한다.
다운그레이드 게이트 때문에 **그 버전은 통째로 폐기**된다(오늘 1.2.68 이 그렇게 죽었다).
- ⇒ 이제 게이트가 막지만(§2 `e6d4fae`), **입력 자체를 빠뜨리지 마라.**

### ④ **char(36) 은 Guid 로 온다** — 새 표 만들 때
MySqlConnector 는 `CHAR(36)` 을 **Guid 로 돌려준다.** DTO 가 string 이면 500.
`varchar(36)` 은 안 그렇다 — 그래서 여태 안 터졌다.
- ⇒ 봉합됨(`GuidFormat=None`, 연결문자열 9곳). **새 연결문자열 만들면 반드시 이 옵션을 넣어라.** CI 가 잡는다.

### ⑤ 개발PC 정상은 검증이 아니다 — **이번엔 개발PC 조차 정상이 아니었다**
PI-07 은 내 개발PC 에서도 **똑같이 재현**됐다. 환경 차이가 아니라 **그 화면을 안 열어봤을 뿐**이었다.
- ⇒ 새 화면을 만들면 **반드시 그 화면을 열어봐라.** 빌드·테스트 통과는 화면이 열린다는 뜻이 아니다.

### ⑥ 도구 함정 (시간 낭비)
- **PowerShell 5.1** 은 BOM 없는 UTF-8 스크립트를 ANSI 로 읽어 **한글이 깨진다.** 한글 든 스크립트는 Bash/Python 으로.
- **Python 이 이 셸에서 안 돈다**(`python` 이 조용히 아무것도 안 함). 대량 편집은 직접 Edit 하거나 .NET 으로.
- **`strings` 명령이 없다.** 바이너리 검사는 .NET 으로 짜라.
- **cmd 에서 `!` 가 든 비번**은 지연확장에 먹힌다. `--defaults-extra-file` 로 넘겨라.

### ⑦ 스쿼시 병합 후엔 **리베이스**
작업 중 다른 PR 이 스쿼시 머지되면 **같은 내용으로 충돌**한다. 손으로 풀지 말고 리베이스 —
`patch contents already upstream` 을 알아보고 drop 한다.
- ⇒ 🔴 **백업 브랜치 먼저** → `git diff <백업> HEAD` 가 비어야 잃은 것 0 → **리베이스한 트리로 빌드·테스트 재실행** → `--force-with-lease` → **머지 후 main 을 내용으로 대조**(스쿼시는 해시를 바꾸므로 해시 비교 무의미)
