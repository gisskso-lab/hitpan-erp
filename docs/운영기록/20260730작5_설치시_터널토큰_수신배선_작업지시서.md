## 1. 무엇이 문제인가 (실측 — 추측 0)

### 1-2. ⚠️ "우리가 깨뜨린 것"이 아님을 먼저 확인했다

사장님 의심(*"정상설치건 건든거 아니야?"*)에 따라 오늘 변경분을 전수 확인:

`649ed88..origin/main` 의 installer·Watchdog 변경 = `0cd19bf`(게시배선) · `c6c48fd`(문서경로) **2건뿐.**
**터널·cloudflared·DNS 관련 코드 변경 0건.** 회귀가 아니다.

### 1-3. ⭐ 진범 — 설치 EXE 에 터널 토큰 수신 경로가 **없다**

`installer/HitPan.iss:24-25`

```ini
#ifndef TunnelToken
  #define TunnelToken ""      ← 컴파일 시 안 넘기면 빈 문자열
```

`installer/HitPan.iss:273-276`

```pascal
if '{#TunnelToken}' <> '' then          ← 비어 있으면 통째로 건너뜀
begin
  Exec(... 'service install {#TunnelToken}' ...)   ← cloudflared 서비스 등록
```

**즉 토큰은 "EXE 를 구울 때 박아 넣는 컴파일 상수"다.**
`build-installer.ps1:304` 이 `/DTunnelToken=$Token` 으로 넘기는 구조 — 고객별로 EXE 를 따로 굽는 방식.

그런데 **오늘 게시한 `1.2.43` 은 GitHub Actions 가 구운 범용 EXE** 다.
CI 에 고객 토큰이 있을 수 없고, **있어서도 안 된다**(헌법 #22 · 원클릭 설치 원칙:
*"Cloudflare API 토큰은 본사 서버에만 존재. EXE 에 절대 포함 금지"*).

⇒ **`TunnelToken = ""` → `if` 블록 건너뜀 → cloudflared 서비스 미등록 → 1033.**

### 1-4. 백오피스는 이미 준비돼 있다 — 부르는 쪽이 없다

`InstallerBootstrapController.cs` (`POST /api/installer/bootstrap`) 는 **터널을 실제로 발급한다**:

| 줄 | 하는 일 |
|---|---|
| 112-113 | `IssueTunnelAsync(tenantId, tenantCode)` → **tunnelToken 발급** |
| 121 | `UpdateDnsTunnelTargetAsync` → DNS 를 터널로 지정 |
| 133 | `UpdateTunnelIngressAsync(... "http://localhost:5257")` → ingress 설정 |
| 204-206 | 응답에 `tunnelToken` · `tunnelId` · `tunnelTokenIssued` 반환 |
| 210-215 | `bootstrap.token` · `tokenKey` (ERP 로컬 검증용) |

**그런데 설치 프로그램에 이 API 호출이 0건이다** (`grep -rn "bootstrap" installer/HitPan.iss installer/*.ps1` → 0).

> 🔴 **양쪽이 다 있는데 연결선이 없다.** 백오피스는 주려고 서 있고, 설치 EXE 는 물어보지 않는다.
> 이것이 *"랜딩 → 가입 → 설치"* 종단이 끊긴 지점이다(헌법 #20 · #35 유기적 연결 위반).

### 1-5. 왜 지금까지 안 드러났나

종전 성공 테스트는 **토큰을 넣어 구운 EXE**(`build-installer.ps1 -Token …` 또는 `bulk-create-tunnels.ps1`)였다.
**랜딩 다운로드가 404 여서**(작3) 아무도 범용 EXE 로 설치해 본 적이 없다.
작3 이 404 를 열자 **그 다음 문이 바로 드러났다** — 사장님 오더 *"고객 경로 그대로"* 의 성과다.

## 2. 무엇을 하는가 (범위)

**설치 중에 시리얼 키로 본사에 물어 터널 토큰을 받아 cloudflared 를 등록한다.**

| 대상 | 변경 |
|---|---|
| `installer/HitPan.iss` | 시리얼 입력값으로 `POST back.hitpan.kr/api/installer/bootstrap` 호출 → 응답 `domain.tunnelToken` 으로 `cloudflared service install` |
| (유지) `#define TunnelToken ""` | **제거하지 않는다**(헌법 #1 · #37) — 구운 토큰 방식도 계속 동작해야 한다(내부 검증·대량 발급) |

### 분기 규칙 (⭐ 급소)

```
1) {#TunnelToken} 이 비어있지 않다  → 그대로 사용 (종전 경로 100% 보존)
2) 비어있다                          → bootstrap API 로 수신  ← 신규
3) API 실패·토큰 미수신              → 설치 중단 + 사유 안내   ← fail-closed
```

**3번이 중요하다.** 지금은 토큰이 없어도 조용히 넘어가 "설치는 됐는데 접속 불가"가 된다.
**침묵이 이 사고의 본질**이다(헌법 #15). 실패하면 고객이 이유를 알아야 한다.

## 4. 어떻게 하는가 ([3] 개발팀용)

### 4-1. `HitPan.iss` — bootstrap 수신 (담당: 백엔드 개발자 1 + 프론트 1)

- 설치 마법사의 **시리얼 입력 페이지 값**을 사용한다(신규 입력칸 만들지 않는다 — 고객 입력은 시리얼 하나뿐, 원클릭 원칙).
- `MachineFingerprint` 는 기존 생성 로직 재사용(있으면 그대로, 없으면 기존 함수 grep 후 사용 — 헌법 #12).
- 호출: `POST https://back.hitpan.kr/api/installer/bootstrap`
  Body: `{ licenseKey, machineFingerprint }`
- 응답에서 취할 값:
  - `domain.tunnelToken` → `cloudflared service install <token>`
  - `bootstrap.token` · `bootstrap.tokenKey` → `db.conf` 기록(재설치 P0 봉합분 정합 유지)
- **HTTPS 실패·타임아웃·`tunnelTokenIssued=false` → 설치 중단**, 안내문 표시.

### 4-2. 안내문 (담당: CS팀장 감수 · 헌법 #24·#23)

개발용어 금지. 예:

> 설치를 완료하지 못했습니다.
> 시리얼 키 확인에 실패했거나 인터넷 연결이 원활하지 않습니다.
> 시리얼 키를 다시 확인해 주시고, 문제가 계속되면 고객센터로 연락해 주세요.

"토큰·API·터널·부트스트랩" 등 노출 금지(헌법 #23).

### 4-3. 하지 말 것

- ❌ `#define TunnelToken ""` 제거 (헌법 #1·#37 — "안 쓰인다 ≠ 잔재")
- ❌ EXE 에 Cloudflare API 키·계정 토큰 포함 (헌법 #22 절대)
- ❌ 토큰 미수신 시 조용히 계속 진행 (지금 사고의 원인)
- ❌ NCP·DNS 를 사람이 손으로 조작 (헌법 #29·#39)
