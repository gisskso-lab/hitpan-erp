## 1. 🚫 손대지 않는 영역 (사장님 명시)

> **"마스터, 매입, 판매, 워크플로우는 탄탄하게 완성되어 있어"**

| 영역 | 화면 | 처리 |
|---|---|---|
| 업체관리 (마스터) | 업체 마스터 · 특별단가 · 업체별 원장 | ⛔ **건드리지 않는다** |
| 상품관리 (마스터) | 상품 마스터 · BOM · 특별단가 · 상품별 원장 | ⛔ |
| 판매관리 (문서 흐름) | 견적서 · 수주서 · 거래명세서 | ⛔ |
| 매입관리 (문서 흐름) | 발주서 · 매입 처리 · 반품 처리 | ⛔ |

⚠️ **단, 판매·매입 그룹 안의 "현황·분석" 화면은 대상이다**(§2-3).
사장님이 *"현황, 분석"* 을 시급 영역으로 따로 지목하셨다.
**문서 흐름(견적→수주→명세서)은 완성, 그 결과를 보는 화면은 미완**이라는 뜻으로 읽는다.

## 4. 📝 기록 형식 — 화면당 1장 (사장님 결재)

### 4-1. 파일 위치·이름

```
docs/개발/erp/{날짜}_화면수정_{영역}_{화면명}.md
예) docs/개발/erp/20260808_화면수정_계정관리_회사정보.md
```

### 4-2. 틀 (초안 — 첫 화면 할 때 확정)

```markdown
# 화면 수정 — {영역} · {화면명}

| 항목 | 내용 |
|---|---|
| 화면 | {이름} (`{경로}`) |
| 파일 | `src/HitPan.Web/Pages/...` |
| 작업일 | |
| 사장님 확인 | ⬜ |

## 1. 사장님이 짚으신 것
> (원문 그대로)

## 2. 실측 — 실제로 어땠나
(화면을 열어 확인한 사실. 추측 금지)

## 3. 고친 것
| # | 무엇이 문제였나 | 어떻게 고쳤나 | 파일:라인 |

## 4. 안 고친 것 (있으면)
| # | 무엇 | 왜 안 고쳤나 |

## 5. 남은 것 / 다음에 볼 것
```

### 4-3. 왜 화면당 1장인가 (사장님 결재 근거)

- **챗봇 학습 자료**로도 화면 단위가 깔끔하다 (4대 과제 ②)
- 파일이 많아지는 것은 감수한다

- 하루 끝 → **일일작업보고서**에 그날 목록을 모은다
