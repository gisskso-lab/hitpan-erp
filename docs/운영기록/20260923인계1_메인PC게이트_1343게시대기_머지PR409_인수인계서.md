## 3. 🚨 이번에 찾은 P0 — 왕복이 실물에서 한 번도 안 돌았다

실측 준비로 이 PC 의 API 를 두드려 보다 나왔다. **가설이 아니라 돌려서 쟀다.**

```
/api/devices/mainpc-proof      → 401 · 컨트롤러 도달 False   🔴
/api/auth/update-status-local  → 200 · 도달 True             (대조군 — 화이트리스트에 있다)
/api/devices/zzz-없는-길       → 401 · 도달 False            (대조군)
```

- `TenantMiddleware` 가 **인증 안 된 `/api/*` 를 전부 401** 로 자르고, 화이트리스트에 `mainpc-proof` 가 **없었다**
- ②는 설계상 **토큰을 싣지 않는다** — `hitpan-mainpc-proof.js` 의 `credentials:'omit'`
- 🔴 **`[AllowAnonymous]` 는 이 미들웨어보다 뒤라 소용이 없다**
- 다른 미들웨어는 벽이 아니다(확인함): `TermsConsent`·`SessionLimit` 은 미인증 통과 · `Idempotency` 는 `[IdempotencyKey]` 붙은 곳만

⇒ `confirmed` 가 영원히 `false` ⇒ **모든 PC 가 클라이언트로 판정** ⇒ **사장님이 보신 증상 ②③ 이 하나도 봉합되지 않은 상태였다.** 구조는 맞았는데 **길이 막혀 있었다.**

🔴 **같은 파일에서 세 번째 사고다** — 그 파일 주석이 이미 두 번 적고 있다(작10 `update-status-local` · 작12 `update-consent-local`).
⇒ **ERP API 에 토큰 없이 부르는 길을 새로 낼 때는 `TenantMiddleware` 화이트리스트를 먼저 본다.**

🔴 **내가 붙인 게이트 18건이 전부 이것을 못 잡았다.** 게이트는 `MainPcOnlyAttribute`·`MainPcProofService` 를
**따로** 부르고 **미들웨어 파이프라인을 지나가 보지 않는다.**
⇒ 그래서 **G-1c**(문을 실제로 지나가 보는 게이트)를 새로 만들었다. 음성 대조군 포함 —
`verify`·`register`·목록·없는 길은 **여전히 401** 이어야 한다(통째로 열어 버린 것을 잡는다).

🟢 봉합: 화이트리스트에 **그 주소 하나만**. C-16 대조군(그 줄을 빼면 G-1c FAIL) 확인. 회귀 1551/1551.
