## 0. 히트판 ERP 프로젝트 전체 개요 (처음 보는 사람용 — "그동안 뭘 했나")

### 0-1. 이 프로젝트가 뭔가
- **히트판 ERP** = 중소 도소매·제조·서비스 업체용 ERP(전사적 자원관리) SaaS. 레거시 히트판(VB+Access)의 후속.
- 핵심 철학: **"쉬움으로 이긴다."** 현장 직원이 설명서 없이 처음 앉아서도 쓸 수 있어야 통과(CLAUDE.md "히트판의 존재 이유").
- 개발 시작 2026-04-09, 현재 누적 639커밋(2026-06-25 기준). 단일 개발자(사장님) + AI 협업(바이브코딩 — 외부엔 비공개, 헌법 #23).

### 0-2. 3시스템 구조 (헌법 #35 — 완벽한 분리 + 완벽한 연결)
| 시스템 | 역할 | 도메인 | 배포 위치 | 코드 |
|---|---|---|---|---|
| **랜딩페이지** | 가입 영역(입구) — 사업자등록증·결제·다운로드 | `landing.hitpan.kr` (정식 www.hitpan.kr) | NCP 클라우드 | HitPan.Landing |
| **백오피스** | 워크스페이스(관리실) — 프로비저닝·고객·대리점·CS | `back.hitpan.kr` | NCP 클라우드(DB도 클라우드) | HitPan.Backoffice |
| **히트판 ERP** | 판매하는 상품(업무 처리) | `{고객사ID}.hitpan.kr` | **고객사 PC 로컬 + cloudflared 터널** | HitPan.API / HitPan.Web |
- **데이터 흐름**: 가입(랜딩) → 계정ID 발급(백오피스, =라이선스) → ERP 자동 반영. 끊김 0(헌법 #20·#35).
- **본사 데이터 최소주의(헌법 #18·#22)**: ERP 업무데이터(매출·매입·원장·거래처·직원·세금계산서)는 **절대 본사로 전송 금지.** 본사는 SaaS 메타(가입·결제·라이선스·CS)만. 백업조차 E2E 암호화.
- **계정 계층(헌법 #38)**: ERP 는 부모(tenant_admin)·자식(tenant_user) 2계층뿐. 본사/대리점 계층(platform_admin/reseller_admin)은 백오피스 전용 — ERP JWT 에 미발급(보안 격벽 2026-06-18). reseller_id 는 영업출처 수신캐시(헌법 #37, 보존 — 제거 금지).

### 0-3. 기술 스택

- 주요 경로: Sidebar(src/HitPan.Web/Layout/Sidebar.razor), API Program.cs(src/HitPan.API/Program.cs), Web Program.cs(src/HitPan.Web/Program.cs), 워치독(src/HitPan.Watchdog/), 설치(installer/HitPan-Universal.iss), 출하DDL 단일진실원(installer/hitpan_db_clean.sql, 121테이블).

### 0-4. 6단계 개발 워크플로우 (순서 엄수 — 헌법 #8)
1. **설정**(사용자·사원·권한·양식) → 2. **마스터**(업체·상품·BOM·특별단가·원장) → 3. **매입**(발주→매입/반품→재고) → 4. **판매**(견적→수주→거래명세서→세금계산서) → 5. **현황/필터**(재고·매입·판매·계산서 현황) → 6. **재무**(회계·경비·경리).

### 0-5. 데이터 3흐름 (헌법 #20 — 한 단계라도 끊기면 무결성 깨짐 = P0)
상품마스터 재고는 다음 3흐름의 결과로만 변한다:
1. **매입**: 발주→매입(or 반품) → 재고↑
2. **BOM 생산**: 완제품↑ + 자재↓ (동일 트랜잭션)
3. **판매**: 견적→수주→거래명세서 → 재고↓ → 세금계산서 → 매출·경리·세무
원장(stock_ledger·journal_lines)은 **INSERT-ONLY**(UPDATE/DELETE 금지, 헌법 #3). 원장 반영은 **confirmed 시점에만**(헌법 #6).

오늘 한 것은 **API 레벨·코드 레벨까지**다. 아래는 **한 번도 실제로 안 돌려봤다 = 사장님 실측 대상:**

2. **UI 클릭 전수 0회** — 버튼·콤보박스·저장 이벤트가 실제 값을 보내나(둔갑저장·무반응·0건유실). PM 이 제일 약한 축. setup 둔갑이 UI 에도 있을 수 있음.
3. **EXE 빌드→빈PC 설치→ERP 죽여 자가복구 실증 0회** — f905e96·3967adf 가 코드는 됐으나 실제 설치본에서 도는지 미실증. 베타 GO 의 진짜 관문.
4. **운영DB ALTER 갭** — clean DDL 에 넣은 컬럼(discount_rate 등)이 기존 운영DB 엔 ALTER 안 됨. 신규설치 OK, 기존DB 저장 500. (헌법 #29, 사장님 결재 후 ALTER + clean DDL↔운영DB 전체 diff 필요.) 상세: [[project_clean_ddl_vs_live_db_gap_20260623]].
