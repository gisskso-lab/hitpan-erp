## §6 🔴 제가 틀린 것 — 8건

1. 🔴 **재지 않고 추천했다.** 「고객 PC 보관 + 본사가 터널로 당김」을 추천 딸지까지 붙였는데, 사장님 "가능해??" 로 재보니 **원리적으로 불가**였다(#38 ERP 에 본사 계정 없음 · #40 본사 비번 0건 · 백오피스가 고객 ERP 로 거는 코드 0건).
2. 🔴 **「승인」과 「취소」를 한 문장에 섞었다** ⇒ 묵은 런이 승인돼 **운영이 되돌아갔다**(§3-3). 위험을 적어 두고도 동작 이름을 뭉갰다. → [[feedback_stale_pending_run_is_rollback_bomb]]
3. 🔴 **작4 봉합이 막다른 길이었다.** 500 을 사람 말로 바꾸고 「사장님 손」으로 두 번 넘겼다. 「안 터지는 것」과 「되는 것」을 같은 것으로 적었다.
4. 🔴 **G-W3-11 첫 판이 아무것도 안 쟀다.** 범위 체를 빼도 11/11 초록이었다(`ReadyAsync` 가 전 파일을 미리 적용해 해시 일치로 건너뛴다). 44번 이력도 지워 **대기 상태**를 만들고서야 물었다.
5. 🔴 **G-W3-2 가 사전으로 읽어 작6 사고를 못 잡았다.** 컨트롤러를 바로 불러 dictionary 로 읽으면 화면이 지나는 **JSON → 비널러블 모델** 경로를 안 지나간다. **이 교훈을 같은 세션 문서에 두 번 적어 놓고 또 했다.**
6. 출하 DDL 에 칸은 더하고 **`schema_migrations` 시드 한 줄을 빼먹었다**(CI DDL Smoke 가 109≠108 로 잡아 줬다).
7. SQL 문자열 안에 **`//` 를 주석으로 썼다**(MySQL 은 주석으로 안 읽는다). 빌드 전에 스스로 발견.
8. **「게시 올렸습니다」를 승인 완료처럼 읽히게 적었다** — 사장님이 "승인까지 했어??" 로 되물으셨다. dispatch ≠ 승인 ≠ 반영.

## §10 다음 사람에게 — 🔴 이것만은

1. **「돈다」는 사장님 판정에만 쓴다.** CI 초록 · 빌드 0/0 · 게이트 12/12 은 **코드가 맞물렸다**는 뜻이고, 10/12 에 그 전부가 초록인데 왕복은 0회였다.
2. **게이트가 컨트롤러를 바로 부르면 화면 경로를 못 잰다.** 응답을 **직렬화→화면 모델로 역직렬화**해야 비널러블 칸의 NULL 이 잡힌다(§6-5). `ReadAsWeb` 가 그 본이다.
3. **묵은 승인 대기 런은 되돌림 폭탄이다.** 작업 끝에 **대기 0건**을 확인한다. 사람에게 넘길 때 **「🔴 승인 금지 · 취소만」** 을 첫 줄에 쓴다.
4. **가드와 기능은 다른 사실이다.** 「안 터지게」 했다고 「된다」가 아니다(§6-3).
5. **`gh run cancel` 은 내 환경에서 거절된다**(Interfere With Workloads). 빨간 체크가 있는 PR **머지도 거절된다**(CI Bypass). 그 둘은 사람 손이다.
