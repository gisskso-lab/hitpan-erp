## 2. 무엇을 하는가

### 2-1. 클라이언트PC — 등록 전 상태로 회귀 (사장님 원문 그대로)

- [ ] 🔴 `RegisterOrRefreshAsync` 의 `revoked` 거부 갈래(`:343-346`)를 **거부에서 회귀로** 바꾼다:
  `status='pending'` + `revoked_at/reason` 정리 → **대표 승인 대기**로 되돌린다(rejected 갈래와 같은 모양).
  - ⚠️ **자동 승인이 아니다.** 문지기는 그대로 대표다 — 대기 줄에 다시 설 뿐이다.
  - ⚠️ 폐기 시 `auth_key_hash` 는 이미 지워진다(`RevokeAsync` · G-DP1) ⇒ **옛 열쇠 부활 없음.**
  - 감사기록 `device_reapply_after_revoke` 로 **폐기였다는 사실**을 남긴다(폐기 이력이 사라지지 않는다).
- [ ] 🟢 **기존 게이트 G-33-c 는 손대지 않는다** — 사장님 정정(8/20): *"게이트 의미를 재정의 하는게 아니라 **회귀 게이트만 열어두면 되**"*.
  - G-33-c 가 지키는 것은 **"폐기 기기가 그대로 통과(approved)하지 않는다"** 이고, 그것은 이 봉합 뒤에도 **그대로 참**이다(회귀 도착지는 `pending`).
  - ⇒ 판정 축만 **`allowed` 불리언 → 표의 `status`** 로 정확히 겨눈다. **뜻은 한 글자도 안 바꾼다.**
  - 🔴 새로 여는 것은 **회귀 게이트 하나**(G-42) 뿐이다.

### 2-2. 메인PC(대표 화면) — 🟢 **별도 작업 없음**

🔴 **사장님 확정 (8/20)**: *"디바이스어커운트 다른거 건들지 말고, **로그인 거부를 회귀로만 바꿔**"*
⇒ 대표 화면([다시 사용] 버튼·`restore` API)은 **만들지 않는다.**
회귀한 기기는 **승인 대기 목록에 저절로 다시 뜨므로**, 대표는 종전 [승인] 버튼 하나로 끝난다.
사장님 지적 *"등록기기관리에서 재등록할 관문이 없음"* 은 **이 회귀 하나로 해소**된다
(관문이 없던 진짜 이유 = 폐기 기기가 로그인 401 이라 **대기 목록에 올라오지 못한 것**).

## 5. [3-V] 반증 결과 — **반려 의견 접수 · 사장님 결재로 범위 확정**

보안상무 반증은 **반려** 의견이었다(핵심: *"폐기는 판단해서 거부한 상태 — 재접속만으로 뒤집으면
도난·퇴사 기기를 막을 수단이 `revoked` 하나뿐인데 그것이 무력화된다"*, G-33-c 충돌, 8/18 설계 역행).

🔴 **사장님이 그 위에서 직접 결정하셨다** (헌법 #33 — 의중 확인 완료):
> *"디바이스어커운트 다른거 건들지 말고, **로그인 거부를 회귀로만 바꿔**"*
> *"어차피 **관리자 재승인 없이는 등록못함**"*

**PM 판단**: 반증의 우려는 *"폐기가 자동으로 풀린다"* 를 전제했으나, 이 봉합의 도착지는
**`pending`(대기)** 이고 **승인은 여전히 대표만** 한다 ⇒ 도난 기기는 **승인되지 않는 한 못 쓴다.**
바뀐 것은 *"막힌 채로 대표 화면에 보이느냐"* 뿐이다 — 종전엔 **안 보여서 대표가 손쓸 수 없었다**(실측).

⚠️ **남는 것(정직하게)**: 폐기 기기가 재접속하면 대표 승인 대기 목록에 **다시 뜬다**(대기열 유입).
대표가 오승인하면 그 기기는 살아난다 ⇒ **영구 차단(차단 목록) 수단은 별건**으로 남긴다.
반증 §3 이 지적한 그대로이며, 사장님 결재 사항으로 이월한다.
