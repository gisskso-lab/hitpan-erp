## 2. 원인 — 서버는 옳고, **전달 경로가 끊겼다**

🔴 [[project_fixed_vs_delivered_gap]] **6차 재발.** 작7 서버 가드는 **정상 동작한다**
(2-1 이 반품번호를 정확히 뿌린 것이 그 증거다 — 같은 서비스, 같은 예외 경로다).
끊긴 자리는 **화면**이고, 이번에도 **끊기는 자리가 옮겨가 있었다.**

### C-1. 매입명세서 — 서버를 **부르지도 않는다**
`PurchaseReceiptList.razor.cs:506` `BulkDeleteAsync`

```csharp
.Where(... && string.Equals(x.Status, "draft", ...))   // ← 확정 건이 여기서 탈락
if (draftTargets.Count == 0) { Snackbar.Add("삭제 가능한 draft 상태 매입명세가 없습니다."); return; }
```

확정 매입은 **클라이언트에서 걸러져 DELETE 요청이 나가지 않는다.**
⇒ 서버 `blockingReturns` 가드는 **실행될 기회조차 없다.**
사장님이 보신 문장은 가드의 답이 아니라 **화면이 자기 혼자 만든 문장**이다.

동일 패턴: `PurchaseOrderList.razor.cs:330` (발주 목록도 같은 사전 필터).

### C-2. 발주서 화면 — 응답 **본문을 버린다**
`PurchaseOrderPage.razor.cs:465`

```csharp
if (!resp.IsSuccessStatusCode) { Snackbar.Add("삭제에 실패했습니다."); return; }  // body 안 읽음
```

서버는 `400 {"message":"... 매입전표 매입-20260826-00x ..."}` 를 정확히 준다.
화면이 그 본문을 **읽지 않고 고정 문구로 덮어쓴다.**
동일 패턴: `PurchaseReceiptPage.razor.cs:533`.

🟢 **대조군 = `ReturnPage.razor.cs:336`** — 여기만 body 를 읽는다.
그래서 **1-3 만 통과했다.** 이 파일이 정답 구현이다.

### C-3. 회계검산 — 화면이 **API 를 한 번도 안 부른다**
`GET /api/finance/integrity-check` 는 살아 있고 **15건**을 돌려준다
(`FinanceService.cs` `items.Add` **15회** 실측).
그런데 `src/HitPan.Web/` 전체에서 `integrity` 호출 **0건**.

🔴 **PM 오보**: 내가 *"검산 화면에 15건 보일 것"* 이라 보고했다.
`/accounting/ledger`(TrialBalancePage)는 **시산표만** 그리며 검산 API 와 연결된 적이 **없다.**
화면을 확인하지 않고 단정했다. → [[feedback_gate_must_test_behavior]]

## 3. 작업 항목

### W1 — 목록 사전필터 제거 (C-1)
- `PurchaseReceiptList.BulkDeleteAsync` / `PurchaseOrderList.BulkDeleteAsync`
- **선택 행 전부를 서버로 보낸다.** 막을지 말지는 **서버가 정한다.**
- 근거: 화면이 판정하면 **서버 가드와 판정 기준이 갈린다.** 지금이 정확히 그 사고다.
- 실패분은 **전표번호 + 서버 문장**으로 모아 보여준다 (몇 건이 왜 막혔는지).

### W2 — 응답 본문 표시 (C-2)
- `PurchaseOrderPage.DeleteAsync` / `PurchaseReceiptPage.DeleteAsync`
- `ReturnPage` 와 **같은 모양**으로 통일.

### W3 — `ExtractMessage` 공용화
- 현재 `PurchaseReturnList.razor.cs:176` 에 **private 으로 갇혀 있다.**
- `src/HitPan.Web/Services/ApiErrorText.cs` 로 올려 5개 화면이 공유.
- 🔴 **원문 노출 금지** — 사장님께 `{"message":...}` 날 JSON 이 보이면 안 된다
  ([[feedback_no_dev_jargon_customer_facing]]).

### W4 — 회계검산 화면 신설 (C-3)
- 신규 `Pages/Finance/IntegrityCheckPage.razor` → `@page "/accounting/integrity"`
- 사이드바 **회계장부 바로 아래** (핵심 도구는 위로 — 작4 선례).
- 15건을 **분류별**(재고·매입·매출·마스터·BOM·결재·회계)로, FAIL 을 **맨 위**로.
- 🔴 **점수(`Score`) 표시 금지** — 헌법 #32. 서버가 주더라도 **화면에 안 쓴다.**
  사장님이 원한 건 *"틀린 데이터를 빠르게 발견"* 이지 점수가 아니다.
- FAIL 행은 **무엇이 몇 건 틀렸는지**(`Detail`) 를 그대로 보여준다.

### W5 — 게이트
🔴 이번 게이트는 **"서버 함수가 맞는 문자열을 만드나"** 를 보면 **안 된다.**
그건 작7 에서 이미 통과했고 **화면에서 끊겼다.** 이번엔 **전달 경로**를 본다.

| G | 검사 | 반증 |
|---|---|---|
| G1 | 목록 삭제에 `Status=="draft"` **사전필터가 없다** | 필터 되살리면 FAIL |
| G2 | 4개 삭제 화면이 **응답 본문을 읽는다** | body 읽기 지우면 FAIL |
| G3 | 고정 문구 `"삭제에 실패했습니다"` 가 **매입라인에 없다** | 되돌리면 FAIL |
| G4 | `ApiErrorText` 가 `{"message":"X"}` → `X` | — |
| G5 | 검산 화면이 `integrity-check` 를 **호출한다** | 호출 지우면 FAIL |
| G6 | 검산 화면에 **`Score` 표시가 없다** | 넣으면 FAIL |
| G7 | 사이드바에 `/accounting/integrity` 진입점 존재 | — |
| G8 | 죽은가드 탐지 (`if (false`, `&& false`, `|| true`) | 작7 GPG10 승계 |
| G9 | **대조군** — `ReturnPage` 는 원래 통과했으니 G2 를 만족해야 한다 | 만족 못하면 게이트가 틀린 것 |
