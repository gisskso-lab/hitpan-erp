### 🔴 이어진 것 — 실측으로 확인한 자리

**휴직 → 급여** (사장님: *"자연스럽게 급여, 회계이슈도 해결될듯"*)
- 단계6 에서 **사람이 정해 둔 금액**을 단계8 급여 화면이 가져온다.
- 실측: 8월 휴직자에게 정해 둔 70만원을 급여 화면이 그대로 읽음.
- ⚠️ **자동으로 안 넣는다.** 담당자가 [이 금액으로 지급 항목 추가] 를 눌러야 들어간다.
- 코드: `PayrollService.GetContextAsync` → `PayrollPage.ApplyAbsencePay`

**휴직 → 사원 상태**
- 승인하면 `employees.work_status` 가 재직→휴직, 복직하면 되돌아온다(같은 트랜잭션).
- ⚠️ `is_active` 는 **안 건드린다.** 그 칸은 재직/퇴사고 층이 다르다 —
  건드리면 퇴사자와 구분이 사라지고 기존 화면에서 사원이 통째로 사라진다.

**경비 → 결재·경리**
- 직원 신청분이 `FinanceService` 의 `UNION ALL` 로 경리 화면에 함께 나온다.
- ⚠️ 이 UNION 을 지우면 **직원이 올린 경비가 경리에게 안 보인다.**

### ⬜ 아직 안 이어진 것 — **다음 사람이 할 일**

## 5. 🔴 이 5개 단계에서 배운 것 — **같은 실수 반복 금지**

### ① 문자열 존재 확인은 배선 확인이 아니다

단계4 에서 P0 가 났다 — SQL 에 `@WeeklyHours` 는 있는데 **파라미터 객체에 없어** 값이
조용히 NULL 로 들어갔다. **가드 15개가 전부 통과하면서 기능은 깨져 있었다.**

⚠️ `AllowUserVariables=true` 때문에 **예외조차 안 난다**(MySqlConnector 가 사용자변수로 재해석).

⇒ `AssertDapperParametersBound` 를 쓴다. SQL 의 `@파라미터`마다 **객체에 짝이 있는지** 본다.
   (`GroupwareStage4GuardTests` · `AbsenceGuardTests` · `PayrollGuardTests` 에 있다)

**단계7 에서 같은 병이 재발했다** — 결재 문서유형 시험이 `Assert.Contains("\"expense\"")` 라
문서유형을 바꿔도 통과했다. 훼손 실험에서 잡아 **호출문의 첫 인자를 직접 보게** 고쳤다.

### ② 시험은 반드시 일부러 깨서 확인한다

이번 5단계에서 **매번 훼손 실험을 했고, 두 번은 시험이 헛통과했다.**
훼손 실험을 안 했으면 그대로 넘어갔다.

⚠️ 훼손이 **실재하는지 `grep` 으로 먼저 확인**한다. CRLF 때문에 `sed` 가 안 먹었는데
   "통과"가 나온 적이 있다 — 그건 시험이 잡은 게 아니라 훼손이 안 된 것이다.

⚠️ 컴파일이 깨지는 훼손은 **무효다.** 시험이 안 돌아서 판정이 안 된다(단계7 에서 겪음).

### ③ 주석에 걸려 헛실패한다

시험이 소스를 문자열로 훑으므로 **내가 쓴 설명 주석에 걸린다.**
- 단계6: `-- leave_days decimal(3,1)` 설명문에 `Assert.DoesNotContain("leave_days")` 가 걸림
- 단계8: `-- float/double 금지` 설명문에 `Assert.DoesNotContain("float")` 가 걸림

⇒ `StripComments()` 를 쓴다. 개수를 세는 것(`Assert.Equal(3, ...)`)도 주석 때문에 틀린다 —
   **개수 대신 "각각 있는지"** 를 본다.

### ④ 신규 고객사는 직원이 0명이다

단계6 에서 P0 를 잡았다. 마이그 시드가 `SELECT DISTINCT tenant_id FROM employees` 인데
**신규 설치는 그 시점에 직원이 0명**이라 어느 회사에도 안 깔린다.
(직급 DB-93 이 같은 이유로 안 깔렸던 자리)

⇒ 신규 고객사용 시드는 **`CompanyBootstrapProvisioner`** 에 넣는다.
   그대로 뒀으면 신규 고객사에서 연차가 15일이 아니라 **0일**로 나왔다.

### ⑤ 마이그는 clean DDL 에도 넣어야 한다 (헌법 #36)

단계8 에서 기존 게이트(`MigrationLocationGuardTests`)가 잡았다.
표만 만들고 clean DDL 에 안 넣으면 **신규 설치에 그 표가 없어 화면이 죽는다.**
⇒ 마이그 파일 + `installer/hitpan_db_clean.sql` **둘 다** 고친다. ddl-smoke 가 시드 개수를 센다.

### ⑥ 정책과 컨트롤러의 판정 기준이 갈리면 안 된다

단계6 에서 실측으로 잡았다 — 정책은 `account_type` 을 보는데 내가 컨트롤러에 `role` 을 썼다.
그대로 뒀으면 **같은 관리자가 [승인]은 되고 [전원 목록]은 본인 것만 보이는** 어긋남이 났다.

⇒ 화면·컨트롤러가 **스스로 판단하지 않는다.** 서버 판정을 그대로 따른다.
   (단계8 급여 화면은 `context` API 성공 여부로 권한을 판정한다)
