## §5. 🔴 함정 (이번에 새로 — 전부 실제로 당했다)

1. 🔴 **계획(EXPLAIN)은 대리물이다. 재야 하는 것은 잠금 행 수다.** L5 는 계획이 교과서처럼 좋아졌는데(`ALL`→`ref rows 1`) **잠금이 늘었다**(3,124→3,295). 계획만 보는 게이트로는 **L4·L5 가 초록으로 통과한다.**
2. 🔴 **대조군은 「넣었다」로 부족하다.** PM 이 넣은 대조군이 가른 변수(`partner_id`)가 **정작 잠금이 찍힌 인덱스(`uq_payments_source`)에 없었다** → 두 사례가 **같은 자리**였다. **차이가 나올 수 없는 실험**으로 가설을 기각했다.
3. 🔴 **빈 표의 EXPLAIN 은 근거가 못 된다.** PM 의 측정용 DB 가 `collections` 0행이라 판정이 무효였고, **제일 나쁜 문장(L2)을 표에서 통째로 빠뜨렸다.** ⇒ 측정 DB 는 **전 표 행수를 먼저 찍고** 시작한다.
4. 🔴 **측정 DB 오염** — 검증이 시험하면서 인덱스를 더하고 값을 채워 놓은 DB 에서 다음 사람이 쟀다. **어느 DB 에서 쟀는지 매번 적어라.**
5. 🔴 **죽은 단언** — PM 이 `MaxCrossTenantBlocked = 4` 를 박았는데 재는 사례가 **정확히 4건**이라 **절대 실패 불가**였다. 같은 문서에 「고정 상수 상한 금지」라고 써 놓고 본인이 했다.
6. 🔴 **잠금은 격리해서 하나씩 잡고 재라** — 여러 개를 동시에 잡으면 **한 원인이 다른 원인을 가린다.**
7. 🔴 **게이트가 제품 상수를 쓰면 그 상수 변경은 아무도 못 잡는다** — 「복제 금지」와 「한 글자 바꾸면 빨간불」은 동시 성립 불가 → 고객 문구는 **본문 앵커**로 따로.
8. 🔴 **읽기 문장끼리는 안 막는다**(S 끼리 양립). 게이트를 읽기끼리 부딪혀 만들면 **영원히 초록**이다 → **경로 끝 INSERT** 로 만들어라.
9. 🔴 **서브에이전트가 턴 한도로 6번 멈췄고, 한 번은 50턴 동안 한 줄도 안 남겼다.** 착수문에 **「문서 뼈대 먼저 커밋 · N턴마다 갱신 · 멈추기 전 커밋」**을 반드시 넣어라. 5분 넘게 쉰 에이전트는 **새로 띄운다**(훅이 막는다).
10. **원인에 이름을 먼저 붙이면 없는 원인을 고치러 간다** — 「수기 등록 유니크 간극」은 **재현 안 됐다.** 이름을 빼고 「원인 미상」으로 되돌렸다.
