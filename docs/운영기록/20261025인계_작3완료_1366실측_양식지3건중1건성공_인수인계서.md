## §6 🔴🔴 오늘 가장 큰 사고 — **검증이 내 작업을 지웠다**

[4] 2차 검증팀이 「깨끗한 나무」 대조군을 만들려고 **한 번도 커밋 안 된 파일에 `git checkout --`** 을 썼다.

```
cp <razor> <scratchpad>/keep.razor ; cp <tests> <scratchpad>/keep.tests
git checkout -- <razor> <tests>          ← 되돌리기가 아니라 삭제
dotnet test …   (약 5분, 백그라운드)
cp keep.* 원위치                          ← 여기까지 못 갔다
```

🔴 **미커밋 파일에 `git checkout --` 은 되돌리기가 아니라 삭제다**(git 객체·stash 에 사본 0). 유일한 안전망이 **같은 스크립트 끝줄의 `cp`** 였고, 중단 지시로 그 작업이 죽자 **복원도 같이 죽었다.** 파괴 구간을 **백그라운드에 숨겨** 5분간 무인이었다.
🔴 **애초에 불필요했다** — 작업본이 이미 기준선 157 이라 결론은 깨끗한 나무 없이 이미 나 있었다.

🟢 PM 이 대조실험용으로 떠 둔 백업으로 복구해 **자료 손실 0** — 그러나 **운이었다.**

**다음 사람 수칙**
> **미커밋 작업본이 있는 나무에서 대조군을 만들지 마라.** 딴 나무(`git worktree add`)나 **빈 폴더 복사본**에서 재고, 작업나무는 **읽기만**.
> `git checkout --`·`restore`·`stash drop` 은 미커밋 위에서 **파괴 명령**이다.
> 되돌리기 실험은 **전경에서, 복원까지 한 호출 안에서.**
> 🔴 **되돌림 검증을 남에게 맡기기 전에 내 쪽에서 먼저 백업을 뜨거나 커밋해 두고 넘긴다.**
