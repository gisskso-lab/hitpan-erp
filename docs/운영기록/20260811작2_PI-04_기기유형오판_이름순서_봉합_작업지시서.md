# §1. P0-1 — 유형 오판 (슬롯 과금 자리)

## 현행 코드 — 있는 그대로

[`src/HitPan.Web/wwwroot/js/device-fingerprint.js:118-124`](../../src/HitPan.Web/wwwroot/js/device-fingerprint.js)

```js
// UA 기반 디바이스 타입 간이 판별
getDeviceType: function () {
    var ua = navigator.userAgent || '';
    if (/iPad|Tablet/i.test(ua)) return 'tablet';
    if (/Mobi|Android|iPhone|iPod/i.test(ua)) return 'mobile';
    return 'pc';
},
```

🔴 **`Macintosh` 분기가 없다.**
iPadOS 13+ 사파리는 UA 를 `Macintosh` 로 신고한다 ⇒ 세 조건 **전부 안 걸림** ⇒ **`return 'pc'`**.

그리고 서버가 그 값을 그대로 받는다 —
[`TenantDeviceService.cs:220-221`](../../src/HitPan.Infrastructure/Services/TenantDeviceService.cs):

```csharp
var type = string.IsNullOrWhiteSpace(req.DeviceType) ? "pc" : req.DeviceType.ToLowerInvariant();
if (type is not ("pc" or "mobile" or "tablet")) type = "pc";
```

**이상값·미상값도 전부 `pc` 로 폴백**한다. 그리고 `:236` 에서 `pcUsed` 를 깎는다.

## 왜 P0 인가 — 개발명세서 §1 그 문장

> *"기기 수로 과금하므로, 실제보다 많이 세면 고객이 돈을 더 낸다."*

아이패드로 로그인한 직원 1명이 **PC 슬롯 1칸을 먹는다**(BASIC = PC 5칸).
아이패드 3대인 회사는 **PC 슬롯이 3칸 사라진 채** 한도초과를 만난다.

## 🟢 고칠 재료가 이미 파일 안에 있다 — 새로 만들지 않는다

**같은 파일 [`:147-156`](../../src/HitPan.Web/wwwroot/js/device-fingerprint.js) `isIos()`**:

```js
// iPadOS 13+ : "Macintosh" 로 위장하지만 터치가 된다
if (/Macintosh/i.test(ua) && navigator.maxTouchPoints > 1) return true;   // :153
```

**판별식은 이미 쓰여 있다.** 용도가 "홈화면 안내를 iOS/안드로이드로 가르는 것" 뿐이라
`getDeviceType()` 이 **호출하지 않을** 뿐이다.

⇒ **발명이 아니라 연결이다.** 헌법 #1(덮어쓰기 금지 · 추가만)에 정확히 맞는다.

## 지시 — P0-1

| # | 지시 | 파일 |
|---|---|---|
| 1-1 | `getDeviceType()` 에 **`Macintosh` + `maxTouchPoints > 1` ⇒ `'tablet'`** 분기 추가. 기존 3줄은 **지우지 않고** 그 앞에 넣는다 | `device-fingerprint.js:119` |
| 1-2 | `isIos()` 의 판별식을 **재작성하지 말 것** — 같은 근거를 두 곳에 두면 한쪽만 고쳐지는 사고가 난다. 공용 내부 함수로 빼거나 `isIos()` 를 호출한다 | 동일 |
| 1-3 | 진짜 Mac(터치 없음)은 **`'pc'` 유지**. 데스크톱 Mac 을 모바일로 깎으면 반대 방향 사고다 | 동일 |

🔴 **`'tablet'` 로 보내는 이유**: [`TenantDeviceService.cs:218`](../../src/HitPan.Infrastructure/Services/TenantDeviceService.cs) 이
`mobile` + `tablet` 을 **모바일 칸으로 합산**한다. 아이패드는 모바일 칸이 맞고,
화면 라벨([`DeviceManagePage.razor:537`](../../src/HitPan.Web/Pages/Settings/DeviceManagePage.razor))도 `태블릿` 으로 이미 있다.

# §2. P0-2 — 이름 `Mac · Safari` (같은 뿌리)

## 실측 — 어제 봉합(`cdc1fa3`)은 살아있다

| 확인 | 결과 |
|---|---|
| 이름 생성 `getDeviceName()` | 🟢 있다 (`:92-116`) |
| 로그인 전송 `AuthService.cs:47,59` | 🟢 보낸다 |
| QR 전송 `MobileDeviceRegisterPage.razor:212` | 🟢 보낸다 |
| 서버 폴백 `DeviceController.cs:178` | 🟢 `?? "모바일 기기"` |
| DB 반영 `TenantDeviceService.cs:178` | 🟢 `COALESCE` |

⇒ 화면의 `(이름없음)` 은 **08:23 등록분 = 1.2.61 이전 옛 기록**으로 판단.
🔴 **단, 추정이다. 새 기기 1대 등록 실측 전엔 닫지 않는다**(§4 참조).

## 🔴 그러나 이름에도 같은 순서 버그가 있다

[`device-fingerprint.js:96-101`](../../src/HitPan.Web/wwwroot/js/device-fingerprint.js):

```js
if (/Windows/i.test(ua)) os = 'Windows';
else if (/Macintosh|Mac OS/i.test(ua)) os = 'Mac';        // :98  ← 먼저 걸린다
else if (/Android/i.test(ua)) os = 'Android';
else if (/iPhone|iPad|iPod/i.test(ua)) os = 'iPhone/iPad'; // :100 ← 도달 못 함
```

**`Macintosh` 가 `iPhone|iPad` 보다 위**라, 위장 UA 는 `Mac` 으로 확정된다.
⇒ 사장님 화면의 **`Mac · Safari` 가 정확히 이것**이다.

⚠️ 이름은 `getDeviceName()`, 유형은 `getDeviceType()` 로 **함수가 다르지만 원인은 하나**다.
따로 고치면 한쪽만 고쳐진다.

## 지시 — P0-2

| # | 지시 | 파일 |
|---|---|---|
| 2-1 | `getDeviceName()` OS 분기에서 **위장 아이패드를 `iPhone/iPad` 로** 판정. §1 의 공용 판별을 **같이 쓴다** | `device-fingerprint.js:96` |
| 2-2 | 기존 분기 순서 주석(`:103` "Edge·Whale 은 Chrome 을 포함") **유지**. 브라우저 순서는 정상이다 | 동일 |
| 2-3 | 고객이 읽는 값 — **개발용어 금지**(`:91` 주석). `iPad`·`Tablet` 같은 영어 노출 여부는 기존 `iPhone/iPad` 표기를 따른다 | 동일 |

# §3. 🔴 배포 사본 주의 — 어제의 계통이 여기도 있다

`device-fingerprint.js` 는 **진실원 1개 + 배포 사본 5개**가 있다.

```
🟢 진실원  src/HitPan.Web/wwwroot/js/device-fingerprint.js
⬛ 사본    installer/web-new/... · installer/api-new4/... · installer/api-new5/...
          hitpan-api/... · hitpan-publish-web/...
```

🔴 **진실원만 고친다.** 사본은 빌드·게시가 만든다.
🔴 사본을 직접 고치면 **다음 빌드가 덮어써서 "고쳤는데 안 고쳐진" 현상**이 난다
— 인수인계서 §5 *"만들었다 ≠ 실행된다"* 계통.

⚠️ **JS 파일이라 마이그레이션·DDL 은 없다.** `requiresMigration` 은 **false** 다.
(§5 3곳 규칙은 테이블·컬럼 신설 때의 규칙이며 이 건에는 해당 없음)
