## 0. 이 절차서가 있는 이유

**한 번뿐이라 순서가 곧 성패다.** 어느 단계에서 막히면 그 회차가 날아간다.
그래서 PM 이 **막힐 지점을 먼저 제거**하고, 사장님은 순서대로만 따라가시면 되게 만든다.

## 1. 🔴 PM 이 실측 전에 반드시 해결한 것 — 6단계 차단 요소

### 1-1. 버전 충돌 (실측으로 확정)

```
랜딩이 주는 설치 EXE : 1.2.46
게시된 manifest      : 1.2.46
                       ↑ 같다
```

**버전이 같으면 워치독이 "최신입니다" 로 판정하고 업데이트가 안 돈다.**
7월에 이것으로 며칠 소모한 이력이 있다 (교훈: *"버전 동일하면 감지 0"*).

⇒ **6단계는 사장님이 5단계를 마치신 뒤, PM 이 `1.2.47` 을 게시**해야 성립한다.
   미리 올리면 사장님이 1.2.47 을 설치하게 되어 또 같아진다.

### 1-2. 🔴 하루 1회 게이트 (코드 실측)

```csharp
// src/HitPan.Watchdog/Worker.cs:306-308
var today = DateOnly.FromDateTime(DateTime.Now);
if (_lastUpdateCheckDate == today)
    return;                        // ← 오늘 이미 봤으면 그냥 나간다
```

**워치독은 업데이트를 하루에 한 번만 확인한다.**
사장님이 설치하시면 그 순간 오늘자 체크가 소진되고, 그 뒤 1.2.47 을 올려도
**내일까지 안 본다.**

⇒ **해법**: `_lastUpdateCheckDate` 는 **인메모리 필드**다(`Worker.cs:28`).
   **워치독 서비스를 재시작하면 `null` 로 초기화**되어 즉시 재조회한다.

```
관리자 명령 프롬프트에서:
sc stop HitPanWatchdog
sc start HitPanWatchdog
```

> 이 두 줄이 6단계의 열쇠다. 이것 없이는 오늘 안에 업데이트를 볼 수 없다.
