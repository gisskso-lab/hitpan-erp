## 0. ⭐ 사장님 오더 (원문 그대로 — 이 문서의 원본)

> **S5** *"맞음. 기본적으로 **계정로그인/로그아웃이 되면 자동근퇴 처리** 할수 있게 하고, **사원등록만 되있고 계정이 없는 직원은 인사담당자가 수동으로 근퇴처리 할 수 있는 장치**를 만들어야 됨. 이건 그룹웨어 처음 붙일때 내가 얘기했던 내용임. 여기에 **연장, 조퇴, 외출을 수동으로 붙일 수 있도록**도 만들고"*
>
> **추가** *"남의 근퇴 넣는건 **권한설정에 넣자.**"*
>
> **경비-1** *"경리등록은 **직원계정 권한설정으로 고객사가 자유롭게 수동설정** 할수있도록 열어두면 되지. **자동강제로 하면, 오히려 더 불편**하지 않을까?"*
>
> **경비-2** *"경리없이 **대표가 직접 경리업무 보는 소규모 회사**도 있고, **경리팀이나 회계팀 조직을 빌딩할 정도로 큰 회사**도 있고 **이건 케바케**라"*
>
> **경비-3** *"직원이 자기가 쓴 돈을 올리는 화면 = 이건 **경비처리 항목에 넣으면 됨.** 경비처리 옵션에 **"법인카드, 지출결의" 등**으로"*
>
> **경비-4** *"**일단 두개만 넣고, 더 붙일 수 있도록 모듈화**" / "**화면만 합치고, 옵션컬럼을 붙여.**"*
>
> **예외** *(U1·U3·A 세 건을 어떻게 할지 묻자)* → *"**세개 다. 예외처리로**"*
>
> **경로** *(계정 없는 직원이 앞으로 계정을 받나 묻자)* → *"**이건 고객사 마음이지**" / "**우리가 정할게 아님**"*
>
> **확정** *(PM 이 "권한이 예외 / 경로가 예외" 두 안을 올리자)* → *"**권한이 예외. 기본 OFF, 고객사가 켬 — 이걸로**"*

**이 아래 모든 내용은 위 오더를 명문화한 것이다.** 오더에 없던 요구를 넣지 않는다.

## 1. 오더를 이렇게 이해했다 (명문화)

- **사장님 의중**: 계정 유무가 근태를 가르면 안 된다. **계정 없는 직원도 근태가 남아야 한다.**
  경비는 화면을 하나로 하되 **누가 쓰냐가 아니라 무엇이냐로** 가른다.
  역할을 코드가 정하지 않는다 — **권한으로 연다**(케바케).
- **안 하면 무슨 일이 나는가**: 실측 사원 12명 중 계정 보유 **1명** ⇒ **11명의 근태가 영영 안 남는다.**
- **실측 근거** (헌법 #32): 설계 20260821설6 §1 참조. 요약:
  - 🟢 자동 출근 `AuthController.cs:236-258` / 자동 퇴근 `:313` — **이미 있다**

## 2. 무엇을 하는가 (범위)

🔴 **권한 칸 = 예외처리 확정** (사장님 결재 — U3 해소)
`user_permissions` 는 `menu_code` + **view/create/update/delete/export 5축뿐**이다.
⇒ 🔴 **5축 밖의 별도 항목으로 만든다.** 기존 축에 얹지 않는다.
**근거**: 5축은 *"내 데이터에 무엇을 하나"* 축이고, 대리입력은 *"남의 데이터를 건드리나"* 축이다.
`update` 에 얹으면 **자기 근태 고치라고 준 권한이 남의 근태까지 연다.**
⇒ 새 `menu_code` 추가 — `PermissionPage.razor.cs` **ErpMenus·EnforcedMenus 동시 갱신**

🔴 **경로는 예외가 아니다** — 자동 근퇴·대리 입력 **둘 다 정상 경로**로 같은 수준으로 만든다.
실측 사원 12명 중 계정 1명 ⇒ 대리입력이 예외면 **92%가 예외**다. 예외 경로는 덜 다듬어지는데
**제일 많이 쓰는 길이 제일 허술해진다.** 예외인 것은 **권한 하나뿐**이고, 기본 OFF 라
고객사가 안 켜면 그 회사엔 **없는 것처럼** 된다(사장님: *"이건 고객사 마음이지"* · 헌법 #11).
🔴 **어느 쪽이든 `EnforcedMenus` 에 반드시 넣는다** — 안 넣으면 **안 먹는 체크박스**가 된다
   (`PermissionPage.razor.cs:63-85` 주석: *"안 먹는 체크박스를 보여주는 것이 제일 나쁘다"* · 1.2.74 P0 재발).
