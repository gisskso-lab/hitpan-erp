## 2. 🔴 진범 — 스키마도 마이그도 아니었다

`PurchaseService.GetReturnsAsync` 의 **문자열 이어붙이기 한 줄**이다.

```
WHERE r.tenant_id = @Tid AND r.is_deleted = 0      ← raw string 이 여기서 끝난다
```

C# raw string(`"""`)은 **닫는 따옴표 앞 줄바꿈을 버린다.** 그래서 base SQL 은 `0` 으로 끝난다.
여기에 `sql += string.Join(" ", conditions)` 로 `"AND r.return_date >= @From"` 을 **공백 없이** 붙이면

```
... AND r.is_deleted = 0AND r.return_date >= @From
```

`0AND` 가 되어 MariaDB 가 파싱하다 죽는다 → `SQL syntax error` → 컨트롤러에 try/catch 가 없어 **그대로 500**.

### 🔴 왜 아무도 못 잡았나 — 날짜가 있을 때만 터진다

| 호출 | conditions | 결과 |
|---|---|---|
| 날짜 0개 | 비어 있음 → 붙일 것이 없다 | 🟢 **200** |
| `from` 만 | 1개 | 🔴 500 |
| `to` 만 | 1개 | 🔴 500 |
| `from`+`to` (**화면 기본값**) | 2개 | 🔴 500 |

화면은 **항상 최근 30일**을 보낸다 ⇒ **고객은 100% 500**.
그런데 날짜 없이 부르는 시험은 **전부 통과**한다.
⇒ 빌드 0/0 · 단위시험 944 · 빈 DB 실측이 **셋 다 초록불**이었다.

### ⚠️ 마이그·스키마는 무죄임을 실측으로 확인했다
- `purchase_returns` 17컬럼 (`memo`·`created_by`·`return_reason` 포함) **전부 실재**
- 재현 중 DB-108·109·110 이 *신규 적용* 됐는데도 **증상 그대로** ⇒ 마이그 미적용은 원인이 아니다
- 같은 SQL 을 `mysql.exe` 로 직접 실행 → **정상** (Dapper 조립 단계에서만 깨진다)

## 4. 게이트 — `PurchaseReturnListSqlGateTests`

**글자검사가 아니다.** 소스에서 base SQL 과 조건 조각을 읽어 **실제로 조립한 뒤** 토큰 융합(`0AND`)을 본다.

🔴 **반증 확인 (가짜 게이트 금지)**
1. 처음 짠 게이트는 봉합을 빼도 **통과**했다 = 가짜였다.
   원인: raw string 의 **들여쓰기 제거 규칙을 재현하지 않아** 남은 공백을 "구분됨" 으로 오판.
2. C# raw string 의미(닫는 따옴표 들여쓰기만큼 전 줄에서 제거 + 마지막 줄바꿈 버림)를 재현하도록 고침.
3. **봉합 제거 → FAIL** 확인:
   `조립된 SQL 에 토큰이 붙었다 ... r.is_deleted = 0AND r.return_date >= @From`
4. **봉합 복구 → PASS** 확인.
