## 0. 왜 이게 필요한가

`publish-update.sh`·`publish-run.sh`·`emergency-recovery.sh` 는 **NCP 상주본이 진실원**이다
(`/opt/hitpan/…`). 리포 파일을 고쳐도 **NCP 에 반영하지 않으면 아무 일도 일어나지 않는다.**

> 오늘 고친 것: 설치 EXE 를 `packages/` 에 함께 게시하는 배선.
> 이걸 반영해야 **랜딩 다운로드 404 가 풀린다.**

## 1. 접속

```bash
ssh -i ~/.ssh/id_ed25519 -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null root@211.188.58.140
```

> 한글 사용자명 경고는 무해. fail2ban 텀이 있으니 연속 실패 시 잠시 대기.

## 2. 현재 상태 확인 (덮어쓰기 전 — 헌법 #1)

```bash
cd /opt/hitpan/repo
git log --oneline -1
git status --short | head
```

> 로컬 수정본이 있으면 **여기서 멈추고 PM 에게 알려주십시오.** 덮어쓰면 그 수정이 사라집니다.

## 3. 백업

```bash
mkdir -p /var/hitpan/backup-scripts/$(date +%Y%m%d-%H%M%S)
BK=/var/hitpan/backup-scripts/$(ls -1 /var/hitpan/backup-scripts | tail -1)
cp -av /opt/hitpan/installer/updates/publish-update.sh "$BK/"
cp -av /opt/hitpan/deploy/publish-run.sh "$BK/"
cp -av /opt/hitpan/deploy/emergency-recovery.sh "$BK/"
ls -la "$BK"
```

## 4. 최신 코드 받기

```bash
cd /opt/hitpan/repo
git fetch origin
git log --oneline origin/develop -1        # 오늘 커밋인지 눈으로 확인
git checkout develop && git pull --ff-only origin develop
```

## 5. 상주본 갱신 (3파일)

```bash
install -m 0755 -o root -g root /opt/hitpan/repo/installer/updates/publish-update.sh \
  /opt/hitpan/installer/updates/publish-update.sh
install -m 0755 -o root -g root /opt/hitpan/repo/installer/deploy/publish-run.sh \
  /opt/hitpan/deploy/publish-run.sh
install -m 0755 -o root -g root /opt/hitpan/repo/installer/deploy/emergency-recovery.sh \
  /opt/hitpan/deploy/emergency-recovery.sh
```

## 6. 검증 (덮어쓴 뒤 반드시)

```bash
# 6-1. 문법 — 하나라도 오류면 게시가 통째로 깨진다
for f in /opt/hitpan/installer/updates/publish-update.sh \
         /opt/hitpan/deploy/publish-run.sh \
         /opt/hitpan/deploy/emergency-recovery.sh; do
  bash -n "$f" && echo "OK  $f" || echo "🔴 문법오류 $f"
done

# 6-2. 권한·소유자 (sudoers 정확매칭 유지 확인)
ls -la /opt/hitpan/deploy/publish-run.sh /opt/hitpan/installer/updates/publish-update.sh

# 6-3. 새 코드가 실제로 들어갔는지
grep -c "HITPAN_INSTALLER_EXE" /opt/hitpan/deploy/publish-run.sh          # 1 이상
grep -c "HITPAN_ALLOW_NO_INSTALLER" /opt/hitpan/installer/updates/publish-update.sh   # 1 이상

# 6-4. 디스크 여유 — EXE 260MB 가 매 게시마다 쌓인다
df -h /var/www/updates
```

| 확인 | 기대값 |
|---|---|
| 6-1 문법 | 3개 전부 `OK` |
| 6-2 권한 | `-rwxr-xr-x root root` |
| 6-3 grep | 둘 다 **1 이상** (0 이면 갱신 실패) |
| 6-4 디스크 | **최소 2GB 이상** 여유 |

## 7. 다음 — 게시 (1.2.42)

상주본 갱신이 끝나면 PM 에게 알려주십시오. 그다음:

```bash
gh workflow run deploy-update.yml --ref main \
  -f version=1.2.42 -f channel=Major -f environment=production
```

> ⚠️ **1.2.41 이 아니라 1.2.42 다.** 다운그레이드 게이트가 같은 버전 재게시를 막는다.
> ⚠️ **먼저 develop → main 반영이 필요하다** (워크플로가 `--ref main` 으로 돈다). PM 이 PR 을 올린다.
> ⏱️ 이번엔 EXE 빌드가 붙어 **약 11~15분** 걸린다(기존 4분). 폰 승인은 빌드 후에 온다.

## 8. 롤백 (문제 생기면)

```bash
BK=/var/hitpan/backup-scripts/$(ls -1 /var/hitpan/backup-scripts | tail -1)
install -m 0755 -o root -g root "$BK/publish-update.sh"     /opt/hitpan/installer/updates/publish-update.sh
install -m 0755 -o root -g root "$BK/publish-run.sh"        /opt/hitpan/deploy/publish-run.sh
install -m 0755 -o root -g root "$BK/emergency-recovery.sh" /opt/hitpan/deploy/emergency-recovery.sh
```

## 9. PM 이 하지 않은 것 (명시)

| 안 한 것 | 왜 |
|---|---|
| NCP 원격 실행 | 헌법 #29 — 인프라 조작은 사장님 |
| nginx 설정 변경 | 불필요 (`.exe` 차단 없음 실측 확인) |
| sudoers 변경 | 불필요 (래퍼 인자 2개 불변) |
| 디스크 정리 정책 | 별건 — orphan EXE 회전은 후속 |
