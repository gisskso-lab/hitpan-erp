## 6. 🚨 함정 — 다음 사람이 반드시 알아야 할 것

### 6-1. 🔴 `IsLocalConsole` 과 `IsMainPc` 를 절대 합치지 마라

```
IsLocalConsole   소켓만 본다            ← 왕복 확인(②)이 쓴다
IsMainPc         IsLocalConsole OR 출입증  ← 자료관리가 쓴다
```

합치면 **출입증을 가진 브라우저가 스스로 출입증을 갱신하는 고리**가 생긴다.
한 번 새어 나간 출입증이 **영원히 산다.** 두 파일 모두 주석으로 경고해 뒀다.

### 6-2. 🔴 헤드리스 브라우저로 재면 결과가 **정반대**로 나온다

```
headless: true   → 🔴 "Permission was denied … loopback"   ← A안 불가로 오판한다
headless: false  → 🟢 HTTP 200, 차단 메시지 0
```

**실제로 이 함정에 빠질 뻔했다.** 헤드리스 결과만 보고 *"브라우저가 막는다 = A안 불가"* 로
보고할 참이었다. **반드시 실제 브라우저 창으로 잰다.**
(재현 스크립트 모양은 [1-V] 선행검증서 §4 에 있다)

### 6-3. 🔴 팝업이 두 번 뜨는 것은 **정상**이다 — 없애지 마라

```
새 PC 설치(빈 DB) → [등록] 팝업 1회차 → 자료복구
→ 복원이 옛 DB 를 덮어써 **옛 메인PC 등록이 되살아난다**
→ 봉인 불일치 → [변경] 팝업 2회차 → 재등록
```

④는 버그가 아니라 **복원의 정의**다. *"왜 두 번 뜨지?"* 하고 ⑤를 없애면 **자동 감지가 통째로 죽는다.**

### 6-4. 🔴 봉인키를 파일로 옮기지 마라

`hitpan-keys.conf` 가 아니라 **DB(`tenant_devices.mainpc_sealed_key`)** 에 둔 이유가 있다 —
**자료와 함께 이사해야** *"컴퓨터가 바뀌었다"* 를 알 수 있다.
파일에 두면 복원해도 안 따라오므로 **그 신호가 영영 안 뜨고, 메인PC 를 영영 못 옮긴다.**

### 6-5. 이번에 실제로 밟은 지뢰 3개

- **헤더 이름** — `RegisterMainPc` 가 `X-Device-Id` 를 읽고 있었는데 핸들러는 `X-HitPan-Device-Id` 를 보낸다.
  그대로 뒀으면 등록이 늘 *"기기 정보를 확인할 수 없습니다"* 로만 끝났을 것이다
- **Dapper 튜플** — `ValueTuple` 은 **이름이 아니라 순서**로 채워진다. 컬럼 순서를 바꾸면
  값이 조용히 뒤바뀌고 빌드는 멀쩡하다 ⇒ 명시 클래스로 받게 바꿨다
- **네임스페이스** — `src/HitPan.Infrastructure/Services/` 폴더인데 네임스페이스는 `HitPan.Application.Services` 다.
  같은 폴더의 `TenantDeviceService` 가 그렇다. 혼자 다르게 쓰면 `Program.cs` 가 못 찾는다

### 6-6. `@if (false)` 는 경고를 만든다

Razor 가 미도달 코드를 생성해 `CS0162` 가 난다(#19 경고 0 위반).
`static readonly bool` 필드로 막아야 한다. `const` 도 안 된다 — 컴파일러가 단정해 버린다.

⇒ 손으로 바꿔 끼우려면 **백업(`api.bak_*`) → 교체 → `hitpan-start.bat` 재기동** 이고,
