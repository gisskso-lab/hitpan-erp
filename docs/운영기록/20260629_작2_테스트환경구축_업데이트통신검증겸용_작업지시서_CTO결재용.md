## 3. 작업 항목
### 3-1. test 슬롯 구축 (통신검증 + 업데이트 공용 베이스)
- `C:\HitPanTest\` 격리 디렉토리 (ASCII 경로, 헌법 #39 한글경로 차단 정합)
- hitpan_e2e DB 생성 + clean DDL import(121테이블) → ddl-smoke 통과 확인
- API(15257)·Web(15234) test 슬롯 기동
- cloudflared-test / MariaDB-test 서비스 (test 접미사 — 안전망 가드 정합)
- db.conf: PRIMARY_DOMAIN=test… (demo면 스크립트 차단)
- **HITPAN_TEST_ENV.marker 생성** (ENV=TEST, 서비스명 단일진실원)

### 3-2. test 도메인·터널 발급 (#29 결재 후)
- IssueTestDomain 도구로 test 도메인 DNS + **터널 발급(IssueTunnelAsync)** + Ingress → 15257 매핑
- ※ 어제 e2e-comms는 DNS만 발급·터널 미발급이었음 → 이번엔 터널·ingress까지 완결 (작1 고리와 같은 경로 실증)

### 3-3. test manifest 피드 (업데이트 검증용 — 신규)
- 가짜 "새 버전" manifest 게시 경로 (test 전용, 운영 updates.hitpan.kr 무관)
- 채널별(Normal/Emergency/Major) 테스트 매니페스트 샘플

### 3-4. 반증 테스트 (데이비드 박, 완료 게이트 — SoD)
어제 설계된 4건 그대로:
1. 마커 없는 상태(demo 모사) → -Confirm 실행 시 exit 1 차단 실증
2. 마커 + demo 서비스 Running → 차단
3. -test 없는 서비스명 → SKIP
4. demo cloudflared·HitPan.API 죽이는 경로 도달 불가 코드 반증
→ 4건 통과 전 실측 금지
