## 1. 배경 (Why)

W2 D5 스모크 3건 → W3 100만 건 본격 처리. 단순 1행 INSERT 루프로는 100만건 처리 시 수십시간 소요.

설계 문서 `docs/migration/W3_CHUNK_ALGORITHM.md` 완성(2026-05-13). AIMD 동적 조정 + 청크 트랜잭션 + 체크포인트 보존. 본 작지서로 구현.

## 2. 목표 산출물

### 서비스
- `ChunkProcessor<TSource, TTarget>` 제네릭 신규
  - `ProcessAsync(IAsyncEnumerable<TSource> source, Func<TSource, TTarget> mapper)`
  - AIMD: commit_ms [500ms, 1500ms] → 위반 시 chunk_size /= 2, 안정 시 +500
  - MIN=100, MAX=10,000 (W3_CHUNK_ALGORITHM.md §3 매트릭스)
- 체크포인트 저장: `migration_checkpoints` (last_pk_value JSON, 복합 PK 5컬럼)
- 에러 처리: 행 단위 SKIP + `migration_errors` 적재 (raw_data는 결재 #2 결과 반영)

### MdbMigrationService 통합
- 기존 1755줄 서비스에 ChunkProcessor 주입
- 마스터 테이블(partners/items/employees) = 단일 tx
- 거래 = 청크 1,000
- 원장(DOCFB) = 청크 5,000

### MariaDB 튜닝
- `innodb_flush_log_at_trx_commit=2` 일시 변경 (try/finally 복원 의무)
- `max_allowed_packet=64MB`

### 테스트
- 멱등성 시나리오 12종 (W3_IDEMPOTENCY_SCENARIOS.md 참조) 중 P0 7건

## 6. 구현 가이드

### 6.1 DB
- `migration_checkpoints` 컬럼: `last_pk_value JSON` (복합 PK 수용)
- `innodb_flush_log_at_trx_commit=2` 변경은 `SET SESSION` 한정 (전역 변경 금지)
- DESCRIBE 의무 (헌법 #13)

### 6.2 백엔드
- ChunkProcessor 단일 connection 사용 (헌법 #16: MySqlConnection Task.WhenAll 금지)
- 청크 트랜잭션 `IDbContextTransaction` 또는 raw `BEGIN/COMMIT`
- 재시도 3회 (Polly Exponential Backoff)
- INSERT ONLY (헌법 #3)

### 6.3 프론트
- 비범위

### 6.4 보안
- AES 암호화 5컬럼은 청크 내 1행씩 처리 (Bulk 암호화 불가, IV 랜덤)
- 평문 데이터 로그 절대 금지

### 6.5 테스트
- P0 7 시나리오: #1 완전재실행 / #2 부분재실행 / #3 트랜잭션 롤백 / #4 중복 INSERT SKIP / #5 AES 멱등 / #8 동시 실행 차단 / #9 NULL 보존
