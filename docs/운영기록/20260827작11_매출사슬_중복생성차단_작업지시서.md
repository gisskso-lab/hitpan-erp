## 1. 🔴🔴 W1 — 수주 1건으로 거래명세서 **2장**이 나온다

### 증상 (실측 · main `6f2f39bc`)

`ConvertOrderToDeliveryAsync` (`SalesService.cs:1306~`) 의 유일한 방어:

```csharp
var deliveryItems = items.Where(x => x.OrderedQty - x.DeliveredQty > 0)...
if (deliveryItems.Count == 0) throw ...   // ← 이것뿐이었다
```

🔴 **이 방어는 `delivered_qty` 가 올라간 뒤에만 듣는다.**
그런데 `delivered_qty` 는 **확정**(`ConfirmDeliveryAsync:459` `orderItem.DeliveredQty += line.Qty`)에서만 증가한다.

⇒ **명세서를 만들고 확정하기 전(draft) 에 다시 전환하면 `delivered_qty` 가 아직 0 이라
그대로 통과한다.** 수주 1건으로 명세서 2장이 나오고, **둘 다 확정하면 재고가 2배 출고**된다.

### 🔴 매입은 이 사고를 이미 겪고 봉합했다 — 매출만 안 받았다

`PurchaseService.cs:726-747` 주석 원문:
> *"즉 **발주 1건으로 매입 2장을 만들 수 있었다(재고 2배 입고)**.
> 남은 방어는 `receiptItems.Count == 0` 뿐인데 그건 `received_qty` 가 제대로 올라갔을 때만 듣는다.
> ⇒ **취소분만 빼고 전부 센다.** 살아있는 매입명세서가 하나라도 있으면 막는다.
> 번호를 알려준다 — 담당자가 무엇을 정리할지 알아야 한다(사장님 지시)."*

**매출은 지금 그 봉합 전 상태 그대로였다.**

### 봉합
매입과 **대칭 이식**. 살아있는 명세서(취소·삭제 제외)가 하나라도 있으면 막고, **번호를 알려준다.**
- ⚠️ 철자 — `sales_deliveries` 는 **`cancelled`**(l 둘). `sales_returns`(`canceled`, l 하나)와 다르다
- 빈 품목 메시지도 매입과 대칭(`allClosed` → *"이미 출고가 완료된 수주서입니다"*)

## 2. 🔴 W2 — 계산서 중복 가드가 **테넌트를 안 본다**

### 증상 (`TaxInvoiceService.cs:73-82` 종전)
```sql
SELECT invoice_id FROM tax_invoices WHERE delivery_id = @DeliveryId AND status = 'issued' LIMIT 1
```

결함 3개:
| # | 결함 | 피해 |
|---|---|---|
| ① | **`tenant_id` 조건 없음** | 남의 회사 계산서가 걸려 **우리 발행이 막히거나**, 우리 것이 안 걸린다 (헌법 #2) |
| ② | **번호를 안 알려준다** | *"이미 발행됨"* 만 말해 담당자가 목록에서 눈으로 찾아야 한다 (작8 교훈) |
| ③ | 주석이 **없는 UNIQUE 를 있다고** 적어놨다 | 실제 방어는 이 SELECT 하나뿐인데 **2층인 줄 알고** 약하게 뒀다 |

③ 근거 — clean DDL `tax_invoices` 주석:
> *16차에 `active_delivery_id` 생성컬럼+UNIQUE 를 넣었으나 MariaDB 가 FK 컬럼 참조
> STORED generated 를 금지 → **ERROR 1901 로 clean DDL import 자체가 실패** → 회수.
> 중복차단은 `IssueAsync` 의 SELECT 체크로 환원.*

### 봉합
`tenant_id` 추가 + `invoice_no` 를 뽑아 **메시지에 담는다** + 클래스 주석의 거짓 기술 정정.

## 3. 게이트 5건 — `SalesChainNoDuplicateGateTests`

| G | 검사 |
|---|---|
| G-1 | 🔴 **본 판정** — draft 명세서가 있으면 재전환이 막힌다. **옛 가드는 통과시키고 새 가드는 막는다**(대조군) |
| G-2 | 취소·삭제된 명세서는 **막지 않는다** (과잉봉합 방지 — 취소했으면 다시 만들 수 있어야 한다) |
| G-3 | **남의 회사 명세서는 우리 전환을 막지 않는다** (헌법 #2) |
| G-4 | 수주 재전환 차단이 **기존 번호를 알려준다** + 조건이 **살아 있다** |
| G-5 | 계산서 중복차단에 **테넌트 조건과 번호**가 있다 |

### 🔴🔴 G-4 가 처음엔 **가짜였다** — 이 작업에서 실제로 적발

가드를 **`if (false && …)`** 로 죽이고 돌렸더니 **그대로 통과**했다.
문자열이 파일에 남아 있어서다 — **게이트 체크리스트 ⑧ 그대로**.
⇒ *"조건이 살아서 던지는지"* 를 함께 보도록 고쳤고, 다시 죽이니 **FAIL** 로 바뀌었다.

### 반증 실측
| 반증 | 결과 |
|---|---|
| W1 가드를 `if (false &&)` 로 죽임 | **FAIL** ✅ (게이트 고친 뒤) |
| W2 에서 `tenant_id` 제거 | **FAIL** ✅ |
