## §1 [판별] 「사슬이 막혔다」는 무엇을 보면 아는가

**보는 사람**: PM 세션(읽기만) + 사장님(화면·UAC). 판별 도구 넷 — 전부 **읽기**다.

| 도구 | 어떻게 | 주의 |
|---|---|---|
| T-1 이벤트로그 | `Get-WinEvent -FilterHashtable @{LogName='Application'; ProviderName='HitPanWatchdog'} -MaxEvents 50` | 9/29 인계1 §4 — 이게 첫 행동. EventLog 수준 = Information(`src/HitPan.Watchdog/appsettings.json:7-11`) ⇒ 아래 Information 줄이 보인다 |
| T-2 `/health` | `http://127.0.0.1:5257/health` 의 `version` · `uptime_sec` | 적용 여부의 유일한 판정. 화면의 「완료」는 믿지 않는다 |
| T-3 사이드바 | 자료관리 아래 버전 줄의 이슈 줄(설계 §4·§7) | 판정 T1=10분 · T2=30분(설계 §4 · P-2 확정값은 PM) |
| T-4 운영 DB | `local_update_consents`·`local_update_attempts` 최신 5행 **SELECT** | 관리자 권한으로 `db.conf` 를 읽어야 해서 **사장님 UAC** · 결과 파일은 `%PUBLIC%` 에 쓰고 곧바로 삭제 · 비밀번호 출력 금지(9/29 인계1 §4) |

T-4 SELECT(이 두 줄만 · 칸 이름은 설계 §12-1 · 실행 전 `DESCRIBE` 로 확인 #13):
```sql

SELECT id, consent_id, update_version, result, LEFT(detail,60), started_at, ended_at FROM local_update_attempts ORDER BY id DESC LIMIT 5;
```

**④ `force-update.ps1` 이 하는 일과 금지의 관계**
- 하는 일: `local_update_consents` 에 `approve`(user_id=`manual-force`) 한 줄 INSERT(`:222-230`) · 선택 시 `Restart-Service HitPanWatchdog`(`:262-270`). 업데이트 자체는 하지 않는다 — 워치독이 같은 절차(백업→교체→검증→되돌림)로 한다.
- 새 규칙 아래 효과: 새 id 라서 「새 [예]」로 소비된다. 단 🔴 **ⓑ 의 두 겹(`[MainPcOnly]`·준비된 버전 400 대조)을 건너뛴다.** 역행은 워치독 둘째 겹(`IsAboveInstalled` · `Worker.cs:767-774`)이 막는다. ⓒ 가 결함이면 이 INSERT 도 같은 결함에 걸린다 ⇒ **④ 가 푸는 것은 ⓐⓑ 막힘뿐**.
- 금지와의 관계: 작업지시서 §3 #39 「`force-update.ps1` 수동 INSERT 금지(1차 C-5)」는 [3]·[4] **시험 경로**의 금지다. 탈출 절차에서도 운영 DB 쓰기라는 성질은 같다 ⇒ **PM·개발팀이 판단해 돌리지 않는다.** 사장님이 그 자리에서 명시 결정하고, 무엇을 넣었는지(버전·action·시각)를 운영기록에 남길 때만 예외. 그 전에 ①-b 를 먼저 다 한다.
- ⬛ 스크립트 주석 「멱등 장치 `Worker.cs:602` · 버전 키」는 새 워치독에서 낡았다(키 = 동의 id · `:876`). 새 워치독에서는 펜딩이 서 있으면 재기동 없이 소비된다 — 스크립트 수정은 이 문서 범위 밖(별건 후보).

## §3 [되돌림] R 이 같은 사슬로 막힐 때

- R 정의: 1.3.48 트리 `08ee240f` · Major · 번호는 **게시 시점의 게시원 최신(N+1 포함)과 설치 버전보다 큰 번호**(작업지시서 §10 G-1). ⚠️U-3 게시원이 최신 1개만 내보내는지 — 그렇다면 R 번호 > N+1 이어야 펜딩이 R 로 바뀐다(`Worker.cs:815-817` 「더 새 버전이 오면 펜딩을 그 버전으로」).
- 순서:
  1. **§1 로 막힌 고리를 먼저 가른다.** R 게시(NCP 1회분 · G-2)를 쓰기 전에.
  2. 막힌 고리 = ⓓ(적용 실패 · 원인 해소 가능) → R 불필요. 원인 해소 뒤 §2-①.
  3. 막힌 고리 = ⓐⓑ(화면·API) → R 을 게시해도 **같은 ⓐⓑ 를 탄다.** R 게시 → 워치독 발견(정규 주기 ⚠️U-4) → 사이드바 「새 버전 있음」 → §2-① → ①-b → (사장님 결정 시) ④ `-Version R`.
  4. 막힌 고리 = ⓒ(워치독 소비 결함) → R 도 **새 워치독이 소비한다** ⇒ R 만으로는 안 풀린다. §2-② 재기동 → ③ Z-1 대기 → 그래도면 §4 J-3.
  5. R 적용 성공 뒤: 워치독이 R 의 워치독(옛 규칙)으로 자기교체된다(설계 §10 · 교체는 적용 성공 뒤). 시도 표는 남지만 옛 코드는 안 읽는다(추가형 · 설계 §12-7). T-2 `version` = R 번호 확인.
- R 이 ⓓ 에서 실패(rolled_back)하면 N 그대로 — 사이드바 사유 문구를 보고 §2-① 로 R 재시도.
