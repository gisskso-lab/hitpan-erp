## §4 [구현] 어떻게 ([3] 개발팀 · PM 지휘)
### §4-1 JS — `openRoom(url)` 추가
1. `this._win` 이 살아 있으면(`!closed`) → 그 창을 `url` 로 보낸다 → `focus()` → `true`.
   - 권고: 같은 출처이므로 팝업 쪽 `Blazor.navigateTo(url)` 가 있으면 그것(앱 재시작 없음), 없으면 `this._win.location.assign(url)`. ⚠️ .NET 8 WASM 에서 `Blazor.navigateTo` 공개 여부는 [3] 착수 때 확인 — 못 쓰면 `location.assign` 하나로 간다(창이 다시 뜨는 몇 초 지연은 리스크 표).
2. 살아 있지 않으면 → **기존 `this.open(url)` 을 부른다**(같은 크기·같은 이름 `'hitpanChat'`). 본 창을 새로고침해 `_win` 을 잃어도 같은 이름이라 브라우저가 떠 있는 팝업을 재사용해 그 주소로 보낸다.
3. 전부 `try/catch` · 실패는 `console.error` + `false`(기존 `open` 과 같은 꼴).
- 호출자 grep(#12): `hitpanChat.open` = TopHeader:58 · Sidebar:480 두 곳 — **둘 다 그대로**. `openRoom` 호출자는 NotificationBell 하나.

### §4-2 판정 함수 `ChatNotificationRoute.TryGetRoomId(string? link, out string roomId)`
- `"/chat/{한 칸}"` 만 참. `/chat`·`/chat/a/b`·`/approval/pending`·`/settings/devices`·빈값·`null` 은 거짓.
- 방 번호 글자 허용 범위를 좁힌다(주소 끼워넣기 방지): ⚠️ [3] 에서 `DESCRIBE chat_rooms`(#13)로 `room_id` 형식을 재고 그에 맞춘다(예: 영숫자·`-`·`_` · 64자 이하). 방 열람 권한은 지금처럼 **서버가 판정**(Sidebar.razor:200 「방에 낀 사람인가」) — 화면 판정은 길 고르기일 뿐.
- **판정 기준 = 링크 모양**(종류 `Type` 이 아니라). 이유: 이동 대상이 링크이고, `chat_message`·`chat_approval` 둘 다 같은 링크를 쓴다. `chat_approval` 포함 여부는 §0 확인 필요 ②.
- 시험이 Web 을 참조하지 않으므로 `HitPan.Tests.csproj` 에 `Compile Include … Link=` 로 끌어온다(참조 없는 화면 프로젝트 파일을 끌어온 선례 `ApiErrorText.cs`(백오피스) · csproj:115 주석 — HitPan.Web 파일은 처음이니 CS0436 형 겹침을 [3] 에서 확인).

### §4-3 서버 링크 — 두 안
| | A안: 서버를 `/chat-window/{roomId}` 로 | **B안: 서버 그대로, 화면이 해석 (권고)** |
|---|---|---|
| 서버 변경 | `ChatService.cs:849` 1줄 | 0줄 |
| 막힌 PC 대체 길 | 화면이 `/chat-window/…` → `/chat/…` 로 **되바꿔야** 함 | 링크 그대로 `Nav.NavigateTo(n.Link)` |
| 옛 링크 | 이미 받은 메모리 알림(최대 50) · 옛 서버는 `/chat/…` → 화면이 어차피 둘 다 해석해야 함 | 처음부터 한 형식 |
| 「어느 창」 결정 위치 | 서버가 화면 사정(팝업 막힘)을 모른 채 정함 | 그 PC 의 화면이 정함 |
- **권고 B.** 알림은 DB 에 안 남으므로(§2) 「저장된 옛 행」은 세션 메모리뿐이고, B안은 형식이 안 바뀌어 옛·새 구분 자체가 없다.

### §5-3 실측 (시험 환경만 · #39 · 운영 접촉 0)
- 테넌트 1곳 자식계정 2개(가·나). 가 → 나 메시지 → 나의 종·토스트에 알림 → 클릭 → 400×680 팝업에 그 방 · 본 창 화면 유지 · 스크린샷.
- 팝업 열린 상태에서 다른 방 메시지 알림 → 같은 창이 그 방으로.

- 실사용 경로: 터널 주소로 접속해 잰다(개발PC localhost 통과는 근거 아님).
- 모바일: ⚠️**미확인** — 휴대폰 브라우저는 크기 지정을 무시하고 새 탭으로 열거나 막을 수 있다(추정). 상단바 버튼도 같은 길이다. 실측 결과(새 탭 / 막힘→본 창+안내)를 개발명세서에 적고, 다르게 할지는 대표께 여쭌다(이번 범위 아님).
