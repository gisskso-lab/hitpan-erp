## 3. 원인 — 끊긴 자리가 또 옮겨갔다 (고쳤다≠갔다 **6차**)

### C-1. 매입명세서 목록 — **서버를 부르지도 않았다**
`PurchaseReceiptList.BulkDeleteAsync` 가 `Status=="draft"` 로 **먼저 걸러서**
확정 건은 **DELETE 요청조차 안 나갔다.** 서버 가드는 실행될 기회가 없었고,
화면이 자기 혼자 만든 문장이 사장님께 갔다. (발주 목록도 동일)

### C-2. 발주서·매입명세서 화면 — **응답 본문을 버렸다**
`if (!resp.IsSuccessStatusCode) { Snackbar.Add("삭제에 실패했습니다."); }`
전표번호는 그 **버려진 본문 안**에 있었다.
🟢 대조군 = `ReturnPage` — **여기만 body 를 읽었다. 그래서 1-3 만 통과했다.**

### C-3. 회계검산 — **화면이 API 를 한 번도 안 불렀다**
`integrity-check` 는 15개 검사를 돌려주는데 Web 전체 호출 **0건**.
🔴 **PM 오보**: 화면을 확인하지 않고 *"검산 화면에 15건 보일 것"* 이라 보고했다.

### C-4 🔴 **화면만 고쳤으면 여전히 안 됐다** (작업 중 추가 규명)
서버가 **상태검사를 사슬검사보다 먼저** 던져 반품번호 검사까지 **가지 못했다.**
사장님 실측 건이 정확히 *확정 매입 + 확정 반품* 이라 이 순서에 걸려 있었다.
⇒ 매입·발주 삭제 **둘 다 사슬검사를 앞으로** 옮겼다.
**막는 것과 알려주는 것은 다른 문제다.**
