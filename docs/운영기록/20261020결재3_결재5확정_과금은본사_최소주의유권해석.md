# 🔴 §1 가장 중요 — **#18·#22 「본사 데이터 최소주의」의 뜻**

> 사장님 2026-10-20: *"본사데이터 최소주의를 지킨다는것이 **고객정보를 안받는다는뜻이 아니야.** 불필요한 정보를 받지 않고, **운영에 필요한 과금이나 CS, 운영에 필요한 정보들은 최소한으로 받는다**는 원칙이지."*

## 1-1 PM 이 거꾸로 읽고 있었다

| | PM 이 읽던 뜻 | 🟢 사장님이 바로잡은 뜻 |
|---|---|---|
| 축 | **「받지 않는다」** — 받는 것이 있으면 의심하고 **줄이려 했다** | **「필요한 것은 받는다. 불필요한 것을 받지 않는다」** |
| 판정 기준 | 목록에 없으면 **빼자** | **운영(과금·CS)에 필요한가** — 필요하면 **받는 것이 맞다** |
| 결과 | 🔴 사원 구분값 칸을 **빼자고 건의**했고(결재 5-ⓒ) **거꾸로였다** · 🔴 공개 문서도 「받는 것」을 **숨기듯** 적으려 했다 | 🟢 **필요한 것은 당당히 받고, 왜 필요한지 밝힌다** |

🔴 **오늘 내가 틀린 것들의 뿌리가 이것이다** — 「여덟 칸뿐」·「경로가 없다」·「사원번호를 빼자」가 전부 **「덜 받는 것이 옳다」는 잘못된 전제**에서 나왔다.

## 1-2 🟢 이제 쓰는 판정 순서

| | 물음 |
|---|---|
| 1 | 이 정보가 **운영(과금·CS·설치·장애 대응)에 필요한가?** |
| 2 | 필요하면 → **받는다.** 🔴 다만 **왜 필요한지 글로 남긴다**(이유 없는 칸은 다음 사람이 뺀다) |
| 3 | 불필요하면 → **받지 않는다** |
| 🔴 4 | **업무 자료(장부·거래처·단가·매출·재고·계산서)는 별 축** — 이것은 「필요성」과 무관하게 **받지 않는다**(#18 본문) |

⇒ 🟢 **최소주의 = 「적게」가 아니라 「필요한 만큼」.**

# 🟢 §2 결재 5 — **과금 장부 진실원 = 본사**

> 사장님: *"**과금은 모두 본사에게, 본사가, 영업실적에 따라 대리점에게 수수료를 정산해주는 방식.**"*

| | |
|---|---|
| 진실원 | 🟢 **본사**(백오피스) |
| 정산 흐름 | 🟢 **본사 → 대리점**, **영업실적 기준** |
| 🔴 지금 코드 | **반대로 서 있다** — `billing_*` 표가 **출하 DDL(고객사 PC) 5개 / 백오피스 DDL 0개** ⇒ **보완 대상** |

| 처분 | 🔴 **코드 0줄.** 루틴대로 **B3 차수 [1-V](10/25)** 에서 이 결재를 전제로 전제 실측 → 작업지시서 → 결재 → 구현 |

# 🟢 §4 결재 추가 — **수수료율은 본사가 자유롭게 설정** (사장님 2026-10-20)

> *"본사가 대리점에게 수수료 지급하는 방식은 **대리점 몆%를 못박아두는것이 아니라**, 본사가 대리점에게 **실적에 따라 수수료율을 자유롭게 설정할수 있도록** 해."*

## 4-1 확정된 것

| | |
|---|---|
| 🔴 금지 | **고정 비율을 코드·시드에 두는 것** — 「대리점은 몇 %」를 못 박지 않는다 |
| 🟢 방식 | **본사가 대리점별로, 실적에 따라 자유롭게 설정**한다 |
| 🟢 같은 정신 | **#11**(권한은 어드민이 직접 설정 · 템플릿 제공 금지)과 **같은 축**이다 — 우리가 값을 정해 주지 않는다 |
| 🟢 10/8 결재와 정합 | *"대리점관리 ⊃ 정산 · 수수료% 는 **본사 설정**"* (10/8 메뉴 결재) — **같은 말을 다시 확인해 주셨다** |

## 4-2 🔴 그래서 지금 코드가 **정면으로 어긋나 있다**

| | 실측 | 뜻 |
|---|---|---|
| 계산기 | 🔴 **고정 `0.15`**(`ResellerSettlementCalculator.cs:34` `DefaultCommissionRate`) | **못 박아 둔 상태** = 결재 위반 방향 |
| 저장 칸 | 🟢 **실재**(`installer/backoffice/00_backoffice_core.sql:633` `commission_rate decimal(5,4) DEFAULT 0`) | 칸은 있다 |
| 읽는 코드 | 🔴 **0건**(별건 P2-6) | 설정해도 반영 안 된다 |
| 설정 화면 | 🔴 **0건** — `AdminCommission.razor` 는 **11줄 리다이렉트** | 본사가 설정할 자리가 없다 |
| 🔴🔴 선행 조건 | **단위가 2체계** — 백오피스 칸은 **분수**(0.1500) / ERP 쪽은 **퍼센트**(15.00) / 화면은 「%」 | 🔴 **읽기 시작하는 순간 100배 오차** ⇒ **단위 통일이 봉합의 1번**이다 |

## 4-3 처분 — 루틴대로

| | 무엇 | 자리 |
|---|---|---|
| 1 | **단위 통일**(분수 ↔ 퍼센트 중 하나로) | 🔴 **봉합 1번** — 이것 없이 읽기부터 고치면 100배 오차 |
| 2 | 계산기가 **칸을 읽게** 한다(고정값 제거) | P2-6 |
| 3 | **본사 설정 화면** 신설(대리점별 수수료율 · 실적 기준) | 대리점관리 ⊃ 정산 |
| 자리 | 🟢 **B5 차수 [1-V](11/08)** 에서 위 3건을 한 묶음으로 전제 실측 → 작업지시서 → 결재 → 구현 | 🔴 **코드 0줄 · 지금 착수 안 함** |

🟢 **자료·상담 금지는 유지되고, 이유가 바뀐다** — 종전 「설정이 반영 안 되니 약속 금지」 → 🟢 **「본사가 대리점별로 자유롭게 정하는 값이므로, 고정 숫자를 밖에서 약속하지 않는다」**(금지 11 유지).

# 🔴 §5 PM 보고 교정 (사장님 2026-10-20) — **「엇나감 1급」은 이상한 보고였다**

> *"1. **고객사pc에도 과금결재내역이 나와야 맞지.** 이유 → 해당 유저가 과금이슈가 생겼을시, **결재를 했는지에 대한 조회**를 할수있도록 함. **과금 중단 후 구독취소를 할수 있는 (구독취소) 버튼**도 있어야 함."*
> *"2. 수수료 … = **퍼센트로 통일해!!** 그런데 **수수료 계산은 고객사에게 보여지면 안되지, erp유져한테 왜 공개를 해?** 본사와 대리점간의 히트판구독에 대한 **영업수익영역**인데?? 그리고 **과금결재금액은 퍼센트로** 해."*
> *"**등재는 안되.** 피엠 너가 얘기한게 이상해서 교정한거야."*

## 5-1 🔴 내가 이상하게 보고한 것 — **철회**

| | PM 보고 | 🟢 사실 |
|---|---|---|
| 「엇나감 1급」 | *"과금 장부가 **본사가 아니라 고객사 PC 에 있다** ⇒ 기조 4 와 반대 방향"* | 🔴 **이상한 보고였다.** **고객사 PC 에 결제 내역이 있는 것이 맞다** — 유저가 **자기 결제 여부를 조회**해야 한다 |
| 내가 혼동한 것 | **진실원(원장·정산 기준)** 과 **고객 조회용 내역** 을 **한 덩어리로** 봤다 | 🟢 **둘은 모순이 아니다** — 진실원은 **본사**, 조회는 **고객사 PC** |
| 🔴 처분 | **「엇나감 1급」 철회** · **별건 등재 0건**(사장님 지시) | — |

🔴 **남는 참 하나** — `billing_*` 표가 **백오피스 DDL 에 0개**다. 진실원이 본사인데 **본사 쪽 표가 아직 없다** ⇒ 🔴 **이것은 「엇나감」이 아니라 B3⑧(과금 장부 일원화)이 아직 안 된 것**이다. 일정표에 **이미 있는 칸**이다.

## 5-2 🟢 실측 — **수수료는 ERP 에 노출되지 않는다**

사장님 우려(*"erp유져한테 왜 공개를 해?"*)를 **코드로 재 봤다.**

| | 실측 | 대조군 |
|---|---|---|
| 출하 DDL `billing_*` 5표 | 🟢 **수수료·정산 칸 0건**(invoices·payment_attempts·payment_methods·settings·subscriptions) | 🟢 `reseller_id`·`reseller_tier` 는 **소속 표시**(#37 수신 캐시)이고 수수료율·정산액이 아니다 |
| ERP `BillingController` | 🟢 **commission·settlement 노출 0건** | 🟢 파일 **126줄** 실재(검사기 작동) |
| `card_commission_rate`(`:2938`) | 🟢 **카드 결제 수수료**(ERP 업무) — 대리점 수수료와 **다른 것** | — |

⇒ 🟢 **경계가 이미 지켜져 있다.** 본사↔대리점 영업수익은 **백오피스 전용**이고 ERP 에 들어가 있지 않다(#7 권한 혼용 금지와 같은 축).
🔴 **앞으로 지킬 선** — 수수료·정산·영업실적·순위는 **ERP 로 내려보내지 않는다.** 고객사 PC 에 드러나는 것은 **자기 결제 내역과 구독 상태**뿐이다.

## 5-3 🟢 확정 — 단위는 **퍼센트**

| | |
|---|---|
| 🟢 정본 단위 | **퍼센트** (예: `15.00` = 15%) |
| 🔴 버리는 것 | **분수 표기**(0.1500) — 백오피스 칸이 `decimal(5,4)` 이므로 **칸 형식까지 함께 고친다** |
| 🔴 봉합 순서 | **① 단위를 퍼센트로 통일 → ② 계산기가 칸을 읽게 → ③ 본사 설정 화면 신설** (순서 바뀌면 **100배 오차**) |
| 🟡 PM 해석(틀리면 한 줄 교정) | *"과금결재금액은 퍼센트로"* = **정산액 = 과금 결제 금액 × 수수료율(%)** 로 읽었다. 결제 금액 자체는 금액(원)으로 둔다 |
