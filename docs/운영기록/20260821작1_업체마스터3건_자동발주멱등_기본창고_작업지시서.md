## 5. W4 — 자동발주·자동매입확정 멱등 (P0)

### 진단
- BOM 경로 `BomService.OrderAlertAsync` — ✅ `stock_alerts.status` 로 이미 정상
- 판매 경로 `SalesService.GetAutoOrderCandidatesAsync` — ❌ **실시간 재고만 조회, 발주 사실 미반영**
  → 입고 전까지 재고 그대로 → 같은 품목 반복 후보

### 지시
`GetAutoOrderCandidatesAsync` 에 미결 자동발주 제외 조건 추가:

```sql
AND NOT EXISTS (
      SELECT 1 FROM purchase_order_items poi
        JOIN purchase_orders po ON po.po_id = poi.po_id AND po.tenant_id = poi.tenant_id
       WHERE poi.tenant_id = i.tenant_id
         AND poi.item_id   = i.item_id
         AND po.is_auto    = 1
         AND po.status IN ('draft','ordered','partial')
         AND po.is_deleted = 0
    )
```

### ✅ DESCRIBE 실측 반영 (§#13) — 설계 초안 2건 교정
```
status enum('draft','ordered','partial','received','cancelled') NOT NULL DEFAULT 'draft'
is_deleted tinyint(1) NOT NULL DEFAULT 0
```
- 🔴 **`partial` 필수** — 부분입고는 잔량이 미결. 빠지면 **중복 발주 그대로 재발**
- `received` 제외 불필요 (재고 상승으로 자연 탈락)
- `cancelled`·`is_deleted=1` **제외 안 함** — 재발주 가능해야 함 (#20)

### 완료 판정 (🔴 반증 필수 — 글자검사 금지)
1. 자동발주 실행 → **재조회 시 해당 품목 사라짐**
2. **필터를 빼면 다시 나타남** ← 게이트 진위 확인 (feedback_gate_must_test_behavior)
3. 발주 취소 후 → **다시 후보로 나타남** (#20)
4. 부분입고 상태 → **후보에 안 나타남** (교정 항목 직접 검증)
5. 자동매입확정도 동일 동작

## 6. W5 — 기본창고 코드리뷰 (완료)

**결론: 사장님 지적이 맞다. 원인은 예상과 다르다.**

`ItemDetail.razor:121` — `private string? _selectedWarehouseId; // 참조용 — DB에 저장하지 않음`

- 기본창고 드롭다운은 **아무것도 저장하지 않는다**
- `items` 실측 40컬럼 — **창고 컬럼 자체가 없다** (저장 버그가 아니라 저장할 자리가 없음)
- 발주·매입은 **테넌트 단위 폴백**(`wh_code MAIN` 우선)만 사용 — 품목별 기본창고는 **조회조차 안 함**
- ⇒ 설정해도 **아무 변화 없음**. 화면이 사용자에게 거짓말 중

**부가 발견**: 활성 창고 0건이면 `"등록된 창고가 없습니다."` 로 매입확정 중단.
사장님이 보신 게 이 오류면 원인은 **창고 미등록**이다 — 실측에서 분리 확인 필요.
