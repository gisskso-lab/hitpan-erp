## §2 [화면] 고르기 — 자리 · 글자(처음 보는 직원 기준)

- 고르기 = `MudSelect T="string"` · `@bind-Value` 아님 — `Value="_form.StyleKey"` + `ValueChanged="OnStyleChangedAsync"`(§6).
- 글자(고객 노출 · 개발 용어 0 · `basic` 등 영문 키는 화면에 안 보임):

| 칸 | 글자 |
|---|---|
| 제목(Label) | **인쇄 모양** |
| `basic` | 기본 — 지금 쓰는 모양 |
| `formal` | 격식 — 관공서 · 처음 거래처에 낼 때 |
| `simple` | 간결 — 팩스 · 잉크를 아낄 때 |

## §3 [흐리게] 안 쓰이는 양식 — 조건 · 까닭 한 줄
- 판정 = 새 순수 함수 `FormStyleChoice.WhyNotUsed(formType, paperMode, backgroundImageUrl)` → `null` = 쓰임 / 글자 = 흐리게(`Disabled="true"`) + 그 글자를 칸 밑 한 줄(`MudText Typo.caption`). **숨기지 않는다**(인쇄 창 결-2 꼴).
- 조건은 서버 `ResolvePrintStyle`(`PdfRenderService.cs:2772~2786` · 고침 1 뒤 판)과 **같은 조건**이어야 한다 — 다르면 고객이 거짓 안내를 받는다(편집창 `PaperChoiceIgnored` 주석 `:985~990` 과 같은 원칙). 위에서부터 먼저 걸리는 줄 1개만 보인다:

| 차례 | 조건 | 까닭 한 줄(고객 노출) | 서버 짝 |
|---|---|---|---|
| 1 | 양식 유형 ∈ 법정 3종(`tax_invoice` · `invoice_exempt` · `payment_receipt`) — **목록은 편집창 `LegalFormTypes`(`:1042~1043`)를 그대로 넘겨 받음 · 두 벌 금지** | 법으로 모양이 정해진 서식이라 인쇄 모양을 바꿀 수 없습니다. | 세금계산서 전용 작성기 · E⑵ 고침 1 E-1 막음 · `LegalFormDocTypes`(`:2676`) |
| 2 | `PaperMode` ≠ `plain`(양식용지) | 미리 인쇄된 양식용지에는 인쇄 모양이 쓰이지 않습니다. 내용만 채워 인쇄합니다. | `ResolvePrintStyle` ② · 시안 PM Q-C |
| 3 | `BackgroundImageUrl` 비어 있지 않음(빈 A4 + 양식 그림 = Y 템플릿 · K3) | 양식 그림을 깐 양식에는 인쇄 모양이 쓰이지 않습니다. 올린 그림 모양대로 인쇄합니다. | `ResolvePrintStyle` ④ |
| — | 위 셋 다 아님(빈 A4 · 그림 없음 · 7종 전표) | (흐리게 0 · 도움말 §2) | 스타일 먹음(K4 옛 좌표 빈 A4 포함 · PM §72 E-3) |
- 1번 글자는 이미 나간 용지 안내(`:1003~1006` 「이 서식은 법으로 모양이 정해져 있어 …」)와 같은 말투 — 법정성 판정은 법무 몫이라는 기존 정책 그대로(§59 ⑥ (나)).
- 급여명세서: 편집창 양식 유형 목록(`FormTypes` `:575~588`)에 없음 → 이 화면 해당 0 · 서버 전용 길 그대로.
- 흐린 동안에도 저장 값은 **불러온 값 그대로**(§5) — 순백지로 되돌리면 고른 모양이 살아난다.
- 3번 글자는 F-1 편집창 고정 글(「이 양식에서는 칸 위치를 바꿀 수 없습니다」 · §73 ④)과 다른 줄 · 다른 뜻(칸 위치 말 0) — 부딪힘 0. [4] 가 두 글이 한 화면에 함께 뜨는 경우를 대조.

## §4 [2단] 큰글씨 폭 모자람 안내 — E⑵ 고침 2 뒤
- 전제: 큰글씨 시안 정정(`../설계/erp/20261120_WG1-51_큰글씨스타일_시안정정.md`) **§4 R-4 · R-5 를 PM 이 결재**하고 E⑵ 고침 2 가 서버 셈(본문 폭 W < 459pt → basic)을 넣은 뒤. 결재가 안 나면 2단 = 0.
- 판정 = `FormStyleChoice.LargeFallsBack(paperSize, orientation, marginLeftMm, marginRightMm)` — 서버 고침 2 의 셈과 **같은 식**(종이 폭 A4 595.28 · A5 419.53 · Letter 612 / 가로 = 긴 변 / 여백 빈 칸 = 20mm / 1mm = 72/25.4pt).
- 보이는 때: 고른 값 = `large` **이고** §3 흐리게 아님 **이고** `LargeFallsBack` 참 → 칸 밑 한 줄(경고색 아님 · 정보):
  「이 용지와 여백에서는 큰글씨 칸이 다 들어가지 않아 **기본 모양으로 인쇄됩니다.** 좌우 여백을 줄이거나 방향을 가로로 바꾸면 큰글씨로 인쇄됩니다.」
- 고르기는 막지 않는다(고객 자유 · 까닭만 말함 — `PaperChoiceIgnored` 꼴).

## §5 [저장] 저장 값 · 불러온 값
- 저장 값 = `basic` · `formal` · `simple` · `large` 넷 중 하나(소문자) — E⑵ 고침 1 저장 문 허용 4값과 같은 글자. 고르기 항목 값 = 서버 `KnownStyleKeys`(`PdfRenderService.cs:2745`)와 같은 집합(§9 T5 가 대조).
- 불러올 때(`:741` `StyleKey = Template.StyleKey,`): `FormStyleChoice.Normalize(Template.StyleKey)` 로 고름 — 앞뒤 공백 자름 · 대소문자 무시 · 빈 값 · null · 모르는 값 = `basic`. 옛 줄은 지우지 않고 `⬛` 주석으로 남김(#1).
  - 까닭: 모르는 값은 지금도 종이에 basic 으로 나감(`ResolveStyleKey` `:2717~2731`) → 화면에 「기본」 으로 보이는 것이 사실과 같고, 그대로 보내면 고침 1 허용 목록에 걸려 **양식 저장 자체가 막힘**. 알림 0(종이 무변 · 고객이 알 거리 없음 — E4-4).
- 새 양식: `_form` 기본값 `"basic"`(`FormTemplatesPage.razor:245`) 그대로.
