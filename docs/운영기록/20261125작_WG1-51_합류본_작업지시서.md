## §5 [합류 실행] 명령 꼴 · 충돌 푸는 법

**5-0 합류 직전 다시 셈(§132 ⑧ 의무)** — ⓐ `git ls-remote origin refs/heads/main` ⓑ 갈래 머리 6개 `git rev-parse` = S-2 ⓒ §4 를 `merge-tree --write-tree --name-only` 로 다시(쓰기 0) — 충돌 파일 목록이 §4 와 다르면 멈추고 PM 보고.

**5-1 가지** — 수동 나무: `git worktree add -b feat/20261125-WG1-51-합류본 <스크래치 경로> <ⓐ 의 SHA>`(레포 루트 작업 사본 쓰지 않음 · 두 창 금지).

**5-2 머지** — 단계마다 `git merge --no-ff --no-commit <SHA>` → 충돌 있으면 아래 꼴로 풀기 → **파일 이름 지정 `git add <그 파일>`**(`git add -A` 금지) → `git commit -F <메시지 파일>`(제목 「Merge W-G1-51 갈래 <이름> (<SHA8>) into 합류본」) → `git rev-parse HEAD^{tree}` = §4 값.

**5-3 설계 문서(①)** — 충돌 덩이 하나뿐(나머지 main 정정 L133 · L162 는 자동으로 섞임):
```
(main 쪽 2줄) - **정정(2026-11-19 · CTO 판정 F-1 Ⓐ (나))**: ⓘ-11 …
              - **정정(2026-11-19 · [4] P2-2 · PM 판단)**: Y 재사용 …
(§59 쪽 1줄)  - **§59 고침 1 설계 1줄**(2026-11-20 · 설계팀장 존 · PM 결재 §85 ⑥ …
```
→ 표지 3줄(`<<<<<<<` · `=======` · `>>>>>>>`)만 지우고 **main 2줄 → §59 1줄** 차례로 셋 다 남김. 결과 줄 수 = main 판 305 + 1 = **306** · 모의 blob `0ed896e2`. 「main 판으로」 · 「§59 판으로」 · 「바닥판(189ad5f6)으로」 어느 한쪽 고르기 = #1 위반(O9).

**5-4 csproj(⑤)** — 같은 자리에 각자 `<Compile Include … Link=…>` 1개 + 주석 1줄:
```

<Compile Include="..\HitPan.Web\Services\RenderedPdfDownload.cs" Link="Linked\RenderedPdfDownload.cs" />
<!-- 🔴 20261120 W-G1-51 갈래 E⑷ … -->                    ← E⑷ 2줄
<Compile Include="..\HitPan.Web\Services\FormStyleChoice.cs" Link="Linked\FormStyleChoice.cs" />
```
