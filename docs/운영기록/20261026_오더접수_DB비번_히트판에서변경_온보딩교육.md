### 사장님 오더 원문
> *"한가지 방법을 제안한다면, 히트판 설치 후, 히트판 자료관리 메뉴에서 데이터베이스 암호를 변경할 수 있도록 하고, 온보딩떄, 데이터베이스 암호는 수시로 변경해줘야 한다. 라는 교육을 하면 어때? 최초로 설치시 나가는건 동일하게 나가고!!"*
>
> *"고객사가 마리아디비를 켜서 디비패스워드를 바꾸고 하는게 아니라 히트판에서 바꿀수 있다면?"*

### 이렇게 이해했다 (명문화 · #33)
1. **첫 설치는 지금과 똑같다** — 공통 비번으로 나간다. 설치마법사는 **한 글자도 안 바뀐다**
2. 설치 **뒤에** 고객이 **히트판 화면**(자료관리)에서 DB 비번을 바꾼다
3. 🔴 **고객이 MariaDB 를 열지 않는다** — 콘솔·HeidiSQL·명령창 0회. 히트판이 대신 한다
4. 온보딩에서 *"DB 암호는 수시로 바꿔야 한다"* 를 **교육**한다
5. ⇒ 공통 비번의 위험(한 곳 뚫리면 전 고객사 동일 자격증명)이 **고객 손으로** 끊긴다

## §1 🟢 PM 1차 판단 — **된다고 본다. 그리고 재료가 이미 있다**

오더를 받고 실측한 것(파일 단위):

| 전제 | 실측 | 뜻 |
|---|---|---|
| 런타임 비번의 **단일 진실원**이 있나 | 🟢 **`db.conf`** — `src/HitPan.Application/Common/TenantConfigReader.cs:47~49` 가 exe 기준 3단계로 찾는다 · `src/HitPan.Infrastructure/Configuration/TenantConfigReader.cs` 도 같은 축 | 비번이 **한 파일**에 산다 ⇒ 바꿀 자리가 흩어져 있지 않다 |
| 히트판이 **그 파일을 쓸 수** 있나 | 🟢 **`src/HitPan.Watchdog/DbConfWriter.cs` 가 이미 있다**(읽기는 `DbConfReader.cs`) | 🔴 **새로 만들 기능이 아니다** — 이미 쓰는 통로가 산다 |
| 자료관리 메뉴에 화면을 더할 자리가 있나 | 🟢 `src/HitPan.Web/Pages/Settings/BackupPage.razor` · `DataResetPage.razor` | 세 번째 화면이 들어갈 자리다 |
| `appsettings` 를 고쳐야 하나 | 🟢 **아니다** — 연결문자열이 `db.conf` 에서 온다 | **#21 에 안 걸린다**(이게 제일 중요했다) |

🔴 그래서 제 1차 판단은 **「고칠 자리가 많아서 못 한다」가 아니라 「이미 있는 통로를 화면에 잇는 일」**이다.
🔴 다만 **1차 판단이고 [1-V] 가 아니다.** 아래 §2 를 재지 않고 설계로 넘어가지 않는다.

## §2 🔴 [1-V] 가 **반드시** 재야 하는 것 (전제 미확인 설계 금지)

| # | 재야 할 것 | 왜 — 틀리면 무슨 일이 나나 |
|---|---|---|
| **V-1** | 🔴 **원자성** — ⒜ MariaDB 계정 비번 변경 ⒝ `db.conf` 쓰기 ⒞ API 재기동, 이 **셋 중 하나가 실패하면** 어떻게 되나 | ⒜만 되고 ⒝가 실패하면 **히트판이 자기 DB 에 못 붙는다** ⇒ **고객 장사가 멈춘다**(#20 P0). **되돌리기(rollback)가 설계의 본체**다 |
| **V-2** | 🔴 **바꾸기 전에 왕복으로 증명**하나 — 새 비번으로 **실제 접속해 본 뒤** `db.conf` 를 쓰나 | 「바꿨다」와 「붙는다」는 다르다. 오늘 두 번 배운 자리다 |
| **V-3** | 🔴 **비번을 들고 있는 그 밖 자리** 전수 — 특히 `scripts/backup-daily.ps1:7` **하드코딩 폴백** | 비번을 바꾸면 **백업이 조용히 실패**할 수 있다. 🔴 백업 실패는 **업데이트 차단** 조건이다 ⇒ 자동업데이트까지 멈춘다 |
| **V-4** | 🔴 **워치독**이 옛 비번을 들고 있나 · 바뀐 걸 어떻게 아나 | #43 — 워치독·업데이트 흐름은 **안 바뀐다**. 워치독이 못 붙으면 자가 회복이 죽는다(#30) |
| **V-5** | **API 재기동이 필요한가** · 필요하면 **서비스 조작**이다 | 🚨 **#29 인프라 조작 사전 승인제** — 서비스 재시작은 사장님 승인 축이다 |
| **V-6** | **누가 바꿀 수 있나** — 부모계정만인가 | #38·#40 · 자식계정이 DB 비번을 바꾸면 안 된다 |
| **V-7** | 바꾼 비번을 **어디에 적어 주나**(고객이 잊으면?) | 🔴 **본사는 안 가진다**(#18·#22). 잊으면 복구 경로가 무엇인지가 설계거리 — *"본사에 문의"* 는 답이 아니다 |
| **V-8** | 설치본(`HitPan-Universal.iss`)이 만드는 계정과 **같은 계정**인가 | 다른 계정이면 바꿔도 효과가 없다 |

## §3 🔴 온보딩 교육 — 이건 **문서 축**이다

| | |
|---|---|
| 무엇 | 온보딩에 *"DB 암호는 수시로 바꿔야 한다"* 를 넣는다 |
| 어디 | CS 누리집 / 온보딩 자료 (코드 아님) |
| 🔴 주의 | **#23** — 고객 글에 「DB」·「MariaDB」 같은 개발 용어를 그대로 쓸지는 **수석 웹디자이너·CS팀장 판단**이다. *"데이터베이스 암호"* 가 현장 직원에게 읽히는 말인지 묻는다 |
| 🔴 주의 | **「수시로」는 측정 불가**다. 온보딩 글은 **구체적으로** — *"처음 쓰실 때 한 번 · 그 뒤 ○개월마다"* 처럼. 숫자는 **사장님 결재거리** |
