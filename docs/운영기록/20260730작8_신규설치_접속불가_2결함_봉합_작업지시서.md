## 1. P0-1 — cloudflared 서비스 시작 누락

### 1-1. 원인

`cloudflared service install <token>` 은 **등록만** 한다. Windows 서비스는 자동 시작되지 않는다.
설치 스크립트에 시작 호출이 없다.

### 1-2. 봉합 (담당: 백엔드 개발자 1 + 보안 개발자 1)

**대상 파일 = `installer/HitPan-Universal.iss`** (게시본. `deploy-update.yml:348` ISCC 인자로 확정)

> ⚠️ **`installer/HitPan.iss` 를 고치지 마라.** 게시 경로가 아니다. 작5 가 이 파일을 오지목해 반려됐다.

`service install` 직후 3가지를 **추가**한다(헌법 #1 추가만):

```
1) sc config cloudflared start= auto      ← 재부팅 후에도 살아남음 (헌법 #28)
2) sc start cloudflared                   ← 지금 시작
3) 시작 확인 (sc query → RUNNING)          ← 확인까지가 봉합이다
```

### 1-3. 🔴 3번이 핵심 — 확인 없는 시작은 봉합이 아니다

**[3] 착수 전 확인 의무**: `sc qc cloudflared` 로 현재 `START_TYPE` 실측.
`DEMAND_START` 면 1) 이 반드시 필요하다. **개발명세서에 실측값 기록.**

### 1-4. N-2 — 실패 시 조용히 넘어가지 않는다

시작 실패·`RUNNING` 미도달 시 **설치를 실패로 처리**하고 안내한다(헌법 #15·#24).

> 지금은 서비스가 죽어 있어도 **"설치 완료"로 끝난다.** 그 침묵이 이 사고의 본질이다.

안내문 예(개발용어 금지, 헌법 #23):
> 설치를 마무리하지 못했습니다. 네트워크 연결 프로그램이 시작되지 않았습니다.

## 3. P0-2 — API 주소 하드코딩 🚨 헌법 #21 결재 필요

### 3-1. ⭐ 봉합 로직이 이미 있다 — 하드코딩이 그것을 무력화한다

`src/HitPan.Web/Program.cs` 실측:

| 줄 | 코드 | 동작 |
|---|---|---|
| 14 | `apiBase = builder.Configuration["ApiBaseUrl"]` | **`api-demo` 채택 ← 여기서 끝남** |
| 17·22 | 환경변수 폴백 | 미도달 |
| **35** | `apiBase = builder.HostEnvironment.BaseAddress` | **근본 해결책. 절대 도달 못 함** |

35행 주석이 오늘 상황을 정확히 예언했다:

> *"근본 해결: 폴백을 '현재 페이지 출처'(HostEnvironment.BaseAddress)로 둔다."*
> *"명시값(api-demo 등)이 있으면 위에서 채택되므로 기존 정상 배포는 무영향"*

⇒ **코드는 이미 옳다. `appsettings.json` 의 값 한 줄이 그것을 막고 있다.**

### 3-2. 채증 — 3개 파일

```
src/HitPan.Web/wwwroot/appsettings.json:2              "ApiBaseUrl": "https://api-demo.hitpan.kr"
src/HitPan.Web/wwwroot/appsettings.Development.json:2   동일
src/HitPan.Web/wwwroot/appsettings.Local.json:2         동일
```

### 3-2-B. ⭐ "전에 됐는데 왜 안 되나" — 사장님 의문의 답 (git 이력 실측)

> **사장님 의문**: *"근데 전에 됫는데 지금 안되는게 말이 안되잖아??"*

| 시점 | `ApiBaseUrl` | 됐나 |
|---|---|---|
| 4/30 이전 | `http://localhost:5257` | 개발 PC 만 |
| **4/30 `867f636`** *"demo.hitpan.kr 통신 인프라 완전 봉합(12시간 작전)"* | **`api-demo.hitpan.kr`** | **demo 한 대만 — 이때 "됐다"** |
| 지금 | 그대로 | demo 외 **전부 안 됨** |

**회귀가 아니다. 임시값이 정본으로 굳은 것이다.**
4/30 당시 고객이 demo 한 대뿐이라 그 값이 **정답이었다.** 고객이 늘어나자 같은 값이 오답이 됐다.
6/25 에 `Program.cs:35` 로 근본 해결책이 들어왔으나, **이 하드코딩이 :14 에서 먼저 채택돼 무력화**했다.

⇒ 사장님 의문이 정확했다. "전에 됐다"는 **사실**이고, 조건이 변한 것이다.

### 3-3. 🚨 헌법 #21 충돌 → **근본 봉합으로 우회 없이 해결** (사장님 지시)

> **사장님 지시**: *"지금 그 헌법으로 안되는거라면, 되는방향으로 봉합해"* · *"1회만 이라는 방법은 없어. 근본적인 방법으로 봉합해"*

**실측**: `pre-commit` 훅이 `appsettings.json` 커밋을 **실제로 차단**한다.
훅에 결재 우회 장치는 **설계돼 있지 않다**(확인). `--no-verify` 만이 길이었다.

⇒ **`--no-verify` 를 쓰지 않는다.** 훅은 WASM 부트 파괴를 막는 방어선이다.

**채택안 = 리포 무손상 + 출하본만 중립화** (`deploy-update.yml` 신규 스텝)

| 항목 | 처리 |
|---|---|
| `src/HitPan.Web/wwwroot/appsettings.json` | ✅ **손대지 않음** (헌법 #21 · 훅 통과) |
| 출하 payload `web/wwwroot/appsettings.json` | 빌드 중 `ApiBaseUrl` → `""` |
| 출하 payload `api/wwwroot/appsettings.json` | 동일 (터널이 서빙하는 실체) |
| 검증 | `api-demo` 잔존 0건 확인 · 대상 0개면 **배포 중단**(fail-closed) |

**이 방식이 근본인 이유**:
- 리포 파일이 어떤 값이든 **출하본은 항상 중립** — 사람이 실수로 다시 넣어도 무해
- 위 `strip` 스텝과 **같은 정신**(리포는 두고 산출물만 정정) — 기존 설계와 정합
- 훅·#21 을 **느슨하게 하지 않는다**(헌법 #22 정신: 게이트를 낮추지 말고 산출물을 맞춘다)

> **헌법 #21**: `appsettings.json`·`appsettings.Development.json` **삭제·수정 금지** (WASM 부트 필수)

메모리에도 같은 이유로 커밋 보류된 이력이 있다(`project_appsettings_backoffice_url_pending`).

**봉합안 = `ApiBaseUrl` 값을 빈 문자열(`""`)로 두거나 키를 비운다.**
그러면 `Program.cs:35` 폴백이 살아나 **각 고객이 자기 도메인을 부른다.**

| 항목 | 내용 |
|---|---|
| 파일 **삭제** | ❌ 안 함 (헌법 #21 준수 — 파일은 유지, WASM 부트 무영향) |
| 파일 **구조 변경** | ❌ 안 함 (키 유지, 값만) |
| 변경 | `"ApiBaseUrl"` **값만** `""` 로 |
| 영향 | 개발 PC 는 `Local`/환경변수로 지정 가능(17·22행 경로 유지) |

> 🔴 **[3] 은 사장님 명시 결재 없이 이 3개 파일을 건드리지 마라.**
> P0-1 만 먼저 봉합하고, P0-2 는 결재 후 별도 커밋한다.

### 3-4. 보안 심사 대상 (보안 매니저 1 + 보안 상무)

현재 `api-demo` 호출은 **CORS 가 막아서** 차단되고 있다. 그러나:

> **CORS 가 사고를 막아준 것이며, 설계가 안전한 것이 아니다.**
> `api-demo` 가 CORS 를 열면 **다른 회사 API 로 요청이 가는 구조**가 된다.

헌법 #2(tenant_id 는 JWT 만)·#18(데이터 경계) 관점에서 심사 의견을 개발명세서에 남긴다.
