# 【2】 업무 주의사항 — 반복해서 틀린 자리

## 🔴 2-1. "고쳤다" ≠ "갔다" — **6차 재발**

코드는 **매번 정상**이었다. 끊긴 건 **전달 경로**이고, **끊기는 자리만 옮겨간다.**

| 차수 | 끊긴 자리 |
|---|---|
| 1~4차 | 배선·화면·머지·게시 |
| 5차 | 게이트 13건 초록불인데 반려 |
| **6차(작8)** | **화면이 서버를 부르지도 않았다 / 답을 받고도 버렸다 / API를 안 불렀다** |

**검증 질문을 바꿔라**: *"고쳤나"* ❌ → **"갔나"** ⭕

🟢 **통과한 항목이 최고의 단서다.** 작8에서 중복차단만 전표번호가 떴는데,
그건 **같은 서비스·같은 예외 경로**였다 ⇒ *서버 정상, 화면 문제* 로 **즉시** 좁혀졌다.
**하나만 되면, 공통부는 정상이고 갈린 데가 범인이다.**

## 🔴 2-2. 게이트는 글자가 아니라 **동작** — 가짜 누적 21번

작7 게이트 **9건이 전부 사실**이었는데 사장님은 반려하셨다.
*"서버가 반품번호를 담은 문장을 만드는가"* 를 쟀기 때문이다. **만드는 쪽만 봤다.**

**게이트 체크리스트:**
1. 짜면 **곧바로 봉합 빼고 FAIL 확인** — 안 하면 짠 게 아니다
2. **초록불이 어디서 오나** (내 코드냐, DB 제약이냐)
3. **낱말 하나로 검사 금지** — 같은 이름이 정의·배선·주석에 다 산다
4. **`if (false && …)` 로 죽여도 통과하면 가짜** — 낱말은 그대로 남는다
5. **부르는 것과 따르는 것은 다르다** — 답을 담은 변수로 **막는지**까지
6. **대조군 필수** — 없으면 "전부 막기"로도 통과한다
7. 🔴 **만드는 쪽만 재지 마라** — 화면이 부르는지·읽는지·표시하는지

**서버는 처음부터 맞았다.** 반품번호를 담은 문장을 정확히 만들고 있었다.

2. **발주·매입 화면 = 응답 본문을 버렸다**

3. **회계검산 = 화면이 API 를 한 번도 안 불렀다** (Web 전체 호출 0건)
   🔴 **PM 오보** — 화면을 안 보고 *"15건 보일 것"* 이라 보고했다.
4. 🔴 **화면만 고쳤어도 안 됐다** — 서버가 **상태검사를 사슬검사보다 먼저** 던져
