자격증명도(P0-1·P0-3·P0-4), 스키마도(P0-2) **서버까지 가지 못한다.** 오늘 사장님 손으로 두 번(환경변수 이름 교정 · 표 1장) 메운 것이 **전부 손으로 메운 것**이다.

# 1. P0 — 전달 경로 4건 (한 작지서로 묶는다)

## P0-1 🔴 비밀 배포 스크립트가 **정본 이름을 영구히 못 보낸다**
```
scripts/deploy-ncp-secrets.sh:42   if [[ "$line" =~ ^([A-Z_][A-Z0-9_]*)=(.+)$ ]]; then
```
🔴 **대문자·숫자·밑줄만 받는다.** 그런데 코드가 읽는 정본 이름은 **섞인 대소문자**다 — `License__Pepper` · `Backoffice__BizNoPepper` · `Smtp__Host`.
⇒ **그 줄들은 아무 말 없이 건너뛴다**(에러도, 경고도 없다). 🔴 **고친 이름을 넣으려 해도 이 스크립트로는 영원히 못 넣는다.**
**처분**: 정규식을 `^([A-Za-z_][A-Za-z0-9_]*)=` 로 넓히고, 🔴 **건너뛴 줄이 1개라도 있으면 `exit 1`** 로 **큰 소리로 실패**시킨다(#15). 게이트 = 섞인 대소문자 키 1개를 넣고 **override 파일에 실제로 적히는지** · 음성 대조군 = 빈 줄·주석은 조용히 건너뛴다.

## P0-2 🔴 스키마가 운영에 닿는 경로가 **아예 없다** + **적용 이력 표도 없다**
```
grep -c installer .github/workflows/deploy-ncp.yml   → 0
SchemaMigrator.cs:51-56   폴더 없으면 경고 1줄 남기고 통과
```
⇒ `installer/backoffice/*.sql` 이 **서버로 가지 않고**, `HITPAN_BO_AUTO_MIGRATE=1` 을 켜도 **읽을 파일이 없어 무력**하다.
🟢 오늘 배포가 운영 DB 를 안 바꾼 이유가 이것이고, 🔴 **`46_*.sql`(10/15 신설)이 운영에 없어 메일 장부가 비었던 이유**도 이것이다(1호 피해 **실증**).
🔴 **그리고 어젯밤 손으로 넣은 `46` 은 레포에 흔적이 없다** — 적용 이력 표(`schema_migrations` 류)가 백오피스에 **0건**이라 **PM 문서 1장이 유일한 근거**다(CTO 못 잼 ④).
**처분**: ① 배포가 `installer/backoffice/` 를 **서버로 나른다** ② `HITPAN_BO_SCHEMA_DIR` 를 그 자리로 지정 ③ **적용 이력 표 신설**(파일명·체크섬·적용시각) ④ 🔴 **`AUTO_MIGRATE` 를 켜는 것은 별 결재** — 경로를 만드는 것과 자동 적용을 켜는 것은 다른 사안이다(#29).

## P0-3 🔴 레포 문서가 **아직도 틀린 이름을 지시한다**
```
docs/개발/설치배포/ENV_SECRETS.md:8-25   🟢 정정 블록 있다(오늘 추가)
                              :40-41   🔴 본표가 여전히 BACKOFFICE_License__Pepper
                              :56-57   🔴 PowerShell 예시도 BACKOFFICE_ 그대로
```
🔴 **머리의 정정을 못 보고 표부터 읽는 사람은 어제와 똑같이 틀린 이름을 넣는다.** 정정 블록은 **덮어쓰기 금지(#1)를 지킨 결과**지만, **표가 살아 있는 한 재발 장치도 살아 있다.**
**처분**: 표·예시의 각 줄에 **🔴 취소선 + 정본 이름 병기**(지우지 않는다). 게이트 = 그 문서에 `BACKOFFICE_` 가 **정정 표시 없이** 나오면 FAIL.

## P0-4 🔴🔴 **거짓 초록의 기계장치 — 내가 적어 둔 것보다 나쁘다**
`CredentialsStatusController.cs` 의 `Probe(envName, configKey, display)`:
```
var env = Environment.GetEnvironmentVariable(envName);   // 화면에 지시하는 이름
var cfg = _config[configKey];                            // 코드가 실제로 읽는 키
var v = !IsNullOrWhiteSpace(env) ? env : cfg;            // 🔴 둘 중 하나만 있으면 present
...  EnvName = envName                                    // 🔴 사람에게 보여주는 이름
```
🔴 **화면은 `HITPAN_LICENSE_PEPPER` 를 넣으라고 지시하는데, 소비자 11곳은 `License:Pepper` 를 읽는다.**
⇒ 지시대로 `HITPAN_LICENSE_PEPPER` 를 넣으면 **`env` 가 채워져 칸이 초록이 된다. 그런데 설치 경로는 그대로 500 이다.**
🔴 **이건 「이름이 다르다」가 아니라 「지시를 따르면 거짓 초록이 만들어진다」다.** 화면과 소비자가 **서로 다른 자리를 본다.**
🟢 **정본 모양은 같은 파일에 이미 있다** — `ProbeSmtp("Smtp:Host", …)` 는 **설정키만** 받는다.
**처분**: `Probe` 를 `ProbeSmtp` 와 같은 모양(**설정키 1개**)으로 바꾸고, 화면에 보여줄 이름은 **설정키에서 기계적으로 만든다**(`License:Pepper` → `License__Pepper`). 게이트 = **「화면이 지시한 이름만 넣으면 칸이 빨강이어야 한다」**(지금은 초록 ⇒ 봉합 전 FAIL 확인 가능) · 음성 대조군 = 정본 이름을 넣으면 초록.
