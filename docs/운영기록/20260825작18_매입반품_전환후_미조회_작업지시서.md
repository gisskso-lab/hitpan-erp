## 3. 실측으로 확정한 것

### 🟢 확정 1 — 만드는 쪽은 정상 (SQL 실측)
전환 INSERT 를 로컬 MariaDB(`hitpan_e2e`)에서 그대로 실행 → `INSERT OK`. `is_deleted=0`·`status='draft'` 정상.
목록 SQL 도 그대로 실행 → **그 행이 조회된다.** ⇒ **행은 만들어지고 SQL 도 읽는다.**

### 🔴 확정 2 — 현황이 0건인 이유 (SQL 실측)
같은 행에 두 질의를 나란히:

| 질의 | 조건 | 결과 |
|---|---|---|
| 목록 `GetReturnsAsync` | `is_deleted=0` | **1건** 🟢 |
| 현황 `RT_BY_PERIOD` | `is_deleted=0 AND status='confirmed'` | **0건** 🔴 |

⇒ **전환은 `draft` 로 만드는데 현황은 `confirmed` 만 센다.**

### 🔴 확정 3 — P0-1 재현 (SQL 실측)
매입반품 ID 를 `sales_returns` 에서 조회 → **0건**. 두 테이블은 별개다.
⇒ 목록에서 확정을 누르면 **반드시 실패**한다. 확정 경로가 원천 차단돼 있다.

## 4. 🔴 원인 — 증상 3개, 원인은 하나로 수렴한다

ERP 매니저 판정:
> **"전환 버튼이 담당자를 아무 데도 데려다주지 않는다"** — 증상이 세 개로 보였을 뿐이다.

서버는 `returnId`·`returnNo` 를 **정상 반환**하는데(`PurchaseController.cs:235`)
클라이언트가 **`bool` 로 버린다**(`DeliveryService.cs:699`). 그래서 담당자는 방금 만든 반품서의
**번호도 위치도 모른 채** 원래 화면에 서 있다.

| 오더 | 진짜 원인 |
|---|---|
| ① | 매입용 불러오기 **미구현** (판매쪽 대칭물 없음) |
| ② | 전환 후 **그 문서로 데려가지 않는다** — 목록 재조회 문제가 아니다 |
| ③ | `draft` 라 현황 집계 대상이 아니다 **+ 확정하러 가도 P0-1 로 실패** |

## 5. 🔴 현장 판정 — 왜 draft 가 맞나 (ERP 매니저)

전환은 매입 품목을 **전량 복사**한다. 100개 입고 중 3개 불량이어도 **100개짜리 반품서**가 나온다.

| 순서 | 누가 | 무엇을 |
|---|---|---|
| 1~2 | 창고→구매 | 불량 발견 → **반품전환** |
| 3~4 | 구매 | **수량 100→3 수정 · 반품사유 입력** |
| 5 | 구매 | 🔴 **거래처 통화 — "받아주십니까"** (당일~3일) |
| 6~7 | 거래처→구매 | 동의/거절 → **반품확정** |

⇒ **draft 는 "덜 된 상태"가 아니라 "거래처 답을 기다리는 상태"다.**
자동확정하면 안 보낸 97개가 재고에서 빠지고 미지급금이 깎인다.

🟢 **결론: 자동확정 금지 · 현황 `confirmed` 필터 유지.** (헌법 #6 + 작3 결재 + **업무상으로도 맞다**)

### W7 — 반품현황 조회유형 (사장님 추가오더) — 🟢 **코드 수정 불요**

> 사장님: *"반품현황 클릭시 조회유형으로 필터링이 다 되야되."*
> 사장님: *"조회유형 상관없이 다 안보임. **그런데, 반품처리가 작동이 안되니 당연.**"*

🔴 **사장님 진단이 정확하다. 실측으로 확인했다.**

| 검사 | 결과 |
|---|---|
| 화면 재조회 (`ReturnStatusPage.razor:19`) | 🟢 `ValueChanged` + 즉시 `SearchAsync` — **작17 패턴 이미 적용됨** |
| 서버 필터 4종 | 🟢 각 유형에 맞는 컬럼(거래처명/품명/사원명)을 정확히 건다 |
| 빈 검색어 처리 | 🟢 `LIKE '%%'` 전부 통과 — SQL 실측 확인 |

⇒ **필터링 로직은 멀쩡하다.** 4종이 다 0건인 건 **확정된 반품이 0건**이기 때문이다.

**직접 작성한 반품(=`receipt_id` NULL)은 '미지정'으로 뭉친다.**
🔴 그 근거 주석(`:1212` *"purchase_returns 에 created_by 컬럼 없음"*)은 **거짓**이다 —
DESCRIBE 실측 결과 `created_by` **실재**하고 `GetReturnsAsync:769` 는 이미 그걸 쓴다.
⇒ `rt.created_by` 기반으로 정정 + 낡은 주석 삭제.

⚠️ *"주석·안내문은 코드가 아니다"* 가 또 재발한 자리다.
