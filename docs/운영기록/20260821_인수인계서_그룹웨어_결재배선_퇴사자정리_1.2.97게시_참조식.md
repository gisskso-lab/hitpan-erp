## 1. 오늘 한 일 — 사장님 오더: 그룹웨어 재설계

시작은 *"작업 후 ci/cd 잘 안 돌아가는거 점검하고, 이제 그룹웨어 재설계 수준으로 다시 만질거야"* 였다.

### 🔴 조사에서 드러난 것 — 오더보다 결함이 먼저였다

그룹웨어 13화면을 전수 조사하니 **결재가 3가지 방향으로 고장나 있었다**:

| 결함 | 증상 | 공통점 |
|---|---|---|
| **휴직** | 상신 코드는 있는데 **설정에 항목이 없어** 켤 수가 없다 | 화면은 정상 |
| **초과근무** | 설정엔 뜨는데 **상신 코드가 없다** | 화면은 정상 |
| **원본 미반영** | 결재는 승인되는데 **신청서는 대기중** | 화면은 정상 |

> 🔴 **셋 다 "화면은 멀쩡한데 아무 일도 안 일어나는" 종류다.**
> 빌드 0/0 · 시험 452개를 전부 통과하면서 살아 있었다.

### 봉합 7건 (전부 게시됨)

1. 휴직 결재 라벨 — 설정화면에 "휴직" 이 뜬다
2. 휴직 승인 → 원본 + **사원 상태(재직→휴직)** 반영
3. 초과근무 결재 배선 — 신청하면 결재로 올라간다
4. 초과근무 승인/반려 → 원본 상태 반영
5. **초과근무 관리자 게이트** — 본인이 본인 걸 승인하던 것
6. **백필 퇴사자 차단** — 퇴사자 로그인 시 새 사번 발급되던 것
7. **퇴사 → 결재선 해제 + 미결 회수**

## 2. 🔴 오늘의 교훈 — 대조실험이 **내 시험을 3번 잡았다**

시험을 먼저 짜고 FAIL 을 확인한 뒤 봉합하는 방식으로 갔다.
그런데 **봉합만 되돌려 다시 FAIL 되는지** 확인하는 자리에서, **내 시험이 가짜였던 것을 3번 잡았다**:

| # | 무슨 일 | 안 잡았으면 |
|---|---|---|
| 1 | `UPDATE overtime SET` 존재만 봐서 **반려 줄이 승인 조건을 대신 만족** | 승인이 죽어도 초록불 |
| 2 | `Resign\|IsActive` 를 느슨하게 봐서 **봉합 전 코드가 조건을 만족** | 봉합 안 해도 초록불 |
| 3 | 파일 전체에서 `["x"]=` 를 긁어 **다른 사전**(`pending`·`cash`)까지 문서유형으로 오인 | **없는 결함 9건을 "봉합"** |

> 🔴 **1·2 는 "봉합을 빼도 통과하는" 반쪽 게이트였다.**
> 대조실험을 안 했으면 *"시험 619개 통과"* 를 근거로 **안 되는 코드를 내보냈다.**
> 3 은 반대로 **없는 결함을 만들 뻔했다.**

⇒ feedback_gate_must_test_behavior 그대로다. **초록불이 어디서 오는지 봐야 한다.**

## 3. 🔴 PM 오판 2건 — 실측이 바로잡았다

### 오판① *"퇴사자 로그인이 안 막힌다"* → **틀렸다**
`AuthService` 에서 `is_active`(스네이크)만 grep 해 **`user.IsActive`(프로퍼티)를 놓쳤다.**
실측: `ResignAsync` 가 `employees`·`users` 를 **함께 끄고**, 로그인이 그걸 검사한다.

> 🔴 시험이 **예상과 달리 통과**했을 때 그냥 넘기지 않고 파고들어 잡았다.
> 넘겼으면 **이미 있는 방어를 또 만드는** 헛작업을 했다.

### 오판② *"안 고치면 급여가 잘못 나간다"* → **틀렸다**
주석에 그렇게 적었는데, `PayrollService` 는 `absence_id` 로 **잇기만** 하고 금액을 자동계산하지 않는다.
**사장님 수동원칙이 이미 코드에 지켜지고 있었다.** 주석을 사실대로 고쳤다.

## 4. 사장님 결재 기록 (이번 세션)

| 결재 | 내용 |
|---|---|
| 순서 | **①퇴사 → ②휴직배치 → ③초과근무게이트 → ④메뉴·필터 → ⑤메신저** |
| V2 | 승인경로 **결재로 일원화** |
| 결재 메뉴 | **A안** — 창구는 통합, 결재설정은 ON/OFF+결재라인 한 화면 |
| 🔴 **급여** | **수동입력 원칙.** *"급여가 휴직을 모르고 사원만 알면 됨"* |
| 🔴 **휴직급여** | *"휴직에 휴직급여가 나갈 수도 있으니 **급여 비활성 처리하면 안됨**"* |
| 퇴사 | **상태변경**(근로확인서 떼러 올 수 있으니) + 기능 비활성 + **재입사(부모계정만)** + 숨김처리 |
| 급여 트랙 | **회계·경리 파트 손볼 때 함께** |
| 초과근무수당 | 회계 **구조는 열어두되 구현은 회계 때** |
| 메신저 | **프로젝트 분리 안 함. 지금 상태에서 수정만** |
| 연봉계산기 | **정식배포 때** |

## 5. 김삼성 상무 판정 — 🔴 PM 제안을 뒤집었다

> *"자체 승인 버튼 제거는 **회수·전결·결재선변경이 갖춰지기 전엔 하면 안 된다.**
> **순서가 거꾸로다. 탈출구를 먼저 만들고 정문을 좁혀야 한다.**"*

**PM 실측으로 상무님 지적 2건 확인**:
- 휴직 상태 자동 배치 **없음** — 수동 버튼뿐
- 초과근무 관리자 게이트 **없음** — 휴직엔 있는데 (③에서 봉합)

**주요 반증**:
- 자체 승인 버튼은 **없애지 말고 [긴급 처리]로 남기고 사유·이력 기록** — *"막는 게 아니라 흔적을 남긴다"*
- 중소기업은 **대표가 결재함에 안 들어온다** — 강제하면 결재를 아예 끄고 쓴다
- 초과근무 3단계 결재는 현장에서 **안 쓰인다**(월 200~300건 → 일괄승인)
- 오더 15 메뉴는 **관리자 기준** — 여는 사람 90%가 직원
- 오더 1 필터2 에 **초과근무·영업구매 7종이 빠졌다**
