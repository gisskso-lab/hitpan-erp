## 1. 배경

W3_CHUNK_ALGORITHM.md 학습 결과에서 발견. `migration_errors.raw_data` 형식 권장안 = **JSON + AES Value Converter** (대안: VARBINARY).

결재 #2(이미 상신)에서는 **B안 VARBINARY 채택**으로 가결되었음. 학습 문서의 JSON+AES 권장과 충돌 → 통합 결재 필요.

## 2. 핵심 차이

| 안 | 컬럼 타입 | 직렬화 위치 | 운영 부담 |
|---|---|---|---|
| 결재 #2 B안 | VARBINARY(8000) | 어플 레이어 직렬화 + 암호화 | 디버깅 시 매번 복호화 |
| 학습 권장 | JSON + EF Value Converter | EF가 자동 직렬화·암호화·복호화 | 어플에서 객체 형태로 접근 |

## 3. 검토

결재 #2 B안과 학습 권장은 **본질적으로 동일** — 모두 평문 저장 금지 + AES-256.
차이는 단순히 **EF Value Converter 사용 여부**.

- VARBINARY 컬럼 + EF Value Converter 사용 시 두 안 자동 통합
- 기존 `EncryptedBinaryValueConverter` (W2 D2 완성) 그대로 재사용 가능

## 4. PM 권고

**통합안 채택:**
- DDL: `raw_data VARBINARY(8192) NULL` + `raw_data_format VARCHAR(10) NULL`
- 어플: `EncryptedBinaryValueConverter` 재사용
- 객체 매핑: `MigrationErrorRawData` record + `JsonSerializer` 직렬화 → 암호화

→ 결재 #2 B안 + 학습 권장 모두 만족. 추가 결재 불필요.
