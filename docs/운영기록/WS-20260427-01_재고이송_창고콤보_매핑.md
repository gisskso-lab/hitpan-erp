## 2. 진단 (어벤져스 합의 사실관계)

### 2.1 API 응답 구조

`/api/warehouses` (GET):
```json
[
  {
    "warehouseId": "0e9fdcd055e64b1bbe5e7de9e83f8443",
    "whCode": "01",
    "whName": "스마트비즈창고1",
    "whType": "자사창고",
    "isActive": true,
    ...
  },
  ...
]
```

ASP.NET Core 기본 직렬화 = camelCase. 즉 응답 필드명은 `warehouseId`, `whCode`, `whName`.

### 2.2 Web 클라이언트 모델

[StockTransferPage.razor:306-310](../../src/HitPan.Web/Pages/Stock/StockTransferPage.razor#L306-L310)

```csharp
private class WarehouseOption
{
    public string Code { get; set; } = "";   // ← API 응답에 'code' 필드 없음
    public string Name { get; set; } = "";   // ← API 응답에 'name' 필드 없음
}
```

### 2.3 진범

**JSON 필드명 불일치.**
- API 응답: `whCode`, `whName`, `warehouseId`
- 클라이언트 모델: `Code`, `Name`

`System.Text.Json`은 PropertyNameCaseInsensitive 옵션이 켜져도 **다른 단어**로는 매핑 못 함. 결과적으로 모든 `WarehouseOption` 객체가 `Code=""`, `Name=""` — 빈 옵션 노출.

### 2.4 영향 범위

같은 모델 패턴이 다음 화면들에 복제되어 있음 — **모두 동일 증상 의심**:
- `/stock/transfer` (이번 보고)
- `/stock/adjust` ([StockAdjustPage.razor:217-221](../../src/HitPan.Web/Pages/Stock/StockAdjustPage.razor#L217-L221))

수정 시 두 화면 같이 처리 필요.

## 3. 처방안

### 3.1 권고 (최소 변경, 회귀 위험 0)

`WarehouseOption` 클래스에 `[JsonPropertyName]` 어노테이션 추가:

```csharp
private class WarehouseOption
{
    [System.Text.Json.Serialization.JsonPropertyName("warehouseId")]
    public string Code { get; set; } = "";

    [System.Text.Json.Serialization.JsonPropertyName("whName")]
    public string Name { get; set; } = "";
}
```

> **`warehouseId`를 Code로 매핑하는 이유:**
> `item_stock.warehouse_id`, `stock_ledger.warehouse_id`가 모두 `warehouse_id` (PK) 기준이므로,
> 콤보 선택값 = `warehouse_id` 가 자연스럽다. `wh_code`(예: "WH-MAIN", "01")는 사용자 표시용이며
> DB 외래키 일치를 위해 PK 사용이 정공법.

### 3.2 검증 시나리오

1. 재고이송 화면 진입 → 출고창고 콤보 펼침 → "본사창고", "스마트비즈창고1" 등 노출 확인
2. 품목 "테스트반제품1" 선택 → 출고창고가 "본사창고" (잔량 60) 자동 셋팅 확인
   (※ AutoFillFromWarehouseAsync 는 이미 추가됨 — 본 작지서 처방 후 자동 작동)
3. 입고창고 "스마트비즈창고1" 선택 → 수량 10 → 이송
4. 재고현황 조회 → 음수 -10 → 0 회복 확인
5. stock_ledger 'stock_transfer' 2행 INSERT 확인 (out + in)
6. 회사합산 50 그대로 (이송은 자산 변동 X)

## 6. 미해결 확장 의문 (참고만)

### Q1. 다른 화면에도 같은 매핑 누락이 있나?

`WarehouseOption` 외에 `Code`/`Name`처럼 일반 영문명을 쓰는 모델이 있다면 같은 함정 가능성.
별도 진단 작지서로 분리 권고 (오늘 진단 범위에서 제외).

### Q2. ASP.NET 기본 옵션 통일?

`Program.cs` 에서 `AddJsonOptions(o => o.JsonSerializerOptions.PropertyNamingPolicy = null)`
같은 통일 정책으로 해결할 수도 있으나, 다른 화면이 camelCase에 의존할 수 있어 위험 큼.
**개별 모델별 어노테이션 (3.1)이 최소 위험 처방.**
