## §0 사장님 확정 전제 (토론 대상 아님)

- **계층은 두 갈래가 전부다**(10/6): **본사 = 마스터** — 모든 고객사·모든 대리점의 영업현황·CS현황을 보고 접근한다. **대리점 = 자기 것만.** 세부 계층을 PM·설계팀이 덧붙이지 않는다.
- **Q-1 결재**(10/6): 권한 역할명은 **단일 enum·단일 컬럼** · 내부값 4개(본사owner / 본사admin / 대리점admin / 대리점user) · **화면 표시만 한글.**
- **메뉴 결재**(10/7): 본사 **9대메뉴** / 대리점 **5대메뉴**(설계서 §1·§2) · 「협력업체」→**「대리점」** 한 이름 · 대리점 사이드바 구판 중복 줄 제거(§4-③).
- **빈 화면은 「준비 중」이 아니라 메뉴 자체를 안 보인다**(설계서 §6) — 「빈 껍데기」 재발 방지.
- ⏸ **F-4(대리점 내부 직원 계정)는 보류** — 계층 정의 두 줄 밖이라 사장님 별도 결재 대기. **이 사이클에서 만들지 않는다.**

## §1 이 사이클의 범위 (PM 초안 — [1-V] 결과로 확정)

| # | 할 일 | 완료 기준(실동작) |
|---|---|---|
| 1 | 권한 역할 **단일 enum 4값**으로 통일 | 역할 판정이 서버 **한 곳**에서만 나온다 · 기존 role 값으로 들어오던 사용자가 전환 후에도 같은 범위로 들어온다(마이그 포함) |
| 2 | 권한 **서버 강제** 공통 필터 한 곳 | A 대리점 토큰으로 B 대리점 데이터 요청 시 **403 또는 빈 집합**(음성 대조군 포함 실측) · 화면 숨김만인 자리 0 |
| 3 | 메뉴 뼈대 — 본사 9 / 대리점 5 | 역할별 화면 진입 가능/불가가 메뉴 노출과 **일치** · 아직 안 만든 화면은 메뉴에 안 보인다 |
| 4 | 어휘 통일 「대리점」 + 구판 중복 줄 제거 | 화면 전수에서 「협력업체」 0건(고객 노출면) · 대리점 사이드바에 같은 뜻 두 줄 0 |
| 5 | 설정 ▸ 권한 화면 (F-1) | 본사가 역할을 지정하면 그 계정의 메뉴·API 범위가 **즉시** 바뀐다(재로그인 요구 여부 명시) |

🚫 **이 사이클이 하지 않는 것**: 결제·과금(②) · 영업현황(③) · 순위(④) · CS(⑤⑥) 화면 내용 · F-4 · 외부 AI(작9 별건) · ERP 안 권한(#7·#38 — SaaS 계층과 섞지 않는다).

## §2 [1-V] 선행검증 지시 — 검증팀장 데이비드 박

⛔ **전제 미확인 설계 금지.** 아래를 **실측**으로 답한다(추측·문서 인용 금지 · 근거는 파일:줄).

1. **역할 어휘 실태 전수** — 지금 코드·DB·JWT 클레임에 실제로 쓰이는 역할 값 전부와 각각이 **읽히는 지점**. 선행검증 A 의 「4~6갈래·owner 역할 없음」이 지금도 사실인가.
2. **owner 판정** — `owner` 역할 행이 없는데 Owner 전용 메뉴가 뜨는 근거는 무엇인가(무엇을 보고 owner 라 판정하나).
3. **서버 강제 지점** — 대리점이 자기 것만 보게 하는 강제가 **지금 몇 곳에서, 어떻게** 되는가. **화면 숨김만이고 서버가 안 막는 자리**를 전수로 찾는다(이게 이 사이클의 진짜 위험).
4. **enum 4값 전환 영향 범위** — 전환 시 깨지는 곳 전수(쿼리 리터럴·if 분기·시드·시험). **기존 계정 행의 role 값 → 새 값 매핑표**와 마이그 필요 여부.
5. **CI 게이트 `권한 메뉴 코드 정합 (프론트 ↔ 백엔드)`** (`scripts/check-permission-menu-sync.sh`) 가 **정확히 무엇을 재는가.** 역할명을 바꾸면 이 게이트가 먼저 깨지는지 — 깨진다면 어떻게 깨지는지(ERP 쪽 권한을 재는 것인지 백오피스인지 확인).
6. **메뉴 노출 로직 위치** — 사이드바 2종(`PlatformSidebar`·`ResellerSidebar`) 외에 메뉴를 만드는 자리가 또 있는가. 라우트 가드(`/admin/*`·`/reseller/*`)는 누가 거는가.
7. **백오피스 계정 저장 구조** — 계정 표·역할 칸의 실제 `DESCRIBE`(#13). 역할이 **단일 컬럼**으로 들어갈 자리가 있는가, 아니면 칸 추가가 필요한가.
8. **메뉴 9/5 중 지금 실물이 있는 화면 / 없는 화면** 판정 — 설계서 §6 의 「아직 안 만든 화면은 메뉴에 안 보인다」를 적용하려면 이 목록이 먼저 있어야 한다.
