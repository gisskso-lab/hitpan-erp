## 2. 🔴 설치 hang P0 (실측 발견 → 봉합 f06615b)

### 진범 (추측 아닌 프로세스 관측)
- 백지 Sandbox 랜딩 1.2.33 다운로드 성공 → 설치가 `[재설치안전] 정지 시작` 로그에서 25분+ 무한 hang.
- 관측: `taskkill` 죽이면 **새 taskkill 재출현**(반복 hang). `sc.exe query cloudflared/HitPanWatchdog` = 1060(서비스 없음) → sc stop 무죄 확정.
- 진범 = [`StopRunningComponentsForReinstall`](../../installer/HitPan-Universal.iss) 의 `taskkill /F /IM`. Windows Sandbox 는 taskkill /IM 프로세스 이미지 열거가 제약 계층에 걸려 무한 대기(`Get-CimInstance Win32_Process` 도 "액세스 거부" 난 것과 동일 계층).
- 근본: 재설치 방어코드가 `ssInstall` 마다 **최초/재설치 구분 없이 무조건** 실행 → 백지 최초설치도 걸림 = **전 신규고객 설치 차단.** 헌법 #40(덮어 재설치 없음)과 충돌 — 재설치 코드가 최초설치를 죽임.

### 봉합 (축 A, 커밋 f06615b, 사장님 결재)
- `IsPreviouslyInstalled()` 신설 — `{app}\db.conf` or `hitpan-keys.conf` 있으면 재설치, 없으면 최초.
- 최초면 정지 로직 **통째 스킵**(로그도 안 남김) → taskkill hang 원천 차단.
- 판정은 레지스트리 대신 `FileExists({app})` — 이 [Code] 섹션은 리터럴 중괄호 안 씀(Inno Pascal `{` 주석 위험). db.conf 는 [UninstallDelete] 비대상이라 재설치에 살아남아 판정 정확.
- 기존 정지로직 **무삭제**(헌법 #1 추가만).

### 검증팀 SoD (데이비드 박) — 조건부 안전
- ✅ 거짓음성 CLEAR / ✅ 문법·{app}시점·무손상 CLEAR
- ⚠️ **CONFIRMED(P1)**: "제거 후 재설치"는 db.conf 잔존→taskkill 돎→Sandbox hang 재발 가능. **단 이건 봉합 주석이 스스로 "축 B 다음 작지서 P1"로 이월한 알려진 갭**(새 결함 아님).
- **정직 보고 원칙**: 이번 봉합 = "**최초설치** hang 차단"으로만. "재설치 hang 완전해소" 아님.

### 축 B (P1, 다음 작지서 — CTO·대표 결재됨)
- 재설치 경로 taskkill /IM hang-safe 교체(타임아웃 or sc query/PID 기반 대상지정). Stop-Process 도 Sandbox 열거 hang 가능성 있어 재빌드 후 실측 선행.
