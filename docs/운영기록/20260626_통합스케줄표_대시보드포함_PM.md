## 2. 묶음·실행 순서 (작업지시서 단위)

### 작4 — quotations DDL 갭 (순위 1)
- DB 매니저. DESCRIBE→clean DDL 동기화(헌법 #36)+ddl-smoke. 판매흐름 시작점이라 단독 선행.

### 작5 — 멱등성 source_id (순위 2)
- 백엔드 매니저. 원장 INSERT 경로 멱등 가드. 작4와 독립이라 병행 가능하나, 무결성 핵심이라 순위 2.

### 작6 — 대시보드 일괄 (순위 3·4·5 묶음)
- 프론트 매니저. **같은 Dashboard.razor 한 파일이라 3·4·5를 한 작업지시서로 묶음**(파일 충돌·재빌드 중복 방지).
  - D-2·3·5 라우팅(저난이도) + D-1 멀티캘린더 라디오 + D-4 매입카드.
  - 라우트 대상은 매니저가 각 목록 페이지 기능 확인 후 확정(현재 `/sales/summary`·`/deliveries`·`/purchases`·`/collections` 실재 확인됨).
- ⚠️ 대시보드는 표시계층이라 워크플로우 영향 0 → **작4·작5(무결성)보다 뒤.** 단 사장님 체감 큰 항목이라 무결성 2건 직후 바로.

### 작7 — P2 메시지 + BOM UX (순위 6·7)
- 잔여 정리. 베타 차단 아님.

## 3. PM 권고 순서
**작4(DDL) → 작5(멱등성) → 작6(대시보드 일괄) → 작7(잔여).**
무결성·워크플로우 직결 2건 먼저, 그다음 사장님 체감 큰 대시보드 일괄, 마지막 잔여. 대시보드 5건을 1개 작업지시서로 묶어 같은 파일 중복 수술 방지.
