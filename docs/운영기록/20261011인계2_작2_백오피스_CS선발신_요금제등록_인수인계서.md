## §2 사장님 오더가 화면에서 무엇이 됐나 (개발 용어 없이)

### ⓞ 전화접수 — 이제 **회사 이름**으로 찾는다
접수 창의 「고객사코드」 칸이 **「고객사명」 자동완성**으로 바뀌었다. 회사 이름을 치면 목록이 뜨고
고르면 **코드가 저절로 채워진다**(도움말에 `코드 XXXX` 로 보인다). 저장 경로는 종전과 **똑같다** —
화면이 코드를 채워 보내므로 서버 계약은 한 글자도 안 바뀌었다.

### ① 요금제 — 이제 **화면에서 등록**된다
운영 요금제 표는 **0행**이고, 종전 화면에는 **고치는 입구만** 있었다(등록 입구가 없었다).
⇒ 0행에서는 아무것도 할 수 없는 상태였다. 등록 입구를 새로 냈고, 0행이면 「등록된 요금제가 없습니다
+ 첫 등록」 화면이 뜬다. **결재를 거치지 않고 베타 요금제를 넣을 수 있다**(사장님 오더의 이유).

- 같은 이름(`plan_id`)으로 또 등록하면 **거절**되고 **기존 요금제는 한 글자도 안 바뀐다**(값·수정시각까지).
  가장 그럴듯한 사고가 「등록도 수정도 되는 편한 한 줄」인데, 그 줄을 넣는 순간 게이트가 빨간불이 된다.

### ① 「제외」 — 🔴 **사장님께 솔직히 올릴 것 하나**
제 전제가 틀렸습니다. **기능은 이미 있었고, 낱말이 「비활성화」였습니다.**
없던 것은 기능이 아니라 **사장님이 쓰신 말**이었습니다. 그래서 이렇게 좁혔습니다:

| | 전 | 후 |
|---|---|---|
| 상태 표시 | 활성 / 비활성 | **판매중 / 제외됨** (아이콘 + 색) |
| 버튼 | 비활성화 / 활성화 | **제외 / 포함** |
| 설명 | 없음 | **「지워지지 않습니다 · 다시 포함할 수 있습니다」** 를 화면이 직접 말한다 |

호출 경로·서버 코드는 **한 글자도 안 건드렸다.** 새로 생긴 것은 **등록 입구**다.
🔴 이 좁힘이 오더를 만족하는지는 **사장님 판정**이다(§4-1).

### ③ 쪽지 보내기 — 🔴 **「보냈습니다」라고 말하지 않는다**
ERP 쪽 수신부는 **원본 문의가 없는 쪽지를 조용히 버린다**(코드로 확인했다 — 넣을 줄이 0줄이 된다).
그래서 **보내는 척하지 않는다.** 화면은 이렇게 말한다:

> **「전달 대기함에 넣었습니다 — ERP 수신 통로가 열리면 자동으로 나갑니다」**

- 용도 4종: **프로모션 · 이벤트 · 구독요금 미결재 · 기타** (사장님 오더 3종 + 기타)
- 보낸 쪽지 표에 **전달 대기 / 전달됨 / 취소됨** 이 보인다. **나가기 전이면 취소**할 수 있다
- 쌓인 쪽지는 **사라지지 않는다.** 통로가 열리면 그대로 나간다 ⇒ 그 통로가 **다음 작업**이다

### ③ 보관 · 폐기 — 🔴 **저절로 지워지는 길이 없다**
- 보관기한 기본값 = **무기한.** 기한을 정해도 **지우지 않고** 「폐기 후보」로 **보여만 준다**
- 폐기는 **사유를 적어야** 되고, **내용만 비우고** 「누가·언제·왜」는 감사기록에 **남는다**
- 행과 이력은 지우지 않는다 — 지우면 고객 분쟁에서 **우리 쪽 증거가 없어진다**

## §4 사장님 손 — 3건

### §4-1 🔴 「제외」 판정 (내가 못 정하는 것)
기능은 이미 있었고 **낱말만** 「비활성화」였다 ⇒ 글자를 「제외/포함」으로 바꾸는 선에서 좁혔다.
**이게 오더를 만족합니까?** 만족 못 하면 별도 버튼을 더하는 쪽으로 다시 갑니다.

### §4-2 🔴 「제외」가 **어느 축**인가
지금 「제외」는 **요금제를 안 팔린 상태로** 만든다(과금 축 하나만 움직인다).
베타에서 **「랜딩에서만 감추고 과금은 유지」** 가 필요하면 **다른 축**이 맞습니다.
과금 축이 둘로 갈라지면 나중에 돈 계산이 어긋나므로 **임의로 안 건드렸습니다.**

### §4-3 ⏳ 머지 결재 (오더 ②)
사장님이 「머지 결재승인」을 이미 주셨고, 「**머지 전에** 기능추가」도 지시하셨습니다 ⇒ 기능을 먼저 넣었습니다.
**남은 조건은 둘**: ⓐ CI 초록(돌고 있음) ⓑ [4] 판정(돌고 있음). 둘이 끝나면 머지합니다.

### §4-4 ⏸ 별건으로 뺀 것 — **대리점 구독요금 면제**
사장님이 말씀하신 「대리점은 히트판 구독요금 면제정책을 쓸 예정」은
**요금제(상품) 축이 아니라 고객사·대리점 속성 축**입니다. 요금제에 섞으면 **과금 축이 둘로 갈라집니다.**
⇒ **별건 트랙**으로 뺐습니다. 작2 범위 밖입니다.

### §6-1 왜 이게 다음인가 — **지금 끊긴 자리가 정확히 여기다**

```

백오피스 ──선발신 쪽지──▶  ???  ──▶ 고객사(ERP)                 🔴 끊겼다 ← 여기
```

본사가 쓴 쪽지는 지금 **전달 대기함에 쌓인다.** 나갈 통로가 없다.
🔴 **이유를 코드로 확인했다**: ERP 수신부가 **원본 문의가 없는 쪽지를 조용히 버린다**
(`src/HitPan.API/.../CsOutboxSenderWorker.cs:316` — 원본을 찾는 조회가 0행이면 넣는 줄이 **0줄**).
막는 것도 아니고 알려 주는 것도 아니고 **조용히 사라진다.** 그래서 작2 는 **보내는 척하지 않았다.**

### §6-3 [2] 설계가 답해야 할 것

1. 선발신 쪽지를 **Pull 에 실을까, 별도 입구를 낼까** — 기존 `cs/replies/pull` 계약을 깨지 않는 쪽
2. ERP 쪽 **받는 표**(원본 문의 없는 쪽지가 앉을 자리) — 신설이냐, 기존 `cs_replies` 확장이냐
3. 전달 성공 시 `bo_cs_outbound.delivered_at` 을 **누가 언제 채우나** — 화면의 「전달 대기」가 **「전달됨」으로 바뀌는 것까지**가 완료 조건
4. 실패·재시도 — 못 나간 쪽지가 **조용히 사라지지 않는** 구조 (#20 흐름 불단절)
5. 고객사 **화면 어디에** 보이나 — 「처음 보는 사람이 혼자 쓸 수 있냐」가 통과 기준

### §6-4 완료 판정 (이것 없이 「됐다」 하지 마라)

- 🔴 **왕복 실측 1회**: 백오피스에서 쪽지 보내기 → ERP 화면에 **보인다** → `delivered_at` 채워짐 → 화면이 **「전달됨」** 으로 바뀜
- 🔴 **FAIL 대조**: 봉합을 빼면 **그 게이트만** 빨간불
- 🔴 **CI 초록** — `db-gate`(MariaDB) + `bo-mysql8-gate`(MySQL 8) **둘 다**
- 작2 가 쌓아 둔 **대기 쪽지가 실제로 나가는 것**까지
