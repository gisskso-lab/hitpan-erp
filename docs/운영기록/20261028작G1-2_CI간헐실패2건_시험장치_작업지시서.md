### §1-1 이해
- **F-2**: 시험 장치가 「로그인 연결이 refresh 저장 안에서 붙잡혔다」를 **너무 넓게** 판정해, 그보다 앞 순간(세션 INSERT 전)에 연결을 죽이는 일이 가끔 생긴다 → 양성 전제 `:2493`(세션 INSERT 는 돌았다)이 0 으로 깨진다. 장치를 고친다.
- **F-1**: 원인 미측정(선행검증 F1-①② 가설) — 이번에는 **고치지 않고**, 다음 실패 때 가를 증거를 남기게만 한다.
- 안 하면: F-2 는 PR 마다 약 1% 꼴로 DB 게이트 잡이 빨강(최근 300런 중 4런 · 선행검증 F2-H) → 「재실행하면 초록」 습관이 굳는다. F-1 은 다음 실패도 증거 없이 지나간다.

### §1-2 해석이 갈리는 자리 (확인 필요)
- 오더 문구 「탐침을 **세션 INSERT 문장**과 트리거 표지로 좁힌다」 — 실제로 연결을 붙잡는 자리는 **refresh_tokens INSERT**(`AuthService.cs:252-254` · 붙잡는 트리거 `BEFORE INSERT ON refresh_tokens` 시험 `:2444-2446`)다. 세션 INSERT(`:222`)는 그 **앞**이고 표지 트리거(`gate_b13c_mark_insert` 시험 `:3020-3024`)가 따로 잰다.
  - ⇒ 존은 「**refresh_tokens INSERT 문장** + **트리거 표지**(`gate_b31b_slept` · `User sleep`)」로 읽었다. 선행검증 카드 「`INSERT INTO refresh_tokens` 문장·트리거 표지로 좁힘」과 같다. 다르면 PM 이 반려.

## §4 [구현] — [3] 개발팀용 (지휘 = PM)

### §4-1 갈래 F-2 (DB 게이트 잡)
- ⓐ **탐침 상수** — 예: `HeldProbeSql`(이름은 개발 재량). 조건 = `ID = @Tid AND (INFO LIKE '%INSERT INTO refresh_tokens%' OR INFO LIKE '%gate_b31b_slept%' OR STATE = 'User sleep')`.
  - 옛 조건도 **대조군 전용 상수**(예: `HeldProbeSqlOld_ForContrast`)로 남긴다 — 운영 판정에는 안 쓴다 · 주석에 「⬛ 낡은 조건 · 판정 SELECT·폐기 UPDATE 까지 잡았다 · run 40666254688」(#1 덮어쓰기 금지 · 옛 줄은 `:2458` 처럼 ⬛ 이력으로).
  - ⚠️ 시험 전에 `INFO` 실물 모양 1회 확인 — Dapper 가 매개변수를 글자로 풀어 보내도 `INSERT INTO refresh_tokens` 머리는 그대로인지(대조군 ⓒ-4 가 그 자체로 잰다).
- ⓑ **선택안(확인 필요 ③)** — 조건에 `AND EXISTS (SELECT 1 FROM security_alerts WHERE alert_type = 'gate_b13c_session_inserted')` 를 더하면 「세션 INSERT 전에는 절대 안 죽인다」가 글자로 성립. 대가: 제품이 세션 행을 안 만들면 실패가 `:2493` 이 아닌 `:2490`(준비 불성립)으로 옮겨 가 원인 읽기가 흐려진다. **존 권고 = ⓐ 만.** PM 이 고른다.
- ⓒ **대조군 `[Fact]`** (같은 클래스 · 이름 예: `G_B31b_대조군_판정단계를_붙잡으면_옛탐침은_잡고_새탐침은_안잡는다`) — 실제 `AuthService.LoginAsync` 로 돈다:
  1. `SetUpFreshInstall` · `admin` 연결 · 붙잡는 트리거 + 세션 표지 트리거는 `G_B31b` 와 같게(`:2444-2447`).
  2. **잠금 연결 B**(admin 과 따로)에서 `LOCK TABLES refresh_tokens WRITE` → 로그인 시작 ⇒ 로그인 연결은 **판정 단계**(S-3·S-4 의 첫 문장)에서 멈춘다.
  3. 로그인 연결의 `INFO` 가 비지 않을 때까지 기다린 뒤 **한 시점에** 두 상수를 함께 잰다: **옛 = 1 · 새 = 0** 단언. 그 순간 `INFO` 앞 200자를 메시지에 싣는다. 세션 표지 = 0 도 단언(아직 세션 INSERT 전임을 증명).
  4. B 에서 `UNLOCK TABLES` → 새 탐침이 참이 될 때까지 기존과 같은 예산으로 기다린다 ⇒ **새 = 1** 단언 · 그때 세션 표지 = 1 단언 · 어느 항(`INSERT…` / `gate_b31b_slept` / `User sleep`)이 맞았는지 각각 재서 기록하고, **트리거 표지 둘 중 하나 이상 참**을 단언(S-2 이력 — 이 둘을 지우면 FAIL 하게).

  - ⚠️ #13: `LOCK TABLES` 대상·트리거 대상 표는 출하 DDL 로 DESCRIBE 확인 후 · CI DB 계정 권한(LOCK TABLES)은 CI 에서만 확인.
- ⓓ `G_B31b` 본문은 상수만 갈아 끼운다 — 단언 `:2490`·`:2491-2497` **한 글자도 안 바꾼다.**

### §4-2 갈래 F-1 (Build 잡)
- T7 루프 안 `:617` 을 같은 술어의 메시지 있는 단언으로: `found == expected` 를 그대로 재고, 메시지에 **copyMode · 여백 · 줄 수 · 쪽 수 · 기대 · 찾은 수 · 쪽별 찾은 수 · 같은 반복에서 앞서 지난 벌들의 수**(예: `both=200`)를 싣는다.
- **틀렸을 때만**(단언 직전 `if (found != expected)`): ① 기존 `Dump()` 로 PDF 를 `t7-fail-{copyMode}-{margin}mm-{lineCount}lines-{UTC 시각}.pdf` 로 떨군다 ② 증거를 §4-3 길로 운반 ③ 증거 남기기 자체가 실패하면 그 사실을 메시지에 덧붙이고 **원래 판정(FAIL)은 그대로**(빈 catch 금지 · 삼키지 말고 기록).
- **통과 시 무변화** — 파일 0 · 출력 0 · 단언 수 동일. 기존 `Assert.True(pages.Length > 0 …)`·`AssertNoCopyFragment` 는 손대지 않는다.
- 🔴 `Assert.Equal` → `Assert.True(found == expected, msg)` 는 **같은 조건**이어야 한다 — 허용 오차·`>=`·「한 벌이라도 맞으면」 류 넓히기는 반려.
