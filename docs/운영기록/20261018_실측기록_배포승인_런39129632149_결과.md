## 2. 🔴 CTO 조건이었던 `HITPAN_BO_AUTO_MIGRATE` — 결과적으로 운영 DB 변경은 없었다

CTO 가 승인 전 확인을 걸었던 이유: 오늘 사장님이 얹으신 `99-fix.conf`(환경변수 이름 교정) 때문에 **종전에 안 먹던 변수가 이번 재기동부터 먹을 수 있었다.** `Program.cs:161` 은 `HITPAN_BO_AUTO_MIGRATE == "1"` 일 때 `SchemaMigrator.ApplyAsync()` 를 **`app.Run()` 앞에서** 돌린다.

사장님은 값을 읽지 않고 승인하셨다. 그래서 **사후에 코드·로그로 역산했다.**

| 근거 | 무엇을 말하나 |
|---|---|
| 🟢 재기동 13:12:05 → 응답 13:12:13 (**8초**) | 적용기가 예외를 던지면 `Program.cs:164` 주석대로 **기동이 중단**된다. 기동했다 ⇒ 실패는 없었다 |
| 🟢 `SchemaMigrator.cs:51-56` | 스크립트 폴더가 없으면 **경고 1줄 남기고 통과**(사고 아님) |
| 🟢 `HITPAN_BO_SCHEMA_DIR` 미설정 시 기본값 = `AppContext.BaseDirectory/installer/backoffice` | 배포 산출물 경로다 |
| 🟢 `deploy-ncp.yml` 에 `installer` 문자열 **0건** | 배포가 `installer/backoffice/*.sql` 을 **서버로 보내지 않는다** |

⇒ **AUTO_MIGRATE 가 `1` 이었더라도 적용할 SQL 파일이 서버에 없어 건너뛴다.** 운영 MySQL 8 에 스키마 변경이 가해졌을 경로가 없다.

🔴 **다만 이건 사후 역산이지 직접 측정이 아니다.** 아래 한 줄을 언제든 받으면 기록을 닫는다. 값은 `0/1` 뿐이라 비밀이 아니다.
```
journalctl -u hitpan-backoffice-api --since "2026-10-18 22:12" | grep -i SchemaMigrator
```
- 아무것도 안 나옴 ⇒ 적용기 자체가 안 돌았다(AUTO_MIGRATE ≠ 1)
- 「스크립트 폴더 없음」 경고 ⇒ 돌았으나 **적용 0건**
