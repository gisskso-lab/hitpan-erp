## 0. ⭐ 사장님 오더 (원문 그대로 — 이 문서의 원본)
> "집pc로 로그인 하려고 하는 접근자체가 틀림, 보통은 퇴근 후 사내전산 접속을 안함. 그리고 히트판 그룹웨어 내 근퇴 체크는 로그인/로그아웃으로 함. 로그인을 하도록 유도, 혹여, 이런 실수가 있다면 쿨타임 기능을 넣으면 됨. 쿨타임기능 = 전체퇴근, 로그아웃 기능. 혹여, 야근으로 접속하고있는 사용자가 있다면, 자동 "로그아웃 설정시간입니다. " 로그아웃을 취소하고 작업을 계속하시겠습니까? y/n 팝업을 띄우고 제어하면 됨."
>
> "그리고 팝업에 y/N 선택 안할시 자동로그아웃" · "= 60초"

**이 아래 모든 내용은 위 오더를 명문화한 것이다.** 오더에 없던 요구를 넣지 않는다.

## 1. 오더를 이렇게 이해했다 (명문화)
- 사장님 의중: 로그아웃을 잊은 PC 가 계정을 붙잡아 다른 PC 가 못 들어오는 일(작2 K-4 (다)의 부작용)을 **회사가 정한 시각에 한꺼번에 푼다.** 야근자는 팝업으로 계속할 수 있다. 근태가 틀어지지 않게 그렇게 끝난 사람의 퇴근은 정시 퇴근으로 적고, 인사담당이 고칠 수 있다.
- 안 하면: 작2 가 켜진 뒤 로그아웃을 잊은 PC 하나가 다음 날 아침까지(마지막 사용 + 8시간) 같은 계정의 다른 PC 를 막는다 · 되살아난 로그인은 출근을 안 찍는다.
- **실측 근거**: 선행검증서 §2~§6(코드 읽기 · 파일:줄) + 설계팀장 실측(9/28): `tenant_settings`·출하 DDL 에 근무·퇴근 시각 칸 0(`hitpan_db_clean.sql:4115-4146` · 전체 grep `work_end`·`WorkEnd` 0) · 퇴근 **고치는** API 0(`HrController.cs` 는 조회·출퇴근·대신 출퇴근뿐 · 대신 퇴근은 오늘·빈칸만 `HrService.cs:74-87,126-132`) · 허브 그룹은 사원 단위뿐(`NotificationHub.cs:50,72`) · 시각 작업 0(`Program.cs:327-343`). 🔴 토큰 저장 = sessionStorage(PM 실측 `storage.js:1-10`).
