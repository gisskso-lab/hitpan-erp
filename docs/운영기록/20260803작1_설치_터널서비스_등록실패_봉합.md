## 1. 진범 — `service install` 이 레지스트리 잔재 때문에 거부

### 결정적 실측 (2026-08-03 20:18, 사장님 직접 실행)

```
> sc delete Cloudflared
  [SC] DeleteService SUCCESS          ← SCM 에서 서비스가 실제로 지워짐

> "C:\Program Files\HitPan\cloudflared.exe" service install
  INF Installing cloudflared Windows service
  cloudflared service is already installed at Cloudflared; ...
  you can do `cloudflared service uninstall` to clean up the existing
  service and then try again this command
```

**서비스를 방금 지웠는데도 "이미 설치돼 있다"며 설치를 거부한다.**

⇒ `cloudflared` 는 서비스 존재를 **SCM 이 아닌 자체 상태(레지스트리 잔재)** 로 판정한다.
   `sc delete` 로는 그 잔재가 지워지지 않는다. 잔재가 남으면 **영구히 설치를 거부**한다.

## 2. 폐기된 가설 — 기록으로 남긴다 (같은 오진 반복 차단)

PM 이 오늘 **세 번 오진**했다. 전부 실측이 반증했다.

| # | 가설 | 반증 |
|---|---|---|
| 1 | `cmd /C` 따옴표 파손으로 실행 자체가 안 됨 | 수동 실행 시 cloudflared 정상 응답 |
| 2 | 토큰 미수령/손상 | `:1887` `if G_TunnelToken <> ''` 통과해야 6-1~6-3 이 도는데 전부 돌았다 |
| 3 | **서비스명 대소문자** (`cloudflared` vs `Cloudflared`) | PM PC 실측: `sc query Dnscache`/`dnscache`/`DNSCACHE` **전부 exit 0**. `sc query` 는 대소문자 무시 = 7/15 주석이 맞았다 |

### 🔴 가설3 봉합을 그대로 빌드했으면 8/02 무한정지가 재발했다

가설3 봉합안은 존재 판정을 이렇게 바꾸려 했다:

```
sc queryex type= service state= all | findstr /I "cloudflared"
```

**PM PC 실측 결과 — 이 명령은 없는 서비스에도 exit 0 을 낸다:**

```
있는 서비스(Dnscache)     → exit 0
없는 서비스(cloudflared)  → exit 0    ← 항상 0
```

파이프는 `sc queryex`(항상 exit 0)의 코드를 내고 `findstr` 의 1 을 삼킨다.
괄호 묶기·`&` 체인·리다이렉트 위치 변경 4가지 형태 전부 동일하게 실패했다.

⇒ 6-1 의 taskkill 가드가 `ScStopCode <> 0` 이므로 **항상 거짓 → taskkill 이 항상 실행 →
   Windows Sandbox 무한 hang 재발.** 8/03 에 겨우 봉합한 것이 통째로 무력화될 뻔했다.

**교훈: 종료코드는 추측하지 않고 반드시 실측한다.** (검증팀 P0-1 교훈의 재확인)

### 부수 확인 — `sc query` 종료코드는 환경 의존

| 환경 | 없는 서비스 조회 시 |
|---|---|
| PM PC (Win11) | **1060** |
| 7/31 주석 기록 | 36 |
| Sandbox 8/02·8/03 | 1060 |

⇒ `<> 0`(안전측) 판정이 옳았음이 재확인됐다. 특정 코드값(`= 1060`·`= 36`)으로 판정하면 안 된다.

## 3. 봉합안 (W-1, P0)

`6-2 service install` **직전에 `cloudflared service uninstall` 을 실행**한다.
cloudflared 가 오류 메시지에서 직접 안내한 방법이다.

```pascal
// 6-1-3. cloudflared 자체 잔재 정리 — sc delete 로는 안 지워진다
ExecLogged('6-1-3-svcuninstall',
  '"' + ExpandConstant('{app}\cloudflared.exe') + '" service uninstall');
Sleep(2000);
```

### 설계 판단

- **실패해도 무시한다.** 백지 설치엔 잔재가 없어 실패가 정상이다(비차단).
- `sc delete`(6-1) 는 **남긴다.** SCM 등록분 정리는 여전히 필요하다(헌법 #1 — 추가만).
- taskkill 가드 로직은 **한 글자도 안 건드린다.** 8/03 실측 통과분이다.
- 워치독은 **손대지 않는다.** `ServiceExists` 는 `ServiceController.GetServices()` +
  `OrdinalIgnoreCase` 라 정상이고, 이번 결함(cloudflared 자체 잔재)과 무관하다.
  ※ 단 WS-28-D 의 `ReinstallAsync` 도 `service install` 을 쓰므로 **동일 결함 가능** →
    별도 조사 대상으로 이월(오늘 범위 밖, 추측 수정 금지).

### 검증 (사장님 실측으로 봉합안 자체를 먼저 확인)

```
> cloudflared service uninstall
> cloudflared service install       ← 이게 성공해야 봉합안이 유효
```

**이 확인 전에는 코드에 넣지 않는다.**
