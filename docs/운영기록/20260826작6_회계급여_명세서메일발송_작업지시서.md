## 4. 🔴 이 기능의 위험 — 되돌릴 수 없다

**잘못 나가면 전 직원에게 남의 연봉이 간다. 회수 불가다.**

| 위험 | 대응 |
|---|---|
| 이메일 **없는** 직원 → 조용히 누락. 경리는 "전체 발송했다" 고 알고 **그 직원만 영영 못 받음**(=되는 척) | **발송 전 확인 화면**에서 *"20명 중 18명 발송 가능 / 2명 이메일 없음(홍길동·김철수)"* 를 **이름까지** 보여준다 |
| 이메일 **오입력** → 남의 메일함에 그 직원 연봉 | 확인 화면에 **수신 주소를 그대로 노출**해 경리가 눈으로 본다 |
| 중복 발송 | 발송 버튼 **잠금** + 건별 이력으로 재발송 여부 판단 |
| 미확정 명세서 발송 | **`confirmed`·`paid` 만** 발송 대상 (아래 §5) |

🔴 **100% 자동 금지**(사장님 반자동 원칙) — **제안 → 사람이 확인 → 확정**. 경리가 **보고 나서** 누른다.

- **Y** → 곧바로 발송하지 **않고** §4 확인 화면으로 간다(누가 받고 누가 못 받는지 보여준 뒤 확정).

#### 🔬 착수 전 조사 (2026-08-26) — 팝업을 띄울 자리가 지금은 **알 수가 없다**

| 실측 | 자리 |
|---|---|
| 승인 처리 | `ApprovalController.Process` → `ApprovalService.ProcessAsync` |
| 화면 | `ApprovalPendingPage.razor:61` 「승인」 버튼 → `ProcessAsync(id,"approved")` |
| 최종승인 판정 | `ProcessAsync` 안 **`request.Action=="approved" && doc.CurrentSeq >= doc.TotalLines`** |

🔴 **결재선이 2단이면 1단 승인은 아직 승인이 아니다.** 부장이 승인해도 `current_seq++` 만 되고
문서는 여전히 `pending` 이다. 그런데 **API 응답은 두 경우 모두 `"승인되었습니다."`** 한 문장이고,
화면 서비스(`Web/Services/ApprovalService.ProcessAsync`)는 **응답 본문을 버리고 `bool` 만 돌려준다.**

⇒ 지금 구조에서 팝업을 붙이면 **부장이 승인한 순간에도 "발송하시겠습니까?" 가 뜬다.**
   대표이사 결재 전에 급여명세서가 나가는 길이 열린다 — ⑤결재(*"결재 없이는 안 나간다"*) 정면 위반.

**⇒ 응답에 「최종승인됨」 여부를 실어 보낸다.** `leave`·`absence` 가 이미 쓰는
`CurrentSeq >= TotalLines` 판정을 **그대로** 쓴다(새 규칙을 만들지 않는다).

#### 설계 (확정)

| | 내용 |
|---|---|
| API 응답 | `{ message, isFinalApproved, docType, refId }` — 기존 `message` **유지**(다른 화면이 쓴다) |

🔴 **N 은 상태를 아무것도 안 바꾼다** — 아무 표에도 "거절함" 을 적지 않는다. 적으면 그게 막다른 길이 된다.

| # | 상황 | DB 실제 상태 | 반환값 | 팝업 |
|---|---|---|---|---|
| ① | **부장이 1단 승인** | `status=pending` `seq=2` | `IsFinalApproved=False` | ✅ **안 뜸** |

##### 결재 지킨 것

- **Y 는 발송이 아니다** — `/hr/payroll?send=1&slip=` 로 **보낼 뿐**이다. 게이트가
  결재관리 화면에서 `send-mail`·`SendMail` 을 부르는 것을 **금지**한다(반자동 원칙).
- **N 은 아무것도 기록하지 않는다** — 게이트가 그 분기에서 `SaveAsync`·`PostAsJsonAsync` 등을
  **금지**한다. 적어두면 그 값이 다음 발송을 막는 자물쇠가 된다(헌법 #20).
- **급여표 무접촉** — 이번에도 `payroll_*` 에 한 글자도 안 썼다. 기존 게이트
  `결재승인은_급여표를_건드리지_않는다` 통과 유지.

##### ⚠️ 남긴 것

- `_sendRequested` 는 **W6 이 쓸 값**이다. 지금은 담아만 두고 **아무 동작도 안 한다** —

- 권한: `PAYROLL` + **쓰기** 축 (조회 권한만으로 발송 못 함).


#### 🔬 착수 전 조사 (2026-08-26) — 기존 발송 경로를 그대로 쓰면 **조용히 빈 메일**이 간다

`EmailService.SendDocumentAsync` 를 N번 부르면 끝날 것 같지만, 그 안에 급여명세서에는
**쓸 수 없는 자리**가 하나 있다.

```csharp

catch (Exception ex)
{

```

🔴 **PDF 렌더가 실패해도 메일은 나간다.** 거래명세서라면 *"본문만이라도 가라"* 가 말이 되지만
급여명세서는 **본문에 금액을 안 적는다**(②결재). 그래서 렌더가 실패하면 직원은
**「급여명세서를 발송드립니다」 라고만 적힌 빈 메일**을 받고, 이력에는 **`sent`** 로 남는다.
경리는 다 보낸 줄 안다 — §4 가 막으려던 **"되는 척"** 그 자체다.

⇒ **급여명세서는 PDF 가 없으면 보내지 않는다.** 첨부 실패를 `failed` 로 기록한다.
   기존 `SendDocumentAsync` 는 **고치지 않는다**(거래문서 8종이 쓰는 길이다, 헌법 #1) —
   급여 경로에서 **미리 렌더해서 성공한 것만** 넘긴다.

#### 발송 대상 판정 — 🔴 「결재 승인」은 상태값이 아니라 **결재 여부**다

§6①에서 정한 대로 **결재 승인건만** 나간다. 그런데 `payroll_slips` 에는 승인 칸이 **없다**
(W2 에서 급여표 무접촉 원칙을 지켰기 때문이다 — 사장님 *"급여표에 써지는 내용을 건들라는게 아니고"*).

⇒ 승인 여부는 **`approval_documents` 를 되짚어** 판정한다.

```sql
LEFT JOIN approval_documents a
       ON a.tenant_id = s.tenant_id
      AND a.doc_type  = 'payslip'
      AND a.ref_id    = s.slip_id
      AND a.status    = 'approved'
```

⚠️ **결재선을 안 쓰는 회사는 결재 행이 아예 없다.** 그 회사는 `approved` 행이 영영 안 생기므로
**한 통도 못 보낸다.** 그건 워크플로우가 끊긴 것이다(#20) ⇒ **결재 기능이 꺼져 있으면**
(`approval_settings.is_enabled = 0` 또는 결재선 0줄) **확정(`confirmed`)만으로 발송 가능**하게 한다.
켜져 있으면 승인 없이는 못 나간다(⑤결재).

## 6. 🔴 착수 전 확인 2건

### ① 발송 대상 상태 범위

급여 상태는 `draft → confirmed → paid` 인데, 여기에 **결재**가 붙었다.

- **권고**: **결재 승인된 명세서만** 발송·게시.
  결재를 거치라는 것이 곧 *"승인 전에는 나가지 않는다"* 는 뜻이므로, 상태값보다 **결재 여부가 관문**이다.
- `draft`·미결재는 **제외** — 금액이 바뀔 수 있는데 명세서가 나가면 **직원이 틀린 금액을 받는다.**
- ⚠️ **메일과 그룹웨어가 같은 기준**이어야 한다. 한쪽만 열면 축이 갈린다.

### ② 🚨 기존 게이트와의 관계 — `결재승인은_급여표를_건드리지_않는다`

**이미 있는 게이트**가 결재 승인이 `payroll_*` 를 쓰는 것을 **금지**한다
(사장님 2026-08-21: *"급여는 수동입력원칙이야… 급여가 휴직을 모르고 사원만 알면 됨"*).

🔴 **이번 작업이 그 게이트에 걸릴 수 있다.** 다만 **성격이 다르다**:

| | 게이트가 막는 것 | 이번 작업 |
|---|---|---|
| 무엇 | 결재·휴직·근태가 **급여 금액을 자동 생성** | 사람이 손으로 넣은 명세서를 **승인 표시** |
| 왜 | 금액을 우리가 만들면 안 된다 | 금액은 **안 건드린다** |

⇒ **금액에는 손대지 않는다.** 승인 여부는 `approval_documents.ref_id = slip_id` **조회로 판정**하고,
`payroll_slips` 에는 **아무것도 쓰지 않는 방향**을 우선 검토한다(게이트 무수정).

⚠️ 그래도 상태 컬럼 하나가 필요해지면 **게이트를 고쳐야 하는데, 그건 사장님 결재 사항이다.**
🚫 **게이트를 임의로 완화하지 않는다** — 그 게이트는 사장님이 못박으신 원칙을 지키는 물건이다.
