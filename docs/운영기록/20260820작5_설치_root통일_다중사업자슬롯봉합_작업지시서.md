## 2. 실측으로 확정한 진범

### 2-1. 재현 (2026-08-20 23:39, 이 PC)

### 2-2. 진범 — 난수 root 비번 + 기설치 감지의 조합

`installer/HitPan-Universal.iss`

| 행 | 코드 | 문제 |
|---|---|---|
| 1732 | `MariaRootPw := GenerateRandomKey(24);` | **매 설치마다 난수 생성** |
| 1777 | `if NeedsMariaDB then begin ... PASSWORD="%s" ...` | **기설치면 이 블록을 건너뜀** |
| 1872~1969 | `-u root -p{MariaRootPw}` (12개소) | 난수를 그대로 사용 |

**연쇄**:
```
MariaDB 이미 존재 (NeedsMariaDB=False)
   → msiexec 건너뜀 → 난수 root 가 실제 DB 에 적용되지 않음
   → 이후 모든 mysql 호출이 실제와 다른 비번 사용
   → ERROR 1045 → TBL_COUNT=0 → "스키마 미설치" → 설치 DOA
```

⇒ **root 를 어떤 값으로 재설정해도 안 맞는다.** 설치 프로그램은 자기가 방금 만든 난수를 쓴다.
   (2026-08-20 실측: root 를 `Hitpan2025!` 로 재설정 후에도 동일 실패 재현)

### 2-3. 🔴 진짜 파괴력 — 다중 사업자 슬롯이 죽어 있다

`DetermineMultiTenantSlot()` (L345~479) 은 **한 PC 최대 5 사업자**를 이미 설계·구현했다:

| 분리 축 | 값 |
|---|---|
| DB명 | `hitpan_erp_{tenantCode}` (L478) |
| DB 계정 | `hitpan_{tenantCode}` (L479) |
| API 포트 | `5257 + 100×(N-1)` (L464) |
| 설치 폴더 | `{app}\tenant-{N}` (L1727) |
| 슬롯 | 1~5 |

**그런데 슬롯 2부터 원천 봉쇄된다**:

```
1번째 사업자 설치 : MariaDB 없음 → msiexec 실행 → 난수 A 가 실제 적용 → 성공
2번째 사업자 설치 : MariaDB 있음 → msiexec 건너뜀 → 난수 B 생성
                    실제 root = A ≠ B → ERROR 1045 → 설치 실패
```

⇒ **설계된 핵심 기능(다중 사업자)이 한 번도 동작한 적 없다.** 헌법 #20 P0.

## 3. 봉합 범위

### R-1 🔴 root 비번 통일 (진범)

`MariaRootPw := GenerateRandomKey(24);` → **빌드 주입 고정값**

- 값은 `hitpan` 계정과 동일한 `{#HitPanDbPassword}` (빌드 시 `HITPAN_DB_PASSWORD` 주입)
- **소스에 평문 금지** — 2026-08-11 시크릿스캔 적발 이력 준수
- `IsSafeDbPassword()` 문자 검사를 root 에도 동일 적용 (사고 #26 정합)

### R-2 root 불일치 — 침묵 실패를 명시 중단으로

통일값도 안 맞는 기존 PC(= 이 개발PC)를 위해:

```
root 접속 시도 (통일값, TryRootLogin 으로 실제 접속)
  → 실패 시 원인·해결책을 명시하고 중단 (코드: DB-ROOT-AUTH)
```

- 🔴 **침묵 실패 금지** — `>nul 2>&1` 로 오류를 삼키지 않는다 (검증서 6-1:187).
  종전엔 "설치는 성공, 로그인은 사망" 이었다. 이제는 왜 막혔는지 화면에 말한다.

⚠️ **입력 폴백은 이번 범위에서 뺐다.** 설계(`20260425작3:102`)는 비번을 1회 입력받는
그림이었으나, 이 지점은 `ssPostInstall` 이라 마법사 페이지를 띄울 수 없고 Inno Setup 에는
`InputQuery`/`InputBox` 가 없다(빌드 1차 실패로 확인). 입력을 받으려면
`CreateInputQueryPage` 로 **앞단에 페이지를 세워야** 하며, 그것은 별도 작업지시서 사안이다.
⇒ 통일값(R-1)으로 신규 설치·다중 사업자는 풀린다. 남는 것은 **통일 이전에 깔린 PC** 뿐이고,
   그 PC 는 화면 안내대로 기존 DB 제거 또는 CS 경유로 해결한다.

### R-3 다중 사업자 슬롯 종단 실측 (진짜 게이트)

**R-1·R-2 를 고쳐도 슬롯 2가 실제로 도는지는 실측해야 안다.**

| # | 시나리오 | 합격 기준 |
|---|---|---|
| ① | 백지 PC → 사업자 A 설치 | 스키마 124+ 테이블, 로그인 성공 |
| ② | 같은 PC → 사업자 B 설치 | **ERROR 1045 없이** 설치 완료 |
| ③ | A·B 동시 기동 | 포트 5257 / 5357 각각 응답 |
| ④ | A·B 데이터 격리 | B 계정으로 A DB 접근 불가 |

⇒ **④까지 PASS 해야 봉합 완료.** ①만 되고 ②가 안 되면 지금과 같다.

## 4. 🔴 헌법 #23 — 보안 결재 필요 사항

`HitPan-Universal.iss:1821` 에 **반대 취지의 과거 결재**가 주석으로 남아 있다:

> *"🔴 root(MariaRootPw)는 통일하지 않는다 — 그 PC 의 DB 전부를 여는 열쇠라
>   한 곳에서 새면 다른 고객사까지 열린다. 여기는 설치마다 무작위 그대로 둔다."*

**본 지시서는 이 결정을 사장님 지시로 뒤집는다.** 근거:

1. **한 PC = 한 고객사** — 슬롯 구조는 *같은 회사의 여러 사업자*다. 남의 회사가 같은 PC 에 있지 않다.
2. **실 격리는 계정 단위** — `hitpan_{tenantCode}` 가 `GRANT ALL ON {자기DB}.*` 로 묶인다. root 통일이 이 격리를 깨지 않는다.
3. **2026-08-11 `hitpan` 계정 통일과 같은 논리** — 그때 근거가 *"고객사마다 PC 가 다르다"* 였다.
4. **통일 안 하면 기능 자체가 죽는다** — 슬롯 2~5 가 영구 봉쇄. 잃는 것이 지키는 것보다 크다.

⇒ 보안상무(안철수) 사후 감수 대상으로 기록한다. 주석 1821 은 **삭제하지 않고** 경위와 함께 갱신한다(헌법 #1).
