## 1. 오더를 이렇게 이해했다 (명문화)

### 1-1. 502 건 — **미구현이 아니라 이미 만든 방어선이 뚫린 것**

⚠️ **중요**: 이 화면은 이미 있다. `UpdateProgressOverlay.razor`(20260806작7, 사장님 "a안으로 결재").
그 파일 머리말이 **오늘 사고를 이미 적어 두었다**:

> *"업데이트 중 히트판이 꺼지면 고객 화면에 **502 오류 페이지**가 뜬다.
> 사장님이 직접 '502 에러 떴다'며 고장으로 읽으셨다. **고객은 100% 전화한다.**"*

**그런데 오늘 또 났다.** 원인은 그 안의 힌트 한 줄이다.

`UpdateProgressOverlay.razor:49-52`
```razor
@if (_showManualHint)
{
    <div class="hp-upd-hint">오래 걸리면 F5 를 눌러 주세요</div>
}
```

`:80` — `ManualHintSeconds = 90`

### 1-2. 🔴 진범 — 같은 파일 안에 정답과 오답이 함께 있다

| 경로 | 동작 | 502 |
|---|---|---|
| `RetryAsync()` (`:131`) — [다시 확인] 버튼 | **살아있는지 확인하고** 들여보냄 | 🟢 안 남 |
| `_showManualHint` (`:51`) — 90초 힌트 | **확인 없이** F5 를 권함 | 🔴 **남** |

⭐ **한쪽은 확인하고, 다른 쪽은 확인 없이 권한다.**
`RetryAsync` 주석(`:129`)이 이유까지 정확히 적어 두었다:

> *"F5 를 권하지 않는 이유: 히트판이 아직 안 떴으면 **F5 가 곧 502 다**."*

그 원칙이 90초 힌트에는 적용되지 않았다.

### 1-3. 왜 90초에 떴나 (실측 근거)

`:73-78` 주석: 사장님 원안 30초 → 워치독 판정창 60초와 겹쳐 **90초로 늘림**.
그런데 **오늘 업데이트가 90초를 넘겼다.** 1.2.60 은 99MB 다.

⇒ **시간으로 막는 방식 자체가 한계다.** 시간을 더 늘려도 느린 PC 에서 또 뜬다.
**시간이 아니라 상태로 판정해야 한다.**

### 1-4. 메인PC 건 — 자동등록이 없다

현행 `UserInfoPage.razor:232` `[이 컴퓨터 등록]` 은 **사람이 눌러야** 한다.
`UserInfoPage.razor.cs:72-76` 주석:

> *"시리얼 입력이 사라지면서 이 화면에서 그 키를 얻을 방법이 없어졌고, 아래 값은 항상 비어 있다.
> 기기 등록을 어디서 할지는 **별도 결재 사항**"*

⇒ **버튼은 있는데 눌러도 되지 않는 상태**일 가능성이 높다(실측 필요).
그리고 **DB 를 가진 메인PC 라는 개념 자체가 없다** — 모든 기기가 동등하게 취급된다.

## 2. 무엇을 하는가 (범위)

### T1. 502 봉합 — "확인 후 새로고침" 으로 통일 (P0)

- [ ] `:51` 힌트를 **문구에서 버튼으로** 바꾼다 — `[다시 확인]`(이미 있는 `RetryAsync` 재사용)
- [ ] **F5 를 권하는 문구 제거** — 고객이 직접 누르면 확인 없이 새로고침된다
- [ ] 90초 시점 문구를 *"조금 더 걸리고 있습니다"* + `[다시 확인]` 버튼으로
- [ ] `RetryAsync` 가 유일한 복귀 경로가 되게 한다(경로 1개 = 규칙 1개)

⭐ **핵심: 살아있는지 확인하지 않고 화면을 새로 여는 경로를 0개로 만든다.**

### T2. 브라우저 새로고침 자체를 안전하게 → 🔴 **브라우저에서는 불가능 (실측 완료)**

⚠️ 고객이 **안내와 무관하게** F5 를 누를 수 있다(습관·조급함). 그때도 502 를 보면 안 된다.

#### 실측 결과 (2026-08-10) — 구조적으로 막을 수 없다

`installer/HitPan-Universal.iss:1134-1137` 원문:

> *"터널 — ingress origin = `http://localhost:5257`(API). **API 는 자기 wwwroot 로 Blazor 를
> 서빙**하면서 `/api/*` 도 같은 프로세스가 처리한다."*

```
F5 누름 → 브라우저가 페이지를 다시 받으러 감
        → 그 페이지를 주는 주체가 API(5257)
        → 업데이트 중이라 API 가 꺼져 있음
        → 🔴 Blazor 파일 자체가 안 내려옴
        → 터널이 502 를 냄. 우리 코드는 한 줄도 실행 안 됨
```

⇒ **Blazor 안에서는 이 502 를 잡을 수 없다.** 잡을 코드가 그 시점에 브라우저에 없기 때문이다.
(이미 떠 있는 오버레이가 살아남는 이유도 같다 — 이미 받아둔 것은 살고, 새로 받는 것은 못 받는다)

#### 그래서 이번 범위에서 제외한다

| 대안 | 판정 |
|---|---|
| Blazor 에서 502 가로채기 | ❌ **불가** — 코드가 실행되지 않는다 |
| 터널 오류 페이지 교체 | ⬜ 별건 — cloudflared 설정 영역(**헌법 #29** 인프라 사전 승인) |
| Service Worker 로 오프라인 응답 | ⬜ 별건 — WASM 캐시 전략 변경이라 파급이 크다 |

🔴 **결론: T1 이 유일한 실효 방어다.** 우리가 F5 를 권하지 않으면 대부분 안 누른다.
그래도 누르는 고객은 남으므로, **터널 오류 페이지 교체를 별도 작업지시서로 올린다.**

⚠️ 이것을 "봉합했다" 고 적지 않는다. **줄인 것이지 없앤 것이 아니다.**

### T3. 메인PC 자동등록 (P1)

- [ ] 현행 `[이 컴퓨터 등록]` 이 실제로 동작하는지 **먼저 실측**
- [ ] DB 를 보유한 PC 를 **설치 시 자동 등록** — 고객 손 0번
- [ ] 판정 기준: 이 PC 가 DB 서버인가(로컬 MariaDB 보유 여부)

### T4. 메인PC 표식 (P1)

- [ ] 회사정보 화면 `이 컴퓨터 등록` 영역에 **메인PC 여부 표시**
- [ ] 문구는 고객 말로 — *"이 컴퓨터"*·*"주 컴퓨터"* 등 (개발용어 금지)
- [ ] ⬜ **사장님 결재 필요**: 표식 문구·표시 위치

### 안 하는 것

- ⛔ 워치독 판정창(60초) 변경 — 이번 범위 밖
- ⛔ 기기 슬롯 정책 변경 (사장님 계획 있음 — 앞서가지 말 것)
- ⛔ 시리얼 입력란 부활 (`20260810작1` 에서 변경요청 화면 안으로 확정)

## 3. 완료 판정 기준

| 관문 | 기준 |
|---|---|
| 1 | 빌드 **errors 0 + warnings 0** |
| 2 | 화면에 **F5 를 권하는 문구 0건** (`grep "F5"`) |
| 3 | 독립 반증 — 검증팀 |

### 실동작 판정 (개발PC 정상은 검증 아님)

- [ ] 업데이트 90초 초과 시 **F5 문구 대신 [다시 확인] 버튼**이 뜨는가
- [ ] [다시 확인] 을 아직 안 떴을 때 눌러도 **502 가 안 뜨는가**
- [ ] 살아난 뒤 누르면 **바로 들어가는가**
- [ ] 메인PC 표식이 **실제 메인PC 에서만** 보이는가

⚠️ **돌연변이 시험**: 일부러 API 를 내린 상태에서 [다시 확인] 을 눌러 **502 가 안 나는지** 확인.
