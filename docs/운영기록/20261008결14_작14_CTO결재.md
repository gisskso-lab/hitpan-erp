## 조건 (번호 — 전부 지시서 보강, 설계 변경 아님)

1. **B-게이트·C-게이트 행 신설**: CS설계서 §2-ⓓ⓪~⑥(3중 하나만 틀림 3종 거부·폐기 시리얼 거부·멱등 1건·화이트리스트 밖 거부+로그 실존·음성 대조군) + §5-ⓓ①~⑦(터널 실단절·500/400 분기·PC 전원차단·주민번호 400+거부행·17시나리오 #1·#2·#4 재측정) + AC-01~05c 7건을 지시서에 번호로 결속 · **새 게이트 전부 CI `db-gate` 등록**(로컬 DB 없는 PASS=SKIP · 판별은 소요시간 — 26번 사고 조항) 한 줄 포함.
2. **보안상무 조건 3·7 의 나머지 절반**: B-6 에 ①실패 잠금(`serial_verify_locks` 선례 모양) 추가 ②남용 FAIL 게이트 2개 글자로 — 같은 테넌트 난사→상한 거부+기록 · 본문 상한 초과→413 · 대리점 토큰으로 CS 설정 변경→거부.
3. **금지필드 3문 전부 명기**: 지시서 B-4 는 송신 전 1문만 적었다. ERP 저장 전 · 송신 직전 · **백오피스 수신(화이트리스트 밖 필드 거부)** 3문 + (결-5 ㉯ 채택 시) 값 패턴 검사 3문·FAIL 게이트 **같은 커밋** — B-4·B-5 에 글자로.
4. **B-선결의 실체화**: [1-V] 실측 결과에 따라 **B-0(부모계정 수집 구현 — 백오피스 `tenants` 칸 + 수집 경로) 행을 추가**하거나, 별건 S-2 트랙 완료를 B 착수 조건으로 명기. 수집이 별도 결재 거리면 그것도 §8 에 올린다. 이 행이 없으면 B-5 의 세 번째 다리를 구현자가 발명한다.
5. **갈래 분할 시 인터페이스 변경 선머지 원칙 명기** — CS설계서 §9 「다음 단계」가 지시서에 적으라고 한 줄인데 빠졌다(작8 CS0535: 갈래별 0/0 ≠ 합류 0/0).

## 사장님행 (최종 결재에서 꼭 보실 것 — 쉬운 말)

1. §8 의 17가지 물음은 전부 맞는 물음입니다. 이미 결재하신 건 다시 안 물었고, 「전부 권고대로」 한 마디면 닫힙니다.
2. 다만 쪽지 신분증의 세 번째 다리(부모계정)가 **백오피스에 아직 칸조차 없습니다**. 10/5 에 「명심」하라 하신 대표 아이디 수집이 진짜 앞 단추 — 이게 끝나야 쪽지 받는 문(B-5)을 만들 수 있습니다. 메뉴 정리(A)는 그동안 따로 진행 가능합니다.
3. 법무-1: 탈퇴 때 결제기록까지 지우는 건 전자상거래법 보존 의무에 걸릴 수 있습니다 — 법무팀장 확인 전엔 삭제 기능 구현을 막아 두었습니다.
4. 돈이 드는 건 결-7 하나(월 1,000건 기준 약 1.5만 원 — 추정)이고, AI 는 법무 4건이 끝나기 전엔 한 글자도 밖으로 안 나갑니다(잠금이 기본 잠김).
