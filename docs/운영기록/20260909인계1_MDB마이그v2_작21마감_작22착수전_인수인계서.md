## §5. 함정 — 다음 세션이 밟을 지뢰
> 작21 과정의 함정(perl `${1}` · `git checkout --` 는 인덱스 · CodeQL check-run 둘 · CRLF `$` 앵커 · 비번 추출 · perl 이중인코딩 · 재이관은 덮어쓰기 후)은 **9/7 인계1 §5** 에 있다 — 그대로 유효.
- **DataResetService 의 목록은 "지울 표" 가 아니라 "보존할 표"(시스템·설정·계정)다** — 이관 표 33개는 목록에 없으므로 초기화 대상이다. 덮어쓰기 모드는 이 서비스를 **그대로 부르면** 되지, 이관 표 목록을 새로 만들지 마라(§8-a).
- **찾아보기·업로드는 현재 0건이다** — 화면은 경로 텍스트박스뿐, 컨트롤러에 browse/upload 엔드포인트 없음. ERP 는 고객 PC 로컬에서 도니 "찾아보기" = **서버 측 폴더 탐색 API**(드라이브·하위 폴더 나열, `..`·UNC 차단)가 자연스럽고, 업로드(MDB 300MB 멀티파트)는 별도 판단 — 설계에서 갈라라(§8-b).
- **`hr_reports` 생성 경로(`WorkReportService`)는 `is_active=1` 사원만 받는다** — 이관은 서비스를 거치지 않고 직접 INSERT(마이그 예외 원칙)하되 `LEGACY_FALLBACK` 사원이 활성인지 확인. 목록은 `@EmployeeId IS NULL` 이면 전체 조회라 관리자 화면에서 이관분이 보인다(§8-c).
- **`invoice_no` 는 `{TX_NO}-{SEQ}-{PDT}` 로 방향이 없다**(5월 18차, 1,304건 자기중복 봉합의 잔재). `uq_tax_invoices_io_no(tenant, direction, tax_no)` 가 이미 있으니 **방향 토큰을 invoice_no 에 넣는 쪽**이 UNIQUE 를 안 바꿔 안전하다 — 단 화면이 invoice_no 를 표시·검색하는지 grep 먼저(§8-d).
- `migration_checkpoints` 는 DDL 만 있고 코드 참조 0 — 컬럼(job_id·table_name·status·processed_count·last_pk_value JSON·retry_count)이 W3 체크포인트 설계에 그대로 맞는다. 새 표 만들지 마라(§8-e).
- 세션 튜닝 `unique_checks=0` 은 **일부러 안 고쳤다**(INSERT IGNORE 멱등과 충돌 가능) — 작22 에서 재검토하되 멱등 게이트와 같이 본다.
