| 항목 | 내용 |
|---|---|
| 왜 | 진실원 §4 **B1⑥** 합격선 = *"열린 PR → 5건 이하"*. [4] 작업리뷰서 **조건①** 이 이 문서(1장)와 [문서 22개 구조안](20261015_구조안_문서22개_PR가지기록_PM전결.md)(1장) 누락을 지적했다 |
| 오더 | 사장님 2026-10-15 *"업무스케쥴표대로 첫번째 스케쥴을 실시"* + 결재 7건 **전결** |
| 측정 | 2026-10-15 · `gh pr list --state open --limit 100` = **25건** · 가지별 `git diff origin/main..refs/prs/N --name-status` 전수 대조 |

| 🔴 집행 상태 | **판정만 끝났다.** `gh pr merge`·`gh pr close` 가 PM 세션 권한에 막혀 있다 — 사장님 1탭 또는 권한 허용이 필요하다 |

## §1 🔴 가장 중요한 발견 — **폐기 후보가 0건이다**

PM 이 처음 깔았던 전제(*"문서 PR 은 이미 main 에 들어갔을 것"*)가 **틀렸다.**
25건 전부 `origin/main` 과 **내용이 다르거나 경로 자체가 없다.** ⇒ **그대로 닫으면 손실 없는 PR = 0건.**

그중 **문서 22개는 그 PR 가지에만 있다**(`origin/main`·로컬 **둘 다 없음** · PM 표본 9건 직접 확인). 닫으면 **사라진다**(#42 위반). → 구조안 참조.

**⇒ 「25건 중 20건을 닫는다」가 아니라 「먼저 건져내고, 그 다음에 닫는다」 다.**

## §3 🔴 선행조건 1 — 이것 없이는 ②를 못 움직인다

문서 PR 다수가 **`Scan secrets`(TruffleHog) 실패**다. 🟡 **PM 가설**: 묵은 가지의 **커밋 이력**에 자격증명 모양이 있어 물린다.
⇒ **그 문서를 그대로 건져내면 새 가지에서도 물릴 수 있다.**

**해야 할 것**: 묵은 PR 의 `Scan secrets` 실패 이유 규명. 🔴 **값은 출력하지 않고 건수만 센다.**
🔴 **지금 막혀 있다** — 런 로그 조회가 PM 세션 권한에 막혔다(`[Production Deploy]` 로 분류됨). **사장님 손이 필요한 자리다.**

## §4 집행 순서 — 바꾸면 기록이 날아간다

```
1. 🔴 Scan secrets 실패 이유 규명 (§3 · 권한 필요)
2. 문서 22개를 현재 main 위 새 가지로 복원 → PR 1건  (구조안 §2)
3. 복원 PR 머지 확인  ← 🔴 이 확인 전에는 아무것도 닫지 않는다
4. #50 머지 (갈래①)
5. 갈래② 17건 닫기
6. #51·#8·#5·#13·#485·#552 = 별건 결재로 넘김 (닫지 않음)
7. #408 그대로 둠
```

**이 순서를 지키면** 열린 PR = 25 → **8건**(#51·#8·#5·#13·#408·#485·#552 + 복원 PR 1). 🔴 **목표 5건 이하에는 못 닿는다** — 남는 7건이 전부 **별건 결재 대기**이기 때문이다.

⇒ 🔴 **B1⑥ 합격선 재조정 제안**: *"5건 이하"* → **「닫을 수 있는 것을 다 닫고, 남은 것은 전부 결재 대기 사유가 문서에 있다」**. 숫자를 맞추려 결재 없이 닫으면 그게 사고다.
