## 2. 🔴 이번 세션이 찾은 가장 중요한 것

### 2-1. 작9 를 지금 하면 안 된다 — 확정에 권한 통제가 없다

사장님 지시 7 *"판매확정·구매확정은 **암묵적인 결재기능**"* + 지시 9 *"ERP 결재 7종 모두 빼"*.
그 말이 성립하려면 **확정이 결재만큼 통제**돼야 하는데 —

| 확정 엔드포인트 | 개별 권한 |
|---|---|
| `sales/deliveries/{id}/confirm` | **없음** |
| `sales/deliveries/bulk-confirm` | **없음** (일괄이라 영향 큼) |
| `purchase/receipts/{id}/confirm` | **없음** |
| `purchase/returns/{id}/confirm` | **없음** |
| `sales/returns/{id}/confirm` | `Authorize(SalesManager)` ← **유일** |

```
현재:  확정(통제 약함) + 결재(통제 있음)  → 결재가 뒷문을 막고 있다
작9후: 확정(통제 약함)                     → 막는 게 없다
```

🔴 **작9 의 부작용이 아니라 작9 의 전제가 아직 없는 것이다.**
⇒ **작11**(확정 권한 부여)을 신설해 **작9 보다 먼저** 한다 — **PM·CTO 전결**.

### 2-2. 🔴 `sales_user` 가 지금 거래명세서를 확정할 수 있다

`Program.cs:335-343` 실측:
```
SalesOnly     → system_admin, sales_manager, ★sales_user★, TenantAdmin, tenant_admin
SalesManager  → system_admin, sales_manager,               TenantAdmin, tenant_admin
```
두 정책의 차이가 **정확히 일반 판매담당자 한 칸**이다.
⇒ `sales_user` 는 **거래명세서를 확정할 수 있고 판매반품만 못 한다.** 같은 확정인데 갈린다.
확정은 헌법 #6 에 따라 **원장이 움직이는 시점**이다.
