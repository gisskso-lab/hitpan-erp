## §0 [오더] ⭐ 사장님 오더 (원문 그대로 — 이 문서의 원본)
> (9/29 ①) "루틴대로 진행해" — 별건 N-UPD4 착수
> (9/29 ②) "업데이트 실패후 혹은 업데이트중 컴퓨터 전원종료, 혹은 기타등등 여러 이슈로 업데이트가 되지 않았을 경우 / 업데이트 "나중에" 를 클릭 하여 팝업이 뜨지 않는경우 / 등등 / "업데이트가 정상적으로 이루어지지 않았습니다. 업데이트를 정상상적으로 실행하시겠습니까 Y/n" / 안내가 계속 떠야 함. 자료관리대메뉴 아래 버젼에 업데이트 이슈사항 표기하여, 언제든지 업데이트를 정상적으로 마칠 수 있도록 할것."
> (9/29 ③) 「직원이 [예]를 눌러도 되나」 → "= 메인PC에서만"

**이 아래 모든 내용은 위 오더를 명문화한 것이다.** 오더에 없던 요구를 넣지 않는다. 해석이 갈리는 곳은 설계 §9 Q-1~Q-5 로 사장님께 여쭌다(#33).

## §1 [이해] 오더를 이렇게 이해했다 (명문화)
- 사장님 의중: 업데이트가 어떤 이유로든(실패·전원 종료·[나중에]) 안 끝났으면 **메인PC 에서 다시 Y/n 을 묻고**, 사이드바 버전 줄 아래에 무엇이 안 됐는지 늘 보이며, 거기서 **언제든 마칠 수 있다**. [예]/[나중에]는 메인PC 만, 다른 PC 는 안내만.
- 안 하면: 9/29 처럼 ①[예]를 다시 눌러도 워치독이 무시(N-UPD2) ②[나중에] 한 번에 그 버전이 멈춤(N-UPD4) ③재부팅 때 묻지 않고 옛 [예]로 재시도 ④같은 탭 재로그인은 안 물음(#43 「다음 로그인에 다시」 위반) ⑤직원 [나중에]가 사장님 [예]를 뒤집음 ⑥교체 중 전원이 꺼지면 ERP 가 못 떠 안내 자체가 불가.
- 실측 근거: [1-V] 1차·2차 선행검증서(코드 파일:줄 · SQL 세션 임시표 🧪S2) — 이 문서는 새 실측 없음. 🔴 2차 §2 전원 종료 경로는 **코드 추적(⚠️가설)** — [4] 가 임시 폴더로 재현한다.
