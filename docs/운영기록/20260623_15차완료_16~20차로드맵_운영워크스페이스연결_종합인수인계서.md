## 2. 15차 결과 상세 (방금 완료)

### 방법론 (16~20차도 이대로 반복)
1. **1차 5병렬 실측** — 9축 분담: ①판매 ②매입 ③BOM/재고 ④회계/기표 ⑤결재 ⑥계정계층·권한격벽 ⑦마이그 ⑧출하DDL/신규설치 ⑨프론트/UX/전역. (Explore 에이전트 5명 동시, 읽기전용, file:line 인용 강제)
2. **2단 교차검증(적대)** — 1차 "전원 PASS"를 의심하고 반증 시도. 적대검증관이 PASS를 흔들어 실결함 발굴.
3. **봉합** — 사장님 결재 후(헌법 #33).
4. **거짓봉합 자가검증** — 봉합 직후 적대검증관이 UNIQUE 회귀·역행 부호·멱등·인터페이스 6점 재검.

### 15차 발굴/봉합
- **[15-P1] 반품 취소 경로 부재 → 풀스택 봉합** (커밋 1be6013)
  - 신설: `AutoJournalHelper.RecordSalesReturnCancelAsync` / `RecordPurchaseReturnCancelAsync` (전용 source_type `sales_return_cancel`·`purchase_return_cancel`)
  - `SalesService.CancelSalesReturnAsync`([SalesService.cs](../../src/HitPan.Application/Services/SalesService.cs) — 재고 Reverse OUT + item_stock 차감 + summary/balance 복원)
  - `PurchaseService.CancelPurchaseReturnAsync`(대칭, Reverse IN + 가산)
  - 인터페이스 2(`ISalesService`·`IPurchaseService`) + 컨트롤러 2(`POST returns/{id}/cancel`) + `DeliveryService` Cancel 2 + `ReturnPage` 핸들러·버튼(confirmed에서만)
  - 멱등: confirmed만 취소→canceled
- **[15-P3] doc_type 출하DDL 주석 정합** — `installer/hitpan_db_clean.sql:258` 에 `sales_return`·`purchase_return` 추가

### ⭐ 거짓 경보 기각 (차기 조사 재오판 절대 금지)
- 1차 축1이 "BOM 폭발 source_id = delivery.DeliveryId + item.ItemId = 41자 → stock_ledger varchar(36) 초과 ERROR1406" 의혹 제기.
- **실코드 확인 결과 거짓**: [SalesService.cs:1365](../../src/HitPan.Application/Services/SalesService.cs#L1365) `SourceId = delivery.DeliveryId` **단독 36자**(ItemId 미부착). `materialConsumption` Dictionary로 자재별 1행 합산(7차 B-1 봉합)이라 UNIQUE 충돌도 없음.
- 원인: 축1이 7차 봉합 주석의 *과거버그 설명*을 현재코드로 오독.
- **16~20차에서 이 41자 오판 재발 금지. 보존 사실: BOM 폭발 source_id는 deliveryId 단독 36자.**

## 5. 수요일(6/25)~ 운영 워크스페이스 워크플로우 연결작업 (사장님 5단계 명세)

> 3시스템: 랜딩=`landing.hitpan.kr`(클라우드 가입영역) / 백오피스=`back.hitpan.kr`(클라우드 워크스페이스) / ERP=`{고객사ID}.hitpan.kr`(로컬PC+터널 판매서비스). 헌법 #35 완벽 분리 + 유기적 연결.

| 단계 | 시스템 | 작업 | 검증 |
|---|---|---|---|
| **0** | ERP | 20차 98점 후 설치마법사 EXE 빌드 | 빌드 성공 |
| **1** | 랜딩페이지 | 가입 → 설치마법사 다운로드 → **도메인 생성** | 가입동선·다운로드·DNS 발급 |
| **2** | 백오피스 | 랜딩 가입계정 등록 → **시리얼넘버 생성·발송** | 계정등록·시리얼 생성·발송 |
| **3** | ERP | 설치마법사 설치·셋업 → 시리얼 기입 → 정상설치 | **샌드박스로 테스트**(`installer/sandbox-test.wsb` 활용) |
| **4** | ERP | 정상설치 + 가입계정 + 생성 도메인으로 정상작동 확인 | 외부접속·로그인·업무흐름 |
| **5** | 백오피스 | ERP 유저 백오피스 계정등록·관리 정상작동 확인 | Pull·관리 화면 |

- **연결축은 베타부터 정식 완성도**(헌법 #34): 토큰 자동회전·도메인 자동발급·터널 자동복구·워치독·5중검증·원클릭.
- **데이터 방향 절대**(헌법 #18·#22): ERP→본사 업무데이터 전송 0. 본사가 받는 건 SaaS 메타 + 대리점 영업데이터뿐. 계정ID=라이선스는 백오피스가 부여(고객 입력 금지).
- **계정 계층**(헌법 #38): 랜딩 가입→백오피스가 계정ID 발급→ERP 부모계정 자동반영→부모가 ERP 안에서 자식계정 생성. 부모=백오피스 관리/자식=ERP 로컬만.

### 그리고 → **30차 전수조사** (설치운영 워크스페이스 워크플로우 작동 검증)
위 5단계 흐름(가입→설치→시리얼→정상작동→백오피스관리)이 끊김 0(헌법 #20·#35)으로 작동하는지 전수조사. 16~20차가 ERP 내부 무결성이었다면, 21~30차는 **3시스템 연결 워크플로우** 무결성.
