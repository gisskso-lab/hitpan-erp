## 0. ⭐ 사장님 오더 (원문 그대로 — 이 문서의 원본)

> *"히트판erp에 직접 들어가서 인쇄양식 확인해보니 **못쓸 수준**이던데??"*
> *"**pdf로 그리는 엔진 좋아!!** … 하지만 양식이 못쓸정도로 너무 허접해."*
> *"양식지 기본셋팅이면 **이정도 디자인 퀄리티는 나와야** 하지 싶은데??"*

**이 아래 모든 내용은 위 오더를 명문화한 것이다.** 오더에 없던 요구를 넣지 않는다(#33).

## 1. 오더를 이렇게 이해했다

- **의중**: 세금계산서를 **거래처 경리가 받아 주는 종이**로 만들고, **메일과 종이가 글자 하나까지 같게** 한다.
- **안 하면**: B4 베타 1곳에서 **화면 사진 / 남의 서식 / 빈 종이**가 실제 거래처로 나간다. 법정 서식이라 **반송**된다.
- **실측 근거**: 선행검증서 전문(코드 0줄 · DB 0 · 빌드 0) · 설계문서 §1·§13.

## 12. 🟢 미리보기 범위 — **양식지 전표는 전부** (사장님 결재 2026-10-21)

> 사장님: *"모든 양식, 출력, 인쇄물에 미리보기가 되야함. … 전표 외 자료 출력시엔 엑셀로 변환해서 출력하면 되지만, 양식지가 필요한 전표자료(거래명세서, 견적서, 발주서, 수주서, 매입명세서, 반품명세서, 계산서) 출력물은 미리보기가 되야 함."*

### 12-1 🟢 선이 그어졌다

| 갈래 | 출력 | 미리보기 |
|---|---|---|
| **양식지가 필요한 전표** | **양식 PDF** | 🔴 **필수** |

### 12-2 실측 — **양식 종류는 이미 10종이 정의돼 있다**

`FormTemplateEditorDialog.razor:190-203` — 견적서 · 수주서 · 거래명세서 · 발주서 · 매입명세서 · **매입반품** · **판매반품** · **세금계산서** · **계산서(면세)** · 입금표

⇒ **사장님의 7 = 코드의 9종**(입금표 넣으면 10종).

### 12-3 🟢 구조상 유리한 점 — **한 번 붙이면 전 종류가 된다**

미리보기는 **양식 편집창**에 붙는다. 편집창은 **`form_type` 하나를 편집**하므로, 미리보기를 **한 번** 제대로 만들면 **10종이 자동으로 커버된다.** 종류마다 따로 만들지 않는다.
🔴 전제 = §11-6 대로 **정본 통로(`RenderDocumentAsync`)를 그대로 탄다.** 미리보기 전용으로 따로 그리면 **종류 수만큼 어긋난다.**

### 12-4 🔴 사장님께 미리 말씀드릴 것 — **미리보기를 붙이면 나머지가 다 드러난다**

이번 차수는 **세금계산서 1종**만 고쳤다. 나머지 9종의 종이 품질은 **아무도 재지 않았다.**
🔴 **미리보기가 생기는 순간 9종의 지금 상태가 그대로 보인다.** 좋은 일이지만(처음으로 전수를 눈으로 본다), **「이것도 허접하네」가 9번 나올 수 있다**는 것을 미리 적어 둔다. 그때가 **9종 양식 작업의 시작점**이다 — **미리보기 차수에서 9종을 같이 고치지 않는다**(범위 폭발).

### 12-5 🔴 [1-V] 에서 먼저 잴 것 (미리보기 차수 선행검증)

1. 🔴 **정본 통로가 10종 중 몇 종을 실제로 그리나** — 어제 실측에서 `invoice_exempt` 는 **빈 종이**였고(A-5) 자료 적재 누락이 **5종**이었다. **미리보기에 빈 종이가 뜨면 그게 첫 인상이 된다**
2. `form_type` 목록이 **3곳에 사본**으로 있다(편집창 · 목록 화면 · 서버 `FormTemplateService`) — **어긋나 있나**

4. `preview-pdf` **권한 확인 없음** 봉합 범위

`installer/deploy/publish-run.sh`(main 에 있다) 를 읽어 갈랐다. 🔴 **두 오류 문구가 다르다**:

- 토큰이 없을 때 → `"B-4: GitHub 토큰(/var/hitpan/update-keys/github-b4-token) 미배치·비어있음"`
- 🔴 **이번에 난 것** → `"B-4: GitHub API run 조회 실패(40053009516)"`

즉 **토큰 파일은 있고 비어 있지도 않다.** 깨진 것은 그다음 줄이다:

```
curl -fsS -H "Authorization: Bearer <토큰>" -H "Accept: application/vnd.github+json" \

```

`curl -f` 라서 **HTTP 400 이상 또는 연결 실패**면 전부 같은 한 줄로 떨어진다 ⇒ **지금 로그만으로는 더 못 가른다.**

### 21-3 🔴 PM 이 할 수 없는 일 — 사장님 손 1회

토큰은 `/var/hitpan/update-keys/github-b4-token`(600 root)이고, 가르려면 **NCP 에서 읽어야** 한다.


|---|---|---|
| **401** | 토큰 **만료·폐기** | 새 토큰 발급 → 그 파일만 교체(600 root) |

| **200** | 토큰은 멀쩡 | 🔴 원인이 다른 곳 — 게시 시점 일시 장애였거나 `jq`·DNS·egress. 재게시로 가른다 |
| **000 / 연결실패** | NCP → `api.github.com` **외부 통신 차단** | 방화벽·egress (🔴 #29 사전 승인) |

### 21-6 🔴 §21-3 진단 교정 — **상태코드만으로는 403·404 를 못 가른다** (다른 창 지적 · 2026-10-24)

`hitpan-erp-d3` 가 **§21-3 의 진단 한 줄로는 부족하다**고 지적했고, 맞다.

🔴 **사유는 그쪽이 적은 것과 조금 다르다** — 그쪽은 *"`curl -f` 가 본문을 버린다"* 고 했는데, `-f` 는 **제품 스크립트**(`publish-run.sh`)가 쓰는 것이고 §21-3 의 진단에는 `-f` 가 없다. 본문을 버린 것은 **`-o /dev/null`** 이다. 🟢 **결론은 같다: 거부 사유 문구가 안 남는다.**

🔴 **왜 그게 문제인가** — 상태코드만 보면 다음을 못 가른다:
- **403** = 레이트리밋 / SAML SSO 미승인 / 스코프 부족 — **셋이 전부 403** 이고 조치가 다르다
- **404** = run 이 없다 / fine-grained 토큰에 그 레포 권한이 없다 — **GitHub 은 권한 없음을 404 로 숨긴다**

**🟢 고친 진단 (NCP 에서 읽기만 · 파일 안 만든다 · 토큰 값 안 찍는다)**

```
# ① 인증 호출 — 상태줄 + 거부 사유 + 가르는 헤더
sudo bash -c 'T=$(tr -d "\r\n" < /var/hitpan/update-keys/github-b4-token); \
  curl -sS -i -H "Accept: application/vnd.github+json" -H "Authorization: Bearer $T" \
    https://api.github.com/repos/gisskso-lab/hitpan-erp/actions/runs/40053009516 \
  | sed -n "1p;/^x-ratelimit-remaining:/Ip;/^x-github-sso:/Ip;/^x-accepted-github-permissions:/Ip;/\"message\"/p" \
  | head -8'

# ② 통신 자체 — 인증 없이 (①이 000·연결실패일 때 egress 인지 토큰인지 가른다)
curl -sS -o /dev/null -w "connect=%{http_code}\n" https://api.github.com/zen
```

| 보이는 것 | 뜻 | 할 일 |
|---|---|---|
| `401` + `"message": "Bad credentials"` | **토큰 만료·폐기** ← 가장 유력 | 새 토큰으로 그 파일만 교체(600 root) |
| `403` + `x-ratelimit-remaining: 0` | 레이트리밋 | 잠시 뒤 재게시 |
| `403` + `x-github-sso:` 가 보인다 | **SAML SSO 미승인** | 조직에서 그 토큰 승인 |
| `403` + `x-accepted-github-permissions:` | 스코프 부족 | `actions:read` 부여 |
| `404` + `"message": "Not Found"` | run 없음 **또는** fine-grained 권한 범위 밖 | 레포 접근 권한 확인 |
| `200` + `"head_sha"` 가 보인다 | 토큰 멀쩡 | 🔴 원인이 딴 곳 — 재게시로 가른다 |
| ① 실패 + ② `connect=200` | 토큰·권한 문제 | 위 표대로 |
| ① 실패 + ② **연결 실패** | **NCP → `api.github.com` egress 차단** | 방화벽 (🔴 #29 사전 승인) |

🔴 **PM 오류 1건 추가** — 진단을 올릴 때 **본문을 버리는 형태로 올렸다.** 사장님 손이 **두 번** 갈 수 있었다. 🟢 **지침: 진단 한 줄을 올릴 때는 「그 출력으로 갈래가 갈리는지」를 먼저 따져본다 — 상태코드만으로 갈리지 않는 것이 있다.**

**기록** PM 브라운킴 | 2026-10-24 §21-6 | 지적 = `hitpan-erp-d3`(사유 1곳 교정) · PM 오류 1건

### 21-7 🟢 진단 보강 — 헤더 **3종 → 5종** (토큰 종류를 모르므로 · 2026-10-24)

`hitpan-erp-d3` 가 **또 맞는 자리를 짚었다**: `x-accepted-github-permissions` 는 **파인그레인드 토큰에서만** 돌아온다. 🔴 **그 토큰이 클래식 PAT 이면 스코프 축이 비어** 「레이트리밋 아님 · SSO 아님」까지만 좁히고 멈춘다 ⇒ 사장님 손이 한 번 더 간다.
🔴 **그 토큰이 어느 종류인지 PM 은 모른다**(NCP 안이고 접속하지 않았다) ⇒ **둘 다 받는다.**

```
# ① 인증 호출 — 상태줄 + 거부 사유 + 가르는 헤더 5종
sudo bash -c 'T=$(tr -d "\r\n" < /var/hitpan/update-keys/github-b4-token); \
  curl -sS -i -H "Accept: application/vnd.github+json" -H "Authorization: Bearer $T" \
    https://api.github.com/repos/gisskso-lab/hitpan-erp/actions/runs/40053009516 \
  | sed -n "1p;/^x-ratelimit-remaining:/Ip;/^x-github-sso:/Ip;/^x-accepted-github-permissions:/Ip;/^x-oauth-scopes:/Ip;/^x-accepted-oauth-scopes:/Ip;/\"message\"/p" \
  | head -10'

# ② 통신 자체 — 인증 없이 (①이 연결 실패일 때 egress 인지 토큰인지 가른다)
curl -sS -o /dev/null -w "connect=%{http_code}\n" https://api.github.com/zen
```

| 추가로 보이는 것 | 뜻 |
|---|---|
| `x-oauth-scopes:` 가 찍힌다 | **클래식 PAT** 이다. 그 줄의 목록에 `repo` 또는 `workflow` 가 없으면 **스코프 부족** |
| `x-accepted-oauth-scopes:` | 이 끝점이 **요구하는** 스코프 — 위와 대조한다 |
| `x-accepted-github-permissions:` 가 찍힌다 | **파인그레인드** 다. `actions:read` 가 요구된다 |
| 🔴 **다섯 줄이 전부 비었다** | 요청이 **GitHub 까지 안 갔다**(프록시가 헤더를 깎았거나 egress 차단) ⇒ ② 로 가른다 |

🟢 **이것으로 403 세 갈래(레이트리밋·SSO·스코프)와 404·401·egress 가 전부 갈린다. 진단은 여기서 멈춘다** — 더 다듬는 것은 사장님 손을 늦추는 것이다.
