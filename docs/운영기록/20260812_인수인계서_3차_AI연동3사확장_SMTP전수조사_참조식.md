## §5. 🔴 함정 — 다음 세션이 밟을 지뢰

> 같은 날 1차 인수인계서 §5(함정 7개)도 **여전히 유효하다.** 아래는 그 위에 **추가**되는 것이다.

### ① 🔴 팩토리를 만들었다고 연결된 게 아니다 — 내가 만든 P0

`AiProviderFactory` 를 만들어 놓고 **실제 대화 경로에 연결하지 않았다.**
팩토리는 [연결 확인] 한 곳에서만 쓰였고, 대화는 여전히 클로드 컬럼을 고정으로 읽었다.
⇒ 고객이 챗GPT 를 골라도 **대화는 클로드로 나가는데 화면은 전부 정상으로 보인다.**

**개발명세서 §2-3 에 *"안 보내면서 성공 반환하는 함정을 만들지 않겠다"* 고 써놓고
정확히 같은 함정을 한 층 위에서 만들었다.**

⇒ **새 부품을 만들면 "어디서 실제로 쓰이나" 를 grep 으로 확인하라.**
참조 0건이면 그건 만든 게 아니라 안 만든 것이다.

### ② 🔴 소스 문자열 검사 시험은 한 줄로 우회된다

①을 잡겠다고 만든 시험이 *"본문에 `_providerFactory.Resolve` 가 있나"* 를 봤다.
검증팀이 **한 줄 덧붙여 통과**시켰다 — P0 가 완전히 되살아난 채 284건 전부 통과:
```csharp
adapter = _providerFactory.Resolve("anthropic");   // ← 검사 문자열은 그대로 남는다
```
⇒ 지금은 **리터럴 금지 + 대입 1회 고정**으로 막았다(알려진 우회 2종).
⇒ **근본은 "실행해서 관찰하는" 시험**이다. `ChatbotService` 가 `IDbConnection` 을 직접 받아
실 DB 없이 못 돌려 이번엔 못 했다 — **다음 차수 과제**.
⇒ 교훈: **게이트를 만들면 "의미가 같은 다른 형태"로도 깨뜨려 봐라.** 원래 형태만 막으면 반쪽이다.

### ③ 커밋 메시지를 here-string 으로 넘기면 제목이 `@` 로 깨진다

`git commit -m @'...'@` → 첫 줄 `@'` 가 제목이 되어 `@ (#123)` 이 된다.
코드·본문은 멀쩡하나 git log 에서 무슨 커밋인지 안 보인다.
⇒ **여러 줄 메시지는 파일로**: `git commit -F <파일>`
⇒ **푸시 전에 반드시** `git log -1 --format="%s"` 로 제목 확인.
⇒ 머지 후엔 보호 브랜치 force 푸시라 못 고친다(사장님 결재로 "그대로 둔다" 종결).

### ④ 제미나이는 틀린 키에 **400** 을 준다 (401 아니다)

3사 실측: 클로드 **401** / 챗GPT **401** / **제미나이 400**.
401·403 만 "키 거부" 로 보면 **제미나이의 틀린 키를 "일시 장애" 로 오판**한다.
⇒ `IsAuthFailure` 에 400 을 포함했다. 트레이드오프와 근거는 개발명세서 §7 참조.

### ⑤ 실패를 성공으로 뭉개면 멀쩡한 키가 죽는다

연결 확인 실패 시 원인 불문 `invalid` 를 적으면, 인터넷이 잠깐 끊긴 사이 누른 고객의
**멀쩡한 키가 죽고 재입력해야 살아난다.** ⇒ 키가 **실제로 거부됐을 때만** 무효 처리.

### ⑥ 도구 함정 (1차 §5-⑥ 재확인 — 오늘도 그대로 당했다)

- **Python 없음** — `python -c` 안 돌아간다. Edit 툴 쓸 것
- **MySQL 한글 별칭 깨짐** — `SELECT ... AS 클로드상태` → 구문 오류. **영문 별칭** 쓸 것
- **`grep -v` 뒤 `$?`** 는 마이그 종료코드가 아니다 — 파이프 마지막 명령 값이다. 오판 주의
