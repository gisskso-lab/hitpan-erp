## 2. 🔴 이 작업의 경계 — 넘으면 반려

> 오더 5·8·9 가 **범위를 잘라낸 지시**다. 다음 사람이 "넣어주면 좋잖아" 하기 가장 쉬운 자리다.

| 하는 것 | 안 하는 것 |
|---|---|
| 있는 문서를 **고른다** | 문서를 **만든다** ❌ |
| 링크 문구를 **보낸다** | 결재를 **상신한다** ❌ |
| 누르면 그 화면으로 **이동한다** | 결재를 **승인·반려한다** ❌ |
| | 금액·날짜를 **입력받는다** ❌ |

⚠️ **8/12 PRD §4-2** *"메신저는 결재 워크플로우의 또 다른 입구"* · *"채팅창으로 작성시 워크플로우 자동추가"*
→ **오늘 오더 8 로 범위가 줄었다.** PRD 폐기가 아니라 **그 조항만 오늘 지시가 덮는다.**

**완성 기준 = 사장님이 직접 쓰신 문구가 화면에 나오고, 눌러서 이동하면 끝.**

## 4. 작업 항목

### [T1] DB — DB-101 (DB 매니저)

| 테이블 | 핵심 |
|---|---|
| `chat_rooms` | `room_type`(`direct`/`dept`/`group`) · `direct_key` UNIQUE(1:1 중복 방지) |
| `chat_room_members` | `employee_id` · **`last_read_at`**(읽음의 근거) · `left_at` |
| `chat_messages` | `body` · `ref_type`/`ref_id`/**`ref_title`** · `deleted_at` |

- 🔴 경로 **`src/HitPan.API/Migrations/SQL/DB-101_chat.sql`** 만 ([[project_migration_real_path]])
- `hitpan_db_clean.sql` 동반 갱신 (헌법 #36)
- `ENGINE=InnoDB` · `utf8mb4_unicode_ci` (헌법 #17)
- 🔴 **읽음 전용 테이블 만들지 않는다** — `last_read_at` 한 컬럼으로 판정(설계서 §7-4)

### [T2] 백엔드 — 방·메시지·읽음 (백엔드 매니저)

- `ChatController` 신설 — 🔴 **Write 전 `ChatbotController` 와 심볼 충돌 grep 필수** ([[feedback_check_before_write]])
- 방 만들기 3종 / 내 방 목록 / 대화 조회 / 보내기 / 읽음 알리기 / 나가기 / 메시지 숨기기
- 🔴 `tenant_id` 는 **JWT 에서만** (헌법 #2)
- 🔴 참여자 후보 = **`employees.user_id IS NOT NULL`** (계정 있는 사원만)

### [T3] 문서 연결 (백엔드 + 보안)

- 첨부 = `ref_type` + `ref_id` + `ref_title` **3개만** 저장. **본문 복사 금지**
- 🔴 **권한은 원본 화면이 판정한다.** 메신저는 길만 놓는다
  - A 가 B 에게 급여명세서를 첨부해도 → B 는 **급여 화면에서 막힌다**(단계8 3갈래 판정 그대로)
- 첨부 대상 = 결재문서 · 휴가 · 경비 · 급여 · 근로계약서 · 업무보고서

### [T4] 실시간 (백엔드)

- 🔴 **새 Hub 만들지 않는다.** 기존 `/hubs/notify` 에 알림 종류만 추가
- 🔴 `INotificationService` **확장하지 않는다** — 기존 시그니처 그대로 (헌법 #12)

### [T5] 🔴 결재 결과 → 신청자에게 **메시지** (백엔드)

> ⚠️ **알림(종)이 아니라 메시지다.** 오더 11 이 범위를 바꿨다 — 대화방에 남고 읽음이 찍힌다.
> 🔴 **알림과 메시지를 둘 다 보내지 않는다.** 같은 소식이 두 번 오면 안 된다.

| 시점 | 받는 사람 | 문구 |
|---|---|---|
| **승인** | 🔴 **최초 발신인(신청자)** | `"연차신청서" 가 승인되었습니다.` |
| **반려** | 🔴 **최초 발신인(신청자)** | `"연차신청서" 가 반려되었습니다.` |
| 상신 | 다음 결재자 | `"연차신청서" 결재 요청이 도착했습니다.` |

+ 모두 아래 줄이 붙는다 → `클릭하시면 연차신청서 결재와 연결됩니다.`

- 어느 방 = **결재자↔신청자 1:1 방** (없으면 그때 연다)
- 보내는 이 = 🔴 **결재한 사람 이름으로** — 봇 이름으로 가리지 않는다
- 딱지 = `chat_messages.msg_kind` → `[결재]` / `[메시지]` (오더 13, 인스타·페북 방식)
- 🔴 **결재 로직 손대지 않는다** — 발송 호출만 **추가** (헌법 #1, PRD §3-2)
- 🔴 **발송 실패가 결재를 막으면 안 된다** — try-catch + `LogWarning` (헌법 #15).
  결재는 됐는데 메시지가 안 갔다고 결재가 취소되면 **더 큰 사고다**

### [T5-2] 🔴 파일 전송 (백엔드 + 보안)

| 항목 | 확정 |
|---|---|
| 한 개 | **20MB** |
| 방 하나 | **500MB** |
| 회사 전체 | **5GB** |
| 보관 | `{데이터폴더}/chat-files/{tenant_id}/{yyyyMM}/{file_id}.{ext}` |
| 실행파일 | **막음** — exe·bat·cmd·com·scr·pif·ps1·vbs·js·jar·msi·dll·hta·reg·lnk |

- 🔴 **조각 업로드 안 만든다** — 사장님 *"통신이 안정적이지 않다면 안되는걸로"*
- 🔴 **확장자만 보지 않는다** — 파일 앞부분(시그니처)도 확인 (`.exe`→`.xlsx` 위장 차단)
- 🔴 **저장 이름 = `file_id`** — 원래 이름 그대로 쓰면 `..\..\` 경로 조작
- 🔴 **테넌트별 폴더 분리** (헌법 #2 를 파일에도)
- 🔴 **내려받기도 방 참여 검사** — 업로드만 막으면 §6-1 이 무너진다
- 🔴 **한도는 설정 테이블** (코드 상수 금지 — 반자동 원칙)
- 🔴 **업무는 안 막힌다** — 파일 한도 초과여도 매입·판매·재고 정상
- ⚠️ **백업 범위에 `chat-files` 폴더 포함** — DB 만 백업하면 파일이 안 따라온다
- ASP.NET Core 기본 요청 한도(30MB)·Kestrel 본문 한도 확인 — 20MB 라 여유 있음

### [T6] 프론트 (프론트 매니저)

- 방 목록 / 대화 / 보내기 / 문서 링크
- 읽음: 1:1 = "읽음" · 부서·단체 = **읽은 사람 수 숫자**(보낸사람 제외)
- 새 대화 = 3갈래를 **한 화면에서** 고름. 부서 0건이면 부서방만 안내 문구
- 🔴 첨부 화면에 **"새로 만들기" 버튼 없음** — 있는 문서 고르기만
- 헌법 #14 `.razor` raw string 금지
