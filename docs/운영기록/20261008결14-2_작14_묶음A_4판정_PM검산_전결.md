## §3 🚨 V-1 재판정 — 최악 시나리오는 실측으로 기각 · 그러나 실물 체인이 있다

[4] 의 가설: *"회로 안 이동은 엔드포인트를 다시 타지 않아 잠금 미적용 ⇒ `PlatformOnlyV2` 11건·`OwnerOnly` 6건이 전부 장식"*

### 3-1 구조 전제는 사실 (PM 직접 읽음)

`Components/Routes.razor:8` 은 맨 `RouteView` 다. `AuthorizeRouteView`·`NotAuthorized`·`FallbackPolicy`·`RequireAuthorization` 은
`src/HitPan.Backoffice/` 전체에 **0건**. `App.razor:23` 은 `<Routes @rendermode="InteractiveServer" />` ⇒ 라우터가 회로 안에서 돈다.

### 3-2 🟢 그런데 「전부 장식」은 **거짓이다** — 익명 실측 12경로

로컬 `http://127.0.0.1:5171` 기동 후 PM 이 직접 측정(측정 후 종료 확인 · Listen 0건):

| 경로 | 결과 |
|---|---|
| `/admin/tenants` `/admin/resellers` `/admin/pricing` `/admin/dashboard` `/admin/bo-users` `/owner/permissions` `/admin/promotions` `/admin/cs` `/admin/stats` `/reseller/customers` | **전부 302 → `/backoffice/login?ReturnUrl=…`** |
| `/admin/billing` `/admin/watchdog` `/admin/resellers/issue` `/admin/tenants/issue` `/admin/commission` `/owner/system-config` `/owner/test-flow` `/reseller/revenue` `/reseller/payout` | **전부 302** |
| `/platform/tenants` `/platform/dashboard` (shim) | **302 → `/admin/…`** = 리다이렉트가 **서버에서** 난다 ⇒ 브라우저가 다시 GET ⇒ **그 요청도 엔드포인트 인가를 탄다** |
| `/backoffice/login` | 200 (정상) |

⇒ **엔드포인트 인가는 집행된다.** `@attribute [Authorize(Policy=…)]` 가 장식이 아니다.
⇒ [4] 의 **V-9(shim 이 껍데기를 살린다) 바이패스 경로도 함께 닫혔다** — shim 은 서버 302다.
⇒ 축 4 「미노출 대메뉴 3개 전부 도달」은 **URL 이 살아 있다는 뜻일 뿐, 열린다는 뜻이 아니다.**

### 3-3 🚨 그러나 — 마지막 한 발만 안 잰 실물 체인 (P0 후보 · 선재)

내가 찾은 것이고 [4] 는 못 본 것이다.

```
대리점 계정으로 로그인
  → /admin/dashboard 를 URL 로 연다        ← 이 화면은 @attribute [Authorize] (인증만) 이라 302 가 안 난다
  → 그 화면의 버튼을 누른다                 ← AdminDashboard.razor:25-35 「고객사 관리 (V2)」 버튼
  → OnClick='Nav.NavigateTo("/admin/tenants")'  ← 회로 안 이동 (서버 왕복 없음)
  → AdminTenantsV2 (PlatformOnlyV2) 가 렌더되는가?   ← ⚠️ 여기만 미실측
```

- 링크를 따로 만들 필요가 없다. **그 화면이 자기 버튼으로 본사 화면을 부른다.**
- 자료는 `BoAccessGuard`(deny-by-default)가 따로 막으니 **숫자까지 새는지는 별개** — 그래도 본사 화면 구조가 대리점에 보이면 사고다.
- 🟢 **작14 는 이걸 줄였다** — `/admin/dashboard` 를 사이드바에서 **뺐다**(§4). 늘린 것이 없다.
- ⚠️ **마지막 한 발은 계정 없이 못 잰다**(§7 결재 1건).

**등급 판정**: 지금은 **P0 후보**다. 「P0」이라 적지 않는다 — 마지막 한 발이 미실측이고, 추정을 판정으로 쓰지 않는다(누적 사고).

## §5 OwnerOnly — 두 번째 막다른 길 (선행검증서 보강)

[1-V] 는 사이드바 축만 봤다. 정책 쪽도 막혀 있다.

- `src/HitPan.Backoffice/Program.cs:61-62` `OwnerOnly` = `RequireClaim("role", "owner")`
- 쿠키의 `role` 클레임은 DB 원값이다 — `Controllers/BackofficeAuthController.cs:68`(본사) · `:87`(대리점) — 둘 다 DB 원값을 그대로 쿠키에 넣는다
- `platform_admins.role` enum = `super_admin·billing_admin·cs_admin·readonly` ⇒ **`"owner"` 는 없다**

⇒ **`OwnerOnly` 도 어떤 로그인으로도 통과 못 한다.** 사이드바만 고치면(갈래 ⓒ) 메뉴는 보이고 **누르면 로그인 화면으로 튕긴다**
(`Program.cs:47` `AccessDeniedPath="/backoffice/login"` — [4] V-11 이 맞다).

⇒ **OWNER 트랙은 두 축을 같이 고쳐야 한다**: 사이드바 판정축 + `OwnerOnly` 정책을 `role` 4값 체계에 맞추기.
⇒ 🟢 **[1-V] 갈래 ⓒ 는 유효하나 단독으로는 불충분**하다. 선행검증서에 반영한다.

### 로컬 DB 실측 (운영 아님)
`hitpan_backoffice.platform_admins` = **2행 · 둘 다 `super_admin`**. ⇒ 갈래 ⓒ 를 넣으면 **로컬 본사 계정 전원**이 Owner 6줄을 본다.
운영(NCP) 분포는 여전히 **못 잼**(#39 운영=읽기만).
⚠️ 추가 발견: 로컬 `hitpan_backoffice` 에 **`reseller_accounts` 테이블이 없다**. 출하 DDL `installer/backoffice/00_backoffice_core.sql:173` 에는 있다
⇒ **제품 구멍 아님 · 로컬 DB 가 낡았을 뿐**. 그래서 대리점 로그인 실측이 로컬에서 원천 불가였다(인계2 §5 의 「0건」보다 한 겹 더 나쁜 이유).
