## §1 사실 (PM 이 직접 확인 — 파일:줄)

### ⓐ `api/admin/devices` — 임의 고객사 기기 조회 + 임의 기기 차단
`src/HitPan.Backoffice.API/Controllers/DeviceRegistrationController.cs:318-321`
```
// 본사 기기 관리 API
[ApiController] [Route("api/admin/devices")] [AllowAnonymous]
public class DevicesAdminController
```
- `GET tenant/{tenantId}` (`:333`) — **아무 토큰 없이** 임의 고객사의 기기 목록(기기 지문 `fingerprint` · OS 정보 · 등록·접속 시각)을 돌려준다.
- `POST {deviceId}/revoke` (`:358`) — **아무 토큰 없이** 임의 기기를 차단한다 ⇒ **그 고객이 ERP 를 못 쓴다**(서비스 거부).

### ⓑ `api/admin/serial-locks` — 시리얼 무차별 대입 방어선 무력화
`src/HitPan.Backoffice.API/Controllers/SerialVerifyController.cs:267-270`
```
// 본사 잠금 해제 API (super_admin 권한)      ← 주석은 권한을 말하는데
[ApiController] [Route("api/admin/serial-locks")] [AllowAnonymous]   ← 다음 줄이 익명이다
public class SerialLocksAdminController
```
- `GET` (`:282`) — 잠금 목록(클라이언트 지문·실패 횟수) 익명 조회.
- `POST {lockId}/unlock` (`:307`) — **익명으로 잠금 해제.** 시리얼 오입력 잠금(F-11 속도 제한)이 **잠기면 풀고 다시 시도**가 가능해져, **라이선스 키 무차별 대입 방어선이 사실상 없다.**

### 왜 못 잡았나
**주석이 「super_admin 권한」이라 적혀 있다.** 코드를 안 읽고 주석을 읽으면 막혀 있다고 믿는다 — 「주석은 코드가 아니다」의 교과서 사례(`feedback_easy_claim_needs_refutation`). 게이트도 못 잡았다: CI 의 「권한 메뉴 정합」 게이트는 **ERP 전용**이고 백오피스를 보지 않는다(선행검증 §2-5).

### ⚠️ 미확인 — 외부 도달 가능성
코드가 익명인 것은 **확정**이다. 다만 `back.hitpan.kr` 앞단(nginx·방화벽)이 `/api/admin/*` 을 막고 있는지는 **재지 못했다**(#39 운영 무접촉 · NCP 접속은 분류기 차단). 앞단이 막고 있어도 **코드가 유일한 방어선이 아니어야 한다** — 앞단 설정은 한 번의 실수로 열린다. 봉합은 코드에서 한다.

## §2 봉합 설계 (PM 초안 — CTO·보안상무 결재 대상)

| # | 할 일 | 완료 기준(실동작) |
|---|---|---|
| 1 | 두 컨트롤러의 `[AllowAnonymous]` 제거 → **본사 관리자만** 통과하는 속성으로 교체 | 토큰 없는 요청이 **401** · 대리점 토큰이 **403** · 본사 관리자 토큰이 **200** — 세 경우 전부 실측 |
| 2 | **같은 모양이 또 있는지 전수** — 백오피스 API 의 `[AllowAnonymous]` 전건을 세고, 각각 「익명이어야 하는 이유」를 한 줄로 적는다. 이유를 못 쓰는 것은 봉합 대상 | 백오피스 `[AllowAnonymous]` 목록 + 사유 표 · 사유 없는 것 0건 |
| 3 | 게이트 신설 — **익명으로 열린 관리 API 가 생기면 빨간불** | 봉합 전 FAIL 재현(속성 되돌리면 게이트가 빨간불) → 봉합 후 PASS · 음성 대조군(정상 익명 경로 = 로그인·가입·설치 토큰 검증은 계속 PASS) |

🚫 **하지 않는 것**: 역할 enum 4값 전환(작10 ①사이클) · 행 범위 강제(작10) · 앞단 nginx 설정(#29 인프라 사전 승인) · 정상 익명 경로(로그인·랜딩 가입·설치 부트스트랩) 건드리기.

## §3 작10 과의 관계
작10 ①사이클의 C-6 질문(「익명 API 4 + 무가드 화면 8 을 ①사이클에 넣나」)에서 **익명 API 만 떼어 이 트랙으로** 옮긴다. 이유: ①사이클은 역할 체계를 **바꾸는** 일이라 설계 확정(C-1~C-10)과 사장님 결재가 필요한데, 익명 노출은 **설계 질문이 아니라 사고**다. 기다릴 이유가 없다. 무가드 화면 8개는 역할 판정과 묶여 있어 작10 에 남긴다.
