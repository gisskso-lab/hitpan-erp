## 2. 🔴🔴 [1-V] 선행검증이 「오더 밖」의 P0 를 찾아냈다

`TaxInvoiceService.CancelAsync` 가 **발행이 만들지도 않은 분개를 되돌리고** 있었다.

| 시점 | 기표 |
|---|---|
| 거래명세서 확정 (`SalesService:581`) | 🟢 있다 |
| 계산서 발행 (`IssueAsync`) | 🔴 **0건** |
| 계산서 취소 | 🔴 **역분개 1건** |

**실측**: 계산서를 취소하면 **외상매출금 0 / 매출 0 / 부가세예수금 0.**
명세서는 `confirmed` 이고 재고도 나갔는데 **장부에서 매출만 사라진다.**
⇒ 재고↔회계 분리(헌법 #20) + 부가세 **과소**신고. `FinanceService` 에 `sales_cancel` 0건이라 정합성 검사도 못 잡았다.

**원인은 주석을 믿은 것** — 주석이 *"IssueAsync 기표의 반전"* 이라 했으나 그 메서드에 기표가 없다.

🟢 **[1-V] 가 없었으면 마이너스 계산서가 이 사고 위에 올라탔다.**
