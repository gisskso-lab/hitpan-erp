## 1. 절 나누기 — 순서를 지킨다

```
절A  P1  서버 — MainPcProofService + API 3개          (화면 무변경 · 무영향)
절B  P2  CSP 한 줄 + 브라우저 JS                      (왕복이 실제로 도는가)
절C  P3  [메인PC 등록] 팝업                            (최초 1회 · 키 생성 + 봉인 + 등록)
절D  P4  MainPcOnly 두 곳에 갈래 추가                  (자료관리가 열린다)
절E  P5  DeviceAuthGate 자칭 경로 차단                 (결함 봉합)
절F  P6  [메인PC 연결] — 변경·되돌리기                 (새 컴퓨터로 이전)
```

🔴 **절A → 절B 는 순서를 못 바꾼다.** 절B 가 절A 의 API 를 부른다.
🔴 **절C 는 절A·절B 가 돌아야 성립한다** — 팝업이 누르는 것이 곧 왕복의 첫 바퀴다.
🔴 **절D 를 절C 보다 먼저 하면 안 된다** — 등록되지 않은 상태에서 자료관리 판정만 바뀌면
   메인PC 도 클라이언트도 아닌 상태가 생긴다.

## 2. 절A (P1) — 서버

### 만든다

**`src/HitPan.Infrastructure/Services/MainPcProofService.cs`** (신규)

| 기능 | 내용 |
|---|---|

⚠️ 표는 **쓰는 즉시 버린다**(1회용). 만료된 표도 주기적으로 버린다.

**`src/HitPan.API/Controllers/DeviceController.cs`** 에 3개 추가 (기존 코드 무변경 · 추가만)

## 4. 절C (P3) — [메인PC 등록] 팝업

> 사장님: *"최초 로그인후 메인PC등록을 먼저 해"* · *"다음 접속부터는 팝업이 안보이고 바로 접속"*

### 동작 (설계 §3-4)

```
로그인 직후 — 화면 뒤에서 조용히 확인
  ├ 이미 메인PC 등록됨(is_main_pc=1 존재)  → 팝업 없음. 바로 들어간다
  ├ 미등록 + 왕복 성공                      → 🔵 [메인PC 등록] 팝업 1회
  └ 미등록 + 왕복 실패                      → 팝업 없음. 바로 들어간다
```

🔴 **클라이언트 PC 에서는 팝업이 절대 안 뜬다** (사장님 재확인). 누르고 실패하는 경험조차 만들지 않는다.
🔴 팝업 대상은 **부모계정만** (D-8 기본값 · 사장님 한 줄이면 바꾼다).

### [등록] 을 누르면

```
① MAINPC_PROOF_KEY 생성 (랜덤)
② TpmKeyService.SealKey() 로 봉인 → 저장          ← 🔴 그 PC 에서만 풀린다
③ tenant_devices 에 메인PC 등록 (is_main_pc=1)
④ 팝업 닫고 그대로 진행
```

⚠️ **이미 `is_main_pc=1` 줄이 있으면 새 줄을 만들지 않는다.** 그 줄을 쓴다
   (9/13 사장님 실측: `is_main_pc=1` 이 2줄이 된 사고 계통).
⚠️ 키가 이미 있으면 **덮어쓰지 않는다** (#1).

### 문구 — 고객이 읽는 말이다

- 🚫 "인증키", "왕복", "루프백", "HMAC", "토큰" 같은 개발 용어 금지
- 🟢 *"이 컴퓨터를 회사 자료가 들어 있는 컴퓨터로 등록합니다"* 같은 말로
- ⚠️ 문구 최종안은 **사장님 확인**을 받는다

## 6-2. 절F (P6) — [메인PC 연결] · 변경 · 되돌리기

> 사장님: *"되돌리는 기능도 있어야됨. 고객사가 컴퓨터를 새로 구입해서 메인PC를 변경할수도 있으니까"*
> *"메인pc연결 → 변경하실 메인PC에 히트판이 설치되어 있습니까 (y/n) / y : 자동연결 / n : 설치후 연결"*

🔴 **이 절을 빼고 내보내면 안 된다.** 없으면 고객이 컴퓨터를 바꾸는 순간
**메인PC 를 영영 못 옮긴다** — 옛 등록이 남아 팝업이 안 뜨기 때문이다.

### ① 자동 감지 — 히트판이 스스로 안다

```
새 PC 에서 로그인 → 왕복 성공(본체가 여기 있다) → 그런데 봉인이 안 풀린다
   → 🔵 "메인PC 를 이 컴퓨터로 변경하시겠습니까?" (부모계정)
   → [예] → 새 키 생성·봉인 → 🔴 기존 줄을 **갱신** (새 줄 만들지 마라)
```

⚠️ 봉인 확인은 `TpmKeyService.IsSealedKeyValid()` 를 쓴다 — **이미 그 용도로 있다.**
🔴 **새 줄을 만들면 `is_main_pc=1` 이 2줄이 된다** — 9/13 사장님 실측 사고와 같은 자리다 (G-15).
🟢 옛 PC 가 **꺼져 있어도 된다.** 새 PC 가 스스로 증명한다 (G-16).

### ② 고객 입구 — [메인PC 연결]

```
[메인PC 연결]  (설정 · 부모계정)
   ↓
"변경하실 메인PC에 히트판이 설치되어 있습니까?"
   ├─ [예]     → "그 컴퓨터에서 히트판에 접속하시면 자동으로 연결됩니다"
   └─ [아니요] → 🔴 랜딩페이지 다운로드로 보낸다 → 설치 → 접속하면 ①이 돈다
```

🔴 **ERP 가 설치본을 들고 있지 않는다.** 랜딩으로 보내기만 한다(3시스템 분리 · 랜딩 = 다운로드).
🔴 **브라우저는 받은 프로그램을 자동 실행할 수 없다**(Windows 차단 · 우회 금지).
   *"받은 파일을 한 번 눌러 주세요"* 를 정직하게 안내한다. 🚫 자동 실행 흉내 내지 마라.
⚠️ 어느 갈래로 가도 **갈 곳을 준다.** *"관리자에게 문의하세요"* 로 끝내지 마라 (#20 · G-21).

### ③ 빈 DB 면 복구를 안내한다

신규 설치 직후 등록이 끝났는데 DB 가 비어 있으면:

> 🔵 *"기존에 쓰시던 자료가 있으면 [자료관리 → 자료복구] 에서 가져오세요"*

⚠️ 자료 이전은 **기존 자료관리(백업/복구)가 한다.** 🚫 새로 만들지 마라 (사장님 결재).
⚠️ 이 안내가 없으면 고객은 **빈 화면을 보고 자료가 날아간 줄 안다.**

### ④ 🔴 팝업이 두 번 뜨는 것은 정상이다 — 없애지 마라

```
① 새 PC 설치(빈 DB) → ② [메인PC 등록] 팝업 ← 1회차
→ ③ 자료복구 → ④ 복원이 옛 DB 를 덮어써 옛 등록이 되살아난다
→ ⑤ 봉인 불일치 → [메인PC 변경] 팝업 ← 2회차 → 재등록
```

⚠️ ④는 버그가 아니라 **복원의 정의**다. ⑤가 그걸 받아 정리한다.
🚫 *"왜 두 번 뜨지?"* 하고 ⑤를 없애면 **자동 감지가 통째로 죽는다.** 주석에 이 이유를 남겨라.
