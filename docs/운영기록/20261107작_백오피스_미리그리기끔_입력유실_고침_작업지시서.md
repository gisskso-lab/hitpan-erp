## §16 [4] 2회차 🟢 조건부 · [3-V] 2회차 🟢 조건부 뒤 처리 — PM 결재 (11/8)
> 근거 = [작업리뷰서 2회차](../검증/백오피스/20261107_작업리뷰서_백오피스F6_미리그리기끔.md) 「2회차」 절 · [보안상무 [3-V] 2회차](../검증/병렬이슈/20261107_3V_백오피스F6_미리그리기끔_보안상무.md) 「2회차」 절. H7 값 유실 0/90 · 초점 끌림 0/90 · C1 운영 꼴 콘솔 스택 0 · H1 0/360 · 종료 경계 옛/새 장치 판정 바뀐 칸 0.

### 조건 1건 — 「없는 주소 → 정상 화면」 뒤 h1 초점 빠짐: 받아들이지 않고 고친다
- **무엇**: 회로 안에서 없는 주소로 갔다가(NotFound) 정상 화면으로 돌아오면 고친 꼴은 초점이 BODY · Tab 이 메뉴 첫 링크부터(12/12). 원본은 h1 · Tab 이 본문 첫 칸. [3-V] 가장자리 A(없는 주소를 **전체 로드**한 뒤 메뉴로 정상 화면) 도 같은 뿌리(추정 · 이번에 잰다). 오타 주소 · 옛 즐겨찾기로 닿는다.
- **PM 원문 대조(받아쓰기 아님)**: `Routes.razor` 의 `<NotFound>` 가 그려지는 동안 `<Found>` 안의 `FocusOnNavigateAfterFirst` 는 사라진다 → 정상 화면으로 돌아오면 **새 인스턴스**로 다시 만들어짐 → 필드 `_seenFirstRender` 가 false 로 시작 → 그 렌더를 「회로 첫 렌더」 로 잘못 보고 초점을 안 옮긴다.
- **근본원인**: 「회로의 첫 렌더인가」 는 **회로 단위 사실**인데 이를 **구성요소 인스턴스 필드**에 담았다(인스턴스 수명 ≠ 회로 수명). [3] 2회차 설계(§15 · PM 결재) 가 「Router 가 매 이동마다 같은 인스턴스를 다시 그린다」 만 보고 NotFound 가 인스턴스를 지우는 갈래를 안 셌다. [3-V] 2회차가 이를 「P3 기록」 으로 내놨고 [4] 2회차가 실측으로 확인.
- **판단**: 접근성(화면읽기 사용자에게 새 화면 알림) 후퇴를 「가장자리」 로 남기지 않는다. 고칠 자리가 F6 이 새로 만든 구성요소 안이라 범위가 닫혀 있다.

### 봉합 방향 (PM 결재 · [3] 3회차)
- 「회로 안에서 화면 이동이 한 번이라도 있었나」 를 **회로 수명 자리**에 둔다 — `Routes.razor`(Router 바깥 · 회로마다 하나 · NotFound 에도 살아 있음) 가 `NavigationManager.LocationChanged` 로 기록하고, 감싼 구성요소에 매개변수로 넘긴다(DI 등록 0 선호). 구독은 `Routes.razor` 가 하고 `Dispose` 에서 해제한다.
- 감싼 구성요소의 동작(기대값):
  - (가) 이동 전(회로 첫 렌더 · 전체 문서 로드 직후) → `FocusOnNavigate` 를 안 그린다(H7 막기 그대로).
  - (나) 이동이 있었고 **이 인스턴스가 처음 매개변수를 받는 중**(= NotFound 뒤 다시 생김 · 또는 없는 주소 전체 로드 뒤 처음 정상 화면) → 바로 그린다(원본도 이때 새 인스턴스라 초점을 옮긴다).
  - (다) 이동이 있었고 PageType 이 바뀜 → 그린다(2회차와 같음). 같은 PageType 질의만 바뀜 → 안 그림(원본과 같음).
- [3] 은 프레임워크 원문으로 **구독 순서**(Routes 의 LocationChanged 처리가 Router 의 다시 그리기보다 먼저 도는가)를 확인하고, 순서가 보장 안 되면 다른 회로 수명 자리(범위 서비스 등)를 고르되 위 세 동작을 지킨다. 고른 방식과 근거를 개발명세서에 적는다.
- 고칠 파일 = `Routes.razor` · `FocusOnNavigateAfterFirst.razor`(필요하면 상태 담는 작은 클래스 1) — 그 밖 diff 0 · 옛 줄 주석 보존(#1).
