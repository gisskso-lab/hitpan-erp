## 1. 오더를 이렇게 이해했다 (명문화)

- **사장님 의중**: 메인PC 앞에서 자료관리(찾아보기·모두 지우고 새로 가져오기·초기화·백업복원)에 **들어갈 수 있어야** 마이그 실측이 된다. 그 「메인PC 인가」를 **확실하게** 가려야 한다 — 바깥·사내 다른 PC 에서는 안 열려야 한다.
- **확정된 방법** (회의록 §7-0): 메인PC 는 **그 컴퓨터 안에서 `http://127.0.0.1:{포트}` 로 직접 연 창**으로만 증명한다. 1차 = 그 창에서 **첫 세션부터** 자료관리가 열리고, 그 창이 **새 줄 없이** 메인 줄에 합류.
- 🔴 **1차로 약속하지 않는 것**: 도메인 탭까지 한 줄로 합치는 사장님 「2중」 완전 해소 = 2차 2-C (회의록 §7-0 · §7-6 1번). 게시노트·보고에 그대로 적는다.
- **안 하면**: 사장님 자료관리 양쪽 막힘 지속(인계3 §2) · 사내 PC 가 Host 를 위조하면 자료관리 판정이 참인 현행 구멍 존속(회의록 §4-1 P0 · §7-1 #2).
- **실측 근거** (헌법 #32):

| 사실 | 근거 |
|---|---|
| 도메인 = 문 B(자리) 거짓 · localhost 첫 로그인 = 문 A(기기) 403 | [선행검증서](../검증/선행/20260910_선행검증서_메인PC_식별등록_전제실측.md) §3 · [개발 브리핑](../개발/erp/20260910_개발브리핑_메인PC_판정코드전수_구현타당성.md) §2-2 |
| 5234 프록시에 Host 위조 → 301 없이 200 | 개발 실측 (회의록 §2-2 · §2-0 ③″) |
| 같은 브라우저면 주소가 달라도 지문 동일(`HFPv2-b2e88f45` ×4) ⇒ 127 창이 도메인 줄에 붙는다 | 검증 격리 실측 (회의록 §7-1 #6) |
| API 모든 출처 + 자격증명 허용 ⇒ 교차사이트 거부 필요 | `src/HitPan.API/Program.cs:396-405` |
| ⬜ 운영 DB `tenant_devices` 줄 상태 | `db.conf` 권한 거부 — 게시 전 필수 ① (§6) |

| `BuildLocalConsoleUrl` | `IServer` 의 `IServerAddressesFeature` 주소 중 호스트가 loopback·`0.0.0.0`·`+`·`*` 인 것의 포트 → `http://127.0.0.1:{포트}` · 없으면 `Connection.LocalPort`(>0) · 둘 다 없으면 `null` · 슬롯2 이상 정확성은 보증하지 않는다(§2) |

### 8-2. 조건 (착수 조건 — 빠지면 [4] 반려)

- **C-1 (S) 네 번째 복사본을 없앤다** — `AuthController.cs:136-140` 의 `IsLocalConsole` 채움은 옛 판정(터널헤더 0 ∧ loopback)의 **복사본**이고, 그 판정은 Host 위조로 참이 된다. S-5 의 「남긴다」 대신 **`Login` 안에서 `MainPcSeat.Evaluate` 를 한 번 부르고 그 결과로 `IsLocalConsole`·`IsDirectConsoleOwner` 를 함께 채운다.** 속성은 남긴다(읽는 곳 0 · 주석). 계약 7 「`Login` 1곳」은 그대로. 근거: §6-1 조건 1 「복사본은 위임」 — 죽은 복사본은 다음 사람이 다시 읽는다.
- **C-2 (S·G) 서버 전용 칸 잠금** — `RegisterDeviceRequest.IsDirectConsoleOwner`·`MainPcJoin` 에 `[JsonIgnore]`(`LoginResponse.MainPcJoin` 에는 달지 않는다). G 게이트: **컨트롤러 액션 파라미터에 `RegisterDeviceRequest` 형 0** — 폐기되는 GC44(「요청에서 읽지 않는다」)의 후속.
- **C-3 (W) 합류 번호를 버리지 않는다** — `Web/Services/AuthService.cs:127-135` 의 `keepIdentity` 는 보관 열쇠가 있으면 서버가 준 번호를 버린다 ⇒ 127 창에 옛 신분이 남아 있으면 **J 가 합류시켜도 창은 옛 줄로 남는다.** `mainPcJoin == "joined"` 이면 `keepIdentity` 와 무관하게 받은 번호를 보관한다. 보관 열쇠를 둘지 지울지는 W 가 정하고 명세서에 근거를 적는다.
- **C-4 (PM 판정 — 설계팀장 질의) `device_login_logs` 1행 허용** — 주심 문장 「쓰기는 `last_seen_at` 만」은 `tenant_devices` 의 **신분 칸**(표식·상태·열쇠·이름·종류·다른 줄) 불변이라는 뜻이다(§6-1 F-1). 로그인 이력은 종전 갱신 경로(`TenantDeviceService.cs:581`)와 같게 남겨야 감사가 끊기지 않는다. G-2 는 **`tenant_devices` 전 줄 불변(메인 줄 `last_seen_at` 만 예외) + `device_login_logs` 정확히 +1** 을 값으로 단언한다. [3-V] 가 반대하면 뺀다.
- **C-5 (S) 127 주소의 출처** — `BuildLocalConsoleUrl` 은 **요청 Host 로 만들지 않는다**(터널 요청의 Host 는 바깥 값). `http` 주소만 쓰고, 호스트 목록에 `localhost` 를 넣는다.
- **C-6 (S) P 대조** — `user_id`·`tenant_id` 는 JWT 클레임에서만(#2). 초기화 대조와 **한 메서드를 함께 쓰는 것이 기본**이고, 계층 때문에 복사하면 명세서에 사유를 적고 G-7 이 두 경로를 모두 값으로 잰다. 필터(K1)가 비밀번호보다 먼저다 — **원격 + 틀린 비번 = 403 `main_pc_only`**(400 아님).
- **C-7 (G) G-1 방법** — TestServer 는 `RemoteIpAddress=null`·`LocalPort=0` 이 기본이다 ⇒ `TestServer.SendAsync(ctx => …)` 로 연결 값을 넣는다. 거부 7종은 **양성 대비 한 칸만 바꾼다**(한 변수 대조). 실제 `Program` 이 DB 없이 안 서면 **축소 호스트로 바꾸기 전에 PM 보고**(말없이 바꾸면 파이프라인 시험이 아니다). 시험 환경 이름과 운영 전용 미들웨어(`UseHttpsRedirection` 등) 차이를 명세서에 적는다.
- **C-8 ([3-V]·[4]) 반증 항목 추가**
  - ⓐ 대표가 합류한 **같은 127 창에 직원이 로그인**하면 보관된 메인 줄 번호로 통행하나 — 1.2.89 합류 도메인 탭과 같은 계통. 막는 수정은 2차 「번호만 통행 폐지」 몫이고, 1차는 §7-6 2번 「남는 위험」에 명기. AC-20 은 **빈 127 창** 기준으로 판정한다.

  - ⓒ 원격 + 틀린 비번 복원 = 403.
  - ⓓ 127 창 응답이 https 로 돌려보내지지 않나(8-1 🟡).
- **C-9 (공통) 실물 무접촉** — 이 PC 의 `127.0.0.1:5257` 과 3306 운영 DB(`hitpan_erp_t004`)는 **실물 설치본**이다. 개발·게이트·검증 어느 갈래도 요청·접속 0. 시험은 TestServer(메모리)·CI db-gate·격리 환경만. 로컬 DB 게이트 실행은 PM 확인 전 금지.
