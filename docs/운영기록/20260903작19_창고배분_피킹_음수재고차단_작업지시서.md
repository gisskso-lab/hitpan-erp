### 🟡 W0. 배분 규칙 결재 — **사장님만 정할 수 있다** (착수 차단 항목)

두 창고에 나뉘어 있을 때 어디서 먼저 빼는가:

| 후보 | 규칙 | 비고 |
|---|---|---|
| ① | 지정 창고에서 있는 만큼 → 부족분을 다른 창고에서 | 화면이 고른 창고를 최대한 존중 |

| ④ | 창고 코드 순 (MAIN 우선) | 현행 폴백과 같은 순서 |

🔴 **PM 이 정하면 받아쓰기다.** 현장에서 어느 창고부터 꺼내는지는 사장님 정보다.

### W2. DDL — 원장 UNIQUE 키에 창고 추가

**담당**: DB 개발자 1명 (🔴 **DB 매니저 감수 필수**)

```sql
-- DB-117
ALTER TABLE stock_ledger
  DROP INDEX uq_stock_ledger_source,
  ADD UNIQUE KEY uq_stock_ledger_source
      (tenant_id, source_type, source_id, item_id, move_type, warehouse_id);
```
- [x] 🔴 **마이그 멱등성 반증** (헌법 #26) — 🟢 **실측 완료 (2026-09-03)**
      실제 MariaDB(`hitpan_e2e`)에 옛 키로 씨앗을 깔고 DB-117 을 **두 번** 돌렸다:
      · 충돌 행 **0** · `INSERT IGNORE` 재실행 후 행수 **2 유지 · 중복 0**
      · 최종 인덱스 = 6컬럼(`…,move_type,warehouse_id`) — 두 번 돌려도 같은 상태
      🟢 **안전장치가 세 겹이다**:
        ① `MigrationRunner:92` 가 `success=1` 인 마이그를 조회해 **재실행 자체를 건너뛴다**
        ② 마이그는 창고를 `wh-migration` 하나로 고정(`MdbMigrationService.cs:226`)
           ⇒ 키에 창고가 붙어도 값이 같아 `INSERT IGNORE` 가 그대로 듣는다
        ③ 신규 설치는 출하 DDL 시드에 `DB-117` 이 있어 **애초에 안 돈다**
- [x] 출하 DDL(`installer/hitpan_db_clean.sql`) 동시 갱신 (헌법 #36 — 신규설치 단일 진실원)
      🔴 시드 등록을 **빠뜨렸다가 `MigrationLocationGuardTests` 에 잡혔다.**
         빠졌으면 신규 고객이 이미 반영된 마이그를 다시 돌 뻔했다.
- [x] 🔴 **기존 행 충돌 확인** — 🟢 실측 **충돌 0**
      (키가 넓어지므로 원리상 안 나지만, *"원리상"* 은 실측이 아니라서 쟀다)
