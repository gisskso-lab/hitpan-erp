### 사고 타임라인
1. 사장님: "대시보드·메뉴가 이전 버전 같다" → PM 조사

   - Web만 최신화 → API·DB·키는 옛 버전이라 안 맞음

   - 환경변수 키 ≠ 진짜 키(hitpan-keys.conf) → 복호화 500
   - 한글 경로 깨짐으로 스크립트 4~5회 실패
   - DB 초기화 후 시드값 enum 불일치(role·emp_type) → 로그인 막힘
   - **결국 "고치려다 더 망가지고, 망가진 걸 또 고치는" 두더지잡기 반복**

### 근본 원인 한 줄

## 3. 재발방지 대책 (구조적 차단)

### 대책 1 — 운영(demo)과 검증을 물리 분리 (★최우선)
- **검증은 절대 demo(운영)에서 안 한다.** 별도 테스트 환경(`hitpan_e2e` DB + 테스트 포트 5300)에서만.
- demo는 "사장님이 보는 운영"이므로 **읽기 외 손대기 금지**. 바꿔야 하면 반드시 작업지시서+결재.
- 이미 SOP에 있던 원칙인데 오늘 PM이 어겼다. **"운영 환경 직접 수술 = 즉시 중단" 을 PM 행동수칙 1번으로.**

### 대책 2 — demo 배포는 "원클릭 정합 스크립트" 하나로 (수동 즉흥 금지)
오늘처럼 Web/API/DB/키를 따로 건드리지 않게, **한 번에 정합 맞춰 배포하는 스크립트**를 만들어 둔다:
- `deploy-demo.ps1` (관리자 1회 실행): 최신 Web publish + 최신 API publish + 키·DB conf 자동 정합 + Web(5234)·API(5257) 동시 재기동 + 헬스체크(로그인·캘린더·/me 전부 200 확인까지)
- **버전 정합 보장**: Web과 API를 항상 같은 커밋에서 같이 빌드 (한쪽만 옛 버전 = 오늘 캘린더 사고 원천 차단)
- 한글 경로 문제 차단: 모든 산출물을 ASCII 경로(`C:\HitPanDeploy\`)에 둠
- 키 출처 단일화: hitpan-keys.conf 하나만 진실원 (db.conf 즉석 생성 금지)

### 대책 3 — 배포 전 "정합 게이트" (스모크) 통과 의무
배포 스크립트가 끝에 **자동 검증**을 돌려, 하나라도 실패하면 **이전 버전으로 자동 롤백**:
- 로그인 200 / `/me` 200(복호화) / 캘린더 JSON / 대시보드 200 / 재고·매입·판매 핵심 1개씩
- 통과 못 하면 배포 실패 처리 + 백업본 자동 복원 → **"망가진 채 방치" 차단**

### 대책 4 — 손대기 전 백업 강제
- 운영 DB·설치본 건드리기 전 **자동 백업** (오늘 458MB 백업은 떴으나 수동이었음)
- 배포 스크립트에 백업을 1단계로 내장 → 실패 시 즉시 복원

### 대책 5 — PM 행동수칙 (헌법 정합)
1. **운영(demo) 환경은 읽기만.** 변경은 작업지시서+CTO결재+사장님 승인 후에만 (헌법 #29·#33).
2. **"빨리 끝내려고" 결재 우회 금지.** 빠른 게 아니라 안전한 게 우선 (오늘 정반대로 했다).
3. **검증은 테스트 환경에서.** 운영에서 검증하다 운영 깨뜨리지 않는다.
4. **즉흥 스크립트 금지.** 배포는 검증된 `deploy-demo.ps1` 하나로만.
