### 3-2 C# 규칙 — 상속 클래스가 다시 구현하면 새 구현이 불린다
- C# 명세 「인터페이스 재구현(interface re-implementation)」: 인터페이스 구현을 물려받은 클래스가 **기반 목록에 그 인터페이스를 다시 적으면** 그 클래스의 인터페이스 대응표를 새로 만든다 → `class CsStatusMenu : MudMenu, IHandleEvent` + 명시 구현 `Task IHandleEvent.HandleEventAsync(...)` 이면, 실행 형식이 `CsStatusMenu` 인 객체를 `IHandleEvent` 로 부를 때 새 구현이 불린다. 기반의 명시 구현은 private 이라 `base.` 로 부를 수 없다 → **몸통을 옮겨 쓴다**(3-4).
- 인터페이스 선언 원문(`release/8.0` `IHandleEvent.cs`): `Task HandleEventAsync(EventCallbackWorkItem item, object? arg);` → 매개변수 이름은 `item` 으로 맞춘다.

### 3-3 렌더러가 이 메뉴의 이벤트를 어디로 보내나
- `EventCallbackFactory.cs`(`release/8.0`) `CreateCore` = `new EventCallback<TValue>(callback?.Target as IHandleEvent ?? receiver as IHandleEvent, callback)` — 받는 쪽 = **대리자의 대상**(`HandleKeyDownAsync` 등 인스턴스 메서드 → 메뉴 객체 자신 · 실행 형식 `CsStatusMenu`).
- `EventCallback.cs` `InvokeAsync(object? arg)` = `Receiver.HandleEventAsync(new EventCallbackWorkItem(Delegate), arg)` · `Receiver` 형식 `IHandleEvent?` → 인터페이스 호출 → 3-2 규칙으로 **새 구현**.
- 지나가는 것 = 대리자 대상이 메뉴인 모든 콜백: 바깥 div 포인터 들어옴/나감 · 오른쪽 클릭 · `TrackKeyboardInteraction`(razor L8~13) · 단추 `OnClick=ToggleMenuAsync`(L62 · `MudButton` 이 부름) · 래퍼 `HandleKeyDownAsync` · 포인터(L112~114) · 오버레이 `OnClosed=CloseMenuAsync`(L128). **안 지나는 것** = 칸이 만든 콜백(항목 `OnClick` 람다 · `MenuOpenChangedNoRender`(받는 쪽 null) · 칸 `@onkeydown`) — 대리자 대상이 칸이라 칸의 입구로 간다.

### 3-4 base 동작 보존 — 옮겨 쓰는 꼴
- `ComponentBase` 원문(`release/8.0` · 요약 도구로 읽어 글자 인용은 짧은 조각만 · 줄 번호 근사): `var task = callback.InvokeAsync(arg);` → 끝났나(`RanToCompletion` · `Canceled` 아님) 판단 → `StateHasChanged();`(이벤트마다 동기로 다시 그림) → 안 끝났으면 `CallStateHasChangedOnAsyncCompletion(task)` · 끝났으면 `Task.CompletedTask`. 뒤 메서드 = `await task` · 예외면 `if (task.IsCanceled)` return · 아니면 `throw;`(거름 없이 catch-all — 원문 주석 「AOT 지원 위해 예외 거름 피함」) · 성공하면 `StateHasChanged();`.
- 옮겨 쓴 차이는 **딱 하나**: 뒤 메서드의 catch 앞에 `catch (JSException ex) when (↑·↓)` 한 칸. 거름(`when`)은 백오피스가 Blazor Server(`AddInteractiveServerComponents` · AOT 아님)라 원문이 피한 이유가 해당 없음 · 칸 감쌈(1차)과 같은 꼴. 거름이 거짓이면 아래 catch-all 로 떨어져 원문과 같이 `throw;`(스택 보존).
- `StateHasChanged()` = `ComponentBase` `protected void`(덮기 불가) · 중간 두 기반이 덮지 않음(3-1) → 같은 메서드를 부른다. 동기 예외(콜백이 동기로 던짐)는 원문처럼 `InvokeAsync` 줄에서 그대로 밖으로 나간다(감싸지 않음).
- 🔴 **원문 글자 대조 미완** — 이 PC 에 .NET 원문 사본이 없다. [3] 는 착수 전 `release/8.0` `ComponentBase.cs` 의 두 메서드를 글자로 대조해 개발명세서에 붙이고, 다르면 원문을 따르고 PM 보고(R12).
