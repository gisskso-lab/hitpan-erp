## 2. 🔴 이번에 잡은 것 3개 — **전부 착수 전 조사에서 나왔다**

작업지시서대로 코딩부터 했으면 셋 다 그대로 출하됐다.

### ① W3 — **1단 승인은 승인이 아니다**

결재선이 2단이면 부장 승인은 `current_seq++` 일 뿐 문서는 `pending` 이다.
그런데 **API 응답이 두 경우 모두 `"승인되었습니다."`** 였고, 화면 서비스는 **응답 본문을 버리고 `bool` 만** 돌려줬다.

⇒ 그대로 팝업을 붙였으면 **부장이 승인한 순간 "발송하시겠습니까?" 가 떠서 대표이사 결재 전에 나간다.**
사장님 ⑤결재(*"결재 없이는 안 나간다"*) 정면 위반이고 **회수 불가**다.

**봉합**: 응답에 `isFinalApproved` 를 실었다. 판정은 `leave`·`absence`·`overtime` 이 이미 쓰던
`request.Action=="approved" && CurrentSeq >= TotalLines` 를 **그대로** 썼다 — 새 규칙을 만들면 두 판정이 갈린다.

### ② W4 — **PDF 가 실패해도 메일이 나가고 있었다**

`EmailService.SendDocumentAsync` 는 렌더 실패 시 `catch` 에서 *"첨부 없이 발송 진행"* 한다.
거래명세서면 말이 되지만 급여명세서는 **본문에 금액을 안 적으므로**(②결재)
직원은 **「발송드립니다」 한 줄짜리 빈 메일**을 받고 이력엔 **`sent`** 로 남는다. 경리는 다 보낸 줄 안다.

**봉합**: 급여 경로는 **먼저 렌더해서 성공한 것만** 넘긴다. 실패는 `failed` 로 이력에 남긴다.
⚠️ `EmailService` 는 **안 고쳤다** — 거래문서 8종이 쓰는 길이다(헌법 #1).

### ③ 🚨 W5 — **우리가 낸 구멍. 평직원이 사장님 급여명세서를 받아갔다**

`/api/email/preview-pdf` 는 `[Authorize(TenantOnly)]` 뿐이고 `documentType`·`documentId` 를
**그대로 받아** 렌더로 넘긴다. `RenderDocumentAsync` 는 **`tenant_id` 만 보고 사원 확인을 하지 않는다** —
거래문서에는 사원 개념이 없으니 원래 그럴 이유가 없었다. **그 문은 옳았다.**

🔴 **W1 이 `payslip` 을 문서타입으로 등록하는 순간** 그 문이 구멍이 됐다.

**실측**: 평직원이 사장님 명세서 id 로 불러 **PDF 27,697 bytes 가 그대로 나왔다**
(`급여명세서_사장님_2026-08.pdf`).

🔴 **W1~W4 가 전부 초록불이었다.** 빌드 0/0, 982통과, 실측도 다 통과.
**새로 만든 것만 검사했고, 원래 있던 문은 아무도 다시 안 봤다.**

> **다음에 적용할 것 — 공용 통로에 새 종류를 등록할 때는 그 통로를 쓰는 「기존 문 전부」 를 세어라.**
> `documentType`·`docType`·`menu_code` 처럼 **이름표로 분기하는 축**이 특히 그렇다.
> 내가 짠 코드에는 결함이 없었다. **기존 코드의 전제를 깨뜨린 것**이 결함이었다.

## 4. ⚠️ PM 이 판단해서 넣은 것 — **사장님 확인 필요**

### 결재를 **안 쓰는 회사**는 확정만으로 발송한다

§6① 은 *"결재 승인건만"* 인데, 결재 기능이 꺼져 있거나 **결재선이 0줄**이면
`approved` 행이 **영영 안 생긴다** ⇒ 그 회사는 **한 통도 못 보낸다**(#20 워크플로우 끊김).

⇒ **결재를 쓰는 회사만** 승인을 관문으로 삼고, 안 쓰는 회사는 **확정(`confirmed`)만으로** 보낸다.

🔴 `is_enabled` **와 결재선 줄 수**를 **둘 다** 본다 — 켜두고 결재선을 안 짠 경우가 **14차 P2 사고 자리**다.

### 이메일 없는 직원은 **그룹웨어에서는 받는다**

*"이메일 없음"* 은 **메일을 못 보내는** 사유일 뿐 **그룹웨어에서 못 받을** 사유가 아니다.
양쪽 다 막았으면 **그 직원만 자기 명세서를 영영 못 본다**.

| 명세서 | 메일 | 그룹웨어 |
|---|---|---|
| 승인·이메일 있음 | ✅ | ✅ |
| **미승인** | 🚫 | 🚫 |
| **이메일 없음** | 🚫 | ✅ **받는다** |
| **미확정** | 🚫 | 🚫 |
