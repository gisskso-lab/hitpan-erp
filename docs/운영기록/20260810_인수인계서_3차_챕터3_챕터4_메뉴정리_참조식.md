## §5. 운영 메모 — 다음 사람이 헤매지 않게

- **스쿼시 병합은 해시가 바뀐다.** main 반영 확인은 `git merge-base --is-ancestor` 가 아니라
  **`git diff <내커밋> origin/main -- <파일>` 이 비었는지**로 본다 (8/10 아침 4차 사고 계통)
- **워크플로 입력은 main 기준으로 읽힌다.** PR 브랜치에만 새 input 이 있으면 `gh workflow run` 이 **HTTP 422**.
  머지 후에 다시 부른다
- **1인 저장소**라 자기 PR 승인 불가. `--admin` 머지는 자동분류기가 막는다 → 사장님이 누르신다
- **게시 확인은 매니페스트로** — `curl -s https://updates.hitpan.kr/manifest.json`
- 🔴 **TruffleHog 빨간 X 를 "소음"으로 읽지 말 것 — 살아있는 P0 다.**
  PM 이 오늘 그렇게 오독했다가 워크플로를 열어보고 정정했다. `trufflehog.yml:68` 에 보안팀이 적어뒀다 —
  *"진탐(install.bat 의 고객 공통 DB 비번)은 제외하지 않았다. 그래서 계속 실패로 뜬다. **덮지 않는 것이 의도다.**"*
  실측: `origin/main:installer/install.bat` **5줄에 평문 상수**(값은 여기 안 적는다 — `git show` 로 직접 볼 것).
  **고객 공통 비번**이라 한 곳이 뚫리면 전 고객 DB 가 같은 열쇠로 열린다.
  ⚠️ PM 이 이 문서 초안에 **값을 그대로 옮겨 적었다가 스캔에 걸렸다** — 유출을 기록하려다 한 부 더 만들었다.
  **사고 기록에는 새는 자리를 적고, 새는 값은 적지 않는다.**
  ⇒ ✅ PR 게이트는 **`pull_request` 스캔**이 유효(새 유출 차단은 살아있다).
  ⇒ 🔴 할 일은 **스캔 끄기가 아니라 비번 제거**(고객사별 무작위 발급) — 보안상무 결재 사안. **끄면 '죽은 장치' 가 하나 더 생긴다**

**간단한 사내 메신저로 신규기능 추가**까지 생각중"*

**실측한 현황**

| 구역 | 현황 |
|---|---|
| 그룹웨어 화면 | **13개** (결재4 · 사원·HR직원현황 · 근태 · 휴가·연차 · 연차/경비 신청 · 전자근로계약서 · 전자서명이력 · 결재설정 · 직급관리) |

**🔴🔴 사장님 못박음 (8/11 새벽) — 이게 7번의 전부다**

> *"**HR과 인사, 그룹웨어는 직원계정으로부터 모든 연결이 돼!!!!**
>  그렇기에 지금까지 구현된 기능을 토대로 **설계를 재점검** 하고,
>  **고칠건 고치고, 추가할 기능은 추가**하는게 꼭 필요해"*

⇒ **직원계정 = 뿌리. HR·인사·그룹웨어 = 거기서 뻗은 가지.**
⇒ 갈아엎는 게 아니라 **이미 도는 13화면을 뿌리 기준으로 재점검**하는 일이다.

⚠️ **어제(챕터3)는 화면 이동만 연결했다. 데이터 축은 안 건드렸다.** 그게 내일 할 일이다.
(사장님 어제 원문: *"이 흐름을 **토대로** 그룹웨어·결재라인 워크플로우를 만들어야 함. 매우 중요함"*)

**재점검 판정 기준 — 13화면 각각에 이 질문 하나**
> **"이 화면이 다루는 사람은 직원계정에서 왔나, 계정 없이도 존재하나?"**
> 계정 없이 존재할 수 있으면 **거기가 끊기는 자리다.**
> ⚠️ 근태·휴가·전자근로계약서가 특히 의심 — 사람 단위로 도는데 계정 연결이 안 보인다.

**🔴 재설계의 진짜 쟁점 — 계정과 사원이 끊어질 수 있다**

```
users(직원계정) ←─ user_id ─ employees(사원) ─ employee_id ─→ approval_line_steps
                    ↑ DEFAULT NULL
```

`employees.user_id` 가 **NULL 허용**이다 ⇒ **계정 없는 사원**이 결재선에 들어갈 수 있고,
그 사람은 **로그인할 수단이 없어 결재가 그 자리에서 멈춘다** (헌법 #20 정면).

⇒ 사장님 *"직원계정관리를 마스터데이터로"* 는 **지금 사원이 마스터고 계정이 곁가지인 구조를 뒤집자**는 뜻으로 읽힌다.

삼성인재개발원장 출신. 사장님 *"그런 의미에서 … 그룹웨어 실무개발고문이사로 추대함."*
⇒ **7번 재설계의 실무 판정권자.** 지금까지 팀에 **HR·인사 실무를 아는 사람이 없었다**
(ERP 매니저는 회계·물류 축). 아래 질문 1번은 기술 문제가 아니라 **인사 운영 문제**라 상무님 영역이다.

**⬜ 설계 전 사장님·김삼성 상무께 여쭐 것 3가지**
1. 🔴 **계정 없는 사원을 아예 막나** — **이 답에 따라 구조가 완전히 갈린다. 설계 착수 전 필수.**
   막으면 → 끊길 자리가 사라지고 구조가 깨끗해진다
   막으면 → **계정 안 쓰는 직원**(생산직·일용직)은 사원 등록 자체가 막힌다
   ⇒ **레거시 히트판 쓰던 업체들이 어떻게 했나**가 답인데 **사장님만 아신다**
2. **결재선을 사람으로 짜나 직급으로 짜나** — 지금 **둘 다 있다**(`employee_id` + `position_id`).
   사람=퇴사 시 결재선이 죽는다 / 직급=안 죽는다
3. **메신저 범위** — 1:1 만인가 · 부서 대화방까지인가 · 결재 알림이 메신저로 오는가

🔴 **기존 결재 데이터 보존이 같이 걸린다** — 축을 바꾸면 이미 쌓인 결재 문서가 어떻게 되나.
**헌법 #1(덮어쓰기 금지)이 바로 여기 적용된다.** ⇒ **설계 문서부터.**
