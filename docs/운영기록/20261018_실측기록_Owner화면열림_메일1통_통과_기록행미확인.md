## 3. 🔴 그런데 [5] 조건-6 은 **뒷단이 남았다** — `result='sent'` **1행**

조건-6 은 「1통 발송 **+ `bo_email_send_history` 에 `result='sent'` 1행**」이다. 메일이 왔다고 행이 생긴 건 **아니다.** 구조적으로 의심할 근거가 있다.

| 근거 | 내용 |
|---|---|
| 그 표는 어디서 생기나 | `installer/backoffice/46_backoffice_email_send_history.sql` (`EmailSender.cs:182` 가 직접 그렇게 적어 뒀다) |
| 🔴 언제 생긴 파일인가 | **2026-10-15 작B1 에서 신설**(커밋 `15177319`) — 운영 백오피스 스키마를 복구한 **10/11 이후**다 |
| 🔴 배포가 그 SQL 을 서버로 나르나 | **아니다.** `deploy-ncp.yml` 에 `installer` 문자열 **0건**(오늘 `AUTO_MIGRATE` 역산 때 확인한 바로 그 사실) |
| 🔴 적재 실패하면 어떻게 되나 | `EmailSender.cs:179-189` — 표가 없으면 **MySQL 1146 을 catch 해서 LogWarning 만 남기고 발송 판정은 그대로 성공**으로 둔다 |

⇒ 🔴 **「메일은 갔다」와 「기록이 남았다」가 갈라질 수 있는 자리다.** 그리고 그 설계 자체는 **옳다**(`:132-136` — 적재 실패로 발송을 실패라 말하면 더 나쁜 거짓말이다). 문제는 **지금 어느 쪽인지 안 쟀다**는 것이다.

🔴 이건 **별건 P0 「거짓 초록」과 같은 결**이다 — 화면은 「보냈습니다」인데 장부엔 아무것도 없을 수 있다.

## 6. 🔴 추가 적발 — **비밀번호를 바꿀 기능이 백오피스에 없다** (내 §3-③ 지시 철회)

§5 와 채팅에서 나는 사장님께 **「`master` 비번을 교체하십시오」**를 사장님 손 ③ 으로 드렸다. **그 지시를 철회한다 — 누를 화면이 없다.**

| 측정 | 결과 |
|---|---|
| `master@hitpan.kr` 가 사는 표 | **`platform_admins`** — 로그인이 거기서 읽는다(`BackofficeAuthController.cs:42-44`) |
| `/owner/users`·`/owner/platform-users` 가 만지는 표 | 🔴 **`bo_users`** — **다른 표다**(`OwnerBoUsersController.cs:93`) |
| 그 컨트롤러가 가진 기능 | `request-create` · `request-delete` · `activate` · `deactivate` — 🔴 **비번 변경 0건**(`:75·:132·:172·:176`) |
| 레포 전체 비번 변경 경로 | 🔴 **0건** — `change-password`·`reset-password`·「비밀번호 변경」 grep **전부 0** |
| `BCrypt.HashPassword` 호출처 | **신규 생성 3곳뿐**(`OwnerBoUsersController:98` · `OwnerMfaController:94` 백업코드 · `ResellerApplicationsAdminController:189` 임시비번) — **기존 계정 갱신 0곳** |

⇒ 🔴 **`platform_admins` 의 비번은 화면·API 어디로도 바꿀 수 없다.** 유일한 길은 운영 MySQL 8 에 직접 `UPDATE platform_admins SET password_hash = <BCrypt>` 인데 그건 **운영 직접 수술(#39) + #29 사전승인** 사안이다.

🔴 **이건 master 한 계정의 문제가 아니다.** 본사 관리자 **누구도** 비번을 바꿀 수 없다 ⇒ 유출·퇴사·주기교체에 대응할 수단이 0이다. **베타 출시 전 막아야 하는 구멍**으로 본다.

**처분 (오늘 손대지 않는다)**
1. **별건 신설** — 「백오피스 비밀번호 변경 경로 0건」. 설계: `/owner` 에 본인 비번 변경 + Owner 가 타 관리자 비번 **초기화**(임시비번 1회 메일 — `ResellerApplicationsAdminController:189` 선례가 이미 있다)
2. 🔴 **그 전까지 평문 노출 대응은 「교체」가 아니라 「차단」뿐이다** — 사장님 결재 받아 운영 DB 1줄(#29·#39)로 갈 것인지, 기능을 먼저 만들 것인지 **사장님 선택 사항**으로 올린다
3. 🔴 git 이력의 평문은 어느 쪽을 택해도 남는다 — 이력 세탁은 별건
