## §3 🆕 P2 — 절V 「401 = 완료」가 서버 미도달 갈래를 삼킨다

- **사실(`4d6d497c` 판독)**: `HitPanApiAuthHandler.SendAsync` 는 401 을 받으면 갱신을 시도하고, 결과가 `RefreshDecision.Keep`(갱신이 서버에 닿지 못함 · 5xx·연결 실패)이면 재시도 없이 **원래 401 응답을 그대로 돌려준다**. `LogoutGate.IsServerLogoutDone` 은 상태 코드만 본다 — `code == 401 ⇒ true`.
- **경로**: 오래 둔 탭(접근 토큰 만료) → [로그아웃] → 서버 401 → 갱신이 5xx/끊김(`Keep`) → 원래 401 → 「완료」 → 로컬 토큰 지움 · 미완료 안내 없음. 로그아웃은 서버에 안 닿았으므로 세션 행·refresh 는 **살아 있다** → 같은 PC 재로그인 409 「다른 PC에서 사용 중입니다」 최대 8h.
- **무게**: 잠김 자체는 절V 이전에도 같다(K-7 (나) · 풀어 주는 기능 없음). 절V 가 바꾼 것은 **그 경우의 유일한 설명(미완료 안내)을 지운 것** — 방금 로그아웃한 사람이 「다른 PC에서 사용 중」을 본다. 보안 무관 · 확률 낮음(갱신 순간 끊김) · **N-1 과 같은 계열의 두 번째 갈래**.
- **게이트 공백**: W-3/W-4 는 `LogoutGate` 를 상태 코드 하나로만 잰다 — `Keep` 뒤 돌아온 401 을 재는 게이트가 없다.
- **봉합 요건**(코드는 [3] 몫): 「401 = 완료」를 **갱신이 서버에서 거절된 경우(또는 갱신할 토큰이 없던 경우)로 한정** · `Keep` 뒤 401 은 미완료 · 게이트 1 + 음성 대조군 1 · 같은 게시에 실으므로 게시 추가 비용 0.
- ⇒ 사장님 선택 §5-2.
