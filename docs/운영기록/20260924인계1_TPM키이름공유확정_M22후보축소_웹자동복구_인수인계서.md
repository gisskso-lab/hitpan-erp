## 2. 🚨 오늘의 최대 발견 — **TPM 키 이름 공유가 확정됐다**

### 2-1. 무엇이 달라졌나

인계2 까지 이것은 **⚠️가설 · 미실측**이었다(*"실측하려면 그 키를 덮어써야 한다"*).
**오늘은 키를 건드리지 않고 소스만 읽어서 확정했다.** 실측할 필요가 없었다 — **상수가 하나뿐**이다.

| 항목 | 값 |
|---|---|
| 상수 | `private const string KEY_NAME = "HitPan.TaxInvoice.MasterKey";` (35번 줄) |
| 그 상수를 쓰는 곳 | `SealKey`(83) · `UnsealKey`(111·113) — **전부** |
| 메인PC 전용 키 이름 | **없다** |
| 생성 옵션 | `CngKeyCreationOptions.OverwriteExistingKey` (79) |

⇒ **`ITpmKeyService.SealKey` 를 누가 부르든 같은 키 하나를 덮어쓴다.**
메인PC 등록(`MainPcProofService.RegisterThisPcAsync`)도 그 함수를 **실제로 부른다.**

### 2-2. 그래서 무슨 일이 일어나는가

```
세금계산서가 마스터키를 봉인해 둔다      → 키 A 로 봉인된 값이 DB 에 있다
메인PC 등록을 누른다                     → CngKey.Create(..., OverwriteExistingKey) → 키 A 가 키 B 로 바뀐다
세금계산서가 옛 값을 풀려 한다           → 🔴 키 A 가 없다 → 복호화 불가
```

🔴 **9/23 01:3x 에 사장님이 [이 컴퓨터로 바꾸기] 를 누르셨다.** 그 순간 `SealKey` 가 불렸다.
**덮였는지 아닌지는 PM 이 확인 못 했다** — 근거는 §5(권한 벽).

### 2-3. 🔴 다음 세션이 지킬 것

- **[이 컴퓨터로 바꾸기] 를 시험 삼아 반복해서 누르지 마라.** 누를 때마다 덮는다
- 게이트·시험이 **실물 `SealKey` 를 부르면 안 된다**(이미 지키고 있다 — `LocalSealTpm` 대역)
- 고치는 방향(키 분리)은 **세금계산서 모듈 경계를 넘는다** ⇒ **코드 전에 사장님 결재**(#29 · 9/22 *"모듈 경계를 PM 이 넘었다"* 지적)

## 3. 🟢 M-22 후보 축소 — `SealKey` 는 **예외를 안 던진다**

`TpmKeyService.SealKey` 전체가 `try/catch` 로 덮여 있고, **catch 가 값을 돌려준다**:

```
try {  IsTpmAvailable() ? TPM 봉인 : DPAPI(LocalMachine) 봉인  }
catch {  DPAPI(CurrentUser) 로 봉인해서 **반환**  }     ← 예외가 밖으로 안 나간다
```

⇒ `RegisterThisPcAsync` 의 `catch (Exception) { … return false; }` 는 **사실상 도달 불가**다.

### 판별표 갱신 (인계2 §6-1 → 이번 판)

| # | 응답 | 조건 | 오늘 판정 |
|---|---|---|---|
| A | 403 | 권한·`account_type` | 🔵 낮다 — 팝업이 떴다 = 대표다 |
| B | 400 `"이 컴퓨터에서는 등록할 수 없습니다…"` | 표가 소모·만료 (등록 때 **두 번째 왕복**이 실패) | 🟡 **살아 있다** |
| C | 400 `"기기 정보를 확인할 수 없습니다…"` | 헤더 `X-HitPan-Device-Id` 빈값 | 🟡 **살아 있다** |
| **D-1** | 500 `"등록을 마치지 못했습니다…"` | `SealKey` 예외 | 🟢 **탈락 — 예외가 안 나온다** |
| **D-2** | 500 `"등록을 마치지 못했습니다…"` | `rows == 0` — `tenant_devices` 에 그 `(tenant_id, device_id)` 줄이 **없다** | 🔴 **유력** |
| **E** | 500 (본문이 그 문장이 **아님**) | UPDATE 가 예외 — **`mainpc_sealed_key` 컬럼 없음(DB-126 미적용)** | 🔴 **유력** |

🔴 **D-2 와 E 는 응답 본문 한 줄로 갈린다.** 그래서 §0-② 가 첫 행동이다.

## 6. ⚠️ 새 미결 M-25 — 봉인·해제 경로가 비대칭이다 (별건)

`TpmKeyService` 를 읽다 같이 나왔다. **오늘 고치지 않았다. 기록만 한다.**

1. **`IsTpmAvailable()` 이 TPM 을 사실상 안 잰다** — `CngProvider.MicrosoftPlatformCryptoProvider` 가 null 이 아닌지만 본다. 그 프로퍼티는 **TPM 이 없어도 객체를 돌려준다** ⇒ 거의 항상 `true`
2. **봉인은 3가지 방식**이 될 수 있다 — TPM / DPAPI LocalMachine / (실패 시) **DPAPI CurrentUser**
3. **해제는 순서가 다르다** — `TPM → LocalMachine → CurrentUser`
4. 🔴 **저장된 바이트에 「무엇으로 봉인했는지」 표식이 없다.** 폴백이 조용히 섞이면 **나중에 못 푸는 값**이 생긴다

⇒ **별도 작업지시서 감**이다. 메인PC 트랙에서 즉석으로 손대지 않는다(봉합 즉석 금지).
