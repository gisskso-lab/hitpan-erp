## 1. 확정된 히트판 설계 철학 (영구 원칙)

### 🎯 히트판 정신 (재확인)
> "쉬움으로 이겼다. 이 화면, 처음 보는 사람이 혼자 쓸 수 있냐?"

### 🧭 PM 3계명
1. **늦더라도 항상 검증한다** — 일정 압박이 이유가 될 수 없음
2. **버튼 이벤트 하나도 소홀히 않는다** — `Task.CompletedTask`/`return null`/빈 catch 원천 배제
3. **현 워크플로우·기존 코드 뒤집는 수정·재작성은 하지 않는다** — 얹기만 허용

### 🛡 PM 설계수정 4프로토콜
1. 왠만하면 **건들지 않는다** (디폴트 = 유지)
2. 건드릴 경우 **작업지시서** 필수
3. 민감 작업(DB 스키마/API 시그니처/원장/금액/인증/재고)은 **별도 알림**
4. **쪼개기 필수** — 1파일·1커밋 원칙, 주당 위험 구간 0.5% 이내

### ✅ 타임키퍼 5단계 게이트
1. 안 건드려도 되나? → YES면 반려
2. 작업지시서 제출됐나? → 없으면 반려
3. 민감 작업인가? → YES면 사장님 별도 승인 대기
4. 쪼개기 단위로 왔나? → 덩어리면 재쪼개기
5. 기존 테스트·샘플 영향 없나? → 있으면 사장님 승인 대기

### 📐 4축 설계 규약 (완전판, 점진 도입)
- **① Contract-First**: `HitPan.Contracts` SharedKernel 프로젝트로 서버·클라 DTO 일원화
- **② Explicit State Machine**: 6개 주요 엔티티(견적/수주/거래명세서/계산서/전자발행/반품) 상태 전이 YAML 문서화
- **③ UoW + Idempotency**: 모든 write는 UoW 안에서만, 엔드포인트에 `X-Idempotency-Key` 수용
- **④ Result<T, Error>**: `return null`/빈 catch 금지 (CI lint), 사용자 메시지·개발자 메시지 분리

## 2. 스코어카드 재정의 — "무결성"이란 무엇인가

### ❌ 이전 오독 (4축을 DB 레이어로 축소)
- 데이터 정합성 = DB row count/FK
- 보안 = 테이블 격리
- 성능 = 쿼리 속도
- UI 완성도 = 픽셀 얼라인

### ✅ 올바른 정의 (고객 화면 기준)
- **데이터 정합성** = 고객이 화면에서 누른 대로 데이터가 유실·왜곡·중복 없이 끝까지 흐르는가
- **보안** = 테이블만이 아니라 이벤트 경로·권한·에러 메시지까지 안전한가
- **성능** = 클릭부터 결과 볼 때까지 체감 속도
- **UI 완성도** = 모든 동작이 제 역할을 하는가

고객은 MariaDB 꺼내보지 않는다. **화면에서 보이고 쓰는 데이터가 전부**. 그게 안 되면 DB 무결성은 무의미.

## 4. 세금계산서 3계층 구조 확정 (사장님 설계)

```
[1층] 거래명세서 확정
        ↓ 전제
[2층] 계산서 발행 (내부 상태 마킹, 국세청 미전송)
        ↓ 전제
[3층] 전자세금계산서 발행 (국세청 전송)
          ├─ 2계층 모드: 즉시발행
          └─ 3계층 모드: 예약발행 (타이머 일괄)
```

### 원칙
- **"계산서 발행"과 "전자발행"은 완전히 다른 버튼, 다른 개념**
- 계산서 발행 = 히트판 내부 상태 마킹 (다른 ERP 병행 쓰는 고객 대응)
- 전자발행 = 실제 국세청 API 전송
- **"계산서 발행" 상태가 선행되어야 전자발행 가능** (순서 의존)
- 2계층/3계층은 고객사가 **건별·상황별 선택**
- 국세청 API 연동은 **전자발행 단계에서만**
- 수정/삭제: 계산서 발행 단계만 가능, 전자발행 이후는 **수정세금계산서**로만 정정

### 이번 라운드 구현 범위
- **계산서 발행 단계까지만** 우리가 구현
- 전자발행 단계(국세청 연동)는 **자체개발/외주/시점 모두 미정** — 추후 사장님 결정

## 5. 원클릭 설치 + 터널링 — 사장님 최우선 요구

### 핵심 원칙
**"어떤 통신환경이든(공유기/분배기/이중 NAT/Wi-Fi 중계기/사내방화벽) 원클릭 설치·연결까지 완료."**
고객이 설치 못 하면 나머지 기능 전부 무의미.

### 3티어 배포 아키텍처
```
[고객사 PC]              [히트판 본사]            [Cloudflare]
installer.exe  ──호출──▶ prov.hitpan.app  ──발급──▶ <tenant>.hitpan.app
                              │                          ↑
                              ├── 테넌트 등록            │
                              ├── 초기 암호 발급         │
                              └── 터널 토큰 발급 ────────┘
cloudflared ◀── 토큰 주입
MariaDB·API·Web ◀── 자동 구성 + 방화벽 룰 + 바로가기 2개
```

### 기술 선택 (권장 — 사장님 결정 대기)
- **터널**: Cloudflare Tunnel (무료·자동 HTTPS·DDoS 방어)
- **설치기**: Inno Setup v1.0.7 (기존 v1.0.6 확장)
- **DB**: Portable MariaDB 번들 + 기존 MariaDB 감지 분기
- **프로비저닝**: `prov.hitpan.app` 신규 서버 구축 필요
- **도메인**: 사장님 보유 도메인에 와일드카드 서브도메인

### 4 설치 시나리오 자동 분기
- **S1**: 신규 PC (깨끗)
- **S2**: 기존 MariaDB 있는 PC (v1.0.6에서 실패한 케이스) 🔴
- **S3**: 재설치/업그레이드
