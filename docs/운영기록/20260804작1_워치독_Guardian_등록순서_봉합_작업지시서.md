## 1. 진범 — 자가복구 장치가, 자가복구가 필요한 순간에 안 깔린다

### 1-1. 구조

```
InstallWatchdog.ps1
  :9   $ErrorActionPreference = 'Stop'      ← 모든 cmdlet 오류가 스크립트를 죽인다
  :39  Start-Service $ServiceName            ← ★ 실패하면 여기서 즉사
  :66  Register-ScheduledTask Guardian       ← 도달 못 함
```

`Guardian` 은 **워치독이 죽어 있으면 5분마다 살리는 2층 안전망**이다(`:47-57` 이 그 내용을 기록한다).

그런데 `Start-Service`(:39)가 실패하면 `$ErrorActionPreference='Stop'`(:9) 때문에 스크립트가 즉시 종료되어
**`Register-ScheduledTask`(:66)에 도달하지 못한다.**

```
Start-Service 실패 → 스크립트 즉사 → Guardian 미등록 → 아무도 안 살림 → 영구히 업데이트 0
```

**⇒ 살릴 사람이 필요한 바로 그 상황에서, 살릴 사람이 안 깔린다.**

### 1-2. 왜 P1(시한폭탄)인가

`Start-Service` 는 기본 **30초 타임아웃**이다. 고객 PC 가 느리거나(HDD, 저사양),
백신 실시간 검사가 첫 로드를 지연시키면 타임아웃이 난다.

한 번 타임아웃 나면:
- 워치독 미기동 + Guardian 미등록
- 서비스는 `start= auto` 라 **다음 재부팅 때는 뜬다**(완전 영구는 아님)
- 그러나 **재부팅 전까지 자동업데이트·자가복구 0** 이고, Guardian 2층 안전망은 **영원히 없다**
- 헌법 #28(Windows Update 후 터널 자동복구)·#30(고객 PC 자가회복, 본사 의존 0) 이 무력화

고객은 아무 증상을 못 느끼다가, 정작 복구가 필요한 순간에 아무도 안 온다.

### 1-3. 두 번째 결함 (같은 파일, 코드 정독 중 추가 발견)

```powershell
:32  & sc.exe create $ServiceName binPath= ... | Out-Null    # ← $LASTEXITCODE 미검사
:39  Start-Service $ServiceName                              # ← 없는 서비스를 시작 시도
```

`sc.exe create`(:32)가 실패해도 `| Out-Null` 이라 **조용히 통과**한다.
그러면 `:39` 가 "존재하지 않는 서비스"를 시작하려다 실패하고,
`.iss` 는 그 실패를 **"자동 시작 등록 실패"** 로 보고한다 — **진짜 원인(생성 실패)이 가려진다.**

같은 계통: `sc.exe description`(:33) · `sc.exe failure`(:36) 도 미검사.
단 이 둘은 부가 설정이라 실패해도 서비스 동작 자체엔 무해하므로 **경고만** 남긴다.

## 2. 봉합 설계

### 2-1. 원칙

| # | 원칙 | 근거 |
|---|---|---|
| 1 | **Guardian 을 먼저 등록**하고 `Start-Service` 를 나중에 | 시작이 실패해도 5분 뒤 Guardian 이 살린다 |
| 2 | `Start-Service` 실패가 **스크립트를 죽이지 않게** try/catch | 헌법 #15 — 침묵 금지, 단 비차단 |
| 3 | `sc.exe create` 실패는 **즉시 실패로 승격** | 서비스 자체가 없으면 Guardian 도 무의미 |
| 4 | 종료코드로 **세 상태를 구분** | `.iss` 가 정확한 메시지를 낼 수 있게 |
| 5 | 기존 구조·문구 **삭제 금지, 추가만** | 헌법 #1 |

### 2-2. 순서 변경 (핵심)

```
[변경 전]                          [변경 후]
 sc.exe create                      sc.exe create + 결과검사(실패=exit 1)
 sc.exe description/failure         sc.exe description/failure (경고만)
 Start-Service      ← 실패시 즉사    Guardian.ps1 작성
 Guardian.ps1 작성   ← 도달못함       Register-ScheduledTask   ← 먼저!
 Register-ScheduledTask ← 도달못함    Start-Service (try/catch) ← 나중, 비차단
```

### 2-3. 종료코드 규약 (신설)

| exit | 의미 | `.iss` 처리 |
|---|---|---|
| 0 | 서비스 등록 + 기동 + Guardian 전부 성공 | 정상 |
| 1 | **서비스 생성 실패** 또는 EXE 부재 = 워치독 없음 | 경고 팝업(기존 동작 유지) |
| **2** | **서비스 생성·Guardian 성공, 기동만 실패** (신설) | 경고 팝업 + **"5분 내 자동 시작" 안내** |

exit 2 는 **"자가복구 가능한 실패"** 다. 기존 exit 1 과 뭉뚱그리면 고객 안내가 틀린다.

### 2-4. `.iss` 호출부 정합 (`HitPan-Universal.iss:2296-2302`)

```pascal
if ResultCode <> 0 then
  WarnStartupRegistrationFailure('워치독 서비스 등록(InstallWatchdog.ps1)', ResultCode);
```

`<> 0` 이라 exit 2 도 경고가 뜬다 — **그대로 두면 동작은 안전한 쪽(경고 표시)이다.**
다만 exit 2 는 "5분 내 자동 시작"이 사실이므로 **문구를 분기**한다.

⚠️ 팝업 문구 변경은 고객 노출 영역이다 → 개발용어·영어 금지(사장님 명령 2026-06-05).

### 3-2. 동적 (실패 주입 — 이게 핵심)

| # | 시나리오 | 기대 |
|---|---|---|
| D1 | 정상 | exit 0, 서비스 RUNNING, Guardian 등록됨 |

**D2 가 통과하지 못하면 이 작업은 실패다.** "코드 고쳤다"는 봉합이 아니다.
