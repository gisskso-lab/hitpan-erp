### [1][2] 에서 실제로 있었던 일 — 🔴 스쿼시 충돌과 빠진 봉합

**PR #141 이 `CONFLICTING` 이라 CI 가 안 돌았다.** `#139` 가 스쿼시 머지되며
같은 내용이 다른 해시로 남은 탓이다([[project_squash_rebase_verify]]).

🔴 **그 과정에서 빠진 것을 하나 찾았다** — 메신저 링크 404 봉합(`4669654`)이
**main 에 없었다.** `#139` 스쿼시에 안 실렸다. 내용 대조를 안 했으면
`/approval/detail/{id}`·`/hr/work-report` 가 **404 인 채로 게시**될 뻔했다.
⇒ 체리픽해 실었고 main 에서 재확인했다(`ChatPopup.razor:352,358`).

**교훈 재확인**: 스쿼시 뒤에는 **해시가 아니라 내용으로 대조**한다.
`git log origin/main..HEAD` 는 이미 머지된 것도 미머지로 보여준다.

## 6. 정직하게

- **화면 실측 0건이다.** 오늘 검증은 빌드·시험·주소 대조까지다.
  §4 를 사장님이 눌러보시는 것이 **첫 화면 실측**이다(사장님 못박음 —
  *"개발환경 PC 정상작동은 큰 의미 없다"*).
- 자동 생성은 **상위부서·정렬·코드를 정하지 않는다.** 만들어진 부서는
  정렬 맨 뒤·상위 없음이라, 조직도를 세우려면 **부서 관리**에서 손봐야 한다(헌법 #11).
- 설계서의 "13개" 는 달성하지 못했다(**18개**). 직급관리·연차부여 2건은
  실측 결과 그룹웨어 소관이 아니거나 옮기면 위험이 커서 사장님 결재로 남겼다
  (설계서 §7).
