## 0. ⭐ 사장님 오더 (원문)
> "일해야지 쉬면 안되지"

**본 건은 오더 직접 지시가 아니라, 그 오더로 착수한 작업 중 [3-V] 병렬검증이 발견한 잠복 결함이다.**
§3 규율(끊긴 지점 즉석 봉합 금지)에 따라 **봉합하지 않고 지시서로 이관**한다.
**착수 전 사장님 결재를 받는다** — 고객 PC 동작이 바뀌는 건이다.

## 1. 무엇이 문제인가

**인스톨러는 MariaDB 10.11 을 지원하는데, 워치독은 11.4 만 본다.**

| 계층 | 지원 경로 | 근거 |
|---|---|---|
| 인스톨러 — 설치 판정 | 10.11 있으면 **MSI 설치 건너뜀** | [`HitPan-Universal.iss:240`](../../installer/HitPan-Universal.iss#L240) |
| 인스톨러 — DB 셋업 | 11.4 없으면 **10.11 로 폴백** | [`HitPan-Universal.iss:1440`](../../installer/HitPan-Universal.iss#L1440) |
| **워치독 백업** | **11.4 고정** | [`WatchdogBackupRunner.cs:135`](../../src/HitPan.Watchdog/AutoUpdate/WatchdogBackupRunner.cs#L135) |
| **워치독 동의읽기** | **11.4 고정** | [`WatchdogConsentReader.cs:200`](../../src/HitPan.Watchdog/AutoUpdate/WatchdogConsentReader.cs#L200) |
| **워치독 상태쓰기** | **11.4 고정** | [`WatchdogStatusWriter.cs:304`](../../src/HitPan.Watchdog/AutoUpdate/WatchdogStatusWriter.cs#L304) |

### 1-1. 왜 PATH 폴백으로 안 구제되는가 (실측)

워치독은 고정경로 실패 시 `where` PATH 폴백을 쓴다. 그런데:

| 사실 | 근거 |
|---|---|
| 인스톨러가 10.11 경로를 넣는 PATH 는 **배치파일 지역 변수** (`setlocal` 안) | [`HitPan-Universal.iss:1429-1431`](../../installer/HitPan-Universal.iss#L1429-L1431) |
| 배치 종료 시 소멸 — **시스템 PATH 를 바꾸지 않는다** | 같은 곳 |
| 워치독은 **SYSTEM 계정 서비스** — 사용자 PATH 를 물려받지 않는다 | `InstallWatchdog.ps1:32` |

> **⇒ 시스템 PATH 에 MariaDB bin 이 없으면 폴백도 실패한다.**
> MariaDB MSI 가 시스템 PATH 를 등록했는지에 **우연히 의존**하는 상태다.

### 1-2. 터지면 어떻게 되는가 — 3중 사망

| 경로 | 결과 | 근거 |
|---|---|---|
| 백업 실패 | **업데이트 영구 차단** (물리적 게이트) | [`UpdateOrchestrator.cs:146-153`](../../src/HitPan.Watchdog/AutoUpdate/UpdateOrchestrator.cs#L146-L153) |
| `schema_migrations` 조회 null | **안전측 차단** | [`UpdateOrchestrator.cs:486-491`](../../src/HitPan.Watchdog/AutoUpdate/UpdateOrchestrator.cs#L486-L491) |
| `local_update_status` 미적재 | **동의 팝업 영영 안 뜸** | `WatchdogStatusWriter.UpsertLatestAsync` |

> 🔴 **조용히 죽는다.** 고객 화면에 아무것도 안 뜨고, 업데이트가 안 되는 줄도 모른다.
> 헌법 #24(가르치지 않고 넘기는 건 거짓말) 위반 상태다 — 고객은 최신인 줄 안다.

## 2. 무엇을 하는가 (범위)

### 하는 것
- [ ] 워치독 3개 리더의 MariaDB 경로 탐색을 **버전 목록 순회**로 확장
  - 후보: `MariaDB 11.4` → `MariaDB 10.11` → (기존 `where` PATH 폴백 유지)
  - **7/16 W4-6 봉합 정신 유지**: 고정경로를 PATH 보다 **먼저** 본다(권한상승 차단)
- [ ] 3곳이 **같은 헬퍼를 공유**하도록 정리 — 지금은 동일 로직이 3벌 복사돼 있어 또 갈라진다
- [ ] 경로 탐색 실패 시 **어느 경로를 찾았는지 로그**에 남긴다 (지금은 조용히 실패)

### 하지 않는 것 (명시)
- ❌ **시스템 PATH 조작** — 헌법 #29(인프라 사전승인). 코드에서 해결한다
- ❌ 인스톨러의 10.11 지원 제거 — 기존 고객을 버리는 선택. 사장님 결재 사항
- ❌ MariaDB 버전 강제 업그레이드 — 고객 DB 를 건드리는 건 별건
- ❌ **이번 자동업데이트 수신 실측에 끼워 넣기** — Sandbox 는 11.4 라 재현 안 됨. 별도 검증 필요

## 3. 헌법 체크

| 조항 | 왜 걸리나 | 어떻게 지키나 |
|---|---|---|
| #1 덮어쓰기 금지 | 기존 탐색 로직 수정 | 후보 목록 **추가**만. 11.4 우선순위 불변 |
| #12 인터페이스 확장 시 구현체 전수 grep | 3곳 복사본 존재 | `grep -rn "MariaDB 1" src/` 로 전수 확인 (이미 3곳 확인) |

인프라 조작이 아니므로 사전승인 대상 아님. (그래도 §0 대로 사장님 결재는 받는다 — 고객 영향)

## 4. 어떻게 하는가 ([3] 개발팀용)

- 지휘: PM(개발팀장) → 백엔드 매니저 리뷰
- 관련 코드: 위 §1 표의 3개 파일
- 방향: 공용 헬퍼 1개 신설 → 3곳이 호출. **하드코딩 3벌을 1벌로.**
- 산출물: 개발명세서 → `docs/개발/업데이트배포/`

> ⚠️ **7/16 W4-6 봉합을 깨지 말 것**: 종전 PATH 우선을 고정경로 우선으로 **뒤집은** 봉합이다.
> 백업이 SYSTEM 권한으로 돌기 때문에 PATH 앞에 심긴 악성 `mysqldump.exe` 가 먼저 잡히면
> **권한상승**이 된다. 후보 목록을 늘리되 **PATH 폴백은 여전히 마지막**이어야 한다.

## 5. 검증 방법 (SoD)

**[3-V]** 보안상무 — 권한상승 벡터가 새로 열리지 않았는지 (후보 경로 전부 `Program Files` 하위인지)

**[4]** 검증팀장 데이비드 박
- [ ] 빌드 errors 0 + warnings 0
- [ ] `grep -rn "MariaDB 1" src/` — 하드코딩이 **헬퍼 1곳에만** 남았는지
- [ ] **10.11 환경 재현 검증** — 11.4 폴더를 임시 rename 후 백업이 도는지
- [ ] 고정경로 우선 순서 유지 확인 (PATH 폴백이 마지막인지)
- [ ] 독립 반증 3건

## 6. 리스크 / 롤백

| 리스크 | 확률 | 대응 |
|---|---|---|
| 후보 확장이 권한상승 벡터를 넓힘 | 낮음 | 후보 전부 `C:\Program Files\` 고정 하위로 제한 |
| 3곳 통합 중 한 곳 누락 | 중 | #12 전수 grep 의무 |
| 10.11 환경 재현이 어려움 | 중 | 폴더 rename 로 시뮬레이션 |

- 롤백: 커밋 되돌리기 (코드 3파일 + 헬퍼 1개)

## 7. 완료 정의 (DoD)

① 3곳 통합 + 10.11 후보 추가 ② 10.11 재현 검증 통과 ③ 개발명세서·작업리뷰서 + 커밋
