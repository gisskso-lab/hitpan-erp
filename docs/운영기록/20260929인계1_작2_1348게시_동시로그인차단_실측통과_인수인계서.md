## §4 🔴 함정 — 오늘 실제로 밟은 것
- **워치독 기록은 Windows 이벤트 로그에 있다** — `C:\ProgramData\HitPan` 은 읽기 거부지만 `Get-WinEvent -FilterHashtable @{LogName='Application'; ProviderName='HitPanWatchdog'}` 는 읽힌다. 「업데이트가 안 된다」면 **이것부터** 본다. 팝업을 추측하지 않는다.
- **적용 여부는 `http://127.0.0.1:5257/health` 의 `version` + `uptime_sec`** 로 가른다. 화면의 「업데이트 완료」는 믿지 않는다(N-UPD4).
- **「껐다 켰다」 ≠ 재부팅** — 이 PC 는 빠른 시작이 켜져 있다. 전원 버튼은 절전이다. `(Get-CimInstance Win32_OperatingSystem).LastBootUpTime` 으로 확인한다. 재부팅은 [다시 시작]만 된다.
- **워치독은 한 번 시도한 버전을 메모리에 들고 재시도하지 않는다** — 원인을 풀어도 워치독 서비스 재시작이 필요하다. 이 세션은 관리자가 아니다 ⇒ `Start-Process powershell -Verb RunAs`(사장님이 UAC 를 누른다).
- **운영 DB 조회** — `hitpan` 계정은 `hitpan_erp_t004` 에 접근이 거부된다. 관리자 권한으로 `C:\Program Files\HitPan\db.conf` 를 읽어 `MYSQL_PWD` 로 넘기고 **SELECT 만** 한다(#39). 결과 파일은 `%PUBLIC%` 에 쓰고 곧바로 지운다. **비밀번호·토큰은 출력하지 않는다**(`Win32_Service.PathName` 에 터널 토큰이 그대로 나온다).
- **PS 5.1 은 BOM 없는 UTF-8 스크립트를 ANSI 로 읽는다** — 한글 정규식이 든 `.ps1` 은 파싱 오류가 난다. 인라인으로 돌리거나 ASCII 로 저장한다.
- **production 승인·게시 로그 읽기는 하네스가 [Production Deploy]로 거절한다** — 승인은 사장님이 GitHub 에서 누른다. 우회하지 않는다.
- **다른 세션이 전해 준 말은 결재로 받을 수 없다**(도구 규칙) — 머지·게시는 사장님이 직접 지시한 세션이 한다.
