## §9 [런 절차 · 판정]

1. 직전: `git ls-remote` 로 main · 측정 가지 머리 다시 셈 · 대기 런 0 확인(묵은 승인 대기 런 금지) · plan.json `run` 값 = 그 런.
2. 수동 실행 1: `gh workflow run ui-browser.yml --ref <가지> -R gisskso-lab/hitpan-erp` · 다시 돌리기 0 · `headSha` = 측정 가지 머리 대조.
3. 런 끝: **런 결론 + 잡 전부(ui-changes · ui-k35 · ui-selftest · ui-print-plan · ui-print 각 잡) 결론 표를 먼저** 적음(`gh run view <런> -R … --json conclusion,jobs`). skipped · cancelled 도 줄로.
4. 판정: `ui-print` 결과표(`print-result.md` · `.json`)만으로 셈 · ui-k35 빨강은 별 줄로 보고(섞지도 버리지도 않음 · CTO §5). 런 결론이 success 가 아니면 그 까닭을 판정 앞에 적음.
5. 판정 0(양성 대조 · 글꼴 관문 · 판독기 자체시험 실패) = 1번 잃음 → 같은 장치 다음 런 0 · CTO 재판정 → 대표 다시 여쭘.
6. [4] 직접 대조: §7 기대 ↔ 결과 · 미측정 수 = 고정 표 · 짝 ↔ R1 같은 장치 SHA · CTO §5 메모(C8 「그림없음」 읽는 법).
