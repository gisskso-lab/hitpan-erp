## 0. 결재 박제 정합 사실

사장님 결재 = **정책 방향 결재**. 실제 키·시크릿·인증서·비용 결제는 **사장님 본인 직접 진행** 필요.
PM 역할 = ① 정책 방향 박제 ② 사장님 직접 진행 가이드 박제 ③ 사장님 발급 후 받아서 코드 봉합.

## 1. 가비아 API 키 본사 보관 — ✅ 사장님 결재 박제

### 결재 방향
- **본사 클라우드 서버에만 보관** (헌법 #22·#29 정합)
- EXE에 절대 포함 금지 (헌법 #18 정합)
- 사용 목적 = 가비아 서브도메인 `{고객사}.hitpan.kr` 자동 생성

### 사장님 직접 진행 안건
1. 가비아 콘솔 로그인 → "DNS 호스팅" → API 키 발급
2. 키 종류 = "DNS 레코드 자동 등록" 권한만 (최소 권한 원칙, 헌법 #22 정합)
3. 발급 후 → **본사 서버 환경변수 `Gabia:DnsApiKey`만 저장**
4. PM에게 전달 시 = ① 환경변수 박제 완료 메시지만 ② 키 값 메시지로 전달 절대 금지

### PM 봉합 대기
- `ProvisionDomainService.cs` 박제 (가비아 SDK 또는 REST 직접 호출)
- 환경변수 `Gabia:DnsApiKey` 읽어서 사용

## 2. Cloudflare API 토큰 본사 보관 — ✅ 사장님 결재 박제

### 결재 방향
- 가비아와 동일 (본사 서버만, EXE 절대 미포함)
- 사용 목적 = cloudflared 터널 자동 생성·삭제 + DNS 레코드 자동 박제

### 사장님 직접 진행 안건
1. Cloudflare 대시보드 → "My Profile" → "API Tokens" → "Create Token"
2. 권한 = Zone:Edit + Account:Cloudflare Tunnel:Edit (최소 권한)
3. **현재 활성 토큰 = 닥터스트레인지 사고 후 회전 완료 박제** (헌법 #29 정합)
4. 새 토큰 → 환경변수 `Cloudflare:ApiToken` 박제

### PM 봉합 대기
- `ProvisionTunnelService.cs` 박제 (`cloudflared tunnel create` 자동 호출)
- 헌법 #28 정합 — 토큰 무효화 감지 시 자동 회전

## 3. 라이선스 키 마스터 페퍼 (HSM) — ✅ 사장님 결재 박제

### 결재 방향
- 라이선스 키 = `HP-YYMM-XXXXXXXX-CRC` (HMAC-SHA256 + 페퍼)
- 페퍼 = 본사 HSM 또는 환경변수에만 (헌법 #22 정합)
- 사용 목적 = 라이선스 위조 차단

### 사장님 직접 진행 안건
1. **단기 (베타)**: 환경변수 `License:Pepper` = 32자 랜덤 (PM 박제 가능)
2. **장기 (정식)**: AWS KMS 또는 Azure Key Vault HSM 박제 (비용 월 ~5만원)
3. 사장님 결재 = **단기 환경변수 → 정식 출시 전 HSM 전환** 2단계

### PM 봉합 대기
- `LicenseValidationService.cs` 박제 (이미 일부 박제)
- 환경변수 → HSM SDK 전환 시 인터페이스 추상화 박제

## 4. 코드 서명 인증서 (DigiCert·Sectigo) — ✅ 사장님 결재 박제

### 결재 방향
- 사용 목적 = EXE 서명 → Defender SmartScreen 통과 (헌법 #31 정합)
- 미서명 EXE = "알 수 없는 게시자" 경고 + 백신 격리 위험

### 사장님 직접 진행 안건
**옵션 A — DigiCert EV Code Signing** (권장)
- 비용: 약 130~180만원/년
- 즉시 SmartScreen 명성 박제 (가장 빠름)

**옵션 B — Sectigo Standard Code Signing**
- 비용: 약 30~70만원/년
- SmartScreen 명성 = 첫 1~2개월 누적 필요

**옵션 C — 자체 서명 (무료)**
- 사용자가 "그래도 실행" 클릭 필요 = UX 사고 위험

### 사장님 결재 안건
- 베타 = 옵션 C 또는 B (비용 절감)
- 정식 출시 = 옵션 A (사용자 신뢰)

### PM 봉합 대기
- `installer/build-installer.ps1` 박제 (`signtool.exe sign` 자동 호출)
- 사장님 인증서 발급 후 PFX 파일 + 비번 = 본사 빌드 서버에만

## 5. 베타 EXE 배포 채널 — ✅ 사장님 결재 박제

### 결재 방향 (3개 채널 비교)

**채널 A — 랜딩 다운로드** (8명제 #4 정합)
- 결제 완료 → 1회용 토큰 → `/landing/download` → EXE 다운로드
- 본사 클라우드 서버 = 자동 빌드 + 임시 저장 (24시간 만료)
- 사용자 클릭 4번으로 가동 박제

**채널 B — 직접 발송 (이메일·SMS)**
- 본사 운영팀 = 결제 확인 → 수동 빌드 → 다운로드 링크 이메일·SMS 발송
- 헌법 #24 정합 — 본사 가르침 의무 강함

**채널 C — 대리점 직접 설치 방문**
- 대리점이 고객사 PC 직접 방문 설치
- 베타 100곳 + 대리점 영업 동력

### 사장님 결재
- 베타 = **A + B 병행** (자동 + 수동 보강) 박제
- 정식 = A 단일 (자동화)

### PM 봉합 대기
- `LandingDownloadPage.razor` 박제 (1회용 토큰 검증)
- 본사 API `/api/install/build-exe` 박제 (어제 체크리스트 정합)

## 6. MariaDB root 비번 정책 — ✅ 사장님 결재 박제

### 결재 방향

**옵션 A — 고정 비번** (현재 v1.1.0 박제)
- `PASSWORD=Hitpan2025!` (HitPanSetup.iss line 50)
- 장점: 본사 CS 시 root 접근 용이
- 단점: 비번 유출 시 전체 고객사 위험 (헌법 #22 위반)

**옵션 B — 랜덤 비번 + 본사 메타 박제** (권장)
- 설치 시 32자 랜덤 비번 자동 생성
- 비번 = 고객 PC 로컬 + 본사 백오피스 메타 저장 (4-eyes 결재 후 JIT 복호화)
- 사용자 모름 (헌법 #25 "쉽게" 정합)

**옵션 C — 사용자 입력**
- 사용자 직접 비번 입력
- 헌법 #25 위반 (쉽지 않음)

### 사장님 결재
- 정식 = **옵션 B 정직 박제** (랜덤 + 본사 메타)
- 베타 = 옵션 A 유지 가능 (롤백 가능성 박제)

### PM 봉합 대기
- `installer/HitPanSetup.iss` line 50 정정
- `InstallMariaDb.ps1` 신규 박제 (랜덤 비번 생성 + 본사 박제 API 호출)

## 8. OCR 엔진 (PaddleOCR 온프레미스 vs 외주) — ✅ 사장님 결재 박제

### 결재 방향 (사장님 어제 강화 명령 정합)

**옵션 A — PaddleOCR 온프레미스** (권장)
- 사장님 헌법 #22·#23 정합 (외부 OCR 벤더 미사용)
- 본사 서버 또는 고객 PC 로컬 실행
- 사업자등록증 검증 후 즉시 폐기 가능 (zero-retention)
- 비용: 무료 (오픈소스) + 서버 비용 (월 ~5만원)
- 한국어 정확도 = 약 93~96%

**옵션 B — 외주** (Naver Clova / Kakao OCR / Google Vision)
- 정확도 = 약 98~99%
- 비용: 호출당 5~30원 (베타 100곳 × 1건 = ~3,000원/월)
- 외부 전송 = 헌법 #22 정합 어려움 (사등 사진 외부 전송)

### 사장님 결재
- 베타 = **옵션 A PaddleOCR** (헌법 #22 정합)
- 부정확 시 사용자가 수동 보정 + 본사 CS 백업

### PM 봉합 대기
- `BizLicenseUploader.razor` 박제 (이미 UI만)
- `OcrService.cs` 신규 박제 (PaddleOCR Python 브리지 또는 .NET 포팅)
