④ 7/31 「전수 빨강 = 의도」 뒤집기는 갈래 ㄴ(기준선) 몫 — 갈래 ㄱ 은 일정·수동 전체 검사(`Scan secrets (full)`)의 결과를 바꾸지 않는다. 대표 확인과 함께.
⑤ 오더 대조: 결재 기록 §1 2번 「비밀정보 주간 검사 탐지 후보 123건 처리 담당 · 기한」 → [1-V] §B-5 가 담당·기한 안을 냈고 이 갈래가 그 끝 줄이다. 오더 밖 요구 0.
⑥ 금지 재확인: 공개 레포 — 로그 · 산출물 · 커밋 메시지에 탐지 값 · 모양(가짜 포함) 0. 자체시험은 러너 임시 저장소에서만.

## §2 [이해]
- 의중: `Scan secrets` 를 **필수 검사로 걸 수 있는 상태**로 만든다 — 깨끗한 가지는 초록, 새 유출은 빨강, 기존 후보는 기록된 채 조용히. 비밀 검사 도구 자체의 공급망 구멍을 닫는다.
- 안 하면: 첫 푸시 87.5% 빨강(49/56) · 일정 15주 연속 빨강 = 새 진짜 유출이 묻힘 · 필수로 못 걸어 막는 장치 0.
- 실측 근거: [1-V] N2·§B-4 · 상류 `action.yml` 조회(설계서 §0 「실측 추가」).

## §5 [구현 지시]
- 지휘 PM · hp-implementer 1(갈래 ㄱ → ㄴ 순차). 격리 worktree 는 origin/main 바닥 — 이 지시서·설계서가 바닥에 있는지 먼저 확인.
- 엔진 digest·checkout SHA 는 구현 시점에 조회해 판 번호 주석과 함께 적는다. `@main`·`latest`·판 태그만 쓰는 줄 0.
- 🔴 가짜 비밀은 **실행 때 생성**(키 생성 도구·난수). 규칙 키워드는 조각으로 이어 붙인다. 고정 문자열 값 규칙은 자체시험에 쓰지 않는다(설계서 §5-1).
- 🔴 커밋 전: 고정 엔진으로 **바뀐 파일만** 로컬 검사 → 자기 일치 0 을 개발명세서에 기록(값 출력 없이 개수만).
- 엔진 JSON·자체시험 출력 = 러너 임시 파일 · 단계 끝 삭제 · 로그엔 개수·탐지기 이름·지문만 · artifact 업로드 0.
- 이 PC 이력 검색은 `--no-textconv` 필수([1-V] §C).
- 산출물: 개발명세서 → `docs/개발/보안/` (폴더 없으면 PM 위치 결재).
