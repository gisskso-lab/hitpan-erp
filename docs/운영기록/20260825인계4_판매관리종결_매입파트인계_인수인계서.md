## [2] 🔴 판매관리에 **남은 것** — 매입 들어가기 전 확인 필요

사장님 지시가 이미 나왔으나 **미착수**다. 매입으로 넘어가도 이 3건은 살아 있다.

### 4-C. 로스율·반품 표기 (사장님 정의 2·3·4번)

| 건 | 내용 |
|---|---|
| 로스율 | **판매수익성분석 그리드에 로스율 열** · 계산식 **로스금액 ÷ 매출액**(결재 완료) · 이익률 감소 반영 |
| 반품 제외 | **판매순위표·판매통계·판매현황**에서 반품 반영 빼기 |
| 반품 표기 | **수주서·수주현황·거래명세서**에 반품 표시(파손이면 "파손") |

🔴 **작7 에서 미룬 결재가 여기 걸려 있다** — 원 거래명세서 상태를 바꿀지(B) 표기만 할지(A).
**PM 은 A 를 건의드렸다**: 반품확정이 이미 매출·미수를 빼므로 B 면 **두 번 빠진다**.
**부분반품**(3개 중 1개)이면 통째로 못 바꾼다.

### 4-A. 판매목록 버튼 개편 — 🔴 **착수 전 결재 필요**

> 사장님: *"계산서 발행 버튼을 「판매확정」으로 / 전자발행 버튼을 「계산서 발행」으로
> → 계산서 발행 클릭시 전자발행으로 버튼상태 변경 / 판매확정 전에는 계산서 발행 비활성화"*

**실측으로 드러난 것:**
- 현 「계산서 발행」 → 실제로는 **`BulkConfirmAsync` = 판매확정**. 다이얼로그도 *"확정 처리하시겠습니까?"*
  ⇒ **이름만 틀렸다. 사장님 지시가 맞다.**
- 현 「전자발행」 → **아무 일도 안 한다.** 확인창 띄우고 목록 새로고침만. **서버 호출 0 = 가짜 버튼.**
- 🔴 더 있다 — [SalesListDialog.razor:130](../../src/HitPan.Web/Components/Sales/SalesListDialog.razor#L130)
  「전자발행」 활성 조건이 `Status == "invoiced"` 인데,
  [같은 파일:223](../../src/HitPan.Web/Components/Sales/SalesListDialog.razor#L223) 「계산서 발행」은 `"confirmed"` 로 바꾼다.
  ⇒ **눌러도 영영 안 켜진다.** 아무 일도 안 하는 데다 **켜지지도 않는다** — 두 겹으로 죽어 있다.
- 상태 라벨은 **이미 사장님 표현과 일치** — `confirmed`="판매확정" · `invoiced`="계산서발행"

⇒ **이름만 바꿀지, 실제 발행까지 만들지 결재 필요.** 4-D 와 한 몸이다.

### 4-D. 세금계산서 — **파이프라인만** (사장님 지시)

1. 전자발행(국세청 전송)된 건 → **마이너스 수정계산서**
2. 미확정(일괄발행 대기) → **삭제 가능**
3. 발행옵션 2분할 — **일괄발행**(지정 시각) / **즉시발행**
4. 반품확정 시 국세청 발행건이면 마이너스 수정계산서 연동

🟢 DB 컬럼 있음 — `etax_mode`(`scheduled`/`immediate`) · `batch_time`
⚠️ **코드 사용처 0건** · **반품↔계산서 연동 0건**(지금은 반품해도 계산서가 그대로 남는다)

## [3] 🔴 매입파트 착수 전 실측 — **판매에서 고친 결함이 매입에도 있다**

인계 쓰면서 매입 영역을 **읽기만** 해서 조사했다(수정 0건).
**판매에서 오늘 고친 결함 중 3개가 매입에 그대로 남아 있다.**

### ① 조회유형 재조회 — **매입 6화면 전부 동일 결함** 🔴

사장님이 판매에서 반려하신 바로 그 증상이다:
> *"조회유형 콤보박스 동작시, 그리드 첫칸에 반영된 데이터가 아닌 날짜로만 나옴"*

| 화면 | 재조회 배선 | 방식 |
|---|---|---|
| 발주현황 | ❌ 0 | `@bind-Value` |
| 매입현황 | ❌ 0 | `@bind-Value` |
| 매입종합현황 | ❌ 0 | — |
| 매입순위표 | ❌ 0 | `@bind-Value` |
| 매입통계 | ❌ 0 | `@bind-Value` |
| 반품현황 | ❌ 0 | `@bind-Value` |

🔴 **원인이 판매와 똑같다** — [PurchaseStatusPage.razor:19](../../src/HitPan.Web/Pages/Purchase/PurchaseStatusPage.razor#L19)
`@bind-Value="_viewType"` 라 **값만 바뀌고 다시 조회를 안 한다.**

⇒ 판매는 `Value` + `ValueChanged="OnViewTypeChangedAsync"` 로 고쳤다. **같은 처방이 그대로 듣는다.**
⚠️ 판매에서 **`_searchText=""` 초기화가 필수**였다 — 품목별로 친 품목명이 업체별로 넘어가
**업체 필터가 돼 0건**이 된다. 매입도 같은 함정이 있는지 봐야 한다.

### ② 전표 작성자 기록 — **매입은 아예 없다** 🔴

사장님 오더 4번(*"작성 계정사원 기록으로 남고 그리드에 보여주기"*)을 판매에만 적용했다.

- 매입 화면 `CreatedByName` 표시 — **0건**
- `PurchaseService` 에 `CreatedBy = _currentTenant.UserId` — **0건**

⇒ **발주서·매입명세서·매입반품은 누가 썼는지 기록이 없다.**
🔴 **작성자 = `user_id`** (`employee_id` 아님 — 별개 GUID 라 잘못 잡으면 사원 리포트 조인이 전부 죽는다).
판매에서 이미 확정된 축이니 **그대로 따르면 된다.**

### ③ 더블클릭 가드 — **매입명세서·발주서에 없다** 🔴

| 화면 | 저장 연타 가드 |
|---|---|
| 매입명세서 | ❌ **없음** |
| 발주서 | ❌ **없음** |
| 매입반품 | ✅ 있음 |

[PurchaseReceiptPage.razor.cs:297](../../src/HitPan.Web/Pages/Purchase/PurchaseReceiptPage.razor.cs#L297) `SaveAsync` 진입부에 재진입 가드가 없다.
⇒ 판매 반품에서 **전표가 중복 생성되던 그 결함**과 같은 자리다.

### ④ 매입반품 ↔ 매입명세서 연결 — 🟢 **이미 있다**

[PurchaseReceiptPage.razor.cs:583](../../src/HitPan.Web/Pages/Purchase/PurchaseReceiptPage.razor.cs#L583) 에서 `ConvertReceiptToReturnAsync` 를 부른다.
⇒ 사장님이 *"기존에 매입쪽반품은 워크플로우 흐름대로 잘 됫엇는데"* 라 하신 그 흐름이다.
**작7 같은 봉합이 매입엔 불필요하다.**
