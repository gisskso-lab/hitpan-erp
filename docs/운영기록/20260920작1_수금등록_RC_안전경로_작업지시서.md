## 1. 오더를 이렇게 이해했다

- 3판에서 수금·지급 **등록 트랜잭션 전체**를 READ COMMITTED 로 열었다(`LegacyBalanceMatching.MatchIsolation` · `CollectionService.CreateCollectionAsync`·`CreatePaymentAsync`). 이월잔액 매칭의 동시성(병렬이슈44 교착)을 피하려고 넣은 규칙인데 **영향 범위가 모든 수금·지급 등록**이다.
- MariaDB 는 `log_bin=ON` + `binlog_format=STATEMENT` 이면 RC 트랜잭션의 쓰기를 거절한다고 알려져 있다 → 그런 고객 PC 에서는 **수금·지급 등록이 전부 막힌다**(#20 흐름 끊김 · P0).
- 설치본은 MariaDB 가 이미 있으면 그 설정을 그대로 쓴다(`installer/HitPan-Universal.iss:115` `NeedsMariaDB`) → 고객 설정에 우리 기능이 달려 있다.
- **게시 전에 고친다.** main 머지만으로는 고객에게 안 나가지만(ERP 게시는 수동), 다른 트랙이 먼저 게시하면 같이 나간다.

## 2. 범위 (⬜ [1-V] 결과로 확정)

### 하는 것 (가안)
- 서버 설정을 보고 **안전 경로로 가르는 것** — 거절되는 조합이면 등록이 막히지 않게 하고, 그때도 이월잔액 매칭이 두 번 빠지지 않게 한다.
- 그 조합에서 도는 **동작 게이트**(설정을 실제로 STATEMENT 로 놓고 등록이 되는지).

### 하지 않는 것
- 고객 PC·사장님 PC 설정 변경(#29·#39) · 설치본이 남의 MariaDB 설정을 바꾸는 것 · appsettings 수정(#21) · 3판 기능 되돌리기.

## 4. 구현 범위 (설계팀장 존 · [1-V] 완료 반영)

> 설계 정본 = `docs/설계/erp/20260920_설계_수금등록_RC_안전경로.md`. 아래는 그 설계의 **지시 형태**다. 충돌하면 설계 정본이 우선.

### 4-1. 결정 한 줄
**서버 설정을 보고 두 경로로 가른다. 두 경로가 같은 정확성 계약을 지킨다. 등록이 막히는 경로는 만들지 않는다(#20).**

| 판정 | 경로 | 내용 |
|---|---|---|
| `log_bin=OFF` 또는 `binlog_format∈{MIXED,ROW}` | **RC** | 지금 3판 그대로 (무변경) |
| `log_bin=ON` **AND** `STATEMENT` | **RR** | RR + 거래처 행 잠금 + **R 재계산·전표 남은금액을 잠금 읽기** + 교착 짧은 재시도 |
| 조회 실패·권한거절·타임아웃 | **RR** | RR 은 두 서버 모두에서 돈다 → 모르면 도는 쪽 |

### 4-2. 하는 것
1. **판정기 신설** `BinlogSafetyProbe` — `SELECT @@log_bin,@@binlog_format` · 프로세스 값 1개 · TTL 5분 · 1665 를 만나면 즉시 무효화 · 실패 시 `LogWarning` 한 줄(#15) 후 RR.
2. **모드 계약** `LegacyMatchMode { ReadCommittedFresh, RepeatableReadLocking }` — 호출자가 **선언**하고, 가드는 (모드 ↔ 실제 격리수준) 쌍을 본다. 모드가 SQL 의 잠금절도 고른다.
3. **RR 잠금 읽기** — `GetForUpdateAsync` 의 R 재계산 문장 꼬리에 `LOCK IN SHARE MODE`(RR 모드일 때만). **공용 식 본문은 한 글자도 안 건드린다**(11곳 소비자 계약).
4. **D1 봉합** — `EnsureCollectionTargetAllowedAsync`·`EnsurePaymentTargetAllowedAsync` 의 남은금액 SUM 도 RR 모드에서 잠금 읽기. (설계가 새로 찾은 구멍 — 설계 §4-4)
5. **재시도 껍질** — 등록 **트랜잭션 통째** 재시도. 1213·1205·1665 만. 총 3회 · 50ms→150ms + 지터. 소진 시 고객 문구.
6. **게이트 신설** `RcSafePathGate` + CI 등록.

### 4-3. 하지 않는 것 (§2 에 더한다)
- BINLOG ADMIN 권한 확대 · 설치본의 남의 my.ini/SET GLOBAL 수술(#29) — **둘 다 기본안에서 뺐다**(§9 결재 안건).
- 공용 식(`ReceivableRemainingSql`·`PayableRemainingSql`) 본문 수정 · 3판 기능 되돌리기 · 로거 배선 확대 · RC 경로 동작 변경.
- 기존 G8 사례 삭제(§5-3 의 한 줄 기대값 변경만).

## 5. 게이트 · 기대값

### 5-1. 인스턴스
- CI: db-gate 잡에 스텝 추가 — `docker run -d -p 3307:3306 -e MARIADB_ROOT_PASSWORD=… mariadb:11.4 --log-bin=stmt --binlog-format=STATEMENT --server-id=9920`.
- 게이트는 **`HITPAN_DB_STMT_PORT`** 로만 찾는다. **CI 에서 없거나 못 붙으면 FAIL**(SKIP 을 통과로 세지 않는다).
- 로컬은 새 datadir · 포그라운드 `mariadbd` · **서비스 등록 금지** · 시험 후 SHUTDOWN(선행검증 §7 방식). 운영 3306·격리본 33306 무접촉(#39).

## 8. 갈래별 지시 (최대 2갈래 · 각 파일 5개 이하)

### 갈래 S1 — 판정·경로 (파일 4)
`src/HitPan.Application/Services/BinlogSafetyProbe.cs` 🆕 · `…/LegacyBalanceMatching.cs` · `…/CollectionService.cs` · `src/HitPan.API/Program.cs`(DI 등록 · appsettings 무접촉 #21)

**0단계 — 코딩 전 raw 확인 (⚠️ 미실측 해소)**
STATEMENT 인스턴스에서 `SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ; BEGIN; SELECT … FOR UPDATE;` 가 통과하는지 먼저 잰다.
- 통과 → 설계대로.
- **1665 가 나면** → RR 모드의 거래처 행 잠금도 `LOCK IN SHARE MODE` 로 내리고, 같은 거래처 동시는 교착으로만 갈린다(재시도가 메운다). 설계 §5-3 분기 · **PM 에 보고 후 진행**.

**계약(갈래 간 고정 · S2 가 이 시그니처를 소비한다)**
```
public enum LegacyMatchMode { ReadCommittedFresh, RepeatableReadLocking }
public static IsolationLevel IsolationFor(LegacyMatchMode mode);

public interface IBinlogSafetyProbe {
    Task<LegacyMatchMode> GetModeAsync(IDbConnection db, ILogger? logger, CancellationToken ct);
    void Invalidate();
}
public sealed class BinlogSafetyProbe : IBinlogSafetyProbe {
    public BinlogSafetyProbe(TimeSpan? ttl = null, TimeProvider? clock = null);
}

Task<Remaining?> LegacyBalanceMatching.GetForUpdateAsync(IDbConnection db, IDbTransaction tx,
    LegacyMatchMode mode, string tenantId, string partnerId, bool receivable, CancellationToken ct);
Task LegacyBalanceMatching.EnsureMatchAllowedAsync(IDbConnection db, IDbTransaction tx,
    LegacyMatchMode mode, string tenantId, string partnerId, string? refId, decimal amount,
    DateTime date, bool receivable, ILogger? logger, CancellationToken ct);

private Task<T> CollectionService.RunMatchTxAsync<T>(LegacyMatchMode mode,
    Func<IDbTransaction, CancellationToken, Task<T>> body, string what, CancellationToken ct);
```
- `mode` 는 `tenantId` **앞**에 둔다(잊고 못 지나간다).
- `CollectionService` 생성자에 `IBinlogSafetyProbe? probe = null` **선택 인자** → 기존 호출자·테스트 무변경.
- 가드 실패 = 지금과 같은 `NotSupportedException`. `Serializable`·`ReadUncommitted`·`Unspecified` 는 어느 모드로도 통과 못 한다.
- 재시도는 `InvalidOperationException`(고객 문구 거절)에 **절대 걸지 않는다**. 감사로그는 커밋 뒤 = 껍질 밖.
- 소진 문구(상수 한 곳 · 개발용어 금지 #23): *"지금 다른 사용자가 같은 거래처의 수금을 처리하고 있습니다. 잠시 후 다시 저장해 주세요."* (지급은 "수금"→"지급")

① 판정기 + 순수 판정 사례 → 빌드 0/0 · **커밋** → ② 모드·가드·R 잠금절 → **커밋** → ③ 서비스 분기·재시도·D1 → **커밋**.

## 10. ⚠️ 미실측 (추측을 사실로 쓰지 않는다)
1. **RR + STATEMENT 에서 `FOR UPDATE` 허용 여부** — 안 쟀다. §8 갈래 S1 0단계에서 먼저 확인.
2. **파생표 `LOCK IN SHARE MODE` 가 STATEMENT 서버에서 최신 커밋을 읽는가** — 3판 1차안 기록이 근거일 뿐. G-RC3·G-RC4 가 판정한다.
3. **교착 빈도·재시도 성공률** — 미실측. 3회는 체감 기준이지 실측 근거가 아니다.
4. **고객 PC·사장님 PC 의 `log_bin`/`binlog_format` 분포** — 안 봤다. 「모른다」가 사실. 빈도를 숫자로 말하면 받아쓰기(#32).
5. **D1 이 현장에서 실제로 났는지** — 모른다. RR 경로를 새로 여는 이번 작업이 **만들지 않게** 막는 것이다.

### 12-2. §5-2 게이트 표에 더한다

| 사례 | 잰다 | 무력화(빨간불이어야 한다) |
|---|---|---|
| **G-RC3**(기대값만 정정) | RR 경로에서 앞선 일반 읽기 **뒤에도** 최신 R — 파생표가 아니라 직접읽기로 | 재계산을 파생표로 되돌리면 옛 R(90,000) → 빨간불 |
| **G-RC10** 🆕 동등성 | 같은 상태에서 `공용 식` 과 `RR 재계산` 의 **L0·M·R 이 모두 같다** — 사례 E1 부분매칭 · E2 취소분 · E3 이관분 · E4 음수 이월 · E5 행 없음 · E6 매입 반품(확정/미확정) · E7 초과(음수 R) | RR 식에서 필터 한 줄 빼면(예: `is_active=1`) 두 값이 갈라져 빨간불 |
| **G-RC11** 🆕 앵커 | 공용 식 2개의 **SHA-256 이 기록값과 같다** | 공용 식을 한 글자 고치면 빨간불 → RR 식을 같이 고치게 만든다 |
| **G-RC6**(사례 추가) | D1 **매입 축** — 같은 매입전표 동시 지급 합 초과 거절(반품 포함) | 지급 합산 잠금절 제거 → 초과 통과 |

- **무력화 방법**(게이트가 진짜 잰다는 증거 · 관례): ①㉯ 를 파생표로 되돌린다 → G-RC3 빨간불 ②RR 식의 `COALESCE(source_type,'') <> 'migration'` 한 줄 제거 → G-RC10 E3 빨간불 ③공용 식에 공백 1개 추가 → G-RC11 빨간불 ④㉲ 잠금절 제거 → G-RC6 매입 축 빨간불. **네 가지를 실제로 빼고 FAIL 을 확인한 표**를 개발명세서에 싣는다(초록불만으로 CI 등록 금지).
- 게이트 신설·CI 등록은 종전대로 **갈래 S2**. S1b 는 ㉮~㉲ 와 0단계 실측만 한다.

### 12-4. ⚠️ 2판이 안 잰 것
1. **(다) 「트랜잭션 첫 문장이 `FOR UPDATE` 면 일반 읽기도 최신인가」 — 안 쟀다.** 기각 사유는 실측이 아니라 **코드로 강제할 수 없다**는 것(설계 §11-2 · 병렬이슈44 함정).
2. **신설 RR 문장의 최신성** — 조인 있는 `em`·`rm` 은 미실측 → S1b 0단계가 잰다.
3. **좁아진 잠금의 교착 빈도** — 여전히 미실측. §4-3 재시도가 받는다.
