## 2. 무엇을 하는가

### 2-1. 메인PC 2슬롯 (코드 봉합)

- [ ] **관문 대표 구역에 제2 갈래** — [이 컴퓨터는 회사서버 컴퓨터]:
  새 슬롯을 만들지 않고 **서버 줄(is_main_pc=1)에 합류**한다.
  `GET api/devices`(대표 전용 전체 목록)로 서버 줄 특정 → `reissue-key/{서버줄}` →
  `setDeviceId(서버줄)` **먼저**(verify-key 는 헤더의 장비넘버를 우선 본다) → `verify-key` →
  기계비밀 보관 → reload. 실패 시 **원래 deviceId 복원** + 안내.
- [ ] 🔴 **신분 유지 가드** — `AuthService.cs:106`: **보관된 통행증(키)+장비넘버가 있으면
  로그인 응답의 deviceId 로 덮어쓰지 않는다.** 통행증이 없을 때만 새 신분을 받는다.
- [ ] 계수 SQL·`is_main_pc` 축·승인 상태 **무접촉** (D-3 · G-43)

**왜 안전한가**: ①합류는 대표 전용 API(reissue)라 직원 불가 ②서버 줄은 원래 1대로 세던 줄이라
계수 불변 — 기계 합계 = 1 (사장님 8/15 확정과 오늘 지적 동시 충족) ③재발급이 직전 탑승자의
**축① 비밀**을 죽인다 ④서버 줄의 축②(장비넘버 통과)는 해시와 무관해 로컬 콘솔 동작 무영향.

> 🔴 **[3-V] 정정 (거짓봉합 방지)** — ③을 *"무료 탑승 동시 1개 자기 제한"* 이라 적었던 것은 **과장이다.**
> 자기 제한은 **축①(비밀) 수준에서만** 참이고, **축②는 서버 줄 번호만으로 통과**하므로(번호는
> 비밀이 아님 — G-32-d 기존 한계) 번호를 저장한 브라우저는 비밀이 죽어도 통과한다.
> 이번 봉합이 그 구멍을 넓히지는 않지만 **막지도 않는다** — 축② 폐쇄는 기존대로 "다음 차수 몫".

**[3-V] 실재 판정 ②③ 봉합 (같은 커밋)**: 합류 브라우저의 로그인 갱신(장비넘버 1순위 대조)이
**서버 줄의 이름·UA·IP·종류를 브라우저 것으로 덮었다** — CS 본체 식별 훼손 + 대표 폰 합류 시
종류가 mobile 로 바뀌어 **요금 칸 이동**(pc 계수 -1). ⇒ `RegisterOrRefreshAsync` 갱신문이
`is_main_pc=1` 줄은 **last_seen 만 갱신**하고 정체(이름·종류·UA·IP)를 보존한다. **G-41** 이 값으로 지킨다.

**[3-V] 갇힘 A 봉합 (같은 커밋)**: 신분 유지 가드에 **회사(tenant) 표식**을 짝으로 둔다 —
같은 회사일 때만 신분을 지키고, 다른 회사 로그인(한 PC 다중 사업자 — 사장님 결재)이면 새 신분을
받는다. 표식은 verify·합류 성공 시 함께 저장(`hitpan_auth_tenant`).

**남는 소음(정직하게)**: 합류한 브라우저의 옛 pending 줄은 목록에 남는다(슬롯 0 — pending 은
안 센다). 대표가 거절로 지울 수 있고, 근본 정리는 병합 설계(§2-2 이월)와 한 몸.
**남는 한계(정직하게)**: 서버가 아닌 기계에서 대표가 [회사서버 컴퓨터]를 잘못 누르면 그 기계가
서버 슬롯에 올라탄다 — 표식·정체는 G-41 이 지키므로 피해는 **요금 1대 이내 + 대표 본인 행위**로
한정된다. 오클릭 경고 다이얼로그는 아침 후속(§5).
