## 1. 문제의식 — 사장님 통찰

### 현재 구조의 모순
- 품목 선택 시점에 **시스템은 이미 알고 있다**: "이 품목이 어느 창고에 얼마 있는지"
- 그런데 사용자에게 **"출고창고 골라줘"** 라며 콤보를 던짐
- 사용자는 선택지의 의미를 모름 → 잘못 고르면 "재고 없는 창고에서 출고" 에러 유발

### 히트판 정신 위반
> "이 화면, 처음 보는 사람이 혼자 쓸 수 있냐?"

처음 보는 직원이 출고창고 콤보 앞에서 멈춘다 → 통과 못 함.

## 2. 처방안 — 출고창고를 라벨/텍스트로

### 2.1 케이스별 표시 정책

| 케이스 | 출고창고 표시 | 동작 |
|---|---|---|
| 품목 미선택 | 회색 라벨 "품목을 먼저 선택하세요" | 비활성 |
| 단일 창고 보유 | 검정 라벨 "본사창고 (잔량 60)" | 클릭 불가, 자동 확정 |
| 다중 창고 보유 | "본사창고 (잔량 60) ▼" | 클릭 시 펼침, 기본=잔량 최대 |
| 잔량 0 | 빨간 라벨 "출고 가능 재고 없음" | 이송 버튼 비활성 |
| 일부 창고 잔량 0 | 잔량 0 창고는 회색·비활성, 잔량 있는 것만 선택 | — |

### 2.2 입고창고는 콤보 유지
입고창고는 사용자가 진짜 선택해야 하는 정보 → 현행 콤보 유지.

### 2.3 적용 범위 — `StockTransferPage`만

`StockAdjustPage` (재고조정) 는 **본 작지서 범위 외**:
- 조정은 "특정 창고의 재고를 정정"하는 작업 → 사용자가 창고 명시 필요
- 라벨화하면 의미 자체가 달라짐
- 별도 검토 필요 (현재는 콤보 유지)

### 2.4 분할출고 시나리오 (확장 의문 — 본 작지서 범위 외)
"본사창고 30 + 스마트비즈창고 20 → 입고창고 50" 같은 분할출고는 별도 화면/별도 작지서.
이번엔 **단일 출고창고 → 단일 입고창고** 만 처리.

## 4. 검증 시나리오

### 시나리오 A — 단일 창고 보유 품목
1. 품목 = "테스트원자재1" (본사창고에만 100개)
2. 출고창고 라벨에 "본사창고 (잔량 100)" 표시
3. 클릭해도 펼침 없음
4. 입고창고 = "스마트비즈창고1" 선택 → 수량 30 → 이송
5. 정상 처리 확인

### 시나리오 B — 다중 창고 보유 품목
1. 품목 = "테스트반제품1" (본사창고 60, 스마트비즈창고1 -10)
2. 출고창고 자동 셋팅 = "본사창고 (잔량 60) ▼"
3. ▼ 클릭 → 본사창고 / 스마트비즈창고1(잔량 -10, 회색) 노출
4. 본사창고 그대로 선택 → 입고창고 = 스마트비즈창고1 → 수량 10 → 이송
5. 음수 -10 → 0 회복 확인

### 시나리오 C — 잔량 0 품목
1. 품목 = (잔량 전혀 없는 품목)
2. 빨간 라벨 "출고 가능 재고 없음"
3. 이송 버튼 비활성 확인

## 7. 미해결 확장 의문 (참고만)

### Q1. 분할출고는 언제?
다중 창고에서 부분씩 빼서 한 창고로 합치는 시나리오. 별도 작지서 권고.

### Q2. 다른 화면에도 같은 UX 함정?
- 매입처리 → 입고창고 콤보 (이건 사용자 선택 맞음)
- 거래명세서 → 출고창고 콤보 (이것도 라벨화 검토 필요? 별도 진단 작지서 권고)

### Q3. StockAdjustPage 도 라벨화?
조정은 의미가 다르나, "어차피 잔량이 있는 창고만 조정 의미 있음" 관점이면 같은 패턴 적용 가능.
별도 사장님 의향 확인 후 진행.
