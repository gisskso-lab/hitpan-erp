## 1. 결재 1 — 기본 로직 (판정 기준)

> **사장님**
> *"워크플로우 흐름으로 **금액값은 회계로, 상품재고값은 재고로 정합하게** 나와야 하고,
> 이 값을 **상품이냐, 업체냐의 필터링으로 원장이 정확하게** 나와야 되."*

```
매입  →  재고 IN  + 지급금 ↑          지급 시  →  지급금 ↓
매출  →  재고 OUT + 미수금 ↑          수금 시  →  미수금 ↓ · 현금 ↑
                                       부가세는 매출 시점 기입
원장  →  위 둘을 반영 · 상품 축 / 업체 축
```

**조사 결과**: 🟢 **이 로직 자체는 코드에 살아 있다.**
틀린 건 **반품·취소가 세 곳(재고·회계·원장)에 고르게 안 닿는 것**이다.

🟢 **이 판정식이 그대로 게이트가 된다** — 상품축·업체축이 같은 표를 GROUP BY 만 달리 읽으니
**총합이 반드시 같아야 한다.** 봉합이 깨지면 재고는 2배 빠지는데 회계는 1배라 반드시 FAIL 한다.

## 3. 결재 3 — 마이너스가 수주까지 올라간다

```
수주      1 + (-1) = 0
명세서    1 + (-1) = 0     ← 쌍둥이로 묶여 따라다닌다
```

🔴 **PM 판단 정정** — PM 이 *"마이너스는 되돌리는 장치일 뿐 중복 생성은 못 막는다"* 고 본 것이 **틀렸다.**

왜 틀렸나: **마이너스를 명세서 층에만 두고 생각**해서다.
**사슬 위로 올리면 층마다 0 이 된다.** 수주가 0 이면 그 위에 명세서를 또 못 만든다.

## 4. 결재 4 — 잔량 기준 (분할출고 허용)

```
출고:  수주 잔량 = 주문수량 − 기출고수량   →  잔량 0 이면 차단
반품:  품목 잔량 = 판매수량 − 기반품수량   →  잔량 0 이면 차단
```

🔴 **이 한 줄로 P0-1 과 P0-2 가 동시에 풀린다.**
별개 봉합 2건으로 본 것이 **같은 원리의 양면**이었다.

⚠️ **현재 8/27 작11 가드가 정상 분할출고를 막고 있다.**
코드는 원래 잔량 로직(`OrderedQty − DeliveredQty`)을 갖고 있었는데 **가드가 덮었다.**
⇒ 가드를 지우는 게 아니라 **잔량 기준으로 되돌린다.**

## 5. 결재 5 — 화면을 새로 만들지 않는다

```
판매목록 그리드 ─ [반품하기]
거래명세서 작성 ─ [세금] [반품하기]
        ↓
같은 거래명세서 화면 — 수량·금액이 (−)로 전량 채워진 상태
  · 반품 안 할 품목은 줄을 지운다      · 수량 수정 가능
  · 이미 반품된 품목은 잔량만큼만      · 거기서 마이너스 계산서까지 끊는다

목록 조회:   명-001     1,000,000
             └ 명-001R   -1,000,000   ← 원전표 바로 아래
```

**왜 이 방식인가 (4가지가 한 번에 풀린다)**

| 효과 | 설명 |
|---|---|
| 히트판 정신 통과 | 담당자가 **이미 아는 화면**이다. 교육 0 |
| 근거 연결 자동 | **원전표에서 눌러 들어오니** 사슬이 저절로 걸린다 |
| 수량 상한 자동 | 잔량이 채워지니 **가드로 막는 게 아니라 넘을 경로가 사라진다** |
| 경리 검증 화면 | 목록 배치(원전표 아래 (−))가 그대로 **대사 화면**이 된다 |

🔴 **새 화면 0개** — 사장님 원칙(*"불필요하게 화면을 더 만들지 말고"*) 준수.

## 6. 결재 6 — 반품 누적은 품목 단위

```
명세서: A 10개 · B 5개

A -7 OK  →  A -2 OK(누적 9)  →  A -1 OK(누적 10 소진)  →  A -1 차단
B -5 OK                                                    ← A 와 무관
```

전량 소진된 명세서면 **[반품하기] 버튼 자체가 비활성**.

## 7. 결재 7 — 상태 한글 통일

```
수주서    수주완료 → 판매완료 → 판매확정 → 계산서발행 → 전자발행
거래명세서          판매완료 → 판매확정 → 계산서발행 → 전자발행
                      │          │                      │
                    삭제        취소                반품완료 → 반품확정
              (원장 무접촉) (원장 역기록)        (마이너스 전표)  (국세청 발송)
```

| 상태 | 뜻 | 이 시점에 일어나는 일 |
|---|---|---|
| 수주완료 | 수주 완료 (수주서 전용) | 원장 무접촉 |
| 판매완료 | 거래명세서 작성·저장 | 원장 무접촉 |
| **판매확정** | 판매확정 버튼 누름 | **재고 OUT · 미수금 ↑ · 분개** |
| 계산서발행 | 계산서 임의발행 (일괄발행 대기 포함) | 세금 문서만 |
| 전자발행 | 국세청 전송 완료 | **되돌릴 수 없음** |
| **반품완료** | 마이너스 전표 O · 국세청 **미발송** | **재고 IN · 미수금 ↓ · 역분개** |
| **반품확정** | 마이너스 전표 O · 국세청 **발송** | 상계 완결 |
| 취소 | 판매확정 이후 되돌림 | 원장 역기록 |

### 추가 결정 4건

| # | 결정 | 근거 |
|---|---|---|
| ① | **워딩만 변경** — 상태 개수 그대로, 이름만 한글로 | 마이그 부담 감소 |
| ② | **「분할출고」는 상태가 아니라 표시(뱃지)** — `판매완료 [분할출고]` | 거래조건이 다양해서(잔금까지 받은 경우·계약금만) **상태로 쪼개면 조합 폭발** |
| ③ | **마이너스 명세서는 같은 상태 + 부호로 구분** | 별도 상태 안 만듦 |
| ④ | **취소 상태 유지** | 계산서는 2단(삭제/마이너스)인데 **명세서는 3단(삭제/취소/마이너스)** — 판매확정 시점에 **이미 재고가 움직여서** |

### 되돌리기 3단 — 원장에 무엇이 갔느냐가 기준

| 현재 상태 | 되돌리기 | 내용 |
|---|---|---|
| 판매완료 | **삭제** | 흔적 없이. 목록·현황·분석·통계에서 전부 빠짐 — **사슬 자체 삭제** |
| 판매확정 · 계산서발행 | **취소** | 원장 INSERT ONLY(#3)라 **역기록으로 상계**하고 상태로 남김 |
| 전자발행 | **마이너스** | 국세청에 갔으니 물리적으로 못 지움. **마이너스 전표로 상계** |

## 8. 결재 8 — 확정 건 삭제·수정은 2단으로

> **사장님**
> *"권한가진자만 **확정** 상태를 삭제, 수정할 수 있도록 — 이건 **당연히 지금 동작하고 있는 거지.**
> 권한가진자 **패스워드 한번 더 입력.**"*

```
1단  권한 검사        ← 이미 동작 중 (신설 아님)
2단  패스워드 재입력   ← 이번에 신설
```

**다이얼로그 문구 (사장님 지정 — 그대로 쓸 것)**

```
확정된 거래 입니다. 취소하시려면 패스워드 입력이 필요합니다
```

- **대상**: 판매확정 · 반품확정 + 그 이후 단계(계산서발행 · 전자발행)
- **삭제뿐 아니라 수정도** 대상
- 🔴 **1단이 정말 동작 중인지 실측 필요** — 오늘 하루에만 *"이미 되어 있다"* 가 **두 번 틀렸다**

| *"마이너스는 중복 생성을 못 막는다"* | **틀렸다** — 명세서 층에만 두고 봐서. 사슬 위로 올리면 층마다 0 (결재 3) |

| *"매입엔 가드가 2중"* | **없었다.** 양쪽 다 신규 구현 ⇒ **공수 2배** |
| 부가세를 **P1** 로 분류 | **현장 기준 P0 1순위** — *"급한 건 큰 사고가 아니라 안 들키는 사고"* |

전체 8건은 [5축 전수조사 §7](../검증/20260828_5축전수조사_상품BOM매입매출계산서_실물실측.md) 에 있다.
