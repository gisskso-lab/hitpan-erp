## §3 2단계 — 재기동 (①이 최신일 때만 · 🔴 사장님 손)

`hitpan-backoffice-api` 한 서비스만. **1회용 drop-in → 재기동 → 확인 → drop-in 제거 → 재기동**.

```bash
# (1) 스위치 1회용으로 켜기
sudo mkdir -p /etc/systemd/system/hitpan-backoffice-api.service.d
printf '[Service]\nEnvironment="HITPAN_BO_AUTO_MIGRATE=1"\n' \
  | sudo tee /etc/systemd/system/hitpan-backoffice-api.service.d/99-bo-automigrate.conf >/dev/null
sudo systemctl daemon-reload && sudo systemctl restart hitpan-backoffice-api

# (2) 기동했나 + 적용 로그
systemctl is-active hitpan-backoffice-api
journalctl -u hitpan-backoffice-api -n 60 --no-pager | grep -iE "SchemaMigrator|적용|migrat"

# (3) 스위치 되돌리기 (표는 남는다 — 추가만 된 것이라 기존 동작 무영향)
sudo rm -f /etc/systemd/system/hitpan-backoffice-api.service.d/99-bo-automigrate.conf
sudo systemctl daemon-reload && sudo systemctl restart hitpan-backoffice-api
```

**통과 판정 (셋 다)**: ⓐ `is-active` = `active` · ⓑ 로그에 30·31·32·40·41·42 적용 흔적 · ⓒ `back.hitpan.kr` CS 창구·CS 백과사전이 **열린다**(500 아님).

⚠️ **위험 1 — 기동 거부**: 마이그 하나라도 실패하면 **API 가 기동을 거부**한다(불일치 잠복 방지 설계).
증상 = `is-active` 가 `failed`, 백오피스 전체 접속 불가. **되돌림**: 위 (3) 을 바로 실행하면 스위치가 꺼져 **종전 상태로 기동**한다.
⚠️ **위험 2 — 순서**: **#495 머지 + NCP 배포 완주 뒤**에 해야 42번이 함께 적용된다. 그 전에 하면 42번만 빠진 반쪽이 된다.
🟢 **ERP 쪽지는 안 사라진다**: 본사가 거부하면 ERP 로컬 큐에 남아 재시도하고, 표가 생기는 순간 밀린 것이 올라간다.
