## 3. ⚠️ 핵심 충돌 — EXE 최신성 (사장님 결정 필요)

종단 빌드테스트(②)는 **설치 EXE로 신규설치를 재현**하는 것인데:
- dist 최신 EXE = **1.2.15(6/17)** → 그 후 오늘까지 **고리1~4·항목3·P1·각종 봉합 미반영.**
- 최신 코드로 종단 테스트하려면 **EXE 재빌드 필요** → 그런데 **EXE 빌드는 헌법상 별도 결재**(메모리 `project_exe_build_hold`, 2026-06-02 "빠진 부분 보충 후 GO 결재 후에만 build-installer.ps1").

→ **두 길 중 사장님 결정:**
- **길A**: 기존 1.2.15 EXE로 먼저 종단 흐름 검증(6/17 기준이지만 "설치→가입→시리얼→로그인" 골격은 동일). EXE 빌드 안 함. **오늘 빠름.**
- **길B**: 최신 EXE 재빌드(별도 결재) 후 종단 테스트. **정식 완성도(헌법 #34)지만 EXE 빌드 결재 선행.**

PM 권고: **①(P1 멱등)은 EXE 무관(레포 코드 직접) → 길 무관 즉시 가능. ②(종단)는 길A로 먼저 골격 확인 → 정식 출시 직전 길B.** 단 사장님 결정.

## 4. 작업 분해 (결재 후)

### 4-1. M4 .wsb + 셋업 스크립트 설계 (PM 작성, 코드 산출물)
샌드박스가 휘발성이라 매 기동 자동 셋업 필요. **두 검증의 공통 토대:**
- `tests/sandbox-m4/HitPan-M4.wsb` — 레포(읽기전용)·dist EXE 매핑 + 셋업 스크립트 자동 실행
- `tests/sandbox-m4/setup-m4.ps1` — 샌드박스 안에서 ① mysql/MariaDB 확보 ② .NET 8 런타임 확인 ③ 검증 스크립트 안내
- ⚠️ 샌드박스는 인터넷 Default — 단 본사 시리얼·터널 의존 구간은 실측해야 어디까지 가는지 앎(추측 금지).

### 4-2. ① P1 멱등 검증 스크립트 (EXE 무관)
- 샌드박스 내 빈 MariaDB → `hitpan_db_clean.sql` import(124테이블) → MigrationRunner.ApplyPendingAsync 호출(수동) → DB-*.sql 순차적용 → **2회 실행=동일(멱등)** 확인.
- 검증 대상 = 오늘 배선한 DI가 실제 빈DB에서 도는지. ddl-smoke 정신 + 멱등.

### 4-3. ② 종단 빌드테스트 시나리오 (길A 기준)
- 샌드박스에 1.2.15 EXE 설치 → 가입(랜딩) → 시리얼 발급(백오피스, NCP 실연동) → ERP 로그인 → 핵심화면 스모크.
- **각 단계 화면 캡처**(사장님 의도 — 문제 시 즉시 캡처·대응).
- 막히는 지점 = 그게 진짜 끊김(추측 아닌 실측). FAIL이면 봉합 안건 도출.
