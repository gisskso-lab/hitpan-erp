## [2] 원인 — 실측 확정

**콤보를 바꿔도 서버를 다시 부르지 않는다.**

| 자리 | 상태 |
|---|---|
| 프론트 콤보 값 (`period`/`item`/`partner`/`employee`/`price`) | ✅ 정상 |
| 프론트 → 서버 전송 (`qs.Add($"view={_viewType}")`) | ✅ 정상 |
| 컨트롤러 수신 (`ReportController` `[FromQuery] string view`) | ✅ 정상 |
| 서비스 SQL 분기 (`ReportService` `viewType switch`) | ✅ 정상 |
| **콤보 변경 → 재조회** | ❌ **없음 (여기가 끊긴 자리)** |

`@bind-Value="_viewType"` 만 걸려 있고 `ValueChanged` 재조회가 없다.
조회는 `조회` 버튼과 최초 진입(`OnInitializedAsync`)에서만 돈다.

**증상이 "날짜로만 나옴"인 이유** — 헤더 `GetLabelHeader()` 는 `_viewType` 을 직접 읽어
즉시 "품목"으로 바뀌지만, `_reportData` 는 최초 로드된 **기간별(날짜)** 그대로 남는다.
그래서 **헤더만 바뀌고 데이터는 안 바뀐 상태**로 보인다.

⚠️ **서버·SQL 은 멀쩡하다.** 끊긴 건 화면의 재조회 한 줄이다.
원인 한 자리 · 수정 6곳.

### 부수 발견 (함께 처리)

`_searchText` 가 조회유형 변경 시 그대로 남는다.
품목별에서 품명을 치고 업체별로 바꾸면 그 품명이 업체 필터로 넘어가 **결과 0건**이 된다.
재조회만 붙이면 이 문제가 오히려 드러나므로 **함께 비워야 한다.**

### 전자세금계산서 발행옵션 (사장님 아키텍처, 2026-08-25)

> **레거시 히트판에서 이미 사용 중인 기능** (사장님 확인).
> 새 설계가 아니라 **이식·연결 대상**이다.

1. **일괄발행** — 거래명세서에서 발행을 눌러도 국세청에 바로 안 넘어가고,
   고객사가 설정한 시간대에 일괄 전송.
   → 일괄발행 시각 **이전** 건은 국세청 미전송이므로 **임의 삭제 가능** (마이너스 계산서 불필요)
2. **즉시발행** — 국세청에 넘어간 건이므로 **삭제 불가** → **마이너스 계산서 발행 필요**
3. **반품확정 시** 국세청 발행건이면 **마이너스 수정계산서 발행 연동**
4. 전자발행된 건의 반품 요청 — **추후 논의** (사장님)

**🟢 DB 실측 — 컬럼은 이미 있다:**

| 컬럼 | 테이블 계열 | 정의 |
|---|---|---|
| `etax_mode` | 판매·세금계산서 | `scheduled`(기본) / `immediate`(즉시발행) |
| `batch_time` | 인증·테넌트·사용자 | 매일 일괄발행 시각, 기본 `18:00:00` |
