### ② [4] 숫자 — 채택
- C2: 바닥 컨트롤러 + 새 시험 = 38 중 9 빨강(기대 9 정확히) · 커밋 = 38/38 · REQUIRE_DB · SKIP 0 · 대조군 C0·C1 양쪽 초록. 되돌림 감시: 비활성 한 줄만 지우면 8 빨강(N-B1 초록) · DNS 블록만 살리면 N-B1 1 빨강 ⇒ 두 봉합을 따로 잰다. 구현자 숫자와 독립 일치(SoD).
- 전체 스위트 2855→2863(+8 = 신규 8) · 「바닥 통과 → 커밋 실패」 0 · G-R1 1건은 시간 초과 의존(코드 무관). 판정을 받친다.
- 사각: 전체 스위트는 DB 미설정 → DB 시험은 조용히 통과(리뷰서 §5-2 자인). 4클래스 필터 밖에서 이 컨트롤러를 DB 로 타는 시험이 있다면 미측정이다. 받침은 CI db-gate(REQUIRE_DB)뿐이고, 그게 실제로 돌았는지는 로그 건수로만 안다 ⇒ C1.
- 관찰(비차단 · G1 후보): 새 3클래스가 환경 직렬화 고정 목록 밖(같은 Collection 으로 직렬화는 됨). 기존 반사 게이트는 비활성 표시를 못 거른다 ⇒ 봉합의 상시 감시는 새 HTTP 음성시험 하나뿐 — 이 시험이 CI 목록에서 빠지면 감시가 조용히 사라진다.

### ③ 전달·롤백 — 조건부
- 갖춘 것: 대기 런 0 · PR 머리 SHA 재확인 · 스쿼시 뒤 파일 실재 확인 · 새 런 1개만 승인 · 외부 확인 전·후 · 로그인 뒤 목록(「200 이냐」 아님) · (B) 는 운영에서 쏘지 않고 로그로. develop 미푸시. 골격은 충분.
- 판별력 구멍(C2): 「전 ≠ 404 · 후 = 404」 는 전의 응답이 확실히 404 가 아닐 때만 뜻이 있다. 본문을 타는 요청은 무효 값에 본문이 무엇을 돌려주는지 측정 0 — 본문이 스스로 404 를 내면 전·후가 같아 판별이 무너진다. 운영 DB 를 읽는 요청이기도 하다(#39). 본문 앞 단계에서 갈리는 요청이 판별력·부작용 둘 다 낫고, 운영 실물에서 경로 변형 1종을 재는 효과도 있다(⑥).
- 롤백 기준 구멍(C4): S2 는 남은 DNS 를 승인 때 오류로 드러나게 설계했다(§7 리스크 「중」). 그 오류를 장애로 읽고 되돌리면 구멍을 다시 연다.
- 공개 시간: push→CI→머지→승인 동안 브랜치 diff 가 보이지만, 결함 위치가 이미 main 에 공개돼 추가 노출은 작다. 16:59 이후 매 시간이 노출이다 — 결재 끝나면 바로 진행.
