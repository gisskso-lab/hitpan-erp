## 1. 🔴 사장님 오더 — 원문

> **반려 ③** *"각 전표 인쇄시, 화면인쇄가 되고, 양식적용이 안됨. (거래명세서, 견적서, 수주서, 매입처리, 반품처리, 발주서)"*

> **인쇄기능 워크플로우 흐름은 이렇게 되야 함.**
> 1. 각 전표처리기능에 들어가서(수주서, 견적서, 거래명세서, 세금계산서, 발주서, 매입처리, 반품처리)
> 2. 전표에서든, 목록에서 전표를 불러오든 **인쇄버튼 클릭시**
> 3. **미리보기로 넘어가서, 어떤 양식이 적용되는지 보여줘야 함**
> 4. 그리고 **각 옵션들 선택이 가능해야함**(가령 세금계산서 공급받는자만인쇄, 공급받는자·공급자인쇄, 모두인쇄, 1장으로 ~외1건인쇄 등의 금주 논의했던 옵션)
> 5. **옵션 선택 후 최종 인쇄시, 미리보기 화면하고 동일하게 인쇄**

## 2. 🔴 PM 실측 — 사장님 지적이 전부 참이다

### 2-1 「인쇄」 단추는 **브라우저 화면 인쇄**다

전표 화면 전수 조사(`grep` + 메서드 본문 확인):

| 화면 | 「인쇄」가 실제로 하는 일 | 양식 적용 |
|---|---|---|
| 견적서 `QuotationPage` | `Js.InvokeVoidAsync("print")` | 🔴 **0** |
| 수주서 `SalesOrderPage` | `Js.InvokeVoidAsync("print")` | 🔴 **0** |
| 거래명세서 `DeliveryPage` | `Js.InvokeVoidAsync("print")` | 🔴 **0** |
| 발주서 `PurchaseOrderPage` | `Js.InvokeVoidAsync("print")` | 🔴 **0** |
| 매입처리 `PurchaseReceiptPage` | `Js.InvokeVoidAsync("print")` | 🔴 **0** |
| 반품처리 `ReturnPage` | `Js.InvokeVoidAsync("print")` | 🔴 **0** |
| 세금계산서 `TaxInvoicePage` | `PrintAsync` (같은 꼴) | 🔴 **0** |

🔴 **7화면 전부** 서버 PDF 작성기(`RenderDocumentAsync`)를 **안 탄다.** 양식지·여백·좌표·인쇄매수·절취선이 **하나도 안 먹는다.**

### 2-2 양식이 먹는 길은 **별개의 「PDF」 단추**뿐이다

| 화면 | 인쇄 단추 | PDF 단추 |
|---|---|---|
| 7화면 전부 | 1개 (화면인쇄) | 1개 (`DocService.DownloadPdfAsync` → `api/documents/{docType}/{docId}/{format}`) |

⇒ 지금 구조는 **「인쇄」는 양식 무시 · 「PDF」는 양식 적용** — **두 길이 갈라져 있다.**
🔴 고객이 양식정보설정에서 mm 를 아무리 맞춰도 **「인쇄」를 누르면 아무 의미가 없다.** 사장님 *"미리보기가 되야 양식조정이 의미가 있지"* 가 여기서도 그대로 성립한다.

### 2-3 🔴 PM 오류 자백

10/24 D-3 실측에서 나는 *"전표 화면에 인쇄/PDF 단추가 있다"* 까지만 적고 **그 단추가 어느 통로를 타는지 전수 확인을 안 했다.** 양식지 칸 12개를 세는 데 매달리다 **양식이 애초에 안 타는 길이 7개**인 것을 못 봤다. 사장님 오더 *"인쇄까지 **모두** 양식지 적용"* 의 핵심이 바로 거기였다.
🔴 검증팀 [4] 도 같은 자리를 **반쯤 보고 멈췄다**(자백 §11 — 호출부가 7곳뿐인 걸 손에 들고도 「화면이 거기 닿나」를 되묻지 않았다).

## 3. 집행 방향 (설계 확정은 [2] 결재 후)

### 3-1 🟢 바닥은 이미 있다 — D2 에서 만든 것을 그대로 쓴다

| 쓸 것 | 어디 |
|---|---|
| 정본 통로 **선택 인자** | `RenderDocumentAsync(…, PdfPreviewOverrides?, ct)` — 저장 전 옵션 주입 |
| 미리보기 **창 띄우기** | `hitpanMakeBlobUrl` / `hitpanRevokeBlobUrl` + CSP `frame-src blob:` |
| 양식 매핑 **한 벌** | `ToTemplateInfo` |

🔴 **새 작성기를 만들지 않는다.** 미리보기와 인쇄가 **같은 통로**를 타야 합격선 ⑤(*"미리보기 화면하고 동일하게 인쇄"*)가 성립한다.

### 3-2 바꿀 것

| # | 무엇 | 비고 |
|---|---|---|
| **가** | 7화면의 「인쇄」가 **화면인쇄 대신 미리보기 창**을 연다 | 🔴 `Js.InvokeVoidAsync("print")` 를 **지우지 않는다** — 미리보기 창 **안**의 「인쇄」가 그 자리를 쓴다 |
| **나** | 미리보기 창에 **옵션 칸** | 세금계산서: 인쇄매수(공급받는자만/공급자만/둘 다) · 한 장에 두 벌+절취선. 나머지 6종: 양식 선택·여백은 양식정보설정 값 표시 |
| **다** | 옵션을 **바꾸면 그 자리에서 다시 그린다** | 선택 인자로 주입 — 저장하지 않는다 |
| **라** | 창 안 「인쇄」 = **지금 보고 있는 그 PDF** 를 인쇄 | 🔴 다시 그리지 않는다. 같은 bytes 를 인쇄해야 ⑤가 참이 된다 |
| **마** | 목록에서 불러온 경우도 같은 창 | 사장님 §2 *"전표에서든, 목록에서 전표를 불러오든"* |

### 3-3 🔴 범위를 넓히지 않는 것 (등재만)

9종 PDF **품질** · 이름 체계 3가지 · `TwoCopyFormTypes` · 자료 인쇄 CSS 26곳 · 프린터별 옵셋 보정 · 용지 크기·방향·직인 3칸 · **백지 4종 로더**(결재 ㉮ — 별 칸) · `DocumentController.cs:144` `[AllowAnonymous]` PDF.

## 4. 🔴 합격선 — 「빼면 실패하나」까지 미리 적는다

| # | 합격선 | 음성 대조군 |
|---|---|---|
| ① | 7화면에서 「인쇄」를 누르면 **미리보기 창**이 뜬다 | 화면인쇄로 되돌리면 ① 이 **실패해야** 한다 |
| ② | 그 창의 종이에 **양식정보설정 값이 적용**돼 있다(여백·양식지·매수) | 양식 로드를 빼면 ② 가 **실패해야** 한다 |
| ③ | 옵션을 바꾸면 **종이가 바뀐다** | 주입을 빼면 ③ 이 **실패해야** 한다 |
| ④ | 창 안 「인쇄」가 **보고 있던 그 bytes** 를 인쇄한다 | 다시 그리게 바꾸면 ④ 가 **실패해야** 한다 |
| ⑤ | 🔴 **미리보기와 인쇄물의 글자가 완전히 같다** | 🔴 **같은 자료를 두 길에 먹여서** 잰다 |
| ⑥ | 목록 경로도 ①~⑤ 가 같다 | 전표 경로만 고치면 ⑥ 이 **실패해야** 한다 |

🔴 **⑤ 는 D2 에서 「미측정」으로 남은 합격선 ① 과 같은 축이다.** 이 차수에서 **반드시 숫자로** 닫는다.

🔴 **대조군 없는 게이트는 「미측정」으로 적는다.** 10/24 에 내가 두 번 거짓 초록을 냈다 — 게이트를 세운 뒤 **각 방어를 실제로 빼서** 단독으로 빨개지는지 확인한다.
