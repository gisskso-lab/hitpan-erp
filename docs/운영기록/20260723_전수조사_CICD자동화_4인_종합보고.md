## 0. 한 줄 결론

**자동화는 90% 완성돼 있고, 미싱피스는 딱 하나 — `deploy-update.yml` 워크플로우 파일이 안 짜여 있다.**
설계(20260720작4)·NCP 스크립트(`publish-update.sh`)·CTO 승인까지 다 됐는데 **깃→NCP 전송 다리 코드만 없어서** 게시가 사장님 수작업이다. **이 손작업 불안정이 "UPDATE 실측 0회 통과"의 구조적 진범이다.**

## 1. 현황 지도 — 자동 / 손작업 / 비어있는 다리

| 배포 대상 | 빌드 | NCP 전송 | 서명·게시 | 상태 |
|---|---|---|---|---|
| **백오피스·랜딩 웹** | `deploy-ncp.yml` 자동 | **rsync 자동** | systemd restart + healthcheck + 자동롤백 | ✅ **완성 CD (복붙 원본)** |
| **자동업데이트 zip** | `build-installer.yml` 자동 | ❌ **다리 없음 (손 scp)** | NCP `publish-update.sh` 손 sudo | ⚠️ **미싱피스** |
| **신규설치 EXE** | `build-installer.yml` 자동 | ❌ GitHub Release까지만 | 랜딩 링크·가입메일 손 갱신 | ⚠️ 갭 |

**핵심**: 웹 CD는 이미 백업→rsync→restart→5종 healthcheck→**실패 시 자동 롤백**까지 완성(`deploy-ncp.yml:107-213`). 이게 자동업데이트 CD의 검증된 패턴 원본이다.

## 2. 이미 있는 것 (재료 대부분 갖춰짐)

- **NCP 접속 Secrets 3종** `NCP_SSH_PRIVATE_KEY`·`NCP_HOST`·`NCP_USER` — `deploy-ncp.yml:87-97`에서 이미 검증된 사용 중. **재사용 가능.**
- **`publish-update.sh`** (297줄, 커밋 85206e3) — 입력검증·다운그레이드 게이트·서명·원자교체·자기검증·**자동롤백** 전부 구현.
- **`sign-manifest.sh`·`build-manifest.ps1`** — 서명 규격 단일출처, CI는 unsigned manifest까지만.
- **build-installer.yml** — EXE+update zip+unsigned manifest 산출(태그 트리거).
- **서명 키쌍(upd-v1)** — 개인키 NCP `/var/hitpan/update-keys/`(600 root), 공개키 EXE 내장. 2026-07-20 사장님 생성(헌법 #29).
- **버전 SSOT** `Directory.Build.props:33` = 현재 **1.2.39**. (1.2.40은 코드·manifest 어디에도 없음 = 아직 안 만듦)
- **manifest 현재 게시본 = 1.2.39 Major** (마이클 실측).

## 3. 없는 것 = 설계 갭 (PRD 착수용)

| ID | 갭 | 상태 | 우선순위 |
|---|---|---|---|
| **G1** | **`deploy-update.yml` 워크플로우 코드** | 설계·스크립트·CTO승인 완료, **파일 없음**, 대표결재 대기 | 🔴 **최우선** |
| G1-착수조건 | ① publish-update.sh **NCP 상주 배치** (현재 `/root/`에 임시) ② **sudoers 화이트리스트** ③ environment reviewer 게이트+CODEOWNERS ④ **webroot 기본값 버그**(`/var/www/updates.hitpan.kr` → 실서빙 `/var/www/updates`) | 미완 | 🔴 |
| G2 | 신규설치 EXE의 NCP 배포 경로 자동화 | 부재 | 🟡 |
| G3 | 출하 DDL import 스모크 CI화 (`ddl-smoke-test.sh` → GitHub Actions) | 로컬 수동 전용, 미연결 | 🟡 |
| G5 | 트리거 정책 통합 (언제 자동/언제 수동) | 미확정 | 🟡 |
| G7 | 베타/정식 채널 분리 (환경 파라미터화, 헌법 #34) | 없음 | 🟡 (영구CD 필수) |

**게시 함정 3개 (매번 손게시 사고원, 자동화로 영구 제거 가능):**
1. manifest 파일명 (CI는 `manifest.json`, 목적지 rename 필요)
2. `--webroot /var/www/updates` (스크립트 기본값 버그)
3. 채널 Major (CI channel을 게시 시 `jq`로 수정)

## 4. 자동화가 절대 깨면 안 되는 보안 경계선 (백엔드 실측)

1. **서명 개인키 NCP 전용, CI 반입 절대 금지** (C-1, 헌법 #29·#22). CI는 unsigned까지만, 서명은 NCP `publish-update.sh`에서. 개인키를 GitHub에 두면 "전 고객 PC SYSTEM 코드실행 권한을 제3자 위임".
2. **build-manifest.ps1 게이트 우회 금지** (C-2 `local_update_` 스키마 변경 차단).
3. **버전 SSOT 유지** (하드코딩 8곳 회귀 금지).
4. **manifest 서명 규격 3벌 동기화** (`UpdateManifestSigning.cs`=`sign-manifest.sh`=`publish-update.sh`).
5. **cloudflared·DNS 안 건드림 확인됨** (헌법 #29 벽 안전).

**보강 권고**: ①trufflehog 룰에 EC PRIVATE KEY 패턴 추가 ②MetaPing 400 미규명(본사 버전 가시성·성공률 집계 전제 깨짐, 별도 작지서).

## 5. SOP 다음 스텝 (사장님 지시 프로세스)

```
[현재] 전수조사 완료 (본 문서)

[다음] PM+CTO+설계팀장 → 우선순위·일정표
  ↓  4인 회의·협의 (풀스택·설계·백엔드·네트워크)
```
