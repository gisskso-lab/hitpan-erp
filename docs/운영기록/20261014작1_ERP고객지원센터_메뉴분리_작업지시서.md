## §3 갈래 A — 서버 (설계 §3)

1. `List(CancellationToken ct)` → `List(string? origin, CancellationToken ct)` — **추가만**(#1). 옛 호출은 `null` 로 들어온다.
2. `origin` 해석: `"hq"` → 본사 것만 · `"local"` → 내 것만 · **그 밖·null → 전체**. 낯선 값에 화면을 비우지 않는다.
3. 🔴 **칸 가드**: `HasOriginColumnAsync()` 가 거짓이면 **WHERE 에 origin 조건을 달지 않는다.** 없는 칸을 WHERE 에 넣으면 1054 다.
   SELECT 쪽 `'local'` 대입은 **종전 그대로**(`:247`).
4. 쪽별 `LIMIT` — 각 쪽이 자기 몫을 센다. 전체 호출은 **종전 200 유지**.
5. 🔴 `tenantId` 는 `HttpContext.Items["TenantId"]` 만 쓴다. **매개변수로 받지 않는다**(#2).
6. 숫자 칸 `COALESCE(o.attempt_count, 0)` **유지** · 응답 키 `success`·`data`·`categories`·`subTags` **무변경**.
7. 새 SQL 은 **DESCRIBE 먼저**(#13) · 빈 `catch` 금지(#15) · `float/double` 0건(#4 무관).

**금지**: `unread-count` 손대지 말 것(이미 3칸을 준다) · 새 테이블·새 마이그 0건 · 원장 무접촉(#3).

## §7 게이트표 `G-W9-*` + 🔴 음성 대조군

🔴 **게이트는 글자가 아니라 동작을 잰다**(누적 30회 지적). 각 게이트는 **봉합을 빼면 그 게이트만 FAIL** 해야 한다.
DB 게이트는 `HITPAN_REQUIRE_DB` 아래서 돌고 CI `db-gate` 초록만 증거다. 🔴 **판별은 소요시간** — DB 없이 1초에 초록이면 안 돈 것이다.

| 게이트 | 무엇을 재나 | 종류 | 갈래 | 🔴 음성 대조군 (이걸 빼면 이 게이트만 FAIL) |
|---|---|---|---|---|
| G-W9-1 | `?origin=hq` 가 **공지만** 준다 (`origin='local'` 행 0건) | DB | A | WHERE 의 `origin = 'hq'` 조건을 지운다 → local 행이 섞여 FAIL |
| G-W9-2 | `?origin=local` 이 **내 문의만** 준다 (`'hq'` 행 0건) | DB | A | 같은 조건을 `<>` 로 뒤집는다 → FAIL |
| G-W9-3 | **`origin` 없는 호출 = 종전 전체** (회귀 · #1) | DB | A | 기본값을 `'local'` 로 바꾼다 → hq 행이 사라져 FAIL |
| G-W9-4 | 공지 **N+1건**을 깔아 LIMIT 를 채운 뒤에도 **내 문의가 목록에 산다** | DB | A | 쪽별 LIMIT 를 단일 `LIMIT 200` 으로 되돌린다 → 내 문의 0건 FAIL |
| G-W9-5 | 남의 `tenant_id` 행은 `origin=hq` 로도 **안 넘어온다**(#2) | DB | A | `WHERE r.tenant_id` 를 지운다 → 남의 행이 보여 FAIL |
| G-W9-6 | `unread-count` **직렬화 → 사이드바 모델 역직렬화**로 **3칸이 다 찬다** | DB+정적 | B | 미러 모델에서 `HqCount` 를 빼면 역직렬화 0 → FAIL. 🔴 **덧붙여 `Sidebar.razor` 소스에 3칸 선언이 있는지 문자열로 대조**한다 — 미러만 재면 실물과 달라도 통과한다 |
| G-W9-7 | 목록 응답 **직렬화 → 공지 화면 모델 역직렬화**가 안 터진다 (비널러블 `int` 자리) | DB+정적 | C | 서버 `COALESCE(o.attempt_count,0)` 를 지운다 → `null` 이 들어가 역직렬화 폭발 FAIL |
| G-W9-8 | 사이드바에 **「고객지원센터」 MudNavGroup** + 하위 NavLink **2개**(`/support/cs`·`/support/notice`) | 정적 | B | 묶음 제목 한 글자를 바꾼다 → FAIL |
| G-W9-9 | 업데이트 2종이 **가드 안**에 있고 **자료관리 묶음에선 빠졌다** (줄 순서로 대조) | 정적 | B | 가드 `@if (_isTenantAdmin)` 을 지운다 → 가드 밖 판정 FAIL |
| G-W9-10 | 🔴 경로 2개·낱말 2개 **무변경** (`UpdatePath`·`RollbackPath`·`MenuUpdate`·`MenuRollback` 상수값 고정) | 정적 | B | 낱말 한 글자를 바꾼다 → FAIL (기존 `LocalSwapUiGateTests` 도 같이 FAIL — **두 개가 같이 FAIL 해야 맞다**) |
| G-W9-11 | `SidebarIssueLink` 가 **새 대메뉴 이름**이고 레포 Web 소스에 **「자료관리 ›」 0건** | 정적 | B | 글자를 종전으로 되돌린다 → FAIL |
| G-W9-12 | `@page "/support/cs"` **생존** + `@page "/support/notice"` **신설** (둘 다 있어야 통과) | 정적 | C | 새 `@page` 를 지우거나 옛 `@page` 를 바꾼다 → FAIL |
| G-W9-13 | 입구 분기 — 배너에 `/support/notice` 와 `_hq`·`_reply` 조건이 **같은 자리**에 있고, 상세 [목록으로] 가 **`_isHq`** 로 갈라진다 | 정적 | C | 배너 목적지를 `/support/cs` 고정으로 되돌린다 → FAIL |
| G-W9-14 | `src/HitPan.Web/Pages/Support/**.razor` 에 **하드코딩 hex·`border-radius:NNpx`·`font-size:NNpx` 0건** | 정적 | D | `#6B7280` 한 자리를 되돌린다 → FAIL |
