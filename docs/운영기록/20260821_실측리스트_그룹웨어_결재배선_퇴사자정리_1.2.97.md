## 0. 왜 이 표가 필요한가

이번 봉합 7건은 **빌드 0/0 · 시험 619개 · CI 초록 · 대조실험**까지 통과했다.

> 같은 방식으로 확인하면 또 놓친다.

## 1. 🔴 실측 3건 — 쉬운 순서

### M1. 초과근무 승인버튼이 일반 직원에게 안 보인다 🟢 가장 쉬움

| | |
|---|---|
| **준비** | 일반 직원 계정(부모계정 아님) |
| **경로** | 로그인 → 그룹웨어 → 초과근무 |
| **기대** | 목록에 **승인·반려 버튼이 없다** |
| **대조** | 부모계정으로 같은 화면 → **버튼이 보인다** |

🔴 **대조가 핵심이다.** 직원에게 안 보이는 것만 확인하면
*"원래 아무에게도 안 보이는 것"* 과 구분이 안 된다.

⚠️ 봉합 전에는 **본인이 신청한 초과근무를 본인이 승인하는 버튼**이 떴다.

---

### M2. 휴직 결재가 실제로 올라간다 🟡

| 단계 | 확인 |
|---|---|
| 1 | 설정 → 결재설정에 **"휴직" 행이 뜬다** ← 봉합 전엔 아예 없었다 |
| 2 | 휴직을 **켠다**(사용 ON) |
| 3 | 그 문서유형에 **결재선을 지정**한다 (결재자 1명 이상) |
| 4 | 그룹웨어 → 휴직관리 → 휴직 신청 → **[결재상신]** |
| 5 | 🔴 **결재함(결재 대기)에 그 건이 뜬다** |
| 6 | 승인 → 🔴 **휴직 신청서 상태가 바뀐다** |
| 7 | 승인 → 🔴 **사원 상태가 '휴직' 으로 바뀐다** (시작일이 지난 건만) |

🔴 **5번이 진짜 게이트다.** 봉합 전엔 버튼을 눌러도 **아무 일이 없었다**(조용히 실패).
🔴 **6·7번이 그다음이다.** 결재는 갔는데 원본이 안 바뀌면 그것도 거짓봉합이다.

⚠️ **3번을 빠뜨리면 5번이 실패한다** — 결재선이 없으면 상신이 안 올라간다.
   그게 결함이 아니라 정상 동작이다(화면이 이유를 말해 준다).

---

### M3. 퇴사 시 결재선 해제 + 미결 회수 🔴 되돌리기 어려움

| | |
|---|---|
| ⚠️ **환경** | 🔴 **테스트 환경에서만.** demo 운영 금지(헌법 #39) |
| **준비** | 직원 A를 어느 문서유형의 **결재자로 지정** → 다른 사람이 그 문서를 **상신**(pending 상태로 둠) |
| **실행** | 직원 A를 **퇴사 처리** |
| **기대 ①** | 결재설정 → 그 문서유형 결재선에서 **A가 빠진다** |
| **기대 ②** | 🔴 그 pending 문서가 **'취소' 로 회수된다** |
| **기대 ③** | 결재선을 **다시 편집할 수 있다** (종전엔 pending 때문에 막혔다) |
| **기대 ④** | ⚠️ **다른 사람이 결재자인 pending 은 그대로 살아 있다** |

🔴 **기대 ④가 안전 확인이다.** 범위를 좁혔는지 보는 자리 —
테넌트 pending 을 통째로 취소하면 **멀쩡한 결재까지 죽는다.**

## 3. 실패 시

| 증상 | 먼저 볼 곳 |
|---|---|
| 결재설정에 "휴직" 안 뜸 | 업데이트가 실제로 적용됐나 (버전 확인) |
| 상신했는데 결재함에 없음 | **결재선을 지정했나**(M2-3) |
| 승인했는데 원본 그대로 | 결재선 **마지막 단계**까지 갔나(중간 단계면 원본은 안 바뀐다) |
| 퇴사했는데 결재선에 남음 | 퇴사 처리가 **실제로 커밋됐나** |
