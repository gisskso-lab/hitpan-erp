## §4. 🔴 미결 — 이것부터

### 4-1. G-M4 게이트 판정 (PM · 즉시)

2차 재작업에서 **G-M4 가 빨간불**이 됐다. 그 게이트는 「①단을 건너뛰면 안전장치 만들기가 **실패한다**」를 단언하는데, **(가) 아래서는 ③단이 스스로 건너뛰어 실패하지 않는다.** CTO 판정문 §4 는 V4 세 단언만 다루고 **G-M4 칸이 비어 있다 — 계약의 빈칸**이다.

- 구현자가 **고치지 않고 빨간불 그대로 올린 것은 옳다**(초록 만들려 단언 무르기 = 명시 반려).
- **PM 잠정 판정**(사장님께 보고했고 반대 없음): 이건 「단언을 무르는 것」이 아니라 **「무엇을 재는지가 바뀐 것」**. 순서 의존 자체가 (가)에서 사라졌다. 단 **셋을 한꺼번에** 걸어야 약해지지 않는다 — ⓐ 마이그가 **실패하지 않는다** ⓑ 안전장치가 **안 생긴다** ⓒ 감사 기록 **1줄**. 셋을 다 안 걸면 무르는 것이 맞다.
- ⚠️ **아직 문서에 기록하지 않았다.** 판정을 확정하면 작업지시서 §9-3 에 적고 게이트를 고친다.

## §5. 함정 (오늘 새로)

1. 🔴 **「크다」도 반증해야 한다** — 병렬이슈32 를 P0 로 올렸다가 사장님 반문 *「이걸 왜 해야되지」* 로 P2 로 내렸다. 「쉽다」를 의심하듯 **규모를 키우는 방향도 의심**해야 한다. 연쇄(빨간불→비밀번호→공개저장소)에 끌려갔다.
2. 🔴 **주석을 실측으로 착각했다** — 「3306 은 localhost 바인딩」이라 보고했는데 실측하니 **`0.0.0.0` 으로 열려 있고 방화벽 허용 규칙(`HitPan MariaDB (TCP 3306)` · 사설망)도 있다.** 주석은 코드가 아니다.
3. **TruffleHog PR 스캔은 PR 안 모든 커밋 이력을 읽는다** — 최종 트리가 깨끗해도 중간 커밋이 걸린다. 해법은 **커밋 1개짜리 새 PR**(강제 수정·제외 목록 금지). 새 브랜치 push 스캔은 저장소 전체를 봐 **늘 빨간불**이라 판정에서 뺀다.
4. **스쿼시 트리 동일성 검증 기준** — `git diff <원 head> <새 커밋>` 은 **main 이 앞서 있으면 그 차이까지 잡힌다.** 올바른 비교는 `git diff origin/main...<원 브랜치>` **vs** `git diff origin/main <새 커밋>` 두 diff 가 같은지.
5. **에이전트를 96분 뒤에 이어 부르면** 캐시가 만료돼 대화 전체를 다시 쓴다 — 훅이 막는다. **새 에이전트에 산출물 주소만** 넘긴다.
6. `.claude/worktrees/agent-*` 중 일부는 **셸 실행이 거부**된다(파일 쓰기만 가능). 그 안에서 빌드·게이트·커밋을 시키면 막힌다.
7. `ls | sort | tail` 은 **문자열 정렬**이라 `DB-119` 가 `DB-99` 앞에 온다. 마이그 번호는 **숫자 정렬**로 봐야 한다.
8. `registry.json` 은 **BOM** 이 있어 그냥 `JSON.parse` 하면 깨진다.
