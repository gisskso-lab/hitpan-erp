## [2] 조사로 드러난 것

### 🟢 수주 자동생성은 이미 돌고 있었다

`SalesService` 가 수주 없이 들어온 거래명세서에 대해 **이미 수주서를 자동 생성**하고 있었다
(`closed` 상태, `is_auto=1`, 채번은 정상 수주와 동일 헬퍼). 자동 생성분은 수주 목록에서 숨겨진다.

**없던 것은 「안내」였다.** 사용자는 수주서가 생겼다는 사실을 알 길이 없었다.

### 🔴 별개 사고 — 화면이 문서번호를 지어내고 있었다

브레드크럼이 `$"수-{날짜}-001"` 을 **문자열로 만들어** 표시했다.
실제 자동생성분이 `-004` 여도 화면은 **항상 `-001`** 이었다.
서버가 수주번호를 안 내려줘서 화면이 지어낸 것이다.

**견적번호도 같은 사고**였다 (`$"견-{날짜}-001"`). 이건 게이트 시험이 잡아냈다 — 수주만 고치고
견적을 놓쳤는데 시험이 걸러냈다.

### 🔴 작성자 식별자 모순 — 착수 전 결재가 필요했던 자리

| 자리 | 무엇을 쓰나 |
|---|---|
| 현황·순위표·분석 사원별 집계 (4곳) | `e.user_id = created_by` 로 **조인** |
| 견적 저장 코드 | `created_by` 에 **employee_id** 를 넣음 |

두 값은 **별개 GUID** 다 (`TenantMiddleware` 에 명시). 이 조인은 **절대 매칭되지 않는다.**
견적이 0행이라 표면화만 안 됐을 뿐이다.

⚠️ **이 상태로 나머지 전표에 작성자를 채웠다면 조인이 전부 죽거나 엉뚱한 사람이 떴다.**
그래서 착수 전에 결재를 받았다 → **`user_id` 로 통일**.

### 🟢 DDL 작업 불필요

견적·수주·판매·반품 4개 테이블 모두 `created_by varchar(36) NULL` 을 **이미 갖고 있다.**
NULL 허용이라 **과거 전표 공란** 결재와 그대로 맞는다. **마이그레이션 0건.**

## [3] 봉합

### 3번 — 수주 자동생성 안내

| 자리 | 내용 |
|---|---|
| 저장 전 팝업 | 사장님 문구 그대로. 「저장」/「취소」 — 사용자가 멈출 기회를 준다 |
| 서버 반환 확장 | `(Id, DocumentNumber)` → `(Id, DocumentNumber, **AutoCreatedOrderNo**)` |
| 저장 후 알림 | 실제 생성된 수주번호를 띄우고 브레드크럼 갱신 |
| 가짜 번호 제거 | 수주 3곳 + 견적 3곳 — 지어내는 대신 **서버 실물** 또는 **공란** |
| 상세 조회 | `LinkedOrderNo` 추가 (`sales_orders` 조인) |

**호출부 전수 정합** (헌법 #12): 구현 1 + 호출 3곳(컨트롤러·전환경로·AI도구) 전부 맞췄다.
전환 경로는 `OrderId` 를 넘기므로 자동생성이 일어나지 않아 세 번째 값을 버린다.

### 4번 — 전표 작성자 기록

| 전표 | 종전 | 봉합 |
|---|---|---|
| 견적서 | `created_by` 에 **employee_id** (잘못된 체계) | `user_id` 로 정정 |
| 수주서 | `employee_id` NULL 하드코딩, `created_by` 누락 | `CreatedBy` 대입 (수동·자동 둘 다) |
| 거래명세서 | `CreatedBy` 대입 없음 | `CreatedBy` 대입 |
| 매출반품 | INSERT 컬럼에 `created_by` 없음 | 컬럼·파라미터 추가 |

**읽는 쪽** — 목록 4개 SQL 에 `ec.user_id = X.created_by` 조인 + DTO 4개 + Web 모델 4개
+ 매핑 4곳 + **그리드 4곳에 「작성자」 열**.

⚠️ **매핑을 빠뜨리면 그리드가 항상 공란**이 된다 — 값을 저장해도 목록까지 실어 보내지 않으면
화면에 안 뜬다. 4곳 전부 채웠다.

### 손대지 않은 것

- **현황·순위표·분석의 사원별 집계** — 이미 동작 중이다. 조회유형에 「사원별」이 이미 있다
- `employee_id`(담당 영업사원) — 작성자와 **의미가 다르다.** 사장님 결재는 작성자 기준
- 과거 전표 — **공란** (사장님 결재). 없는 사실을 지어내지 않는다
- `tax_invoices` — `issued_by`(user_id, NOT NULL)로 이미 6만여 건 채워져 있다
