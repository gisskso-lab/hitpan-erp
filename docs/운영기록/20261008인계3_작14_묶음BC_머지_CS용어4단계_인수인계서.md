### #494 가 왜 중요한가 (그냥 시험 수정이 아니다)

1. **게이트가 거짓으로 통과하고 있었다**: 응답을 글자로 바꿀 때 기본 설정이 **한글을 `\uXXXX` 로** 바꾼다.
   그래서 「승격 초안에 회사명이 없어야 한다」는 **음성 단언이 늘 통과**했다 — 유출을 **감지 못 하는 상태**였다.
2. 그 봉합 뒤에 **진짜 제품 결함**이 드러났다: 백과사전 문서를 **폐기**해도 그 문서의 **옛 승인 판**이
   재사용 재료·.MD 미러로 계속 나갔다. 묶음 D 에서 AI 가 이 경로를 읽으면 **틀린 근거로 고객에게 답이 나간다.**
   ⇒ 최신 판을 상태와 무관하게 고르고 **그 최신 판이 승인일 때만** 내보내도록 봉합(여전히 WHERE 절 배제).

## §3 🚨 P0 — 운영 백오피스 CS 화면 500 (사장님 손)

**증상**: `back.hitpan.kr` 에서 CS 창구·CS 백과사전 메뉴를 누르면 500.

**원인(근거 3개)**:
1. `deploy-ncp.yml` 에 **SQL 적용 단계가 0개**다(빌드·게시·재기동만).
2. 표를 만드는 것은 백오피스 API 기동 시 `SchemaMigrator` 인데 **`HITPAN_BO_AUTO_MIGRATE=1` 일 때만** 돈다
   (기본 꺼짐 · 통제권은 사장님 · #29).
3. 표가 없으면 `/admin/cs`·`/admin/kb` 의 첫 조회가 터진다.

**처방 ⓐ(권고 · 설계된 정식 경로)**: 백오피스 API 를 `HITPAN_BO_AUTO_MIGRATE=1` 로 **한 번** 재기동.
번호순·멱등이라 이미 들어간 것은 건너뛰고 빠진 것(30·31·32·40·41·42)만 적용된다.
**되돌림**: 스위치를 끄고 재기동(표는 남지만 추가만 된 것이라 기존 동작 무영향).
**⚠️ 위험**: 마이그가 하나라도 실패하면 **API 가 기동을 거부**한다(불일치 잠복 방지 설계) ⇒ 재기동 직후 접속 확인 1회.

**처방 ⓑ(비권고)**: 운영 DB 에 SQL 직접 적용 — #39 위반.

🟢 **ERP 쪽지는 안 사라진다**: 본사가 거부하면 ERP 로컬 큐에 남아 재시도하고, 표가 생기는 순간 밀린 것이 올라간다.
🟢 **main 의 41번 SQL 은 멀쩡하다** — 아래 §6 의 `--` 사고는 **가지에서만** 있었다. 지금 재기동해도 안전하다.
⚠️ 단 **#495 머지 뒤**에 재기동하려면 그 안의 41번 봉합이 함께 들어간 뒤여야 한다.
