## 2. 게시 전 조건 (G)
- **G-1** 되돌림 판을 다시 정한다: 「사장님 PC 에 지금 깔린 1.3.48 트리」를 N 보다 큰 번호·Major 로 게시한다. 번호·트리·SHA 를 문서에 적고, 1.3.49 예약은 ⬛ 로 표시한다.
- **G-2** NCP 여유를 실측해 기록한다. 1.3.47·1.3.48 게시 뒤로는 ⬜미기록이다 · 게시 1회에 임시로 약 730MB · 문턱 1200MB. N + N+1 + 되돌림 1회 = 3회분이 되는지 보고 게시한다.
- **G-3** 사장님 PC C: 여유를 확인한다. N 은 옛 워치독이 적용하므로, N 이 blocked 되면 이번에 고치는 막다른 길(재기동 전까지 [예] 무시)이 N 자신에게 그대로 나타난다(9/29 1.3.47 전례).
- **G-4** N+1 의 동의 사슬이 막혔을 때 빠져나갈 절차를 게시 **전에** 문서로 남긴다(사장님 PC 에서 누가 무엇을 하나 — 서비스 재시작이면 #29 사전 승인). 되돌림도 같은 사슬을 타므로 게시한 뒤에는 늦다.
- **G-5** 문서 상태: 병렬이슈 02 카드와 INDEX 의 「🟡코드」를 ✅봉합으로 바꾼다(근거 = db-gate 405 · [SKIP] 0). 병렬이슈 03 의 N-UPD7 착수 조건 (b)(c)와 게이트 「익명 N회 → 동의 행 ≤1」을 작업지시서 §2 로 옮긴다([3-V] 2차 §4).

## 3. 사장님 결재 · 보고 (사람·사건으로 여쭌다)
- **S-1** 업데이트 기록 장치가 고장 난 드문 PC 에서는, 약 3분 뒤 옛 방식으로 돌아가 전에 누른 [예]로 재부팅할 때마다 한 번씩 다시 설치를 시도합니다(업데이트가 영영 막히지 않게 하려는 것). 「실패하면 반드시 다시 묻는다」에서 이것 하나만 예외입니다. 괜찮으십니까?
- **S-2** 이번 게시는 옛 방식으로 설치되고, 「실패하면 다시 묻기」는 그다음 게시부터 효력이 납니다. 사장님 PC 확인도 두 번 합니다(이번 = 사이드바·팝업 모양·다른 PC 안내 / 다음 = [예] 한 번에 설치 시도 한 번). 「실패한 뒤 다시 묻는」 장면은 사장님 PC 에서 일부러 만들지 않고 시험으로만 확인했습니다. 이대로 게시를 승인하십니까?
- **보고 R-1** [예]·[나중에]는 로그인한 화면 기준으로 메인PC 에서만 누를 수 있습니다. 로그인 창의 [업데이트] 버튼(지금 고객 PC 에서 안 먹음)은 N-UPD7 에서 같은 원칙으로 고칩니다.
- **보고 R-2** 이미 끝난 업데이트를 띄워 둔 옛 창에서 [예]를 누르면 「잠시 후 다시 안내」가 뜨지만 안내는 다시 오지 않습니다(설치는 되지 않아 안전합니다). 다음 화면 작업(N-UPD11)에서 문구를 바로잡습니다.
