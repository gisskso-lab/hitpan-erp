## 0. ⭐ 사장님 오더 (원문 그대로 — 이 문서의 원본)
> "일해야지 쉬면 안되지"

**해석**: 어제 보고서 §5 「내일 할 일」에 올려 PM 이 결재받은 4건을 이어서 실행하라는 오더.
본 지시서는 그중 **4번(로컬 main 정렬)** 을 명문화한 것이다.
1·2번은 사장님 게시 1회가 선행조건이라 착수 불가, 3번은 사장님 머지가 선행조건이라 착수 불가.
**따라서 오늘 PM 이 단독으로 완결 가능한 유일한 건이 4번이다.**

오더에 없던 요구를 넣지 않는다. 범위는 어제 보고서 §5-4 한 줄로 한정한다.

## 1. 오더를 이렇게 이해했다 (명문화)

- **사장님 의중**: 사장님 손을 기다리는 동안 PM 이 놀지 말고, 손 없이 되는 것부터 끝내라.
- **안 하면 무슨 일이 나는가**: 로컬 `main` 이 4월 상태(`a271400`)로 782 커밋 뒤처져 있다.
  이 PC 에서 `main` 을 체크아웃하는 순간 **4월 코드가 작업 디렉터리에 펼쳐진다.**
  다음 세션이 그걸 최신 main 으로 오인하면 → 옛 코드 기준 판단 = 받아쓰기 사고(헌법 #32·#33).
  7/28 인수인계서에도 *"로컬 main 쓸 일 생기면 fetch 후 정렬 필요"* 로 이미 경고가 올라와 있다.

- **실측 근거** (추측 금지, 헌법 #32):

| 확인 명령 | 결과 |
|---|---|
| `git log --oneline -1 main` | `a271400` (2026-04-09 init) |
| `git log --oneline -1 origin/main` | `649ed88` (PR #11 머지) |
| `git rev-list --count main..origin/main` | **782** (뒤처진 커밋) |
| `git rev-list --count origin/main..main` | **0** ← 로컬 고유 커밋 없음 |
| `git merge-base --is-ancestor main origin/main` | **YES** — 순수 조상 |

> **핵심**: 로컬 고유 커밋이 **0건**이므로 이 정렬은 **잃을 것이 없는 fast-forward** 다.
> 병합도 rebase 도 아니고 포인터만 앞으로 민다. 충돌 발생 여지가 구조적으로 없다.

## 2. 무엇을 하는가 (범위)

### 하는 것
- [ ] `git fetch origin` 으로 원격 최신 확보 (완료)
- [ ] 로컬 `main` 을 `origin/main`(`649ed88`) 으로 **fast-forward only** 이동
- [ ] `develop` 브랜치로 복귀 — 작업 브랜치는 develop 유지
- [ ] 정렬 결과 실측 후 개발명세서 기록

### 하지 않는 것 (명시)
- ❌ **push 하지 않는다.** 원격 main 은 이미 `649ed88` 이다. 보낼 것이 없다.
- ❌ **develop → main 머지 하지 않는다.** 별건이며 PR·Ruleset·사장님 승인 필요.
- ❌ **`--force` 계열 일체 금지.** ff-only 로만 움직인다.
- ❌ **main 에서 작업하지 않는다.** 정렬 즉시 develop 복귀.
- ❌ 어제 §5 의 1·2·3번은 이 지시서 범위 밖 (선행조건 미충족).

## 3. 헌법 체크

| 조항 | 왜 걸리나 | 어떻게 지키나 |
|---|---|---|
| #1 덮어쓰기 금지 | 브랜치 포인터 이동이 이력 덮어쓰기가 될 수 있음 | ff-only 사용. 로컬 고유 커밋 0건 실측 확인 — 덮어쓸 이력 자체가 없음 |
| #32 받아쓰기 금지 | "뒤처졌다"를 감으로 판단하면 안 됨 | §1 실측표 5종 명령으로 확정 |
| #42 문서 근거 | 코드/브랜치 조작 전 문서 선행 | 본 지시서가 근거. PM 결재 후 착수 |

**🚨 예외 5개 해당 여부**: #29(인프라 조작) **해당 없음** — 로컬 git 브랜치 포인터 이동은
cloudflared·DNS·방화벽·서비스·레지스트리 어디에도 속하지 않는다. 원격 조작 0건, push 0건.

## 4. 어떻게 하는가 (구현 지시 — [3] 개발팀용)

- 지휘: **PM(개발팀장)** — 단독 실행 (git 조작 1건, 서브에이전트 불필요)
- 실행 순서:
  1. `git fetch origin --prune` (완료)
  2. `git branch -f` 금지 → **`git fetch origin main:main`** 사용
     (develop 체크아웃 상태를 유지한 채 로컬 main 을 ff. 체크아웃 왕복 불필요 = 작업 디렉터리 무손상)
  3. 실측: `git log --oneline -1 main` 이 `649ed88` 인지
  4. 실측: `git status --short` 로 작업 디렉터리 변화 0 확인
- 산출물: **개발명세서** → `docs/개발/브랜치정렬/20260730_개발명세서_로컬main_정렬.md`

> **왜 checkout 이 아니라 `fetch origin main:main` 인가**:
> checkout 하면 4월 코드가 실제로 디스크에 펼쳐졌다가 되돌아온다. 그 순간 빌드 산출물·IDE 인덱스가 흔들린다.
> `fetch` 로 refs 만 갱신하면 작업 디렉터리는 develop 그대로다. **더 안전한 경로를 택한다.**
