## §3 원인 — 한 줄로

**운영은 MySQL 8.0.45, 우리 CI 는 `mariadb:11.4`.** SQL 이 MariaDB 전용 `ALTER … ADD COLUMN IF NOT EXISTS` 를 써서
MySQL 8 이 **1064** 로 거부하고, 적용기는 첫 실패에서 기동을 중단한다 ⇒ `11` 번 이후 **전부** 운영에 못 들어갔다.

> `MySqlException: You have an error in your SQL syntax … near 'IF NOT EXISTS approved_at_dt`

🔴 **게이트 수십 개가 못 잡은 이유는 하나 — 판이 하나였다.** 백오피스 스키마를 적재하는 게이트가 전부 MariaDB 에서만 돌았다.
⇒ 재발 방지의 본체는 봉합이 아니라 **판을 하나 더 붙이는 것**이고, 그래서 CI 에 `bo-mysql8-gate`(mysql:8.0)를 신설했다.

## §5 교훈 (다음 사람에게)

1. 🔴 **운영 DB 종류를 모르고 DDL 을 쓰지 마라.** 백오피스=**MySQL 8** / ERP=**MariaDB** — **두 판이다.**
2. 🔴 **게이트가 한 판에서만 돌면 다른 판의 사고는 영원히 안 잡힌다.** 게이트 개수는 증거가 아니다.
3. 🔴 **「파일이 서버에 갔다」 ≠ 「적용됐다」.** 적용기는 스위치가 켜질 때만 돈다. 배포만으로는 스키마가 안 들어간다.
4. 🔴 **머지 직전 PR 머리 SHA 를 다시 확인하라.** GitHub API 가 **5분간 옛 SHA** 를 보고했고(`mergeStateStatus=UNKNOWN`), 그 상태로 머지돼 봉합 한 커밋이 빠졌다. 10/8 에 적어 둔 행동을 내가 안 했다.
5. 🔴 **여러 절 `ALTER` + 「이미 있다」 관용 = 조용한 누락.** [4] 가 찾았다. `32`(4절)·`42`(6절)가 그 모양이고 `44`(3문장)가 올바른 모양이다.
6. 🔴 **1차 전수조사는 「줄 머리」만 셌다.** `FOREIGN KEY IF NOT EXISTS` 가 이어진 줄에 있어 grep 이 놓쳤다 — 게이트가 잡았다.
7. 🔴 **여러 줄 붙여넣기가 서버 창에서 깨진다**(`^[[200~`). 사장님께 드리는 명령은 **한 줄씩** 끊어 드린다.
