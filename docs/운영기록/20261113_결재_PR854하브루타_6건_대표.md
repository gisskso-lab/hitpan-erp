## 3. PM 이 읽은 뜻 (범위)
- 6건 모두 **착수 승인**이다. 각 건은 루틴([1-V] → [2] → PM 결재 → [3] ⟷ [3-V] ∥ [4] → [4-X](대상 결정 3인 → CTO → 대표) → [5] → [6])을 그대로 밟는다. 「결재했으니 바로 바꾼다」로 읽지 않는다.
- 1번의 실제 설정 변경(ruleset · develop)은 #29 사전 승인을 받은 것으로 본다. 다만 **어떤 검사를 필수로 거는지 · develop 을 어떻게 막는지는 [1-V] · [2] 뒤 대표 확인을 다시 받는다.** 근거: 흔들리는 검사를 필수로 걸면 머지가 막힌다(CI 간헐 빨강 선례 · MEMORY NU1902 · K35).
- 3번은 비공개 트랙이다. 공개 문서 · PR 에 값 · 경로 · 접속법을 적지 않는다. 기록 위치는 [1-V] 에서 따로 정한다.
- 5번의 격리 환경(별도 OS 사용자 또는 VM)은 PC 설정 변경이다. 만들기 전에 설계안으로 대표 확인을 받는다(#29).
- 6번은 PR #854(초안 · 머지 금지)의 PRD 를 `docs/운영기록/` 으로 옮기는 것이다. 파일 이동과 INDEX 2곳(뺄 곳 · 넣을 곳)만 한다.
- S4 · HQA 관문 ① 은 이 6건과 독립이다. S4 진행을 막지 않는다.
- 관제소 의제는 대표 판단으로 종결됐다(Codex 사용 없음 · 현행 유지). 6건에 포함되지 않는다.
