## §0 범위 — 백오피스만. ERP 는 **다음 작업**

| 절 | 오더 | 하는 일 |
|---|---|---|
| **A** | ⓞ 전화접수 창 | 「고객사 코드」 → **고객사명 입력 시 자동조회·자동입력** |
| **B** | ① 요금제 | **새 요금제 등록**(지금 생성 API 가 없다) + **「제외」 버튼**(과금·노출에서 빼기) |
| **C** | ③ 쪽지 | **본사 선발신**(전달 대기 큐) + **보관기한 설정** + **임의 폐기**(흔적 남김) |

🚫 **이 작업에 섞지 않는 것**
- **대리점 구독요금 면제정책** — 요금제(상품)가 아니라 **고객사·대리점 속성** 축이다. 별건 트랙(§6-1)
- **ERP 수신 자리** — 다음 작업(ERP CS 파이프라인 설계·개발·봉합)
- ERP 코드 · `installer/` 안의 파일(45번 SQL **추가**만) · 배포 워크플로 · 워치독 · 시리얼

## §1 절 A — 고객사명 자동조회

| # | 할 일 |
|---|---|
| A-1 | `GET api/admin/cs/tenant-lookup?q=` 신설 — `(company_name LIKE @Q OR tenant_code LIKE @Q)` · **`tenantCode`·`companyName` 두 칸만** 돌려준다(#22 데이터 최소주의) · `LIMIT 20` |
| A-2 | 화면 `AdminCsListPage.razor` 전화접수 칸을 **`MudAutocomplete`(고객사명)** 으로 — 고르면 코드가 **자동 입력**되고 작은 글씨로 보인다 |
| A-3 | `POST api/admin/cs/phone` **계약 무변경** — 화면이 코드를 채워 보낸다(서버 축 손대지 않는다) |

🔴 왜 기존 `GET admin/tenants?search=` 를 안 쓰나: 그 입구는 `[BoPermission("tenants.list")]` 라 **CS 담당 계정이면 403** 이 될 수 있고, 고객사 9칸을 다 돌려준다. CS 화면에는 **2칸**만 필요하다.

## §2 절 B — 요금제 등록 + 제외

| # | 할 일 |
|---|---|
| B-1 | `POST api/admin/pricing/plans` 신설 — `PUT` 과 **같은 칸 구성** · `plan_id` 중복이면 **409** · `pricing_history` 에 `action='create'` 1줄(#3 INSERT ONLY) |
| B-2 | 화면 `AdminPricing.razor` 에 **「새 요금제」 폼** — 0행에서도 첫 등록이 된다 |
| B-3 | 화면에 **「제외」 버튼** — 이미 있는 `POST plans/{id}/toggle-active` 를 **사람이 쓸 수 있게 노출** |
| B-4 | 제외는 **행을 지우지 않는다** — 과금·노출에서 빼는 것(이력·감사 보존) · 되돌리기(포함) 같은 버튼으로 |

🔴 **「제외」 ≠ 「대리점 면제」.** 면제는 고객사·대리점 속성이라 요금제 제외로는 안 된다 — §6-1 별건.

## §3 절 C — 쪽지 (선발신 · 보관기한 · 폐기)

### §3-1 본사 선발신 — **전달 대기 큐** (사장님 결재 2026-10-11)

ERP 수신부는 **원본 티켓이 없는 답을 조용히 버린다**(선행검증 §4-2). 그래서 지금은 보내는 척하지 않는다.

| # | 할 일 |
|---|---|
| C-1 | 새 표 **`bo_cs_outbound`** — 선발신 쪽지 큐(`delivered_at NULL` = 전달 대기) |
| C-2 | `POST api/admin/cs/outbound` — 고객사 + 본문 + **용도**(promo/event/billing/etc) · 금지필드 검사는 **기존 한 벌**(`BoForbiddenFieldScanner`) 재사용 |
| C-3 | `GET api/admin/cs/outbound` — 목록 + **전달 상태**(대기/전달됨) |
| C-4 | 화면: 「고객사에 쪽지 보내기」 패널 + 목록. 🔴 **「전달 대기 — ERP 수신 준비 중」으로 정직하게 보인다**(「보냄」이라고 말하지 않는다) |
| C-5 | ERP 통로가 열리면 쌓인 것이 자동으로 나간다 — **그 코드는 다음 작업**(이 표가 그 입구다) |

### §3-2 보관기한 — 설정은 된다, **자동 삭제는 안 한다**

| # | 할 일 |
|---|---|
| C-6 | 새 표 **`bo_cs_retention_policy`** 1행 — `retain_days` (**NULL = 무기한**) · 누가 언제 바꿨나 |
| C-7 | `GET/POST api/admin/cs/retention` — 조회·설정 |
| C-8 | `GET api/admin/cs/purge-candidates` — 기한 지난 **미폐기 쪽지 목록**(사람이 보고 고른다) |
| C-9 | 🔴 **자동 삭제 0** — 기한이 지나도 **스스로 지우지 않는다.** 「폐기 후보」로만 보여주고 사람이 확정한다(히트판 반자동 원칙 · 분쟁 증거 소실 방지) |

### §3-3 임의 폐기 — **몸통은 지우고, 지웠다는 사실은 남긴다**

| # | 할 일 |
|---|---|
| C-10 | `bo_cs_tickets` 에 `purged_at` · `purged_by` · `purge_reason` **3칸 추가** |
| C-11 | `POST api/admin/cs/{id}/purge` — 본문·식별 가능 내용을 비우고 `purged_*` 를 채운다 |
| C-12 | `bo_audit_log` 에 1줄(`action='cs.purge'` · 대상 · 사유) — **몸통은 지워도 지웠다는 사실은 안 지운다** |
| C-13 | 화면: 목록·상세에 **「폐기됨」** 표시(내용 없음) · 폐기 버튼은 사유 입력 필수 |

🔴 **왜 행을 통째로 지우지 않나**: `bo_cs_ticket_logs`·`bo_cs_replies` 가 그 티켓을 가리킨다. 통째 삭제는 이력을 함께 지우거나 FK 로 실패한다.
또 **「언제 누가 무엇을 지웠나」가 사라지면 고객 분쟁에서 우리 쪽 증거가 없다.**
