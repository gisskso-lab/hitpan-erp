## [2] 왜 이 오더가 나왔나 — 현장 논리

### ① 자동승인 — 반자동 원칙에 어긋난다

현재 서버는 이렇게 돈다 (`ApprovalService.cs:496`):

```csharp
if (setting is { AutoApproveBelow: true, ThresholdAmount: > 0 } && request.Amount < setting.ThresholdAmount)
{
    status = "approved";     // 결재선을 통째로 건너뛴다
}
```

**금액이 기준 미만이면 결재선을 타지 않고 그 자리에서 승인된다.**

🔴 이것은 사장님 헌법 **「100% 자동화는 없다 — 무조건 반자동」** 과 정면으로 부딪힌다.
결재는 *사람이 판단하는 자리*다. 금액이 작다고 시스템이 대신 승인하면,
**결재선에 이름이 올라간 사람이 보지도 못한 문서가 승인된 것으로 남는다.**

ERP 매니저 관점 — 실제 경리·구매담당이 *"내가 결재한 적 없는데 내 이름으로 승인돼 있다"* 고
말하는 자리다. 감사 추적이 깨진다.

### ② 결재라인 이동 — 「처음 보는 사람이 혼자 쓸 수 있냐」

현재는 「설정」 아이콘을 눌러도 **화면이 움직이지 않는다.**
결재라인 편집 영역은 표 **아래쪽**에 나타나는데, 문서유형이 10줄이라
**화면 밖에 있어 눌러도 아무 일도 안 일어난 것처럼 보인다.**

> 사장님: *"고객입장에서 «설정 아이콘 눌렀는데, 결재설정 어떻게 해요?» 라고 오해할수도"*

히트판 최종 통과 기준 — **"이 화면, 처음 보는 사람이 혼자 쓸 수 있냐?"** 에 걸린다.
누른 결과가 눈에 보여야 한다.

### ① 기준금액 · 미만 자동승인 제거

**화면** — `src/HitPan.Web/Pages/Settings/ApprovalSettingsPage.razor`

| 뺄 것 | 위치 |
|---|---|

| `<MudTh>미만 자동승인</MudTh>` | 51행 |

| 자동승인 `MudCheckBox` | 67~70행 |
| `OnThresholdChange` / `OnAutoApproveChange` | 270~282행 |
| 머리말 설명의 "· 기준금액" | 15행 |

**서버** — `src/HitPan.Application/Services/ApprovalService.cs`

자동승인 분기(496~499행)를 타지 않게 한다.

🔴 **컬럼과 DTO 는 남긴다** (헌법 #37 — *"안 읽힌다 ≠ 잔재"*).
   `threshold_amount` · `auto_approve_below` 컬럼을 지우지 않는다.
   이미 값을 넣어 둔 고객사의 기록이고, 되돌릴 때 필요하다.
   **읽되 쓰지 않는다** — 저장 시 항상 끈 값으로 넣는다.

### ② 「설정」 클릭 → 결재라인 영역으로 이동

**화면** — 같은 파일

`OpenLineEditor` 가 끝난 뒤 결재라인 영역으로 **스크롤**한다.

- 영역에 `id` 를 준다
- `IJSRuntime` 으로 `scrollIntoView({behavior:'smooth', block:'start'})`
- 🔴 **렌더 후에 불러야 한다** — `_editingDocType` 이 설정되기 전에 부르면 대상이 없다
