### 🔴 W1 진범 — 다음 세션이 반드시 알아야 할 것

발주하면 알림은 `pending → ordered` 로 **정상 전환된다.** 그런데
**조회 API 가 조회할 때마다 미달 품목을 `pending` 으로 다시 넣었다** —
중복 가드가 `pending` 만 봐서 방금 `ordered` 로 넘긴 품목이 그냥 통과했다.
⇒ **화면을 갱신하는 그 행위가 경고를 되살렸다.**

🔴 8/21 주석 *"BOM 경로는 이미 정상"* 이 **틀렸다.** 판매 경로만 고친 자리였다.
🔴 자동발주 회귀 게이트가 **0건**이라 아무도 못 잡았다 → 이번에 31개 신설.

### 🔴 반제품 차단 — 사장님 결재 *"데이터 정합성이 중요하지 막아!!"*

사슬은 매입확정을 태우고, 매입확정은 **매입 분개 + 외상매입금**까지 만든다.
반제품은 만들어 채우는 물건이라 **사지 않은 물건에 갚을 돈이 생긴다.**
⇒ **사슬만 막고 발주서는 그대로** 만든다(외주 매입 길 유지 · #20).
판정은 `AutoChainPolicy` **한 곳**. BOM·판매 두 경로가 같이 쓴다.

## 3. 🔴 오늘 PM 이 낸 사고 2건 — 같은 실수 반복 금지

### ① PR 을 올려놓고 그 브랜치에 계속 작업했다

문서 커밋 1개로 PR #262 를 올렸는데, 사장님이 **05:44 에 머지**하셨고
코드 커밋 5개는 **05:52~06:54 에** 올라갔다.
⇒ **머지된 건 문서뿐이고 코드 전부가 main 에 없었다.** 그 상태로 게시했으면 헛게시다.

🔴 게시 직전 `git show origin/main:<파일>` **문자열 대조로 잡았다.** 안 했으면 그냥 나갔다.
⚠️ 8/23 스쿼시 사고와 **증상은 같지만 원인이 다르다** — 그건 스쿼시가 삼킨 것,
이건 **머지 시점 이후에 밀어 넣은 것**. 시각 비교로 갈린다.

**규칙**: PR 은 **작업이 끝난 뒤에** 올린다. 이미 올린 PR 에 더 넣어야 하면
머지 전인지 확인하고, 아니면 **새 PR**. → PR #264 로 복구.

### ② 시험 코드에 개발 DB 비밀번호를 박았다

신설 게이트 3개에 기본값으로 넣어 Secret Scan 이 빨간불이 됐다.
기존 게이트는 **기본값을 비우고 환경변수로만** 받는다 — 그 관례를 어겼다.
🔴 **제외 목록에 넣어 감추지 않았다**(그 파일 주석도 금지한다). 원래 방식으로 되돌렸다. → PR #266.

⚠️ **남은 빨간불 1건** — 봉합을 설명한 **커밋 메시지 안의 글자**다.
코드는 깨끗하고 실제 유출이 아니며(`verified_secrets: 0`),
그 값은 `CLAUDE.md:307`·설치문서·스캔 규칙 파일에 **이미 있는 개발 PC 로컬 비번**이다.
🟢 **사장님 결재: 그대로 두고 게시** — 다음 커밋부터 자연히 초록으로 돌아온다.
