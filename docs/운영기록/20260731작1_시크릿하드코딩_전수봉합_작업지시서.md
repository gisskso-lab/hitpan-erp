## 0. 이 지시서가 나온 경위

오늘 시크릿 스캐너가 **7/21부터 11건 연속 실패**하고 있던 것을 봉합했다
([사고 경위](../설계/보안/20260731_시크릿스캔_정상화_설계서.md) §1).

**스캔이 실제로 돌기 시작하자 진탐이 드러났다.** 이 지시서는 그 진탐을 다룬다.

> 오늘 봉합에서 이것들을 **일부러 제외하지 않았다.** 제외하면 덮는 것이기 때문이다.
> 다만 차등 스캔은 변경분만 읽으므로 `schedule` 주 1회 전수 스캔을 함께 넣었다.
> **그 전수 스캔이 매주 이 항목들을 계속 지적할 것이다.**

## 1. 🔴 P0-1 — 모든 고객 PC 가 동일한 DB 비밀번호를 쓴다

### 1-1. 실측

```
$ grep -n 'Hitpan2025' installer/install.bat
51:    msiexec /i "…mariadb.msi" /quiet SERVICENAME=MariaDB PASSWORD=<비번>
85:    mysql -u root -p%ROOT_PW% -e "CREATE USER IF NOT EXISTS 'hitpan'@'localhost' IDENTIFIED BY '<비번>'; GRANT ALL ON *.* …"
92:    mysql -u hitpan -p<비번> -N -e "SELECT …"
```

`installer/install.bat` 최종 수정 `09369f8` (2026-04-28) — **3개월간 아무도 못 봤다.**

### 1-2. 왜 P0 인가

**고객사 A 의 비밀번호를 알면 고객사 B·C·D 전부 열린다.**

| 항목 | 현재 |
|---|---|
| 비밀번호 생성 | 설치 EXE 에 하드코딩된 고정값 |
| 고객사별 분리 | ❌ 없음 |
| DB 권한 | `GRANT ALL ON *.*` (전체 권한) |
| 노출 경로 | 설치 EXE 를 받은 누구나 `install.bat` 을 열어볼 수 있다 |

로컬 DB(헌법 #22 — 본사가 안 가지면 안 털린다)라는 구조가 이 지점에서 무너진다.
**데이터는 고객 PC 에 있지만 열쇠가 전 고객 공통이다.**

### 1-3. 선례가 있다

```
installer/hitpan-start.bat:20
::   사고 #38 봉합: 폴백 영역 `<비번>` 영역 제거 — 잘못된 영역 자격증명 영역 사용 영역 차단
```

**같은 문제를 사고 #38 에서 한 번 잡았다.** 그런데 `install.bat` 은 남아 있었다.
한 파일만 고치고 전수를 안 한 결과다 (헌법 #12 — 인터페이스 확장 시 모든 구현체 grep).

### 1-4. 봉합 방향 (설계 필요 — 이 지시서는 방향만 제시)

| 후보 | 장점 | 검토 필요 |
|---|---|---|
| 설치 시 **랜덤 생성** → `db.conf` 저장 | 고객사별 완전 분리 | 업데이트 시 보존(헌법 — db.conf 업데이트 시 보존), 백업/복구 경로 |
| 시리얼·테넌트ID 기반 **파생** | 재설치 시 동일값 재현 | 파생 규칙이 EXE 에 있으면 역산 가능 |

⚠️ **설치 흐름 전체가 사정권이다** — 계정 생성 · `db.conf` · 백업 스크립트 ·
마이그레이션 · 워치독 · 재설치 경로. 한 곳만 고치면 로그인 불가로 전 고객 정지.

⇒ **[2] 설계팀장 존이 설계서 먼저 작성**한다. 코딩은 그 뒤다.

## 2. 🟡 P0-2 — 백업 스크립트 하드코딩 폴백

```
$ grep -n 'Hitpan2025' scripts/backup-daily.ps1
7:$DbPass = if ($env:DB_PASS) { $env:DB_PASS } else { '<비번>' }
```

환경변수가 없으면 하드코딩 값으로 폴백한다. P0-1 봉합 시 **함께 처리**해야 한다
(비번이 고객사별로 갈리면 이 폴백은 반드시 실패한다).

## 3. 🟡 P1-1 — SQLServer 검출 8건 미분류

전수 스캔에서 나왔으나 **아직 분석되지 않았다** ([3-V] 검증팀 P1-2 지적).

```
전수 스캔 결과 (run 30614738083):
  hitpan-db-password    102건
  SQLServer               8건   ← 미분류
  hitpan-ssh-private-key  2건   (오탐 확정)
```

접속 문자열(`Server=…;Password=…`) 패턴이며 개발 DB 비번과 같은 위치일
**가능성이 높으나 확인되지 않았다.**

⇒ **추정으로 닫지 않는다.** 8건 각각의 파일·행을 특정해 진탐/오탐 분류.

## 4. 🟡 P1-2 — OWASP ZAP 이 8건 연속 실패 (별건이나 같은 성격)

```
$ gh run list --workflow="OWASP ZAP Baseline DAST" --branch main
failure ×8 (7/30~7/31)

##[error]Create Artifact Container failed: The artifact name zap_scan is not valid.
```

**보안 취약점 검출이 아니라 아티팩트 업로드 실패**다. ZAP 액션이 Actions v4
아티팩트 규격과 맞지 않는다. 스캔 자체는 완료된다.

⚠️ **오늘 봉합한 TruffleHog 와 정확히 같은 구조** — "늘 실패하는 체크"라 아무도 안 본다.
DAST 가 진짜 취약점을 잡아도 같은 빨간 X 라 구분이 안 된다.

## 5. 오늘 이것들을 왜 지금 안 고쳤나

| 이유 | |
|---|---|
| 범위 | 설치 흐름 전체(계정·db.conf·백업·마이그·워치독·재설치)를 건드려야 한다 |
| 절차 | 헌법 #33·#42 — 설계 없이 즉석 봉합 금지. 오늘 작10 이 그 대가를 치렀다 |
| 위험 | 한 곳만 고치면 **전 고객 로그인 불가**. 게시 직전에 손댈 크기가 아니다 |

**덮지 않았다는 것이 오늘의 결론이다.** 스캐너가 매주 이것을 지적하도록 만들어 두었다.

## 6. 요청 사항 (사장님·CTO 결재)

1. **P0-1 우선순위** — 백지 실측(작10)과 이것 중 무엇이 먼저인가?
2. **봉합 방식** — 랜덤 생성 vs 파생. §1-4 검토 필요 항목에 대한 방향 결재
3. **기존 고객 마이그레이션** — 이미 설치된 PC 의 비밀번호를 바꿀 것인가, 신규만 적용할 것인가
   (바꾸면 업데이트 시 DB 접속 끊김 위험, 안 바꾸면 기존 고객은 계속 노출)

> ⚠️ 3번이 가장 무겁다. **이미 나간 설치본이 있다면 그 PC 들은 이미 공통 비번이다.**
> 현재 배포 현황(실사용 고객 수)을 확인한 뒤 결정해야 한다.
