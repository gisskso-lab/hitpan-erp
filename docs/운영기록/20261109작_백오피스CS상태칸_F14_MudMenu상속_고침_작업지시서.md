- 본문(이 꼴 그대로 · 주석 문구는 [3] 재량이나 「AI」 관련 단어 0 · #23):
```csharp
using Microsoft.AspNetCore.Components;
using Microsoft.JSInterop;
using MudBlazor;

namespace HitPan.Backoffice.Components.Pages.Platform.Components;

/// <summary>
/// 🔴 20261109작 S4 F14 — CS 상태 칸(CsStatusCell) 전용 목록. 9.3 MudMenu 를 그대로 쓰고,
/// 그린 뒤 초점(9.3 MudMenu.razor.cs L1020 래퍼 · L1026 첫 항목)이 이미 지워진 요소로 가서 나는 JSException 만 받아 기록한다.
/// 그 밖의 예외는 잡지 않는다. 다른 화면(DataGrid 등)에 쓰지 않는다 — 넓히려면 별건 결재.
/// 9.3 판 올림 때 재검: 작업지시서 20261109작 §9.
/// </summary>
public class CsStatusMenu : MudMenu
{
    [Inject] private ILogger<CsStatusMenu> FocusSkipLog { get; set; } = default!;

    protected override async Task OnAfterRenderAsync(bool firstRender)
    {
        try
        {
            await base.OnAfterRenderAsync(firstRender);
        }
        catch (JSException ex)
        {
            FocusSkipLog.LogWarning(ex, "CS 상태 칸 목록 — 사라진 요소로 가는 초점 한 번 건너뜀");
        }
    }
}
```
- 「다른 예외는 다시 던짐」 = `catch (JSException)` 하나만 둔다 → `JSDisconnectedException`(JSException 의 하위 형식 아님) · `TaskCanceledException` · 그 밖은 **잡히지 않고 그대로 올라간다**. `catch (Exception)` + `throw;` 꼴은 쓰지 않는다(스택 보존 · 읽는 사람 혼동 0).
- 기록: `LogWarning(ex, 고정 문구)` — #15 원문 「최소한 `_logger.LogWarning(ex, ...)`」. 회로 ID · 시각 · 해시 · site 판정 넣지 않음(짧게). [4] 는 이 **고정 문구**로 줄을 세고, 스택에 `FocusItemAsync` 가 있으면 L1026 · 없으면 L1020 으로 가른다([1-V] §1-6 방식).
- 진단 사본과의 차이(가져오지 않는 것): g2 의 `F14 GUARD {T} menu#{H} site={S} swallowed {M}` 문구 · `DateTime.Now` · `GetHashCode()` · 스택 문자열 검사.

```csharp
    //    · 그 밖의 예외는 잡지 않는다 · 살아 있는 회로에선 이 둘이 나지 않아 정상 길은 고침 전과 같다.
    private async Task CloseAllMenusLoggedAsync(MudMenu menu, string where)
    {
        try
        {
            await menu.CloseAllMenusAsync();
        }
        catch (Exception ex) when (ex is JSDisconnectedException or OperationCanceledException)
        {
            Logger.LogWarning(ex, "CS 상태 칸 — 목록 닫은 뒤 단추 초점을 돌리지 못함({Where})", where);
        }
    }
```
