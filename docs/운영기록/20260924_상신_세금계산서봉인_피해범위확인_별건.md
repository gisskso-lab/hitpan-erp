## §1 왜 지금인가 — 🚨 **이번 게시가 나가면 영영 조용해진다**

이번 봉합은 메인PC 등록이 **세금계산서 열쇠를 더 이상 안 건드리게** 만든다.
🔴 **그것은 *"앞으로 안 덮는다"* 일 뿐이다.** *"이미 덮였는가"* 는 **아무도 모른다.**

⇒ 게시 후에는 그 경로가 그 금고를 안 건드리므로 **증상이 나타나지 않는다.**
⇒ 이미 덮였다면 **세금계산서를 실제로 쓰려는 날에야** 알게 된다. 그때는 원인을 되짚기 훨씬 어렵다.

🔴 **CTO 판정**: *"O-1·O-4 는 남길 것이 아니다."* — PM 도 동의한다.

---

## §2 무엇이 일어났나 (확정된 사실)

```
src/HitPan.Application/Services/Security/TpmKeyService.cs:35
    KEY_NAME = "HitPan.TaxInvoice.MasterKey"      ← 상수 하나뿐. 메인PC 전용 이름이 없었다
                                            :79  ← OverwriteExistingKey (덮어쓴다)
```
⇒ **메인PC 등록을 누를 때마다 세금계산서 열쇠가 새 열쇠로 덮였다.**
⇒ 🚨 **9/23 01:26 과 9/24 F12 실측 때 [이 컴퓨터로 바꾸기] 가 눌렸고, 응답은 200 이었다.**
   `mainpc-register` 200 = **봉인이 실제로 불렸다**(리뷰서 §9 R-2 확인).

⚠️ **그 열쇠로 봉인해 둔 값이 있었다면 영영 못 푼다.**

## §4 ⏸ 사장님께 여쭙는 것 — **화면 한 번이면 닫힙니다**

```
히트판 → 설정 → 세금계산서 인증서 화면
  · 인증서 정보(주체·발급자·만료일)가 뜬다   ⇒ 등록돼 있다 → §5 로
  · "등록된 인증서 없음" / 빈 화면           ⇒ 잃은 것이 없다 → 이 건 종결
```
🚨 **[등록] 이나 [다시 등록] 은 누르지 마십시오.** 보기만 하면 됩니다.

---

## §5 등록돼 있다면 — 결재가 필요한 것

| # | 안건 |
|---|---|
| **B-1** | 그 인증서를 **실제로 써서 세금계산서를 발행한 적이 있는가** (있으면 복호화 시도로 생사 확인 가능) |
| **B-2** | 복호화가 안 되면 **인증서를 다시 등록**해야 한다 — 공인인증서 파일과 비밀번호가 필요하다 |
| **B-3** | 🔴 **`TpmKeyService` 자체의 공급자 불일치**(봉인 TPM / 해제 소프트웨어)도 **세금계산서에 그대로 있다** — 이번 봉합은 메인PC 쪽만 고쳤다. 세금계산서도 고칠지 **별도 결재** |

🔴 **B-3 이 크다.** 공급자 불일치가 남아 있으면 **새로 등록해도 나중에 또 못 푼다.**
⚠️ 다만 세금계산서는 **모듈 경계 밖**이라 PM 이 범위를 정하지 않는다.
