## §5 [설계 — 갈래 B · 표시줄 고객사 거름]
### §5-1 서버 — 고객사 숫자 새 입구 (D4 · C4 · C6 · C7)
- `CsAdminController` 에 새 동작 `CountsForTenant` · `[HttpGet("counts/tenant")]` · 인자 `[FromQuery] string? tenantId` · 클래스 정책 상속(새 `AllowAnonymous` 0).
- 기존 `Counts`(`:402~416`) · `StageCountSql`(`:133~143`) **무접촉** → 사이드바·평소 표시줄 응답이 글자 하나 안 바뀜(「인자 없으면 종전」 을 구조로 보장).
- 순서(같은 연결 · 차례로 · #16): ① 값 검사 — 빈 값 · 공백 · 36자 초과 = 400 ② `tenants` 에서 `tenant_id = @TenantId` 로 회사명 1행 — 없으면 `found=false` · 숫자 칸 **없음**(0 으로 채우지 않는다) ③ 있으면 새 상수 `TenantStageCountSql` — 기존 식과 **같은 단계 식**에 하위 질의 `WHERE tenant_id = @TenantId` 한 줄.
- 🔴 칸을 형변환·함수로 감싸지 않는다(색인 `idx_bo_cs_tenant` 무력화 방지 · [1-V] §3) · 값은 Dapper 인자로만(문자열 이어붙이기 0).
- 응답: `success · found · companyName · unread · open · done · rated · total`.

### §5-2 서버 — 목록 고객사 인자 (D8 · C4)
- `List` 매개변수 **맨 끝**에 `[FromQuery] string? tenant = null`(취소 토큰 뒤). 기존 직접 호출 `CsAsCounterStatusGateTests.cs:672` 무수정으로 컴파일.
- 🔴 [3] 첫 일: `CsAdminController` 의 `List`·`Counts` 를 반사(`GetMethod`·`Invoke`)로 부르는 시험 grep — 있으면 **멈춤**(인자 개수 사고 전례).
- 고객사 값이 있을 때만 **고정 글자 조각** `AND k.tenant_id = @Tenant` 를 붙인다(같은 메서드의 `hasPurge` 조건 꼴 `:166~169` · 사용자 글자는 SQL 에 0). 빈 값 · 공백 = 거름 없음.
- 기존 부분 일치 검색 `q`(`:196`)와 **분리** — 둘 다 오면 AND. 고유값 일치라 이름 비슷한 고객사가 섞이지 않는다.
