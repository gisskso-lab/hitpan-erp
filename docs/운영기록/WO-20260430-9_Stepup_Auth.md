# 작20260430-9 — Step-up Authentication (P0 보안, 사장님 검증 발견)

## 🔴 우선순위
P0 (사장님 라운드 2 검증 발견, 즉시 빠른 트랙)

## 발견 (사장님 2026-04-30)
> "기존 사용자 수정 아이콘 클릭 시 비밀번호 묻는 메시지 안 나오고
>  비밀번호 안 치고 바로 사용자 정보수정이 가능함"

## 진범 (CTO 분석)
- 사용자 추가는 어드민이 직접 입력 → 의도된 입력
- **사용자 정보 수정은 권한 가진 어드민 누구든지 무인증 통과** = 보안 구멍
- 절대원칙 #12 위반 흔적: 추가 화면엔 보호 있고 수정 화면엔 없음 = 일관성 깨짐
- 2차 검증팀에서 횡단 감사로 잡았어야 했음 (헌법 4조 직무유기)

## 적용 범위 (사장님 결재: A1·A2·A3·A4 전부)
| 액션 | 처방 |
|---|---|
| **A1** 다른 직원 정보 수정 (이름·부서·직책·역할) | Step-up 재인증 다이얼로그 |
| **A2** 다른 직원 비밀번호 초기화 | Step-up 재인증 다이얼로그 |
| **A3** 다른 직원 비활성화/삭제 | Step-up 재인증 다이얼로그 |
| **A4** 권한 설정 변경 | Step-up 재인증 다이얼로그 |
| 본인 정보 수정 | ❌ 적용 안 함 |
| 신규 사용자 추가 | ❌ 적용 안 함 (어드민이 직접 입력 중) |

## 처방 (Step-up Authentication 모델)
1. **공통 컴포넌트 신설:** `StepUpDialog.razor`
   - 어드민 본인 비밀번호 입력란
   - 백엔드 검증: `POST /api/auth/verify-password` (현재 토큰의 user_id로 BCrypt 비교)
   - 통과 시 단발성 step-up 토큰 발급 (5분 TTL)
2. **사용자 흐름:** 민감 액션 클릭 → StepUpDialog → OK 후 실제 액션 호출
3. **백엔드 보호:**
   - 민감 엔드포인트(`PUT /api/users/{id}`, `POST /api/users/{id}/reset-password`,
     `POST /api/users/{id}/deactivate`, `PUT /api/permissions/{id}` 등)
   - 헤더 `X-StepUp-Token` 필수 검증 (서버 캐시 또는 짧은 JWT)
4. **5분 캐싱:** 같은 어드민 같은 세션 내 재인증 면제 (UX 보호)
5. **감사 로그:** Step-up 발급/사용/만료 모두 기록 (헌법 #18 v3 보안감사로그)

## 담당
- 메인: 보안 매니저 (직접 처리)
- 보조: 백엔드 매니저, 프론트 매니저
- 검증: CTO Final Verifier + 법무팀장

## 헌법 4조 검증
- DB: 비밀번호 BCrypt 비교 정상
- 백엔드: 검증 API 200 / 401, 미검증 시 403
- 프론트: 다이얼로그 표시·통과 후 액션 진행
- 끊김 0: 어드민 → 다른 직원 정보 수정 풀스택 흐름
- 고객 시선: "비밀번호 또 입력? 안전하니까 OK" 직관적
