# 본건 1 — 결재 5 · **과금 장부의 진실원이 본사인가**

**결정할 것**: 「누가 몇 계정을 쓰고 있는가」의 **최종 판단 근거**를 본사(백오피스)가 가지는가, 고객사 ERP 가 가지는가.

| | 사실 |
|---|---|
| 🟢 전제(확정) | 과금 단위 = **계정 수**(직원 수 아님) · 5계정 / 10계정 / 추가 증설 · 모바일 무료 · 계정 수 = 동시 PC 수 |
| 🟡 지금 설계 | 백오피스는 ERP 로컬 DB 를 **5분 주기 Pull** 한다 — `tenant_employees`·`tenant_devices` 는 **복사본**이라고 적혀 있다(`THREE_SYSTEM_ARCHITECTURE.md:57-58`) |
| 🔴 기록없음 | **불일치가 났을 때 어느 쪽을 믿는다**는 기록이 없다. 과금 분쟁·연체 판정이 전부 이 한 줄에 달린다 |

| 선택지 | 뜻 | 대가 |
|---|---|---|
| **(가)** 🟢 **본사 = 진실원** | 과금·연체·조임 판정은 **백오피스 장부**로 한다. ERP 는 보고만 한다 | 본사가 「계정 수·활성 여부」를 계속 들고 있어야 한다(업무 데이터는 아니다) |
| (나) ERP 로컬 = 진실원 | 본사는 집계 사본만 본다 | 🔴 고객 PC 가 꺼져 있으면 **과금 근거가 사라진다** · 분쟁에서 본사가 아무것도 증명 못 한다 |
| (다) 이중 장부 + 불일치 시 우선순위 지정 | 둘 다 두고 규칙으로 가른다 | 🔴 규칙이 틀리면 **조용히 과금 사고**. 1인 운영에서 가장 비싸다 |

🟢 **PM 건의 = (가).** 과금은 **본사의 사업 행위**이고 「계정 수·활성 여부」는 **업무 데이터가 아니다** ⇒ #18·#22 위반이 아니다. 단 본사가 가지는 칸은 **계정 수·활성 여부·구독 상태**로 **못 박아** 두고, 그 밖은 금지로 남긴다.
**안 떨어지면**: B3⑧ 과금 장부 일원화 · B3⑥ 「본사가 활성계정을 당긴다」가 **설계부터 못 열린다.**
