## 4. 🟢🟢 왕복 증명이 실물에서 돈다 — 이 트랙 최대 성과

### 4-1. 팝업이 떴다는 것이 ①②③ 전부가 돌았다는 증거다

사장님 화면에 뜬 팝업은 **`Prompt.Change`**(*"회사 자료 컴퓨터를 이 컴퓨터로 바꿀까요?"*)다.
`MainPcGate.razor` 를 보면 이 팝업은 **`RunProofAsync()` 가 `"DifferentPc"` 를 돌려줬을 때만** 뜬다.
거기까지 가려면 **세 걸음이 전부 성공해야 한다**:

```
① POST api/devices/mainpc-challenge  (도메인 경유)   → 성공해야 표가 나온다
② JS hitpanMainPc.probe(challenge)   (127.0.0.1 직접) → true 여야 한다   🔴 여기가 P0 자리였다
③ POST api/devices/mainpc-verify     (도메인 경유)   → outcome 을 받는다
```

⇒ **① 도 ② 도 ③ 도 실물 브라우저에서 돌았다.** 그리고 ③ 이 내린 판정은 **`DifferentPc`** —
*"회사 자료가 다른 컴퓨터에 등록돼 있다"* 를 **정확히** 알아봤다.

🟢 **설계가 실물에서 증명됐다.** 브라우저가 자기 PC 안의 히트판을 두드려 물리적으로 자기를 증명하는 구조가, 터널 너머에서 실제로 작동한다.

### 4-2. 🟢 P0 봉합이 실물에 갔다 — 대조군까지 세워 쟀다

PM 이 실행 중인 실물 API 에 직접 두드린 값:

```
POST http://127.0.0.1:5257/api/devices/mainpc-proof      → HTTP 200  {"confirmed":false}   🟢 미들웨어 통과
POST http://127.0.0.1:5257/api/devices/mainpc-challenge  → HTTP 401                        🟢 대조군
```

- 위: 토큰 없이도 **`TenantMiddleware` 를 지나갔다.** 9/22 에 401 로 잘리던 바로 그 길이다 → **봉합이 살아 있다**
- `confirmed:false` 는 **정상** — 없는 표(0-GUID)를 넣었으니 거절이 맞다
- 아래: **화이트리스트가 넓어지지 않았다.** 같은 컨트롤러의 다른 길은 여전히 401
  ⇒ *"통째로 열어 버린 것"* 이 아니다. **G-1c 가 CI 에서 막던 그 실패 모양이 실물에서도 안 난다**

🔴 **세 번째 재발이었던 `TenantMiddleware` 사고는 이것으로 실물에서 닫혔다.**

🔴 **화면 글자로는 D 와 E 를 못 가른다.** 그래서 §0 의 **Response 본문 확보가 첫 행동**이다.
