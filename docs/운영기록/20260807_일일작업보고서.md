|---|---|---|
| 19:30:01 | 워치독 발견 기록 | 1.2.54 |
| — | 13회 조회 — 변화 없음 | 1.2.54 |

| 19:34:27 | 재시작 직후 | **1.2.55** |

### 2-2. 원인 — 하루 1회 게이트 + 메모리 변수 (유력 확정)

`src/HitPan.Watchdog/Worker.cs:324-326`
```csharp
if (_lastUpdateCheckDate == today)
    return;                    // ← 로그도 남기지 않고 그냥 나간다
```

새 버전 확인은 **하루 한 번뿐**이고, 그 기억은 디스크가 아니라 **메모리**에 있다.
재시작이 통한 건 무언가를 고쳐서가 아니라 **메모리가 날아가 게이트가 풀렸기** 때문이다.

### 2-3. 로그의 침묵이 증거였다

워치독 이벤트 기록 조회 결과:

| 조회 | 결과 |
|---|---|
| 전체 | **500건** (Information 493 · Warning 7) |
| 19:25~19:40 (문제 구간) | **0건** |
| `[Update` / `manifest` / `W4-` / `1.2.5` | **0건** |

기록이 500건인데 업데이트 관련은 한 줄도 없다. 검색어가 영문·숫자라 한글 깨짐 탓도 아니다.
**못 찾은 게 아니라 찾으려 하지 않았다.** `:326` 의 `return` 은 아무것도 안 남기므로 침묵이 남는다.

### 2-4. 같은 벽에 두 번째다

`4cc5842` 주석이 이미 같은 현상을 적어 두었다 —
*"[나중에] 를 눌러도 그날 안에는 새 버전을 다시 발견하지 못한다."*

**그 봉합은 팝업이 떴다 해소된 경우만 게이트를 푼다.**
이번은 **팝업 전, 발견 단계**라 그 경로에 안 걸렸다. 같은 진범의 다른 얼굴이다.

### 2-5. 사장님 오늘 오더와 정면으로 연결된다

> 사장님: *"워치독·업데이트 종단이 구현되면 그 후부터 수정·보완이 쉬워질거야.
> 재설치 없이 **코드수정 → 업데이트 → 실측** 세 단계면 되거든."*

**이 항목이 그 3단계를 막고 있다.** 실제로는:
```

```
오늘 사장님이 `sc start` 를 치신 것이 그 증거다.
**고객 영향보다 우리 개발 속도에서 더 무겁다.**
