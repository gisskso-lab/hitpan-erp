
## 2. 봉합 대상 — 실측 재현 결과 (2026-08-06)

### A-1 🔴 `Move-Item -Force` 가 폴더를 대체하지 않는다

`watchdog.old` 가 **이미 있으면** 대체가 아니라 **안으로 중첩**시킨다. 예외도 안 난다.

실측:
```
Move-Item watchdog watchdog.old -Force   (watchdog.old 가 이미 존재)
  →  watchdog.old\stale.txt
     watchdog.old\watchdog\HitPan.Watchdog.exe   ← 한 칸 더 들어감
```

**이게 왜 영구 고립인가** — 롤백 코드까지 돌려본 실측:
```
롤백 조건 (-not (Test-Path $cur)) -and (Test-Path $old)  →  True  (성립함)
Move-Item $old $cur -Force                               →  실행됨
결과: watchdog\HitPan.Watchdog.exe 존재 = False
      watchdog\watchdog\HitPan.Watchdog.exe  ← 여기 갇힘
```
⇒ **롤백이 "성공"했는데 EXE 는 제자리에 없다.** 서비스가 찾는 경로가 빈 폴더다.
   예외가 안 나므로 로그에도 안 남는다.

**봉합**: 옮기기 전에 **목적지를 먼저 지운다.**
```powershell
if (Test-Path $old) { Remove-Item $old -Recurse -Force }
Move-Item $cur $old -Force
if (Test-Path $cur) { Remove-Item $cur -Recurse -Force }
Move-Item $new $cur -Force
```
실측 검증 완료 — 새 버전 제자리, 구버전 백업 자리, **중첩 0건**.
롤백 경로도 동일 방식으로 검증 완료(구버전이 제자리로 정상 복귀).

### A-2 🔴 폴더가 없는 순간에 전원이 끊기면 복구 코드가 0건

`watchdog` → `watchdog.old` 로 옮긴 직후 ~ `watchdog.new` → `watchdog` 이전 사이,
**`watchdog` 폴더가 존재하지 않는 창(window)** 이 있다.

그때 정전·강제종료가 나면:
- `/SC ONCE` 예약작업은 **이미 실행이 끝난 상태** → 다시 안 돈다
- 부팅 시 복구 코드가 **레포에 0건** (실측: 워치독 대상 `ONSTART` 작업 없음)
- Guardian 은 서비스를 `start` 하려 하지만 **EXE 자체가 없다**

⇒ **영구 고립**

**봉합**: 부팅 시 복구 작업(`/SC ONSTART`)을 **교체 시작 전에 먼저 등록**한다.
- 이름: `HitPanWatchdogSelfReplaceRecover`
- 교체가 정상 완료되면 **스스로 삭제**한다
- ※ `ONSTART` 는 이 레포의 지배적 관용구다(`HitPan-Universal.iss` API/Web 등록과 동일 방식)

**복구 판정 규칙** (PM 결재 시 보강 — "성한 쪽"의 정의가 없으면 복구가 새 사고를 만든다).
전원 차단 시점별로 남는 조합을 전수 나열한 결과:

| 차단 시점 | `watchdog` | `.old` | `.new` | 판정 |
|---|---|---|---|---|
| S0 교체 전 | ○ | × | ○ | 정상 — 그대로 시작 |
| S1 `.old` 지운 직후 | ○ | × | ○ | 정상 — 그대로 시작 |
| **S2 `cur`→`.old` 직후** | **×** | ○ | ○ | **`.new` 로 복구** |
| S3 `.new`→`cur` 직후 | ○ | ○ | × | 정상 — 그대로 시작 |
| S4 정리 후 | ○ | × | × | 정상 — 그대로 시작 |

⇒ **`watchdog` 이 없는 단계는 S2 하나뿐이고, 그때 `.old`·`.new` 가 둘 다 남아 있다.**
   **복구 자산이 없는 조합은 발생하지 않는다.**

판정 순서(위에서부터):
1. `watchdog\HitPan.Watchdog.exe` 가 **있으면** → 복구 불필요, 서비스만 시작
2. 없고 `watchdog.new\HitPan.Watchdog.exe` 가 있으면 → `.new` 를 `watchdog` 으로 (S2)
3. 없고 `watchdog.old\HitPan.Watchdog.exe` 가 있으면 → `.old` 를 `watchdog` 으로 (최후 보루)
4. 셋 다 없으면 → 로그만 남기고 종료 (여기서 뭘 더 하면 상태만 악화)

⚠️ **판정은 폴더 존재가 아니라 `HitPan.Watchdog.exe` 존재로 한다.**
   빈 폴더가 남아 있는 경우 폴더만 보면 "정상"으로 오판한다(A-1 이 정확히 그 사고였다).
   이동은 A-1 봉합과 동일하게 **목적지 선삭제** 후 수행한다.

### A-3 🟠 `Stop-Service` 실패를 이중으로 삼키고 그대로 교체

```powershell
try { Stop-Service HitPanWatchdog -Force -ErrorAction SilentlyContinue } catch {}
Start-Sleep -Seconds 5
```
`-ErrorAction SilentlyContinue` + `catch {}` 로 **두 번** 삼킨다.
서비스가 안 멈춘 채로 교체에 들어가면 EXE 가 잠겨 있어 A-1 을 유발한다.

**봉합**: 중지 후 **상태를 확인**한다. `Stopped` 가 아니면 최대 30초 대기,
그래도 안 멈추면 **교체를 시작하지 않고 중단**한다(구버전 유지 = 안전).

### B-1 🟠 자정 직전이면 예약이 과거 시각으로 등록되는데 `exit 0`

```csharp
var runAt = DateTime.Now.AddMinutes(1).ToString("HH:mm");   // 23:59 + 1분 = "00:00"
```
`/SC ONCE /ST 00:00` = **오늘 00:00** = 이미 지난 시각.

실측:
```
schtasks /Create /SC ONCE /ST <과거시각>
  exit = 0
  WARNING: Task may not run because /ST is earlier than current time.
  SUCCESS: The scheduled task has successfully been created.
```
⇒ 코드는 `exit 0` 만 보고 **성공으로 판단**하는데 실제로는 **영원히 안 돈다**(침묵 실패).

**봉합**: `/SD`(시작 날짜)를 함께 준다. 실측 검증 완료 — 자정을 넘겨도 `exit 0`, 경고 없음.
```csharp
var runAt = DateTime.Now.AddMinutes(2);
... /SC ONCE /SD {runAt:yyyy/MM/dd} /ST {runAt:HH:mm}
```
※ 여유를 1분 → **2분**으로 늘린다. 1분은 예약 등록~트리거 사이가 너무 촉박하다.

## 4. 불변 안전 원칙 (하나라도 깨지면 반려)

1. **이 기능의 어떤 실패도 "업데이트 성공"을 뒤집지 않는다.** 최악이어도 *워치독만 구버전으로 남는다.*
2. **영구 고립 0.** 어느 순간에 전원이 끊겨도 다음 부팅에 복구된다.
3. **바닥 없이 뛰지 않는다.** 부팅 복구 등록 → 예약 등록 → 중지 확인, **전부 성공한 뒤에만** 교체 시작.
4. **침묵 금지**(헌법 #15). 모든 분기에 로그. `exit 0` 을 성공의 근거로 삼지 않는다.
5. **순수 ASCII 스크립트.** 인코딩 왕복 사고 원천 차단(20260804 P0-E 교훈).
6. `schtasks` 사용. CIM 미의존(20260804작1 — Sandbox 에서 `Register-ScheduledTask` 가 CIM 거부로 실패).
7. `/TR` 인자의 경로는 `\"` 로 감싼다(공백 경로 쪼개짐 방지, 20260804작1 실측).

## 6. 첫 교체의 특수성 — 반드시 인지할 것

🚨 **1차 상신에서 PM 이 사장님께 틀린 답을 드린 지점이다.**

**교체를 수행하는 주체는 "받는 버전"이 아니라 "이미 돌고 있는 버전"이다.**

| 업데이트 | 수행 주체 | 결과 |
|---|---|---|
| 1.2.53 → **1.2.54** | 1.2.53 (자기교체 코드 **없음**) | ❌ 워치독 안 바뀜 |
| 1.2.54 → 1.2.55 | 1.2.54 (코드 있음) | ✅ 바뀜 |

⇒ **이 작업의 효력은 1.2.55 부터다. 1.2.54 에서는 안 돈다.**
   그래도 지금 넣는 이유: 1.2.54 에 안 실으면 1.2.56 으로 또 밀린다.

**따라서 첫 실동작(1.2.54→1.2.55)은 구버전이 아니라 1.2.54 워치독이 수행하며,
1.2.54 에는 Guardian 봉합(#55)이 함께 실려 있다** — 교체 실패 시 Guardian 이 뒤를 받친다.
단 **Guardian 이 아직 없는 PC** 가 있을 수 있으므로 §4-2(영구 고립 0)는 그것과 무관하게 성립해야 한다.
