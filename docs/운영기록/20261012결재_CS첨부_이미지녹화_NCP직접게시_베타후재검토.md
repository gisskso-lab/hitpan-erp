## §3 왜 「고객 PC 보관 + 본사가 터널로 당김」이 탈락했나 (실측)

PM 이 먼저 그 안을 추천했으나 **재보지 않고 추천했고, 재보니 현 구조에서 불가능**했다.

| 측정 | 결과 |
|---|---|
| 본사가 고객 터널 주소를 아나 | 🟢 안다 (`tenants.domain` · `tenant_domains`) |
| 본사가 고객 ERP 로 거는 코드 | 🔴 **0건** — 백오피스 HttpClient 는 전부 외부(국세청·토스·Cloudflare) 또는 고객이 등록한 webhook `target_url` |
| 본사가 고객 ERP 에 로그인할 자격 | 🔴 **원리적으로 없다** — #38(ERP 계정은 부모/자식 2개뿐 · 본사 계정 없음) · #40(본사 비번 0건) |

⇒ 터널은 열려 있어도 **문을 열 열쇠가 없다.** 만들면 #38·#40 을 뒤집고, #22 *"본사가 안 가지면 털릴 일 없다"* 의 정반대가 된다(본사 1곳 뚫리면 전 고객 ERP). CS 첨부 때문에 열 자리가 아니다.

## §4 「빠르게」 축으로 재본 것 — 다음에 또 묻지 않게

| 수단 | 효과 | 비용 |
|---|---|---|
| `async/await` | **0** | 지연 원인이 서버 블로킹이 아니라 **고객 PC 가 아직 안 물어봤기** 때문. 이미 전부 async |
| 메시지큐 | **0**(이미 있다) | `cs_outbox`·`cs_rating_outbox`(ERP) · `bo_cs_outbound`·`webhook_outbox`(본사). 없는 건 큐가 아니라 **깨우는 신호** |
| Pull 주기 5분→30초 | 최대 30초 | 🔴 5만 고객사(공영정보) 기준 본사가 **초당 약 1,600건**. NCP 한 대로 못 버틴다 |
| 상주 연결(SignalR 허브) | 거의 즉시 | ERP 에 SignalR 이 이미 있다(`NotificationHub`·`MigrationProgressHub` · 백오피스 0건). 🔴 **진짜 비용은 #27 통신무결성 17시나리오를 새로 무는 것** — 베타 출시 게이트다. 별건 트랙 |

실측 현재 주기: `PollInterval = 30초`(발신) · `PullInterval = 5분`(수신) — `CsOutboxSenderWorker.cs:35-36`

## §5 착수할 때 **먼저 다시 재야 할 것** (지금 값은 그때 낡는다)

1. 🔴 **NCP 디스크** — 2026-10-12 실측 여유 **2,194MB**(게시 1회 ≈ 730MB ⇒ 게시 3회분). 녹화파일을 NCP 에 직접 올리면 **ERP 업데이트 게시가 먼저 죽는다.** 상한·보관기한·자동폐기를 같이 설계하지 않으면 안 된다
2. 🔴 **#18·#22** — 화면 캡쳐에는 거래처명·금액·사원 이름이 **그대로 찍힌다.** 본사로 가는 업무 데이터다. 보관기한·열람권한·고객 동의 문구를 작2 보관기한 정책(`bo_cs_retention_policy`)에 묶을지 결재 필요
3. **봉투 계약** — CS 봉투는 **필드 화이트리스트**(밖의 키 하나면 통째 거부). 쪽지·답·평가·ack **네 문** 전부 추가형 변경 필요
4. **CS 표에 첨부 칸 0건** — ERP·백오피스 양쪽 다 없다. 신규 칸·표 설계 필요
5. **재사용 선례** — ERP `chat_files` 표 + `ChatController` **25MB 상한**. 이미지는 이 선례에 맞출 수 있다. 녹화는 별도 상한 필요
6. ⏸ **10/1 보류건과 같은 축** — 첨부 저장위치(프로그램 폴더 안) 건이 별건 트랙으로 보류돼 있다. 착수 시 같이 본다
