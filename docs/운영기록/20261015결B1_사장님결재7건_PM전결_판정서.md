## §2 판정 근거 — 하나씩

### 1. SMTP 자격증명 값 — 🟢 승인 · 🔴 PM 이 못 만든다
**값은 사장님 소유 자산이다.** 전결로도 PM 이 메일 계정을 만들 수 없다. 🔴 **자격증명 값·모양은 코드·문서·커밋 어디에도 적지 않는다**(가짜 값도 금지).

🔴 **넣는 이름을 틀리면 초록만 뜨고 메일은 0통이다** — 이게 [1-V] 축A 의 P0 다.
- 자격증명 화면은 `HITPAN_SMTP_*` **또는** `Smtp:*` 를 보고 초록을 띄운다 (`CredentialsStatusController.cs:114-117` · `Probe :133-137`)
- 발송기는 **`Smtp:Host`·`Smtp:User`·`Smtp:Password`·`Smtp:Port` 계열만** 읽는다 (`EmailSender.cs:51-59`)
- 둘을 잇는 매핑 코드 **0건** · 레포에 `Smtp__` 참조 **0건**

**⇒ 사장님께 요청하는 형태**: 환경변수 이름을 **`Smtp__Host` / `Smtp__Port` / `Smtp__User` / `Smtp__Password` / `Smtp__From`** 로 넣는다(ASP.NET Core 가 `__` 를 `:` 로 읽는다).
🟢 이 방식이면 **`appsettings.json` 무접촉**이다 — **#21 은 이 일의 차단 사유가 아니었다**(제가 앞서 그렇게 보고한 것을 정정한다).
🟢 보낼 입구도 이미 있다 — `CredentialsStatusController.cs:157` `POST test-mail`(Owner 전용).

**PM 이 값 없이 먼저 하는 것** = 갈래 **G1**: 화면과 발송기가 **같은 이름을 보게** 통일한다. 그래야 초록이 거짓말을 하지 않는다. 게이트는 「매핑 빼면 FAIL」 음성 대조군으로 세운다.
