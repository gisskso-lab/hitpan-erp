## 5. ③축 제기 신규 리스크 — PM 판정

### R-1. 마이그 교차검증 게이트가 적용을 막을 수 있다 → **이번 릴리스는 해당 없음 (PM 반증)**

③ 주장: 게시본에 마이그 SQL 55개. `UpdateOrchestrator.cs:483-509` 는 **하나라도 로컬 미적용이면 차단**, **조회 실패도 차단**(fail-closed).

PM 반증 실행 — 게시본 마이그 ID 와 `hitpan_db_clean.sql` 적재 이력의 **차집합 계산**:

```
게시본(1.2.54) 마이그 ID = 55 개
clean DDL 심는 이력      = 55 개
★ 미적용 판정될 마이그   = 0 개  → 게이트 통과
```

**판정**: 정상 설치 PC 에서는 차단되지 않는다. **단 ③의 지적 자체는 유효** — `schema_migrations` 조회 실패(테이블 손상·mariadb.exe 경로 실패) 시에도 차단되므로, 실측에서 반드시 확인한다.

### R-2. 디스크 여유공간 검사 없음 → **별건 백로그**

③ 확인: 워치독 전체에 `DriveInfo`/`AvailableFreeSpace` **0건**. 98MB zip + 전개 + `.old` 보존 = 300MB+ 무점검.
**판정**: 실재 리스크. 단 이번 팝업 이슈와 무관 → **별도 작업지시서로 분리**(오늘 범위 아님).

### R-3. `UpsertLatestAsync` 실패해도 "적재 완료" 로그 → **별건 백로그**

`Worker.cs:363` 이 반환값을 무시하고 `:365` 에서 성공 로그. **로그가 거짓말을 한다.**
**판정**: 실재 결함. 헌법 #15 취지 위반. 이번 이슈와 무관 → **별도 분리**.

### [지시 3] 1.2.55 게시 — **실측 완주 후에만**

1.2.54 가 적용되면, 그때 비로소 **오늘 봉합 3건이 실제로 도는 버전**이 고객 PC 에 올라간다.
1.2.55 를 게시해 **1.2.54 가 1.2.55 를 새 방식으로 잡는지** 확인해야 봉합이 실증된다.

> **중요**: 업데이트는 **받는 쪽**이 실행한다. 1.2.52 가 1.2.54 를 받을 땐 **1.2.52 의 옛 방식**으로 받는다.
> 그래서 오늘 봉합의 실증은 **1.2.54 → 1.2.55 구간**에서만 가능하다. 1.2.54 설치 성공은 그 전제 조건일 뿐이다.
