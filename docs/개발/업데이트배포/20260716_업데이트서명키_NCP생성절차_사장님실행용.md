## 왜 이 열쇠가 필요한가

지금 자동 업데이트는 **"업데이트 파일 목록(manifest)이 진짜 우리가 만든 것인지" 확인할 방법이 없습니다.**

- 목록 주소는 환경변수 하나로 바꿀 수 있습니다
- 목록 안의 검사값(sha256)도 목록 안에 있어서, 목록을 바꾸는 사람이 그것도 같이 바꿉니다

지금은 **파일 교체 기능이 없어서** 다운로드까지만 하고 멈추니 구멍이 막혀 있습니다.
**그런데 다음 단계(W4-2)에서 파일 교체를 붙이는 순간** — 환경변수 하나로 **남의 프로그램이 고객 PC에 관리자 권한으로 설치**됩니다.

그래서 **파일 교체보다 이 열쇠가 먼저**입니다.

### 이 열쇠의 위력 (CTO 경고)

> *"시리얼 열쇠가 새면 = 가짜 라이선스.
> **업데이트 열쇠가 새면 = 전 고객 PC에서 아무 프로그램이나 실행.**
> 더 센 열쇠를 더 약한 곳에 두면 안 된다."*

그래서:
- **개인키는 NCP에만** — GitHub에 절대 안 둡니다. CI는 파일과 목록까지만 만들고, **서명은 사장님이 NCP에서 1회**
- **시리얼 열쇠와 다른 열쇠** — 하나가 새도 다른 쪽으로 안 번지게
- **공개키만 프로그램에 넣습니다** — 공개키는 새도 위조가 불가능합니다

---

## 사장님이 하실 일

### 1단계 — NCP 서버 접속

평소 쓰시던 방법으로 NCP 서버에 접속하십시오.

### 2단계 — 열쇠 만들기 (복사해서 붙여넣기)

```bash
sudo mkdir -p /var/hitpan/update-keys
cd /var/hitpan/update-keys

# 개인키 생성 (이 파일이 새면 전 고객 PC가 위험합니다)
sudo openssl ecparam -name prime256v1 -genkey -noout -out update_private.pem

# 공개키 뽑기 (이건 새도 무해합니다)
sudo openssl ec -in update_private.pem -pubout -out update_public.pem

# 권한 잠그기 — root만 읽을 수 있게 (시리얼 열쇠와 동일 정책)
sudo chmod 600 update_private.pem
sudo chmod 644 update_public.pem
sudo chown root:root update_private.pem update_public.pem

# 확인
sudo ls -l /var/hitpan/update-keys
```

**기대 결과**: `update_private.pem`이 `-rw-------` (600), 소유자 `root`

### 3단계 — 공개키만 저에게 주십시오

```bash
sudo cat /var/hitpan/update-keys/update_public.pem
```

출력된 내용(`-----BEGIN PUBLIC KEY-----` ~ `-----END PUBLIC KEY-----`)을 **채팅에 붙여넣어 주십시오.**

> ⚠️ **`update_private.pem`은 절대 열지도, 붙여넣지도 마십시오.**
> 공개키(`update_public.pem`)만입니다. 파일 이름에 `public`이 있는 것만 됩니다.
> 7월 7일 시리얼 열쇠 때와 같은 원칙입니다.

## 나중에 배포할 때 — 서명 1회 (지금은 아님, 미리 규격만 못박음)

> ⚠️ **검증팀 SoD 반증 P0 (2026-07-16) 반영**: 서명 규격이 "나중에 정하자"로 비어 있으면,
> 발급(openssl)과 검증(프로그램)이 어긋나 **정상 업데이트가 전 고객 PC에서 거부**되는 사고가
> 릴리스 당일 터집니다. 그래서 지금 서명 절차를 **완성해 못박습니다.** 실제 서명은 나중에 하십니다.

새 버전을 NCP에 올릴 때, 사장님이 아래 **서명 스크립트 1회**를 실행하시게 됩니다.
스크립트는 레포에 있습니다: `installer/updates/sign-manifest.sh` (NCP로 함께 올라갑니다).

```bash
# 예시 — 실제 값은 그때 제가 채워 드립니다
sudo bash installer/updates/sign-manifest.sh \
  --private /var/hitpan/update-keys/update_private.pem \
  --version 1.2.35 \
  --channel normal \
  --url https://updates.hitpan.kr/packages/hitpan-1.2.35.zip \
  --sha256 <zip의 sha256> \
  --size <zip 바이트수> \
  --migration false
```

스크립트가 하는 일:
1. 프로그램이 검증하는 것과 **똑같은 서명 대상 문자열**을 만듭니다(규격 `hitpan-update-v1`).
2. 그 문자열에 개인키로 서명합니다(`openssl dgst -sha256 -sign`).
3. 서명(Base64)과 kid(`upd-v1`)를 출력합니다 → manifest.json에 넣습니다.

**규격이 한 곳(스크립트)에 못박혀 있어**, 사람이 문자열을 손으로 만들다 한 글자 틀려 전 고객 업데이트가
막히는 사고가 원천 차단됩니다. 프로그램(검증)과 스크립트(발급)가 같은 규격을 쓰는지는 자동 테스트로 고정돼 있습니다.

**이 번거로움이 곧 안전장치입니다** — 전 고객 PC에 프로그램을 심는 방아쇠에 사람 결재가 붙는 것입니다(헌법 #29 정신). 자동화는 정식 출시 때 별도로 설계합니다(mTLS + 감사로그).
