## §1. 목적 · 범위

### 목적
자동배포(GitHub Actions)가 NCP 에서 **root 임의 셸·개인키 서명오라클을 못 쓰게** 비특권 전용계정 + 인자최소 래퍼 2종으로 가둔다. "NCP 안쪽 sudoers"만이 아니라 **GitHub→NCP 신뢰경계(공급망·Secret)**까지 닫는다(안 상무).

### 범위 (IN)
1. NCP: 비특권 계정 `hitpan-deployer`(셸 有·sudo그룹 無·홈700·restrict SSH).
2. NCP: 전용 SSH 키쌍 신설(기존 root키 재사용 금지) → authorized_keys `restrict` 프리픽스.
3. NCP: 래퍼 2종 상주 — **publish-run.sh**(자동업데이트, 인자 zip/manifest 파일명만·webroot 등 오버라이드 봉인) + **deploy-web.sh**(웹CD, rsync·drop-in·롤백 전부 흡수).
4. NCP: `/etc/sudoers.d/hitpan-deployer` — 래퍼 2개만 NOPASSWD + `log_output` 감사. `visudo -c` 필수.
5. NCP: 파일권한 트리 root:root 755(updates·deploy·상위 전부).
6. 레포: `publish-update.sh:41` WEBROOT 정정 커밋(SSOT) + trufflehog OPENSSH 개인키 룰 신설 + GitHub 액션 SHA 핀.
7. GitHub: `NCP_USER` root→hitpan-deployer, `NCP_SSH_PRIVATE_KEY` 신규키. **교체 전 기존 root Secret 백업**.

## §2. 🔴 핵심 리스크 (6관점 종합 — 받아쓰기 차단)

### R-1 (BLOCKING·CTO+검증+안상무) — sudoers 와일드카드는 인자를 못 가둔다 → 래퍼로 원천 제거
sudoers `publish-update.sh --zip * --manifest *` 의 `*` 는 공백 포함 탐욕 매칭이라 `--zip a --private /tmp/evil.pem --manifest b` 가 통과 → **개인키 오버라이드 서명**. §3-3 v1 초안 폐기. **정공법 = publish도 인자 최소 래퍼(publish-run.sh)**.

### R-2 (BLOCKING·안상무 V-1) — 서명 오라클: 계정이 개인키를 못 읽어도 서명을 대행시킬 수 있다
화이트리스트 래퍼를 정상 호출해 **악성 zip 에 유효 서명** → 전 고객 워치독이 검증 통과 → 악성 자동설치. `cat` 차단(정보유출)만으론 부족. **베타 방어 = publish-run.sh 가 sha256·다운그레이드·zip↔manifest 파일명 게이트로 임의내용 서명을 거부**(약한 오라클 방어) + **sudo I/O 감사로그**(사후추적). **정식 = HSM/KMS + 릴리스 서명 사람결재**(별건).

### R-3 (BLOCKING·보안2 D-1) — 웹CD 래퍼가 systemd drop-in 을 안 흡수하면 ExecStart 변조=root RCE
`sudo tee /etc/systemd/system/*/release-version.conf` 를 sudoers 로 열면 drop-in 에 `ExecStart=/bin/bash -c ...` 주입 가능. **deploy-web.sh 가 drop-in 생성·daemon-reload·restart·롤백까지 전부 하드코딩 흡수.** sudoers 에 tee/mkdir/systemctl 개별 허용 0.

### R-4 (BLOCKING·검증팀) — source 체인 + rename 우회: 파일 755 만으론 부족
publish-update.sh 가 sign-manifest.sh 를 root 로 `source`. hitpan-deployer 가 **디렉토리** 쓰기권 있으면 `mv` 로 교체 → root RCE. **상위 트리 전부 root:root 755(디렉토리 쓰기 root만).** DoD 에 rename 우회 실측(`mv` → denied).

### R-5 (BLOCKING·CTO) — 롤백 불능 2건
① 계정 전환 시 옛 root Secret 소실 → **교체 전 기존 NCP_USER·NCP_SSH_PRIVATE_KEY 값 안전 보관**(순서 step0). ② 배포 실패 시 자동 원복이 래퍼에 없으면 장애 방치(#39) → **deploy-web.sh 에 healthcheck 실패 시 백업본 롤백 하드코딩**.

### R-6 (BLOCKING·안상무 4-1) — 공급망: GitHub 액션 이동태그 → SHA 핀
`actions/checkout@v5` 등 이동태그는 태그 재지정·계정침해 시 다른 코드 실행(SolarWinds형). 개인키 서명 파이프라인은 **전 액션 커밋 SHA 핀**(`@<40자> # v5.x`).

### R-7 (BLOCKING·안상무 V-3) — 운영 시크릿(appsettings.Production.json) 격리
개인키만 격리하고 DB·SMTP 비번은 방치. **hitpan-deployer 의 `/opt/hitpan/*/appsettings.Production.json` 읽기 차단 + 빌드 아티팩트에 미포함 확인**.

### R-8 (BLOCKING·보안1 D-1) — trufflehog OPENSSH 개인키 사각
현 EC 룰은 `BEGIN OPENSSH PRIVATE KEY`(ed25519) 미탐지. **이번에 만드는 배포 SSH 개인키가 정확히 사각지대.** OPENSSH 룰 신설(동일 커밋).

### §3-2. SSH 키 (보안1 S-1·S-2, 보안2 D-4)
```
ssh-keygen -t ed25519 -f hitpan-deployer-key -C "hitpan-deployer@cd" -N ""
# authorized_keys 내용: restrict,no-pty ssh-ed25519 AAAA... hitpan-deployer@cd
#   (restrict=포워딩·X11·agent 전면차단, no-pty=대화형 최소화. command= 는 웹CD 다중명령과 충돌→미사용)

# 개인키 → GitHub Secret: gh secret set NCP_SSH_PRIVATE_KEY < hitpan-deployer-key   (stdin만! --body 금지)
# 등록 후: shred -u hitpan-deployer-key                                              (복구불가 삭제)
```

### §3-3. 래퍼 2종 (R-1·R-3·R-5 핵심)

**publish-run.sh** (자동업데이트 — 와일드카드 제거):
- 인자 = **zip·manifest 파일명 조각만**(경로 접두 `/home/hitpan-deployer/staging/` 하드코딩, 파일명 `[A-Za-z0-9._-]+` 검증). 또는 인자0 + staging glob 스캔.
- `--webroot·--private·--feed-url·--public·--allow-republish` **수용 불가**(래퍼가 publish-update.sh 에 안 넘김). = 오버라이드 물리봉인.
- 내부에서 `sudo` 불요(래퍼 자체가 sudoers 대상). publish-update.sh 호출은 고정 기본값으로만.

**deploy-web.sh** (웹CD — 안상무·CTO·보안2 8+조건):
1. 인자 0개 강제(`[[ $# -eq 0 ]] || exit 1`). RELEASE_VERSION 은 **환경변수**로 받되 `[[ =~ ^[A-Za-z0-9._-]+$ ]]` 검증(drop-in tee 주입 차단, 보안2 D-1).
2. rsync 소스(`/tmp/backoffice-api/`…)·타겟(`/opt/hitpan/…`)·`--exclude=appsettings.Production.json`·`--exclude=appsettings.Development.json` **전부 상수**(R-7 운영시크릿 보존).
3. systemd drop-in 경로·`[Service]` 템플릿·유닛 3개(`hitpan-backoffice-api/web`,`hitpan-landing`) 하드코딩 + `daemon-reload` + `restart` (R-3 흡수).
4. **healthcheck + 실패 시 백업본 롤백 하드코딩**(R-5②, #39 "망가진채 방치" 차단).
5. `set -euo pipefail`, `flock`(동시 dispatch 경합 차단), 소유 root:root 755.
6. `rsync --safe-links`(심링크 공격 차단, 검증팀 HOLE-5).

### §3-4. sudoers (`/etc/sudoers.d/hitpan-deployer`) — 래퍼만·감사
```
Defaults:hitpan-deployer  log_output, logfile=/var/log/hitpan-deploy-sudo.log
hitpan-deployer ALL=(root) NOPASSWD: /opt/hitpan/deploy/publish-run.sh
hitpan-deployer ALL=(root) NOPASSWD: /opt/hitpan/deploy/deploy-web.sh
# tee·mkdir·rsync·cp·systemctl·daemon-reload 개별 항목 절대 0. 와일드카드 인자 0.
```
- `visudo -cf /etc/sudoers.d/hitpan-deployer` 통과 못 하면 배치 금지.

### §3-5. 파일권한 트리 (R-4, 보안2 D-3)
```
for d in /opt /opt/hitpan /opt/hitpan/installer /opt/hitpan/installer/updates /opt/hitpan/deploy; do
  chown root:root "$d"; chmod 755 "$d"; done
chown root:root /opt/hitpan/installer/updates/*.sh /opt/hitpan/deploy/*.sh
chmod 755        /opt/hitpan/installer/updates/*.sh /opt/hitpan/deploy/*.sh
```

### §3-6. GitHub Secret (맨 마지막, R-5①)
- **step0(순서 최우선): 기존 NCP_USER(root)·NCP_SSH_PRIVATE_KEY 값 안전 보관**(롤백 자산).
