## 0. 사장님 지시 원문 (의중 = 이 작업의 헌법)

> **"정공법으로 실측해!!! 임시라는 건 없어. 그냥 되면 되는 거고 아니면 아닌 거고."**

### 이 지시의 의중 (PM 해석 — CTO·대표 확인 요망)
1. **게이트를 우회·제거·완화하는 테스트 코드 = 금지.** 그건 "임시"다. 임시로 통과시킨 실측은 실측이 아니다.
2. **영업시간 게이트·야간 창·하루 1회 게이트는 실제 동작의 일부다.** 그것까지 포함해 "그냥 되는지" 본다. 실제로 적용되는 시간대(§3)에 관측하는 게 정공법.
3. **결과는 정직하게.** 되면 "됐다", 안 되면 "안 됐다 + 어디서 멈췄나". **분식·받아쓰기·거짓봉합 금지**(헌법 #32·SOP).

  - ⓐ 고리4 코드(a2c249f)가 실제로 교체·재시작을 하는가? (코드 정상성)

## 3. 실측 시나리오 (정공법 — Major 채널 기준)

> **⛔ 착수 전제조건 (BLOCKING GATE — CTO 결재 B-1·B-2 반영, 미충족 시 착수 금지)**
> 1. **버전 못박음**: 설치본 = **1.2.33**(고리4 포함) / 업데이트본 = **1.2.34**. 서버(1.2.34) > 설치(1.2.33) 확정 — 아니면 다운그레이드 차단 발동해 "감지 0"을 고리4 실패로 오판한다.
> 2. **NCP manifest 게시 확인**: 업데이트본(1.2.34) manifest·zip 이 `updates.hitpan.kr` 에 실제 게시됐는지 **사장님 손으로 확인**(PM·에이전트 NCP 직접 조작 금지 — 헌법 #29). 인수인계서의 "manifest 1.2.30 고정" 재발 지점이다.
> 3. **실측 시간대**: Major 동의 적용은 영업시간(평일 09~18시) **밖**에만 진입한다. **실측·검증팀 SoD 재현 모두 평일 18시 이후 또는 주말에 수행. 낮 착수 금지** — 낮이면 "보류"가 정상인데 실패로 오판한다.

### 준비물
- **설치본 EXE = 1.2.33(고리4 포함본).** (dist/실측패키지-20260720/ 의 1.2.33 EXE = 오늘 HEAD 빌드라 고리4 포함.)
- **업데이트본 = 1.2.34 + manifest(channel: Major)** — NCP `updates.hitpan.kr/manifest.json` 에 게시(위 전제조건 2).
- **환경 = Windows Sandbox(백지)** — 개발 PC 정상작동은 검증 아님([[feedback_dev_pc_proves_nothing]]).

### 실측 절차 (관측 항목 = 되면/안 되면 정직 기록)
1. **설치**: 고리4 든 EXE 백지 Sandbox 설치 → 워치독 서비스 Running 확인 → 로그인 성공.
2. **버전 게시**: 상위 버전 zip + Major manifest NCP 업로드(서버 > 설치). `publish-update.sh` 또는 수동.
3. **감지**: 워치독 하루 1회 평가 → `local_update_status`(DB-83)에 새 버전 적재 → 로그.
   - 재실측이면 **워치독 서비스 재시작**으로 하루 1회 게이트 리셋(우회 아님, 정상 재기동).
4. **팝업**: ERP 로그인/새로고침 → **Y/N 팝업 노출 + 변경내용(releaseNotes/consentMessage) 표시** 확인.
5. **Y 클릭**: 동의 → `local_update_status` 갱신.
6. **적용 관측 (핵심)**: 워치독이 동의 읽음 → **영업시간 게이트**(평일 9~18시면 보류가 정상) → **적용되는 시간대(평일 저녁/주말)에** `ApplyUpdateAsync` 진입:
   - 다운로드 + sha256·서명 검증
   - 백업 생성
   - W4-1 구성요소 정지 → W4-2 파일 스왑 → W4-4 재시작 → W4-5 기동 검증 → (실패 시 롤백) → W4-6 상태 기록
7. **결과 확인**: 재기동 후 **ERP 버전이 상위 버전으로 바뀌었는가**(어셈블리 버전·about 화면) + `local_update_apply_status` 성패 기록.

### 실측 케이스 2 — 롤백 유도 (CTO 결재 B-3, 성공만 보면 거짓봉합)
고리4의 절반은 **실패 시 롤백**이다. 성공만 보고 "고리4 검증 완료"라 하면 롤백 미검증인데 검증됐다 착각한다. 아래 중 1건 이상 실측:
- **다운로드 검증 실패 주입**: 업데이트본 zip 을 의도적으로 손상(sha256 불일치) → "다운로드/검증 실패 → 적용 차단, 구버전 무손상" 관측(`ApplyUpdateAsync` L134~139).
- **or 백업 실패 강제** → "🛑 적용 전 백업 실패 → 물리적 차단, status=blocked" 관측(L146~152).
- **핵심 관측**: 롤백/차단 후 **ERP가 구버전 그대로 살아있는가**(다운되지 않았는가). = 실패 주입 = 게이트 우회 아님 = 정공법 범위.

### 관측 결과 기록 양식 (정직)
- 각 단계 PASS/FAIL + 로그 근거(`watchdog` 로그·`install.log`·**`local_update_apply_status` DB 행 스냅샷** = 1차 진실원, CTO C-2).
- **버전 바뀜 판정 = 파일 FileVersion + about 화면 2중 확인**(어셈블리 1.0.0 스탬핑 미반영 이력 대비, CTO C-1). 검증팀은 로그 아닌 파일 타임스탬프로 교차확인.
- FAIL 시 **정확히 어느 단계에서 멈췄나**(감지 0 / 팝업 0 / 동의 미전달 / 스왑 실패 / 재시작 실패 / 롤백 발동).
- **"영업시간이라 보류됨"은 FAIL 아님 = 정상 동작.** 적용되는 시간대에 재관측.
