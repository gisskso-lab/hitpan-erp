## 1. 실측 순서 (한눈에)

```
① NCP manifest 를 1.2.30 → 1.2.33 으로 정정      (publish-update.sh)
② 1.2.33 EXE 를 Sandbox 신규 설치 → 정상 확인      ← 실측 1: 설치마법사
```

## 3. 단계별 실행

### ① manifest 1.2.30 → 1.2.33 정정
재료 `1.2.33/` 의 zip·manifest 를 NCP 로 올린 뒤:
```bash
sudo bash publish-update.sh \
  --zip      hitpan-1.2.33.zip \
  --manifest manifest-1.2.33-unsigned.json
```
- 1.2.30 → 1.2.33 은 상향이라 다운그레이드 게이트 통과.
- 끝 화면: `✅ 배포 완료 — updates.hitpan.kr 이 이제 1.2.33 을 가리킵니다.`
- 확인: 브라우저로 `updates.hitpan.kr/manifest.json` → version 이 1.2.33, signature 있음.

### ② 1.2.33 Sandbox 신규 설치 (실측 1)
- Windows Sandbox 실행(휘발성 — 헌법 #39, 운영 안 건드림).
- `HitPan-ERP-Setup-1.2.33.exe` 실행 → 시리얼 입력 → 설치 완료 → 부모계정 등록 → 로그인.
- **관측 포인트**:
  - [ ] 설치가 끝까지 되는가(설치마법사 정상작동)
  - [ ] 로그인·첫 화면 정상인가
  - [ ] (선택) 워치독이 "나는 1.2.33" 으로 감지하는가 — 본사 백오피스 메타핑에 1.2.33 으로 찍히는지, 또는 로컬 진단 로그
- 이 단계까지 = **실측 1(설치마법사) 완료**. 여기서 **1.2.34 를 아직 안 올렸으므로** 워치독은 "최신 1.2.33 유지" 라 업데이트를 안 한다(정상).

### ③ 1.2.34 업로드 → manifest 자동 1.2.34
재료 `1.2.34/` 를 NCP 로 올린 뒤:
```bash
sudo bash publish-update.sh \
  --zip      hitpan-1.2.34.zip \
  --manifest manifest-1.2.34-unsigned.json
```
- 1.2.33 → 1.2.34 상향, 게이트 통과.
- 끝 화면: `✅ 배포 완료 — updates.hitpan.kr 이 이제 1.2.34 를 가리킵니다.`

### ④ 자동 업데이트 관측 (실측 2)
- ②에서 설치한 Sandbox 의 1.2.33 PC 를 **켜둔 채** 둔다(끄면 워치독 안 돎).
- 워치독이 다음 점검 주기에 manifest(1.2.34)를 감지 → "1.2.33 < 1.2.34" → 업데이트 진행.
- **관측 포인트** (사장님 원칙 확인):
  - [ ] 워치독이 **1.2.33 → 1.2.34** 로 감지하는가(1.0.0 이 아니라 정확히 1.2.33 에서 출발)
  - [ ] Major 채널이라 "새 버전(1.2.34) 준비됨. 업데이트할까요?" 동의 팝업이 뜨는가
  - [ ] 동의 후 다운로드 → sha256 검증 → 백업 → **파일 교체 → 재시작 → 검증** 이 도는가
  - [ ] 업데이트 후 히트판이 **1.2.34 로 정상 기동**하는가
  - [ ] 실패 시 **롤백**으로 1.2.33 이 살아있는가
- 이게 되면 = **실측 2(자동 업데이트) 완료 = 고리4 실증.**

> ⏱️ 워치독 업데이트 점검은 하루 1회 게이트가 있을 수 있음 — 즉시 관측하려면 Sandbox 에서 워치독 서비스 재시작 또는 점검 주기 앞당김(재료 옆 참고).
