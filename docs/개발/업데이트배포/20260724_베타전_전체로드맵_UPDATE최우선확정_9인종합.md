## 0. 사장님이 못박은 것 (이 로드맵의 뿌리)

> **"한 건 한 건 수정해서 또 NCP에 수동으로 올리고 또 설치하고 테스트할래? 아니면 수정 건수 수정해서 ERP 웹에서 업데이트 버튼 하나 딸깍해서 테스트할래?"**
> **"UPDATE 자동화 성공의 워크스페이스 구축이 가장 기본이고 먼저다."**

핵심: **UPDATE는 "기능 하나"가 아니라 "남은 모든 수정의 작업속도를 결정하는 인프라"다.** 이게 안 서면 남은 6개+α를 고칠 때마다 재설치 지옥(두더지잡기). 서면 전부 "딸깍". 그래서 가장 기본·먼저.

## 1. 베타 전 미완 목록 (사장님 제시 6개 + α)

| # | 영역 | 현 상태 | UPDATE로 고쳐지나 |
|---|---|---|---|
| 1 | 데이터 마이그레이션 | 불안정 → 100% 달성 필요 | 코드=OK / 스키마=고리5 선행 |
| 2 | 워크플로우 풀스택 테스트 | 개별기능만, 종단 풀스택 절차 없음 | 절차 신설(테스트환경) |
| 3 | 데이터 무결성·정합성·안정성 | 신뢰수준 미통과 | 코드=OK / 스키마=고리5 |
| 4 | 백오피스 CS 영역 재설계 | 실행도 못함 | 서버측 = UPDATE 무관(NCP 배포) |
| 5 | ERP CS(챗봇·매뉴얼) | 초등단계 | 코드=UPDATE OK |
| 6 | 보안 | 취약(배포계정·HMAC·서명키·rate-limit) | 서버측=OK / 클라이언트측=EXE재배포(UPDATE) |
| α | 신규설치 clean DDL(CF-1·2) | licenses·watchdog 누락 | **UPDATE로 못 고침**(신규설치 진실원) |

**통찰(9인 공통):** 위 대부분이 결국 **UPDATE 통로로 고쳐 재배포해야 도달**한다. UPDATE 없으면 이미 깔린 고객에게 전달 불가(재설치=없는 경로). → **UPDATE = 다른 모든 수정의 전제.**

## 2. 어벤져스 9인 판정 — 만장일치 지지 (조건부)

| 관점 | 판정 | 핵심 |
|---|---|---|
| 설계(AI수석) | 지지 | UPDATE 살면 나머지 등급↓. 스키마변경은 고리5 선행 |
| 검증팀장 | 지지 | "UPDATE로 고침"은 백지종단 1회 통과 후 참. 실측0회=미검증 |
| 안철수 상무 | 조건부수용 | 서명키 무방비노출 차단 1선만 UPDATE와 동시 |
| CTO | 부분지지 | UPDATE는 "설치 이후"만 고침. 파이프라인·신규설치·데이터 사각 |
| 네트워크 | 지지 | 통신 초록. webroot 정정 1건 남음 |

| 풀스택 | 지지 | 코드 6고리 다 이어짐. 끊긴 건 CI→NCP 게시다리 1개 |

## 3. 🔴 "UPDATE로 못 고치는 것" — 부트스트랩 사각 (9인 공통 경계선)

UPDATE는 **"설치 이후 + 애플리케이션 계층"만** 고친다. 아래는 UPDATE로 못 고침 → UPDATE와 동시/선행 필요:

| 사각 | 왜 UPDATE로 못 고치나 | 처리 |
|---|---|---|
| **A. 파이프라인 자신**(서명 개인키 무방비노출, 검증기 버그, 다운그레이드 방어) | 파이프가 오염되면 파이프로 보낸 소독약도 오염. 검증기가 자기 자신 검증 | **서명키 노출차단 1선 = UPDATE와 동시**(안상무·CTO). HSM·2인서명은 정식 |
| **B. 신규설치**(clean DDL·설치마법사·시리얼·부모계정) | UPDATE 도달 전 단계. 깨지면 UPDATE 채널이 안 열림 | **clean DDL 무결성(#36) 병렬 봉합**. 단 첫 실측은 안 막음(P0검사) |
| **C. 스키마 변경**(새 테이블/컬럼, DB-*.sql) | 워치독은 파일교체만. 적용기(고리5) 미결선 + 교차검증 게이트가 릴리스 통째 차단 | **첫 실측 릴리스엔 스키마 절대 안 실음**. 스키마변경은 다음 설치본 clean DDL로 |
| **D. 데이터 되돌림**(파괴적 마이그) | 데이터 손실은 UPDATE로 복구 불가 | 백업·롤백 게이트(#39) 상시 |

## 4. ⭐ UPDATE 최우선 확정 — 첫 실측 최소 선행 3개 (9인 공통)

**목표: "UPDATE 실측 사상 첫 통과" = 백지PC에서 1.2.39 설치 → 1.2.40 자동교체 완주.**

| 선행 | 내용 | 담당/결재 |
|---|---|---|
| **①앞단 1회** | demo T-001 시리얼로 백지 Sandbox에 1.2.39 설치→부모계정→로그인200 (HMAC 폴백, 공개키 개인키 불필요) | 사장님 Sandbox |
| **②게시다리 정정** | publish-update.sh **webroot 정정**(안하면 첫실측 100%실패, 상주본 완료·레포 미정정) + deploy-update.yml 활성화 | A-3·A-4·A-5 (NCP결재) |
| **③새버전** | 1.2.40 게시 (같은버전 감지0) | A-6 dispatch |

**막지 않는 것(9인 확인):** CF-1·CF-2(licenses/watchdog 누락)는 로그인·UPDATE 실측 **안 막음**(P0검사·코드실측 일치). 설치마법사·백오피스 인증 완성도도 흐름 안 끊음(HMAC 폴백).

## 5. 전체 로드맵 (UPDATE 최우선 → 나머지 순서)

```
━━━ PHASE 0: UPDATE 워크스페이스 (최우선·기본) ━━━
  A-3 NCP sudo(webroot정정 포함) → A-4 GitHub → A-5 활성화 → A-6 dispatch
  → A-7 백지 종단 첫 실측 (설치→UPDATE 자동교체→롤백 리허설)  ★통로 확보★
  [동시필요 최소선] 서명키 무방비노출 차단(비특권화 트랙A sudoers 2인자)
       ↓ 통로 확보 = 이후 전부 "딸깍"으로 전환
━━━ PHASE 1: 신규설치 무결성 (UPDATE로 못 고치는 것) ━━━
  clean DDL CF-1·2 봉합(#36) + 고리5(스키마 적용기 결선, #39 백업·롤백세트)
━━━ PHASE 2: 남은 6개 (UPDATE 통로로 딸깍 반복) ━━━
  1 마이그 100% / 2 풀스택 종단 테스트 절차 / 3 데이터 무결성·정합성
  5 ERP CS 챗봇·매뉴얼  ← 코드수정형, UPDATE로 반복 배포
  4 백오피스 CS 재설계  ← NCP 서버배포(UPDATE 무관)
━━━ PHASE 3: 과금 전 보안 데드라인 (안상무·보안매니저 못박음) ━━━
  ①백오피스 refresh토큰 회전 ②rate-limit·잠금(IP·라이선스키) 
  ③서명키 정식격리(HSM/KMS) ④HMAC 2-part 제거(기존시리얼 소진 후)
  ⑤배포계정 완전 비특권화(오늘 v2)
  → 이 5개 없이 SaaS 과금 절대 금지 (④안닫히면 대칭키1개=임의회사 결제우회)
```

**PHASE 경계 원칙:** PHASE 0(UPDATE)이 서기 전엔 PHASE 2를 손대도 전달 불가. PHASE 3은 과금이 데드라인(무기한 연기 방지, 안상무 감수).
