## 7. 검증팀에 요청 (내가 스스로 위험하다고 보는 곳)

1. 🔴 **`Request.Headers["User-Agent"]` 가 없을 때** — `.ToString()` 은 빈 문자열을 돌려준다(null 아님).
   ⇒ 갈래 A 의 `ResolveDeviceType(null, "")` 가 **빈 문자열을 "UA 있음"** 으로 읽으면 판정이 갈린다.
   내 쪽에서 `null` 로 바꾸지 **않았다**(설계가 그렇게 안 적었고, 자기 판단으로 메우지 않기 위해). **이 경계를 봐 달라.**
2. 🔴 **로그아웃 401 경주** — `sid` 로 좁히면 자기 세션 한 줄만 지운다. 같은 PC 에서 탭 두 개로 로그인한 경우
   한쪽 로그아웃 뒤 다른 탭의 `sid` 가 살아 있을 수 있다. 종전 전삭이 우연히 덮던 상황이다. **의도된 동작인지 판정 필요.**
3. ⚠️ **캐시 10초의 반대 방향** — 고객이 축 B 를 **끈 직후에도 최대 10초는 401 이 더 난다**(캐시 TTL).
   *"끄면 즉시 풀린다"* 가 아니다. 축 A 와 같은 값을 쓴 것이라 새로 만든 문제는 아니지만, 문구로 약속하면 안 된다.
4. ⚠️ **회귀 우려** — 축 B 킬스위치가 켜진 테넌트(현재 DB 기본값 `1`)에서는 동작이 종전과 같고,
   **꺼진 테넌트에서만** 생존 조회가 건너뛰어진다. 즉 이 변경은 *"401 을 덜 내는"* 방향이다.
   반대로 **`DB-128` 이 안 붙은 DB 에서는 F-1 잠금이 그대로 남는다** — 갈래 C 없이 이 절만 머지하면 봉합이 아니다.
