## ② 압축 풀고 NCP로 올리기 (PowerShell — 한 줄씩)

### 2-1. Downloads로 이동 + 압축 풀기 (복붙)
```powershell
cd "$env:USERPROFILE\Downloads"
$upd = Get-ChildItem -Filter "HitPanUpdate-1.2.38*.zip" | Select-Object -First 1
Expand-Archive -Path $upd.FullName -DestinationPath ".\upd-1.2.38" -Force
Get-ChildItem ".\upd-1.2.38" -Recurse -File | Select-Object Name
```
→ `hitpan-1.2.38.zip` 과 `manifest-1.2.38-unsigned.json` 두 개가 보이면 정상.

### 2-2. NCP로 두 파일 업로드 (복붙 — 키 경로 그대로)

## ③ NCP 접속 → publish-update.sh 실행 (복붙)

### 3-1. 서버 접속
```powershell
ssh -i "C:\Users\소순근\Downloads\hitpan-key.pem" root@211.188.58.140
```
→ 암호 `P6-eUEJuiFFi`

### 3-2. 게시 (서버 안에서)
```bash
cd /root
bash publish-update.sh --zip hitpan-1.2.38.zip --manifest manifest-1.2.38-unsigned.json
```

**publish-update.sh 가 자동으로 하는 것:**
1. 입력 검증 (zip sha256 == manifest.sha256)
2. 다운그레이드 게이트 (현 1.2.37 < 1.2.38 → 통과)
3. zip 배치 → `packages/hitpan-1.2.38.zip`
4. 개인키 서명 (NCP 전용, 헌법 #22)
5. 원자 교체 (tmp→mv, 옛것 .bak 백업)
6. 자기검증 (서빙본 재취득 → 버전·서명·zip 200)

끝에 **"배포 완료"** 나오면 성공. 실패 시 `.bak` 자동 롤백(전 고객 정지 아님).

### 3-3. 게시 확인 (서버 안에서, 복붙)
```bash
curl -s https://updates.hitpan.kr/manifest.json | grep -o '"version":"[^"]*"'
```
→ `"version":"1.2.38"` 나오면 게시 성공. 서버 나가기: `exit`

### 4-B. 자동업데이트 실측 (1.2.37 → 1.2.38)
지금 Sandbox 워치독(1.2.37) 재시작:
```powershell
Restart-Service HitPanWatchdog
```
1분 뒤 워치독 로그:
```powershell
Get-EventLog -LogName Application -Source HitPanWatchdog -Newest 30 | Format-List TimeGenerated, Message
```

**성공 신호:**
| 로그 | 의미 |
|---|---|
| `Emergency 채널 — 안내 후 적용 진입: 1.2.38` | 감지·판정 성공 |
| `서명 확인 완료(1.2.38, kid=upd-v1)` | 서명 통과 |
| **ERP 화면에 업데이트 팝업이 뜨고 유지됨** | 팝업 봉합(작1) 실측 |
| Y 누름 → 백업→교체→재시작 로그 | **고리4 실동작** |
| `HitPan Watchdog started v1.2.38` | 교체 완료 |

교체 후 브라우저 test1 로그인 화면 뜨면 → **404 봉합 + 자동업데이트 종단 완주 동시 확인.**
