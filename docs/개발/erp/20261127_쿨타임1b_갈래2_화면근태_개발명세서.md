### 8-2 V1 — 저장소 이벤트가 아니라 서버 「계속됨」 푸시를 고른 까닭

1. **판정은 서버가 한다(설계 §2 · §5-2)** — 「계속됨」 은 [계속] UPDATE 가 **이긴 순간** 서버만 안다. 저장소 이벤트는 탭의 주장이라 서버와 어긋날 수 있다(예: 65초 경계에서 진 [계속]).
2. **받는 쪽이 정확히 같은 출입증 묶음** — 그룹 `s:{tenant}:{sid}` = 같은 로그인(=같은 브라우저 저장소를 함께 쓰는 탭들). 다른 브라우저는 sid 가 달라 각자 묻고 각자 답한다(문제 자체가 없음).
3. **새 JS · `index.html` 무접촉** — 저장소 이벤트는 브라우저 이벤트를 받는 JS 함수가 필요하고 `index.html` 스크립트 꼬리표(캐시)까지 건드린다. 푸시는 이미 있는 연결 · 재연결(E-1) 위에 이벤트 하나만 더한다.
4. **뒷받침** — 푸시를 놓친 탭(숨은 탭 타이머 늦음 · 연결 끊김)도 0초 `ended:false` → 다시 확인 → `asked:false` 로 팝업만 닫는다. 두 장치 중 하나만 살아 있어도 공유 출입증을 지우지 않는다.

3. **화면 실측 0** — 탭 2개 · 한 탭 [계속] · 다른 탭 0초 = 팝업만 닫힘 / 팝업 중 끔 = 팝업만 닫힘 / 「고침」 행 다시 고치기 칸 = [4] 실물 실측 거리.
4. **확인 실패 = 팝업만 닫음** 을 골랐다(서버가 이미 「안 끝냈다」 고 답한 뒤라 출입증을 지우지 않는 쪽). 정말 무응답이면 서버 작업 ① 이 끝내고 `CooltimeEnded` 푸시 또는 다음 요청 401 → 로그인 화면. 반대로 기울이려면 `AfterRecheck` 1줄 — PM.
5. **[로그아웃] 자체가 연결 실패 · 5xx** 면 기존대로 화면은 끝남(설계 §5-2 「실패해도 저장소 비움」) — 이번 범위 밖으로 둠.
6. 이력 줄 `HH:mm` 만(V7 · P3)은 이번 범위 밖(이미 `M/d HH:mm` 로 보이는 것은 고친 시각 칸뿐).
