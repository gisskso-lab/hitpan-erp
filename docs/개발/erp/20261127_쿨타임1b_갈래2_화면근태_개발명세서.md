## §5 못 한 것 · 확인 필요 (🔴 PM)

1. **시험 실행 0 · 앱 실행 0 · 화면 실측 0**(DB 금지 PC). 팝업 모양 · 60초 · 설정 저장 · 근태 표시는 게시 뒤 실물 또는 갈래 ③ 에서.
2. **401 때 전역 안내 한 줄이 먼저 뜬다** — 팝업 중 [계속] · [로그아웃] 이 401 이면 기존 `HitPanApiAuthHandler` 가 갱신을 시도하다 실패하고 「로그인이 만료되었습니다. 다시 로그인해주세요.」 알림을 띄운 뒤 화면이 로그인으로 넘어간다(곧 새로 고침되어 사라짐). §E-5 「401 본문 문구는 안 보여 줌」 은 지켰지만(서버 본문 「다른 컴퓨터에서…」 안 보임) 이 알림을 막으려면 공용 처리기를 고쳐야 해 범위 밖으로 두었다 → PM 판단.
3. **「고침」 행은 다시 못 고친다** — C-5 대상 = `cooltime · cooltime_blank`(갈래 ① 명세서 §1-5 · 설계 §D-2 안 A) 라 `edited` 는 409. 인사담당이 잘못 고치면 되돌릴 길이 없다(「처음 보는 사람이 혼자」 기준에서 걸림). `edited` 를 대상에 넣을지 = **PM 결재 칸**(넣으면 `EditableCheckOutSources` · `IsEditableSource` · UPDATE WHERE 세 곳 1단어씩).
4. **입력 검사 「출근 + 24시간 안」 은 이 갈래가 덧건 것** — 설계에 없는 값. 야간 근무(22:00 → 06:00)는 통과 · 엉뚱한 날짜 입력만 막는다. 빼거나 바꿀지 PM.
5. **[초기화] 는 자동 로그아웃을 끈다**(새 모델 = 켬 false · 시각 두 칸 null = 그대로). 「모든 설정을 기본값」 문구와 맞고 기본 꺼짐(Q4)이지만, 자동 로그아웃만 따로 지키려면 업종처럼 들고 가야 함 → PM.
6. **토큰 갱신 뒤 `sid` 가 같은지** — 같다고 보고(설계 §E-1 ⚠️ · DB-130 `refresh_tokens.session_id`) 「같은 로그인 갱신은 연결 그대로」 로 짰다. 다르면 갱신마다 푸시 연결을 새로 만든다(동작은 맞고 낭비만). 갈래 ③ · [4] 확인 거리.
7. **팝업 중 관리자가 끔(§E-5 ⚠️)** — 화면은 409 · `ended:false` 를 끝남으로 보고 로그인 화면으로 간다(설계 (가) 그대로). 서버 세션이 남아 「두 번째 PC 불가」 에 걸리는지는 갈래 ③ 반증 거리.
8. **휴대폰 머리글** — 팝업은 `MainLayout` 에 있어 모든 화면에 붙고 스스로 연결을 시작한다. 서버가 PC 행에만 보내므로 휴대폰에는 안 뜬다(서버 판정에 기댐).
