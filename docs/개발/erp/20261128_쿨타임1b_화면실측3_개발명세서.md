## 2. 시각 맞추기

- 러너 시계 = 서버 시계(같은 러너 · node 의 로컬 시각 = .NET `DateTime.Now`). 설정 시각은 분 단위(`HH:mm`).
- **C = 지금 + 45초 뒤 첫 분 경계**(`pickC`). 바퀴 A(C1)는 5분 눈금(분 % 5 = 0)이면 1분 더 — ③ 둘째 값(5분 눈금)과 첫 값(C1)이 겹치지 않게.
- 저장 = 설정 화면과 같은 API(`GET api/settings` → 세 칸만 바꿔 `PUT api/settings`). E-2(「C 가 마지막 저장 순간 뒤」 일 때만 적용) — C ≥ 저장 + 45초라 늘 적용.
- 관리자(부모) 세션은 저장 직후 로그아웃 → C 전에 열린 관리자 세션이 물음 대상(`login_at < C`)이 되어 65초 뒤 끝나는 일 0. 끄기는 **C 뒤 새 로그인**으로.
- 바퀴 B 는 시각만 바꿈(켬 그대로 · E-3 의 물음 칸 비우기 안 일어남). 바퀴 A 의 나 세션은 [계속](1시간 미룸) 뒤 로그아웃해 바퀴 B 와 안 섞인다.
- 정시 퇴근 = C1 → 가의 무응답 끝냄이 `FirstRegularLeaveAfter(출근, C1) = C1 ≤ 물은 순간` 으로 「자동」 퇴근 C1 을 적는다.
- 자정 근처: C 계산은 날짜를 넘어도 서버 규칙이 받는다. ③ 둘째 값은 출근 날짜와 같은 날의 눈금만 고른다(날짜 고르기 없음) — 없으면 그 키 DEVICE 「자정 넘김이면 미측정」.

## 7. 확인 거리(실측 전 가설 · CI 첫 런에서 판정)

1. **② [계속] 409 갈래의 기대** — 코드상 끈 뒤 [계속] = 409 → 다시 물음 → 물음만 닫힘(로그인 유지). 오더의 「→ 로그인 화면」 은 세션이 이미 끝났을 때만. 이 몸은 코드 기준으로 단언했다 — PM 이 다른 기대면 키 뜻을 바꾸는 결재가 필요.
2. **③ 시각 고르기(MudBlazor 9.3 `MudTimePicker`)** — 입력 칸 클릭 → 열린 고르기 창의 `.mud-clock-number` 에서 시 → 분 숫자 클릭 → 창이 남아 있으면 바깥(덮개) 한 번 클릭 → 칸 값이 HH:mm 와 같은지 본다. 클래스 이름 · 24시간 표시 · 바깥 클릭 확정은 **실측 전 가설**. 틀리면 그 키 DEVICE 「시각 고르기 — …」 로 서고 그림(`CT3-fail`)이 남는다 → 제품 코드는 안 고치고 장치만 다시.
3. **시간** — 이 몸 보통 7분 안팎(바퀴 둘 ≈ 2분씩 + 무응답 끝냄 ≈ 1.3분 + 화면) · 최악 14분 상한. ui-k35 가 도는 모든 PR 에 더해진다.
4. **② 옛 토큰** — 손 로그아웃 뒤 옛 접속 토큰이 401 인지(세션 확인 미들웨어) · 200 `active=false` 인지 미측정 → 둘 다 「서버 세션 끝」 으로 받고 got 에 어느 쪽인지 남긴다.
5. **가 화면 로그인 · 관리자 화면 로그인의 새 기기** — 앞 몸 · 장치 점검은 나만 화면 로그인한다. 가 · 부모가 브라우저(새 기기)로 처음 들어갈 때 기기 승인 대기 · 안내 창이 다르면 그 키 DEVICE(`로그인 뒤 자리=…`).
6. **근태 화면 첫 조회 범위** — `/hr/attendance` 가 들어가자마자 오늘 줄을 보이는지(기간 기본값) 미측정. 안 보이면 ③ DEVICE(`근태 화면` 단계).
7. **부모의 HR_PROXY 수정 권한** — 화면 고치기 칸은 권한이 있을 때만 그려진다. 부모(테넌트 관리자)가 권한 검사를 지나는지 미측정.
8. **잔여 세션** — 시드 · 앞 몸이 남긴 PC 세션이 있으면 C1 · C2 에 물음을 받고 65초 뒤 서버가 끝낸다(이 몸 판정과 무관 · 기록만).
