## 2. 판단 근거 (다음 사람이 다시 묻지 않도록)
- **7 의 동작 차이**: 종전 `TenantConfigReader` 는 exe 옆 → `..\db.conf` → 환경변수 폴백. `DbConfReader` 는 `..\db.conf` → exe 옆, **환경변수 폴백 없음**. 정식 설치 구조(`{app}\api\` · `{app}\db.conf` — 이 PC `C:\Program Files\HitPan` 목록으로 확인)에서는 **둘 다 `{app}\db.conf`** 를 읽는다. 갈리는 경우는 db.conf 가 없을 때뿐이며, 그때 `Slot=null` 이 워치독과 같은 판정이다. ⚠️ [3-V] 확인 요청: db.conf 없는 환경에서 런처가 `Slot=null` 이면 무엇을 답하나.
- **7 링크를 뺄 수 없는 이유**: 링크한 워치독 원본 `UpdateSignatureVerifier.cs:73` 이 `DbConfReader.GetValue` 를 쓴다(서명 검증 한 벌). 워치독 파일 수정 0 이므로 `DbConfReader.Parse` 빈 catch 억제는 그대로 두고, 원본에 로그 넣기는 별건(워치독 #15).
- **§5-1 `last` 는 추가만**(기본값 null · 헌법 #1): 확인 번호를 발급하는 되돌리기 GET 을 업데이트 화면에서 부르는 우회는 쓰지 않는다(부수효과). 출처는 되돌리기와 같은 `request.json`(두 모드 공통).
- **§5-3 계약 문구**: 초판 「대표 컴퓨터에서만」은 지우지 않고 ⬛ 폐기 표시(문서는 지우지 않고 상태만 바꾼다).
