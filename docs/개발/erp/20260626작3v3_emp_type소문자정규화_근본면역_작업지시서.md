## 1. 목적 — 진통제 아닌 영구 면역

emp_type가 **단일 진실원 없이** 4개 값(`'fulltime'`/`'full_time'`/`'regular'`/`'Regular'`)으로 갈라져, EF enum 변환(`HasConversion<string>()`, 멤버명 'Regular' 기대)과 충돌한다. **신규 가입 부모/자식계정 로그인 시 Parse 폭발 → employee_id 빈 클레임 → 결재·HR·근로계약·휴가 막힘.** 베타 고객 100% 신규가입 = 전원 발생 P0.

**근본 면역책**: EF 변환을 **소문자 저장 + ignoreCase 조회**로 바꿔, 누가 어디서 무슨 대소문자 값을 넣어도 enum이 받아 다시는 안 깨지게 한다. + 유령값 2곳을 정합 소문자로. → **암세포 절제(임시 아님)**, **회귀 0**.

## 3. 절제 범위 (코드 3곳 — 모두 봉합)

### 절제 A — EF 변환 근본 면역 (`EmployeeConfiguration.cs:36`) ★핵심
현재:
```csharp
builder.Property(e => e.EmpType).HasColumnName("emp_type").HasConversion<string>().IsRequired();
```
→ 커스텀 변환으로:
```csharp
builder.Property(e => e.EmpType).HasColumnName("emp_type")
    .HasConversion(
        v => v.ToString().ToLowerInvariant(),                 // 저장: 항상 소문자
        v => Enum.Parse<EmployeeType>(v, ignoreCase: true))   // 조회: 대/소문자 무관
    .IsRequired();
```
→ **저장은 소문자 통일, 조회는 대·소문자 다 받음** = 어떤 경로가 무슨 값 넣어도 안 깨지는 영구 면역. 기존 'Regular'·'regular' 둘 다 살아남음(회귀 0).

### 절제 B — 진범 유령값 2곳 정합 (코드)
| # | 위치 | 현재값 | → |
|---|---|---|---|
| 1 | `CompanyBootstrapController.cs:289` | `'fulltime'` | `'regular'` |
| 2 | `UserService.cs:171` | `'full_time'` | `'regular'` |

→ enum에 없는 유령값 제거. 이제 모든 쓰기가 소문자 정합값.

### 안 한다 (정상 조직 보호 — 회귀 0의 핵심)
- **raw SELECT 읽기(EmployeeService:98·화면 표시) 절대 안 건드림** — 문자열 그대로라 무영향.
- **MdbMigrationService(이미 소문자 'regular') 무변경** — 면역하 정합.
- **운영DB(hitpan_erp/demo) 무변경** — 기존 데이터가 이미 소문자라 ignoreCase 코드가 그대로 받음 → **헌법 #29 결재 면제**(v2의 절제 C 삭제).
- **DDL 무변경** — `emp_type longtext` 그대로, 값은 코드가 소문자 통일.
- emp_type 기반 권한 로직 없음(Role/account_type 기준) → 무관.
- 코드 구조 변경 금지 — 변환 1줄 + 유령값 2곳만.

## 5. 리스크 / 정상조직 보호
- **회귀 핵심**: enum 변환 거치는 건 AuthService 3곳(login/refresh/backfill)뿐. ignoreCase 조회라 'regular'·'Regular' 둘 다 Parse 성공 → 기존·신규 모두 안전.
- **v2 대비 우위**: 운영DB UPDATE 불필요(기존 소문자 그대로 받음) → 헌법 #29 결재 게이트 제거 → 신규·기존 동시 정상(v2는 운영DB 결재 안 나면 절반 상태였음).
- **유령값 잔존 위험**: 만에 하나 'fulltime'/'full_time' 운영DB에 이미 박힌 게 있으면 ignoreCase로도 Parse 실패. → 검증팀이 운영DB emp_type DISTINCT 조회로 유령값 존재 여부 사전 확인, 있으면 별도 안건(현재 demo는 소문자 11건으로 파악됨).
- DDL ENUM 전환 안 함 — 마이그 회귀 위험, 코드 면역으로 충분.
