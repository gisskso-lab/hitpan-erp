## 1. 🔴 사장님이 PM 권고를 정정하셨다 — 이 작업의 핵심

PM 권고는 **"권한자만"** 이었다. **그대로 짰으면 대표가 결재자 목록에서 사라진다.**

### 왜 그런가 — 실측

`PermissionService.HasPermissionAsync` 의 첫 줄:

```csharp
// Layer 0 — 부모계정(tenant_admin)은 항상 전권 (락아웃 방지)
if (userId == _currentTenant.UserId &&
    _currentTenant.AccountType == "tenant_admin")
{
    return true;
}
```

부모계정은 `user_permissions` 표를 **거치지 않는다.** 여기서 바로 통과한다.

⇒ 목록을 `user_permissions` 에서 뽑으면 **대표는 그 표에 줄이 없어 안 잡힌다.**
⇒ 그런데 [A] 의 규칙이 *"최종 단계 = 대표이사"* 다.
⇒ **반드시 넣어야 할 사람을 고를 수 없는 화면**이 된다. G1 이 스스로와 충돌한다.

### 값으로 확인했다 (글자검사 아님)

`hitpan_e2e` 에 4명을 세우고 실제 SQL 을 돌렸다.
🔴 **김대표에게는 권한 줄을 일부러 안 줬고, 최퇴사에게는 권한 줄을 남겨뒀다.**

| 실험 | 결과 | 판정 |
|---|---|---|
| **[1] 봉합 그대로** | 김대표 + 이결재 | ✅ 의도대로 |
| **[2] 권한조건 제거** | **박무권 나타남** | 🟢 봉합이 진짜 |
| **[3] `is_parent` 갈래 제거** (=PM 권고) | **김대표 사라짐** | 🔴 **권고가 틀렸음이 값으로 증명됨** |
| **[4] 계정상태 안 봄** | **최퇴사 나타남** | 🟢 봉합이 진짜 |

**초록불이 어디서 오는가**: 이 데이터에는 어떤 UNIQUE·FK 도 안 걸린다 —
거르는 것은 **오직 이 SQL** 이다. 조건을 지우면 그 사람이 즉시 나타난다.

**PM 오판의 종류**: 있는 구조(Layer 0)를 안 보고 권고부터 냈다.
8/22 인수인계서 §4 의 오판 6건과 **같은 병**이다.

## 2. 무엇을 고쳤나

### [A] 최종 단계 = 대표이사 — **경고만** (Q1 결재)

`ApprovalSettingsPage.FinalApproverWarning`

- 마지막 줄의 결재자가 대표가 아니면 경고를 띄운다.
- 🔴 **자동으로 넣지 않는다.** 사람이 짠 결재선을 시스템이 덮어쓰면 반자동 원칙 위반.
- 🔴 대표 판정은 **`IsParentAccount`(= `users.is_parent`)** — `Position` 문자열이 아니다.
      T-004 실측에서 대표인데도 `position` 이 `null` 이었다(G1-5).
- 🔴 판정 대상을 **`_employeeLookup`(전 직원)** 에서 찾는다. 후보 목록에서 찾으면
      "모른다" 를 "대표가 아니다" 로 단정해 **없는 경고**가 뜬다.

### [B] 그 외 단계 = 부모계정 + 권한자 (Q2 결재)

**신규 조회 1건** — 권한으로 사람을 거르는 조회가 **어디에도 없었다**(실측).

| 계층 | 추가한 것 |
|---|---|
| API | `GET /api/employees/approver-candidates` |
| Application | `EmployeeService.GetApproverCandidatesAsync` |
| Web 서비스 | `EmployeeService.GetApproverCandidatesOrNullAsync` |
| DTO·모델 | `IsParentAccount` · `HasApprovalPermission` (서버·클라 짝 — 헌법 #12) |

핵심 조건:

```sql
WHERE e.tenant_id = @TenantId
  AND e.is_active = 1
  AND e.is_resigned = 0
  AND (u.is_parent = 1 OR p.user_id IS NOT NULL)
```

- 🔴 **라우트 자리** — `[HttpGet("{id}")]` **앞**에 뒀다. 뒤에 두면
      `approver-candidates` 가 `{id}` 로 먹혀 사원 조회로 샌다.
- 🔴 **계정이 살아 있는지까지 본다**(`is_deleted=0 AND is_active=1`).
      2026-08-14 사고와 같은 자리 — 퇴사자는 계정이 `is_active=0` 으로만 꺼지고
      **권한 줄은 그대로 남는다.** 안 걸면 퇴사자가 후보로 올라온다(실험 [4]).
- 계정 없는 사원은 INNER JOIN 에서 자연히 빠진다 — 로그인을 못 하니 결재도 못 한다.

#### 🔴 화면이 목록을 **둘** 들고 있다 — 합치면 사고

```
_employees      = 고를 수 있는 사람  (부모계정 + 권한자)
_employeeLookup = 이름을 찾아볼 사람 (전 직원)
```

이미 저장된 결재선에 권한을 잃은 사람이 남아 있을 수 있다.
후보 목록만 들면 그 사람 **이름을 못 찾아 결재자 칸이 빈칸**으로 보이고,
빈칸은 *"결재자가 없다"* 로 읽혀 담당자가 **멀쩡한 결재선을 지운다.**
⇒ 고르는 것은 막고, **보이는 것은 살린다**(작업지시서 §7).

### [C] 권한이 꺼지면 알린다 — **막지 않는다**

`RecomputePermissionLost()` — 결재선에 있는데 후보 목록에 없는 사람의 이름을 모은다.

- 🔴 **막지 않고 알린다**(§7). 갑자기 막으면 **지금 도는 결재가 선다.**
- 화면이 권한을 직접 판정하지 않는다 — `user_permissions` 를 볼 수 없고,
  부모계정은 그 표를 거치지도 않는다. **서버가 거른 결과로만 판정한다.**
- 재계산 호출 3곳: `OpenLineEditor`(열자마자) · `RemoveLine` · `OnApproverChanged`.
  `AddLine` 은 빈 줄이라 대상이 아니다.

### [D] 직책관리 메뉴 내림 — **메뉴만**

- 사이드바에서 `/settings/positions` 링크 제거.
- 🔴 **화면·주소·표는 전부 살아 있다.**
  - `positions` 표를 **10곳 이상**이 쓴다(프로비저너 시드 등 — 헌법 #37).
  - 주소가 404 나면 즐겨찾기가 깨진다(G1-6).
- 직책 자동 등재(`EnsurePositionExistsAsync`)는 **무변경** — 사장님 오더대로 그대로 자동.

## 6-2. 🔴 [3-V] 동시검증 적발 2건 — 둘 다 봉합

작업이 **도는 중에** 병렬검증이 돌았고 2건이 나왔다. 상세는 `docs/검증/병렬이슈/`.

### ① 위임자가 권한검사에서 빠져 있었다 (내 결함)

`RecomputePermissionLost` 가 `ApproverId` 만 보고 `DelegateId` 를 안 봤다.
🔴 `ProcessAsync:592` 실측 — **위임자도 실제로 결재한다.**
⇒ 권한을 잃으면 결재자와 똑같이 문서가 서는데 **경고가 안 떴다.**
   [C] 가 막으려던 사고를 **절반만** 막고 있었다.

**봉합**: `AddIfCannotApprove()` 로 갈라 결재자·위임자 둘 다 통과.
`OnDelegateChanged` 에도 재계산 연결.

### ② 서버가 결재자 권한을 안 보고 저장했다 (기존 구멍 + 이번 작업의 사각)

`SaveLinesAsync` 가 **활성 사원인지만** 봤다(권한 참조 0건).
⇒ **화면만 거르면 그것은 규칙이 아니라 권유다.**

⚠️ **심각도 정확히**: `TenantAdminOnly` 라 권한 상승 구멍이 **아니다** —
   **대표가 자기 발등을 찍는 자리**다. 부풀리지 않는다(헌법 #32).

**봉합**: 저장 시점에 막는다. §7 *"막지 말고 알린다"* 와 안 어긋난다 —
§7 이 지키는 것은 **이미 저장된 결재선**이고(막으면 도는 결재가 선다),
여기는 **새로 저장하는 순간**이라 막아야 잘못된 결재선이 안 생긴다.
바로 위 퇴직자 검사도 똑같이 저장 시점에 막는다(2026-06-20 P1-7).

**값 확인**: 3명(대표·권한자·무권한자) 세우고 검사 SQL —
봉합 시 **박무권만** 걸리고(대표는 권한 줄 없어도 통과), `NOT` 절 빼면 **0명**.
