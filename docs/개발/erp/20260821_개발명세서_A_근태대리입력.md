## 2. 무엇을 만들었나

| 층 | 추가 |
|---|---|
| DTO | `ProxyCheckInRequest` · `ProxyCheckOutRequest` (🚨 `TenantId` **안 받는다** — #2) |
| 서비스 | `CheckInProxyAsync` · `CheckOutProxyAsync` + `EnsureSameTenantEmployeeAsync` |
| 컨트롤러 | `POST api/hr/attendance/proxy/check-in` · `.../check-out` |
| 권한 | **`HR_PROXY`** — 백엔드 마스터 + 프론트 `ErpMenus` + **`EnforcedMenus`** (3곳) |
| 웹 클라이언트 | `CheckInProxyAsync` — 🔴 **`bool` 이 아니라 사유까지** 돌려준다 |
| 화면 | `HrAttendancePage` 대리입력 카드 |

### 2-1. 🔴 권한을 HR 이 아니라 HR_PROXY 로 가른다

> 사장님: *"남의 근퇴 넣는건 **권한설정에 넣자.**"*

HR 5축(`view`/`create`/`update`/`delete`/`export`)은 **"내 데이터에 무엇을 하나"** 축이고,
대리입력은 **"남의 데이터를 건드리나"** 축이다.
`HR update` 에 얹으면 **자기 근태 고치라고 준 권한이 남의 근태까지 연다.**

🔴 **역할("인사담당자")을 코드에 박지 않는다** — 누구에게 줄지는 고객사가 정한다(헌법 #11).
> 사장님: *"이건 고객사 마음이지"* / *"우리가 정할게 아님"*

⚠️ **`EnforcedMenus` 등록이 핵심이다.** 빠지면 화면에서 감춰져 **고객이 켤 방법이 없다**
(1.2.74 P0 — *"권한설정으로 모든걸 풀었지만 아무것도 못함"*).

### 2-2. 🚨 테넌트 격리 (헌법 #2)

`employee_id` 를 **파라미터로 받는 첫 경로**다. `tenant_id` 는 여전히 JWT 에서만 오지만,
대상 사원이 내 테넌트 소속인지 확인하지 않으면 **남의 회사 사원 번호로 근태를 만들 수 있다.**

⇒ `EnsureSameTenantEmployeeAsync` 가 **실제 처리보다 먼저** 돈다. 시험이 그 순서를 지킨다.

### 2-3. 실패 사유를 뭉개지 않는다

기존 `CheckInAsync` 는 `bool` 만 돌려줘 **왜 실패했는지가 사라진다.**
대리입력은 **권한 없음(403)** 과 **이미 출근(400)** 이 사용자가 할 일이 다르다.
⇒ 서버 메시지를 살려 넘기고, 403 은 *"관리자에게 [근태 대리입력] 권한을 요청해 주세요"* 로 안내한다.

### 2-4. 화면 — 기본값이 [계정 없는 직원만]

`EmployeeListItemModel.HasUserAccount` 가 **이미 있어서** 그대로 썼다.
이 기능이 있는 이유가 그 사람들이라 기본으로 걸러 보여준다. 스위치를 끄면 전원이 보인다.

🔴 **권한이 없으면 카드를 아예 안 그린다** — 눌러도 안 되는 버튼을 보여주지 않는다.
⚠️ 화면 판정은 **표시용**이고 진짜 문지기는 서버 `[RequirePermission]` 다.

### 2-5. 🟢 자동 근퇴 경로 무접촉

이미 돌고 있고 6/22 봉합이 `employee_id` 키를 통일해 **자동/수동 이중행**을 막아 뒀다.
시험이 이 경로가 살아 있는지 지킨다.
