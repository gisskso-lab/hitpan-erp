## §2 봉합 내용 (§7-1 안 ⓑ)

- 두 파일 본문을 머리말 주석 + `SELECT 1;` 로 교체. 머리말에 ⓖ6 전제 1줄 명기:
  **「이 파일은 success=1 기록만으로 skip 된다 — 러너에 내용 비교를 추가하면 이 예외가 깨진다」**.
- 효과: 옛 DB(시드 두 행 없음)는 no-op 실행 → success=1 → 중단됐던 체인(DB-70~137)이 이어진다.
  기존 적용 DB 는 러너가 checksum 을 비교하지 않아(선행검증 §1 · `MigrationRunner.cs:130,139`) 영향 0.
- ⚠️ 평문 비밀번호는 git **이력에 잔존** — 별도 보고 사안(§7-6 ⓒ② 비번 회전 포함 · 이 갈래 범위 밖).
- 이미 생긴 DB 의 뒷정리(표 5·FK·계정)는 범위 밖(§7-2 — 사장님 결재 사안). ⓖ5 가 「잔존 그대로 + 체인 재개」를 보증한다.

### ⓖ5 손상상태 재개 — 동작 실측 (하네스 · hitpan_e2e)
손상상태(잔존 표 5 + FK + admin 행 + DB-39 success=1 + DB-60 success=0) 구성 후 러너 실행:
```

  backoffice_tables=5 fk_tenants_reseller=1 success0_rows=0 admin_row=1
```
= 러너가 **success=0 을 재실행**(전제 검증 — DB-60 만 Applied)하고 success=1 인 DB-39 는 건너뜀 ·
완주 · 잔존물 무접촉(충돌 0). 실행 후 §6 패턴으로 복구.

### ⓖ6 예외 전제 고정 — 동작 실측 (하네스 · hitpan_e2e)
통제 폴더(탐침 2개)로 러너 실행 — DB-998(이력 없음)·DB-999(success=1 + 본문≠기록 checksum):
```

G6 probe_ran=1 probe_must_not_exist=0
```
= 양성 대조(이력 없는 파일은 실행됨) + **success=1 파일은 본문이 바뀌어도 skip**(음성대조군).
훗날 러너에 checksum 비교가 생기면 이 게이트가 FAIL 로 알린다. 실행 후 탐침 표·행 전부 제거.

## §6 안 한 것 · 못 한 것 (정직 신고)

1. ⚠️ **CI db-gate 실측 0회** — 푸시·PR 금지(작지 [산출]) + db-gate 잡은 PR 에서만 깨어난다. 로컬은 CREATE DATABASE 거부로 6건 전부 `[SKIP]`. **게이트 6건이 xUnit 으로는 아직 한 번도 안 돌았다** — 동작은 §3 하네스 실측으로 검산했으나, xUnit 본체의 첫 계측은 머지 PR 의 db-gate 잡이다(선례: 작3 메인PC 게이트와 같은 구조).
2. ⚠️ 평문 비번 **git 이력 잔존** + 본사측 admin@hitpan.kr 비번 회전(§7-6 ⓒ②) — 범위 밖 · 사장님 보고 사안.
3. ⚠️ 이미 생긴 DB 뒷정리(표 5·FK·계정)(§7-2) — 범위 밖 · 사장님 결재 사안. 이 PC 실물 DB 실태 읽기(§7-7 ②)도 분류기에 막혀 미실행(사장님 직접 또는 settings 규칙).
4. ⚠️ ⓖ1 의 「DB-70~137 전부 적용」은 **통제 재현**(시드 두 행만 삭제) 위에서의 완주 판정이다 — DB-50 이후 전부를 빈 이력에서 재실행하면 비멱등 ALTER 별건 실패가 판정 변수를 오염시킨다(선행검증 §3-0 과 같은 선택). 진짜 옛 DB(이력 DB-38 까지)의 종단 완주는 이 게이트가 재지 않는다.
5. 백오피스 쪽 두 파일 참조 없음은 선행검증 A-⑤·C-⑤ 의 사실을 그대로 썼다(이 갈래에서 재실측 안 함).
