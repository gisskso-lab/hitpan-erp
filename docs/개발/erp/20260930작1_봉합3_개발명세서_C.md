## 0. C-0 첫 행동 — 전제 실측 (소스 변경 0)

**① 가설 「폴더 안 파일을 `FileShare.None` 으로 쥐면 그 폴더 `Move-Item` 이 던진다」 — 🟢 던진다. 단 🔴 전제에 없던 사실 하나: 다른 파일을 먼저 옮긴 뒤에 던진다(부분 이동).**
- 실측(10/1 · 이 PC · Windows PowerShell 5.1 · 임시 폴더 `%TEMP%\hp-c0-*` · 실물 무접촉): `app\web.rbk` 에 `other.bin`·`web.bin` 두 파일 → `web.bin` 을 `[IO.File]::Open(...,'Open','Read','None')` 로 쥔 채 `Move-Item web.rbk → rollback\prev\web`.
- 결과 (그대로 옮김):
  ```
  MOVE: threw IOException : The process cannot access the file because it is being used by another process.
  AFTER THROW files:  \rollback\prev\web\other.bin   \web.rbk\web.bin
  MOVE after release: succeeded
  ```
- ⇒ 주입은 설계 16-3 대로 **`PVH`/`PVHH`(진짜 잠김)** 유지 — `PVX` 로 바꾸지 않았다.
- ⇒ 🔴 설계 16-1 ⓑ 「부분마다 `prev\{p}` 없고 `{p}.rbk` 있으면 `Move-Part`」 그대로 짜면 두 곳이 샌다: (가) 부분 이동 뒤엔 `prev\{p}` 와 `{p}.rbk` 가 **둘 다** 있다 → 그 부분을 건너뛰고 「세 부분 다 있음」으로 `sha256.txt` 를 써 **반쪽을 완성본으로 봉인** (나) 거꾸로 `Move-Part` 를 부르면 목적지를 먼저 지워(`:522-526`) **이미 옮겨진 파일(유일한 사본)을 지운다**. 그래서 `Complete-PrevGeneration` 에 두 줄을 더했다(§1 ⓑ 비고) — 구조 변경 아님 · 설계 게이트 G-PV1·PV2 가 기대하는 결과(「`.rbk` 파일 수·해시 = 시드」)를 실제로 내기 위한 최소.

## 7. 검증팀에 요청

- 🔴 C-0 부분 이동: `Complete-PrevGeneration` 의 `Test-DirFree` 는 확인과 이동 사이 틈(TOCTOU)이 있다 — 그 틈에 잡히면 부분 이동 → 다음 호출이 합치기 경로로 마친다. 합치기 경로가 「같은 이름이 이미 있음」에서 `$false` 로 멈추는 것이 맞는지.
- 16ⓐ 던진 뒤 `Get-RbkLeftReason` 이 null(남은 `.rbk` 0)이어도 `cleanup_pending` 으로 거부한다 — 설계 문장(「정직한 사유 반환」)의 보수 쪽 해석.
- 회귀 우려: 업데이트 모드 성공 정리에서 `api.rbk` 가 잠기면(G-LO1 RBKH) 이제 세 `.rbk` 가 **모두** 남는다(종전: web·watchdog 는 `prev` 로 가고 api 만 반쪽). 사유는 같은 `cleanup_pending` · 다음 S0 가 M6 로 마친다.
