## 2. 반려 3건 — 원인과 처방

### [2번] 「판매불러오기」가 판매를 못 불러옴

**원인은 불러오는 로직이 아니었다.**
`FillFromDeliveryAsync` 는 정상이었고, 실측 4번 통과가 그 증거다.

끊긴 자리는 **다이얼로그가 고른 행을 돌려주는 자리**였다.
`SalesListDialog` 의 행 선택 수단이 `@ondblclick` 하나뿐이라, 체크만 하고 「종료」를 누르면
`DialogResult.Cancel()` 로 닫혀 호출부가 아무것도 못 받았다.

**처방** — 「선택」 버튼 신설(1건 체크 시 활성), `DialogResult.Ok(picked)` 로 반환.
더블클릭 경로는 **그대로 뒀다**(헌법 #1 — 추가만).
호출부에 `ListType="sales"` 도 명시했다(종전엔 빈 `DialogParameters`).

> 🔴 **체크박스가 보이는데 그 체크가 아무 일도 안 하면, 사용자는 고장으로 판단한다.**
> *"처음 보는 사람이 혼자 쓸 수 있냐"* 가 통과 기준이다.

### [5번] 거래처를 한 번 더 골라야 함

**원인은 거래처 칸이 아니라 저장부에 있었다.**

`SaveAsync` 는 거래처를 `_partnerCache` 에서 **이름으로** 찾는데(184줄),
그 캐시는 사람이 자동완성에 **타이핑해야** 처음 적재된다(`SearchPartnerAsync`).
판매불러오기로 들어오면 캐시가 비어 있어, 거래처가 화면에 멀쩡히 보이는데도
저장이 *"거래처를 선택해주세요"* 로 막혔다. **그래서 한 번 더 골라야 했다.**

**처방** 두 겹:
1. `FillFromDeliveryAsync` 안에서 `_partnerCache` 선적재
2. `SaveAsync` 가 **식별자 우선**으로 판정 — `partner?.PartnerId ?? _draft.PartnerId`

> 이름은 바뀌고 중복될 수도 있다. **식별자가 있으면 식별자가 우선이다.**
> 자동 선택이 아니다 — 사용자가 이미 고른 거래의 거래처를 반영할 뿐이다([[feedback_semi_auto_principle]] 위반 아님).

### [7번] 반품확인현황·반품직원 그리드가 빔

🔴 **현황 화면의 결함이 아니었다. SQL 은 안 고쳤다.**

현황 4종 SQL 은 `sr.status='confirmed'` 만 집계하고, 저장은 `'draft'` 로 들어간다.
⇒ **저장만 하고 「반품확정」을 안 누르면 안 뜨는 것이 설계대로다.**
재고·회계가 확정에만 반응하므로 현황도 같은 잣대여야 한다(헌법 #6 · 작3·작6 계승).

**필터를 풀면 현황이 재고·회계와 어긋난다.** 그래서 안 풀었다.

**진짜 결함은 다음에 뭘 해야 하는지 아무도 안 알려준 것**이다.
사용자는 저장했으니 끝났다고 믿는다 — 그래서 현황이 비면 고장으로 읽는다.

**처방** — 정합성은 지키고 흐름만 이어준다(헌법 #20):
- 저장 직후(신규·수정 **양쪽**) 안내: *"「반품확정」을 눌러야 현황과 사원별 집계에 반영됩니다"*
- 현황 빈 화면에도 같은 이유를 적어둠

## 3. 🔴 게이트가 세 번 가짜였다 — 기록으로 남긴다

[[feedback_gate_must_test_behavior]] 대로 **짜자마자 봉합을 빼고 FAIL 을 확인**했고, **세 번 다 초록불이 나왔다.**

| 회차 | 가짜였던 이유 | 고친 방법 |
|---|---|---|
| 1차 | `"SelectChecked"` 낱말이 `OnClick="SelectChecked"` **바인딩에도** 있어, 핸들러를 통째로 지워도 통과 | `private void SelectChecked()` **정의** + `OnClick=` **배선** 을 따로 검사 |
| 2차 | `"_draft.PartnerId"` 낱말이 `OnPartnerChangedAsync` **에도** 있어, 폴백을 지워도 통과 | 폴백 **표현 자체**(`partner?.PartnerId ?? _draft.PartnerId`)를 검사 |
| 3차 | 매출 구간만 잘라 봐서, **구간 밖(매입 RT_*)** 필터를 풀었더니 통과 | SR_* **4종을 각각** 열어 검사 + `AND 1=1` 흔적 차단 |

**반증 최종 결과** — 봉합을 빼면 해당 게이트가 **정확히 FAIL** 한다:
```
매출반품현황_4종은_확정분만_집계한다      [FAIL]
저장직후_확정필요를_안내한다              [FAIL]
저장은_거래처식별자로_판정한다            [FAIL]
판매목록_다이얼로그는_체크한행을_돌려주는_경로를_갖는다 [FAIL]
```
반증 실험 중 건드린 `ReportService.cs` 는 **`git checkout` 으로 원복** — 최종 diff **0줄**.

> 🔴 **교훈: 낱말 검사는 게이트가 아니다.** 같은 낱말이 정의·배선·주석 어디에나 있다.
> **정의와 배선을 따로**, 그리고 **구간을 자를 땐 자른 밖도** 봐야 한다.
