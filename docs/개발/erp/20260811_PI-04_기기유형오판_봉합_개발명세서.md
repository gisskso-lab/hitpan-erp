# §0. 🔴 판정 기준이 작업 중에 바뀌었다 — 사장님 확정

작업 도중 사장님이 **판정 기준 자체**를 다시 잡아주셨다. 아래가 최종이다.

> *"태블릿도 모바일로 잡으면 됨 — **운영체제가 안드로이드이거나 iOS이기 때문에**"*
> *"**태블릿, 폰, 스마트TV = 모바일** · 운영체제로 구분하면 됨"*
> *"**윈도우, 맥OS, 리눅스 등의 PC기반 운영체제가 아닌 것은 모두 모바일**"*
> *"TV로 히트판을 돌리는 업체는 없어. **예시를 든 것 뿐이야.** TV로 돌릴 것 같으면 **PC에 TV를 연결해서** 보겠지"*

## 무엇이 바뀌었나

> *"웹브라우저로 판단하면 안 돼. **윈도우PC에서 사파리를 돌릴 수도 있잖아.**
> 파이어폭스를 돌릴 수도 있고 **모바일에서 크롬을 돌릴 수도 있고** — 브라우저는 판정 근거가 없어"*

| | 종전(PM 안) | **최종(사장님 판정)** |
|---|---|---|
| 가르는 기준 | 화면 크기·터치 여부 | 🔴 **운영체제** |
| 묻는 방향 | *"휴대기기 목록에 있나"* | 🔴 **"컴퓨터 운영체제가 아니면 전부 모바일"** |
| 칸 | pc / mobile / **tablet** 셋 | 🔴 **pc / mobile 둘** |
| 브라우저 | (판정에 안 씀) | 🔴 **판정 근거 아님 — 명문화** |

## 🔴 묻는 방향이 핵심이다 — 이게 결함 여러 개를 한 번에 없앴다

휴대기기 목록을 만들고 *"여기 있으면 모바일"* 로 물으면, **목록에 없는 처음 보는 기기가
전부 컴퓨터로 떨어진다.** 컴퓨터 칸이 더 비싸므로 **고객이 손해 보는 방향**이다.

반대로 물으면 — **컴퓨터 운영체제는 셋뿐이고 새로 생기지 않는다** —
새 기기가 나와도 저절로 휴대기기 칸으로 간다. **모르는 것은 싼 칸으로.**

⇒ 실제로 이 한 번의 방향 전환이 **병렬검증이 잡은 결함 2건을 동시에 없앴다**(§6).
⇒ 그리고 **스마트TV 목록을 만들 필요 자체가 사라졌다.** 사장님이 TV를 예시라고
정정하신 대로, 목록 없이도 규칙이 알아서 처리한다.

# §1. 무엇을 고쳤나 — 3곳 + 신설 1개

## 1-1. 🆕 `_isTouchMac(ua)` 신설 — 판별 근거를 한 곳에 모았다

```js
_isTouchMac: function (ua) {
    try {
        return /Macintosh/i.test(ua || navigator.userAgent || '')
            && (navigator.maxTouchPoints || 0) > 1;
    } catch (e) { return false; }
},
```

**왜 함수로 뺐나**: 같은 판별이 종전에 `isIos()` 안에만 있었고,
이름 짓기·종류 가르기는 그것을 **쓰지 않았다.** 세 곳이 각자 판단하면
한쪽만 고쳐지는 사고가 난다. **근거는 한 곳에만 둔다.**

⚠️ `(navigator.maxTouchPoints || 0)` — 구형 브라우저에 이 값이 없을 때
`undefined > 1` 로 새지 않도록 0 으로 받는다.

## 1-2. `getDeviceType()` — 🔴 요금이 걸린 자리 (전면 재작성)

```js
getDeviceType: function () {
    var ua = navigator.userAgent || '';

    // 1) 컴퓨터 운영체제와 헷갈리는 휴대기기부터 걷어낸다. 순서가 전부다.
    if (hitpanDevice._isTouchMac(ua)) return 'mobile';   // Mac 으로 위장한 아이패드
    if (/iPhone|iPad|iPod/i.test(ua)) return 'mobile';   // "like Mac OS X" 함정
    if (/Android/i.test(ua)) return 'mobile';            // 문구에 'Linux' 가 들어간다

    // 2) 컴퓨터 운영체제인가 — 이 셋뿐이다.
    if (/Windows NT|Win64|Win32/i.test(ua)) return 'pc';
    if (/Macintosh|Mac OS X/i.test(ua)) return 'pc';
    if (/X11|Wayland|CrOS|Ubuntu|Fedora|Debian|FreeBSD|OpenBSD/i.test(ua)) return 'pc';

    // 3) 컴퓨터 운영체제가 아니면 전부 휴대기기 (사장님 판정)
    return 'mobile';
},
```

🔴 **판정에 브라우저 이름이 한 글자도 없다.** 운영체제만 본다(§0 사장님 못박음).

⚠️ **1)의 순서가 안전장치 전부다.** 아이폰·안드로이드를 먼저 걷어내지 않으면
2)의 Mac·리눅스 검사가 그것들을 컴퓨터로 판정한다 — 실제로 §2-2 에서 그 사고를 냈다.

⚠️ 리눅스만 조건을 좁게 잡았다(`X11`·배포판 이름). `Linux` 라는 낱말 하나로 보면
리눅스 위에서 도는 기기가 전부 컴퓨터로 새어든다.

## 1-3. `getDeviceName()` — 순서를 바꿨다

```js
if (hitpanDevice._isTouchMac(ua)) os = 'iPhone/iPad';
else if (/iPhone|iPad|iPod/i.test(ua)) os = 'iPhone/iPad';   // 🔴 Mac 보다 위로 올림
else if (/Windows/i.test(ua)) os = 'Windows';
else if (/Macintosh|Mac OS/i.test(ua)) os = 'Mac';
else if (/Android/i.test(ua)) os = 'Android';
else if (/Linux/i.test(ua)) os = 'Linux';
```

## 1-4. `isIos()` — 중복 제거

```js
- if (/Macintosh/i.test(ua) && navigator.maxTouchPoints > 1) return true;
+ if (hitpanDevice._isTouchMac(ua)) return true;
```

# §2. 🔴 검증이 잔존 결함 1건을 잡았다 — 1차 봉합은 불완전했다

**첫 봉합 직후 8케이스 검증에서 2건이 실패했다.**

```
FAIL  아이폰            종류=mobile  이름=Mac · Safari   ← 이름이 안 고쳐졌다
FAIL  아이패드(옛 UA)    종류=tablet  이름=Mac · Safari
```

**원인**: 아이폰·구형 아이패드 UA 에는 **`like Mac OS X`** 라는 문구가 들어 있다.

```
Mozilla/5.0 (iPhone; CPU iPhone OS 17_0 like Mac OS X) AppleWebKit/605.1.15 …
                                        ^^^^^^^^^^ 여기
```

`getDeviceName()` 의 `/Macintosh|Mac OS/i` 에서 **`Mac OS` 쪽이 이것을 잡아** `Mac` 으로 확정했다.

🔴 **1차 봉합은 `Macintosh` 만 보고 `Mac OS` 를 놓쳤다.**
⇒ 사장님이 실측하신 `Mac · Safari` 증상이 **아이폰 경로에서 그대로 살아있었다.**

⇒ 애플 손기기 분기를 Mac 보다 **위로** 올려 봉합(§1-3). 재검증 8/8 통과.

**교훈**: 종류 판정만 보고 통과시켰으면 못 잡았다. **이름까지 같이 본 것이 잡았다.**

## §2-2. 🔴 그리고 **같은 함정에 두 번째로 빠졌다** — 아이폰이 컴퓨터로

판정 기준을 운영체제로 바꿔 쓰면서 `/Macintosh|Mac OS X/ ⇒ pc` 한 줄을 넣었다.
검증 결과:

```
FAIL  아이폰          pc  ← 🔴 아이폰이 컴퓨터 칸을 먹는다
FAIL  아이패드(옛UA)   pc
FAIL  카톡인앱(iOS)    pc
```

**`like Mac OS X` 를 §2-1 에서 방금 겪고도, 유형 판정에서 똑같이 반복했다.**
아이폰을 Mac 검사보다 **먼저** 걷어내도록 순서를 잡아 봉합. 재검증 20/20 통과.

⇒ **이래서 검증을 코드마다 돌린다.** 한 번 고친 함정도 다른 함수에서 되살아난다.
⇒ 지금은 1) 블록이 그 방어다. **거기에 무엇을 끼워 넣으면 즉시 재발한다.**

# §4. 🔴 서버 실측 — 기존 고객은 안전하다, 그러나 옛 오판은 안 고쳐진다

[`TenantDeviceService.cs:172-187`](../../src/HitPan.Infrastructure/Services/TenantDeviceService.cs) 실측:

```sql
UPDATE tenant_devices
SET last_seen_at = NOW(), ip_address = @Ip,
    user_agent = COALESCE(@Ua, user_agent),
    device_name = COALESCE(@Name, device_name)
WHERE device_id = @Id
```

🔴 **`device_type` 이 UPDATE 대상에 없다.** 그리고 `:150` 기존기기 분기라
한도 검사(`:199` 이하)에 **아예 들어가지 않는다.**

## 🔴 사장님 지시로 이것도 고쳤다 — 유형을 갱신하게 만들었다

> *"업데이트 이후 **막히지 않고 정확하게 모바일이냐 PC냐 잡으면 됨**"*

PM 은 위 사실을 *"기존 고객이 안 막히니 다행"* 으로 보고했으나,
사장님 기준으로는 **결함**이다 — 유형이 영원히 안 고쳐지면 **과금이 계속 틀린다.**

⇒ UPDATE 에 `device_type` 을 추가했다:

```sql
UPDATE tenant_devices
SET last_seen_at = NOW(), ip_address = @Ip,
    user_agent  = COALESCE(@Ua, user_agent),
    device_name = COALESCE(@Name, device_name),
    device_type = COALESCE(@Type, device_type)   -- 🆕 추가
WHERE device_id = @Id
```

## 🟢 그런데도 막히지 않는다 — 근거

이 자리는 **이미 등록된 기기**만 지나간다(`:150` existing 분기).
종류가 바뀌어도 **한도 검사(`:236` 이하)에 다시 들어가지 않는다.**

⇒ 휴대기기 칸이 꽉 찬 상태에서 아이패드가 컴퓨터→휴대기기로 옮겨와도
**그 사람이 쫓겨나지 않는다.** 칸 수를 잠깐 넘길 수는 있으나,
**쓰던 사람을 막지 않는 쪽**을 택한다(2026-08-10 아침 4차 사고 계통 재발 방지).

🟢 **병렬검증이 이 구조를 코드 3단으로 독립 확인**했다(§5).

⚠️ **`COALESCE` 는 실제로는 죽은 방어다** (검증팀 지적 · 문서 정정).
PM 은 *"종류를 못 보내면 null 이 흘러 기존 값을 지킨다"* 고 적었으나,
[`DeviceDtos.cs:37`](../../src/HitPan.Application/DTOs/Device/DeviceDtos.cs) 기본값 `"pc"` 와
[`AuthController.cs:93`](../../src/HitPan.API/Controllers/AuthController.cs) 의 `?? "pc"` 가
**먼저 채워버려서** null 이 서비스까지 오지 않는다.
⇒ 옛 화면이 있으면 기존 값 보존이 아니라 **`pc` 로 덮인다.** 지금은 옛 화면이 0개라
발생하지 않지만, **명세서 기술이 사실과 달랐다.** COALESCE 는 남겨둔다(해롭지 않다).

## 5-1. [3-V] 병렬검증 — 보안상무 안철수

**판정: 조건부통과.** 22개 실제 UA 를 독립 실행해 반증. 코드 자체는 반려 사유 없음.

## 🟢 검증이 독립 확인해 준 것

- 아이패드 위장 UA → 휴대기기 (P0-1 해소) · 아이폰·아이패드 이름 (P0-2 해소)
- **진짜 Mac 은 `pc` 유지** — 반대 방향 사고 없음
- 인앱 브라우저(카톡·네이버)·CriOS·FxiOS·삼성인터넷·Surface·구형 브라우저 전부 정상
