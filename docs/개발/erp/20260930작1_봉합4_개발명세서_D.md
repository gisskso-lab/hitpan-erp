## 0. D-0 첫 행동 — 전제 실측 (설계 17-2 ⚠️가설 · 17-4 넷째 줄)

- 방법: 임시 폴더 `app\web.rbk` 에 파일 셋(`web.bin` · `z-web.css` · `lib\web-lib.dll`) · `Get-ChildItem -Recurse -File` 열거 순서 기록 · 한 파일을 `FileShare.None` 으로 쥔 채 `Move-Item web.rbk → rollback\prev\web` · PS **5.1.26100.9444**.
- 결과 (일꾼과 같은 `$ErrorActionPreference='Stop'`):

| 쥔 파일 | Move-Item | web.rbk 에 남음 | prev\web 에 옮겨짐 |
|---|---|---|---|
| **마지막**(`lib\web-lib.dll`) | IOException 던짐 | `lib\web-lib.dll` 1 | `web.bin` · `z-web.css` 2 = **부분 이동 남** |
| 첫 번째(`web.bin`) | IOException 던짐 | 셋 다 | 0 — 단 **빈 `prev\web` 폴더는 생김** |

- 열거 순서 = 맨 위 파일 → 하위 폴더 = Move-Item 이 옮기는 순서 ⇒ 설계 17-4 「`Open-TestHoldLast` 의 마지막 = 옮기는 순서」 전제 **확정**.
- ⇒ G-PV5 는 **주입 방식**(`PVL`) 그대로 · 시드 방식 불필요.
- 🟡 곁 관찰(참고만): `$ErrorActionPreference` 기본(Continue)에서는 Move-Item 이 **던지지 않고** 부분 이동만 한다(비종료 오류). 일꾼은 `:43` 에서 Stop 이라 해당 없음. 첫 파일을 쥐어도 빈 목적지 폴더가 생기므로 다음 호출은 합치기 경로를 탄다(기존 코드가 이미 처리).
- 🟡 기존 주석 `local-swap.ps1` Complete-PrevGeneration 머리말 · 게이트 파일 봉합3 머리말의 「C-0: 다른 파일을 먼저 옮긴 뒤 던진다」는 **마지막 파일을 쥘 때만** 맞다(첫 파일이면 0개). 주석 정정은 범위 밖이라 손대지 않음(§5).
