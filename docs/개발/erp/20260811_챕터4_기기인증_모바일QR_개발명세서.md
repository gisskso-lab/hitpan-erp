## 1. 설계의 핵심 — 판정 대상을 바꾼다

종전에는 **브라우저에게 "너 누구냐"** 를 물었다(지문). 브라우저는 자기 안에만 흔적을 남기니
Edge 와 Chrome 이 각자 다른 답을 했고 **같은 PC 가 2대로 세어졌다.**

사장님 설계는 묻는 대상을 **기기에 발급한 인증**으로 바꾼다. 추측을 정교하게 하는 게 아니라
**애초에 추측을 안 하게** 만든다. 기기 수로 과금하므로, 실제보다 많이 세면 고객이 돈을 더 낸다.

## 2. 흐름

```
직원 사용PC 로그인 → 접속 OK, 메뉴 잠김 "기기인증을 먼저 진행하세요" [인증]
   ├─ 슬롯 남음 → 승인 대기 → 대표계정 승인 → 사용
   └─ 슬롯 없음 → 직원 "인증기기 한도초과. 관리자에게 문의하세요."
                  대표 "비인증 PC에서 접속이 시도되었습니다. 슬롯 1개를 추가하시겠습니까?"
                        Y → 랜딩페이지 / N → 등록기기 변경 · 기기차단

모바일: [모바일기기 등록] → QR → 폰 촬영 → Y/N → 등록 + 홈화면 아이콘
```

## 4. 판단 근거

### (E) 스위치를 왜 최우선으로 만들었나
사장님 지적: *"개발하면서 슬롯을 다 써서 테스트도 못하는 상황이 올수 있음"*
Sandbox 를 여러 번 띄우면 슬롯이 찬다 — **우리가 만든 기능 때문에 우리가 테스트를 못 한다.**
급할 때 코드를 뒤져 주석 처리하는 게 아니라 설정 한 줄로 끈다.
**기본값 꺼짐**이라 게시해도 동작이 안 바뀐다. 켜는 것은 사장님 별도 결재.

### (F) 기존 기기를 왜 그냥 인정하나
사장님 결재 *"나 로 가"*. 재접속 경로에서 `_approvalEnabled` 를 **보지 않는 것**이 핵심이다 —
보면 규칙을 켜는 순간 쓰던 사람이 전부 막힌다(8/10 아침 4차 사고 계통).

### 직원 문구를 왜 바꿨나
종전: *"등록된 기기가 아닙니다… 기존 기기를 해제하거나 관리자에게 문의하세요."*
→ 직원에게 **직원이 할 수 없는 일**(기기 해제는 대표계정만 가능)을 시키고 있었다.
→ **"인증기기 한도초과. 관리자에게 문의하세요."** 로 통일하고, 파는 쪽 제안은 대표 화면에 띄운다.

### 승인 시점에 한도를 다시 보는 이유
대기 3대에 남은 슬롯 1대면 **첫 건만 통과해야** 한다. 등록 시점에만 검사하면 대기분이
한도를 넘겨 통과한다 — 슬롯 과금이 무너지는 자리다.

### 모바일 등록 화면을 로그인 없이 여는 이유
현장 직원 폰에 히트판 계정이 없을 수 있다. 로그인을 요구하면 그 자리에서 흐름이 끊긴다.
대신 **토큰이 열쇠**다 — 대표계정만 발급하고, 10분 만료·1회용이며, 테넌트를 물고 있다.

## 5. QR 생성기 — 자체구현이 실패했다

사장님 지시대로 **먼저 직접 만들었다**(ISO/IEC 18004, GF(256) 리드-솔로몬 포함).
화면상 완벽한 QR 이 나왔다 — 위치 검출·타이밍·정렬 패턴 모두 제자리.

**그런데 안 읽혔다.** 독립 디코더(jsQR)로 확인했고, 검증본과 한 칸씩 대조하니
21×21 = 441칸 중 **122칸이 달랐다.** 포맷 비트 배치와 예약 영역을 고쳐도 그대로였다.

→ 사장님께 보고 후 **(나) 결재**: QRCoder(MIT, 다운로드 7,400만) 채택.
→ **디코딩 검증 통과** — 읽힌 값이 원문과 완전 일치.

⚠️ 이것은 "외부 API" 가 아니다. 우리 안에서 돌고 **인터넷을 쓰지 않는다.**
토큰이 밖으로 안 나가므로 데이터 주권(헌법 #18·#22·#30)에 어긋나지 않는다.

**교훈: "그려졌다" 와 "읽힌다" 는 다르다.** 눈으로만 봤으면 폰으로 찍어야 드러났을 결함이다.

## 6. 아이폰 홈화면 — 한계와 대응

애플 정책상 **웹이 홈화면 추가를 자동으로 못 한다.** 우회로가 없다.
사장님 제안이던 *"아이폰에 크롬 설치를 권장해서 크롬에서 홈화면에 빼는 것"* 은 **안 통한다** —
아이폰의 크롬은 속이 사파리라 같은 제약을 받고, 앱스토어 왕복 한 단계만 늘어난다
(사장님 확인 2026-08-11 "안통하구먼.오케이").

**대응**
- 안드로이드: `beforeinstallprompt` 를 잡아 뒀다가 [홈 화면에 추가] 버튼으로 띄운다
- 아이폰·아이패드: 공유(□↑) → 홈 화면에 추가 → 추가, **3단계 그림 안내**
- **접속 기기를 보고 맞는 쪽만** 보여준다 — 둘 다 보이면 더 헷갈린다
- 🔴 **인증은 Y 시점에 끝난다.** 아이콘을 못 만들어도 그 폰은 쓸 수 있다

## 7. [3-V] 병렬검증 — 사장님 실측이 P0 을 잡았다

**PI-02: 마이그레이션을 실행되지 않는 폴더에 두어 QR 생성 500**

PM 이 `installer/migrations/` 에 두었는데 **그 폴더는 아무도 실행하지 않는다.**
진실원은 `src/HitPan.API/Migrations/SQL/DB-NN_*.sql` 이고 `MigrationRunner` 가 여기만 읽는다.

**CI 가 못 잡은 이유**: clean DDL 에는 제대로 넣었기 때문에 DDL Smoke 가 통과했다.
**신규 설치는 정상이고 기존 DB 업데이트만 깨진 상태** — 돌고 있는 DB 에 얹어야만 드러난다.

→ **DB-87** 로 봉합. `bin/.../Migrations/SQL/` 에 실린 것까지 확인(7월 "publish 에 0개" 사고 계통).
