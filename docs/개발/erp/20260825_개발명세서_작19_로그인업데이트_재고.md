## 2. 🔴 S3 창고분리 — 증상 4개가 원인 하나였다

사장님이 오류 하나와 미반영 4개(자사·위탁·품목수·금액)를 따로 적으셨는데, **뿌리가 같았다.**

서버 `StockService.GetWarehouseSplitAsync` 는 **JSON 배열**을 주는데
화면은 **객체**(`{Rows, Kpi}`)로 받으려 했다 → `[` 를 만나자마자 터진다.
사장님이 보신 `Path: $ | BytePositionInLine: 1` 이 정확히 그 자리다.
예외가 `catch` 로 빠지며 **그리드도 KPI 4개도 전부 비었다.**

### 🔴 그런데 형태만 고치면 안 됐다 — 두 겹이 더 있었다

**(가) 필드 이름이 서로 달랐다** — 서버 `WhCode`/`WhName`/`TotalValue` vs 화면 `WarehouseCode`/`WarehouseName`/`StockAmount`.
형태만 맞추면 **표는 뜨는데 칸이 전부 비는** 더 나쁜 상태가 된다.

**(나) 🔴 같은 뜻을 서로 다른 말로 저장하고 있었다**

| 어디 | 저장하는 값 |
|---|---|
| 창고관리 화면 | **한글** — 자사창고 · 3PL · 기타 |
| API 기본값 | **"자사창고"** |
| 창고분리 화면이 아는 값 | **영문** — normal · consign |

**실측**: 같은 테넌트에 `[]`(빈 문자열)과 `[자사창고]`(한글)가 **섞여 있었다.**
⇒ 창고관리에서 만든 창고가 자사도 위탁도 아닌 것이 되어 **KPI 가 0**.
사장님 *"창고관리에서 창고생성한 자사창고, 위탁창고 … 모두 미반영"* 이 이것이다.

**봉합**: `NormalizeType` 으로 읽는 쪽에서 관용 수용.
⚠️ 저장 어휘를 영문으로 바꾸는 정규화는 **하지 않았다** — 이미 한글로 쌓인 데이터가 있어
단독으로 바꾸면 회귀한다(헌법 #1). `WarehouseConfiguration.ParseWarehouseType` 이 이미 같은 방식이다.

## 3. 🔴 S6 — 콤보를 맞추다 숨은 버그를 찾았다

사장님 오더는 *"콤보가 동일한 정보를 낼 것"* 이었다. 세 화면이 **이미 같은 서버**를 쓰고 있어
콤보만 맞추면 되는 줄 알았는데, **상품별 원장이 조용히 고장나 있었다.**

`ItemLedgerPage` 는 `view=item` 인데 상품명을 **`partner=`** 로 보냈다.
서버 item 브랜치는 `@Item` 만 매칭하고 `@Partner` 는 쳐다보지 않는다.
⇒ **상품을 골라도 필터가 통째로 무시되어 전체가 나왔다.**

**SQL 대조실험**:

| 보내는 파라미터 | 결과 |
|---|---|
| `partner=` (종전) | **1건** — 필터 무시 🔴 |
| `item=` (봉합 후) | **0건** — 제대로 걸림 🟢 |

⚠️ `StockLedgerPage` 는 **19차에 이미 고쳤다.** 한쪽만 고쳐진 **미봉합 잔여물**이었다.
*"판매에서 고친 걸 매입에 안 옮겼다"* 와 같은 부류다.
