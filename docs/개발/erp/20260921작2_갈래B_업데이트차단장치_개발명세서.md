## 4. 🔴 V-3 — 맞바꿈을 그대로 적는다

### 4-1. 무엇을 닫고 무엇을 열었나

- **닫는 것**: **조용한 부분 적용.** 인덱스가 안 생겼는데 신버전 코드가 `success` 로 기록되고 `.old` 까지 정리되는 상태.
- **여는 것**: **판정 불가 시 부분 적용.** DB 를 못 읽은 그 회차는 예전처럼 통과한다.
- **왜 이쪽으로 기울였나**: 후자가 **훨씬 드물고**, 전자는 **롤백으로 복구**되지만 **잘못된 롤백은 고객이 쓰던 버전을 뺏는다.**
  🔴 여기를 fail-closed 로 바꾸면 **DB 를 잠깐 못 읽었다는 이유로 멀쩡한 업데이트가 되돌아간다** — 사장님 오더(§16-1) 정면 위반이다.

### 4-2. ⚠️ 문서 충돌 1건 — 숨기지 않는다

설계 **§16-2 S-2**(「모르면 통과는 절대 없다 — 조회 실패도 통과가 아니라 실패다」)·**S-3**(「조회 실패 = null = 안전측 = 실패」)는
작지 **§16-4 V-2**(fail-open)와 **정면으로 다르다.**
**V-2 를 따랐다** — ① 작2 §16 이 설계 §16-2 보다 뒤이고 ② 사장님 오더를 PM 이 옮긴 것이며 ③ §16-6 중단조건 6번이 *"차단 장치가 「판정 불가」에서 롤백을 낸다"* 를 **중단 사유**로 못 박았기 때문이다.
🔴 **설계 §16-2 S-2·S-3 문구 정정은 PM·설계팀장 몫으로 남긴다**(이 갈래가 설계문서를 고치지 않았다).

### 4-3. 기존 게이트 ①과 규칙이 다른 이유

`GetAppliedMigrationIdsAsync`(교차검증 게이트 ①)는 **null = 차단**이다. 새 메서드는 **null = 통과**다.
**의도적으로 다르다** — ①은 **스왑 전**(아직 아무것도 안 바꿈, 막아도 구버전 무손상)이고,
3번째 조건은 **스왑·재시작 후**(막으면 **되돌리는 것**)다. 같은 「안전측」이 양쪽에서 반대 방향이다. 주석에 그대로 적었다.
