### 2-1. G-C24 — 「동작」 으로 잰 방법 · 왜 이 방법인가

- **잰 것**: ERP API 어셈블리의 진짜 진입점(`typeof(CooltimeService).Assembly.EntryPoint` = 최상위 `Program` 의 `<Main>`)을 시험 프로세스에서 부른다. `builder.Build()` 안 `HostBuilding` 진단 이벤트(`Microsoft.Extensions.Hosting`)에서 `IHostBuilder.ConfigureServices` 콜백을 걸어 **Program.cs 가 실제로 쌓은 서비스 목록**을 복사하고 예외로 멈춘다 → `IHostedService` 중 구현 = `CooltimeService` 1개(Singleton) · `CooltimeEngine` Scoped · `ICooltimePusher` = `SignalRCooltimePusher` Singleton. 양성 대조 = 목록 100줄 넘음 · `CsAutoDispatchService` 도 보임. `WebApplicationFactory` 가 최소 호스팅에서 쓰는 `HostFactoryResolver` 와 같은 원리.
- **글자 grep 이 아닌 이유**: 등록 코드가 실제로 돌아 생긴 목록을 본다 — 줄을 주석 처리 · 다른 메서드로 옮김 · 조건문 안에 넣음 등이 전부 목록에 그대로 반영된다.
- **`WebApplicationFactory<Program>` 을 안 쓴 이유**: ① ERP API `Program` 은 최상위 문장이라 `internal` · `InternalsVisibleTo` 없음 ② 그 장치는 호스트를 **시작**한다 → 서버 작업(쿨타임 바퀴 · `Build()` 뒤 마이그 자동 적용 등)이 돌며 DB 에 붙는다(이 PC 기본 DB = 실물 · 금지).
- **안전장치**: (a) 진입점 전에 빈 `HostApplicationBuilder` 로 가로채기가 먹는지 먼저 확인 — 안 먹으면 진입점을 부르지 않고 FAIL (b) `HostBuilding` 을 놓쳐도 `HostBuilt`(Build 안 · 마이그 적용보다 앞)에서 멈춤 (c) 서비스 공급자를 만들기 전에 멈추므로 서버 작업 객체 0 · DB 연결 0 (d) 등록 코드가 요구하는 `DB_NAME` · `DB_USER` · `DB_PASSWORD` · `DB_HOST` 는 **비어 있을 때만** 채우고(호스트 = `gate-never-connect.invalid` · RFC 2606 안 풀리는 이름) 끝나면 되돌림 · `JWT_SECRET` 은 비었으면 무작위(CooltimeDbGateTests 와 같은 방식) (e) 다른 시험의 호스트는 `AsyncLocal` 표지로 건드리지 않음 (f) 진입점이 바꾼 Serilog 전역 로거는 `CloseAndFlush`.
- **남는 한계**: `Build()` 앞까지만 돈다 — `app.Run()` 뒤 실제로 `ExecuteAsync` 가 15초마다 도는지는 안 잰다(바퀴 본체는 G-C1~G-C22 가 `RunOnceAsync` 로 잼 · 실제 기동은 게시 뒤 실물).
