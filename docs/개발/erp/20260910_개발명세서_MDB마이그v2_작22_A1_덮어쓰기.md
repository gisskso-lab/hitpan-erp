## 0. 한 줄

**초기화가 지운 회사 뼈대를 되살리는 코드가 0건**이었다. 그것을 만들고, 초기화 화면과 덮어쓰기가 **같은 메서드**를 타게 했다. 그리고 그것을 넣자마자 대사표 ⑩(사원)이 **레거시보다 1 많아지는 것**을 실측으로 잡아 같이 고쳤다.

## 1. 무엇을 만들었나

### 1-1. `CompanyBootstrapProvisioner` — 시드 5종을 메서드로 잘라냄 (헌법 #1)

`CreateParentAsync` 안에 있던 블록을 **본문 그대로** 옮겼다. 새로 고안한 값·이름·목록은 **하나도 없다**.

| 메서드 | 무엇 | 멱등 |
|---|---|---|
| `SeedOwnerEmployeeAsync` | 대표 사원 1행 (`emp_no '0001'` · 직급 「대표이사」 · 부모계정 연결) | 🔴 `NOT EXISTS` **추가** |
| `SeedDefaultWarehouseAsync` | 기본창고 MAIN | 종전부터 `NOT EXISTS` |
| `SeedStandardPositionsAsync` | 직급 6 | 종전부터 |
| `SeedLaborPolicyAsync` | 근로 기준값 16 | 종전부터 |
| `SeedStandardAccountsAsync` | 표준 계정과목 27 | 종전부터 |

> 🔴 **유일한 동작 변경**은 대표 사원 INSERT 에 `NOT EXISTS` 를 더한 것이다. `VALUES` → `SELECT … WHERE NOT EXISTS (사원 중 이 user_id 가 있나)` 로 모양이 바뀌었다.
> **신규 설치 경로에서는 결과가 같다** — 그 시점 이 회사의 사원은 0명이라 조건이 언제나 참이다. 바뀐 것은 *재시드가 두 번 불려도 대표가 둘이 되지 않는다* 는 점뿐이다.

### 1-2. `ReseedCompanySkeletonAsync(tenantId, ct)` — 재시드 진입점 (신설)

- 자기 커넥션 · **한 트랜잭션** · 실패 시 롤백.
- 대표 사원은 **부모계정(`users.is_parent=1`)에서 이름·아이디를 읽어** 만든다. 부모계정이 없으면 사원만 건너뛰고 나머지는 깐다.
- 끝나고 **표를 다시 세어** 돌려준다(`CompanySkeletonReseedResult`) — *"불렀다"* 가 아니라 *"깔렸다"* 를 보고하기 위해서다.

### 1-3. 두 경로가 같은 재시드를 탄다

| 경로 | 어디 |
|---|---|
| 초기화 화면 | `DataResetController.ResetAll` — 초기화 성공 뒤 호출, 응답에 `skeleton` 동봉 |
| 덮어쓰기 가져오기 | `MigrationController.PrepareOverwriteAsync` |

### 1-4. `MigrationController` — 덮어쓰기 분기

```
POST legacy-mdb/start  (mode=overwrite)
  → 확인문구 "덮어쓰기" 일치 · 대표계정 비번 있음   (아니면 400, 아무것도 안 지움)
  → IDataResetService.ResetAllAsync              (비번 재검증 · 강제백업 · 삭제 · 감사기록)
  → ReseedCompanySkeletonAsync                    (실패하면 500 · **잡을 만들지 않는다**)
  → 잡 생성 → 1단계 이관
```

- `continue`(이어서 가져오기)와 동기 `POST legacy-mdb` 는 **덮어쓰기를 거절**한다(`RejectOverwriteHere`).
  `continue` 가 받으면 1단계에 이미 들어온 자료를 지우고 2단계를 얹게 된다.
- `RejectUnsupportedMode` 의 *"덮어쓰기는 준비 중입니다"* 400 은 **없앴다**.
- 신설: `GET legacy-mdb/overwrite-impact` — 히트판에서 **사람이 직접 입력한 거래** 건수(명세서·매입·수금·지급 중 `source_type <> 'migration'`). 읽기 전용 · 테넌트 범위.

### 1-5. 화면 (`MdbMigration.razor`) — 개발용어 0

- 방식 선택: **「기존 자료는 두고 없는 것만 보태기」**(기본) / **「기존 자료를 모두 지우고 새로 가져오기」**
- 지우는 쪽을 고르면 → 경고(+지워질 건수) · 대표계정 비번 · 확인문구 「덮어쓰기」 · **시작 직전 한 번 더 확인 대화상자**
- 「초기화」·「마이그레이션」·「모드」 같은 말은 화면에 없다.

### 1-6. 대사표 ⑩ — 이관분만 센다 🔴 (실측으로 나온 것)

`(SELECT COUNT(*) FROM employees WHERE tenant_id=@T AND emp_no <> 'LEGACY_FALLBACK')`
→ `… AND emp_no LIKE 'MIG-%'`

**왜**: 재시드가 대표 사원 1행을 만들면 이 항목은 **언제나 레거시보다 1 많다**. 실제 고객 설치도 마찬가지다(신규 설치가 부모계정과 함께 만든다).
⚠️ **e2e 테스트 DB 는 부트스트랩을 안 태워 대표가 없었기 때문에 지금까지 이 차이가 안 보였다** — *"테스트에서 안 보인다 ≠ 고객에게 안 보인다"*(DB-100 사고 계통).
Detail 문구도 「히트판에서 따로 만든 사원 N명 제외(대표·자리표시)」로 바꿨다.

## 2. 설계 대비 정정 1건 (PM 전결)

별지 §1-1 은 **① 백업을 따로 부르라**고 했다. 실측하니 `DataResetService.ResetAllAsync` 가 이미 **비번 재검증 → 강제 백업(`before_data_reset`, 실패 시 중단) → 삭제 → 감사기록**을 한 몸으로 한다(`DataResetService.cs:95-107`).
⇒ 따로 부르면 **큰 DB 에서 백업이 두 번** 돈다. **`ResetAllAsync` 하나로 ①②를 대신**했다. 백업 없이 지우는 일은 없으므로 안전 요건은 그대로다.

## 5. 이 명세서가 **하지 못한 것**

- ⚠️ **화면 종단(HTTP)은 못 쟀다.** 인증이 라우팅보다 먼저 서서 없는 주소도 401 이라 HTTP 로는 경로 유무를 가를 수 없다(작22 §5 와 같은 한계). **사장님 화면 실측이 첫 확인**이다.
- ⚠️ **초기화 화면 경로의 실 호출**은 게이트(G-OW7)가 구조로만 확인했다 — 실제 버튼을 눌러 본 것은 아니다.
- ⚠️ **부가세 3자리(−5·+1·+1)** 는 여전히 **미규명**이다. 끝수로 보이지만 재지 않았으므로 "반올림" 이라 적지 않는다.
- ⚠️ 측정 도구가 `HitPan.API` 를 참조하게 되면서 `Microsoft.Extensions.Logging.Console` 을 8.0.0 → 10.0.7 로 올렸다(다운그레이드 오류 회피). **도구 전용**이라 제품 빌드에는 영향이 없다.
