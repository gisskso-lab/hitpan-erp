## 3. 세 쓰기 자리 — 재확인 꼴

재확인 문장(한 곳 · `CooltimeEngine.cs:589-593`):

```sql
SELECT 1 FROM tenant_settings WHERE tenant_id = @TenantId AND cooltime_enabled = 1
 AND cooltime_at <=> @At AND cooltime_changed_at <=> @Changed LOCK IN SHARE MODE
```
→ 1 이면 계속 · 행 없음(NULL)이면 되돌리고 물러남.

| 자리 | 거래 | 재확인 위치 | 다르면 |

| ① 무응답 끝내기 | `CooltimeLogoutCoreAsync` 거래(옛 그대로) | **첫 문장**(세션 행 `FOR UPDATE` :396-399 보다 앞 · :385) | `tx.Rollback()` · `NotEnded` · 정보 로그 1줄 — 세션 DELETE · refresh 폐기 · 근태 · 접속기록 · 푸시 전부 0 |
| ② 놓침 끝내기 | 같음 | 같음 | 같음 |
| ③④ 묻기 | **새 거래**(옛 = 자동 커밋 한 문장) | **첫 문장**(UPDATE 앞 · :241) | `askTx.Rollback()` · 그 로그인 묻지 않음 · Prompt 푸시 0 |

## 4. 잠금 순서 확인

| 거래 | 순서 |
|---|---|
| 설정 저장 `SaveCooltimeAsync`(바꾸지 않음) | `tenant_settings` X(`FOR UPDATE`) → UPSERT → `user_sessions` X(그 회사 PC 행 전부) |
| 루트 저장 `SaveAsync` 의 UPSERT(자동 커밋 · 바꾸지 않음) | `tenant_settings` X 한 행만 |
| 엔진 끝내기(서버 원인) | **`tenant_settings` S(첫 문장)** → `user_sessions` X → DELETE → `refresh_tokens` X → `employees` · `tenant_settings`(일반 읽기 · 이미 S 보유) → `attendance` X |
| 엔진 묻기 | **`tenant_settings` S** → `user_sessions` X(UPDATE) → 커밋 → 밀어 보내기 |

- 저장 ↔ 엔진 = 둘 다 `tenant_settings` 를 **먼저** ⇒ 순환 0. 저장이 먼저면 엔진이 S 에서 기다렸다 바뀐 값을 보고 물러남(꼴 A · B) · 엔진이 먼저면 저장이 X 에서 기다리고 엔진은 아직 유효한 설정으로 끝낸 뒤 저장이 비움.
- 엔진 두 프로세스: S · S 함께 잡힘 → 세션 행 잠금 심판 그대로.
- §D-6 기존 교차(정지 · 비번 바꿈 `refresh → sessions` 대 엔진 `sessions → refresh`)는 그대로 — 1213 잡기 · 다음 바퀴 재판정.
- 금지 꼴(세션 행 잠근 **뒤** 설정 행) = 변이 M5 → G-C26 ⓐ 빨강.
