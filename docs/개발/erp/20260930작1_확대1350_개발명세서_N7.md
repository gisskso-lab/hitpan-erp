### 1-1. (ㄴ) 「기다리지 않음」 방식과 근거

- **가르는 기준 = 「이 프로세스의 첫 `CheckAsync` 인가」**(`Interlocked.Increment(ref _checkCalls) == 1`). 부르는 쪽을 구별할 인자가 `IUpdateFeed.CheckAsync(string, CancellationToken)` 에 없고, 인터페이스를 넓히면 구현체 전수(#12)·이전 기능 변경이 생기므로 부름 순서로 가른다.
- **첫 확인 = 기동 확인**: `InstalledVersionLedger`(`Program.cs:437`, `StartAsync` 동기 기록) → `SignedManifestStartupCheck`(`:445`, `Task.Yield` 뒤 `CheckAsync` 한 번). 화면 확인은 로그인 뒤에야 오므로 실제로는 기동 확인이 첫 부름이다. 기동 확인은 이미 뒤에서 돌아 기동을 막지 않으므로 거기서 기다리는 것은 무해하고, 기존 G-NF1(새 어댑터 첫 부름 직후 요청 2개·저장을 바로 잰다)이 무수정으로 통과한다.
- **그 뒤 부름(화면)**: 표지가 서 있으면(기동 확인이 받는 중이어도) 건너뛴다 → 바깥 요청 0·지연 0. 표지가 아직이면(기동 확인이 피드에 못 닿아 받기 자리에 못 온 경우) `Task.Run` 으로 뒤에서 한 번 시작하고 곧바로 돌아온다(작업지시 허용 방식).
- **뒤 받기의 취소 토큰 = 없음**: 화면 요청 토큰을 넘기면 요청이 끝나는 순간 받기가 끊겨 「한 번」을 헛쓴다. 상한은 받기 안의 `http.Timeout = 30초`(`:131`) 그대로.
- **관찰 안 된 예외 0**: `TryFetchFirstPrevious` 의 try 밖 줄은 판 읽기(`TryParse` · 던지지 않음)뿐이고, 안은 `catch (Exception)` 이 경고 한 줄로 끝낸다(#15).
