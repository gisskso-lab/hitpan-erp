## 5. 안 한 것 / 못 한 것 / PM 결정 필요

1. ⚠️ **S2 경계 — 기준일 당일도 막는다**(`date <= base_date`). 설계 문구는 「기준일 **이전**」이지만 레거시 최종잔액은 기준일까지의 거래를 품으므로 당일도 두 번 빼기다(§15-9 「2/20~2/28」 표현과 같은 해석). 문구도 「기준일(yyyy-MM-dd) 이전 날짜는…」 그대로라 당일 거절 때 어색할 수 있다 → PM 확인. 바꾸려면 `IsBlockedByBaseDate` 한 줄.
2. ⚠️ **P2 명세서 status** — `confirmed`·`invoiced` 둘 다 허용(대시보드 식과 같게). 수금 화면 목록은 `confirmed` 만 보인다. `invoiced` 전이 경로는 미실측④ 그대로 → [4] 확인 대상.
3. 지시 밖 보강 1건 — 삭제 UPDATE 에 `AND is_active = 1` + 0행 롤백. 역분개 신설로 동시 삭제 시 잔액·역분개 이중이 생길 수 있어 넣었다. 빼라면 두 줄.
4. **역분개는 원 분개가 있을 때만** — 이관 수금·지급(분개 `migration` 계열)과 20260827작4 이전 수금은 삭제해도 역분개 0. 과거 취소분 치료는 범위 밖(작지 §15-0) 그대로.
5. 명세서 쪽 조건의 이관 제외는 **거래처 단위 M 여집합**(설계 문언) — 이월잔액 회사인데 이월잔액 행이 **없는** 거래처의 이관 명세서에 붙은 사람 수금은 M 에도 안 들고 명세서 쪽에 남는다(종전 대시보드와 같은 값). P3 로 새로 생기지는 않는다. R2 가 #1·#9 교차 일치를 볼 때 참고.
6. 안 한 것(지시대로 다른 갈래): 11곳 소비자 식(R2) · 화면 칩·이월 한 줄·Web 문구 전달 메서드(R4) · CI GATES 등록(Z) · push.
