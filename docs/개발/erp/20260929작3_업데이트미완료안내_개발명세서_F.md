### 1-1. 지시서에 없던 선택 (PM 확인 요청 — 3건)
1. **「이미 안내했다」 표 값 = 버전 + 종류**(`UpdatePromptPlan.GuardValue` `:134` · 예 `1.3.50|failed`). 종전은 버전만이었다.
   - 왜: 로그인 유지가 localStorage(최대 7일)라 「다음 로그인」이 드물다. 버전만 적으면 같은 탭에서 [예] → 실패 → 화면 복귀(F5) 때 **다시 안 묻는다** = Q-1 「실패 뒤 반드시 다시 묻는다」 위반. 종류가 바뀔 때(first → failed 등)만 다시 뜬다 — 같은 버전·같은 종류 반복 방지(CTO B-1)는 그대로. 주기 조회 아님.
   - 영향: 업데이트 직후 옛 표(버전만)를 가진 탭에서 한 번 더 뜰 수 있다(무해).
2. **메인PC 팝업에 사유(`IssueText`) 한 줄을 함께 보임**(설계 §7 은 사장님 문구 + 종전 안내만). 작업지시서 §6 리스크 「blocked(디스크) 직후 [예] 반복 → 사유 문구가 원인을 말한다(P-1)」를 누르는 자리에서 성립시키려고.
3. **옛 API(4필드 없음) 대비** — `IssueKind` 가 비면 종전 동작 그대로(새 버전이면 Y/n). Web·API 는 한 게시물이라 정상 운영에선 안 탄다. 새 판정 없이 막아 버리면 팝업이 사라지는 쪽으로 실패하므로(#43) 종전을 유지했다(`UpdatePromptPlan.IsLegacy`).

## 7. 검증팀에 요청

- **경주(M-22 R-1)**: 대표가 메인PC 에서 로그인 → `UpdateConsentGate`(MainLayout `:47`)가 `MainPcGate`(`:74`)보다 먼저 조회할 때, 게이트가 단일 비행에 합류해 **왕복 1회**만 돌고 재조회에서 `CanRespond=true` 를 받는지. 왕복이 이미 끝난 뒤(실패) 조회가 나가면 게이트가 **한 바퀴 더** 돈다(끝난 결과를 붙잡지 않으므로) — 다른 PC 의 대표에게 로컬 권한 대기(최대 약 20초)가 한 번 더 생길 수 있다.

- 사이드바는 자기 조회보다 게이트가 **뒤에 흘린** 값을 우선한다(`Sidebar.razor:501` 순번 대조) — 늦게 온 자기 값이 R-1 재조회 결과를 덮지 않는지.
