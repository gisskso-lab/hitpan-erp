## 1. 착수 전 확인 — ⛔ 중단 조건 점검

### 1-1. 🟢 중단조건 1 (C-B1) — **L2 의 조인은 INNER 다**

`src/HitPan.Application/Services/LegacyBalanceMatching.cs:274` — `ReceivableMatchedDocLockedSql` 본문 둘째 줄:

```
  JOIN sales_deliveries sd ON sd.delivery_id = ec.ref_doc_id AND sd.tenant_id = ec.tenant_id
```

`LEFT`·`RIGHT`·`OUTER` 없는 **평문 `JOIN` = INNER JOIN**. 따라서 `ec.ref_doc_id IS NULL` 인 행은
등치 비교가 UNKNOWN 이라 **이미 조인이 버린다** ⇒ ㉪(`AND ec.ref_doc_id IS NOT NULL`)는 결과집합을 안 바꾼다.
🟢 **중단·반송 사유 없음.**

### 2-4. ⚠️ 🔴 **쌍의 계통 편차 — K-1 이 생각보다 얇다**

동일 데이터·동일 인덱스·동일 SQL 인 **두 사본이 계통적으로 5% 어긋난다**(3,136 vs 2,975 · **4/4 재현**).

| 실측 | 값 |
|---|---|
| 같은 DB 를 매회 `ANALYZE` 후 8회 반복 | **8/8 = 3,136** — 🟢 **측정 자체는 완전히 안정** |
| 같은 테이블 `ANALYZE` 5회의 `table_rows` | **112,800 / 112,680 사이를 오간다** — 표본추출이 결정적이 아니다 |
| 두 사본의 동일 조건 잠금 행 수 | **3,136 vs 2,975 (5.1%)** — 4/4 재현 |

⇒ **잡음이 아니라 사본 간 물리 배치·통계 차이의 계통 편차**다.
🔴 **2% 칸 완충이 0.059(8.0%)인데 쌍의 계통 편차가 5.1%** ⇒ 실질 완충은 **약 3%** 뿐이다.
설계 K-1 이 「가장 얇다」고 적은 칸이 **적힌 것보다 더 얇다.** → §8 에 열어 둔다.
