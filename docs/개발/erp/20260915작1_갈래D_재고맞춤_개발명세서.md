### 1-1. 규칙 — 대소문자·공백만 다른 품목이 히트판에 여럿일 때
- 후보 = DOCFC 표기마다 `ensureItem(pum, ku)` 가 돌려준 item_id ∪ **items 의 품명·규격 재고 키(Trim+대소문자 무시)가 같은 기존 품목**(삭제 표시 제외 · 옛 등록분 `item_name="품명|규격"`·spec 빈칸은 첫 `|` 로 나눔 `ItemNameKey` `:475`).
- 맞춤 줄을 넣을 품목 = **items.created_at 가장 이른 품목 → 같으면 item_id 서수** (`ChooseItem`). 입력 순서와 무관(G3-5).
- 나머지 후보 · DOCFC 에 없는 이관 원장 품목(용역 누계 · 품명 없는 폴백) = **목표 0**.
- 여러 DOCFC 키가 같은 품목으로 모이면(폴백 품목 등) 목표를 더한다.

### 1-2. 규칙 — 끝전
- 품목(① 이 고른 item) 단위 수량·금액 합 → `avg_cost = ROUND(금액 ÷ 수량, 6)`(0 에서 먼 쪽 반올림 = MariaDB DECIMAL) → **기본창고** `item_stock` 행만 UPDATE. SQL 에서 나누지 않고 C# decimal 로 계산해 넘긴다.
- **수량 0 · 금액≠0** → 수량×단가로 표현 불가 → avg_cost **안 바꿈**(리빌드 값 · 화면 금액 0) + 건수·금액합 LogWarning. 공영정보 MDB 실측 **0건**(§4).
- 품목 못 찾음 · 기본창고 재고 행 없음 → 건수 LogWarning.
