## 🚨 #70 진짜 원인 분석 (PM 별도 조사 필요)

### 사실 확인
1. **sourceId는 무조건 unique** — lineSeq 전역 카운터 + kcode + 부호 추가
2. **본 테이블 UNIQUE 키 = `uq_jl_source(tenant_id, source_id)` 만 잔존** (uk_journal_line_dedup DROP 완료)
3. **DropStageUniqueIndexesAsync는 본 테이블 UNIQUE 인덱스를 staging에서도 DROP**
4. **그런데도 BulkCopy 27,661 → 23,994 (3,667 손실)**

### 가설
- A. **MySqlBulkCopy 자체 결함** — warnings=64는 truncation. truncation 시 일부 행 IGNORE 가능성
- B. **PRIMARY KEY 인덱스 잔존** — line_id auto_increment PK DROP 처리(line 4801)에서 실패하면 fallback 동작
- C. **staging 안 다른 INDEX** — 5/20 DROP 전에 만들어진 TEMPORARY가 캐시될 가능성
