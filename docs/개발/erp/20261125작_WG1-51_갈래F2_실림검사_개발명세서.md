## §1 중단 사유 (실측)

작업지시서 §4-2 G3 참고 「표식 = ASCII `.net core bundle` 의 SHA-256 32바이트를 시험이 **계산**해 exe 에서 찾음」 이 **실측과 다르다.**

| 잰 것 | 값 | exe 안 개수 |
|---|---|---|
| SHA-256(ASCII `.net core bundle`) | `db2a6c16fec7fbeb…` | **0** |
| SHA-256(ASCII + NUL) | `df19cf0cd196b102…` | 0 |
| SHA-256(UTF-16LE) | `4750150ac5cf64b4…` | 0 |
| 실제 표식(apphost 고정 32바이트) | `8b1202b96a612038727b930214d7a03213f5b9e6efae3318ee3b2dce24b36aae` | **1**(위치 7,953,960) |

- 설계가 고를 거리(개발이 정하지 않음): ㉠ 표식 32바이트를 상수로 적음(출처 주석) ㉡ 다른 방법(새 꾸러미는 지시서상 금지 · 회송 대상) ㉢ 그 밖.

### §7-7 한계 · 안내

- **S-5**(「nuget 원본」 이 증명하는 범위): 원본 = 이 러너에 복원된 꾸러미 폴더 바이트. `.nupkg` 자체 서명 · 내용 대조는 안 함(지시서 §15-1 #13 · O14 때 함께).
- **xUnit 스택 추적**: 실패 레코드의 스택 추적 줄에는 빌드 때 소스 파일 전체 경로가 찍힌다(시험 메시지가 아니라 PDB 경로 · xUnit 기본). CI 에선 러너 경로라 사용자 이름이 없다 · 로컬 trx 는 scratch 에만 두고 지움. 시험이 만드는 메시지 문장엔 전체 경로 0.
- **#16 다른 작업 나무**: 다른 나무(autocrlf=true)에서 G1 이 빨강이면 `.gitattributes` 커밋 뒤 고지 파일을 지우고 `git checkout -- src/HitPan.Application/Resources/Fonts/NotoSerifKR-OFL.txt` 로 다시 풀 것(시험 손 0).
- 로컬은 pwsh 7 이 없어 증거 줄을 Windows PowerShell 로 대신 돌렸다(판정 무관) · CI 는 pwsh.
- 남은 것: **A3 CI 런**(push 는 PM 몫) — 첫 런의 `dotnet --version` · G3 결과로 러너 SDK 의 `--self-contained false` 꼴이 잰다. 자기 포함이면 G3 빨강 = 의도(§142 ③) → PM · 대표 판단 거리(배포 길). C(CI 변이 1런)는 K3 결재 따름.
