## 7. 검증팀에 요청 (자기 판단 아님)

- **특히 봐줬으면 하는 곳**
  - `EnsureRestrictedBackupFolderWindows` `:749` — API 가 **서비스(SYSTEM)** 로 돌 때 새 폴더 소유자가 SYSTEM/Administrators 중 무엇이 되는지, 셋 판정이 실물에서 거짓 거부를 내지 않는지 (이 PC 사용자 계정으로만 실측).
  - `StopProcessTree` `:459` — 숨은 콘솔(conhost)까지 끝나는지 실물 API 부모(svchost 계열)에서. 게이트는 시험 프로세스 자손으로만 쟀다.
  - `ResolveDbCredentialsFromConfig` `:584` — API 프로세스의 `db.conf`(TenantConfigReader 캐시)가 연결 문자열과 같은 값을 주는지 실물 확인(PM 반증 §11-1 은 코드 대조).
  - DB 이름 비교를 대소문자 무시로 했다(Windows MariaDB `lower_case_table_names`) — 옳은지.
  - `FindOnPath` 는 상대 경로 PATH 항목을 건너뛴다 — 설치 PC 에 상대 PATH 로만 MariaDB 가 잡힌 경우가 있는지.
- **회귀 우려**
  - 기본 폴더가 사용자 계정 API 에서는 여전히 문서 폴더(종전 동일), SYSTEM 에서는 `%ProgramData%\HitPan\Backup` 으로 **바뀐다** — 기존 `C:\Windows\System32\HitpanBackup` 의 옛 백업은 옮기지 않는다(교정 후 목록의 옛 파일 경로는 그대로 이력에 남음).
  - `GetSettingsAsync`(조회)가 교정 시 UPDATE 를 한다 — 읽기 전용 권한 문맥에서 호출되는 곳이 있는지.
  - 복원 버튼이 모든 PC 에서 막힌다(C-11 의도) — 화면 안내는 §5 PM 보고.
