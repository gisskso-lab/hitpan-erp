## 3. 어떻게 만들었나 — 판단 근거

### (A) 메뉴 소속
사장님 판정 그대로. *"직급관리, 결재설정은 그룹웨어"* / *"권한설정은 히트판의 권한을 설정하는 과목이니 계정관리"*.
결재 설정을 **결재 3형제 바로 뒤**에 뒀다 — 결재라인을 세우는 곳과 그 결재가 도는 곳이 붙어 있어야 흐름이 보인다.
주소(`/settings/positions`·`/settings/approval`)는 그대로. **위치만** 옮겨 즐겨찾기가 안 깨진다.

### (B) 용어 — 3층 중 화면만
| 층 | 처리 |
|---|---|
| 고객 화면 17곳 | ✅ 대표계정 / 직원계정 |
| 법적 문서 9곳 | ⏸️ **사장님 결재 대기** (법무팀장 영역·약관 버전) |
| 코드 내부 13곳 | ⛔ **불변** — `is_parent`·`IsParent` 그대로 |

"계층" 헤더, "ERP 마스터 계정" 도 개발용어라 함께 정리했다(헌법 #23).

### (C) 흐름 손잡이
- **계정 생성 후 다이얼로그** — 종전엔 스낵바 한 줄 뜨고 길이 끊겼다. 계정만 만들면 그 직원은
  로그인은 되는데 **볼 수 있는 메뉴가 없다.** 그 사실을 알리고 권한설정으로 보낸다
- **권한설정 빈 상태** — 글자로 "[사용자 추가·관리]에서 하세요" 라고만 하던 것을 **버튼**으로.
  글자로 안내하면 고객은 그 메뉴를 찾아 헤맨다
- **`empId` 전달** — 12명 중 김대리를 눌러도 첫 사원이 열리던 것을 봉합. 값이 없거나
  목록에 없으면 **조용히 첫 사원**으로 되돌린다(사이드바 직접 진입 경로 보호)

### (D) 부서 — API 를 왜 안 건드리나
🔴 **PM 초기 오판을 사장님이 잡으셨다** — *"계정생성 API를 왜 건들지?"*

실측: `users.department` 는 **문자열 컬럼**이고 `UserService.cs:130·144` 가 문자열을 받아 그대로 저장한다.
화면에서 드롭다운으로 고르든 손으로 치든 **API 가 받는 것은 문자열 하나로 동일**하다.
→ 화면만 바꿨다. **API·DTO·SQL 0건.**

부서는 **선택 항목**으로 뒀다. 부서 마스터가 빈 회사에서도 계정은 만들어져야 한다(헌법 #20).

## 4. [3-V] 병렬검증이 잡은 것

**PI-01 — 부서 드롭다운 전환 시 기존 자유 텍스트 소실 (P1)**

기존 계정 4개는 부서가 자유 텍스트("영업부")로 저장돼 있다. 마스터에 그 이름이 없으면
수정 다이얼로그에서 **빈 칸으로 보이고, 저장하면 조용히 지워진다.**

→ `_editDeptOptions` 로 **마스터 + 지금 저장된 값**을 합쳐 옛 값을 살렸다. 상세는 PI-01 문서.
