**설계에서 고른 해석 (확인 요청 — §7)**
- IssueText: 설계 §7 에 행이 있는 종류는 §7 문구, 없는 종류(first·requested·in_progress)는 §4 사이드바 칸 문구(「새 버전 {L} 있음」·「업데이트 준비 중」·「업데이트 진행 중」). ⇒ later 는 §7 「나중에 하기를 선택하셨습니다.」 (§4 사이드바 칸 「업데이트 미완료 · 나중에 선택」 아님).
- `success` 인데 I<L(§4 failed 행): §7 에 전용 문구가 없어 「failed · 그 밖」 문구 「업데이트가 시작되지 않았습니다.」.
- detail 판별은 머리 일치가 아니라 **포함**(`Contains`) — 갈래 W 가 detail 앞에 꾸밈을 붙여도 같은 문구로 간다.
- 모르는 action → first(종전처럼 묻는다) · 모르는 result → failed(다시 묻는다). 「더 묻는 쪽」.
- 쿼리 1회: 종전 L 조회(무변경 · #1) 뒤 **같은 연결로 순차 1회** 추가. L 을 알아야 C·A 를 찾는다. WhenAll 0(#16).
- C·A 조회 실패 폴백 = `first`(= 종전: 새 버전 있으면 팝업). 종전 L 조회 실패 폴백은 종전 그대로 + 4필드 none/false.
