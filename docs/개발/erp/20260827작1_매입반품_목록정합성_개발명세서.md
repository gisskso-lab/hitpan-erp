## 3. 🔴 실측으로 뒤집힌 판단 3건 (PM 자기반증)

1. ❌ *"매입목록만 LIMIT 200 이라 어긋난다"*
   → 무관. **진짜 원인은 날짜 컬럼 차이**(매입일 vs 반품일)
2. ❌ *"취소분이 반품현황 집계에 섞인다"*
   → `ReportService` RT_BY_* 4종은 **이미 `status='confirmed'`**(8/25 사장님 결재분).
     고칠 곳은 현황이 아니라 **목록**이었다
3. ❌ *"반품목록 화면이 status 를 안 보여준다"*
   → `ReturnStatusPage`(집계현황)만 보고 내린 판단. 진짜 소비자는
     `PurchaseReturnList.razor` 이고 **이미 렌더한다**. 이름이 비슷한 화면을 착각했다

### 부수 발견 — `'canceled'AND` 는 안 터진다
반증 중 확인: MariaDB 는 **따옴표 뒤 `AND`** 는 공백 없이도 정상 파싱한다
(`0AND` = 숫자/문자 뒤만 ERROR 1064).
⇒ W1 봉합이 raw string 을 **따옴표로 끝나게** 만들어, 같은 이어붙이기 실수가 나도
   더는 500 이 되지 않는 부수 효과가 생겼다. **다만 이걸 안전장치로 믿지 않는다** —
   조건은 여전히 raw string 안에 둔다.

## 4. 남은 것 — 사장님 결재 대기

**원인 ② 날짜 기준 불일치는 이번에 고치지 않았다.**
