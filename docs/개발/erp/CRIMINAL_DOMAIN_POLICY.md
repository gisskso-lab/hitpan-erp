## 2. 1차/2차 안건 폐기 사유 (자기 비판)

### 1차 안건 폐기 (받아쓰기 1차 사고)
- **잘못:** SW_PAY 4종을 "근로기준법 §39 보호 대상" 표기
- **실제 §39:** 퇴직증명서(사용증명서) 발급 의무 조항 — 급여 데이터와 무관
- **원인:** 보안매니저 의견 받아쓰기, 법령 원문 미검증

### 2차 안건 폐기 (받아쓰기 2차 사고)
- **잘못:** "주민번호 수집 불법, 앞 6자리만 추출" 제안
- **실제:** ERP는 소득세법 §127·§164, 4대보험법 등에서 **주민번호 13자리 보유 합법** (개인정보보호법 §24의2 ①항 단서 — "법령에서 구체적으로 허용한 경우")
- **원인:** ERP 업무 도메인 상식 누락. 사장님이 회계·연봉계약 맥락으로 잡아줌

### 결론
하브루타 헌법 위반 2회 연속. 사장님 지적이 없었으면 잘못된 정책으로 W2 진입할 뻔.

| 레거시 | 신 매핑 | 처리 | 처리 근거 법령 |
|---|---|---|---|
| `SW_JUMIN` (Text14) | `employees.resident_no_encrypted` (VARBINARY 255) | **AES-256** | 소득세법 §127·§134·§164 (원천징수·지급명세서), 국민연금법·건강보험법·고용보험법·산재보험법 (4대보험 신고) |

| `SW_PAY` (Int32) | `employees.salary_encrypted` (VARBINARY 255) | **AES-256** | 근로기준법 §48 (임금대장 작성·5년 보존), 개인정보보호법 §29 (안전조치 의무) |

| `SW_PAYeuy` (TinyInt) | `employees.salary_category` (TINYINT) | 평문 OK | 식별성 낮음 (분류 코드만) |
| `SW_PAYoth` (Text100) | `employees.salary_extra_encrypted` (VARBINARY 255) | **AES-256** | 금액·세부내역 포함 → 개인정보보호법 §29 |

## 4. 처리 근거 법령 — 핵심 조문

### 4.1 개인정보보호법 §24의2 (주민번호 처리 제한)
> ①항: "개인정보처리자는 **법령에서 구체적으로 허용한 경우**를 제외하고는 주민등록번호를 처리할 수 없다."

→ ERP는 **단서 조항에 해당** (소득세법·4대보험법 등 처리 근거 다수 존재).

### 4.2 소득세법 §127 (원천징수)
사용자는 근로소득 지급 시 소득세 원천징수 → **주민번호 13자리 보유 필수**.

### 4.3 소득세법 §164 (지급명세서 제출)
국세청 제출용 지급명세서 → **주민번호 13자리 필수**.

### 4.4 4대보험 신고 (각 보험법)
국민연금법, 건강보험법, 고용보험법, 산재보험법 → **주민번호 13자리 신고 의무**.

### 4.5 근로기준법 §48 (임금대장)
> "사용자는 각 사업장별로 임금대장을 작성하고 임금과 가족수당 계산의 기초가 되는 사항, 임금액, 그 밖에 대통령령으로 정하는 사항을 임금 지급할 때마다 적어야 한다."
> 시행령 §27: 5년 보존 의무.

→ 급여 보존은 **법적 의무**. 보존하되 안전조치(§29) 필수.

### 4.6 개인정보보호법 §29 (안전조치 의무)
> "개인정보처리자는 개인정보가 분실·도난·유출·위조·변조 또는 훼손되지 아니하도록 ... 안전성 확보에 필요한 기술적·관리적 및 물리적 조치를 하여야 한다."

→ AES-256 암호화 + 접근통제 + 감사로그 = 안전조치 이행.

### 4.7 부가가치세법 §32 (세금계산서 발급)
거래처 대표가 개인사업자일 때 세금계산서 발급 → **대표 주민번호 필요**.
법인사업자는 사업자등록번호로 갈음 → 주민번호 불필요.

→ `buy_topjumin`은 **선택 입력**. 개인사업자 거래처일 때만 입력.

## 5. 보안 정책 3종 — 사장님 결재 완료

### 5.1 저장 (헌법 #5·#18·#22)
- **AES-256 Value Converter** (.NET 8 Entity Framework Core 컨버터)
- **컬럼 타입:** `VARBINARY(255)`
- **마스터키:** ERP 로컬 보관 (`appsettings.json` 분리, 환경변수 또는 보안 키 저장소)
- **본사 송신 0** — 마스터키도 평문 데이터도 본사로 전송하지 않음 (헌법 #18·#22)

### 5.2 동의·고지
- **직원 채용 시:** 개인정보 처리 동의서 1회
  - 처리 목적 명시: 급여 지급, 4대보험 신고, 연말정산, 임금대장 작성, 지급명세서 제출
  - 보유 기간 명시: 퇴직 후 5년 (근로기준법 §48 시행령)
  - 동의 일시·IP·약관 버전 DB 기록
- **거래처 등록 시:** 대표 주민번호 입력란은 **선택 입력** + 동의 체크박스
  - 개인사업자 거래처일 때만 입력 안내
  - 법인사업자는 사업자등록번호로 갈음

### 5.3 접근 권한 분리
| 역할 | 권한 |
|---|---|
| 평사원 | 본인 정보만 + 마스킹 표시 (`880101-*******`, 급여 `●●●`) |
| 인사·경리 담당자 | 권한 범위 내 조회 + 감사로그 INSERT |
| tenant_admin | 전체 조회 가능 + step-up 인증 필수 |

- **기본 표시:** 마스킹 (`880101-*******`, 급여 `●●●`)
- **[보기] 버튼:** step-up 인증 (비밀번호 재입력 또는 간편인증) → 5분 평문 조회 → 자동 마스킹 복귀
- **감사로그 INSERT:** 누가·언제·어떤 컬럼·어떤 직원의 정보를 조회했는지 전수 기록

## 6. 마이그 시 적용

### 6.1 레거시 MDB → 신 히트판 변환
```csharp
// SW_JUMIN (Text14) → resident_no_encrypted (VARBINARY)
employees.ResidentNoEncrypted = _crypto.Encrypt(GetStr(row, "SW_JUMIN"));

// SW_PAY (Int32) → salary_encrypted (VARBINARY)
employees.SalaryEncrypted = _crypto.Encrypt(GetInt(row, "SW_PAY").ToString());

// SW_PAYoth (Text100) → salary_extra_encrypted (VARBINARY)
employees.SalaryExtraEncrypted = _crypto.Encrypt(GetStr(row, "SW_PAYoth"));

// SW_PAYgu, SW_PAYeuy → 평문 (식별성 낮음)
employees.SalaryType = GetByte(row, "SW_PAYgu");
employees.SalaryCategory = GetByte(row, "SW_PAYeuy");

// buy_topjumin (Text13) → ceo_resident_no_encrypted (선택)
if (!string.IsNullOrWhiteSpace(GetStr(row, "buy_topjumin")))
{
    partners.CeoResidentNoEncrypted = _crypto.Encrypt(GetStr(row, "buy_topjumin"));
}
```
