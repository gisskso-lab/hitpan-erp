## §2 시각 심기 · DB 준비 (설계 §7 머리 · §D-5)

- DB 시계는 주입 못 함 ⇒ `login_at` · `cooltime_asked_at` · `cooltime_snooze_until` 을 `UTC_TIMESTAMP(6) - INTERVAL n SECOND` 로 과거에 심거나, 고정 기준일 **D = DB 시계 서버 로컬 오늘 − 2일** 의 로컬 시각을 엔진 `ServerLocalToUtc` 로 바꿔 심는다(이틀 전이라 ② 「지금 ≥ C+5분」 이 늘 성립).
- 「지금 직후」 시각 = `CooltimeJustPassedAsync`(설정 시각 = DB 시계 로컬 − 15초 · 초 단위 내림) · 한 바퀴에는 그 순간 `nowLocal` 을 넣는다.
- G-C19 「다음 날」 = 주입 `nowLocal` = 오늘 C + 1일 + 15초(엔진은 `nowLocal` 을 C 계산에만 쓴다 · 세션 판정은 DB 시계).
- 격리 DB = 시험마다 새 DB(`hitpan_ctm_xxxxxxxx`) + 출하 DDL 한 방(#36) · 연결 풀 끔(`Pooling=false`) · 끝나면 DROP · 시험 DB 환경 변수 `HITPAN_DB_HOST/PORT/USER/PASS` · `HITPAN_MYSQL` · `HITPAN_REQUIRE_DB` — 선례 `ApprovalRetiredAccessGateDbTests` 그대로. CI 아닌 곳에서 접속·권한 없으면 `[SKIP]`(CI 에선 FAIL).
- 이 파일의 SQL = 상태를 **만드는** 준비 · **읽는** 확인뿐. 판정 SQL 복사 0(작2 절I 교훈).

## §6 발견 · 확인 거리 (🔴 PM)

1. **G-C14 설계 문장과 코드가 한 칸 다르다** — 설계 §E 「ⓐ 행 있음 · 물음 만료 → continue 409 · logout `ended:false` · state 200」. 코드의 API 끝내기 조건은 `cooltime_asked_at IS NOT NULL AND user_id`(갈래 ① §5-2 · 65초 안 봄)라, **물음이 만료돼도 칸이 남아 있으면 logout = `ended:true`**(정시 퇴근 적음). `ended:false` 는 물음 칸이 빈 행(③ · 예: 팝업 중 끔 E-3)에서 나온다. 게이트는 코드 동작대로 상태를 갈라(①~④) 기대값을 고정했다. 설계 문장 정정 또는 API 끝내기에 65초 조건 덧 — PM 판단.
2. **E-5 ⚠️ 「팝업 중 끔 → 같은 PC 다시 로그인」** — 코드 읽기 예측 = **409**(작2 판정은 같은 계정의 살아 있는 PC 행만 본다 · 끔(E-3)으로 물음 칸이 비면 ① 이 안 돌아 행은 만료(8시간)까지 남는다) ⇒ 그 직원은 같은 PC 에서도 만료까지 로그인 불가 가능. 확정은 CI trx 의 `[E-5 확인]` 줄. 걸리면 E-5 (나) 여부 · 끌 때 PC 세션 정리 여부 = PM.
3. **G-C12 대조 거리(갈래 ② §3 「UPDATE WHERE 에서 tenant_id 를 빼면 FAIL」)는 변이로 못 잡는다** — `EditCheckOutAsync` 는 앞의 `SELECT … FOR UPDATE` 가 회사로 먼저 거른다(없으면 `NotFound`). UPDATE 쪽 `tenant_id` 는 이중 장치라 단독 제거는 동작이 안 바뀐다. 게이트는 「다른 회사 id → NotFound · 행·이력 0」 동작을 잰다.
4. **경계 시각 위험(작음)** — G-C16 은 정시 23:59:59 · 출근 오늘 00:00 으로 빈칸을 만든다(CI 서버 로컬 23:59:59 이후 1초 안에 돌면 빈칸 대신 정시). G-C13 · G-C16 의 손 퇴근은 오늘 날짜 행만 찾는 기존 함수라 자정 직전·직후 몇 초는 날짜가 갈릴 수 있다. 재현되면 재시도 1회로 판별.
5. **G-C18 ⓑ · 실물 항목은 코드 게이트가 아니다** — [4] 실물 실측(지시서 §5 마지막 줄).
6. **DESCRIBE 대조(#13)** — 이 갈래도 DB 접속 금지. CI 격리 DB(출하 DDL)에서 시험이 표를 실제로 쓴다(`tenant_settings` 쿨타임 4칸 · `user_sessions` 물음 2칸 · `attendance.check_out_source` · `employees.user_id` · `audit_trail`) — 칸 이름이 틀리면 시험이 SQL 오류로 FAIL. `DESCRIBE` 출력 첨부는 [4] 몫(갈래 ① §3).
7. 휴대폰 행에 물음 칸이 찬 상태(G-C7)는 정상 흐름에선 안 생긴다(묻기 문장이 `device_kind='pc'`) — 삭제 심판 ⓐ 를 재려고 심은 상태다.
