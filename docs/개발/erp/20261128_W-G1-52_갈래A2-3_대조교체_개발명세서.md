### ② 원인과 근거 — 판단: 「출하 트리거의 형 변환 × 시험의 UUID 꼴 아닌 id」 · 🟡 DB 로 직접 재지 못함(이 PC DB 금지) — **CI 에서 확인 안 되면 철회**
1. 출하 DDL `installer/hitpan_db_clean.sql:2801` `trg_psp_ratio_insert` = `SET NEW.id = IF(NEW.id IS NULL OR NEW.id = '', UUID(), NEW.id), …`.
2. MariaDB 10.7 이상(11.4 포함)에서 `UUID()` 는 문자열이 아니라 **`uuid` 자료형**을 돌려줌(MariaDB 이슈 MDEV-33827 — `CREATE TABLE … AS SELECT UUID()` 결과 칸이 `uuid` · 영향 판에 11.4 · 고침 11.5.1 은 「널 가능」 표시만 고침).
3. MariaDB 의 고정 이진 형(INET6 · UUID 같은 틀) 은 `CASE` · `COALESCE` 같은 섞음 식에서 **문자열과 섞이면 결과 형이 그 형** · 형식이 안 맞는 문자열은 「경고 + NULL」(결과가 널 가능일 때) — MariaDB INET6 문서. ⇒ `IF(…, UUID(), NEW.id)` 의 결과 형 = `uuid` · `NEW.id = 'sr3-psp-1'`(16진 UUID 꼴 아님) → NULL(트리거 `sql_mode = ''` 라 오류 아닌 경고) → `NEW.id = NULL` → INSERT 가 1048 `Column 'id' cannot be null`. **증상 모양(빈칸도 아닌 id 를 직접 넣었는데 id 널 오류)과 맞음.**
4. 왜 다른 DB 게이트(같은 런 1095 통과)는 안 걸렸나 — 레포 전체에서 이 표에 INSERT 하는 곳 = 제품 `PartnerService.cs:115` · `:652` 와 G15 뿐. **G15 가 출하 DDL 위에서 이 표에 줄을 넣는 첫 시험.**
5. 제품 길: 두 자리 모두 id = `Guid.NewGuid().ToString()`(`PartnerService.cs:101` · `:635` — 소문자 대시 꼴 = 유효 UUID) → `uuid` 로 바뀌었다 같은 글자로 돌아옴 ⇒ **지금 제품의 업체특별단가 저장 길은 이 꼴로는 깨지지 않을 것으로 봄**(이것도 문서 근거 · 직접 측정 아님).
6. 그러나 이 동작은 **출하 트리거의 성질**이다 — UUID 꼴이 아닌 id(예: 옛 자료 이관 · 손으로 넣은 줄 · 다른 꼴 Guid)를 넣거나 복원으로 다시 부을 때 id 가 조용히 NULL 이 되어 INSERT 가 죽음. G15 의 「붓기 전후 값 같음」 이 바로 이 트리거를 지나는 길이다.
