- 원인(실측): 고지 `src/HitPan.Application/Resources/Fonts/NotoSerifKR-OFL.txt` 는 main `4eebdb44` 에 없고 ① §59 머지로 작업 사본에 처음 풀림 — 그때는 `.gitattributes` 의 `eol=lf` 줄(② F-2 가 더함)이 아직 없어 이 PC `core.autocrlf=true` 로 CRLF 로 풀림. ② 가 규칙만 더하고 그 파일 내용은 안 바꿔 git 이 다시 풀지 않음 → 작업 사본만 CRLF 로 남음. `git status` 에는 「바뀜」 으로 **안 보임**(지시서가 예상한 반대 모양).
- 커밋 쪽: `git cat-file -s HEAD:<고지>` = **5682** · blob sha256 앞 12 = **`20c156a223d1`** = G1 기대값 · `check-attr eol` = `lf`. 커밋 · 트리 무결.

- `eol=lf` 규칙이 걸린 파일은 이 1개뿐(`.gitattributes` diff 실측).
- 뜻: CI(새 체크아웃)는 처음부터 규칙대로 LF 로 풀어 이 일이 안 생김. 기존 작업 사본에 합류본을 머지해 쓰는 사람(autocrlf=true)은 같은 G1 빨강을 볼 수 있음 → PM 확인 거리(Q6).
