## 4. 🔴 아직 안 된 것 (결재 요청)

### 4-1. 출력이미지 저장 — 물리적으로 막혀 있다

`BuildPreviewAsync` 가 만드는 base64 는 최대 약 **270만 자**, 컬럼은 **varchar(200)** 이다.

> 그대로 보내면 서버 `TruncateNullable` 이 **말없이 앞 200자만 잘라 저장**한다.
> 오류도 없이 `data:image/png;base64,iVBORw0KGgo...` 로 잘린 **깨진 값이 DB 에 남는다.**
> **조용히 썩는 쪽이 안 되는 것보다 나쁘다.**

⇒ `KeepPathOnly()` 가드로 `data:` 로 시작하는 값은 **보내지 않는다.** 화면에도 안내를 띄웠다.

| 안 | 내용 | PM 의견 |
|---|---|---|
| **(가)** | **파일 업로드 API 신설** — 파일은 고객 PC 로컬에 두고 경로만 컬럼에 | 🟢 **권장.** `CertificateController` 에 `IFormFile` 선례 있음. DB-85 가 원래 의도한 설계가 이것. 컬럼 변경 불필요 |
| (나) | 컬럼을 LONGTEXT 로 바꿔 base64 저장 | 회사 정보 한 행이 수 MB. 조회마다 그 무게를 지불. **권하지 않음** |
| (다) | 현 상태 유지(미리보기만) | 거짓 저장은 없지만 기능 미완 |

⚠️ **(가)를 하더라도 확인이 하나 더 필요합니다** — 인쇄 양식이 인장을 참조하는 코드를
아직 못 찾았습니다(`grep "인장"` → 0건). 저장만 되고 **안 찍히면 반쪽**입니다.
