## 7. 검증팀에 요청

- **INFO 앞 200자에 refresh 토큰 해시가 섞이나** — refresh INSERT 문장은 `(token_id, user_id, token_hash, …) VALUES ('uuid', 'user', '해시…'` 순이라 줄바꿈·공백 포함 약 200~205자에서 해시가 시작한다(눈어림 · 미측정). 시험용 일회 토큰이지만 [3-V] 판정 요청. 줄이려면 상수 `LEFT(INFO, 200)` 두 곳.
- **대조군 ⓒ-3 대기 조건**(§1-1 ③) — `Waiting for table` 접두가 CI MariaDB 에서 다르면 「판정 단계에서 멈추지 않았다」로 FAIL(원인 메시지에 마지막 STATE·INFO 가 실림).
- **잠금 풀림** — LOCK 은 `try` 안(권한 없어 터져도 finally 가 트리거를 지움) · finally 첫 줄 UNLOCK(실패해도 `using` 닫힘이 푼다) · KILL · `await login` · DROP 2개 순. 로그인이 시작 안 됐으면 `login == null` 이라 기다리지 않음.
- **회귀 우려** — T7 클래스에 생성자 인자(`ITestOutputHelper`)가 생겼다. 이 클래스를 반사로 만드는 곳 grep 0건(`TaxInvoicePdfRenderGuardTests` 언급은 자기 파일뿐). R-1 110/110 통과.
- **T7 단언 개수** — 통과 때도 `Assert.True(found == expected, "")` 를 한 번 부른다(조건부 단언 아님 · 메시지만 실패 때 만든다).
