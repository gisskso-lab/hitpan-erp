## 2. 작업 범위

### 2.1 무엇을 한다
깨끗한 테스트 DB(`hitpan_e2e`, 테스트 API 포트 5300)로 **6단계 워크플로우를 끝까지 API 호출로 관통**한다. 각 단계에서 응답·데이터 상태를 확인하고, **깨지는 곳(500·둔갑저장·끊김·0건유실·미배선)을 file:line/엔드포인트로 기록**한다.

관통 시나리오(헌법 #20 3흐름 + 회계):
```
로그인
 → [마스터] 상품 등록 → 거래처 등록 → 창고 확인
 → [매입] 발주 생성 → 매입(영수) 생성 → 매입 확정 → 재고 증가 확인 → 회계 자동기표 확인
 → [BOM] (자재 있으면) BOM 생산 → 완제품↑·자재↓ 확인
 → [판매] 견적 → 수주 전환 → 거래명세서 전환 → 판매 확정 → 재고 차감 확인 → 회계 자동기표 확인
 → [세금] 세금계산서 발행 → 발행상태 확인
 → [현황] 재고현황·매입현황·판매현황 조회 → 숫자 정합 확인
 → [재무] 현금출납·회계 원장 조회 → 차변=대변 확인
```

### 2.2 무엇을 안 한다 (절대)
- **코드 한 줄도 안 고친다.** 깨져도 봉합 금지. 목록만.
- **운영DB(hitpan_erp/demo) 안 건드린다.** 테스트 DB(hitpan_e2e)만.
- **EXE 빌드·터널·인프라 조작 안 한다** (헌법 #29).
