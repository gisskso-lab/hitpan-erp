## 7. 검증팀에 요청

- **`Get` 의 연결 재사용**: `FillAsync` 가 시간 초과로 끝난 뒤 같은 연결로 결제 조회가 이어진다. 취소가 깔끔하면 그대로 살지만, 연결이 끊긴 채 끝나면 결제 조회가 던져 상세가 500 이 될 수 있다. 설계 자리(결제 조회 앞)를 따랐고 G-6 은 시간 초과를 재지 않는다.
- **판정 없는 행의 경로**: 두 문장 사이에 사라진 행은 `null` 로 남는다 — 「확인 불가」. 삭제 경합이라 표시 영향은 잠깐이다.
- **G-6ⓒ**: 1267 을 `serial_verify_attempts.tenant_id` 문자 규칙 변경으로 일으킨다. 시험 안에서 오류 번호를 직접 단언하므로 MySQL 8 이 다른 번호를 내면 빨강이다.
- **음성 ⓒ(EXISTS → LEFT JOIN)**: `FillAsync` 는 키로 합쳐 응답 행이 안 불어난다. 그래서 설치④ 가 `ReadSql` 행 수를 직접 잰다.
- **회귀 우려**: `BackofficeRoleScopeGateTests` 가 실물 목록을 탄다(`db-gate`). 둘째 문장이 MariaDB 에서 실패해도 200 이라 그 게이트로는 안 보인다.
- **#12 잔여**: 칩 색 함수는 설계대로 razor 2곳에 있다. 상수 정의도 API · 화면 2벌이라 G-7 이 두 쪽 글자를 맞춰 잰다.
