## §2 봉합 — 이미 있는 장치를 썼다 (새 바퀴 0개)

`Program.cs:78` 에 정책이 **이미** 있었다.

```
o.AddPolicy("PlatformAdmin", p => p.RequireClaim("account_type", "platform_admin", "platform_owner"));
```

이것이 §2-1 결재문(현행 축 `account_type` = `platform_admin`/`platform_owner`)과 **글자 그대로 일치**한다. 신설 0건.
선례도 같다 — `SignupsAdminController.cs:40` (2026-08-02 P0 봉합), `PricingAdminController.cs:30`, `PromotionsAdminController.cs:11·164`.

변경한 것은 **두 줄**뿐이다(그 줄에 봉합 경위 주석 추가).

| 파일 | 변경 |
|---|---|
| `src/HitPan.Backoffice.API/Controllers/DeviceRegistrationController.cs` | 클래스 `[AllowAnonymous]` → `[Authorize(Policy = "PlatformAdmin")]` |
| `src/HitPan.Backoffice.API/Controllers/SerialVerifyController.cs` | 클래스 `[AllowAnonymous]` → `[Authorize(Policy = "PlatformAdmin")]` |

### 왜 `[BoPermission]` 이 아닌가
선례(`SignupsAdminController.cs:31-37`)와 같은 이유다. `installer/backoffice/90_seed_permissions.sql` 에
`devices.*`·`serial-locks.*` 권한 키가 **0건**이라 `[BoPermission]` 을 붙이면 **사장님 본인도 403** 으로 튕긴다
(2026-06-19 실사고 — 테이블만 있고 행이 없어 전원 403). Policy 는 JWT 클레임 기반이라 DB 어휘 불일치를 타지 않는다.

### 2단 방식 (결재 사항)
작10 ①사이클에서 역할 enum 4값으로 전환할 때 이 속성을 **함께** 옮긴다.
**지금 4값을 앞당기지 않았다** — 작10 설계 확정 전에 체계가 갈라진다(사장님 결재문 그대로).

### §6-2 M-2 — 게이트 판정식을 리플렉션 전수로 넓혔다

검증자가 찾은 「게이트는 초록인데 봉합이 뚫리는 조합」 2개를 봉합했다.

| 구멍 | 봉합 |
|---|---|
| 판정식이 **글자 의존**(클래스명 `Admin`/라우트 `admin`)이라 백오피스 컨트롤러 **32개 중 10개만** 감시. 인가 표시가 아예 없는 4건(`Promotion`·`TossPayments`·`LandingSignup`·`BackofficeAuth`)은 집합에 **안 들어왔다** | 집합을 `ControllerBase` 파생 **전수**(추상 제외)로. 관리 표면 = `admin` 조각 \| `api/backoffice/*` \| 클래스명 `Admin` ⇒ **감시 10 → 21개** |
| `G_W11_5` 가 **`[Authorize]` 단독을 합격**으로 셌다 ⇒ 앞으로 `api/admin` 컨트롤러에 `[Authorize]` 만 달면 초록인데 대리점에 열린다 | 관리 표면은 **역할까지 요구**해야 합격: `[Authorize(Policy/Roles=…)]` 또는 액션의 `[BoPermission("…")]`. **`[Authorize]` 단독은 불합격** |

신설: `G_W11_11`(전수 분류에서 샌 컨트롤러 0건 — 새 접두어 누락을 드러낸다) · `G_W11_12`(예외표 썩음 방지 — 고쳐지면 표를 줄여야 초록).
감시 범위는 `ITestOutputHelper` 로 **통과할 때도** 출력에 찍는다:
`[작11 게이트 범위] 백오피스 컨트롤러 전수 32개 · 관리 표면 21개 감시 (종전 글자 판정식 10개) · 문서화 익명 예외 3건 · 역할미요구 기지 예외 3건`.

**FAIL 확인(대조실험)**: 예외표의 `OwnerMfaController` 한 줄을 어긋나게 하면 `G_W11_5` 가
「`[Authorize]` 단독 — 인증만 묻는다」로, `G_W11_12` 가 「예외표에서 지워라」로 **FAIL 한다(2건)**. 원복하면 전건 PASS.

🔴 **리플렉션으로 못 넓힌 한계** (게이트 주석에도 같은 문장으로 적었다):
- **본문 역할검사는 못 읽는다** — `IsOwner()` 같은 본문 검사는 속성이 아니라 리플렉션에 안 보인다 ⇒ 예외표로만 다룬다.
- **런타임 정책 내용은 못 읽는다** — `[Authorize(Policy="X")]` 는 붙어 있으면 합격으로 센다. `X` 가 실제로 역할을 요구하는지는 `G_W11_1~4` 의 **실제 요청**(토큰없음 401 / 대리점 403 / 본사 통과)이 담당한다.
- **라우트 접두어는 규약 의존** — `api/admin`·`api/backoffice` 밖에 새 관리 접두어(예: `api/platform`)가 생기면 관리 표면으로 안 잡힌다. 그 누락은 `G_W11_11` 의 미분류 적발이 드러낸다.

### §6-3 M-1 — 시험이 외부로 실제 송신할 수 있었다 (봉합)

이 게이트는 `WebApplicationFactory` 로 **실제 호스트**를 띄운다 ⇒ `Program.cs:31` 의 `WebhookDispatcher`(BackgroundService) 도 함께 깨어난다.
그 `ExecuteAsync` 는 `Task.Delay` 가 `TickAsync` **뒤**에 있어 **첫 틱을 지연 없이** 돈다(`WebhookDispatcher.cs:46-57`).
`TickAsync` 는 `ConnectionStrings:BackofficeDb` 로 접속해 `status='pending'` 행을 읽고 그 행의 `target_url` 로 **실제 HTTP POST** 를 보낸 뒤 행을 `UPDATE` 한다.
`appsettings.json:12-14` 기본값이 `localhost/hitpan_backoffice` 이므로, **그 DB 가 있는 PC·CI 에서는 시험이 외부 웹훅을 실제 발송하고 데이터를 갱신**할 수 있었다 — 작9 게이트가 지킨 「외부 실호출 0」 과 헌법 #39 를 깨는 모양.

봉합: `Factory.ConfigureWebHost` 에서 `AddInMemoryCollection` 으로 `ConnectionStrings:BackofficeDb`·`Default` 를
`Server=127.0.0.1;Port=1;Database=hitpan_w11_gate_nonexistent` 로 덮었다. **`appsettings*.json` 무접촉(#21).**
loopback `Port=1` 은 즉시 거절되므로 **나가는 패킷 0**, 틱은 `OpenAsync` 에서 끊겨 `SELECT`·`POST`·`UPDATE` 어디에도 닿지 못한다. 그 예외는 Dispatcher 의 `catch` 가 로그로 남긴다(#15).
덮개가 실제로 먹었는지는 **`G_W11_10` 이 돌아가는 앱의 `IConfiguration` 을 읽어 검산**한다 — 주석은 코드가 아니므로, 덮개가 빠지면 이 시험이 빨간불이 된다.
