### ⚠️ 보고 (지시 그대로 못 한 것 · 판단이 들어간 곳)
1. **신설 컬럼 이름 = `approved_at_dt`** — 작지는 "`approved_at` DATETIME 신설 + 기존 varchar 칸 병행 보존"인데, 같은 테이블에 같은 이름 컬럼 둘은 물리적으로 불가(#13 DESCRIBE 실측: `approved_at varchar(32)` 이미 존재). 두 요구를 모두 지키는 유일한 길이라 `_dt` 접미로 신설. 구조 변경 아님 — 추가 1컬럼.
2. **신규 행의 `approved_at_dt` 기록 경로 없음** — 기록 지점은 `TossPaymentsController` 인데 작지 §6 갈래 나 파일 목록 밖("판독 경로만")이라 **무접촉**. 현재는 ① 마이그 backfill 이 기존 행을 채우고 ② 신규 행은 varchar 폴백(종전 동작 그대로)으로 집계된다. Toss 기록부에 `approved_at_dt` 병행 기록을 넣으려면 **PM 재결재 필요**(파일이 갈래 분배 밖).
3. **월 축을 `COALESCE(approved_at_dt, approved_at, created_at)` 로 확장** — B-3-4(varchar 날짜 변환 실패 위험)가 이 DDL 의 존재 이유라, 신설 컬럼을 집계가 읽도록 맨 앞에 추가. `approved_at_dt` NULL 이면 종전과 바이트 동일 동작(무회귀). 과하다고 판정되면 이 COALESCE 첫 항만 빼면 된다.
4. **시각대**: backfill·varchar 는 토스 원문(KST) 앞 19자, `created_at` 은 UTC — 월 경계 최대 9시간 차는 **종전 varchar 경로에 이미 있던 성질** 그대로다(이번에 새로 만들지도, 고치지도 않음 — 고치는 건 범위 밖).
