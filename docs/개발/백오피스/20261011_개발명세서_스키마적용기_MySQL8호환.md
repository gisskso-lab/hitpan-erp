### §2-1 🔴 설계 도중 바뀐 것 두 가지 (게이트가 잡았다)

**① 토큰 벗기기를 「모양 열거」에서 「위치 기반」으로 바꿨다.**
처음 구현은 `ADD COLUMN IF NOT EXISTS` 처럼 **모양을 열거**하는 정규식이었다.
G-M8-5c(실물 14파일)가 바로 FAIL 했다 — `31` 번에 **실행되는** 문장이 하나 더 있었다:

```
ADD CONSTRAINT fk_landing_signups_tenant
    FOREIGN KEY IF NOT EXISTS (tenant_id) …
```

이름(`fk_…`)이 `CONSTRAINT` 와 `FOREIGN KEY` 사이에 끼어 열거형 정규식이 못 잡는다.
⇒ **MySQL 8 의 `ALTER` 에는 이 토큰이 설 자리가 아예 없다**는 사실을 근거로, 인용·주석 밖이면 전부 벗기는 방식으로 바꿨다.
🔴 이 한 건을 못 잡았으면 **봉합하고도 운영에서 31번에서 또 멈췄다.** PM 의 1차 전수조사(`^\s*(ALTER|ADD|…)` grep)는 **줄 머리가 `FOREIGN KEY` 인 이어진 줄**을 못 셌다.

**② 관용 오류코드에 1826 을 더했다.**
`31` 번 FK 는 `IF NOT EXISTS` 가 없다. 파일이 중간에 실패하면 이력에 안 남아 다음 기동이 처음부터 다시 돌리는데,
그때 FK 이름 중복(1826)에서 또 멈춰 **영영 안 열린다.** G-M8-3(이력 비우고 2회차) 설계가 이 덫을 드러냈다.
