## 1. 무엇을 만들었나

고객이 설치 실패 화면에서 보던 글자가 **`{\` 두 글자**였다. 원인은 **423 이 아니라 이중 포장 하나**다 —

**401·423·500·400 전부 같았고, 1차수 전부터 그랬다.**

- 대신 붙인 것: `.iss` 의 `JsonHexDigit`+`ExtractJsonString` 본문 **SHA-256 고정** · `.iss` 의 **실패 분기 세 줄(호출 함수·폴백 문장·MsgBox 식)을 읽어 dispatch** ⇒ `.iss` 만 고치고 시험을 안 고치면 **FAIL** 한다.

### 6-2 ⚠️ 하네스와 출하본의 **파일 인코딩이 다르다**

출하본은 `.ps1` 을 Inno `SaveStringToFile(…, False)` = **ANSI** 로 쓰고 고객 PC 의 ANSI=CP949 라 맞아떨어진다.
게이트는 **UTF-8 + BOM** 으로 쓴다(이 PC 임시 경로에 한글이 있어 ANSI 로는 깨진다 · §4-1).
⇒ **ANSI 경로 자체는 이 게이트가 재지 않는다.** 봉합이 ASCII 만 더했으므로 이 축의 위험은 낮다고 **판단**했을 뿐 **재지 않았다**.

### 8-1 🟢 실측 — 무엇이 깨져 있었나 (`&` 문제)

이 PC Windows PowerShell 5.1 에서 직접 쟀다:

```
[pscustomobject]@{ companyName = "히트판😀상사 & <주> 'x'" } | ConvertTo-Json -Compress
→ {"companyName":"히트판😀상사 \u0026 \u003c주\u003e \u0027x\u0027"}
```

- 🔴 **`& < > '` 넷만** `\uXXXX` 로 바뀐다. **한글은 안 바뀐다. 대리쌍(이모지)도 안 바뀐다.**
- 옛 `ExtractJsonValue` 는 `\uXXXX` 를 **못 푼다** ⇒ **상호에 `&` 가 든 고객은 지금까지 `\u0026` 으로 설치됐다.**
- 네 글자 전부 **코드값 < 256** 이라 새 함수의 `Chr(Code)` 범위 안이다 ⇒ **되돌아온다**.
- 🟢 **대리쌍은 escape 되지 않으므로 그대로 왕복한다**(게이트로 고정 — escape 되어 오는 날에는 복원 안 하고 원문 글자를 남긴다는 쪽으로 갈린다).

### 8-2 9개 이름 전수 전환 — 됐다

부트스트랩 추출 **8줄 + `message` 1줄 = 9개 전부** `ExtractJsonString` 으로 바꿨다.

- 🚫 옛 `ExtractJsonValue` **안 지웠다**(#1) — 쌍둥이 `CallLicenseClaimApi` 가 아직 쓴다.
- 🚫 쌍둥이(`signedProof`·`signedProofKid` 2곳 포함) **무접촉** — 요청 본문에 사업자번호가 있다.
- 🔴 **「성공 경로 무접촉」의 뜻을 분명히 한다**: **PS 호출·응답 기록 줄**(`$r = Invoke-RestMethod …` ~ `[System.IO.File]::WriteAllText(ResponseFile, $json …)`)은 **한 글자도 안 건드렸다.** 바뀐 것은 **그 뒤에서 값을 뽑는 함수 이름뿐**이다.

**게이트(G-T6-3 확장)**: 상호에 `& < > ' " \ 한글 공백` 을 전부 넣고 **9개 값을 바이트 단위로** 대조한다.
값은 **`.iss` 가 그 이름에 실제로 부르는 파서**로 뽑는다 ⇒ 호출 자리를 되돌리면 갈린다.
