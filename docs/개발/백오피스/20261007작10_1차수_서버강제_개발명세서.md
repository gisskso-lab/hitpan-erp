## §2 [동작 — 요청 한 건이 지나가는 길]

```
인증 안 됨 ───────────────────────────────→ 통과 (익명 입구는 이 필터 소관 아님 · [Authorize] 는 앞 미들웨어가 판정)
인증됨
 ├ sub 없음 ─────────────────────────────→ 403 (우리가 발급한 토큰이 아니다)
 ├ ⓞ 라이브 판독 (UNION ALL 1왕복 · 캐시 0)
 │    platform_admins(admin_id) ∪ bo_users(user_id) ∪ reseller_accounts(account_id)   ← 셋 다 PK 점 조회
 │    ├ 0건            → 403 「계정을 찾을 수 없습니다」
 │    ├ is_active=0    → 403 「계정이 비활성화되었습니다」          ← 즉시
 │    ├ 갈래·소속 불일치 → 403 「소속이 변경되었습니다. 다시 로그인해 주세요」 ← 즉시
 │    └ 유효역할 = 좁은 쪽(토큰, DB 중 낮은 등급)                  ← 하향 즉시 · 상향은 재로그인   ⚠️**정정 → §8**
 ├ ① 본사 갈래 ──────────────────────────→ 통과 (전건 조회가 정당 · [BoPermission]·Policy 가 뒤에서 판정)
 └ ① 대리점 갈래
      ├ [ResellerScoped] 없음 → 403 「대리점 계정은 이 기능을 사용할 수 없습니다」  ← 36엔드포인트가 여기서 닫힌다
      ├ 사다리 등급 부족     → 403 「이 기능은 대리점 관리자만 사용할 수 있습니다」
      └ 통과 → Items["bo.reseller_scope"] = DB 소속 → ② 가 resellerId 덮어씀 → ③ 이 @Rid 공급
```

판독 실패(예외)도 **403** 이다 — 통과로 바꾸지 않는다(fail-closed · #15 로그 남김).

### 4-1 내가 틀렸던 것 (기록)
1. 🔴 **G-2·G-3 봉합 전 재현을 처음에 잘못 짰다.** 필터만 떼고 재니 봉합 전에도 403 이었는데, 그것은
   **CSV 가 막은 403**(본문 「권한이 없습니다 (필요 권한: reseller_settlement.list)」)이고 필터의 증거가 아니다.
   선행검증 §2-3-c 가 적은 대로 봉합 전 유일 장벽은 CSV 하나였고, 그래서 설계 G-2·G-3 의 재현 절차에
   「CSV 에 대리점 역할 1회 추가」가 들어 있다. 그대로 맞춰 교정했다.
2. 🔴 **harness 가 401 로 전부 막혔다** — 실물 `IssueTokens` 는 환경변수 `HITPAN_BO_JWT_SECRET` 가
   `Jwt:Secret` 을 **이긴다**(`BackofficeAuthController.cs:162`). 검증이 설정값을 쓰면
   `401 invalid_token "The signature key was not found"`. 같은 우선순위로 맞췄다.
   이 PC 에는 그 환경변수가 실제로 있고 CI 에는 없다. **값은 어디에도 적지 않았다.**
3. 🔴 **맨손 `ApplicationBuilder` 파이프라인에는 `IHttpContextAccessor.HttpContext` 를 채우는 호스팅 계층이 없다**
   (운영에서는 `HostingApplication.CreateContext` 가 한다). 그래서 `IResellerScope` 가 null 을 보고
   컨트롤러가 `Forbid()` 를 냈다. 그 한 줄만 대역했다(가드·범위서비스·컨트롤러는 전부 실물).
4. MVC 엔드포인트 경로가 `DiagnosticSource`·`IActionContextAccessor` 를 요구한다(선례 `Pipeline.cs:142-143`).

### 8-3 교정④ — 조용한 초록 차단 (`DbGateEnvironment.SkipOrFailStrict`)
**사고 재현(PM 직접)**: 같은 `--filter`, DB 환경변수 0 ⇒ `Failed 0 / Passed 10 / Skipped 0 / **0.97초**`.
DB 를 물리면 **같은 글자**에 50초. `[SKIP]` 는 stderr 로만 나가 기본 출력에 **0건** ⇒ 판별 수단이 **소요시간 하나**였다.

🔴 **「Skipped 로 보이게」는 못 한다** — `xunit 2.9.3` 에 동적 skip 이 없다. v2 토큰(`$XunitDynamicSkip$`)은 이 러너에서 **Failed 로 집계된다**(실측 Failed 1 / Skipped 0). 글자로 믿지 않고 재서 가렸다.
⇒ 채택: **선언 없으면 빨간불.**

| 모드 | 환경 | 실측 |
|---|---|---|
| ① | DB 없음 · 선언 없음 | 🔴 **Failed 11 / Passed 2** (사유에 복구 방법 3줄) |
| ② | DB 없음 · `HITPAN_GATE_SKIP_OK=1` | 🟢 13/13 · 0.56초 — ⚠️**정정 → §8-5**: `[SKIP]` 는 **로컬 기본 출력에 안 보인다**(stderr · 실측 0건). CI `build` 잡(`--verbosity normal`)에서는 보인다(346건) |
| ③ | DB 있음(`hitpan_trgtest`) | 🟢 13/13 · **23초** |

- 종전 `SkipOrFail` **호출 101곳은 한 줄도 안 바꿨다**(#1) — 전환은 2차수. G-10 ⓔ 가 그 사실을 **음성 대조군**으로 들고 있다.
