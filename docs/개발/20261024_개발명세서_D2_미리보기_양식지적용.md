## 3. ② 정본 통로 — 조건 1 을 어떻게 지켰나

```
4인자 RenderDocumentAsync(tenantId, type, id, ct)        ← 기존 호출부 전부. 한 글자도 안 고쳤다
    └─> 5인자 RenderDocumentAsync(…, overrides: null, ct) ← 같은 몸통
```

- 인터페이스의 5인자는 **기본 구현**(4인자로 되돌림)이라, 시험 `StubPdf` 가 **안 고쳐도 컴파일된다**
- 실서비스만 재정의한다 ⇒ **그 재정의를 빼면 미리보기가 저장값으로 떨어진다**(조건 3 의 자리)
- 🔴 **미리보기 전용 작성기 0개.** 양식 매핑도 `ToTemplateInfo` **한 벌**로 모았다 — 두 벌이 되면 미리보기와 인쇄물이 조용히 어긋난다(20261021작 §11-3 이 닫던 바로 그 사고)

## 6. ⑤ 🔴 **멈췄다 — 내 적발이 거짓이었다**

진실원 D-3 에 *"세금계산서 전용 작성기에 로고·테두리 미전달"* 을 결함으로 적었다. **틀렸다.**

| | |
|---|---|
| 내가 쟀던 방법 | **글자** — 작성기 서명에 `showHeader`·`showBorder` 인자가 없다 |
| 구현하려고 열어 보니 | 🔴 머리·격자가 **법정 서식**(부가가치세법 시행규칙). 「세 금 계 산 서」 제목 + 공급자/공급받는자 2단 대칭 격자 · `.Border(1.2f)` 는 **법정 칸선**. **로고 붙일 자리가 없다** |
| 판정 | 🟢 **전달하지 않는 것이 맞다.** 고객이 테두리를 끄면 법정 서식이 깨진다 |

🔴 그대로 집행했으면 세금계산서가 법정 서식에서 벗어났다. **적발이 그럴듯해서 더 위험했다.** 진짜 구멍 네 칸(`paper_size`·`orientation`·`show_company_seal`·`background_image_url`)과 **같은 표에 섞어 적은 것이 잘못**이다. 진실원 **D-5** 에 교정하고 *"이 두 줄을 고치지 마라 · 법무팀장 결재가 먼저다"* 로 남겼다.
