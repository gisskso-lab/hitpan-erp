## 7. 검증팀에 요청 (자기 판단 아님)

- 🔴 **가장 위험하다고 스스로 보는 곳** — D-2 가 만든 **잔여 세션 행**. 새 세션 INSERT 가 refresh_tokens 회전
  **앞**으로 갔으므로, 회전이 `deleted == 0`(동시 갱신 2발) 으로 401 이 되면 `pc` 세션 행 1개가 만료까지 남는다.
  축 B 가 **켜진** 테넌트에서 그 사용자가 곧바로 재로그인하면 **자기 잔여 행 때문에 409** 를 볼 수 있다.
  ⚠️ 로그인 경로도 같은 모양(INSERT 뒤 refresh_tokens 쓰기 실패)이라 선례와 같은 형태를 유지했다 —
  **구조를 바꾸는 것은 새 결정이라 하지 않았다.** 이 교환이 받아들일 만한지 판정해 달라.
- 🔴 **401 문장 재사용** — 갱신 거절 메시지를 절C 와 **한 글자 같게** 썼다(`:610`·`:400`). 화면이 두 경우를
  구분해야 한다면 여기서 갈라야 한다. 지금은 사용자에게 같은 일로 보인다는 판단이다.
- ⚠️ **회귀 우려** — 옛 토큰(`sid` 없음) 갱신이 이제 축 B 판정을 거친다 ⇒ **킬스위치 ON** 테넌트에서
  *"두 PC 가 옛 토큰으로 조용히 공존"* 하던 상태가 갱신 시점에 401 로 드러난다. 의도한 변화지만,
  출하 기본값이 OFF 라 고객에게는 아직 닿지 않는다는 전제에 의존한다(갈래C1 §DB-128).
- ⚠️ **모바일 무영향 확인 요청** — `EnforceSinglePcLoginAsync` 첫 줄이 `deviceKind != "pc"` 면 즉시 반환하므로
  모바일 갱신은 종전과 같다(9/25 결재 모바일 FREE). 실측은 못 했다.
