# 작업 루틴 (사장님 원칙 확정 2026-07-28)

> # 🔴 대원칙
> ## **모든 작업 루틴은 문서로 남긴다.**
> ## **그 문서를 근거로 작업한다.**
>
> — 사장님 확정 2026-07-28
>
> 문서는 작업의 **부산물이 아니라 근거**다.
> **문서 없는 작업 = 근거 없는 작업 = 즉시 중단.**
> 기억으로 일하지 않는다. 대화로만 합의한 것은 작업 근거가 되지 못한다.

---

## 0. 왜 이 원칙인가 (실측 근거)

| 문서 없이 일했을 때 실제로 난 사고 | 결과 |
|---|---|
| 헌법 #37·#38 | AI가 `reseller_id` 를 "잔재"로 반복 오판 → 사장님이 헌법에 못박음 |
| 헌법 #39 | demo 환경 즉석 수술 → "고치려다 더 망가지고 그걸 또 고치는" 두더지잡기 |
| 헌법 #33 | 의중 확인 없이 코드 → PricingPage 누락·ResellerSidebar 작동불가 |
| 2026-07-28 조직 정의 | PM이 "정의가 없다"고 판단해 이력을 **임의로 지어냄** |

**공통점**: 근거 문서 없이 기억·감으로 판단했다. 그래서 이 원칙이다.

## 1. 작업 사이클 (사장님 확정 2026-07-28 — 5단계)

```
[1] 사장 오더
      ↓
[2] 설계팀 — 설계팀장 존
    · 설계문서 작성                    → 📄 설계/{영역}/
    · 작업지시서(PRD) 작성             → 📄 운영기록/
    · → 개발팀에 넘김
    · → PM 결재 OR 반려                → 📄 운영기록/ (결재의견)
      ↓  ⛔ 결재 없으면 코드 금지
[3] 개발팀 — PM(개발팀장) 지휘        ⟷  [3-V] 동시 병렬검증 — 안철수 상무
    · 역할분배 (매니저·서브에이전트)        · 작업과 **동시**에 실시간 반증
    · 코딩                                   · 적발 즉시 반려·재작업
    · 개발명세서 작성                  → 📄 개발/{영역}/
                                            → 📄 검증/병렬이슈/  ⭐별도 폴더
      ↓
[4] 검증팀 — 검증팀장 데이비드 박
    · 개발명세서 검토 + 코드리뷰
    · 최종 결재 OR 반려
    · 작업리뷰서 작성                  → 📄 검증/{영역}/
      ↓
[5] 최종 결재
    · CTO 래리 결재                    → 📄 운영기록/ (CTO 결재의견)
    · 사장님 최종 결재                 → 📄 (작업지시서에 결재 상태 기록)
      ↓
[★] 인수인계서                         → 📄 운영기록/  ← 세션·컨텍스트 만료 전 필수
```

**각 단계에 📄가 붙어 있다 = 그 단계는 문서를 남긴다.**
문서가 없으면 그 단계는 **하지 않은 것**이다. (헌법 #42)

### 역할 (사장님 확정)

| 단계 | 누가 | 무엇 |
|---|---|---|
| [2] 작성 | **설계팀장 존** | 설계문서 + 작업지시서(PRD) |
| [2] 결재 | **PM 브라운킴** | 결재 OR 반려 — 작성자와 다른 사람(SoD) |
| [3] 지휘 | **PM(개발팀장)** | 역할분배·코딩·개발명세서 |
| [3-V] 병렬검증 | **안철수 상무** | 작업과 동시에 반증. 이슈는 `검증/병렬이슈/` 별도 관리 |
| [4] 검증 | **검증팀장 데이비드 박** | 개발명세서 + 코드리뷰 → 작업리뷰서 |
| [5] 최종 | **CTO 래리 → 사장님** | 팀 최종 결재권은 임원이 갖는다 |

### 산출 문서 3종 (이 루틴의 핵심)

| 문서 | 누가 | 어디에 | 틀 |
|---|---|---|---|
| **작업지시서(PRD)** | 설계팀장 | `운영기록/` | [`_틀/작업지시서_틀.md`](_틀/작업지시서_틀.md) |
| **개발명세서** | 개발팀(PM 지휘) | `개발/{영역}/` | [`_틀/개발명세서_틀.md`](_틀/개발명세서_틀.md) |
| **작업리뷰서** | 검증팀 | `검증/{영역}/` | [`_틀/작업리뷰서_틀.md`](_틀/작업리뷰서_틀.md) |

## 2. 불변 규칙

| # | 규칙 | 왜 |
|---|---|---|
| 1 | **봉합 즉석 금지** | [2] PM 결재 없이 코드 손대지 않는다 (헌법 #29·#33·#39·#42) |
| 2 | **작성자 ≠ 결재자** | 설계팀장이 쓰고 **PM이 결재**한다. 자기가 쓴 걸 자기가 결재하지 않는다 |
| 3 | **병렬검증 동시 진행** | [3] 작업과 [3-V] 안철수 상무 검증이 **동시**에 돈다. 끝나고 하는 게 아니다 |
| 4 | **SoD** | 만든 사람 ≠ 검증하는 사람. 자기검증은 거짓봉합을 통과시킨다 |
| 5 | **병렬이슈 별도 관리** | [3-V] 적발 건은 `검증/병렬이슈/` 에. 최종 검증보고서에 묻히면 추적 불가 |
| 6 | **최종 결재는 임원** | [5] CTO → 사장님. 팀 내부에서 끝내지 않는다 |
| 7 | **매 단계 기록** | 기록 없으면 받아쓰기·거짓봉합이 끼어든다 (헌법 #42) |
| 8 | **인수인계서 필수** | 우리 개발 자체의 워크플로우 끊김 0 (헌법 #20을 개발 프로세스에 적용) |

## 3. 문서 작성 루틴 (매번 이 순서)

```
① 무슨 문서인지 판정   → docs/CATEGORIES.md 판정 순서 ①~⑥
② 틀을 연다            → docs/_틀/  해당 틀
③ 사장님께 결재         → "{위치}에 {문서명} 저장하고 진행합니다 — {한줄요약}. 진행할까요?"
                          ⭐ 작업 단위로 묶어 1번 (문서마다 매번 아님)
④ 참조식으로 쓴다      → 다른 문서 내용 복사 금지, 주소만
⑤ 저장 후 3가지         → 폴더 INDEX 한 줄 추가
                        → 대체한 옛 문서 ⬛흡수 표시
                        → (인수인계서면) START_HERE §0-1 진실원 주소 갱신
```

## 4. 세션 루틴

### 세션 시작
```
1. docs/START_HERE.md 를 읽는다        ← 이거 하나면 지형 파악
2. §0-1 🟢진실원 인수인계서 1개를 연다  ← 지금 뭘 하고 있었나
3. §9 "다음 세션 첫 행동" 대로 시작
```

### 작업 중
```
· 코드 고치기 전 → START_HERE §2 판단 트리거에서 헌법 확인
· 🚨 #29·#33·#37·#39·#40 에 걸리면 → 원문 필독 (요약 신뢰 금지)
· 문서 만들기 전 → CATEGORIES.md 판정 + 저장 위치 결재
```

### 세션 끝 (컨텍스트 만료 전)
```
1. 인수인계서 작성 (docs/_틀/인수인계서_틀.md)
2. START_HERE §0-1 진실원 주소 갱신
3. 운영기록 INDEX 🟢진실원 절 갱신 + 옛 문서 ⬛흡수
4. 미커밋 0 확인
```

## 5. 코드 작업 루틴

```
작업지시서(PRD) 없음        → 코드 금지. [2] 설계팀으로 돌아간다.
작업지시서 있으나 PM 미결재 → 코드 금지. 결재부터 받는다.
PM 결재 완료               → 아래 순서로 진행
  ① 헌법 체크 (작업지시서 §3에 이미 적혀 있어야 함)
  ② 새 SQL 이면 DESCRIBE 먼저 (헌법 #13)
  ③ 새 테이블·컬럼이면 clean DDL 편입 (헌법 #36)
  ④ 인터페이스 확장이면 구현체 전수 grep (헌법 #12)
  ⑤ 구현 — 기존 코드 추가만, 덮어쓰기 금지 (헌법 #1)
  ⑥ 빌드 errors 0 + warnings 0 (헌법 #19)
  ⑦ 개발명세서 작성 → 개발/{영역}/
  ⑧ [4] 검증팀 코드리뷰 통과 → [5] CTO·사장님 결재
     ※ [3-V] 안철수 상무 병렬검증은 ①~⑦ 내내 동시에 돌고 있다
```

## 6. 이 원칙을 어겼을 때

| 상황 | 조치 |
|---|---|
| 문서 없이 코드부터 나옴 | **즉시 중단.** [2] 작업지시서(PRD)부터 만든다 |
| PM 결재 없이 코딩 시작 | **즉시 중단.** [2] 결재 벽을 우회한 것 |
| "대화에서 합의했으니 됐다" | 대화는 근거가 아니다. 문서로 남긴다 (헌법 #42) |
| "급하니까 나중에 문서" | 그게 두더지잡기의 시작이다 (헌법 #39 사고 원인) |
| 병렬검증을 작업 후로 미룸 | [3-V]는 **동시**다. 끝나고 하면 거짓봉합을 못 잡는다 |
| 병렬이슈를 최종보고서에만 기록 | `검증/병렬이슈/` 에 별도로 남긴다. 묻히면 추적 불가 |
| 검증 없이 "됐다" 보고 | [4] 미통과 = [5] 결재 요청 불가 |
| 팀 내부에서 결재 종결 | 최종 결재는 CTO → 사장님. 임원 결재 없이 완료 아님 |
