## 1. 배경

작14 `sensitive_access_log` 어플 3중 강제(Decorator+ActionFilter+Roslyn) 도입 후에도 **DBA root SQL 직접 우회** 잔존 리스크 존재 (SENSITIVE_ACCESS_LOG_DDL.md §6 T5).

MariaDB Audit Plugin은 DB 레벨에서 모든 쿼리 로깅 → root 우회도 추적 가능. 단 성능 오버헤드 5~10%.

## 2. 선택지

### A안: 베타 출시(7/15) 전 도입
- 장점: 출시 시점부터 완벽 감사. 법령 §29 안전성 확보조치 만점
- 단점: 베타 D-63 일정 부담. 성능 측정·튜닝 별도 작업

### B안: 베타 출시 후 Phase 2 도입 (PM 추천)
- 장점: 베타 일정 영향 0. 베타 운영 데이터로 성능 튜닝 가능
- 단점: 베타 기간(7/15~9/30 가정) 동안 root 우회 미감사

### C안: 영구 미도입 (어플 3중 강제만)
- 장점: 성능 100%. 운영 단순
- 단점: 법령 §29 권고 미충족. 정식 출시 시 행정처분 리스크

## 3. 어벤져스 리뷰

| 매니저 | 의견 | 추천 |
|---|---|---|
| 보안 매니저 | 베타 기간 root 우회는 본사 직원 1~2명 + 베타 체험단 20곳 → 리스크 통제 가능 | **B안** |
| DB 매니저 | 베타 데이터로 성능 5~10% 검증 후 튜닝 결정이 합리 | **B안** |
| 법무팀장 | 베타는 시범 운영 → 정식 출시 전까지 도입 명문화하면 법령 충족 | **B안 + 정식출시전** |
| 본부장 춘식 | 베타 D-63에 추가 작업 무리. 정식 9/30 가정 시 8월 도입 가능 | **B안** |
| 본인(PM) | 3중 강제 + DBA root는 본사 1명만 → 사람 통제로 베타 충분 | **B안** |

**전원 B안 추천.**
