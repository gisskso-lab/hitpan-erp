## 3. 선택지

### A안: NULL 처리 (DB 매니저 추천)
- `keyman_name == partner_name` 이면 NULL 적재
- 장점: 데이터 무결성. 진짜 키맨 없음을 정확히 표현
- 단점: ERP 화면에서 "키맨 미지정" 거래처가 폭증 → 영업 매니저 불편

### B안: placeholder "(미입력)" (ERP 매니저 추천)
- `keyman_name == partner_name` 이면 `"(미입력)"` 문자열 적재
- 장점: 현장 직원이 "키맨 미입력"임을 한눈에 인식. ERP 운영 친화
- 단점: 진짜 키맨 이름이 우연히 "(미입력)" 글자와 충돌 가능 (실무상 0%)

### C안: 원본 보존 + 플래그 컬럼 추가
- `keyman_name`은 원본 그대로, `keyman_name_inferred BOOLEAN` 추가
- 장점: 정보 손실 0
- 단점: 컬럼 신설 (ALTER 추가) + 화면 로직 분기 부담
