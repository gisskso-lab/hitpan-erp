# 틀 — 검증보고서 (PM 정의)

> **쓰는 때**: SOP [7-V] 검증팀이 작업과 **동시에** 검증할 때. 작업이 끝난 뒤가 아니다.
> **저장 위치**: `docs/검증/erp/` — 저장 위치는 사장님 결재(헌법 #41).
> **파일명**: `{YYYYMMDD}_검증_{대상}_{판정}.md`
>
> ## 🔒 SoD 절대 원칙 — 만든 사람 ≠ 검증하는 사람
> 구현한 에이전트가 자기 작업을 검증하면 **거짓봉합**이 통과한다. 검증팀은 독립이어야 한다.
> 검증의 목적은 "됐다"를 확인하는 게 아니라 **"안 되는 경우를 찾는 것"**이다.

```markdown
# 검증보고서 {YYYY-MM-DD} — {검증 대상}

| 항목 | 내용 |
|---|---|
| 검증 대상 | {작업지시서 번호 / 커밋 해시} |
| 구현자 | {누가 만들었나} |
| 검증자 | {누가 검증하나 — 구현자와 달라야 함} |
| 판정 | ✅통과 / ⚠️조건부 / ❌반려 |

## 1. 3관문 (전부 통과해야 함)
| 관문 | 결과 | 근거 |
|---|---|---|
| 빌드 errors 0 + warnings 0 (헌법 #19) | ⬜ | {실제 출력} |
| ddl-smoke (DDL 변경 시, 헌법 #36) | ⬜ | {실제 출력} |
| 독립 반증 | ⬜ | 아래 §2 |

## 2. 독립 반증 — "안 되는 경우"를 찾았나
> 통과를 확인하는 게 아니라 **깨뜨리려고** 시도한 기록.

| 시도한 공격 | 결과 | 판정 |
|---|---|---|
| {정상 경로 말고 이렇게 하면?} | | |
| {빈 값·경계값·중복 실행하면?} | | |
| {권한 없는 계정으로 하면?} | | |

## 3. 적발 사항
| # | 등급 | 내용 | 재현 방법 | 봉합 여부 |
|---|---|---|---|---|
| 1 | P0/P1/P2 | | | ⬜ |

**P0 = 워크플로우 차단·데이터 손상·보안 (헌법 #20·#18·#22 위반) → 즉시 반려**

## 4. 거짓봉합 점검
> "고쳤다"고 한 것이 실제로 고쳐졌나. **코드가 아니라 동작으로 확인한다.**
- [ ] 봉합 전 증상을 재현해봤나 → 이제 안 나는가
- [ ] 봉합이 다른 곳을 깨뜨리지 않았나 (회귀)
- [ ] 문서에만 고쳤다고 쓰고 코드는 안 고친 것 아닌가

## 5. 판정 근거
- ✅통과: 3관문 전부 + 적발 P0 0건
- ⚠️조건부: {무엇을 하면 통과인지}
- ❌반려: {무엇 때문에 반려인지}
```

## PM 검증 지침 (이 틀을 쓰는 사람에게)

1. **"확인했습니다"는 검증이 아니다.** 어떤 명령을 쳤고 무엇이 출력됐는지 붙여라.
2. **개발 PC에서 됐다 = 검증 아님.** 사장님 못박음 — 백지 환경(Sandbox)·실제 경로에서 봐야 한다.
3. **깨뜨리려고 해라.** §2에 시도가 3개 미만이면 그 검증은 부실하다.
4. **P0는 무조건 반려다.** "일단 넘기고 나중에"가 두더지잡기의 시작이다.
5. **검증 통과 못 한 봉합은 PM 종합보고(SOP [9])에 올리지 않는다.**
