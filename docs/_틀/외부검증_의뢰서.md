# 틀 — 외부검증 의뢰서 / 지적서

> **저장**: 의뢰서·지적서 모두 `docs/검증/외부/` | **파일명**: `{YYYYMMDD}_외부검증의뢰_{범위}.md` · `{YYYYMMDD}_외부지적서_{범위}.md`
> **규범**: [`docs/헌법/외부독립검증팀_운영지침.md`](../헌법/외부독립검증팀_운영지침.md) — 이 틀은 그 지침의 §6~§13 을 **채우는 양식**이다.
> **참조식** — 다른 문서에 있는 내용은 **주소만** 적는다.
>
> 🔴 **의뢰서를 쓰기 전 확인 3가지**
> 1. 기준 SHA 를 **다시** 확인했나 (GitHub API 가 옛 SHA 를 보고한 전례 — 10/11)
> 2. **미커밋·미푸시 변경은 GPT 에게 존재하지 않는다**
> 3. **게시 통제**(지침 §9) — 미결 런 전수 확인·판정부터

---

## 1. 의뢰서 양식

```markdown
# 외부검증 의뢰 — {범위}

| 항목 | 내용 |
|---|---|
| 발행 시각 | {YYYY-MM-DD HH:MM} ← 🔴 **③ 고유 탐지 판정의 기준 시각** |
| 기준 SHA | `{sha}` (브랜치 `{branch}`) |
| 🔴 **SHA 고정 링크** | `github.com/gisskso-lab/hitpan-erp/blob/{sha}/{경로}` ← **`blob/main/…` 을 쓰지 않는다**(내용이 나중에 바뀌어 검토 근거가 재현되지 않는다) |
| 변경 범위 | 코드 {n}칸 · 화면 {n} · 마이그 {n} · 일정표 칸 {n} |
| 라운드 | 1 / 1 (상한 = 초안 1회 → GPT 1회 → 사장님 판정) |
| 게시 통제 | 미결 런 전수 확인 ⬜ · 각 런 실행·취소·보류 판정 ⬜ |

## 입력물 5종 (지침 §7 · 각 항목에 출처·기준시각·확인상태)

### ① 변경 범위
| 파일:줄 | 무엇을 바꿨나 |
|---|---|

### ② 사장님 실측 완료 항목 (정본 증거)
> 5단계 경로 = 지침 §8. **어디까지 돌았는지** 적는다.
| 단계 | 실측 | 결과 |
|---|---|---|
| 1 랜딩가입·시리얼 | ⬜ | |
| 2 도메인 생성 | ⬜ | |
| 3 설치마법사·부모계정 | ⬜ | |
| 4 ERP 접속 | ⬜ | |
| 5 CICD → ERP 업데이트 | ⬜ | |

### ③ CI/CD 검증 범위
| 워크플로 | PASS | FAIL | **SKIP** | 미실행 | 전체 대상 |
|---|---|---|---|---|---|
> 🔴 **SKIP 수 미기재 = 미측정.** 8/28 에 DB 게이트 101곳이 조용히 SKIP 했다.

### ④ 🔴 우리가 이미 식별한 미검증 항목 — **이 칸이 핵심이다**
> 커밋 `못 쟀다` 칸을 그대로 옮긴다. 칸이 없으면 **PM 이 새로 쓴다**(최근 300커밋 중 25건뿐).
| # | 못 쟀다 | 왜 못 쟀나 |
|---|---|---|

### ⑤ 미검증 가설 (⚠️ 표시 의무)
| 문서·줄 | 적혀 있는 「원인은 ~다」 | 실측 여부 |
|---|---|---|
> 🔴 문서의 「원인은 ~다」가 다음 사람에게는 사실이 된다. **가설은 가설로 넘긴다.**

### 전제 출처 (지침 §8)
| 전제 | 출처 | 수신 | 기준시각 | 확인상태 |
|---|---|---|---|---|
| | 사장님 구두 / 문서 | GPT만 / Claude만 / 양측 | | 🟢확정 / ⚠️미확인 |

## 추적 요청 (지침 §13 · 축을 고른다)
| 축 | 요청 | GPT 가 낼 증거 | 우리가 낼 증거 |
|---|---|---|---|
| 1 워크플로우 전파 | ⬜ | 호출부·화면·API 파일:줄 | 화면 실동작 |
| 2 핵심 업무 흐름 | ⬜ | 끊길 지점 + 조건 | DB 전후 값 |
| 3 원장·회계 | ⬜ | #3·#6 위반 의심 경로 | 원장 행·차대변·역분개 |
| 4 3시스템 경계 | ⬜ | 페이로드·DTO 필드 | 전송 로그 |
| 5 반사·동적 호출 | ⬜ | `Invoke`·리플렉션 grep | 회귀 PASS/SKIP |
> 사고 유형 3종(⑤거짓초록·⑥마이그·출하DDL·⑦테넌트격리)은 **별도 분류**로 함께 요청.

## 요청하지 않는 것
- 🔴 **기존 실측·CI/CD 중복 실행 금지.** 위 ②③ 이 덮는 범위는 다시 짚지 않는다
- 🔴 **추가 실측을 자동 실행 금지** — 필요하면 목적·합격 기준·예상 자원·일정 영향을 제시해 **사장님 결정**을 받는다
```

## 2. 지적서 양식 (GPT 보고 → PM 대응)

```markdown
# 외부 지적서 — {범위} / 대응

| 의뢰 기준시각 | {} | 라운드 | 1/1 |

## 지적 목록
| # | 지적 | 잠재 심각도 | 원인 축 | 증거 상태 | 내부 판정 | PM 대응 |
|---|---|---|---|---|---|---|
| 1 | | P0/P1/P2 | 보안·테넌트 / 데이터 무결성 / 워크플로우 / 회계 정합 | 확인된 규칙 위반 / 정적 검토상 위험 / 미검증 / 반박 근거 확인 | **미확정** | 수용 / 반박 / 추가검증 |

> 🔴 **「정적 검토상 위험 P0」는 반려가 아니다** — 확인 우선순위 1위다 (지침 §5).
> 🔴 반려는 **「확인된 결함·확인된 규칙 위반」에서만.** 단 **사장님 긴급 브레이크는 이 순서를 안 탄다.**

## 🔴 GPT 가 못 낸 증거 (칸이 비면 미측정)
| # | 필요한 증거 | 왜 못 냈나 | 누가 내야 하나 |
|---|---|---|---|

## PM 반박 근거
| # | 근거 파일:줄 | 무엇을 반증하나 | 반박 범위 |
|---|---|---|---|
> 🔴 **반박도 판정이 아니다.** 채택은 [5]. 「모든 환경에서 문제없다」로 확대 금지.

## ②-b 중복 판정 (지침 §6 · PM 단독 확정 금지)
| # | 테스트명 | 실행 경로 | 검증 대상 | 결과 판정 | PASS/SKIP |
|---|---|---|---|---|---|
> 🔴 **SKIP 은 중복 근거가 아니다.** 경로를 실제로 실행하고 판정하는지 보여야 중복.

## 미해결 쟁점 (추가 라운드 대신 기록)
| # | 쟁점 | 양측 근거 | 상태 |
|---|---|---|---|
| | | Claude: / GPT: | 사장님 판정 대기 |

## 측정 반영
→ [`docs/운영기록/외부검증_측정장부.md`](../운영기록/외부검증_측정장부.md) 에 ①②②-b③④-1④-2⑤ 기록
```

## 3. 🚫 쓰면 반려되는 것

| 금지 | 왜 |
|---|---|
| **SKIP 수 없는 시험 결과** | 미측정으로 처리 (8/28 101곳 SKIP) |
| **범위·개수 단정** (「~뿐」·「전부」·「N건이 전부」) | 10/26 하루에 PM 이 네 번 틀렸다. 못 세면 **「미측정」** |
| **합의를 「닫힘」으로 표기** | 양측 합의 ≠ 사장님 승인 (지침 §0) |
| **개발 PC 결과를 「확인된 결함」으로** | 회귀 2,692 초록인데 브라우저에 도달 못 한 전례 |
| **전제를 양쪽 설명 합쳐서 확정** | 10/26 에 양측 다 틀렸다. ⚠️미확인으로 두고 **사장님께 여쭌다** |
| **원문·사장님 문구 요약·재서술** | 압축이 사실을 바꾼다. **순서·단계 수 건드리지 마라** |
| **헌법 예외를 임의 적용** | 🔴 **예외는 반드시 사장님 보고.** 예외조항은 줄여나간다 (지침 §10) |
| **라운드 추가 개설** | 상한 = 1회. 추가는 사장님 지시로만 |
