# 문서 분류 규칙 (사장님 확정 2026-07-28)

> **이 문서가 분류의 근거다.** 새 문서를 만들 때 여기서 카테고리를 찾고, 사장님께 저장 위치를 결재받는다.
> 감으로 고르지 않는다 — 아래 판정 순서를 기계적으로 따른다. (헌법 #41)
>
> 근거: 2026-07-28 실제로 635건을 분류하며 부딪힌 판단 지점에서 도출. 추측 아님.

---

## 0. 판정 순서 (위에서부터 순서대로 — 처음 걸리는 데서 멈춘다)

```
① 이 문서가 "결재를 받으려고" 만드는 것인가?        → 운영기록/
② 이 문서가 "잘못된 걸 찾으려고" 만드는 것인가?      → 검증/
③ 이 문서가 "어떻게 만들지 정하는" 것인가?          → 설계/
④ 이 문서가 "어떻게 만들었는지 남기는" 것인가?      → 개발/
⑤ 이 문서를 고객이 읽는가?                        → CS/
⑥ 이 문서가 우리 팀의 규범인가?                    → 헌법/
```

**한 문서가 둘 이상에 걸리면 ①→⑥ 순서에서 먼저 걸리는 쪽**이다.
그래도 애매하면 **사장님께 여쭙는다** (헌법 #33).

## 1. 카테고리 정의 (무엇이 여기 속하나)

### 운영기록/ — 결재·기록·이력
> 담당: CTO 래리 · PM 브라운킴 · AI수석

| 속하는 것 | 예 |
|---|---|
| **작업지시서** (⭐가장 많음) | `20260724작3_UPDATE자동화_17구멍봉합_구현작업지시서.md` |
| 인수인계서 | `20260728_인수인계서_자동배포완주_참조식.md` |
| 결재 의견·승인 이력 | `20260722_CTO결재의견_20260722작1.md` |
| 회의록 | `20260424_avengers_meeting.md` |
| PM 스케줄표·종합보고 | `20260723밤_PM작업스케줄표_….md` |
| 사장님 실행 매뉴얼 | `20260724_트랙2_사장님_복붙매뉴얼_….md` |
| **약관·SLA·법무** | `약관_v2.0.0_SLA_99_99_추가조항.md` |
| 운영 체크리스트 | `DEPLOY_CHECKLIST_….md` |

> **⭐ 작업지시서는 처음부터 여기에 만든다** (사장님 확정 2026-07-28).
> 결재받으려고 만드는 문서이므로 개발/ 에 뒀다가 옮기지 않는다 — 옮기면 링크가 깨진다.
> **약관·헌장은 개발 헌법이 아니다** → 헌법/ 아니라 여기다 (사장님 판정).

### 검증/ — 잘못된 걸 찾는 것 (= 리뷰어)
> 담당: 검증팀장 데이비드 박 · 검증팀 · 법무팀장 김앤장 · 보안상무 안철수
> **SoD: 만든 사람은 이 폴더의 담당이 아니다.**

| 속하는 것 | 예 |
|---|---|
| 검증보고서 (SOP [7-V]) | `20260724작2_2대시나리오_검증게이트_….md` |
| **감사** (= 검증과 같은 의미) | `20260514_code_audit/…` |
| 전수조사 | `20260702_3시스템정합_전수조사완료_….md` |
| 테스트 시나리오·결과 | `UNIT_TEST_SCENARIOS.md` · `W1_GATE_RESULT.md` |
| 갭 분석·반증 | `W3_D1_GAP_ANALYSIS.md` |
| 보안 점검 (DAST·SAST) | `DAST_FINDINGS_TEMPLATE.md` |

> **"감사와 검증은 같은 의미"** (사장님 판정 2026-07-28). audit 폴더를 따로 두지 않는다.

### 설계/ — 어떻게 만들지 정하는 것
> 담당: 설계팀장 존(=풀스택 매니저) · PM · CTO 래리

| 속하는 것 | 예 |
|---|---|
| PRD·요구사항 | `PRD_ERP.md` · `PRD_LANDING.md` |
| ERD·스키마 설계 | `ERD_INTEGRATED.md` · `INFRA_DDL_SPEC.md` |
| 아키텍처 | `THREE_SYSTEM_ARCHITECTURE.md` |
| **명세(SPEC)·계획(PLAN)** | `VALUE_CONVERTER_SPEC.md` · `MIGRATION_MASTER_PLAN.md` |
| 매핑 정의 | `MDB_FULL_MAPPING.md` |
| 기술 조사 | `INFRA-FREE-OPTIONS-….md` |

> ⚠️ **SPEC·PLAN·DDL 은 "작업"이 아니라 "설계"다.** 2026-07-28 migration 폴더 분류 때
> "작업된 마이그는 개발"이라는 지침에도 불구하고 13건이 설계로 간 이유가 이것이다.

### 개발/ — 어떻게 만들었는지 남기는 것 (= 디벨롭)
> 담당: 개발팀 (DB · 풀스택 존 · 프론트 · 백엔드 · 보안 매니저)

| 속하는 것 | 예 |
|---|---|
| 구현 기록·봉합 결과 | 진범 규명·P0 봉합 보고 |
| 설치·배포 실행 절차 | `CLOUDFLARE-SETUP-GUIDE.md` · `ENV_SECRETS.md` |

| 마이그레이션 실행분 | 실제 돌린 기록 |

> 작업**지시**서는 운영기록/ 이고, 그 지시로 **만든 결과**가 개발/ 이다.

### CS/ — 고객이 읽는 것
> 담당: CS팀장 강지원 · 기술영업팀장 · ERP매니저 · 마케팅팀장

| 속하는 것 | 예 |

### 헌법/ — 우리 팀의 규범

## 4. 저장 시 의무 (헌법 #41)

문서를 만들 때 **한 번에** 다음을 한다:

1. **저장 위치를 사장님께 결재받는다** — 작업 단위로 묶어 1번
   > *"{위치}에 {문서명} 저장하고 진행합니다 — {한줄요약}. 진행할까요?"*
2. **틀을 쓴다** → [`_틀/`](_틀/)
3. **참조식으로 쓴다** — 다른 문서 내용 복사 금지, 주소만
4. **폴더 INDEX 에 한 줄 추가**
5. **대체한 옛 문서에 ⬛흡수 표시** ← 이걸 안 하면 문서가 다시 쌓인다
