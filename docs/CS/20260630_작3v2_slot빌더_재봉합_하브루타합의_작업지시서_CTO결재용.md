## 2. 재봉합 항목 (하브루타 합의표)

| ID | 구멍 | 합의 판정 | 정공법 |
|---|---|---|---|

## 3. 봉합안 (구현은 결재 후)

### R1 봉합 — db.conf 경로 화이트리스트 (정규식 폐기)
**현재**(Build-TestSlot.ps1:387):
```powershell
if ($DbConfPath -match '(?i)Program Files\\HitPan') { Abort ... }
```
**봉합** — "$TestRoot 하위가 아니면 abort"로 역전 + 경로 정규화:
```powershell
# 의사코드(결재 후 구현)
$fullConf = [System.IO.Path]::GetFullPath($DbConfPath)   # 8.3단축·상대경로·심볼릭 정규화
$fullRoot = [System.IO.Path]::GetFullPath($TestRoot)
if (-not $fullConf.StartsWith($fullRoot, [StringComparison]::OrdinalIgnoreCase)) {
    Abort "db.conf 경로가 격리 루트($TestRoot) 하위가 아닙니다: '$fullConf' → 운영 db.conf 덮어쓰기 차단(R1, 헌법#39). 격리 경로만 허용."
}
```
- 효과: PROGRA~1·D:\HitPan·심볼릭링크·커스텀 경로 **전부 한 번에 차단**. 화이트리스트라 빠짐 없음.

### R2 봉합 — fail-closed (catch가 abort)
**현재**(Build-TestSlot.ps1:224 catch):
```powershell
} catch {
    Write-Log 'INFO' "운영DB 존재 가드 조회 실패(이후 단계 재확인): ..."   # silent 통과
}
```
**봉합** — 조회 실패 시 abort:
```powershell
} catch {
    Abort "운영 DB 존재 여부를 확인하지 못했습니다(조회 실패): $($_.Exception.Message) → 안전하게 중단(R2 fail-closed, 헌법#39). 운영 인스턴스 여부 불확실 시 슬롯 생성 금지."
}
```
- 효과: "mysql 인증된 채 probe만 실패→catch 통과→CREATE 성공" 사고변종 차단. **확인 못 하면 멈춤**(헌법 #15 정신 + fail-closed).
- 단, mysql **부재**는 [2]단계에서 abort되므로 그 케이스는 현 동작 유지(중복 abort 무해). 단 R2는 "있는데 조회 실패"를 막음.

### R3 봉합 — 사용자 DB 화이트리스트 (P2)
**현재**(Build-TestSlot.ps1:216): `WHERE SCHEMA_NAME='hitpan_erp'`
**봉합** — 시스템 DB·슬롯 자신 제외 사용자 DB 존재 시 abort:
```powershell
# 의사코드
$probeSql = "SELECT GROUP_CONCAT(SCHEMA_NAME) FROM information_schema.SCHEMATA " +
            "WHERE SCHEMA_NAME NOT IN ('hitpan_e2e','information_schema','mysql','performance_schema','sys','test');"
# 결과가 비어있지 않으면(=운영/타 사용자 DB 존재) abort
```
- 효과: 운영 DB가 hitpan_erp·demo·hitpan_t001 무엇이든 **이름 무관 차단**. 멀티사업자(#35) 대응.
- 주의: hitpan_backoffice도 사용자 DB라 걸림 → 의도된 것(백오피스 있는 인스턴스도 운영 공유). 단 테스트 전용 인스턴스(시스템DB만)는 통과.

### R4 — 별도 (본 작지 범위 밖)
hitpan-start.bat DB_NAME 이중정의 단일화는 운영 배포파일이라 별도 결재. 권고로만 기록.
