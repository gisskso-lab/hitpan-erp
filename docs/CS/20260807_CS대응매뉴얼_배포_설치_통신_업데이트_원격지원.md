### 0-3. 관리자 권한 — 열 때 한 번만 확인

이 문서의 명령 대부분은 **관리자 권한 창**이 필요합니다.

고객에게 이렇게 안내합니다:
> "화면 왼쪽 아래 시작 단추를 마우스 오른쪽으로 눌러 주시겠어요?
>  거기 **터미널(관리자)** 또는 **Windows PowerShell(관리자)** 라고 적힌 걸 눌러주세요.
>  '이 앱이 변경할 수 있도록 허용하시겠습니까?' 가 나오면 **예** 눌러주십시오."

창을 연 뒤 **관리자인지부터 확인**합니다 — 이걸 안 보고 진행하면 아래 명령들이
조용히 빈 결과를 내고, 상담원이 "정상"으로 오판합니다.

🟩 **[보기] 관리자 권한 확인**
```powershell
if (([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)) { "관리자 창 맞습니다 - 계속 진행하세요" } else { "관리자 창이 아닙니다 - 창을 닫고 다시 열어주세요" }
```
- **뭘 하는 건가**: 지금 이 창이 관리자 권한인지만 봅니다.
- **정상이면**: `관리자 창 맞습니다 - 계속 진행하세요`
- **아니면**: 창을 닫고 0-3 안내를 다시 합니다. 그냥 진행하면 안 됩니다.

### 0-5. 🔴 예약작업은 `schtasks` 로만 봅니다 — `Get-ScheduledTask` 금지

**이 문서에서 `Get-ScheduledTask` 는 쓰지 않습니다.** 아래 명령만 씁니다.

🟩 **[보기] 히트판 예약작업 전체 (이걸 쓰십시오)**
```powershell
schtasks /query /FO TABLE | Select-String "HitPan"
```
- **뭘 하는 건가**: 히트판이 만든 예약작업 이름과 상태를 봅니다. 아무것도 바꾸지 않습니다.
- **관리자 권한**: 필요합니다.
- **정상이면**: **다섯 줄**이 나오고 끝이 전부 `준비`(또는 `Ready`) 입니다.
  이름은 §0-4 표의 다섯 개입니다.
- **아무 줄도 안 나오면**: **§3-4** 로 갑니다.

🟩 **[보기] 특정 예약작업 하나만 자세히**
```powershell
schtasks /query /TN "HitPanWatchdogGuardian" /FO LIST /V
```
- 회사를 여러 개 쓰는 고객이면 이름 뒤 숫자가 다릅니다. 위 목록에서 **실제 이름**을 보고 넣으십시오.

> 🔴 **왜 `Get-ScheduledTask` 를 쓰면 안 되는가 — 반드시 알아두십시오**
>
> 2026-08-07 백지환경 실측에서 **관리자 창인데도** 이 오류가 났습니다:
> ```
> Get-ScheduledTask : Cannot connect to CIM server. 액세스가 거부되었습니다.
> ```
> 이건 **고장이 아닙니다.** 윈도우 내부 통로가 막혀 있는 환경이 있고, 그 통로를 쓰는 명령만
> 실패합니다. **히트판은 멀쩡히 돌고 있었습니다.**
>
> 제품 자체는 이미 이 통로를 피해 가도록 고쳐졌습니다(커밋 `ae18dc0` — 감시 프로그램 등록 순서 + 이 통로 회피).
> **고쳐지지 않은 것은 상담원의 진단 절차였습니다.** 그래서 이번 개정에서 전부 바꿨습니다.
>
> ⛔ 상담원이 이 오류를 보고 **"예약작업이 없다" · "고장났다" 로 오판하면 안 됩니다.**

> 📌 **회사를 알아보는 값은 뒤섞어서 나옵니다**(`TenantIdHash`). 원래 값은 화면에 안 나옵니다.
> 고객 자료가 이 출력으로 새어나가지 않습니다. **이 출력 그대로 본사에 보내도 됩니다.**

#### 🔴 이 출력에서 반드시 볼 곳 — `ProcessStatus` 네 줄

여기가 진단의 심장입니다. **네 개가 전부 `true` 여야 정상**입니다.

| 항목 | 무엇인가 | `false` 면 어디로 |
|---|---|---|
| `MariaDB` | 자료 보관함 | **§3-3** |
| `cloudflared` | 통신 프로그램 | **§2-2** |
| `HitPan.API` | 히트판 본체(업무 처리) | **§3-1** |
| `HitPan.Web` | 고객이 보는 화면 | **§3-1** |

> ⭐ **`HitPan.Web` 이 여기 들어 있는 것 자체가 봉합의 결과입니다.**
> 예전에는 화면 담당이 감시 대상에서 빠져 있어 **죽어도 아무도 안 살렸습니다**(§5 [C-4]).

**그 밖에 함께 보는 값** (실측 출력 기준):

| 값 | 정상 | 아니면 |
|---|---|---|
| `ExternalHealthOk` | `true` | `false` = 밖에서 이 회사 주소가 안 열림 → **§2** |
| `TunnelSecretInvalid` | `false` | `true` = 통신 열쇠 문제 → 🔴 **본사 이관.** 상담원이 못 고칩니다 |
| `CloudflaredServiceExists` | `true` | `false` = 통신 프로그램 등록 자체가 없음 → **§2-3** |
| `WatchdogServiceExists` | `true` | `false` = 감시 프로그램 등록 없음 → **§3-4** |
| `RebootImminent` | `false` | `true` = 곧 컴퓨터가 다시 켜짐. **지금 조작하지 말고 기다립니다** |
| `IsElevated` | `true` | `false` = **관리자 창이 아닙니다.** §0-3 부터 다시 |
| `HasTunnelId`·`HasLicenseKey`·`HasTenantId` | 셋 다 `true` | 하나라도 `false` = 설정이 덜 끝남 → 🔴 **본사 이관** |

**`OverallStatus` 한 줄로 갈립니다** (판정 규칙 근거: `HealthProbe.cs:92~99`):

| 값 | 뜻 | 다음 |
|---|---|---|
| `healthy` | 전부 정상 | 통신 문제 아닙니다 → **§4** |
| `recovering` | 뭔가 꺼져 있고, 스스로 고치는 중 | **3분 기다린 뒤 다시 실행** → 안 바뀌면 §3 |
| `down` | 외부에서 이 회사 주소가 안 열림 | **§2** |

> ⚠️ **이 명령이 아예 실행되지 않으면**(파일을 찾을 수 없다는 메시지) 감시 프로그램이
> 설치되지 않았거나 백신이 지운 것입니다. → **§3-4** 로 갑니다.
>
> ⚠️ **`WatchdogVersion` 이 `1.2.55` 미만이면** 이 PC 는 감시 프로그램이 옛것입니다.
> 옛 감시 프로그램은 **자기 자신을 새것으로 못 바꿉니다**(§5 표 [U-9]).
>
> ⭐ **다만 2026-08-07 실측에서, 새 본체가 옛 감시 프로그램(1.2.52)을 대신 1.2.55 로 바꿔주는 것이
> 실제로 확인됐습니다.** 고객이 아무것도 안 했는데 저절로 바뀌었습니다.
> 그러니 **하루 기다린 뒤 다시 봅니다.** 그래도 그대로면 본사로 넘깁니다.
> 근거: [채증기록 C-1](../검증/20260807_채증기록_C-1_워치독자기교체_실동작_원본.md) §2

## 2. "접속이 안 돼요" — 통신 갈래

### 2-1. 먼저 상담원 컴퓨터에서 봅니다 (고객 PC 만지기 전)

원격에 들어가기 전에 **상담원 브라우저**로 고객 주소를 엽니다. 이게 제일 빠릅니다.

```
https://{회사아이디}.hitpan.kr
```

| 화면에 보이는 것 | 뜻 | 다음 |
|---|---|---|
| **502** | 길은 뚫렸는데 끝의 프로그램이 꺼짐 | **§3** (고객 PC 안쪽 문제) |
| **1033 / 530** | 통신 프로그램이 본사 통신망에 안 붙음 | **§2-2** |
| **로그인 화면이 뜸** | 통신 정상 | **§4** |
| 아무것도 안 뜸 | 주소가 아예 없음 | 본사 이관 (§6) |

> ⭐ **502 와 1033 을 가르는 것이 CS 업무의 절반입니다.**
> 502 는 고객 PC 를 켜면 대개 풀립니다. 1033 은 고객이 뭘 해도 안 풀립니다.

### 2-2. 1033 / 530 — 통신 프로그램이 꺼져 있다

🟩 **[보기] 통신 프로그램 상태**
```powershell
Get-Service cloudflared -ErrorAction SilentlyContinue | Format-List Name,Status,StartType
Get-Process cloudflared -ErrorAction SilentlyContinue | Select-Object Id,StartTime
```
- **뭘 하는 건가**: 통신 프로그램이 등록돼 있는지, 켜져 있는지만 봅니다.
- **정상이면**: `Status : Running` · `StartType : Automatic`
- **`Status : Stopped` 면**: 아래 2-2-B 로.
- **`Get-Service` 가 아무것도 못 찾으면**: **§2-3** 으로 (등록 자체가 안 된 것 — 완전히 다른 건입니다).

> 📌 **왜 이게 제일 흔한가**: 2026-07-30 실측에서 확인된 진범입니다.
> 서비스가 **오류 없이 그냥 안 켜져 있었습니다**(`WIN32_EXIT_CODE : 0`).
> 오류가 아니라서 아무 기록도 안 남아 아무도 몰랐습니다.
> 근거: [네트워크 진단서](../검증/20260730_네트워크진단서_터널1033_원인확정_실측완료.md) §1-2

🟨 **[되살리기] 통신 프로그램 켜기** — 상담원 판단으로 실행 가능
```powershell
Start-Service cloudflared
Start-Sleep -Seconds 5
Get-Service cloudflared | Format-List Name,Status,StartType
```
- **뭘 하는 건가**: 이미 설치돼 있는 통신 프로그램을 다시 켭니다. 새로 만들거나 지우지 않습니다.
- **관리자 권한**: 필요합니다.
- **정상이면**: `Status : Running`
- **그 다음**: 상담원 브라우저에서 고객 주소를 **다시 엽니다.** 로그인 화면이 뜨면 해결입니다.
- **근거**: 2026-07-30 실측에서 이 조치로 1033 이 **즉시 해소**됐습니다(진단서 §1-3).

🟥 **[변경] 다음에 컴퓨터를 껐다 켜도 자동으로 켜지게** — ⚠️ 본사 담당 확인 후
```powershell
Set-Service cloudflared -StartupType Automatic
Get-Service cloudflared | Format-List Name,Status,StartType
```
- **뭘 하는 건가**: 통신 프로그램이 컴퓨터를 켤 때마다 자동으로 시작되도록 바꿉니다.
- **왜 확인이 필요한가**: 설치 프로그램이 이미 이렇게 설정합니다(`.iss:2151`).
  **이게 안 돼 있다면 설치가 정상적으로 안 끝났다는 뜻**이라, 값만 바꾸고 넘어가면
  다른 것도 빠져 있을 수 있습니다. 담당이 설치 기록을 먼저 봐야 합니다.
- **정상이면**: `StartType : Automatic`

### 2-3. 통신 프로그램이 **아예 없다** — 🔴 상담원이 손대면 안 되는 건

`Get-Service cloudflared` 가 아무것도 못 찾는 경우입니다.

🟩 **[보기] 왜 등록이 안 됐는지 확인**
```powershell
"=== 프로그램 파일은 있나 ==="; Test-Path "C:\Program Files\HitPan\cloudflared.exe"
"=== 남은 흔적이 있나 ==="; Test-Path "HKLM:\SYSTEM\CurrentControlSet\Services\EventLog\Application\Cloudflared"
"=== 설치 기록 ==="; Get-ChildItem "$env:TEMP\Setup Log*.txt" -ErrorAction SilentlyContinue | Sort-Object LastWriteTime -Descending | Select-Object -First 1 | ForEach-Object { Select-String -Path $_.FullName -Pattern '6-1|6-2|6-3|serviceinstall' | Select-Object -Last 20 }
```
- **뭘 하는 건가**: 프로그램 파일 존재 여부, 지워지지 않은 옛 흔적 존재 여부, 설치 기록을 읽습니다. 아무것도 바꾸지 않습니다.
- **정상이면**: 첫 줄 `True`, 둘째 줄 `False`
- **둘째 줄이 `True` 면**: 🔴 **이것이 8/03 에 확정한 진범입니다.**

> 🔴 **`True` 가 나오면 상담원은 여기서 멈추고 본사로 넘기십시오** — **`{{고객센터_메일}}`** (§6-0).
>
> 통신 프로그램은 자기가 이미 설치돼 있는지를 **Windows 서비스 목록이 아니라 자기만의 흔적**으로
> 판단합니다. 그 흔적이 남아 있으면 **몇 번을 다시 설치해도 영원히 거부합니다.**
> 실측(2026-08-03): 서비스를 방금 지웠는데도 *"이미 설치돼 있다"* 며 거부.
>
> ⛔ **재설치를 안내하지 마십시오. 효과가 없습니다.**
> ⛔ **레지스트리를 상담원이 지우지 마십시오.** 잘못 지우면 되돌릴 수 없습니다.
>
> 봉합은 1.2.49 이상 설치본에 들어갔습니다(커밋 `42f06d3`).
> 근거: [작업지시서](../운영기록/20260803작1_설치_터널서비스_등록실패_봉합.md) §1

### 2-4. 회사 방화벽이 막는 경우 (드묾 · 사례 0건)

🟩 **[보기] 통신 길이 열려 있나**

- **뭘 하는 건가**: 본사 서버까지 길이 열려 있는지, 이 회사 주소가 인터넷에 등록돼 있는지 봅니다.
- **정상이면**: `TcpTestSucceeded : True` + 주소 정보가 나옵니다.
- **`False` 면**: 회사 방화벽이 막고 있을 가능성. 고객사 전산 담당에게 확인 요청 → 본사 이관.

🟩 **[보기] 히트판이 만든 방화벽 규칙이 살아 있나**

## 3. "화면이 안 떠요" / 502 — 고객 PC 안쪽 갈래

통신은 살아 있는데 그 끝의 프로그램이 안 도는 상태입니다.

### 3-1. 히트판 본체·화면이 안 돌 때

🟩 **[보기] 본체·화면이 응답하나**
```powershell
"=== 본체(5257) ==="; try { (Invoke-WebRequest "http://127.0.0.1:5257/health" -UseBasicParsing -TimeoutSec 10).Content } catch { "응답 없음: $($_.Exception.Message)" }
"=== 화면(5234) ==="; try { "응답코드 " + (Invoke-WebRequest "http://127.0.0.1:5234/" -UseBasicParsing -TimeoutSec 10).StatusCode } catch { "응답 없음: $($_.Exception.Message)" }
"=== 예약작업 상태 ==="; schtasks /query /FO TABLE | Select-String "HitPan-ERP-"
```
- **뭘 하는 건가**: 히트판 본체와 화면이 이 컴퓨터 안에서 응답하는지 봅니다. 아무것도 바꾸지 않습니다.
- **근거**: 포트 5257·5234 는 `.iss:204, 2390` 에서 확인. 감시 프로그램도 이 두 곳을 봅니다(`src/HitPan.Watchdog/appsettings.json`).

⭐ **정상이면 첫 줄이 이렇게 나옵니다 — 2026-08-07 백지환경 실제 출력 전문입니다.**

```json
{
  "status": "healthy",
  "timestamp": "2026-08-06T10:39:30.25486Z",
  "checks": {
    "database": "ok",
    "version": "1.2.55",
    "environment": "Unknown",
    "uptime_sec": 134
  }
}
```
- 근거: [채증기록 C-1](../검증/20260807_채증기록_C-1_워치독자기교체_실동작_원본.md) §3-3

**이 출력에서 볼 곳:**

| 값 | 뜻 | 아니면 |
|---|---|---|
| `"status": "healthy"` | 본체가 살아 있음 | 이 줄이 아예 없으면 → 아래 되살리기 |
| `"database": "ok"` | 자료 보관함까지 잘 붙음 | 다른 값이면 → **§3-3** |
| `"version"` | 지금 깔린 본체 버전 | 본사 최신과 다르면 → **§4-3** |
| `"uptime_sec"` | 본체가 켜진 지 몇 초 | **숫자가 작으면(수백 초 이하) 방금 켜진 것**입니다. 2~3분 더 기다렸다 다시 봅니다 |

> 📌 **`"environment": "Unknown"` 은 정상입니다.** 고장 표시가 아닙니다.
> 이 값으로 판단하지 마십시오.

- **둘째 줄(화면)이 정상이면**: `응답코드 200`

🟨 **[되살리기] 본체·화면 다시 켜기** — 상담원 판단으로 실행 가능
```powershell
schtasks /run /TN "HitPan-ERP-API-tenant-1"
schtasks /run /TN "HitPan-ERP-WEB-tenant-1"
Start-Sleep -Seconds 20
try { (Invoke-WebRequest "http://127.0.0.1:5257/health" -UseBasicParsing -TimeoutSec 10).Content } catch { "아직 응답 없음" }
```
- **뭘 하는 건가**: 이미 등록돼 있는 히트판 본체·화면을 다시 시작합니다. 새로 만들지 않습니다.
- **관리자 권한**: 필요합니다.
- **정상이면**: 20초 뒤 `"status":"healthy"`
- ⚠️ **한 컴퓨터에 회사를 여러 개 쓰는 고객**은 뒤 숫자가 다릅니다(`-2`, `-3`…).
  §1-2 의 예약작업 목록에서 **실제로 있는 이름**을 보고 그 숫자를 쓰십시오.
- 🔴 `Start-ScheduledTask` 를 쓰지 마십시오. 같은 통로를 써서 **관리자 창인데도 막히는 환경**이
  실측으로 확인됐습니다(§0-5). `schtasks /run` 은 그 통로를 안 씁니다.

> 💡 **왜 재부팅을 권하는가**: 히트판 감시 프로그램은 **컴퓨터가 켜질 때를 복구 기회로 씁니다.**
> 위 명령이 안 통하면 **"컴퓨터를 한 번 다시 시작해 주시겠어요? 자료는 그대로 있습니다"** 가
> 가장 안전하고 확실한 안내입니다.

### 3-2. 502 인데 고객은 "컴퓨터 켜져 있다"고 할 때

고객 안내 문장 (그대로 읽어도 됩니다):
> "히트판이 설치된 컴퓨터가 켜져 있는지 확인 부탁드립니다.
>  히트판은 그 컴퓨터에서 직접 돌아가기 때문에, 컴퓨터가 꺼지면 접속이 안 됩니다."

켜져 있다는데도 502 면:
> "컴퓨터를 한 번 다시 시작해 주시겠어요? 자료는 그대로 있습니다."

**절전·최대 절전 모드도 꺼진 것과 같습니다.** 노트북 덮개를 닫아두는 고객이 실제로 많습니다.

🟩 **[보기] 컴퓨터가 언제부터 켜져 있나**
```powershell
"부팅 시각: " + (Get-CimInstance Win32_OperatingSystem).LastBootUpTime
"현재 시각: " + (Get-Date)
```
- **뭘 하는 건가**: 이 컴퓨터가 마지막으로 켜진 시각을 봅니다.
- **왜 보나**: 방금 켜졌다면 **아직 히트판이 다 뜨지 않았을 수 있습니다.** 2~3분 기다립니다.

### 3-3. 자료 보관함이 꺼져 있을 때

🟩 **[보기] 자료 보관함 상태**
```powershell
Get-Service MariaDB -ErrorAction SilentlyContinue | Format-List Name,Status,StartType
Get-NetTCPConnection -State Listen -LocalPort 3306 -ErrorAction SilentlyContinue | Select-Object LocalPort,OwningProcess
"=== 디스크 여유 ==="; Get-PSDrive C | Select-Object @{n='남은용량(GB)';e={[math]::Round($_.Free/1GB,1)}}
```
- **뭘 하는 건가**: 자료 보관함이 돌고 있는지, 디스크가 꽉 차지 않았는지 봅니다.
- **정상이면**: `Status : Running` · 포트 3306 이 보임 · 남은 용량 **2GB 이상**
- 🔴 **남은 용량이 2GB 미만이면 그것이 원인일 수 있습니다.**
  본사 서버에서 실제로 디스크가 가득 차 자료 보관함이 죽은 사고가 있었습니다(§5 [D-4]).
  같은 일이 고객 PC 에서도 납니다. **업데이트 백업도 실패합니다.**

> 🆕 🔴 **업데이트 문의를 받으면 디스크부터 보십시오.**
> **히트판은 업데이트 전에 남은 용량을 재지 않습니다**(2026-08-07 확인).
> 업데이트 한 번이 수백 MB 를 쓰는데, 부족하면 **업데이트만 실패하는 게 아니라
> 원래대로 되돌리는 것까지 함께 실패합니다.** 안전망이 같이 무너집니다.
> **얼마가 있어야 하는지는 아직 정해진 기준이 없습니다**(§10-2). 여유가 적어 보이면 본사로 넘기십시오 — **`{{고객센터_메일}}`** (§6-0).
>
> ⚠️ 일부 환경에서는 이 명령이 **남은 용량을 `0` 으로 잘못 보여줍니다**(실측 확인).
> `0` 이 나왔다고 바로 "디스크가 가득 찼다" 고 단정하지 마십시오. **다른 방법으로 한 번 더 확인**하십시오:
> ```powershell
> Get-CimInstance Win32_LogicalDisk -Filter "DeviceID='C:'" | Select-Object @{n='남은GB';e={[math]::Round($_.FreeSpace/1GB,1)}},@{n='전체GB';e={[math]::Round($_.Size/1GB,1)}}
> ```

🟨 **[되살리기] 자료 보관함 켜기** — 상담원 판단으로 실행 가능
```powershell
Start-Service MariaDB
Start-Sleep -Seconds 10
Get-Service MariaDB | Format-List Name,Status
```
- **정상이면**: `Status : Running`
- **안 켜지면**: 본사 이관. 상담원이 더 손대지 않습니다.

### 3-4. 감시 프로그램이 없어졌을 때 (백신 의심)

## 4. "업데이트가 안 끝나요" / "느려요" — 업데이트 갈래

### 4-1. 🔴 업데이트 중에는 잠깐 접속이 끊깁니다 — 고장이 아닙니다

> **앞으로 가장 많이 들어올 문의입니다.** 8/03·8/07 실측으로 확인됐습니다.

고객이 보는 것:
```
"서버에 연결할 수 없습니다"
사이트에 연결할 수 없음
```

🟩 **[보기] 지금 업데이트 중인가**
```powershell
if (Test-Path "C:\Program Files\HitPan\update.lock") { "업데이트 진행 중입니다"; Get-Item "C:\Program Files\HitPan\update.lock" | Select-Object LastWriteTime } else { "업데이트 중 아닙니다" }
Get-ChildItem "$env:LOCALAPPDATA\HitPan\Updates\pre-update-backup" -ErrorAction SilentlyContinue | Sort-Object LastWriteTime -Descending | Select-Object -First 3 Name,Length,LastWriteTime
```
- **뭘 하는 건가**: 업데이트가 진행 중인지, 자료 백업이 됐는지 봅니다. 아무것도 바꾸지 않습니다.
- **`업데이트 진행 중입니다` 가 나오면**: 🔴 **아무것도 하지 마십시오.** 기다립니다.
- **백업 파일 크기가 0 이 아니면**: 자료는 안전합니다. 고객을 안심시키십시오.
- **근거**: `UpdateLockFile.cs:60` · `WatchdogBackupRunner.cs:51`. 백업이 실패하면 업데이트 자체가 **차단**됩니다(같은 파일, 크기 0 검사).

고객 안내 문장:
> "업데이트가 진행 중이어서 잠시 접속이 안 되는 것입니다.
>  **자료는 먼저 백업되니** 걱정하지 않으셔도 됩니다.
>  2~3분 뒤에 다시 접속해 주시겠어요?"

> 🔴 **CS 주의 — 이때 절대 안내하면 안 되는 것:**
> - "컴퓨터를 끄세요" ⛔ 교체 도중에 끊으면 반쪽 상태로 남습니다
> - "다시 설치하세요" ⛔ 상황을 더 망칩니다
> - **기다리는 게 맞습니다.**
>
> 표시는 **15분이 지나면 저절로 사라집니다**(`UpdateLockFile.cs:37`).
> 15분이 넘도록 그대로면 그때 본사로 넘기십시오 — **`{{고객센터_메일}}`** (§6-0).

### 4-2. "업데이트하겠냐고 물어보는 창이 떴어요"

큰 업데이트일 때 고객 화면에 확인 창이 뜹니다.

**[예] 를 누르면**: 자료를 백업한 뒤 **히트판이 잠시 꺼졌다가 다시 켜집니다.**
**[나중에] 를 누르면**: 지금 하던 입력을 저장할 수 있습니다. 나중에 다시 물어봅니다.

> 🔴 **고객이 저장 안 한 입력이 있다고 하면 반드시 [나중에] 를 안내하십시오.**
> [예] 를 누르면 히트판이 강제로 꺼지면서 **저장하지 않은 견적서·거래명세서 입력이 사라집니다.**
> (이미 저장을 끝낸 자료는 안전합니다.)
> 근거: 커밋 `c5ebfc1` — 이 안내 문구가 없어 사고가 날 뻔한 것을 봉합했습니다.

### 4-3. "업데이트를 눌렀는데 아무 일도 안 일어나요"

🟩 **[보기] 지금 버전과 최신 버전 비교**
```powershell
"=== 이 컴퓨터 ==="
"  본체:   " + (Get-Item "C:\Program Files\HitPan\api\HitPan.API.exe" -ErrorAction SilentlyContinue).VersionInfo.FileVersion
"  감시:   " + (Get-Item "C:\Program Files\HitPan\watchdog\HitPan.Watchdog.exe" -ErrorAction SilentlyContinue).VersionInfo.FileVersion
"=== 본사 최신 ==="
try { (Invoke-RestMethod "https://updates.hitpan.kr/manifest.json" -TimeoutSec 15) | Select-Object version,channel } catch { "본사 업데이트 서버에 연결할 수 없습니다: $($_.Exception.Message)" }
```
- **뭘 하는 건가**: 이 컴퓨터 버전과 본사 최신 버전을 비교합니다. 아무것도 바꾸지 않습니다.
- **근거**: `UpdateClient.cs:63, 73`
- **판정**:

| 본 것 | 뜻 | 다음 |
|---|---|---|
| 본체 버전 = 본사 버전 | 이미 최신입니다 | 고객에게 최신이라고 안내 |
| 본체 버전 < 본사 버전 | 아직 안 받았습니다 | 아래 4-4 → 하루 지나도 그대로면 🆕 **§4-6** |
| **감시 버전 < 1.2.55** | 🔴 감시 프로그램이 옛것 | §5 [U-9] — 하루 기다린 뒤 그대로면 본사 이관 |
| 본사 연결이 안 됨 | 본사 서버 문제이거나 회사 방화벽 | §6 본사 이관 |

> 🆕 **본체 버전이 본사보다 낮은데 며칠째 그대로면** 새 증상일 수 있습니다 → **§4-6**
> 그때는 §4-7 로 **이 컴퓨터가 최신이라고 알고 있는 버전**까지 함께 봐야 판정이 됩니다.

### 4-4. 업데이트가 언제 도는지 (상담원 기본 지식)

| 종류 | 언제 | 고객이 할 일 |
|---|---|---|
| 일반 | **새벽 3시~4시 사이** | 없음. 저절로 됩니다 |
| 긴급 | 즉시 (5분 전 안내) | 없음 |
| 큰 업데이트 | 고객이 [예] 를 누른 **직후** | 확인 창에 답하기 |

- **근거**: `UpdateOrchestrator.cs:1423` (`IsNightWindow` = 3시~4시) · `:98` (긴급 5분)
- **고객에게**: *"새 기능이나 개선이 있으면 밤에 저절로 업데이트됩니다. 따로 하실 일은 없습니다."*

> ⚠️ **"업데이트 안 하겠다"는 고객에게**: 일반·긴급은 안전을 위해 선택할 수 없습니다.
> 큰 업데이트만 미룰 수 있습니다. 자세한 건 [자동 업데이트 안내](AUTO_UPDATE_CUSTOMER_NOTICE.md) 를 보십시오.

### 4-5. 업데이트가 실패하면 어떻게 되나

- 근거: `UpdateOrchestrator.cs:216, 230` — 다시 켜기에 실패하거나 새 버전 검사에 실패하면
  **구버전으로 되돌립니다.** 되돌리기까지 실패하면 본사에 자동으로 알립니다(`:51`).

고객 안내:

> **왜 그냥 🟨 가 아닌가**: 감시 프로그램은 **다른 모든 것을 살려주는 프로그램**입니다.
> 이것이 꺼져 있는 동안에는 통신·본체·화면이 죽어도 **아무도 살리지 않습니다.**
> 그래서 아래 4가지를 **전부** 만족해야 합니다.
>
> ✅ **① `update.lock` 이 없어야 합니다** (§1-2 로 확인). 있으면 🔴 **절대 금지** — 교체 중에 끊는 것입니다
> ✅ **② `--health` 가 `healthy` 여야 합니다** (§1-1). `recovering`·`down` 이면 지금 뭔가를 고치는 중입니다. 끊지 마십시오
> ✅ **③ §4-3 으로 버전 차이를 실제로 확인했어야 합니다.** 추측으로 돌리지 않습니다
> ✅ **④ 최소 하루는 기다려봤어야 합니다.** 저절로 잡히는 것을 안 기다리고 손대지 않습니다
>
> **하나라도 아니면 → §6 본사 이관.** 상담원이 판단하지 않습니다.
>
> ⛔ **고객에게 이 명령을 직접 시키지 마십시오.** 상담원이 원격으로만 실행합니다(§7-3 와 같은 기준).
> ⛔ **이걸 돌렸으면 §6-3 보고 양식의 "상담원이 실행한 명령" 칸에 반드시 적으십시오.**

> ⛔ **말하면 안 되는 것**: "감시 프로그램이 고장났습니다" · "다시 설치하셔야 합니다"
> **둘 다 사실이 아닙니다.** 히트판은 정상 작동 중이고, 새 버전만 늦게 오는 것입니다.

**읽는 법:**

| 나온 값 | 뜻 |
|---|---|

$log += "=== 버전 ==="; $log += ("API " + (Get-Item "C:\Program Files\HitPan\api\HitPan.API.exe" -ErrorAction SilentlyContinue).VersionInfo.FileVersion + " / 감시 " + (Get-Item "C:\Program Files\HitPan\watchdog\HitPan.Watchdog.exe" -ErrorAction SilentlyContinue).VersionInfo.FileVersion)

"저장했습니다: $out"

**보여주는 방식**의 문제입니다(2026-08-07 실측에서 확인 — [채증기록 C-1](../검증/20260807_채증기록_C-1_워치독자기교체_실동작_원본.md) §2-2).

> 🔴 **깨진 글자를 억지로 읽으려 하지 마십시오.**

> 우리가 겪은 사고의 절반이 *"됐다는데 실제로는 안 되는"* 구조였습니다(§5-6).

#### 상담원이 할 일 — 이것뿐입니다

🟩 **[보기] 기록 파일을 파일째 바탕화면으로 복사**

- **관리자 권한**: 필요합니다.
- **그 다음**: 그 폴더를 **통째로 본사에 전달**합니다 → **`{{고객센터_메일}}`** (§6-0). 상담원이 읽으려 하지 않습니다.
- **근거**: 기록 파일 경로는 2026-08-07 실측에서 확인했습니다(§0-4).

> ⚠️ **미확인 — 깨진 글자를 상담원 화면에서 제대로 보이게 하는 방법**
> 여러 방법이 거론되고 있으나 **아직 우리가 직접 확인한 것이 없습니다.**
> 확인 안 된 방법을 시도하다 잘못 읽으면 **틀린 판단이 고객에게 갑니다.**
>
> ✅ **지금 정답은 하나입니다 — 파일을 그대로 본사로 보내십시오.**
> 본사에서 제대로 읽어 결과를 알려드립니다.
> (개발팀에 정식 이관된 사안입니다 — 채증기록 §6 이관사항 D)

### 7-1. 고객 PC 에서 절대 금지

| 금지 | 무슨 일이 나는가 |
|---|---|

| **자료 보관함 지우거나 초기화** | 🔴 **고객 자료가 전부 사라집니다.** 되돌릴 수 없습니다 |
| **자료 보관함 비밀번호 변경** | 백업·업데이트가 조용히 실패합니다. 컴퓨터가 고장 나면 **자료를 못 꺼냅니다** ([안내 기준](20260731_DB비밀번호_CS안내기준.md)) |
| **서비스 삭제** (`sc delete`, `Remove-Service`) | 🔴 **되살릴 방법이 없습니다.** 통신 프로그램은 지운 흔적 때문에 재설치도 거부합니다(§5 [I-4]) |
| **레지스트리 편집** | 잘못 지우면 되돌릴 수 없습니다. 본사 담당만 합니다 |
| **설치 폴더 파일 삭제** | 통신 프로그램 파일이 없으면 자동 복구가 **물리적으로 불가능**해집니다 |
| **업데이트 중에 컴퓨터 끄기·재설치** | 반쪽 상태로 남습니다 |
| **덮어 재설치 반복** | 실행 중인 파일을 못 지워 옛·새 파일이 섞입니다(§5 [I-5]) |
| **예약작업 삭제** | 히트판이 컴퓨터를 켤 때 안 뜹니다 |
| 🆕 **`watchdog.new` · `watchdog.old` · `watchdog.handoff` 폴더 삭제** | 감시 프로그램이 **자기를 새것으로 바꾸는 중**입니다. 지우면 교체가 반쪽으로 끝납니다. 끝나면 **저절로 사라집니다**(§0-4) |
| 🆕 **자료 보관함 비밀번호를 명령줄에 붙여 치기** | 화면·기록·녹화 파일에 **그대로 남습니다.** `-p` 만 치고 물어볼 때 입력합니다(§4-7) |
| 🆕 **업데이트 중에 감시 프로그램 껐다 켜기** | 교체 도중에 끊는 것입니다. §4-6 의 4가지 조건을 **전부** 확인하고서만 |
| 🆕 **깨진 기록 글자를 짐작해서 판단** | 반쯤 읽고 뜻을 지어내는 것이 가장 위험합니다. 파일째 본사로(§6-4) |
| **원인을 모른 채 🟥 명령 실행** | 우리가 겪은 사고의 절반이 이렇게 커졌습니다 |

  **고객에게 시키는 것은 금지**입니다.
