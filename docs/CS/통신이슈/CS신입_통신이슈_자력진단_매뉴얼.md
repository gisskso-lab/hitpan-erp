# CS 신입 매뉴얼 — 통신·접속 문의 스스로 진단하기

| 항목 | 내용 |
|---|---|
| 작성 | **CS팀장 강지원** · 2026-07-30 |
| 지시 | 사장님 — *"사장의 SSH 몫으로 남기지 말고, CS의 새로운 인력이 대응 할수 있도록 메뉴얼을 만들어"* |
| 대상 | **입사 첫날 CS 담당자** — 개발 지식 0 을 전제로 씀 |
| 상태 | 🟢 **진실원** — 원인 실측 확정 + 봉합 완료(2026-07-30) |
| 기술 근거 | [네트워크 진단서 — 원인확정 실측완료](../../검증/20260730_네트워크진단서_터널1033_원인확정_실측완료.md) |
| 봉합 반영 버전 | **1.2.45 이상** |

## 0. 이 매뉴얼이 있는 이유

전에는 접속 문의가 오면 **사장님이 서버에 들어가서 봐야** 원인을 알았다.
그래서 CS 는 기다릴 수밖에 없었고, 고객도 같이 기다렸다.

**이제 CS 가 직접 본다.** 아래 3단계면 원인이 나온다. 서버 접속 필요 없다.

> 💡 **개발 용어를 몰라도 됩니다.** 숫자 3개(200·502·530)만 구분하면 됩니다.

---

# 1단계 — 본사가 살아있나 (10초)

브라우저 주소창에 아래 3개를 차례로 붙여넣는다.

```
https://back.hitpan.kr
https://landing.hitpan.kr
https://updates.hitpan.kr/manifest.json
```

| 결과 | 뜻 | 할 일 |
|---|---|---|
| 3개 다 화면이 나온다 | 본사 정상 | **2단계로** |
| 하나라도 안 나온다 | **본사 장애** | 🚨 **즉시 개발팀·사장님 보고.** 전체 고객 영향 |

> ✅ 2026-07-30 실측: 3개 모두 정상(200).

---

# 2단계 — 고객 주소를 열어본다 (⭐ 여기서 원인이 갈린다)

고객이 말한 주소를 **CS 컴퓨터에서** 열어본다.

```
https://{고객주소}.hitpan.kr
```

## ⭐⭐ 화면에 나오는 것으로 판정한다 — 이게 이 매뉴얼의 핵심

| 고객 화면 | 판정 | 누가 처리 |
|---|---|---|
| **ERP 로그인 화면이 나온다** | **정상** | 고객 쪽 인터넷·브라우저 문제. §5-1 안내 |
| **`Error 502` / 502 Bad Gateway** | **고객 컴퓨터가 꺼져 있음** | **CS 자체 처리** → §5-2 |
| **`Error 1033` / 530** | **본사에서 설정이 안 끝남** | **3단계로** |
| 아무것도 안 나옴·시간초과 | 판정 불가 | §5-4 |

> 🔴 **502 와 1033 을 반드시 구분하세요. 완전히 다른 문제입니다.**
>
> - **502** = 길은 다 뚫려 있는데 **고객 컴퓨터가 꺼져 있다** → 켜면 됩니다
> - **1033** = **길 자체가 안 만들어졌다** → 고객이 뭘 해도 안 됩니다
>
> 실측 예: `demo.hitpan.kr` → **502**(정상 발급, PC만 꺼짐) / `test1.hitpan.kr` → **530**(발급 실패)

---

# 3단계 — 1033 이면 설치본 버전을 확인한다

## ⭐ 실측으로 확정된 원인 (2026-07-30)

> **고객 컴퓨터에서 연결 프로그램이 실행되지 않고 멈춰 있었다.**
> 오류로 죽은 게 아니라 **조용히 정상 종료**돼 있었다. 그래서 기록이 안 남았다.

**이 원인은 1.2.45 부터 설치 프로그램이 스스로 잡는다.** 그래서 3단계는 **버전 확인**이다.

> 🔴 **옛 매뉴얼에서 바뀐 것**: 종전 3단계는 *"가입 승인이 안 된 것일 가능성이 가장 높다"* 였다.
> **실측 결과 그게 틀렸다.** `test1`·`test2` 는 **승인도 됐고 터널도 발급돼 있었다.**
> 승인 상태를 보는 건 이제 3단계가 아니다(§3-2 보조 확인으로 내려갔다).

## 3-1. 설치 시각·버전을 묻는다 (⭐ 핵심)

고객에게 묻는다:

> "혹시 언제쯤 설치하셨는지 기억나세요? 며칠쯤인지만요."

| 설치 시점 | 판정 | 할 일 |
|---|---|---|
| **2026-07-30 이전** | 옛 버전(1.2.44 이하) — **원인 확정** | **§5-6 최신본 재설치 안내** ✅ 해결됨 |
| 2026-07-30 이후 | 1.2.45 이상 가능성 | **§3-2 보조 확인 → 아니면 §4 이관** |
| 모른다 | 판정 불가 | **§5-6 을 먼저 시도**(해되지 않는다) |

> 💡 **모른다고 하면 그냥 최신본 재설치를 안내한다.** 최신본으로 다시 깔아도
> 자료는 유지되고 손해가 없다. 원인 규명보다 **고객이 빨리 쓰는 게 우선**이다.

## 3-2. 보조 확인 — 승인 상태 (1.2.45 이상인데 안 될 때만)

최신본인데도 1033 이면 그때 본다.

1. `https://back.hitpan.kr` 로그인
2. **가입관리** 메뉴
3. 고객 **회사명** 검색 → **상태** 칸

| 상태 | 판정 | 할 일 |
|---|---|---|
| **승인대기 / submitted** | 승인이 안 됐다 | §5-3 (승인 후 재설치) |
| **반려 / rejected** | 반려된 계정 | §5-3 (담당 확인 후 안내) |
| **승인 / approved / active** | 승인은 정상 | **§4 개발팀 이관** (백신 차단 의심) |
| 목록에 없다 | 시리얼·회사명 오류 | §5-5 (정보 재확인) |

> 💡 **테넌트코드가 비어 있는 것은 정상입니다.**
> 승인을 하면 그때 만들어집니다. 승인 전에 없는 게 맞습니다. 이걸 문제로 보고하지 마세요.

## 3-3. `진단` 버튼 (준비 중)

백오피스에 **`진단`** 버튼이 추가될 예정이다(작7). 완성되면 시리얼만 넣으면
**판정 · 고객안내문 · 다음조치** 3줄이 바로 나온다. **그때는 이 3단계가 1클릭으로 끝난다.**

버튼이 아직 없으면 위 3-1·3-2 를 손으로 한다.

# 4. 개발팀 이관 기준

**최신본(1.2.45+)으로 재설치했는데도 1033** 이면 CS 가 처리할 수 없다.
남은 원인은 **백신·방화벽 차단**이 가장 유력하다. 아래를 그대로 담당에게 보낸다.

```
[통신이슈] Error 1033 — 최신본(1.2.45+) 재설치 후에도 접속 불가
· 회사명    :
· 시리얼    :
· 접속 주소 :
· 1단계 본사 3개    : 정상 / 이상(어느 것)
· 2단계 고객 주소   : 1033(530)
· 3-1 설치 시각·버전 : (1.2.45 이상 확인됨)
· 3-2 승인 상태     : active(승인완료)
· 관리자 권한으로 실행했는지 : 예 / 아니오
· 쓰고 있는 백신 이름 :          ← ⭐ 이 줄이 제일 중요하다
· 고객에게 약속한 재연락 시각 :
```

> ⭐ **백신 이름을 반드시 받는다.** 실측에서 봉합 후 남은 유일한 원인이 백신 차단으로 좁혀졌다.
> 이 한 줄이 담당의 확인 시간을 크게 줄인다.

담당은 [네트워크 진단서](../../검증/20260730_네트워크진단서_터널1033_원인확정_실측완료.md) 로 확정한다.
**CS 는 원인을 추측해서 적지 않는다.** 본 것만 적는다.

# 5. 고객 응대 문구 (그대로 읽어도 됨)

## 5-1. 정상인데 고객만 안 보임

> "저희 쪽에서는 화면이 정상적으로 열립니다.
> 고객님 사무실 인터넷이나 브라우저 문제일 수 있어요.
> 다른 브라우저(엣지·크롬)로 한 번 열어봐 주시겠어요?
> 그래도 안 되면 다시 연락 주세요. 원격으로 함께 봐드리겠습니다."

## 5-2. 502 — 고객 컴퓨터가 꺼져 있음

> "확인해보니 히트판이 설치된 **사무실 컴퓨터가 꺼져 있는 것 같습니다.**
> 그 컴퓨터를 켜주시면 바로 접속됩니다.
> (히트판은 고객님 사무실 컴퓨터에서 돌아가기 때문에, 그 컴퓨터가 켜져 있어야 합니다.)"

💡 이게 **셀링 포인트**다 — 자료가 고객 사무실에만 있다는 뜻. 불편이 아니라 **안전**으로 설명한다.

## 5-3. 승인이 안 된 계정이었음

> "확인해보니 가입 승인이 아직 완료되지 않은 상태였습니다.
> 지금 승인 처리하겠습니다. 승인 후 **다시 설치하시면** 정상적으로 연결됩니다.
> 번거롭게 해서 죄송합니다."

⚠️ **이 경우에만 재설치를 안내한다.** 다른 경우엔 재설치해도 안 된다.

## 5-4. 판정 불가 / 원인 확인 중

> "확인에 시간이 조금 더 필요합니다.
> **○시까지 다시 연락드리겠습니다.** 그때까지 따로 조작하실 것은 없습니다."

**반드시 시각을 말한다.** "확인해보겠습니다"만 하고 끊지 않는다.

## 5-5. 시리얼·회사명이 안 맞음

> "알려주신 정보로 가입 내역을 찾지 못했습니다.
> 가입하실 때 받으신 안내 메일에 적힌 번호와 회사명을 그대로 알려주시겠어요?"

## 5-6. ⭐ 최신본 재설치 안내 (1033 의 표준 해결책)

> "고객님, 저희 프로그램 최신 버전에서 이 부분이 개선되었습니다.
> 최신 파일로 한 번만 다시 설치하시면 정상 작동합니다.
> 지금 쓰시던 **자료는 그대로 유지**됩니다. 지워지지 않습니다."

**고객에게 알려주는 순서:**

1. `https://landing.hitpan.kr/download` 접속
2. **다운로드 버튼** 클릭 (약 270MB · 2~10분)
3. 내려받은 파일 **오른쪽 클릭 → 관리자 권한으로 실행**
4. 시리얼 키 입력 (처음 설치할 때 넣었던 그 번호)
5. 안내대로 진행 → 완료

> ⚠️ **"관리자 권한으로 실행" 을 반드시 강조한다.** 빠지면 또 실패한다.
> 고객이 뭔지 모르면: *"파일 위에서 마우스 오른쪽 버튼을 누르시면 목록이 나오는데,
> 거기 '관리자 권한으로 실행' 이라고 적힌 걸 눌러주세요."*

**자료가 안 지워진다고 먼저 말한다.** 고객이 가장 무서워하는 게 그것이다.

설치 후 함께 확인한다:

| 결과 | 다음 |
|---|---|
| ✅ 로그인 화면 나옴 | **해결.** 마무리 안내 |
| ❌ 여전히 1033·530 | §3-2 → §4 이관 |
| ⚠️ 502 로 바뀜 | 연결은 성공. ERP 실행 문제 → §5-2 |

# 6. 절대 하지 말 것

| 금지 | 왜 |
|---|---|
| **"다시 설치해도 똑같습니다"** | **옛 안내. 실측으로 틀렸음이 확인됐다.** 최신본(1.2.45+)은 해결된다 |
| 버전 확인 없이 이관 | §3-1 을 건너뛰면 담당이 다시 CS 에 물어본다. **설치 시점을 먼저 받는다** |
| "터널이 연결 안 됐어요" | 개발 용어. 고객이 못 알아듣는다 (헌법 #23) |
| "DNS·토큰·API" 같은 말 | 위와 같음 |
| "인터넷 확인해보세요"(1033인데) | 인터넷 문제 아니다. 고객을 의심하는 말 |
| "원래 그럴 수 있어요" | 원래 그러면 안 되는 것이다 |
| 원인을 추측해서 단정 | 모르면 "확인 중"이라고 한다 |
| 502 를 1033 처럼 처리 | **완전히 다른 문제.** §2 판정표 필수 |

# 7. 책임 경계 (고객에게 설명할 때)

| 영역 | 어떤 경우 | 고객에게 |
|---|---|---|
| **본사** | 1033(발급 실패·승인 누락) | 명확히 사과. **본사가 처리한다**고 말한다 |
| **고객** | 502(컴퓨터 꺼짐), 사내 인터넷 | 탓하지 않고 **방법만** 알려준다 |
| 제3자 | 통신사 장애, 백신 차단 | 확인된 경우만 언급. 추측으로 남의 탓 금지 |

**책임을 흐리지 않는다.** 본사 건이면 본사 건이라고 말한다.

# 9. 확정된 것 / 아직 확정 안 된 것

## ✅ 확정 (2026-07-30 실측)

- **`test1`·`test2` 근본 원인** — 연결 프로그램이 실행되지 않고 멈춰 있었음(조용한 정상 종료)
- **해결 방법** — **최신본(1.2.45+) 재설치.** 실측으로 확인됨
- **승인 상태는 원인이 아니었다** — 두 계정 모두 승인·터널 발급 완료 상태였다

## ⬜ 아직 확정 안 된 것

- **백신별 차단 사례** — §4 이관 건이 실제로 나오면 그때 축적한다(현재 0건)
- **사용 기간 보상 기준** — 미정. 사장님 결재 필요
- **`진단` 버튼** — 개발 중(작7)

> 확정되면 **이 문서를 고친다.** 옛 안내가 고객에게 나가면 그게 2차 사고다.
> (이 문서 자체가 그 예다 — 종전 3단계 "승인 확인"이 실측에서 오답으로 뒤집혔다.)
