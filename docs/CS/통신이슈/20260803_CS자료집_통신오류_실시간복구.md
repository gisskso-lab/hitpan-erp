## 0. 🔴 CS가 가장 먼저 할 일 — 10초 판별

고객이 "접속이 안 된다"고 하면, **설명을 더 듣기 전에** CS가 직접 고객 주소를 브라우저로 엽니다.

```
https://{고객사아이디}.hitpan.kr
```

**화면에 뜨는 것으로 절반이 갈립니다.**

| 보이는 것 | 뜻 | 누구 문제 | 첫 마디 |
|---|---|---|---|
| **502** | 길은 뚫렸는데 끝의 프로그램이 꺼짐 | **고객 PC** | "컴퓨터가 켜져 있는지 봐주시겠어요?" |
| **1033 / 530** | 통신 프로그램이 아예 안 붙음 | **본사 확인 필요** | "확인해서 연락드리겠습니다" |
| **로그인 화면이 뜸** | 통신은 정상 | 다른 문제 | §3 으로 |
| **아무것도 안 뜸 / 주소 없음** | 도메인 미발급 | 본사 | §4 로 |

> ⭐ **502 와 1033 을 가르는 것이 CS 업무의 전부입니다.**
> 502 는 고객이 스스로 해결합니다. 1033 은 고객이 뭘 해도 안 됩니다.

## 1. 502 — "컴퓨터를 켜주세요"

**뜻**: 통신 길은 살아 있는데, 그 끝에서 히트판이 안 돌고 있습니다.

**원인은 셋 중 하나입니다:**
1. 고객 PC 가 꺼져 있음 ← **대부분 이것**
2. PC 는 켜져 있는데 히트판이 멈춤
3. 히트판은 도는데 화면 담당 부분만 멈춤

**고객 안내:**
> "히트판이 설치된 컴퓨터가 켜져 있는지 확인 부탁드립니다.
>  히트판은 그 컴퓨터에서 직접 돌아가기 때문에, 컴퓨터가 꺼지면 접속이 안 됩니다."

**켜져 있다는데도 502 면:**
> "컴퓨터를 한 번 다시 시작해 주시겠어요? 자료는 그대로 있습니다."

**재부팅은 안전할 뿐 아니라 권장됩니다.** 히트판 감시 프로그램이 재시작을 복구 기회로 쓰도록 만들어져 있어서, 켜지면서 통신을 스스로 점검하고 고칩니다.

## 2. 1033 / 530 — "확인해서 연락드리겠습니다"

**뜻**: 고객 PC 의 통신 연결 프로그램이 본사 통신망에 **아예 안 붙어 있습니다.**

🔴 **고객이 뭘 해도 안 됩니다.** 재부팅해도, 재설치해도 안 될 수 있습니다.
**절대 "다시 설치해 보세요"라고 먼저 말하지 마십시오.** (§8 참조 — 8/03 이후 바뀐 부분)

**고객 안내:**
> "확인해서 곧 연락드리겠습니다. 그동안 컴퓨터는 켜두시면 됩니다."

**본사 확인 절차 (CS → 기술 담당 전달용):**

| 확인 | 방법 | 판정 |
|---|---|---|
| 통신망에 붙어 있나 | Cloudflare 대시보드 → 해당 터널 → **`복제본`** 칸 | **1** = 붙음(502 쪽) / **0** = 안 붙음(1033) |
| 자동 복구가 도는가 | 최소 3분 기다려 보기 | 감시 프로그램이 60초마다 점검, 3회 실패해야 복구 시작 |

**⏱ 자동 복구 소요 — 고객에게 시간을 약속할 때 주의:**

```
감시 주기        60초
복구 시작 조건   3회 연속 실패 = 최소 3분
실제 사고 사례   7분 14초까지 걸린 적 있음
```

> "5분 안에 복구됩니다"는 **목표이지 보장이 아닙니다.** 고객에게는
> **"보통 몇 분 안에 저절로 복구됩니다"** 정도로만 말하십시오.

## 3. 화면은 뜨는데 로그인이 안 될 때

**"서버에 연결할 수 없습니다"** 라는 메시지가 로그인 버튼을 누른 뒤 나옵니다.

⭐ **이건 통신 문제가 아닙니다.** 화면이 떴다는 건 통신이 살아 있다는 뜻입니다.

**판별:**

| 언제 나오나 | 뜻 |
|---|---|
| 화면 자체가 안 뜸 | 통신 문제 → §1·§2 |
| **화면은 떴는데 로그인 누르면** | 프로그램 설정 문제 → 본사 |

**고객 안내:**
> "화면은 뜨는데 로그인만 안 되시는 거군요. 본사에서 확인하겠습니다."

## 4. 업데이트 중에는 잠깐 접속이 끊깁니다 ⭐ 신규

> **2026-08-03 실측으로 확인된, 앞으로 가장 많이 들어올 문의입니다.**

히트판은 새 버전이 나오면 **밤에 저절로 업데이트**됩니다. 그 2~3분 동안 접속이 끊깁니다.

**고객이 보는 것:**
```
"서버에 연결할 수 없습니다"
사이트에 연결할 수 없음
```

**이건 고장이 아닙니다. 정상 동작입니다.**

실제 순서(8/03 실측):
```
① 자료 자동 백업        ← 먼저 백업합니다
② 안전장치 등록          ← 중간에 꺼져도 복구되게
③ 히트판 잠시 종료       ← 이때 접속 끊김
④ 새 버전으로 교체
⑤ 자동으로 다시 시작
⑥ 접속 복구
```

**고객 안내:**
> "업데이트가 진행 중이어서 잠시 접속이 안 되는 것입니다.
>  자료는 먼저 백업되니 걱정하지 않으셔도 됩니다.
>  2~3분 뒤에 다시 접속해 주시겠어요?"

**🔴 CS 주의:** 고객이 이때 **컴퓨터를 강제로 끄거나 재설치하면 안 됩니다.**
교체 도중에 끊으면 반쪽 상태로 남습니다. **기다리는 게 맞습니다.**

**3분 지나도 안 되면** 그때 본사로 넘기십시오.

## 6. 고객이 해도 되는 것 / 절대 안 되는 것

### ✅ 안전 — 안내해도 됩니다

| 조치 | 왜 안전한가 |
|---|---|
| **컴퓨터 재시작** | 감시 프로그램이 재시작을 복구 기회로 씁니다. 자료 그대로 |
| **컴퓨터 켜기** (502) | 502 의 표준 해결책 |
| **다른 브라우저로 열어보기** | 아무것도 안 바꿉니다 |
| **화면 위 "1클릭 봉합" 단추** | 다시 확인만 합니다. 지우거나 바꾸는 동작 없음 |

### ⛔ 절대 안내하면 안 되는 것

| 조치 | 무슨 일이 나는가 |
|---|---|
| **설정 파일(db.conf) 열기·수정·삭제** | 🔴 **연쇄 붕괴.** 통신 주소·열쇠·포트가 전부 이 파일 하나에 있습니다. 지우면 **감시 프로그램이 고장을 고장으로 못 봅니다** — 터널이 죽어도 "정상"으로 판정합니다 |
| **설치 폴더 파일 삭제** | 통신 프로그램 파일이 없으면 자동 복구가 **물리적으로 불가능**해집니다 |
| **데이터베이스 비밀번호 변경** | 백업·업데이트가 조용히 실패합니다. 지원 불가 |
| **관리자 권한 없이 설치** | 반드시 실패합니다 |
| **덮어 재설치 반복** | 실행 중인 파일을 못 지워서 새·옛 파일이 섞입니다 |

### ⏸ 결재 전까지 안내 금지

**명령 프롬프트로 통신 프로그램 수동 시작** (`sc start ...`)
→ 실측에서 이걸로 1033 이 풀린 적이 있으나, **고객에게 안내해도 되는지 결재가 없습니다.**
   고객 노출 영역에 개발용어를 쓰지 않는다는 원칙과도 충돌합니다. **사장님 결재 전까지 금지.**
