## 이 폴더가 따로 있는 이유

통신·접속 문의는 **고객이 가장 무서워하는 문의**다.
"프로그램이 안 열려요" 는 곧 **업무가 멈췄다**는 뜻이고, 1분이 급하다.

그런데 이 영역은 원인이 **고객 PC · 인터넷 · 본사 설정** 셋에 걸쳐 있어
CS 가 원인을 모른 채 *"재설치해보세요"* 를 던지기 쉽다.
**그게 최악이다** — 고객 시간을 버리고, 되지도 않는다.

⇒ 그래서 **기술 진단서를 근거로**, 고객이 겪는 증상별로 정리해 관리한다.

## 원칙 (사장님 헌법)

| # | 원칙 |
|---|---|
| 1 | **CS 지식은 히트판 만든 사람이 직접 정의한다.** 외부에서 긁어오지 않는다 |
| 2 | **개발용어·영어·외래어 금지** (헌법 #23·#24) — 터널·토큰·DNS·API·부트스트랩 노출 0 |
| 3 | **고객이 실제로 쓰는 표현 그대로 받는다** — "안 열려요", "에러 떠요" |
| 4 | **모르면 모른다고 한다.** 억지 안내 금지 — 본사 확인이 필요하면 그렇게 말한다 |
| 5 | **"재설치해보세요" 선반사 금지** — 덮어 재설치는 존재하지 않는 경로(사장님 못박음 2026-07-15).<br>⚠️ **단 1033 은 예외** — 옛 버전 설치본이 원인이므로 **최신본 재설치가 정답**이다(실측 확정 2026-07-30). "아무 생각 없이 던지는 재설치"가 금지 대상이고, **근거 있는 최신본 재설치는 해결책**이다 |
| 6 | **책임 경계 명시** (헌법 #24) — 본사 / 고객 / 제3자(통신사·백신) |

## 문서 규칙

```
{증상 한글 키워드}_{화면에 뜨는 것}.md
예: 설치후_접속안됨_Error1033.md
```

- 문서 첫 줄은 **고객이 보는 화면 그대로** 적는다(코드·용어 아님)
- 각 문서에 **기술 근거 문서 주소**를 반드시 링크한다(참조식 — 내용 복사 금지)
- 기술 진단이 바뀌면 **이 문서도 같이 고친다**(옛 안내가 고객에게 나가면 사고)
