# CS 자료집 — 로그인이 막혔을 때 (기기 잠김 탈출)

| 항목 | 내용 |
|---|---|
| 근거 | 사장님 실측 사고 2026-08-11 · *"이런문제들이 고객사에 생길수 있겠어 보니까"* |
| 작성 | CS팀장 강지원 |
| 대상 | 본사·대리점 상담원 (고객 응대 중 보는 문서) |
| 등급 | 🔴 **최우선** — 고객이 히트판에 아예 못 들어가는 상황 |

---

# §0. 이 문서를 언제 여나

고객이 이렇게 말할 때:

> *"로그인이 안 돼요"* · *"폐기된 기기래요"* · *"인증기기 한도초과라고 떠요"*
> *"아이디 비밀번호 맞는데 안 들어가져요"*

🔴 **비밀번호 문제가 아닙니다.** 기기 판정에 막힌 것입니다.

---

# §1. 실제로 있었던 일 (2026-08-11)

사장님 실측 중 **메인PC(회사 서버)가 폐기 상태**가 되었다.

```
로그인 시도 → "폐기된 기기입니다. 관리자에게 문의하세요."
```

**그런데 빠져나갈 길이 전부 막혀 있었다:**

| 시도한 것 | 결과 |
|---|---|
| 다른 PC 로 로그인 | 같은 화면 (관리자만 풀 수 있는데 그 관리자가 못 들어감) |
| `localhost` 로 접속 | 안 됨 |
| 명령창에서 DB 수정 | 권한·비밀번호 벽 |
| 업데이트로 고치기 | 🔴 **팝업이 로그인 후에 떠서 도달 불가** |

⇒ **고치는 수단 자체가 잠겼다.** 봉합은 새 버전 안에 있는데,
그걸 받으려면 로그인해야 하고, 그 로그인이 막혀 있었다.

🔴 **이것이 고객사에서 나면 그 회사는 업무가 멈춘다.**

---

# §2. 고객이 갇히는 경로 3가지 (코드 확인분)

| # | 화면 문구 | 왜 나나 |
|---|---|---|
| **1** | **"폐기된 기기입니다. 관리자에게 문의하세요."** | 그 기기가 `revoked` 상태 |
| **2** | **"인증기기 한도초과. 관리자에게 문의하세요."** | 슬롯이 다 참 (PC 5대 / 모바일 3대 기준) |
| **3** | **"기기 승인 대기 중입니다."** | 승인제가 켜져 있고 아직 승인 안 됨 |

## 🔴 가장 위험한 조합

**대표계정이 쓰는 그 PC 가 1·2·3 에 걸리는 경우.**

기기를 풀어줄 수 있는 사람은 대표계정뿐인데, **그 대표계정이 못 들어옵니다.**
직원이 아무리 많아도 소용없습니다.

---

# §3. 🟢 1.2.67 부터 — 스스로 빠져나올 수 있다

## 3-1. 로그인 화면에 업데이트 버튼이 생겼다

```
┌─────────────────────────────┐
│  히트판 ERP                  │
│  ⓘ 새 버전(1.2.xx)이 준비…   │
│     [ 지금 업데이트 ]         │  ← 로그인 안 해도 눌린다
│  아이디 [          ]          │
│  비밀번호 [        ]          │
└─────────────────────────────┘
```

**로그인이 막혀도 이 버튼은 눌립니다.** 새 버전에 봉합이 들어 있으면 그것으로 풀립니다.

⚠️ **그 PC 앞에 앉아서**만 눌립니다(원격·터널로는 안 보입니다). 보안 때문입니다.

## 3-2. 메인PC 는 이제 폐기되지 않는다

메인PC(회사 서버)는 **DB 차원에서 보호**됩니다.

- 폐기하려 해도 자동으로 되돌아감
- 이미 폐기돼 있던 것도 업데이트 때 되살아남
- 폐기 상태여도 **로그인은 통과**

⇒ §1 의 사고는 **1.2.67 부터 구조적으로 안 납니다.**

# §4. 상담 순서 (이 순서대로 물어본다)

## 1단계 — 어느 문구인지 확인

> **"화면에 뜬 글자를 그대로 읽어주시겠어요?"**

| 고객이 읽은 문구 | 가는 곳 |
|---|---|
| 폐기된 기기입니다 | §5-1 |
| 인증기기 한도초과 | §5-2 |
| 기기 승인 대기 중 | §5-3 |
| 비밀번호가 올바르지… | 🟢 기기 문제 아님 — 비밀번호 재설정 |

## 2단계 — 대표계정이 들어갈 수 있는지 확인

> **"대표님 계정으로는 들어가지시나요?"**

- **들어감** → 🟢 §5 로. 대표가 화면에서 풀 수 있습니다
- **못 들어감** → 🔴 **갇힘** → §6 으로

## 3단계 — 버전 확인

> **"화면 왼쪽 아래에 '버전' 이라고 적힌 숫자를 읽어주세요"**

- **1.2.67 이상** → §6-1 (스스로 탈출 가능)
- **1.2.66 이하** → §6-2 (원격지원 필요)

# §5. 대표계정이 들어가는 경우 — 화면에서 해결

## 5-1. 폐기된 기기

```
설정관리 → 등록 기기 관리 → 그 기기 찾기
```
폐기된 기기는 목록에 남아 있습니다. **자물쇠(🔒)가 있는 회사 서버는 원래 못 지웁니다.**

⚠️ 폐기를 되돌리는 화면 기능은 **아직 없습니다**(1.2.67 기준).
⇒ 지금은 §6 원격지원으로 처리합니다. **화면 기능 추가는 다음 차수 대상입니다.**

## 5-2. 한도초과

```
설정관리 → 등록 기기 관리
```
안 쓰는 기기를 **폐기(⊘)** 하면 자리가 납니다.

> **"안 쓰시는 컴퓨터나 휴대폰이 목록에 있으면 그것부터 정리해 주세요."**

슬롯을 늘리려면 **1개당 1만원**입니다(대표계정 화면에서 안내가 뜹니다).

## 5-3. 승인 대기

```
설정관리 → 등록 기기 관리 → 승인
```
승인하면 **인증 번호**가 화면에 뜹니다. 그 번호를 **직원에게 알려주면** 직원이 입력해서 들어갑니다.

> ⚠️ 번호는 **대표님이 직접 전달**하셔야 합니다. 시스템이 대신 보내지 않습니다.
> 그래야 그 사람이 진짜 우리 직원인지 대표님이 확인하게 됩니다.

# §6. 🔴 아무도 못 들어가는 경우 (갇힘)

## 6-1. 1.2.67 이상 — 스스로 탈출

> **"히트판이 설치된 그 컴퓨터 앞으로 가주세요."**
> **"로그인 화면 위쪽에 '새 버전이 준비되었습니다' 라고 보이시나요?"**

- **보임** → **[지금 업데이트]** 를 누르시면 됩니다. 몇 분 뒤 다시 켜집니다
- **안 보임** → 아직 새 버전이 안 내려온 것입니다 → §6-2

## 6-2. 원격지원 (상담원 작업)

🔴 **여기서부터는 상담원이 직접 그 PC 를 봅니다.**

### 준비 — DB 접속 정보는 그 PC 안에 있다

⚠️ **비밀번호는 고객사마다 다릅니다.** 공통 비밀번호는 없습니다.

명령 프롬프트를 **관리자 권한으로** 열고:

```
type "C:\Program Files\HitPan\db.conf"
```

여기서 **`DB_NAME` · `DB_USER` · `DB_PASSWORD`** 세 줄을 확인합니다.

> 🔴 **이 파일에는 암호화 키·터널 토큰도 함께 들어 있습니다.**
> **화면을 공유 중이면 고객에게 보입니다.** 반드시 고객 화면 공유를 끄거나,
> 그 부분을 가린 뒤 진행하십시오. **캡처·붙여넣기 금지.**

### 폐기 풀기

```
"C:\Program Files\MariaDB 11.4\bin\mysql.exe" -u (DB_USER) -p(DB_PASSWORD) (DB_NAME) -e "UPDATE tenant_devices SET status='approved' WHERE is_main_pc=1 AND status='revoked'; SELECT device_name, status, is_main_pc FROM tenant_devices;"
```

⚠️ `-p` 와 비밀번호는 **붙여서** 씁니다 (`-pabc123`).

**결과에서 `status` 가 `approved` 면 성공.** 바로 로그인해 보시라고 안내합니다.

### 한도초과 풀기 (안 쓰는 기기 정리)

```
"C:\Program Files\MariaDB 11.4\bin\mysql.exe" -u (DB_USER) -p(DB_PASSWORD) (DB_NAME) -e "SELECT device_id, device_name, device_type, status, is_main_pc FROM tenant_devices;"
```

목록을 **고객과 함께 보고**, 안 쓰는 기기를 확인한 뒤:

```
"C:\Program Files\MariaDB 11.4\bin\mysql.exe" -u (DB_USER) -p(DB_PASSWORD) (DB_NAME) -e "UPDATE tenant_devices SET status='revoked' WHERE device_id='(고객이 지목한 값)';"
```

🔴 **고객이 지목하지 않은 기기는 절대 건드리지 않습니다.** 남의 PC 를 끊는 셈이 됩니다.

---

# §7. 🚫 절대 하지 말 것

| 금지 | 왜 |
|---|---|
| `DELETE FROM tenant_devices` | 기록이 사라져 나중에 추적 불가 (헌법 #1) |
| 고객 동의 없이 기기 폐기 | 남의 업무를 끊는 것 |
| `db.conf` 내용을 메신저·메일로 전달 | 암호화 키가 함께 유출됨 |
| 비밀번호를 문서·메모에 적기 | 고객사마다 다르고, 남기면 유출 경로 |
| 재설치 권유 | **덮어 재설치는 존재하지 않는 경로**(사장님 못박음). 자료가 위험해짐 |

# §8. 예방 — 고객에게 미리 안내할 것

> **"기기를 정리하실 때 회사 서버(자료가 든 컴퓨터)는 건드리지 마세요."**

1.2.67 부터는 시스템이 막지만, **그 이전 버전 고객에게는 미리 말해두는 것이 안전**합니다.

목록에서 **자물쇠(🔒)** 가 붙은 줄이 회사 서버입니다.

# §9. 🔴 아직 안 된 것 (상담원이 알고 있어야 할 한계)

| 항목 | 현황 |
|---|---|
| 폐기 되돌리기 **화면 기능** | ❌ 없음 — §6-2 원격지원으로만 |
| 기기 이름이 비어 있는 경우 | ⚠️ `(이름없음)` 으로 보여 **어느 PC 인지 구분 안 됨** |
| 1.2.66 이하에서 갇힘 | ❌ 스스로 탈출 불가 — 원격지원 필수 |

⇒ 이 셋은 **다음 차수 개선 대상**입니다. 지금은 위 절차로 대응합니다.

# §10. 에스컬레이션 기준

이럴 때는 **본사로 넘깁니다**:

- `db.conf` 를 못 찾음 (설치 경로가 다름)
- 명령을 실행했는데 `Access denied` 가 계속 남
- 메인PC 가 **목록에 아예 없음** (등록 자체가 안 된 상태)
- 고객 자료가 이미 손상된 정황

⚠️ **모르면 넘깁니다.** CS 20년에서 가장 큰 사고는 **모르면서 아는 척한 조치**입니다.
DB 를 잘못 건드리면 고객 자료가 틀어지고, 그건 되돌릴 수 없습니다.
