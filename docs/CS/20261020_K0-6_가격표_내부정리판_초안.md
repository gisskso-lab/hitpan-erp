## §1 🔴 먼저 — **금액의 집은 문서가 아니다**

| | 어디 |
|---|---|
| 🟢 **금액이 사는 곳** | 본사 운영 화면에서 정하고, 그 값이 **가입·안내 화면에 그대로 반영**된다 |
| 🟢 **실측** | 요금제 표에 **이름 · 월 금액 · 포함 계정 수** 칸이 이미 있다(`pricing_plans`) · 대리점 **수수료율 칸**도 있다 |
| 🔴 **금액이 살면 안 되는 곳** | 이 문서 · 소개서 · 제안서 · 설치 파일 · 코드 · 시드 자료 |
| 🔴 **왜** | 가격이 문서에 적히면 **바꿀 때마다 자료를 다시 돌려야 하고**, 어느 숫자가 참인지 **아무도 모르게 된다** |

⚠️ **지금 레포에는 서로 다른 숫자 두 판이 남아 있다.** 그래서 이 문서는 **어느 쪽도 적지 않는다.**
🔴 **숫자가 필요하면 문서를 보지 말고 본사 안내 화면을 본다.**

## §2 구간 틀 — **칸만** 만든다 (금액은 ⬜)

| 구간 | 포함 계정 수 | 월 금액 | 누구에게 |
|---|---|---|---|
| 1구간 | **소수 계정** | ⬜ | 사장님 + 사무 1~2명 |
| 2구간 | **중간 계정** | ⬜ | 사무·영업·생산 관리자가 각자 쓰는 회사 |
| 계정 추가 | **1계정 단위** | ⬜ | 구간을 넘길 때 |
| 휴대전화 | **세지 않는다** | **받지 않는다** | PC 계정과 **함께** 쓸 수 있다 |

🔴 **구간 이름을 지금 정하지 않는다** — 이름이 먼저 퍼지면 금액이 확정될 때 바꾸기 어렵다.

### 과금 단위 — 이것만은 확정이다
| | |
|---|---|
| 🟢 **단위 = 계정(아이디) 수** | **직원 수가 아니다.** 히트판을 켜지 않는 직원은 **사원으로만** 넣으면 요금에 안 들어간다 |
| 🟢 **계정 수 = 동시에 쓰는 PC 수** | 한 아이디를 여러 PC 가 동시에 쓰지는 못한다 |
| 🔴 **버린 축 = 기기(대수) 과금** | 다시 꺼내지 않는다 — 기기를 세는 방식은 **분쟁이 되고**, 지난 자료에 남아 있는 「1대 / 무제한」 표현은 **폐기된 것**이다 |

## §3 대리점 — 수수료

| | |
|---|---|
| 🟢 **구조** | 정산 결과에 **수수료율**이 건별로 기록된다(칸 실재) |
| 🔴🔴 **정하는 사람 — 지금은 「없다」** | 🔴 **본사가 정한 값이 정산에 반영되지 않는다.** 정산 계산이 **한 비율로 고정**돼 있고(`ResellerSettlementCalculator.cs:65`), 대리점 표의 수수료율 칸을 **읽는 코드가 0건**이다. 🔴 그 칸에 값을 **저장하는 코드도 0건**이다 ⇒ **화면에서 정해도 정산은 안 바뀐다**(별건 상신 — §6) |
| ⬜ **비율** | **미정** — 이 문서에 적지 않는다. 🔴 **그러나 「정하지 않으면 안 나간다」가 아니다** — 고정값으로 계산된다 |
| ⚠️ **표현이 두 가지다** | 🔴 한쪽은 **퍼센트 꼴**(`DB-02_3tier_schema.sql:35` 15.00 = 15%), 다른 쪽은 **비율 꼴**(`00_backoffice_core.sql:633` 소수 4자리 · 정산 화면이 `×100%` 로 그린다) ⇒ **같은 숫자를 두 뜻으로 읽을 수 있다.** 비율을 정할 때 **어느 꼴인지 함께** 정해야 한다 |
| 🔴 **금지** | 상담 자리에서 비율을 **입으로 약속**하기 — 정산 분쟁의 1번 원인이고, **지금은 약속해도 그 값으로 계산되지 않는다** |

### 🔴 §3-1 내가 틀렸던 자리 (기록으로 남긴다)

1판에 *"본사가 운영 화면에서 구간으로 정한다"* 라고 🟢 로 적었다. **근거가 코드가 아니라 주석이었다.**
`ResellerSettlementCalculator.cs:14` 주석은 *"commission_amount = gross × (resellers.commission_rate ?? 기본 0.15)"* 라고 적혀 있지만,
🔴 **같은 파일 `:65` 는 `resellers.commission_rate` 를 아예 읽지 않는다.** 주석과 코드가 다르고, 나는 **주석을 받아썼다.**
⇒ **교훈: 「된다」는 주석이 아니라 그 값을 읽는 줄로 확인한다.**

## §6 🔴 별건 상신 — **대리점 수수료가 설정대로 계산되지 않는다**

| | |
|---|---|
| 증상 | 정산 계산이 **고정 비율**로 돈다 — 대리점별 수수료율을 **읽지 않는다** |
| 실측 | `ResellerSettlementCalculator.cs:65`(고정값 사용) · 대리점 표 수수료율 칸을 **읽는 코드 0건 · 저장하는 코드 0건** |
| 왜 중요한가 | 🔴 **대리점마다 다른 비율을 약속하면 정산이 그와 다르게 나온다 = 수금 분쟁** |
| 성격 | **제품 결함**이다 — 자료(K0) 차수 범위 밖 ⇒ **별건 트랙 + 결재** |
| 지금 자료가 할 일 | 🔴 **비율을 어디에도 적지 않고, 입으로도 약속하지 않는다**(§3·§4) |
