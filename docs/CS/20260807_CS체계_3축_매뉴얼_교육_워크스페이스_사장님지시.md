## 0. 사장님 지시 원문 (가공 없음 · 시간순)

> **①** *"그 오류 대응에 대한 부분을 실제 사람인 CS직원이 원격으로 파워쉘을 열어
> 복사->붙여넣기 할 수 있을 수준의 **초등학생도 할수 있는 메뉴얼**을 만드는 것이 목표임.
> 기존의 히트판 CS직원은 **윈도우애플리케이션의 엑세스db 로컬네트워크 버젼체계**라
> 터널링을 통한 **로컬+웹 하이브리드 히트판의 CS에 적응도 못하고 지식도 없음**"*

> **②** *"**교육이 필요함**"*

> **③** *"그리고 보다 **쉬운 CS워크스페이스를 구축**해야함."*

## 1. 이 세 지시가 하나의 그림이다

**매뉴얼 하나로는 안 된다.** 사장님이 세 문장으로 그것을 말씀하셨다.

```
        [지금 있는 것]                    [있어야 하는 것]

   Access DB · 로컬 네트워크                터널링 · 로컬+웹 하이브리드
   20년 경력 CS 직원                        처음 보는 구조
            │                                      │
            └──────────── 이 간격 ─────────────────┘
                            │
        ┌───────────────────┼───────────────────┐
        │                   │                   │
   ① 매뉴얼            ② 교육              ③ 워크스페이스
   따라만 하면 됨      사람을 올린다        도구를 낮춘다
```

| 축 | 하는 일 | 없으면 |
|---|---|---|
| **① 매뉴얼** | 그 순간 무엇을 할지 알려준다 | 아무것도 못 한다 |
| **② 교육** | 매뉴얼을 **읽을 수 있는 사람**으로 만든다 | 매뉴얼이 있어도 못 읽는다 |
| **③ 워크스페이스** | 매뉴얼이 필요한 상황 자체를 줄인다 | 매뉴얼과 교육에만 매달린다 |

**셋 다 있어야 만난다.** 매뉴얼만 잘 써도, 교육만 시켜도 안 된다.

## 2. 왜 기존 CS 직원이 못 하는가 — 구조를 정확히

사장님이 지적하신 것은 "직원이 부족하다"가 아니라 **"구조가 바뀌었다"** 이다.

| | 레거시 히트판 | 새 히트판 |
|---|---|---|
| 프로그램 | 윈도우 프로그램 | 윈도우 프로그램 **+ 웹 화면** |
| 자료 보관 | Access 파일 | MariaDB (고객 PC) |
| 접속 | 사무실 안 네트워크 | **터널을 통해 인터넷 주소로** |
| 고장 지점 | 파일 / 공유 폴더 | 프로그램 · 자료보관함 · **터널** · 감시 프로그램 · 업데이트 |
| 진단 도구 | 파일 열어보기 | **명령 창** |

**고장 날 수 있는 자리가 2개에서 5개로 늘었다.**
그리고 그중 3개(터널·감시 프로그램·업데이트)는 **레거시에 존재하지 않던 것**이다.

> 20년 경력이 도움이 안 되는 게 아니다.
> **경력이 가리키는 곳에 이제 아무것도 없는 것**이다.

## 3. ① 매뉴얼 — "초등학생도 할 수 있는" 기준

### 3-1. 판정 기준 (사장님 원문에서 도출)

> **"원격으로 파워쉘을 열어 복사→붙여넣기 할 수 있을 수준"**

| 기준 | 내용 |
|---|---|
| **판단을 요구하지 않는다** | *"상황을 보고 판단하세요"* 금지. 예/아니오 질문으로 쪼갠다 |
| **명령 창 여는 것부터** | *"관리자 권한 PowerShell을 열고"* 로 시작하면 안 된다. 그걸 못 연다 |
| **한 번 붙여넣기 = 한 가지 확인** | 여러 명령을 한 덩어리에 넣지 않는다 |
| **예상 출력을 글자 그대로** | *"정상이면 healthy 가 보입니다"* 수준으로 구체적으로 |
| **막다른 길 없음** | 모든 갈래에 다음 행동이 있다. 마지막은 항상 "본사로 넘긴다" |
| **원리를 가르치지 않는다** | ❌ *"터널이 5257 포트로 프록시"* → ✅ *"히트판이 켜져 있는지 확인합니다"* |
| **용어 하나로 고정** | 감시 프로그램 / 워치독 / HitPan.Watchdog → **하나만 쓴다** |

### 3-2. 8/07 매뉴얼의 현재 수준 — 재작성 필요

오늘 만든 [CS대응매뉴얼](20260807_CS대응매뉴얼_배포_설치_통신_업데이트_원격지원.md)(1,269줄)은
**"이해하면 따라올 수 있는 사람"** 을 독자로 썼다. 사장님이 지정하신 독자와 다르다.

**다만 버리지 않는다.** 그 안의 **사실**(경로·명령·과거 사고 54건)은 전부 유효하다.
**표현 방식만** 이 기준으로 다시 짠다.

⇒ 현재 CS팀이 **견본 2~3건**을 이 수준으로 작성 중이다. 그것이 전체 재작성의 틀이 된다.

## 4. ② 교육 — 사장님 지시 *"교육이 필요함"*

### 4-1. 왜 매뉴얼만으로 안 되는가

**매뉴얼은 혼자 읽고 이해해야 한다.** Access 시대 사람에게는 그것 자체가 벽이다.

| 매뉴얼이 못 하는 것 | 교육이 하는 것 |
|---|---|
| 처음 겪는 당황을 없애준다 | **미리 겪어보게 한다** |
| "왜 이렇게 하는지" 감을 준다 | 한 번 해보면 손에 남는다 |
| 매뉴얼에 없는 상황 대처 | **넘겨야 할 때를 안다** |
| 고객 앞에서의 말투 | 실습으로 익힌다 |

### 4-2. 교육이 다뤄야 할 것 (초안 — 확정 아님)

| # | 내용 | 왜 |
|---|---|---|
| 1 | **새 히트판이 레거시와 무엇이 다른가** | §2 표 한 장. 원리가 아니라 **고장 나는 자리가 늘었다**는 것만 |
| 2 | **명령 창 열고 붙여넣기** | 실습. 이것만 되면 매뉴얼의 절반이 열린다 |
| 3 | **정상 화면 눈에 익히기** | 정상을 모르면 비정상도 모른다 |
| 4 | **넘겨야 할 때** | 🔴 가장 중요. **모르면 아는 척하게 된다** |
| 5 | **하면 안 되는 것** | 고객 PC 에서 사고 나는 조작 |
| 6 | **고객 앞에서 쓰는 말** | 개발용어 금지가 몸에 배야 한다 |

### 4-3. 교육 형태 (미정 — 사장님 결정 사항)

- 문서 자습인가 / 영상인가 / 사장님이 직접 하시는가
- 시험·합격 기준을 둘 것인가 (CS팀 제안 8번)
- 베타 단계에는 상담원이 아직 없다 — **누구를 교육하는가**부터 정해야 한다

> ⚠️ **지금 단계에서 교육 대상이 없다.** 그러나 **교육 자료를 지금 만드는 것**은 의미가 있다 —
> 사람이 생겼을 때 만들기 시작하면 늦고, 지금 겪은 것이 가장 생생하다.

## 5. ③ CS 워크스페이스 — 사장님 지시 *"보다 쉬운"*

### 5-1. 이것이 근본 해결이다

매뉴얼과 교육은 **사람이 명령 창을 여는 것**을 전제한다.
**워크스페이스는 그 전제 자체를 없앤다.**

> **명령을 외워서 치는 대신, 화면에서 단추를 누른다.**

### 5-2. 지금 없는 것 (오늘 검증에서 드러난 것)

| 없는 것 | 근거 | 결과 |
|---|---|---|
| **고객 버전 조회 화면** | 설계팀 P1-6 | 기록은 쌓이는데 **볼 수 없다**(write-only) |
| 고객 상태 한눈에 보기 | — | 어느 고객이 막혔는지 모른다 |
| 원격 진단 실행 | — | 상담원이 고객 PC 에 직접 들어가야 한다 |
| 문의 기록 남기는 곳 | CS 제안 9번 | 같은 문의가 몇 번 왔는지 셀 수 없다 |

🔴 **오늘 두 사고가 같은 구조였다** — 8/02 대리점 설치 실패, 8/07 새 버전 미발견.
둘 다 **"고객이 말해주지 않았으면 아무도 몰랐다"** 이다.

### 5-3. "쉬운"의 뜻 — 히트판 정신 그대로

> **"이 화면, 처음 보는 사람이 혼자 쓸 수 있냐?"**

이 기준은 고객용 화면에만 적용되는 게 아니다. **CS 워크스페이스에도 똑같이 적용된다.**
Access 시대 직원이 앉아서 **설명서 없이** 쓸 수 있어야 한다.

### 5-4. 4대 과제 ③과 같은 자리

CS 워크스페이스는 **백오피스(`back.hitpan.kr`) 안**에 있어야 한다.
→ [4대 과제 ③ 랜딩·백오피스 수정·보완](../운영기록/20260807_사장님오더_배포CS후_다음단계_4대과제_로드맵.md)과 **한 몸**이다.

그리고 사장님 최우선 지시 **②(본사 워크스페이스 시스템이 안정적인가)** 와도 직결된다.

## 6. 세 축의 관계 — 서로 줄여준다

```
워크스페이스가 좋아지면  →  매뉴얼이 짧아진다  →  교육이 가벼워진다
        (단추로 되면)          (명령이 줄면)         (외울 게 줄면)
```

**반대도 성립한다** — 워크스페이스가 없으면 매뉴얼이 두꺼워지고 교육이 무거워진다.
지금 매뉴얼이 1,269줄인 이유가 그것이다.

⇒ **투자 우선순위는 워크스페이스가 가장 높다.** 다만 만드는 데 시간이 걸리므로,
그 사이를 매뉴얼과 교육이 메운다.
