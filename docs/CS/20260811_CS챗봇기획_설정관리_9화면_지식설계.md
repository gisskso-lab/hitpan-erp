> ① *"설정관리, 화면단 하나하나 개발하는 **개발문서·설계문서·검증문서 모두 학습**해!!!!!"*

**③이 이 기획의 뼈대다.** API 없이 답하려면 **답이 DB 에 미리 다 들어 있어야** 한다.
LLM 이 지어내는 게 아니라 **우리가 쓴 문장을 찾아서 보여주는** 구조다.
⇒ 이건 검색 문제이지 생성 문제가 아니다.

## 0-1. 🔴🔴 CS 챗봇 ≠ AI 도우미 연동 — 둘은 다른 물건이다

> 사장님 정정 (2026-08-11):
> *"히트판 **AI챗봇연동은 업무자동화, 업무분석, a업체 니즈에 맞는 B상품제안서 자동생성** 등의
>  **고도의 업무를 위한 도구**이지, **CS챗봇이 아니야.**"*
> *"**API연동은 그렇게 쓸거야.**"*
> *"**고객들이 히트판의 기능을 물어보려고 비싼 토큰을 쓰게 하지마.**"*

| | **CS 챗봇** (이 문서) | **AI 도우미 연동** (별건) |
|---|---|---|
| 용도 | 히트판 **사용법** 안내 | 업무자동화 · 업무분석 · **제안서 자동생성** |
| 동력 | **DB 검색** — API 없음 | **API 연동**(제미나이·오픈AI·클로드) |
| 비용 | **0원** | 토큰 과금 |
| 성격 | 필수 · 전 고객 | 고급 기능 |
| 질문 예 | *"기기 등록 어디서 해요"* | *"A업체 거래 분석해서 B상품 제안서 만들어줘"* |

🔴 **판정 기준: 답이 이미 정해져 있나?**
- **정해져 있다** → CS 챗봇. DB 에서 꺼낸다. **0원·즉시.**
- **매번 다르다** → AI 도우미. 그때 계산해야 하니 API 를 쓴다.

⚠️ *"어디서 등록해요"* 는 **답이 정해진 질문**이다. 여기에 토큰을 태우면
**고객이 기능을 물어보다 요금을 낸다.** 낭비이면서 느리다.

⇒ **API 는 AI 가 아니면 못 하는 일에만 쓴다.**

### ✅ 사장님 확정 — **버튼 하나로 입구를 나눈다**

> *"**단순 CS챗봇이랑 고급기능챗봇이랑 버튼 하나로 구분해서 쓰게**"*
> *"**고객 토큰은 소중하니까**"*

```
┌─────────────────────┬─────────────────────┐
│  [사용법 물어보기]   │   [업무 도우미]      │
│  무료 · 0원          │   토큰 사용          │
│  답이 정해진 질문     │   AI가 계산할 질문    │
└─────────────────────┴─────────────────────┘
```

🔴 **왜 버튼이어야 하나 — 지금은 고객이 자기가 뭘 쓰는지 모른다.**
입구가 하나라 *"기기 등록 어디서 해요"* 를 쳐도 **무료인지 과금인지 알 수 없다.**
버튼으로 나누면 **누르는 순간 본인이 안다.**

🔴 **"고객 토큰은 소중하니까" 가 설계 원칙이다.**
토큰은 **고객 돈**이다. **고객 돈을 우리가 대신 쓰는 구조를 만들면 안 된다.**

**이 하나로 세 문제가 같이 풀린다**

| 문제 | 버튼 분리로 |
|---|---|
| KB 0건이라 CS 질문이 API 로 샌다(§1) | 입구가 다르니 **애초에 안 샌다** |
| 켬/끔 스위치가 CS 까지 죽일까(§5-9) | CS 버튼은 **스위치와 무관** |
| 고객이 비용을 예측 못 함 | 버튼에 **토큰 사용 여부 표시** |

⚠️ **현행 실측**: 상단 *"히트판에게 물어보세요 Ctrl+K"* 하나뿐이고
`api/chatbot/ask` 와 `api/chatbot/quota`(토큰 잔량)가 **같은 입구에 붙어 있다**
(`Layout/ChatbotBar.razor`). ⇒ **지금은 안 갈라져 있다. 갈라야 한다.**

⚠️ **PM 오류 기록**: 초안에서 §5-9 에 *"AI 도우미 연동"* 을 CS 챗봇 지식 대상으로 넣었다.
**그건 지식 항목이 아니라 별개 기능**이다. 둘을 한 덩어리로 보고 있었다.

## 3. 🔴 촘촘함의 기준 — "모든 질문" 을 어떻게 세나

*"모든 질문을 받을 수 있을만큼"* 은 검증 가능한 수로 바꿔야 한다.
안 그러면 **다 했다고 착각**한다.

### 화면 하나당 최소 6갈래 (강지원 20년 경험 기준)

| 갈래 | 질문 유형 | 예 (등록 기기 관리) |
|---|---|---|
| **① 어디** | 메뉴를 못 찾음 | *"기기 등록 어디서 해요"* |
| **② 어떻게** | 하는 법 | *"휴대폰 등록하려면요"* |
| **③ 왜 안 됨** | 막혔을 때 | *"기기 등록이 안 돼요"* |
| **④ 오류** | 화면에 뜬 메시지 | *"인증기기 한도초과라고 떠요"* |
| **⑤ 뜻** | 용어를 모름 | *"슬롯이 뭐예요"* |
| **⑥ 바꾸기** | 이미 한 걸 되돌림 | *"등록한 기기 지우고 싶어요"* |

⇒ **9화면 × 6갈래 = 최소 54건.**
여기에 화면별 고유 항목(회사정보 8필드 · 권한 항목 등)이 붙어 **목표 90~120건**.

### 🔴 ④번이 가장 중요하다

**고객은 오류 문구를 그대로 친다.** *"인증기기 한도초과. 관리자에게 문의하세요"* 를
통째로 복사해서 붙인다. 그래서 **화면에 뜨는 모든 안내 문구가 그대로 검색어**가 되어야 한다.

⇒ **작업 방법: 코드에서 고객 노출 문구를 전부 뽑아 `question_keywords` 에 넣는다.**
이게 API 없이도 답이 맞는 이유다.

## 4. API 없이 답하는 방식 (3단)

```
1단  정확 일치   화면 문구·메뉴명이 질문에 그대로 있나  → FULLTEXT
2단  키워드      question_keywords 부분 일치            → FULLTEXT
3단  못 찾음     "이 질문은 사람이 답해야 합니다" + 문의 안내
```

🔴 **3단이 핵심이다.** 못 찾았을 때 **지어내지 않는다.**
CS 20년에서 가장 큰 사고는 *모르는 것을 아는 척한 답변*이다.
고객이 그 답대로 하다 자료가 틀어지면 **신뢰가 한 번에 무너진다.**

⇒ **못 찾은 질문은 로그로 남긴다**(`ai_conversations`). 그게 **다음에 채울 지식 목록**이다.
**빈틈은 이 로그로 메운다** — 우리가 상상해서 메우는 게 아니다.

🔴 **3단에서도 API 로 넘기지 않는다.**
못 찾으면 *"이 질문은 사람이 답해야 합니다"* 로 끝내고 문의 안내를 준다.
API 로 넘기면 **답이 정해진 질문에 토큰이 나가는** 바로 그 구조가 된다(§0-1).

⇒ **CS 챗봇은 어떤 경로로도 과금되지 않는다.** 이것이 설계 불변 조건이다.

## 5. 화면별 지식 항목 (설정관리 9화면)

> 각 화면 = 6갈래 + 고유 항목. 아래는 **고유 항목**만 적는다.

### 5-1. 회사 정보 `/company`
- 사업자등록증 8필드가 **왜 수정이 안 되나** (🔴 가장 많이 올 질문 — 잠금이 의도다)
- 바꾸려면 어디로 (변경 요청 경로)
- 사업자등록증을 왜 보관하나 (법정 5년 · 국세기본법)

### 5-2. 직원 계정 관리 `/users`
- **대표계정 / 직원계정** 차이 (⚠️ 부모·자식 계정이라 하지 않는다)
- 계정 만들면 다음에 뭘 하나 → 권한 설정
- 비밀번호 초기화
- 🆕 **사원은 있는데 계정이 없는 경우** (MDB 마이그 직원 · 발급은 수동)

### 5-3. 권한 설정 `/users/permissions`
- 권한을 왜 직접 정해야 하나 (⚠️ 헌법 #11 — 업종별 템플릿 제공 안 함)
- 메뉴가 안 보이는 이유 = 권한
- 대표계정 권한은 못 바꾸는 이유

### 5-4. 등록 기기 관리 `/settings/devices`
- **슬롯이 무엇인가** (PC · 모바일 · 추가구매)
- *"인증기기 한도초과"* 대처
- 회사 서버가 목록에 뜨는 이유 · **왜 지울 수 없나**(자물쇠)
- 🆕 모바일 QR 등록 절차 · **아이폰 홈화면 추가 3단계**(애플 제약이라 자동 불가)
- 기기 폐기 방법

### 5-5. 사용환경 설정 `/settings`
🟡 문서가 얇다 → 내일 (2)번 코드리뷰 결과가 원천이 된다

### 5-6. 양식(인쇄)정보 `/print-settings`
- **순백지 / 양식용지** 차이 (🔴 레거시 히트판 쓰던 고객이 반드시 묻는다)
- 인쇄가 밀려서 나올 때 (여백 mm)

### 5-7. 양식 템플릿 `/settings/form-templates`
- 6대 양식이 각각 무엇인가
- 기본 양식 지정
- 좌표가 안 맞을 때

### 5-8. 이메일(SMTP) `/settings/email`
- 네이버·구글 설정값
- **앱 비밀번호**가 무엇인가 (🔴 여기서 대부분 막힌다)
- 발송 실패 원인

### 5-9. AI 도우미 연동 `/settings/ai-assistant`

🔴 **이 화면은 CS 챗봇의 "지식 대상" 이지 "동력" 이 아니다.**
CS 챗봇은 이 화면을 **설명만** 한다 — 여기에 API 를 쓰지 않는다.

**CS 챗봇이 답할 것** (DB 검색 · 0원)
- AI 도우미가 **무엇을 하는 기능인가** (업무자동화·업무분석·제안서 생성)
- 연동을 **어디서 켜나**
- API 키를 **어디서 받나**
- 🔴 **"이거 쓰면 돈이 나가나요"** ← 가장 많이 올 질문. **비용 구조를 정직하게 답해야 한다**

**CS 챗봇이 답하지 않을 것**
- 실제 업무 분석·제안서 생성 → 그건 **AI 도우미 본체가 하는 일**

🔴 문서 0건 — 내일 (6)번 작업 후 개발명세서 작성 필요. **없는 것은 학습할 수 없다.**
⬜ API 키를 고객사가 넣나 본사가 대행하나 **결재 선행**

### 🆕 사장님 지시 — **AI API 토큰 켬/끔** (내일 (6)번에 포함)

> *"내일 시작할 설정관리 파트5에 ai연동 영역에 **AI API토큰 켬/끔 기능**을 추가해서 넣어야 겠어."*

🔴 **이 스위치가 §1 에서 찾은 문제의 안전장치다.**

지금은 KB 가 0건이라 **모든 질문이 API 로 나간다**(`ChatbotService.cs:116`).
스위치를 끄면 **그 경로가 막히고 토큰이 0원**이 된다.

**왜 필요한가 — 세 가지**
1. **고객 보호** — 사장님: *"기능 물어보려고 비싼 토큰 쓰게 하지마"*. 끄면 물리적으로 못 쓴다
2. **비용 상한** — 고객이 스스로 요금을 통제한다. 안 쓰는 회사는 아예 꺼둔다
3. **우리 개발 중** — 챕터4 `DeviceApproval:Enabled` 와 같은 이유.
   테스트하다 토큰을 태우는 사고를 막는다

**CS 챗봇과의 관계 (중요)**
```
스위치 ON   → CS 질문은 KB(0원) · AI 도우미는 API 사용
스위치 OFF  → CS 질문은 KB(0원) 그대로 · AI 도우미만 멈춤
```
🔴 **끈다고 CS 챗봇이 죽으면 안 된다.** CS 는 애초에 API 를 안 쓰기 때문이다(§0-1).
⇒ **이게 두 기능이 갈라져 있는지 확인하는 시험지**이기도 하다.
끄고 나서 *"기기 등록 어디서 해요"* 가 안 되면 **둘이 안 갈라져 있다는 증거**다.

⚠️ 지금은 KB 가 비어 있어 **끄면 CS 도 답을 못 한다** — 그건 스위치 문제가 아니라 **KB 0건 문제**다.

⬜ **확인 필요**: 끄기 단위가 **고객사 전체**인가 **직원별**인가.
직원별이면 *"김대리만 쓸 수 있게"* 가 되는데, 그러면 권한 설정과 물린다.
