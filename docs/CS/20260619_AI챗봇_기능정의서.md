# 히트판 AI 챗봇 — 기능정의서 (실행 명세)
> 문서번호: 20260619-FUNC-AI
> 작성: PM 브라운킴 (2026-06-19 하브루타 기준, 사장님 "지금 걸로 반영")
> 범위: 현재 히트판 ERP 내 AI 챗봇. **오픈마켓 셀러버전 제외.**
> 형식: 자연어 명령 → 기능 실행 수준의 실행 명세 (intent/경로/action/파라미터/검증/확인멘트/되묻기).

---

## 1. 전체 구조 — 3층 + 두 얼굴
- **3층**: ①데이터(히트판 DB, 정확) ②분석 메뉴(검증된 집계, 안 틀림) ③Claude(해석·예측·판단). Claude는 SQL 안 짬.
- **두 얼굴**: ⓐ 고객사 AI 직원(구매·자재·영업관리 + 능동 조언) / ⓑ CS 반자동(챗봇 1차 + 본사 인계).
- **불변 원칙**: AI는 준비, **실행은 사람**. 변경=확인 게이트. 권한=로그인 사용자 JWT.

---

## 2. AI 직원 동작 (REQ-A)

### 2.1 업무 실행 명세 (말로 시키면 준비, 사람이 실행)
| FN | intent 예시 | 경로 | action | 파라미터 | 검증·되묻기 | 확인·결과 |
|----|-----------|------|--------|---------|-----------|----------|
| FN-01 사원추가 | "김철수 사원 추가" | 설정→사원관리 | create(초안) | 이름·사번(수동,중복거부)·부서·계정(선택) | 사번 누락→"어떻게 매길까요(예 001)" | "등록합니다, 진행?"→사람승인→완료 |
| FN-02 거래처추가 | "신라상사 등록" | 마스터→업체관리 | create(초안) | 상호·사업자번호(형식검증)·**매입/매출 구분(필수)** | 구분 누락→"매입처/매출처?" | 승인→"신라상사(매입처) 등록" |
| FN-03 상품추가 | "사과 상품 등록" | 마스터→상품관리 | create(초안) | 상품명·품목코드·단위·**세율(과세/면세/영세)** | 세율 누락 되물음 | 승인→"등록(재고=0, 매입 시 증가)" |
| FN-04 발주 | "신라상사에 사과 100박스 발주" | 매입→발주 | create(초안) | 매입처·품목·수량·단가 | **선행조건**(거래처·상품)없으면 등록 유도 | "발주합니다, 단가 확인?"→승인 |
| FN-05 매입확정 | "사과 입고, 매입 처리" | 매입→매입 | confirm | 발주참조·수량(부분입고) | 부족분 잔량 처리 | 승인→"재고↑ + 외상매입↑" 동시 노출 |
| FN-06 거래명세서 | "동서마트 사과 50 거래명세서" | 판매→거래명세서 | confirm | 수주참조·수량 | **재고부족 차단**→매입 유도 | 승인→"재고↓ + 외상매출↑" |
| FN-07 세금계산서 | "동서마트 세금계산서 발행" | 판매→세금계산서 | confirm | 거래명세서참조 | **3대 차단진단**(미확정·사업자번호·세율) | 발행=변조잠금 강한 확인 |

> 모든 변경(create/confirm)은 **AI 초안·준비 → 사람 승인 → 실행**. AI 단독 실행 0.

### 2.2 분석·판단 동작 (조회는 즉시, 기밀은 권한)
| FN | intent | 동작 | 결과 |
|----|--------|------|------|
| FN-10 재고조회 | "사과 재고 얼마" | 즉시 조회 | "70박스(매입90−출고20)" 근거 동반 |
| FN-11 수익성분석 | "신라상사 4~6월 사과 수익성" | 정해진 분석메뉴 호출 | 표+막대·선차트+**문제지점 짚기**+분석화면 연결 |
| FN-12 원가방식 | "이동평균으로 계산해줘" | 파라미터 변경 | 기본=이동평균, 답에 "어떤 원가 기준" 명시 |

> FN-11/12 = 권한 최상위(경영·회계). 읽기라 확인게이트 면제, 대용량은 "기간 좁혀주세요" 안내.

### 2.3 능동형 5대 AI 동작 (Claude라서 되는 것, 외부연동 0)
| FN | 동작 | 예시 멘트 |
|----|------|----------|
| FN-20 원인추론 | 이익 변화 원인 짚기 | "5월 이익↓ = 신라상사 매입단가 올랐는데 판매가 그대로라 마진 깎임" |
| FN-21 이탈경보 | 거래 끊긴 거래처 발견 | "동서마트 2달째 발길 끊겼어요, 연락해보실래요?" |
| FN-22 이상치발견 | 비정상 거래 감지 | "어제 사과를 평소 절반값에 판 거래, 실수 아닌가요?" |
| FN-23 미수금판단 | 외상 위험 경보 | "이 거래처 외상 3개월째 안 들어와요, 출고 더 하면 위험" |
| FN-24 재고판단 | 발주 제안 | "사과 안전재고 아래 + 잘 나감 → 발주 제안" |
| FN-25 비교벤치마크 | 기간 비교 통찰 | "많이 팔았는데 이익률↓, 할인 많이 하셨죠?" |

> FN-20~25는 **개입 4단계 설정**(끔/물어보면/중요한것만/적극참모)에 따라 발동. 알림은 중요도 차등(긴급만 팝업).

## 3. CS 반자동화 동작 (REQ-B)

| FN | 동작 | 상세 |
|----|------|------|
| FN-30 1차 자동진단 | "0000가 안돼요" → 오류·작업 로그 보며 진단 | 세금계산서 안됨→3대 원인 자동 체크 등 |
| FN-31 등급별 분기 | 본사 넘김 임계값 | 돈·마감(세금계산서·로그인)=즉시 인계 / 사용법=챗봇 끝까지 |
| FN-32 본사 인계 | 못 풀면 정리·요약해 본사 CS 데이터로 전송 | "test1 / 세금계산서 오류 / 자동진단 결과 / 사업자번호 누락 확인" 맥락 포함, **업무 본문 제외** |
| FN-33 아웃바운드 | 본사가 CS 내역 보고 고객사 전화 | 백오피스 CS 큐에 적재 |
| FN-34 원격지원 | 필요 시 애니서포트 세션 | **동의 2분리**(전송/원격전체노출) + 1클릭 차단(1초) + 녹화 고객PC |
| FN-35 채널 병행 | 챗봇·전화 둘 다, 전화로 와도 상담원이 챗봇 로그 조회 | 강제 관문화 금지 |
| FN-36 패턴 집계 | 문의 패턴 본사 집계(제품개선) | 헌법 #22 — 패턴만, 업무 본문 0 |
| FN-37 상담원 비서 | AI가 매뉴얼·과거사례 검색해 상담원에 제시 | 신입도 정확 응대 |

## 4. BYOK 연동 동작 (REQ-C)

| FN | 동작 | 상세 |
|----|------|------|

## 5. 안전·권한 동작 (REQ-D)

| FN | 동작 | 상세 |
|----|------|------|
| FN-50 권한 게이트 | 모든 동작 = 로그인 사용자 JWT 권한 | 챗봇 자체 권한 0, 우회 불가 |
| FN-51 확인 게이트 | 변경 액션은 "~합니다, 맞습니까?" 후 실행 | 조회는 즉시 |
| FN-52 역전표 복구 | 오발 시 반품·조정 전표로 복구 | 삭제 0, 흔적 보존 |
| FN-53 거부 감사 | 권한·테넌트·룰 위반 거부 시 audit INSERT | denial_reason 분류 |
| FN-54 기밀 권한 | 원가·수익 분석=경영·회계만 | 일반 직원 거부 |
| FN-55 능동 개입 설정 | 4단계 on/off | 고객 선택 |

> ⚖️ **법무팀장 최종 검토 게이트** — 본 기능정의(특히 FN-32 본사 전송, FN-34 원격, FN-20~25 능동개입)는 법무 검토 통과 후 구현.
