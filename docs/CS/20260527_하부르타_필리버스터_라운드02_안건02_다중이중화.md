# 🎓 하부르타 필리버스터 — Round 2 / 안건 2

## 📋 안건 2 — 다중 터널 이중화 아키텍처

### 출발점 (안건 1 합의)
99.99% 도달 필수 조건 #1 = 다중 이중화

---

### Round 2.1 — 설계팀장 1차 제안

**박사논문 + 사례:**
- Cloudflare 공식 문서 (2024): cloudflared 1 인스턴스 = 4 connections × 2 데이터센터 = 자동 이중화. 단 **자동 failover 메커니즘은 없음**. 수동 오케스트레이션 필요.
- Tailscale vs CF Tunnel 비교 (2026): CF = 공개 URL용·HTTPS 443. Tailscale = 사설 mesh·WireGuard 기반. **각자 용도 다름**
- WireGuard self-hosted: 최대 제어·최소 오버헤드. **10,000 고객사 운영 = 본사 관리 부담 폭발**

**제안:** 3중 아키텍처
- **1차**: Cloudflare Tunnel (외부 공개·DDoS 방어)
- **2차**: Tailscale (mesh 네트워크 백업)
- **3차**: Headscale 자체 구축 (Cloudflare·Tailscale 모두 차단된 환경)

---

### Round 2.2 — 백엔드 매니저 반박

> *"3중 = 과잉. 10,000 고객사 × 3 터널 = 운영 부담 폭발.*
>
> *Cloudflare 공식 문서: 동일 터널에 replica 최대 25개. 4 connection × 25 = 100 connection. **이미 Cloudflare 안에서 이중화 가능**.*
>
> *Tailscale 추가 = 라이선스 비용. 10,000 노드 × $5/월 = 월 5천만원. 사업성 0.*
>
> *제안: Cloudflare 단일 + replica 2개 + 워치독 5단계 = 99.99% 도달 가능. Tailscale은 본사 관리 영역만."*

---

### Round 2.3 — 설계팀장 재반박

> *"백엔드 의견 부분 정합. 단 Cloudflare 자체 다운 (2022-06-21 1.5시간 사례) = SPOF.*
>
> *Cloudflare 단일 = 본 시스템 = Cloudflare 다운 시 100% 다운. 99.99% 불가능.*
>
> *Tailscale 무료 플랜: 3명 사용자·100 디바이스. 10,000 고객사 → 100명 단위로 tenant 분할 가능. 또는 Headscale 자체 구축 = 라이선스 0.*"

---

### Round 2.4 — DB 매니저 반박

> *"두 분 모두 클라우드 사고 영역 간과.*
>
> *Cloudflare 2022 사고 = 19개 데이터센터 (4%). 영향 = 50% 요청. 즉 **Cloudflare 다운은 부분적**이고 영역별. 한국(ICN) 데이터센터 다운 확률 = 별도 계산 필요.*
>
> *AWS US-EAST-1 2017 = 단일 region. AWS multi-region 적용했으면 살았음. **Cloudflare도 동일 — multi-region 자동 이중화 영역 내장**.*
>
> *결론: Cloudflare 단일도 multi-region 효과 = 99.99% 도달 가능. Tailscale 백업 = overkill."*

---

### Round 2.5 — 보안 매니저 2 반박

> *"DB 의견 부분 정합. 단 보안 영역 추가.*
>
> *Tailscale = WireGuard 기반 mesh. 본사 → 고객사 PC 양방향 통신 = 헌법 #22 위반 위험. 본사가 고객 PC 영역 접근 가능 = 데이터 영역 접근 가능 = 본사 책임 영역 확대.*
>
> *cloudflared 단방향(고객 → CF → 외부) 정합. Tailscale 추가 시 본사 영역 책임 영역 폭발."*

---

### Round 2.6 — 검증팀장 중재

> *"전원 의견 정합. 합의안:*
>
> *Phase 1 (베타): Cloudflare 단일 + replica + 워치독 = 99.9% 도달 시도. 실측 후 99.99% 도달 여부 확정.*
>
> *Phase 2 (정식 6개월 후): 99.99% 미달 시 Tailscale 영역 추가 (단 헌법 #22 정합 영역으로 본사 영역 접근 영역 차단 영역).*
>
> *결정 기준: 베타 4주 실측 SLA."*

---

### Round 2.7 — 본부장 추가

> *"비용 검토 필수.*
>
> *Cloudflare Tunnel = 무료 (무제한 데이터·연결). 10,000 고객사 = 비용 0.*
>
> *Tailscale Personal = 무료 (3 user, 100 device). 10,000 고객사 = 별도 tenant 분할 운영 가능. 단 관리 부담.*
>
> *Headscale (자체) = 서버 비용 (월 5~10만원). 10,000 고객사 운영 가능. 단 본사 영역 의존 영역 = 헌법 #30 위반 위험.*
>
> *결론: Phase 1 = Cloudflare 단일. Phase 2 = 베타 실측 후 결정.*"

### Round 2.8 — 외부 AI (OpenAI 시각, PM 시뮬레이션)

> *"본 시스템(로컬 + 터널)의 진짜 SPOF는 터널 자체가 아니라 customer's PC. PC 꺼지면 0%. 터널 이중화로 해결 안 됨.*
>
> *진짜 99.99% 도달 경로:*
> *1. UPS 권고 매뉴얼 (헌법 #24 가르침)*

> *3. Cloudflare 단일 + 워치독 (충분)*
> *4. PC 자동 wake (Wake-on-LAN) 영역 옵션*
>
> *Tailscale 추가 = 비용/관리 부담만 증가. 효과 0."*

### Round 2.9 — 외부 AI (Gemini 시각, PM 시뮬레이션)

> *"OpenAI 의견 정합. 단 한 가지 추가.*
>
> *Cloudflare 영역 정책 변경 위험 = 단일 의존 영역 본질 위험. Cloudflare가 무료 터널 폐지 영역 시 = 전체 영역 다운.*
>
> *대비책: 본사 영역에 Headscale 영역 보유 (사용 안 함 / 비상 대기). Cloudflare 정책 변경 영역 시 EXE 영역 자동 업데이트 영역으로 Tailscale 전환.*
>
> *결론: Phase 1 = Cloudflare 단일. Phase 2 = Headscale 영역 비상 대기 영역만. Tailscale 정식 도입 영역은 영역 사고 영역 시만 영역."*
