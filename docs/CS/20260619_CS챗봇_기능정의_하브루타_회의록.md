## 1. 교시별 실행 명세 (챗봇 Tool Use 재료)

### 1교시 — 사원관리
- **#1-1 사원추가**: intent "김철수 사원 추가/직원 등록/신입 넣어" · 경로 설정→사원관리 · action create · 필수 이름·사번(수동,중복거부) · 선택 부서/직급/연락처/로그인계정 · 권한 부모 or 인사권한 자식 · 되묻기 "사번 어떻게 매길까요(예 001)" · 확인 "등록합니다, 진행할까요?" · 결과 "김철수 등록 완료. 로그인 계정도 만들까요?"
- **#1-2 퇴사처리**: action update(status=퇴사, 삭제 아님) · 결과멘트에 이유 한 줄 "기록 보존 위해 삭제 대신 퇴사 처리됩니다".
- 도출: **사번 수동입력**(자동채번 아님) / 등록≠로그인(계정 선택) / 퇴사=삭제 아님(전표 이력 보존).

### 2교시 — 권한설정 (CS 콜 1순위)
- **#2-1 권한조회**(즉시 실행): "김철수 권한 뭐야"→직원×메뉴 매트릭스(조회/등록/수정/삭제 4단계).
- **#2-2 권한변경**: 최초 안내형 논의 → 11교시에서 **실행형 격상(부모계정만)**.
- 도출: 권한은 메뉴×4단계 매트릭스. 권한 변경은 초민감 → 권한 게이트 필수.

### 3교시 — 업체관리(거래처)
- **#3-1 업체추가**: 필수 상호·사업자번호(10자리 형식검증)·**매입/매출 구분(필수 되물음)** · 결과 "신라상사(매입처) 등록 완료".
- 도출: 매입처/매출처 구분 안 하면 발주·판매에서 거래처 안 뜸 → 등록 시점 차단.

### 4교시 — 상품관리
- **#4-1 상품추가**: 필수 상품명·품목코드·단위 · **세율 구분(과세/면세/영세 되물음)** · 등록 후 **재고=0 안내**.
- 도출: 단위·세율 안 정하면 거래명세서·세금계산서 깨짐. "등록=재고 아님" FAQ.

### 5교시 — 발주 (매입 흐름 시작)
- **#5-1 발주**: 필수 매입처·품목·수량·단가 · **선행조건 체크**(거래처·상품 존재) → 없으면 등록 유도 · 확인 후 실행 · "발주는 재고 무영향, 매입 확정 시 반영" 안내.
- 도출: 선행조건 빠지면 챗봇이 등록으로 연결(헌법 #20 끊김0).

### 6교시 — 매입 확정 (재고 반영점, 문1)
- **#6-1 매입확정**: 발주 참조 → 수량조정(부분입고) → confirmed → **재고↑ + 외상매입↑ 동시** · 확인 후 실행 · 멘트에 두 변화 명시.
- 도출: confirmed 시점에만 반영(헌법 #6). 부분입고 처리. 재고와 돈이 같이 돈다.

### 7교시 — 견적·수주 (판매 흐름 시작)
- **#7-1 견적**: 매출처·품목·수량·단가 · 재고 무영향 안내. **#7-2 수주**: 견적→수주, 재고 예약.
- 도출: 견적=제안(재고무관)/수주=예약/거래명세서=출고(재고↓) 3단계 구분.

### 8교시 — 거래명세서 (판매 재고 차감점, 문3)
- **#8-1 거래명세서**: **재고부족 차단**(재고<출고량이면 거부+매입 유도) · confirmed → 재고↓ + 외상매출↑.
- 도출: 매입의 거울. 재고 부족 시 흐름 연결로 매입 유도.

### 9교시 — 세금계산서
- **#9-1 세금계산서**: 선행=거래명세서 confirmed · **3대 차단원인 자동진단**(①거래명세서 미확정 ②거래처 사업자번호 누락 ③품목 세율 불일치) · 발행 = 변조잠금(trg_tax_invoices_issued_lock) 강한 확인.
- 도출: "세금계산서 안 눌려요" = 5초 자동 체크리스트(어제 P0 봉합 정신).

### 10교시 — 재고현황
- **#10-1 재고조회**(즉시 실행): "사과 재고 얼마야" → "70박스(매입90−출고20)" **근거 동반**.
- 도출: INSERT only 덕에 추적 가능. 안 맞으면 원장으로 연결.

### 11교시 — 실행형(Tool Use) 완전체
- 10교시 혼합형 → 사장님 "실행까지" → **전면 실행형** 격상.
- 난제 4개 해결: ①권한우회 ②오발 ③추적 ④끊김.

## 2. 챗봇 설계 최종 합의 (실행형 6대 원칙)
1. **전면 실행형(Tool Use)** — 조회·등록·수정·매입·출고·발행·권한·되돌리기 전부 챗봇이 직접 실행. 안내형 폐기.
2. **권한이 게이트** — 챗봇은 **로그인 사용자의 권한(JWT)으로 실행.** 사용자가 화면에서 못 하는 건 챗봇으로도 불가. 권한변경도 부모계정이면 실행 OK. 챗봇 자체 권한 없음 → 우회 불가.
3. **변경 3종 안전장치** — ①사용자 권한 실행(우회불가) ②변경 전 확인 게이트("~합니다, 맞습니까?") ③감사로그(출처=챗봇·누가·언제·뭘).
4. **오발은 실행으로 복구** — 삭제 아닌 역전표(반품·조정)를 챗봇이 confirmed. 흔적 남김(헌법 #3 INSERT only 유지). "말로 일하고 말로 되돌린다."
5. **연쇄 실행 + 단계 확인** — 선행조건 빠지면 챗봇이 직접 채우며 완주(거래처 없음→등록→발주). 단 각 단계 확인.
6. **연쇄 변화 전부 노출** — "매입 확정 → 재고↑ + 외상매입↑" 한 동작의 모든 결과를 멘트로(무결성 신뢰).

### 공통 답변 톤 원칙
- **"답 + 왜 한 줄"** — 모든 답변에 이유 한 줄(콜 재발 차단, 마케팅 원칙).
- 변경 멘트엔 연쇄 변화·근거 수치 동반.

## 3. 무결성 보존 확인 (헌법 정합)
실행형이어도 헌법 그대로 — #3(원장 INSERT only)·#6(confirmed 시점 반영)·#8(6단계 순서)·#20(워크플로우 끊김0). **챗봇은 화면이 하는 일을 말로 대신할 뿐, 업무 규칙은 동일.**

## 5. CS 처리 흐름 설계 — 챗봇 1차 → 본사 인계 → 아웃바운드 → 원격지원

### 5.1 사장님이 그린 실제 흐름 (히트판 로그 메뉴 기반)
히트판 내 **로그 메뉴**는 두 갈래: **오류 영역**(시스템 에러 로그) / **작업 영역**(사용자 작업 로그).
```
① 고객사: 챗봇에 "0000가 안돼요" 남김
② 챗봇: 1차 대응 (오류·작업 로그 보며 자동진단)
③ 챗봇 판단: "본사 도움 필요 영역" 이라고 판단하면
④ 전송: CS 처리내역 → 본사 백오피스 CS 데이터로
⑤ 본사: CS 내역 보고 → 고객사에 아웃바운드 전화
⑥ 대응: 필요 시 애니서포트(원격지원)로 처리   ← 현재 히트판 본사 실제 사용 중
```
= 강지원 교집합 ②번(AI가 거르고, 못 풀면 정리해서 사람에게 인계)의 실물 배선.

### 5.2 법무팀장 판정 — 원격지원 CS는 합법 (업계 표준)
- 근거: 개인정보보호법 §15①4호(계약 이행 위한 처리, 별도 동의 불요) / 정보통신망법(고객이 세션 직접 개시=동의) / **데이터가 본사로 안 넘어오니 '처리위탁'(§26) 아님** — 법적으로 가벼움.
- 이카운트·더존·SAP·은행 콜센터 다 함 = 위험 감수 아니라 *법대로*. 20년 관행, 제재 사례 없음.
- 합법 **조건 3개**: ①목적 구속(CS만, 영업 전용 시 위법 §18) ②동의·고지(원격 세션 개시=동의, 기록) ③최소·비보관(그 건 동안만, 본사 미축적 — 헌법 #22 정합).
- **"CS 위해 데이터 안 받겠다"가 오히려 채무불이행 위험** (헌법 #24 지원 의무). 동의받고 봐서 빨리 고치는 게 법적으로도 옳음.

### 5.3 반대 라운드 → 보강 5건 (객체 자율, 억지 반대 0)
1. **(보안)** JIT '그 건 한정'은 원격지원엔 불성립 — 원격 붙으면 화면 전체 노출. → 동의서 2분리: *데이터 전송용*(한정 가능) vs *원격지원용*('전체 화면 노출 가능' 명시). 법무 찬성.
2. **(ERP)** 챗봇을 1차 *강제* 관문화 금지 — 급한 고객 폭발. 챗봇·전화 병행 + **전화로 와도 상담원이 챗봇 로그 조회** 가능해야.
3. **(백엔드)** '본사 넘김 판단 임계값'을 오류 등급별 분기 — 돈·마감(세금계산서·로그인)=즉시 인계 / 단순 사용법=챗봇 끝까지.
4. **(마케팅)** 헌법 #23으로 고객앞 챗봇 호칭('AI·클로드' 금지) 미정 — CS 멘트 통일 필요. (별건)
5. **(DB→법무 해소)** CS 로그 본사 축적 vs 메타만 = **택일 아닌 분리.** *처리이력·메타*(누가·언제·무슨 오류·해결법)=본사 보관 **권장**(분쟁·품질). *업무 데이터 본문*(거래처·금액·품목)=로그에서 **제외**. 헌법 #22·법 동시 충족.

### 5.4 베타 전 법무 준비물
- 원격지원·CS 데이터 처리 **동의 약관 1종** + 개인정보 처리방침에 **'CS 목적 원격지원' 항목** 명시.
