### 작지#1 — DB-77/78 신규 snapshot 테이블 DDL
**책임**: DB 매니저
**산출물**:
```sql
-- DB-77_tenant_employees_snapshot.sql
CREATE TABLE tenant_employees_snapshot (
    snapshot_id CHAR(36) NOT NULL,
    tenant_id CHAR(36) NOT NULL,
    employee_id CHAR(36) NOT NULL,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL,
    position VARCHAR(30),
    is_active TINYINT(1) NOT NULL DEFAULT 1,
    synced_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (snapshot_id),
    UNIQUE KEY uq_tenant_employee (tenant_id, employee_id),
    INDEX idx_synced (synced_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- DB-78_tenant_devices_snapshot.sql
CREATE TABLE tenant_devices_snapshot (
    snapshot_id CHAR(36) NOT NULL,
    tenant_id CHAR(36) NOT NULL,
    device_id CHAR(36) NOT NULL,
    device_name VARCHAR(100),
    registered_at TIMESTAMP NOT NULL,
    synced_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (snapshot_id),
    UNIQUE KEY uq_tenant_device (tenant_id, device_id),
    INDEX idx_synced (synced_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 작지#5 — 토스페이먼츠 Webhook 표준
**책임**: 백엔드 매니저

#### 표준
```
POST /api/billing/webhook/toss
  Header: TossPayments-Signature: {HMAC-SHA256}
  Body: { eventType, paymentKey, orderId, status, ... }

검증:
  1. 서명 검증 (HMAC-SHA256)
  2. Idempotency-Key (paymentKey)
  3. 멱등 처리 (billing_payment_attempts)
  4. 응답 5초 이내

이벤트 매핑:
  - PAYMENT_DONE → billing_invoices 상태 paid
  - PAYMENT_FAILED → 재시도 큐
  - PAYMENT_REFUNDED → 환불 처리
```

**헌법**: #5·#23
