## 1. 왜 이 설계가 필요한가 — 실측 채증

### 1-1. 사장님 지적이 출발점이다

> *"되던 게 안 되니 문제인거지"* (2026-07-30)

샌드박스 설치는 이전에 성공한 이력이 있다. 그런데 오늘 실패했다. **회귀(regression)다.**

### 1-2. 그런데 원인을 알 수 없었다

실측 결과 — 전제 조건이 **전부 정상**인데 결과만 실패:

| 전제 | 실측 | 방법 |
|---|---|---|
| `cloudflared.exe` 존재 | ✅ 54,213,360 bytes | `dir` |
| 실행 가능 | ✅ `version 2026.7.3` | `--version` |
| 터널 토큰 유효 | ✅ base64 디코딩 → `tunnel: fd1d3bbf-98f3-...` | 백오피스 발급분과 일치 |
| `db.conf` 기록 | ✅ `TUNNEL_TOKEN=eyJhIjoi...` | `findstr` |
| 부트스트랩 | ✅ `[InstallerBootstrap] success cf=True` | NCP 로그 `18:52:20` |
| `6-1` 좀비 제거 | ✅ 정상 동작 | 사장님 수동 실행 실측 |
| 관리자 권한 | ✅ `PrivilegesRequired=admin` | .iss:62 |
| **결과** | ❌ **`sc query cloudflared` = 1060(미등록)** | 관리자 명령창 |

### 1-3. 진단 실패의 원인 — 로그가 침묵했다

설치 로그(`%temp%\Setup Log*.txt`) 마지막 줄:

```
19:21:49.506   [FixupWatchdog] 정정 완료 → HealthCheckUrl=https://test2.hitpan.kr/health
```

그 다음이 `6-1`·`6-2`(cloudflared 좀비정리·service install)인데 **로그가 한 줄도 없다.**

원인 코드:

```pascal
// 6-2. service install
Exec(ExpandConstant('{app}\cloudflared.exe'),
     'service install ' + G_TunnelToken,
     ExpandConstant('{app}'), SW_HIDE, ewWaitUntilTerminated, ResultCode);
Sleep(3000);
// ResultCode 를 받아놓고 검사하지 않는다. 로그도 없다.
```

**실패가 세 겹으로 은폐된다:**

| 겹 | 내용 |
|---|---|
| ① `SW_HIDE` | cloudflared 의 오류 메시지가 화면에 안 보인다 |
| ② `ResultCode` 미검사 | 실패해도 무시하고 다음 단계로 진행한다 |
| ③ 로그 0줄 | 성공·실패 어느 쪽도 기록되지 않는다 |

### 1-4. 그 대가 — PM 이 9번 잘못 짚었다

| # | 가설 | 반증 |
|---|---|---|
| 1 | MariaDB 기동 실패 | `[SeedParent] exit code = 0` |
| 2 | `5-0 seed-parent` 멈춤 | 통과 확인 |
| 3 | `ConvertFrom-Json -AsHashtable` (PS7 전용) | PS 5.1 로컬 재현 → `DONE` |
| 4 | `timeout /t` 무한 대기 | 사장님 수동 실행이 정상 증명 |
| 5 | `cloudflared.exe` 누락 | 54MB 존재 |
| 6 | 바이너리 실행 불가 | `version 2026.7.3` 정상 |
| 7 | 토큰 누락·손상 | 디코딩 완전 정합 |
| 8 | 관리자 권한 부족 | 설치는 admin 으로 실행됨 |
| 9 | 샌드박스 서비스 등록 제약 | **사장님 반증: "샌드박스에서 됐었어"** |

**아홉 번 모두 추측이었고 매번 실측이 뒤집었다.**
로그 한 줄이 있었으면 첫 번에 끝났다. 이것이 관측성 부재의 비용이다.

### 1-5. 헌법 위반

> **#15 빈 catch 금지 — 최소 `_logger.LogWarning(ex, ...)` 한 줄**

`ResultCode` 를 받고도 검사·기록을 0건 하는 것은 **실패를 침묵시키는 행위**로 #15 위반이다.
`6-1`·`6-2`·`6-3`·`P0-3` 자동복구 경로 전체가 해당된다.

## 2. 설계 목표

| # | 목표 | 측정 가능 기준 |
|---|---|---|
| G-1 | 6단계 각 명령의 **성공·실패를 로그로 판별**할 수 있다 | 로그에 종료코드가 남는다 |
| G-2 | 실패 시 **원인 메시지**를 알 수 있다 | cloudflared 의 stdout·stderr 가 로그에 남는다 |
| G-3 | 시크릿이 **로그로 새지 않는다** | 설치 로그에 터널 토큰 문자열 0건 |
| G-4 | 관측성 추가가 **설치 동작을 바꾸지 않는다** | 기존 성공 경로 무영향 |
| G-5 | 로그가 **폭주하지 않는다** | 명령당 출력 상한 존재 |

### 비목표 (이 설계가 하지 않는 것)

- **원인 봉합** — 이 설계는 원인을 '보이게' 만들 뿐, 고치지 않는다.
  실제 원인은 로그가 나온 뒤 별건으로 봉합한다.
- **설치 중단 판단** — 실패해도 여기서 멈추지 않는다.
  중단·경고 판정은 기존 `6-3` RUNNING 확인(작8 P0-1)과 `WarnTunnelFailure` 가 담당한다.

## 4. 설계 — `ExecLogged` 헬퍼

### 4-1. 구조

```
ExecLogged(Tag, CmdLine) : Integer
  │
  ├─ cmd /C "<CmdLine> > {tmp}\execlog-<Tag>.txt 2>&1"
  │     └─ C-1 우회: 출력을 파일로 받는다
  ├─ 종료코드를 로그에 기록
  ├─ 출력 파일을 LoadStringsFromFile 로 읽어 로그에 기록 (최대 12줄)
  ├─ 임시파일 삭제
  └─ 종료코드 반환 (호출부가 분기에 쓸 수 있게)
```

### 4-2. 왜 이 방식인가 — 대안 비교

| 방안 | 채택 | 이유 |
|---|---|---|
| **파일 리다이렉트 + LoadStringsFromFile** | ✅ **채택** | 이 파일의 **기존 검증된 패턴**(395·519행 PowerShell 결과 수신에 이미 사용 중). C-2 위험 최소 |
| PowerShell 경유 캡처 | ❌ | 계층이 하나 더 늘고, PS 버전 차이(5.1 vs 7)가 새 변수를 만든다. 오늘 3번째 오답이 정확히 그 함정이었다 |
| `Exec` 대신 `ExecAsOriginalUser` | ❌ | 권한 컨텍스트가 바뀐다. G-4(동작 무변경) 위반 |
| Inno 외부 DLL 로 파이프 캡처 | ❌ | 의존물 추가 = 출하본 증가 + 백신 오탐 위험(헌법 #31) |

### 4-3. 시크릿 차단 설계 (G-3)

```
로그에 남기는 것:  Tag 만 (예: '6-2-serviceinstall')
로그에 안 남기는 것: CmdLine 전문 (토큰이 여기 있다)
```

**`Tag` 와 `CmdLine` 을 분리한 이유가 이것이다.** 명령을 그대로 로그에 찍으면 토큰이 노출된다.
출력 본문은 cloudflared 의 메시지일 뿐 토큰을 되뱉지 않으므로 안전하다.

### 4-4. 성공(exit 0)도 출력을 남기는 이유

작8 P0-3 실측 근거:

> cloudflared 는 **무효 토큰을 받으면 오류가 아니라 정상 종료(exit 0)** 로 조용히 죽는다.
> 실측(test2): `sc query` = STOPPED / `WIN32_EXIT_CODE` = 0

**종료코드만으로는 실패를 판별할 수 없다.** 그래서 성공이어도 출력을 남긴다.

### 4-5. 적용 지점 (13곳)

| 단계 | Tag | 대상 명령 |
|---|---|---|
| 6-1 | `6-1-stopdel` | `sc stop` + `sc delete` (+timeout) |
| 6-1 | `6-1-taskkill` | `taskkill /F /IM cloudflared.exe` |
| 6-1-2 | `6-1-2-recheck` | `sc query && sc delete` |
| **6-2** | **`6-2-serviceinstall`** | **`cloudflared service install <토큰>`** ← 실패 현장 |
| 6-3 | `6-3-scconfig` | `sc config cloudflared start= auto` |
| 6-3 | `6-3-scstart` | `sc start cloudflared` |
| 6-3 | `6-3-scquery` | `sc query cloudflared` |
| W1-3 재시도 | `6-3-retry-serviceinstall` | 2차 `service install` |
| W1-3 재시도 | `6-3-retry-scstart` | 2차 `sc start` |
| W1-3 재시도 | `6-3-retry-scquery` | 2차 `sc query` |
| P0-3 복구 | `P0-3-stopdel` | 복구 경로 좀비 제거 |
| P0-3 복구 | `P0-3-serviceinstall` | 복구 경로 재설치 |
| P0-3 복구 | `P0-3-scconfig` / `P0-3-scstart` | 복구 경로 시작 |

### 4-6. 부수 결함 발견 — `6-1-2` 리다이렉트 충돌

기존 코드:
```
sc query cloudflared >nul 2>&1 && sc delete cloudflared
```

`ExecLogged` 가 `> file 2>&1` 을 덧붙이면 **같은 명령에 리다이렉트가 2개**가 된다.
뒤쪽이 이기며 앞쪽 출력이 유실되거나 cmd 파싱이 흔들린다.

⇒ 출력은 `ExecLogged` 가 파일로 받으므로 `>nul` 억제는 불필요하다. **제거한다.**

## 6. 이 설계가 원인을 찾아주는 방식

다음 설치에서 로그에 이렇게 남는다:

```
[작10 P0-5][6-1-stopdel] 종료코드 0 (성공)
[작10 P0-5][6-1-stopdel] > [SC] OpenService 실패 1060: 지정된 서비스가 ...
[작10 P0-5][6-2-serviceinstall] ❌ 종료코드 ? (실패)
[작10 P0-5][6-2-serviceinstall] > <cloudflared 의 실제 오류 메시지>
```

**마지막 줄이 회귀 원인이다.** 추측 없이 확정된다.

## 7. 검증 기준 (검증문서가 확인할 것)

| # | 기준 | 방법 |
|---|---|---|
| V-1 | ISCC 컴파일 성공 | CI 로그 `Successful compile` |
| V-2 | 신규 경고 0 | 기존 `REGISTRYSIZE` 힌트 외 증가 없음 |
| V-3 | 선언·호출 순서 정합 | 선언 행번호 < 최소 호출 행번호 |
| V-4 | 토큰 미노출 | 실제 설치 로그에 토큰 문자열 0건 |
| V-5 | 6단계 로그 실측 출력 | 실제 설치 로그에 `[작10 P0-5]` 줄 존재 |
| V-6 | 기존 동작 무변경 | 성공 경로에서 터널이 정상 등록·기동 |

**⚠️ V-4·V-5·V-6 은 실제 설치를 해야 확정된다.** 코드만 넣고 "됐다"고 하지 않는다 —
