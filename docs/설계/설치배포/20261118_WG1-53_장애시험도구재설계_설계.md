### §3-3 N4 대체 — 「`cloudflared` 가 돌면 자진중단」 을 무엇으로 바꾸나 · 실물을 잘못 끊지 않는다는 보장

옛 가드 ③ 의 목적 = 「마커가 실물 PC 에 잘못 남았을 때 막기」(:58 주석 · CTO 6-1 #1). 고객 루틴 PC 는 늘 `cloudflared` 가 돌므로 이 가드는 시험 PC 와 실물 PC 를 **가르지 못한다**. 같은 목적을 다음으로 덮는다.

## §5 [판정] 멈춤 관측 → 복구 대기 · 판정 칸 · 종합 (F5 · N1 · N2 · N3 · N6)

### §5-1 한 건의 순서

1. **쿨다운 확인** — 워치독 복구 허용은 대상별 키(`Worker.cs:398` `svc:{name}` · :416 `http:{ep.Name}` · :427 `TunnelSecret`)마다 시간당 `CoolDownMaxPerHour`(appsettings · 5). 도구는 보고서 폴더의 지난 실행 기록으로 **같은 대상 60분 안 4회째까지만** 허용, 넘으면 「미실행(쿨다운 보호)」. (키가 대상별임은 정적 확인 · [1-V] §7 미확인 1건 닫힘 · 실행 확인은 H3 뒤)
   **정정(H1 3인 F9)**: 셈 = **둘 중 큰 값** — ⓐ 보고서 폴더 지난 실행 기록(폴더 비움 · 다른 사본이면 0 으로 돌아감) ⓑ 워치독 이벤트 로그(원본 `HitPanWatchdog` · **읽기만**)의 지난 60분 같은 대상 복구 기록 수(실제 장애 복구도 워치독 셈에 들어가므로 · 워치독 셈은 메모리 큐 `WS28F_CoolDown.cs:41~44` · UTC 기준 :42). 이벤트 로그를 못 읽으면 「미실행(쿨다운 보호)」(fail-closed). 복구 기록 문구 = §12 미확인과 같은 자리.
2. **끊기** — 오류를 삼키지 않는다(옛 :124 · :138 `-ErrorAction SilentlyContinue` 버림). 명령 실패 = 「측정불가(멈추기 실패)」 · 사유 기록.
3. **멈춤 관측**(최대 30초 · 1초 간격) — 서비스: 상태 `Stopped` 를 한 번이라도 보거나 서비스 프로세스 번호가 바뀜 / 프로세스: 끊기 전 번호가 모두 사라짐 + `/health` 실패 1회 이상. 못 보면 「측정불가(멈춤 미관측)」 — **복구 대기로 넘어가지 않는다**(N1 · N2 닫음). 이때와 ② 멈추기 실패(`StopPending` 포함)는 판정과 별개로 **실물은 멈췄거나 반쯤 멈췄을 수 있다** → R2 정지 + §3-3 「사람이 할 일 안내」 출력 · 보고서 경고 칸 「대상 상태 불명 · 사람 확인 필요」(H1 3인 F7).
4. **복구 대기** — 시작점 t0 = **멈춤 관측 시각**. 5분 안에 서비스 Running(S-A · S-B) · `/health` 200(S-C) → PASS(초) / 넘으면 FAIL.
5. **기록만 하는 칸**(판정 미반영): 복구 주체 증거(이벤트 로그 `HitPanWatchdog` 원본의 t0 뒤 기록 유무) · 터널 도메인 외부 `/health`. 판정 반영 여부 = ~~확인 필요(CTO)~~ **CTO 판정(05:15 · 3인 문서 §7)**: 복구 주체 = 기록만 · H2 재판정 / 외부 `/health` = H1 ⑨ 회신 뒤 [3] 착수 전 CTO 결정(그때까지 기록만) / 이 도구의 「합격」 = 「로컬 복구 합격」 으로만 적는다(#32) — CTO 판정 대기 그대로(H1 3인 F6).

### §5-2 판정 칸 (6종 · 모든 결과가 어느 한 칸에 들어간다)

`PASS` · `FAIL` · `측정불가(가드)` · `측정불가(멈추기 실패 · 멈춤 미관측 · 감시 대상 아님 · 재기동 작업 없음)` · `미실행(쿨다운 보호 · 앞 건 정지)` · `반자동`

- **`PASS` 의 뜻(H1 3인 F6 · 헌법 #32)**: 「멈춤 관측 뒤 **5분 안에 복구됨**」 이다. 「**워치독이 살림**」 이 아니다 — 복구 주체는 §5-1 ⑤ 기록 칸에만 있고 판정에 들어가지 않는다. 보고서 판정 칸 설명 · 종합 문구 · 개발명세서 · [4] 리뷰서에 「워치독이 살렸다」 로 적지 않는다(정적으로는 `cloudflared` · `MariaDB` 에 SCM 실패 동작이 깔리지 않음 — `installer/scripts/InstallWatchdog.ps1:83` 은 워치독 자신만 · 3인 근거 · 다른 살림 주체 가능성은 낮으나 판정 반영 전엔 안 쓴다).

### §5-3 종합 (N3)

- 칸마다 개수를 **전부** 적는다(옛 :183 은 정확히 `SKIP` 만 셈).
- **종합 판정 = 「합격」 은 대상 시나리오가 전부 PASS 일 때만.** 하나라도 다르면 「미합격」 + 칸별 사유. 끊은 것이 0건이면 「미합격(측정 0건)」 — 「실패 0」 으로 읽히는 경로를 없앤다.
- 종료 코드: 합격 0 · 그 밖 1(H3 · 기록 대조용).
- 보고서 머리 고정 문구(H1 3인 F6 · F7): 「합격 = 대상 전부 5분 안 복구됨(복구 주체 판정 아님)」 · 측정불가(멈추기 실패 · 멈춤 미관측)가 1건이라도 있으면 「⚠ 대상 상태 불명 · 사람 확인 필요」 경고 줄.
