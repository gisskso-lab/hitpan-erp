## §2 [Q1 첫 푸시 범위]

### §2-1 대안 비교

| 안 | 내용 | 놓침 | 소음 | 판정 |
|---|---|---|---|---|
| A | push 는 main 만 · 나머지 가지는 PR 사건이 담당 | 🔴 PR 없는 가지·태그는 주간 전수까지(최대 7일) 아무도 안 봄. 공개 레포라 **푸시 = 공개 시점** | 0 | 반려 |
| **B** | push: `before`=0 이거나 `before` 가 `after` 의 조상이 아니면 BASE = `merge-base(origin/main, after)` · 그 밖은 현행(`before..after`). PR 은 현행(`base.sha..head.sha`) | 새 놓침 0 (§2-3) | 깨끗한 가지 0 | **채택** |
| C | push 는 언제나 BASE = 합류점 (B 의 강화) | 0 | 🟡 가지 안 유출이 고쳐질 때까지 푸시마다 빨강 — PR 검사가 이미 같은 범위를 같은 방식으로 봄(중복) | 보류(PR 검사로 충분) |
| D | 현행 범위 유지 + push 에도 기준선 적용 | 0 | 🟡 첫 푸시마다 전체 이력(조각 7만여) · 기준선 키가 모든 가지 경로에 필요 → 키 장애 = 전 가지 빨강 | 반려 |

### §2-2 안 B 의 동작 (사건별)

```
사건            BASE                                     HEAD          검사 이름
pull_request    PR base.sha (현행)                        PR head.sha   Scan secrets            ← 필수 후보
push(첫·강제)   merge-base(origin/main, after)            after         Scan secrets (push)
push(그 밖)     before (현행)                             after         Scan secrets (push)
push(삭제)      — 스캔 안 함 · 「삭제 사건」 로그 · 초록       —             Scan secrets (push)
schedule·수동   (전체 이력)                               (전체)        Scan secrets (full) — §3 기준선 적용
```
- 합류점 == after (main 과 같은 커밋을 그냥 푸시) → 「새 커밋 0」 로그 + 초록. **합류점 계산 실패 = 빨강**(조용히 전체·0 으로 떨어지지 않는다).
- 태그도 같은 규칙(필터로 빼지 않는다 — 빼면 가지에 없는 태그 커밋이 사각지대).
- 이름 분리는 잡(job) 이름 식으로 한다. 필수 후보는 PR 사건의 `Scan secrets` **하나**.

### §2-3 반증 — 진짜 새 유출을 놓치는 경로가 생기나

| # | 경로 | 안 B 결과 |
|---|---|---|
| R1 | 가지가 main 아닌 다른 가지에서 갈라짐 | 합류점이 더 과거 → 부모 가지 커밋까지 봄 = 과탐 쪽(안전) |
| R2 | 아직 main 에 없는 가지 X 를 복사한 가지 Y 첫 푸시 | X 커밋을 다시 봄 = 과탐 쪽(안전) |
| R3 | 강제 푸시(이력 재작성) | `before` 가 조상 아님 → 합류점 기준으로 전환 → 가지 전체 재검사 |
| R4 | checkout 이 origin/main 을 못 가져옴 | 합류점 실패 → 빨강 + 이유 출력 |
| R5 | main 과 같은 커밋만 푸시 | 새 커밋 0 → 초록. S4 자체시험이 「커밋이 있는데 0 으로 처리」를 막는다 |
| R6 | 태그만 가리키는 커밋 | 태그도 같은 규칙 → 합류점..태그 커밋 검사 |
| R7 | 이미 main 에 있는 유출 | 그 커밋이 들어올 때의 PR·main push 가 봤음 + 주간 전수(§3)가 기준선 밖이면 빨강 |
| R8 | 포크 PR | PR 사건 현행 그대로(비밀 키 불필요 경로) |
| R9 | main squash 머지 커밋 | main push `before..after` 현행 그대로 |
| R10 | 첫 푸시 뒤 두 번째 푸시가 앞 유출을 덮음(지움) | 두 번째는 `before..after` 라 초록 — **현행과 동일**. 그 유출은 PR 사건(base..head 전체)과 주간 전수가 계속 잡음 → C 를 안 쓰는 근거 |
| R11 | 워크플로 자체를 가지에서 고쳐 검사를 끄는 PR | pull_request 사건은 PR 쪽(머지 미리보기 커밋) 워크플로로 돈다 → PR 이 검사를 끌 수 있음 = **현행과 같은 위험**(이 설계가 새로 만들지 않음) · CODEOWNERS(§4-3)로 막는다 |

## §3 [Q2 기준선]

### §3-1 어디에 쓰나
- **일정·수동 전수 검사에만.** PR·push 는 새 커밋만 보므로 기준선이 필요 없다(키도 필요 없다 → 포크 PR 영향 0).
- 판정: 전수 결과 − 기준선 = **새 후보**. 새 후보 > 0 → 빨강. 0 → 초록 + 「기준선 N건 · 새 0건 · 훑은 조각 수」 요약.

### §3-2 지문 — 값도 위치도 담지 않는다

| 안 | 내용 | 문제 | 판정 |
|---|---|---|---|
| 가 | 값의 단순 해시 | 값이 짧거나 사전에 있는 꼴이면 공개 해시를 거꾸로 맞혀 볼 수 있음 | 반려 |
| 나 | 위치(커밋·파일·줄·탐지기)의 단순 해시 | 공개 레포라 모든 위치를 해시해 대조 → **어느 줄이 비밀인지** 드러남 | 반려 |
| **다** | HMAC-SHA256(키, 탐지기 ‖ 커밋 ‖ 파일 ‖ 줄 ‖ HMAC(키, 값)) | 키 없이는 거꾸로 못 감. 키는 저장소 비밀에만 | **채택** |
| 라 | 탐지기별 개수만 기준선 | 하나 고치고 하나 새로 들어오면 상쇄 → 놓침 | 반려 |
| 마 | 지문 목록을 저장소 비밀에 보관(파일 없음) | 공개 흔적 0 이지만 등재 이력·리뷰 흔적이 없음 | 반려(감사 추적 우선) |

- 기준선 파일 `.github/trufflehog-baseline.txt` 한 줄 = `지문 · 탐지기 이름 · 등재일 · 근거 문서 경로`. **값·값 일부·길이·파일·줄·커밋 금지.**
- 위치를 지문에 넣으므로 이미 알려진 값이 **새 파일·새 커밋에 퍼지면 새 후보 = 빨강**(퍼짐도 잡는다).

### §3-3 로그·산출물 위생 (공개 레포)
- 엔진 JSON 출력은 러너 임시 폴더 파일로만 · 단계 끝에 지운다. 로그에는 **개수·탐지기 이름·지문**만.
- 산출물(artifact) 업로드 금지 — 공개 레포 산출물은 외부에서 받을 수 있다.
- 키가 없거나 틀리면 → 기존 후보 전건이 새 후보로 보임 = **빨강(시끄럽게 실패)** + 「키 없음/불일치」 메시지. 조용히 초록 금지.

### §3-4 권한·절차

| 일 | 누가 | 절차 |
|---|---|---|
| 첫 등재(기존 후보 전건) | 보안 매니저 2 작성 · **보안상무 결재** | 수동 실행(`mode=propose`, main) → 로그의 지문·탐지기 목록 → 기준선 PR. 근거 = [1-V] §B |
| 새 후보 처리 | 보안 매니저 1·2 | 위치 확인은 **로컬에서만**(고정 엔진 · 출력은 레포 밖 임시 파일 · 값 화면 출력 금지 · 확인 뒤 삭제). 오탐 → 기존 제외 목록 원칙(실측 오탐만 · 폴더 통째 금지) / 진탐 → 회전 트랙 등재 뒤 기준선 등재 |
| 기준선 추가 PR | CODEOWNERS 리뷰 + 보안상무 결재 | 줄마다 근거 문서 경로 필수. **제외 목록 추가와 같은 무게**로 다룬다 |
| 줄 삭제 | 하지 않는다 | 이력은 안 바뀐다. 회전 끝난 후보는 근거 문서에 「회전 끝」만 적는다 |
| 키 교체 | 대표 사전 승인(§7-2) → 보안 매니저 2 | 키 교체 = 전건 재생성 PR. **줄 수가 교체 전과 같아야** 통과 |
| 엔진 판 갱신 | §4-2 | 갱신 PR 에서 전수 결과가 기준선과 전건 일치하는지 확인(줄 번호 해석이 바뀌면 여기서 드러남) |

## §4 [Q3 판 고정]

### §4-1 대안

| 안 | 내용 | 판정 |
|---|---|---|
| 가 | 액션을 커밋 SHA 로 + `version` 입력을 판 번호로 | 🟡 이미지 **태그**는 다시 덮어쓸 수 있어 완전 고정 아님 · 액션의 자동 범위 분기가 §2 의 합류점 계산과 충돌(BASE·HEAD 를 넣으면 「같으면 오류」 분기로 빠짐 — §0 실측) |
| **나** | 액션 래퍼를 걷고 `docker run` 으로 엔진 이미지를 **digest(@sha256)** 고정 · 범위·JSON·기준선은 우리 스크립트 | **채택** — §2·§3 모두 우리 스크립트가 필요하므로 래퍼가 주는 것이 없다 |
| 다 | 엔진 실행 파일을 내려받아 체크섬 대조 | 🟡 가능하나 이미지 digest 보다 단계가 많음 · 보류 |

- `actions/checkout` 도 이 워크플로 안에서는 커밋 SHA + 판 주석으로 고정(Dependabot 이 SHA 핀을 갱신 PR 로 올린다 — `.github/dependabot.yml` 의 짝). **다른 워크플로의 핀은 범위 밖**(#33 — 오더에 없음).

### §4-2 갱신 절차 (dependabot 은 `run:` 줄의 digest 를 못 올린다)
1. 주기: **분기 1회** + 상류 보안 공지 때 · 담당 보안 매니저 2.
2. 새 판 digest 확인 → 갱신 PR (워크플로의 digest 한 줄 + 판 번호 주석).
3. 그 PR 에서 자체시험 S1~S6 초록 + 같은 가지 수동 전수(`mode=check`) 결과가 기준선 **전건 일치 · 새 0**.
4. CODEOWNERS 리뷰 + 보안상무 결재 → 머지. 불일치면 원인(엔진 출력 변화) 문서화 후 §3-4 재생성.

### §4-3 소유자 리뷰 범위 추가
- CODEOWNERS 에 `trufflehog.yml` · 제외 목록 파일 · 기준선 파일 · 스크립트 폴더 4줄 추가(설정 파일은 이미 있음).
- 효력은 ruleset 의 「코드 소유자 리뷰 필수」에 달림 — **확인 필요**(§0). 꺼져 있으면 이 줄은 표시일 뿐이라고 보고서에 정직하게 적는다.

## §5 [Q4 대조 시험]

### §5-1 원칙
- 🔴 **실레포(공개)에 가짜 유출을 심지 않는다.** 이력은 지울 수 없고, 자격증명 「모양」은 가짜여도 레포 어디에도 금지(메모리 규칙).
- 대신 **같은 엔진 digest · 같은 설정 · 같은 범위·기준선 스크립트**를 러너 임시 폴더의 일회용 git 저장소에 돌린다. 매 실행 첫 단계 = 자체시험. 자체시험 빨강 = 잡 빨강.
- 가짜 비밀은 **실행 때 만든다** — 키 생성 도구가 만든 일회용 개인 키(엔진 내장 탐지기 + 자체 개인 키 규칙 대상) · 난수 생성기 출력. 고정 문자열 값 규칙(DB 기본값 규칙)은 값을 다시 써야 하므로 **자체시험 대상에서 뺀다** — 그 규칙은 §5-3 실레포 음성 대조(기존 후보가 지문으로 일치하는가)로 동작을 확인한다.
- 스크립트·워크플로 파일 **자체가 어떤 규칙에도 안 걸려야** 한다: 규칙 키워드가 필요하면 조각으로 이어 붙여 만든다. 커밋 전 고정 엔진으로 **바뀐 파일만** 로컬 검사 → 0건(자기 일치 0)을 개발명세서에 적는다.
- 자체시험 출력도 파일로만, 로그엔 개수만. 엔진 검증 호출은 끈다(일회용 값이 밖으로 나가지 않게).

### §5-2 자체시험 (러너 임시 저장소 · 매 실행)

| # | 꾸밈 | 실행 | 기대 | 무엇을 증명 |
|---|---|---|---|---|
| S1 양성 | main 깨끗 · 가지 커밋에 실행 때 만든 가짜 비밀 B | 첫 푸시 모드 | ≥1건 · 탐지기 이름 일치 · 엔진 종료 코드 = 「찾음」 | 고정 엔진·설정이 실제로 잡는다 |
| S2 음성(범위) | main 과거 커밋에 가짜 비밀 A · 가지 커밋 깨끗 | 첫 푸시 모드 | **0건** | 첫 푸시가 전체 이력을 안 훑는다(P1). **대조군**: 현행 로직(BASE 비움)으로 같은 꾸밈 → ≥1건 — 두 결과를 개발명세서에 나란히 |
| S3 강제 푸시 | S1 가지를 재작성, `before` 를 조상 아닌 커밋으로 | 강제 모드 | B 잡힘 | R3 |
| S4 범위 0 | 가지 = main 과 같은 커밋 / 합류점 계산 불가 꾸밈 | 첫 푸시 모드 | 앞 = 초록 「새 커밋 0」 · 뒤 = **빨강** | R4·R5 — 조용한 0 금지 |
| S5 기준선 | A 를 임시 키로 지문 등재 → 전수 / 그 뒤 B 추가 → 전수 / 다른 키로 전수 | 전수 모드 | 새 0 초록 / 새 1 빨강 / 키 불일치 → 전건 새 → 빨강 | §3 판정·키 장애 시끄러움 |
| S6 엔진 오류 | 없는 설정 파일 경로 | 아무 모드 | 빨강 · 「검사 오류」(「0건」 과 구분) | 오류를 통과로 삼키지 않는다 |

### §5-3 실레포 재측정 (머지 뒤 · 필수 걸기 전)

| # | 무엇 | 통과 기준 | 대조(현행) |
|---|---|---|---|
| M1 | 새 가지 첫 푸시 ≥ 10회(평소 작업 가지) | `Scan secrets (push)` 초록 10/10 | 49/56 빨강 |
| M2 | PR 사건 ≥ 10회 | `Scan secrets` 초록 유지 · **한 SHA 에 그 이름 1개** | 97/97 · 이름 2개 |
| M3 | 수동 전수(`mode=check`, main) | 기준선 전건 일치 · 새 0 · 훑은 조각 수 ≥ 직전 실측의 90% | 15주 빨강 |
| M4 | 다음 일정 실행 1회 | 초록 | 빨강 |
- 훑은 조각 하한(M3)이 「아무것도 안 훑고 초록」 을 막는 동작 게이트다. 하한 값은 첫 등재 때의 실측 조각 수로 정해 워크플로 상수에 둔다.
- M1~M4 통과 → 「`Scan secrets` 필수 걸기」 를 **별도 결재 상신**(ruleset 변경은 이 설계 범위 밖).

## §6 [규모·갈래·되돌림]

### §6-1 규모 = M
- 바뀌는 곳: `.github/workflows/trufflehog.yml`(수정) · `.github/scripts/trufflehog/` 새 스크립트 3(범위 계산 · 기준선 비교 · 자체시험) · `.github/trufflehog-baseline.txt`(새) · `.github/CODEOWNERS`(4줄 추가). 제품 코드·DB·설치 0.
- L 이 아닌 근거: 고객 PC·서버·배포 경로에 닿지 않음 · 되돌림 한 번. S 가 아닌 근거: 보안 게이트의 판정 논리가 바뀌고 새 비밀 1개와 결재 절차가 생김.
- 언어: 범위 계산·자체시험 = bash · 기준선 비교 = python3 표준 라이브러리만(HMAC 키를 명령줄 인자로 넘기지 않기 위해 환경변수로 읽음).

### §6-2 갈래 (순차 — 같은 워크플로 파일)

| 갈래 | 내용 | 끝 |
|---|---|---|
| ㄱ | §2 범위 · §4 판 고정 · 이름 분리 · 자체시험 S1~S4·S6 | 자체시험 초록 + S2 대조군 기록 |
| ㄴ | §3 기준선 · S5 · CODEOWNERS · 첫 등재 PR(키 등록 승인 뒤) | M3 통과 |

### §6-3 되돌림
- 워크플로 PR 되돌리기 = 현행(`@main` · 같은 이름 · 전수 빨강)으로 복귀. 기준선 파일은 남아도 해 없음(지문뿐).
- 저장소 비밀 삭제 = 전수 검사 빨강(키 없음 메시지) — 의도된 시끄러움.
- 첫 등재가 틀렸을 때: 기준선 PR 되돌리기 → 전수 빨강 복귀(정보 손실 0).

### §7-2 결재 쟁점 (PM 이 볼 것)
1. **안 B 대 안 C**: B 는 가지 안 유출의 「두 번째 푸시 뒤 초록」 이 현행과 같다(R10). PR 검사가 잡으므로 B 추천. 보안상무가 C 를 요구하면 소음 증가를 감수.
2. **HMAC 키 = 저장소 비밀**(대표 사전 승인 필요 · 확인 필요): 쓰기 권한자는 가지에서 워크플로를 고쳐 키를 볼 수 있다 → 키가 새면 지문이 사전 대조에 열림 → 키 교체 + 재생성(§3-4). Environment(가지 = main 제한)로 막으면 엔진 갱신 PR 에서 M3 꼴 확인을 못 함 → **저장소 비밀 추천**.
3. **CODEOWNERS 효력**은 ruleset 설정에 달림 — 꺼져 있으면 「소유자 리뷰」 는 실효 없음(별도 결재).
4. 「전수 빨강 = 의도」(7/31 설계 §5)를 **뒤집는다** — 근거 [1-V] §B-4(경보 피로가 더 큰 위험). 기존 후보는 기준선·근거 문서·회전 트랙에 남는다.
5. 필수 걸기는 이 작업의 끝이 아니다 — M1~M4 보고 뒤 별도 상신.
