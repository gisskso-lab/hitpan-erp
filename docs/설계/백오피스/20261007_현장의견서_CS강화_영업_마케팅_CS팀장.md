## §0 우리가 먼저 재 본 것 (실측 · 확정)

| 잰 것 | 결과 | 뜻 |
|---|---|---|
| `bo_cs_tickets` 가 코드·DDL·화면에 있나 | **0건** (`.cs`·`.sql`·`.razor` 전체) | 🟢확정 — CS 는 **설계만 있고 구현이 하나도 없다** |
| ERP 쪽에 CS 요청(쪽지) 화면이 있나 | **0건** (ERP 화면 폴더 전수 · 파일 이름 수준) | 🟢확정 — 고객이 요청을 넣을 **입구부터 없다** ⚠️파일 이름으로만 봤다 |
| ERP 에 챗봇이 있나 | **있다** (`ChatbotController` 등 · 키는 고객사 것) | 🟢확정 — 챗봇은 이미 고객 손에 있고, 백오피스 쪽 CS 만 비어 있다 |

**세 팀장 공통 첫 마디**: 지금은 **고객이 불편을 말할 길이 전화뿐**이다. 전화는 흔적이 안 남는다.
그래서 이 오더는 「기능 추가」가 아니라 **없던 입구를 처음 내는 일**이다. 입구를 내면 **들어오는 양이 갑자기 늘어난다** — 이게 아래 모든 의견의 바탕이다.

> **강지원(CS팀장)**: 20년 동안 본 것 하나. **접수 창구를 쉽게 만들면 문의가 2~3배로 뛴다.** ⚠️추정(히트판 수치 아님 · 동종업계 경험)
> 지금 설계는 「들어온 걸 어떻게 다루나」는 잘 짜여 있는데, **「한꺼번에 밀려올 때 안 무너지나」** 가 비어 있다.
> 아래 의견의 절반은 그 얘기다. 나머지 절반은 **숫자가 거짓말하지 않게 만드는 것**이다.

## §1 더 들어가야 할 기능 — 1차 (⑤ CS기록 사이클에 같이 넣기를 권고)

> 표 읽는 법: **누가** = 요구한 팀장 이름 · **없으면 나는 일** = 현장에서 실제로 벌어질 일 · **앉는 자리** = 결재된 9대메뉴 안의 위치

### N-1. 답 약속 시계 (언제까지 답해야 하나)

| | |
|---|---|
| **누가·왜** | **강지원(CS팀장)** — 「미처리 건수」만 보는 건 **사후**다. 100건 중 어느 게 급한지 모른다. 티켓마다 「**답 약속 시각**」이 있고, 남은 시간이 색으로 보여야 손이 움직인다. |
| **없으면 나는 일** | 목소리 큰 고객 건만 먼저 처리된다. 조용한 고객 건은 **3일 묵는다.** 묵은 건이 터지면 그게 해지 사유가 된다. |
| **앉는 자리** | **4. CS 관리 ▸ 고객사 CS 요청사항** — 목록에 「남은 시간」 열 1개 + 목록 위 「지난 건 N / 2시간 내 N」 신호 2칸 |

> **기술영업팀장**: 이 숫자가 있으면 계약서에 쓸 말이 생긴다. 없으면 「빨리 해 드립니다」가 전부라 아무 말도 아니다.

### N-2. 「고객 답 대기」 칸 ⚠️결재 — 상태 고정목록 한 칸 추가

| | |
|---|---|
| **누가·왜** | **강지원(CS팀장)** — 결재된 상태는 접수→처리중→보류→완료 넷이다. 실제 CS 의 **절반 가까이는 「고객에게 되물어 놓고 기다리는 중」**이다 ⚠️추정. 그걸 「보류」에 넣으면 **우리 탓인 보류와 고객 답 기다리는 보류가 한 통에 섞인다.** |
| **없으면 나는 일** | **미처리·평균처리시간(F-20)이 거짓 숫자가 된다.** 대리점 평가를 그 숫자로 하면(평가 연동 = 본사 설정) 대리점이 억울해진다. → 「고객이 2주 답 안 했는데 왜 내 처리시간이 2주냐」 분쟁. |
| **앉는 자리** | 상태 목록은 F-15 가 「고정목록 · 서버 1곳」으로 결재된 자리라 **우리가 못 정한다. 사장님 결재 사항으로 올린다.** |
| **대안** | 칸을 안 늘릴 거면, **「보류」에 사유 2택(우리 대기 / 고객 대기)** 을 붙여 집계에서 가르는 방식. 둘 중 하나는 꼭 있어야 한다. |

### N-3. 중복 접수 합치기 (한 고객이 세 번 넣은 걸 한 건으로)

| | |
|---|---|
| **누가·왜** | **강지원(CS팀장)** — 급한 고객은 **쪽지 넣고, 전화하고, 챗봇에도 물어본다.** 그러면 한 가지 일로 티켓 3개가 생긴다. F-23(공통장애 묶음)은 **여러 고객 한 장애**를 묶는 것이고, 이건 **한 고객 여러 접수** — 다른 일이다. |
| **없으면 나는 일** | ⓐ 미처리 숫자가 **부풀어** 보인다 ⓑ 더 나쁜 건 **두 사람이 같은 건에 각각 답장**한다 → 고객이 「말이 다르다」고 한다. 이게 신뢰를 가장 빨리 깎는다. |
| **앉는 자리** | **4. CS 관리 ▸ 고객사 CS 요청사항** — 티켓 여러 건 고르고 「한 건으로 합치기」 · 합친 흔적은 남긴다(지우지 않는다) |
| **AI 쓸 자리** | 같은 고객·짧은 시간·비슷한 말이면 **「합칠까요?」 제안만**. 자동 합치기 금지(틀리면 고객 글이 숨는다). |

| | |
|---|---|
| **누가·왜** | **강지원(CS팀장)** — F-24(재배정)는 **퇴사·교체** 같은 사고 처리다. 평상시 **「이 건 누가 맡나」** 가 없다. 20년 동안 CS 팀이 깨지는 이유 1위가 이것이다 — 서로 미루거나, 둘이 동시에 답한다. |

| **앉는 자리** | **4. CS 관리 ▸ 내 응대함** 🆕소메뉴 — 담당 배정 1동작 + 「내 것 / 안 맡은 것 / 지난 것」 3탭 |

### N-5. 전화 30초 입력 틀

| | |
|---|---|
| **누가·왜** | **강지원(CS팀장)** — 🟢Q-4 로 **전화도 전건 기록 의무**가 결재됐다. 반갑다. 그런데 **입력이 길면 직원은 안 적는다.** 20년 동안 본 바, 「적어라」는 규칙은 **입력이 30초를 넘으면 지켜지지 않는다** ⚠️추정. 그러면 결재된 의무가 **문서에만 있는 의무**가 된다. |

| **검증 기준 제안** | 사람이 **30초 안에** 한 건을 넣을 수 있나 (처음 쓰는 직원으로 재기) |

### N-7. 답장 문구 틀 (상용구)

| | |
|---|---|

### N-8. 「답 왔습니다」가 고객 화면에 보이는 자리 🔴

| | |
|---|---|
| **누가·왜** | **마케팅팀장** + **강지원** — §5 그림의 마지막 칸이 「ERP 화면에 알림」인데, **그 알림이 앉을 자리가 ERP 화면에 지금 없다**(실측: ERP 에 CS 화면 0건). |
| **없으면 나는 일** | **이게 이 오더 전체를 무너뜨릴 수 있는 한 지점이다.** 고객은 쪽지를 보내고 **화면을 떠난다.** 우리가 1시간에 답해도 고객은 3일 뒤에 본다. 그러면 고객 체감은 「3일 걸렸다」다 — **우리가 잘해도 못한 걸로 기록된다.** 7차 재발한 「고쳤다 ≠ 갔다」와 같은 모양이다. |

| **우리 요구** | 이 한 칸이 없으면 **쪽지 파이프라인은 1차에서도 반쪽**이다. ⑤ 사이클에 같이 가야 한다. |

## §2 더 들어가야 할 기능 — 2차

### N-9. 고객이 직접 보는 도움말 (공개 누리집)

| | |
|---|---|
| **누가·왜** | **마케팅팀장** — 문의를 **줄이는** 유일한 방법은 고객이 **묻기 전에 답을 보는 것**이다. 내부 누리집에서 **고객에게 보여도 되는 문서만 골라** 공개 묶음으로 올린다. |
| **없으면 나는 일** | 「어떻게 하나요」 문의가 전부 사람에게 온다 — 이 유형이 **건수 1위**일 것이다 ⚠️추정(동종업계 경험). 사람이 같은 답을 100번 쓴다. |
| **앉는 자리** | **4. CS 관리 ▸ CS 누리집** 안에 「공개」 표시 1칸 (승격·승인 길은 §8-6 결재 그대로 · 공개는 **CS팀장 승인 뒤 한 단계 더**) |
| **경계 🔴** | 공개 문서에는 고객사 이름·거래처·금액이 **한 글자도 없어야 한다**(§8-5 일반화와 같은 검사). 공개는 **외부 노출**이라 #23 금지어(AI·Claude·개발용어) 검사도 같이 걸린다. |

### N-10. 틀린 답 신고 → 누리집으로 되돌아가는 길

| | |
|---|---|
| **누가·왜** | **강지원(CS팀장)** — §8-9 ⑥에 「되돌린 건수 관찰」이 있다. 좋다. 그런데 **「이 답 틀렸다」를 누르는 단추**와, 그게 **문서 한 장에 꽂히는 길**은 안 보인다. 「근거 문서를 같이 보여준다」(§8-3)가 값을 하려면 **그 문서에 틀림 표시가 쌓여야** 한다. |
| **없으면 나는 일** | 틀린 문서가 **계속 쓰인다.** 자동화는 틀린 걸 **빠르게** 뿌린다 — 사람보다 피해가 크다. |
| **앉는 자리** | **4. CS 관리 ▸ CS 누리집** — 문서마다 「쓰인 N회 / 틀림 신고 N회 / 마지막 고친 날」 세 숫자 |
| **덤** | 이 세 숫자가 F-22(지식 라우팅 통계)를 **쓸 수 있는 화면**으로 만든다. |

### N-11. CS 에서 나온 영업 단서 넘기기

| | |
|---|---|
| **누가·왜** | **기술영업팀장** — CS 통화 중에 영업 단서가 **제일 많이 나온다.** 「직원 늘어서 계정 더 필요한데요」, 「지점 하나 더 열어요」. 지금은 그 말이 CS 직원 머릿속에서 끝난다. |
| **없으면 나는 일** | **돈이 되는 말이 버려진다.** 더존·이카운트가 CS 를 영업 창구로 쓰는 게 바로 이거다 ⚠️추정(업계 통념). |
| **앉는 자리** | 티켓에 「영업 단서」 표시 1개 → **8. 마케팅** ▸ 「CS 단서」 목록 (대리점은 자기 고객만) |
| **경계** | 단서에 **본문을 복사하지 않는다.** 「계정 증설 문의 · 고객사 코드」 정도만 — 업무 데이터는 안 옮긴다(#18·#22). |

### N-12. 해지 전 CS 이력 붙이기

## §3 AI 자동화 — 현장이 바라는 것

### §3-1 카테고리는 「기능별」로 묶으면 못 쓴다 — 들어오는 모양대로 묶어야 한다

> **강지원(CS팀장 · 챗봇 지식 직접 정의 당사자)**:
> 설계하는 사람은 보통 「재고·판매·회계」처럼 **메뉴 이름으로** 분류를 만든다. 현장에 안 맞다.
> 고객은 「재고 모듈 문의입니다」라고 말하지 않는다. **「어제까진 됐는데 오늘 안 돼요」** 라고 말한다.
> 20년 동안 들어온 문의는 아래 일곱 모양이다. 이 일곱으로 묶어야 **묶자마자 손이 달라진다.**

| # | 들어오는 모양 (고객 말 그대로) | 급한가 | 자동 답 되나 | 처음 받는 곳 |
|---|---|---|---|---|
| ① | **「안 열려요 / 안 켜져요」** — 접속·설치·판 올리기 | 🔴업무 정지 | 일부 (됐던 처방이 있다) | 대리점 1차 · 30분 안 되면 본사 |
| ② | **「숫자가 안 맞아요」** — 재고·미수·금액 | 🔴돈 문제 | **금지 🔴** | **사람만.** 본사까지 올라가야 하는 유형 |
| ③ | **「이거 어떻게 해요」** — 사용법 | 보통 | **잘 된다** | 자동 초안 → 사람 확정 |
| ④ | **「안 찍혀요 / 안 뽑혀요」** — 출력·양식·용지 | 급함 | 일부 | 대리점 1차 |
| ⑤ | **「바꿔주세요」** — 사원·권한·설정·계정 | 보통 | 안내는 된다, **바꾸는 건 사람** | 대리점 1차 |
| ⑥ | **「돈 얘기」** — 요금·결제·계산서·해지 | 보통 | **금지 🔴** | **본사만** (결재된 §5 법무 필수⑥ — 과금·해지 자동판단 배제) |
| ⑦ | **「이거 되게 해주세요」** — 기능 요청 | 안 급함 | 답할 게 없다 | CS 아님 → 영업·개발로 보낸다 |

**이 일곱 위에 축 두 개만 더 얹어 주십시오. 이게 자동화의 안전장치다.**
- **축1 「업무가 멈췄나」** (멈춤 / 불편) — 멈춤이면 약속시간이 짧아지고 맨 위로 올라간다
- **축2 「사람만 해야 하나」** (②⑥은 **무조건 사람**) — **AI 초안이 아예 안 만들어지는 유형 목록**을 설정에 둔다

> **강지원**: 🔴 **②와 ⑥에 자동 초안이 붙는 순간 이 기능은 끝난다.**
> 「재고 숫자가 안 맞아요」에 AI 가 그럴듯한 설명을 적어 보내면, 그건 **우리가 고객 장부에 대해 거짓말한 것**이 된다. 사람이 확정한다 해도, 바쁜 직원은 그럴듯한 초안을 **그냥 보낸다.** 20년 동안 수없이 봤다.
> 초안을 **안 만드는 것**이 유일한 안전장치다. 「만들지만 조심해서 쓰기」는 안 지켜진다.

### §3-2 3사(ChatGPT·Gemini·Claude)를 쓰는 게 현장에 만드는 차이

> **강지원**: 우리는 「셋 중 어느 게 똑똑한가」에 관심이 없다. 현장이 바라는 건 셋이다.

| 바라는 것 | 뜻 | 현장에 생기는 차이 |
|---|---|---|
| ⓐ **한 곳이 멈춰도 CS 는 안 멈춘다** | 한 곳이 느리거나 막히면 다른 곳으로 | 🔴 **이게 1번이다.** 외부 한 곳 사정으로 우리 CS 가 서는 건 **고객에겐 우리 잘못**이다 |
| ⓑ **답이 갈리면 그게 위험 신호다** | 같은 질문을 두 곳에 물어 **답이 다르면 사람에게 넘긴다** | 「확실한 것」과 「애매한 것」을 **기계가 스스로 가른다.** 애매한 걸 자신 있게 답하는 게 가장 무섭다 |
| ⓒ **값** | 쉬운 ③은 싼 곳, 어려운 건만 비싼 곳 | 본사 부담(§8-7 ⓐ 권고)이면 **값이 곧 우리 이익**이다 |

> **기술영업팀장**: ⓑ 는 **팔 때도 쓸 말**이다. 「세 곳에 물어 **답이 같을 때만** 자동으로 씁니다. 다르면 사람이 봅니다.」 — 경쟁사가 못 하는 말이고, **고객이 AI 를 겁내는 지점을 정확히 짚는다.**

> **마케팅팀장**: 다만 ⓑ를 바깥에 말할 때 **「세 AI」라고 쓰면 안 된다**(#23 · §8-8 「히트판 도우미」 결재 권고). 고객 말로는 **「여러 번 교차 확인하고, 확실할 때만 자동으로 답합니다」**.

### §3-3 자동화 숫자는 「처리 건수」가 아니라 「되돌린 건수」로 봐야 한다

> **강지원**: 자동화를 「몇 건 처리했나」로 재면, 사람은 숫자를 올리려고 **애매한 것도 보낸다.**
> 봐야 할 숫자는 셋이다 — **①자동 초안이 그대로 나간 비율 ②사람이 고쳐서 나간 비율 ③고객이 「이게 아니에요」 한 비율.**
> 🔴 **③이 올라가면 자동화를 끄는 것이 맞다.** 끌 수 있어야 한다. 「끄는 단추」를 **9. 설정**에 유형별로 두십시오.

## §4 팔리는 이야기 / 30초 설명

### §4-1 30초 설명 (마케팅팀장)

> **마케팅팀장** — 세 줄을 넘기면 현장에서 안 먹힌다. 이렇게 말한다.

> **「히트판은 프로그램 안에서 바로 물어볼 수 있습니다.**
> **전화 걸고 기다릴 필요 없이, 쓰던 화면에서 한 줄 쓰면 끝입니다.**
> **답은 다시 그 화면으로 옵니다. 그리고 한 번 해결된 일은 다음부터 바로 답이 나옵니다.」**

- 한 단어로 줄이면: **「화면 안에서 묻고, 화면 안에서 받는다」**
- 🔴 **「AI」로 팔지 않는다.** AI 로 팔면 고객은 「사람 안 붙냐」로 듣는다(§4-3 반대 의견). 「쓸수록 빨라진다」로 판다.

### §4-2 경쟁사 대비 (기술영업팀장)

> **기술영업팀장** — 더존·이카운트를 15년 상대했다. 그쪽 CS 의 아픈 데는 **「전화 연결」**이다.
> ⚠️아래 비교는 **업계 경험·통념**이고 우리가 잰 숫자가 아니다. 숫자로 말하려면 §1 N-1·N-15 가 돌고 **3개월 실측이 쌓여야** 한다.

| 현장에서 자주 듣는 소리 ⚠️추정 | 히트판이 할 수 있는 말 (N-x 가 돌면) |
|---|---|
| 「전화가 안 돼서 하루 날렸다」 | **「전화 안 걸어도 됩니다. 쓰던 화면에서 쓰면 접수됩니다.」** (§5 쪽지 — 결재됨) |
| 「누가 받을지 몰라 매번 처음부터 설명한다」 | **「받는 사람이 당신 지난 이력을 먼저 봅니다.」** (N-6) |
| 「언제 답 올지 모른다」 | **「유형별로 답 약속 시간이 정해져 있습니다.」** (N-1) |
| 「대리점에 물었는데 모른다더라」 | **「대리점이 못 풀면 정해진 시간에 본사로 올라갑니다.」** (F-16 + 인계 시간 상한 — §5 위험 R-5) |

> **기술영업팀장**: 🔴 그리고 **가장 센 말은 아직 아무도 안 쓴 이것**이다 —
> **「우리는 우리가 당신 문의에 몇 시간에 답했는지 종이로 뽑아 드립니다.」** (N-15)
> 더존·이카운트가 이걸 못 준다 ⚠️추정. **재는 회사만 줄 수 있는 종이**다. 갱신 협상에서 값 얘기를 **품질 얘기로 바꾼다.**

### §4-3 계약서·상품설명에 쓸 때 조심할 것

> **기술영업팀장**: 「답 약속 시간」을 **계약서에 숫자로 쓰면 그때부터 어기면 배상**이다.
> 1차에서는 **계약서 아닌 상품 설명**에만 쓰고, 계약서 문구는 **법무팀장 확인 뒤**에 넣기를 권고한다. 이건 우리 소관이 아니다.

## §5 🔴 반대 의견·위험 — 「이건 안 쓸 것 같다」·「고객이 화낸다」

> 좋은 말만 쓰면 쓸모 없는 의견서다. 여기가 이 의견서의 본론이다.

| # | 누가 | 반대·위험 | 왜 | 어떻게 하면 되나 |
|---|---|---|---|---|
| **R-1** 🔴 | **기술영업팀장** | **「AI 가 답한다」를 앞세우면 계약이 깨진다** | 우리 고객은 **50~60대 사무실 직원**이 많다 ⚠️추정. 이 분들에게 AI 는 「사람이랑 연결 안 됨」으로 들린다. 더존·이카운트 욕 1위가 바로 그거다 | **팔 때는 AI 를 말하지 않는다.** 「쓸수록 빨라진다」로만 말한다(§8-8 「히트판 도우미」 결재와 같은 방향). 「언제든 사람이 받습니다」를 **같은 문장에** 붙인다 |
| **R-2** 🔴 | **강지원** | **②「숫자가 안 맞아요」·⑥「돈 얘기」에 자동 초안이 붙으면 끝난다** | 그럴듯한 초안은 **바쁜 직원이 그냥 보낸다.** 「사람 확정」이 서류상으론 지켜지고 실제론 안 지켜진다 | **그 두 유형은 초안을 아예 안 만든다.** 설정에 「초안 금지 유형」 목록(§3-1 축2) |
| **R-3** 🔴 | **강지원** | **누리집 승격 초안 자동 = CS팀장 한 사람에게 검수가 몰린다** | §8-6 결재는 맞다(자동 승격 금지). 그런데 하루 티켓 50건이면 **초안 50장이 내 책상에 쌓인다.** 사람 수가 안 늘면 **밀린 초안이 0장 승인**으로 끝난다 — 고리(§8-2)가 안 돈다 | ⓐ **초안을 아무 티켓에나 만들지 않는다** — 「같은 증상 N번 이상」일 때만 ⓑ **하루 상한**(예: 5장)을 설정값으로 ⓒ 승인 권한을 **CS팀장 + 지명한 사람 1~2명** |
| **R-4** 🔴 | **강지원** | **상태 칸이 5~6개 넘어가면 직원이 안 바꾼다** | CS 20년 불변의 법칙이다. 상태를 늘리면 **집계가 더 정확해지는 게 아니라 더 거짓**이 된다(아무도 안 바꿔서 전부 「처리중」) | N-2 는 **한 칸만** 늘린다. 더는 늘리지 않는다. 그 한 칸도 사장님 결재 사항 |
| **R-5** 🔴 | **기술영업팀장** | **대리점 1차 응대는 칼이자 흉기다** | 대리점이 못 풀고 붙들고 있으면 고객은 **「히트판이 못 한다」**고 본다 — 대리점이 1차라는 걸 **고객은 모르고 알 필요도 없다** | **인계 시간 상한**(유형별 · 본사 설정): 지나면 **본사 화면에 자동으로 뜬다.** 자동 인계가 아니라 **자동 알림** — 반자동 원칙 유지 |
| **R-6** | **마케팅팀장** | **실시간 채팅이 없다는 걸 경쟁사가 때릴 것이다** ⚠️추정 | 「저쪽은 채팅 되는데 여기는 쪽지?」 라는 말이 나올 수 있다. §5 판정(1차 쪽지)은 기술상 맞다 — 우리가 뒤집을 생각 없다 | **말을 바꿔서 이긴다**: 「채팅은 **사람이 앉아 있을 때만** 됩니다. 쪽지는 **밤에 써도 아침에 답이 와 있습니다.**」 ⓑ N-8(답 왔음 표시)이 **반드시** 돌아야 이 말이 성립한다 |
| **R-7** 🔴 | **마케팅팀장** | **N-8 이 없으면 쪽지 기능은 역효과다** | 고객이 보내고 **잊는다.** 우리가 1시간에 답해도 체감은 3일이다. 그러면 **안 만든 것보다 나쁘다** — 「히트판은 답을 안 준다」는 인상이 남는다 | ⑤ 사이클에 **N-8 을 같이** 넣는다. 못 넣으면 쪽지도 미룬다 |
| **R-8** 🔴 | **강지원** | **대리점이 내 글을 읽는다는 걸 고객이 알면 싫어한다** | 지역 대리점은 **같은 동네 사람**이다. 「3월 매출이 안 맞아요」를 옆 건물 사장이 읽는다고 생각하면, 고객은 **쪽지를 안 쓴다.** 약관 고지는 결재됐지만, 약관은 아무도 안 읽는다 | **쪽지 쓰는 그 화면에 한 줄**: 「이 내용은 담당 대리점과 본사 상담원이 봅니다」 + **「본사만 보기」 고르기 1칸**(고객이 고른 건 대리점에 안 보낸다). 이건 **설계·법무 결재 사항**으로 올린다 |
| **R-9** | **강지원** | **완료 후 만족도 묻기 — 안 쓸 것 같다. 1차에 넣지 말자** | 답 받고 또 뭘 누르라고 하면 **고객이 피곤해한다.** 응답률은 ⚠️추정 1할 밑이고, 그 1할은 **화난 사람만** 눌러서 숫자가 거짓이 된다 | **보류.** 꼭 재야 하면 「해결됐나요 / 아직이에요」 **두 칸만**, 그것도 2차 이후 |
| **R-10** | **강지원** | **공통장애 선언(F-23)을 대리점이 할 수 있으면 남용한다** | 자기 미처리 숫자를 **장애로 묶어 빼면** 성적이 좋아진다. 사람은 평가받는 숫자를 피한다 | **장애 선언은 본사만.** 대리점은 「장애 같아요」 **신고**만 |
| **R-11** 🔴 | **강지원** | **미처리 숫자가 거짓이 되는 길이 셋이다 — 셋 다 막아야 F-20 이 쓸모 있다** | ⓐ 고객 답 대기(N-2) ⓑ 한 고객 중복 접수(N-3) ⓒ 공통장애 묶음(F-23 — 이미 완료 기준에 분리 표시 있음 🟢) | ⓐⓑ 를 **ⓒ와 같은 격**으로 다뤄 주십시오. 하나만 빠져도 **대리점 평가가 분쟁이 된다** |
| **R-12** | **기술영업팀장** | **CS 비용 본사 부담(§8-7 ⓐ)은 찬성인데, 한 고객이 폭주시킬 수 있다** | 쪽지가 쉬우면 **하루 20건 쓰는 집**이 반드시 나온다 ⚠️추정. 그 집 하나가 그 달 비용을 다 쓴다 | 상한을 **고객에게 걸지 않는다**(고객 막으면 그게 바로 해지 사유다). **「자동 초안 쓰는 횟수」에 상한**을 걸고, 넘으면 **사람이 받는다.** 느려질 뿐 막히지 않는다 + 관찰 화면(**9. 설정**) |
| **R-13** | **마케팅팀장** | **공개 도움말(N-9)을 급히 열면 우리 민망한 게 바깥에 남는다** | 설명이 엉성한 문서가 공개되면 **검색에 그대로 남는다.** 지우기 어렵다 | 공개는 **CS팀장 승인 + 한 단계 더**(마케팅 확인). 공개 문서는 **#23 금지어 + 고객 식별정보 검사**를 통과해야 열린다 |
| **R-14** 🔴 | **강지원** | **우리는 지금 「누가 CS 를 받나」가 안 정해져 있다** | 기능을 아무리 잘 만들어도, **⑤ 사이클 때 앉아서 답할 사람이 몇 명인가**가 안 정해지면 전부 밀린다. 접수 창구를 열면 양이 2~3배로 뛴다 ⚠️추정 | 🔴 **사람 배치는 사장님 결재 사항**이다. 우리는 「기능보다 이게 먼저다」만 올린다 |
| **R-15** | **기술영업팀장** | **F-18(결제상태 읽기전용)이 현장에서 가장 자주 깨질 유혹이다** | 「미납이라 막혔는데요」 전화를 받은 CS 직원은 **그 화면에서 풀어주고 싶어한다.** 못 풀면 **6. 결제·구독**으로 가야 하는데, 급하면 **아무나에게 전화해서 풀어달라 한다** — 그게 흔적 없는 해제가 된다 | 읽기전용은 유지(결재됨). 대신 **「풀어달라 요청」 1동작**을 CS 화면에 두고, 그 요청이 **6번에 줄로 쌓이게** 한다. 말로 부탁하는 길을 막는 유일한 방법이다 |

## §9 한 줄 요약

> **강지원(CS팀장)**: 접수 창구를 여는 건 찬성이다. 다만 **열면 밀려온다.** 밀려올 때 안 무너지는 장치 — 답 약속 시계·고객 답 대기 칸·내 응대함·중복 합치기 — 가 같이 가야 한다. 그리고 **「숫자가 안 맞아요」와 「돈 얘기」에는 AI 초안을 만들지 말아 주십시오.** 이 둘만 지켜지면 나머지는 고쳐 가며 쓸 수 있다.

> **기술영업팀장**: 이 기능은 **팔린다.** 단 「AI」로 팔면 안 되고 **「물어볼 데가 있는 ERP」**로 팔아야 한다. 그리고 계약 갱신에 쓸 **성적표 한 장**이 나오게만 해 주십시오. 그게 더존·이카운트가 못 주는 종이다.

> **마케팅팀장**: 30초 설명은 **「화면 안에서 묻고, 화면 안에서 받는다」** 한 줄이다. 🔴 그 한 줄이 성립하려면 **「답 왔습니다」가 ERP 화면에 보여야 한다.** 그게 없으면 설명이 거짓말이 되고, 거짓말로 판 기능은 반드시 돌아온다.
