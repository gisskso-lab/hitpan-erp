▶ 경우 (나) K-결함 — 측정 코드에 「키보드 도달 0(측정됨)」 판독을 만든다

- `tabTo` 는 못 가도 throw 하지 않고 `{ reached:false, cause:'keyboard-unreachable', tabs, path }` 를 돌려준다. **아래 4조건을 모두 채울 때만** 그 표본을 유효(valid=true)로 센다. 하나라도 빠지면 지금처럼 「장치 실패」.
  - U1 측정 전 회로 연결 양성 대조 통과 · U2 경로의 초점이 움직였고 1번 줄 뒤 요소에 1회 이상 도달 · U3 같은 런의 같은 칸 /after 에서 도달 ≥ 1(판정 함수 양성 대조) · U4 같은 표본에서 1번 줄 R1 구조가 K-결함 조건과 같음

▶ 경우 (가) K-장치 — 판정 함수를 고친다

- `describe` 의 상태 단추 판정을 R2 에서 실제로 초점을 받은 꼴(예: 줄 안 `.mud-menu-activator` · `[tabindex]` 요소)까지 넓힌다. 넓힌 판정은 /after 양성 대조(7회 도달)가 그대로인지 자체시험으로 묶는다. **음성 대조 추가(C2-4)**: 1번 줄의 상태 단추가 아닌 초점 요소(예: 같은 줄의 다른 칸 · 다음 줄 요소)에 넓힌 판정이 `false` 를 내는지 자체시험에 넣는다 — 양성만으로는 넓힌 판정이 아무거나 잡는 것을 못 막는다.
- /before 는 지금 설계대로 정상 측정. 판정 글자 · 기대값 변경 0. 리허설부터 다시(장전 전이므로 회차 아님 · 설계 §4-2 끝 줄 규칙).

▶ K-미결 — 장전 금지 · HQA 에 구조 기록(R1 · R2)을 보이고 회신을 받는다.

### 12-3. Y2 잔여 — `=` · `.` · `-` 바로 뒤 base64

- 원인: `mask.js:19` `B64_RE` 의 앞쪽 금지 글자 `[A-Za-z0-9+/=._-]` 에 `=` · `.` · `-` · `_` 가 있어 시작 자리가 없다. 대신 도는 `TOKEN_RE` 는 `+` · `/` 에서 끊겨 22자 미만. 숫자 없는 base64 는 `isB64Secret`(`:93` 대 · 소 · 숫자 셋 다)에 막힌다.
- 고침 방향: ① 앞쪽 금지 글자를 **base64 몸 글자 `[A-Za-z0-9+/]` 만**으로 줄인다(`=` · `.` · `-` · `_` · `:` · `?` · `&` 뒤 시작 허용) ② 뒤쪽은 몸 글자 + `=` 만 금지 ③ `isB64Secret` 의 숫자 요구를 「숫자 **또는** 몸 안 `+`/`/` **또는** 끝 `=` 패딩」 으로 완화(대 · 소문자 둘 다는 유지) ④ leak-scan 은 같은 `findSecrets` 를 쓰므로 함께 바뀐다(한 함수 원칙 유지).
- 오탐 경계: 러너 경로는 ① 단계(`<러너>`)가 먼저 바꾼다. 점 · `-` 로 잘린 파일 이름 · CSS 주소 · 선택자는 22자 덩어리가 안 된다 — **대조군으로 확인**한다(아래 지시서 §G2-3).

> **S4 관문 ① — 화살표 연타 항목(N-1)의 대조판**
> 결재된 범위대로면 /before(운영 판)는 키보드로 목록을 못 열어서 N-1 은 「대조 무효(통과로 안 셈)」 가 됩니다. 11/13 결재에 이미 들어 있는 경우이고, 리허설 3 에서 실제로 확인했습니다. 이대로 가면 A′ 의 핵심 고침(화살표 연타 때 연결이 끊기는 문제)은 GitHub 서버 측정에서 「고쳐졌다」 는 증거가 0 인 채로 관문 ② 로 갑니다. 측정 장치를 개발팀이 만든 경로라서, 문제를 재현하는 대조판이 없으면 「고쳐졌다」 와 「장치가 그 틈을 못 만들었다」 를 가를 수 없습니다. 어떻게 할까요?
