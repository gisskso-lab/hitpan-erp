## §2 [판정] 판정식

## §4 [API] 읽기 · 응답 칸

```sql
SELECT CAST(t.tenant_id AS CHAR) AS TenantId,
       t.owner_collected_at AS LastErpStartAt,
       CASE WHEN EXISTS (SELECT 1 FROM tenant_update_state u
                          WHERE u.tenant_id = t.tenant_id) THEN 1 ELSE 0 END AS HasUpdateReport,
       CASE WHEN EXISTS (SELECT 1 FROM serial_verify_attempts a
                          WHERE a.tenant_id = t.tenant_id
                            AND a.result = 'installer-bootstrap') THEN 1 ELSE 0 END AS HasSerialPass
FROM tenants t
WHERE t.tenant_id IN @Ids
```

- 🔴 **SQL 문자열 안에 `--` 를 쓰지 않는다.** 설명은 C# 주석으로. 줄끝 `--` 다음 줄 매개변수 꼴을 원천 차단한다.
- `Ids` = 첫 문장이 돌려준 `TenantId`. 클라이언트 값이 아니다. 빈 목록이면 문장을 보내지 않는다.
- `HasUpdateReport` · `HasSerialPass` 는 `long` 으로 받는다. 결과형은 판마다 다르다 — 게이트가 MySQL 8 실물로 잰다.

| 코드 자리 | 내용 |
|---|---|
| 신규 `src/HitPan.Backoffice.API/Services/TenantInstallStateReader.cs` | 상수 3개 · `Decide(lastErpStartAt, hasUpdateReport, hasSerialPass)` · `FillAsync(db, rows, logger, ct)` |
| `TenantsAdminController.List` | `QueryAsync` 결과를 `AsList()` 로 받고 `FillAsync` 1줄 |
| `TenantsAdminController.Get` | `row is null` 판정 뒤 · 결제 조회 앞에 `FillAsync` 1줄 |
| `TenantRow` (`:363`) | 널 허용 칸 2개. `TenantDetailRow` 는 상속으로 따라온다 |

| 응답 칸 | 형 | 뜻 |
|---|---|---|
| `InstallState` | `string?` | `installed` · `started` · `none` · `null` |
| `LastErpStartAt` | `DateTime?` | 최근 ERP 기동 보고 시각(UTC). 설치 시각이 아니다 |
| `IsLocked` · `BootstrapAt` | 유지 | 화면이 안 읽어도 지우지 않는다(#1 · #37 정신) |

**역호환**: 구판 화면 + 신판 API = 모르는 칸 무시 · 지금과 같은 표시. 신판 화면 + 구판 API = 칸 없음 → `null` → 「확인 불가」(배포 순간 · 되돌림 중 잠깐). F-3: 값 없는 고객 1건이 화면 전체를 가리지 않게 새 칸은 전부 널 허용.
