### §0-1 🔴 한 줄 결론

**원인은 423 이 아니다. `:565`+`:567` 의 이중 포장 하나다.**
서버가 보낸 **본문 전체(이미 JSON)** 를 다시 JSON `message` **문자열 안에** 싸고, 그걸 평면 파서로 읽어 **앞 두 글자 `{\`** 만 남는다.
**401·423·500·400 전부 같은 글자**를 띄운다 ⇒ **1종 → 1종**이고 **1차수 전부터 그랬다.**

### §0-2 🟢 이 설계가 재서 알아낸 가장 중요한 한 가지

**423 의 서버 `message` 에 「1시간 뒤 다시 시도해주세요」가 이미 들어 있다**
(`InstallerBootstrapController.cs:164`·`:187` — `"시리얼 입력 5회 실패로 잠시 중지되었습니다. 1시간 뒤 다시 시도해주세요."`).
⇒ **설치본이 문구를 지어낼 필요가 없다.** 서버 `message` 를 **그대로** 전달하면 사장님이 요구한 「약 1시간 뒤 다시 시도할 수 있습니다」가 **그 자체로 닿는다**(실측 §1-3).

### §0-3 🔴 거짓이 되지 않게 미리 적는다

**이미 고객 PC 에 들어간 설치 EXE 는 이 봉합으로 안 고쳐진다.**
설치본은 자동업데이트 대상이 아니다(부트스트랩은 **설치 중**에 돈다). 효과는 **이 봉합 뒤에 새로 내려받는 EXE 부터**다.
⇒ 보고·공지에 「고쳤다」로 쓰면 **거짓**이다. 「다음 설치본부터 닿는다」로 쓴다.

### §1-2 파서가 왜 두 글자에서 멈추나 (`:359-360`)

```
while (EndPos <= Length(Json)) and (Json[EndPos] <> '"') and (Json[EndPos] <> ',') and (Json[EndPos] <> '}') do
```
값의 **종료 조건이 `"` · `,` · `}` 세 글자 중 아무것**이다.
⑤ 가 만든 값의 첫 글자는 `{`, 둘째가 `\`, 셋째가 `"` ⇒ **`{\` 에서 멈춘다.**

### §1-3 🟢 재실측 (내가 직접 · Windows PowerShell **5.1.26100.9444** · 실물 EXE 아님)

로컬 `HttpListener` 로 **423 + 한글 JSON** 을 돌려주고 `:563-571` 을 그대로 돌렸다.

```
ExceptionMessage : 원격 서버가 (423) Locked 오류를 반환했습니다.
ErrorDetailsNull : False          ← ErrorDetails 가 채워진다 ⇒ :565 가 본문 전체를 집는다
StatusCode       : 423
```

이어서 **지금 조립식 vs 제안 조립식**을 같은 본문 4종에 먹이고, **`ExtractJsonValue` 를 충실히 옮긴 복제본**(⚠️ 복제본이다 — §3-0 참조)으로 최종 글자를 재었다.

| 서버 응답 | 지금 고객이 보는 글자 | 제안 뒤 고객이 보는 글자 |
|---|---|---|
| 423 잠금 (`:164`) | **`{\`** (2자) | `시리얼 입력 5회 실패로 잠시 중지되었습니다. 1시간 뒤 다시 시도해주세요.` (42자) |
| 401 시리얼 (`:198`) | **`{\`** (2자) | `올바르지 않은 시리얼이거나 승인되지 않은 계정입니다.` (29자) |
| 500 서버 (`:389`) | **`{\`** (2자) | `부트스트랩 처리 중 오류가 발생했습니다.` (22자) |
| ⚠️**쉼표를 품은 message**(가상) | **`{\`** (2자) | `PC 정보가 누락되었습니다` — 🔴 **쉼표에서 잘린다** |

🟢 **ConvertTo-Json 은 PS 5.1 에서 한글을 `\uXXXX` 로 바꾸지 않는다**(실측 — 성공 경로 `:560` 이 이미 이 방식이라는 것과 일치).
🔴 **남는 구멍**: 서버 `message` 에 `"` · `,` · `}` 가 들어가면 **조용히 잘린다**. 오늘 서버 메시지 **4종에는 쉼표 0건**이라 안 터지지만, `:564` 폴백(`$_.Exception.Message`)은 통신 사고 문구라 **쉼표를 품을 수 있다** ⚠️(전수 미측정).

## §2 바꾼 경로 (설계안 · 자리 3개)

### §2-1 S-1 (필수) — PS `catch` 에서 **한 겹만** 꺼낸다 (`:563-571`)

**원칙**: 손으로 JSON 문자열을 만들지 않는다. 서버가 준 `message` **한 겹만** 꺼내 `ConvertTo-Json` 에 맡긴다.

의도(구현은 [3] 이 작성 · 아래는 설계 규약):

1. `$human` 을 다음 순서로 정한다 — ⓐ `$_.ErrorDetails.Message` 를 `ConvertFrom-Json` 해서 `.message` 가 있으면 그 값 · ⓑ 실패하면 `$_.ErrorDetails.Message` 원문 · ⓒ 그것도 없으면 `$_.Exception.Message`.
2. `ResponseFile` 에 쓰는 내용은 **`[pscustomobject][ordered]@{ success=$false; message=$human } | ConvertTo-Json -Compress`**.
   🔴 `@{}` 해시테이블을 그냥 넘기면 **키 순서가 뒤바뀐다**(실측: `message` 가 먼저 나왔다). `[ordered]` 로 `success` 를 앞에 고정한다 — `:601` 의 `Pos('"success":true')` 판정에 영향은 없지만 사람이 읽는 순서를 고정한다.
3. `ErrorFile`(`:569`)·`exit 1`(`:570`)·TLS 블록(`:555-556`)·요청 조립(`:539-543`)은 **무접촉**.
4. 🔴 **`:557-562` 성공 경로는 한 글자도 안 건드린다.**

### §2-2 S-2 (필수 · **추가형**) — `message` 만 제대로 읽는 함수를 **새로 만든다**

`ExtractJsonValue`(`:339-365`)는 **고치지 않는다** — 9개 이름이 그 함수에 매여 있다(§4-2).
대신 **새 함수 `ExtractJsonString(Json, Key): String`** 을 추가하고 **`:603` 한 곳에서만** 쓴다.

규약:
- 여는 `"` 를 **반드시 요구**한다(없으면 빈 문자열).
- **이스케이프하지 않은 `"` 에서만** 끝낸다 ⇒ `,` `}` 가 값 안에 있어도 안 잘린다.
- `\"` `\\` `\/` `\n` `\r` `\t` 를 풀고, `\uXXXX` 는 해당 글자로 바꾼다.
- 🔴 **평면 검색은 그대로 둔다** — 바깥 `message` 하나만 찾으면 되고(§4-2), 검색 규칙을 바꾸면 비교 대상이 둘이 된다.

**왜 필요한가**: S-1 만 하면 오늘은 닿지만, 서버가 `message` 에 쉼표 한 개를 더하는 날 **조용히 다시 잘린다**(§1-3 4행). 같은 PR 에서 막는다.

### §2-3 S-3 (**결재 사항** — 내가 정하지 않는다) — 고객이 읽을 문구

지금 `:605` 머리글은 **`시리얼 인증 실패:`** 다.
🔴 **423 은 시리얼이 틀린 게 아니라 잠긴 것**이다. 고객은 「내 시리얼이 잘못됐나」로 읽고 **시리얼을 다시 찾으러 간다** — 다음 행동이 틀린다.

| 안 | 머리글 | 본문 |
|---|---|---|
| **A (권고)** | `설치를 계속할 수 없습니다` | 빈 줄 + **서버 `message` 그대로** |
| B (현행 유지) | `시리얼 인증 실패:` | 서버 `message` 그대로 |

- 안 A 는 401·423·500 **전부에 맞는 한 문장**이고, 다음 행동은 서버 `message` 가 말한다(423 = 1시간 뒤 · 401 = 시리얼/계정 확인).
- 🚫 설치본이 **상태코드를 보고 문구를 지어내지 않는다** — 서버가 유일한 문구 원본이다(#23 개발용어 0 · 중복 원본 0).
- 🚫 「인터넷·방화벽 확인」 같은 안내를 이 분기에 붙이지 않는다 — **응답은 왔다.** 틀린 안내가 된다(그 안내는 `:589` 의 **다른 분기** 몫이고 그 줄은 무접촉).
- 🔴 **머리글 변경은 오더 범위 경계에 있다.** 설계만 올리고 **PM 결재 없이는 B(현행)로 둔다.**

- 동작: ISCC 컴파일 → 생성 EXE 를 `/SELFTEST="<입력 json 파일>" /SILENT` 로 실행 → `InitializeSetup` 이 `ExtractJsonString`/`ExtractJsonValue` 를 **실물로 호출**해 결과를 파일에 쓰고 **아무것도 설치하지 않고 종료**.
- 입력: **G-T6-1 이 만든 `ResponseFile` 실물**(손으로 쓴 fixture 금지 ⇒ G-7 함정 차단).
- 단언: 최종 문자열 == 서버 `message` (문자 단위) · 길이 ≠ 2.
- 🔴 **봉합을 빼면**: 같은 하네스에 **옛 `ResponseFile`** 을 먹였을 때 **`{\`(길이 2)** 가 나와야 한다 — 이것이 **음성대조군**이다. `ExtractJsonString` 을 빼고 `:603` 을 옛 함수로 되돌리면 **쉼표 케이스가 FAIL** 한다.
- 🔴 **쉼표 케이스를 반드시 넣는다** — S-2 를 빼면 **여기서만** 떨어진다(S-1 만으로는 통과하므로).

### §3-4 S-2 를 재는 차선 (ⓑ1 이 CI 에서 못 서면)

ⓑ1 이 ISCC·`#include` 때문에 서지 않으면, **그때만** ⓑ(복제본)로 간다. 그 경우 반드시 함께 붙인다:
1. 시험이 `.iss` 에서 `ExtractJsonString` **본문 텍스트를 뽑아** 정규화 해시를 비교 — `.iss` 가 바뀌면 **FAIL**(시험 갱신 강제).
2. §3-2 의 음성대조군을 복제본 쪽에도 그대로.
🔴 **그래도 이것은 「복제본이 실물과 같다」를 증명하지 않는다.** 차선임을 **문서와 시험 주석 양쪽에 적는다.**

### §3-5 **G-T6-3** — 성공 경로 9개 이름 불변 (회귀)

- 같은 ⓑ1 하네스에 **성공 응답**(중첩 `domain`·`bootstrap` 포함)을 먹여 **9개 전부**를 단언: `tenantCode` `companyName` `primary` `api` `tunnelToken` `tunnelId` `token` `tokenKey` (+ `message` 는 **빈 문자열**이어야 한다).
- 🔴 **이 게이트는 봉합을 빼도 통과한다** — 회귀 감시용이므로 그대로는 「동작으로 재는 게이트」 조건을 못 채운다. 그래서 **민감도 대조군**을 하나 붙인다: `ExtractJsonString` 을 **9개 전부에** 일부러 적용한 변종에서 **최소 1개 이름이 FAIL** 해야 한다(안 그러면 이 게이트는 아무것도 재지 않는다).
- §1-3 복제본 측정으로 **오늘 9개가 전부 제대로 집히는 것**은 확인했다(대조군 통과).

### §3-6 **G-T6-4** — CI 등록

- `watchdog-ci.yml` 에 **실행 잡**을 더한다: `installer-bootstrap-message` (**windows-latest** — `HttpListener` + `powershell.exe` 5.1 + ISCC 가 필요).
- 🟢 깨어나는 조건은 이미 맞다(`installer/**`). 🔴 **required check 등록은 레포 설정 ⇒ PM 결재**(§8-D4).
- 🔴 기존 두 잡(`installer-validate`·`scenario-lint`)은 **그대로 둔다**(지우지 않는다 · #1).
