## §1 [문제]
- 문제: HQA 가 독립 실행 환경을 못 갖춰 관문 ① 이 「실행 미실시」(외부지적서 PM 대응 §5 L850-7). 개발 PC 실측은 증거가 안 된다(개발PC 정상 ≠ 검증).
- 목표: 개발 PC 밖(GitHub 호스트 러너 · ubuntu-24.04)에서 11/7 항목 + N-1 · N-2 를 재고, **원자료 · 장치 원문 · 기대값을 HQA 가 로그인 없이 SHA 고정 링크로** 대조할 수 있게 한다.
- 대표 결재가 이미 드러낸 조건: 장치는 개발팀 몫 → 독립성 감소. 그래서 **발행 전 고정 · 장치 원문 공개 · 원자료 대조**로 메운다(결재 §3).

### 4-3. 장치 판독 규칙 (장전 전 커밋 · 결과 본 뒤 변경 = 새 회차)
- 판독 글자는 정본 글자만 쓴다: N-1 = 11/13 §6 「대조 무효 / 🔴 / 🟡」 그대로. 11/7 항목 중 정본에 기대값 글자가 있는 것(I-6 두 목록 0 · I-7 행 클릭 0 · F10 다른 줄 0)만 기계 판독, **나머지는 「판독값 기록 · 판정 = HQA」** — 장치가 기대값을 새로 만들지 않는다.
- 회로 죽음 신호 = 재연결 표시 요소(blazor 기본 `components-reconnect-*`) 보임 · 페이지 이동 아닌 웹소켓 닫힘 · 회로 종료 꼴 콘솔 오류 — 셋을 따로 기록하고 「하나라도 = 죽음」. 신호 정의의 맞음은 `/before` 대조가 재현하는지로 드러난다(재현 0 = 대조 무효 · 통과로 안 셈).
- **잰 표본 0 = 빨강**: 계획 칸(항목 × 화면 × 지연 × 창)마다 유효 표본 ≥ 1. 하나라도 0 이면 그 칸 「장치 실패」 + 잡 빨강. `/before` 표본 0 도 빨강(「대조 무효」 와 구별: 무효 = 표본 있음 · 재현 0).
- 표본 수 · 간격 · 횟수는 장치 원문 `rules.json` 한 곳(③ 회신 대기).

### 4-4. 입력 · 문맥 규칙
- 신뢰 입력만(11/7 C4 「JS 합성 키 = 측정 무효」). 자체시험에 정적 검사: 측정 스크립트에 `dispatchEvent` · evaluate 안 `click(` · `focus(` · `KeyboardEvent` 생성 0.
- 시험 앱에 스크립트 주입 0(addInitScript 0) — 읽기는 측정 시점 evaluate 로만.
- 이전 내부 측정 스크립트(레포 밖 · Windows · Edge)는 **읽지도 옮기지도 않는다**. 구현 담당은 정본 글자 · 시험 앱 README · 이 설계서만 받는다(11/13 X-5 꼴 · 결과 비공개).

### 4-5. 자체시험 (리허설 · 장전 둘 다 · 측정 전에)
- 판독기: 손으로 만든 JSONL 4벌 — 「after 회로 죽음 1건(🔴 나와야)」 · 「before 재현 0(대조 무효 나와야)」 · 「칸 표본 0(빨강 나와야)」 · 「정상(기록)」. 기대와 다르면 [장치] 빨강.

## §5 [원자료] 형식 · 가림 · 커밋

| 파일(`hqa-raw/<런ID>-<시도>/`) | 내용 |
|---|---|
| `run.json` | 런 ID · 시도 · 잡 이름 · 장치(장전) 커밋 SHA · 시험 앱 나무 해시 · MODE · 러너 이미지 판(ImageOS · ImageVersion) · Node · Playwright · 브라우저 판 · 시작/끝 UTC · 고정 머리 ls-remote 2회 |

| `samples.jsonl` | 표본 1줄 = 항목 · 화면 · 지연 인자 · 창 · 표본 번호 · 시각 · 입력 열 · 판독값 · 회로 신호 3종 · 스크린샷 이름 · errors |

| `SHA256SUMS.raw` | 위 파일 전부의 SHA-256 (자기 자신 제외) |

- **gitignore 함정**: 확장자는 `.json` · `.jsonl` · `.txt` · `.png` 만(`*.log` · `*.zip` 안 씀 · [1-V] P2). publish 잡이 `git check-ignore` 를 파일마다 돌려 **하나라도 걸리면 빨강**(`-f` 강제 추가 금지 · 루트 `.gitignore` 수정 0).
- **가림(M8)**: 텍스트 파일만 · ① 러너 경로(`GITHUB_WORKSPACE` · `RUNNER_TEMP` · `HOME` 실값) → `<러너>` ② 영숫자 · `-_` 22자 이상 토큰 중 40자 · 64자 16진(SHA)이 아닌 것 → `<가림:n>`(회로 ID 후보 · CTO 11/13 「22자 이상 토큰」 기준) ③ 데이터 보호 키 폴더 내용 수집 0. 가린 개수는 `run.json` 에 수로만.
- **누출 검사(M9 · publish 잡에서 다시)**: 가린 뒤 남은 꼴 0 이어야 통과 · 걸린 파일은 커밋에서 빼고 `withheld.json` + 잡 빨강 · 「통과분만 공개」([1-V] §7-5).
- **커밋**: publish 잡만 `contents: write` · measure 잡은 `read` · 워크플로 머리 `permissions: {}`(잡별로만 줌). 원자료 가지가 없으면 장전 커밋에서 새로 만들고, 있으면 그 가지 끝의 첫 부모 사슬에 장전 커밋이 있는지 단언 뒤 덧붙임(다른 회차 섞임 0). 강제 push 0 · 커밋 메시지에 런 ID · 시험 앱 나무 해시.
- **운반 산출물**: 잡 사이 전달용 · `retention-days: 90`(7일 금지 · [1-V] §7-4) · 판정 근거는 커밋 blob 뿐.
- 외부 액션: `actions/checkout` · `upload-artifact` · `download-artifact` 만. 쓰기 잡의 액션은 전체 SHA 고정을 권함(⚠️ [3-V] 결정 · 선례는 태그 고정).

## §6 [고정] 발행 전 고정 · 점화 순서

1. 갈래 A·B 구현 → 장치 가지 push(`MODE=rehearsal`) → 리허설 런: M0~M4 + 자체시험 → 원자료 가지(리허설)에 커밋. Linux 첫 기동 결과가 여기서 처음 나온다 — 실패면 단계 · 오류 글자 원자료를 근거로 고친다(항목 측정 0 이라 결과 오염 0).
2. [3-V] · [4] 가 장치 원문 + 리허설 원자료를 본다(§7-3).
3. 범위 재확정(3인 → CTO → 대표 최종) 끝.
4. **발행**: PM 이 #850 에 장치 커밋 D 의 SHA 고정 링크(워크플로 · `rules.json` · 측정 스크립트 · 대응표) + 판정 기대값 정본 §6 링크 + HQA 회신 반영 표를 댓글로. 댓글 생성 시각 = 고정 시각.
5. **장전**: D 위에 `tools/hqa-s4-measure/MODE` 한 파일만 `armed:<D 전체 SHA>:r1` 로 바꾼 커밋 E push. M0 이 「D..E diff = MODE 한 줄 · 적힌 SHA = 부모」 를 단언. 런 생성 시각 > 발행 댓글 시각을 `run.json` 과 댓글로 대조 가능.
6. 결과 본 뒤: 장치 · 규칙 · 조건 변경 = D′ → 리허설 → 재발행 → `r2` 장전 → 새 원자료 가지. `[측정]` 빨강 재실행 금지 · `[장치]` 빨강은 같은 커밋 재실행 1회(선례 규칙 꼴) — 재실행도 원자료에 시도 번호로 남음.
