## §5 CS 파이프라인 — 사장님 질문 판정 🔴 핵심

> 「히트판ERP에서 cs요청을 쪽지나 채팅으로 바로 본사 백오피스나 대리점에 연결 시킬수 있는 파이프라인 설계는 어떄?」

**판정: 해야 한다. 단 「채팅」이 아니라 「쪽지」로 1차를 열고, 본문 검사 게이트와 법무 확인을 같은 묶음으로 간다.**

### ⓐ 왜 좋은가
지금 CS 는 고객이 **전화로** 알려야 티켓이 생긴다(Q-4 결재 「전화 기록 의무 = CS 들어오는 모든 영역」). ERP 화면에서 바로 넘기면 ① 고객이 화면을 안 떠난다 ② 어느 화면에서 났는지(`screen_code`)·어느 판인지(`erp_version`)가 **자동으로 실린다** — 이 두 칸은 이미 DB명세서 `bo_cs_tickets` 에 설계돼 있다. CS 자동 분류(F-21)의 정확도가 사람이 적어 주는 것보다 올라간다.

### ⓑ 방향은 한 쪽뿐이다 (3시스템 구조의 제약)
ERP 는 **고객사 PC 로컬 + 터널**이고 본사는 NCP 다. 본사가 고객 PC 를 먼저 두드리는 길은 없다(원칙 #30 — 본사 의존 0). 그래서:

```
[ERP 화면] 고객이 CS 요청 쓰기
     │ ① 즉시 Push (구독결제와 같은 길 · 실패하면 로컬 큐 + 재시도)
     ▼
[백오피스]  bo_cs_tickets 행 생성 → 직판이면 본사 1차 · 코드 경유면 대리점 1차 (F-14)
     │ ② 응대 작성 (사람 · 또는 누리집에서 답 고르기)
     ▼
[ERP]  다음 Pull(5분) 또는 접속 시 수신 → 고객 화면에 「답 왔음」 알림
```

- **1차 = 쪽지(비동기)**: 위 그림 그대로. 고객 PC 가 꺼져 있어도 켜지면 받는다. 지금 있는 Push·Pull 길을 그대로 쓰므로 통신 무결성 17시나리오를 새로 흔들지 않는다.
- **2차 = 실시간 채팅**: 터널 양방향(WebSocket)이 필요하다 — 자동 복구 시나리오를 다시 재야 한다. **1차가 돌고 나서** 별건으로 판단하기를 권고한다. 「쪽지로도 왕복이 되는데 채팅이 꼭 필요한가」를 그때 실물로 보고 정하는 게 싸다.

### ⓒ 반드시 같이 가야 하는 것 — 본문 (법무·보안 🔴)
CS 티켓 **본문**은 고객이 자유롭게 쓴다. 「3월 A거래처 매출이 안 맞아요」라고 쓰면 거래처·금액이 본사로 들어온다 — 이건 **#18·#22(본사로 업무 데이터 전송 금지)** 의 경계다. CS 응대에 필요한 최소한은 받아야 하므로, 받되 막는다:

1. **금지필드 자동 검사** — 주민번호·카드번호·계좌·사업자번호 패턴은 송신 단계에서 **거부**(F-19 가 이미 같은 장치를 쓴다 · 음성 대조군 = 금지필드 실은 전송이 막히는지 실측).
2. **화면 스냅·첨부** — 보낼 때마다 고객 동의 1회 + 보존기간 적용(Q-5 본사 설정값). 동의 없으면 본문만.
3. **보존·파기** — F-25 그대로(90일/6개월/1년/3년 본사 설정 + 배포 후 초기 3년 축적).
4. **법무팀장·보안상무 확인 필수** — 사장님 지시(「개인정보·보안 법적분쟁 이슈는 법무팀장·보안상무 피드백」)에 정확히 해당한다. 약관에 「CS 요청 시 입력 내용이 본사·대리점에 전달됨」 고지가 들어가야 하고, **대리점이 본다**는 점 때문에 위탁계약(작9 법무 묶음)과 한 묶음이다.

### ⓓ CS 누리집 (cs.md) — 설계 제안
- **사람이 쓰는 누리집 먼저.** 대리점·본사 직원이 「이 증상엔 이렇게」를 찾아 쓰는 문서. 챗봇 지식 원칙(외부에서 긁어오지 않고 **CS팀장이 직접 정의**)과 정합한다.
- ⚠️ **파일 하나로 두지 말기를 권고**: `cs.md` 를 파일로만 두면 누가 언제 왜 고쳤는지, CS팀장이 승인했는지가 안 남는다. **DB 에 지식문서로 저장하고 md 형식으로 쓰고·보여주고·내보내는** 방식을 제안한다(쓰는 사람 입장에선 똑같이 md 를 쓴다 · 대신 이력·승인·버전이 남고 F-22 지식 라우팅 통계가 붙는다).
- 🔴 **AI 응대는 지금 열 수 없다**: 외부 AI 반출이 작9 게이트로 **fail-closed 차단** 상태다(동의 기록 0건 = 전면 차단 · 법무 판정 「현 상태 그 자체로 위법」). 선택지 둘 —
  - **(가)** 외부로 안 나가는 응대(누리집 검색 + 규칙 기반 「이 증상엔 이 문서」 제안) → **작9 와 무관하게 지금 가능**.
  - **(나)** 외부 AI 응대 → 작9 봉합 해제(법무 계약·고지 + 사장님 결재) 후. 그 전엔 게이트가 막는다.
  - 권고: **(가)로 열고, (나)는 법무 묶음이 끝난 뒤**. 반자동 원칙(F-21)대로 **사람 확정 전 고객 발송 0건**은 어느 쪽이든 지킨다.

## §8 AI CS 자동화 — 사장님 확정 오더 (2026-10-07) 🔴

### §8-1 오더 원문 (토론 대상 아님)

> 「.md형태의 cs누리집으로 AI를 활용한 cs자동화는 **꼭 진행할 예정**이야. 배포 후 터지는 수많은 이슈를 cs.md의 누리집 형태로 만들어 학습을 시키긴 하겠지만, **히트판에 대해 가장 잘 알고있는 현 어벤져스팀을 백오피스 api로 연결** 할 거야.」

> 「고객사의 히트판ERP에서 쪽지를 받는다 → 누리집에 이슈를 정리하여 접수한다 → 문제 해결시, 누리집으로 저장되어 AI는 학습하여, 비슷한 이슈에 AI자동화로 빠른대응을 한다.」

**⇒ §5 의 「AI 응대는 (가) 무경유부터」 권고는 사장님 오더로 갱신된다. 외부 무경유는 1차 발판일 뿐이고, 목표는 어벤져스팀 API 연결이다.** 단 그 문을 여는 열쇠는 작9 동의 원장이다(§8-4).

### §8-2 닫힌 고리 — 사장님이 그린 4단계

```
① 접수   고객사 ERP 에서 쪽지 → 백오피스 티켓 생성
             (화면코드·판 번호·증상 자동 실림 · 본문은 금지필드 검사 통과분)
              ▼
② 정리   누리집에 이슈로 정리하여 접수 — 증상·원인·재현 조건을 사람이 다듬는다
              ▼
③ 해결   대리점 1차 또는 본사 2차가 해결 → **해결 내용이 누리집 문서로 저장**
              ▼
④ 재사용  비슷한 이슈가 오면 어벤져스팀이 누리집을 근거로 답 초안을 즉시 만든다
              ▼ (사람 확정 후 발송 — 반자동 원칙)
          → 다시 ①
```

**고리가 돌 때마다 누리집이 두꺼워지고, 두꺼워진 만큼 ④가 빨라진다.** 이것이 이 설계의 전부다.

### §8-3 「학습」의 뜻 — 모델 학습이 아니라 **누리집 참조** (설계팀 판정 🔴)

사장님 말씀의 「학습」을 **모델 파인튜닝**으로 구현하면 안 된다. 이유는 셋이고, 셋 다 되돌릴 수 없는 종류다.

| | 파인튜닝(모델에 박는 방식) | **누리집 참조(채택)** |
|---|---|---|
| 삭제 요구 | 모델에 박힌 내용은 **지울 수 없다** — 개인정보 삭제권에 응할 방법이 없다 | 문서를 지우면 그 순간부터 안 쓰인다 |
| 틀린 답 | 잘못 학습되면 전체를 다시 만들어야 한다 | 문서 한 장 고치면 끝 |
| 왜 그렇게 답했나 | 설명 불가 | **근거 문서를 같이 보여준다** — CS팀장이 검산 가능 |

⇒ 구현은 **누리집 문서를 찾아 근거로 주고 답 초안을 받는 방식**. 사장님 말씀의 「학습」은 **누리집이 쌓여 똑똑해진다**는 뜻으로 받고, 그대로 성립한다. 우리 지식은 우리가 쥐고, 외부에는 그때그때 필요한 조각만 보낸다 — 본사 데이터 최소주의(#22)와 같은 방향이다.

### §8-4 어벤져스팀 API 연결 — 작9 게이트가 전제다

지금 외부 AI 반출은 **fail-closed 로 전면 차단**돼 있다(작9 · `ai_export_consents` 시드 0건 · 법무 판정 「현 상태 그 자체로 위법」). 이 봉합은 이 계획을 **막는 게 아니라 길을 내는 것**이다 — 동의 기록이 있으면 열리는 문이라, 지금 잠가 둔 자리가 그대로 어벤져스팀 연결 지점이 된다.

문을 열기 위해 필요한 것 (법무 묶음 — 작9 §7 재개 조건):
1. **개인정보 처리위탁 계약** — 외부 AI 제공자와. 위탁 사실·범위·기간 명시.
2. **국외이전 고지·동의** — 제공자가 국외면 별도 고지 항목이 필요하다(약관 개정).
3. **대리점 위탁계약** — 대리점이 고객 CS 를 본다는 사실 자체가 위탁이다. 작9 묶음과 한 몸.
4. **사장님 결재** + 동의 원장에 기록 1건 — 그 순간 게이트가 열린다.

### §8-5 어벤져스팀에 보내는 것·안 보내는 것 (보안상무·법무 필수 검토)

| 보낸다 | 안 보낸다 🔴 |
|---|---|
| 누리집 문서(우리가 쓴 지식 — 개인정보 없음) | 고객사 상호·사업자번호·담당자 이름·연락처 |
| 증상 요약 · 화면코드 · 판 번호 · 오류 메시지 | 거래처명 · 금액 · 재고 수량 등 **ERP 업무 데이터**(#18·#22) |
| 금지필드 검사를 통과한 본문 | 주민번호·카드·계좌 패턴(①에서 이미 거부) |
| | DB 접속 정보 · 토큰 · 라이선스 키 |

- ③에서 **누리집으로 승격할 때 고객 식별 정보를 전부 지우고 일반화**한다. 안 하면 A사 이슈가 B사 응대 중에 노출된다 — 테넌트 격리가 CS 지식에서 새는 길이다.
- 어벤져스팀이 **DB 를 직접 보지 않는다.** 백오피스 API 가 필요한 조각만 뽑아 넘긴다(권한은 서버 한 곳에서만 강제).

### §8-6 ③ 승격은 자동이 아니다 — 초안 자동 + 승인 수동 ⚠️

사장님 흐름의 「문제 해결시 누리집으로 저장」을 **완전 자동**으로 하면, 이미 결재된 원칙(지식 자동 승격 금지 · CS팀장 승인 필수)과 부딪힌다. 둘을 다 만족시키는 방식으로 설계한다:

- 티켓이 완료되면 **누리집 초안이 자동으로 생긴다**(증상·원인·해결 순서를 티켓에서 끌어와 md 로 채움 · 고객 식별 정보 제거된 상태).
- CS팀장이 **다듬고 승인**하면 누리집에 등재되고 ④에서 쓰인다. 승인 전 초안은 어벤져스팀에 안 넘어간다.
- 사장님 흐름은 그대로 돈다 — 사람이 하는 일은 「쓰기」가 아니라 「확인」으로 줄어든다. 자동화의 이득은 유지하고, 틀린 지식이 굳는 사고만 막는다.

### §8-7 비용·장부 ⚠️결재 필요

지금 챗봇 키는 **전부 고객사 것**이다(테넌트 BYOK). 그런데 어벤져스팀을 **본사 백오피스 API** 로 붙이면 호출 비용은 **본사가 낸다.** 정할 것:

| 선택지 | 내용 | PM 권고 |
|---|---|---|
| ⓐ 본사 부담 | 요금제에 포함 — CS 품질이 상품의 일부가 된다 | 🟢 **권고** — 「CS 가 빠른 ERP」가 팔리는 이유가 된다. 단 호출 상한·건당 비용 관찰 화면 필요(🆕E 설정) |
| ⓑ 고객 부담 | 고객이 키를 넣어야 CS 자동화가 돈다 | 쓰는 집만 쓰게 돼 ④의 고리가 안 돈다 |
| ⓒ 혼합 | 기본 제공 N건 + 초과는 유상 | 1차에는 과하다 — 쓰임을 본 뒤 |

⇒ ⓐ로 가면 결제 설계에 **본사 풀 과금 장부**가 처음 실제로 생긴다(지금까지 `hitpan_pool` 은 거짓 장부였고 작8에서 `byok` 로 교정했다). 🆕B 결제·구독 사이클에 한 줄로 들어간다.

### §8-8 고객에게 보이는 이름 ⚠️결재 필요
고객 화면에 「AI」라고 쓸지, **「히트판 도우미」** 같은 이름으로 쓸지. 개발 용어를 고객에게 안 보인다는 원칙(#23 계열)에 따라 **후자를 권고**한다. 내부 문서·설정 화면에서는 그대로 쓴다.

### §8-9 짓는 순서 (§6 에 얹음)
| 때 | 하는 것 |
|---|---|
| ⑤ CS기록 | ① 쪽지 파이프라인 · ② 누리집(DB 저장 + md 입출력) · ③ 승격 초안 자동 + CS팀장 승인 |
| ⑤ 뒤 (법무 완료 시) | ④ 어벤져스팀 API 연결 — 작9 동의 원장에 기록 1건으로 문이 열린다 · 반자동(사람 확정 전 발송 0건) |
