## §2 설계 — 4단

### §2-1 ① 서버 판 1회 판정 (기동 시)

`SELECT VERSION()` 1회. 문자열에 `MariaDB` 가 있으면 **MariaDB**, 없으면 **MySQL**.
로그 한 줄로 남긴다 — 어느 경로를 탔는지 나중에 사람이 알아야 한다.

```
[SchemaMigrator] 서버 판 = MySQL 8.0.45 → 호환 보정 경로
[SchemaMigrator] 서버 판 = 11.4.10-MariaDB → 종전 경로(무변경)
```

🔴 **MariaDB 면 종전 코드 경로를 그대로 탄다**(#1 — 수정은 OK, 덮어쓰기 금지). 기존 CI `db-gate` 의 백오피스 게이트가 회귀하지 않는 근거가 이것이다.

### §2-2 ② 문장 단위로 쪼갠다 (MySQL 경로에서만)

종전은 파일 하나를 **한 배치**로 보냈다. 보정 경로는 문장으로 쪼갠다 — 그래야 「이미 있다」를 문장별로 가릴 수 있다.

쪼개기는 다음을 인식한다: `'…'` · `"…"` · `` `…` `` · `--` 줄주석 · `#` 줄주석 · `/* … */` 블록주석.
그 밖의 `;` 를 경계로 삼는다.

🟢 **안전 근거 (14파일 전수 실측 2026-10-11)**: 문자열 안 `;` **0건** · 인라인 주석 안 `;` **0건**.
그래도 파서는 위 6가지를 인식하게 만든다 — 다음에 누가 그런 SQL 을 넣어도 안 깨지게.

### §2-3 ③ `IF NOT EXISTS` 토큰을 벗긴다 — **`ALTER` 계열만**

| 대상 (벗긴다) | 예 |
|---|---|
| `ADD COLUMN IF NOT EXISTS` → `ADD COLUMN` | 11·30·31·32·41·42·44 |
| `ADD KEY` / `ADD INDEX` / `ADD UNIQUE` / `ADD CONSTRAINT … IF NOT EXISTS` → 토큰 제거 | 31·42 |
| `DROP COLUMN` / `DROP INDEX` / `DROP KEY … IF EXISTS` → 토큰 제거 | (현재 0건 · 앞을 위해) |
| `MODIFY` / `CHANGE … IF EXISTS` → 토큰 제거 | (현재 0건) |

🔴 **건드리지 않는 것**: `CREATE TABLE IF NOT EXISTS` · `CREATE DATABASE IF NOT EXISTS` · `DROP TABLE IF EXISTS` — **MySQL 도 아는 문법**이다. 여기까지 벗기면 멱등성이 깨진다.

### §2-4 ④ 「이미 있다」는 적용됨으로 보고 **계속** — 그 밖은 종전처럼 중단

토큰을 벗기면 재실행 때 "이미 있다" 오류가 난다. 그것만 관용한다.

| 오류코드 | 뜻 | 처리 |
|---|---|---|
| **1060** | Duplicate column name | 🟢 넘어간다 + `LogInformation` 한 줄 |
| **1061** | Duplicate key name | 🟢 넘어간다 + 로그 |
| **1091** | Can't DROP … check that it exists | 🟢 넘어간다 + 로그 |
| **1826** | Duplicate foreign key constraint name | 🟢 넘어간다 + 로그 |
| 그 밖 전부 | — | 🔴 **종전과 같다 — 로그 + throw → 기동 중단** (#15·#19 유지) |

🔴 **1826 을 넣은 이유 (설계 도중 게이트가 잡아낸 자리)**: `31` 번은
`ADD CONSTRAINT fk_landing_signups_tenant FOREIGN KEY …` 를 **`IF NOT EXISTS` 없이** 쓴다.
파일이 중간에 실패하면 이력에 안 남아 다음 기동이 그 파일을 **처음부터** 다시 돌리는데,
그때 FK 이름 중복(1826)에서 또 멈춰 **영영 안 열린다.** 그 덫을 막는다.

🔴 **조용히 넘기지 않는다.** 관용 1건마다 파일명·문장번호·오류코드를 로그에 남긴다. 「덮어서 초록」이 이 설계의 실패 모양이다.

### §3-1 FAIL 대조 (#26 — 봉합 빼고 FAIL 확인) — 🔴 방법을 고쳤다

**처음 설계(커밋 2개로 쪼개 1커밋을 빨갛게)는 폐기했다.** 게이트가 보정 함수를 호출하므로
봉합 없는 커밋은 **컴파일이 안 된다** — 그건 FAIL 대조가 아니라 빌드 실패다. 대신 셋으로 간다:

| 축 | 어떻게 | 결과 |
|---|---|---|
| ① **운영 실측** (가장 강한 증거) | 보정 없는 코드가 **실물 MySQL 8.0.45** 에서 같은 파일을 돌렸다 | `1064 … near 'IF NOT EXISTS approved_at_dt` — 시뮬레이션이 아니다 |
| ② **같은 CI 실행 안의 대조군** G-M8-4 | 같은 DB 에 `11` 번 **원문을 종전 방식(통째 한 배치)** 으로 보낸다 | **1064 로 거부돼야 통과.** 거부되지 않으면 판이 MySQL 8 이 아니라는 뜻이므로 **게이트 전체가 무효**임을 그 자리에서 드러낸다 |
| ③ **무력화 시험** (로컬 · 2026-10-11 실측) | 봉합을 끄고 돌렸다 | **벗기기**를 끄면 G-M8-5b·5c FAIL (5a 초록) · **쪼개기의 인용·주석 인식**을 끄면 G-M8-5a 만 FAIL ⇒ **두 축이 서로 독립으로 걸린다** · 되돌린 뒤 sha256 **바이트 동일** 확인 |

🔴 로컬 PASS 는 증거가 아니다. 이 PC 에 MySQL 8 이 없다 — **DB 축 증거는 CI `bo-mysql8-gate` 초록뿐**이다.
