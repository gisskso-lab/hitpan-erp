## 1. 확정 근본 아키텍처 (검증 통과 = 채택)

### 1.1 신뢰경계 3원칙
```
경계 A (GitHub→NCP): 데이터만 통과 — zip·unsigned manifest. 개인키·.sh·셸블록 금지
경계 B (NCP 내부):    서명·교체·롤백 = 개인키 사는 곳에서만. 권한을 NCP에 가둠
경계 C (NCP→고객PC):  서명본만. 공개키 EXE 내장(유출 무해), 오프라인 검증(#30)
```
불변식: 실행코드·개인키가 경계 A를 넘으려 하면 = 설계 위반. 권한 있는 모든 동사(서명·교체·롤백)는 B 안에서만.

### 1.2 SSOT = 재빌드 (승계 아님)
dispatch 커밋 → checkout → publish(-p:HitPanVersion=X) → manifest(EXE FileVersion 읽기만) 단방향. 커밋-버전-파일명 한 몸. N-1 fail-closed 3자 정합 + NCP 다운그레이드 게이트 2중.

### 1.3 비특권화 4산출물
계정 hitpan-deployer(sudo그룹0·개인키 read0) + publish-run.sh(인자봉인) + deploy-web.sh(광역sudo 흡수) + sudoers(래퍼 2파일만, 와일드카드0). "계정은 무엇을 실행할지 못 고른다"를 실제로 성립.

### 1.4 롤백 경계
update CD GHA = 롤백스텝 영구부재(exit1 알림만), 되돌림은 NCP publish 자기검증 단독. web CD = GHA healthcheck→백업본 복원 단독. 두 주체 영역침범 금지(이중경합 방지).

### 1.5 착수순서 = 창(window) 0
NCP에 두 계정 동시유효 먼저 → GitHub Secret 마지막 원자교체. "GitHub 먼저" 금지.
