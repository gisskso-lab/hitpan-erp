## §2 [판정] 감시 규칙 — `RollbackWatchPlan`(순수 · 화면 비의존)

매 5초 한 번 `api/app-version` 을 부른다(기존 기본 `HttpClient` = `HitPanApiAuthHandler` 경유 · Bearer + 401 자동 갱신 · 🔴2 대안 B).
판이 from 또는 to 면 상태 API(`LocalRollbackClient.GetStatusAsync`)를 **한 번 더** 부른다(보조).

| # | 관측 | 판정 | 근거 |

## §4 [P6] 「한 번」 표 — 되돌린 판의 완료 팝업 중복 막기

- J-3 에서 받은 `Last` 로 `localStorage[hitpan_swap_done_seen] = DonePopupStamp(Last.Mode, Last.To, Last.AtUtc)` 를 **완료 카드를 보이기 전에** 쓴다.
- 되돌린 판(≥1.3.50)의 `SwapDoneNotice` 는 같은 표를 보면 안 띄운다(`ShouldShowDonePopup` `:427`) · `/` 첫 화면에서는 원래 안 띄운다(P6).
- 표 쓰기 실패 → `LogWarning` 후 진행(완료 안내는 띄운다 — 나중 재방문 때 한 번 더 뜨는 쪽이 완료 안내를 빼먹는 쪽보다 낫다).
- **W-1 잔여 위험**: J-5(상태 못 읽음)로 끝나면 표를 못 쓴다 ⇒ V≥1.3.50 이고 24시간 안에 자료관리 결과 화면을 열면 「되돌리기가 끝났습니다」가 **한 번 더** 뜬다. 1.3.49 대상은 조각이 없어 0건.

## §5 [화면] 덮개 컴포넌트 — `RollbackProgressOverlay.razor`

- 자리: `LocalRollbackPage` 안 `<SwapDoneNotice>` 바로 옆(`:30`) — **`MainPcOnly` 밖**(그 안이면 출입증 판정에 따라 덮개가 사라질 수 있다).
- 공개: `Start(string from, string to)` · `[Parameter] EventCallback OnRefused`.
- 주입: `HttpClient`(기본) · `LocalRollbackClient` · `NavigationManager` · `IJSRuntime` · `ILogger<RollbackProgressOverlay>`. **DI 등록 변경 0**(전부 기존 등록).
- 감시는 `RollbackWatcher`(순수 클래스)에 맡긴다 — 컴포넌트는 판정 결과를 그리기만 한다(bUnit 이 없어 화면 동작을 시험으로 못 잡는다 ⇒ 판단은 전부 시험 가능한 쪽에 둔다).
- `IDisposable` — 화면을 떠나면 감시를 끊는다. 상태 API 호출은 한 번에 하나 · 자기 시간 상한(D-2 · 권고 25초 — M-1 왕복 20006ms 실측).
- CSS: `UpdateProgressOverlay.razor.css` 를 **복사**해 `.razor.css` 새 파일(격리 CSS 라 공유 불가 · 원본 무접촉). 바탕 밝게(고장 느낌 금지)·z-index 20000 그대로.
- catch 는 전부 `when (ex is HttpRequestException or TaskCanceledException or JsonException …)` + `LogWarning`(#15) — 5초마다 쌓이지 않게 **종류별 첫 회만** 남기고 횟수를 센다. 오버레이 `:296` 의 빈 `catch` 는 **베끼지 않는다**.
