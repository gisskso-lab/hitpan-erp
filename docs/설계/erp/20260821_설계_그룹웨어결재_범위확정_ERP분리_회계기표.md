## 1. 🔴 지시 7이 밝힌 것 — 이것은 "기능 제거"가 아니라 "중복 제거"다

PM 이 지시 1을 처음 받았을 때 **"결재 기능을 빼는 것"** 으로 브리핑했다. **틀렸다.**

사장님 지시 7 — *"판매확정 또는 구매확정 같은 메뉴가 있어. 이건 암묵적인 결재기능이 됨"* — 이
설계의 근거를 바꾼다. 실측하면 ERP 결재 트리거는 **전부 "확정" 시점에 걸려 있다**:

| 코드 | 시점 |
|---|---|
| `SalesService.cs:588` | 거래명세서 **확정** 후 |
| `SalesService.cs:2128` | 매출반품 **확정** 후 |
| `PurchaseService.cs:484` | 매입명세서 **확정** 후 |
| `PurchaseService.cs:1160` | 매입반품 **확정** 후 |

⇒ **확정이 이미 승인 행위다.** 그 위에 결재 문서를 또 만들면 **같은 승인을 두 번** 시킨다.

| 오해 | 사실 |
|---|---|
| 결재 기능을 뺀다 | **중복된 두 번째 승인을 없앤다** |
| 승인 절차가 사라진다 | 승인은 **확정 메뉴에 그대로 있다** |
| 결재 원하는 고객이 아쉽다 | 확정 권한 = 결재 권한. **아쉬울 것 없다** |

> 🔴 대표가 발주를 직접 보고 싶으면 **확정 권한을 대표만 갖게 하면 된다.** 이미 있는 기능이다.

### PM 자기반증 기록

PM 은 *"매입·매출에 결재를 걸고 싶어 하는 고객이 있을 수 있다"* 를 리스크로 남기려 했다.
사장님 지시 6이 이를 기각했다 — **한 고객사 요구를 제품에 반영하는 것은 SI 사고다.**
그리고 상무님이 초과근무에 적용한 판정(*"월 300건이면 전체선택 후 일괄승인 → 결재가 형식이 된다"*)을
**건수가 더 많은 영업·구매에는 적용하지 않은 것**이 PM 의 잣대 불일치였다.
⇒ **해당 리스크 항목은 기록에서 삭제한다.** 남기면 다음 세션이 되돌릴 씨앗이 된다(헌법 #11 과 같은 논리).

## 3. 확정 설계

### 3-1. 결재함 = 그룹웨어 8종

```
경비 · 휴가 · 휴직 · 초과근무 · 일일보고서 · 주간보고서 · 월간보고서 · 경위서
```

> 8종이면 **2단 필터가 필요 없다.** 콤보 하나로 충분하다.
> 상무님 2단 안(`전체/인사·근태/영업/구매/경비`)은 **15종을 전제로 나온 것**이라 자연히 폐기된다.
> ⇒ **S4 는 사장님 지시 1·2로 해소됐다. 별도 결재 불요.**

### 3-2. 지시 2 중 문서유형이 없는 2건

| 항목 | 판정 | 근거 |
|---|---|---|
| **입사퇴사** | ❌ **만들지 않는다** | 상무님: *"결재 문서종류가 아니다. 넣어도 항상 0건"*. 사원관리 업무 흐름(①)에 이미 있다 |
| **근퇴** | ⚠️ **갈라야 한다** | 출퇴근 **기록** = 결재 아님 / 연장·조퇴·외출 **신청** = 결재 맞음 |
| **급여** | ⏸ **보류** | 사장님 기결재: *"회계경리파트는 좀 손을 봐야해. 급여는 그때하자"* |

> 🔴 **근퇴는 사장님 확인 대기.** 연장·조퇴·외출 신청이면 `attendance_request` 신규 문서유형이
> 필요하다(DDL·트리거·신청화면 = 신규 작업). 확인 전까지 **8종으로 둔다.**

### 3-3. 회계 연결 — 지시 10·11 의 정확한 모습

PM 이 지시 10을 받고 *"사람이 확정 후 기표"* 라고만 브리핑해 **금액까지 손으로 넣는 것처럼** 들렸다.
지시 11이 이를 교정했다 — *"해당금액이 자동반영 되야겠지. 안그러면 데이터 틀어지니."*

| | 누가 정하나 |
|---|---|
| 기표**할지 말지** · **언제** | 🧑 **사람** (이번 달/다음 달, 넣을지 말지) |
| 기표되는 **금액·계정·거래처** | 🤖 **시스템 자동** (승인건에서 그대로) |

```
결재 승인 (금액 확정)
     ↓  금액을 그대로 들고 감 — 사람이 못 고침
[기표 대기]  ← 사람은 "언제 넣을지" 만 정한다
     ↓  확정
회계 전표 자동 생성 (금액·계정·거래처 전부 승인건에서)
```

> 이것이 [반자동 원칙]의 정확한 모습이다 — **제안값을 시스템이 만들고 사람이 확정**한다.
> 금액을 사람이 만드는 것이 아니다. 승인 금액 ≠ 전표 금액이면 그 순간 대사가 깨진다.

**상무님 판정과 일치**: *"결재가 났어도 그 달에 넣을지 다음 달로 넘길지는 급여 담당자가 정한다."*
→ **"넣을지"** 를 정한다고 했지 **"얼마를"** 정한다고 하지 않았다.

### 3-4. 모듈화 (지시 10)

🔴 **결재 승인 코드가 회계를 직접 호출하지 않는다.** "기표 대기" 상태만 남긴다.

| | 지금 | 나중(자동 기표) |
|---|---|---|
| 금액 계산 | 승인건에서 | **안 바뀜** |
| 전표 생성 | 공통 헬퍼 | **안 바뀜** |
| 확정 주체 | 🧑 사람 | 🤖 배치 |

⇒ 나중에 자동을 붙일 때 **바뀌는 것은 "누가 확정을 누르나" 하나뿐**이다.
승인 코드에서 회계를 직접 부르면 나중에 앞단까지 뜯어야 하므로 **그 배선을 만들지 않는다.**
