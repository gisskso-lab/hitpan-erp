> 제품명: 스마트비즈(SmartBiz). 기존 저장소·문서의 히트판 명칭은 추적성 유지를 위해 임의 변경 금지.

## §0 의뢰 및 절대 제한

대표 오더: Claude Code 스킬·플러그인을 실제 스마트비즈 업무에 어떻게 활용할지 PRD로 정리하고, 기존 헌법·WORKFLOW·스킬·토큰 매뉴얼과 충돌하면 근거 기반 하브루타 토론으로 **유지/보완/개정/폐기**를 비교해 대표에게 보고하라.

**이 PRD의 커밋은 토론 문서 등록이지 설치·규칙 개정·제품 코딩·머지·배포 승인으로 해석해서는 안 된다.**
헌법 #33(작업 의중 확인), #41(문서 위치 결재), #42(문서 근거), #29·#37·#39·#40 원문 필독 조건, SoD 및 대표 결재권 유지.
PRD 제안 저장위치 `docs/설계/erp/`는 기존 CATEGORIES를 준용한 잠정 분류이며, 대표 위치 결재가 필요한지 PM이 검증 후 보고한다. 이 문서만으로 다른 폴더를 개편하지 않는다.

## §4 하브루타 토론 프로토콜

**두 독립 관점:** (A) 기존 헌법·품질 수호 측, (B) 자동화·생산성 개선 측. 동일 에이전트의 역할극만으로 독립 검증이라고 보고하지 말 것. 서로 다른 에이전트/세션 또는 담당자가 문서·코드 증거를 각자 검토하고, 반대측 주장을 재검증한다. 외부 GPT는 의심 제기권만 보유하고 결재/판정권이 없다.

라운드 1 — FACT: 주장마다 파일 경로·절·SHA·실행환경·현재 적용상태 표시. 미확인은 UNKNOWN.
라운드 2 — STEELMAN: 서로의 강점을 가장 강하게 재구성한 뒤 반증. 의제별 최소 대안 3개: 현행유지 / 하위 운영규칙 보완 / 헌법·루틴 개정.
라운드 3 — TEST: 실제 충돌을 작은 격리 PoC로 확인. G1·고객 DB·운영환경·진행 브랜치 무접촉. 토큰·시간·오탐·테스트 재현율·승인 우회 여부 비교.
라운드 4 — DECISION PROPOSAL: 합의·불일치·추가실측 필요/미실행·대표 의사결정 항목 분리. **합의가 없는데 합의로 보고 금지.**

서로의 반론/재반론은 GitHub PR 대화 또는 승인된 기존 하브루타 기록 경로에 원문으로 남긴다. 반론 요청만 올려놓고 '토론 완료' 보고 금지.

## §5 우선 시험 및 채택 기준

1) baseline: 현재 hooks/agents/skills/MCP/CI·사용량·테스트 경로를 변경 없이 기록
2) Hookify ↔ 기존 후크 중복·우회/오탐 실측
3) Agent Browser ↔ 기존 Browser E2E 동일 시나리오 재현
4) Security Guidance ↔ 기존 보안 검사 중복·탐지·비용 대조
5) Frontend Design은 승인된 **단일** 화면에서만 제안 검토
6) Skill Creator/MCP Builder는 실제 반복 작업·AI 기능 WBS가 있을 때만
7) GSD/Everything은 별도 격리 실험 외 비활성

대조는 동일 SHA·테스트데이터·환경·업무지시를 사용. 성공률·회귀·감사증거·비용과 시간을 제시. 승인우회·비밀반출·중대 회귀는 불합격. 'AI가 좋아졌다'는 정성 결론은 불합격.

## §6 결과물과 수용 기준

- R1 현행 규범·스킬·후크·CI 실측 대조표 (증거 경로 포함)
- R2 후보 12종 **실제 기능/버전/필요 업무/중복/위험/비용** 분류
- R3 의제별 하브루타 원문·반론·재반론 및 근거
- R4 옵션별 비교표: 현행 유지 / 하위 보완 / 헌법·루틴 개정 (영향·비용·되돌림 포함)
- R5 PoC 결과 또는 미실행 사유; 실행하지 않은 결과는 PASS로 쓰지 않음
- R6 대표 브리핑: 합의 / 이견 / 대표 결재 질문 / 채택권고·미채택 사유
- R7 개정이 필요하면 **원문·통합본·WORKFLOW·CLAUDE.md·에이전트·인덱스 동시 갱신안은 별도 PR 제안만**. 대표 명시 결재 전 수정 금지.

검토 문서의 PR이 생성되어도 메인에 머지하지 않는다. 메인 규정 수정·제품 코드 수정·스킬 설치·운영 접근·배포는 이 PRD 범위 밖.
