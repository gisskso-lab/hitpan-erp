## 0. 사장님이 그린 정식 흐름 (기준)

```
① 랜딩(landing.hitpan.kr, NCP)
   1) 사업자등록증 이미지 업로드 → OCR 인식 → 사업자정보 자동입력
   2) 희망 도메인 입력 → 중복검사 → 승인 후 도메인 자동생성
        ↓
② 백오피스(back.hitpan.kr, NCP)
   1) 고객사 계정·도메인 등록, 시리얼넘버 생성·발송
   2) 시리얼 활성화 → 구독상태 정보 표시
        ↓
③ 히트판 ERP 설치(고객 PC)
   1) 랜딩에서 설치마법사 다운로드·설치
   2) 설치 중 시리얼넘버 입력
   3) 시리얼 입력·설치 → 해당 도메인 데이터를 저장하는 '메인PC'로 자동 등록
   4) 설치 완료 후:
      - 부모계정 정상 로그인
      - 사용업체등록에 랜딩 회사정보 자동 등록 + 비활성화(수정금지)
      - 수정금지 이유 = 무단사용 금지 (사업자정보 변경 시 랜딩에서 사업자등록증 재촬영 후에만)
```

**시리얼 통일 원칙(사장님 확정 2026-07-02)**: 베타1도 정식(시리얼) 경로로 통일. 어제 '시리얼 없이(LOCAL)'는 임시 봉합이었고, 앞으로는 정식 시리얼 흐름을 제대로 만들어 그걸 쓴다.

## 3. 착수 우선순위 (사장님 확정 2026-07-02: "연결 먼저 종단검증")

**대원칙**: 이미 70~80% 살아있으니, 새 코드를 짜기 전에 **정식 시리얼 경로가 랜딩→백오피스→ERP 한 흐름으로 실제 이어지는지부터 실측**한다. 끊긴 지점을 찾는 게 먼저(헌법 #20·#35). 공백 메우기는 그 다음.

### ✅ 검증 방식 확정 (사장님 2026-07-02): "코드 정합검증부터"
실물 서버(NCP)·시리얼 발급·결재 전에, **각 단계 API의 입출력 계약이 코드상 이어지는지 정독·대조**부터 한다:
- 랜딩이 백오피스에 보내는 값(payload/claim) = 백오피스가 기대하는 값 = ERP가 받는 값(부트스트랩 토큰 클레임·webhook)이 필드 단위로 일치하는지.
- 끊긴 지점(필드 불일치·수신부 없음)을 **코드로 먼저 목록화** → 그게 공백/봉합 우선순위를 재확정.
- 실물 NCP 종단 실측은 그 다음(별도 결재, 헌법 #29).

### 🎯 1단계 — 정식 연결축 종단검증 (오늘~다음, 코드변경 최소)
어제 LOCAL로 우회했던 걸 **정식 시리얼 경로로 처음부터 끝까지** 실측한다:
```
[랜딩] 가입(도메인 발급) → [백오피스] 시리얼 생성·claim → [ERP설치] 시리얼 입력·검증
  → CompanyBootstrap(bootstrap + create-parent) → 부모계정 로그인 → 회사정보 자동등록·수정금지 확인
```
- **검증 항목**: 각 단계 API가 실제로 다음 단계로 데이터를 넘기는지, 어디서 끊기는지.
- **특히 G5**(구독변경 웹훅 ERP 수신 측)가 실제 이어지는지.
- **산출물**: "정식 경로 종단 흐름도 + 끊긴 지점 목록" → 그게 공백 우선순위를 재확정.
- ⚠️ 실측 환경·방법(샌드박스 vs 로컬 3서비스 기동, 백오피스 NCP vs 로컬)은 §6에서 사장님 확인.

## 3-A. 사장님 확정 정의·결정 (2026-07-02) — G3·G4 설계 기준

### 📌 메인PC / 클라이언트PC 정의 (사장님 못박음 2026-07-02)
| 구분 | 정의 | 갖는 것 | 대수 |
|---|---|---|---|
| **메인PC** | 데이터가 들어가 있고, 히트판 **설치마법사(EXE)가 설치**된 PC | 로컬 DB(MariaDB) + ERP 본체(API·Web) + cloudflared 터널 | **1대** |
| **클라이언트PC** | 웹브라우저로 `{도메인}.hitpan.kr`에 **접속만** 하는 PC | 설치 없음. 브라우저만 | 제한 있음(무제한 아님) |

- 설치(EXE)는 **메인PC에만**. 클라이언트PC는 설치 자체가 없다.
- 데이터는 오직 메인PC 1곳(로컬 DB, 헌법 #22 데이터 주권).
- **클라이언트PC 접속 수는 무제한이 아니다(사장님 정정 2026-07-02).** 라이선스·기기 슬롯·MaxUsers로 통제되는 유료 개념. → 단, 이 접속 수 제한은 **G3(메인PC 1대 고정 = 도난 방지)와는 다른 축**의 통제다. G3은 "설치되는 메인PC가 1대", 클라이언트 제한은 "그 도메인에 붙는 단말 수".

### G3 결정 — **1PC 고정 = 라이선스 도난 방지** (사장님 선택 2026-07-02)
- 고정 대상 = **메인PC(설치되는 그 1대)**. 클라이언트PC 아님.
- 시리얼로 **설치**하는 순간 그 메인PC 지문(fingerprint)을 백오피스에 등록 → 이후 **다른 PC에 같은 시리얼로 설치 시도하면 거부**.
- 메인PC 교체(고장 등)는 G4와 유사하게 별도 승인 경로 필요(후속).

### G4 결정 — **사업자정보 재등록 = 본사 승인 경유(반자동)** (사장님 선택 2026-07-02)
- 회사정보 잠금(`is_locked_from_landing`) 해제는 자동이 아니라 **본사(백오피스) 검토·승인 경유**.
- 흐름: 고객 재촬영/변경 신청 → 본사 검토·승인 → 승인 시 잠금 해제·ERP 갱신. (거절 시 사유 안내)
- 랜딩 완전자동보다 한 단계 통제 — 부정 변경(사업자 세탁 등) 본사가 거름.

### → G3·G4 코드 현황·최소 변경 목록은 §3-B (정독 결과 대기 후 채움)
