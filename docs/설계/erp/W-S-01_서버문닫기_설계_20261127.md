### 3-2 닫는 방법 (서비스 = 한 자리 · 두 길 다 막힘)

1. **새 인터페이스** `IDataResetAvailability { bool IsOpen { get; } }`(Application/Interfaces) · **운영 구현** `DataResetBetaAvailability`(Application/Services) = `public bool IsOpen => false;` — **되돌림 1줄 = 이 줄 false → true**. 설정 파일(`appsettings*` · #21) · DB 칸(#36)에 두지 않음 — 고객 PC 에서 손으로 열 수 없어야 「대표 확인 뒤에만 엶」 이 지켜진다.
2. `DataResetService` 생성자에 `IDataResetAvailability` 하나 더함(생성자 1개 유지 · 선택 인자 금지) · Program.cs(API) :143 옆에 `AddSingleton<IDataResetAvailability, DataResetBetaAvailability>()` 한 줄.
3. `ResetAllAsync` **맨 첫 문장**(EnsureOpenAsync · 대표 판정 · 비번 · 강제 백업보다 앞): 닫힘이면 감사 `data_reset_denied`(reason 「베타 판 닫힘: closed」) 1행 → `DataResetResponse { Success=false, DenyCode="closed", Error=ClosedMessage }`. DB 를 읽지 않고 백업도 돌리지 않는다.
4. 둘째 · 셋째 겹: `GetResetGateAsync` · `GetResetGateInTransactionAsync` 도 닫힘이면 DB 질의 전에 `DataResetGate.Closed` — 누가 3 의 순서를 바꿔도 막힘 · my-level 이 「closed」 를 받아 메뉴가 저절로 사라짐(`ShowResetLink` 의 `_ => false`).
5. 계약 글자: `DataResetGate.Closed`(enum 끝에 더함) · `DataResetGateCodes.Closed = "closed"` · **`ToCode` 에 `DataResetGate.Closed => Closed` 줄을 드러내 적음**(`DataResetDtos.cs` :33~:38 기본 칸이 `_ => NotParent` 라 빠뜨려도 빌드 초록) · **`DataResetService.GateMessage` 에 `DataResetGate.Closed => ClosedMessage` 줄을 드러내 적음**(:241~:245 기본 칸이 `_ => NotParentMessage` 라 빠뜨리면 순서가 바뀌었을 때 대표에게 「대표 계정이 아닙니다」 가 뜸 · [반증 S-2]) · Web `DataResetMenuRule.Closed = "closed"` + `ShowResetLink` 에 `Closed => false` 를 드러내 적음(네 글자 → 다섯 글자 · 시험이 서버 ↔ 화면 대조).
6. **지우지 않는 것**(#1): #978 대표 판정(:77~:87 · :152 · `Decide`) · 확인 문구 서버 검사(컨트롤러 :54 · 이관 「덮어쓰기」 :695) · 비번 대조 · 강제 백업 · 보존 표 · 뼈대 재시드 — 다시 열면 그대로 돈다.
