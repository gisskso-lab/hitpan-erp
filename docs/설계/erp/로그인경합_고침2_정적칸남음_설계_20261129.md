## §3 [추천 동작 정의] (라′) — [3] 이 지킬 것

1. **판정은 `LoginInFlightSafetyNet` 한 곳.** 화면은 묻고 따르기만.
2. `Next` **손 0** — `StandDown` 의 뜻(「안전망 `/` 영구 해제」)은 그대로 맞음(물러남도 `/` 를 내지 않음). 기존 시험 8건 손 0.
3. 새 상수 `FallBackToFormMs = 30000` · 새 칸 `_navigatedSeenAtMs`(long?) · 새 판정 `public bool ShouldFallBackToForm(long nowMs)`:
   - 이동 냄 아님 → `false`(그 길은 `Next` 가 맡음).
   - 이동 냄 → 기다리는 화면이 이 판정을 **처음 부른 시각**을 적음(`??=` · 멈춤 상한과 같은 「기다리는 쪽 시계 하나」 꼴 — 앞 화면은 시각을 넘기지 않음 → 앞 화면 이동 3곳 손 0) · 그때부터 30초 지나면 `true`.
4. `Reset()` 에 `_navigatedSeenAtMs = null` 1줄(다음 로그인 시도가 앞 시도 시계를 안 물려받게).
5. `Login.razor` `WaitForInFlightLoginAsync` 의 `StandDown` 가지(`:301~304`): 바로 return 하지 않고 물러남 고리로 —
   - 주소가 `login` 이 아니면(화면이 바뀜) return(지금과 같음).
   - `ShouldFallBackToForm(Environment.TickCount64)` 이면 `_waitingForInFlightLogin = false` + `Logger.LogWarning("[Login] 로그인 뒤 이동이 열리지 않아 로그인 화면을 다시 보인다(안전망).")` → return(`OnInitializedAsync` 가 끝나며 Blazor 가 다시 그림 · 필요하면 `StateHasChanged()` 1줄 — [3] 판단 · 개발명세서에 기록).
   - 아니면 `await Task.Delay(LoginInFlightSafetyNet.PollMs)` 뒤 다시.
6. **이동 0 · 표시 칸 손 0**: 물러남은 `NavigateTo` 를 부르지 않음. `s_loginInFlight` 도 끄지 않음 — 느린 문서가 아직 오는 중일 수 있어, 그사이 화면이 또 다시 만들어져도 `/` 로 덮어쓰지 않게(3V-P2 보존). 사용자가 입력 칸에서 다시 로그인하면 `HandleLogin`(`:502` · `Reset`)이 지금처럼 새로 시작.

## §11 [확인 필요]

1. 문서 간 이동을 중지했을 때 Navigation API 사건이 오는지 — (다) 기각 근거라 재지 않음.
2. Chromium 의 `no-store` 문서 복원 실험 현황 — (마) 기각 근거 보조.
3. 복원 뒤 Blazor 타이머(`Task.Delay`)가 이어 도는지 — `back-restore` 장면이 바로 이것을 잼(빨강이면 B 만 따로: E3 승격).
4. `back-restore` 직원 = `relogin-home` 준비 직원 재사용 가능 여부(계정 자리 5 한도 · §8-12) — [3] 이 장치 준비에서 판단 · 모자라면 만든 몸이 치움 꼴.
5. 물러난 뒤 다시 그리기에 `StateHasChanged()` 가 필요한지(§3-5) — [3] 이 구현에서 판단 · 장면 2 가 동작으로 잼.
