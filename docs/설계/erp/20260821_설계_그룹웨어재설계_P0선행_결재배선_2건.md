## 1. 결함① — 휴직 결재는 구조적으로 100% 실패한다

### 1-1. 인과사슬 (실측 — 전부 파일에서 확인)

```
AbsenceService.cs:42     const string DocType = "absence";
                    :363 TryCreateApprovalAsync(..., "absence", ...)
                              ↓
ApprovalTriggerHelper    var setting = SELECT ... WHERE doc_type = @DocType

```

⇒ **설정화면에 "휴직" 행이 안 뜬다 → 켤 수 없다 → 상신은 항상 조용히 실패.**

### 1-2. 🔴 이것이 왜 심각한가

`AbsencePage.razor` 는 **"결재상신"·"저장하고 결재상신" 버튼을 보여준다.**
눌러도 아무 일이 없다. **화면이 사용자에게 거짓말을 한다.**

> 어제 기본창고(`_selectedWarehouseId // DB에 저장하지 않음`)와 **같은 종류**다.
> `ApprovalTriggerHelper.cs:225` 주석이 *"두 곳을 함께 고쳐야 하며, 빠뜨리면…"* 이라고
> **경고해 놓고 정작 `absence` 에서 빠뜨렸다.** — **주석은 게이트가 아니다.**

### 1-3. 봉합

| 파일 | 변경 |
|---|---|
| `ApprovalService.cs` `DocTypeLabels` | `["absence"] = "휴직"` **추가** |

🔴 **기존 항목은 건드리지 않는다**(헌법 #1 — 추가만).

## 2. 결함② — 초과근무는 설정만 있고 트리거가 없다

### 2-1. 결함①과 정반대 방향의 같은 병

| | 결함① 휴직 | 결함② 초과근무 |
|---|---|---|
| 설정화면 | ❌ 안 뜸 | ✅ **뜬다 (켤 수 있다)** |
| 상신 코드 | ✅ 있다 | ❌ **없다** |
| 결과 | 조용히 실패 | **아무 일도 안 일어남** |
| 화면 | 정상으로 보임 | 정상으로 보임 |

`HrService.CreateOvertimeAsync` — INSERT 만 하고 return (실측: `TryCreateApprovalAsync` 호출 0건).

> 고객이 결재설정에서 "초과근무" 를 켜고 **결재선까지 짰는데** 아무 일도 안 일어난다.
> 이건 기능이 없는 것보다 나쁘다 — **했다고 믿게 만든다.**

### 2-2. 사장님 오더 7번과 정확히 같은 자리

> *"초과근무신청서 작성시 결재메뉴로 보이도록"*

⇒ 본안 오더의 선행조건이다. 여기를 안 고치면 오더 7번을 만들 수 없다.

### 2-3. 봉합 — ⚠️ 단, 병렬검증 결과를 반영한다

`CreateOvertimeAsync` 에 `TryCreateApprovalAsync(..., "overtime", ...)` 배선.

🔴 **[3-V] 동시검증에 부친 쟁점 2건** (결과 반영 후 확정):
1. **이중 승인 모순** — `ApproveOvertimeAsync`(자체 승인 버튼)가 남아 있는데 결재도 태우면
   승인 경로가 둘이 된다. 어느 쪽이 정본인가?
2. 🔴 **원본 상태 연동** — 결재가 승인되면 `overtime.status` 가 자동으로 바뀌는가,
   아니면 결재만 돌고 원본은 `pending` 에 남는가?
   **후자면 또 다른 거짓봉합**이다("결재는 갔는데 신청서는 그대로").

⇒ **2번이 미해결이면 이번 범위에서 배선하지 않고 사장님께 별도 보고한다.**

같은 방식으로 확인하면 또 놓친다(feedback_gate_must_test_behavior).

| # | 반증 | 기대 |
|---|---|---|
| **G1** | 🔴 **봉합 전에** 새 가드시험 실행 | **FAIL 이어야 한다** — 아니면 시험이 가짜다 |
| G2 | 봉합 후 같은 시험 | PASS |

### 3-1. G1 실측 결과 (2026-08-21, 봉합 **전**)

```
휴직_상신_docType_이_설정화면_목록에_있다      [FAIL]   ← 결함① 재현
초과근무_설정이_있으면_상신코드도_있다          [FAIL]   ← 결함② 재현
설정화면_문서유형은_알림라벨도_가진다           [PASS]
```

🔴 **시험을 먼저 짜고 FAIL 을 확인했다.** 봉합 후 PASS 로 바뀌는 것이 봉합의 증거다.

> ⚠️ **시험 자체의 거짓양성을 한 번 잡았다.** 처음 판정이 파일 전체에서 `["x"] =` 를 긁어
> **다른 사전**(결재상태 `pending`·결제수단 `cash` 등)까지 문서유형으로 오인해 FAIL 이 났다.
> `DocTypeLabels` **블록만 잘라 읽도록** 고쳤다 — 고치자 PASS.
> **없는 결함을 "봉합"할 뻔했다.**
