## 0. 본 문서의 존재 이유

> *"본사가 안 가지면 본사가 털릴 일 없다. 본사가 안 알면 본사가 책임질 일 없다. 사장님 데이터는 사장님 것이다."* — 사장님 (2026-05-12)

쿠팡·SKT·KT 사고 시대, 본사가 보유한 데이터가 사고의 1차 원인. 본 문서는 **본사가 무엇을 가지고 무엇을 안 가지는지** 명문화한다.

## 1. 본사 보유 영역 (메타정보·카운터·식별자만)

### 1.1 본사 백오피스 DB 보유 데이터

| 카테고리 | 보유 가능 | 보유 금지 |
|---|---|---|
| **고객사** | tenant_id, business_no, 대표자명, 이메일, 휴대폰, 주소, 상태 | 매출/매입/원장/거래처/직원명부/세금계산서 등 ERP 업무 데이터 일체 |
| **구독·결제** | subscription_id, plan_code, billing_cycle, billing_key (PG 토큰), 결제 일시·금액 | 카드번호·CVC·유효기간·OTP·계좌번호 |
| **계정** | account_id, login_id, 표시명, 이메일, 역할 코드 | 자식계정 비밀번호 해시·평문, 자식계정 권한 매트릭스 상세 |
| **대리점** | reseller_id, business_no, 계약·수수료율, 산하 tenant_id 매핑 | 대리점 산하 고객사 매출 상세·거래처명 |
| **본사 관리자** | admin_id, password_hash (bcrypt), TOTP_secret_enc (AES-256), 세션 | (해당 없음 — 본사 자체 데이터) |
| **모니터링** | heartbeat 메타 (client_ver·db_ver·os_ver·watchdog_status), 카운터 (menu_open_count·api_call_count·error_count·ai_token_used·active_user_count) | 금액·거래처명·상품명·세금계산서 내용·매출 추이 절대 미보유 |

### 1.2 본사가 절대 보유 금지 (헌법 #18 v3)

- 매출 금액·매입 금액·원장 잔액
- 거래처 명단·거래처별 거래 내역
- 직원 명부 (이름·주민번호·계좌·급여)
- 상품 목록·재고 수량
- 세금계산서·거래명세서·견적서·수주서 내용
- 결재 라인·결재 내역
- 카드정보 평문/암호문 (PG 토큰 billing_key만 허용)

## 2. ERP 로컬 보유 영역 (헌법 #24 책임 분산)

### 2.1 ERP 로컬 DB만 보유

- 매출·매입·원장·거래처·직원·상품·재고·세금계산서·결재 일체
- 자식계정 비밀번호 해시 (argon2)
- 자식계정 권한 매트릭스 (Role × Permission)
- 백업 (E2E 암호화) — 본사가 받아도 내용 모름

### 2.2 백업 정책

- 일 1회 자동 백업 (워치독)
- 백업 키는 고객 PC 로컬에만 (DPAPI + 사장님 패스프레이즈)
- 본사는 백업 파일을 보관할 수 있어도 **복호화 키 미보유** = 내용 0 (헌법 #22)

### 3.2 핵심 흐름 박제 (F7 텔레메트리)

```
ERP (5분 타이머)
  │
  ▼ POST /api/heartbeat
  {
    "tenant_id": 1234,
    "ping_at": "2026-05-26T10:00:00Z",
    "client_version": "1.2.5",
    "db_version": "11.4.10",
    "os_version": "Windows 11 Pro",
    "watchdog_status": "healthy",
    "counters": {
      "menu_open_count": 145,
      "api_call_count": 2340,
      "error_count": 0,
      "ai_token_used": 12500,
      "active_user_count": 3
    }
  }
  │
  ▼
백오피스 → 200 OK + 라이선스·알림 메시지
```

**절대 금지 (5중 검증 통과 못 하면 머지 금지)**
- ❌ `"daily_sales": 1234567` — 매출 금액 절대 미포함
- ❌ `"top_customer": "ABC상사"` — 거래처명 절대 미포함
- ❌ `"new_invoices": [{...}]` — 세금계산서 내용 절대 미포함

## 4. 법령 9개 형사 영역 차단 박제

### 4.1 법령 매핑

| # | 법령 | 본사 차단 영역 |
|---|---|---|
| L1 | 개인정보보호법 | 자식계정 주민번호·연락처 본사 보유 0 |
| L2 | 전자상거래법 | 거래내역 본사 보유 0 (PG 영수증은 PG 책임) |
| L3 | 신용정보법 | 거래처 신용정보·매출 채권 본사 보유 0 |
| L4 | 부가가치세법 | 세금계산서 본사 보유 0 (홈택스 직접 신고는 외주) |
| L5 | 소득세법 | 직원 급여·원천징수 본사 보유 0 |
| L6 | 근로기준법 | 직원 근로계약·근태 본사 보유 0 |
| L7 | 정보통신망법 | 침해사고 통지 60일 / SaaS 결제 운영 메타는 본사 책임 |
| L8 | 위치정보법 | 위치정보 본사 보유 0 (수집 자체 안 함) |
| L9 | 통신비밀보호법 | 통신 내용 본사 보유 0 (E2E 암호화 백업) |

### 4.2 차단 메커니즘

1. **API 게이트웨이 화이트리스트** — `/api/heartbeat`, `/api/license`, `/api/subscription` 등 허용 엔드포인트만. 업무 데이터 엔드포인트 자체가 존재 안 함
2. **5중 검증** (헌법 #23) — AI 협업 코드는 ① 작업지시서 → ② 매니저 리뷰 → ③ SAST → ④ DAST → ⑤ 데이터 최소주의 검증 통과 후 머지
3. **DB 스키마 강제** — 백오피스 DB에 매출·거래처·세금계산서 테이블이 **존재하지 않음**. 코드로 실수해도 INSERT할 곳이 없음.
4. **PR 자동 차단 룰** — `transactions`, `sales`, `invoices` (ERP 도메인) 등 금지 단어 본사 DB 마이그레이션 파일에 등장 시 PR 자동 차단
