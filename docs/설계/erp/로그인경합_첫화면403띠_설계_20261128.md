### 2-2 (가′) 동작 정의 — [3] 이 지킬 것
1. 표시 = `Login.razor` @code 의 **정적 칸 1개**(앱 한 벌 = 브라우저 탭 한 개 · forceLoad 다시 읽기로 저절로 초기화). DI 등록 · `Program.cs` 손 0(겹치는 PR 많음). 대안 = 작은 서비스 클래스 + `Program.cs` 1줄 → D1.
2. 로그인 함수: `AuthService.LoginAsync` 부르기 **직전** 표시 켬. 실패 결과 · 예외면 끔. 성공이면 끄지 않음(이동이 문서를 새로 읽어 지움).
3. 성공 뒤 이동은 **지금 자리 그대로**(`:400` `/terms` · 새 기기 알림 `:427~445` · `:449`/`:456`). 식 · 순서 손 0. 「이동을 냈다」 칸 1개를 두고, `finally` 에서 성공인데 이동을 못 냈으면 `/` 로 한 번 보냄(예외 길 막음).
4. `OnInitializedAsync`(`:198~208`): 로그인 상태 **이고** 표시가 켜져 있으면 → `/` 로 가지 않고 return. 표시가 꺼져 있으면 **지금 그대로**(이미 로그인한 사람이 `/login` 을 직접 열면 `/` 로 — 기존 동작 보존).
5. 안전망: 4의 return 길에서 15초 기다려도 아직 `/login` 이면 `/` 로 forceLoad(최악 = 지금 동작). 15초 = D2.
6. 그림: 표시가 켜져 있고 로그인 상태면 입력 칸 대신 진행 막대 + 기존 로그인 단추의 「로그인 중」 문구만(새 문구 0 · 다시 누르기 막음). 문구 실제 글은 [3] 이 기존 단추 글 그대로 가져옴(확인 필요).
7. **가설 2개(측정으로 닫음)**: ⓐ 경합 원인이 「Authorizing 중 Login 폐기 → 새로 만듦」 이다(선행 §1-2 추정 단계) ⓑ 폐기된 Login 의 이어지는 비동기(`LoginAsync` 뒤 줄)가 끝까지 돈다(CI :2632 에서 `/data/update` 이동이 **나갔다** = 지금도 돈다는 간접 증거). ⓑ가 틀리면 5 안전망이 늘 돌아 `/` 착지 = 지금과 같음 → G1·G2 빨강으로 드러남.
