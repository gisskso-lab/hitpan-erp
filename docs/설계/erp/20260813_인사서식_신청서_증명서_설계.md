## 1. 🔴 가장 중요한 갈림 — 신청서 ≠ 증명서

사장님이 짚으신 한 줄이 이 설계의 축이다: **"회사가 증명해야지"**

|  | **신청서** (Request) | **증명서** (Certificate) |
|---|---|---|
| 성격 | 직원이 **회사에 요청**한다 | 회사가 **사실을 증명**한다 |
| 누가 만드나 | 직원 본인 | **회사(관리자·권한자)** |
| 발급 권한 | 본인 | 🔴 **관리자 또는 권한을 가진 자** |
| 흐름 | 작성 → **결재** → 승인/반려 | **결재 없음.** 사실 조회 → 발급 |
| 결과 | 상태가 바뀐다(휴직중이 된다) | 상태가 안 바뀐다(종이만 나간다) |
| 회사 직인 | 없음 | 🔴 **필수** |
| 남는 것 | 신청 이력 + 결재 이력 | 🔴 **발급 이력**(누가·언제·왜·몇 통) |
| 대상 | 재직자 | 재직자 **+ 퇴직자** |

### 왜 이 구분이 중요한가

**① 권한이 반대다.** 신청서는 "본인 것만" 이 맞지만, 증명서는 **본인이 뽑으면 안 된다.**
직원이 자기 재직증명서를 스스로 발급하면 그건 증명이 아니다 — 회사가 보증한 것이 아니기 때문이다.
은행·관공서가 그 종이를 믿는 이유는 **회사가 뗐기 때문**이다.

**② 결재를 붙이면 안 된다.** 증명서에 결재를 걸면 은행 갈 사람이 이틀을 기다린다.
증명서는 **이미 확정된 사실을 뽑는 것**이라 승인할 대상이 없다.
대신 **발급 이력**을 남긴다 — 그것이 통제 수단이다.

**③ 퇴직자도 대상이다.** 경력증명서·퇴직증명서는 **이미 나간 사람**이 요청한다.
`is_active = 1` 로만 조회하면 정작 필요한 사람이 안 나온다. (⚠️ 구현 시 주의)

## 3. 데이터 설계

### 3-1. 기존 것을 쓴다 — `form_templates`

실측: 이미 있다. 용지·여백·배경이미지·도장·복사본 모드까지 갖췄다.

```
template_id · tenant_id · form_type · template_name
paper_mode(plain/preprinted) · paper_size · orientation · 여백 4종
field_coords_json · background_image_url
show_company_logo · show_company_seal · show_border
print_copy_mode · style_key · is_default · is_active
```

지금 `form_type` 은 거래 서식 10종뿐이다:
`delivery` `estimate` `invoice_exempt` `payment_receipt` `purchase_order`
`purchase_return` `receipt` `sales_order` `sales_return` `tax_invoice`

⇒ **인사 서식 form_type 을 여기에 추가한다.** 새 표를 만들지 않는다 —
용지·도장·좌표 설계가 이미 다 되어 있고, 인사 서식도 똑같이 필요하다.

**추가할 `form_type`:**
```
cert_employment    재직증명서
cert_career        경력증명서
cert_resignation   퇴직증명서
cert_absence       휴직증명서
cert_attendance    근무확인서
```

> 🔴 접두 `cert_` 로 가른다. 거래 서식과 섞이면 [양식 설정] 화면에서
> 경리가 세금계산서 고치려다 재직증명서를 본다.

### 3-2. 신설 — `hr_certificates` (발급 이력)

🔴 **이 표가 증명서 설계의 핵심이다.** 증명서는 결재가 없으므로
**발급 이력이 유일한 통제 수단**이다.

```sql
CREATE TABLE `hr_certificates` (
  `cert_id`        varchar(36)  NOT NULL,
  `tenant_id`      varchar(36)  NOT NULL,
  `employee_id`    varchar(36)  NOT NULL COMMENT '누구에 대한 증명인가',
  `cert_type`      varchar(30)  NOT NULL COMMENT 'cert_employment 등 form_type 과 같은 값',

  -- 🔴 발급 시점의 사실을 **얼어붙여 남긴다**
  `snapshot_json`  longtext     NOT NULL COMMENT '발급 당시의 입사일·부서·직급 등',

  `purpose`        varchar(200) DEFAULT NULL COMMENT '용도(은행 제출용 등). 사람이 적는다',
  `submit_to`      varchar(100) DEFAULT NULL COMMENT '제출처',
  `copies`         int          NOT NULL DEFAULT 1 COMMENT '발급 통수',

  -- 🔴 누가 발급했나 — "관리자 혹은 권한을 가진 자"(사장님)
  `issued_by`      varchar(36)  NOT NULL,
  `issued_at`      datetime(6)  NOT NULL DEFAULT current_timestamp(6),
  `cert_no`        varchar(40)  NOT NULL COMMENT '증명서 번호. 문서에 찍혀 나간다',

  -- 기간이 있는 증명서(근무확인서·휴직증명서)
  `period_from`    date         DEFAULT NULL,
  `period_to`      date         DEFAULT NULL,

  `is_voided`      tinyint(1)   NOT NULL DEFAULT 0 COMMENT '1=무효 처리',
  `void_reason`    varchar(200) DEFAULT NULL,
  `created_at`     datetime(6)  NOT NULL DEFAULT current_timestamp(6),

  PRIMARY KEY (`cert_id`),
  UNIQUE KEY `uk_cert_no` (`tenant_id`, `cert_no`),
  KEY `idx_cert_emp` (`tenant_id`, `employee_id`, `cert_type`),
  KEY `idx_cert_issued` (`tenant_id`, `issued_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

#### 🔴 왜 `snapshot_json` 인가 — 이 설계에서 가장 중요한 결정

증명서를 **다시 열 때 지금 값으로 그리면 안 된다.**

예: 2026년 3월에 "영업부 과장" 으로 재직증명서를 뗐다.
2026년 8월에 그 사람이 퇴사했다. 발급 이력을 열면?
- 지금 값으로 그리면 → **"퇴직" 으로 나온다.** 3월에 준 종이와 다르다.
- 스냅샷으로 그리면 → **3월에 준 그대로.** 맞다.

은행이 그 종이를 들고 물어보면 우리는 **그때 뭐라고 써서 줬는지** 답할 수 있어야 한다.
⇒ **발급 순간의 사실을 얼려서 남긴다.**

#### 증명서 번호 규칙

```
{연도}-{종류 2자}-{일련 4자}     예: 2026-재직-0001
```
- 회사 안에서 유일해야 한다(`UNIQUE (tenant_id, cert_no)`).
- 🔴 번호가 찍혀야 위조 대조가 된다. 번호 없는 증명서는 나중에 확인할 방법이 없다.

## 3-3. 🔴 직인 · 로고 워터마크 — 사장님 지시 (2026-08-13)

> *"히트판에 등록된 **회사 직인이 찍혀있는 채로 발급, 인쇄**가 되야함"*
> *"**회사 로고 워터마크**도"*

### 왜 이게 필수인가

증명서는 **회사가 보증하는 문서**다(사장님: *"회사가 증명해야지"*).
직인이 없으면 은행·관공서가 안 받는다. **도장 없는 증명서는 종이일 뿐이다.**
워터마크는 **위조·복사 방지** — 원본과 복사본을 구분하게 한다.

### 실측 — 지금 어디까지 되어 있나

| 항목 | 실측 결과 |
|---|---|
| 직인 칸 | ✅ `local_company.seal_url` **있다** |
| 로고 칸 | ✅ `local_company.logo_url` **있다** |
| 등록 화면 | ✅ [회사 정보](../../src/HitPan.Web/Pages/Settings/UserInfoPage.razor.cs) 에서 올린다 |
| 양식 옵션 | ✅ `form_templates.show_company_seal` / `show_company_logo` **있다** |
| 🔴 **실제 등록값** | ❌ **직인·로고 둘 다 비어 있다**(`NULL`) |
| 🔴 **워터마크** | ❌ **없다.** 로고는 머리글에만 쓴다 |

⇒ **칸은 다 있고 채워지지 않았다.** 새로 만들 것은 워터마크뿐이다.

### 🔴 직인이 없으면 어떻게 할 것인가 — 막는다

**직인이 등록 안 된 상태로 증명서를 뽑으면 안 된다.**
관리자는 뽑힌 줄 알고 직원에게 주고, 직원은 은행에서 퇴짜를 맞는다.
그때는 이미 늦다 — 종이가 밖에 나간 뒤다.

```
발급 누르면 →
  직인 있나?
    없다 → 🔴 막는다.
           "회사 직인이 등록되지 않았습니다.
            설정 → 회사 정보에서 직인 이미지를 올려주세요.
            직인 없는 증명서는 은행·관공서에서 받지 않습니다."
           [회사 정보로 가기] 버튼을 함께 준다
    있다 → 발급
```

> ⚠️ 이것은 **휴직의 '기준 초과' 와 성격이 다르다.**
> 기준 초과는 회사가 더 주는 것이라 막으면 안 됐다. 여기는 **못 쓸 종이가 나가는 것**이라 막는다.
> (거래 서식은 안 막는다 — 견적서는 도장 없이도 나간다)

### 신설 — 워터마크 옵션

`form_templates` 에 칸을 더한다(표는 새로 안 만든다):

```sql
ALTER TABLE `form_templates`
  ADD COLUMN IF NOT EXISTS `watermark_mode` varchar(20) NOT NULL DEFAULT 'none'
    COMMENT 'none=없음 · logo=회사 로고 · text=글자',
  ADD COLUMN IF NOT EXISTS `watermark_text` varchar(60) DEFAULT NULL
    COMMENT '글자 워터마크 내용. 예: 사본 · 원본대조필',
  ADD COLUMN IF NOT EXISTS `watermark_opacity` decimal(3,2) NOT NULL DEFAULT 0.08
    COMMENT '진하기 0.00~1.00. 기본 0.08 — 글자를 가리면 안 된다';
```

**기본값 판단:**
- 인사 증명서 → `watermark_mode = 'logo'` (회사 로고를 연하게)
- 거래 서식 → `watermark_mode = 'none'` (지금 그대로. 🔴 **기존 10종을 안 건드린다** — 헌법 #1)

**진하기 0.08 로 두는 이유:** 워터마크가 진하면 **본문 글자를 읽기 어렵다.**
증명서는 은행 직원이 읽어야 하는 문서다. 흐릿하게 배경에만 깔린다.

### 인쇄 시 겹치는 순서

```
   ① 배경(용지 이미지, preprinted 모드일 때)
   ② 🔴 워터마크 (로고, 연하게 — 종이 한가운데)
   ③ 본문 (제목·표·내용)
   ④ 하단 회사 정보 (회사명·사업자번호·대표자·주소)
   ⑤ 🔴 직인 (대표자명 오른쪽에 겹쳐서)
```

> 🔴 **직인은 ⑤ 맨 위**다. 대표자 이름 위에 겹쳐 찍혀야 실제 도장처럼 보인다.
> 옆에 따로 떨어져 있으면 붙여넣은 그림처럼 보인다.

### 발급 이력에도 남긴다

`hr_certificates.snapshot_json` 에 **그때 쓴 직인·로고 주소**를 함께 남긴다.
회사가 나중에 직인을 바꿔도, 3월에 준 종이에 어떤 도장이 찍혔는지 답할 수 있어야 한다.
(스냅샷을 남기는 이유와 같다 — 3-2 참고)

## 4. 권한 설계

### 4-1. 사장님 지시 = "관리자 혹은 권한을 가진 자"

```
발급(증명서)  → 관리자 + 인사 권한을 받은 사람
조회(이력)    → 같음
본인 것 조회  → 직원 본인도 "내가 언제 뭘 뗐나" 는 볼 수 있다
```

> ⚠️ **헌법 #11** — 권한은 어드민이 직접 설정한다.
> 우리가 "인사팀은 이거 됩니다" 같은 템플릿을 깔지 않는다.
> 권한 항목만 만들어 두고, **누구에게 줄지는 회사가 정한다.**

### 4-2. 🔴 직원 본인은 발급할 수 없다

사장님: **"회사가 증명해야지"**

본인이 본인 재직증명서를 뽑으면 그건 증명이 아니다.
⇒ API 에서 **본인 여부와 무관하게** 권한을 본다.
(휴직신청서와 정반대다 — 그건 본인만 낼 수 있다)

### 4-3. 대조 — 신청서 쪽 권한

```
신청  → 본인만 (관리자는 대신 넣을 수 있다)
조회  → 본인 것만 / 관리자는 전원
승인·반려 → 관리자 (결재선이 있으면 결재자)
```

## 5. 각 증명서가 필요로 하는 데이터 — **단계별 확보 여부**

🔴 이 표가 이 문서를 지금 쓰는 이유다. **각 단계가 이 값을 남겨야 한다.**

| 증명서 | 필요한 값 | 어디서 | 확보 |
|---|---|---|---|
| 재직증명서 | 이름·주민번호·주소·입사일·부서·직급 | `employees` | ✅ |
| | 회사명·사업자번호·대표자·주소·직인 | `local_company` | ✅ |
| 경력증명서 | 부서·직급 **이력**(언제부터 언제까지) | ⬜ **없다** | 🔴 |
| 퇴직증명서 | 퇴사일·퇴사사유 | `employees.resign_*` | ✅ |
| 휴직증명서 | 휴직 기간·사유·상태 | `employee_leave_of_absence` | ✅ **단계6** |
| 근무확인서 | 기간별 출퇴근 집계 | `hr_attendance` | ✅ |

### 🔴 확보 안 된 것 — 경력증명서의 "이력"

지금 `employees` 는 **현재 부서·직급만** 갖는다. 언제 바뀌었는지 없다.
⇒ 경력증명서에 *"2024.03~2025.02 영업부 대리 / 2025.03~ 영업부 과장"* 을 못 쓴다.

**대안 2가지:**
- (A) `employee_history` 표 신설 — 부서·직급이 바뀔 때마다 한 행
- (B) 경력증명서는 **입사일~현재, 현재 부서·직급**만 쓴다(간이형)

⇒ 🔴 **사장님 결재 필요.** (B) 로도 실무의 8할은 된다.
(A) 는 사원 수정 화면 전체를 건드려야 해서 별도 차수가 맞다.

## 6. 화면 설계

### 6-1. [인사 서식] 한 화면

> 히트판 정신 — *"이 화면, 처음 보는 사람이 혼자 쓸 수 있냐?"*
> 증명서 5종을 메뉴 5개로 늘리면 사이드바만 길어지고 같은 화면을 다섯 번 배운다.
> **단계3 업무보고서 4종을 한 화면 탭으로 묶은 것과 같은 방식.**

```
┌─ 인사 서식 ──────────────────────────────────┐
│ [증명서 발급] [발급 이력]                      │
├──────────────────────────────────────────────┤
│ 직원  [김철수 ▼]   ← 퇴직자 포함 검색          │
│ 종류  [재직증명서 ▼]                          │
│ 기간  [____] ~ [____]  ← 근무확인서일 때만     │
│ 용도  [은행 제출용_______]  제출처 [국민은행__] │
│ 통수  [1]                                     │
│                                               │
│         [미리보기]  [발급하고 인쇄]            │
└──────────────────────────────────────────────┘
```

- **미리보기가 먼저** — 뽑기 전에 눈으로 본다. 잘못 나가면 회수가 안 된다.
- 용도·제출처는 **적으면 좋고 안 적어도 된다.** 은행 앞에서 급한 사람을 막으면 안 된다.

### 6-2. 신청서는 각 화면에 이미 있다

휴직신청서 = 휴직 관리 화면 · 연차신청서 = 연차 신청 화면.
⇒ **신청서를 위한 별도 화면을 만들지 않는다.** 이미 그 자리에서 신청한다.
서식은 **인쇄할 때** 필요한 것이므로, 각 화면에 [인쇄] 를 붙이면 된다.
