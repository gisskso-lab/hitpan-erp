## §2 [판정] 판정기 하나 — `AccountSeatGuard`

위치 `src/HitPan.Application/Services/AccountSeatGuard.cs`(static · API 프로젝트의 Bootstrap 도 부른다).

```
EnsureSeatAsync(IDbConnection db, IDbTransaction tx, string tenantId, int adding, CancellationToken ct)
  ① SELECT max_users, <추가구매계정 칸> FROM local_subscription WHERE tenant_id=@T FOR UPDATE   ← 트랜잭션 첫 문장
  ② SELECT COUNT(*) FROM users WHERE tenant_id=@T AND is_active=1 AND is_deleted=0               ← idx_users_tenant_parent 근처 · DESCRIBE 후 인덱스 확인
  ③ limit = (행 없음 || max_users<1 ? 5 : max_users) + max(추가,0)   · 5 쪽으로 간 경우 LogWarning 은 부르는 쪽 _logger
  ④ active + adding > limit ⇒ throw AccountSeatFullException(active, limit)
GetSeatsAsync(db, tenantId) → (Active, BaseLimit, Extra, Limit, Tier)   ← 잠금 없음 · KPI·화면용
```
- `AccountSeatFullException : InvalidOperationException` — 기존 `catch (InvalidOperationException)` 400 경로보다 **먼저** 잡아 409 로 낸다(§4). 메시지 「계정 사용 한도({limit}개)가 찼습니다. 계정을 더 쓰려면 [구독계정추가]를 눌러 주세요.」
- ③ 의 5 는 상수 한 곳(`DefaultBaseAccounts = 5`) — 출하 DDL 기본값과 같은 수. 프로 8 은 ERP 가 정하지 않는다(본사가 보낸 `max_users`).
- 셈에 `account_type` 을 쓰지 않는다(F-4 — `is_parent=0` 인 `tenant_admin` 이 있을 수 있다). 대표는 활성이면 그냥 1로 들어간다(C-1).
- 🔴 REPEATABLE READ 함정: ① 의 잠금 읽기가 **첫 문장**이어야 ② 의 스냅숏이 잠금 뒤에 잡힌다. ① 앞에 일반 SELECT 를 넣으면 F-6 가 되살아난다 ⇒ G-A6 이 동작으로 잡는다.
