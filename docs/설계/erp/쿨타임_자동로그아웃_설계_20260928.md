## §2 [방식] 서버 시각 작업 — 화면 타이머 안 씀

| 기준 | 화면 타이머(각 PC 브라우저) | 🟢 서버 시각 작업(고객 PC 로컬 API) |
|---|---|---|
| 팝업 못 보는 PC(닫힘·절전) | 아무도 안 끝낸다 ⇒ 다른 PC 가 막힌 채(Q5 불성립) | 서버가 끝낸다 |
| 숨은 탭·절전 | 타이머가 늦거나 멈춘다(선행 §4 ⚠️) | 서버 시계는 안 멈춘다 |
| 시각 기준 | PC 마다 시계가 다를 수 있다 | 서버 PC 벽시계 하나 = `attendance` 가 쓰는 시계(`DateTime.Now`)와 같다 |
| 본사 의존 | 0 | 0 — 고객 PC 안에서 돈다(#30) |

- **HostedService 1개 신설**(`CooltimeService`) · 15초마다 한 바퀴. 기존 5개(`Program.cs:327-343`)와 나란히 등록, 스코프는 `CsAutoDispatchService` 모양(`CreateScope`).
- 판단 본체는 **`RunOnceAsync(DateTime nowLocal)`** — 시각을 인자로 받는다 ⇒ 시험이 시계를 주입(새 패키지 0).
- 켜진 회사가 없으면 한 바퀴 = 가벼운 조회 1회(`WHERE cooltime_enabled = 1`).

**시각 기준 (선행 §3 🔴 섞임 정리)**: 회사 설정 두 시각 = **서버 PC 벽시계(로컬)**. 설정 시각 순간 `C` = 오늘 `HH:mm` 이 지났으면 오늘, 아니면 어제의 그 시각(로컬) → 비교할 때만 `C_utc` 로 바꾼다. `user_sessions` 새 칸은 기존대로 **UTC**. `attendance` 는 기존대로 **로컬**.

## §3 [상태] 로그인 한 건마다 두 칸 — 한 바퀴의 규칙

`user_sessions`(PC 행만 대상) 새 칸: `cooltime_asked_at`(물은 순간 · UTC · NULL=안 물음) · `cooltime_snooze_until`(이 순간 전엔 안 묻는다 · UTC · NULL=없음). 행은 로그아웃 때 지워지므로 **다음 로그인은 새로 시작**.

한 바퀴(켜진 회사마다 · `N`=지금):

| # | 조건 (`device_kind='pc'` · 만료 안 된 행만) | 동작 |
|---|---|---|
| ① | `asked_at` 있음 · `N ≥ asked_at + 65초`(60초 + 여유 5초) | **끝낸다**(§4) — 무응답 |
| ② | `asked_at` 없음 · `snooze_until` 없음 · `login_at < C` · `N ≥ C + 5분` | **묻지 않고 끝낸다** — 설정 시각+60초가 이미 지났다(서버가 꺼져 있다 켜진 경우 등 · Q5 그대로) |
| ③ | `asked_at` 없음 · `login_at < C` · (`snooze_until` 없음 또는 `≤ N`) · ②가 아님 | **묻는다**: `asked_at = N` · 그룹 `s:{tenant}:{sid}` 로 `CooltimePrompt{secondsLeft:60}` |
| ④ | `login_at ≥ C` (설정 시각 뒤 로그인) | **C-4 결재**에 따른다 — 권고 (나): `N ≥ login_at + 1h` 이면 ③과 같이 묻는다 |

- [계속] = `POST /api/auth/cooltime/continue` → **한 문장**: `UPDATE user_sessions SET cooltime_asked_at=NULL, cooltime_snooze_until=@N+1h WHERE session_id=@Sid AND tenant_id=@T AND cooltime_asked_at IS NOT NULL AND cooltime_asked_at > @N-65초`. 0행 = 이미 끝남 → 409 *「이미 로그아웃되었습니다」*. (Q2 · 1시간 뒤 ③이 다시 묻는다)
- ①의 끝내기도 같은 조건(`asked_at <= @N-65초`)을 **삭제 문장 WHERE 에** 넣는다 ⇒ [계속]과 끝내기가 동시에 와도 한쪽만 이긴다.
- 밤새 [계속]을 누른 로그인은 로그아웃할 때까지 한 시간마다 묻는다(`C` 가 안 바뀌므로). 오더 Q2 그대로.
- 첫 물음은 한 바퀴(15초) 늦을 수 있다 ⇒ 실제 종료 = 설정 시각 + 60~85초. 오더 「+60초」의 허용 폭으로 적는다(⚠️ PM 확인).

## §4 [끝내기] 함수 하나 — `CooltimeLogoutAsync(tenantId, sid, nowLocal, 원인)`

부르는 곳 3: ① 서버 작업(§3 ①②) · ② 팝업 [지금 로그아웃] · ③ 카운트다운 0 — ②③은 `POST /api/auth/cooltime/logout`(`sid`·테넌트 = JWT 에서만 · #2).

| 순서 | 한 트랜잭션 안 | 비고 |
|---|---|---|
| 1 | `DELETE FROM user_sessions WHERE session_id=@Sid AND tenant_id=@T AND device_kind='pc'` (①은 §3 조건 추가) | **0행이면 여기서 끝**(이미 끝남 = 중복 퇴근 기록 방지) |
| 2 | `refresh_tokens` 폐기 `WHERE user_id=@U AND session_id=@Sid` | 작2 DB-130 재사용 · 휴대폰 무접촉(Q3) |
| 3 | 퇴근 기록(§6) | 사원 연결 없는 계정은 건너뜀(정보 로그) |
| 트랜잭션 밖 | 접속기록 `audit_trail`(작2 §6 의 공용 정적 함수 · `action_type='logout'` · `reason='자동 로그아웃(설정 시각)'`) · 그룹으로 `CooltimeEnded` | 실패는 `LogWarning` 1줄(#15) · 끝내기를 되돌리지 않는다 |

- 기존 `AuthController.Logout`(손 로그아웃)은 **무접촉** — 지금처럼 「그 순간」을 퇴근으로 찍는다. 쿨타임 경로만 정시 퇴근(Q1).
- 서버가 끝낸 뒤: 열린 화면은 `CooltimeEnded` 로 즉시 로그인 화면 · 푸시를 못 받은 화면은 `SessionValidityMiddleware`(최대 10초 캐시) 401 → 갱신 → refresh 폐기로 401 → 로그인 화면. 다음 로그인이 **출근을 찍는다**(오더 「로그인을 하도록 유도」).
- 두 번째 PC: 1번 삭제 순간부터 작2 의 409 판정에 더 이상 안 걸린다 ⇒ 풀림(G-C4).
- ⚠️ 저장 위치별 차이(§0 전제 · 작2 개정2): **sessionStorage(지금)** — 창을 닫은 PC 는 토큰이 이미 없지만 서버 세션 행은 남아 다른 PC 를 막는다 ⇒ 서버 끝내기가 그 행을 치운다. **localStorage(개정2 안)** — 다음 날 같은 브라우저를 열면 로그인 화면 없이 되살아나 출근이 안 찍힐 수 있다 ⇒ 서버 끝내기 + refresh 폐기가 **로그인을 다시 하게 만든다**. 둘 다 이 설계로 덮인다.

## §6 [퇴근 기록] 정시 퇴근 · 어느 날짜에 붙이나

**붙일 행**: 그 사원의 `attendance` 중 **퇴근 빈칸(`check_out IS NULL`)** · `check_in` 이 **물은 순간(없으면 끝낸 순간) `A` 의 24시간 이내이고 `A` 이전**인 것 중 가장 최근 1줄.
⇒ 자정 넘김(예 쿨타임 02:00): 전날 09:00 출근 행에 붙는다(`work_date` = **출근한 날**). 기존 `CheckOutAsync` 의 `work_date = 오늘` 제약(`HrService.cs:79`)을 쓰지 않는다 — 새 함수.

**적을 시각**: 그 행 `check_in` 이후 **처음 오는 정시 퇴근 시각**(로컬).
- 주간(출근 09:00 · 정시 18:00) → 같은 날 18:00 · 야간(출근 22:00 · 정시 06:00) → 다음 날 06:00.
- `work_hours` = 적은 퇴근 − 출근(소수 1자리 · 기존 식 `HrService.cs:83`).
- `check_out_source = 'cooltime'`(자동 표시 · DB-134).
- 🔴 그 시각이 **`A` 보다 뒤**(아직 안 온 시각)면 → **C-2 결재**.
- 🔴 퇴근이 **이미 있는** 행(휴대폰 로그아웃·[퇴근] 버튼) → **C-3 결재** · 권고 안 건드림.
- 해당 행 없음(출근 기록 없음 · 24시간 밖) → 아무것도 안 적는다(정보 로그).

**정시 퇴근 칸을 쿨타임 시각과 따로 두는 이유(C-1 권고)**: 사장님 Q1 예가 곧 근거다 — 18시에 나간 사람이 22시 쿨타임에 걸려 **18:00** 으로 적혀야 한다. 한 칸이면 ① 쿨타임이 18시에 돌아 제시간 퇴근 전원에게 팝업이 뜨거나 ② 22:00 이 퇴근으로 적힌다. 둘 다 오더 위반.

**고치기**(Q1 「수정 여지」 · 반자동 원칙 제안값→수정→확정)
- 🟢 실측: 퇴근을 **고치는** 길은 없다. 있는 것은 [퇴근](본인 · 오늘 · 빈칸)·[대신 퇴근](`HrController.cs:84` · `HR_PROXY` update · 오늘 · 빈칸)뿐.
