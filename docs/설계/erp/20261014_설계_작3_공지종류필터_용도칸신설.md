## §0 카드

- 🟢 **결-D ⓑ** — 받을 때 종류를 **칸**에 적는다. 본문 글자를 되읽는 ⓐ 는 사장님이 버렸다.
- 🔴 **필터는 서버**다(1V P-5). 화면에서 거르면 쪽별 `LIMIT 200` 밖 행이 사라진다.
- 🔴 **낱말은 서버가 내려보낸다**(1V P-7). 화면에 표를 두면 ERP 안에서 **사본이 둘**이 된다.
- 🔴 **값과 낱말을 둘 다** 보낸다 — 필터는 **값**, 표시는 **낱말**. 그게 결-D ⓑ 를 고른 이유다.
- 🔴 기본값은 **`NULL`**. 옛 행에 `'etc'` 를 적으면 **모르는 것을 안다고 거짓 주장**한다.

## §1 DB-146 — 용도 칸 신설

```
ALTER TABLE cs_requests
    ADD COLUMN IF NOT EXISTS purpose varchar(20) DEFAULT NULL
        COMMENT '본사 발신 종류(update/notice/promo/etc/event/billing) — NULL = 작3 이전에 내려온 옛 쪽지(종류를 모른다) · 고객 문의(origin=local)는 늘 NULL';

ALTER TABLE cs_requests
    ADD KEY IF NOT EXISTS idx_cs_req_purpose (tenant_id, origin, purpose, created_at);
```

| 판단 | 근거 |
|---|---|
| `varchar(20)` | 백오피스 허용값 중 가장 긴 것이 `billing`(7자) — 여유를 둔다. `category` 가 같은 폭이다 |
| 🔴 `DEFAULT NULL` | 1V P-11 — `'etc'` 면 **옛 행이 거짓**을 말하고, `NOT NULL` 이면 칸을 안 적는 **기존 INSERT 가 깨진다** |
| KEY 에 `origin` 포함 | 필터는 **항상 공지 쪽(`origin='hq'`)에서만** 걸린다 ⇒ 선행 칸으로 둔다 |
| `IF NOT EXISTS` | 추가형·재실행 안전 · **MariaDB 문법**(ERP 축 · 백오피스 MySQL 8 과 판이 다르다 — `DB-144` 가 적어 둔 그대로) |
| 🔴 출하 DDL | **같이 더한다**(#36 — 신규설치 단일 진실원). 안 더하면 새로 설치한 고객은 칸이 없다 |

🔴 **옛 행은 한 줄도 안 바뀐다**(#1). `UPDATE` 문 **0건**이다.

## §2 수신기 — 받은 종류를 칸에 적는다

`CsOutboxSenderWorker.ReceiveOutboundAsync` 의 `cs_requests` INSERT 에 `purpose` 를 **더한다**.

- 🔴 **칸이 없는 DB 에서도 돌아야 한다** — 업데이트 직후 마이그 적용 전 1회가 그 상태다. 그래서 **칸 존재를 보고** INSERT 문을 가른다(목록 쪽 가드와 같은 모양 · 1V P-4).
- 🔴 봉투는 **이미 `purpose` 를 싣고 온다**(작2 P-2 실측 — 백오피스 SELECT → DTO → 역직렬화 대소문자 무관).
- 🔴 **값을 그대로 적는다** — 낱말이 아니라 **값**이다. 낱말로 적으면 결-D ⓑ 를 고른 이유(「낱말을 바꿔도 필터가 안 깨진다」)가 무너진다.
- 🔴 **본문 머리 한 줄은 그대로 둔다**(작2 가 세운 것). 칸이 생겼다고 머리글을 빼면 **옛 쪽지는 머리글만 있고 새 쪽지는 칸만 있어** 목록이 두 모양이 된다.

## §3 목록 API — 질의칸 + 서버 필터 + 낱말 동행

`CsRequestController.List` 에 **더한다**(#1 · 기존 호출자 안 깨뜨린다).

```csharp
public async Task<IActionResult> List(string? origin = null, string? purpose = null, CancellationToken ct = default)
```

🔴 **기본값을 준다** — 기존 게이트가 `List(default)`·`List("hq", default)` 로 부른다(작2 실측). 기본값이 없으면 그 파일들을 고쳐야 하고 그건 이 차수 소유가 아니다.

| 자리 | 설계 |
|---|---|
| 칸 존재 가드 | `HasPurposeColumnAsync()` 신설 + `ResetPurposeColumnCache()` — `origin`·`hq_status` 와 **같은 모양** |
| SELECT | `{(hasPurpose ? "r.purpose" : "NULL")} AS purpose` + **낱말** `purposeLabel` 동행 |
| 🔴 WHERE | **칸이 있을 때만** 단다. 없으면 1054 로 목록이 통째로 죽는다 |
| 🔴 **A-1** | `purpose=etc` 는 **`(r.purpose = 'etc' OR r.purpose IS NULL)`** — 옛 쪽지가 사라지면 사장님께 「쪽지가 없어졌다」로 보인다 |
| 낯선 값 | `?purpose=zzz` 는 **전체**로 떨어뜨린다(화면을 비우지 않는다 — `origin` 선례 그대로) |
| 칸이 없는 DB + 필터 | **전체**를 준다. `origin=hq` 와 달리 「원리적으로 0건」이 아니다 — 칸이 없으면 **모든 공지가 「기타」**이므로 비우면 거짓이다 |

### §3-1 🔴 낱말을 서버가 내려보낸다

`PurposeLabel` 의 접근성을 `private static` → **`internal static`** 으로 **한 낱말** 올린다(1V P-10).

| 왜 | |
|---|---|
| 🔴 **사본이 둘이 되는 것을 막는다** | `HitPan.Web` 은 서버 코드를 참조하지 않는다. 화면이 자기 표를 들면 작2 C-2(본사↔고객 낱말 어긋남)와 **같은 종류의 결함**을 ERP 안에서 새로 만든다 |
| 왜 옮기지 않나 | 메서드를 다른 자리로 **옮기면** 작2 게이트 `G-W10-1·7` 의 리플렉션이 깨진다. **이름·클래스를 그대로 두고 접근성만** 올린다(#1 추가만의 정신) |
| 🔴 확인 | 리플렉션은 `BindingFlags.NonPublic` 이라 `internal` 도 찾는다 — **[3] 에서 G-W10 8/8 로 확인한다.** 원리만 적고 넘기지 않는다 |

`NULL` 의 낱말은 **「기타 공지사항」**이다(결-D: 옛 쪽지는 기타로 보인다).

## §4 공지 화면 — 종류별 보기 + C-5 봉합

### §4-1 칩 — 못 박은 낱말을 **서버가 준 낱말**로

`CsNoticePage.razor:111` `KindLabel(it) => "본사 안내"` → `it.PurposeLabel` 을 쓴다.

🔴 **이것이 C-5 봉합의 본체다.** 제목(`[히트판 공지사항] …`)과 칩이 **같은 출처**가 되므로 「한 줄에서 두 번 말하고 값이 다른」 문제가 **사라진다**.

### §4-2 🔴 표기를 한 가지로 — 「본사안내」 (안 띈다)

코드에 **두 표기**가 있다: 칩 쪽 「본사 안내」(띈다) / 낱말 표 fallback 「본사안내」(안 띈다).

**「본사안내」로 합친다.** 근거: 그쪽이 **낱말 표 = 정본**에 있는 글자이고, 본문 머리 한 줄(`[본사안내] …`)로 **이미 고객 화면에 나가 있는** 글자다. 칩 쪽을 바꾸면 **아직 안 나간 글자**를 고치는 것이고, 표 쪽을 바꾸면 **이미 나간 옛 쪽지의 머리글과 어긋난다**.

### §4-3 필터 자리 — **칩 줄**(MudChipSet) · 목록 위 한 줄

| 기준 | 설계 |
|---|---|
| **처음 보는 사람** | 「전체 / 업데이트공지사항 / 히트판 공지사항 / 프로모션 안내 / 기타 공지사항」이 **눈에 다 보인다.** 드롭다운은 **열어야 뭐가 있는지 안다** ⇒ 쓰지 않는다 |
| 🔴 ① 화면과 안 헷갈린다 | ① 화면의 `MudSelect` 2개는 **문의를 쓰는 칸**이다. 공지 화면 필터를 같은 모양으로 두면 **쓰는 칸처럼 보인다** ⇒ 모양을 다르게 한다 |
| **한 화면 완결** | 칩 줄 한 줄 ⇒ 목록이 밀리는 높이가 최소다 |
| 종류 목록 | **서버가 준 것만** 세운다 — 쓰기 콤보 4종(①~④). 🔴 옛 값(`event`·`billing`)은 **따로 안 세운다**(쓰기 콤보에 없는 종류라 필터에 세우면 늘 0건으로 보인다). 그 쪽지는 **「전체」에서 보인다** |
| 토큰 | 🔴 색·px 를 적지 않는다. `hp-cs-*` 와 `--hp-*` 토큰만(작1 디자인 기준 §7 그대로) |

### §4-4 🔴 빈 결과를 견딘다

필터를 걸어 0건이면 **「전체」로 돌아가는 길**을 한 줄로 보여 준다. 🔴 「조건에 맞는 자료가 없습니다」만 두면 처음 보는 사람은 **쪽지가 없어졌다고 읽는다**.

## §6 함정

1. 🔴 **번호가 겹치면 뒤 파일이 조용히 skip** 된다 — `DB-146` 이 유일한지 확인(게이트가 돈다).
2. 🔴 **출하 DDL 을 같이 안 더하면 새 고객은 칸이 없다**(#36).
3. 🔴 **`NOT NULL` 금지** — 기존 INSERT 가 깨진다(1V P-11).
4. 🔴 **옛 행에 `UPDATE` 금지** — 모르는 것을 안다고 적으면 거짓이다.
5. 🔴 **낱말을 화면에 복사 금지**(1V P-7 · G-W11-7 이 막는다).
6. 🔴 **`PurposeLabel` 을 옮기지 마라** — 작2 게이트 리플렉션이 깨진다. 접근성만 올린다.
7. 🔴 **게시 때 `requiresMigration=true`** — 안 켜면 워크플로가 던진다(1V P-9). 그래도 **손으로 고른다.**
8. 🔴 **전체 회귀**를 돌린다 — 작2 에서 이웃 회귀 1건이 나왔다.
9. 🔴 **「빌드 0/0」을 적을 때 `--force-evaluate`** 로 한 번 잰다(작8 에서 배운 것 — 캐시된 restore 는 지금 상태가 아니다).
