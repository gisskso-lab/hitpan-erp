## 1. 전결 1 — 선후 교체 (작11 → 작9)

설7 실측: 확정 5개 중 **4개에 개별 권한 검사 없음**.
결재가 지금 **뒷문을 막고 있다** ⇒ 작9 로 결재를 빼면 막는 게 없어진다.

🟢 **전결 판정: 작11(확정 권한 부여)을 신설하고 작9 보다 먼저 한다.**

근거는 사장님 지시 자체다. 지시 7 *"판매확정·구매확정은 **암묵적인 결재기능**"* —
확정이 **결재를 대신한다**는 뜻이므로, 확정은 **결재만큼 통제돼야** 그 말이 성립한다.
지금은 통제가 없으므로 **사장님 지시의 전제를 우리가 아직 못 만든 것**이다.

⇒ 작9 를 미루는 게 아니라 **작9 를 성립시키러 가는 것**이다.

## 2. 전결 2 — U2 확정 권한 기본값

### 2-1. 처음 질문이 틀렸다

설7 에서 *"기본 OFF 면 기존 고객이 확정을 못 하는 회귀"* 라 적고 사장님께 물으려 했다.
**실측하니 질문 자체가 반쯤 틀렸다.**

`PermissionService.cs:236-266` · `PermissionFilter.cs`:

```
Layer 0   tenant_admin  → 무조건 true (락아웃 방지)
Layer 1   user_permissions 행 조회 → COALESCE(col, 0)
          행이 없으면 → 0 → ForbidResult
```

🔴 **이 시스템은 원래 전부 "기본 OFF" 다.** 권한 행이 없으면 막는다.
⇒ *"기본값을 OFF 로 할까요"* 는 **이미 정해진 것을 다시 묻는 질문**이었다.
사장님 예외처리 축(*"기본 OFF, 고객사가 켬"*)과도 **이미 일치**한다.

### 2-2. 그럼 회귀는 진짜 있나 — 갈라서 봐야 한다

| 대상 | 지금 | 작11 후 | 회귀 |
|---|---|---|---|
| **대표**(`tenant_admin`) | 확정 가능 | 확정 가능 (**Layer 0 바이패스**) | 🟢 **없음** |
| `sales_manager` | 확정 가능 | **권한 행 필요** | 🔴 **있음** |
| `sales_user` | **확정 가능**(설7) | **권한 행 필요** | 🔴 **있음** |

🟢 **대표는 절대 안 막힌다** — 1인 사업자·소규모는 영향 0.
🔴 **직원 계정을 쓰는 고객사만** 업데이트 직후 확정이 막힌다.

### 2-3. 🟢 전결 판정

**기본값을 새로 정하지 않는다. 기존 규칙(행 없으면 OFF)을 그대로 따른다.**
대신 **회귀를 마이그레이션으로 흡수**한다:

> **작11 DDL 은 기존 `sales_manager`·`purchase_manager`·`sales_user` 보유 계정에
> 확정 권한 행을 `1` 로 넣고 시작한다.**
> = **지금 할 수 있던 사람은 계속 할 수 있다**(회귀 0),
>   **앞으로 새로 만드는 계정은 기본 OFF**(사장님 축 유지).

이건 새 정책이 아니라 **현 상태를 명시적으로 옮겨 적는 것**이다(#1 덮어쓰기 아님).

⚠️ **단 `sales_user` 를 그대로 옮기면 설7 이 지적한 구멍을 그대로 데려온다.**
⇒ 🔴 **`sales_user` 는 옮기지 않는다.** 이유:
   - `sales_user` 가 확정 가능한 것 **자체가 이번에 찾은 결함**이다
   - 옮기면 *"고쳤는데 아무것도 안 바뀌는"* 봉합이 된다
   - 대표가 필요하면 **권한 화면에서 켜면 된다**(#11 — 어드민이 직접)

### 2-4. 그래서 U2 는 사장님께 안 묻는다 — 대신 알린다

묻지 않는 이유: **기본값은 이미 정해져 있었고**, 남은 건 회귀 흡수라는 **기술 판단**이다.
알리는 이유: **`sales_user` 를 뺀 것**은 일부 고객사에서 *"어제 되던 게 안 된다"* 로 나타난다.
⇒ **사후 보고 대상**이지 사전 결재 대상이 아니다(전결의 정의).

## 3. 전결 3 — U1 은 전결하지 않는다

경비 옵션 2개의 **표시 문구**는 사장님이 고객에게 보일 **말**을 정하는 일이다.
PM 이 지어내면 그게 곧 **받아쓰기의 반대편**(우리가 사장님 말을 창작).
⇒ **U1 은 계속 대기.** C(경비 화면통합)만 막히고 나머지는 안 막힌다.

## 4. 작11 범위 (신설)

| 대상 | 부여할 권한 |
|---|---|
| `sales/deliveries/{id}/confirm` | `SALES` · `update` (안) |
| `sales/deliveries/bulk-confirm` | 개별과 **동일**(B11 해소 — 다르면 우회로가 생긴다) |
| `purchase/returns/{id}/confirm` | `PURCHASE` · `update` (안) |
| `purchase/receipts/{id}/confirm` | `PURCHASE` · `update` (안) |

🔴 **메뉴코드·액션은 안이다.** 착수 시 `EnforcedMenus` 등록이 **필수**(안 하면 1.2.74 P0 재발 —
체크박스가 화면에 안 뜨는데 서버는 막는 상태 = 고객이 켤 방법이 없다).

⚠️ **`SALES`·`PURCHASE` 는 현재 `EnforcedMenus` 에 없다**(9개만 등록).
⇒ 작11 은 **권한 부여 + EnforcedMenus 등록 + 마이그레이션** 세 개가 **한 커밋**이어야 한다.
   하나라도 빠지면 *"고쳤다≠갔다"* 가 된다.
