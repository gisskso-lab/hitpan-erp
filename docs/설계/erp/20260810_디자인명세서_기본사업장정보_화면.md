## 4. 필드 배치 (6행 유지 — 늘리지 않는다)

### 4-1. 잠금 묶음 3행

| 행 | 필드 (md 폭) |
|---|---|
| 1 | 사용업체명 `4` · 사업자번호 `4` · 대표자 `4` |
| 2 | 업태 `4` · 업종 `4` · 법인등록번호 `4` |
| 3 | 우편번호 `3` · 사업장 주소 `9` |

⭐ **각 행의 폭 합계 = 12.** 현행 1행은 `6+3+2=11` 이라 우측이 어긋나 있다 — 이번에 해소된다.

### 4-2. 입력 묶음 3행

| 행 | 필드 (md 폭) |
|---|---|
| 4 | 상세주소 `4` · 전화 `4` · 종사업장번호 `4` |
| 5 | 팩스 `4` · 홈페이지 `4` · 이메일 `4` |
| 6 | 비고 `12` (`Lines="2"`) |

### 4-3. 모바일 (`xs`)

전 필드 `xs="12"` 유지(현행과 동일). 좁은 화면에서는 **잠금 묶음 배경색이 유일한 구분 신호**가 되므로
배경 대비를 확보한다.

## 5. 입력칸 명세

### 5-1. 잠금 필드

```razor
<MudTextField T="string" Label="사용업체명" @bind-Value="_model.CompanyName"
              Variant="Variant.Outlined" Margin="Margin.Dense"
              ReadOnly="@_model.IsLockedFromLanding"
              Class="@(_model.IsLockedFromLanding ? "hitpan-locked-field" : null)" />
```

🔴 **`ReadOnly` 를 쓴다. `Disabled` 금지.**

| | `ReadOnly` ✅ | `Disabled` ❌ |
|---|---|---|
| 글자 | 또렷하게 읽힘 | **흐려짐** — 읽으라고 채운 값을 못 읽음 |
| 복사 | 가능 | **불가** — 사업자번호 복사 못 함 |
| 값 전달 | 유지 | (이 화면은 폼 제출이 아니라 무관) |

### 5-2. 잠금 필드 CSS (`hitpan.css` 에 추가)

```css
/* 기본 사업장 정보 — 사업자등록증 자동 반영 필드 */
.hitpan-locked-field .mud-input-slot {
    background: var(--mud-palette-background);
    font-weight: 600;
}
.hitpan-locked-field .mud-input-outlined-border {
    border-left: 2.5px solid var(--hitpan-primary);
}
```

⚠️ MudBlazor 내부 클래스명은 **버전에 따라 다르다.** 구현 시 실제 DOM 을 확인하고 맞춘다.
안 되면 `MudTextField` 를 감싸는 `<div>` 에 좌측 띠를 주는 방식으로 대체한다.

### 5-3. 입력 필드

현행 그대로. 변경 없음.

## 6. [기본 사업장 정보 변경 요청] 버튼

```razor
@if (_model.IsLockedFromLanding)
{
    <MudStack Row="true" Justify="Justify.FlexEnd" Class="mt-3">
        <MudButton Variant="Variant.Outlined"
                   Color="Color.Warning"
                   StartIcon="@Icons.Material.Filled.EditNote"
                   OnClick="OpenChangeRequest">
            기본 사업장 정보 변경 요청
        </MudButton>
    </MudStack>
}
```

| 항목 | 값 |
|---|---|
| 문구 | **`기본 사업장 정보 변경 요청`** — 사장님 확정. 줄이거나 바꾸지 않는다 |
| 위치 | 잠금 묶음 **안쪽 맨 아래**, 우측 정렬 |
| 표시 조건 | `IsLockedFromLanding == true` 일 때만 |
| 색 | `Color.Warning` (주황) — 잠금 초록과 대비되어 "여는 동작"으로 읽힌다 |

### 상태별 표시

| 상태 | 화면 |
|---|---|
| 요청 전 | `[기본 사업장 정보 변경 요청]` |
| 접수됨 | `MudChip` — `변경 요청 검토 중 (접수 8/10)` · 버튼 비활성 |
| 반려됨 | `MudAlert Severity="Warning"` — 사유 표시 + 재요청 가능 |
| 승인됨 | 값 자동 갱신 + 버튼 원상 복귀 |

## 7. 🔴 문구 정정 2건 (그대로 두면 거짓이 된다)

| 위치 | 현재 | 조치 |
|---|---|---|
| `:25-27` `MudAlert` | *"회사명·사업자번호·대표자명은 변경할 수 없습니다"* | 🔴 **삭제.** 잠금이 8개가 되면 3개만 적은 이 문장은 거짓이 된다. 역할은 §3-1 머리글이 흡수한다 (약 60px 확보 → 6행 유지에 기여) |
| `:36`·`:54`·`:69` `HelperText` | *"🔒 랜딩 자동 반영 (변경 불가)"* | 🔴 **삭제.** '랜딩'은 **내부 3시스템 이름**(헌법 #35)이라 고객이 모른다 |

⚠️ **`:27` 의 *"본사 고객지원으로 요청해주세요"* 는 §6 버튼으로 대체된다.**
(연락처가 없어 안내가 성립하지 않던 문제도 함께 해소)

⭐ **화면에 쓰지 않는 말**: `OCR` · `랜딩` · `부트스트랩` · `테넌트` — 고객 노출 개발용어 금지.

## 8. 우편번호 찾기 버튼 (`:42`)

| 상태 | 처리 |

## 9. 완료 판정 (디자인 관점)

- [ ] 잠금/입력 묶음이 **한눈에 구분**되는가 (색 없이 흑백으로 봐도 구분되는가)
- [ ] 행 폭 합계가 **모두 12** 인가
- [ ] **6행 유지** — 스크롤 없이 한 화면에 들어오는가 (헌법: 한 화면 완결)
- [ ] 잠긴 값이 **또렷하게 읽히는가** (흐리면 `Disabled` 를 쓴 것)
- [ ] 사업자번호를 **복사**할 수 있는가
- [ ] 화면에 `OCR`·`랜딩` 같은 개발용어가 **0건**인가
- [ ] 다크 모드에서 잠금 배경이 **구분되는가**
- [ ] 모바일(`xs`)에서 묶음 구분이 **살아 있는가**
