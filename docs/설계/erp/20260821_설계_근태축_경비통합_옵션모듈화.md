## 2. ⚠️ 지시 해석 — 확인 필요 1건

사장님 지시: *"경비처리 옵션에 **법인카드, 지출결의** 등으로"*

**"법인카드" 는 이미 있다.** 그리고 두 값은 **성격이 다르다**:

| 값 | 무엇을 묻나 |
|---|---|
| 법인카드·현금·개인카드 | **어떻게 결제했나** (결제수단 = 기존 `payment_method`) |
| **지출결의** | **어떤 절차로 올리나** (문서 성격) |

한 칸에 섞으면 *"법인카드로 낸 지출결의"* 를 표현할 수 없다.

⚠️ **PM 해석**: 기존 `payment_method` 에 값을 추가하는 것이 아니라,
**새 옵션 컬럼**을 붙이는 것으로 읽었다 — 사장님 *"옵션컬럼을 붙여"* 와도 맞는다.

🔴 **미확인으로 남긴다.** 아니면 사장님이 잡아 주신다(헌법 #32 — 받아쓰기 금지).

## 3. 확정 설계

### 3-1. 근태 (S5 축 A) — **남을 지목할 수 있게 한다**

> 🔴 **사장님 지시(추가)**: *"남의 근퇴 넣는건 **권한설정에 넣자.**"*

```
[지금] 근태 API = 내 employee_id 고정   → 계정 없는 11명 진입 불가
[본안] 권한을 가진 사람이 employee_id 를 지정한다
```

🔴 **역할을 코드에 박지 않는다.** *"인사담당자만"* 이라고 짜면 그것이 곧 템플릿이다(헌법 #11).
**권한 항목 하나를 만들고, 누구에게 줄지는 고객사가 정한다** — §3-5 경비 권한과 **같은 축**이다.

| 회사 유형 | 이 권한을 받는 사람 |
|---|---|
| 대표 혼자 (지시 경비-2) | 대표 |
| 인사팀 있음 | 인사담당자 |
| 회계팀까지 있음 | 고객사가 정한다 |

- 🔴 **자동 근퇴 경로는 손대지 않는다** — 이미 돌고, 6/22 봉합이 키를 통일해 뒀다
- **대리 입력** 경로 신설 — 🔴 **새 권한 항목**으로 통제(`RequirePermission`)
- `attendance.uq_att_date` (tenant+employee+date) 가 **이중행을 막는다** — 기존 제약 활용

⚠️ **헌법 #2**: `employee_id` 를 파라미터로 받되 **`tenant_id` 는 JWT 에서만**.
⚠️ **누가 대신 넣었는지 남긴다** — `memo` 또는 감사로그(경비 `CreateHrExpenseAsync` 가 이미 하는 방식).

### 3-2. 연장·조퇴·외출 (S5 축 B) — 결재 문서

- 신규 문서유형: `attendance_request`
- `DocTypeLabels` **두 곳** 등록 필수(`ApprovalService.cs:15` + `ApprovalTriggerHelper.cs:229`)
- 🔴 `ProcessAsync` **원본 반영 블록 필수** — 안 넣으면 `expense` 와 같은 병
  (승인해도 원본이 `pending` 고착 = 이번에 잡은 결함과 동형)
- ⇒ 결재함이 **8종 → 9종**

### 3-3. 경비 — **화면만 합치고 옵션 컬럼** (지시 경비-4)

```
[지금] 화면 2개 (직원신청 / 경리등록)   ← 누가 쓰냐로 갈림
[본안] 화면 1개 + 옵션 컬럼             ← 무엇이냐로 갈림
       표는 2개 그대로 (사장님 지시: "화면만 합치고")
```

🔴 **"누가" 가 아니라 "무엇" 으로 가른다.** 지시 경비-2 의 케바케가 여기서 흡수된다 —
대표 혼자든 회계팀이 있든 **화면은 하나**고, **권한만 열고 닫으면 된다**(지시 경비-1).

⚠️ **표는 합치지 않는다**(사장님 명시). 데이터 이관 없음 ⇒ 마이그 작업 0.

### 3-4. 🔴 옵션 모듈화 (지시 경비-4 *"일단 두개만, 더 붙일 수 있도록"*)

**값을 코드에 넣지 않는다.** 설정 표에서 읽는다.

| | |
|---|---|
| 지금 넣을 값 | **2개** (사장님 지시) |
| 나중에 | 표에 행만 추가 — **코드 무변경** |

> 근거: [labor_policy_settings](../../../installer/hitpan_db_clean.sql) 가 이미 같은 방식이다 —
> *"법정값을 코드에 넣지 않는다. 법이 바뀌면 이 표의 값만 갈아끼운다."*
> 🔴 **같은 원칙을 여기 적용한다.** 코드에 `switch` 로 박으면 "더 붙이기" 가 코드 수정이 된다.

⚠️ **헌법 #11** — 값을 우리가 정해 강제하지 않는다. 고객이 추가할 수 있어야 한다.

### 3-5. 경비 권한 — **코드로 강제하지 않는다** (지시 경비-1·2)

- 🔴 어느 경로로 경비가 들어오는지 **코드가 정하지 않는다**
- 고객사가 **직원계정 권한설정**으로 연다
- ⇒ B1 봉합이 **두 표 모두 시도**여야 하는 근거가 하나 더 붙는다
  (정본을 하나 고르면 한쪽 회사 유형이 죽는다)

## 6. 🔴 예외처리 축 (사장님 지시 2026-08-21 — 3건 전부)

> 사장님: *"세개 다 **예외처리로**"*

### 6-1. 무엇이 예외인가 — **권한이 예외이지 경로가 예외가 아니다**

PM 이 처음 A 를 *"예외 경로"* 로 이해했으나 **실측과 어긋난다**:
사원 12명 중 계정 보유 **1명** ⇒ 대리입력이 예외라면 **11명(92%)이 예외**다.
**예외가 92% 면 그것은 예외가 아니라 정상 경로다.**

⚠️ 그리고 예외 경로로 만들면 자연히 **덜 다듬어진다** — 화면도 덜, 감사로그도 덜, 검증도 덜.
그런데 실제로는 그 길로 대부분이 들어온다 ⇒ **제일 많이 쓰는 길이 제일 허술해진다.**

🔴 **사장님 결재**: *"계정 없는 직원이 앞으로 계정을 받나"* 물었더니 — **"이건 고객사 마음이지."**
⇒ **PM 질문이 틀렸다.** 우리가 정할 수 없는 것을 전제로 설계를 가르려 했다.
   5만 고객사면 전원 계정 주는 회사·사무직만 주는 회사·아무도 안 주는 회사가 다 있다.
   어느 쪽을 전제하든 나머지가 틀어진다.

### 6-2. ⇒ 확정

```
자동 근퇴  ← 계정 있는 직원      ┐ 둘 다 정상 경로.
대리 입력  ← 계정 없는 직원      ┘ 같은 수준으로 다듬는다.

예외인 것 = 권한 축 하나뿐
```

| 대상 | 예외처리 방식 |
|---|---|
| **U3 권한 칸** | 🔴 5축(view/create/update/delete/export) **밖의 별도 항목**. 5축은 *"내 데이터에 무엇을 하나"* 축이고 대리입력은 *"남의 데이터를 건드리나"* 축이라 **다르다**. `update` 에 얹으면 **자기 근태 고치라고 준 권한이 남의 근태까지 연다** |
| **U1 경비 옵션** | 🔴 기존 `payment_method` **밖의 별도 컬럼**. 섞으면 *"법인카드로 낸 지출결의"* 표현 불가(§2) |
| **A 근태 경로** | 🔴 **경로는 정상**. 권한이 예외라 **기본 OFF** — 고객사가 필요할 때 켠다 |

🟢 **권한을 예외로 두는 것만으로 의도가 달성된다**:
전원 계정 주는 회사는 안 켜면 그만이고, 그 회사에선 이 경로가 **없는 것처럼** 된다.
⇒ 결국 **고객사 마음대로**가 되고, 그것이 헌법 #11 이다.
