## §1 무엇이 고장났나 — 확정 사실만

```
SealKey    TpmKeyService.cs:78  Provider = CngProvider.MicrosoftPlatformCryptoProvider
           :79  KeyCreationOptions = OverwriteExistingKey
           :83  CngKey.Create(Rsa, KEY_NAME, keyParams)         → TPM 금고에 만든다
UnsealKey  TpmKeyService.cs:111 CngKey.Exists(KEY_NAME)          → 1인자 = Software 금고
           :113 CngKey.Open(KEY_NAME)                            → 1인자 = Software 금고
KEY_NAME   TpmKeyService.cs:35  "HitPan.TaxInvoice.MasterKey"    → 상수 하나뿐
```

PM 동작 실측(선행검증 §PM): Software 금고에만 만든 키가 `Exists(name)`=True · `Exists(name, Platform)`=**False**.
⇒ **공급자별로 키 공간이 완전히 분리된다.** 이름이 같아도 건너편은 못 본다.

그래서 일어나는 일:
`Exists` false → `TpmKeyService.cs:118` DPAPI LocalMachine 으로 **TPM RSA 암호문**을 풀려다 실패
→ `:123` CurrentUser 폴백도 실패 → 예외가 밖으로 나간다
→ `MainPcProofService.cs:137-146` 이 그 예외를 **`DifferentPc`** 로 흡수한다
→ `:171-174` **출입증을 안 준다** → `MainPcOnlyAttribute.cs:95-111` 이 403 `main_pc_only`.

🔴 여기서 더 나쁜 것: `:139` 주석이 *"오류가 아니라 정상 경로다"* 라고 적혀 있다.
⇒ **모든 해제 실패가 「컴퓨터가 바뀌었다」로 위장된다.** 진짜 고장이 안내 문구 뒤에 숨는다.
사장님이 본 [이 컴퓨터로 바꾸기] 버튼(`MainPcGate.razor:92`)이 그 위장의 결과다.

## §2 채택 — 봉투를 씌우고, 공급자를 말하게 한다 (절A)

### §2-1 왜 「공급자 한 줄 고치기」로 안 끝내나

`UnsealKey:111` 에 공급자만 넣으면 이 증상은 사라진다. 그러나 **세 가지가 남는다.**

1. `SealKey` 는 **세 갈래**로 나갈 수 있다 — TPM(`:83`) · DPAPI LocalMachine(`:93`) · DPAPI CurrentUser(`:98` catch 폴백).
   나온 값에는 **어느 갈래였는지 표식이 없다.** 해제는 추측하고, 틀리면 폴백을 또 추측한다.
2. `IsTpmAvailable()`(`:43-59`)은 TPM 을 **사실상 안 잰다** — `CngProvider.MicrosoftPlatformCryptoProvider` 는 그냥 객체라 항상 non-null.
   ⇒ TPM 없는 PC 에서도 TPM 갈래를 시도했다가 catch 로 떨어져 **CurrentUser** 로 봉인된다. 프로필이 바뀌면 그날로 안 풀린다.
3. `KEY_NAME` 이 세금계산서와 공유다(C-1 결재 = 분리).

⇒ **값 자신이 자기 출신을 말하게** 만든다. 그러면 해제에 추측이 0회가 된다.

### §2-2 봉투 포맷

```
[0..3]  매직 'H' 'P' 'M' '1'      — 메인PC 봉인 v1
[4]     갈래 1바이트              'P' = Platform(TPM) · 'L' = DPAPI LocalMachine · 'U' = DPAPI CurrentUser
[5..]   본문                      해당 갈래가 만든 바이트 그대로
```

- 오버헤드 5바이트. `VARBINARY(1024)` 여유 안에 들어간다 ⇒ **DDL 변경 없음.**
- 해제는 `[4]` 가 말하는 **그 방법 하나만** 쓴다. 실패하면 폴백하지 않고 **실패로 보고한다.**
  (지금은 실패가 폴백을 타고 내려가 「컴퓨터가 바뀌었다」로 끝난다 — 그 통로를 끊는다.)
- 매직이 없으면 = 옛 값 → §3.

### §2-3 새 서비스 (신규 파일 · 기존 파일 무접촉)

`src/HitPan.Application/Services/Security/MainPcSealService.cs` — `IMainPcSealService` 신설.

| 멤버 | 하는 일 |
|---|---|
| `byte[] Seal(byte[] raw)` | 갈래를 **재서** 고르고, 그 공급자로 봉인하고, 봉투를 씌운다 |
| `MainPcUnsealResult Unseal(byte[] envelope)` | 매직 확인 → 갈래 읽기 → **그 공급자를 명시해** 해제. 결과는 `Ok` / `LegacyFormat` / `NotThisPc` |
| `bool IsPlatformKspUsable()` | 🔴 **실제로 잰다** — 임시 키 이름으로 `CngKey.Create(..., Platform)` 을 시도해 보고 성공하면 **즉시 삭제**한다. 실물 `KEY_NAME` 무접촉 |

- 키 이름 상수 `HitPan.MainPc.SealKey` (C-1). `HitPan.TaxInvoice.MasterKey` 와 **글자가 겹치지 않는다.**
- 생성자에 **키 이름을 주입할 수 있게** 둔다(기본값 = 위 상수). 게이트가 격리된 이름으로 진짜 왕복을 돌기 위한 유일한 통로다(§5).
- 🚫 `ITpmKeyService` 를 **확장하지 않는다.** 확장하면 구현체 4개(`TpmKeyService` + 시험 가짜 3개)가 전부 깨진다(#12 grep 결과).
  별도 인터페이스면 세금계산서 경로는 **컴파일 단위로 무접촉**이다.

### §2-4 결선

`MainPcProofService` 는 `_tpm`(`:43`)을 **그대로 남기고** `_seal` 을 **더한다**(#1 추가만).
- `:235` `_tpm.SealKey(raw)` → `_seal.Seal(raw)`
- `:127` `_tpm.UnsealKey(sealedKey)` → `_seal.Unseal(sealedKey)` 의 결과로 갈래를 판정
- 생성자는 **오버로드를 더한다** — 기존 3인자 생성자를 지우지 않는다(기존 시험 무회귀).

## §3 옛 봉인값 — 「푼다」가 아니라 「알아본다」 (절B · C-2)

### §3-1 사실

`tenant_devices.mainpc_sealed_key` 에 값이 이미 있다(9/23 등록). 그 값은
`OverwriteExistingKey`(`TpmKeyService.cs:79`)로 **여러 번 덮인** TPM RSA 키로 봉인됐다.
덮인 키는 복구 수단이 없다. ⇒ **옛 값은 못 푼다는 전제로 설계한다.**

### §3-2 어떻게 보이나 — 막다른 방을 만들지 않는다

`MainPcProofOutcome` 에 값을 **하나 더한다**: `ReRegisterRequired`.
판정표(`MainPcProofService.JudgeRegistrationAsync`):

| 봉인칸 상태 | 판정 | 화면 |
|---|---|---|
| 없음/빈값 | `NotRegisteredYet` (종전) | [등록] 팝업 (종전) |
| 봉투 있음 · 이 PC 에서 풀림 | `MainPcConfirmed` (종전) | 조용히 통과 + 출입증 |
| 봉투 있음 · 안 풀림 | `DifferentPc` (종전) | [이 컴퓨터로 바꾸기] (종전) |
| **봉투 없음(옛 형식)** | **`ReRegisterRequired`** (신규) | **[다시 인증] 팝업** (신규) |

- 🔴 옛 값은 **풀려고 시도조차 안 한다.** 매직 4바이트만 본다 ⇒ TPM 접근 0회 · 예외 0회 · 로그 오염 0.
- 팝업 문구(고객어 · 개발용어 금지):
  *"자료보관 컴퓨터 인증을 한 번 더 받아야 합니다. 이 컴퓨터가 회사 자료가 들어 있는 그 컴퓨터가 맞으면 [다시 인증] 을 눌러 주세요."*
- 버튼이 부르는 곳은 **기존 `mainpc-register` 그대로**다. 새 API 를 만들지 않는다.
  `MainPcGate.RegisterAsync`(`:184-230`)가 왕복 → 등록 → `RunProofAsync()` 를 이미 한다.
- 🔴 대표(`tenant_admin`)에게만 뜬다 — `MainPcGate.razor:126` 의 기존 규칙을 그대로 따른다. 직원 화면은 변화 0.

### §3-3 자동 재봉인은 안 한다 (중요)

옛 값을 못 푼다 = **이 PC 가 그 PC 라는 증거가 없다.** 자동으로 새 키를 심으면
**아무 PC 나 먼저 로그인한 쪽이 메인PC 가 된다.** 반드시 대표 확인 1회를 거친다(반자동 원칙).

### §4-1 절C — 403 을 받으면 왕복을 한 번 더 돈다 (주 봉합)

`HitPanApiAuthHandler.cs:54` 에 **401 1회 자동 재발급**이 이미 있다. **그 옆에** 같은 모양으로 더한다.

- 동작: `MainPcGate` 가 쓰는 왕복을 **한 바퀴 돌고**(①표 → ②로컬 두드리기 → ③확인), 출입증을 받았으면 **원요청 1회 재시도**.
- 🔴 **재시도는 요청당 1회.** 실패하면 **60초 쿨다운** — 클라이언트 PC 에서 매 403 마다 왕복을 돌면 소음이 된다.
- 이 한 자리가 **셋을 동시에 덮는다**: C-3 경주 · C-5 30분 만료(`MainPcProofService.cs:191`) · SPA 이동 중 만료.
  🔴 `:186-189` 주석이 *"화면이 조용히 왕복을 다시 돌아 새로 받는다"* 라고 적혀 있는데 **그 코드가 없다.** 이 절이 그 주석을 코드로 만든다.

### §4-2 절D — 화면은 통과한 뒤에 부른다 (소음 제거)

## §5 게이트 — 진짜 왕복을 돌되 실물 키를 안 덮는다 (절E · C-7)

### §5-1 왜 게이트 18건이 다 통과했나

- `MainPcProofRoundTripGateTests.cs:98-99` — `SealKey` 를 부르면 **일부러 실패**시킨다(#39 보호).
- `MainPcSealRegistryGateTests.cs:173-196` — `SealKey`·`UnsealKey` **둘 다 가짜**.
⇒ **봉인 → 해제를 한 번도 이어서 돌린 적이 없다.** 글자는 다 보는데 **왕복 동작**을 안 본다.
누적 25번 지적된 *"게이트는 글자가 아니라 동작"* 의 26번째 재발이다.

### §5-2 격리 방식 (🚨 실물 키 무접촉의 근거)

`MainPcSealService` 생성자에 키 이름을 주입할 수 있으므로(§2-3), 게이트는
`HitPanTest.MainPcSeal.<GUID8>` 이라는 **1회용 이름**으로 서비스를 만들어 **진짜 Seal → 진짜 Unseal** 을 돈다.
`finally` 에서 그 이름의 키를 **삭제**하고, 삭제됐는지까지 확인한다.

- 실물 `HitPan.MainPc.SealKey` · `HitPan.TaxInvoice.MasterKey` 는 **이름이 안 겹치므로 안 덮인다.**
- PM 이 선행검증 §PM 에서 쓴 방식과 같다 — 이미 이 PC 에서 안전하게 돌려 본 방식이다.

### §5-3 CI 에서 실제로 도는가

- `build` 잡 = **`windows-latest`**(`.github/workflows/build-and-test.yml:20`) · `dotnet test src/HitPan.sln` 이 **필터 없이** 전부 문다 ⇒ 새 게이트 클래스는 **등록 없이도 돈다.**
- `db-gate` 잡 = `ubuntu-latest`(`:93`) ⇒ **CNG 가 없다.** 여기에 넣지 않는다.
- 🔴 **Software 금고는 어느 Windows 에나 있다.** ⇒ 본질(공급자 대칭)을 무는 게이트를 **Software 금고로** 세운다(G-21a).
  TPM 금고는 러너에 없을 수 있다 ⇒ **G-21b 는 TPM 이 있을 때만** 돌되, **G-21a 가 언제나 돌므로 건너뛰기가 본질을 가리지 못한다.**
  (「DB 없는 로컬 PASS = SKIP」 사고를 구조로 막는다.)

게이트 8건의 ID·판정식·**봉합 제거 시 FAIL 대응표**는 작업지시서 §5.

## §6 버린 대안과 버린 이유

| 버린 것 | 왜 버렸나 |
|---|---|
| **A. `UnsealKey:111` 에 공급자만 넣기** | 증상은 사라지지만 §2-1 의 셋이 남는다. 무엇보다 그 줄은 **세금계산서도 쓴다**(`DoubleEncryptionService.cs:111`) ⇒ 트랙 밖을 건드린다(#33) |
| **B. `SealKey` 를 Software 금고로 낮추기** | 대칭은 맞지만 **TPM 봉인을 포기**한다. DB 가 새면 봉인값도 새고, 그 값을 다른 PC 로 옮기면 풀린다 ⇒ DB-126 설계의 급소를 버리는 셈 |
| **C. 마이그레이션으로 옛 `mainpc_sealed_key` 를 NULL 로 밀기** | 팝업이 [등록] 으로 바뀌어 자연스러워 보이나 — ①운영 데이터를 지우는 되돌릴 수 없는 수술(#39 계통) ②실패해도 아무 흔적이 없다 ③코드가 알아보면 DDL 없이 끝난다. **읽는 쪽에서 가른다** |
| **D. 옛 값을 만나면 자동으로 새 키를 심기(무언 재봉인)** | 옛 값이 안 풀린다 = **이 PC 라는 증거가 없다.** 먼저 로그인한 아무 PC 나 메인PC 가 된다 — 보안 구멍(§3-3) |
| **E. 25분 타이머로 출입증 갱신** | 타이머는 **실패해도 아무도 모른다.** 브라우저 절전에 눌리고, 창 비활성 시 어긋난다. 403 은 **실패가 난 그 순간**을 정확히 가리킨다 |
| **F. `ITpmKeyService` 에 메서드 추가** | 구현체 4개(실물 1 + 시험 가짜 3)가 전부 깨진다(#12 grep). 세금계산서 경로 무접촉이 컴파일 단위로 보장되지 않는다 |
| **G. `MainPcGate` 를 `@Body` 를 감싸도록 바꾸기** | 팝업이 본문을 막지 않는다는 기존 설계(`MainLayout.razor:69-74`)를 뒤집는다. 절C 로 같은 목적을 **훨씬 적은 자리**에서 이룬다 |

## §7 실패 시 되돌리는 법

| 단계 | 되돌리는 법 | 남는 것 |
|---|---|---|
| 절A 만 | `MainPcSealService` 주입만 되돌린다(`MainPcProofService` 생성자 오버로드 제거). 신규 파일은 남겨도 아무것도 안 부른다 | 옛 동작 = 지금 증상 그대로 |
| 절B | `ReRegisterRequired` 갈래를 `DifferentPc` 로 되돌린다 | 팝업 문구만 옛것으로 |
| 절C | 403 재시도 블록만 제거. 401 재시도(`:54`)는 무접촉이라 인증은 안 깨진다 | 30분 만료 뒤 F5 필요(현재와 동일) |
| 절D | `OnAllowed` 미사용으로 되돌린다(파라미터는 선택이라 남아도 무해) | 콘솔 403 소음 부활 |
| **DB** | **되돌릴 것 없다** — 스키마 변경 0 · 데이터 삭제 0 | — |
| **고객 PC** | 새 봉투 값이 심긴 뒤 구버전으로 내려가면 옛 코드가 그 값을 못 푼다 ⇒ **`DifferentPc` 팝업 1회**로 끝난다. 잠기지 않는다 | 팝업 1회 |

🔴 배포는 **업데이트 경로로만**(#39 · #43 Major 팝업 흐름 무접촉).

| O-1 | **세금계산서 인증서도 같은 이유로 안 풀릴 수 있다** — `DoubleEncryptionService.cs:111` 이 같은 `UnsealKey` 를 쓴다 | 사장님이 트랙을 메인PC 로 지정하셨다. **모듈 경계 · 피해범위**는 사장님 결재 사항(9/24 인계1 ①) |

| O-4 | 9/23 등록이 **이 PC 의 세금계산서 TPM 키를 이미 덮었는지** | 로그·키 조회 권한이 PM 에게 없다(M-23). 사실 확인 자체가 결재 사항 |
