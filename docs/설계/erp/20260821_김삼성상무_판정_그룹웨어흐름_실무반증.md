## 1. 🔴 최우선 — 결재자 퇴사 = 전사 결재 마비

### 상무님 지적
> *"부장이 퇴사하면, 그 부장이 2단계 결재자인 **모든 문서가 동시에 멈춘다.** 한 건이 아니라 전부다."*
> *"인사 실무에서 이건 **매달 일어나는 일**이다. 삼성에서도 결재 적체 1순위는 늘 **'결재자가 자리에 없다'** 였다."*

### 근거 (상무님이 코드에서 확인)
- 퇴사 처리는 `is_active=0` 만 — **`approval_doc_lines` 를 안 건드린다**
- 결재선은 `doc_type` 단위 **전역 마스터 1행** (문서별 스냅샷 아님)
- 대결(delegate)은 **기간을 미리 걸어둔 경우만** 동작 — *"갑자기 퇴사한 사람은 대결을 걸어두고 나가지 않는다"*

> *"어느 회사든 결재 시스템엔 반드시 **전결·대결·회수·결재선 변경 4종**이 있다.*
> *히트판엔 대결만 있고, 그것도 기간을 걸어둔 경우만이다."*

## 2. 🔴 자체 승인 버튼 — 없애면 안 된다. **이름을 바꿔라**

### 현장에는 결재선을 안 타는 일이 실제로 있다

| 상황 | 상무님 판정 빈도 |
|---|---|
| 소급 처리(지난달 초과근무 누락) | **매달** |
| **대표 구두승인 후 사후입력** | **중소기업 일상** |
| 결재자 부재 중 긴급건 | 분기 1~2회 |
| 감사 지적 정정 | 연 1~2회 |

> 🔴 *"**두 번째가 히트판 고객층의 핵심**이다. 5만 고객사가 대리점·중소기업이면,
> 대표가 결재함에 로그인해 버튼 누르는 회사보다 **'사장님이 그러라고 했으니 경리가 입력'** 하는 회사가 훨씬 많다.*
> *결재선을 강제하면 그 회사들은 **결재 설정을 아예 끄고** 쓴다."*

### ✅ 상무님 대안 — 감추지 말고 **흔적을 남겨라**

```
[전] 결재 진행 중이면 버튼 감춤          → "왜 승인이 안 되지" 전화 온다(CS 문의)
[후] [결재 진행중 — 2/3단계 김부장]  ← 상태를 보여준다
     [긴급 처리]  ← 관리자에게만. 사유 필수 입력
                    결재 이력에 "결재선 미경유 — 사유 — 처리자" 기록
```

> *"실제 대기업 결재 시스템이 하는 방식이다. **막는 게 아니라 흔적을 남긴다.***
> *버튼을 없애면 사람들은 **DB를 직접 고치거나 엑셀로 따로 관리**하기 시작하고,*
> ***그건 흔적이 아예 안 남는다.**"*

## 4. 🔴 초과근무 — 결재 3단계면 현장에서 안 쓰인다

> *"초과근무는 **팀장 1명 승인**으로 끝나는 게 정상이다. 2~3단계 타는 회사는 거의 없다.*
> *직원 50명이면 **월 200~300건**이 나온다. 3단계에 태우면 결재자가 월 300번 버튼을 누른다.*
> ***그 순간 사람들은 전체선택 후 일괄승인한다.** 결재가 형식이 되는 전형적 자리다."*

### ✅ PM 구현 중 잘한 것
`amount: (decimal)hours` — 시간을 기준값으로 넣은 것.
> *"이 설계는 좋다. 실무에 정확히 맞는다 — **짧은 잔업은 통과, 긴 잔업만 결재.**"*

### ✅ 상무님 권고 — 기본값을 잡아줘라
> *"고객이 직접 정하게 두면 대부분 안 정하고 전부 결재로 흘린다."*

| 항목 | 출하 기본값 |
|---|---|
| 초과근무 결재선 | **1단계** (직속 팀장) |
| 자동승인 기준 | **2시간** |

⚠️ **헌법 #11 검토 필요** — "업종·규모별 템플릿 제공 금지" 와 충돌하는지.
PM 의견: 이건 업종 템플릿이 아니라 **문서유형 기본값**이라 다르다고 보나 **사장님 결재 필요**.

## 5. 오더 14번 — 큰 축은 맞다. **두 자리가 빠졌다**

```
[사장님] 사원관리 → 그룹웨어 업무 → 결재라인 → 회계
[상무님] 사원관리 → ①결재선 설정 → 그룹웨어 업무 → 결재라인 → ②확정(마감) → 회계
```

**① 결재선이 업무보다 먼저**
> *"결재선이 없으면 상신이 조용히 안 된다(`lineCount == 0` → return).*
> *결재선 없이 업무부터 열면 **첫 신청이 전부 허공에 뜬다.**"*

**② 결재 승인 ≠ 회계 반영**
> *"실무는 **결재 승인 → 급여 마감 → 회계 기표** 순이다.*
> *결재가 났어도 그 달에 넣을지 다음 달로 넘길지는 **급여 담당자가 정한다.**"*

⇒ 사장님 **급여 수동원칙과 정확히 맞물린다.**

**③ 근본 지적**
> *"'결재라인이 필요한 모든' 이라고 뭉뚱그렸는데 **실무에선 갈린다.***
> *근태(출퇴근 기록)는 결재를 안 탄다. 초과근무는 탄다.*
> ***어떤 업무가 결재를 타는지 목록을 먼저 확정**하고 넘어가야 한다."*

> *그런데 1·2·3번이 맨 위에 있다. **직원은 자기가 쓸 게 4번째부터 나온다.**"*

### 인사담당자 하루 동선 (상무님)
```
아침 → 결재함 (밤새 올라온 것)
     → 근태 (어제 누가 안 찍었나)
월중 → 휴가/휴직 승인
월말 → 급여
```

### 🔴 휴가 3형제 이름이 틀렸다
지금 **휴가·연차 / 연차 신청 / 연차 부여** 3개가 흩어져 있다.
> *"직원이 '휴가 쓰려면 어디로 가지' 할 때 **둘 다 아니다.**"*

| 상무님 안 | 누가 | 빈도 |
|---|---|---|
| **연차 신청** | 직원 — *내가 쓴다* | 매일 |
| **휴가 승인** | 관리자 — *남의 것을 처리한다* | 매일 |
| **연차 규정** | 관리자 | 연 1~2회 |

> *"히트판 정신 — **'처음 보는 사람이 혼자 쓸 수 있냐'** 가 여기서 걸린다."*

### ✅ "입사퇴사" 에 뭘 담나 — **여기가 1번 문제의 해법**

| 입사 | 퇴사 |
|---|---|
| 사원 등록 → 계정 발급 → 근로계약서 서명 → 연차 부여 → 결재선 편입 | 퇴사 처리 → 🔴**결재선에서 빼기** → 🔴**미결 결재 회수** → 잔여연차 정산 → 계정 정지 |

> 🔴 *"퇴사 쪽 2·3번이 바로 **1번에서 지적한 그 구멍**이다.*
> ***별건으로 미루지 말고 여기 묶어라.** 이게 제일 자연스러운 자리다."*
