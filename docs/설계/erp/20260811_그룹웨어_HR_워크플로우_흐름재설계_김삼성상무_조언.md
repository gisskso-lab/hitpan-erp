## 2. 김삼성 상무 조언

> *"13화면을 다 만들어놓고 순서를 안 잡으면, 직원은 어디서 시작할지 모릅니다.
>  삼성에서도 그랬습니다. **기능이 없어서 안 쓴 게 아니라, 어디서부터 눌러야 할지 몰라서** 안 썼습니다."*

이 말은 히트판 정신과 같은 자리다 — *"쓰기가 겁나 쉬웠기 때문이다."*

### 2-1. 인사 워크플로우 6단계 — ERP 6단계와 같은 원리

```
① 계정   직원계정 생성 → 권한설정          ← 뿌리 (사장님 못박음)
② 신분   사원 등록 → 직급 → 부서            ← "이 사람이 누구인가"
③ 계약   전자근로계약서 → 서명              ← "언제부터 우리 직원인가"
④ 일상   근태 → 휴가·연차                   ← 매일 도는 것
⑤ 신청   연차신청 · 경비신청                ← 직원이 올리는 것
⑥ 결재   결재선 → 상신 → 승인 → 이력        ← 위가 판단하는 것
```

> *"히트판이 ERP 를 6단계로 잡은 건 잘한 겁니다. **인사도 똑같이 순서가 있습니다.**
>  지금 13화면은 이 순서 없이 나열돼 있습니다."*

### 2-2. 🔴 가장 큰 문제 — **③ 계약이 빠져 있다**

> *"②에서 ④로 바로 건너뜁니다. **입사일이 없는데 근태를 찍고 연차를 계산합니다.**"*

**연차는 입사일로 계산한다** — 1년 미만 월 1개 / 1년 이상 15개(법정).
입사일이 전자근로계약서에만 있고 근태·연차와 안 물리면 **연차 일수가 틀린다.**
숫자가 틀리는 게 아니라 **노동법 문제로 번진다.**

> *"화면을 하나 더 만드는 문제가 아니라 **순서를 바로잡는 문제**입니다."*

⚠️ **법무팀장 교차 확인 필요** — 근로기준법 연차 산정 기준.

### 2-3. 🔴 결재선은 **직급으로 짜야 한다** (상무님 단호)

> *"사람 이름으로 결재선을 짜면 **그 사람이 퇴사하는 날 회사의 모든 결재가 멈춥니다.**
>  삼성에서 실제로 겪었습니다."*

**현황**: `approval_line_steps` 에 `employee_id`(사람)와 `position_id`(직급)가 **둘 다** 있다.

**권고**
- 결재선은 **직급으로 정의**한다
- 실행 시점에 **그 직급인 사람을 찾아 넣는다**
- 사람 지정(`employee_id`)은 **대결(대리결재)** 용으로만 남긴다

⇒ 컬럼은 **둘 다 유지**한다(헌법 #1·#37 — 안 읽힌다 ≠ 잔재). **용도를 나눈다.**

### 2-4. 사내 메신저 — **결재 알림부터**

> *"메신저를 채팅으로 먼저 만들면 **잡담방**이 됩니다.
>  **'결재가 올라왔습니다' 알림부터** 붙이세요. 그러면 직원이 메신저를 켤 이유가 생깁니다.
>  채팅은 그 다음입니다."*

⇒ 1단계 **결재 알림** / 2단계 1:1 / 3단계 부서방.

## 3. 🔴 재설계의 구조적 쟁점 — 계정과 사원이 끊어진다

```
users(직원계정) ←── user_id ── employees(사원) ──→ 결재선·근태·휴가·계약서
                     ↑ DEFAULT NULL
```

**화살표가 거꾸로다.** 계정이 뿌리가 아니라 **사원에 딸린 선택 항목**이다.

⇒ **계정 없는 사원**이 결재선에 들어갈 수 있고, 그 사람은 **로그인할 수단이 없어 결재가 멈춘다.**
**헌법 #20(워크플로우는 절대 안 끊긴다) 정면.**

⚠️ 어제(챕터3)는 **화면 이동만** 연결했다. **데이터 축은 안 건드렸다.**

## 3-1. 🔴🔴 사장님이 짚은 결정적 지점 — **MDB 마이그레이션된 직원**

> *"MDB 데이터 마이그레이션시, **MDB통해 마이그레이션된 직원에 대해!!!**"*

**PM 이 완전히 놓치고 있던 자리다.**

레거시 히트판에서 넘어온 직원은 **계정이 없다.** MDB 에는 사원 명부가 있지
그 사람들의 히트판 로그인 계정이 있을 리 없다.

그런데 §3 에서 *"계정이 뿌리"* 로 설계를 잡았다. 그대로 가면
**마이그레이션된 직원 전원이 뿌리 없는 가지**가 된다.

### 왜 이게 결정적인가

사장님이 못박은 **마이그 합격선 = "레거시와 숫자가 맞는다"**
(원본이 살아 있어 **대조가 반드시 일어난다**).

레거시에 직원 50명인데 히트판에 50명이 안 뜨면 **거기서 마이그레이션 실패다.**
그런데 *"계정 없는 사원 금지"* 로 막으면 **50명이 아예 안 들어온다.**

🔴 베타 대상 = **대리점 10곳 + 기존 5만 고객사.** 첫 화면이 *"자료 옮겼는데 직원이 없다"* 가 된다.

⇒ **§5 1번 질문은 이미 답이 나왔다: 막으면 안 된다.**
   다만 지금처럼 **NULL 로 방치**하면 결재선이 끊기는 문제는 그대로다. **둘 다 풀어야 한다.**

## 3-2. 🔴 사장님 확정 — **연결은 양방향이어야 정합하다**

> *"계정추가 → 직원등록 도 되야 하지만
>  **역으로 직원등록 → 계정등록도 되야 정합함**"*

```
users(계정) ←──────────→ employees(사원)
                1:1
      양쪽 어디서 시작하든 만나야 한다
```

| 순서 | 언제 쓰이나 |
|---|---|
| **계정 → 직원** | 신규 입사자를 대표계정이 직접 만들 때 |
| **직원 → 계정** | 🔴 **MDB 마이그레이션** · 명부 먼저 받고 계정 나중 |

**한 방향만 허용하면 나머지가 막다른 길이 된다.** 마이그레이션이 정확히 그 길에 걸려 있었다.

### ⇒ 핵심 전환

문제는 *"계정 없는 사원을 허용하느냐"* 가 **아니었다.**
허용하되 — **그게 미완성 상태라는 걸 시스템이 알고 있어야** 한다.

지금 `user_id = NULL` 은 **조용하다. 끊긴 걸 아무도 모른다.**

### 그래서 필요한 것 2개

**① 양쪽에 연결 버튼**
- 직원계정 화면 → `[사원 등록]` (계정 있는데 사원 없을 때)
- 사원관리 화면 → `[계정 발급]` (사원 있는데 계정 없을 때)

**② 끊긴 것을 보여주는 자리**
- *"계정 미발급 12명"* — **마이그레이션 직후 이게 떠야 한다**
- 인사담당자가 보고 하나씩 처리한다

> **김삼성 상무**: *"삼성에서도 인수합병 때 같은 일이 있었습니다.
>  **명부는 먼저 오고 계정은 나중에** 옵니다. 그게 정상입니다.
>  문제는 그 중간 상태를 **시스템이 모르는 척** 하는 겁니다.
>  '계정 미발급 12명' 이라고 띄워주면 인사담당자가 하나씩 처리합니다."*

### ✅ 사장님 결재 — **수동 확정** (자동 생성 금지)

> *"**수동!!!** 결국 직원계정은 **그 계정을 사용하고자 하는 직원이 결정**해야지"*

🔴 **이건 편의 문제가 아니라 원칙이다.**
자동 생성은 **쓸 의사가 없는 사람 몫까지 시스템이 정해버리는 것**이다.

**자동이었으면 따라왔을 문제 3개 — 수동이라 전부 사라진다**

| | 자동 생성 시 | 수동이라서 |
|---|---|---|
| **초기 비밀번호** | 50명분 전달 경로 필요 → 종이·문자 어느 쪽이든 **유출 경로 신설** | 없음 |
| **안 쓰는 계정** | 퇴사자·생산직 계정이 **열린 채 방치** (보안 매니저 반려 사유) | 없음 |
| **약관 동의** | 헌법상 **모든 사용자 첫 로그인 필수 동의**인데, 남이 만든 계정에 **본인이 동의한 적 없는** 상태 | 본인이 받으니 정상 |

⚠️ **약관 항목은 특히 크다** — 동의 일시·IP·약관 버전을 DB 에 기록해야 하는데,
자동 생성분은 **누가 동의했는지 자체가 성립하지 않는다.**

### ⬜ 남은 부담 하나 — 50명이면 50번

**제안(⬜사장님 확인 필요): 일괄이되 자동은 아닌 방식**

사원관리에서 **계정 미발급자 목록**을 띄우고, 대표가 **체크박스로 골라** 한 번에 발급.

```
계정 미발급 12명
 ☑ 김철수  영업부   ← 쓸 사람만 고른다
 ☑ 이영희  경리부
 ☐ 박생산  생산부   ← 계정 안 쓰는 직원은 안 고름
        [선택한 2명 계정 발급]
```

🔴 **"누가 쓸지" 는 여전히 사람이 정한다 — 자동이 아니다.**
다만 12번 화면 왕복할 것을 한 번에 끝낸다. **사장님 원칙을 지키면서 누르는 부담만 없앤다.**

⚠️ 마이그레이션은 **원본이 살아 있는 복사**다(자료 손실 경로 없음).
그러나 **숫자가 안 맞으면 그 자체가 실패**다.

## 4. 재점검 판정 기준 — 13화면 각각에 질문 하나

> **"이 화면이 다루는 사람은 직원계정에서 왔나, 계정 없이도 존재하나?"**

계정 없이 존재할 수 있으면 **거기가 끊기는 자리**다.
⚠️ 근태·휴가·전자근로계약서가 특히 의심 — 사람 단위로 도는데 계정 연결이 안 보인다.

## 5. ⬜ 착수 전 결재 필요 — 4건

| # | 질문 | 상태 |
|---|---|---|
| 1 | ~~계정 없는 사원을 막나~~ | ✅ **닫힘 — 막지 않는다.** MDB 마이그레이션 직원이 전부 못 들어오기 때문(§3-1). 대신 **양방향 연결 + 미발급 표시**로 푼다(§3-2) |
| 1-2 | ~~마이그 직원 계정 자동 생성하나~~ | ✅ **닫힘 — 수동 확정.** *"그 계정을 사용하고자 하는 직원이 결정해야지"*(§3-2). ⬜단 **체크박스 일괄 발급** UI 는 확인 필요 |
| 2 | **결재선 = 직급** 으로 가나 | 상무님 권고. 기존 결재 데이터 처리와 함께 걸린다 |
| 3 | **입사일 → 연차 자동계산** 붙이나 | 법정 기준이라 안 붙이면 **숫자가 틀린다**. 법무팀장 교차 확인 |
| 4 | 메신저 **결재알림 먼저 / 채팅 나중** 순서 | 범위 확정 |
