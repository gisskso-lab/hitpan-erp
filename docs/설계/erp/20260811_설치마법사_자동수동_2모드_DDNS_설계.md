## 0. 사장님 지시 원문

> *"설치마법사 파일도 지금처럼 **터널을 통해 DB, 히트판, 닷넷, 터널 자동 설치**해주는 모드와,
>  **수동설치 모드**로 나눠야해. 수동설치 모드는 터널을 이용하지 않고,
>  **직접 ddns 포트를 열어서** 설치하는 방식이야.
>  자동설치와 수동설치는 설치마법사 옵션에 **라디오 버튼**으로 고객이 선택할 수 있도록 해."*

> *"수동설치 모드시에는 **ddns로 수동포트 열고, 희망도메인 주소 제출해서 도메인 생성하고,
>  수동으로 연 포트에 히트판 설치마법사 통해 제출한 도메인 주소로 연결** 할 수 있는 로직"*

> 🔴 *"3번도 지금껏 우리가 했던 **자동모드 못지않게 탄탄하면서 쉬운 설치로직**을 설계해야 해"*

> *"자동설치가 안되는 **특수환경**에서, **대리점이나 본사에서 원격지원**으로 수동설치를 하게 될거야.
>  그에 대한 **매뉴얼도 CS팀장에게 전달**해서 문서로 꼭 만들어."*

## 1. 왜 필요한가 — 자동이 막히는 자리

지금 자동 설치는 **cloudflared 터널**에 전적으로 기댄다. 그런데 이것이 안 되는 환경이 실재한다.

| 막히는 이유 | 흔한 곳 |
|---|---|
| 회사 방화벽이 터널 트래픽 차단 | 대기업 협력사·관공서 납품업체 |
| 보안 정책상 외부 터널 금지 | 금융·의료 |
| 이미 자체 DDNS·고정IP 운영 중 | IT 담당자가 있는 회사 |
| 터널 발급 실패 반복 | 특수 통신 환경 |

⇒ **지금은 이런 고객에게 팔 수 없다.** 베타 대상이 대리점 10곳 + 5만 고객사라면 반드시 나온다.

## 2. 두 모드 비교

| | **자동 (터널)** | **수동 (DDNS 직접)** |
|---|---|---|
| 외부 연결 | cloudflared 터널 | **공유기 포트포워딩** |
| 주소 | `{고객사ID}.hitpan.kr` | 희망 도메인 (본사 발급) |
| 공인 IP | 불필요 | **필요** (유동IP 도 DDNS 로 가능) |
| 고객 작업 | 라이선스 키 하나 | 🔴 **공유기 설정 필요** |
| 대상 | 대부분의 고객 | 터널이 막힌 특수환경 |
| 설치 주체 | 고객 스스로 | 🔴 **대리점·본사 원격지원** |

🔴 **자동이 기본이다.** 수동은 자동이 안 될 때의 길이지, 동등한 선택지가 아니다.
⇒ 라디오 버튼 기본 선택은 **자동**, 수동에는 *"특수환경 전용"* 을 명시한다.

## 3. 화면 — 라디오 버튼

```
┌────────────────────────────────────────────┐
│  히트판을 어떻게 연결할까요?                  │
│                                            │
│  ⦿ 자동 연결  (권장)                        │
│     설치 프로그램이 알아서 연결합니다.        │
│     대부분 이것을 선택하시면 됩니다.          │
│                                            │
│  ○ 직접 연결  (특수환경 전용)                │
│     회사 방화벽이 자동 연결을 막는 경우에만.   │
│     🔴 공유기 설정이 필요합니다.              │
│     → 본사·대리점 지원을 받으세요             │
│                                            │
│         [ 뒤로 ]      [ 다음 ]              │
└────────────────────────────────────────────┘
```

⚠️ **"터널"·"포트포워딩"·"DDNS" 같은 말을 쓰지 않는다**(헌법 — 고객 노출 개발용어 금지).
고객이 판단할 기준은 *"자동이 안 되나?"* 하나다.

## 4. 수동 모드 흐름 (7단계)

```
① 모드 선택        직접 연결 선택
② 사전 점검        공인 IP 인가 · 포트 열 수 있나  ← 여기서 걸러야 한다
③ 희망 도메인 입력  예: mycompany  →  mycompany.hitpan.kr
④ 본사에 발급 요청  라이선스 키로 인증 → 도메인 + DDNS 계정 발급
⑤ 공유기 설정       🔴 사람이 하는 유일한 단계 (안내 화면 + 원격지원)
⑥ 연결 확인        본사가 그 주소로 실제 접속해 본다  ← 통과해야 다음
⑦ 설치 완료        DB·히트판·닷넷 설치 (자동모드와 동일)
```

### 🔴 ②와 ⑥이 이 설계의 핵심이다

**②를 건너뛰면** 공유기 설정까지 다 하고 나서야 "안 되네" 를 알게 된다.
**⑥을 건너뛰면** 설치는 끝났는데 **밖에서 접속이 안 되는 상태**로 고객을 남긴다.

⇒ *"탄탄하면서 쉬운"* 은 여기서 갈린다. **막힐 것을 미리 알려주고, 됐는지 확인해준다.**

---

## 5. 각 단계 상세

### ② 사전 점검 — 시작 전에 거른다

설치 프로그램이 자동으로 검사한다:

| 검사 | 실패 시 |
|---|---|
| 공인 IP 인가 (본사에 물어본다) | 🔴 *"인터넷 회선이 이 방식을 지원하지 않습니다"* → 자동 모드 권유 |
| 통신사 차단 여부 (80/443) | 대체 포트 안내 |
| 공유기 UPnP 지원 | 지원 시 **⑤를 자동화**할 수 있다 |

🟢 **UPnP 가 되면 공유기 설정도 자동으로 시도한다.** 그러면 수동 모드도 자동에 가까워진다.
⚠️ 단 UPnP 는 보안상 꺼둔 회사가 많다. 되면 좋고, 안 되면 ⑤로 간다.

### ③④ 도메인 발급

```
고객 입력:  mycompany
      ↓
본사 확인:  중복 아닌가 · 금지어 아닌가 · 라이선스 키가 유효한가
      ↓
발급:      mycompany.hitpan.kr  →  고객 공인 IP
           + DDNS 갱신 계정 (유동IP 대응)
```

🔴 **본사 Cloudflare API 토큰은 EXE 에 절대 없다**(헌법 · 기존 원칙).
설치 프로그램은 **본사 서버에 요청만** 하고, DNS 레코드는 본사가 만든다.

⚠️ **유동 IP 대응**: 대부분의 인터넷 회선은 IP 가 바뀐다. 워치독이 주기적으로
현재 IP 를 본사에 알려 DNS 를 갱신한다. 이게 없으면 **며칠 뒤 접속이 끊긴다.**

### ⑤ 공유기 설정 — 사람이 하는 단계

```
공유기 관리 화면 → 포트포워딩 →
   외부 443  →  이 컴퓨터 IP : 5257
```

🔴 **공유기 모델마다 화면이 다르다.** 이걸 글로만 설명하면 현장에서 막힌다.

**대응**
- 주요 공유기(iptime·넷기어·ASUS·통신사 제공)별 **그림 안내**
- 그래도 안 되면 **원격지원** (§7)
- 🟢 UPnP 되면 이 단계 자동 시도

### ⑥ 연결 확인 — 설치를 끝내기 전에

```
설치 프로그램 → 본사에 "이 주소로 접속해봐 주세요" 요청
본사 서버 → mycompany.hitpan.kr 로 실제 HTTP 요청
      ↓
   성공 → ⑦ 진행
   실패 → 🔴 무엇이 문제인지 알려준다 (포트? DNS? 방화벽?)
```

⚠️ **자기가 자기를 확인하면 안 된다.** 그 PC 안에서는 되는데 밖에서 안 되는 경우가
바로 이 방식의 가장 흔한 실패다. **반드시 밖(본사)에서 들어와 봐야 한다.**

## 6. 🔴 보안 — 자동보다 위험하다

터널은 **들어오는 포트를 열지 않는다**. 수동은 **문을 하나 여는 것**이다.

| 위험 | 대응 |
|---|---|
| 열린 포트가 공격 대상 | **HTTPS 필수**(인증서 자동 발급) · 관리 화면은 로컬만 |
| 무차별 로그인 시도 | 실패 횟수 제한 · 차단 |
| 공유기 관리 화면 노출 | 점검 항목에 포함 — 열려 있으면 경고 |
| 고객이 포트를 잘못 열음 | ⑥에서 **의도한 포트만** 열렸는지 확인 |

🔴 **보안상무 결재 필요.** 이건 고객 PC 에 외부 접점을 만드는 일이다.

## 7. CS 매뉴얼 (사장님 지시 — 별도 문서)

> *"대리점이나 본사에서 **원격지원으로 수동설치**를 하게 될거야. 그에 대한 매뉴얼도"*

📄 **작성 예정**: `docs/CS/{날짜}_CS매뉴얼_수동설치_원격지원.md`

**담아야 할 것**
- 자동/수동 **판정 기준** — 언제 수동으로 넘어가나
- 공유기 모델별 포트포워딩 **그림 안내**
- 실패 유형별 대처 (포트 안 열림 · DNS 전파 대기 · 통신사 차단)
- 🔴 **원격지원 중 절대 금지** — 고객 공유기 비밀번호를 받아 적지 않는다
- 에스컬레이션 기준

⚠️ CS 체계 3축(매뉴얼·교육·워크스페이스) 중 **교육**도 함께 필요하다.
대리점 사장이 공유기를 만져야 하는 일이라, 문서만으로는 부족하다.
