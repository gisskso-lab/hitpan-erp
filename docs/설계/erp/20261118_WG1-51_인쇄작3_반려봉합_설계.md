### §1-2 시험 차림 (CI 시험 테넌트 1 · 갈래 Z 가 만든다)
- 로고 1장(회사정보 화면으로 올림) · 양식용지 그림 1장(눈에 띄는 무늬 · 바이트 해시를 시험이 안다).
- **견적서 양식은 화면으로 만든다** — 대표 경로 그대로: 양식정보설정 → 새 견적서 양식 → 빈 A4(`plain`) → 그림 올림 → 칸 위치 맞춤 → 저장. 나머지 5종(거래명세서 `delivery` · 수주서 `sales_order` · 발주서 `purchase_order` · 매입처리 `purchase_receipt` · 반품처리 `purchase_return`)은 **같은 화면이 부르는 저장 문**으로 만든다(차림 시간 · 확인 필요 Q3).
- 칸마다 **표지 값**을 고른다: 견본·전표 값이 **그 칸 상자 안**에 떨어지는지 보려고, 칸 좌표(mm)를 시험이 안다.
- 화면별 전표 1건(거래처·품목 2줄) — 화면으로 저장. 저장 안 한 전표는 미리보기가 막힌다(`DocumentController.cs:839`).
- 워터마크: 켠 양식 A · 끈 양식 B(같은 종 · 같은 전표) — 켬/끔 **차이**로 판독한다.

### §1-3 판독 — 「된다 / 안 된다」
판독기는 미리보기 응답 PDF 바이트를 잡아(화면이 받는 그 응답) 읽는다. 읽는 도구 = 시험 프로젝트에 이미 있는 PdfPig(`src/HitPan.Tests/HitPan.Tests.csproj:20`) — 새 외부 의존 0이 기본안(확인 필요 Q4).

| 원문 | 「된다」 (전부 참이어야) | 「안 된다」 (하나라도) |
|---|---|---|
| ① | 양식 A 의 쪽에 로고 겹이 있다(그림/벡터 객체 1개 이상 · 쪽 가운데 · 투명도 상태 있음) **그리고** 양식 B 같은 전표에는 없다 · 설정 미리보기와 전표 미리보기 **둘 다** | A 에 없음 · 또는 B 에도 있음 · 또는 한 길만 있음 |
| ② | 양식정보설정 미리보기에서 **맞춘 칸 전부**에 견본 값 글자가 칸 상자(±2mm) 안 · 자리표 글자(`{` 류 · 빈 칸) 0 · 표준 품목표 머리(`품명`·`수량`·`공급가액` — `PdfRenderService.cs:342~346`)가 칸 밖에 0 | 칸 하나라도 비었거나 상자 밖 · 또는 표준 표가 겹쳐 찍힘 |
| ③ | 6화면 **각각**: ⓐ 그 종 양식의 그림 해시가 쪽에 있다(`print_background` 를 고객이 켠 경우) ⓑ 전표 값이 칸 상자 안 ⓒ 표준 머리·품목표 글자가 칸 밖에 0 ⓓ 미리보기 창에 주황 경고 0(R-2 꼴) | 한 화면이라도 기본 폼(표준 머리·표) · 그림 없음 · 값 칸 밖 · 경고 뜸 |

- **대조군**: 같은 차림·같은 판독을 main `19518b03` 위에서 먼저 돌린다(갈래 Z). 기대 = ②③ 빨강. **main 에서 초록이 나온 항목은 그 측정이 대표의 실패를 못 잡는다는 뜻** → 그 항목은 「고침 0」 으로 넘기지 않고 멈춰 PM 보고 · 측정 재설계(진단도 실측 전엔 가설).
- ① 의 대조군 주의: 로고를 제대로 올린 main 은 **초록일 수 있다**(작2 [1-V] §1 — 판정 코드는 돌고 재료가 없었다). 그래서 ① 은 두 경우를 잰다 — (가) 로고 있음 + 켬 → 찍힘 (나) 로고 없음 + 켬 → 대표가 켜는 자리·미리보기 자리에서 「로고가 없어 안 찍힌다」 를 본다. (가) 가 main 에서 초록이면 대표 실패 자리는 (나)이고, (나) 의 「된다」 정의는 **대표 확인 전 확정하지 않는다**(Q1).
