## 2. 현행법 근거 (조문 번호)

### 2-1. 무엇이 개인정보인가

| 법령 | 조문 | 내용 |
|---|---|---|
| 개인정보보호법 | **제2조 제1호** | 개인정보 = "**살아 있는 개인**에 관한 정보" — 주체는 **자연인** |
| 〃 | (해석) | **법인·단체의 상호·소재지·영업실적은 개인정보 아님.** 개인사업자의 상호·사업장주소·사업자등록번호도 **사업체 운영 정보로서 원칙적으로 개인정보 아님** |

⭐ **히트판 적용**: 수집 항목 중 **개인정보는 대표자명·담당자 연락처 두 개뿐**이다.
⇒ 암호화·동의 UI 를 **그 두 필드로 좁힐 수 있다** (사장님 *"타이트하지 않게"* 방향과 일치).

### 2-2. 보유기간 — 🔴 5년이 강제된다

| 법령 | 조문 | 기간 |
|---|---|---|
| **국세기본법** | **제85조의3 제2항** | 장부·증거서류 **5년** (역외거래 7년) |
| **부가가치세법** | **제71조** | 세금계산서·영수증 **5년** |
| **전자상거래법 시행령** | **제6조** | 계약·청약철회 **5년** / 대금결제·재화공급 **5년** / 소비자 불만·분쟁 **3년** / 표시·광고 6개월 |
| 전자상거래법 | (제재) | 미보존 시 과태료 최대 **500만원** |

🔴 **현행 `privacy.html:68` = "회원 탈퇴 후 즉시 파기" → 법정 보존의무와 충돌. 정정 필수.**
이카운트는 4개 법령 5년을 방침에 명시하고 있다 (스탠다드).

⭐ **부가세법 제71조 단서** — 전자세금계산서 발급명세를 **국세청에 전송하면 별도 보존의무 없음**.
⇒ 세금계산서 원본을 자체 보관할 법적 이유가 없다. **데이터 최소주의(#22)와 법이 일치.**

### 2-3. 위탁·국외이전 (OCR 도입 시)

| 법령 | 조문 | 내용 |
|---|---|---|
| 개인정보보호법 | **제26조** | 처리위탁 시 **문서 작성 의무** (목적 외 처리금지·안전조치·감독) |
| 〃 | **제28조의8** | 국외이전 — 원칙 동의. **단 계약 이행 목적 위탁·보관은 처리방침 공개로 갈음 가능**, 제32조의2 인증(ISMS-P)+안전조치 시 별도 동의 불요 |

⇒ **국내 리전 + 위탁 처리**면 별도 동의 없이 처리방침 공개로 갈음 가능.
⚠️ 네이버 클로바 OCR 의 **사업자등록증 모델은 사전 신청·승인 대상**이다.

### 2-4. 국세청 진위확인 API

| 항목 | 내용 |
|---|---|
| 출처 | 공공데이터포털 **15081808** |
| 진위확인 | 사업자등록번호 + **대표자명 + 개업일자** 입력 |
| 상태조회 | 번호만으로 휴업·폐업·과세유형·폐업일자 |
| 비용·한도 | **무료** · 1회 100건 / 1일 100만건 · 30분 주기 갱신 |

🔴 **주의 — 이 API 단독으로는 무단사용을 막지 못한다.**
사업자번호는 **공개정보**(세금계산서·명함·홈페이지)이므로, 번호만 검증하면 **남의 번호로 가입 가능**하다.

⭐ **사장님 설계는 2중 관문이다** (8/10):

| 관문 | 시점 | 수단 | 막는 것 |
|---|---|---|---|
| ① | **가입 때** | 국세청 진위확인 API | 실재하지 않는 사업자 |
| ② | **설치 후** | 기본사업장정보 **OCR 잠금** | 가입 후 **딴 회사로 바꿔치기** |

⇒ 두 검증은 **경쟁이 아니라 직렬**이다. ①만 있으면 정상 가입 후 ERP 안에서 회사정보를 바꿔
다른 사업장에서 쓸 수 있다. **API 는 1관문으로 유효하고, 등록증 OCR 이 2관문이다.**
(설계팀이 두 관문을 택일 관계로 오판했다 — PRD §9-1)
