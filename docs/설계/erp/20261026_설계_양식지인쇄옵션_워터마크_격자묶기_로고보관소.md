## §3 🔴 실측표 — 이 설계의 전제 (2026-10-26 직접 측정)

> [1-V] 가 *"설계의 첫 할 일"* 로 넘긴 축을 전부 실측했다. **가설 0건.**
> 측정 도구 = `scratchpad/opacityprobe` (QuestPDF 2026.2.4 실물 · PDF→PNG 래스터 후 **픽셀값 판독**)

| 축 | 물음 | 실측값 | 판정 |
|---|---|---|---|
| ⓐ | `.Opacity()` 가 공개돼 있나 | 컴파일 **CS1061** · `QuestPDF.xml` 에 `Opacity` 심볼 **0건** | 🔴 **없다** |
| ⓑ | `<image opacity='0.12'>` 가 통하나 | 중앙픽셀 **R=255 G=0 B=0** (대조군과 **동일**) | 🔴🪤 **무시된다** |
| ⓒ | `<g opacity='0.12'>` 로 감싸면 | 중앙픽셀 **R=255 G=223 B=223** (기대 224.4) | 🟢 **통한다** |
| ⓓ | `<rect opacity>` (렌더러 자체 지원) | **R=255 G=224 B=224** | 🟢 통한다 |
| ⓔ | 채도 `feColorMatrix saturate='0.15'` | 빨강 → **R=156 G=118 B=118** | 🟢 **통한다** — 명도·채도 **둘 다** 제어 가능 |
| ⓕ | 3겹(양식지그림+워터마크+본문) 동시 | 모서리 **순수 파랑(0,0,255)** · 중앙 **(31,0,223)** · 본문글자 살아 있음 | 🟢 **셋이 서로 안 잡아먹는다** |
| ⓖ | 깨진 바이트를 data URI 에 넣으면 | **예외 0건 · 흰 종이** | 🟢 **안전** — 10/24 P0 와 **정반대** |
| ⓗ | SVG 문자열이 쓰레기면 | 🔴 **예외** `Cannot decode the provided SVG image.` | 🔴 **울타리 필요** |
| ⓘ | 새 NuGet 패키지가 필요한가 | SkiaSharp·ImageSharp 참조 **0건**이어도 전부 됨 | 🟢 **패키지 추가 0건** |
| ⓙ | 격자가 왜 안 꺼지나 | `CellHead`/`CellBody` 가 **`static` 지역함수** → `showBorder` 를 **캡처할 수 없다**. 같은 메서드 `:259` 에 `borderWidth` 가 **이미 계산돼 있고 쓰이지 않는다** | 🟢 봉합이 작다 |
| ⓚ | 올바른 본이 코드에 있나 | `PayslipCell(c, showBorder)` `:2350` 이 **정답 모양** | 🟢 **베낄 본이 있다** |
| ⓛ | 로고·직인 DB 칸 | `local_company.logo_url`·`seal_url`·`header_url` **실재** · `SettingsService:419` 저장 배선 **실재** | 🔴 **없는 건 「파일 받는 통로」뿐** |
| ⓜ | 반사·호출처 개수 | `ResolveFormBackground` **6곳** · `TryLoadFormBackground` **9곳** | 🔴 **인자 추가 금지** |
| ⓝ | 마이그 최대 번호 | `DB-147_form_templates_tear_line.sql` | 다음 = **DB-148** |
| ⓞ | `TryLoadSealImage` `:2134` | `File.Exists` → `File.ReadAllBytes` **가 전부** · 울타리 **0개** · 사전 디코드 **0건** | 🔴 **P0 — 보관소가 생기는 날 터진다** |

### 🪤 축ⓑ 가 이 설계의 가장 큰 함정이다

`<image opacity='0.12'>` 는 **아무 경고 없이 무시된다.** 코드만 읽으면 `opacity` 가 적혀 있으니 **통과로 보이고**, 고객 종이에는 **진한 로고가 그대로 찍힌다.**
⇒ 🔴 **게이트는 「`opacity` 라는 낱말이 있나」를 세면 안 된다. 픽셀값으로 재야 한다.** (§7)

## §4 설계 결정

### §4-1 축이 세 개다 — 곱해진다

| 축 | 칸 | 뜻 | 기존과의 관계 |
|---|---|---|---|
| ① **종이 종류** | `paper_mode` (기존) | `plain` 순백지 / `preprint` 양식용지 **구입** | 그대로 |
| ② **그림을 종이에 찍나** | `print_background` 🆕 | 0 = 안 찍는다(기본) / 1 = 찍는다 | 🔴 **새 축** — ① 과 곱해진다 |
| ③ **워터마크** | `show_watermark` 🆕 + 수치 3개 | 로고를 정중앙에 연하게 | 🔴 **새 축** |

🔴 **[1-V] 지적대로 ① 로는 ② 를 구분할 수 없다.** 양식용지를 **사다 쓰는** 고객(`preprint`)은 그림을 **안 찍어야** 하고, 양식지를 **그림으로 받아** 순백지에 찍는 고객(`plain` + `print_background=1`)은 **찍어야** 한다. 같은 칸으로는 둘을 못 가른다.

### §4-2 「공통 + 양식마다」를 어떻게 — 결-I

- **공통**: 새 테이블 `print_common_settings` (tenant_id PK) — 테넌트 한 벌
- **양식마다**: `form_templates` 의 수치 칸은 **NULL 허용**. NULL = **공통값을 따른다**. 값이 있으면 그 양식만 덮는다.
- 🔴 **고객 선택 옵션**이므로 화면에 「공통값 따름 / 이 양식만 따로」 선택이 **있어야 한다.** 값만 늘어놓으면 「공통을 따른다」가 사라진다 (10/25 함정 2).

### §4-3 수치는 개발팀이 정하지 않는다 (반자동 원칙)

DDL 의 DEFAULT 는 **제안값**이고, 화면에서 고칠 수 있어야 한다. 아래는 **제안값**이다 — 사장님·고객이 바꾼다.

| 수치 | 제안값 | 근거 |
|---|---|---|
| 명도 `watermark_opacity` | **0.12** | 실측 ⓒ 에서 (255,223,223) — 글자 가독성을 해치지 않는 자리 |
| 채도 `watermark_saturate` | **0.15** | 실측 ⓔ — 색이 옅은 회색에 가까워져 본문과 안 다툼 |
| 크기 `watermark_scale_pct` | **60** (용지 폭의 60%) | *"정중앙 크게"* · 여백을 침범하지 않는 선 |

### §4-4 워터마크를 어떻게 그리나 — 실측 ⓒ·ⓔ·ⓕ 위에

```
page.Content().Layers(l =>
{
    l.Layer()        -> 양식지 그림   (print_background=1 또는 설계 미리보기일 때만)
    l.Layer()        -> 워터마크       (show_watermark=1 · 정중앙 · 폭 scale_pct%)
    l.PrimaryLayer() -> 본문          (지금 그대로)
});
```

워터마크 한 겹은 **SVG 문자열**이다 — 패키지 0건으로 명도·채도를 둘 다 제어한다:

```
<svg ...><defs><filter id='s'><feColorMatrix type='saturate' values='{채도}'/></filter></defs>
  <g opacity='{명도}' filter='url(#s)'>
    <image width='..' height='..' xlink:href='data:image/{형식};base64,{로고}'/>
  </g></svg>
```

🔴 **`opacity` 는 반드시 `<g>` 에 건다. `<image>` 에 걸면 실측 ⓑ 로 무시된다.**

### §4-5 반사 경고 대응 — 인자를 더하지 않는다 (축ⓜ)

[1-V] 경고: `ResolveFormBackground` 에 인자를 더하면 **6곳**, `TryLoadFormBackground` 는 **9곳**이 깨진다. 10/25 작2 의 **157→265** 와 같은 모양이다.

⇒ **시그니처를 건드리지 않는다.**
- `ResolveFormBackground(overrides, template)` — 인자 **그대로**. 안에서 조건만 넓힌다:
  `overrides?.IsFormDesignPreview == true` **또는** `template?.PrintBackground == true`
- 워터마크는 **새 메서드** `TryBuildWatermarkSvg(...)` 로 **따로** 짓는다. 기존 함수에 얹지 않는다.

### §4-6 격자 묶기 — 결-G (축ⓙ·ⓚ)

`CellHead`/`CellBody` 의 `static` 을 떼고, **같은 메서드에 이미 있는** `borderWidth`(`:259`)를 쓴다. `PayslipCell`(`:2350`)이 본이다.
🔴 결재: *"묶은 뒤 실 문서 크기는 용지에 맞춰 임의 조정"* — 격자를 끄면 테두리 두께가 0이 되어 표가 좁아진다. 패딩으로 보정한다.

### §4-7 로고 보관소 — 결-H (축ⓛ·ⓞ)

- `CompanyImageStore` 신설 — `FormBackgroundStore` 의 **울타리 7개를 본 그대로** 쓴다(새로 설계하지 않는다).
- 업로드 입구 = 로고·직인·헤더 **3종**. 저장 후 경로를 `local_company.logo_url`/`seal_url`/`header_url` 에 적는다.

- 워터마크는 **모든 양식**에 걸린다 ⇒ 한 군데 터지면 **전표 인쇄·이메일·팩스 전부**가 멈춘다 (#20 워크플로우 흐름은 절대 안 끊긴다).
- 그래서 **G-W6**(깨진 그림에도 500 0건)이 이 차수의 **절대 게이트**다.
- 🔴 **종이 0회가 열 차수 연속**이다. 이 차수는 사장님께 **프린터 실인쇄**를 요청드린다 — 미리보기로는 축 ② 를 영영 못 잰다.
