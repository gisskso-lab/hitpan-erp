**경주 두 꼴**
- **A(끄기 먼저 커밋)** — 주기 F1 읽기(켬) → 저장 F5 커밋(물음·미룸 NULL) → 주기 ② 놓침 SELECT · DELETE 둘 다 참(놓침 후보는 원래 NULL·NULL 이라 비우기가 막지 못함) → 세션 삭제 · 토큰 폐기 · 근태 기록. 또는 ③ 묻기 UPDATE 참 → 꺼진 회사에 물음이 써지고 팝업이 뜸 → 사용자가 [지금 로그아웃] 을 누르면 API 끝내기(물음 65초 안)가 삭제.
- **B(저장이 거래 중)** — 주기가 설정을 잠금 없이 읽은 뒤 세션 행 잠금을 기다리는 사이 저장이 커밋하면, 세션 행을 얻는 순간 최신 행은 놓침 guard 참 → A 와 같은 결과. ⇒ **일반 SELECT 재확인으로는 B 가 남는다**(공유 잠금이 필요한 까닭).

## §5 [시각 바꾸기] 포함 — 같은 경주

- 켜진 채 `cooltime_at` 만 바뀌면 저장은 물음·미룸을 **비우지 않는다**(:360 `wasEnabled != Enabled` 거짓). 오래된 주기는 옛 `C` 로 ② 놓침 삭제(근태 기준 순간도 옛 `C` · :319–323) · ③ 물음 쓰기가 가능 ⇒ 끄기보다 넓게 열림.
- 저장 뒤 새 주기는 E-2 건너뛰기(:138)로 첫 `C` 를 막는다 — 열린 것은 「이미 시작한 주기」 뿐 = HQA 와 같은 자리. **같이 막는다**(비교 칸에 `cooltime_at` · `changed_at` 이 있으므로 추가 비용 0).
- ① 무응답(시각 바꿈 뒤 오래된 주기)도 비교 불일치로 이번 바퀴는 물러나고, 다음 바퀴(새 값)가 E-2 설계대로 「떠 있던 물음의 무응답」 을 끝낸다 = **최대 한 바퀴 늦음 · 최종 결과 같음**(G-C25 ⓖ 로 잼).
