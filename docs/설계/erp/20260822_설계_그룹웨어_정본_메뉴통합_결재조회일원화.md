## 4. 🔧 축을 세우려면 필요한 것 (수단)

> 🔴 아래는 **목적이 아니라 축을 세우는 데 필요해서 나온 것**이다.

### 4-1. 결재선 2중화 — **가장 무거운 수단**

**실측**: 결재 엔진이 `approval_line_steps` 를 **한 번도 안 읽는다**(참조 0건).

```
approval_lines / approval_line_steps   직책·단계로 짠 선   ← 화면에서 만든다
                                        ✖ 안 이어짐
approval_doc_lines                      doc_type 전역 1행  ← 결재는 이것만 본다
```

⇒ 직책으로 짜도 실제 결재는 **사람 고정 1행**으로 돈다 ⇒ **사람이 바뀌면 선이 죽는다.**
🔴 **1번에 결재를 모으는 만큼 이 구멍이 더 아파진다**(상무: *"모아놓으면 한 사람 퇴사에 결재함 전체가 선다"*).

**할 일** — 상신 시점에 `approval_line_steps` 를 읽어 `approval_doc_lines` 로 펼친다.
🟢 **엔진 무변경 · 표 신설 0건.**

### 4-2. 사장 직권 🔴 신규

> 상무 인정: *"오늘 사장님 말 중 **제일 값어치 있다.** 내가 8/21에 '최우선' 이라 해놓고
> **답을 못 냈던 자리**다. 나는 교과서만 읊었지 **한국 중소기업이 실제로 뭘 하는지**는 못 말했다."*

| 항목 | 확정 |
|---|---|
| 발동 | 🔴 **반자동** — 자동 판정 없음. 시스템은 **묻기만** |
| 공석 사유 | **휴가 · 퇴사 · 휴직**(버튼 띄우는 근거이지 자동조건 아님) |
| 흔적 | `is_delegated=1` + `original_approver_id` + `comment="부장공석 — 직권결재"` ⇒ **DDL 0건** |
| 권한 | `APPROVAL_OVERRIDE` · 기본 OFF · **부모계정이 준다** |
| 묻는 곳 | 🟢 **기존 자리** — `Dashboard.razor:216`(5/26 브리핑팝업) · `ChatPage.razor:166`(결재봇 딱지) |
| 문구 | *"결재자가 00중입니다. 변경하시겠습니까? 유지하시겠습니까?"* |
| **[Y]** | 🔴 **`/settings/approval` 로 링크이동**(결재자·위임결재자 칸 **이미 있음** `:99`·`:101`·`:109`) |
| **[N]** | **상태유지** · 다음 로그인에 다시 묻는다(#43 정신) |

🔴 **[Y] 는 그 자리 결재가 아니다** — PM 초안 정정. 한 건만 넘기면 **다음 문서도 또 막힌다.**
   결재자를 바꾸면 **뒤에 밀린 것까지 한 번에** 풀린다.

### 4-3. 전결 🔴 신규
