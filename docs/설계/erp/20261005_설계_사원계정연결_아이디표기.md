## §2 [보기] 계정 상태 · 사원계정 칸

### §2-1 상태 판정 — `EmployeeService.GetListAsync`(:54-110)에 **칸 더하기**
- 기존 `LEFT JOIN users u … AND u.is_active = 1`(:94-98)과 `HasUserAccount`(:89)는 **그대로 둔다**(#1). 읽는 곳 = `HrEmployeesPage.razor:40·93` · `HrAttendancePage.razor:161` · (별도 쿼리 :904 → `EmployeeResignDialog:42`). 바꾸면 그 셋의 뜻이 바뀐다.
- 두 번째 조인 `LEFT JOIN users ua ON ua.user_id = e.user_id AND ua.tenant_id = e.tenant_id`(활성 거르지 않음) 추가 → 새 칸:
```
CASE WHEN ua.user_id IS NULL OR ua.is_deleted = 1 THEN 'none'
     WHEN ua.is_parent = 1 THEN 'owner'
     WHEN ua.is_active = 1 THEN 'active'
     ELSE 'suspended' END AS AccountStatus,
CASE WHEN e.is_active = 0 OR e.is_resigned = 1 THEN 1 ELSE 0 END AS IsLeaver,
e.login_id AS LoginId
```
- DTO 2곳(`Application/DTOs/Employee/EmployeeDtos.cs:18` 줄 근처 · `Web/Models/EmployeeModels.cs:18`)에 `AccountStatus`·`IsLeaver`·`LoginId` 추가 — **#12: 두 DTO 동시 · 상세 DTO(:225·:289)는 [3] 이 같은 칸이 필요한지 판단**.

## §3 [만들기] 사원관리 [계정 만들기] — 그 사원에 연결

- **새 API** `POST /api/users/for-employee` `{ employeeId, loginId, password, userName? }` — `UserController`(기존 메서드 무접촉 · 추가만). 인가 = §5 단계 ≥2.
- **새 서비스** `UserService.CreateForEmployeeAsync(employeeId, dto, tenantId)` — 순서 고정:
  1. `ValidatePassword` · 아이디 중복(:103-128 과 같은 두 검사 · 문구는 「아이디」 §6).
  2. `BeginTransaction` → **첫 문장** `AccountSeatGuard.AcquireAsync` → `EnsureSeatAsync(…,1)`(A · 작3 규칙 그대로).
  3. `SELECT employee_id, user_id, is_active, is_resigned, emp_name, position, role FROM employees WHERE tenant_id=@T AND employee_id=@E FOR UPDATE` — 없으면 404.
  4. 퇴사(C-1)면 409 「퇴사한 사원은 계정을 만들 수 없습니다.」(B).
  5. `user_id` 가 있으면 그 users 행 확인: `is_deleted=0` 이면 409 「이미 계정이 있는 사원입니다. 직원 계정 관리에서 확인하세요.」(사용중지 포함 · F-2 차단). `is_deleted=1` 또는 행 없음 = 죽은 연결(C-4) ⇒ 덮어쓴다.
  6. `INSERT INTO users`(:156-171 과 같은 칸 · `emp_name`·`position` 은 사원 값 · role = §5-3).
  7. `UPDATE employees SET user_id=@New, login_id=@LoginId, updated_at=NOW(6) WHERE tenant_id=@T AND employee_id=@E AND (user_id IS NULL OR user_id='' OR user_id=@DeadId)` — `affected=0` ⇒ 409(두 창 경쟁 · C-3). UNIQUE 위반(1062)도 같은 409 문구로.
  8. Commit · 감사로그 `create user {"employee_id":…}`.
- **사원 행은 INSERT 0**(쌍둥이 차단 · D 와 같은 함수).
- 한도 409(`AccountSeatLimitException`) → 화면이 `Components/Users/AccountSeatNoticeDialog.razor`(`Blocked=true`)를 그대로 연다. 문구 「계정을 추가 구매하세요」 + [구독계정추가] 안내(A). 단계 3 없는 사람의 버튼 노출 = **P-5**.

| 2 계정설정 | `USERS_ACCOUNT`(신규) | 계정설정 | 사원 계정 만들기(§3·§4) · 사용 안 함 · 다시 사용 |

- 판정 함수 `PermissionService.GetUsersLevelAsync(userId)`: tenant_admin(Layer 0 · :248-254 와 같은 조건) ⇒ 3 · 아니면 `SELECT MAX(level)` 식으로 `USERS_SEAT can_view=1 ⇒ 3 · USERS_ACCOUNT ⇒ 2 · USERS ⇒ 1 · 없음 0`. **아래 단계 행이 없어도 위가 포함**(판정이 보장 · 저장이 어긋나도 안전).

- **CI 「권한 메뉴 코드 정합」**: 백엔드 `PermissionService.MenuList`(:58 근처) + 프론트 `PermissionPage.razor.cs` `ErpMenus`(:64 근처)에 두 코드 동시 추가 · `EnforcedMenus`(:88-96)에 추가(서버가 실제로 강제하는 것만 — §5-2 가 강제한다 · 3단계는 P-2).

### §5-3 2단계의 울타리 (P-4)
- 호출자가 tenant_admin 이 아니면: 만드는 계정 role = **일반(User · `tenant_user`) 고정**(요청 role 무시) · suspend/resume 대상이 `is_parent=1` · `account_type='tenant_admin'` · **본인**이면 403. 대표 보호 `RejectParentAsync`·`UpdateAsync:278-285`(G-S1b) 그대로.
- 이유: 2단계가 관리자 계정을 만들면 Layer 0(전권)으로 한 번에 올라간다 = 권한설정 우회.
