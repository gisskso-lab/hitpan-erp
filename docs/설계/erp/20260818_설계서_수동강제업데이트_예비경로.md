## 0. 왜 이 길이 필요한가 — 오늘의 사고

1.2.84 에서 로그인 화면이 무한 반복에 빠졌다. 봉합은 1.2.85 에 실려 게시됐다.
그런데 **그 봉합을 받으려면 팝업이 떠야 하고, 팝업은 화면이 정상이어야 뜬다.**

🔴 **화면이 죽으면 고치는 것을 보낼 길이 통째로 막힌다.**

`project_fixed_vs_delivered_gap` 이 기록한 **닭과 달걀 패턴의 5차 재발**이다.
1·2차=커밋~main, 3차=main~서버, 4차=서버~설치본, **5차=설치본~화면**.
매번 코드는 정상이었고, 끊긴 것은 **전달 경로**였다.

### 🔴 사장님이 정의한 이 문제의 성격 (결재 2)

> *"수동 업데이트, 강제복구는 **항상** 열어둬야됨. 안그러면 **CS쪽에서 사고남.**"*

⇒ 목적은 **업데이트 편의가 아니라 CS 사고 방지**다.
**조건부로 만들면 그 조건에 걸리는 날 CS 가 손을 못 쓴다.** 그것이 곧 사고다.

## 1. 🔴 실측이 뒤집은 것

> 헌법 #32·#33 에 따라 판단을 받아쓰지 않고 코드로 확인했다.

### 1-1. 「워치독 EXE 인자」 — 근거는 맞고, **적용 방식이 틀렸다**

**맞은 것**: 서비스 등록에 인자가 없다 — `installer/scripts/InstallWatchdog.ps1:58`
`sc.exe create` 의 `binPath` 에 인자가 하나도 없다 ⇒ **서비스는 언제나 인자 없이 뜬다.**
인자를 주려면 사람이 EXE 를 따로 실행해야 하고, 그것은 **두 번째 프로세스**다.
전례: `src/HitPan.Watchdog/Program.cs:8-11` 의 `--health` (호스트 세우기 **전** 분기, 서비스 등록 없음).

**🔴 틀린 것**: 그 두 번째 프로세스가 **업데이트를 직접 실행하면 안 된다.**

| 반증 질문 | 실측 답 | 근거 |
|---|---|---|
| 이미 도는 서비스와 충돌하나? | 🔴 **막을 것이 없다** | 아래 |
| 중복 실행 방지 장치가 있나? | 🔴 **0건** | `grep -rn "Mutex" src/HitPan.Watchdog/` = 0건 |
| `update.lock` 이 막아주나? | 🔴 **아니다** | `UpdateOrchestrator.cs:194` 는 **쓰기만** 한다. 적용 전 **읽는 코드가 없다** |

`UpdateLockFile` 은 자기 주석(`UpdateLockFile.cs:8-13`)대로 **keepalive 자가점검용 표식**이지
상호배제 잠금이 아니다(TTL 15분 `:37`, 실패해도 예외 안 던짐 `:72-77`).

⇒ 🔴 동시 진입 시 **롤백 원본이 파괴**될 수 있고, `:816` 은 그것을 **롤백 불가**로 판정한다.

### 1-2. 🟢 설계 중심축 — 「**동의만** 넣고 종료」 (결재 후에도 유지)

`scripts/force-update.ps1:20` 이 이미 옳은 답을 하고 있었다:
> *"이 도구는 업데이트를 대신 하지 않는다. 동의만 대신 넣는다."*

```
[CS] 명령 한 줄
       │  ① 게시원 manifest 조회 → 그 버전이 실재하는지 확인
       │  ② local_update_consents 에 approve 한 줄 INSERT   ← 여기서 끝. 프로세스 종료
       ▼
[서비스] 이미 도는 워치독이 다음 루프(60초)에 읽는다
       → ConsumeConsentForMajorAsync (Worker.cs:600)
       → ApplyUpdateAsync (백업→차단→교체→재기동→검증→롤백)
```

**적용은 언제나 서비스 프로세스 하나뿐이다.** 동시 진입이 성립하지 않는다.
⇒ **동시성 문제를 푸는 게 아니라 만들지 않는다.**

### 1-3. 🔴 동의만으로는 **안 걸리는 경우가 있다**

`Worker.cs:387` — 동의 조회는 `_pendingConsentUpdate` 가 **있을 때만** 돈다.
그 필드는 **인메모리**(`:96`)이며 Major 를 발견해야 채워진다(`:563`).

⇒ 두 경우 수동 동의가 **영영 소비되지 않는다**:
- **(a)** 워치독 재시작으로 펜딩이 날아갔고 확인 게이트가 아직 안 열렸을 때
- **(b)** 이미 그 버전을 시도해 `_consentAppliedVersions` 에 들어갔을 때 (`:603-608` — 펜딩만 비우고 **끝**)

🔴 **(b) 가 오늘 상황과 정확히 겹친다.** ⇒ §B 에서 닫는다.

## 2. 설계 — 무엇을 만드나 (**결재 반영**)

### 🔴 §A. 대상은 **CS 담당자**다 — 화면 없음, 명령줄이 정본 (결재 1)

> 사장님: *"수동조치라면, **파워쉘이나 CMD에서 명령어로 CS적 조치가 가능해야 된다는 의미**"*

**⇒ 1차 설계에서 폐기**: ❌ 고객용 바탕화면 바로가기 ❌ 고객 배려용 안내 문구·단계별 확인 ❌ 화면·UI 일체

**⇒ 대신 지킬 것 — CS 는 전문가다. 짧고 정확한 것이 낫다**:

| 원칙 | 내용 |
|---|---|
| **CS-1** | **PowerShell 과 CMD 양쪽에서** 된다. 한쪽만 되면 안 된다(사장님 명시 *"파워쉘이나 CMD"*) |
| **CS-2** | 출력은 **기계가 읽을 수 있게** — 결과 한 줄 + 종료코드. CS 가 원격도구 로그로 판정한다 |
| **CS-3** | 실패 사유는 **무엇을 하면 되는지**까지. *"DB_USER 없음"* 이 아니라 *"db.conf 에 DB_USER 가 없다 → 설치본 확인 필요"* |
| **CS-4** | 🔴 **되묻지 않는다.** 확인 프롬프트는 원격·무인 실행에서 멈춰 선다 |
| **CS-5** | 🔴 **받을 수 있는 버전을 먼저 보여준다** — §E-2. 없는 버전을 조용히 실패시키지 않는다 |

### 🔴 §B. 「항상 열어둔다」 — 조건·횟수·쿨다운 전부 없다 (결재 2)

**⇒ 폐기**: ❌ *"1회만 해제"*(1차 §2-B) ❌ 요청 파일 1회성을 **제한 장치로** 쓰는 것 ❌ 쿨다운·횟수 상한

**⇒ 대신**: `_consentAppliedVersions`(`Worker.cs:602`) 는 **CS 명령 앞에서 언제나 무력화**된다.
같은 버전을 몇 번이고 다시 시도할 수 있다.

> ⚠️ **요청 파일 삭제는 남긴다 — 성격이 다르다.**
> *"제한"* 이 아니라 **"1회 실행 = 1회 반영"** 이라는 신호 소비다.
> 파일이 남으면 워치독이 매 루프 같은 요청을 재해석해 **무한 재시도**가 된다 — CS 가 원한 동작이 아니다.
> 🔴 **CS 가 다시 치면 언제나 다시 된다.** 이것이 "항상 열어둔다"의 실제 의미다.

### 🔴 §C. 강제복구의 정체 — **결재 2 와 3 은 한 기능이다**

> *"수동 업데이트, **강제복구**는 항상 열어둬야됨."* (결재 2)
> *"다운그레이드 막으면 안됨."* (결재 3)

**추적 질문**: `api.old` 롤백 경로를 CS 가 부를 수 있나? — **실측 결과 부를 것이 없다.**

| 확인 | 실측 결과 | 근거 |
|---|---|---|
| 롤백 함수가 있나 | ✅ 있다 | `UpdateOrchestrator.cs:804` `RollbackToOldAsync` |
| CS 가 부를 수 있나 | 🔴 **못 부른다** | `private` + **호출부 단 1곳**(`:979`), 실패하는 `ApplyUpdateAsync` 내부에서만 |
| 🔴 **되돌릴 파일이 남아 있나** | 🔴🔴 **아니다 — 성공하면 지운다** | `:999-1001` `CleanupAfterSuccess` 가 `api.old`·`web.old` 를 **삭제**. `:256` 주석: *"성공 정리(staging·**.old**·watchdog.new…)"* |
| 백업으로 되돌릴 수 있나 | 🔴 **아니다** | `WatchdogBackupRunner.cs:56` 은 **DB `.sql` 만**. **프로그램 파일 백업 0건** |

🔴🔴 **결론 — 이번 설계에서 가장 중요한 판정**

> **`.old` 는 "적용 도중 실패" 를 위한 자산**이지 **"어제 것으로 되돌려 달라"** 를 위한 것이 아니다.
> 업데이트가 **"성공" 한 뒤에는 되돌릴 파일이 이 제품에 존재하지 않는다.**

**오늘 1.2.84 가 정확히 그 경우다.** 파일 교체·재기동·`/health` 검증까지 **전부 통과해 "성공"** 이었고,
그래서 `.old` 가 지워졌다. **망가진 것은 로그인 화면**이라 `/health` 200 으로는 잡히지 않는다.

🔴 **그러므로 강제복구의 정체는 이것이다**:

> ## **강제복구 = 옛 버전을 다시 받아 설치하는 것. 다운그레이드가 곧 복구다.**
> **별도 롤백 장치를 만들지 않는다. 결재 3 이 결재 2 를 실현한다. 한 가지 기능이다.**

⚠️ **다음 사람에게 남기는 경고**: `.old` 복원 기능을 만들려 하지 마라. **없는 파일을 찾게 된다.**

| 안 | 판정 |
|---|---|
| **C-1** — 되돌리기를 **"지정 버전 강제 설치"** 로 구현. `--force-update 1.2.83` 이 다운그레이드로도 동작 | ✅ **채택**. 새 경로를 안 만들고 **같은 한 줄로 복구까지** 된다. 백업·서명·검증·롤백이 전부 그대로 걸린다 |
| C-2 — `.old` 를 지우지 말고 보존 | ⚠️ **별건**. `CleanupAfterSuccess` 수정 = **적용 절차 변경**(헌법 #43 금지 3 인접). 사장님 결재 사안 |
| C-3 — `RollbackToOldAsync` 를 public 노출 | ❌ **폐기**. `.old` 가 없으면 `:816` 이 즉시 "롤백 불가" 반환 — **부를 수 있어도 할 일이 없다** |

### 🔴 §D. 다운그레이드 **허용** — 막는 가드를 넣지 않는다 (결재 3)

**⇒ 폐기**: ❌ *"현재 버전보다 낮으면 거부"*(1차 §2-D) ❌ 버전 비교 가드 ❌ **게이트 G-1(거부)**

**근거**: *"새 버전이 고장났을 때 되돌리는 것이 곧 강제복구"* — 오늘 1.2.84 가 그 경우다.
막았으면 CS 가 손을 못 썼다. §C 의 C-1 이 여기에 통째로 기대고 있다.

**⇒ 대신 남기는 것 — 이력**: 누가(`user_id='manual-force'`) · 언제(`consented_at`, DB-82 `:22`) ·
어느 버전으로(`update_version`, `:20`).
⇒ 🔴 **막지 않는 대신 전부 보이게 한다.** 헌법 #15(침묵 금지) 정신.

**여전히 남기는 검사 2개** (다운그레이드 가드가 아니다):
- **미게시 버전 거부** — 게시원에 실재하는 버전만. 🔴 **§E-2 와 한 몸이다**
- **형식 검사** — `WatchdogConsentReader.cs:144` `IsSafeVersionLiteral` 재사용(숫자·점만, 20자)

### 🔴 §E. 게시원에 옛 버전이 남아 있나 — **이것이 진짜 급소다** (결재 5)

§C·§D 가 성립하려면 **되돌아갈 패키지가 게시원에 실재해야** 한다. 없으면 둘 다 무용지물이다.

#### E-1. 보존 정책은 **이미 있다** — 새로 만들 것이 없다

`installer/updates/publish-update.sh:340`
```
PKG_KEEP="${HITPAN_PKG_KEEP:-3}"
```
`:341-358` `rotate_packages` 가 `hitpan-*.zip` 과 `HitPan-ERP-Setup-*.exe` 를 **둘 다** 회전한다.
🔴 **현행 버전은 KEEP 계산에서 아예 제외**한다(`:345-350` 이름 대조 후 `continue`).
그 근거를 코드가 직접 적어 뒀다(`:337`):
> *"몇 개 남기냐"보다 "현역을 지우지 않는다"가 먼저다. 그게 404 의 교훈이다.*
(사고 기록 → `docs/운영기록/20260802_사고기록_대리점_설치실패_승인메일_404.md`)

⇒ **설계할 것이 없다. 이미 되고 있다.**

#### E-2. 🔴 실측 — 설계팀장 직접 확인 (2026-08-18, `curl -I`)

| 버전 | zip | exe |
|---|---|---|
| 1.2.85 (현행) | **200** | **200** |
| 1.2.84 (직전) | **200** | **200** |
| 1.2.83 | 404 | 404 |
| 1.2.82 | 404 | 404 |

⇒ **되돌아갈 곳은 직전 1버전(1.2.84)뿐이다.**
사장님 결재 **"두개"** 와 **현재 상태가 일치**한다 ⇒ 🔴 **인프라 변경 불필요**(헌법 #29 대상 아님).

> ### ⚠️ 다만 설계팀장이 남기는 관찰 — 숫자가 정책과 어긋난다
> `PKG_KEEP=3` 이고 **현행은 계산에서 제외**되므로, 산술적으로는 **현행 1 + 옛것 3 = 4개**가 살아야 한다.
> 실측은 **2개**다. 가능한 설명: ① 게시 횟수가 아직 적다 ② 다른 경로가 정리한다 ③ `PACKAGES_DIR` 에
> 그만큼 쌓인 적이 없다. **원인을 확인하지 않았으므로 단정하지 않는다.**
> 🔴 **결재("두개")는 현재 상태로 충족되므로 이번 작업은 여기서 멈춘다.** 확인은 별건(§7).

#### E-3. 🔴 그래서 CS 도구가 반드시 할 일 (CS-5)

되돌아갈 곳이 **2개뿐**이므로, CS 가 `1.2.83` 을 치면 **404** 다.
🔴 **조용히 실패하면 그것이 최악이다** — CS 는 명령이 먹혔다고 믿고 60초를 기다린다.

⇒ **동의를 넣기 전에 게시원을 먼저 확인하고, 안 되면 명확히 말한다**:
```
[안됨] 1.2.83 은 게시원에 없습니다(404).
       지금 받을 수 있는 버전: 1.2.85(현행), 1.2.84
```
🔴 **"받을 수 있는 목록을 보여주는 것"이 이 도구의 필수 기능**이다(§5 G-2·실측7).

| **실측5** 🔄 | 🔴 **강제복구 — 1.2.85 에서 1.2.84 로 되돌리기** | **되돌아간다**(막히지 않는다). 🔴 **결재 2·3 이 한 기능임을 증명하는 실측**. ~~1차의 "거부 확인"은 폐기~~ |
| **실측6** | 🔴 **설치본 실측** — 새 설치본을 깔고 **`{app}\scripts\`·`{app}\watchdog\` 에서** 실행 | 🔴 *"고쳤나"가 아니라 **"갔나"*** — 개발 폴더에서 되는 것은 증거가 아니다 |
| **실측7** 🆕 | 🔴 **없는 버전 지정** — `1.2.83` (실측상 404) | **조용히 실패하지 않고** 거부 + **받을 수 있는 목록(1.2.85·1.2.84)을 보여준다**(CS-5) |
| **실측8** 🆕 | **CMD 에서 실행** — PowerShell 아닌 `cmd.exe` 로 | 🔴 사장님 *"파워쉘이나 CMD"* — **CS-1 검증** |
| **실측9** 🆕 | 🔴 **항상 열림** — 같은 버전을 **연달아 3회** 실행 | **3회 다 받아들여진다**(막히지 않는다). 결재 2 검증 |

**🔴 실측을 게이트로 만드는 방법**:
1. 실측 9건을 **작업지시서 DoD 에 체크박스로** — 전부 ✅ 아니면 [4] 검증 통과 불가
2. **검증팀장(데이비드 박)이 직접 실측** — SoD. 만든 사람 결과는 안 받는다
3. 🔴 **실측1 은 이 기능의 존재 이유** — 미통과 = 작업 전체 미완료
4. 🔴 **실측5 는 결재 2·3 을 동시에 증명**한다 — 강제복구가 곧 다운그레이드임을 실물로 보인다
5. 결과를 `docs/검증/워치독/` 에 **화면·로그 증거와 함께** (헌법 #42)

## 🔴 5-3. 관측에 대한 교훈 — 이번 설계 중 실제로 겪은 것

> **게시 직후에 잰 값은 회전이 끝나기 전 상태일 수 있다.**
> **시점을 밝히지 않은 관측은 근거가 아니다.**

이번 §E-2 를 확인하는 과정에서 *"옛 패키지가 1개만 남는다"* 는 1차 관측이 나왔고,
다시 재보니 **2개**였다. 첫 관측이 **1.2.85 게시 직후**여서 회전 중간 상태를 본 것으로 보인다.

⇒ **앞으로 게시원·배포 상태를 잴 때는 반드시 함께 적는다**: ① 잰 시각 ② 직전 게시 시각 ③ 명령 원문.
그리고 *"보존 정책을 새로 만들자"* 처럼 **구조를 바꾸자는 결론일수록, 이미 있는 것부터 찾는다** —
이번에도 `publish-update.sh:340` 에 **이미 있었다**.
(같은 계통 교훈: `feedback_gate_must_test_behavior` — 초록불이 어디서 오는지부터 묻기)

| **Q5** 🆕 | 게시원에 옛 버전을 몇 개 남기나 | **"두개"** | §E. ✅ **실측 2개와 일치** ⇒ 🔴 **인프라 변경 불필요**(헌법 #29 대상 아님). 이번에 손대지 않는다 |

### 🔴 이 결재들이 하나로 합쳐지는 자리

| 사장님 결재 | 실측 후 뜻 |
|---|---|
| **2. 강제복구 항상 열어둔다** | = **옛 버전을 다시 받는 길을 항상 열어둔다** (별도 롤백 장치 아님 — `.old` 는 이미 지워졌다) |
| **3. 다운그레이드 막지 않는다** | = **그 길 자체다** |

⇒ 🔴 **한 가지 기능이다. 둘로 나눠 설계하지 않는다.**
⇒ 🔴 **다만 게시원에 옛 패키지가 없으면 둘 다 무용지물이다** — 그래서 §E 가 급소이고, 결재 5 가 그것을 정했다.

🔴 **1차 설계에서 폐기된 것**: 고객용 화면·바로가기 / 1회 해제 제한 / 다운그레이드 가드 / 게이트 G-1 / `.old` 노출안(C-3)
