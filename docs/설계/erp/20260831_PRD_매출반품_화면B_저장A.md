## 1. 배경 — 한 줄

2026-08-31 사장님 실측: **[반품하기]로 반품했는데 판매 전표가 한 장 더 생겼다.**
화면은 반품인데 저장이 판매였다 ⇒ 재고·미수금·회계가 **반대 방향**으로 갔다.

## 2. 사용자 정의 — 누가 쓰나

| 역할 | 이 기능에서 하는 일 | 아는 것 / 모르는 것 |
|---|---|---|
| **경리** | 반품 전표 입력 · 세무사 제출 자료 뽑기 | 세금은 안다 / 재고 위치는 모른다 |
| **창고담당** | 반품 물건 받고 양품·불량 판정 | 물건은 안다 / **세금·부호는 모른다** (40~60대·바코드) |
| **대표** | 이번 달 반품 얼마인지 확인 | 합계만 본다 |

🔴 **부호 입력은 이 셋 중 누구의 업무도 아니다.** 화면이 채우고 사람은 줄만 지운다.

---

## 3. 사용자 시나리오 (정본)

### 3-1. 정상 흐름 — 전량 반품

```
① 판매 목록 조회 → 원 거래명세서(확정된 것) 선택
② [반품하기] 클릭
③ 같은 거래명세서 화면이 열린다
   · 상단 배너: "명-20260410-001 의 반품 전표입니다"
   · 거래처·품목·단가 자동 · 수량 (−) 전량 채워짐
   · 비고 자동: "반품 : 명-20260410-001"
④ 반품 사유 선택 (필수)         ⭐신규
⑤ [저장]
⑥ 결과: 반-20260503-001 생성   ⭐종전엔 명-…-003 (판매) 이 생겼다
⑦ [확정]
⑧ 재고 입고 · 미수금 감소 · 역분개 · (선택) 마이너스 계산서
```

### 3-2. 부분 반품

③에서 **안 돌려받을 줄을 지우거나 수량을 줄인다.** 나머지는 동일.

### 3-3. 재반품 (이미 일부 반품한 건)

③에서 **잔량만큼만** 채워진다. 잔량 0이면 [반품하기] 비활성.

### 3-4. 불량 반품 ⭐

④에서 **불량** 선택 → 창고 화면에 **「폐기」로 표시** · 재고 미가산.

## 4. 화면 명세

### 4-1. 진입점 — 2곳 (신설 0)

| 위치 | 버튼 | 활성 조건 |
|---|---|---|
| 판매 목록 조회 | [반품하기] | 확정된 건 **1건** 체크 시 |
| 거래명세서 작성 | [반품하기] | `status = confirmed` |

🔴 **새 메뉴·새 화면 0개** (사장님 결재 2·5).

### 4-2. 반품 모드 화면 — 평소 명세서 화면과 **다른 점만**

| 요소 | 평소 | 반품 모드 |
|---|---|---|
| 상단 배너 | 없음 | 🟠 `명-… 의 반품 전표입니다. 반품하지 않을 품목은 줄을 지우세요.` |
| 수량 | 직접 입력 | **(−) 자동 채움** · 잔량 상한 |
| 거래처 | 선택 | **고정** (원전표 승계·변경 불가) |
| 비고 | 자유 | `반품 : 명-…` 자동 (덧붙임 가능) |
| **반품 사유** | 없음 | ⭐**필수 선택** |
| 저장 결과 | `명-…` | **`반-…`** |

### 4-3. ⭐ 반품 사유 (신규 · 필수)

| 표시 | 저장값 | 재고 |
|---|---|---|
| 고객 단순 반품 | `customer_return` | 🟢 입고 |
| **불량·파손** | `defect` | 🔴 **폐기** (`is_loss=1`) |
| 교환 | `exchange` | 🟢 입고 |

**미선택 시 저장 불가.** 근거: 창고가 양품·폐기를 갈라야 한다 (아키텍처 §6-3).

### 4-4. 목록 표기

```
일자         전표번호            업체        상태        금액
2026-04-10   명-20260410-001    삼성전자    판매확정    10,000,000
  └          반-20260503-001    삼성전자    반품확정    -2,000,000   ← 원전표 아래 · (−) 표시
```

🔴 **번호는 `반-…`** (아키텍처 §7-4) · **금액은 (−)로 보인다** (사장님 결재 3-4 대사 화면).
