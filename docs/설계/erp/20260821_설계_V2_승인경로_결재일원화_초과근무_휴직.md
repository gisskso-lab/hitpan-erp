## 1. 🔴 일원화의 함정 — 그냥 지우면 사고가 난다

*"결재로 일원화"* 를 **버튼 삭제**로 구현하면 안 된다. 이유:

```
결재설정에서 초과근무·휴직이 꺼져 있는 고객   ← 지금 전원이 이 상태다
        ↓ 자체 승인 버튼을 지우면
승인할 방법이 하나도 없어진다  → 신청서가 영원히 대기중
```

⇒ **워크플로우 끊김**(헌법 #20 = P0). 6/23 자체 승인 경로가 만들어진 이유가
*"신청만 되고 승인 경로가 없던 워크플로우 끊김 봉합"* 이었다 — **그 사고를 되돌리는 꼴**이다.

### 그래서 일원화의 정의를 이렇게 잡는다

> **"결재를 쓰는 고객은 결재로만 승인한다."**
> 결재를 안 쓰는(못 켠) 고객에게서 승인 수단을 빼앗지 않는다.

**결재 ON 이면 버튼을 감춘다. OFF 면 남긴다.** 지우는 게 아니라 **갈라 준다.**

## 2. 설계

### 2-1. 판정 기준 — 이미 있는 것을 쓴다

`ApprovalTriggerHelper.DescribeApprovalBlockerAsync(db, tenantId, docType, ct)`
- 결재를 **걸 수 있으면** `null`
- 못 걸면 **사용자 말로 된 이유**

이미 경비가 이 패턴을 쓴다(`HrService.CheckHrExpenseApprovalAsync`). **새로 만들지 않는다**(헌법 #1).

### 2-2. 화면 동작

| 결재설정 | 자체 승인 버튼 | 안내 |
|---|---|---|
| **ON** (설정+결재선 있음) | 🔴 **감춤** | *"결재함에서 승인합니다"* |
| **OFF** | ✅ **남김** (지금 그대로) | 없음 |

🔴 **버튼을 지우는 게 아니라 조건부로 감춘다.** 코드는 남는다 — 되돌리기 쉽다.

### 2-3. 초과근무는 결재 배선도 함께 (오더 7번)

지금 `CreateOvertimeAsync` 는 결재를 안 부른다. 일원화하려면 **먼저 올라가야** 한다.

```
CreateOvertimeAsync  →  TryCreateApprovalAsync(..., "overtime", ...)
ProcessAsync         →  UPDATE overtime SET status=... (신설)
```

⚠️ **원본 반영을 반드시 함께** 넣는다. 상신만 배선하면 병렬이슈1 이 지적한
*"결재는 승인됐는데 신청서는 대기중"* 이 그대로 재현된다.

### 2-4. 🔴 초과근무는 승인이 금액을 만들지 않는다

사장님 급여 수동원칙([[feedback_payroll_manual_principle]]):
> *"급여는 수동입력원칙. 급여가 휴직을 모르고 사원만 알면 됨"*

⇒ 초과근무 승인은 **`overtime.status` 만** 바꾼다. **수당 계산·급여 반영 없다.**
`hours` 는 이미 저장돼 있고, 급여 명세는 고객이 직접 넣는다.

---

## 3. ⚠️ 미해결 — DDL 판단이 필요하다

`overtime` 표에 **`approval_id` 컬럼이 없다**(실측). `employee_leave_of_absence` 에는 있다.

| 방식 | 장 | 단 |
|---|---|---|
| `ref_id` 로만 잇기 | **DDL 변경 0** | 역방향(초과근무→결재) 추적이 반쪽 |
| `approval_id` 컬럼 신설 | 양방향 완전 | **DDL 변경** — 출하 DDL·마이그 필요(헌법 #36) |

**PM 의견**: `ref_id` 로 충분하다. `ProcessAsync` 는 `doc.RefId` 로 원본을 찾으므로
**동기화에 `approval_id` 는 필요 없다.** 역방향 추적은 지금 쓰는 화면이 없다.
⇒ **DDL 변경 없이 간다.** 필요해지면 그때 추가한다(헌법 #9 — DB는 미리 다, 단 근거 있을 때).

## 4. 검증 게이트 — 🔴 대조실험 필수

| # | 반증 | 기대 |
|---|---|---|
| **W1** | 🔴 시험을 **봉합 전** 실행 | **FAIL** — 아니면 가짜 게이트 |
| W2 | 봉합 후 | PASS |
| **W3** | 🔴 **대조실험** — 배선만 되돌림 | **다시 FAIL** |
| **W4** | 🔴 **결재 OFF 고객** 시나리오 | 자체 승인 버튼이 **보인다** (끊김 0) |
| **W5** | 🔴 **결재 ON 고객** 시나리오 | 버튼이 **감춰지고** 결재함에서 승인된다 |
| W6 | 결재 승인 → `overtime.status` | `approved` 로 **바뀐다** |
| W7 | 급여 무접촉 | `payroll_*` UPDATE **0건** |
| W8 | 전체 시험 | 회귀 0 |
| W9 | 빌드 | errors 0 / warnings 0 |
| W10 | ⚠️ 종단 실측 | **백지환경** — 개발PC 아님 |

🔴 **W4 가 가장 중요하다.** 일원화가 *"승인 못 하는 고객"* 을 만들지 않았는지 보는 자리다.
