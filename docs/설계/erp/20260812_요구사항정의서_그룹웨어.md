## §0. 🔴🔴 상위 원칙 — **히트판에 100% 자동화는 없다. 무조건 반자동.**

> **사장님 못박음 (2026-08-12)**:
> *"무조건 자동이 아닌, **자동계산하되 수동으로 수정가능**하도록 해야지."*
> → *"**히트판은 100%자동화는 없어. 무조건 반자동이야.**"*

**이 문서의 모든 요구사항(GW-001~)에 우선한다.** 아래와 충돌하는 요구는 아래를 따른다.
그룹웨어 한정 규칙이 아니라 **히트판 전 영역**에 적용된다.

### GW-000 반자동 3단 — 자동은 제안, 확정은 사람

```
① 자동계산  →  ② 사람이 보고 고침  →  ③ 확정
   (제안값)       (수정 이력 남음)      (이때만 반영)
```

| 규칙 | 내용 |
|---|---|
| **R1** | 시스템이 계산한 값은 **제안값**이다. 확정 전에는 **어디에도 반영되지 않는다**(헌법 #6) |
| **R2** | 모든 자동계산 값은 **사람이 수정할 수 있어야** 한다. 잠긴 값 금지 |
| **R3** | 🔴 **수정하면 이력이 남는다 — 누가·언제·무엇을·왜.** 이력 없는 수정은 **금지** |
| **R4** | 화면은 **자동값과 사람이 고친 값을 구분 표시**한다. 고친 값이 자동값인 척하면 안 된다 |
| **R5** | 계산 **근거를 함께 보여준다**. 숫자만 던지지 않는다 (예: *"입사 2024-03-02 기준 근속 2년 → 15일"*) |
| **R6** | 기준값은 **코드 상수 금지 → 설정 테이블.** 법 개정 시 재배포 없이 값만 바꾼다 |
| **R7** | 자동계산 결과는 **법정 최소**임을 명시. 회사가 더 줄 수는 있어도 **덜 주면 위법** |

**Why (근거)**

> 🔴 **사장님 (2026-08-12)**: *"사업장의 **직원수, 규모, 법인·개인, 면세사업장** 등 여러 상황이 있어서
> **자동화는 현실적으로 어려워.** 반자동원칙"*

**① 사업장마다 정답이 다르다 — 이것이 근본 이유다**

| 사업장 변수 | 무엇이 달라지나 | 시스템이 알 수 있나 |
|---|---|---|
| **상시근로자 5인 미만/이상** | **연차·가산수당 의무 자체가 없어진다**(근로기준법 제11조·시행령 별표1) | 🔴 **모른다.** 상시근로자수는 재직자 수가 아니라 **연인원÷가동일수**(시행령 제7조의2). 일용직·아르바이트·**사업주 동거가족**까지 센다 |
| **4명 이하** | 급여명세서에 **연장·야간·휴일 시간수 기재 면제**(시행령 제27조의2) | 🔴 위와 동일 |
| **법인 / 개인사업자** | 대표자 4대보험 자격·급여 처리·계정과목이 다르다 | 🔴 모른다 |
| **면세 / 과세** | 매입세액·계정 처리가 갈린다 | 🔴 모른다 |
| **업종** | **산재 요율이 업종별로 전부 다르다**(수십 종 고시) | 🔴 모른다 |
| **취업규칙·단체협약** | 약정 연차·수당이 법정보다 많을 수 있고, **약정하면 지켜야 할 의무**가 된다 | 🔴 모른다 |
| **회계연도 / 입사일 기준** | 연차 기산일이 통째로 달라진다 | 🔴 모른다 |

⇒ **이 변수들은 코드 어디에도 없고 DB에도 없다. 사업장만 안다.**
시스템이 단정하는 순간 **틀린 값을 사실로 만든다.**

**② 법정 영역에서 자동화는 위험을 줄이는 게 아니라 옮긴다**
현행 연차 15일 하드코딩은 대부분 법정보다 **많이** 줘서 우연히 안전지대다.
자동계산하면 11일·3일·0일을 내기 시작하고 — **하나만 틀려도 없던 위법이 새로 생긴다.**

**③ 책임** — 5만 고객사에 같은 로직이 나간다. 오류 1건이 **5만 건**이 된다(헌법 #24)

**④ 업계도 같은 자리에 서 있다** — 이카운트 약관: *"법률·재무·회계·세무 자문을 제공하지 않는다"*.
더존은 급여를 **회계 본체가 아닌 별도 유료 모듈**로 분리했다. **계산은 하되 신고 책임은 지지 않는 것이 표준.**

**⑤ 헌법 #11**(권한은 어드민이 직접 설정, **업종·규모별 템플릿 제공 금지**)과 같은 정신.
사장님이 이미 못박은 원칙이 급여·연차에서 되풀이된 것이다.

**구현 지침**
- 수정 이력은 **신규 구조를 만들지 않는다.** 기존 `audit_trail`(`before_value`/`after_value`/`reason`) 재사용
- 🔴 단, **급여·퇴직금은 `before/after` 에 금액이 평문으로 남는다** — 감사로그 암호화 정책 별도 필요(§8 GW-061)
- 확정 단계는 **결재**로 처리한다(별도 확정 버튼을 새로 만들지 않음)

### GW-000-B 🔴 사업장 정보는 **물어본다** (추론 금지)

위 표의 변수들은 **시스템이 알 수 없으므로 관리자에게 받는다.** 신규 `사업장 설정` 화면 1개.

| 받을 것 | 왜 | 주의 |
|---|---|---|
| **상시근로자수** | 5인 미만 판정(연차·가산수당 의무) | 🔴 **`COUNT(재직사원)` 으로 자동판정 절대 금지.** 계산 근거(연인원÷가동일수)를 화면에 안내하고 **관리자가 입력**. 월별로 변동하므로 **한 번 받고 고정하지 않는다** |
| **법인 / 개인** | 대표자 처리·계정과목 | |
| **과세 / 면세** | 매입세액·계정 | |
| **업종(산재 요율)** | 산재보험료 | 업종별 고시 요율. 값은 관리자 입력 |
| **연차 부여기준** (입사일 / 회계연도) | 연차 기산 | 🔴 회계연도 기준이어도 **입사일 기준 값을 병행 계산·보관**해야 한다. 퇴직 정산 때 둘을 비교해 **많은 쪽**을 지급하지 않으면 위법 ⇒ **단일 기준만 저장하는 설계는 불가** |
| **약정 연차·수당** (법정 초과분) | 취업규칙 반영 | 5인 미만이어도 회사가 주기로 정했으면 **지켜야 할 의무** |

**표시 규칙**
- 🔴 **5인 미만이라고 연차 기능을 숨기지 않는다.** 약정으로 주는 사업장이 실제로 많다
- 화면에 **`법정 의무` / `회사 약정`** 을 구분 표시한다
- 미입력 상태에서는 **계산값을 내지 않고** *"사업장 정보를 먼저 입력해 주세요"* 로 안내한다.
  🔴 **모르는 상태에서 기본값을 사실처럼 보여주는 것이 지금 15일 하드코딩이 만든 사고다**

**현상**: 그룹웨어에서 **유일하게 `user_id` 기준.** 계정 없는 사원은 근로계약서에 **서명 불가**.
