## §1 [범위] 오더를 이렇게 쪼갰다

### 하는 것
1. 「받은답」 화면(`CsInboxPage.razor`)에 **3단 + 한 줄** 평가 카드.
2. 평가를 **로컬에 먼저 적고**(유실 0) 본사로 보내는 **새 줄기**.
3. 평가가 **열리는 조건**을 서버가 판정 — 조용히 사라지는 경우를 원천 차단(§4).

- 평가 **집계·화면**(본사 CS 실적 8단계) — 백오피스 몫.

## §4 [열림] 평가가 열리는 조건 — 이 표가 「조용히 사라짐」을 막는 전부다

ERP 는 본사 티켓이 있는지 **직접 모른다.** ERP 가 아는 가장 가까운 사실은 **「`messages` 가 2xx 를 받았다」**(= 본사가 티켓을 넣었다)이고, 그 자리는 `cs_outbox.sent_at` 이다.

| 쪽지 상태(`cs_requests.status`) | `cs_outbox.sent_at` | `terminal_reason` | 본사에 티켓 있나 | 평가 열림? | 화면 글자 |
|---|---|---|---|---|---|
| 접수 / 전송중 | NULL | NULL | **없다** | ⛔ 닫힘 | 「아직 본사에 안 갔습니다. 전달된 뒤에 평가할 수 있습니다」 |
| 거부 | NULL | `rejected` | **없다** | ⛔ 닫힘 | 「보낼 수 없는 문의입니다 — 내용을 확인해 주세요」 |
| (전송 상한 도달) | NULL | `failed` | **없다** | ⛔ 닫힘 | 「전달이 지연되고 있습니다. 본사가 확인 중입니다」 |
| 전송완료 · 답 0건 | NOT NULL | NULL | 있다 | ⏸ **Q-1** (권고: 닫힘) | 「답이 오면 평가할 수 있습니다」 |
| 답변도착 · 답 1건 이상 | NOT NULL | NULL | 있다 | ⭕ **열림** | 평가 카드 |
| 종결 · 답 1건 이상 | NOT NULL | NULL | 있다 | ⭕ 열림 | 평가 카드 |
| 이미 평가한 건 | — | — | — | ⛔ 닫힘 | 「이 답변을 「좋아요」로 평가하셨습니다」(내 평가 표시) |

- 판정식(서버): `열림 = (o.sent_at IS NOT NULL) AND (o.terminal_reason IS NULL) AND (답 건수 >= 1) AND (평가 행 없음)`.
- 🔴 **화면만 숨기지 않는다** — 같은 판정을 `POST .../rating` 이 **서버에서 다시** 한다. 화면을 우회해 들어온 평가가 본사에서 `duplicated` 로 사라지는 길을 닫는 자리다(G-E1-1).
- 권고(Q-1)는 **「답 1건 이상」**: 오더가 「**받은답** 화면에 달라」이고, 답이 없는데 묻는 평가는 상담 품질이 아니라 전송 속도를 재게 된다.

## §5 [API] ERP 쪽 두 자리 — 둘 다 추가만

### ① 신설 `POST api/cs/requests/{id}/rating` (`CsRequestController`)
순서대로:
1. `TenantId`·`UserId` = `HttpContext.Items` 에서만(#2). 비면 `Forbid()`.
2. **열림 판정**(§4) — 닫혀 있으면 `400` + 사유 글자(§7). 사유 코드를 응답에 함께 싣는다.
3. `rating` 이 정수 1~3 아니면 `400`(본사 계약과 같은 범위 — 여기서 걸러 본사 400 을 만들지 않는다).
4. `comment` trim · 500 초과면 `400` 「한 줄로 적어 주세요」.
5. **문①** `ForbiddenFieldScanner.Scan(comment)` → 걸리면 `400` + `RecordRejectAsync(rule)`(기존 함수 재사용 · 값은 저장 0) + `ForbiddenFieldScanner.GuideMessage(rule)`. 🔴 본사는 금지필드 글을 **조용히 버리고 점수만 저장**하므로, ERP 가 먼저 **고칠 기회**를 줘야 고객 글이 사라지지 않는다.
6. `INSERT INTO cs_rating_outbox (… , next_attempt_at) VALUES (…, UTC_TIMESTAMP(6))` — 🔴 **UTC 명시**. 표 기본값은 서버 로컬시각이고 폴링은 `UTC_TIMESTAMP(6)` 비교라, KST 고객 PC 에서 기본값에 맡기면 **9시간 뒤에야 집힌다**(`CsRequestController.cs:136-138` 과 같은 함정).
7. `UNIQUE` 충돌(1062) → `200 {success:true, alreadyRated:true}` — 두 번 눌러도 사고가 아니다(멱등).

### ② 기존 `GET api/cs/requests/{id}/replies` 응답에 블록 **동봉**(`:189-204`)
기존 키(`success`·`data`)는 **한 글자도 안 바꾼다.** `rating` 객체를 더한다:

| 키 | 값 |
|---|---|
| `canRate` | bool — §4 판정 |
| `reason` | `open` / `not_sent` / `rejected` / `failed` / `no_reply` / `already_rated` |
| `myRating` · `myComment` | 이미 평가한 건의 내 평가(없으면 null) |
| `deliveryState` | `pending` / `sent` / `rejected` / `failed` — 내 평가가 전달됐나 |

판정은 한 번의 조회로: `cs_requests r LEFT JOIN cs_outbox o LEFT JOIN cs_rating_outbox g` + 답 건수. 🔴 `#16` — 한 요청 = 한 연결, `Task.WhenAll` 금지.

## §6 [워커] 보내는 갈래 — 기존과 **같은 모양**으로

`CsOutboxSenderWorker` 에 `public static async Task SendPendingRatingsAsync(db, hq, ownerAccountId, logger, ct)` 를 **더한다**(기존 두 함수 본문 무접촉 · `public static` 이유는 게이트가 사이클을 직접 돌리기 때문 — `:102-103` 과 같은 규율). 호출 자리는 `ExecuteAsync` 안 `await SendPendingAsync(...)`(`:81`) **바로 뒤 한 줄** — 같은 사이클·같은 연결(#16) · 30초 주기.

주소 = `"/api/backoffice/cs/ratings"` · 몸통 = **정확히 3키** `{csRequestId, rating, comment}`(4번째 키면 본사가 통째 400) · 봉투는 `HeadquartersClient.Envelope` 가 자동(3중 재료 · `PostAsync(path, …)` 가 주소를 인자로 받는다).

| 본사 응답 | 처리 | 왜 |
|---|---|---|
| 2xx (평범) | `sent_at = UTC_TIMESTAMP(6)` · `last_status_code` | 끝 |
| 2xx + 본문 `duplicated:true` | `sent_at` 채우고 **`last_error = 'duplicated'`** | §8 — 사라진 평가의 **유일한 흔적**. 행은 남고 사람이 본다 |
| 400 · 422 | `terminal_reason = 'rejected'` · 재시도 0 · **행 삭제 0** | 재시도해도 같은 답. 화면에 사유 |
| 401 · 403 · **429** · 5xx · 0(타임아웃·연결) | `attempt_count+1` · `next_attempt_at = +min(30·2^min(n,10), 600)초` · 50회 후 `terminal_reason='failed'` | 🔴 **429(60분 잠금)를 `rejected` 로 종결하면 그 창의 평가가 영구 소실**(G-E1-4) |

- **문② 재검**: 송신 직전 `comment` 를 한 번 더 검사한다. 기존 `ScanPayloadBody` 는 `payload.body` 만 보므로(`:216-229`) **평가는 그 그물에 안 걸린다** ⇒ 같은 스캐너를 쓰는 과부하 하나를 더하고, 기존 함수의 동작은 한 글자도 바꾸지 않는다(게이트가 messages 쪽 불변도 함께 문다). 걸리면 `rejected` + `cs_forbidden_rejects` 기록(값 저장 0).
- 🔴 `cs_requests.status` **무접촉** — 평가는 쪽지 상태축이 아니다. 섞으면 「답변 도착」이 평가에 덮인다.
- 본사가 죽어도 ERP 는 돈다(#30) · 워커는 죽지 않는다(#15) — 기존 규율 그대로.
