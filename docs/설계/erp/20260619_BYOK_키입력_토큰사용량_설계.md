## 2. 기존 BYOK API · 프론트 현황 (있음/없음 — 실코드)

### 2-1. 백엔드 — `ChatbotController.cs` (실재)
- `[Authorize(Policy="TenantOnly")]`, tenant_id는 `HttpContext.Items["TenantId"]`(JWT)에서만. **헌법 #2 준수.**
- 엔드포인트: `POST ask` / `POST feedback` / `GET quota` / `GET kb` / `GET kb/popular`.
- **BYOK 키 저장(PUT)·삭제(DELETE)·연결확인 엔드포인트 = 없음 (미구현).**

### 2-2. 백엔드 서비스 — `ChatbotService.cs` (실재, Dapper)
- `GetQuotaAsync`: `local_subscription`에서 ai_mode/limit/extra/tier/last4/status SELECT + `ai_usage_logs` 당월(`ym`) total_tokens SUM. → `TokenQuotaDto` 반환. **읽기 전용. 키 평문 디코드 안 함(last4만).**
- `AskAsync`: KB LIKE 매칭 답변 + `ai_conversations` INSERT + `ai_usage_logs`에 **fake 토큰**(50 + msg/2) INSERT. ai_provider='none', charge_mode='hitpan_pool'. **실제 Anthropic 호출 0 (Phase A).**
- 인터페이스 주석 명시: *"Phase B 예정: Anthropic Claude 연동 + 토큰 차감/과금."* → BYOK는 설계상 Phase B로 예약됨.
- **키 암호화 저장/검증 로직 = 없음.**
- ⚠️ 버그 발견(부수): `GetQuotaAsync`의 `AnthropicKeyConfigured` 판정이 status=`"verified"`를 비교(line 309)하나, 스키마 DEFAULT/주석상 유효값은 `'valid'`. **status 값 정합 불일치** → §7에 정정 명시.

### 2-3. 암호화 인프라 (실재 — 재활용 가능)
- `IEncryptionService` (`EncryptionService.cs`): AES-256-CBC, IV 매회 랜덤, `Encrypt(string)→base64`/`Decrypt`. 키는 `ERP_ENCRYPTION_KEY` 환경변수(Base64/hex/UTF8 32B). **DI: `AddSingleton<IEncryptionService>`(Program.cs:67).**
- `EncryptedValueConverter`/`NullableEncryptedValueConverter`: **EF Core 전용** ValueConverter. ChatbotService는 Dapper라 ValueConverter 미적용 → **`IEncryptionService` 직접 호출**이 정답(헌법 #5의 "암호화 필수"는 충족, ValueConverter 미적용 PR 반려 조항은 EF 매핑 컬럼에 한함).

### 2-4. 프론트 — 설정 페이지 (실재 목록 확인)
`src/HitPan.Web/Pages/Settings/` 16개 .razor 존재. AI/키 입력/사용량 관련 페이지 = **없음 (미구현).**
- 단, `ChatbotBar.razor`(레이아웃) + `Web/Services/ChatbotService.cs` + `Models/ChatbotModels.cs`(`TokenQuotaModel`에 `AnthropicKeyConfigured`/`AnthropicKeyLast4` 필드 실재)는 존재. → 사용량 표시 모델은 이미 일부 준비됨.

**요약**: 테이블·암호화 컬럼·암호화 서비스·쿼터 조회 API·프론트 쿼터 모델은 **있음**. BYOK **키 입력/삭제/검증 API와 설정 화면, 키 입력 UI는 전부 없음(미구현).**

## 3. 신규/수정 테이블 DDL (실스키마 기준 · 전면 재설계 허용)

**설계 판단: 신규 테이블 만들지 않는다.** 실재 `local_subscription`이 이미 BYOK 키 3컬럼(encrypted/last4/status)을 보유하고 ERP AI 설정의 SoT이므로 **재활용**한다. `ai_usage_logs`도 cost_krw/charge_krw/ym까지 이미 충분 → **컬럼 추가만 최소 보강.**

### 3-1. `local_subscription` — 키 관리 메타 보강 (ALTER, 신규 컬럼 2개)
```sql
-- BYOK 키 저장/검증 시각 추적 (감사·UI '마지막 확인' 표시용)
ALTER TABLE `local_subscription`
  ADD COLUMN `anthropic_key_saved_at`     datetime(6) DEFAULT NULL COMMENT 'BYOK 키 마지막 저장 시각'    AFTER `anthropic_key_status`,
  ADD COLUMN `anthropic_key_verified_at`  datetime(6) DEFAULT NULL COMMENT 'BYOK 키 마지막 연결확인 성공 시각' AFTER `anthropic_key_saved_at`;
-- anthropic_api_key_encrypted varchar(512) 는 실재 → 그대로 사용 (AES-256-CBC base64, §2-3)
-- 헌법 #17: 기존 테이블 InnoDB 유지. 신규 테이블 없으므로 ENGINE 재지정 불요.
```
> **status 값 표준 고정**: `none`(미설정) / `valid`(연결확인 성공) / `invalid`(키 거부) / `expired`. ChatbotService의 `"verified"` 비교는 `"valid"`로 정정(§7-A).

### 3-2. `ai_usage_logs` — BYOK 집계 구분 (변경 없음, 사용 규약만 명시)
- BYOK 호출 기록 시: `ai_provider='anthropic'`, `charge_mode='byok'`, `cost_krw`=Anthropic 실단가 환산, `charge_krw=0`(BYOK는 본사 청구 0, 고객이 Anthropic에 직접 지불). `ym`=KST 기준 'YYYY-MM'.
- 신규 컬럼 불요. 기존 cost_krw/charge_krw/input/output/cached/total로 사용량 화면 100% 구성 가능.

### 3-3. `tenants` AI 컬럼 처리
- ERP 런타임 SoT는 `local_subscription`이므로 **`tenants.anthropic_*`에는 키를 쓰지 않는다**(혼선 방지). 베타 전이므로 향후 `tenants`의 AI 컬럼 DROP 여부는 별도 결재(§7-D). 본 설계 범위에선 미사용 유지.

## 4. 키 입력 화면 설계 (Blazor · 설정 페이지)

신규 페이지: `src/HitPan.Web/Pages/Settings/AiAssistantPage.razor`
라우트: `@page "/settings/ai-assistant"` · 사이드바 라벨 **"AI 도우미 연동"** (헌법 #23 — "AI·Claude" 단어 노출 금지. "AI 도우미"는 일반명사로 허용, "Claude/Anthropic" 미노출).

### 4-1. 화면 구성 (UserInfoPage 패턴 — MudPaper 카드 + MudGrid)
- 상단 안내(MudAlert info): *"AI 도우미를 쓰려면 사용하실 AI 서비스 키를 입력하세요. 토큰 사용료는 고객님 계정으로 직접 청구됩니다."*
- **연동 모드 선택** (MudRadioGroup): `히트판 기본(공용)` / `내 키 사용(직접 결제)` ← ai_mode = hitpan_pool / byok.
- **키 입력 영역** (모드=byok일 때만 활성):
  - `MudTextField` `InputType=Password`, Label="연동 키", Placeholder는 `sk-...` 형태 힌트(내부적으로 Anthropic 키임을 입력란 HelperText에 *"제공받으신 AI 서비스 비밀 키"* 로 명확화).
  - 이미 저장됨 상태: 평문 미표시. **`••••••••{last4}`** 마스킹 + "마지막 확인: {verified_at}" + status 칩(valid=초록/invalid=빨강/none=회색).
  - 버튼 3종: **[저장]** (PUT) · **[연결 확인]** (POST verify) · **[삭제]** (DELETE, 확인 다이얼로그).
- 저장/삭제/확인은 `Snackbar`로 결과 안내. 키 평문은 **저장 직후 입력란 즉시 비움**(메모리 잔류 최소화).

### 4-2. 보안 표시 규칙 (보안 매니저)
- 화면·로그·스낵바·네트워크 응답 어디에도 **평문 키 재노출 0**. 서버는 last4/status만 반환.
- BYOK 키 호출은 **고객 PC ERP가 Anthropic에 직통**(본사 프록시 금지). 키는 ERP 로컬 DB(`local_subscription`)에만 암호화 저장, 본사 백오피스로 전송 금지(헌법 #18·#22). → §6 verify는 **ERP 서버가 직접** Anthropic에 호출.

### 4-3. 헌법 #35 정합
- 회사정보처럼 잠그지 않는다. BYOK 키는 고객 자산 → 고객이 자유 입력/수정/삭제.

## 6. API 명세 (신규)

컨트롤러 확장: `ChatbotController` 내 추가 또는 신규 `AiSettingsController` (Route `api/ai-settings`, `[Authorize(Policy="TenantOnly")]`). tenant_id는 JWT(`HttpContext.Items["TenantId"]`)에서만 — 파라미터 수신 금지(헌법 #2).

| 메서드 | 경로 | 설명 | 요청 | 응답 |
|---|---|---|---|---|
| GET | `api/ai-settings` | 현재 모드·키 상태 조회 | — | `{ aiMode, keyStatus, keyLast4, savedAt, verifiedAt }` (평문 키 절대 미반환) |
| PUT | `api/ai-settings/key` | BYOK 키 저장 | `{ apiKey }` | `{ keyStatus:'valid|invalid', keyLast4 }` |
| POST | `api/ai-settings/key/verify` | 연결 확인(저장된 키로) | — | `{ keyStatus, verifiedAt }` |
| DELETE | `api/ai-settings/key` | 키 삭제 + 모드 hitpan_pool 복귀 | — | `204` |
| PUT | `api/ai-settings/mode` | ai_mode 전환 | `{ aiMode }` | `{ aiMode }` |
| GET | `api/chatbot/usage` | 당월/월별 사용량 | `?months=6`(opt) | `{ current:{used,limit,extra,remaining,costKrw,chargeKrw}, months:[{ym,used,costKrw}] }` |

### 6-1. PUT key 서버 처리 (보안 시퀀스)
1. 입력 키 형식 1차 검증(비어있지 않음, 길이/prefix). 2. **연결 확인**: ERP 서버 → Anthropic `/v1/models` 또는 최소 토큰 messages 호출(키 유효성). 3. 성공 시 `IEncryptionService.Encrypt(apiKey)` → `local_subscription.anthropic_api_key_encrypted`, `last4`=끝 4자, `status='valid'`, `saved_at/verified_at=NOW(6)`, `ai_mode` 그대로(또는 byok 전환은 별도 mode API). 4. 실패 시 저장하지 않고 `invalid` 응답(기존 유효 키 보존). 평문은 즉시 폐기, **로그에 키/암호문 미기록**(헌법 #15는 빈 catch 금지지 키 로깅 강제 아님).
- Dapper UPDATE, `IEncryptionService` 주입. ValueConverter 미사용(Dapper 경로).

### 6-2. usage 조회
- `GetQuotaAsync` 확장 또는 신규 메서드: `ai_usage_logs` WHERE tenant_id(JWT) AND ym GROUP BY ym, SUM(total_tokens/cost_krw/charge_krw). 단일 쿼리(헌법 #16 — MySqlConnection 병렬 금지 준수).

## 7. 미검증 · DESCRIBE 필요 · 정정 목록

- **A. (정정 필요·확인됨)** `ChatbotService.GetQuotaAsync`의 키 설정 판정이 `status=="verified"` 비교 → 스키마 표준값은 `'valid'`. **불일치 버그**. 신규 API와 함께 `'valid'`로 통일. *(코드/스키마 양쪽 read로 확인된 사실, 추측 아님.)*
- **B. (DESCRIBE 권장)** 실 DB(MariaDB 런타임)에 `local_subscription`/`ai_usage_logs`가 덤프와 동일한지 — 본 분석은 `installer/hitpan_db.sql` 덤프 기준. ALTER 전 `DESCRIBE local_subscription;` 실행 의무(헌법 #13).
- **C. (미검증)** `tenants` vs `local_subscription` 중 AI 컬럼의 **정식 SoT 확정** — 코드는 `local_subscription`을 읽지만, 백오피스 동기화/마이그가 `tenants.ai_*`도 채우는지 미확인. 키 쓰기는 `local_subscription` 단일화 권고(본 설계 가정).
- **D. (결재 필요)** 베타 전 `tenants`의 AI 컬럼 DROP/유지 — 데이터 정합 단순화 위해 DROP 후보지만 사장님/DB매니저 결재 전까지 유지.
- **E. (미검증)** Anthropic 키 검증 호출의 실제 엔드포인트·최소 비용·타임아웃 — 구현 시 Anthropic 공식 API 스펙 재확인 필요(외부 직통, 본사 프록시 금지).
- **F. (미검증)** `ai_usage_logs.ym` 타임존 — 현행 `AskAsync`는 `DateTime.UtcNow`로 ym 생성. KST 월 경계와 어긋날 수 있음. 사용량 화면 월 집계 시 KST 기준 통일 검토.
