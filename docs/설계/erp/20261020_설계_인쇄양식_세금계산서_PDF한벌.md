 「인쇄」 → window.print()                       (화면 사진)

## §5 [인쇄창] 3-4 — PDF 를 인쇄 대화상자까지

| 층 | 설계 |
|---|---|
| **서버** | `DownloadPdf` 에 `?disposition=inline` **선택 인자 신설**. 값이 `inline` 일 때만 `Content-Disposition: inline`. **기본은 지금 그대로 `attachment`** ⇒ 「PDF」 단추·모바일 동작 무변경 (더하기만 · #1) |
| **클라이언트** | `index.html` 에 `hitpan.printPdf(url)` 신설 — 숨은 `<iframe>` 에 inline URL → `onload` → `contentWindow.focus(); contentWindow.print();` → 일정 시간 뒤 제거 |
| **같은 출처인가** | 🟢 운영(터널)은 `ApiBaseUrl` 이 **현재 페이지 출처로 폴백**(`Program.cs:35`) ⇒ 같은 출처 ⇒ `contentWindow.print()` 가 선다 |
| 🔴 **개발 PC** | `:5234` ↔ `:5257` 로 **다른 출처** ⇒ 같은 코드가 **개발 PC 에서만 막힌다**. 🔴 **이 게이트는 터널 도메인에서만 잰다**(사장님 10/20: 시험 루틴도 고객과 같게) |

### 5-1 🔴 되돌아갈 길 (실패 시 · 순서대로)

| 차례 | 길 | 언제 |
|---|---|---|
| 1 | iframe + `contentWindow.print()` | 기본 |
| 2 | **새 창으로 inline PDF 열기**(`<a target="_blank">` — 이미 팝업 차단을 피하는 수법이 `index.html:141` 에 있다) + 「열린 창에서 인쇄하세요」 안내 | 1 이 예외·시간초과 |
| 3 | **내려받기**(지금 「PDF」 단추와 같은 길) + 「내려받은 파일을 열어 인쇄하세요」 안내 | 2 도 막힘 |
| 🔴 **금지** | **`window.print()` 로 되돌아가기** | 되돌아가면 화면 사진이 다시 나가고, 전표 밖 CSS(§7)가 범위로 끌려온다 |

⚠️ 팝업 차단·blob 정책·엣지/크롬 차이는 **실물 미측정**이다(선행검증서 ②). 3단 길을 **코드에 다 넣어** 미측정을 흡수한다 — 어느 하나가 막혀도 고객은 종이를 얻는다.

## §6 [CSS] 3-5 — `@media print` 는 **이번 차수에서 뺀다**

| 판정 | **뺀다 (별건 등재)** |
|---|---|
| ① | 결재 ⓑ 범위는 **세금계산서 1종**이다. 이 CSS 는 **자료 인쇄 20곳 + 장부 6곳 = 26곳**에 선다 — 전부 **이번 범위 밖**(쟁점표 §15-2 가 「현황·통계는 손대지 않는다」·「장부 6곳은 등재만」이라고 이미 적었다) |
| ② | 세금계산서 「인쇄」가 PDF 로 가면 **이 CSS 를 안 탄다** ⇒ 합격선·대조군 1 달성에 **필요 없다** |
