## §0. 이 문서를 만든 이유 — 나무를 보다 숲을 놓쳤다

법무 조사 5건을 돌린 결과 조문·요율·판례가 쏟아졌다. 그런데 **그건 N차에 바뀔 것들이다.**

> 🔴 **사장님 판단**: 법리는 2-3차·N차에 얼마든지 바꾼다. **지금 필요한 건 큰 틀이다.**

**조사의 진짜 수확은 조문이 아니라 이것이다:**

### 🔴 바뀌는 것과 안 바뀌는 것을 가른다

| | 예시 | 어디에 두나 |
|---|---|---|
| **자주 바뀜** | 연차 일수·4대보험 요율·최저임금·세액표·기간(육아휴직 1년→1년6개월) | 🟢 **설정 테이블**(값) |
| **가끔 바뀜** | 판정 규칙(5인 미만 기준·15시간 기준) | 🟢 **설정 + 관리자 확정** |
| **거의 안 바뀜** | **신청→결재→반영** 흐름 / 사원이 축 / 이력이 남는다 / 사람이 확정한다 | 🔵 **구조**(코드) |

⇒ **법이 바뀌어도 구조는 안 바뀐다. 그래서 구조부터 짓는다.**
⇒ 🔴 **법정값을 코드에 넣지 않는다.** 지금 연차 15일이 코드에 박혀 있어서 못 바꾸는 것이 바로 그 실패다.

### 🔴 법은 계속 바뀐다 — 이것이 설계 방향을 정한다

> 🔴 **사장님 (2026-08-12)**: *"어차피 지금 자세하게 법령조사하고 만들어도
> **법이라는 게 언제, 어떻게 바뀔지는 몰라. 계속 모니터링 해야 해.**"*

**조사가 이미 증명했다** — 우리가 "정확히 조사한" 것들이 최근에 바뀐 것들이다:

| 무엇 | 언제 바뀜 |
|---|---|
| 육아휴직 **1년 → 1년 6개월**, 분할 3회, 배우자 출산휴가 20일 | **2025-02** |
| 🔴 법제처 해석(육아기 단축 = 출근 아님) → **법 개정으로 폐기** | 2024-10 |
| 국민연금 9% → **9.5%**, 그리고 **2033년까지 매년 인상 확정** | 2026-01 |
| 건강보험 7.09% → **7.19%** (2년 동결 후) | 2026-01 |
| 간이세액표 개정 | **2026-02** |
| 연차 "365일=11일 / 366일=26일" 대법원 해석 변경 | 2021 |

⇒ **지금 정확한 것이 내년에 틀린다. 그게 정상이다.**

**그래서 설계 목표가 바뀐다:**

| ❌ 하지 않을 것 | 🟢 할 것 |
|---|---|
| 지금 법을 정확히 코드에 박기 | **바뀌면 갈아끼울 수 있게** 만들기 |
| "법정 15일" 을 상수로 | **설정 테이블 + 적용시작일** |
| 한 번 조사하고 끝 | **모니터링 대상 목록**을 남기기 |

**구체 지침 3가지**
1. **법정값은 전부 설정 테이블.** 하드코딩 금지, **상수로 빼는 것도 금지**(재배포가 필요하면 실패다)
2. 🔴 **값마다 `적용시작일`을 둔다.** 법은 시행일이 있고, **과거분은 옛 값으로 계산**해야 한다.
   (예: 2012년 이전 근속·요율 변경 전 기간 — 단일 값만 저장하면 과거 계산이 전부 틀린다)
3. **"이 값은 언제 기준인가"를 화면에 표시.** 고객이 낡은 값인지 알 수 있어야 한다

⇒ 상세 조문은 §7로 내린다. **N차에 값만 갈아끼운다.**

## §1. 숲 — 그룹웨어는 결국 이 그림 하나다

```
                          ┌──────────────────┐
                          │   사원 (employees) │ ★축 — 모든 것이 여기 매달린다
                          └────────┬──────────┘
                                   │
        ┌──────────────┬───────────┼───────────┬──────────────┐
        │              │           │           │              │
   [누구인가]      [무엇을 했나]  [무엇을 신청]  [얼마를 받나]   [어떻게 말하나]
        │              │           │           │              │
    직급·부서       근태·휴직     신청 6종     급여·퇴직금      메신저
    고용형태          출근기록        │          명세서        (계정 있는
    계정                            │                          사원만)
        │                           │           │
        └───────────────────────────┼───────────┘
                                    ↓
                        ╔═══════════════════════╗
                        ║   결재 (한 곳으로 모임)  ║  ← 🔴 이것이 그룹웨어의 심장
                        ╚═══════════╤═══════════╝
                                    ↓
                        ┌───────────┴───────────┐
                        ↓                       ↓
                  원본에 반영               회계에 반영
              (연차 차감·근태 표시)      (경비·급여 → 전표)
```

**읽는 법 — 이 그림이 말하는 것 3가지**

1. **모든 입구가 결재 한 곳으로 모인다.** 화면에서 신청하든 메신저에서 쓰든 캘린더에서 누르든, 결재 문서는 하나의 흐름을 탄다. ⇒ 신규 기능이 생겨도 **결재 흐름은 재사용**한다
2. **사원이 축이다.** 계정이 아니다. 계정 없는 사원 11명이 실재한다
3. **결재 다음에만 반영된다.** 신청 단계에서는 아무것도 바뀌지 않는다(헌법 #6)

## §2. 🔴 관통 원칙 — 100% 자동화는 없다

> 사장님: *"**히트판은 100%자동화는 없어. 무조건 반자동이야.**"*
> *"사업장의 직원수, 규모, 법인·개인, 면세사업장 등 여러 상황이 있어서 자동화는 현실적으로 어려워."*
> *"정직원이냐, 알바냐, 계약직이냐, 무기계약직이냐에 따라서도 달라짐."*

```
   자동계산  →  사람이 보고 고침  →  확정
   (제안값)      (이력이 남음)      (이때만 반영)
```

**왜 자동이 불가능한가 — 사업장마다 정답이 다르기 때문이다**

시스템이 **모르는 것**들이다. 코드에도 DB에도 없고 **사업장만 안다**:
- 상시근로자 수 (5인 미만이면 연차 의무 자체가 없다)
- 법인/개인 · 과세/면세 · 업종
- 취업규칙 약정 (법정보다 더 주기로 했으면 그게 의무가 된다)
- 고용형태별 실제 근로시간

⇒ **물어본다. 추론하지 않는다.** 모르면 계산값을 내지 않고 *"사업장 정보를 먼저 입력해 주세요"*.
🔴 **모르는 상태에서 기본값을 사실처럼 보여주는 것이 지금 연차 15일이 만든 사고다.**

**대신 반드시 따라오는 것**: 고칠 수 있으면 **누가·언제·무엇을·왜 고쳤는지 남는다.** 이력 없는 수정은 금지.
(신규 구조 불필요 — 기존 `audit_trail` 재사용)

## §3. 그릇 8개 — 무엇을 짓는가

> 세부 필드는 ERD에. 여기서는 **왜 이 그릇이 필요한가**만.

| # | 그릇 | 왜 필요한가 | 상태 |
|---|---|---|---|
| **1** | **사업장 설정** | 5인 미만·법인/개인·과세/면세·업종. **모든 판정의 전제** | 🔴 없음 |
| **2** | **고용형태** | 정직원/알바/계약직/무기계약직에 따라 권리가 다름 | 🟡 **콤보는 있는데 아무도 안 읽음** |
| **3** | **연차 엔진** | 지금은 **관리자가 손으로 타이핑**. 계산이 아예 없음 | 🔴 없음 |
| **4** | **휴직** | 육아휴직 1년 6개월이 휴가 칸(최대 99.9일)에 안 들어감 | 🔴 없음 |
| **5** | **급여명세서** | 법정 교부 의무. 계산은 세무사가 이미 함 | 🔴 없음 |
| **6** | **퇴직금명세서** | 퇴사 처리 자체가 반쪽 | 🔴 없음 |
| **7** | **보고서 4종** | 일일·주간·월간·경위서 | 🟢 **결재만 붙이면 됨**(DDL 0) |
| **8** | **메신저** | 전체·부서방 + 알림 + 양식작성 | 🟢 **SignalR 완비** |

### 그릇을 나눈 기준 — 왜 합치지 않는가

| 안 합치는 것 | 이유 |
|---|---|
| **휴가 ↔ 휴직** | 육아휴직은 **1년 6개월**. 휴가 일수 칸은 최대 99.9일 — **물리적으로 안 들어감** |
| **급여명세서 ↔ 퇴직금명세서** | 근거·주기·계산이 전혀 다름 |
| **AI 챗봇 ↔ 사내 메신저** | 🔴 AI는 대화를 **외부로 보낸다**. 합치면 사내 대화가 외부로 나가는 경로가 생김(헌법 #18·#22) |

## §4. 조립 순서 — 무엇부터 해야 다음이 쉬워지나

> 김삼성 상무: *"부품은 다 있다. **조립 순서**를 잡는다."*
> 원칙: **다른 것을 쉽게 만드는 것을 앞으로, 선행조건이 있는 것을 뒤로.**

```
[0] 이미 터진 것 봉합    ← 🔴 결재 불필요·지금 즉시
      ↓
[1] 있는 걸 보이게       ← 결재 불필요
      ↓
[2] 알림 (결재가 왔다)    ← 배관 완비, 여기부터 그룹웨어가 살아난다
      ↓
[3] 보고서 4종           ← 결재만 붙이면 됨
      ↓
[4] 토대 세우기          ← 직급·부서·고용형태·사업장설정
      ↓
[5] 연차 엔진            ← [4] 필요
      ↓
[6] 휴직                 ← [5] 필요
      ↓
[7] 경비 → 회계          ← 기표 자체가 신규
      ↓
[8] 급여·퇴직금 명세서    ← [4][5] 필요
      ↓
[9] 메신저               ← 부서(=[4]) 필요
```

### 🔴 단계 0 — 이미 터져 있다 (결재 없이 지금)

퇴직금을 조사하다 **퇴직금과 무관한 실존 사고**를 찾았다.

| # | 무엇 | 왜 P0 |
|---|---|---|
| **0-A** | **퇴사자가 계속 로그인된다** | 퇴사는 `employees.is_active` 를 끄는데 로그인은 **`users.IsActive`** 를 본다. **다른 표의 다른 칸.** 퇴사자가 거래처·단가를 계속 봄 |
| **0-B** | **죽은 결재자가 결재선에 남는다** | 퇴사해도 결재선을 안 건드림 ⇒ 그 차례에서 **결재가 영원히 멈춤**(헌법 #20) |
| **0-C** | 버튼이 **"삭제"** 다 | `is_resigned`·`resign_reason` 칸은 있는데 **아무도 안 채움**. 퇴사일도 **버튼 누른 시각**이라 소급 처리 불가 |
| **0-D** | **되는 척 3건** | 급여 항상 0원 / 무효 서명이 "유효" / [무효화] 눌러도 **스낵바만** |

> 🔴 **0-B 는 김삼성 상무님이 경고한 바로 그 자리다.**
> *"사람 이름으로 결재선을 짜면 그 사람이 퇴사하는 날 회사의 모든 결재가 멈춥니다."*
> — 가설이 아니라 **현재 상태**였다.

### 단계 1 — 있는 걸 보이게 (가장 싸고 체감 큼)

**숨은 화면 7개**(초과근무·부서관리·근태캘린더·휴가캘린더·경비현황·휴가현황·HR직급)를 메뉴에 올린다.
🟢 **야근·주말근무는 표·화면·승인 API가 이미 있다** — 3종으로 가르면 사장님 지시가 여기서 거의 끝난다.

### 단계 2 — 알림

김삼성 상무: *"**'결재가 올라왔습니다' 알림부터** 붙이세요. 그러면 직원이 메신저를 켤 이유가 생깁니다."*
🟢 SignalR 완비(WebSocket 인증 봉합까지) ⇒ **신규 인프라가 아니라 검증된 패턴 복제**.

### 단계 4 — 토대 (여기가 진짜 분기점)

| 세울 것 | 지금 |
|---|---|
| 직급 마스터 | **0행** — 아무 직급도 못 고름 |
| 사원 직급 | 12명 중 **8명이 직급 없음**(NULL·공백·`"0"`) |
| 부서 마스터 | **0행** (자유문자에만 10건) ⇒ **지금 부서방 만들면 방이 0개** |
| 고용형태 | 콤보는 있으나 **전원 `regular`**, 읽는 코드 0 |
| 사업장 설정 | 없음 |

## §5. 🔴 설계 전제 정정 2건 — 실측이 문서를 뒤집었다

> 헌법 #32(받아쓰기 금지). **틀린 전제 위에 지으면 전부 무너진다.**

### 정정 1 — 결재선은 "문서별"이 아니라 **전역 템플릿**이다

문서 1건마다 결재선이 복사되는 게 아니라 **결재할 때마다 실시간 조회**한다.

🔴 **그래서 결재선을 바꾸면 이미 진행 중인 결재의 결재자가 소급으로 바뀐다.**
지금은 *"진행 중 결재가 1건이라도 있으면 결재선 저장 차단"* 이라는 임시 가드로 막아둔 상태다.

⇒ **직급 기반으로 바꾸면 위험이 커진다.** 지금은 관리자가 설정을 건드릴 때만 위험한데, 직급 기반이 되면 **승진·퇴사만 해도** 진행 중 결재가 흔들린다. 임시 가드는 인사이동을 못 막는다.

**결론: 직급 전환 전에 "상신 시점의 결재선을 문서에 고정(동결)"이 반드시 선행.**

🟢 다행인 것: 결재 생성이 **공통 함수 1개**로 통합돼 있고, 진행 중 결재 **0건**, 죽은 표는 이미 **직급/사람 택일 구조**. 수술 자리가 **3곳뿐**.

### 정정 2 — **ERP 경비도 전표를 안 만든다**

*"ERP 경비는 정상 동작하니 그 패턴을 복제하면 된다"* 고 썼는데 **틀렸다.**
경비 **27,639건 중 전표 생성 0건.** 손익 화면에서 **따로 집계**할 뿐이다.

⇒ 이 작업은 *"그룹웨어를 ERP 패턴에 붙이기"* 가 아니라 **"경비→회계 기표를 처음 만들고 ERP·그룹웨어 양쪽을 함께 태우기"** 다. **범위가 전제보다 크다.**

🔴 **"회계와 연결"의 뜻을 하나로 정해야 한다** — **(a) 전표 자동생성** 인가 **(b) 손익 집계 반영** 인가. 지금 경비는 (b)다.

## §7. N차로 미룬 것 + 🔴 계속 모니터링할 것

> 사장님: *"법리해석은 2-3차 혹은 N차 수정 때 얼마든지 바꿀 수 있어."*
> *"법이라는 게 언제, 어떻게 바뀔지는 몰라. **계속 모니터링 해야 해.**"*

법무 조사 5건 결과는 **문서로 보관**한다. 필요할 때 꺼내 쓴다.

| 미룬 것 | 어디에 |
|---|---|
| 연차 법정 산정식·경계조건 | 법무 조사분(§3 그릇 3에 요약) |
| 휴직 종류별 법적 효과 | [휴직 법적명세](20260812_휴직_육아휴직_법적명세.md) |
| 4대보험 요율·간이세액표 | 조사분 — **설정 테이블 값으로 들어갈 것** |
| 퇴직금 평균임금 산정 | 조사분 |
| 고용형태별 권리 차이 | 조사분 |

### 🔴 모니터링 대상 — 바뀌면 값을 갈아야 하는 것

**한 번 미루고 잊으면 안 된다.** 아래는 **주기적으로 확인해 설정값을 갱신**할 대상이다.

| 무엇 | 언제 바뀌나 | 갱신 주체 |
|---|---|---|
| **국민연금 요율** | 🔴 **2033년까지 매년 인상 확정**(9.5%→13%) | 본사 → 설정 기본값 |
| **국민연금 기준소득 상·하한** | **매년 7월** (1월 아님) | 본사 |
| **건강보험·장기요양 요율** | 매년 심의(동결도 있음) | 본사 |
| **최저임금** | 매년 (익년 1월 적용) | 본사 |
| **간이세액표** | 세법 개정 시 | 본사 |
| **산재 요율** | 매년 고시 · **업종별로 다름** | 사업장 입력 |
| **연차·휴직 법정 기준** | 개정 시 | 본사 + 노무사 |

**운영 방식 (제안 — 별도 결재)**
- 값은 **본사가 기본값을 배포**하고, 고객사가 **필요 시 조정**(약정이 법정보다 많을 수 있음)
- 🔴 값 배포가 **코드 재배포를 요구하면 실패**다. 값만 갱신되는 경로여야 한다
- 갱신 이력이 남아 **과거분은 옛 값으로 계산**된다(`적용시작일`)

### 지금 지킬 것 3가지

1. 🔴 **법정값을 코드에 넣지 않는다** — 상수도 안 된다. 재배포가 필요하면 실패
2. 🔴 **값마다 `적용시작일`** — 과거 계산이 틀리지 않게
3. 🔴 **노무사 검토 전에는 "법정 기준"이라고 화면에 단정하지 않는다** — *"참고용 산정값, 최종 확인은 사업장 책임"*
