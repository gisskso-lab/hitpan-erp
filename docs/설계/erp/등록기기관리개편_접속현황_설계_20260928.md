## §2 [걷기] 한 배포 묶음 — 다섯 곳

| # | 자리 | 지금 | 바꾼 뒤 |
|---|---|---|---|
| ① | 새 기기 줄 생성 `TenantDeviceService.cs:759` | 스위치 켜짐 → `pending` | 늘 `approved`(메인PC 표식·본사 동기화가 이 줄을 쓰므로 **줄은 계속 만든다**) |
| ② | 새 기기 한도 거절 `:716`(컴퓨터) · `:728`(휴대폰) | 칸이 차면 `(false, "인증기기 한도초과…", null)` → **로그인 401** | 거절 두 갈래를 걷는다. 기록 `LogDeniedAsync` 도 함께 |
| ③ | 등록 결과 `RegisterOrRefreshAsync` 반환 (`:170`) | 대기·폐기·거부 줄이면 `allowed=false` → 로그인 응답에 `DeviceAwaitingApproval=true` | **반환 직전 한 자리**에서 `allowed=true`. 안의 메인PC 구제·표식 정리 갈래(`:274-501`)는 **무접촉** — 줄 상태는 표시용으로만 남는다 |
| ④ | 업무 API 통행 `DeviceAuthMiddleware.cs:77` | 스위치 켜짐 → 인증키 없으면 403 `forbidden_device_auth` | 스위치를 읽지 않고 **늘 통과**(`:83-87` 갈래). 클래스·등록 줄(`Program.cs:660`)은 남긴다 — 되돌림 판독용 |
| ⑤ | 직원 관문 `MainLayout.razor:67` `<DeviceAuthGate/>` · `Login.razor:372-377` | 대기 표시 → 관문 → 대표 승인까지 3초 폴링 | 렌더 한 줄과 로그인 분기를 걷는다. 컴포넌트 파일은 §2-2 C 묶음에서 정리 |
| (화면) | `DeviceManagePage.razor` | 승인·거부·재발급·인증키·QR·슬롯창·KPI·[기기 폐기] | §6 으로 재구성 |

- 🔴 **쪼개면 사람이 갇힌다.** ①만 → ④가 인증키 없는 새 직원을 403. ④만 → ⑤가 `pending` 줄을 보고 관문. ①④⑤만 → ②가 칸 찬 회사의 새 직원을 **로그인에서** 401. ⇒ **①~⑤ + 화면 = 한 커밋 묶음 · 한 게시.**
- `AuthController.cs:180-196`(대기·401 분기)은 ③ 뒤에 **닿지 않는 줄**이 된다. 이 파일은 1 이 로그인 흐름을 고치는 자리라 **이번엔 손대지 않는다**(겹침 회피). 정리는 1 담당과 합의 후 C 묶음.
- ③ 을 AuthController 가 아니라 서비스 반환 한 자리에서 하는 이유: 로그인 흐름(1 소유)에 줄을 안 더하고, `:274-501` 의 메인PC 구제 갈래(P0 3회 이력)를 한 줄도 안 건드린다.
- 휴대폰 QR 등록(`[모바일기기 등록]` · `MobileDeviceRegisterPage.razor`)은 **같은 묶음에서** 입구를 걷는다. 휴대폰은 로그인만 하면 ①로 들어온다. 옛 QR 주소로 오면 *"이제 등록 없이 휴대폰에서 로그인하시면 됩니다."* + [로그인] 만 보여준다.

## §3 [스위치] D-6 — `appsettings.json` 을 못 고치는 채로 걷기

| | (가) 코드가 그 값을 읽지 않는다 — **권고** | (나) 회사별 DB 설정으로 옮기고 끈다 |
|---|---|---|
| 방법 | `HitPan.Application.Common` 에 값 하나(`static readonly bool`)를 두고 ①·④ 두 자리가 **같은 값**을 본다. `DeviceApproval:Enabled` 는 파일에 남지만 아무도 안 읽는다 | `tenant_settings` 에 새 칸 DEFAULT 0 + 출하 DDL(#36) · 미들웨어가 요청마다 읽음 |
| 되살리기 | 이전 판 재게시 | 행 한 줄 UPDATE |
| 비용 | 없음 | DDL 1 · **매 요청 DB 조회가 미들웨어에 생긴다**(P0 3회 자리) · 승인 화면·관문 코드를 숨긴 채 계속 유지 · 1 이 겪은 「행 없는 고객사」 문제(F-4 설계 §5)를 그대로 다시 짊어진다 |
| 권고 근거 | 사장님이 승인을 **걷어냄**으로 확정(6번 지시) — 켰다 껐다 할 운영 수요가 없고, 되살리는 길은 이전 판 재게시로 충분하다 | |

- 🔴 `const` 금지 — `const bool false` 는 닿지 않는 코드 경고(CS0162)를 낸다(#19). `static readonly`.
- 🔴 파일에 `"Enabled": true` 가 그대로 보이므로 **G-AR1 은 설정을 `true` 로 넣고** 잰다 — 「읽지 않는다」를 동작으로 증명한다.

## §4 [조회 API] 추가형 2개 — 읽기만

| | `GET api/access-status/current` | `GET api/access-status/alerts` |
|---|---|---|
| 누가 | 대표계정(`account_type = tenant_admin`)만 — `DeviceController.cs:199` 와 같은 검사. 직원은 403 | 같음 |
| 테넌트 | `HttpContext.Items["TenantId"]` 만(#2). **쿼리 파라미터에 tenant 없음** | 같음 |
| 읽는 곳 | 계정 목록(`users` — 이름·아이디 열은 **착수 시 DESCRIBE**, #13) LEFT JOIN `user_sessions` `WHERE tenant_id AND expires_at > UTC_TIMESTAMP(6)` → `user_id`·`device_kind`·`login_at`·`last_active_at` · 브라우저 = `audit_trail` `action_type='login'` `entity_id = session_id` 의 `after_value.$.user_agent` | `security_alerts` `WHERE tenant_id AND alert_type IN (고객용 목록) AND created_at >= 기간` |
| 열 출처 | **1 의 설계 §6·§10 을 따른다**(`audit_trail` 재사용 · IP 안 씀). 1 이 바뀌면 여기를 맞춘다 | 고객용 목록 = `pc_session_forced_out` + (1 의 K-5 가 (가)면 그 시도 유형). `session_insert_failed` 같은 기술 경고는 **넣지 않는다** — 대표가 할 일이 없다 |
| 돌려주는 모양 | 사람마다 `{이름, 아이디, 컴퓨터: {로그인 시각, 마지막 사용, 브라우저} 또는 없음, 휴대폰: [...]}` + 합계 2개 | `{시각, 이름, 종류, 문장}` — **문장은 서버가 한글로 만든다**(§6-2) |

- 시각: `user_sessions` 는 UTC, `audit_trail`·`security_alerts` 는 DB 기본값(1 의 §10 주의). **API 한 곳에서** 한국 시각으로 맞춰 내보낸다 — 화면은 받은 그대로 쓴다.
- 브라우저 표시: 저장된 문자열에서 「엣지·크롬·웨일·사파리·삼성 인터넷·파이어폭스」 × 「윈도우·맥·안드로이드·아이폰」만 뽑는다. 못 뽑으면 *"알 수 없음"*. **표시용 — 어떤 판정에도 쓰지 않는다.**
- 한 연결에서 `QueryMultipleAsync`(#16 — `Task.WhenAll` 금지). 새 인터페이스를 만들면 구현체 grep(#12).
- #18: 로컬 DB 만 읽는다. 본사 동기화 무접촉(D-8).
- ⚠️ `expires_at IS NULL` 인 옛 줄: 1 이 INSERT 에서 늘 채우는지에 따른다 — **1 확정 후 맞춤**(지금은 「보이지 않음」으로 둔다).
