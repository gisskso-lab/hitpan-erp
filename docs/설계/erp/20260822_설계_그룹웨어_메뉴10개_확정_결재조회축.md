## 1. 오더를 이렇게 이해했다 (명문화)

### 1-1. 사장님이 정한 것은 메뉴 개수가 아니라 **축**이다

```
문서를 만드는 곳  =  각 업무 메뉴 (4·6·7·9·10)
문서를 결재하는 곳 =  1번 결재조회  ← 여기 하나로 모인다
결과가 보이는 곳  =  다시 각 업무 메뉴 (상태 반영)
```

⇒ **만드는 곳과 결재하는 곳을 분리한다.** 결재는 **한 군데서만** 한다.
⇒ 각 화면은 **그리드(목록) + 문서생성** 두 가지만 한다. **결재 버튼을 안 만든다.**

### 1-2. 이 축의 값어치

지금은 *"내 휴가 결재가 어디 있지"* 를 찾으려면 화면을 돌아다녀야 한다.
앞으로는 **1번만 열면 전부 있다.** 직원이 배울 게 하나로 준다.

> 히트판 정신: *"이 화면, 처음 보는 사람이 혼자 쓸 수 있냐?"*

### 1-3. 🔴 사장님이 못박으신 두 원칙 (모든 판단의 잣대)

> **① 라인은 하나, 창구만 구분** (2026-08-22)
> *"결재라인은 하나로 통합하되, **필터링으로 결재**를 하면되고, **창구만 구분**하자는거야.
> 메뉴가 많으면 불편해. **메뉴 최소화 시키고 직관적으로** 바꾸는게 더 효율적이지"*
>
> **② 기능·컬럼은 안 없어진다** (2026-08-22)
> *"**컬럼이 삭제되거나 기능이 없어지는게 아님. 메뉴에 녹아들어가게** 하는거지"*
>
> **③ 새 화면 만들지 마라** (2026-08-22)
> *"**불필요하게 화면을 더 만들지 말고 이미 있는 화면으로 링크이동**"*

🔴 **이 셋이 잣대다.**
- 결재선을 쪼개는 안 ⇒ ① 위반 · **폐기**
- 기능·컬럼을 빼는 안 ⇒ ② 위반 · **폐기**
- 메뉴·화면을 늘리는 안 ⇒ ①③ 위반 ⇒ **필터 값·탭·링크**로 푼다

⇒ 🟢 **이 설계에서 빠지는 화면은 0개다.** 17개가 10개가 되는 것은
   **화면이 없어지는 게 아니라 메뉴에서 안 보이고 안으로 들어가는 것**이다(§3-1).
   ⚠️ 내린 주소는 **리다이렉트로 살린다**(8/13 원칙 · 404 금지) — 즐겨찾기한 직원이 있다.

## 5. 🔴 1번 결재조회 — 이 설계의 심장

### 5-1. 무엇을 하나

```
[전]  결재 대기 · 내가 보낸 결재 · 완료된 결재     메뉴 3개, 필터 0개
[후]  결재조회 1개  +  상태 콤보  +  문서종류 콤보
```

### 5-2. 🔴 지금 API 가 필터를 아예 안 받는다

`ApprovalController.cs:106`·`:119`·`:132` — **파라미터 0개**(실측).
⇒ 통합은 **메뉴만 합치는 게 아니라 화면·API 양쪽 신규 작업**이다.

### 5-3. 🔴 문서종류 필터를 `DocTypeLabels` 에서 뽑지 마라

작9 **이전에는 ERP 7종이 살아 있다.** 지금 뽑으면 결재조회에 견적서·발주서가 섞인다.
⇒ **작9 를 먼저** 하거나, **그룹웨어 8종을 별도 정의**한다.

### 5-4. 상태 반영 (사장님 지시 3단계)

```
목록조회 → 문서생성 → [1번] 결재 → 목록에 상태반영
                                    ↑
                        🔴 ProcessAsync 원본반영 블록
```

🔴 **이 마지막 화살표가 오늘 봉합한 P0 그 자체다.**
`expense` 에만 원본반영 블록이 없어서 *"승인했는데 목록이 안 바뀌는"* 일이 **이미 출하됐다.**

⇒ **4·6·7·9·10 문서유형 전부** `ProcessAsync` 에 원본반영이 있는지 확인해야 한다.
   **없으면 사장님이 지시하신 3단계의 마지막 칸이 비는 것이다.**
