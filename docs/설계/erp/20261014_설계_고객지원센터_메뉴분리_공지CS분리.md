### 🔴 이 차수의 축 (사장님 교정 10/14)

> **공지사항 ↔ CS쪽지 분리**가 축이다. 「과금결재 안내」는 본사가 쪽지를 보내는 **명분의 한 예**일 뿐
> 축이 아니다 — 그쪽으로 새지 않는다(일정표 §6-5 · 결-A). 과금·프로모션은 ②의 **내용**이고 **분류가 아니다.**

### 통과 기준 (이 둘로 판정한다)

> ① **한 화면 완결** — 스크롤 없이 공지 목록의 핵심(제목·종류·날짜·안읽음)이 한 줄에 선다.
> ② **처음 보는 사람이 혼자 쓰나** — 10/12 사장님 반려의 뿌리가 「공지와 내 문의를 섞어 보여준 것」이었다.

## §2 바뀌는 모양 — 메뉴 구조

```
[지금]                              [바꾼 뒤]
CS 요청            /support/cs      고객지원센터  (MudNavGroup · 묶음 if 밖)
                                    ├ 고객지원 요청      /support/cs      ← 주소 그대로
자료관리 (관리자만)                 │   (쪽지 보내기 + 내 문의 목록 조회)
├ …                                 ├ 본사공지사항      /support/notice  ← 신설
├ 최신 버전 확인/업데이트            ├ 최신 버전 확인/업데이트  /data/update    ← @if (_isTenantAdmin)
└ 이전 버전으로 되돌리기             └ 이전 버전으로 되돌리기  /data/rollback  ← @if (_isTenantAdmin)
                                    자료관리 (관리자만)
                                    └ … (업데이트 2종만 빠진다)
```

- 「고객지원센터」 묶음 **자체는 전원이 본다**(직원도 쪽지를 보낸다) · 업데이트 2종만 가드 안.
- 🔴 가드는 **편의**다. 직원을 실제로 막는 것은 서버의 `TenantAdminOnly`+`MainPcOnly` 두 줄이고,
  그 줄은 메뉴를 어디로 옮겨도 한 글자도 안 바뀐다(선행검증 §1-4). 메뉴 숨김은 종전 자료관리와 **같은 수준**이다.
- 자료관리 묶음은 **지우지 않는다** — 2줄만 빠지고 나머지는 그대로(#1).

## §3 서버 — `origin` 질의칸 + 쪽별 `LIMIT` (S-2 · C-4 안 (가))

```
GET api/cs/requests                   → 종전 그대로 (전체 · 회귀 0)
GET api/cs/requests?origin=hq         → 본사가 보낸 것만
GET api/cs/requests?origin=local      → 내가 쓴 것만
그 밖의 값                            → 전체 (낯선 값에 화면을 비우지 않는다)
```

| 항목 | 설계 |
|---|---|
| 서명 | `List(string? origin, CancellationToken ct)` — **추가만**(#1 · 옛 호출은 null 로 들어온다) |
| 칸이 없는 DB | `HasOriginColumnAsync()` 가 거짓이면 **WHERE 에 origin 조건을 달지 않는다** — `'local'` 대입은 SELECT 쪽에만 둔다. 없는 칸을 WHERE 에 넣으면 1054 로 터진다 |
| `LIMIT` | 쪽별로 **각자 센다** — 한 쪽이 다른 쪽을 밀어내지 못한다. 전체 호출은 종전 200 |
| 테넌트 | `HttpContext.Items["TenantId"]` 만 쓴다 · `origin` 은 매개변수로 받지만 **tenant 는 절대 매개변수로 안 받는다**(#2) |
| 정렬 | `ORDER BY r.created_at DESC` 무변경 |
| 숫자 칸 | `COALESCE(o.attempt_count, 0)` 유지 · `replyCount` 는 서브쿼리라 NULL 이 안 나온다 — **서버가 0 을 보장한다**(C-6) |

🔴 **(나) 클라이언트 걸러내기만으로 끝내지 않는다.** 200행을 받아 둘로 그리면 공지가 쌓일 때
내 문의가 밀려 사라지는 A-1 이 그대로 남는다. 「된다」로 적으면 안 되는 자리다.

## §4 모델 — 사이드바 안읽음 3칸 (S-4 · C-2 · 결-C)

- `Sidebar.razor:567` `CsUnreadResponse` 에 `HqCount`·`ReplyCount` **추가만**. 서버는 바꾸지 않는다(이미 내려준다).
- 숫자를 **하위 둘에 각각** 붙인다 — 「본사공지사항」 = `HqCount` · 「고객지원 요청」 = `ReplyCount`.
- 묶음 머리(「고객지원센터」)에는 **합계를 쓰지 않는다** — 하위 숫자와 겹쳐 보여 어느 쪽인지 사라진다.
- 못 읽으면 **세 칸 모두 0** — 안 보여 준다(종전 규칙 유지: 틀린 숫자는 안 보여주는 것보다 나쁘다 · #15 로그 한 줄).
- 🔴 **옛 판 서버와 섞여도 산다** — 칸이 없으면 역직렬화가 0 을 준다(`CsReplyBadge.razor:91-92` 주석과 같은 성격).
- 🔴 **이 칸은 직렬화→역직렬화로 잰다**(C-6 · G-W9-6). 10/12 에 사전으로 읽어 통과하고 화면이 터진 전례가 있다.

## §5 화면 — ② 「본사공지사항」 신설 · ① 생존

| 항목 | ① 고객지원 요청 `/support/cs` | ② 본사공지사항 `/support/notice` |
|---|---|---|
| 상태 | **그대로 산다** — 주소·칩·상태 축 무변경(#1) | **신설**(지금 grep 0건) |
| 질의 | `?origin=local` | `?origin=hq` |
| 쓰기 | CS 요청 쪽지 보내기 **유지** | **없다** — 읽기 전용(본사가 보내는 것이다) |
| 목록 한 줄 | 종류 · 미리보기 · 날짜 · 답N · 상태 · 본사상태 (종전) | **제목 · 종류 · 날짜 · 안읽음** (§9 규격표) |
| 상세 | `/support/cs/{RequestId}` | **같은 상세를 쓴다**(S-3) |
| 빈 상태 | 「보낸 문의가 없습니다.」(종전) | §8 의 사람 말 한 줄 |

- ②의 「종류」는 **결-D ⓑ 용도 칸**이 들어오면 그 값으로 채워진다(작3 거리 · 이 차수는 칸을 만들지 않는다).
  이 차수에서는 용도 칸이 없으므로 「본사 안내」 한 종류로 서고, 칸이 생기면 **목록 한 줄의 그 자리**가 채워진다 — 자리를 미리 비워 둔다.
- ①의 목록에서 본사 안내를 **빼지 않는 선택지도 있었으나 택하지 않는다** — 섞어 보여준 것이 10/12 반려의 뿌리다.
  단, §8 의 보장을 위해 **전체 호출 경로(`origin` 없음)는 코드에 그대로 남는다.**

## §8 🔴 빈 화면을 견딘다 (S-8 · C-1 못 쟀음)

- **못 쟀다**: 이 PC 실물 DB 에 `origin`(DB-144) 칸이 적용됐는지 검증팀이 못 쟀다 — 설치 계정 권한 밖이고 사장님 승인 사안이다(선행검증 §3·C-1).
- **그래서 설계가 견딘다**: 칸이 없으면 서버가 모든 행에 `'local'` 을 주므로 ②가 **0건**으로 선다. 터지지 않는다.
- ⇒ ① **0건일 때 사람 말 한 줄**을 세운다. 보기: **「아직 본사에서 보낸 안내가 없습니다.」**
  🔴 「칸이 없다」·「마이그」·「컬럼」·「DB」 같은 말은 **쓰지 않는다**(#23 · 고객 노출에 개발 용어 금지).
- ⇒ ② 🔴 **보장**: 옛 통합 목록(`/support/cs` · `origin` 없는 전체 호출 경로)을 **죽이지 않는다.**
  그러므로 ②가 0건으로 서는 경우에도 본사 안내는 ①의 목록에 「본사에서 보냄」 칩을 달고 그대로 보인다 —
  **어떤 경우에도 공지를 아예 못 보는 상태는 생기지 않는다.**
- 이 차수는 **새 마이그를 만들지 않는다**(작3 거리). C-1 측정은 [4] 검증·사장님 실측 항목으로 넘긴다.

### §9-3 목록 한 줄에 서는 것 · 한 화면 완결

```
┌──────────────────────────────────────────────── 860px ────────────┐
│ ● 제목(14/600, 말줄임)                       [종류] [안읽음]      │   ← 1행
│   2026-10-14 14:30 · 본사                                         │   ← 2행 메타 12/tertiary
├───────────────────────────── --hp-border-subtle ──────────────────┤
```

- 🔴 **한 줄 = 2행 묶음**(제목행 + 메타행)이고, 칩은 **제목행 오른쪽 끝에 모은다** — 줄이 늘면 스크롤이 생긴다.
- 🔴 스크롤 없이 보이는 범위 = **1024×768 에서 최소 8행**. 행 높이가 이 숫자를 넘기면 여백을 `--hp-space-2` 로 줄인다.
- **빈 상태**: 카드 안쪽 `--hp-space-6`(24px) 여백 · `--hp-fs-body` · `--hp-text-tertiary` · 그림·아이콘 없이 **한 줄만**(§8 문구).
- **읽는 중 상태**: `MudProgressLinear Indeterminate` — ①과 같은 모양(새 모양을 만들지 않는다).
- 🔴 게이트가 칸·간격·글꼴을 **못 잰다**(렌더 하네스 0건) ⇒ 작업지시서 마지막 절의 **사장님 실측 항목표**가 유일한 판정이다.
