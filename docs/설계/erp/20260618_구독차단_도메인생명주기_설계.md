## 0. 대원칙 — "도메인은 살려놔야 한다"

사장님 격언: **"고객이 실수로 구독 결제를 못 한 걸 수도 있으니."**

- 구독 끊겼다고 **도메인(터널)을 바로 끊으면 안 됨** → 고객이 결제하러 들어올 길까지 막는 사고.
- 차단은 **도메인 레벨이 아니라 ERP 화면 레벨**에서.
- 결제 동선(버튼)은 **항상 열려 있음**.

---

## 1. ERP가 구독 상태를 아는 법

- **ERP 로그인 성공 직후, 백오피스 API(`back.hitpan.kr`)에 "이 회사 구독 active?"를 실시간 조회.**
- 구독 데이터는 **ERP DB가 안 가짐** (헌법 #22·#35). 백오피스가 진실의 원천.
- active → 통과 / 만료 → 차단 화면.
- ERP 설정에 `BackofficeApiBaseUrl: back.hitpan.kr` 통로 이미 존재 → 이걸 사용.

---

## 2. 구독 끊긴 화면 (ERP 프론트, Blazor)

차단 방식 — **A·B 둘 다 사장님 OK** (둘 다 구현 또는 둘 다 열어둠):

- **A안 — ERP 화면 팝업 잠금**: ERP 화면 진입하되 모달 팝업. 결제 버튼만 활성, 뒤 화면 동작 전부 비활성. 닫기 없음(강제). 고객이 자기 데이터(미수금·작년자료)는 볼 수 있음. 히트판 정신(쓰기 쉬움)에 가까움.
- **B안 — 로그인 즉시 랜딩 결제화면 리다이렉트**: 로그인하자마자 랜딩페이지 구독결제 안내로 튕김. 데이터 안 보임. 동선 단순·명확. 헌법 #35(랜딩=결제 입구)와 자연스러움.

### 화면 버튼 2개 (필수)
- **[구독결제 연장]** — 결제하면 구독 복구.
- **[구독취소]** — 고객이 명시적으로 그만둔다 선택.

---

## 3. 도메인 생명주기 (핵심)

| 상황 | 도메인 처리 | 이유 |
|---|---|---|
| 구독 만료(미결제) | **살려둠** | 실수로 못 냈을 수 있음 → 결제하러 들어와야 함 |
| 만료 후 **한 달까지** | **유지(유예)** | 그 안에 결제하면 복구 |
| 만료 후 **한 달 경과** | **강제 삭제** | 장기 미결제 = 도메인 회수 |
| **[구독취소] 버튼 클릭** | **즉시 삭제** | 고객이 직접 취소 의사 → 바로 회수 |

→ **도메인 삭제 트리거 2개**: ① [구독취소] 클릭(즉시) ② 미결제 한 달 경과(자동 배치/스케줄러).

## 4. 만들 것 목록 (2단계 범위)

### 백오피스 (클라우드, `HitPan.Backoffice.API`)
1. **구독상태 조회 API** — ERP 로그인 시 호출. "이 tenant 구독 active/만료?"
2. **도메인 사용중지/삭제 기능 신규 구현** — ⚠️ **현재 없음**. (PM 정정: 기존 `TenantsAdminController.suspend`는 status 플래그만 바꿀 뿐 실제 도메인 차단 아님. `RevokeByDomainAsync`는 있으나 생명주기 연동 필요.)
3. **[구독취소] → 도메인 즉시 삭제** 연동.
4. **만료 후 한 달 경과 자동 도메인 삭제 스케줄러/배치.**

### ERP 프론트 (`HitPan.Web`, Blazor)
5. 로그인 시 백오피스 구독상태 조회.
6. 만료 시 차단 화면 (A 팝업 / B 리다이렉트) + 버튼 2개.

### 관련 기존 코드
- `src/HitPan.Backoffice.API/Controllers/TenantsAdminController.cs` — suspend(149줄), RevokeByDomainAsync(247줄)
- `src/HitPan.Backoffice.API/Services/CloudflareDomainService.cs` — 도메인/터널 발급·관리
- `src/HitPan.Backoffice.API/Controllers/TenantDomainController.cs`

## 5. 1단계와의 관계

- 1단계(ERP tenant 흔적 제거)에서 ERP의 결제·구독 테이블·코드를 들어냄.
- 그 후 구독 관리는 **전부 백오피스 + 랜딩**으로 이동. ERP는 화면(차단 UI)만.
- 1단계 때 만든 P1 게이트(local_subscription.status 검사)는 **이 설계로 대체** — ERP 로컬 status가 아니라 백오피스 실시간 조회 + 화면 차단.
