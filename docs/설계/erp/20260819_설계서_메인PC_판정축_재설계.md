## 1. 🔴 실측 — 축이 왜 거짓이 되는가

> 헌법 #32 에 따라 어제 결론을 받아쓰지 않고 코드로 다시 확인했다.

### 1-1. 판정식은 **세 곳에 같은 모양**으로 있다

| # | 자리 | 무엇을 막나 |
|---|---|---|
| ① | `src/HitPan.API/Controllers/AuthController.cs:136-140` | 메인PC 자동 승인 (`IsLocalConsole`) |
| ② | `src/HitPan.API/Controllers/DeviceController.cs:106-113` | 자료관리 화면 (`is-main-pc`) |
| ③ | `src/HitPan.API/Controllers/AuthController.cs:509-512` | 로컬 업데이트 상태 |

셋 다 **같은 두 조건**이다 — 터널 헤더가 없을 것 + 소켓이 loopback 일 것.

### 1-2. 🔴 그 두 조건은 **사장님 경로에서 반드시 거짓**이다

사장님과 고객은 `https://test1.hitpan.kr` 로 여신다. **메인PC 앞에 앉아서도 그렇다.**

그 요청은 브라우저 → 인터넷 → Cloudflare → cloudflared → API 로 온다.
⇒ `CF-Connecting-IP` 가 **반드시 붙는다.** ⇒ ①②③ 전부 거짓.

🔴 **결론: 봉합이 틀린 게 아니라, 봉합이 깔린 길로 아무도 안 다닌다.**
`localhost:5257` 로 여는 사람은 **개발 PC 의 우리뿐**이다.

### 1-3. 🔴 그런데 그 조건을 뺄 수도 없다 — 8/10 에 두 번 무너진 자리

터널은 **고객 PC 안에서 돌며 자기 PC 의 localhost 를 다시 부른다**
(`MainPcRegistrationService.cs` 클래스 주석 · `HitPan-Universal.iss:1212` ingress origin).
API 는 loopback 에만 귀를 연다.

⇒ 헤더 배제절을 빼면 **도달한 요청이 100% loopback** 이라 판정이 **항상 참**이 된다.
그러면 **바깥 휴대폰까지 메인PC 를 자칭**한다. 그것이 8/10 에 걷어낸 사고다.

### 🔴 1-4. 이것이 이 문제의 정체

> **접속 경로로는 이 문제를 풀 수 없다.**
> 헤더를 보면 사장님이 막히고, 안 보면 아무나 통과한다. **양쪽 다 사고다.**
> ⇒ 판정축을 **접속 경로가 아닌 다른 축**으로 옮겨야 한다.

이것은 이미 우리가 아는 결론이다 — `MainPcRegistrationService` 클래스 주석이
*"접속 경로를 아예 보지 않는다. **내가 어디서 도나** 를 본다"* 고 **8/10 에 적어 뒀다.**
🔴 **8/18 봉합은 그 결론을 잊고 접속 경로로 되돌아간 것**이다. (받아쓰기 계통 · 헌법 #33)

## 2. 🔴 축을 다시 세운다 — 무엇이 "그 컴퓨터"인가

### 2-1. 서버는 **이미 답을 알고 있다**

`MainPcRegistrationService` 가 기동 때마다 `MAINPC-{해시}` 지문 줄을 심는다
(`MainPcRegistrationService.cs` — `BuildServerFingerprint()`, `MachineName|TENANT_CODE|SLOT_INDEX`).

**그 프로세스가 도는 컴퓨터 = 메인PC.** 이 축은 터널과 무관하다 — 흔들린 적이 없다.

### 2-2. 🔴 그런데 브라우저 줄과 **이어지지 않는다**

| | 서버 줄 | 화면 줄 |
|---|---|---|
| 지문 | `MAINPC-…` (컴퓨터 이름) | `HFPv2-…` (화면·브라우저 특성) |
| `is_main_pc` | 1 | 0 |
| 상태 | approved | **pending** ← 여기서 갇힌다 |

두 지문은 **서로 만들 수 없다.** 일부러 그렇게 갈라 놨다(네임스페이스 충돌 방지).
브라우저는 **컴퓨터 이름을 알 수 없다** — OS 정보 접근이 막혀 있다
(`device-fingerprint.js` — `getDeviceName` 주석).

🔴 **진짜 문제는 이 한 줄이다: 서버는 자기가 메인PC 인 걸 알지만, 그 앞에 앉은 브라우저에게 그것을 증명해 줄 길이 없다.**

## 3. 🔴 설계안 — **판정을 포기하고 순환을 끊는다**
### 3-1. 뼈대 (헌법 #34 — 뼈대 먼저)

> ⚠️ **아래 1차 뼈대는 §3-3 에서 폐기됐다.** 사장님이 터널만 쓰신다는 답변으로 무너졌다.
> **판단 과정을 지우지 않고 남긴다**(헌법 #1) — 다음 사람이 같은 길을 다시 파지 않게.

<details>
<summary>🔴 폐기된 1차 뼈대 — 「서버가 자기 디스크에 표식을 적는다」</summary>

```
[서버 기동] MainPcRegistrationService → 지문을 자기 PC 파일에 적는다
[화면 열림] 브라우저가 API 에 "이 컴퓨터 표식 좀 줘" → 파일을 읽어 돌려준다
[로그인]   브라우저가 그 값을 같이 보낸다 → 서버가 자기 파일 값과 대조
```

**폐기 사유**: 표식을 **건네주는 경로**가 터널로 열려 있다. 그 경로를 loopback 으로 잠그면
사장님은 표식을 **한 번도 못 받으신다**(터널만 쓰시므로) ⇒ 어제와 똑같은 *"아무도 안 가는 길"*.

</details>

#### 🟢 본안 뼈대 — **메인PC 를 알아보려는 시도를 그만둔다**

```
[문제] 대표가 갇혔다 → 자기를 승인해야 풀린다 → 승인 화면이 관문 뒤에 있다 → 못 들어간다
                                                                    ↑ 순환
[본안] 관문이 대표계정에게는 **승인 화면 하나만** 열어 준다
       └ 업무 화면은 그대로 막힌다 (관문의 뜻은 유지)
       └ 메인PC 인지 **묻지 않는다** — 물을 방법이 없으므로(§3-4)
```

🔴 **"그 컴퓨터인가" 를 푸는 대신, 그것을 몰라도 되게 만든다.**

### 3-2. 🔴 왜 이것이 안전한가 — 자칭을 막는 자리

| 반증 질문 | 답 |
|---|---|
| 바깥 휴대폰이 승인 화면에 들어가나? | ⚠️ **대표 비밀번호를 알면 들어간다** — 아래 |
| 그것이 위험한가? | ❌ **대표 계정을 뺏긴 상황은 이미 전면 장악**이다. 기기 관문이 막을 급이 아니다 |
| 자칭할 수 있나? | ❌ 브라우저가 보내는 값이 아니라 **로그인 통과 사실**로 판정한다 |
| 슬롯이 새나? | ❌ 화면 하나를 여는 것이지 **기기가 승인되는 것이 아니다.** 줄을 만들지 않는다 |
| 8/10 처럼 항상 참이 되나? | ❌ 접속 경로를 **아예 안 본다** |

🔴 **판정축이 "어느 컴퓨터인가"(알 수 없다) 에서 "누가 로그인했나"(서버가 이미 안다) 로 바뀐다.**
### 3-3. 🔴 급소 — **표식을 어떻게 건네주는가**

값을 돌려주는 경로가 **터널로도 열려 있으면** 바깥에서 그 주소를 불러 표식을 받아 간다.
⇒ **그때부터 아무나 메인PC 다.** 🔴 **이 자리가 이 설계의 전부다.**

#### 🔴 1차 설계안은 폐기한다 — 사장님 답변으로 무너졌다

1차는 *"값을 주는 경로만 loopback 으로 잠근다"* 였다. 근거는 **한 번은 로컬로 여실 것**이라는
**PM 의 추측**이었다.

> **사장님 답변 (8/19)**: *"테스트1으로 하고 있어."* — **터널만 쓰신다.**

⇒ 그 발급 경로는 **한 번도 실행되지 않는다.** 🔴 **어제 봉합과 똑같이 "아무도 안 가는 길"이다.**
같은 계통을 **하루 만에 두 번** 낼 뻔했다 — 추측을 근거로 삼았기 때문이다.

> ⚠️ **API 는 `127.0.0.1` 에만 귀를 연다**(`HitPan-Universal.iss:2643`). `localhost:5257` 로 여는 것이
> 기술적으로 **가능은 하다.** 그러나 **사장님이 안 그러신다.** 되는 것과 하시는 것은 다르다.

#### 🔴 본안 — 브라우저를 거치지 않는다

표식을 **화면에 건네주지 않는다.** 건네주는 순간 그 경로를 지켜야 하고, 그 경로는 터널로 열려 있다.

> **대신 서버가 자기 파일을 자기가 읽고, 자기가 판정한다.**
> 브라우저는 표식을 **모르고, 보관하지 않고, 보내지 않는다.**

그러면 **무엇으로 그 브라우저가 그 컴퓨터에 있다고 아는가** — 이것이 남는 유일한 질문이다.

**이 프로세스가 이 컴퓨터에서 돈다**는 뜻이다. 필요한 것은 그 줄과 지금 로그인한 화면 줄을
**잇는 근거** 하나뿐이다.

| 안 | 잇는 근거 | 판정 |
|---|---|---|
| A | 접속 경로(loopback·헤더) | 🔴 **폐기** — §1-4. 사장님 경로에서 항상 거짓 |
| B | 브라우저가 보관한 표식 | 🔴 **폐기** — 건네주는 경로가 터널에 열린다(위) |

| 🔴 **""안 연다""** | **P0 는 못 닫는다.** 대표는 **강제경로**(DB 한 줄 + 워치독 재시작)로 푼다 — **이미 있고 8/18 에 실측된 길**이다 |

🔴 **대표 계정은 여럿일 수 있다**(`account_type` 은 **N행** · `is_parent` 는 **JWT 에 없다**).
⇒ **PM 은 ""연다"" 를 권하지 않는다. 사장님 사업 판단이다.**

### 🔴 4-1. `IsLocalConsole` 을 **왜 안 걷어내나** — 그리고 [3-V] 중6

`IsLocalConsole` 축은 **틀린 게 아니라 사장님 경로에서 안 돌 뿐**이다.
`localhost` 로 여는 경우엔 정상 동작한다 ⇒ **걷어내면 그 경우가 죽는다.**

⇒ **그대로 두고, 그 위에 본안 E 를 얹는다.** 🔴 **고장난 것을 고치는 대신, 고장나도 갇히지 않게 만든다.**

#### 🔴 그런데 [3-V] 중6 이 반대 방향을 짚었다 — **그 축이 참이 될 때**

`TenantDeviceService.cs:270-315` 는 `IsLocalConsole && !isMainPc` 이면
① **옛 메인PC 줄을 `revoked` 로 내리고** ② 지금 줄을 `is_main_pc=1, approved` 로 세운다.

**시나리오**: 사장님이 본안 E 로 터널에서 정리한 뒤, 누군가 그 PC 에서 **`localhost:5257` 로 한 번만**
열면(개발자·CS 원격지원이 하는 일) ①이 돌아 **방금 세운 줄을 내리고 표식을 가져간다.**

⚠️ **이번 작업에서 이것을 고치지 않는다.** 이유:

| 왜 | |
|---|---|
| **본안 E 의 P0 는 안 깨진다** | E 는 `is_main_pc` 를 **안 쓴다.** 대표 여부(`account_type`)만 본다 ⇒ 표식이 옮겨가도 **대표는 계속 승인할 수 있다** |
| 영향 범위가 **자료관리(D-2)** 다 | `is_main_pc` 를 읽는 곳은 자료관리와 `DeviceAuthMiddleware.cs:180-186` ⇒ **D-2 결재와 같이 봐야 한다** |
| 🔴 **여기서 손대면 슬롯·과금 줄을 건드린다** | ①은 `status` 를 바꾼다. 돈이 걸린 자리를 P0 봉합에 끼워 넣지 않는다 |

🔴 **그러나 "없는 문제" 로 적지 않는다.** `docs/검증/병렬이슈/…_진범은화면.md` 중6 에 남아 있고,
**D-2 작업지시서의 선행 조건**으로 이월한다(§7-2 ③).

### 🔴 4-2. [3-V] 중5 — **대표계정이 0줄이면 본안 E 도 아무도 못 구한다**

| 근거 (실측) | |
|---|---|
| `installer/hitpan_db_clean.sql:4045` | `account_type … DEFAULT 'tenant_user'` |
| 같은 파일 | `tenant_admin` **시드 INSERT 0건** |

⇒ 프로비저닝이 실패했거나 옛 사고를 겪은 회사는 **`tenant_admin` 이 0줄**이고,
그러면 **관문 안 승인 구역이 아무에게도 안 뜬다.**

#### 🔴 이번 작업에서 **탐지만** 한다 — 고치지 않는다

| 하는 것 | 안 하는 것 |
|---|---|
| 🟢 `tenant_admin` 이 0줄이면 **로그에 경고 한 줄** | 🚫 계정을 **자동 승격**시키기 |
| 🟢 관문 화면에 **"강제 경로" 안내** 노출 | 🚫 관문을 **자동으로 열어주기** |

🔴 **왜 자동 승격을 안 하나**: 누구를 대표로 올릴지 **시스템이 정하면 안 된다**
(헌법 #11 — 권한은 어드민이 직접 · *"100% 자동화는 없다"*).
🔴 **왜 관문을 자동으로 안 여나**: 그것은 **기기 통제를 통째로 끄는 것**이다.

⇒ 그 회사의 탈출구는 **강제 경로**(DB 한 줄 + `Restart-Service HitPanWatchdog`)다.
그것은 **이미 있고 8/18 에 실측으로 확인됐다**(1.2.87 `force-update.ps1`).
🔴 **관문 화면이 그 안내를 보여준다** — 갇힌 사람이 **다음에 뭘 할지 알게** 하는 것이 이번 몫이다.
## 5. 🔴 검증 설계 — **"고쳤나" 가 아니라 "갔나"**

> `feedback_gate_must_test_behavior` (가짜게이트 누적 9번) · `project_fixed_vs_delivered_gap`

### 5-1. 🚫 이번에 **쓰지 않을** 게이트

| 금지 | 왜 |
|---|---|
| 문자열이 소스에 있나 검사 | 8번째 가짜게이트가 정확히 이것이었다 (`/api/appversion`) |
| 하드코딩 주소를 하드코딩 주소와 대조 | **둘 다 틀려도 통과**한다 |
| 함수 반환값으로 판정 | 그 함수가 판정 주체다 — 자기가 자기를 시험한다 |

### 🔴 5-1-1. **로컬(loopback)로 시험하는 것** — 이번의 가장 큰 함정

> **사장님 (8/19)**: *"로컬로 두고 테스트를 하면 당연히 안되지."*

🔴 **이것은 "틀린 답이 나온다" 가 아니다. 그보다 나쁘다.**

로컬에서는 `IsLocalConsole` 이 **참**이다 ⇒ **8/18 봉합(`TenantDeviceService.cs:269`)이 이미 돈다.**
⇒ 대표는 로컬에서 **원래부터 안 갇힌다.**

| 무엇 | 로컬에서 | 터널에서 |
|---|---|---|
| D-1 **있을 때** | ✅ 통과 | ✅ 통과 |
| D-1 **없을 때** | ✅ **통과** ← 🔴 여기 | ❌ 갇힘 |

🔴 **로컬 게이트는 D-1 이 있으나 없으나 초록불이다.**
**시험 대상을 시험하지 않는다** — 옆에 있는 옛 봉합이 초록불을 만들어 준다.

> 🔴 **그리고 그 초록불은 "통과했다" 고 보고된다.**
> 어제 게이트 5/5·반증 3회가 정확히 이 모양이었다. **초록불의 출처를 안 물었다.**

⇒ **모든 게이트에 터널 헤더를 붙인다.** 로컬 게이트는 **한 건도 만들지 않는다.**
붙이지 않은 게이트는 통과해도 **판정 근거로 쓰지 않는다.**

### 5-2. ✅ 이번에 쓸 게이트 — **대조실험** (4차 · [3-V] 2회 반영)

> 🔴 **전제 ①**: 전부 `CF-Connecting-IP` 를 붙여 돌린다 (= 사장님 경로).
> 🔴 **전제 ②**: **화면 축에 건다.** 서버 축에 걸면 §5-2-1 대로 **또 가짜가 된다.**
> 🔴 **전제 ③(4차 신설)**: **"승인됐나" 로 끝내지 않는다. "그 다음에 일할 수 있나" 까지 본다.**

#### 🔴 5-2-1. [3-V] 1회차가 잡은 것 — **2차 게이트는 가짜가 될 뻔했다**

2차 설계의 `G-E`(봉합 빼면 FAIL)를 **서버에 돌리면**, 봉합을 빼도
`DeviceAuthMiddleware.cs:225-231` 옛 대표예외와 `:41` Bypass 가 남아 **여전히 PASS** 한다.

> ⇒ 겨눌 것은 *"`DeviceAuthGate` 가 승인 구역을 그리는가"* 이지 *"서버가 200 을 주는가"* 가 아니다.

#### 🔴 5-2-2. [3-V] 2회차가 잡은 것 — **G-A 만으로는 갇힌 것을 못 잡는다**

E 는 **승인까지는 성공**한다. 그런데 **열쇠를 안 챙겨** 업무 화면이 전부 403 이었다.
🔴 **G-A(승인 구역이 뜨나)가 초록불이어도 사장님은 갇히신다.**

> 🔴 **"됐나" 와 "그 다음에 되나" 는 다른 질문이다.** 아래 **G-I·G-J** 가 그 자리를 겨눈다.

| G | 무엇 | 통과 조건 |
|---|---|---|
| G-A | 터널 + **대표** + `pending` | ✅ 관문 안에 승인 구역이 뜬다 |
| G-B | 터널 + **직원** + `pending` | ❌ 승인 구역 **안 뜬다** |
| G-C | 🔴 **승인 전** 업무 API 요청 | ❌ **업무 화면이 안 그려진다** ← 🔴 4차에서 문구 교정(§F-3) |
| G-D | 터널 + 대표 + 기기 `approved` | ❌ 관문 자체가 안 뜬다 (종전 무변경) |
| G-E | 🔴 **봉합 빼고 G-A** | 🔴 **FAIL 이 나야 한다 — 가장 먼저 확인** |
| G-F | 🔴 로컬 + 봉합 뺀 상태 | ⚠️ **통과할 것이고 그것이 정상** — 초록불 출처 증명 |
| G-G | 🔴 `account_type` **화면에서 위조** | 🔴 **서버가 거부** ([3-V] 1회차 경8) |
| G-H | 🔴 **`tenant_admin` 0줄** | ⚠️ 승인 구역 대신 **안내**가 뜬다 ([3-V] 1회차 중5) |
| ~~G-I~~ | ~~승인 직후 열쇠 보관~~ | 🔴 **폐기** — F-1 이 폐기됐다(본안 G 는 열쇠를 안 만진다) |
| **G-J** | 🔴🔴 **터널 헤더 + 승인 직후 업무 API 호출** | 🔴 **200 이어야 한다** — 403 이면 **관문만 풀고 갇힌 것** |
| **G-N** | 🔴🔴 **남의 `device_id`** 를 헤더에 넣고 업무 API | 🔴 **403** — 8/18 좁힘이 **유지되는지**(H 는 미들웨어 무변경이므로 **그대로여야** 한다) |
| **G-O** | 🔴 `is_main_pc=0` + `approved` + **열쇠 보유** + 터널 | 🔴 **200** — 본안 H 가 여는 자리 |
| **G-P** | 🔴 `is_main_pc=0` + **`pending`** + 자기 줄 | 🔴 **403** — 승인제가 살아 있는지 |
| ~~G-Q~~ | ~~`user_id` NULL 판정~~ | 🔴 **폐기** — G 가 반려돼 `user_id` 를 판정에 안 쓴다 |
| **G-R** | 🔴 **열쇠를 복사해** 다른 기기에서 업무 API | ⚠️ **통과한다 — 그리고 그것을 기록한다.** 이번 차수에 안 막는다(§3-4-2) |
| **G-K** | 🔴 승인 버튼 **연타** | 🔴 두 번째 호출이 **안 나가야 한다** (F-4 · 열쇠 유실 방지) |
| **G-L** | 🔴 **다른 줄**(`ConfirmCode` 불일치)을 승인 | ⚠️ 관문이 **안 풀린다** — 그리고 화면이 **그 사실을 알려준다** (F-2) |
| **G-M** | 🔴 **직원 기기를 승인한 뒤** 대표가 업무 API 호출 | 🔴 **200 이어야 한다** — 본안 G 는 열쇠를 안 만지므로 **영향이 없어야** 한다 |

🔴 **G-J·G-N 이 이번 설계의 두 수문장이다.**
· **G-J** = *대표가 실제로 일할 수 있게 됐나* (열려야 하는 것)
· **G-N** = *8/18 좁힘이 그대로인가* (닫혀 있어야 하는 것)
🔴 **둘 중 하나만 보면 안 된다.** G-J 만 보면 문을 통째로 연 것을 못 잡고, G-N 만 보면 P0 가 안 닫힌다.
· **G-J** = [3-V] 2회차가 잡은 자리 — *자기를 승인한 뒤 일이 되나*
· **G-M** = PM 선제 적발 자리 — *남을 승인한 뒤에도 **내** 일이 되나*

**G-A·G-I 가 초록불이어도 G-J·G-M 이 빨간불이면 사장님은 갇히신다.**

🔴 **G-E 는 여전히 가장 먼저.** FAIL 안 나면 초록불의 출처를 모른다.

## 7. 🔴 결재 요청

### 7-1. 🔴 설계 방향 — 이것부터

> **"메인PC 를 알아보는 것" 을 포기하고, "대표가 안 갇히게" 로 목표를 바꾼다.**

터널만 쓰시는 환경에서 서버가 스스로 그 컴퓨터를 알아낼 방법이 **없다**(§3-4).
없는 것을 있는 척 짜면 어제와 같은 일이 반복된다.

⇒ 🔴 **사장님 결재 필요** — 자동 판정을 **포기**하는 결정이다.

### 🟢 7-1-1. 3차에서 달라진 것 — **더 작아졌다**

[3-V] 반증 뒤 본안이 **E** 로 바뀌면서 손대는 자리가 줄었다.

| | 2차 (D-1) | 🟢 3차 (E) |
|---|---|---|
| 서버 미들웨어 | 대표 예외 **추가** | 🟢 **무변경** (이미 있다) |
| `MainLayout.razor` | `@Body` 렌더 조건 **변경** | 🟢 **무변경** |
| 라우팅 · 주소 대조 | 필요 | 🟢 **없음** |
| 새 API · DDL | 없음 | 🟢 **없음** |
| 실제 변경 | — | **관문 컴포넌트에 구역 하나 + `gate-status` 응답에 값 하나** |

🔴 **4차 정정**: 위 표의 `_gateActive` **무변경**은 **취소한다.** [3-V] 2회차 치명3 —
`_gateActive` 는 `_awaitingApproval` 의 **파생값**이라, 그것을 안 건드리면 **관문이 안 풀린다.**

⇒ 🔴 **G-C 를 "관문이 유지되나" 가 아니라 "업무 화면이 안 그려지나" 로 다시 썼다**(§5-2).

🔴 **관문(`_gateActive`)을 안 건드리는 것이 본안 E 의 핵심이다.** 그래서 G-C 가 수문장이다.
