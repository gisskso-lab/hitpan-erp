## §3 [조회] 서버 — 9/28 §4 를 이렇게 고친다

### 3-1 `current` (접속된 기기 · 로그인 상태)
- 9/28 §4 왼쪽 열 그대로. 추가 두 가지: ㉠ 「로그인 상태」 = `user_sessions.is_active = 1 AND expires_at > UTC_TIMESTAMP(6)` (9/28 은 `expires_at` 만 — 로그아웃이 `is_active` 를 0 으로 만드는지 [3] 이 판독 후 맞춘다 · ⚠️미확인) ㉡ 사람마다 `컴퓨터: 사용 중/없음` · `휴대폰: n대` · `마지막 사용`.
- 브라우저 이름은 F-2 대로 `audit_trail`(`SessionAccessTrail.cs:77` · `entity_id = session_id`)에서만 나온다. 못 찾으면 「알 수 없음」. **표시용 — 어떤 판정에도 안 쓴다.**

### 3-2 `alerts` (로그인 충돌 이슈 기록)
- 원천: `security_alerts` `alert_type IN ('pc_login_blocked', 'pc_session_forced_out')` · 최근 30일(Q-3). 앞 것은 지금 `AuthService.cs:519` 가 쓴다 · 뒤 것은 옛 판이 남겼을 수 있는 줄(지금 쓰는 곳 0).
- 🔴 `description` 원문은 **내보내지 않는다** — 「…마지막 사용 2026-10-05 03:12 UTC」처럼 UTC 와 개발 문장이 들어 있다. 문장은 서버가 `alert_type` + `users` 이름 + `created_at`(한국 시각)으로 새로 만든다(§5-2).
- **화면은 「누가 · 언제」만** — F-1(`ip_address` NULL) · F-2(막힌 쪽 브라우저 없음) 때문에 「어느 컴퓨터에서」는 재료가 없다. 만들지 않는다(추측 표시 금지).
- F-3: 갱신 중 막힌 경우(`AuthService.cs:989`)는 기록이 없다 ⇒ 이 화면에 안 나온다. 화면 머리에 그렇게 적지는 않는다(고객 언어로 설명할 수 없는 공백) — **Q-2 로 사장님께**. 보강하면 쓰는 쪽은 작2(`AuthService`) · 이 화면은 0줄로 받는다(유형 목록에 이미 있음).

### 3-3 어디에 두나 — `ITenantDeviceService` 에 메서드 2개 더함 (P-B)
- 9/28 B-2 는 Application 새 서비스 + DI 한 줄 ⇒ `Program.cs` 를 고쳐야 하는데 그 파일은 이 판에서 작3 이 고친다(`:686`). **한 파일 한 주인** ⇒ 이미 등록된 `TenantDeviceService`(`Program.cs:107`)에 `GetAccessStatusAsync` · `GetLoginConflictAlertsAsync` 를 더하고, `AccessStatusController`(신설 · 자동 발견)가 부른다.
- 한 연결 `QueryMultipleAsync`(#16) · tenant 는 `HttpContext.Items["TenantId"]` 만(#2) · 대표만(`account_type = tenant_admin` · 직원 403) · DTO 는 `HitPan.Application` 에 신설.
- 다른 안: 9/28 대로 새 서비스 + `Program.cs` 한 줄 — 작3 갈래와 같은 파일 머지. 추천하지 않는다.
