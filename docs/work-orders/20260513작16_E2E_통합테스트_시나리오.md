## 1. 배경 (Why)

작13(API) + 작14(감사로그) + 작15(청크) 통합 시 단위 테스트로 잡히지 않는 결합 사고 발생 가능. W4 매뉴얼 작성 전에 W3 산출물 전체를 E2E로 검증해야 베타 D-63 일정 안전.

기존 W2 단위 테스트 18 케이스 통과. W3는 통합 단위로 확장.

## 2. 목표 산출물

### 시나리오 12 케이스

**P0 골든 패스 (5건)**
1. **G1** — 로그인 → MDB 업로드 → 시작 → 진행 폴링 → 완료 → 결과 조회
2. **G2** — partners 100건 마이그 → ERP 거래처 화면 조회 일치
3. **G3** — employees 형사영역 5컬럼 암호화 후 → 평문 조회 시 마스킹 화면 + 감사 로그 1행 적재
4. **G4** — items 100건 마이그 → BOM·재고 화면 정합
5. **G5** — etax_send_history 마이그 → 세금계산서 발행 이력 조회 일치

**P1 장애·악의 (4건)**
6. **F1** — 마이그 중 50% 지점 API 재시작 → 자가진단으로 RUNNING 좀비 처리 후 재개 가능
7. **F2** — 다른 tenant의 jobId 조회 시도 → 403 + 시도자 감사 적재
8. **F3** — `[SensitiveAccess]` 없이 컨트롤러 추가 시도 → Roslyn 컴파일 에러
9. **F4** — UPDATE sensitive_access_log → 트리거 SQLSTATE 45000 거부

**P2 혼돈·노후 (3건)**
10. **C1** — 시작 API 10회 동시 호출 → UNIQUE로 9건 거부, 1건만 RUNNING
11. **N1** — 3년치 300만건 마이그 + sensitive_access_log 100만건 → 조회 100ms 이내
12. **N2** — Access 1899-12-30 epoch → NULL 정규화 일관 확인 (멱등성 #11)
