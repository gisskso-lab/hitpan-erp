## 1. 배경 (Why)

- 사용자에게 "Environment file missing" 가짜 오류 노출

### 1.2 PRD §5 S2 시나리오 미구현 — 4/24 회의록 결정

**4 시나리오 분기 의무화:**

- **S2: 기존 MariaDB 감지** — v1.0.6 실패, **이번 라운드 핵심**
- S3: 재설치 (히트판 이미 있음)
- S4: 복구 (DB 손상)

### 1.3 Cloudflare Tunnel 도입 — 사장님 ⭐⭐⭐⭐⭐ 1순위

**3티어 아키텍처** (DESIGN_PRINCIPLES §10 외부 연동) — **2단계 도메인 전환 정책** (사장님 2026-04-25 결재):

#### Stage 1 — 베타 (무료, MVP 검증용)
```
[고객사 PC: 히트판 ERP]
    ↓ outbound-only (Cloudflare Tunnel)
[Cloudflare 엣지]
    ↓
[hitpan-prov.workers.dev]    ← 무료 Cloudflare Workers 서브도메인
    ↓
[테넌트 등록 + 토큰 발급]
```

**비용**: $0 / **기간**: 베타 20곳 운영 ~ 정식 배포 직전

#### Stage 2 — 정식 배포 (유료, 셀링·신뢰성)
```
[고객사 PC: 히트판 ERP]
    ↓ Cloudflare Tunnel
[prov.hitpan.app]            ← `.app` 도메인 (Google 운영 + HTTPS 강제)
    ↓
[테넌트 등록 + 토큰 발급]
```

**비용**: ~$15/년 / **전환 트리거** (3개 모두 만족):
1. ✅ 베타 20곳 중 15곳 이상 정상 가동
2. ✅ EVF 6대 게이트 통과
3. ✅ 사장님 정식 GO 결정

**전환 작업**: DNS 레코드만 변경 (~1시간) + 클라이언트 설정 자동 갱신.

**효과**: 공유기·NAT·방화벽·이중 NAT·Wi-Fi 중계기 무관 → 100% 연결 보장.

### 1.4 베타 출시 절대 의존성

## 2. 목표 산출물 (What)

### 2.1 인프라 (마커스 리 A)

- **Cloudflare 계정 회사 명의 신규 개설** (마커스)
- **Stage 1 베타 도메인**: `hitpan-prov.workers.dev` (무료 Workers 서브도메인)
- **Cloudflare Tunnel 서비스 셋업**
- **`hitpan-prov.workers.dev` 신규 백엔드 서버 구축** (정식 전환 시 `prov.hitpan.app`로 DNS만 변경)
  - ASP.NET Core 8 미니 API (테넌트 등록 + 토큰 발급)
  - Contract-First 적용 (DTO는 `HitPan.Contracts/Provisioning/`)
  - 엔드포인트:
    - `POST /api/prov/register` — 설치 PC 등록 (HW ID + 라이선스 키)
    - `POST /api/prov/token` — JWT 발급 (24h)
    - `GET /api/prov/health` — 헬스체크
- **모니터링** — Grafana + Loki (베타 20곳 추적)
- **자동 인증서 갱신** (Let's Encrypt via Cloudflare)

### 2.2 설치 스크립트 (마커스 + 백엔드 개발팀)

- **`installer-build/scripts/install-setup.ps1` 재설계 (PRD S1~S4 4 시나리오)**
- 핵심 로직:
  1. `hitpan` 계정으로 DB 접속 시도
  2. 성공 → S3(재설치) 분기 → root 단계 스킵
  3. 실패 → root(`Hitpan2025!`)로 시도
  4. root 실패 → **WinForms 입력 다이얼로그**로 사용자에게 root 비번 요청 (Inno Setup runhidden 환경에서도 표시)
  5. 입력받은 비번으로 hitpan 계정·DB 생성
  6. `.env` UTF-8 no-BOM 생성 (BOM 검증 강제)
  7. Cloudflare Tunnel 자동 등록 + 토큰 받기
  8. 첫 부팅 시 `prov.hitpan.app`에 라이선스 등록

- **`installer-build/scripts/start-hitpan.ps1`** — Tunnel 자동 시작 추가
- **`installer-build/hitpan-installer.iss`** — v1.0.7 버전·런타임 구성 갱신

### 2.3 백엔드 (Contract-First — 옵션 C 적용)

- **`HitPan.Contracts/Provisioning/`** (작2와 동일 솔루션):
  - `RegisterDeviceRequest.cs` (HW ID, 라이선스 키, 회사명)
  - `RegisterDeviceResponse.cs` (테넌트 ID, JWT 토큰)
  - `IssueTokenRequest.cs` (HW ID, 갱신 토큰)
  - `IssueTokenResponse.cs`

- **`prov` 서버 신규 프로젝트** (`src/HitPan.Provisioning/`):
  - 본 ERP API와 분리된 독립 서비스
  - DB 별도 (`hitpan_prov`) — 라이선스·토큰만 관리
  - 멱등키 처리 (P0-4 `idempotency_keys` 재사용)

### 2.4 보안 (보안 매니저 + DV-S 검증)

- 라이선스 키 AES-256 암호화 저장
- HW ID는 SHA-256 해시 (역추적 불가)
- 토큰은 JWT + 24h 만료 + Refresh Token
- root 비번 입력 다이얼로그는 메모리에서 즉시 폐기 (로그 미기록)
- prov 서버 → ERP 서버 양방향 mTLS

### 2.5 마이그레이션 (DB 매니저)

- `prov` 서버용 DB 스키마 신설 (`devices`, `licenses`, `tokens`)
- 본 ERP 서버는 변경 없음

## 3. 비범위 (What Not)

- 자동 업데이트 기능 (별도 라운드)
- 다중 PC 라이선스 (1 라이선스 = 1 PC만 이번 라운드)
- 모바일 접속 (다이애나 윤 합류 후 Phase 3)
- 백오피스에서 베타 20곳 모니터링 UI (루이스 김 PRD 후)

## 6. 구현 가이드

### 6.1 install-setup.ps1 재설계 (S1~S4 4 시나리오)

```powershell
# 핵심 분기 로직 (의사코드)
function Detect-Scenario {
    # S3: 히트판 이미 설치?
    if (Test-Path "C:\HitPan\hitpan\.env" -and Test-MariaDBConnection -User "hitpan") {
        return "S3-Reinstall"
    }
    # S2: 기존 MariaDB?
    if (Test-MariaDBService) {
        if (Test-MariaDBConnection -User "hitpan") {
            return "S3-Reinstall"  # hitpan 계정 살아있음
        }
        if (Test-MariaDBConnection -User "root" -Pass "Hitpan2025!") {
            return "S1-CleanWithKnownRoot"
        }
        return "S2-ExistingMariaDB"  # root 비번 모름 — 사용자 입력 필요
    }
    # S4: DB 손상?
    if (Test-Path "C:\HitPan\hitpan\.env" -and -not (Test-MariaDBService)) {
        return "S4-Recovery"
    }
    return "S1-FreshInstall"
}

# S2 분기: 사용자에게 root 비번 입력 다이얼로그
function Prompt-RootPassword-WinForms {
    Add-Type -AssemblyName System.Windows.Forms
    # ... WinForms 입력 다이얼로그 (Inno Setup runhidden 환경에서도 표시되도록)
}
```

### 6.2 prov 서버 (Contract-First)

- 신규 프로젝트 `src/HitPan.Provisioning/`
- 본 ERP와 별도 솔루션 빌드도 가능하도록 분리
- ASP.NET Core 8 + Dapper (가벼운 DB)
- 도커라이즈 (Cloudflare 서버 배포용)

### 6.3 Cloudflare Tunnel

- `cloudflared` 클라이언트 설치 (설치 스크립트에 포함)
- 토큰 자동 등록 → outbound 영구 연결
- Health check 5분 간격
- 끊김 시 자동 재연결

### 6.4 보안 (DV-S 검증 핵심)

- root 비번 입력 시 `SecureString` 사용
- 메모리 폐기 (`[System.Runtime.InteropServices.Marshal]::ZeroFreeBSTR`)
- 어떤 로그에도 기록 금지 (마스킹)
- 라이선스 키는 AES-256 + tenant_id별 키 분리

### 6.5 테스트·검증

- **로컬 테스트**: 깨끗한 Win10/Win11 VM 5종 (S1~S4 + 까다로운 환경 1)
- **현장 모의**: 4/23 대리점 PC 환경 재현 (root 비번 모름)
- **EVF ⑤ 무지**: 신입 직원 5명 무설명 설치 → 30분 내 부팅 성공률

## 7. EVF 검증 계획

| 영역 | 시나리오 | 책임자 | 통과 기준 |
|---|---|---|---|
| ② 장애 | Tunnel 끊김 5초 → 자동 재연결 / DB 권한 부족 → 명확한 오류 다이얼로그 | 마커스 + BK | 우아한 실패·복구 |
| ③ 악의 | 설치 파일 변조 검증 (코드 사이닝) / root 비번 메모리 폐기 검증 | DV-S | 무결성 깨지면 거부, 비번 dump 안 됨 |
