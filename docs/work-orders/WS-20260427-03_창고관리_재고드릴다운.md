## 3. 기술 가이드 (백엔드 매니저 + 프론트 매니저 합의안)

### 3.1 백엔드 — 신규 GET 엔드포인트 1개

**경로**: `GET /api/stock/balance-by-warehouse?warehouseId={id}`

**응답** (예시):
```json
{
  "warehouseId": "0e9fdcd...",
  "whName": "본사창고",
  "totalItems": 12,
  "totalQty": 245.0,
  "items": [
    {
      "itemId": "...",
      "itemName": "테스트반제품1",
      "itemCode": "RM-001",
      "currentQty": 60.0,
      "unit": "EA"
    },
    ...
  ]
}
```

**SQL** (Dapper):
```sql
SELECT i.item_id, i.item_name, i.item_code, s.current_qty, i.unit
FROM item_stock s
JOIN items i ON i.item_id = s.item_id
WHERE s.warehouse_id = @WarehouseId
  AND i.is_deleted = 0
  AND s.current_qty != 0  -- 0인 행은 시각 잡음, 옵션
ORDER BY s.current_qty DESC;
```

**테넌트 격리**: `tenant_id` JWT 클레임에서만, 파라미터 미수신 (헌법 #2)

**대안 — 기존 API 재활용**: `api/stock/balance` 가 이미 있다면 (재고이송 화면에서 사용 중),
warehouseId 필터 옵션 추가하는 방향도 가능. **신규 vs 확장**은 백엔드 매니저가 결정.

### 3.2 프론트엔드 — `WarehouseManagePage.razor` 추가만

**변경 위치**:
- `<MudTable>` 의 `OnRowClick` 이벤트 추가 (행 클릭 → 우측 패널 갱신)

**기존 코드 0줄 변경 보장**:
- 창고 추가/수정/삭제 다이얼로그 → 그대로
- `WarehouseViewModel` → 그대로
- API 호출 (`api/warehouses` GET, POST, PUT, DELETE) → 그대로

### 3.3 사장님 헌법 #20 (워크플로우 끊김 금지) 점검

이 화면은 **읽기 전용 드릴다운** — 워크플로우 사슬 (매입/BOM/판매)에 일절 영향 X.
재고 데이터는 `item_stock` 단일 진실에서만 읽음 — 정합성 보장.

## 7. 미해결 확장 의문 (참고만, 본 작지서 범위 외)

### Q1. 우측 패널에 "이 창고로 이송 보내기" 버튼?
이송 화면으로 입고창고 미리 셋팅하고 점프하는 단축 동선. **별도 작지서로 분리 권고** (이번엔 read-only만).

### Q2. 창고별 잔량 추이 (시계열)?
"본사창고 1주 전 vs 지금" 같은 그래프. **MVP 이후 P3** — 베타 출시에 영향 없음.

### Q3. 품목 행 클릭 → 상품마스터로 점프?
사장님이 "건들 필요 없지?" 확인하셨으니 **이번엔 안 함**. 별도 작지서로 분리 권고.

### Q4. 창고 권한별 필터?
어드민이 특정 창고만 볼 수 있게 하는 권한 모델. **권한 설정 화면 별도 검토 필요**.
