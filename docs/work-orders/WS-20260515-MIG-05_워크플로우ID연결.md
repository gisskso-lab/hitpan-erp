## 1. 목적

사장님 격언 객관 증거화. 레거시 ERP가 **재고원장(DOCFB) ↔ 세금계산서(DOCF4)** 를 8자리 코드로 양방향 연결한 사실을 우리 마이그본에서도 보존.

> 사장님 격언 (5/14 새벽): "워크플로우는 절대 끊기지 않는다. 한 단계라도 끊기면 무결성 깨진 것."

## 2. 객관 증거 (MSSQL sys.indexes 5/15 추출)

`GIS_PANDATA_V5.dbo.DOCFB` 인덱스 전수 분석 결과:

```
PK_DOCFB    = IJ_DT + IJ_IO + IJ_SEQ + IJ_BUY + IJ_SUN  (5컬럼 PK)
IX_DOCFB_2  = IJ_IO + IJ_TAXNO + IJ_TAXBUY + IJ_DT + IJ_SEQ + IJ_SUN  ⭐
IX_DOCFB_3  = IJ_TAXBUY + IJ_IO + ... (역방향 검색)
```

`IX_DOCFB_2`의 의미:
- `IJ_TAXNO char(8)` = 세금계산서 번호 (DOCF4.TX_NO와 동일)
- `IJ_TAXBUY int` = 세금계산서 거래처 (DOCF4.TX_BUY와 동일)
- `IJ_IO char(1)` = 매출/매입 구분 (DOCF4.TX_IO와 동일)

**결론:** 레거시는 재고 입출고 row 하나마다 어떤 세금계산서에서 발생했는지 IJ_TAXNO/IJ_TAXBUY 컬럼으로 추적함. "00000000" = 세금계산서 없는 입출고 (창고 이동, BOM 생산 등).

## 3. 현행 stock_ledger 문제

```sql
DESCRIBE stock_ledger;
-- doc_no varchar(N) — 단일 컬럼만 존재
```

- 단일 `doc_no` 컬럼만 있어서 입출고 구분 (IJ_IO) 별도 추적 불가
- 매입(B) 8자리 ↔ 매출(S) 8자리 = 같은 숫자라도 다른 세금계산서
- 워크플로우 양방향 추적 (재고→계산서, 계산서→재고) 끊김

## 4. 봉합 액션 (3 단계)

### 단계 1: DDL ALTER (DB매니저)

```sql
ALTER TABLE stock_ledger
  ADD COLUMN tax_io CHAR(1) NULL COMMENT 'IJ_IO (S=매출/B=매입)',
  ADD COLUMN tax_no CHAR(8) NULL COMMENT 'IJ_TAXNO 세금계산서 번호 ("00000000"=무관계)',
  ADD COLUMN tax_partner_code INT NULL COMMENT 'IJ_TAXBUY 레거시 거래처 코드',
  ADD INDEX idx_stock_ledger_tax (tenant_id, tax_io, tax_no, tax_partner_code) COMMENT '재고↔세금계산서 양방향 추적';

-- 기존 doc_no 컬럼은 유지 (호환성). tax_io/tax_no가 새 정답 소스.
```

### 단계 2: 마이그 코드 정정 (백엔드매니저)

```csharp
// MigrateStockLedgerAsync — 기존 doc_no 매핑에 tax_io/tax_no/tax_partner_code 추가
foreach (DataRow r in dt.Rows) {
    var ijIo = GetStr(r, "IJ_IO");
    var ijTaxNo = GetStr(r, "IJ_TAXNO");           // 8자리, "00000000" 가능
    var ijTaxBuy = GetInt(r, "IJ_TAXBUY");

    // 워크플로우 끊김 정답 — "00000000"는 NULL로 저장하지 않음 (의미 보존)
    // 단, 검색 시 "00000000" OR NULL을 동일 취급해야 함
    rows.Add(new StockLedgerRow {
        // ... 기존 컬럼
        TaxIo = string.IsNullOrEmpty(ijIo) ? null : ijIo,
        TaxNo = string.IsNullOrEmpty(ijTaxNo) ? null : ijTaxNo,
        TaxPartnerCode = ijTaxBuy == 0 ? (int?)null : ijTaxBuy,
    });
}
```

### 단계 3: 검증 (DB매니저)

```sql
-- 워크플로우 ID 연결 정합 검증
-- 1) "00000000" 비율 (창고 이동 등 정상)
SELECT
  SUM(CASE WHEN tax_no = '00000000' OR tax_no IS NULL THEN 1 ELSE 0 END) AS no_tax_invoice_rows,
  SUM(CASE WHEN tax_no IS NOT NULL AND tax_no <> '00000000' THEN 1 ELSE 0 END) AS linked_rows,
  COUNT(*) AS total
FROM stock_ledger WHERE tenant_id = @tenant;

-- 2) tax_no 보유 row 중 tax_invoices에 실제 존재하는 비율 (참조 무결성)
SELECT
  COUNT(*) AS stock_with_tax,
  SUM(CASE WHEN ti.tax_no IS NOT NULL THEN 1 ELSE 0 END) AS matched
FROM stock_ledger sl
LEFT JOIN tax_invoices ti
  ON sl.tenant_id = ti.tenant_id
  AND sl.tax_io = ti.direction
  AND sl.tax_no = ti.tax_no
WHERE sl.tenant_id = @tenant
  AND sl.tax_no IS NOT NULL
  AND sl.tax_no <> '00000000';

-- 3) 반대 방향 — 세금계산서마다 재고 row 존재 확인
SELECT
  ti.invoice_id, ti.direction, ti.tax_no,
  COUNT(sl.stock_ledger_id) AS stock_rows
FROM tax_invoices ti
LEFT JOIN stock_ledger sl
  ON sl.tenant_id = ti.tenant_id
  AND sl.tax_io = ti.direction
  AND sl.tax_no = ti.tax_no
WHERE ti.tenant_id = @tenant
GROUP BY ti.invoice_id, ti.direction, ti.tax_no
HAVING stock_rows = 0;  -- 0건이어야 정합
```
