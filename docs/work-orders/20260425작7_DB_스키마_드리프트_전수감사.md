## 1. 배경 (Why)

4/25 P0 감사 과정에서 DB 크로스체크 #2가 **스키마 드리프트 증거**를 드러냈다:

- 원본 DDL `docs/design/hitpan_db_ddl_FINAL_v1.0.sql:627`에 이미 `sales_deliveries.tax_invoice_id CHAR(36)` 존재
- 그러나 실 DB에 컬럼 없음 → DB-20 `ADD COLUMN`이 성공 → **실 DB는 원본 DDL 미반영 상태 증명됨**
- 즉, 원본 DDL과 실제 배포 DB 간 **불특정 다수 컬럼·테이블 드리프트** 존재 가능성

DB-04 11개 테이블 COLLATE 미명시 지적(1차 감사 ⭐⭐⭐⭐⭐)도 이 드리프트의 변종 — 원본 DDL은 명시했을 수도 있으나 실제 적용 경로에서 소실 가능.

고객사 프로덕션 환경에서 드리프트가 발견되면 런타임 `1146/1054/1253/1267` 에러 연쇄 → 헌법 #19 "본사에선 됐는데" 위반의 구조적 원인.

## 2. 목표 산출물 (What)

1. **드리프트 감사 스크립트** (`src/HitPan.API/Migrations/SQL/audit_schema_drift.sql`):
   - `information_schema.TABLES` 전수 조회 → 원본 DDL 테이블 목록과 diff
   - `information_schema.COLUMNS` 전수 조회 → 컬럼 유무·타입·COLLATION·NULL·기본값 diff
   - `information_schema.KEY_COLUMN_USAGE` FK 전수 존재 확인
   - 결과를 `drift_report.csv` 또는 MD 표로 출력
2. **누락 마이그레이션 패치 DB-21** (드리프트 발견 시):
   - 누락 컬럼 `ADD COLUMN IF NOT EXISTS`
   - 누락 FK `ALTER TABLE ... ADD CONSTRAINT`
   - COLLATE 불일치 `CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci`
3. **기동 시 스키마 검증 헬퍼** (옵션, 권고):
   - API `Program.cs` 기동 초기에 핵심 테이블·컬럼 존재 검증
   - 누락 시 `_logger.LogCritical` + 명시적 오류 화면 (헌법 #19)

## 3. 비범위 (What Not)

- 스키마 리팩터·정규화는 건드리지 않음 (드리프트 복구만).
- EF Core 마이그레이션 자동 생성 도입은 별도 작지서 (현재는 수동 SQL 유지).
- 고객사 프로덕션 DB 자동 마이그레이션 도구는 별개 — 본 작지서는 내부 검증 환경만.
