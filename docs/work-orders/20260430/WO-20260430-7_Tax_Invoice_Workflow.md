# 작20260430-7 — 세금계산서 워크플로우 완성 (P1)

## 🟡 우선순위
P1 (브라운킴 강력 권고: 단일 작업지시서로 묶음 — 흐름 끊김 위험)

## 핵심 의미
**더존·이카운트 대비 셀링 포인트 1순위.** 거래명세서 → 판매확정 → 전자세금계산서 → 누락 가시화 → 일괄 발행 = 절대원칙 #20(워크플로우 끊김 0) 완성판.

## 담당
- 메인: ERP 매니저 (단독 책임 — 흐름 일관성 사수)
- 보조: 백엔드 매니저, 프론트 매니저
- 검증: CTO + 법무팀장 (가산세 리스크 차원)

## 작업 범위

### A. 거래명세서 그리드 — "세금" → "판매확정" 토글
- 그리드 컬럼 라벨 변경: "세금" → "판매확정"
- 미확정 상태: 체크박스 또는 "확정" 버튼
- **확정 클릭 시:** 해당 셀이 "전자세금계산서" 발행 버튼으로 토글
- 클릭 시 발행 흐름 진입

### B. 거래명세서 목록 — "계산서 발행" → "판매확정"
- 목록 화면 액션 버튼 라벨 변경: "계산서 발행" → "판매확정"
- 동일 워크플로우 진입

### C. 거래명세서 목록 다중선택 → 일괄 발행
- 체크박스 다중선택
- "판매확정" 항목만 선택된 경우 → 상단 "전자세금계산서 발행" 버튼 활성화
- 미확정 항목 포함 시 → 비활성화 또는 경고
- 일괄 발행 흐름

### D. 세금계산서 통계 — 누락 가시화
- 판매확정됐으나 전자세금계산서 미발행 건수 표시
- 시각화: 카드형 카운터 + 차트 (대시보드 디자인 토큰 통일 — 작20260430-8과 연동)
- 클릭 시 누락 건 목록으로 이동 → C의 일괄 발행 흐름으로 연결

## 워크플로우 (헌법 4조 #4 끊김 0)
```
거래명세서 작성
  ↓
판매확정 (그리드 또는 목록)
  ↓
[전자세금계산서 발행] 버튼 활성화
  ↓
발행 (단건 또는 다건 일괄)
  ↓
세금계산서 통계: 누락 0건 확인
```

## 검증 보고서 양식 (헌법 4조)
- DB 계층:
  - 거래명세서 status = 'confirmed' 정확히 INSERT
  - 세금계산서 발행 시 invoices 테이블 INSERT
  - stock_ledger·journal_lines 동시 반영 (절대원칙 #3 INSERT ONLY 사수)
- 백엔드 계층:
  - 판매확정 API 200 OK (트랜잭션 단일)
  - 일괄 발행 API 부분실패 처리 정확
- 프론트 계층:
  - 라벨 변경 정확
  - 토글 동작 정상
  - 다중선택 + 일괄 발행 동작
- 연결 끊김 0:
  - 거래명세서 확정 → 세금계산서 통계에 미발행 건수 즉시 반영
  - 일괄 발행 후 누락 카운트 정확히 감소
- 고객 시선:
  - "가산세 안 맞을 수 있나?" 답변 = "누락 자동 표시"
  - 처음 쓰는 경리 직원이 흐름 따라갈 수 있나?

## 법무 검토 항목 (법무팀장)

- 누락 1건당 가산세 1~10% (사업자 손해)
