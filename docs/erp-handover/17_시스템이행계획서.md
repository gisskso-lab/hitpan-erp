## 2. 이행 단계 (3시스템 통합 가도)

### Phase A: 랜딩페이지 + 백오피스 설계 (2026-06-01 ~ 06-15, 2주)
- PRD 정독 → 설계 → 구현
- 데이터 흐름: 랜딩 가입 → 백오피스 DB Push
- 프로비저닝: tenant 생성 → DNS · 터널 자동 발급 → EXE 다운로드

### Phase B: 3시스템 통합 (2026-06-15 ~ 06-30, 2주)
- 랜딩 ↔ 백오피스 ↔ ERP 유기적 연결
- 5분 주기 ERP→백오피스 Pull (직원·기기 메타정보만, 헌법 #22)
- 첫 로그인 약관 동의 미들웨어 검증
- 원클릭 설치 EXE 완성 (10분 이내 목표)

### Phase C: EVF 6대 영역 실측 (2026-07-01 ~ 07-15, 2주)
- 부하: k6 100명 동시 / 1만 건 데이터
- 장애: 통신 끊김 17개 시나리오 5분 자동 복구
- 악의: OWASP ZAP DAST 1회+
- 혼돈: 랜덤 입력 봇
- 무지: 현장 직원 3명 3분 안에 쓸 수 있냐
- 노후: 3년 누적 데이터 시뮬레이션

### Phase D: 백신 5종 호환 (2026-07-15 ~ 07-22, 1주)
- Windows Defender + V3 Lite + 알약 + 네이버 + Norton + McAfee
- 격리 0건 보장
- 1클릭 봉합 매뉴얼 검증

### Phase E: 베타 체험단 (2026-07-22 ~ 08-15, 4주)
- 베타 20곳 (로컬 터널 10 + 클라우드 10)
- 8월 24일 동시 출시 → 3주 롤링 (마스터플랜 v3)
  - 1차: 서비스업 8곳 (2026-08-24)
  - 2차: 도소매 12곳 (2026-09-14)
  - 3차: 제조 10곳 (2026-10-05)

### Phase F: 정식 출시 (2026-10-15+)
- 베타 4주 무사고 통과 시
- 사장님 최종 결재

## 3. 환경 준비

### 3.1 본사 클라우드 서버
- 1대 통합 (랜딩 + 백오피스 + 프로비저닝)
- 월 3~5만원 (project_cloud_server 박제)
- 도메인 구조:
  - 랜딩: `hitpan.kr`
  - 백오피스: `admin.hitpan.kr`
  - 프로비저닝: `prov.hitpan.app` (정식) / `hitpan-prov.workers.dev` (베타)

### 3.2 고객 PC 환경
- Windows 10/11
- MariaDB 11.4.10 (로컬, EXE 자동 설치)
- cloudflared (워치독 자동 복구)
- HitPan.API + HitPan.Web + HitPan.Watchdog (Windows 서비스 3개)

### 3.3 도메인 자동 생성
- 패턴: `hitpan-{tenant}.kr` (정식) / `hitpan-{tenant}.workers.dev` (베타)
- Cloudflare API 토큰 본사 서버에만 (EXE에 절대 금지)

## 4. 데이터 이행

### 4.1 신규 가입 고객
- 빈 DB로 시작
- 첫 로그인 약관 동의 → 회사 정보 입력 → 사용 시작

### 4.2 레거시 히트판 (Access MDB) → 신규 마이그
- `/settings/mdb-migration` 화면
- 5축+α 정공법 (헌법 #26)
  - MySqlBulkCopy LOAD DATA LOCAL INFILE
  - OLEDB 병렬 SELECT
  - Stream 처리
  - 인덱스 DISABLE/ENABLE
  - 테이블별 병렬
- 목표 10분 러프 / Timeout 24시간
- ERP 매니저 95% 개시잔액 메인 경로 (과거 100% 욕심 금지)

### 4.3 마이그 예외 (사장님 결재)
- 거래명세서/세금계산서: 정합성 무시하고 레거시 그대로 이관
- 운영은 무결성 절대 (헌법 #20)

- 17개 시나리오 5분 자동 복구

5. 외부 헬스체크 후 정상화
