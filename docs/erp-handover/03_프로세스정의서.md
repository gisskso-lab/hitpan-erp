## 1. 흐름 1 — 매입 프로세스

### 1.1 프로세스 다이어그램
```
[Actor: 구매담당]
    │
    ▼
┌─────────────┐         ┌─────────────┐         ┌──────────────┐
│  발주서 작성   │ ──────► │  매입명세서 발행 │ ──────► │  반품 (선택)   │
│ (purchase_   │ confirm │ (purchases   │ confirm │ (purchase_   │
│  orders)     │         │  receipts)   │         │  returns)    │
└─────────────┘         └─────────────┘         └──────────────┘
                                │                        │
                                ▼ confirmed              ▼ confirmed
                        ┌────────────────────────────────────┐
                        │  stock_ledger INSERT (헌법 #3 #6)   │
                        │  매입: +N / 반품: -N                │
                        └────────────────────────────────────┘
                                        │
                                        ▼
                        ┌────────────────────────────────────┐
                        │  journal_lines INSERT (원장 반영)   │
                        │  차변: 재고자산 / 대변: 외상매입금   │
                        └────────────────────────────────────┘
```

### 1.2 상태 전이
| 상태 | 의미 | 다음 가능 상태 |
|---|---|---|
| `draft` | 작성 중 | confirmed, cancelled |
| `confirmed` | 확정 (원장 반영) | partial, completed |
| `partial` | 일부 입고 | completed |
| `completed` | 완료 | (종결) |
| `cancelled` | 취소 | (종결) |

### 1.3 절대 규칙
- 헌법 #6: 원장 반영은 **confirmed 시점**에만
- 헌법 #3: stock_ledger / journal_lines **INSERT ONLY**
- 헌법 #20: 매입 → 재고 반영 끊기면 즉시 P0

### 1.4 화면 흐름
1. `/purchase-orders` (발주서) → 신규 작성 → 라인 추가 → 저장(draft) → 확정(confirmed)
2. `/purchases` (매입명세서) → 발주에서 가져오기 OR 신규 → 입고처리 → 확정
3. `/returns` (반품) → 매입에서 가져오기 → 반품 사유 입력 → 확정
4. `/stock` (재고현황) → 자동 반영 확인

## 2. 흐름 2 — BOM 생산 프로세스

### 2.1 프로세스 다이어그램
```
[Actor: 생산담당]
    │
    ▼
┌──────────────┐        ┌──────────────┐
│  BOM 마스터    │ ─────► │  생산 명령    │
│  (bom_headers)│        │  (confirmed)  │
│  + bom_items │        │              │
└──────────────┘        └──────────────┘
                                │
                                ▼ 동일 트랜잭션 (헌법 #20)
                        ┌─────────────────────────────────────┐
                        │  stock_ledger INSERT (2 entries)    │
                        │  ① 완제품 +1                         │
                        │  ② 자재 N건 -각각의 quantity         │
                        └─────────────────────────────────────┘
                                │
                                ▼
                        ┌─────────────────────────────────────┐
                        │  bom_cost_cache UPDATE (단가 캐시)   │
                        └─────────────────────────────────────┘
```

### 2.2 절대 규칙
- 완제품↑ + 자재↓ 는 **반드시 동일 트랜잭션** (롤백 가능)
- 자재 부족 시 생산 명령 거부 (재고 음수 금지)
- BomService는 `EnsureOpenAsync` 패턴 정합 (DbConnection 안전)

### 2.3 화면 흐름
1. `/bom` (BOM 마스터) → 신규 → 완제품 + 자재 N건 + 수량
2. `/bom/{Id}` (상세) → 생산 명령 → 확정
3. `/stock` → 자동 반영 확인

## 3. 흐름 3 — 판매 프로세스

### 3.1 프로세스 다이어그램
```
[Actor: 영업담당]
    │
    ▼
┌──────────┐    ┌──────────┐    ┌────────────┐    ┌──────────────┐
│ 견적서    │───►│ 수주서    │───►│ 거래명세서  │───►│ 세금계산서    │
│(quotations)│   │(sales_   │   │(deliveries)│   │(tax_invoices)│
│           │    │ orders)  │    │            │    │              │
└──────────┘    └──────────┘    └────────────┘    └──────────────┘
                                       │                  │
                                       ▼ confirmed        ▼ confirmed
                            ┌────────────────────────────────────┐
                            │  stock_ledger INSERT (재고 -N)     │
                            │  journal_lines INSERT (외상매출금)  │
                            └────────────────────────────────────┘
                                            │
                                            ▼
                                ┌────────────────────────┐
                                │  매출·경리·세무 반영     │
                                │  (메이크빌 ASP 외주)    │
                                └────────────────────────┘
```

### 3.2 단축 경로 (헌법 #20)
- 견적 생략 → 수주 → 거래명세서: ✅ 허용
- 수주 생략 → 거래명세서: ✅ 허용 ("바로 명세서")
- 거래명세서 생략 → 세금계산서: ❌ 금지 (출고 무결성)

### 3.3 세금계산서 분리 (3계층, 2026-04-24 결재)
| 계층 | 시스템 | 용도 |
|---|---|---|
| L1 | tax_invoices (로컬 DB) | 발행 원장 |
| L2 | 메이크빌 ASP | 외부 전송 (인쇄·메일·문자) |
| L3 | 홈택스 API (외주 검토) | 국세청 전송 |

### 3.4 화면 흐름
1. `/quotations` (견적) → 작성 → PDF/메일 발송
2. `/sales-orders` (수주) → 견적에서 가져오기 OR 신규
3. `/deliveries` (거래명세서) → 수주에서 가져오기 → 발행 → 재고 차감
4. `/tax-invoice` (세금계산서) → 거래명세에서 가져오기 → 발행

## 4. 부가 프로세스 — 결재

### 4.1 결재 라인 흐름
```
문서 작성
    │
    ▼
결재 요청 (approval_documents INSERT)
    │
    ▼
approval_line_steps 순서대로
    │
    ├─ 1단계 검토자 → 승인/반려
    ├─ 2단계 부장 → 승인/반려
    └─ N단계 대표 → 최종 승인
    │
    ▼
완료 (approval_history INSERT, 원본 문서 confirmed)
```

### 4.2 적용 대상
- 발주서 / 매입명세서 / 반품
- 견적서 / 수주서 / 거래명세서
- 경비 신청 / 연차 신청 / 초과근무
- 근로계약 / 기타 인사

### 4.3 화면 흐름
1. 어떤 문서든 "결재 요청" 클릭 → `/approval/sent`
2. 결재자: `/approval/pending` → 승인/반려
3. 완료: `/approval/completed`
