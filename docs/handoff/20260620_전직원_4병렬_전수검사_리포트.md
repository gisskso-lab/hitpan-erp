## 1. P0 — 고객 첫 등장 차단 / 통신 0점 위험 (즉시 봉합 대상, 결재 후)

### P0-1 [통신] 헌법 #28 자동복구 WS28B가 "감지만 하고 복구 액션 없음"
- 위치: `src/HitPan.Watchdog/Worker.cs:72-138`, `src/HitPan.Watchdog/Stages/` (WS28B)
- 증거: WS28B(재부팅 후 5분 내 점검)가 post-reboot 플래그 확인 → `ClearFlag()` 하고 끝. 실제로 cloudflared 재설치/TunnelSecret 재생성을 트리거하지 않음.
- 왜 P0: Windows Update 강제 재부팅 후 터널이 깨졌을 때, 워치독이 "점검"만 하고 봉합을 안 한다 → 고객 PC 오프라인 지속 → 헌법 #30(자가 회복, 본사 의존 0) 위반. **5/15 demo 6시간 다운 = 이 시나리오.**

### P0-2 [통신] WS28C(TunnelSecret 무효화 감지)가 cloudflared.log 부재 시 무기력
- 위치: `src/HitPan.Watchdog/Stages/WS28C_TunnelSecret.cs:21-24`
- 증거: `if (!File.Exists(_logPath)) return false;` — 로그 파일 없으면 무조건 "정상"으로 판정.
- 왜 P0: 초기 설치 직후·로그 삭제 시 실제 터널 무효화를 감지 못함. 외부 접속 끊겨도 워치독은 "OK" 신호 유지 → 본사 모니터링 맹점.
- 권고 방향(수정 아님, 진단): 로그 부재 시 cloudflared **서비스 상태 직접 조회**로 폴백.

### P0-3 [통신] HealthProbe 빈 catch — 헌법 #15 위반
- 위치: `src/HitPan.Watchdog/HealthProbe.cs:91` (`catch { return "sha256:unknown"; }`), `:96-106`
- 왜 P0(통신 영역): 자가진단 실패를 침묵 → CS팀이 원인 추적 불가. 통신 무결성 영역이라 등급 상향.

## 2. P1 — 잠복 버그 (운영 중 사고 가능)

### P1-1 [그룹웨어] leave_requests 테이블이 마이그레이션 SQL에 없음

- 왜: 신규 고객 DB를 마이그레이션 SQL로 재생성하면 연차/휴가 테이블이 안 생김 → 그룹웨어 휴가 기능 전체 불가.

### P1-2 [그룹웨어] 연차 반려사유(reject_reason)가 목록 API에서 안 내려옴

- 왜: DB엔 저장되는데 조회 SELECT에 컬럼 누락 → 직원이 "왜 반려됐는지" 영영 못 봄.

### P1-3 [그룹웨어] 연차 승인자(approved_by)를 "첫 TenantAdmin"으로 자동 박음

### P1-4 [결재] 동시 중복 승인 가능성 (좁은 창)
- 위치: `ApprovalService.cs:381-382`(status 체크) → `:449-462`(무조건 UPDATE)

- 권고 방향: UPDATE에 `AND status='pending'` 추가 + affected rows 확인.

### P1-5 [결재] 결재 승인 완료 후 원 문서(발주/수주) 상태 미반영

- 왜: "결재 완료했는데 발주서가 아직 미결재" → 이후 입고/수금 막힘. **헌법 #20 워크플로우 끊김**에 해당. (결재→문서 연결축 확인 필요)

### P1-6 [결재] 기준금액 자동승인 이력이 seq_no=0 → 이력 정렬 꼬임

### P1-7 [결재] 결재선 설정 시 결재자 유효성 검증 없음

## 4. PM 교차검증 — 에이전트 보고 정정 (헌법 #32 받아쓰기 금지)

여러 검증 에이전트가 같은 사안을 다르게 판정해, PM이 코드를 직접 열어 사실 확인했다.

1. **"미승인자도 결재 승인 가능" (결재팀 P0 주장) → 정정: 사실 아님.**
   `ApprovalService.cs:398-413`에 현재 결재선 approver_id/위임자 검증이 명확히 있다. 아니면 "결재 권한이 없습니다" 예외. → P0 철회, 에러 메시지 불명확(P2)만 인정.

2. **"StockService가 tenantId 파라미터로 받아 헌법 #2 위반" (워크플로우팀 P1 주장) → 정정: 위반 아님.**
   컨트롤러(`StockController.cs:50`)가 JWT(`HttpContext.Items["TenantId"]`)에서 꺼내 서비스에 넘기는 구조. 클라이언트가 임의 주입하는 게 아니다. 헌법 #2는 "클라이언트 파라미터로 받지 마라"이지 "서비스 시그니처에 두지 마라"가 아니다. → 정상.

3. **"동시 중복 승인" P0 → P1로 하향.** 동시성 창은 실재하나 권한 게이트가 살아있어 임팩트 제한적.

4. **HitPanApiAuthHandler 401 자동 재발급** → PM 직접 확인 결과 견고하게 구현됨, 빈 catch 없음. 통신팀 판정 정확. (진범 #22 봉합 양호)

## 6. 별도 쟁점 — AI(헌법 #18) 경계 (사장님 판단 필요)

AI 직원은 사용자 자연어를 외부 Anthropic API로 보내 이해한다. 데이터 **생성/변경(SQL·확정)** 은 고객 PC 로컬에서만 일어나지만, 자연어에 거래처명·금액이 섞이면 그 텍스트가 외부 LLM으로 나간다.
- 현재 통제: BYOK 키를 고객이 명시 설정해야만 작동(고객 PC→Anthropic 직통, 본사 프록시 0), 키 AES-256 암호화, 직전 8턴만 전송.
- 쟁점: 헌법 #18은 "본사로 전송 금지"이고 Anthropic은 본사가 아니므로 문자적으론 위반 아님. 다만 "고객 업무 데이터의 외부 유출" 관점에서 **고객 고지·동의 화면 강화**가 필요. → 사장님 정책 판단 영역.
