## 1. CORS — 소스 정상, 배포 옛빌드가 원인

**실측**: `src/HitPan.API/Program.cs:284-296`
```
builder.Services.AddCors(options =>
  options.AddPolicy("BlazorWasmDev", policy =>
    policy.SetIsOriginAllowed(_ => true)   // 모든 출처 허용(서브도메인+LAN)
          .AllowAnyHeader().AllowAnyMethod()
          .AllowCredentials();              // SignalR 자격증명 호환
```
- `:348` `app.UseCors("BlazorWasmDev")` 적용됨.
- 즉 **소스에는 CORS가 정상 설정돼 있다.** 어제 "CORS 미설정" 증상 = demo에 올린 API가 이 정책 이전/다른 빌드라 출처 차단.
- **봉합 불필요.** 최신 코드 배포 시 `demo.hitpan.kr` → `api-demo.hitpan.kr` 허용 자동 해소.

## 2. approval 403 — 소스 정상, 배포 옛빌드가 원인

**실측**: `src/HitPan.Application/Services/AuthService.cs`
- `:82` 부모계정인데 `employee=null` → `BackfillParentEmployeeAsync` (login 경로)
- `:188` refresh 경로도 동일 백필 (일관)
- `:294-298` `empNo = MAX(파싱)+1` — **정의상 기존에 존재할 수 없는 값** → 0001 중복 불가
- `:327` 실패 시 `Detach(newEmployee)` — 좀비 Added 엔티티 제거 → 재INSERT 500 차단
- `:368,379` `employeeId = employee?.Id` → `new("employee_id", employeeId)` 클레임 발급

**모순 해소**: 코드가 `MAX+1`인데 어제 demo에서 `Duplicate entry 'demo-tenant-0001-0001'`(=0001 중복)이 났다.
→ `MAX+1` 로직에선 0001 중복이 **날 수 없다.** 0001 중복이 났다는 것 자체가 **demo API가 이 봉합(MAX+1·Detach) 이전 옛 빌드**라는 결정적 증거.
→ 인수인계서 기록("demo API는 5/17 옛빌드")과 일치. **봉합 불필요.** 최신 코드 배포 시 백필이 정상 동작해 employee_id 클레임 채워짐 → 403 해소.
