## 2. 근본 원인 (코드 라인 확정)

`installer/HitPan-Universal.iss` (출하본 — build-installer-universal.ps1:178이 컴파일):

| 단계 | 코드 | 사실 |
|---|---|---|
| 시리얼없이 「예」 | L521-528 | `G_TenantCode:='LOCAL'` 후 **`DetermineMultiTenantSlot()` 호출 없이 Exit** |
| 시리얼인증 실패 「예」 | L559-566 | 동일 — 호출 없이 Exit |
| 시리얼 정상 | L581 | `DetermineMultiTenantSlot()` **여기서만** 호출 |
| G_DbUser/Name 기본값 | L276-277 | **그 함수 안에만** 존재(`'hitpan'`/`'hitpan_erp'`) |
| DB셋업 mysql | L862·864·879·883·894·897·900 | `mysql -u %s -p%s ...` 에 빈 `G_DbUser` 주입 |

**인과**: 시리얼없이 설치 → 함수 미호출 → `G_DbUser`·`G_DbName` = 빈 문자열 →
`mysql -u  -p<비번> <빈dbname> < dump` → mysql이 `-p` 다음 비번을 **유저명**으로 해석 →
`using password: NO` → 인증거부 → import 실패(exit 1) → 설치 DOA.

**증거 3겹**: ① 에러 유저명 `-p<hex32>` = `GenerateAlphanumericKey`(hex, L670) 형식 = G_DbPassword와 일치(=`-u` 비어 `-p` 밀림) ② 시리얼없이 분기 2곳 DetermineMultiTenantSlot 호출 0 ③ G_DbUser 기본값은 L276-277에만.

## 4. 봉합안 (구현은 결재 후) — 2안 비교

### 안A (권고) — DB셋업 직전 단일 가드 (모든 경로 커버)
DB 셋업 BatchContent 작성 직전(L853 부근, ssPostInstall)에서 빈 값이면 기본값 보장:
```pascal
// 봉합(작6): 시리얼없이 설치(LOCAL) 등 DetermineMultiTenantSlot 미호출 경로에서
//   G_DbUser/G_DbName 이 빈 채 mysql 인자에 들어가 ERROR 1045 → 설치 DOA(헌법 #20).
//   DB셋업 진입 직전 빈 값이면 단독모드 기본값으로 보장(모든 경로 화이트리스트).
if G_DbName = '' then G_DbName := 'hitpan_erp';
if G_DbUser = '' then G_DbUser := 'hitpan';
```
- 장점: **분기 N개 무관 — DB셋업 들어오는 모든 경로를 한 곳에서 차단**(화이트리스트 정신, slot빌더 R1 교훈). 미래에 새 분기 생겨도 안전.
- 단점: 근본(분기에서 함수 미호출)을 우회하는 방어. 단 LOCAL은 슬롯로직 불필요하므로 기본값 직접 세팅이 오히려 정합.
- 헌법 #1: 기존 줄 무수정, 신규 4줄 추가만.

### 안B — 시리얼없이 분기 2곳에서 기본값 세팅
L521·L559 Exit 직전에 각각 `G_DbName/G_DbUser` 기본값 추가.
- 장점: 원인 지점에 직접.
- 단점: **분기 2곳 중복 + 미래 새 분기 누락 위험**(헌법 #12 정신 — 빠짐). LOCAL 외 다른 미호출 경로 생기면 재발.

→ **PM 권고 = 안A**(단일 가드, 빠짐 없음). 단 사장님 결정.
