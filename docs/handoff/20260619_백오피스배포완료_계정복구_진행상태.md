## 2-B. ✅ NCP 복구 완료 (2026-06-19 추가 — 시드계정+권한 둘 다 복구)
**상황**: DB 통째 교체로 ① platform_admins 계정 ② bo_permissions 권한 시드 둘 다 날아감(빈 자립형 스키마라 시드 0). 화면에서 로그인은 됐는데 협력업체 목록이 **403** → 원인 = bo_permissions 비어있음 + role 어휘 어긋남.

**실측 진범 (코드 증명)**:
- 권한검사 = BoPermissionAttribute → BoPermissionService.IsAllowedAsync(key, role). role은 JWT의 `role` 클레임.
- master 계정 role = **super_admin** (platform_admins.role enum: super_admin/billing_admin/cs_admin/readonly).
- 기존 권한 시드(db/migrations/20260604_bo_permissions*.sql)의 allowed_roles = `owner,platform_owner,platform_admin` → **super_admin 없음** → 403.

**복구 (사장님이 NCP ssh로 직접 실행, 둘 다 성공 실측)**:
1. platform_admins INSERT (master@hitpan.kr / super_admin / BCrypt해시 60자 검증). → 로그인 OK.
2. bo_permissions 10행 INSERT IGNORE — 기존 6/4 시드 전체 + **allowed_roles 끝에 super_admin 추가**. (tenants.suspend만 owner,platform_owner,super_admin) → 협력업체 403 사라짐(강력 새로고침 후, 60초 캐시 때문).

**아직 미확인 (다음 세션 P0)**: 협력업체 메뉴 1개만 확인됨. **다른 메뉴(대리점 정산/시리얼, 프로모션 등)는 권한 키가 시드 10개에 없으면 또 403**. 백오피스 전체 [BoPermission("...")] 키 전수 추출 필요.
