## 2. 진범 (코드로 좁힘, 실측으로 최종확정 남음)
- **지문 생성** `src/HitPan.Web/wwwroot/js/device-fingerprint.js:7-22` = `localStorage['hitpan_fp_id']`에 **`crypto.randomUUID()` 난수**를 심어 재사용. **기기 특성(UA·OS·해상도) 0개 사용.** 주석은 "환경값 기반 해시"라 써놓고 실제 난수(설계-구현 불일치). DDL `tenant_devices.fingerprint` COMMENT는 "UA+OS+해상도+시간대 SHA-256"(원설계).
- **정확한 진범 재기술(검증팀)**: "난수라 매번 다름"은 부정확(난수는 재사용됨). 정확히는 **난수 + 저장소 리셋 무방비 + origin(scheme+host+port) 격리**. localhost/127.0.0.1/터널도메인/demo가 각각 다른 origin=다른 localStorage → 접속 주소 바뀌면 새 난수=새 기기.
- **반증 완료(재조사 금지)**:
  - ❌ "지문 JS 미로드"(PM 1차 가설) = 거짓. index.html:47 정상 로드, 파일 실존.
  - ❌ "index.html:55-61이 지문 지운다"(CTO 의심) = 부분거짓. 그 코드는 ServiceWorker+Cache Storage만 삭제, **localStorage(지문)는 안 건드림**(PM·검증팀 코드 확인 일치).
  - ❌ "암호화저장소 vs 평문fp 생명주기 차이"(CTO 의심) = 기각. hitpan_fp_id는 device-fingerprint.js에만, HitPanProtectedLocalStorage·storage.js와 접점 0.
  - ✅ 슬롯 로직 본체(`TenantDeviceService` 등록·매칭·한도차단·revoked차단)는 **정상 작동**. UNIQUE(tenant_id,fingerprint) 정확 매칭. **봉합 대상은 지문 안정성이지 슬롯 로직 아님.**
- **부수 결함**: F2 빈지문(`getFingerprint` catch→''→`TenantDeviceService.cs:102-105` 등록스킵) / F3 "처음 기기 등록하시겠습니까?" 안내 코드에 아예 없음(조용히 자동 approved INSERT).
