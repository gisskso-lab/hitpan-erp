## 4. ⚠️ 최대 리스크 = 같은 PC라서 demo 오염 위험 (#39)

사장님 PC에 슬롯을 또 얹으므로, 17시나리오가 **실제 프로세스를 죽일 때** demo 까지 같이 죽을 위험이 1순위 리스크다. 방어 3중:

2. **죽이는 대상을 test 슬롯으로 한정** — `sc.exe stop` 대상 서비스명·프로세스를 test 인스턴스로 명시(demo 서비스명과 분리). ← **구축 시 검증팀 SoD 확인 항목**

→ 이 3중 방어가 안 서면 17시나리오 실행 금지. (헌법 #39 — "검증하다 운영 깨뜨리는 사고 원천 차단")

## 6. 결과물·검증 방법·영향 범위 (사장님 결재 판단용)

- **결과물**: 격리 테스트 환경 + 자동4건(S-A~D) PASS/FAIL 리포트(`reports/comms-scenarios-{타임스탬프}.md`).
- **검증 방법**: 워치독이 죽인 서비스를 5분 내 복구하는지 계측(Running·/health 200·EventLog).
- **영향 범위**: 운영(demo) **무손상이 절대 전제**. test 슬롯·test 도메인·hitpan_e2e 만 영향.
- **이 작업이 안 하는 것**: 수동 13건(물리·정전·백신격리)은 별도 세션. 코드 봉합은 FAIL 발견 후 별도 작업지시서.

## 6-1. 🚨 출하 마법사 EXE 빌드 절대 게이트 (사장님 못박음 2026-06-28)

> 사장님: *"마법사 설치파일 빌드할 때 빈 데이터여야 한다. 테스트용 데이터 들어간 채로 마법사 파일 빌드하면 안 돼."*

- **출하 마법사 EXE(.iss 빌드)는 본 작업 범위가 아니다.** 본 작업은 테스트 환경 구축·실측까지만.
- 출하 마법사 EXE는 **신규 고객 첫 설치 출하본**이므로, DB는 **`installer/hitpan_db_clean.sql`(빈 DDL, 데이터 0건)만** 들어간다(헌법 #36 단일 진실원).
- **금지(절대)**: 테스트 데이터(`hitpan_e2e` items·partners·거래) / 운영 demo 데이터(items 336·partners 13,542) 가 출하 EXE에 섞이는 것. 섞이면 신규 고객이 남의 거래처·상품을 보는 데이터 격리 사고(헌법 #18·#22 위반) = 즉시 P0.
- **빌드 전 게이트**: 마법사 EXE 빌드 직전 → ① 번들 DB가 clean DDL인지 확인 ② 어떤 인스턴스(demo·test) 데이터도 미포함 확인 ③ 121테이블 게이트 통과(빈 데이터). 이 3확인 없이 `build-installer.ps1` 실행 금지.
- 본 게이트는 EXE 빌드 결재가 떨어졌을 때(별도 작업지시서) 다시 명시한다. EXE 빌드 자체는 여전히 사장님 GO 결재 후에만(EXE 빌드 홀드 정책).
