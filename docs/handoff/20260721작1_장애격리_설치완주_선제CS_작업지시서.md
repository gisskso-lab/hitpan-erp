## 1. 배경 — 왜 지금 이 작업인가

2026-07-21 Windows Sandbox 백지 환경 실측에서 **설치가 사상 처음 완주**했다.
그러나 동시에 **사장님 원칙을 정면으로 위반하는 구조**가 드러났다.

| 관측 | 의미 |
|---|---|
| 워치독 등록이 설치를 **32분 정지** | 검증팀이 개발팀을 멈춰 세움 |
| 실제 워치독은 **RUNNING**인데 "실패" 안내 | 거짓 안내 → CS 사고 |
| 안내에 **"고객센터 문의"** | 전 고객 전화 시 CS 마비 |
| 본사 **수신 엔드포인트 0건** | 선제 CS 불가 (고객 전화에만 의존) |

**진범** (가설 5회 반증 후 확정):
`installer/scripts/InstallWatchdog.ps1` L60-67 `Register-ScheduledTask` (CIM 기반)가
32분 대기 후 예외 → `$ErrorActionPreference='Stop'`(L9)이 exit 1로 변환.
같은 스크립트의 `sc.exe`(비-CIM)는 전부 성공 — **CIM 계열만 실패**.

## 3. W-1 — 설치 완주 보장

**담당**: 네트워크 매니저(마이클) + 백엔드 개발자 1명
**대상**: `installer/scripts/InstallWatchdog.ps1`, `installer/HitPan-Universal.iss`

### W-1-1. CIM 제거 → `schtasks.exe` 전환 (진범 봉합)

| 현재 (CIM — 32분 hang) | 전환 후 (비-CIM) |
|---|---|
| `New-ScheduledTaskAction` | `schtasks /Create` 인자 |
| `New-ScheduledTaskTrigger -Once -RepetitionInterval 5분` | `/SC MINUTE /MO 5` |
| `New-ScheduledTaskPrincipal -UserId SYSTEM -RunLevel Highest` | `/RU SYSTEM /RL HIGHEST` |
| `Register-ScheduledTask -Force` | `/F` |

**근거**: `.iss` L1305·L1837 등에서 `schtasks`가 이미 정상 동작 중. **사내 검증된 방식으로 통일**.

### W-1-2. 시간 상한 (피호출측 구현)

⚠️ **Inno Setup `ewWaitUntilTerminated`는 타임아웃 인자를 제공하지 않는다.**
→ 상한은 **PowerShell 스크립트 자신이** 갖는다.

| 구간 | 상한 |
|---|---|
| 서비스 등록 | 짧게 |
| 서비스 기동 | 중간 |
| Guardian 등록 | 짧게 |
| **스크립트 전체** | **상한 필수 — 어떤 경우도 초과 금지** |

> **구체 수치 = 사장님 결재 Q-1.** 미확정 상태로 착수 금지.

### W-1-3. `$ErrorActionPreference` 구간별 완화

L9의 전역 `'Stop'`을 **부가 단계에서 완화**한다. Guardian 등록 실패가 서비스 등록 성공을
무효화하면 안 된다(사장님 원칙: A가 죽어도 B는 산다).

### W-1-4. 성공/실패 정확 판정 (거짓 실패 제거)

**현재**: 스크립트 exit code만 판정 → "RUNNING인데 실패" 발생
**전환**: **실제 상태로 판정**

```
워치독 성공  = sc query HitPanWatchdog → RUNNING
Guardian 성공 = schtasks /query → 존재
```

| 워치독 | Guardian | 판정 | 고객 안내 | 본사 보고 |
|---|---|---|---|---|
| RUNNING | 존재 | 완전 성공 | **없음** | 성공 |
| RUNNING | 없음 | 부분 성공 | 있음 | 실패 |
| 미기동 | — | 실패 | 있음 | 실패 |

### W-1-5. 진행 표시

.NET 18분·VC++ 4분 구간에 경과 안내 추가 (문구만, 기능 변경 없음).

### W-1 수용 기준
- [ ] Guardian이 `schtasks /query`로 확인됨
- [ ] 워치독 등록 구간이 상한 이내 종료
- [ ] 워치독 RUNNING이면 경고 팝업 **0건**
- [ ] **워치독 강제 실패 주입 시에도 ERP 로그인 도달** ← 사장님 원칙 핵심

## 5. W-3 — 본사 선제 CS

**담당**: 백엔드 매니저 + 백엔드 개발자 2명 + 보안 개발자 1명

### W-3-1. 수신 엔드포인트 (`HitPan.Backoffice.API`)

🔴 **CTO BLOCKING C-1 반영 — 수신 경로는 이미 확정되어 있다. 신규 작명 금지.**

워치독은 **이미 특정 주소로 송신 중**이며, 1.2.34가 고객 PC에 배포되어 있다.

```

src/HitPan.Watchdog/appsettings.json:21      https://back.hitpan.kr/watchdog/emergency
src/HitPan.Watchdog/WatchdogOptions.cs:12-13 (동일 기본값 하드코딩)
```

| 규칙 | 내용 |
|---|---|
| **메타핑 경로** | **`/watchdog/ping`·`/watchdog/emergency` 고정. 변경 절대 금지** |
| 설치 보고 경로 | 별도 신설 가능 (메타핑과 분리) |
| 불가피한 변경 시 | **구 경로 병행 유지** → 전 고객 버전 소진 확인 후에만 제거 |

> ⚠️ **다른 경로로 만들면 이미 배포된 전 고객 워치독의 메타핑이 영구 단절된다.**
> 7/16 고리4 서명 사고(`openssl DER ≠ 검증기 P1363`)와 동일 유형 —
> **송신·수신 계약 불일치**가 전 고객 기능을 조용히 죽인다. 헌법 #20 위반.

| 항목 | 설계 |
|---|---|
| 인증 | **시리얼 기반**. ERP 로그인 토큰 사용 **금지** (헌법 #7 계층 혼용) |
| 멱등 | 동일 시리얼+시각 중복 수신 시 갱신 |
| 저장 | 고객사별 최신 1행 + 이력 |
| 보관 정책 | **보관 기간·용량 상한 명시** (전 고객 설치마다 1건 유입 — CTO 권고 A-3) |
| 실패 | 수신 실패해도 설치·워치독 **무영향** |

### W-3-2. 데이터 최소주의 게이트 (헌법 #18·#22)

**화이트리스트 방식** (블랙리스트 아님 — 새 필드 실수 유입 시 기본 거부):

### W-4-4. 미들웨어 예외 격리

🔴 **CTO BLOCKING C-2 반영 — "fail-open"의 범위를 오독하면 보안이 열린다.**

**정확한 구분 (반드시 이대로 구현할 것):**

| 구분 | 처리 | 사유 |
|---|---|---|
| 레이트리밋 **초과 판정** (429 반환) | ✅ **그대로 유지** | 정상 동작. **보안 기능이다** |
| IP 화이트리스트 **차단 판정** | ✅ **그대로 유지** | 정상 동작. 보안 기능 |
| 위 로직 **자체의 예외** (헤더 파싱·설정 바인딩 오류) | catch 후 `_next()` 통과 | 부가기능 고장이 본 기능을 막으면 안 됨 |

> ⛔ **"fail-open = 초과해도 통과"로 구현하면 브루트포스가 열린다. 절대 금지.**
> 실제 코드 확인: `RateLimitMiddleware.cs:33-41`(로그인 1000회/5분)·`:48-54`(쓰기 600회/분)의
> **429 반환은 정상 동작이지 실패가 아니다.**

| 미들웨어 | 현재 | 조치 |
|---|---|---|
| `SessionLimitMiddleware.cs:83` | ✅ 예외 격리됨 | 유지 (정답 패턴) |
| `TermsConsentMiddleware.cs:107` | ✅ 예외 격리됨 | 유지 (정답 패턴) |
| `RateLimitMiddleware.cs:19-90` | ❌ try/catch 0건 | **예외만 격리.** 429 판정 로직 무손상 |
| `HealthIpWhitelistMiddleware.cs:11` | ❌ 생성자 파싱 → 전 API 500 | **안전 파싱.** 차단 판정 무손상 |

> **보안 상무(안철수) 사전 검토 대상** — 헌법 #23 5중 검증 ②.
