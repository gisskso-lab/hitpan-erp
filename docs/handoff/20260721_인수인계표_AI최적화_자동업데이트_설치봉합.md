# §0. 판단 알고리즘 (이걸 지키면 오늘보다 똑똑해진다)

> 오늘 세 번의 헛발은 **정보 부족이 아니라 판단 절차 부재** 때문이었다.
> 아래 4개 규칙은 오늘 실패에서 역산한 것이다. 새로운 상황에도 그대로 적용하라.

## 규칙 1 — 가설을 세웠으면 **반증부터** 실행 (RCA 게이트)
```
증상 발견 → 가설 수립 → ❌ 바로 수정 금지
                      → ✅ "이 가설이 틀렸다면 무엇으로 알 수 있나?" 를 먼저 실행
                      → 그 관측이 가설을 지지할 때만 수정
```
**비용 근거**: 반증 1회 = 3분. 틀린 수정 1회 = 40분(빌드·배포·재시작·재확인). **13배 차이.**

| 증상 유형 | 반증 명령 (수정 전 필수) |
|---|---|
| 프로세스 hang | `Get-Process` — 무엇이 살아있나 |
| 서비스 이상 | `sc.exe query <name>` (⚠️ `sc`는 PowerShell에서 Set-Content 별칭) |
| 배포 반영 안 됨 | `systemctl show <svc> -p ExecStart` — **실제 실행 경로부터** |
| 기능이 안 돎 | 그 기능 코드가 **그 빌드에 실제로 있나** (문자열 grep) |
| 설정값 안 먹음 | 파일 vs 환경변수 — 어느 쪽이 이기나 |

## 규칙 2 — "왜 안 되지?" 보다 **"어디까지 갔나?"**
증상을 통째로 보지 말고 **파이프라인을 쪼개서 마지막 성공 지점**을 찾는다.
- 오늘 예: 설치 hang → 로그 마지막 줄이 `[재설치안전] 정지 시작` → **그 함수 안에서 멈춤** 확정 → 그 안의 명령만 후보로 좁힘.
- 이 방식이 아니면 "설치가 안 된다"는 무한한 원인 공간에서 헤맨다.

## 규칙 3 — 관측과 추론을 **문장에서 분리**
```
❌ "cloudflared 서비스가 hang을 일으키고 있습니다"        (추론을 사실처럼)
✅ "로그 마지막 줄이 X다. 이 구간 명령은 A/B/C. 아직 어느 것인지 모른다" (관측+미지 명시)
```
사장님이 오늘 `sc.exe query`로 PM 가설을 깬 것 = 이 분리가 안 돼서 생긴 일. **모르면 모른다고 쓴다.**

## 규칙 4 — 검증 안 된 것을 "완료"라 하지 않는다
- 코드리뷰 통과 ≠ 동작함. 빌드 0/0 ≠ 동작함. **백지 Sandbox 종단만 검증**(사장님 헌법).
- 보고 시 **[검증됨] / [미검증]** 라벨을 붙인다. §2가 그 예시다.

## 규칙 5 — 스코프가 커지면 **멈추고 보고**
오늘 "자동업데이트 실측" → "설치 봉합" → "랜딩 재배포"로 두 번 커졌다.
커지는 것 자체는 정상(진짜 원인이 앞단에 있었으므로)이나, **커질 때마다 사장님께 보고**하고 진행 여부를 받는다. 단 사장님이 "진행해"라고 하시면 그게 승인이다 — 같은 걸 두 번 묻지 않는다.

# §3. 오늘 밤 한 일 (커밋 순)

## A. manifest 1.2.34 게시 (완료)
- 문제였던 "manifest 1.2.30 고정 = 전 고객 업데이트 정지" 해소.
- 방식: 로컬 빌드 → **사장님이 scp/ssh로 NCP 업로드 + `publish-update.sh` 실행**.
- ⚠️ `--webroot /var/www/updates` 필수(스크립트 기본값과 실제 웹루트가 다름).

## B. 설치 hang P0 봉합 — 커밋 `f06615b`
- **진범**: 재설치용 `StopRunningComponentsForReinstall`가 `ssInstall`마다 **최초/재설치 구분 없이 무조건 실행** → 백지 설치에서 `taskkill /F /IM` 무한 hang → **전 신규고객 설치 차단**.
- **봉합(축 A)**: `IsPreviouslyInstalled()` 신설 — `{app}\db.conf` or `hitpan-keys.conf` 있으면 재설치, 없으면 최초 → **최초면 통째 스킵**.
- 검증팀 SoD: 코드는 CLEAR. 단 **"제거 후 재설치"는 축 B(P1)로 이월** — "재설치 hang 완전해소"라고 보고하면 안 됨.

## C. 랜딩 manifest 자동조회 — 커밋 `b3a2764`
- 사장님 지시 **"랜딩은 무조건 최신"** 구현. manifest(단일 진실원)를 읽어 다운로드 버전 자동 결정.
- 효과: **새 버전 = manifest만 갱신하면 랜딩·자동업데이트 동시 최신.** "랜딩만 옛 버전" 사고 구조적 불가.
- 폴백: manifest 실패 시 설정값 → 그것도 없으면 미표시+에러로그(헌법 #15).

### C-1. 새 버전 배포 절차 (이제 이게 표준)
```
1) Directory.Build.props 의 HitPanVersion 을 새 버전으로 (단일출처)

   ⚠️ -SkipBundleDownload 필수 (번들 캐시 있는데 다운로드 검증에서 죽음)
```

# §5. 🔴 함정 (Claude가 반복해서 빠지는 곳 — 반드시 읽을 것)

## A. 진범 확인 전에 손대지 말 것 (오늘 3번 반복됨)
| 증상 | 틀린 가설 | 진짜 |
|---|---|---|
| 자동업데이트 실패 | 배포도구 문제 | 옛 EXE에 고리4 코드 자체가 없었음 |
| 설치 hang | `sc stop cloudflared` | `taskkill` (사장님이 `sc.exe query`로 반증) |
| 랜딩 1.2.33 | `/var/www/landing` 배포 | 실행 폴더는 `/opt/hitpan/landing` |

**절차**: 가설을 세웠으면 **"틀렸다면 무엇으로 알 수 있나"를 먼저 실행**한다.
- 프로세스 hang → `Get-Process`로 무엇이 살아있는지
- 서비스 문제 → `sc.exe query <이름>` (⚠️ PowerShell에서 `sc`는 Set-Content 별칭, `sc.exe`로)
- 배포 반영 안 됨 → `systemctl show <svc> -p ExecStart` 로 **실제 실행 경로**부터

## B. 버전 동일하면 자동업데이트 안 뜬다
설치본 == manifest 버전이면 감지 0. 실측하려면 **manifest가 설치본보다 높아야** 한다.

## C. 실측 시간대 게이트 (낮에 하면 오판)
- **Major 채널 적용 = 영업시간(평일 09~18시) 밖에만** (`Worker.cs` `IsBusinessHour`)
- 낮에 Y 눌러도 "보류"가 **정상 동작**이다. 실패로 오판 금지.
- 하루 1회 평가 게이트 있음 → 재실측 시 워치독 서비스 재시작.

## D. "덮어 재설치"는 존재하지 않는 경로 (사장님 헌법 #40)
최초 1회 설치 → 이후 워치독 자동업데이트. 재설치는 포맷·PC교체(백지)뿐.
**"덮어 재설치로 검증" = 틀린 전제.** 검증은 "1.2.xx PC가 스스로 다음 버전으로 가나".

## E. 개발 PC 정상작동은 검증이 아니다 (사장님 헌법)
빌드 0/0·로컬 200 = 검증 아님. **백지 Windows Sandbox 종단만 진짜.**

## F. 보고는 정직하게
- 검증 안 된 것을 "완료"라 하지 않는다. 오늘 봉합 2건은 **실측 전**이다.
- "재설치 hang 완전해소" ❌ → "최초설치 hang 차단(재설치는 P1 이월)" ✅

# §7. 사장님 자동업데이트 목표 그림 (변하지 않는 최종 스펙)

```
로그인/새로고침 → 버전비교(서버가 높을 때만, 다운그레이드 절대 금지)
→ Y/N 팝업 + 변경내용 반드시 공지 → Y=실제 진행 / N=안 함
```
- **완전자동 아님**(로컬 ERP는 고객사마다 환경이 달라 강제 배포 시 일부 고객 다운)
- **전 등급 동의 필요**(강제 등급조차) — 통제권은 고객이 전적으로 가짐
- 등급제: 강제(보안·치명)/권장(버그)/선택(UI). CS는 등급을 안내만, 판단하지 않음

# §10. 사장님과 일하는 법 (이 프로젝트 고유 지식 — 범용 Claude가 모르는 것)

## 10-1. 같은 걸 두 번 묻지 않는다 (오늘 지적받음)
사장님이 이미 답한 것을 재확인하면 **"몇 번을 말했는데"**가 나온다.
- 결정된 사항은 **결정으로 취급하고 실행**한다.
- 물어야 할 때: 답이 **작업 방향을 바꾸는** 경우만. 그 외엔 판단해서 진행하고 결과를 보고.
- ❌ "A로 할까요 B로 할까요?"를 이미 A로 정해진 뒤 다시 묻기
- ✅ "A로 진행합니다" 하고 실행 → 결과 보고

## 10-2. 당연한 것은 묻지 않는다
"설치도 안 되는 버전을 폐기할까요?" 같은 질문 = 사장님 시간 낭비.
**상식적으로 하나뿐인 답이면 그냥 한다.**

## 10-3. 사장님은 관측으로 반증한다 — 배울 것
오늘 PM 가설(`sc stop`)을 사장님이 `sc.exe query` 한 줄로 깼다. **이게 올바른 디버깅이다.**
사장님이 명령 결과를 붙여주시면 그건 **가설 검증 데이터**다. 정독하고 가설을 갱신하라.

## 10-4. 정직이 최우선
- 안 되면 "안 됐다", 모르면 "모른다". **거짓 봉합·받아쓰기 = 최악.**
- 사장님이 가장 싫어하는 것: 검증 안 됐는데 됐다고 하기, 진범 모르면서 아는 척.
- PM이 틀렸으면 인정하고 바로 정정. 변명 금지.

## 10-5. 말투 금지어
- **"박제/박다/박힘/박혀있음" 일체 금지** → 정상 한국어(저장했다/적용했다/기록했다)
- 채팅 본문에 도구 호출·코드 타이핑 금지
- 고객 노출 영역에 개발용어·영어 남발 금지

## 10-6. 이 프로젝트에서 반복되는 오판 3종 (미리 알고 피하라)
| 오판 | 진실 |
|---|---|
| "reseller_id가 안 읽히네 = 잔재다" | **헌법 #37 덩어리2** — 수신 캐시 컬럼, 보존 대상. 제거 절대 금지 |
