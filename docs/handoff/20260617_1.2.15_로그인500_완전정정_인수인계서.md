## 3. 진범 흐름 (1.2.13 → 1.2.14 → 1.2.15)

| 버전 | 진범 | 결과 |
|---|---|---|
| 1.2.13 | (로그인 화면까지 도달) | users doesn't exist 500 |
| 1.2.14 | USE hitpan_erp 제거 → 테이블이 t003로 정상 진입 | 하지만 ALTER DATABASE 잔존 → 50개에서 중단 → 여전히 500 |
| **1.2.15** | **ALTER DATABASE 16줄 제거 + 4건 보강** | 91개 전수 import 기대 |

### 1.2.14가 부분 성공한 증거 (검증 과정)
설치 후 DB 직접 조회:
- `hitpan_erp_t003` = 50개 테이블 (91개 아님)
- `hitpan_erp`(원본) = 0개 → **USE 봉합은 성공** (테이블이 올바른 DB로 감)
- 50개를 알파벳 정렬하면 마지막이 `partner_special_prices`(50번째), 그 다음 `partners`...`users`...가 전부 없음

### 진범② 메커니즘 (매니저 4명 만장일치)
`hitpan_db.sql`(mysqldump --databases 산물)에 `ALTER DATABASE \`hitpan_erp\`` 16줄이
박혀 있었음. 첫 번째가 50번째 테이블 직후 라인에서 실행되는데, 회사별 DB로 import
중이라 `hitpan_erp` DB가 없음 → **ERROR 1049 Unknown database** → import 중단 →
51번째부터 미생성 → users 없음 → 로그인 500.

(이 ALTER DATABASE는 mysqldump가 객체별 collation 차이로 토해낸 부산물. 기능 불필요.)

## 5. 빌드 환경 주의 (다음 PM 필수)

**EXE 빌드는 알약 제외 폴더(`installer-build`)로 출력해야 성공.**
- 알약(백신) 실시간 감시가 ISCC의 `BeginUpdateResource`를 차단 → `dist`로 직접 출력 시
  `Resource update error (5)`로 빌드 실패.
- 알약 "탐지 제외 폴더" 등록만으로는 부족 (행위 기반 실시간 감시는 별개).
- 검증된 빌드 명령:
  ```
  ISCC.exe /DAppVersion=X.Y.Z /DBackofficeApi=https://back.hitpan.kr
    /DOutputName=HitPan-ERP-Setup-X.Y.Z /DOutputDir=<installer-build>
    /DBundleDir=<installer-build/bundle> HitPan-Universal.iss
  ```
  → 성공 후 dist로 Move-Item.
- 빌드 소요 약 200~220초 (ERP/워치독/번들 스킵).
