## 2. PM 조율 — 이견 2건 판정

### 조율 1 — sudoers 엄격 vs webroot 인자 (존 ↔ 마이클 ↔ 백엔드)

**세 의견이 사실상 한 점으로 수렴한다:**
- 백엔드: sudoers를 `--zip … --manifest …` 두 인자만 허용. 오버라이드 인자(`--webroot`·`--private`·`--allow-republish`) 차단.
- 존: sudoers를 엄격하게 하려면 `--webroot`를 안 넘겨야 함 → 스크립트 기본값 정정이 화이트리스트를 단순화.
- 마이클: webroot 기본값을 `/var/www/updates`로 정정하는 게 근본책 (손실행도 보호).

**PM 판정:** ✅ **스크립트 기본값 `/var/www/updates` 정정 + sudoers는 `--zip`/`--manifest` 두 인자만.**
→ webroot·feed-url을 CI가 인자로 안 넘기므로 sudoers 패턴이 단순·엄격해지고, 손실행도 보호되고, 오버라이드 우회로도 봉인됨. **1석 3조.** (단 정식 피드 기준. G7 베타 피드는 조율2 참조)

### 조율 2 — G7 베타/정식 채널: 옵션A 내장 vs 별건 (AI수석 ↔ 마이클)

- AI수석: G7은 "미설계"가 아니라 "미배선". `HITPAN_UPDATE_FEED`·`--webroot`/`--feed-url`·`-DownloadUrlBase` 레버 이미 존재. **옵션A(피드 하위 디렉토리 `/beta/`) 를 G1에 내장** (나중에 끼우면 재수술).
- 마이클: feed **물리 분리**는 nginx 설정 추가(서브도메인이면 DNS·인증서 = #29 정면) 수반 → **별건 결재로 분리**. G1은 단일 feed 전제로 착수, webroot 파라미터화로 미래 확보.

**PM 판정:** ✅ **절충 — "파라미터는 G1에 내장, 값 주입(베타 피드 물리 생성)은 별건."**
- G1 워크플로우는 `environment`(beta/production) input + webroot/feed-url/download-url-base **분기 배선을 처음부터 넣는다** (AI수석 정합 — 재수술 방지).
- 단 **베타 피드 디렉토리 실제 생성 + nginx location 추가**는 별건 (마이클 정합 — nginx 변경은 결재). G1 착수 시엔 production 피드만 실동작, beta 분기는 배선만 대기.
- 이러면 조율1의 "sudoers는 --webroot 안 받음"과 충돌? → **아니다.** 베타 배포가 필요해지는 시점에 sudoers에 beta용 두 번째 화이트리스트 라인을 추가(사장님 sudo)하면 됨. G1(정식) 착수엔 영향 0.
