## 2. 작업 범위

### W-1 · [보안 핵심] 증표에 사업자번호 바인딩 + 오프라인 재대조
**보안팀 필수조건 1·2·3** — 무단사용 방지의 실효 게이트. **이것이 이 작업의 보안 본체.**
- **증표 발급**(`LandingPublicController.cs:236-247`): `tokenPayload`에 `biz_no_hash` 추가(평문 아님, HMAC — #22·#40 정합).
- **오프라인 재대조**(`SeedParentCommand.cs` / `SerialProofVerifier.cs`): seed-parent가 **입력 사업자번호의 해시 == 증표 내 biz_no_hash** 를 오프라인 검증. 불일치 시 부모계정 생성 거부.
  - 현재: 온라인 claim에서만 bizHash 대조, 오프라인은 서명·aud·exp만. → 온라인 검증이 오프라인 경로에서 무력화되는 구멍 봉합.
- **replay 방어**(보안팀 필수조건 2, **CTO 부분수정 1 확정**): `allowExpired:true`가 무효화를 무의미하게 만듦.
  - **jti blocklist·온라인 카운터 금지**(#30 오프라인 완결 위반). 확정 방식 = **① 증표 절대수명 상한**(seed-parent가 `allowExpired`여도 "발급 후 N시간(예: 72h) 절대상한"은 검사 — 현재 exp 완전무시를 좁힘) **+ ② 기존 replay 2게이트 명문화**(`CompanyBootstrapProvisioner` `is_locked_from_landing=1` 재부트스트랩 차단 + `existingParent>0` tenant당 부모 1명 가드, 이미 존재·실측 확인).
  - 옛 시리얼 온라인 무효화는 `ResendLicense`의 `license_key_hash` 교체로 자동 성립(claim 통과 후에만 증표 발급). 잔여 위협 = "손에 쥔 유효 증표를 백지 PC 재주입"뿐 → 절대수명 상한이 이걸 좁힘. 온라인 0.
- **하위호환**(CTO 부분수정 2·3): `ProofPayload`에 `biz_no_hash` **nullable 필드** 추가 = payload 필드 추가일 뿐 **서명 규격·개인키 불변 → kid 롤오버 불필요**(과잉조치, 삭제). 이행기 규칙 = "payload에 biz_no_hash 있으면 반드시 대조, 없으면(옛 증표·2-part HMAC) 통과". **이행기 종료 트리거 = 7/7 작지서 ④단계(기발급 HMAC 시리얼 소진)와 동일 시점에 필수화 전환**(영구화 금지, §8-3).

### W-3 · 신규설치 로컬 사업자번호 차단 (경고→실제 차단)
- **저장**: registry.json 쓰기(`iss:1531-1571`)에 `BIZ_NO_HASH` 필드 추가. 사업자번호 SHA-256 해시(평문 미저장, #22·#40 로컬 정합).
- **⚠️ 페퍼 정합(CTO 부분수정 5) — 해시가 두 종류다, 혼용 금지**: (a) **로컬 registry `BIZ_NO_HASH`** = 로컬 자기중복 탐지 편의용 → **페퍼 없는 SHA-256**(본사 페퍼를 EXE에 넣을 수 없음, #22·#23). (b) **증표 내 `biz_no_hash`**(W-1) = 본사 `Backoffice:BizNoPepper` HMAC(claim 대조용). **둘은 다른 해시다.** W-3 로컬 차단은 (a)로, W-1 오프라인 재대조는 (b)로. 착수 전 세 곳(registry·증표·claim) 해시 입력·페퍼 못박기.
- **조회·차단**: `DetermineMultiTenantSlot` PS 스크립트(`iss:337-348`)에 **신규설치 모드일 때** bizNoHash 중복 검사 → 중복이면 `$slot=-2`.
- **★ 실제 차단**(현재 구멍 봉합): `-2` 시 `Result:=False` 실제 차단(현재 `-1`이 `G_SlotIndex:=1`로 덮고 통과하는 구조를 함수화 또는 전역 `G_SlotBlocked`로 `NextButtonClick`이 `False` 리턴하게 배선).
- **멀티슬롯 유지**: 다른 사업자번호면 bizNoHash 불일치 → 기존 슬롯 로직 그대로. 무손상.

### W-4 · 재설치 흐름 (새 시리얼 검증)
- 재설치 모드는 로컬 bizNo 중복이 정상 → `-2` 차단 건너뜀. 대신 그 사업자번호 슬롯이 registry에 **없으면** "재설치 대상 없음 — 처음 설치를 선택하세요" 안내 후 차단(설계팀 미결 #4, 사장님 확인 반영).
- 새 시리얼 유효성 = `CallLicenseClaimApi`(`iss:521`) 재사용. 재발급으로 옛 해시 교체됨 → 옛 시리얼로 오면 `Valid=false` 자동 거부. **본사 재발급 없이는 재설치 불가**가 자동 성립.
- 슬롯 = 기존 tenantCode 슬롯 재사용(새 슬롯 안 뽑음, db.conf·포트·DB 보존).

### W-5 · 백오피스 시리얼 재발급 (기존 재사용 + 이력)
- **엔드포인트 신규 0** — `ResendLicense`(`SignupsAdminController.cs:232-314`) 재사용. 새 시리얼 생성 → `tenants.license_key_hash` 교체(옛 무효화) → 평문 1회 노출. #22(해시만)·#35(백오피스 전담) 정합.
- **재발급 이력**(설계팀 미결 #2, 헌법 #24 추적): `tenant_license_reissue_history`(tenant_id, reason, reissued_by, reissued_at, old_hash_prefix) — 백오피스 DB(NCP, ERP clean DDL과 무관). 사장님 확인 후.
- UI 문구 "재설치/분실 시 재발급"으로 확장.
- **조회 키 상향 검토**(설계팀 미결 #5): `ResendLicense`가 company_name 기반 → tenant_code/signupId 정확 매칭으로 상향(동명 회사 사고 방지).

### W-6 · 폴백 조건부 차단 (사장님 옵션 B)
- `CallLicenseClaimApi` 반환 3분기: **취득 / 통신실패 / 검증거부**.

## 4. 정직한 한계 — 실패가 아니라 물리적 경계 (CTO 부분수정 4)
- **다른 PC 무단복제(S3)는 로컬만으론 못 막음. 이건 "보안 실패"가 아니라 물리적 경계다.** 완전 차단하려면 본사가 고객 기기를 알아야 하는데, 그건 사장님 데이터 최소주의(#22)와 **정면충돌**한다. 지금 설계 = "같은 PC 무단사용 **실제 차단** + 다른 PC 복제는 **탐지·사후무효화**(후속)"라는 헌법 정합 균형점이며, 이 경계를 정직하게 그은 게 오히려 옳다.
- 사업자번호는 공개정보 → 표적의 실제 시리얼+실제 사업자번호 동시 확보 시 정품과 구분 불가(구조적, 어떤 로컬 방지로도 불가).
