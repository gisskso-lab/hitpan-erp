사장님 지시로 Windows Sandbox 설치가 "런타임 설치 중"에서 멈춘 건을 조사.

**사장님이 세우신 원칙 (중요, 영구 적용)**:
> "히트판의 개발취지는 각 기능별 철저한 모듈화가 기본 원칙이야.
> A가 안된다고 해서 시스템 전체가 다 안되는건 안되. A만 안되고, A만 복구하도록 해야지."
>
> "설치는 히트판개발팀이라면, 워치독은 검증팀의 역할이 되야하지.
> 검증팀이 놓친 게 있다고 한들, 개발팀이 개발을 안 하고 쉬는 게 아니잖아."

## 5-2. 판단 알고리즘 (새벽 문서 §0 유효 — 계속 적용)
1. **가설 세웠으면 반증부터.** 반증 3분 vs 틀린 수정 40분 = **13배**
2. **"왜 안 되지?" 보다 "어디까지 갔나?"** — 파이프라인 쪼개 마지막 성공 지점 찾기
3. **관측과 추론을 문장에서 분리** — 모르면 모른다고 쓴다
4. **검증 안 된 것을 "완료"라 하지 않는다** — [검증됨]/[미검증] 라벨
5. **스코프 커지면 멈추고 보고** (단 "진행해"는 승인 — 같은 걸 두 번 묻지 않는다)

## 5-3. 오늘 새로 배운 것

**"정상 동작"을 "고장"으로 읽지 말 것.**
- 약관 미동의 → `/terms` 이동 + `return` → 팝업 코드에 도달 못 함 = **설계상 정상**.
  오늘 팝업이 처음에 안 뜬 이유가 이것이었다. 재로그인하니 떴다.
- 403 = `TermsConsentMiddleware` 정상 동작(헌법 #24). 2주간 이걸 "로그인 깨짐"으로 읽었다.

**"한 번도 실행된 적 없는 코드"는 검증된 적 없는 코드다.**
팝업 코드는 6/29에 들어가 리뷰·빌드를 통과했으나, **실제로 뜬 적이 0회**라 결함이 잠복했다.
오늘 처음 실행되자 즉시 드러났다. → 사장님 헌법 *"개발PC 정상작동은 검증이 아니다"* 의 정확한 사례.

**CI가 죽으면 그 위의 모든 작업이 무의미해진다.**
2주 두더지잡기의 근본 원인은 개별 버그가 아니라 **검증 장치의 부재**였다.
증상을 고치기 전에 **"검증이 돌고 있나"부터** 확인한다.
