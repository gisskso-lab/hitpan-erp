# 🟢 트랙2 사장님 GitHub 작업 매뉴얼 (몰아서 한 번에)

> **이 문서는 사장님이 GitHub 브라우저에서 하실 3가지를 모은 것입니다.**
> PM이 NCP 쪽(래퍼·계정·git미러·비상경로)은 이미 다 해뒀고, **GitHub 계정 작업만 사장님 손**입니다.
> (PM은 사장님 GitHub 계정에 로그인 못 하므로 이건 사장님만 가능)
>
> 준비물: GitHub 로그인 된 웹브라우저 + 휴대폰
> 소요: 약 10분. 순서대로. 각 작업 끝에 "이 화면 나오면 성공".

---

## 🗺️ 사장님이 하실 3가지

```
[A] GitHub 토큰 발급 → NCP가 GitHub에 직접 확인하는 열쇠 (B-4 보안)
[B] production 환경에 사장님을 승인자로 → 게시 시 폰에 "승인?" 뜸
[C] main 브랜치 보호 → 검증 안 된 코드가 고객에게 못 가게
```

세 개 다 하시고 나면, PM이 마지막 6단계(자동배포 켜기)를 하고 **첫 실측(딸깍)**으로 넘어갑니다.

---

## [A] GitHub 토큰 발급 (B-4 보안 열쇠)

**왜**: NCP가 "이 게시가 진짜 GitHub에서 승인된 것인지" 스스로 확인하려면, GitHub에 물어볼 열쇠(토큰)가 필요합니다.

### A-1. 토큰 발급 화면 열기
브라우저 주소창에 붙여넣기 → 엔터:
```
https://github.com/settings/personal-access-tokens/new
```
*(GitHub 로그인 안 돼 있으면 로그인 먼저)*

### A-2. 화면 채우기 (위에서부터)
| 항목 | 입력값 |
|---|---|
| **Token name** | `hitpan-ncp-b4-readonly` (아무 이름이나 OK) |
| **Expiration** | `90 days` (또는 원하는 기간) |
| **Repository access** | ⦿ **Only select repositories** 클릭 → `gisskso-lab/hitpan-erp` 선택 |
| **Permissions → Repository permissions** | 아래 2개만 `Read-only`로: |
| &nbsp;&nbsp;• **Contents** | `Read-only` |
| &nbsp;&nbsp;• **Actions** | `Read-only` |
| (그 외 전부) | `No access` 그대로 |

### A-3. 맨 아래 **Generate token** 클릭
→ `github_pat_...` 로 시작하는 긴 문자열이 화면에 뜸.

**✅ 성공 화면**: `github_pat_...` 토큰이 보임.

### A-4. ⚠️ 이 토큰을 PM에게 안전하게 전달
- 이 토큰은 **한 번만 보입니다** (화면 닫으면 다시 못 봄).
- **복사해서 저(PM)에게 채팅으로 주세요.** PM이 NCP에 안전하게 저장합니다.
  *(토큰은 읽기전용이라 유출돼도 코드 변경 불가. 그래도 안전하게 다룹니다)*
- 또는 사장님이 직접 NCP에 넣고 싶으시면, PM이 그 명령도 드립니다.

---

## [B] production 환경에 사장님을 승인자로 (폰 승인 게이트)

**왜**: 이걸 해야 게시할 때 **사장님 휴대폰에 "승인하시겠습니까?" 알림**이 뜹니다. 사장님이 결재하신 "폰 1탭".

### B-1. Environments 화면 열기
```
https://github.com/gisskso-lab/hitpan-erp/settings/environments
```

### B-2. `production` 환경 만들기(없으면) / 열기(있으면)
- `production`이 목록에 있으면 → 클릭
- 없으면 → **New environment** 클릭 → 이름 `production` 입력 → **Configure environment**

### B-3. 승인자 추가
- **Required reviewers** 체크박스 ✅ 켜기
- 나타나는 입력칸에 **사장님 본인 GitHub 아이디** 입력 → 선택
- 아래 **Save protection rules** 클릭

**✅ 성공 화면**: `production` 환경에 "Required reviewers: (사장님 아이디)" 보임.

> 💡 나중에 부승인자가 생기면 여기에 1명 더 추가하면 됩니다(1-of-2). 지금은 사장님 혼자(1-of-1).

---

## [C] main 브랜치 보호 (검증 안 된 코드 차단)

**왜**: 보안팀 결론 — 고객에게 나가는 코드는 main이 진실원. main을 잠가야 "검증 통과분만 고객에게"가 강제됩니다.

### C-1. Branches 화면 열기
```
https://github.com/gisskso-lab/hitpan-erp/settings/branches
```

### C-2. 규칙 추가
- **Add branch ruleset** (또는 **Add rule**) 클릭
- **Branch name pattern**: `main` 입력
- 아래 체크박스 켜기:
  - ✅ **Require a pull request before merging**
  - ✅ **Require review from Code Owners** (CODEOWNERS 파일 실효화)
  - ✅ **Require status checks to pass** (있으면 — build-and-test 선택)
- **Create** / **Save changes** 클릭

**✅ 성공 화면**: main에 보호 규칙이 생기고 "Require pull request" 등이 켜져 있음.

> ⚠️ 지금 main 정렬(develop→main)은 **나중에** 하기로 했으니(첫 실측 후 PR), 이 보호는 지금 걸어둬도 됩니다. 오히려 걸어둬야 나중 정렬을 PR로 안전하게 하게 됩니다.

---

## ✅ 3개 다 하시면

저(PM)에게 알려주세요. 그러면:
1. (A에서 받은 토큰을) NCP에 안전하게 저장 → B-4 완전 작동
2. 6단계: 자동배포 켜기 (.disabled 제거)
3. 🎯 **첫 실측(딸깍)**: 버전 넣고 Run → **사장님 폰에 승인 알림** → 탭 → UPDATE 게시 확인

## 📌 참고 — 각 작업이 뭘 하는지 (안심용)

| 작업 | 한 줄 설명 | 위험도 |
|---|---|---|
| A 토큰 | NCP가 GitHub에 "이거 진짜야?" 물어보는 읽기전용 열쇠 | 낮음(읽기만) |
| B 승인자 | 게시 때 사장님 폰이 최종 결재 | 없음(보안 강화) |
| C main 보호 | 검증 안 된 코드 고객 차단 | 없음(보안 강화) |

3개 다 **보안을 강화하는 것**이고, 되돌리기도 다 가능합니다(각 화면에서 끄면 됨).
