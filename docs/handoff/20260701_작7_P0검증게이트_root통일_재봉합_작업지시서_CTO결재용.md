## 1. 배경 — 진범 (샌드박스 8단계 실측 확정, 추측 0)

시리얼 없이 설치 시 "데이터베이스 초기화 실패(코드 1)" → 설치 DOA.

**실측 결과: 데이터는 100% 정상 생성됐고(124테이블·hitpan유저·import 전부 OK), 마지막 검증 게이트만 실패해 설치가 자기 손으로 실패 처리했다.**

- CREATE DATABASE(L870)·CREATE USER(L872)·import(L902) = **전부 `-u root`** → 성공.
- 검증 카운트(L887·891·905·908) = **`-u hitpan -p<G_DbPassword 랜덤32자>`** → `for /f (...)` cmd 재파싱 + `enabledelayedexpansion`(L867)에서 접속 실패 → 카운트 빈값 → `FINAL_COUNT=0` → L913 `if !FINAL_COUNT! LSS 124` → **exit /b 1**.
- **결정타**: 동일 랜덤 비번도 `for/f` 없이 직접 접속하면 `SELECT COUNT`→124/exit0 정상. 차이는 오직 `for/f` 래핑.

### 어제 봉합(a252f19)이 미적중이었던 이유
어제 진단 "G_DbUser 빈값"은 **오진**. 실측에서 hitpan 유저 정상 생성 확인 = 유저 빈값 아니었음. 어제 봉합(L859-860 유저 빈값 가드)은 무해하나 **원인과 무관한 위치**였다.

## 2. 봉합안 (CTO 택1 — PM 권고 = 안A)

### ✅ 안A (권고) — 검증 조회를 root로 통일
CREATE·import가 이미 root인데 검증만 hitpan인 게 어긋남. 검증 4곳을 root로 맞춘다.

| 라인 | 현재 | 봉합 후 |
|---|---|---|
| L887 (TBL_COUNT) | `mysql -u %s -p%s %s` = hitpan/랜덤/DB | `mysql -u root -p%s %s` = **root/MariaRootPw**/DB |
| L891 (EXISTING_DATA) | `mysql -u %s -p%s` = hitpan/랜덤 | `mysql -u root -p%s` = **root** |
| L905 (FINAL_COUNT) | `mysql -u %s -p%s %s` = hitpan/랜덤/DB | `mysql -u root -p%s %s` = **root**/DB |
| L908 (USERS_OK) | `mysql -u %s -p%s %s` = hitpan/랜덤/DB | `mysql -u root -p%s %s` = **root**/DB |

- root 비번(`MariaRootPw`, hex 48자)도 `for/f`를 타지만 **영숫자 hex라 특수문자 0** + 이미 L870·872·876·899에서 `for/f` 없는 `-e` 로 정상 작동 검증됨. 단 검증은 `for/f` 안이므로 **root라도 `for/f` 취약성이 남을 수 있다** → 아래 안B 가드 병행 필수.

### 🔒 안A 필수 병행 — hitpan 접속 별도 1회 검증 (회귀 차단)
검증을 root로 바꾸면 "hitpan 유저를 만들었지만 실제 접속은 안 되는" 상태를 못 잡는다. 그래서 **`for/f` 밖에서** hitpan 접속을 1회 명시 확인:
```
mysql -u hitpan -p<G_DbPassword> hitpan_erp -e "SELECT 1" 2> nul
if errorlevel 1 (echo [오류] hitpan 유저 접속 불가. & exit /b 1)
```
- `for/f` 없이 `-e "SELECT 1"` + `errorlevel` 검사 = 실측 8번에서 이 방식이 정상 작동 확인됨.
- 이 가드가 "ERP 런타임이 실제로 쓸 hitpan 접속"을 설치 시점에 보증 → 로그인 500 재발도 차단.

### 안B (대안) — 비번을 defaults-extra-file로 전달
`--defaults-extra-file=임시ini`로 비번을 명령줄에서 빼면 `for/f` 파싱 취약성 원천 제거. 더 견고하나 임시파일 생성·ACL·삭제 로직 추가 = 변경 범위 큼. **PM 권고: 안A(root 통일 + hitpan 1회 가드)가 최소 변경·최대 안전.**

- **함정**: root라도 `for/f`가 원인이면 안 고쳐질 수 있음 → 그래서 **안A + hitpan 별도 가드 병행**으로 이중 안전. 재검증에서 여전히 실패하면 즉시 안B(defaults-file)로 전환.
