## 3. 작업 항목

### W0 — 실측 확정 (코드 0건, 즉시)
1. Sandbox: `Get-Service *cloudflare*` + `Get-Process cloudflared -ErrorAction SilentlyContinue` + `Get-WinEvent -ProviderName cloudflared -MaxEvents 10`
2. Sandbox: 설치폴더 `db.conf`의 `TUNNEL_ID`/`TUNNEL_TOKEN` 값 유무(값 자체는 채팅에 붙이지 말 것 — 유/무·길이만)
3. 사장님: Win10 테스트 PC 켜져 있는지 확인 → 켜져 있으면 그 PC cloudflared 서비스 중지(유령 커넥터 제거)

### W1 — P0: 재설치 터널 체인 봉합 (.iss + 백오피스)
1. **침묵 스킵 제거**: `G_TunnelToken = ''`이면 터널 단계를 조용히 건너뛰지 말고 W2-2 패턴(Log + 경고 MsgBox)으로 가시화. 재설치(기존 터널 정상) 분기에서는 **기존 서비스를 삭제하지 않고 보존**.
2. **재설치 토큰 보장**: 재설치 분기(ParentExists·is_locked_from_landing)에서도 license/claim이 해당 테넌트의 tunnelToken을 반환하도록 백오피스 응답 정합 — 또는 반환 불가 시 .iss가 기존 db.conf의 TUNNEL_TOKEN을 보존(빈값 덮어쓰기 금지).
3. **좀비 정리와 재설치의 원자성**: `sc delete` 후 `service install` 실패 시 롤백(기존 토큰으로 재설치 시도) — "지우기만 하고 못 깔면 터널 소멸" 차단.
4. **서비스명 전수 정합**: `cloudflared service install`이 만드는 실제 서비스명 실측 → .iss(`sc stop/start/delete cloudflared` 7곳+)·워치독 WS-28-D·Guardian이 같은 이름을 보도록 통일. (demo PC는 `CloudflaredAgent`로 확인됨 — 버전별 상이 가능성)
5. 터널 단계 전체 `ResultCode` 검사 + 헬스체크 실패 시 설치 결과 화면에 정직 표기(헌법 #15).

### W2 — P0 연계: 워치독 자가회복 실효성 (헌법 #27·#28·#30)
1. WS-28-D: TUNNEL_TOKEN 빈값/서비스 부재 시나리오에서의 동작 실측 — 복구 불능이면 그 사실을 메타 ping으로 본사 통지(지금은 침묵).
2. "서비스 자체가 없음" 시나리오를 17시나리오 실측 목록에 정식 편입, Sandbox에서 재현→5분 내 복구 PASS를 게이트로.

### W3 — P1: 본사(Cloudflare·백오피스) 정합 정리 (사장님 결재 후 실행)
1. 유령 커넥터 제거(W0-3) 후 잔재 터널 t001/t002/t003·test2 DNS 정리 — 살아있는 매핑만 남김.
2. 백오피스의 테넌트↔터널↔DNS 매핑 단일 진실원 점검: 재발급·재설치 시 세 값이 항상 같이 갱신되는지(오늘 1033의 구조적 원인). DNS 레코드 생성이 "이미 존재" 충돌 시 upsert로 정정.
3. 오늘 DNS 변경·원복 이력 기록(본 문서 §1)을 감사 추적으로 보존.

### W4 — P2: 고리4 (자동 업데이트 완성, 사장님 기결재 안건)
- Velopack(또는 자체) 실제 EXE 교체 → 서비스 재시작 → DB ALTER 마이그 → 실패 시 백업본 자동 롤백. 현재는 백업까지만 수행 후 보류(UpdateOrchestrator 자리표시). manifest 1.2.30(Major)·패키지는 이미 NCP 가동 중.
