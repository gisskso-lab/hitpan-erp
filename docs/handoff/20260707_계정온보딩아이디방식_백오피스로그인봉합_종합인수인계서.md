### 1-1. 백오피스 로그인 400 봉합 (오전~오후)
**증상:** 사장님이 `back.hitpan.kr` 로그인 시 400 "지금 이 페이지가 작동하지 않습니다". 새벽까진 됐는데 아침에 안 됨.

**헛발질(정직 기록):** PM이 사장님 첫 직감("토큰만료")을 무시하고 렌더모드·blazor.web.js로 오진 → 봉합안 만들고 배포까지 → 그 배포가 서비스 재시작을 일으켜 오히려 사장님 토큰 무효화 → 빙 돌아 결국 사장님 말이 맞았음. **교훈: 사장님이 증상 짚으면 그것부터 실측. curl 통과로 "됐다" 판정 금지(브라우저 실행 흐름이 진짜).**

**진범(실측 확정):** `Program.cs`에 `AddDataProtection()` 설정이 없어 기본값 동작 → 서비스 재시작/재배포마다 DataProtection 키 컨텍스트 흔들림 → 기존 브라우저 antiforgery 토큰 무효 → 400. + 배포 스크립트 `rsync --delete`가 배포폴더 내 키를 지우던 것도 원인.

**봉합(배포완료):**
- `src/HitPan.Backoffice/Program.cs`: `AddDataProtection().PersistKeysToFileSystem(/var/hitpan/backoffice-dp-keys).SetApplicationName("HitPanBackoffice")` — 키 영구고정(배포폴더 밖). 재배포·재시작에도 토큰 유지. 인증쿠키(hitpan_bo) 서명키도 고정되어 재배포 후 로그인 유지 부가효과.
- `src/HitPan.Backoffice/Controllers/BackofficeAuthController.cs`: `[ValidateAntiForgeryToken]` → `IAntiforgery.ValidateRequestAsync` 수동검증. 토큰 만료 시 400 대신 `/backoffice/login?error=...` 재진입. signin·signout 둘 다. CSRF 방어 유지.
- **실측 검증:** 재시작 후 옛 토큰 POST → 302(기존 400). 무효 토큰 → 로그인 리다이렉트(기존 400 dead-end). NCP 배포 완료, 사장님 실브라우저 로그인 성공.
