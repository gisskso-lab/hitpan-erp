## 🎯 #71 옵션 3 진단 SQL (PM 박제, 사장님 결재 후 실행)

### SQL-1: 어떤 UNIQUE에서 충돌하는지 후보별 분류
```sql
-- staging 적재 후 본 INSERT 직전에 실행 (LEFT JOIN으로 충돌 후보 노출)
SELECT
  CASE
    WHEN t1.invoice_id IS NOT NULL THEN 'invoice_no_collision'
    WHEN t2.invoice_id IS NOT NULL THEN 'source_hash_collision'
    WHEN t3.invoice_id IS NOT NULL THEN 'io_no_collision'
    WHEN t4.invoice_id IS NOT NULL THEN 'source_id_collision'
    ELSE 'no_collision_should_insert'
  END AS collision_type,
  COUNT(*) AS cnt
FROM tax_invoices_stage_xxx s
LEFT JOIN tax_invoices t1 ON s.tenant_id = t1.tenant_id AND s.invoice_no = t1.invoice_no
LEFT JOIN tax_invoices t2 ON s.tenant_id = t2.tenant_id AND s.migrated_source_hash = t2.migrated_source_hash
LEFT JOIN tax_invoices t3 ON s.tenant_id = t3.tenant_id AND s.direction = t3.direction AND s.tax_no = t3.tax_no
LEFT JOIN tax_invoices t4 ON s.tenant_id = t4.tenant_id AND s.source_type = t4.source_type AND s.source_id = t4.source_id
GROUP BY collision_type;
```

## 📊 #70 journal_lines 본 테이블 진단

| UNIQUE KEY | 컬럼 조합 |
|---|---|

### 추가 의심: CHECK 제약
```sql
CONSTRAINT `chk_jl_debit_or_credit` CHECK (
  `debit_amount` > 0 and `credit_amount` = 0 or
  `debit_amount` = 0 and `credit_amount` > 0
)
```
**시나리오**: 원본 DOCF7에서 debit/credit 둘 다 양수거나 둘 다 0인 라인 = CHECK 위반 → BulkCopy silent IGNORE 가능성.

### #70 옵션 3 진단 SQL
```sql
-- staging에 적재된 데이터 중 CHECK 위반 후보 카운트
SELECT
  CASE
    WHEN debit_amount > 0 AND credit_amount > 0 THEN 'both_positive_check_fail'
    WHEN debit_amount = 0 AND credit_amount = 0 THEN 'both_zero_check_fail'
    WHEN debit_amount < 0 OR credit_amount < 0 THEN 'negative_check_fail'
    ELSE 'check_pass'
  END AS check_status,
  COUNT(*) AS cnt
FROM journal_lines_stage_xxx
GROUP BY check_status;
```
