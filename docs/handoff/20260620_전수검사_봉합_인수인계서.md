**다음 세션 PM 행동 수칙**:

## 1. 이 작업의 배경

- **지시(사장님, 2026-06-20)**: 히트판 ERP 7개 영역(워크플로우·그룹웨어·자료분석·결재라인·재고관리·AI·마이그레이션) + **통신연결** 전 직원 4병렬(정합성·무결성·속도·보안) 전수검사 → 발견된 이슈 전부 봉합 → 퇴근.

- **다음 주 월요일 예정**: 워크스페이스(백오피스)·랜딩페이지·히트판 ERP 연결 + 배포 준비 작업.

## 4. 앞으로 할 작업 (다음 세션이 이어받을 것)

### 4-1. 이번 봉합 마무리 (즉시)
1. **전체 솔루션 빌드 검증** — errors 0 + warnings 0 (헌법 #19).
   - ⚠️ demo가 dotnet run으로 떠 있어 `bin\Debug`의 DLL을 잠금 → 일반 빌드 시 MSB3027 파일잠금 오류 발생. **코드 오류 아님.** 검증은 `-p:BaseOutputPath=obj/verify-build/` 같은 별도 출력경로로 컴파일만 확인하거나, demo를 정상 종료 후 빌드.
   - **demo 종료 시 헌법 #28·[[feedback_api_restart_after_kill]] 준수** — 빌드 후 반드시 재기동(demo.hitpan.kr 외부 다운 방지).
   - 현재까지 영역별 컴파일 확인: 워치독(0/0), Application(0/0) 통과. **API+Web 전체 통합 빌드는 아직 미완** → 다음 세션 1순위.
2. **검증팀장 실시간 최종 검증** — 그룹웨어·결재·자료분석·AI 봉합분 일괄(통신은 이미 통과).
3. **demo 재기동** 후 실제 화면 스모크 확인(연차 반려사유 표시, 결재 동시성, 재고 키워드 검색).
4. **커밋** — 사장님 결재 후. 단위: 영역별 또는 "전수검사 봉합 일괄". 헌법 #19(0/0) 통과 후에만.

### 4-2. 사장님 정책 판단 필요 (보류 2건)
- **P1-5 결재→원문서 상태 반영**: 결재 완료 시 발주/수주 상태도 함께 바꿀지(워크플로우 설계). 사장님 결재 필요.
