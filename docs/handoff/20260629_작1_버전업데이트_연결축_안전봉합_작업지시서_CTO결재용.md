## 2. 목표 흐름 (봉합 후 그림)
```
[로그인 성공]
   ↓
ERP가 업데이트 확인 (manifest 조회 → 새 버전?)   ← ERP는 "묻기만"
   ↓ 있으면
"새 버전 vX 나왔습니다. 업데이트하시겠습니까? [예 / 나중에]"  ← ERP 화면 팝업
   ↓ 예 (사용자 동의를 워치독에 전달)
워치독이 실행: 자료 자동백업(BackupService)            ← 워치독은 "실행"
   ├─ 백업 실패 → 🛑 업데이트 물리적 차단 + 안내
   └─ 백업 성공 → 다운로드→sha256검증→Velopack 적용→DB 마이그
        ├─ 마이그 성공 → 재시작 → 신버전 정상
        └─ 마이그 실패 → 🔁 백업본 자동 복원(DB+EXE 롤백) → 구버전 복구 + 안내
```
**ERP=묻기 / 워치독=실행** 분담 (3시스템 분리 정합). 동의 전달 다리(IPC/파일/DB 플래그)를 신설.

## 3. 작업 항목 (고리별)

### 고리 1 — UpdateOrchestrator를 워치독 Worker에 연결
- DI 등록 (HitPan.Watchdog/Program.cs): UpdateOrchestrator·IUpdateClient·VelopackUpdater
- Worker.RunOneLoopAsync에 EvaluateAsync 호출 추가 (채널 분기: Emergency/Normal/Major)

### 고리 2 — ERP 로그인 시 Y/N 프롬프트
- 로그인 성공 직후 ERP가 manifest "새 버전 여부"만 조회 (다운로드 X)
- 새 버전 시 ERP 화면 팝업 "[예/나중에]"
- "예" → 동의 신호를 워치독에 전달 (전달 다리 신설)
- "나중에" → 다음 로그인 시 재안내 (영업시간 강제 재시작 방지)

### 고리 3 — 백업→업데이트 연결 + 물리적 차단
- 워치독이 동의 수신 → BackupService.RunBackupAsync 호출
- **백업 실패 시 업데이트 전 과정 중단(물리적 차단)** + 사용자 안내 + 본사 메타 통지
- 백업 성공 검증(파일 존재·크기>0) 후에만 다음 단계 진입

### 고리 4 — Velopack 실제 통합 + 마이그 자동 롤백 (★사장님 추가)
- VelopackUpdaterStub → 실제 Velopack NuGet 통합 (원자적 교체·재시작)
- 적용 후 DB ALTER 마이그 실행 경로 정의
- **마이그 실패 시 백업본으로 DB+EXE 자동 복원(롤백)** → 구버전 무손상 복구
- 업데이트 중 전원차단 대비(원자성) 확인 (EVF "혼돈")

### 선행 — 테스트 환경 (헌법 #39, #29 결재 필요)
- 검증은 **운영(demo) 절대 금지**. 별도 테스트 슬롯에서만.
- 17시나리오 통신검증 때 막혔던 그 환경과 동일 — **한 번 구축으로 공용**.
- 구성: hitpan_e2e DB + 테스트 포트 + 테스트 터널/도메인 + 테스트 manifest 피드.
