## 3. 진범 확정 (전 직원 7명 + 4병렬 검증 만장일치)

### 증상
1.2.13 설치 후 로그인 화면은 정상으로 떴으나, 로그인 요청만 500.
로그(`C:\Program Files\HitPan\api\logs\hitpan-20260617.log`):
```
MySqlException: Table 'hitpan_erp_t003.users' doesn't exist
```
→ DB(`hitpan_erp_t003`)는 생성됐는데 그 안에 테이블이 0개.

### 진범
`installer/hitpan_db.sql`은 `mysqldump --databases`로 뽑은 덤프라 안에 원본 회사ID가 들어있었음:
- 23줄 `DROP DATABASE hitpan_erp`
- 25줄 `CREATE DATABASE hitpan_erp`
- **27줄·5348줄 `USE hitpan_erp`** ← 핵심 진범
- DEFINER 18곳 `hitpan@localhost` ← 2차 진범

설치기가 `mysql hitpan_erp_t003 < hitpan_db.sql`로 회사별 DB를 지정해도,
27줄 `USE hitpan_erp`가 그 지정을 덮어써서 91개 테이블이 전부 `hitpan_erp`로 들어감.
→ `hitpan_erp_t003`는 빈 껍데기 → users 없음 → 로그인 500.

### 검증팀이 추가로 잡은 더 큰 잠재 사고 2건
1. **데이터 삭제 위험**: 멀티사업자 1PC에서 두 번째 사업자 설치 시
   23줄 `DROP DATABASE hitpan_erp`가 앞 사업자 데이터까지 삭제 (헌법 #22 위반).
2. **트리거 생성 실패**: DEFINER가 `hitpan@localhost`인데 회사별 import 유저는
   `hitpan_t003` → 불일치로 트리거 9개 + 뷰 생성 ERROR 1227. DEFINER 제거는 필수.

### 왜 12시간 동안 안 잡혔나 (CTO 분석)
1.2.6~1.2.13 봉합은 전부 앞단(API 503·터널 1033·CORS·CSP)이라 로그인 요청까지
도달 못 했음. 1.2.13에서 CORS가 풀려 처음으로 로그인 요청이 DB까지 도달 →
잠복하던 이 사고가 처음 발현. 재발이 아니라 새 진범.

## 4. 정정 3건 (모두 검증 통과)

### 정정 ① (근본) — hitpan_db.sql 텍스트 정리
- `USE`(2곳)·`DROP/CREATE DATABASE`·`DEFINER`(18곳) 텍스트 제거.
- 뷰는 `SQL SECURITY INVOKER`로 전환 (현재 유저로 실행).
- **재덤프가 아니라 기존 파일 텍스트 정리** → 데이터 무손상.
- 검증: USE 0건·DEFINER 0건·테이블 91개·데이터 INSERT 17건·트리거 9개 유지.
- ⚠️ `hitpan_db.sql`은 `.gitignore` 대상이라 git에 안 올라감.
  원본 백업: `installer/hitpan_db.sql.bak-1.2.13` (롤백용 보존).

### 정정 ② (방어) — HitPan-Universal.iss bat 로직
- import 판정을 `items COUNT` → `information_schema`의 `users` 테이블 존재로 변경
  (빈 DB에서도 오류 0).
- 풀스택 매니저가 잡은 2중 버그 정정: `skip=1`(-N이라 결과 1줄인데 그걸 버림)
  + `2^^^>nul`(caret 3겹으로 redirect 사망).
- import 후 users 실존 재확인 가드 추가. 실패 시 명확한 한국어 메시지 + exit 1
  (헌법 #15 silent swallow 금지).

### 정정 ③ (재발방지) — build-installer-universal.ps1 게이트
- 빌드 시 덤프에 DB명/DEFINER가 박혀 있으면 빌드 중단.
- 양방향 검증: 정정된 파일 통과 / 원본(22건) 차단 확인.
- 빌드 실행 시 "정합성 게이트 통과" 메시지 실제 출력 확인.

## 5. 빌드 사고 기록 (다음 PM 참고)

EXE 빌드가 2회 실패. 진범 = **알약(백신) 실시간 감시가 ISCC의 EXE 리소스 쓰기
(BeginUpdateResource API)를 차단** → `Resource update error: BeginUpdateResource failed (5)`.

- 알약 **탐지 제외 폴더 등록만으로는 부족**했음 (행위 기반 실시간 감시는 별개 모듈).
- 해결: 출력 폴더를 알약 제외 등록된 `installer-build`로 지정해 빌드 성공.
  (dist 폴더는 EXE 25개 6.27GB 누적으로 스캔 부하 + 제외 미적용 가능성)
- 빌드 명령:
  ```
  ISCC.exe /DAppVersion=1.2.14 /DBackofficeApi=https://back.hitpan.kr
    /DOutputName=HitPan-ERP-Setup-1.2.14 /DOutputDir=<installer-build>
    /DBundleDir=<installer-build/bundle> HitPan-Universal.iss
  ```
- 빌드 소요: 약 195초 (ERP/워치독/번들다운로드 스킵, db.sql+iss만 반영).
