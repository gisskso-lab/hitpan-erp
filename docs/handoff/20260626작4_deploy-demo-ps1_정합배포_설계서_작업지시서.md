## 3. `deploy-demo.ps1` 단계 설계 (8단계)

```
[0] 사전 가드     → 관리자 권한 확인 / ASCII 경로 확인 / 같은 커밋 빌드 강제
[1] 백업          → DB 덤프 + 현재 Web/API 폴더 백업 (C:\HitPanDeploy\backup\<timestamp>\)
[2] 빌드          → 같은 HEAD 커밋에서 Web publish + API publish 동시 (버전 정합 ★)
[3] 정지          → 기존 Web(5234)·API(5257) 프로세스 graceful stop
[4] 교체          → 백업본 보존하며 신규 산출물 배치 (ASCII 경로)
[5] 키 정합       → hitpan-keys.conf의 ERP_ENCRYPTION_KEY를 API 환경변수로 주입 (단일 진실원)
[6] 기동          → API(5257) → Web(5234) 순서 기동 + 헬스 대기
[7] 정합 게이트   → 스모크 5종 자동 검증
[8] 판정          → 전부 200 → 배포 성공 / 하나라도 실패 → 자동 롤백([1] 백업본 복원)
```

### 정합 게이트(스모크) 5종 — 헌법 #39 대책 3
| # | 검사 | 통과 기준 |
|---|---|---|
| 1 | 로그인 | `POST /api/auth/login` 200 + 토큰 발급 |
| 2 | `/me` 복호화 | `GET /api/auth/me` 200 (암호화 컬럼 복호화 성공 = 키 정합 증명) |
| 3 | 캘린더 | `GET /api/dashboard/unified-calendar` JSON 200 (HTML 폴백 아님 = 버전 정합 증명) |
| 4 | 대시보드 | `GET /api/dashboard/...` 200 |
| 5 | 워크플로우 핵심 | 재고·매입·판매 조회 각 1개 200 |

> 하나라도 실패 = `throw` → `[8]`에서 catch → 백업본 복원 → 배포 실패 종료. **"망가진 채 방치" 차단.**

## 4. 미해결 2건과의 관계 (배포 스크립트가 푸는 것 / 못 푸는 것)

| 미해결 | deploy-demo.ps1이 푸나? |
|---|---|
| **CORS** (최신 API가 CORS 없이 떠서 외부 접속 차단) | **푼다(코드 영역).** API의 CORS 정책에 `demo.hitpan.kr` 허용을 코드/설정으로 박고 같은 빌드에 포함. 별도 작업지시서로 봉합 후 본 스크립트가 정합 배포. |
| **approval 403** (토큰 employee_id 빈 클레임) | **본 스크립트 영역 아님.** `AuthService` 백필이 emp_no 중복(`Duplicate entry`)으로 실패하는 데이터·로직 결함. SOP대로 별도 전수조사→작업지시서. 운영DB 직접 UPDATE는 안전장치 차단(맞는 차단, 헌법 #39). |

→ 두 건 모두 **테스트 환경에서 봉합·검증 후**(헌법 #39 절대원칙 2), 정합된 코드를 deploy-demo.ps1로 한 번에 배포한다.
