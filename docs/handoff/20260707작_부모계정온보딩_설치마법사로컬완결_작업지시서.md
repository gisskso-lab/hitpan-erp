## 2. 확정 설계 ((가)정식완성도, 6인 검증)

### 2-1. 새 온보딩 흐름
```
① 랜딩 가입 → 백오피스에 시리얼·테넌트넘버·회사정보·구독 저장 [비번 안 받음]
② 설치마법사 → 시리얼 입력 → 로컬 슬롯 API(또는 .iss) 경유 백오피스 서버간 1회 조회
   → 백오피스가 [회사정보 + tenant_id + 구독 + 개인키로 서명한 증표(payload에 tenant_id·시리얼·kid 포함)] 반환
   ※ 브라우저 아님 = CORS 원천 무관
③ 설치마법사/ERP → 그 증표를 EXE 내장 공개키로 오프라인 검증 (통신 0)
   → 통과 시에만: local_company(백오피스 tenant_id, is_locked_from_landing=1) + local_subscription + 부모계정
     (users+employees+warehouses+accounts 8계정) 로컬 트랜잭션 생성
④ 로그인 200 (tenant_id 로컬값 그대로 통과, 백오피스 대조 안 함 — AuthService.cs:35·372)
⑤ 터널 발급은 이후 분리 단계 (터널 죽어도 로컬 로그인 가능)
```

## 4. 🔴 반드시 지킬 3대 원칙 (6인 만장일치 — 위반 시 백도어)

### 원칙 A — 옛 HMAC 공용키 경로 교체 (반쪽=백도어), 단 병행 이행기로 (CTO 조건 1)
- create-parent에서 `VerifyBootstrapToken`+`allowExpired` 경로(`:226·:408`)를 공개키 검증으로 교체. 옛 경로를 어정쩡하게 남기면 폐지했다던 공용키(`HITPAN_BOOTSTRAP_TOKEN_KEY`)가 우회 백도어로 잔존(보안상무·검증팀장).
- **🔴 [CTO 조건 1 — 하위호환 blocking] 한 방에 HMAC 제거 금지.** 이미 발급된 시리얼(demo T-001 등)은 HMAC 서명이라 공개키로 검증 안 됨 → 즉시 제거하면 **기발급 고객 재설치 전멸.** 반드시 **공개키·HMAC 병행 이행기** → 기존 시리얼 소진 후 HMAC 제거. kid(key-id)로 HMAC-kid·공개키-kid 병행검증해 이행기 흡수.
- `TenantMiddleware.cs:41`의 `/api/setup` 익명 허용 근거가 "진입 즉시 서명검증"이므로, 검증 주체 교체 후 **익명 요청이 부모계정을 심을 수 있는지 반증테스트 필수**.
- **bootstrap + create-parent 둘 다 한 번에 (가)로 이전** (반쪽 하면 10분 만료·저장참사 재발, 7/6 봉합). 단일 메서드 `VerifyBootstrapToken`이 두 진입점 호출.
- **🔴 [CTO 조건 4 — replay 방어] 오프라인 공개키 검증은 위조는 막아도 캡처된 유효 증표 재사용(replay)은 못 막는다**(서버 nonce 소각 불가). `local_company.is_locked_from_landing=1`이 곧 replay 방어(한 번 잠기면 재부트스트랩 차단)임을 게이트로 명시. jti 미저장(현 `:403`)이 공개키 전환 후에도 남는 점 인지.

### 원칙 B — tenant_id는 백오피스 단일 진실원 (파생 금지)
- tenant_id를 시리얼에서 파생하지 말 것. **서명 payload에 tenant_id를 포함**시켜 회사정보 조회 응답과 동일 소스화. 분열 시 `local_company.tenant_id ≠ users.tenant_id` → create-parent 400·빈 화면 (DB).
- 로컬 6테이블 전부에 이 단일 tenant_id 사용.

### 원칙 C — 개인키 격리 (2층 분리) + 공개키 롤오버 경로 (CTO 조건 3)
- 개인키를 systemd 환경변수 평문에 두지 말 것(NCP 1대가 전 고객 위조 단일표적).
- **🔴 [CTO 조건 3 — 층 분리] 베타 = 서버 격리 프로세스 + 파일 ACL / 정식 = HSM·KMS.** HSM을 베타에 넣으면 일정 발목(현 종단설치 미통과 크리티컬 패스). `iss:1040` 주석의 "베타=공용키 / 정식 전=파생키" 예고와 정합. 이 2층을 안 박으면 베타가 HSM에 발목잡힘.
- 시리얼 payload에 **key-id(kid) 버전 필드** → 개인키 유출 시 공개키 롤오버 가능하게(다중 공개키 병행검증). 없으면 전 고객 재설치 사태 (보안상무·네트워크).

### P0-3. 설치마법사 .iss
- 부모계정 입력 페이지(아이디+비번) 신설, 비번 평문 SetupLog·PowerShell 인자 미노출(임시파일 ACL·즉시소각).

- **부모계정 생성 방식 = A안(HitPan.API.exe seed-parent 오프라인 서브커맨드) 사장님 결재 반영.**

### P0-4. web setup 절단 + 토큰 재배선 + 재생성 경로
- `LicenseSetupPage.razor:240` 브라우저→백오피스 호출 제거.
- **🔴 [CTO 조건 2 — 토큰 이중경로 해소] 진범은 "브라우저 호출 하나"가 아니라 "토큰 경로 이중화"다.** 설치마법사는 이미 서버간으로 `installer/bootstrap` 호출해 `BOOTSTRAP_TOKEN`(`iss:840`)을 db.conf에 기록하는데, 웹 setup은 그걸 무시하고 브라우저에서 `landing/license/claim`을 또 호출(razor:248)했다. → **절단만 하지 말고, db.conf에 이미 있는 서버간 토큰(→새 공개키 서명증표)을 웹/서브커맨드가 재사용하도록 배선.** 재배선 누락 시 setup 화면 토큰 공백사.
- **razor 3-step(claim→bootstrap→create-parent) 은퇴 경계 명시:** A안(오프라인 서브커맨드 seed-parent)으로 부모계정을 옮기면 Step2·Step3(razor:291·357)도 연쇄 은퇴. "web setup 절단"과 "재생성 폼 잔존" 사이 회색지대를 개발 착수 전 경계 확정.
- web setup 제거 시 재설치·계정분실 재생성 경로 → **로그인 화면에 "부모계정 0건이면 최초등록폼" 조건부 잔존** (create-parent existingParent>0 가드 `:252` 회피).

### P0-순서. 착수 순서 강제 (CTO — 한 방에 HMAC 제거 금지)
```
① 백오피스 발급기(공개키쌍 생성·kid)를 먼저 배포 + HMAC과 병행 발급
② ERP가 공개키+HMAC 둘 다 수용(이행기)
③ 설치마법사(.iss) 배선
④ 이행기 검증 완료(기존 시리얼 소진) 후 HMAC 제거
```
- db.conf HMAC키 제거는 **되돌리기 어려운 단방향** → iss 변경은 이행기 검증 완료 후 마지막에.
- 롤백: EXE는 재빌드로 복구되나 **백오피스 개인키 분실 시 발급 전 고객 재설치 불가**(원칙 C가 대응).

### P1. 정리
- Web 고아 DI(`Program.cs:107-115`) 제거.
- 설치완료 신호(bootstrap_at·serial_verified) 백오피스 되보내는 메타 telemetry 1건(헌법 #24·#35, #22 위반 아님).
