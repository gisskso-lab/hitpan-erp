## 1. 증상 (사장님 실측)

- `back.hitpan.kr`에서 로그인 시도 → `/backoffice/auth/signin` 에서 **HTTP 400 (Bad Request)** / `net::ERR_HTTP_RESPONSE_CODE_FAILURE`
- 브라우저 재시도·강력새로고침으로 안 풀림 = 브라우저 일시 문제 아님
- **"원래 되던 게 지금 안 됨"** — 특정 시점부터 회귀

## 2. 진범 (실측 확정 — 추측 아님)

### 실측 근거 체인
| # | 실측 | 결과 |
|---|---|---|
| 1 | antiforgery 토큰 없이 POST | **400** (antiforgery 검증이 400의 원인) |
| 2 | 로그인 페이지 `Set-Cookie` | `.AspNetCore.Antiforgery...` 정상 발급 |
| 3 | 쿠키+폼토큰 **정상 동봉** POST (서버측 재현) | **302** (정상 흐름은 통과 = 서버 antiforgery 로직 정상) |
| 4 | 배포 DLL 빌드 시각 | `/opt/hitpan/backoffice-web` = **2026-07-06 17:11 재배포** |
| 5 | 7/4 이후 백오피스 커밋 | `50628ec`(App.razor rendermode)·`5488fc0`(삭제버튼) |
| 6 | `50628ec` diff | `<Routes />` → `<Routes @rendermode="InteractiveServer" />` |
| 7 | 백오피스 전체 `method="post"` SSR 폼 | **`BackofficeLogin.razor` 1개뿐** |

### 인과관계
커밋 `50628ec`가 MudBlazor 버튼 무반응(Missing MudPopoverProvider)을 고치려고 `<Routes>`에 **전역 `@rendermode="InteractiveServer"`**를 지정.
→ 그 결과 `/backoffice/login`의 **순수 SSR HTML 폼**(`<form method="post">` + `<AntiforgeryToken/>`)까지 InteractiveServer 회로로 렌더됨
→ 인터랙티브 렌더 페이지의 antiforgery 토큰 발급 방식이 정적 SSR 폼 POST 검증과 어긋남
→ 폼 제출 시 antiforgery 검증 실패 → **400** (미들웨어 단에서 거부, 컨트롤러 로그 안 남김 — 실측상 로그에 antiforgery 에러 없음과 정합)

### 두더지잡기 성격
`50628ec`는 대시보드·목록 등 MudBlazor 인터랙티브(mud=8~97)를 살렸으나 **로그인 SSR 폼 1개를 깨뜨림**. 커밋 메시지 자체에 "배포 후 로그인 전면 재확인 필요"라고 경고가 있었으나 그 재확인에서 누락됨.

## 3. 봉합 방향 (사장님 결재: 페이지별 렌더모드 정공법 → 설계팀장 net8.0 최적안 확정)

**⚠️ 1차 봉합안(.NET9 `AcceptsInteractiveRouting`/`[ExcludeFromInteractiveRouting]`)은 CTO 반려됨** — 백오피스가 **net8.0** 타겟이라 그 두 API가 없어 **CS0246 컴파일 실패**. (반려가 거짓봉합·빌드사고를 사전 차단)

**설계팀장 재검증 확정안 (실측: 실제 컴파일 + 실제 구동 HTTP)**:
전역 InteractiveServer 유지 + 로그인 SSR 폼만 정적 렌더로 예외.
구현 = net8.0 정석 `RenderModeForPage` 경로 분기 (**.NET9 API 미사용**, 원시 `HttpContext.Request.Path.StartsWithSegments`).
→ **App.razor 단 1파일 변경. 회귀 0.**

### 대안 비교 (설계팀장 실측)
| 기준 | 대안 A (전역제거+Provider재배치) | **대안 B (경로분기) — 채택** |
|---|---|---|
| 회귀 위험 | 높음 — Provider를 레이아웃 4종에 재배치, 하나라도 빠지면 버튼 무반응 재발(50628ec 되돌림) | **없음** — Provider 4종 Routes.razor에 그대로 |
| 변경 파일 | App.razor + Routes.razor + 레이아웃 최대 4개 | **App.razor 1개** |
| net8 컴파일 | 통과(실측) | **0 warn / 0 error (실측)** |

### 봉합 대상 페이지 분류 (실측)
- **정적 SSR 고정 필요**: `BackofficeLogin.razor` (form=1, mud=0) — 백오피스 전체 유일한 method=post SSR 폼
- **인터랙티브 유지**: 나머지 전체 (mud 8~97, 대시보드·목록·삭제버튼 등)
- 중립(무관): reseller-apply(EditForm)·Error·not-found·platform/*

## 4. 변경 파일 (1개 — App.razor만)

### 4-1. `src/HitPan.Backoffice/Components/App.razor`
23행 `<Routes @rendermode="InteractiveServer" />` → 경로분기로 교체 + `</html>` 뒤 `@code` 추가:
```razor
    @* 로그인 SSR 폼(antiforgery)만 정적 렌더, 나머지는 InteractiveServer 유지.
       진범: 50628ec 전역 InteractiveServer가 로그인 SSR 폼 antiforgery 깨뜨려 400. (봉합 2026-07-07) *@
    <Routes @rendermode="RenderModeForPage" />
```
```razor
@code {
    [CascadingParameter] private HttpContext HttpContext { get; set; } = default!;

    private IComponentRenderMode? RenderModeForPage =>
        HttpContext.Request.Path.StartsWithSegments("/backoffice/login")
            ? null               // 로그인 = 정적 SSR (antiforgery 폼 보존)
            : InteractiveServer; // 나머지 = 인터랙티브 (MudBlazor 유지)
}
```
설계팀장 실측 확정:
- `InteractiveServer` 심볼 = `_Imports.razor`의 `@using static ...Web.RenderMode`로 이미 해석됨(추가 using 불필요)
- `HttpContext` = net8 Blazor Web App이 App 컴포넌트에 자동 캐스케이드(등록 불필요)
- **net8.0 컴파일 0/0** 실측 통과
- **BackofficeLogin.razor는 손대지 않음** (1차안의 속성 추가 불필요 — 경로분기가 처리)
