### 수정 #7 — 정공법 5축+α 미완성 봉합 (가속)

**현재 적용 현황 (PM 실측):**

| 축 | 적용 | 위치 |
|---|---|---|
| ① MySqlBulkCopy | ✅ | stock_ledger·collections·cashbook·expenses·bank_transactions |
| ② OleDB 병렬 SELECT (3 MDB) | ✅ | line 370 Task.WhenAll + 잡당 OpenOleDb |
| ③ Stream 처리 | ⚠️ | `ReadMdbTable`로 DataTable 변환 (Stream 아님) |
| ④ 인덱스 DISABLE→ENABLE | ✅ | DROP UNIQUE INDEX (line 1751) |
| ⑤ 테이블별 병렬 마이그 | ✅ | line 370 Task.WhenAll 11잡 |
| +α 백신 5종 예외 자동 | ❌ | **미적용** (헌법 #31 보안2) |
| +α 청크 단위 Commit | ❌ | **미적용** (단일 트랜잭션 끝까지) |
| +α 재개 가능 마이그 | ❌ | **미적용** (실패 시 처음부터) |

**수정 내용:**
- ③ Stream: `ReadMdbTable` (DataTable 한꺼번에) → `OleDbDataReader` 직접 read
- +α 백신 예외: 설치 EXE에서 Defender·V3·알약·Norton·McAfee 예외 등록
- +α 청크 Commit: 10만건 단위 트랜잭션 분할
- +α 재개: source_id 기준 재시작

**기존 코드 영향:**
- ③ Stream 변경: `ReadMdbTable` 호출처 전수 (10곳+) 영향 = **위험도 높음**
- +α 백신: 설치 EXE 영역 (마이그 코드 영향 0)
- +α 청크: 트랜잭션 경계 재설계 (정합성 영향 검토 필수)
- +α 재개: 멱등 키 활용 = 기존 source_id로 가능

**효과:**
- 메모리 사용량 절감 (DataTable 2GB → Stream)
- 청크 실패 시 재개 = 사장님 안 *"고객 인내 보호"* 정합
- 작업 시간: 백엔드 매니저 **3~5일 (위험도 높아 단계별)**
