## 🚨 SignalR 신호 흐름 진단

### 진범 #22 흐름 박제
```
백엔드: RunTableStepAsync("warehouse_migration") {
  cb?.Invoke("running", 0, 0, null);  ← 즉시 (0ms)
  ...
  cb?.Invoke("completed", 0, 197ms, null);  ← 197ms 후
}

프론트:
  Start API 호출 → JobId 받기 (~1초)
  SignalR 연결 + SubscribeJob (~500ms)
  ← 이 시점에 warehouse_migration 이미 완료 (197ms < 1500ms)
  → "running"/"completed" 신호 둘 다 미수신
  → 카드 영구 "대기"
```

### 진범 #22 봉합 (이미 완료)
- JobCompleted 후 status GET 401 retry 추가 ✅
- 그러나 **첫 카드 SignalR 미수신 문제는 그대로** — status GET이 최종 결과만 수신, 진행 중 카드는 못 받음

### 진범 #43 후보 (NEW)
사장님 9차 스크린샷 보고 시 "기본창고 = 대기" 그대로 유지된 이유:
- 진범 #22 봉합 코드가 JobCompleted 시점에만 작동
- 마이그 진행 중 카드 UI는 옛 SignalR 신호 미수신 그대로
- 봉합 보완: SubscribeJob 직후 status GET 1회 호출 → 누락 카드 동기화 필요
