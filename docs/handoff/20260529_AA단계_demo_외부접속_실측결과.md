## 3. 보안 검증 (배포 후 의무)

배포 후 즉시 재실측:

```powershell
# 1. Bearer 미들웨어가 /watchdog/* 모든 POST 401 거부
Invoke-WebRequest 'https://api-demo.hitpan.kr/watchdog/ping' -Method Post `
    -Body '{}' -ContentType 'application/json' -ErrorAction SilentlyContinue
# 기대: 401 (Bearer missing)

# 2. PlatformOnly 정책이 /api/admin/* 모든 GET 401 거부
Invoke-WebRequest 'https://api-demo.hitpan.kr/api/admin/watchdog/summary' -ErrorAction SilentlyContinue
# 기대: 401 (Authorize)
```

배포 전 + 후 차이:
- 배포 전: POST → 405 (라우팅 안 됨)
- 배포 후: POST → 401 (Bearer 미들웨어 차단)

---

## 4. SPA Authorize 동작 박제

`/admin/watchdog`이 200 응답하는 이유:
- Blazor WASM은 SPA → 모든 라우트가 `index.html` 반환
- 실제 Authorize 정책은 클라이언트 측 `<AuthorizeView>` 또는 `@attribute [Authorize]`에서 적용
- 미로그인 사용자가 진입 시 자동 `/admin/login` 리디렉트

→ HTTP 200 응답은 보안 사고가 아니라 SPA 표준 동작.
