# CTO 결재의견 — 20260721작1 설치 hang(최초설치 차단) P0 봉합

> 결재: CTO 마커스 리 / 2026-07-21 새벽
> 대상: `20260721작1_설치hang_최초설치차단P0_봉합_작업지시서.md`
> **결재 결과: 부분수정후승인 (blocking 2건 + 방법 확정 + advisory 1건)**

---

## A. 진단 검증 (실측 근거 확인)

PM 진단 **일치.** 프로세스 관측(taskkill 죽이면 새 taskkill 재출현)이 반복 hang 을 실증했고, `sc.exe query` 1060 으로 sc stop 무죄를 갈랐다. 추측 아닌 관측 기반 — 승인.

근본 원인(재설치 코드가 최초설치에서 무조건 실행) 정확. 헌법 #40 정신과의 충돌 지적도 옳다.

---

## B. Blocking (해소 전 착수 불가)

### B-1 [BLOCKING] 축 A 판정 기준 = `hitpan-keys.conf` 는 맞으나, `{app}` 시점 정확성 확인 필요
`StopRunningComponentsForReinstall` 은 `ssInstall`(L1302)에서 호출되는데, 작지서 L1311~1314 주석을 보면 **`{app}` 상수는 ssPostInstall 이후에나 안정**이라 했다(SerialKeyPage 시점 미초기화 사고 이력). ssInstall 시점에 `ExpandConstant('{app}')` 가 최종 설치 경로를 정확히 가리키는지 **먼저 확인**해야 한다. 안 그러면 판정이 엉뚱한 폴더를 보고 "최초"로 오판 → 재설치인데 스킵 → 파일 잠금 사고 재발.
- **수정 요구**: ssInstall 시점 `{app}` 유효성 확인. 불확실하면 판정 기준을 `{app}` 대신 **레지스트리 언인스톨 키**(`Software\Microsoft\Windows\CurrentVersion\Uninstall\{앱ID}` 존재 여부 = Inno 가 이전 설치 시 남긴 것)로 판정 — 이게 Inno 표준 "이미 설치됨" 판정이라 더 안전.

### B-2 [BLOCKING] 축 B-1(Stop-Process) 이 Sandbox 에서도 hang 안 하는지 미검증
작지서는 `taskkill /IM` → `Stop-Process -Name` 대체를 "권장"했으나, **PowerShell `Stop-Process` 나 그 프로세스 열거도 Sandbox 제약 계층을 탈 수 있다**(실측 중 `Get-CimInstance Win32_Process` 가 "액세스 거부" 난 게 경고 신호 — 프로세스 열거 자체가 Sandbox 에서 막힌다). Stop-Process 로 바꿔도 똑같이 hang 하면 헛수고.
- **수정 요구**: 축 A(최초설치 스킵)를 **1순위 필수**로 확정하고, 축 B 는 **재빌드 EXE 로 재설치 케이스 실측 후** 방법 결정(B-1 이 Sandbox hang 안 하는지 실측으로 먼저 확인). 즉 **이번 봉합 = 축 A 단독으로 P0 해소**, 축 B 는 실측 근거 확보 후 별도. 한 번에 B 까지 넣다 또 hang 하면 실측이 오염된다.

## C. 방법 확정 (CTO 결정)

- **이번 봉합 = 축 A 단독** (최초설치 스킵). 이걸로 오늘 실측 hang 100% 해소되고, 헌법 #40 정합. 리스크 최소.
- **축 B(재설치 경로 taskkill hang 방어) = 다음 작지서**로 분리. 근거: B-2. 재설치는 헌법 #40 상 포맷·PC교체 후에만 = 빈도 낮음 = P0 아님(P1). 축 A 로 최초설치(전 신규고객) 뚫는 게 급하다.
- 판정 기준 = **레지스트리 언인스톨 키 우선, `hitpan-keys.conf` 차선**(B-1).

## D. 재빌드 EXE 버전 (CTO 결정)
- **1.2.34 로 재빌드.** 현 manifest 가 1.2.34 라 정합. 단 **설치 EXE 1.2.34 ≠ 자동업데이트 zip 1.2.34** 는 내용이 같아야 한다(둘 다 HEAD). 이미 게시한 zip 은 그대로 두고, 설치 EXE 만 봉합 커밋 포함해 새로 굽는다.
- ⚠️ **주의**: 그러면 "설치도 1.2.34, 업데이트 대상도 1.2.34" 가 되어 **자동업데이트 실측이 안 된다**(동일버전). → 고리4 실측하려면 **설치 EXE 는 1.2.34(봉합본)로 깔고, 자동업데이트 대상은 1.2.35 zip 을 새로 게시**해야 한다. 이건 봉합 후 실측 단계에서 처리(본 작지서 범위 밖, 다음 실측대본에 반영).

## E. Advisory
- **E-1**: `schtasks /End`(슬롯 1~5, L1273~1278)도 최초설치엔 불필요. 축 A 스킵에 자연히 포함되니 별도 조치 불요. 단 축 A 판정이 함수 진입 최상단(L1271 로그 앞)에 와야 = 로그도 안 찍히고 통째 스킵.

## F. 리스크 요약 (대표 보고용)
| 리스크 | 등급 | 통제 |
|---|---|---|
| 최초설치 전 고객 차단 | 高(현재진행) | 축 A 스킵 — 이번 봉합 |
| ssInstall 시점 {app} 오판 | 中 | B-1 레지스트리 키 판정 |
| Stop-Process 도 Sandbox hang | 中 | 축 B 분리, 실측 후 결정 |
| 재설치 경로 taskkill hang | 低(P1) | 다음 작지서 |

**총평**: 진단 정확, 봉합 방향 옳음. 단 **한 번에 A+B 넣지 말고 A 단독**으로 최초설치부터 뚫어라(B-2). 판정은 레지스트리 키로(B-1). 재빌드는 1.2.34, 실측 대상은 1.2.35 별도 게시. 이 조건으로 승인.

## G. 대표 결재 요청
1. 축 A 단독 봉합 + 레지스트리 판정 승인 여부.
2. 축 B(재설치 taskkill 방어)를 다음 작지서(P1)로 분리 승인.
3. 재빌드 EXE 1.2.34 + 실측용 1.2.35 별도 게시 방향 승인.
4. 결재 = OK / 부분수정 / 반려 / 보류.
