## 2. 봉합 설계 (사장님 화이트리스트 결재 반영)

### 봉합 ① 안전가드 → 화이트리스트 fail-safe (현 L32-41 교체)

```
[현재 — 블랙리스트(취약)]
  db.conf 의 PRIMARY_DOMAIN=demo 면 차단.  ← db.conf 없으면 통과(무력)

[봉합 후 — 화이트리스트(fail-safe)]
  1) test 마커 파일 존재 확인: C:\HitPanTest\HITPAN_TEST_ENV.marker
     · 없으면 → 무조건 차단 ("test 환경 명시 증명 안 됨")
  2) 마커 내용 검증: ENV=TEST 줄 + SLOT 식별자 포함
  3) (2차 방어 유지) db.conf 있고 PRIMARY_DOMAIN=demo 면 추가 차단
  → 마커 통과 + demo 아님 = 둘 다 만족해야 실행
```
- **demo엔 이 마커가 절대 없다** → demo에서 실행 시 100% 차단. fail-safe.
- 마커는 test 슬롯 구축(작1 5-4) 시에만 생성. 운영 배포본엔 절대 미포함.

### 봉합 ② 죽이는 대상 → test 서비스명 파라미터화 (L15-21 param·L78·90·102)

```
[추가 파라미터]
  $CloudflaredSvc = 'cloudflared-test'    # 기본값 -test 접미사
  $MariaDbSvc     = 'MariaDB-test'
  $ApiProcName    = 'HitPan.API'          # 프로세스는 test 슬롯 작업폴더로 식별

[죽이기 직전 가드]
  · Stop-Service 대상이 '-test' 또는 마커 명세 서비스명인지 재확인.
  · 이름에 '-test' 없으면 → 그 시나리오 SKIP + 경고("demo 서비스명일 수 있음, 분리 안 됨").
  · API kill 은 ProcessPath 가 test 슬롯 경로(C:\HitPanTest\...) 일 때만.
```
- 마커 파일이 이 슬롯의 서비스명을 명세 → 스크립트가 마커에서 읽어옴. 마커=서비스명 단일 진실원.
