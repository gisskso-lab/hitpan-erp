### P0-1: 작A 단일 DB tx 1택 (Saga·2PC 폐기)
**백엔드 매니저 Oracle 30년 단호 반박 — PM "Saga·2PC·단일 tx 선택" 폐기**

- 단일 MariaDB 노드·단일 tenant DB 내 작업 → **단일 tx 외 선택지 없음**
- 헌법 #25 (쉽게) + 헌법 #16 (MySqlConnection 단일성) 정합
- Oracle 30년 경험: "단일 DB 내 N:N 쓰기에 2PC를 붙인 프로젝트는 100% 운영 사고로 회귀"

**tx 패턴 박제**:
```
BEGIN;
  INSERT purchase_returns (header)         -- 1건
  INSERT purchase_return_lines (lines)     -- N건
  INSERT stock_ledger (qty = -원본qty)     -- N건, INSERT ONLY
  INSERT journal_lines (차/대 swap)        -- M건, INSERT ONLY
COMMIT;  -- 부분실패 0
```

**DB 매니저 Oracle 30년 단호 권고 — 신규 4테이블 폐기**

- 기존 `purchase_receipts`·`sales_deliveries` 헤더에 `is_return` flag + `original_*_id` self FK 추가

- **신규 4테이블 분리 폐기 사유**:
  - JOIN 복잡도 폭증
  - 잔액 view 양분 (4테이블 UNION ALL → 30년 누적 시 view 응답 5초+)
  - 마이그 ETL 2배 부담
- **flag 모델 보장**: 단일 인덱스 `(tenant_id, is_return, confirmed_at)` 0.1초 이내

**DDL 영역 (5/26 DESCRIBE 후 최종 확정)**:
```sql
ALTER TABLE purchase_receipts
  ADD COLUMN is_return TINYINT(1) NOT NULL DEFAULT 0 AFTER status,
  ADD COLUMN original_receipt_id BIGINT NULL AFTER is_return,
  ADD INDEX idx_is_return (tenant_id, is_return, confirmed_at),
  ADD CONSTRAINT fk_pr_original FOREIGN KEY (original_receipt_id)
      REFERENCES purchase_receipts(receipt_id);

ALTER TABLE sales_deliveries (동일 패턴);
```
