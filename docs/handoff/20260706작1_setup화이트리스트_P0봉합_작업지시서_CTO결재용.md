## 1-B. 🔴🔴 CTO 검토가 잡은 2차 벽 — BOOTSTRAP_TOKEN_KEY 불일치 (실측 확정 2026-07-06)

## 2. ⚠️ CTO·사장님 결재 전 반드시 짚을 미해결 2건 (오진 방지 — 봉합만으로 종단 보장 못 할 수 있음)

### 미해결 A: "수요일 test000 은 됐다" vs ed46b1f 시각 모순
- ed46b1f = 6/25 21:56 = 수요일(7/1~7/2) test000 설치보다 **먼저**. 즉 test000 도 결함 코드였어야 하는데 사장님은 "됐다" 기억.
- 가능성: (A) 수요일도 실은 부모계정 미생성인데 다른 화면을 성공으로 기억 (B) 수요일 설치가 이 경로를 안 탄 특수 상황.
- **봉합 판단**: 현 코드 결함은 실측 확정이므로 봉합은 정당. 단 **수요일 미스터리는 봉합 후 종단 재현으로 검증**(봉합 후 users 1건 생기면 이게 진범 확정 / 여전히 안 되면 B의 숨은 원인 추적). 봉합을 막을 사유는 아니나, "봉합=끝"으로 단정 금지.

### 미해결 B: 프론트는 이미 실패를 막게 돼 있다 (2차 결함 재평가)
- `LicenseSetupPage.razor` L289~301·L348~357: bootstrap/create-parent 실패 시 `_error` 표시 + 다음 단계 진행 차단(`if IsSuccessStatusCode && Success`). **조용히 넘기지 않음.**
- 즉 지난 진단의 "프론트가 401 조용히 넘겨 정상처럼" 은 **부정확**. 프론트는 막는다.
- 그럼 사장님이 "3단계 완료·다운로드까지 봤다"는 것과 상충 → **미해결 A 와 같은 뿌리**(수요일 설치가 어떤 경로였는지)일 가능성. 프론트 봉합은 **본 작지서 범위에서 제외**(현 코드에 결함 근거 부족). 종단 재현에서 프론트 거동 실관찰 후 필요시 별도 작지서.
