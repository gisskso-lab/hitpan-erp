## 1. 봉합 완료 — 설치 중단 진범 (실측 확정)

### 진범 = HitPan-Universal.iss의 SQL 따옴표 버그 (4팀 만장일치 + PM 직접 cmd 재현)
- **위치**: `installer/HitPan-Universal.iss` 830·844·847줄
- **버그**: 검증 쿼리가 `table_schema=''hitpan_erp''`(작은따옴표 2겹)으로 나가 **ERROR 1064** → 테이블 수가 **항상 0**으로 읽힘 → `USERS_OK=0` → `exit /b 1` → "데이터베이스 초기화 실패(코드 1)" → 설치 중단.
- **PM 직접 재현**: 2겹따옴표 → ERROR 1064 → 카운트 0 / 1겹 → 137 정상. cmd.exe 실측 확인.
- **"수정 전엔 됐던" 이유**: 이 버그는 줄곧 있었으나 1.2.15에서 `exit /b 1` 전파를 추가하며 비로소 드러남. PM 빈 스키마와 무관.

### 봉합 내용 (완료)
830·844·847줄: `table_schema=''''%s''''` → `table_schema=DATABASE()` + `-p%s` 뒤에 ` %s`(DB명) 추가해 회사 DB 직접 접속.
- 834줄(items/partners)은 `%s.items`로 DB명 직접 한정 → 따옴표 문제 없음, 봉합 불필요.

### 봉합 실측 검증 (PASS)
137 빈스키마를 회사user로 import 후 봉합 쿼리 실행:
- FINAL_COUNT = **137** (전엔 0)
- USERS_OK = **1** (테이블 인식됨)
→ 설치 검증 통과 → 설치 끝까지 진행됨 (중단 사라짐)

## 2. 사장님 두 의문 — 실측으로 답 나옴

### Q1. "데모랑 설치본 스키마가 다르다?" → **아니다. 동일.**
4팀 전수 diff: 데모(38MB)·빈스키마·번들 **전부 137 테이블, 테이블명 0줄 차이**. md5도 빈스키마=번들 동일. PM이 봤던 91/114/115 숫자는 따옴표 버그로 카운트가 0으로 읽힌 착시.

따옴표 버그는 데모 DB로 빌드해도 똑같이 터진다. 빈 스키마와 무관.

- 진범 A (sql_mode NO_AUTO_CREATE_USER): 데모에도 같은 토큰 있고 됐음. 로컬 import 통과. **무죄.**
- 진범 C (ALTER DATABASE 잔존): 빈스키마·번들 0건. **무죄.**

## 3. ⚠️ 미해결 — 다음 작업자 최우선 (로그인까지 가는가)

### 핵심: 설치는 되는데 로그인 계정이 0명
- 빈 DB라 `users = 0`. 데모는 master 1명 있어 로그인됐음.
- **설계상 정상**: 랜딩 가입 → 부모계정 발급 → 설치 시 시리얼 등록 → ERP 첫 접속 시 부모계정이 users에 INSERT(0→1) → 로그인.

### 부모계정 등록 흐름 — 코드는 있음 (CompanyBootstrapController.cs)
```
/setup/license Step1 → 백오피스 /api/landing/license/claim (시리얼로 부모계정 확인)
→ bootstrap (local_company INSERT = 회사정보 자동 반영, 76줄)
→ POST /api/setup/create-parent → users INSERT (is_parent=1, 240줄)
```

### 🔴 PM이 발견한 의심 끊김점 (미확정 — 반드시 확인)
- **bootstrap은 `local_company`에 INSERT(76줄). 그런데 users는 `tenants` 테이블을 FK 참조(`fk_users_tenant`).**
- PM 간이 테스트에서 부모계정 INSERT 시 **ERROR 1452 (FK 위반)** 발생 — tenants가 안 채워져서.
- **즉 create-parent가 users INSERT 전에 `tenants`를 채우는지 미확인.** 안 채우면 빈 DB에서 부모계정 생성이 FK로 막혀 로그인 불가.
- ※ 단 PM 간이 테스트는 컬럼을 덜 넣은 불완전 테스트라, 실제 API가 tenants를 채우는지 코드로 확인 필요. CompanyBootstrapController.cs 195~240줄 (create-parent가 tenantId/tenants 처리하는 부분) 정독 필요.

### 다음 작업자 할 일 (순서)
1. CompanyBootstrapController.cs create-parent가 users INSERT 전에 tenants를 채우는지 확인. 안 채우면 그게 끊김점 → 봉합.
2. 빈 DB에서 bootstrap→create-parent 전체 흐름을 실제 API로 돌려 users 0→1 되는지 실측.
3. 로그인까지 도는지 확인 (그 계정으로 로그인 200).
