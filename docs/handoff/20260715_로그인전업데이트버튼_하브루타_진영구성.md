# 로그인 전 "최신으로 업데이트" 버튼 — 하브루타 진영 구성 (사장님 지시 박제)

> 2026-07-15 새벽, 사장님 연속 지시로 확정된 토론 구조. 최종 임원 보고서 작성 시 이 관점 배치를 지킬 것.

## 사장님 못박음 (지시 순서대로)

1. **전 직원 하브루타** — 받아쓰기 없이, 위계 없이 토론. 회의록은 임원단(CTO·PM·보안상무·설계팀장·검증팀장)이 정리해 보고서 제출.
2. **더 딥하게** — 예상치 못한 문제까지 예상. (→ 레드팀 8각도 워크플로우)
3. **검증팀 = 최강 레드팀** — 치고박고 싸우며.
4. **근거강제** — 레드팀은 "이게 왜 안 되는지" 확실한 근거(파일:라인/재현절차), 반대진영은 "이게 왜 되는지" 확실한 근거. **근거 없는 공격·방어는 무효.**
5. **주심 = 임원단 철저 관리감독** — 매 라운드 임원단 5인이 주심으로 근거부실·인상비평 각하.
6. **영업·ERP·마케팅 팀장 = CS 강지원과 같은 현장관점, 개발팀과 활발한 피드백.**
7. **⭐영업·ERP·마케팅 셋 = 현장 관리자로서 철저히 고객 관점** (CS는 응대현장 관점, 이 셋은 고객이 화면 앞에서 느끼는 것).
8. **법적 근거 가이드라인 = 법무팀장 지휘.**

## 진영 배치 (최종 보고서에서 이 구분 유지)

| 진영 | 구성원 | 관점 |
|---|---|---|
| 레드팀(공격) | 검증팀장 데이비드 박 + 검증팀 | "왜 안 되는지" 근거강제 |
| 아키텍처(방어) | 설계팀장·풀스택 존·백엔드·네트워크 마이클 | "왜 되는지" 근거강제 |
| 보안 | 보안상무 안철수·보안매니저1·2·보안개발자 | 공격면·서명·최소권한 |
| **현장(고객관점)** | **영업팀장·ERP매니저·마케팅팀장** | **고객이 화면 앞에서 느끼고 막히는 것** |
| CS(응대현장) | CS팀장 강지원 | 전화응대·재설치 제거·무반응버튼 |
| 개발 | 프론트·백엔드·워치독 개발자 | 실현가능성 코드응답 |

| **주심(관리감독)** | **CTO·PM·보안상무·설계팀장·검증팀장 5인** | 매 라운드 근거부실 각하 |

## 규칙
- 인상비평("~일 것 같다") 금지. 파일:라인 코드근거 또는 백지환경 재현절차 없으면 각하.
- 각하된 주장은 다음 라운드로 못 넘어감.
- 최종 결론은 근거로 살아남은 위협만. 과장·낙관 금지.
