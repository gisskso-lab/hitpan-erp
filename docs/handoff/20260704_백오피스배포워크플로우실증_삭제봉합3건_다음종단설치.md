### 실측으로 확정된 사실
- **ERP·API·DB = 완벽 정상.** 테스트 PC에서 `curl http://localhost:5257/api/auth/login` → 400(정상 validation 응답). 설치 자체 성공(`Installation process succeeded`).
- **`[FixupBlazor]` 정상 작동** — appsettings 4개(web/api·Local·Development)를 `https://test1.hitpan.kr`로 정확히 정정. 즉 화면이 test1 API를 부르는 건 **정상**(옛 잔재 아님).
- **cloudflared 서비스 = 미설치** (`sc query cloudflared` → 1060 없음). 그래서 **test1.hitpan.kr → Cloudflare 530(=Error 1033, 터널 미연결)**. 로그인 fetch가 CORS/ERR_FAILED로 뜬 건 이 530의 증상.
- cloudflared.exe **파일은 설치됨**(`C:\Program Files\HitPan\cloudflared.exe` 65MB, `--version` 정상). 파일 문제 아님.
- 백오피스 부트스트랩(18:28) 로그: 터널 발급 성공(`success cf=True`), ingress PUT `host=test1.hitpan.kr origin=localhost:5257` 완료. **백오피스는 제 할 일 다 함.**
- 설치 로그 마지막 = "터널 연결 활성화에 5~10분 필요, 안 되면 고객센터" **폴백 메시지** = 설치 스크립트가 터널 헬스체크 실패를 감지하고 띄운 것.

### 🔴 진범 = 터널 공유 구조 결함 (2가지 겹침)
1. **터널 이름이 tenantCode 고정** — `CloudflareDomainService.IssueTunnelAsync` L182 `tunnelName = $"hitpan-{tenantCode}"` = 항상 `hitpan-t001`(고객사코드는 T-001 하나). 그래서 test000·test1·모든 재설치가 **같은 관리형 터널 UUID `b8efde38-c50b-49ac-91bc-5abf3cfce753` 공유**. 관리형 터널(config_src=cloudflare) 1개는 토큰 하나로 한 곳만 연결 — 여러 PC/재설치가 못 나눠 씀. ingress도 마지막 도메인(test1)만 가리킴.
2. **6-2 service install 실패를 안 잡음** — `HitPan-Universal.iss` L1150 `Exec('...cloudflared.exe','service install '+G_TunnelToken,...)` 후 **ResultCode 미검사(헌법#15 위반)**. 실패해도 조용히 통과 → 서비스 없이 "설치 완료"로 끝남. 오늘 4번 재설치 시 6-1 좀비제거(`sc delete cloudflared`)가 매번 돌며 타이밍/토큰 꼬임 유발 가능. 전체 터널블록은 `if G_TunnelToken <> ''` 조건(L1128) — 토큰 빈값이면 통째 스킵.
