## 1. 진범 (2026-07-22 오전 실측 확정)

### 증상
- 7/21 밤 자동업데이트 팝업이 **처음으로 떴으나**, 뜨자마자(0.5초) 사라져 **"예"를 누를 수 없다.**
- 사장님 실측: "팝업 뜨자마자 바로 없어짐", "누를 경황도 없이".

### 반증으로 좁힌 과정 (추측 아님)
| 확인 | 결과 |
|---|---|
| 콘솔 에러 | **없음** → 예외로 죽은 게 아님 |
| `ConfirmDialog.ShowAsync` | 정상(`await dlg.Result` 로 클릭 대기, `BackdropClick=false`) — 스스로 못 사라짐 |
| 사라지는 속도 | **0.5초** → 타이머 자동닫힘 아님, 재렌더/폐기 계열 |

### 진범 (코드 확정)
[`AuthService.cs:91`](../../src/HitPan.Web/Services/AuthService.cs#L91) `NotifySessionChangedAsync()` 가
로그인 성공 시 **인증 상태 변경을 방송** → Blazor 라우터가 "인증된 사용자가 `/login` 에 있으면 안 됨"으로
판단해 **`Login.razor` 컴포넌트를 즉시 폐기(dispose)** → 그 위에 뜬 다이얼로그가 딸려 사라진다.

**핵심**: 로그인이 성공한 순간 `/login` 페이지는 사라질 운명이다. [`Login.razor:114`](../../src/HitPan.Web/Pages/Login.razor#L114)
에서 `await` 로 순서를 맞춰도 소용없다 — **페이지 자체가 없어지므로.** 순서 조정으로 해결 불가, 구조 이동이 답.

### 왜 지금까지 안 잡혔나
팝업 코드는 6/29(`c1221f9`)에 들어갔으나, 서버에 새 버전이 없어 **팝업이 실제로 뜬 적이 0회**였다.
어제 처음 뜨자 즉시 드러났다. → 사장님 헌법 "개발PC 정상작동은 검증이 아니다" 정확한 사례.

## 2. 봉합 설계 (사장님 방향 그대로)

> 사장님 지시(2026-07-22): **"팝업을 로그인창이 아닌, 히트판ERP창에 띄우면 되잖아."** — 이게 정답.

```
[현재 — 고장]
Login.razor 에서 팝업 → 로그인 성공 → /login 폐기 → 팝업 딸려 사라짐 (0.5초)

[봉합]
Login.razor : 팝업 코드 제거 (L110-115 삭제). 이동만.
        ↓ (기존 이동 흐름 그대로)
MainLayout : 신규 게이트 컴포넌트 <UpdateConsentGate /> 삽입 (배너 2개와 동일 패턴)
             → ERP 화면 로드 시 API 조회 → 새버전 있으면 팝업 → 이 화면은 안 사라짐 → 유지
```

### 모듈화 (사장님 원칙 정합)
- 팝업 표시를 **독립 컴포넌트** `UpdateConsentGate.razor` 로 분리. Login·MainLayout 본체 손상 최소.
- 게이트가 실패해도(조회 실패·팝업 실패) **로그인·ERP 사용은 안 막힌다**(기존 배너와 동일 방어).
- 기존 `TermsConsentBanner`·`CommsRecoveryBanner` 와 **완전히 같은 삽입 패턴** → 검증된 자리.

## 3. 작업 항목

### W-1 (백엔드) — 업데이트 상태 조회 GET 엔드포인트 신설
**목적**: 게이트 컴포넌트가 로그인 응답에 의존하지 않고 독립적으로 상태를 조회(모듈화).

- 파일: `src/HitPan.API/Controllers/AuthController.cs`
- 신설: `GET api/auth/update-status` — **`[Authorize]` 필수**(CTO B-2). `[AllowAnonymous]` 금지.
  - 미인증 401 시 게이트는 조용히 스킵(W-2 방어와 정합).
  - 기존 `EnrichUpdateConsentInfoAsync` 의 `local_update_status` 조회 로직을 **재사용**
    (중복 구현 금지 — private 메서드로 추출해 로그인·신규엔드포인트 공용).
  - ⚠️ 추출 후 로그인 경로 동작이 **1비트도 안 변해야** 함(SemVer 비교·폴백 포함, CTO A-2).
  - 응답: `{ currentVersion, updateAvailable, latestVersion, updateChannel, consentMessage }`
  - **로그인 응답의 기존 필드는 유지**(하위호환 — 제거 시 회귀 위험). 게이트는 신규 GET을 쓴다.
- 방어: 테이블 부재·조회 실패 → `updateAvailable=false` 안전 폴백(기존 로직 그대로, 헌법 #15).

### W-2 (프론트) — 팝업 표시 게이트 컴포넌트 신설
- 신설 파일: `src/HitPan.Web/Components/Common/UpdateConsentGate.razor`
- 패턴: `TermsConsentBanner.razor` 를 본떠 작성
  - `OnInitializedAsync` 에서 인증 확인 → `GET api/auth/update-status` 조회
  - `updateAvailable == true` 면 `ConfirmDialog.ShowAsync` 로 팝업(기존 `PromptUpdateConsentAsync` 로직 이식)
  - [예]=approve / [나중에]=reject → `SubmitUpdateConsentAsync` (기존 서비스 재사용)
  - **⚠️ CTO B-1 (무한 안내 차단, 필수)**:
    - `MainLayout` 은 모든 화면 껍데기라 페이지 이동마다 재조회될 수 있다. **반드시 가드.**
    - 조회·팝업은 **레이아웃 생명주기 1회만**. `Nav.LocationChanged` 로 재트리거하지 **않는다**
      (`TermsConsentBanner` 는 경로표시 갱신용으로 구독하나, 게이트는 팝업 재노출을 막아야 하므로 미구독).
    - [나중에] 거부 시 **이 세션 재노출 안 함**: `sessionStorage["hitpan_update_prompt_shown"]="1"` 저장,
      `OnInitializedAsync` 진입 시 이 키 있으면 즉시 return. (다음 로그인은 새 세션 → 재안내 OK)
  - 미인증·조회실패·팝업실패 → 조용히 스킵(ERP 사용 안 막음).

### W-3 (프론트) — MainLayout 에 게이트 삽입
- 파일: `src/HitPan.Web/Layout/MainLayout.razor`
- `<TermsConsentBanner />`(L43) **다음 줄**에 `<UpdateConsentGate />` 추가.
- ⚠️ 약관 미동의 시엔 팝업을 띄우지 않는다(약관이 우선 — 게이트 내부에서 `/terms` 경로·미동의 가드).

### W-4 (프론트) — Login.razor 팝업 코드 제거
- 파일: `src/HitPan.Web/Pages/Login.razor`
- 제거: L110-115(`if (UpdateAvailable) await PromptUpdateConsentAsync`) + `PromptUpdateConsentAsync` 메서드(L155-186)
- **주의**: `DeviceNewlyRegistered` 통지(L120-138)·약관 분기(L104-108)·이동(L140-147)은 **건드리지 않는다.**
- 결과: Login.razor 는 로그인·약관·기기통지·이동만. 업데이트 팝업 책임 없음(모듈화).
