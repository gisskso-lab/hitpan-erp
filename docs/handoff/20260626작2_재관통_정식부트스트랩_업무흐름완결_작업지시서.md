## 1. 목적 (사장님 결재)

작1이 "절반"에서 막혔다 — 테스트 테넌트가 정식 가입 경로(create-parent)를 안 거쳐 **창고·표준계정이 시드 안 됨**. 그래서 매입확정·판매확정·세금계산서까지 도달 못 함. 이번엔 **정상 신규고객과 동일하게 부트스트랩(창고1+계정8 시드)을 거친 깨끗한 테넌트**로 6단계 흐름을 **끝까지** 관통해, "흐름이 진짜 끝까지 도는가(헌법 #20)"를 실증한다.

## 2. 범위

### 2.1 한다
1. **정식 부트스트랩 시드 재현**: 정상 고객이 `POST /api/setup/create-parent` 시 거치는 시드(warehouses 1건 'MAIN' + accounts 표준 8계정, CompanyBootstrapController.cs:308-356)를 거친 테넌트 상태를 만든다.
   - **1순위(정공법)**: 정식 create-parent 경로를 그대로 태운다(local_company UPSERT → bootstrapToken 재검증 → 부모생성+시드). 테스트용 bootstrapToken 발급이 가능한지 코드로 확인 후 진행.
   - **2순위(불가 시)**: 정식 경로가 테스트 환경에서 토큰 문제로 막히면, **create-parent가 실행하는 시드 SQL과 100% 동일한 내용**(:309 warehouses INSERT, :348 accounts 8계정 INSERT)을 테스트 DB(hitpan_e2e)에만 적용해 "정상 가입 후 상태"를 재현한다. ⚠️이건 운영 아님·테스트DB만·코드 수정 아님(데이터 시드).
2. **6단계 끝까지 관통**: 거래처→상품→발주→매입생성→**매입확정(stock_ledger 증가+journal_lines 기표)**→견적→수주→거래명세서→**판매확정(재고차감+기표)**→**세금계산서 발행**→현황·재무(차변=대변).
3. 각 단계 **DB 쿼리 교차확인**(200 둔갑 방지). 깨지면 목록만.
