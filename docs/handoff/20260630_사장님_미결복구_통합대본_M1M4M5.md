## 🔴 M1 — demo db.conf 복구 (가장 급함, 단순)

**왜**: slot빌더가 demo db.conf를 테스트값으로 덮음. demo API(TenantConfigReader)가 읽으므로 **재시작 시 인증 깨짐 잠복**. 현재 demo는 정상(메모리에 옛 설정)이라 재시작 전 복구하면 안전.

**관리자 PowerShell에서 한 줄씩:**
```powershell
# [1] 오염본 증거 백업
Copy-Item "C:\Program Files\HitPan\db.conf" "C:\Program Files\HitPan\db.conf.testslot-bak-20260630" -Force

# [2] 백업 확인 (e2e-comms 보이면 정상 백업)
Get-Content "C:\Program Files\HitPan\db.conf.testslot-bak-20260630"

# [3] demo 원본값 복구 (UTF-8, BOM 없이)
$demo = @(
  "# ===== HitPan demo 운영 db.conf (2026-06-30 PM 복구) =====",
  "PRIMARY_DOMAIN=demo.hitpan.kr",
  "API_PORT=5257",
  "DB_NAME=hitpan_erp"
)
[System.IO.File]::WriteAllLines("C:\Program Files\HitPan\db.conf", $demo, (New-Object System.Text.UTF8Encoding($false)))

# [4] 복구 확인 (demo.hitpan.kr / hitpan_erp 보이면 성공)
Get-Content "C:\Program Files\HitPan\db.conf"
```
- **성공 신호**: [4]에서 `PRIMARY_DOMAIN=demo.hitpan.kr` + `DB_NAME=hitpan_erp`
- ⚠️ demo API **재시작 불필요** — 지금 정상, 이건 다음 재시작 대비.
- 끝나면 PM에게 [4] 결과 알려주시면 검증합니다.

## 🟡 M4 — 테스트 인스턴스 분리 (결재 필요, 무거움)

**왜**: hitpan_e2e(테스트)가 운영(hitpan_erp 129만행)과 **같은 MariaDB 3306 인스턴스**에 있음. P1·고리4 검증을 안전하게 하려면 **운영과 물리 분리된 인스턴스/포트** 필요. (작3 봉합으로 이제 slot빌더는 운영 인스턴스에 슬롯 못 만듦 → M4가 있어야 슬롯 생성 가능)

**선택지 (사장님 결재 필요 — PM 단정 안 함):**

### 옵션 A — 별도 포트의 MariaDB 인스턴스 (이 PC 안)
- 이미 `MariaDBssk`(11.7, 3307)가 있음. 여기에 테스트 슬롯을 둘 수 있음.
- 또는 새 MariaDB 인스턴스를 3308 등에 설치.
- 장점: 이 PC에서 완결. 단점: 같은 PC라 완전 격리는 아님.

### 옵션 B — 별도 PC/VM
- 운영(demo)과 물리적으로 다른 PC/VM에서 테스트.
- 장점: 완전 격리(헌법 #39 정석). 단점: 장비·셋업 필요.

→ **이건 사장님 결정사항.** 결정하시면 PM이 그에 맞는 slot빌더 포트·인스턴스 파라미터 대본을 드립니다.
