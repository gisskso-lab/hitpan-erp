## 2. ⭐ 사장님이 그려주신 자동업데이트 목표 그림 (이게 목표 상태다)

사장님이 며칠에 걸쳐 친절하게 설명하신 완성 그림. **이대로 실동작시키는 게 다음 세션 목표.**

### 자동업데이트 흐름 (반자동)
1. **트리거** = 고객사 ERP **로그인 시 또는 새로고침 시**.
2. **버전 비교** = 고객사 설치 버전 vs 백오피스 최신 버전. 같으면 유지, **서버가 높을 때만** 업데이트(다운그레이드 방지 절대).
3. **Y/N 팝업** = "새 버전 있습니다, 업데이트할까요?" + **변경 내용 반드시 공지**(뭐가 바뀌고 수정되는지 — 깜깜이 Y 금지, 사장님 느낌표 다섯 개 강조).
4. **Y 누르면 → 실제 업데이트 진행**(다운로드·교체·재시작). ← **지금 이게 안 돼서 며칠째 하는 것.**
5. N 누르면 안 함.

### 반자동 원칙 (사장님 확정)
- **완전자동 아님.** 로컬 ERP라 고객사마다 환경(OS·백신·데이터양) 다름 → 무조건 최신 강제하면 B 고객사 죽는다.
- **전 등급 모두 고객 동의(Y) 필요** — 강제(보안·치명)조차 동의 있어야. 본사가 강제로 밀거나 팝업 막지 않음.
- **통제권 = 고객이 전적으로 쥠.** 팝업은 항상 뜨고, 진행/안 함은 고객이 정함(#22·#24 데이터 주권 정합).

### 등급제 (CS팀장 강지원 동의, 본사가 배포 시 박음)
- **강제(보안·치명) / 권장(버그) / 선택(UI)** — manifest 에 등급 필드 추가.
- CS 는 등급을 **읽고 안내**만, **판단 안 함**(상담원이 판단하면 사고). 등급 있어도 동의는 필요(위 원칙).

### 백오피스 고객사 관리 (CS 첫 도구)
- **버전 테이블** = 고객사별 **현재 설치 버전** (고객사 → 백오피스 보고). 본사가 각 고객 버전을 안다.
- **왜**: 고객한테 "몇 버전 쓰세요?" 물으면 그 확인 자체가 CS 업무가 됨. 고객은 자기 버전 모름. **본사가 백오피스에서 확인·선제 대응**이 맞다.
- **비고(메모) 컬럼** (사장님 추가 요구): 고객사별 "업데이트 금지"·"버전 X 최적화" 등 메모. **단 비고는 CS 참고용 — 팝업을 막지 않음**(고객 통제권 우선).
- CS팀장 강지원 "MVP 에 꼭": 버전만 말고 **(현재버전 + 마지막보고시각 + 업데이트 성공/실패)** 세트. *"로컬 ERP는 '업데이트했다'가 '업데이트됐다'를 보장 안 한다. 실패 여부 없으면 CS가 눈 감고 일한다."*

### CS 시나리오 (사장님·강지원 정리)
- **A 케이스**: 귀찮아 업데이트 안 한 고객 → 이미 고친 문제 겪음 → CS 가 버전 보고 "업데이트하세요"로 간단 조치.
- **B 케이스**: 최신인데 문제 터짐 → 새 버그, 개발 에스컬레이션 → 다음 버전 배포. **단 이전 버전에선 안 터지면 그 고객은 이전 버전 유지도** (로컬 ERP 환경차).

### 강지원 회의 안건 (MVP 아님, 나중 — 로컬 ERP CS 핵심)
- 원격접근 불가라 텔레메트리가 클라우드보다 더 중요 / B케이스 자동감지("같은버전+같은에러+3개사↑") / 버전 pin(고정) 기능 / 업데이트 실패로 멈춤을 고객 전화 전 인지 / 미보고 N일 선제연락.

## 5. 🔴 다음 세션 = 실동작 검증 (진범 봉합 확인)

### 핵심 이해
- 진범 = 옛 EXE 에 고리4 없음. **고리4 코드(a2c249f) 자체가 진짜로 교체를 하는지**는 아직 Sandbox 실측 안 됨(코드 SoD 는 통과, 실동작 미확인).
- 즉 두 가지를 갈라야: ⓐ 고리4 코드가 실제로 파일 교체·재시작을 하는가(코드 정상성) ⓑ 그게 옛 EXE 엔 없었을 뿐인가(진범).

### 실동작 검증 경로
1. **고리4 든 EXE 로 설치** (오늘 만든 1.2.33 EXE = 고리4 포함, 또는 다음 버전).
2. 다음 버전(고리4 포함) 올려서 로그인 → 팝업 → **Y → 실제 다운로드·교체·재시작 관측.**
3. ⚠️ **두 게이트가 낮 실측을 막음** (Worker.cs):
   - **영업시간 게이트**(L398 `IsBusinessHour`): Y 눌러도 낮이면 "보류", 밤에만 적용. **낮에 실측하면 Y 눌러도 아무 일 없음 = 정상 동작인데 실패로 오판.**
   - **하루 1회 게이트**(L307): 워치독 하루 1회만 점검. 재실측 시 워치독 서비스 재시작 필요.
   - → **실측 전 이 게이트 처리(즉시 적용 옵션 or 테스트 우회)를 사장님과 정해야 함.** 안 정하면 또 "안 된다" 오판.

- 사장님 목표 그림(§2)을 **작지서로 만들어 CTO→대표 결재 후 구현.** [[project_dev_process_sop_20260625]]
