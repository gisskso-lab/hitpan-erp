# §5. 🔴 PM 오판 기록 (반드시 읽기 — 같은 실수 금지)

## 5-1. 손으로 API 띄운 게 유령 프로세스 사고의 근원
어제 test1 404 봉합 때 `Start-Process HitPan.API.exe`로 API를 손수 띄움 → Session 1 유령 → 파일잠금 → 교체 실패(taskkill이 Session 0에서 Session 1 못 죽임). **API는 절대 손으로 띄우지 말 것.** schtasks(keepalive)가 Session 0으로만 관리.

## 5-2. Emergency 채널로 게시해 팝업이 원천적으로 안 뜸
사장님이 원한 건 "팝업→Y→교체"인데 PM이 "실측 빨리 보려고" Emergency(팝업 없이 자동적용)로 게시 → "팝업 안 뜬다"가 계속 나옴. **팝업은 Major 전용.** 채널을 먼저 확인하라.

## 5-3. "1.2.38 교체 완주"라 보고한 게 오판 (헌법 #32)
파일 교체 직후 순간 FileVersion=1.2.38을 보고 "완주!"라 보고 → 실은 **직후 검증(.dll 부재)이 롤백**시켜 1.2.37로 돌아감. **순간값을 완주로 착각.** 2분 뒤 재확인했어야 함. 사장님이 "뭐한거야"로 지적. → 봉합 #3의 진짜 심각성(성공교체 롤백)을 그제야 CTO가 교정.

## 5-4. 오염 환경에서 계속 판 것 (오늘 두더지잡기)
손시드·유령·롤백 5회+ 반복된 Sandbox에서 팝업/교체를 짜맞추려다 "안뜸" 반복. **오염 환경은 버리고 백지로 가는 게 정답**인데 늦게 판단. 사장님이 B(백지) 결정. → 교훈: **환경이 꼬였으면 짜맞추지 말고 백지 리셋.**

## 5-5. 판단 알고리즘 (계속 유효)
1. 가설 세우면 반증부터(반증 3분 vs 틀린수정 40분).
2. 관측과 추론 분리 — 순간값을 완주로 단정 금지(5-3).
3. 검증 안 된 걸 "완주/진전"이라 하지 않는다(헌법 #32).
4. 환경 오염되면 짜맞추지 말고 리셋(5-4 신규).
5. 채널·전제부터 확인(팝업=Major, 5-2).
