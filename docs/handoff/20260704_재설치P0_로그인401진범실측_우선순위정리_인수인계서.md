## 0. 한 줄 요약

물리적으로 다른 PC에 히트판 ERP를 **재설치**했더니 로그인이 **401**로 막혔다. 실측 결과 진범 =
**부모계정(users 테이블) 0건**. 재설치가 DB를 새로 깔면서 수요일에 만든 부모계정이 소멸했고,
부모계정 재생성(`/setup/license` 4단계)을 다시 안 밟아서 로그인할 계정 자체가 없었다.
→ **이건 모든 고객의 재설치 시 재현되는 P0.** 봉합 방향은 사장님 결재로 잡힘(비번 재설정 + 3중 인증).

## 1. 실측으로 확정된 사실 (추측 아님 — 전부 DB/코드 실측)

### 1-1. 로그인 401의 진범 = 부모계정 0건
- 설치 PC(test000, **demo 운영 아님 — 헌법 #39 안전**)에서 실측:
  - `SHOW DATABASES` → `hitpan_erp` 존재(테넌트별 `hitpan_erp_t001` 아님)
  - `db.conf` = `C:\Program Files\HitPan\db.conf` (config 폴더 아님). 내용 정상:
    `DB_NAME=hitpan_erp / DB_USER=hitpan / DB_PASSWORD=ffeb0126... / TENANT_CODE=T-001 /
     PRIMARY_DOMAIN=test000.hitpan.kr / LICENSE_KEY=HITP-T683-NDGE-FS3W-EYAX / TUNNEL_ID·TOKEN 존재`
  - `DESCRIBE users` → 테이블·스키마 정상(user_id, email, password_hash, account_type…)
  - **`SELECT * FROM users` → 0건** ← 진범. 로그인할 계정이 없음.
  - `local_company` 테이블도 존재하나 데이터 확인은 못 함(다음 세션 확인 항목).
- **비번 5회 실패 카운트가 안 뜬 것**(사장님 관찰)이 결정적 단서였음 = 비번 대조 전에 "계정 없음"으로 막힘.

### 1-2. 왜 부모계정이 0건인가 (설치 흐름 실측)
- 부모계정은 설치 EXE가 자동 생성하지 않는다. **설치 후 브라우저 `/setup/license` 4단계**에서 사람이 만든다:
  - Step1 라이선스+사업자번호 → 백오피스 `api/landing/license/claim` 검증 → bootstrapToken 발급
  - Step2 회사정보 → ERP `api/setup/bootstrap` → `local_company` 채움 + `is_locked_from_landing=1`
  - Step3 이메일·비번 → ERP `api/setup/create-parent` → **users에 부모계정 INSERT** ← 이걸 해야 로그인됨
  - Step4 완료 → `/login`
- 파일: `src/HitPan.Web/Pages/Setup/LicenseSetupPage.razor` (4단계 UI),
        `src/HitPan.API/Controllers/CompanyBootstrapController.cs` (bootstrap + create-parent)
- **사장님 경위(확정)**: 수요일에 정식 가입(사업자 중복검사·OCR·도메인)→설치→부모계정 생성까지 함.
  설치본 이슈로 **금일 설치파일만 재설치** → DB 새로 빈 상태 → **부모계정 다시 안 만듦** → users 0건 → 401.

### 1-3. 백오피스는 정상 (실측 — W9 stub 걱정은 기우였음)
- `back.hitpan.kr` 관리자 로그인 됨. 고객사 관리 화면(`AdminTenantDetailV2`) **완전히 작동**.
- T-001("테스트") 상세: **상태=활성**, 시리얼 발급됨, 라이선스 해시 앞12자 `3ef51d2cfd81`, **ERP설치=미설치**.
- 사장님이 이 목록에서 시리얼 발급함 → T-001이 설치 PC와 짝 맞는 실측 대상 확정.
- **"ERP 미설치"** = 설치 PC가 백오피스에 부트스트랩 보고를 안 함(부트스트랩 자체가 안 돌았다는 방증, 1-2와 정합).
- 가입·시리얼·상태추적 코드는 살아있음:
  `LandingSignupController`(가입→landing_signups+tenants pending),
  `SignupsAdminController.Approve`(승인→시리얼 발급·license_key_hash·active·DNS·webhook·메일),
  `SerialVerifyController`(active tenant 해시 매칭, 5회 실패 잠금),
  `TenantsAdminController`(목록/상세/정지/복구/삭제 API 전부 있음).

## 3. 사장님 결재로 잡힌 봉합 방향 (재설치 P0)

### 3-1. 재설치 = 완전 초기화, 데이터는 백업이 책임 (사장님 확정)
- "재설치하면 DB도 덮어쓰기(초기화)". 데이터 보존은 재설치의 몫이 아니라 **백업**의 몫.
- 오류 나면 재설치가 아니라 **백업 복구**가 정상 흐름(헌법 #28 워치독·#20 정합).
- 재설치 복구 순서(사장님 못박음): **로그인이 먼저 돼야 백업 복구도 가능** → 봉합1(로그인 복구)이 봉합2(백업)의 전제.

### 3-2. 재설치 후 부모계정 복구 = 비번 재설정 (사장님 확정)
- 비번을 어디 보관(복호화)하지 않는다 — **해시 유지(보안 절대선, 헌법 #22·#23)**.
- 재설치 시 본인 확인 → **새 비번 재설정**:
  1. 시리얼 넘버 (백오피스 license_key_hash 매칭 — 코드 있음)
  2. 사업자등록번호 (biz_no_hash 매칭 — 코드 있음)
  3. ~~사업자등록증 OCR~~ → **베타2로 미룸**
- ✅ **갈래 확정 (2026-07-04 결재)**: 재설치 복구 = **2중 인증(시리얼 + 사업자번호)**으로 즉시 연다. 사업자등록증 **OCR은 베타2(NCP CLOVA)에 추가**(PM 권고 채택).
  - → 봉합1 작지서 = **2중 인증 기준**으로 확정. OCR 갈래 해소됨.

## 4. 엉킨 안건 우선순위 (다음 세션 이 순서로)

> 지금 여러 미완이 엉켜있음: NCP 배포막힘 + 삭제버튼 미배포 + 재설치P0 미봉합 + T-001 실측중단.
> 무작정 실측 재개하면 또 중간에 막힘. 아래 순서로 하나씩.

### 🥇 P0-A. NCP 접속/배포 경로 확보 (막힘 — 이거 안 되면 뒤가 다 막힘)
- ✅ **접속 방식 확정 (2026-07-04 결재): SSH 키 파일(.pem 등)** — 이전 백오피스 배포·데이터삭제도 이 방식.
- 오늘 `ssh -i hitpan-key.pem ubuntu@211.188.58.140` → **비번 물어보고 Connection closed** = 키를 안 썼거나 키 경로가 틀렸기 때문(비번 SSH는 서버가 거부).
- **다음 세션 첫 확인**: 실제 **키 파일(.pem) 위치**와 **계정명**(ubuntu 등). 이 두 개만 잡으면 그 경로로 배포 재개.
- 이게 확보돼야: 2-1(메일링크)·2-2(삭제버튼) 배포, 재설치 봉합 배포 전부 가능.
- 헌법 #29 — 접속·배포는 사장님 손. PM은 명령만 정확히 제공.

### 🥈 P0-B. 삭제 버튼 NCP 배포 → T-001 삭제 → 종단 실측 재개
- 삭제버튼 배포되면 back.hitpan.kr에서 T-001 삭제(DNS까지 정리) → 랜딩 재가입 → 재설치.
- 설치 PC도 깨끗이: `DROP DATABASE hitpan_erp` + 프로그램 제거 + `C:\Program Files\HitPan` 삭제.
- 도메인 재사용(test000) vs 새이름(test002) 결정 필요(재사용이면 CF DNS도 정리).
- **대안(배포 막히면)**: F12 콘솔로 `DELETE api/backoffice/tenants/{tenant_id}` 직접 호출로 T-001만 먼저 삭제.

### 🥉 P0-C. 재설치 P0 봉합 (본 게임 — §3 방향으로)
- **봉합1(로그인 복구)**: 재설치 후 users 0건이면 자동으로 `/setup/license` 유도 +
  `is_locked_from_landing` 잠금이 재설치를 막지 않게(같은 시리얼·사업자번호면 재부트스트랩/비번재설정 허용).
  - ⚠️ 실측 필요: `/setup/license` Step1 라이선스 검증이 **재설치 시 통과되는지 막히는지**(bootstrap L71 잠금).
    이 실측이 봉합1 범위를 가름(자동유도만 vs 잠금해제까지). 아직 안 함.
- **봉합2(백업 복구)**: "백업 파일 불러오기"가 실제 도는지 검증 + 재설치 전 자동백업.
- SOP: 전수조사→작지서→CTO결재→사장님승인→봉합→이 PC 재설치 재현 검증.
