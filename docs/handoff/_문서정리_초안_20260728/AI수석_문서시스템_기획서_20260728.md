## 0. 핵심 원리 — "왜 이게 클로드를 똑똑하고 빠르게 하나"

클로드(LLM)는 매 작업마다 **한정된 컨텍스트 창**에 정보를 올려 추론한다. 컨텍스트 = 클로드의 작업기억(RAM).
문서가 451개 뒤섞여 있으면 세 가지 손해가 난다:

| 문제 | 결과 | 이 기획의 해법 |
|---|---|---|
| 필요한 문서 하나 찾으려 수백 개를 훑음 | 토큰·시간 낭비 | **INDEX** — 폴더 안 열고 뭐 있는지 파악 |
| 오래된 오답 문서를 최신인 줄 오판 | 두더지잡기 재발 | **상태 태그(진실원/폐기/이력)** |
| 잡음이 신호를 덮음 | 엉뚱한 결론 | **1주제 1파일 + 상호참조** |

**결론**: 문서 정리는 파일 정리가 아니라 **클로드의 신호 대 잡음비(SNR)를 높이는 인프라 투자**다.
SNR이 오르면 정확도↑·속도↑·토큰↓가 **동시에** 개선된다.

## 1. 7대 구성요소 (AI 바이브코딩 효율화 전체 설계)

### ① INDEX (색인) — 폴더 최상단 지도
각 폴더 최상단에 `INDEX.md`. 폴더를 열지 않고도 "여기 뭐 있는지" 한눈에.

```markdown
# INDEX — docs/개발/업데이트배포
> 이 폴더: 자동배포·자동업데이트 구현·작업지시서·봉합
> 진실원: [[20260728_자동배포_첫실측완주]] ← 최신·이것부터

| 문서 | 상태 | 한줄 | 최종수정 |
|---|---|---|---|
| 20260728_첫실측완주.md | 🟢진실원 | UPDATE1.2.40 게시성공·B-4통과 | 2026-07-28 |
| 20260716_고리4_작지서.md | ⬛흡수됨 | 고리4 서명 작지서(→첫실측에 흡수) | 2026-07-16 |
```

**규칙**: 폴더에 파일 추가/수정 시 INDEX 한 줄 갱신 의무. INDEX 없는 폴더 = 미완성.

### ② 상태 태그 (Status) — "이게 아직 유효한가"
문서 프론트매터에 상태를 못박아 클로드가 **오래된 오답을 최신으로 오판하는 사고**를 차단.

```yaml
---
status: 🟢진실원 | 🟡진행중 | ⬛흡수됨 | 🔴폐기 | 📌헌법
supersedes: [20260720_자동업뎃_진범]   # 이 문서가 대체한 옛 문서
superseded_by: null                     # 이 문서를 대체한 새 문서(있으면)
updated: 2026-07-28
---
```

- **🟢진실원**: 현재 유효한 최신. 클로드가 우선 참조.
- **⬛흡수됨/🔴폐기**: 읽지 마라 신호. `superseded_by` 로 최신 위치 안내.
- 오늘 사고 예방 예: "7/23 이전 자동업뎃 진범"들이 🔴폐기로 태그됐으면 오판 0.

### ③ 상호참조 (Cross-ref) — `[[문서명]]` 위키링크
문서끼리 `[[name]]` 로 연결. 클로드가 "관련 문서"를 자동으로 따라가 필요한 것만 꺼냄.
- 이미 MEMORY.md 가 `[[feedback_xxx]]` 방식 사용 중 — **동일 규약을 docs 전체로 확장**.
- 끊긴 링크(대상 없음)도 OK — "나중에 쓸 문서" 표시(MEMORY 규약과 동일).

### ④ 각주·근거 (Footnote/Evidence) — "왜 그렇게 결정했나"
결정·주장에 **근거를 각주로** 달아 추적 가능하게. 헌법 #32(받아쓰기 금지)·SOP(기록주의) 정합.

```markdown
첫 실측은 우회 없이 정석으로 간다.[^1]
[^1]: 사장님 결정 2026-07-28 — "이행기 우회 안 쓰고 B-4 완전통과". 근거: 진짜 게시경로 검증.
```

- 코드 봉합엔 **커밋해시·PR번호·검증팀 판정**을 각주로: `[^2]: PR#11 435debe, 검증팀 SoD 과제2 CONFIRMED→반영.`
- "누가·언제·왜" 가 남으면 다음 세션이 재litigate 안 함(두더지잡기 차단).

### ⑤ 프론트매터 스키마 (Metadata) — 기계가 읽는 태그
모든 문서 최상단 표준 프론트매터. 클로드가 grep 한 번으로 원하는 문서만 골라냄.

```yaml
---
title: 자동배포 첫 실측 완주
status: 🟢진실원
category: 개발/업데이트배포     # 대분류/서브 = 폴더와 일치
tags: [자동배포, B-4, 시크릿게이트, 첫실측]
related: [[20260716_고리4_작지서]], [[헌법41_문서시스템]]
commit: ea7b23d
updated: 2026-07-28
---
```

### ⑥ 명명 규약 (Naming) — 파일명이 곧 검색키
`{YYYYMMDD}_{대분류}_{주제}_{상태}.md` — 파일명만으로 시기·주제·유효성 파악.
- 예: `20260728_개발_자동배포첫실측_진실원.md`
- 오늘 분류가 어려웠던 원인 = 명명 규약이 없어서. 앞으로 이 규약이 자동 분류를 가능케 함.

### ⑦ 루트 MASTER_INDEX — docs 전체 진입점
`docs/INDEX.md` = 모든 폴더 INDEX 로 가는 지도 + "지금 진실원 문서 Top 10".
클로드가 세션 시작 시 이것부터 읽으면 **전체 지형을 30초에 파악**.

## 3. 미래 확장 — RAG 의 뼈대
이 구조 = 나중에 "AI 챗봇이 사내 문서 자동 검색"하는 RAG 의 기초.
- 프론트매터 태그 = 벡터DB 메타필터
- INDEX = 검색 1차 후보군
- 상호참조 = 그래프 탐색
- 지금 폴더+INDEX+메타 를 갖추면, 미래에 임베딩만 얹으면 완전 자동 문서 Q&A 가 된다.

## 4. 헌법 #41 제정 제안 (문구 초안)

> **#41. 문서는 무지성 축적 금지 — 폴더별 분류 + INDEX + 상태태그 (2026-07-28 사장님 헌법)**
> 정리 안 된 .md 를 컨텍스트에 무지성으로 쌓지 않는다. 모든 문서는 ① 대분류 폴더(개발/검증/설계/운영기록/헌법/조직도/CS)에
> 속하고 ② 프론트매터(status·category·tags·related·updated)를 갖고 ③ 폴더 INDEX.md 에 한 줄 등재되며
> ④ 대체 시 옛 문서를 🔴폐기/⬛흡수 태그 + `superseded_by` 로 못박는다. 쓸 때마다 제자리에.
> 목적: 클로드(AI)가 폴더별로 필요한 정보만 자동으로 꺼내 읽고 써서, 신호 대 잡음비를 높여 더 정확·빠르게 일한다.
> 위반 = 정리 안 된 문서 방치 = 두더지잡기·오판 재발 원인.
